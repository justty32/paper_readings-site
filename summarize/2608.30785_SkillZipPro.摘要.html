論文／訪談原始來源

SkillZip Pro: Execution-Aware Dynamic Compression of Progressively Loaded Skills for Self-Evolving Agents 重點摘要

一句話

SkillZip Pro 不把 skill 當成一段可隨意縮寫的 prompt，而是把根檔、參考檔、子 skill、schema、script 與 asset 視為會依執行路徑漸進載入的資源圖；它只在可提供覆蓋證據時移除跨檔冗餘，並在發佈前重讀實體目錄，驗證路由、契約、作用域與鎖定內容。

問題與方法架構

  • 問題：生產環境的 skill 是目錄而非單檔。只壓根檔會漏算大部分部署成本，也可能把罕用分支提到每次都會載入的根層；先把全部檔案串接後再壓縮，則會抹掉漸進揭露的界線與路由關係。因此不能只看單一壓縮率，而要同時管理 catalog、activation、deployment 與 path-weighted cost。
  • 資源圖與類型化契約：編譯器先解析目錄內的顯式參照、載入 guard 與來源 span，把每個文字資源拆成適用條件、工作流狀態、工具需求、規則、輸出格式、驗證義務、來源與必須原樣保留的殘餘。可執行檔、結構化資料與二進位資產一律鎖定。
  • 跨檔壓縮與證據層級：若根檔或已宣告的環境契約已經提供同一義務，可從私有參考檔移除冗餘；多個分支重複的內容只在其共同載入作用域內抽出共用模組，罕用長分支則改成有明確 guard 的按需 capsule。每次刪除都要有字面包含、覆蓋保留轉換或受限邏輯蘊涵的 witness。
  • 路由與入口保護：導航行與參照來源行不允許被重寫或合併。資源還會依宣告分成 private、public 與 conditional；公開子 skill 必須在沒有根檔的情況下仍可獨立使用。壓縮後的目錄會經獨立稽核，任一分支不可達、鎖定 artifact 不同 byte 或 interface contract 不連續時，都退回未壓縮版。
  • 兩條正交的部署軸：One-Shot 每次重建完整 bundle，Continual 則先原樣套用演化 patch，再只重算受影響的圖封閉包，必要時全局 repack。Persistent 會改寫並發佈正式目錄，可同時降低儲存與執行成本；Transient 保留正式目錄原樣，每次執行建立任務專屬視圖，換取公開入口的天然獨立性。

作者報告的結果

主實驗使用 BFCL-v4、LiveMathematicianBench 與 SpreadsheetBench，彙集 102 個 held-out 任務。SkillZip Pro 在三項任務的平均成功率為 0.560，未壓縮 Evolved Bundle 為 0.541（作者自報）。以逐任務配對的 bootstrap 檢定彙集三個 benchmark 後，SkillZip Pro 成功率為 0.480，相對未壓縮版的差異為 +0.010，95% 區間為 [-0.029, +0.059]，通過事前設定的非劣性界線（作者自報）。

在四層成本上，One-Shot 版把已發佈 token 從 2649 降到 2112、每次必載 token 從 212 降到 196、平均單次路徑 token 從 588 降到 500、最差單次路徑 token 從 755 降到 669，分別省下 19.7%、7.3%、14.3% 與 10.8%（作者自報）。它保留 1.000 的原始路由對，而 root-only 與 flat-concat baseline 都為 0.000（作者自報），說明資源還留在磁碟上不等於 agent 還找得到它。

生產環境的中文內容審核 skill 實驗中，受 witness 保護的最終設定移除 38.1% 的已發佈 bundle，在 200 次成對稽核中降低 10.4% 的實測每次 token（作者自報）。兩次壓縮版準確率皆為 89.00%，同 session 未壓縮 baseline 分別為 92.00% 與 91.00%；作者將此解讀為仍在未壓縮系統的觀察變動內，而非證明完全同值（作者自報）。無保護設定雖然可移除 71.4%–75.8%，卻損失 18–26 個準確率百分點，主要是誤刪豁免條款而增加單側偽陽性（作者自報）。

結論與局限

論文的主張是，skill 壓縮的安全上限由「每次移除能提出多強的證據」決定，不由刪除比例決定。對漸進載入的 bundle，品質、路由可達性、公開入口獨立性與四層成本必須並列，單一壓縮率沒有獨立解釋力。

作者明言，類型契約覆蓋保護的是外顯指令與作用域，不是普遍語義等價；自然語言的暗示、語氣與重複強調仍可能影響特定模型。稽核也可能與契約抽取共享同一錯誤，所以高風險 skill 仍需人類審查或更強的形式規格。此外，生產案也暴露語言相依的保護規則：只支援英文的決定性抽取器在中文 bundle 中會漏掉大量義務。

對 ai_core 的價值／接點

這篇對 ai_core 的直接價值，是把「skill 是一個檔案」改成「skill 是一張有載入作用域、入口契約與成本的圖」。任何摘要、去重或結構重整，都應先回答某條指令是否必須獨立使用、會在哪條路徑被載入、被哪個上層內容覆蓋；否則「沒有刪檔」仍可能導致能力完全不可達。

其發佈流程也可作為 ai_core 的固化治理範本：轉換器提出候選，獨立 auditor 不信任記憶體中的宣稱，而是重讀已落盤產物；通過後才原子發佈，失敗就回退本次有效輸入。這種設計把「自我演化」從自由重寫改成可追溯、可驗證、可拒絕的編譯管線。
