論文／訪談原始來源

《FunctionEvolve：以 LLM 進行結構引導的符號迴歸》重點摘要

一句話概括

FunctionEvolve：一個讓 LLM 看得見表達式樹（AST）結構的演化式 SR 框架——洞察是「SR 進步常來自局部編輯而非整式重寫」，故把 AST 結構顯式攤開供「選親／突變／係數擬合」三環共用：結構摘要促進多樣親代選擇、AST 規則局部編輯 + LLM 引導改寫保留有用子式、結構感知擬合拆分/約束/簡化係數以更可靠評分。只用基本函數族、無領域專屬規則。在 LLM-SRBench 的 129 題合成子集配 Claude Opus 4.6，回復 107 條精確式，SA@50 達 82.9%（同骨幹基線的 4.5 倍）、SA@1 達 55.8%（勝先前最強 top-1 結果 PiT-PO 的 3.6 倍）。並稽核出 LLM-SRBench 材料科學子集的共線性→可辨識性問題。

解決什麼問題

現有 LLM 驅動 SR 雖比隨機 GP 更有方向，但對結構盲（structure-blind）：在不透明候選間做選擇、缺顯式局部突變機制、且脆弱的係數擬合會低估正確骨架而過早丟棄。三大瓶頸：(1) 從通用種子而非結構先驗起步；(2) 親代選擇靠固定啟發式、難在不同骨架間分配預算；(3) 不可靠的係數最佳化讓對的骨架顯得沒希望。

核心方法

四個圍繞「AST 可見搜尋」組織的模組：

  • Generator（生成器）：用任務脈絡 + LLM 知識合成領域公式與結構啟發式，並初始化種子表達式（不從無結構池起步）。
  • Selector（選擇器）：每輪抽取演化樹摘要（AST 結構/參數量/樹深/運算子數 + 訓練 NMSE/已擬合參數值）給 LLM，回傳一小組親代節點；偏好低誤差+簡單，並用選擇歷史避免重複展開相似分支。只暴露訓練誤差防洩漏。
  • Mutator（突變器）：對選定親代做三種互補操作——(1) 規則加法（保留親代、掛上基本函數模板，含加/乘/除與 exp/log/sin/abs/冪等一元包裹）;(2) 規則刪除（剪枝/解包以測冗餘）;(3) LLM 引導改寫（用親代結構+擬合資訊+歷史+領域知識做非模板的脈絡相依精修）。突變後以結構指紋正規化去重。
  • structure-aware Optimizer（結構感知最佳化器）：流水線＝變數投影（分離線性/非線性參數）→ DE/CMA-ES 全域探索 → L-BFGS 局部精修 → 參數吸附（snap 結構約束的指數）→ 符號簡化，降低係數搜尋難度、避免低估正確骨架。

結果

  • LLM-SRBench 129 題合成子集 + Claude Opus 4.6：回復 107 條精確式;SA@50 = 82.9%（同骨幹基線的 4.5×）;SA@1 = 55.8%（勝最強已發表 top-1「PiT-PO」3.6×）。
  • 消融：結構可見搜尋、LLM 引導局部精修、結構感知係數最佳化三者皆對可靠回復關鍵；結構可見性是核心，LLM 精修與結構感知擬合是必要的提議與評分機制。
  • 基準稽核：發現 LLM-SRBench 材料科學子集的輸入變數線性相依 + 弱非線性因子變化，造成結構可辨識性問題。

局限

  • 倚賴任務脈絡 T（變數意義/單位/科學背景）做引導，純維度任務（如 AI-Feynman 僅給名稱單位）時資訊較少。
  • 強骨幹依賴大型 LLM（Claude Opus 4.6）；結果以合成子集為主。
  • 點出但未完全解決基準本身的可辨識性問題（共線性）。

對讀者的價值

  • 本批 C 類的**「LLM × 演化 × 結構顯式化」代表**——與 2606.04360 Deliberate Evolution（同攻 LLM-SRBench、強調解耦提議與引導）為姊妹路線；與 2502.03367 SyMANTIC（壓縮感知）、2505.21879 SFR（純 transformer）形成對照。
  • 最值得記：「對結構盲」是 LLM-SR 的關鍵病灶;AST 顯式化讓 mutation 回歸 SR 的局部編輯本性;結構感知擬合（變數投影 + 參數吸附）避免低估正確骨架；以及對基準的共線性稽核（提醒別只看分數）。
  • 與 2606.09276 ERBench 對讀：FunctionEvolve 在「公開」LLM-SRBench 上刷高，ERBench 則主張要在「祕密集 + 複雜度分層」上才看得出真本事——兩者一攻一守。
