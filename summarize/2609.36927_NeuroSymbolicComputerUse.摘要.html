論文／訪談原始來源

Neuro-Symbolic Computer Use: Learning Reusable Policies for Reliable and Efficient Execution 重點摘要

一句話概括

NSPI 把反覆執行的電腦任務學成可重用程式，以程式保存穩定控制流程，以神經模型處理畫面定位與狀態判斷，再靠執行、雙重評審、agent 續作與程式修復改善政策，降低每次從頭規劃的成本。

解決什麼問題

同一工作流只是日期、檔名或起始視窗不同，純神經 agent 卻仍每次重新決策；錄製腳本則容易被狀態改變破壞。本文要學的是每個任務家族的參數化政策，重用穩定程序，保留觀察相關決策的彈性。（§1～2）

可靠性指標 Pass^k=p(g)^k，表示同一任務的 k 次獨立執行全部成功。本文每任務評估三次，Pass^3 是三次皆成功的任務比例，不能當成 Pass@3 或單次成功率；建構失敗也留在分母。（作者自報，§2.1、式 2、§4.1）

核心方法

  • 政策表示：以 Simulang 與 Python 控制流程保存變數、迴圈與分支。快捷鍵、檔案與 shell 操作可不呼叫模型；GUI grounding 把語意目標變成座標，state_satisfies 以觀察判斷條件，供程式分支使用。神經 primitive 仍有模型成本。（§2.2、附錄 A.1）
  • 從示範到迭代修復：以單條 base-agent 軌跡初始化，軌跡不必成功。Converter 抽出程式、用語意定位取代像素座標、把特定值參數化。主實驗最多五次迭代，每輪最多五次重設後 rollout，遇首個失敗即修復。（作者自報，§3.1.1、附錄 A.2～A.3、B.1）
  • 雙重評審與 healer：任務評審以唯讀探查確認持久終態；逐步評審先由不看任務、程式與意圖的 observer 描述變化，再由 localizer 結合任務與程式定位首個偏離。主流程要求 localizer 成功，且任務評審成功或經 applicability gate 跳過；任務評審 abstain 算失敗。失敗後 agent 從 rollout 結束狀態續作，摘要其進展，coding model 改寫政策；執行例外則直接把 traceback 交 healer。（§3.1.2～3.1.3、算法 1）
  • 變體與部署攔查：在參數、起始狀態變體上依序修同一政策，凍結後測未見原任務。此實驗採較寬鬆 judge gate，由任務評審決定成功，localizer 提供定位。政策學習不取 benchmark evaluator 回饋，但變體生成器會讀評估腳本。部署時另以 pre-action verifier 結合任務、動作、意圖註解、當前觀察與執行歷史，依 p_no>=theta 攔下納入檢查的寫入 primitive；被攔後可交 agent、修復或人工處理。它不同於只在程式指定位置執行的狀態檢查。（§3.2、附錄 A.5、B.2）

結果

重用泛化與攤銷

OSWorld 以 Terra 在 40 個參數家族、35 個初始狀態家族上學習，每家族至多三個變體，原任務留出。NSPI／AutoRPA 的 Pass^3 分別為參數變體 55.0%／37.5%、初始狀態變體 60.0%／51.4%（作者自報，§4.3、表 2）。

作者將一次性構建記為 C_pi、政策單次費用為 c_pi、base 單次費用為 c_mu：平均費用 C_pi/n+c_pi，當 c_mu>c_pi 時，費用損益兩平點為 n*=C_pi/(c_mu-c_pi)。表 3 的平均構建費為 2.03～6.45 美元，費用攤平點為 3.1～26.8 次，時間攤平點為 8.6～16.9 次（作者自報，§2.1、式 3、§4.4、表 3）。附錄 B.1 的費用口徑為供應商模型帳單加 grounding 呼叫計費；構建包含 conversion 與 policy iteration，單次費用是一輪最終 trial。不能把 15～217 倍寫成含學習費用的總節省。

驗證器與長工作流的反例

在 OSWorld-V2 延伸，NSPI 的 strict Pass^3 低於 base 5.6 個百分點，partial-credit 指標低 18.5 個百分點；作者歸因於長軌跡轉程式時遺失資訊（作者自報，§4.5）。

在另行測試的 verifier 實驗，theta=0.78。Qwen3.6-35B-A3B 對正確 rollout 的錯擋率最高 8.4%，但對應攔下的 24 個 primitive 漏放 17 個，WPR 為 70.8%；Qwen3.8-27B 則漏放 6 個，WPR 為 25.0%，代價是錯擋率 9.4%～25.0%（作者自報，§4.6、附錄 B.4）。錯擋率的單位是 rollout，漏放率的單位是應攔 primitive，不能混用。

局限

作者自陳：附錄 B.3 列出逐步評審看不到 primitive 回傳值與腳本輸出、延遲或漏點會使錯誤定位落在後續症狀、兩評審不能辨識不可行任務，以及任務評審過度信任可能落後於應用程式的已存檔內容。主文 §4.7 也指出評審過度保守會提高構建成本。附錄 A.5 說 headless API 寫入需另設防護；若 verifier 完成內容沒有 yes／no，會 fail open。verifier 實驗還使用另補意圖註解與 rubric 修訂，不能忽略其設定。（附錄 B.3～B.4、附錄 A.5）

原文敘述邊界：附錄 A.4 的設計描述說 observer 可讀非視覺 primitive 輸出，B.3 卻將實作不可見這些輸出列為限制；A.4 一處說 abstain 回退逐步評審，也與 §3.1.2、算法 1 的 abstain 算失敗不同。本檔分別依主流程規則與 B.3 實測限制表述，不自行假定已修正。（附錄 A.4、附錄 B.3）

本檔補註，非作者自陳：以上是有限 benchmark 的經驗可靠性，不是形式正確性或安全保證。表 1／3 未明示納入另節 verifier 的增量成本；種子取得、變體生成與完整部署成本也不宜逕自視為都已包含。實際決策應按自身重複頻率重算攤銷。

對讀者的價值・接點

本檔補註，非作者自陳：對 agent 編譯與治理，關鍵是把穩定程序固化成可檢查政策，把感知、驗收、修復與攔查保留為不同職責。政策重用省的是反覆規劃，不能連同測試、失敗診斷與環境假設一併省掉。
