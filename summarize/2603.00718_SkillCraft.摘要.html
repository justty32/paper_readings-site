論文／訪談原始來源

《SkillCraft》重點摘要

一句話概括

SkillCraft：一個含 126 個長時程、結構重複工具使用任務的基準，以及一套 Skill Mode protocol——讓 agent 在測試期間自動將多步工具呼叫鏈抽象為可重用的 code-based Skills、快取到本地 Skill Library 中、跨任務重用；頂尖模型（Claude 4.5 Sonnet、GPT-5.2）在 Skill Mode 下 token 用量降低最高 80%，且成功率的提升與模型的工具組合能力（skill execution rate）強正相關（r=0.65），證明工具組合技能是長期自主 agent 的核心能力。

解決什麼問題

既有工具使用基準（Toolathlon、WebArena、AgentCompany）評估的是「agent 能否用給定的原子工具完成單一任務」，難以衡量 agent 的工具組合與技能重用能力。真實長時程工作中充滿重複子結構（如多次搜尋-分析-摘要），重複執行這些子結構既低效（冗餘 state passing 造成 token 浪費、context window 飽和），也未反映 agent 能否形成抽象的可重用組合。本文填補了「評估 agent 工具組合與技能抽象能力」這一空白。

核心方法

  • 三階段任務建構：(1) 探索既有基準→提取設計原則；(2) 從三個來源構建 21 個種子任務（既有基準改編、手寫 web API、手寫本地資料處理），用統一 MCP 介面包裝工具；(3) 沿兩個正交維度系統性擴展：quantitative scaling（增加實體/子任務數 N=3/4/5）與 complexity scaling（增加每子任務所需工具呼叫數 M=3/4/5），產生 126 個任務涵蓋 6 領域×6 難度層級。
  • Skill Mode protocol：四個輕量 MCP 原語（save_skill / get_skill / list_skills / execute_skill）+ Coding Verifier 三階段驗證（語法檢查→執行錯誤報告→輸出品質檢測，如 >50% 欄位為 Unknown/None/0 則拒絕）。流程：重用嘗試→探索→組合→驗證儲存。
  • 三種評估模式：Base（無 Skill Library）、Skill（單層技能）、Hierarchical（技能可嵌套呼叫，max depth=10）。
  • 兩個分析維度：composition depth（單層 vs 層級）與 generalization（跨任務難度轉移、跨模型轉移）。
  • 評估指標：成功率（score ≥90%）+ 技能執行率 + 重用因子 + 效率（tokens/cost/turns/tool calls 的相對變化）。

關鍵發現/數據

  • 效率大幅提升：GPT-5.2 Skill Mode 成功率 87%→90%、token 1.23M→0.26M（-79%）、成本 $1.77→$0.43（-75%）。Claude 4.5 Sonnet：成功率 94%→96%、token 1.36M→0.40M（-71%）、成本 $1.08→$0.28（-74%）。
  • 技能執行率與成功率強相關（r=0.65）：表示高品質 code 生成能力直接轉化為可靠的工具組合。
  • 效率增益與模型能力正相關（r=0.53）：閉源強模型（Claude、GPT）從技能重用獲益最大；開源弱模型（Kimi、DeepSeek）獲益有限或甚至為負——Skill Mode 是能力放大器。
  • 更深層級不是更好的擴展策略：Hierarchical Mode 下 GPT-5.2 成功率從 90% 降至 79%，token 從 0.26M 回升至 0.60M。原因：巢狀技能中錯誤傳播放大（compounding failures）、潛伏 bug 在重用時暴露（latent bugs）、除錯需追蹤依賴鏈（debugging overhead）。
  • 技能跨難度轉移：Claude Easy→Hard 成功率 95%→100% 且 token 1.92M→1.56M；Hard→Hard token 1.96M→0.47M。預計算技能緩存在其他難度層仍達 97-100% 執行率。
  • 跨模型轉移：Claude 建立的技能被 Gemini/GLM/Minimax 執行時均達 100% 成功率。以 Gemini 技能執行 Claude 的 token 節省（69.2%）反而超過 Gemini 自用技能（14.8%）——執行者能力可補償中等技能品質，但無法挽救根本設計錯誤的技能（Minimax 技能導致 -48% 的 token 浪費）。

局限

  • 挑戰題的開放權重模型成功率仍低（<60%），Skill Mode 無法補償基礎能力不足。
  • Hierarchical Mode 的錯誤傳播問題未解決，目前 shallow 技能庫更可靠。
  • 僅在本文構建的受控 MCP 環境中測試，未驗證在真實多模態、多代理場景中的可遷移性。
  • 跨模型技能轉移實驗規模有限（8 個 hard 任務）。

對 ai_core 的價值（§5 接點）

工具使用技能 = 意圖→工具可靠性（§5.1）：SkillCraft 的 Skill Mode 本質上是 ai_core §5 中「意圖到工具調用」的可靠性橋樑。agent 透過 Skill Library 將成功工具序列固化為可執行代碼，從根本上消除了「原子工具鏈中的冗餘狀態傳遞」這一主要失敗模式（對應 §5.2 意圖-工具鴻溝）。Skill execution rate 與任務成功率的高相關性（r=0.65）直接證明了 ai_core §5 的核心主張：工具使用可靠性不是原子 API 呼叫的正確性，而是組合性技能的形成效率。

Coding Verifier 是 api_core 的輸出級把關實例（§5.3）：語法檢查→執行報告→輸出品質檢測的三階段驗證，對應 ai_core 中「程式化輸出驗證以單元測試做確定性判決」的治理模式。用 >50% Unknown/None/0 來檢測無效技能，是典型的符號級 heuristic filter——以可量化的規則而非 LLM 判斷做品質門檻。

層級組合 vs 成本-可靠性取捨（§5.1 + §3.3）：Hierarchical Mode 的發現（執行率 95-99% 但端到端成功率反降）為 ai_core 提供了關鍵警示：工具組合的深度擴展引入了「組合性風險放大」——每個嵌套層的 bug multiplying 效應抵消了重用的效率增益。這對應 ai_core §3.3 成本梯度中的「呼叫複雜度與失敗率的非線性關係」：存在一個最優組合深度，超過後成本反而上升。
