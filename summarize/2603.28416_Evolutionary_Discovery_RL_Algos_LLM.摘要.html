論文／訪談原始來源

《用大型語言模型演化發現強化學習演算法》重點摘要

一句話概括

把 REvolve（用 LLM 當演化變異算子的 reward-function 發現系統）從「發現獎勵函數」推到「發現整個 RL 學習更新規則（update rule）」——直接在可執行的更新規則程式碼空間做島嶼種群（island）演化搜尋，每個候選＝一套完整訓練程序（一個 loss 函數 + 輔助狀態更新）;刻意禁用 actor-critic、TD 誤差、value bootstrapping 等正統機制以逼出非正統演算法；每個候選用完整訓練 run 在 Gymnasium 上端到端評估，演化後再用 LLM 提議超參區間做後處理微調。發現的演算法（CG-FPD、DF-CWP-CP）在 10 個環境上與 SAC/PPO/DQN/A2C 競爭；有趣的是被禁掉 TD 後，演化竟自發收斂到「世界模型 + 規劃蒸餾」這類 model-based 結構。

解決什麼問題

RL 演算法的核心是學習更新規則，但它幾乎總是手工設計且固定。已有自動化只碰架構、超參、訓練訊號；少數碰更新規則（Oh 2020 可微更新函數、Co-Reyes 2021 結構化 loss 表達式）也只在受限的參數化表示內搜尋，產不出「以可執行訓練邏輯表達的根本不同更新規則」。更新規則空間是離散程式結構，梯度法與局部最佳化都不適用（小改動就質變學習動態、超參高度敏感），故需 population-based 演化；但更新規則是緊耦合訓練程序，盲目 mutation/crossover 幾乎只產出無效變體——因此需要 LLM 當「能提出連貫、可執行修改」的引導機制。

核心方法

  • 形式化：RL 演算法 ≡ 更新規則 f，其核心是可微 loss L_f(θ, ξ_t; D_t)（θ 為固定 trunk 的策略參數，ξ 為更新規則引入的所有輔助可訓練元件/內部狀態）；在固定策略架構、optimizer、訓練迴圈下，每個不同 f 即一個不同 RL 演算法。
  • 演化骨架（承 REvolve）：島嶼種群 + LLM 當變異算子；每代 LLM 提議連貫變體（mutation 編輯一個程式 / crossover 融合兩個），訓練評估後選擇更新種群。
  • 強制非正統：變異時禁止顯式實例化 actor-critic 分解、bootstrapped value targets、TD 更新（只在演化搜尋期施加此約束）→ 逼出新穎更新規則。
  • 適應度：每候選在 5 個訓練環境 × 5 seeds = 25 runs 端到端訓練，取各環境訓練中的最佳評估回報，用環境特定 reference bounds 正規化到 [0,1] 後跨環境聚合成單一 scalar fitness。
  • 後演化超參優化：對 top 演算法，LLM 讀完整實作 + 環境規格，提議每個內部 scalar 的可行數值區間 → 評估穩健性、改善固定預算下的穩定性（因為 RL 對內部 scalar 極敏感、穩定 A 的超參常對 B 失效）。

結果

  • 演化進度：GPT-5.2 與 Claude 4.5 Opus 各跑兩 seed，最大 fitness 隨代單調上升；GPT-5.2 全程更高（末代 fitness 0.65–0.69）vs Claude 4.5 Opus（0.37–0.47，未產出有競爭力候選，後續排除）。
  • 兩個發現的演算法：CG-FPD（Cross-Entropy Guided Fractal Plan Distillation，潛在表示 + 動力學學習 + 規劃當教師訊號 + 蒸餾式策略更新）與 DF-CWP-CP（Dual-Flow Confidence World Planning with Controllability Prior，世界模型 + 信心 + 雙流策略正則 + 可控性先驗）。
  • 泛化：在 10 個環境（5 訓練 + 5 未見）上，經後演化超參調後與 PPO/A2C/DQN/SAC（相同 256×256 MLP）相比的最佳評估回報具競爭力；但學習曲線常非單調、末端不穩，靠 best-checkpoint 才達競爭水準。

局限

  • 每代約 30 小時 wall-clock（4×A100 40GB）、每候選 25 個完整訓練 run——極其昂貴。
  • 適應度只在 5 個訓練環境算 → 有過擬合風險（故額外用 5 個未見環境測泛化）。
  • 學習動態非單調、訓練末端不穩，需靠 best checkpoint 取得最終效能。
  • Claude 4.5 Opus 表現明顯較差，結果對 LLM backbone 敏感。

對讀者的價值

  • 本批 D 類**「演化發現 RL 演算法」的最新里程碑——直接對標 2101.03958（Co-Reyes 等的 Evolving RL Algorithms，搜尋結構化 loss 圖）與 2402.05828（Temporally-Aware RL Algorithms），但把搜尋空間從「受限參數化/符號 loss」拉到完整可執行訓練邏輯**，並用 LLM 解決「盲目變異多半無效」的痛點。
