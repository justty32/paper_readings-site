論文／訪談原始來源

《AFlow：自動化的代理工作流生成》重點摘要

一句話概括

AFlow：把代理工作流優化重新表述為**「在以程式碼表示的工作流圖上做搜尋」（節點＝帶 prompt 的 LLM 呼叫、邊＝程式碼定義的控制流／依賴），用一個特製的蒙地卡羅樹搜尋（MCTS）——以 LLM 當優化器、每個樹節點是一個完整工作流、靠樹狀經驗與執行回饋反覆改程式碼——幾乎零人工介入地自動生成有效工作流；在六基準上較最先進基線平均勝 5.7%，並讓小模型以 GPT-4o 推論成本的 4.55% 在特定任務上反超 GPT-4o**。

解決什麼問題

LLM 的能力高度依賴人工設計的代理工作流（帶詳細指令的 LLM 呼叫序列），設計耗費大量人力、難擴展與遷移。既有自動化嘗試都未達完全自動或不夠有效：DSPy 在自動 prompt 優化前仍需人工搭好工作流；GPTSwarm 用「圖＋強化學習」但圖結構難表示帶條件狀態的工作流；ADAS 雖用程式碼表示工作流（表達較完整），卻受其線性啟發式搜尋效率所限，難在有限迭代內找到好工作流。

核心方法

  • 問題形式化：工作流 = 節點 N（模型 M、提示 P、溫度 τ、輸出格式 F） ＋ 邊 E；邊可用圖／神經網路／程式碼表示。程式碼天生支援線性、條件、迴圈並可內嵌圖，表達力最強，故選為主要邊結構。優化即 W* = argmax G(W,T)。
  • 縮小搜尋空間：固定 M、τ、F，只搜程式碼邊 E 與提示 P；引入 **Operator（算子）**＝預定義可重用的節點組合（Generate、Format、Review & Revise、Ensemble、Test、Programmer、Custom）當積木。
  • MCTS 變體（每個樹節點＝一個完整工作流）四步循環：
    1. 軟性混合機率選擇：均勻分布＋分數加權（α=0.4、λ=0.2）從 top-k 與初始工作流中選；納入初始工作流以持久探索、避免局部最優。
    2. LLM 驅動擴展：LLM 當優化器，用被選工作流的經驗（歷次修改及其改善／失敗、預測與期望輸出日誌）改 prompt 或改程式碼連接，生出新工作流。
    3. 執行評估：直接跑（推理任務有明確評估函數），每工作流跑 5 次取均值／標準差。
    4. 經驗反向傳播：把表現、對父的修改、優化成敗存回經驗並傳給父節點。
  • 工程細節：template W₀ 只需補完呼叫函數；驗證/測試 = 20%/80%（seed 42）；空白模板跑 5 次挑高變異子集當驗證集；早停（top-k 均分連續 n 輪無改善或達 N 輪）。優化器用 Claude-3.5-sonnet，執行器用 DeepSeek-V2.5 / GPT-4o-mini / Claude-3.5-sonnet / GPT-4o。

結果

  • 主結果（表 1，GPT-4o-mini 執行）：AFlow 平均 80.3%，較人工設計法（IO/CoT/CoT-SC/MedPrompt/MultiPersona/Self-Refine）平均勝 5.7%、較自動化法 ADAS（67.2%）等勝 19.5%。各項：HotpotQA 73.5 / DROP 80.6 / HumanEval 94.7 / MBPP 83.4 / GSM8K 93.5 / MATH 56.2。
  • 難任務優勢更大：MATHlv5* 與 MBPP 上較 ADAS 提升達 57%。
  • 成本效益：小模型套上 AFlow 工作流，在 Pareto front 上以 GPT-4o 推論成本的 4.55% 反超 GPT-4o。
  • 可遷移＋消融：搜出的工作流多能遷移到其他模型（但不同模型需不同工作流才最佳）；無任何算子仍達 93.1%（GSM8K）並自主長出類 ensemble 結構。

局限

  • 本文只聚焦「具數值評估函數的推理任務」（數學／程式／QA）——沒有明確可算獎勵的開放任務不在範圍。
  • 搜尋成本不低：每次迭代要把工作流在驗證集上跑 5 次、共約 20 輪，且需一顆強優化器（Claude-3.5-sonnet）。
  • 固定了 M、τ、F 才讓搜尋可行，代表未真正搜索完整節點參數空間；algorithm 表述含少數筆誤。
  • 工作流不完全可遷移：換執行模型常要重搜。

對讀者的價值

  • 直接對應 ai_core §1「系統＝可優化的符號神經網路計算圖」＋「對計算圖的自動搜尋」：AFlow 恰好把「帶 prompt 的 LLM 呼叫＝節點、程式碼控制流＝邊」的計算圖交給 MCTS 自動搜索最佳拓撲與 prompt——這正是把「圖結構本身也當成可優化對象」落地的一個具體演算法樣板（選擇/擴展/評估/反向傳播的骨架可直接借鑑）。
  • 呼應 §3.3 成本梯度／級聯路由：其最硬的賣點是「讓便宜小模型跑優化出的工作流去逼近甚至超越貴的大模型（GPT-4o 成本的 4.55%）」——與同庫 2305.05176 FrugalGPT 的級聯路由互補：FrugalGPT 在「選哪顆模型」上省成本，AFlow 在「用什麼工作流結構」上把小模型的上限拉高，兩者可疊加成 ai_core「貴稀有智能當資產工廠、便宜高頻智能當消費者」的一條落地路徑。
  • 與 §3.6 固化引擎的關聯與界線：AFlow 的產物是一段確定性程式碼骨架＋少數 LLM 節點，等於把「一類問題的解法」結晶成程式——這是「固化」的雛形；但要注意它固化的是控制流、LLM 節點仍在，離「把 LLM 反覆處理的案例結晶成純確定性程式」還有距離，可當作固化引擎的上游「結構搜尋」階段。
  • 與 ADAS / GPTSwarm 對照的定位：三者都做自動工作流優化，AFlow 的差異＝程式碼表示（比 GPTSwarm 的圖更能表達條件/迴圈）＋樹狀經驗的 MCTS（比 ADAS 的線性搜尋更高效）。歸 I 類（自動化計算圖搜尋／工作流優化），開源、方法＋實證論文，適合做代理工作流自動生成、prompt/結構聯合搜尋、成本效益優化的人。
