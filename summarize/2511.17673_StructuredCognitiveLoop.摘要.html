作者：Myung Ho Kim（JEI University）

論文／訪談原始來源

《結構化認知迴圈：橋接符號控制與神經推理》重點摘要

一句話概括

將 LLM 智能體的認知拆成五個模組（Retrieval／Cognition／Control／Action／Memory，R-CCAM），並以 Regulation 層施加「軟符號控制（Soft Symbolic Control）」——符號約束不取代神經推理，而是在治理層引導 LLM 生成，Control 模組則作為確定性執行引擎實施加硬性規則（去重、容錯上限、終止判定），從而實現零策略違例、零冗餘調用、百分百決策可追蹤的受治理智能體。（此架構呼應 ai_core §1 所述：符號控制 + 神經推理 = 計算圖——SCL 正是將符號治理約束與 LLM 的機率推理編排為可執行、可審計的有向無環計算圖/迴圈。）

解決什麼問題

  • 現有 LLM 智能體（ReAct、AutoGPT、Reflexion、LangChain agents）將推理、記憶、執行三者糾纏於 prompt 驅動的單一生成迴圈中，導致狀態漂移、重複工具調用、策略違例、長期推理不一致。
  • 純提示工程（"please cite evidence"）把約束遵守的負擔壓在 LLM 自身，隨著上下文增長違例累積。
  • 記憶增強方法（MemGPT, TME, A-MEM）外掛了存儲但缺少治理——Cognition 仍可忽略已存證據、誤用規則或違反政策。
  • 專家系統有結構但僵化（知識工程瓶頸、邊緣案例脆斷），神經方法有彈性但不可控——兩類範式之間缺少一個在架構層實現橋接的治理方案。

核心方法

  • R-CCAM 五相迴圈（§3）：Retrieval（從靜態知識庫升級為動態即時取證層）→ Cognition（LLM 機率推理取代確定性規則鏈）→ Control（確定性執行引擎：去重、累錯終止、循環邊界）→ Action（僅經 Control 驗證後才執行）→ Memory（結搆化外部日誌，兼作狀態持久與約束驗證雙重角色）。
  • Regulation 與軟符號控制（§2.4.1, §3）：Regulation 是常駐治理層，透過 Metaprompt 對 Cognition 施加軟符號約束（如「必須引用證據」「每次只提議單一行動」）——它形塑可被提出的方案但本身不執行、不中止；Control 則獨立地對執行歷史施加確定性硬性規則（重複調用阻斷、錯誤累計閾值、終止判定），兩者互補而不重疊。
  • 與專家系統的結構親緣而非直接繼承（§3.2）：檢索↔動態知識庫，認知↔機率推理引擎，控制↔確定性調度器，記憶↔工作記憶+審計日誌，日誌↔解釋設施。
  • 實驗驗證：SCL Core（mock LLM，完全確定性可復現）做受控多步驟條件推理，另部署 GPT-4o 即時旅行規劃示範驗證跨模型泛化。

結果

  • 零策略違例（0/4 迴圈，100% 合規）vs. 基準 1.5–4.5 違例/任務。
  • 零冗餘工具調用（記憶緩存命中 100%）。
  • 百分之百審計軌跡完整性（13/13 記錄項，所有決策可逆查至證據與 Control 驗證）。
  • 實驗二（受約束任務分配）展示軟符號控制的自適應性：A 方案因工作負載不均被拒絕，保留於記憶中供審計，系統復原生成合規的 B 方案，而非脆斷失敗。
  • GPT-4o 即時 demo：150+ 查詢，0 策略違例，98.7% 任務完成率。

局限

  • 實驗規模限於 4–7 CCAM 迴圈，長視野（20+ 迴圈）的可擴展性未驗證。
  • GPT-4o 使用 temperature=0.7 引入隨機性，缺少跨溫度/跨種子的系統評估。
  • 定量比較基於文獻報告的錯誤率，而非在相同任務上頭對頭實作基準。
  • 領域覆蓋限於規劃與決策類任務，未測試創造生成、數學證明、對抗場景。
  • 缺少正式人類受試研究（信任、可用性、感知可解釋性）。
  • Metaprompt 本身仍是自然語言產物，效果取決於 LLM 對指令的解讀，可能產生新的「Metaprompt 工程瓶頸」。

對讀者的價值

  • 本庫 「方向五：LLM 智能體架構」 的基礎參考文獻之一：SCL 提出了從架構層而非提示層解決智能體可靠性的明確路徑——將符號治理融入計算圖而非依賴 LLM 「記住規則」。
  • 與 ai_core §1（符號控制+神經推理=計算圖）直接對話：SCL 的 R-CCAM 迴圈可視為一個可審計的推理計算圖，其中 Regulation 定義節點約束，Control 定義執行規則，Cognition 提供機率推理算子，Action 與 Memory 定義圖的 I/O 與持久狀態——完整展示了如何將符號控制與神經推理編排為一個可執行、可驗證的計算結構。
  • 與本庫其他智能體架構文獻對讀：可比較 SCL 的模組分解與 ReAct（交織推理-行動）、Reflexion（事後反思）、記憶增強方法（僅外掛存儲無治理）在可靠性來源上的根本差異——SCL 的保證來自結構，而非 LLM 的遵守意願。
  • 與本庫「可解釋性」一線對讀：SCL 提供的是結構式可解釋性（決策過程即審計日誌，無需事後生成 plausible explanation），可與本庫 SAE／概念電路等表徵式可解釋性方法互補——前者回答「系統做了什麼」，後者回答「模型內部表徵了什麼」。
