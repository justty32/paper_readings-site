論文／訪談原始來源

《AXIOM：以信任優先的神經符號執行架構實現可驗證數學推理》重點摘要

一句話概括

AXIOM：一個信任優先（trust-first） 的神經符號執行架構——LLM 嚴格只當「正規化器（canonicalizer）」：把非正式題目文字改寫成一個狹窄 schema，餵給確定性的電腦代數系統（CAS）管線 去推導並驗證答案，或以「棄答（abstain）」作為一等公民輸出。路由採 1:1:1 對齊（題型 regex ↔ schema 專屬 prompt ↔ 封閉式 CAS handler），已上線 3,100+ 條路由、跨 250+ 次連續 ship commit 零 lost_correct 回歸；在 4 個 MATH 類別上達 94.36% 正確率（2,592/2,747）且在可解析題上 100% 信任（零自信而錯）。

解決什麼問題

「不可驗證的 LLM 數學」問題：純 LLM/CoT 做數學會「自信地給出錯誤答案」，且正確與否只能事後靠 benchmark 判定，無法在 API 邊界給出可信保證。作者主張轉向信任優先而非準確率優先：寧可在不確定時明確棄答（abstain），也不要產出「自信但錯」的結果——「今天的棄答，就是明天的正確」（之後補上對應路由即可轉成正確）。

核心方法

  • LLM 僅為正規化器：不讓 LLM「做數學」，只讓它把自然語言題目改寫成一個狹窄、可被 CAS 消費的 schema；真正的推導與驗證交給確定性 CAS 管線。
  • 棄答為一等輸出：謂詞無法識別、題型未涵蓋 → 必須棄答，而非硬猜（Principle 3：predicate-not-recognized must be abstain）。
  • 1:1:1 路由對齊：每條路由＝「題型 regex（problem-shape）↔ schema 專屬 prompt ↔ 封閉式 CAS handler」三者一一對應；已交付 3,100+ 條路由。
  • 組合任務鏈框架：可把多個任務串成鏈（linear-return composition），並有「純規則」架構特例。
  • 運維原則形式化：math-template 分桶；以 LOST_CORRECT 掃描當回歸 oracle；新領域以「可解析優先（parseable-first）」上線。
  • token 效率：靠任務局部化 prompting 降低 token 用量。

結果

  • 4 個 MATH 類別：累計正確率 94.36%（2,592/2,747），在可解析題上達 100% 信任（零 confident-wrong）。
  • lm-eval 算術（2 萬筆基準，覆蓋 88% 算術記錄）：結構正確性達 100%（在可解析子集上）。
  • 生產分布：在 API 邊界零「自信而錯」事件；「無任務池（no-task pool）」成為發現新領域的架構通道；撰稿期間 registry 仍在擴張。
  • 跨 250+ 次連續 ship commit 零 lost_correct 回歸（LOST_CORRECT 掃描當回歸 oracle）。
  • 與純 LLM CoT 對比：AXIOM 的優勢在更難領域上呈凸性放大（越難差距越大）——但作者強調這是「兩種架構哲學，非單純競賽」。

局限

  • 視覺鎖定記錄（vision-locked，需看圖的題）無法處理；
  • NLP 不可化約的應用題（純文字語義題）難正規化；
  • Intermediate Algebra 天花板;
  • 自底向上承諾：覆蓋率靠人工逐條增加路由（bottom-up commitment），不是端到端學習，擴張需持續投入。

對讀者的價值

  • 本批 B 類「可驗證 LLM 推理」中最極端的「信任優先」立場——把 LLM 降格為純正規化器、推理全交確定性 CAS、把棄答當一等公民。與 2606.24124 VeryTrace（驗證既有 CoT）、2605.25618 SSR（軟邏輯求解器）形成「信任光譜」的另一端：AXIOM 用犧牲覆蓋率換 100% 可解析題的零錯。
  • 最值得記：「今天棄答、明天正確」 的運維哲學；1:1:1（regex↔prompt↔CAS handler）路由;LOST_CORRECT 掃描當回歸 oracle；以及「API 邊界零自信而錯」這個對生產級可信數學服務極實用的設計目標。
  • 與 2606.19315 Diffusion-Proof、2604.26311 DreamProver（形式證明追準確率）對照鮮明；與 2502.09100、2508.13678 推理綜述互補。對要把 LLM 數學部署成可信賴生產服務（而非刷 benchmark）的人最有參考價值。
