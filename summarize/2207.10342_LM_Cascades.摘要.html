論文／訪談原始來源

《語言模型級聯（Language Model Cascades）》重點摘要

一句話概括

Language Model Cascades（語言模型級聯）：一篇立場論文（position paper），主張把「重複呼叫單一語言模型」與「把多個模型串接起來」這類做法，統一理解為一種對字串值隨機變數定義聯合機率分布的機率程式（probabilistic program）——用擴充到字串型別的機率程式語言（PPL）來描述，並把 scratchpad／chain of thought、驗證器（verifiers）、STaR、selection-inference、工具使用等既有技術全部形式化為這種程式；作者把由此得到的程式稱為 language model cascade（語言模型級聯）。

解決什麼問題

  • 提示式（prompted）與微調式語言模型已展現亮眼的少樣本能力；在測試期重複與單一模型互動、或組合多個模型能進一步擴展能力。近期出現大量彼此不同的做法（scratchpad、CoT、learned verifiers、selection-inference、bootstrapping／STaR、工具使用、引導定理證明器等），但它們各自為政、缺乏統一語言。
  • 這些組合本質上都是機率模型：可用圖模型（graphical models）語言表達，只是隨機變數的值是字串這種複雜資料型別，而非整數／浮點數。一旦涉及控制流與動態結構（例如迴圈次數隨資料而定、依停止準則展開），就需要機率程式設計的技術，才能在同一種語言裡實作各異的模型結構與推論策略。作者要提供的正是這個統一框架。

核心方法

  • 核心定義（cascade）：一個機率程式，其中含有由 LM 取樣的字串值隨機變數；程式定義了這些變數的聯合分布，可對某些變數做「觀測（observe／condition）」，再對未知變數做推論（infer）。作者用嵌入 Python 的、以 effect handlers＋coroutine 實作的 trace-based PPL 來承載，支援任意控制流與遞迴（受 Pyro／NumPyro／PyMC4 啟發）。
  • 統一表述：p(A|Q,θ) 是零樣本問答；加入輔助「思考」變數 T 得 p(A,T|Q)=p(A|T,Q)p(T|Q) 即 scratchpad／CoT；對 T 求和不可行，故用 beam search 的 MAP 近似，或用 Self-Consistency 的前向取樣＋多數投票。
  • 把既有方法逐一納入框架：
    • Scratchpad／CoT：問題-思考-答案（Q→T→A）模型，few-shot 三元組作為 plate 內的觀測節點，用祖先取樣（ancestral sampling）推論。
    • 半監督與 STaR：少量 (Q,T,A) 監督三元組 DS ＋大量 (Q,A) 對 DL，把 T 當隱變數；STaR 被詮釋為在此級聯上的隨機 EM——E 步用拒絕取樣補全能導出正確答案的 thought（失敗則從 p(T|Q,A) 做「rationalization」以近似後驗），M 步再微調。
    • Selection-Inference：兩個互動的 LM 模組——selection 從事實集選子集、inference 依子集推出新事實，可迭代做多步推理。
    • Verifiers（驗證器）：加一個 V∈{0,1} 驗證標籤，訓練獨立模型判斷 thought/answer 是否有效；可在取樣時拒絕錯例、或把 thought 生成器條件在「驗證正確」上（呼應 RL as inference、decision-transformer）；可延伸為 N 步驗證，且驗證器可輸出自然語言批評。
    • 工具使用：把對外部工具（如計算器、瀏覽器）的呼叫直接寫進程式，即可用 simulation-based inference 等技術做推論。
    • Twenty Questions：把 Alice／Bob 兩代理的對話建模為兩條互動的馬可夫鏈交換字串，可視為字串動作的 RL、或條件在目標狀態上的推論問題。

結果

  • 這是一篇立場／框架論文，主要貢獻是統一形式化而非大規模實證。唯一報告的實驗是 BIG-bench 的 Twenty Questions：用 LaMDA 137B、以溫度 1.0、每個概念前向取樣 50 條對話、以目標概念是否出現在 Bob 提問中判成功，模型解出 29% 的任務（40 個概念中答對 11 個最不抽象的，如 apple、dinosaur、car、love、beauty）。
  • 附錄給出可執行的 Python 級聯範例（question_answer、question_thought_answer、self-critique、逐句驗證器、selection-inference、Twenty Questions），以及一個 infer(program, observe=..., examples=...) 的推論 API。

局限

  • 推論困難是核心技術挑戰：字串值變數上的機率推論很難；本文除拒絕取樣外未評估其他推論／訓練期方法。
  • 定位是立場論文，未做大規模基準比較。
  • 作者指出的未來方向：把 LM 訓練成「填空」以模擬後驗推論（LM 當 proposal／guide 網路，呼應 foundation posteriors）、探索微調而非只用少樣本提示、以及用**機率程式歸納（program induction）**去搜尋能解任務的級聯結構（而非假設固定程式結構）。

對讀者的價值

  • 這是 ai_core 核心比喻的學術理論框架源頭。 ai_core §1 的關鍵領悟把工作單位描述成「像符號神經網路——一張計算圖，多數節點是確定性的 shell／py 函式，少數節點是那個隨機的 LLM」，並把單位視為「帶 LLM 留白的程序／一整條調用鏈」。本文正是把「多次 LM 呼叫＋控制流＋其他組件（工具、驗證器、確定性緩衝節點）」形式化為一個機率程式（cascade）：確定性節點對應 py/shell 函式，隨機的字串節點對應 LLM 留白。cascade ＝ ai_core「調用鏈／計算圖」比喻的形式化。 值得注意的是本文的 Verifier 圖裡明確標出「確定性 buffer 節點（拼接輸入）＋隨機節點」的混合——與 ai_core「多數確定性、少數隨機」的計算圖直觀完全同構。
  • 庫內對照：2310.03714 DSPy 可視為把這種 LM pipeline 進一步宣告化並可編譯／可優化的一條路線（本文則停在把 pipeline 統一表述為機率程式、把推論指認為核心難題）。（DSPy 具體內容以其自身條目為準，此處不杜撰。）
  • 定位：立場／框架論文，貢獻是「用擴充到字串的 PPL 統一一整批 LLM 組合技術」這個觀點與最小實作。適合關心 LLM pipeline／agent 編排、CoT／驗證器／工具使用的統一抽象、把多 LLM 呼叫當機率程式來推論與優化 的讀者。
