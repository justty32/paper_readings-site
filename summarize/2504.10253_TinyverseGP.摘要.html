論文／訪談原始來源

《TinyverseGP：面向遺傳程式設計的模組化跨域基準框架》重點摘要

一句話概括

TinyverseGP（靈感取自 tinyGP）：一個統一、極簡、模組化的遺傳程式設計（GP）框架，把多種解編碼（表示）× 多個問題域（符號迴歸 SR／邏輯合成 LS／策略搜尋）放進同一框架，共用核心庫、各表示用「tiny 模組」實作，目標是跨表示、跨域的公平基準比較，破解 GP 領域長年的碎片化；現為第一版原型（已整合 tree-based 與 graph-based GP），開源、串接 SRBench／GBFS／Gymnasium。

解決什麼問題

GP 本質是程式合成，能跨多個問題域；但隨新表示（linear、graph/Cartesian、grammar-guided）與新應用（分類、電路設計…）增生，領域變得碎片化、封閉化：不同表示彼此不比較、效能不跨域量測；既有基準散在各域專屬套件，跨域評估的實作成本極高。呼應 2012 年「GP needs better benchmarks」（獲 2022 SIGEVO Impact Award）的批評。

核心方法

  • 設計哲學：仿 tinyGP——每個變體保持極簡（minimalist）實作；共用概念放共同庫，易整合新表示、易支援新域。
  • 物件導向 + 模組化雙範式：
    • 輕量表示模組：每個表示繼承一個 model 基類（促進一致性），各自在一個 tiny 模組裡處理初始化、解碼、繁殖（breeding）、評估。
    • GP 模組為核心：已提供函數／終端集、超參與模型配置等基礎設施；既有 Python GP 實作可低成本整合進來。
    • 共同 API：只需實作少數方法即可擴充，不必懂整個 codebase。
  • 三個問題域 + 基準介面：
    • 符號迴歸（SR）：找精簡準確的數學式；介面接 SRBench（含 Feynman、classic）。
    • 邏輯合成（LS）：合成符合布林函數真值表的布林式；介面接 GBFS（General Boolean Function Benchmark Suite，七類布林函數、多輸出）。
    • 策略搜尋（policy search）：MDP 上找最大化回報的決策策略；用一個 agent 類橋接 GP 模型與 Gymnasium 環境。
  • 架構圖（Fig.1-3）：黑箱問題（給定輸入-輸出對）走訓練資料集；策略搜尋走 agent-環境-獎勵迴路。

結果

  • 本文是願景／框架提出論文（position + prototype），非實驗 benchmark 論文，無大規模效能數據。
  • 交付：第一版原型，已實機整合 tree-based 與 graph-based GP 於 LS／SR／policy search 三域；尤其納入長期被忽視的 policy search 域，以平衡被過度使用的舊基準。
  • 開源（GitHub GPBench/TinyverseGP，主分支持續開發 + GECCO-2025 鎖定分支）。
  • 規劃支援（表 1）：LS（Classic、GBFS）、SR（Classic、SRBench、Feynman，部分支援）、Policy Search（Gymnasium，部分支援）、Program Synthesis（LeetCode、PSB1&2、SyGuS，開發中）。

局限

  • 仍是起步原型：僅 2 種表示、3 個域實機；多項基準（程式合成 PSB1/2、SyGuS）標為「開發中」。
  • 走極簡路線，刻意不含島嶼模型、區域搜尋等外加機制（利純表示比較，但離 production 級框架尚遠）。
  • 尚無跨表示／跨域的實證比較結果（留待後續廣泛比較研究）。

對讀者的價值

  • 本批 G 類（遺傳編程）的「基準／基礎設施」代表——和 2501.17168 EvoGP（GP 的 GPU 加速系統）互補：一個談統一基準與表示比較的框架、一個談底層加速。
  • 最值得記：「共同庫 + 每表示一個 tiny 模組」 的極簡可擴展套路；一個框架橫跨 SR／LS／policy search 三域並各接 SRBench／GBFS／Gymnasium；policy search 用 agent 類橋接 MDP 環境。
  • 定位：社群驅動的開放框架願景 + 第一版原型；適合做 GP 跨域基準、表示（tree/graph/linear/grammar）公平比較、想把自家 GP 變體插進統一比較環境的人。承接 SRBench／GBFS 等既有努力、推動跨域基準標準化。
