論文／訪談原始來源

《Leroy：命令式程式語言的庫學習》重點摘要

一句話概括

Leroy 把函數式世界成熟的「庫學習（library learning）」工具 Stitch 包裝起來，透過「AST → Lisp 化 → 剪枝 → 補洞收尾（closing）→ 校驗呼叫點 → 轉回 Python」的管線，讓 Stitch 式的抽象抽取能落地到命令式語言（Python 子集 P2）——核心工程貢獻不是更好的搜尋演算法，而是「馴服命令式語言的不規則性與狀態/副作用」，把 Stitch 產出的、多半在 Python 裡非法的候選抽象，過濾並修補成語意正確、可重用的函數。

解決什麼問題

既有庫學習（DreamCoder、Babble、Stitch）都針對函數式 Lisp 類語言——其規則性（regularity）讓重複結構容易被抽出。但真實工程師寫的是命令式語言，想抽取共用功能是為了可重用性（reusability）與可維護性（maintenance），而非只服務程式合成。直接把 Python AST 餵給 Stitch 會壞掉：Stitch 假設「所有程式元素都是一等公民」，會抽出像 compare(1,2,==)、x = while 這種語法非法、或改了變數卻不回傳（因 Python 賦值產生的是被呼叫函數的區域變數）的破碎抽象。

核心方法（Leroy 管線）

  • Lispify（Lisp 化）：把 P2 程式的 AST 攤成巢狀函數呼叫餵給 Stitch；命令式語句序列以仿 Lisp let 的 StatementList(stmt, 其餘) 遞迴結構編碼。
  • Stitch 搜尋：沿用 Stitch 的語料引導自頂向下搜尋（CTS，branch-and-bound 依效用剪枝）產生候選抽象。
  • 剪枝三類非法候選：(1) 類巨集（macro-like）——如把 1+2 抽成 add(1) 2，靠反轉 lispify 重建 AST 檢查完整性；(2) 非法參數——把運算子 == 當參數傳，靠把參數編為 identifier 節點驗證；(3) 瑣碎抽象——單行加法/列印雖高頻但無價值，用「最小 AST 節點數」門檻濾除。
  • 收尾（closing）補回作用域：用**活躍變數分析（liveness analysis）**找出 live-out 變數並加入回傳值（無則回傳最後一個運算式）；找出未 live-in 卻被使用的變數並補為參數，避免未初始化。
  • 校驗呼叫點：偵測「引數名與函數體內符號衝撞」的隱式改名問題（如迴圈內每輪重算的 x 被當一次算好的引數傳入），衝突則棄用該呼叫點。

結果（具體數字）

  • 語料：122 支小程式（大學編譯課單元測試，平均 7 行，重複性低＝對 Leroy 的最壞情況）。
  • 最小門檻設 20 個 AST 節點時，找到 6 個有效抽象（多為賦值/列印組合，平均用於 2.5 個呼叫點）。
  • 剪枝掉 3123 個類巨集、32 個非法參數、約 42000 個過小候選（Stitch 把每個子樹都當候選，故海量小抽象）。
  • 壓縮比僅 1.04x（不含庫）；含庫反而膨脹 1.2%——因 closing 會加大抽象體與呼叫點；作者坦言小而不重複的語料難有好壓縮，寄望更大真實語料。

局限

尚未大規模嚴格測試；不支援 lambda、巢狀函數、類別；未如 Babble 利用語意等價擴大抽象選擇；只測了壓縮，未測可讀性等其他品質指標（可編進效用函數但未做）；壓縮增益在此語料上幾近於無。

對讀者的價值

  • 直接命中 ai_core §3.6「固化引擎（crystallization engine）」——把反覆處理的案例結晶成確定性程式碼/抽象庫——的跨語言落地工程路徑。ai_core 第一目標是程式碼助手（§5），而真實工程程式絕大多數是命令式；本篇正是把 Stitch 式庫學習從函數式搬到命令式（Python）時，必須解決的那一串工程難題的清單與解法：不規則語法、變數作用域、賦值副作用、活躍變數、呼叫點改名。這正是「固化」不能只靠 LLM 一鍵重寫、而要靠確定性程式分析保證語意等價的骨架。
  • 與 Stitch（函數式）對照：Stitch 是本批同族的函數式基準；Leroy 是它的「命令式落地版」。ai_core 若要把重複的 LLM 處理沉澱成可重用工具函數，函數式路線的乾淨（Stitch）與命令式路線的髒（Leroy 所列的 closing / call-site 校驗）之落差，正是「固化引擎」工程量的真實估計。
  • 對照 §3.4 治理「拒絕為預設＋憑證准入」：Leroy 的剪枝/校驗本質是「候選抽象需通過一系列確定性驗證才准入庫」——與 ai_core「預設拒絕、憑證才放行」同構，且展示了不靠 LLM、純程式分析即可把守關卡（相對 ReGAL 靠 LLM 抽象但無法證明等價、且受 context window 限制）。歸 G 類。
