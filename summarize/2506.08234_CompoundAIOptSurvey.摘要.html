作者：Yu-Ang Lee, Guan-Ting Yi, Mei-Yi Liu, Jui-Chao Lu, Guan-Bo Yang, Yun-Nung Chen（National Taiwan University, 台灣大學）

論文／訪談原始來源

《複合式 AI 系統優化：方法、挑戰與未來方向的綜述》重點摘要

一句話概括

一張把 26 篇「複合式 AI 系統優化」方法歸位的 2×2 地圖：以結構彈性（Fixed vs. Flexible，能否改系統拓撲）× 學習訊號（NL 自然語言回饋 vs. Numerical 數值訊號） 兩軸分類，並提出帶條件邊的統一圖式形式化（系統＝有向圖 Φ=(G,F)，節點參數拆成數值 θ_N 與文字 θ_T，邊由布林函數 c_ij(τ) 決定有效拓撲隨查詢動態變化），把 DSPy / TextGrad / Trace / GPTSwarm / ADAS / AFlow 等散落的方法放進同一座標系比較。

解決什麼問題

以 LLM 為核心、外掛 RAG／工具／程式碼直譯器的複合式 AI 系統普遍勝過單一 LLM，但為特定應用打造時仍需大量啟發式試錯調 prompt 與管線。近年雖冒出許多自動化優化法，卻因「是否允許改拓撲」「如何傳學習訊號」而機制迥異，且缺乏統一術語與概念框架，新手難入門。既有綜述多只談自然語言驅動的優化、忽略「更新系統拓撲」的機制、也未涵蓋最新進展。

核心方法

  • 四個原則性維度：① 結構彈性（Fixed＝只調節點參數／Flexible＝連圖結構一起優化）；② 學習訊號（NL 回饋＝輔助 LLM 產文字指引／數值訊號＝再分規則式、SFT、RL、DPO）；③ 組件選項（LLM／RAG／CI／工具／IGM）；④ 系統表示（DAG、循環圖、自然語言程式、Python 程式碼）。
  • 取前兩維建 2×2 分類法，四象限代表方法：
    • Fixed＋NL：TextGrad（用 NL 模擬反向傳播）、Trace（一次性聯合更新所有 prompt）、AIME/REVOLVE/GASO/LLM-AutoDiff。
    • Fixed＋數值：DSPy（bootstrap 拒絕採樣選示範）、MIPRO、BetterTogether、SiriuS（SFT）、MAPoRL（RL）、SysDPO（DPO）。
    • Flexible＋NL：Agent Symbolic Learning、MASS（證明優化 prompt 比搜拓撲更易得利）、ADAS（首用 Python 程式碼作系統表示）、AFlow（MCTS）、DebFlow。
    • Flexible＋數值：DyLAN、GPTSwarm（把系統建模為可優化圖、REINFORCE 學連結）、及一批「為每個查詢實例化新系統」的 meta-LLM 微調法（MAS-GPT／AutoFlow／MaAS／W4S／FlowReasoner／ScoreFlow）。

結果

綜述論文無實驗數字，主要產出為框架與分類：統一形式化（Φ=(G,F)、條件邊 c_ij(τ)、Θ=(θ_N,θ_T)、目標 max μ 平均）＋涵蓋 26 篇的 2×2 表（標註各法的四維屬性、是否需微調、是否限 DAG）＋基準使用頻率統計（圖 4，顯示多數仍用 GSM8K／MMLU／HumanEval／MBPP 等單 LLM 基準）＋開源可補充儲存庫（github.com/MiuLab/AISysOpt-Survey）。

局限

  • 「複合式 AI 系統」無公認定義，納入自稱 MAS／LM programs 的工作而未系統分析概念重疊；只收明確優化多節點者，可能漏掉相關論文。
  • 因領域快速演進，投稿前兩個月的研究僅部分涵蓋；因篇幅省略各方法的實驗細節與結果，需回讀原文。
  • 指出全領域共通痛點：殘留人工超參數、計算負擔高（API 成本 vs. GPU 的取捨）、實驗範疇偏窄、NL 回饋缺收斂理論、安全風險少人管、函式庫不標準化。

對讀者的價值

  • 這是 ai_core §1「系統像符號神經網路計算圖（多數確定性節點＋少數 LLM）」那張地圖的現成學術索引：本篇的「Φ=(G,F)＋條件邊＋節點參數拆數值/文字」形式化，幾乎就是 ai_core 世界觀的論文版對照——可當導航起點，把 DSPy／TextGrad／Trace／GPTSwarm 等方法一次歸類比較，省去自己重畫地圖。
  • 對 ai_core 定位自己最有用的是兩軸座標：ai_core 的北極星是「逐步剃除對 LLM 依賴、把反覆案例固化成確定性程式碼」，對照本地圖等於選擇 Flexible Structure（改拓撲）＋以能落地成程式碼的表示（Python code 象限，如 ADAS/AFlow/ScoreFlow），而非停在 Fixed＋NL 的 prompt 調校——本篇正好把這條路上的既有工具攤開供挑選。
  • 反向的警訊也有價值：綜述點名的痛點（NL 回饋無收斂保證、meta-LLM 優化 token 成本失控、Flexible 法不正則化系統複雜度）恰恰是 ai_core「成本梯度／級聯路由（§3.3）」與「固化引擎（§3.6）」要正面對治的——本篇說明「為什麼不能只靠 LLM 反覆優化拓撲」，反證了 ai_core 把智能結晶成確定性節點的方向。歸 I 類（地圖式索引／綜述）。
