論文／訪談原始來源

《函式庫漂移（Library Drift）》重點摘要

一句話概括

自我演化技能庫的瓶頸不是作者（LLM），而是圖書管理員（librarian）：無界累積而缺乏結果驅動的生命週期管理（退休、容量上限、meta-skill 先驗），會造成檢索退化、錯誤注入與效能停滯——僅僅加上一個最小治理配方（Ratchet），就能把 frozen LLM 從 +0.002 推到 +0.328。

核心貢獻

  1. 故障定義與可複現觸發器（§3）：操作性定義「函式庫漂移」（library drift）——技能庫累積的 artifacts 使代理表現跌破無技能基準；兩種消融實驗框定此故障：A1 拔掉技能注入（+0.002，無技能地板）、A4 過早退休（−0.019，跌破地板、主動傷害）。
  2. 超越最終分數的追蹤級診斷（§4）：僅看 pass@1 不夠——本文提出三個互補診斷訊號：(a) 逐技能貢獻分數 ĉ(s)；(b) 歸因判決（HELPED/HURT/NEUTRAL/INAPPLICABLE）；(c) Router 參與率。它們在終端指標惡化之前就暴露漂移。
  3. 經驗證的修復配方 Ratchet（§5）：三個治理機制聯合防止漂移——(a) 結果驅動退休（Nmin=100, τ=0.10）；(b) 有界容量上限 C=50；(c) meta-skill 寫作先驗。並給出非發散保證（Proposition 1）。
  4. 八組消融實驗（§6）：分解哪些機制是 load-bearing（退休、meta-skill），哪些可安全移除（顯式去重；A5/A6 甚至略優於 Default）。三個意外發現：A4 主動傷害、A5/A6 優於 Default、A8 成本高但增益邊際。

對讀者的價值（與 ai_core 的接點）

本論文與 ai_core §3.6 固化引擎 直接對齊，其診斷配方是固化引擎的基石：

  • 庫漂移診斷 對應固化引擎的「技能品質監控」：逐技能貢獻分數 ĉ(s)、歸因判決（HURT 比例上升是漂移的領先指標）、Router 參與率（跌破 50% 應中止合成並調查）。
  • 修復配方 Ratchet 的三個機制直接可工程化：(1) 結果驅動退休 → 當 evidence 足夠且貢獻分數 ≤ −τ 時標記 DEPRECATED；(2) 有界 active-cap → 強制 curator 在超 cap 時淘汰最低貢獻技能；(3) meta-skill 先驗 → 強制風格一致性以減少有害技能誕生（是最有價值的單一組件，−0.141 when removed）。
  • 非發散保證（Prop. 1）：在 cap C 與退休閾值 τ 下，期望 pass@1 不會漂移低於無技能地板超過 τ+ε+Cδ，為固化引擎提供形式保證。
  • 工程啟示：(a) 治理不是均勻有益的——證據不足時過早退休（Nmin=20）比不做更糟；(b) meta-skill 可替代顯式去重（在此規模）；(c) 診斷訊號應在終端指標惡化前介入；(d) Default 設定（Nmin=100, τ=0.10, C=50）是安全起點，可在觀察診斷訊號後放寬。
