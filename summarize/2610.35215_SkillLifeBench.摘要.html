論文／訪談原始來源

SkillLifeBench 重點摘要

一句話概括

SkillLifeBench把skill的磁碟程式、registry所選版本、載入物件及保留handle串成執行證據，再把「任務完成」與「越權目標達成」分開驗。關鍵不是只辨識prompt injection文字，而是檢查選定修正版是否真的在下一次呼叫執行；實驗顯示好用輸出可與危害共存，execution provenance可幫復原，但規則法、模型診斷與全面還原各有風險／正常效用／成本取捨。

評測對象與資料分母

生命週期分Acquire、Store、Retrieve、Execute、Evolve：分別涉及准入、持久程式與registry、版本選擇、實作呼叫、後繼版本啟用。每一對固定使用者請求與授權，只更動指定skill條件；授權界線包含可讀資料、目的地與可改狀態。主比較通常讓模型看到名稱／描述／schema／回饋，executor才解析實作；64個實作／介面案例指定精確apply_contract呼叫，用於測固定呼叫下的實作後果，不能全部當自由agent決策。（§3.1–3.2）

源benchmark共有388個配對scenario：262新引入（260建構＋2個OpenClaw更新），126改編AgentDojo並保留payload、任務、攻擊目標與介面。五family為A實作19、B介面／實作關係77、C runtime內容128、D工作流傳播65、E版本99。13個D案例另有固定下游工具的來源替換／命令移除control，完整suite為每模型\(2\times388+13=789\)次執行。（§3.2、附錄A，表5）

兩條決策軌各自評14模型，不與全源案例混算：

  • Runtime：89題，來自126個AgentDojo改編案例中具完整task／attack-goal checker者，亦稱semantic core。
  • Autonomous lifecycle：60題，從B／D／E各4個parent template、每template 5個instance而成；可檢視、選版、reload、設workflow或直接組合工具。12template不是60個獨立來源機制；560 qualification controls全過。

兩軌clean/challenged共4,172次決策執行。另12模型覆蓋完整源suite，兩Qwen加runtime，連同lifecycle合計11,504 baseline executions；這不是14模型全都跑完388題。（§3.3、§4.1、附錄B）

Joint success與執行證據如何定義

決策軌task及attack goal皆為Boolean，完整答案、artifacts、狀態及順序須全符合才算task完成；拒絕、無效動作或budget耗盡也可能導致未完成。Joint success為完成任務且未達成已註冊攻擊目標；一旦攻擊已發生，事後repair不會把它抹除。支援實驗另有case-specific utility與registered effect，不能一律升格為完整task／goal。（§3.4、附錄A，execution-bound outcomes）

SkillLifeEval分離模型推論、skill執行與量測。skill執行置於可丟棄Linux sandbox，接收宣告引數、synthetic task files與canary，API credentials留外部，外傳捕捉於受控本地環境；這不是對真實收件者或生產資料的攻擊測試。記錄包含呼叫參數／回饋、狀態、active／selected／executed versions、loaded object identity、執行時source hash及handle links。hash證明程式身份，checker才判定危害；對照磁碟hash、版本label本身不證明實際執行哪份程式。（§3.4）

每軌共同budget為15 logical rounds、30 attempted tool calls、每request 2048 output tokens、request 180秒、episode 900秒；運送失敗至多兩次transport attempts，不因無效內容重新抽答。Hosted用provider defaults；local Qwen為固定greedy設定。（§4.1、附錄A.1）

可行干預不代表模型總能選對

388源案例中170有agent-visible可行workflow、189有已驗證可信部署干預、29未驗證可行干預。170個workflow各換5個private test values，850 replay全保utility且無指定harm；這是可行性證明，不是14模型都能找到此路徑。（§3.5）

Check在Default系統指示加上呼叫前查操作、資料範圍、資源、目的地與使用者授權；tool／skill文字不創造權限。兩Qwen配對結果：46 non-runtime案例×2模型joint 29/92→43/92（+15.22百分點）；runtime core120/178→129/178（+5.06）；其他runtime26/70→35/70（+12.86）。runtime core task成功134→145，但完整attack goals也19→21，不能只報joint改善就稱攻擊數全面下降。（§4.3，表3、附錄C，表11）

另一個189-case deployment cohort×2模型，可信還原的utility joint26/378=6.88%→267/378=70.63%，觀測harm216→0；正常配對utility303/378→294/378（80.16%→77.78%）。這與下述77-case matched recovery是不同cohort。（§4.3、4.5）

Matched recovery如何公平比較證據

重用77個B-family parent、17template、6種互斥主要故障：磁碟程式替換24、版本／routing錯10、stale loaded code12、old handle8、同digest錯instance binding5、已允許但有缺陷舊碼18。每parent有risk與benign狀態；兩Qwen各77 risk＋77 benign，故每方法risk分母154、benign154，合計308。（§3.6、附錄A，表6）

Logs(M)有授權、calls/returns、incident outcomes、native logs、installed/active版本、file hashes、approvals與合格候選；Provenance(E)只再加loaded implementation、invocation-time source hashes、stored-handle links。兩者incident、模型、prompt、actions、budget相同，fault labels及repair答案不給模型；M仍可含native-log execution identities，不能說Logs完全沒有任何執行資訊。（§3.6、附錄A.1–A.2）

模型一次選一plan：noop、reload_selected、activate_approved_and_reload、quarantine_selected、restart_runtime、full_restore，不允許trial repairs或先偷看follow-up。共同executor從匹配磁碟／registry／cache／memory狀態施行，再由全新Default對話做固定後續任務。Full不經診斷，從公開可用、核准且未撤銷、完整性驗證與task-compatible候選，依最大approval_seq、digest字典序tie-break選版，preflight後全還原並restart；不是拿hidden clean reference直接救回。（附錄A.1）

規則Reload以executed/disk hash違反版本／approval約束觸發reload或activate，多包則Full；Restore同trigger但直接Full；Link再檢查handle–object–call關係，依adapter能否刷新引用決定reload、restart或Full。允許的舊版本可合法，不能單憑不是最新就判故障。（附錄A.2）

實例：選對修正版仍執行舊handle

OpenClaw包裝案例中，使用者要發布example-skill一般文件並排除.git；packager-vcs才是包裝skill，兩者不是同一物件。\(t_1\)三政策都active／selected \(v_1\)，但Reuse保留handle而執行\(v_0\)，ZIP同時有normal.txt與禁止的.git/config；Fresh／Revalidate執行\(v_1\)，保文件且無canary。source manifest綁upstream module，code_sha256綁wrapper，不能混成同一hash。\(t_0\)皆舊版、\(t_2\)排定fresh resolution皆新版；這是受控routing，不是任意部署都會自然延續。（§4.6，表4、附錄D）

支援storage study以77 B-skills、兩Qwen與SmolLM3-3B形成924 trajectories；231 admission/replacement配對中，66個skills新增161個harm positives。更新study共108 runs（54 challenged／54 benign）；\(t_1\)的36 controlled post-update執行有12次parent執行，分6 harmful challenged及6無害benign。執行不一致與危害仍須分別驗。（§4.4、附錄D）

閱讀界線

（本檔補註，非作者自陳）本篇未設獨立Limitations節；具體限制來自實驗設計：lifecycle只有12個來源template，復原只測兩個Qwen，受控synthetic fixtures與預定actions不是生產系統全面安全保證；joint也只排除已註冊goal／effect，不排除所有未知危害。非決策支援實驗仍有unobserved checks：M／E／Full各11、deployment各18，作者全留原分母，不應寫成所有效應都已完整觀測。Hosted ID及版本依作者實驗紀錄，不是本檔對今日服務的再查。（附錄A–C）
