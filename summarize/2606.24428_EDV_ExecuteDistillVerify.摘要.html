論文／訪談原始來源

《Escaping the Self-Confirmation Trap：EDV 執行-蒸餾-驗證的可靠經驗學習》重點摘要

一句話概括

現有 agent 經驗學習多是「同一個 agent 既執行任務、又總結結果、又決定寫什麼進記憶」的單 agent 閉環，會掉進自我確認陷阱（Self-Confirmation Trap）——把「錯但自洽」的軌跡誤當成功經驗寫入記憶、再經檢索重用不斷放大錯誤；本文提出 EDV（Execute-Distill-Verify），把執行、蒸餾、驗證解耦給不同角色（多異質 agent 並行執行 → 第三方蒸餾 agent 對比分析 → 執行組共識驗證後才寫入），在 τ²-bench 上 Pass@1 達 86.6（勝 Router 83.5、無記憶基線 76.4–79.6）、MMTB 達 58.10，並把記憶品質審計中的「噪聲/幻覺」分從 1.21 降到 0.63。

解決什麼問題

開放世界常無明確 ground truth，若執行與評估耦合在同一推理過程，內部連貫但實際錯誤的軌跡會被誤判為成功而寫入記憶。一旦寫入，這些錯誤被反覆檢索重用、持續累積——尤其長視野任務中間決策難直接驗證、表面進展可能掩蓋有缺陷的推理。作者把此失效模式命名為自我確認陷阱，並論證單 agent 自反思閉環在本質上脆弱：核心挑戰不是「收集更多經驗」，而是在寫入記憶前更可靠地構建經驗、抑制錯誤與噪聲。

核心方法

EDV 分「經驗構建階段」與「推理時使用階段」：

  • Execute（執行）：多個異質 agent 並行探索同一任務空間，產生多樣候選軌跡，擴大解空間覆蓋、緩解單 agent 探索偏差。
  • Distill（蒸餾）：一個指定的第三方蒸餾 agent 對這些軌跡做跨軌跡對比分析，產生候選經驗——把「執行者中心的自我總結」換成「旁觀者對比」，降低單一視角偏差。
  • Verify（驗證）：執行組以共識機制聯合交叉驗證候選經驗，只有通過嚴格驗證者才寫入共享或私有記憶庫；抬高記憶插入門檻、降低污染。
  • 推理時：把新任務路由給合適 solver，並從記憶檢索相關經驗（共享記憶 τ_sim=0.80、私有 0.85）。
  • 三個關鍵收益：異質並行執行增多樣性、第三方蒸餾減單視角偏差、共識驗證使長期記憶不易被錯誤噪聲污染。

結果

  • 主基準：τ²-bench 平均 Pass@1 86.6（顯著勝 Router 83.5、Judge 81.5；無記憶基線僅 76.4–79.6）；MMTB 總分 58.10（勝 Router 55.96）；Mind2Web 跨任務/跨網站/跨域設定皆保持強泛化。
  • 記憶品質審計（5 分制）：相對 ReasoningBank（RB），Groundedness/Correctness 3.72→4.41、Actionability 3.58→4.32、Specificity 3.64→4.27；噪聲/幻覺 1.21→0.63、重用潛在危害 1.08→0.51——證明 EDV 在源頭過濾低質資訊。
  • 模擬自我確認陷阱：向 RETAIL 注入 10% 「錯但內部連貫」經驗（如錯誤付款規則），使 RB 的 Pass@1 從 82.5 暴跌到 77.2，量化陷阱的真實危害。
  • 消融：只「解耦執行與驗證角色」（單 agent + 獨立驗證者）僅 +1.2 分——軌跡多樣性是高品質記憶的必要前提；共享記憶檢索率 72.3%、每命中 +3.2% 成功率；學習效率上 EDV 全程比 RB 高 ~7–9% Pass@1，第 4 epoch 達 0.909（RB 第 2 epoch 後停滯甚至 0.830→0.815）；隨檢索條數 EDV 單調升到 0.886（RB 在 1 條後退化）；同時 RETAIL 推理 token 比 RB 省 24.5%。

局限

  • 經驗構建需多個異質 agent 並行 + 第三方蒸餾 + 共識驗證，離線構建成本較高（雖作者主張可離線並行、不增線上協調開銷，並以更高品質記憶省線上 token 補償）。
  • 共識驗證的可靠性依賴執行組能力與異質性；若所有 agent 共享同一盲點，共識仍可能背書錯誤。
  • 驗證門檻 τ 需調（τ=0.8 最佳，過嚴 0.9 會濾掉有用經驗）；SR 上界在三任務僅 24.21%/20.34%/18.31%，顯示長視野任務本身仍難。

對讀者的價值

  • 點破一個關鍵盲點：agent 自我改進的瓶頸常不在「記憶多寡」而在「寫入前的經驗品質」——這與 2605.12978（記憶被 LLM 持續更新會變壞）同源，也與 2509.04439 ArcMemo「選擇性檢索＋抽象」互補（ArcMemo 管讀、EDV 管寫入前的把關）。
  • 與 2606.25115 CURATOR 形成記憶生命週期兩端：EDV 管「寫什麼進記憶」（多 agent 共識驗證）、CURATOR 管「留/傳/信哪些已存條目」（淨值/位元組）；對讀有助建立完整經驗治理觀。
  • 最值得記：「執行與評估解耦」（用第三方蒸餾 + 共識驗證打破自我背書），以及**「軌跡多樣性是可靠經驗的前提」**（單 agent 加驗證者只 +1.2 分）。對任何想做 self-evolving agent 的人是必要的防錯設計，與 2406.18532 代理符號學習的「用語言梯度自我優化」可對照——後者也需防止 agent 自我強化錯誤方向。
