論文／訪談原始來源

《Program Synthesis via Test-Time Transduction》重點摘要

一句話概括

提出transductive program synthesis（轉導式程式合成）這一新表述：合成程式時顯式利用測試輸入來降低不確定性、產出對邊界案例（edge case）更魯棒的程式。框架 SYNTRA（Synthesis-by-TRAnsduction）把合成視為「在由程式輸出定義的有限假設類上做主動學習」——用 LLM 當 transduction 模型對精選測試輸入產高準確「偽標籤」，據此逐一淘汰不一致的假設，並用 greedy maximin 準則挑「最壞情況下能淘汰最多假設」的測試輸入以省 LLM 呼叫。在 4 個基準（Playgol/MBPP+/1D-ARC/MiniGrid）上，任務準確率最高提升 196%，同時更省算力。

解決什麼問題

傳統程式合成（無論從自然語言描述或輸入-輸出範例）都想從訓練範例泛化，但在真實情境（訓練範例少、測試輸入含各種邊界案例）下魯棒性差——從少數範例合成的程式套到測試輸入時，常在 atypical 輸入或角落 bug 上出錯。本文要在「測試輸入可得」的情境下提升魯棒性。

核心方法

  • 轉導式程式合成（formalization）：輸入＝程式規格 + N 個測試輸入；目標＝合成一個對「這批特定測試輸入」產正確輸出的程式（不求整體正確/通用，只求測試集上準）。
  • SYNTRA 框架：把合成當有限假設類上的主動學習——
    1. 建假設類：枚舉一批與訓練輸入-輸出對一致的候選程式（假設只在訓練對上被驗證）。
    2. 轉導預測（transductive prediction）：用 LLM 作 transduction 模型，觀察某個測試輸入與各候選程式對它的輸出，挑出一個輸出當偽標籤（借 LLM 的推理與世界知識產高準確偽標籤）。
    3. 假設淘汰（hypothesis elimination）：淘汰與偽標籤不一致的假設。
    4. 迭代：重複「輸入查詢選擇 → 轉導預測 → 假設淘汰」直到只剩一個假設。
  • greedy maximin 查詢選擇：為省 LLM 呼叫，貪婪選「在最壞情況下能淘汰最多假設」的測試輸入（對每輸入先看「淘汰最少假設」的最壞預測，再取其中 max）；平手時選「候選輸出總長最短」者以減 LLM 輸入長度/推理負擔。據此把「比下界多出的額外 LLM 呼叫」腰斬。
  • LLM 實例化：transduction 模型由 LLM 實作，兼顧推理能力與世界知識。

結果

  • 在 4 個基準——Playgol（字串轉換歸納程式設計）、MBPP+（自然語言→Python）、1D-ARC（視覺推理）、MiniGrid 上的程式化世界建模——SYNTRA顯著勝過純歸納（inductive）或純轉導（transductive）方法。
  • 任務準確率最高提升 196%。
  • maximin 準則下，用遠少的 LLM 呼叫達到與隨機選輸入相當的準確率（把超出下界的額外呼叫腰斬）。

局限

  • 依賴「測試輸入在合成時可得」（轉導設定）——不適用測試輸入未知的純歸納場景。
  • 偽標籤品質受 LLM 限制（雖高準確但非完美，錯誤偽標籤會誤淘汰正確假設）。
  • 假設類由「能擬合訓練對的候選程式」枚舉而成，仍需先有夠好的候選生成器；理論上「勝過貪婪主動學習」常為 provably hard。
