一句話概括

Zooter：既有「reward model 排序（RMR）」集成法要對每個查詢先讓所有候選 LLM 都生成一次、再用 reward model 逐一評分排名才能挑出最佳回覆，成本隨候選模型數線性放大；Zooter 把這套「跑全部＋RM 打分」的訓練期流程蒸餾成監督訊號，訓練一個只看 query（86M 參數的 mDeBERTa-v3-base）就能直接預測「該派給哪個專家模型」的輕量路由函數，推論時只需呼叫一個專家模型＋一次路由器前向傳遞，在 26 個子任務組成的評測集上平均勝過單一最佳模型、44% 任務拿下第一，甚至超越多個 RMR 基線。

解決什麼問題

「LLM 互補潛力（complementary potential）」假設：即便是號稱通才的對齊 LLM，也在不同領域／任務上有異質專長，因此集成多個 LLM 有機會穩定超越單一最佳模型。既有集成法（如 reward model 排序、LLM-Blender 的 pairwise ranking）要驗證並利用這個假設，必須先產生所有候選模型的輸出才能評分挑選，計算開銷隨候選模型數線性增加、不具擴展性。作者要問的是：能否只憑 query 本身（不生成任何候選回覆）就精準判斷該把它交給哪個專家模型，把集成的「判斷」成本從「每題跑 N 次生成＋N 次評分」壓到「每題一次輕量路由器推論」？同時，如何在 reward model 本身帶有不確定性雜訊、且沒有黃金答案標註的訓練查詢集上，穩健地產生路由監督訊號，也是待解問題。

核心方法

  • 核心取捨：reward model 排序準（尤其能利用 oracle 級別的 RM 揭露 LLM 間互補性），但要讓每個候選模型都跑一次推論才能打分排序，推論成本隨候選數 N 線性增加；Zooter 的解法是把這個「貴但準」的排序訊號，蒸餾進一個推論時只需輸入 query（零生成成本）的路由函數，訓練完成後推論時只呼叫路由器＋一個被選中的專家模型，成本不隨候選模型數增加。
  • Reward Distillation（獎勵蒸餾）：離線訓練階段，先讓全部 M 個候選 LLM 對訓練查詢集 \(\hat{Q}\) 中每題都生成回覆，用現成 reward model 對每題的 M 個回覆各打一個純量獎勵，得到獎勵向量 \(\mathbf{r}_i\)；對獎勵向量做 softmax 得到「此 query 屬於各模型專長」的目標分佈，訓練路由函數 \(\mathcal{Z}(q)\) 以 KL 散度做知識蒸餾（\(\mathcal{L}=\mathrm{KL}(\mathcal{Z}(q_i),\mathrm{softmax}(\mathbf{r}_i))\)）去逼近該分佈。訓練查詢集不需要任何標準答案，只需查詢本身，故資料成本低。
  • Tag-based Label Enhancement（標籤增強）：作者實證 reward model 對單題打分帶有明顯不確定性（用 MT-Bench 分析：獎勵熵越高，該題排序結果與實際表現的一致性越差）。解法是用既有的指令標註器（INSTAG，Lu et al. 2023）為每個訓練 query 打標籤，把同標籤查詢的獎勵取平均得到「標籤級」獎勵 \(\mathbf{r}_t\)，再與原本的「樣本級」獎勵線性混合 \(\mathbf{r}_i^*=\beta\mathbf{r}_i+(1-\beta)\mathbf{r}_t\)（\(\beta=0.3\) 最佳），類似 label smoothing，用粗粒度標籤先驗去平滑樣本級雜訊，再拿混合後的獎勵取代原獎勵做蒸餾訓練。
  • 訓練資料 DivInstruct：整合 13 個開源指令資料集，用本地標註器打標後，每個獨特標籤取樣 10 筆，得到 47,986 筆指令、涵蓋 6,270 個標籤；並對評測集做 6-gram 重疊去污染，避免資料洩漏。
  • 實驗設置：候選模型為 6 個同為 13B 的 LLaMA 系模型（WizardLM／WizardCoder／WizardMath／Vicuna／OpenChat／Llama-2-Chat），訓練訊號用 QwenRM（7B）產生（在 RMR 基線中以較小參數量取得接近最佳表現）；路由器骨幹為 mdeberta-v3-base（86M 參數）。

結果

  • 主結果（26 子任務，AlpacaEval 5＋FLASK 10＋MT-Bench 8＋MMLU/GSM8K/HumanEval 3）：以「單一最佳平均模型」BMA（Llama-2-Chat，MTR 2.23、44 個任務中拿第一 31%）為對照，Zooter（β=0.3）MTR 降到 1.94、拿第一比率升到 44%，在 AlpacaEval／MT-Bench／整體 Benchmarks 上勝過 BMA，FLASK 打平；MT-Bench 上單項提升最明顯（平均分高出 BMA 0.39）。
  • 相對 RMR 基線：Zooter（86M 路由器）勝過 RMR w/ OAssistRM（MTR 3.42）、LLM-Blender pairwise ranking（3.39）、Auto-J（2.25），且計算開銷小得多；但未能全面超越 RMR w/ QwenRM（7B RM，MTR 1.58）與 RMR w/ UltraRM（13B RM，MTR 1.53）——作者明白寫出 Zooter 與 RMR w/ QwenRM「仍有明顯落差」，摘要中「超越多個 RMR 方法」是精確措辭，並非全面勝出。
  • Oracle 上界：以 oracle 排序（假想完美 RM）做 RMR，MTR＝1.0、拿第一率 100%，甚至在 AlpacaEval／FLASK 上超越 GPT-4，證實「LLM 互補潛力」假設成立，也是 Zooter 值得蒸餾的訊號來源。
  • RM 對特定領域判斷力不足：RMR 在 MMLU、GSM8K、HumanEval 上表現不佳，顯示現成 reward model 對知識、數學、程式正確性的判斷仍不可靠——這也連帶限制了以 RM 為監督訊號的 Zooter 在這些領域的上限。
  • 標籤增強消融：β=0（純標籤級）MTR 2.06；β=0.3（混合）MTR 1.97（最佳）；β=1（純樣本級，即無增強）MTR 2.34（最差），證實 reward model 的樣本級雜訊確實會傷害蒸餾品質，混合標籤先驗可緩解。

局限

  • 仍存在明顯 RMR 差距：作者自陳 Zooter 與最強 RMR 基線（QwenRM）「仍有明顯落差」，代表以單一路由決策取代「跑全部＋排序」在效果上尚未打平最強的判斷式基線，是效率換效果的權衡而非全面免費午餐。
  • RM 判斷盲區會傳導進路由器：既然監督訊號來自 reward model，而 RMR 本身在 MMLU/GSM8K/HumanEval 這類需要精確判斷對錯的任務上失準，Zooter 蒸餾出的路由決策在這些領域的可信度同樣受限，論文未提出修正此盲區的機制。
  • 硬路由、無棄權／驗證機制：路由函數對每題永遠 argmax 選出單一專家並直接執行，softmax 分佈若接近均勻（代表路由器自己也不確定）也不會觸發任何二次確認、降級或退回 RMR 的機制——沒有 §3.4 意義下的信心門檻或棄權設計。
  • 候選模型同質、單批次評測：六個候選模型皆為同規模（13B）LLaMA 系模型，論文未測試異質規模／異質架構候選集下路由器的表現，也未像同類路由工作那樣測試「換一批候選模型是否要重訓」。
