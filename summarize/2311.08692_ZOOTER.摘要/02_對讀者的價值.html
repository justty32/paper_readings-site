對讀者的價值

  • 這是 ai_core §2「工廠／消費者」＋§3.3「成本梯度」的路由版落地：訓練期「跑全部候選模型＋reward model 逐一評分」正是貴、低頻的工廠流程——一次性把「哪個 query 該給哪個模型」這個判斷結晶成路由器權重（資產）；推論期路由器只看 query 就能直接消費這份資產，完全不必再生成候選、不必再呼叫 reward model，正是便宜、高頻的消費者。§3.3 成本梯度的鐵律「判斷成本必須遠小於它省下的」在此體現為：把「N 次生成＋N 次 RM 評分」的判斷成本，換成「1 次路由器前向傳遞」。
  • 與 2406.15927 SEP 是同一母題的兩個實例，務必對照：SEP 把「10 次取樣＋NLI 蘊含分群才能算出的語意熵」蒸餾成「單次前向傳遞＋線性探針」；Zooter 把「N 個候選模型都生成＋reward model 逐一排序才能挑出最佳回覆」蒸餾成「單次路由器前向傳遞＋argmax」。兩者都是用蒸餾把一個貴的判斷過程壓縮成一個只看輸入（不必跑生成/取樣）就能給出的便宜判斷，差別只在判斷的對象——SEP 判斷「這次生成有多不確定」，Zooter 判斷「這個 query 該給誰生成」。
  • 與庫中已收錄的路由／混合路線對照，釐清 Zooter 的獨特定位：
    • 2406.18665 RouteLLM：用人類偏好資料學一個「強模型會不會贏」的二元 win-prediction router，昂貴基線是「永遠呼叫最貴的單一模型」，目的是把簡單查詢導向便宜模型省成本。
    • 2404.14618 Hybrid LLM：生成前用 BERT 路由器估「小模型追不追得上大模型」的機率，同樣以「永遠呼叫大模型」為昂貴基線，門檻可調滑動成本／品質。
    • 2407.10834 MetaLLM：把選模問題重構成多臂拍霸機，reward 把準確率與成本用旋鈕 p 綁在一起，同樣是「該花多少錢」的成本-品質權衡。
    • 2305.05176 FrugalGPT：cascade 式——先跑便宜模型，scorer 評分不夠可靠才逐級升級到更貴模型，是「事後補救」而非「事前決定」。
    • Zooter 的差異化在於昂貴基線本身不同：上述四篇的「貴」都指「呼叫最強／最貴的單一模型」；Zooter 的「貴」指的是 reward model 排序這個集成過程本身（要讓所有同量級候選模型都生成一次再排名，如 LLM-Blender 的 pairwise ranking 路線），Zooter 要解的不是「大小模型間的成本梯度」，而是「集成／排序判斷本身的成本梯度」——把 RMR 這個貴判斷壓成路由器這個便宜判斷。LLM-Blender（2306.02561，PairRanker+GenFuser 的 ensemble 代表作，與 SEP 等論文同批處理中、尚未入庫，此處僅指路線不加連結）正是 Zooter 論文中直接對標、要蒸餾其判斷過程的 RMR 代表方法。
