《DreamProver》重點摘要

一句話概括

DreamProver 把 DreamCoder 式的 wake-sleep 庫學習搬到形式化定理證明：在 wake 階段用 LLM 嘗試證明訓練集定理（直接證或遞迴分解出中間定理），蒐集「可學習」的經驗；在 sleep 階段把這些中間定理語意分群（句子嵌入 + K-Means + elbow）→ 抽象出更一般的候選引理 → 用結構相似度驗證 → 去重（樹編輯距離）→ 形式驗證 → LRU 遺忘，維護一個 <100 條 緊湊可重用的引理庫。學出的引理高度可遷移：跨多個數學域（不等式/數論/組合/幾何/機器學習理論）一致提升證明數、產出更短結構化證明、token 成本更低，並在 mathlib 未涵蓋的冷門域（平面幾何、ML 理論）達 SOTA。

解決什麼問題

LLM 定理證明缺乏累積、可重用的知識：先前庫學習法（如 LEGO-Prover）產出的引理幾乎不被重用（前人研究指出重用率極低）；證明也常冗長、token 成本高，且在 LLM 訓練資料稀少的冷門數學域表現差。

核心方法

  • Wake 階段（中間定理發現）：以當前引理庫嘗試證訓練集定理。
    • 可學習定理識別：在固定計算預算（證明次數 + 錯誤修正次數上限）內，若 LLM 能用庫中引理直證某定理，則該定理「可學習」，暗示一條建於既有引理之上的更進階引理，收集進 sleep。
    • 中間定理發現：難直證者，靠遞迴定理分解——LLM 先生成形式 proof sketch、再從 sorry 標記的未證子目標抽出中間定理；以「sketch + 中間定理能否重組證出原定理」驗證有效性，並用 LLM 做自然語言 sketch 檢查過濾錯誤分解。
  • Sleep 階段（引理演化 + 庫學習）：
    • 引理抽象（cluster-based）：LLM 為每個中間定理標自然語言描述（子域/難度/可用定理）→ 句子 transformer 嵌入 → K-Means 分群（elbow 定群數）→ 每群餵 LLM 生候選引理 → 把候選與群內定理轉一階邏輯表達式樹算結構相似度，超閾值才保留。
    • 庫更新三步：(1) 遺忘——LRU 追蹤各引理跨 wake 的使用頻率，滿容量時移除最少用者（經驗上維持 <100 條）；(2) 儲存新引理——用樹編輯距離去重；(3) 形式驗證每條新引理（通常是乾淨簡潔的知名定理，小取樣預算即可證）。
  • 推論：輕量框架——先帶庫直接 prompt 證；失敗則退回 sketch-and-prove（生 sketch + 逐子目標證，全程用庫），用更少 token 證未見測試題。

結果

  • RQ1（充分表徵域）：跨不等式/數論/組合，對比專有推理模型（pass@32 一次性生成）、開源 prover（DeepSeek-Prover-V2、Goedel-Prover-V2）、agentic 系統（Hilbert，分解深度 2；DreamProver 僅限單層分解），證明數一致領先（DreamProver 多個域達 ~48%/79%/75% 等最高列）。
  • RQ2：產出更精簡、結構化的證明，token 成本更低。
  • RQ3（引理有效性）：與「引理幾乎不被重用」的 LEGO-Prover 形成對比——DreamProver 平均大比例訓練集引理在測試集被重用並貢獻大比例成功證明，證實可遷移。
  • RQ3 消融：移除迭代式 wake-sleep 精煉，解題數 104→76；再移除語意分群（庫過大難檢索）76→53（甚至低於無庫 vanilla），證實「緊湊、抽象、可重用的庫勝過從龐大低階庫檢索」。
  • RQ4（冷門域泛化）：在 mathlib 未涵蓋的**平面幾何（LeanGeo-Bench）與機器學習理論（FormalML）**上，跨所有資料集與骨幹 LLM 達 SOTA，相對專有 LLM 基線有顯著相對提升。

局限

  • 引理庫本質上是領域特定的（須為各域分別演化）。
  • 仰賴 LLM 做分解、抽象、描述標註與驗證，受其能力與 prompt 設計影響。
  • 容量上限（<100）是經驗折衷；分解限單層在更難問題上的可擴展性待驗證。

對讀者的價值

  • 本批 G 類**「庫學習 / DreamCoder 譜系」的最新代表**——把「wake-sleep 抽象 + 遺忘 + 重用」這套程式歸納經典機制，落到 Lean 形式證明這個高難度符號域，並直面前人庫學習引理不被重用的痛點。
  • 最值得記：「語意分群 → 抽象引理 → 結構相似度/樹編輯距離驗證去重 → LRU 遺忘維持 <100 條」 的庫維護配方；以及「緊湊抽象庫 > 龐大低階庫」這個被消融數字（104→76→53）強力支持的結論。
  • 與 2602.00929（TheoryCoder-2 學 PDDL 抽象）、2512.13857（EvoLattice 累積微算子）同屬「累積可重用抽象」主題，但 DreamProver 場景是形式數學；與 2506.23408（LLM 夢見離散演算法）呼應「LLM 當發現引擎」。
