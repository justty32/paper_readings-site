論文／訪談原始來源

《紅皇后哥德爾機（RQGM）：協同演化的智能體與其評估者》重點摘要

一句話概括

RQGM（Red Queen Gödel Machine）：把「評估標準」本身拉進自我改進迴圈——讓學習型評估者（agent-as-a-judge）與被它評分的任務智能體一起演化；靠**受控效用演化（controlled utility evolution）把搜尋切成「世代（epoch）」，世代內凍結一個評估者（固定準則→保留既有自我改進保證），只在世代邊界用一個在保留真值集上「統計顯著勝出」的挑戰者替換它，並做選擇性抹除（selective erasure）**只丟棄依賴舊評估者的紀錄。在可驗證程式任務上以 1.35×–1.72× 更少 token 超越前 SOTA（HGM-H，pass rate 71.7% vs 69.9%）；論文寫作上協演化作者把接受率從 21.8% 拉到 40.5%；還能用對抗目標修正「偏袒 AI 生成論文」的審稿者偏誤。

解決什麼問題

現有自我改進智能體（Darwin-Gödel Machine、Huxley-Gödel Machine、HyperAgents）都假設評估標準靜止——固定的驗證器、benchmark 或標註資料集在 agent 變強的過程中保持有效。這忽略了演化的核心：物種不是對著靜止環境最佳化，而是隨環境（競爭者）一起改變。靜止評估帶來三個困境：(1) 有些目標任務根本沒有 benchmark（論文寫作、證明寫作）;(2) 評估太慢或訊號太弱；(3) benchmark 飽和或被 reward hacking 攻破。

核心方法

  • 把評估納入搜尋迴圈：每個 archive 節點是「多智能體工作區」（生成者 + 評估者），而非單一 agent；評估者本身是可學習的 agentic 流程。
  • 受控效用演化（核心機制）：
    • 搜尋切成世代（epoch）；世代內凍結一個評估者對所有任務 agent 評分 → 提供靜止效用訊號 → 前人的自我改進保證在世代內直接適用。
    • 並行協演化「挑戰者評估者」，在與任務 agent 共享的 codebase 內、用保留真值集評分。
    • 替換規則：挑戰者只有在保留真值上以 ε-best-belief（機率 1−ε 的下界）統計勝出時，才在世代邊界取代現任。
    • 選擇性抹除：替換後只丟棄「依賴被換掉評估者」的效用紀錄，其餘保留。
  • 三類實證收益：(i) 即使有驗證器，協演化加一個便宜的程式碼審查訊號也能提升搜尋效率；(ii) 在沒有 benchmark 的領域（論文/證明寫作）也能驅動生成器搜尋；(iii) 用對抗樣本目標去偏（debias）過度寬鬆的評估者。

結果

  • 程式（Polyglot，可驗證）：保留集 pass rate 71.7% vs 前 SOTA HGM-H 69.9%，且因審查者只查詢一次（vs 多輪執行）省 1.35×–1.72× token。
  • 科學論文寫作/審稿：協演化作者接受率 21.8% → 40.5%；協演化審稿者比靜止基線高 9% 真值準確率、搜尋成本低 3×。
  • 奧林匹亞級證明寫作/評分：協演化寫作者接受率提升 1.78×–1.86×。
  • 去偏：最強基線審稿者以高達人類 1.91× 的比率過度接受 AI 論文；RQGM 先收集被凍結評估者接受的 AI 樣本、後續世代當對抗樣本回放，產出對機器與人類同等嚴格的審稿者。

局限

  • 僅「初步實證調查」（preliminary preprint）；作者明言要探索更長搜尋視野。
  • 協演化效用換取了收斂保證的鬆動——比靜止準則更難保證收斂（只能保證「每個世代內」）。
  • 效用在每次替換時會掉一段（選擇性抹除丟掉舊紀錄）再重爬。

對讀者的價值

  • 本批 D 類的**「自我改進 × 協同演化 × 哥德爾機」代表**——把 Schmidhuber 哥德爾機的「可證明有益才自改」，用 archive 搜尋落地（承 DGM/HGM/HyperAgents 一脈），再補上「讓評估者也一起演化」這塊缺角，正是開放式（open-ended）自我改進的關鍵一步。
  • 最值得記：「受控效用演化」這個工程巧思——用 epoch 凍結把「非靜止目標」化約成一連串「靜止子問題」，從而同時保有自我改進保證 + 讓目標可演化；以及「便宜的學習型評估者反而提升搜尋效率」「對抗目標可去除 LLM-judge 偏誤」兩個反直覺結果。
  • 與 2101.03958（演化 RL 演算法，目標靜止）、2402.05828 對照：RQGM 攻的是「評估者非靜止」這條正交軸；與 2603.19461 HyperAgents（它的前身之一）一脈相承。
