論文／訪談原始來源

《EVOM：RL 中 Actor-Critic 架構的 Agentic 元演化》重點摘要

一句話概括

EVOM：把 actor-critic 架構搜尋形式化成雙層最佳化——內層用低保真 PPO 訓練權重給出便宜的 fitness 估計，外層由一個純粹當「架構設計師」的 LLM 設計 agent（完全與策略執行、環境控制解耦）迭代精煉「架構程式（可執行 Python）」做元演化；架構以開放式可執行程式表示（不固定拓撲，但受共同介面 PolicyNet/ValueNet 約束），LLM 對 elite 種群做 mutation/crossover 產後代，編譯失敗/非有限輸出/崩潰者罰 fitness −1000。在 MuJoCo Ant-v4、HalfCheetah-v4 上，最終演化出的架構（含殘差 + LayerNorm/SiLU）大幅勝過手工 PPO、LLM-guided random search 與 SOTA 的 MLES；消融證明「元演化迴圈」與「LLM 設計 agent」缺一不可。

解決什麼問題

在 actor-critic RL（如 PPO）中，policy/value 網路架構通常手工設計且當成固定實作繼承自前人，但架構其實會影響學習穩定性與最終效能。自動化 actor-critic 架構設計有兩難：(1) 每個候選都得先訓練才能評估，全預算比較極貴；(2) 設計空間開放式——policy head、value head、共享 trunk、normalization、activation 等可任意組合，沒有正典固定拓撲搜尋空間。

核心方法

  • 雙層最佳化：外層演化「架構程式」種群，內層用 PPO 在縮減預算 B_low 訓練每個候選的權重 → 提供可行的 fitness 訊號。
  • LLM 設計 agent（外層）：純架構設計師，與 RL 執行完全解耦；輸入 elite 程式 + 演化指令（mutation 改一個 / crossover 融兩個）+ 環境描述，輸出結構化設計描述 + 可執行程式。agentic 的有限意義＝維持狀態（current elite + 歷史評估 log）、採取設計動作（程式生成）、觀察反饋（內層 PPO 回報）;prompt 以 current elite 為條件 → 能跨代重用設計樣式而非每步獨立採樣。
  • 開放式架構表示：每候選＝generation label + 結構化設計描述 + 可執行 Python；必須定義 PolicyNet(obs_length, act_length) 與 ValueNet(obs_length)，但深度/寬度/activation/normalization/殘差/dropout/初始化/actor-critic 非對稱性全開放搜尋。可執行程式是評估的權威物件。
  • 驗證守衛：編譯失敗、非有限輸出、違反 tensor shape、訓練崩潰者 → 罰 fitness −1000，使無效架構難以存活 elitist 選擇或當 parent。
  • 流程：LLM 初始化種群 → 每代產 N/2 mutation + N/2 crossover 後代 → 各以 B_low PPO 訓練、K 個確定性 episode 評估 → 與 elite 一起排序、選 top-N → G 代後把最佳架構用全預算 B_full 從頭重訓回報。

結果（MuJoCo，N=16、G=20、B_low=100k步、B_full=5M步、3 獨立 run）

方法 Ant-v4 HalfCheetah-v4
Manual PPO 2517 ± 366 1691 ± 495
MLES（SOTA LLM 程式策略搜尋） 1185 ± 84 1046 ± 134
Random Search 988 ± 3 3613 ± 1953（方差巨大）
EVOM 4652 ± 747 5381 ± 1358
  • 消融：mixed reproduction（mutation+crossover）最佳;crossover-only 次之、mutation-only 較弱（局部編輯與設計樣式重組互補）；增大種群 N∈{8,16,32} 非單調獲益（更大候選池更依賴 noisy 低預算訊號）。
  • 發現的架構：Ant-v4 用殘差 + normalization;HalfCheetah-v4 用更深的 LayerNorm-SiLU MLP——都與手工 baseline 及初代最佳不同。
  • LLM backbone 比較：測 DeepSeek V4、Claude Opus 4.7、Qwen3.6 Plus。

局限

  • 只測兩個 MuJoCo 連續控制任務（Ant、HalfCheetah），泛化性未廣驗。
  • 內層用低保真（100k 步）代理訊號 → 與全預算（5M）結果有 gap（故 random search 的 best 曲線高但全預算重訓方差巨大），需靠最終全預算重訓定論。
  • 增大種群不單調改善，受限於 noisy 低預算 fitness。

對讀者的價值

  • 本批 D 類**「LLM-guided 元演化 × RL 架構搜尋」代表——與 2603.28416（演化發現 update rule）、2601.21847 READY（演化發現 reward）形成「LLM 演化發現 RL 不同元件」三件套，EVOM 打的是架構層，且明確把 LLM 定位成可重用設計算子**而非 RL 的替代品（對比 MLES 直接合成控制器程式）。
  • 最值得記：「雙層：低保真 PPO 當內層 fitness + LLM 當外層解耦設計師」 的配方；「架構＝可執行程式（開放拓撲但受介面約束）+ −1000 罰分守衛」 讓開放式搜尋與系統化評估相容；以及 mutation/crossover 互補、種群增大不單調 兩個演化工程觀察。
  • 與經典 NAS（vision/NLP）對照：把 NAS 思路引進長期被忽視的 actor-critic 架構設計；與 2101.03958 演化 RL 演算法正交（一個演架構、一個演 loss）。
