《EvolveNet》重點摘要

一句話

EvolveNet 讓資料留在各 agent 端，各端平行演化同一份 harness；伺服器只聚合帶有行為證據的程式改動，並以 scope 與逐題 gate 控制衝突和回歸。

方法

  • 每輪 server broadcast 共用 harness；client 在本地 workload 演化成 specialist，回傳相對同一 base 的 diff 與新增／失去能力的逐題證據，不回傳原始 workload。
  • 聚合器將 diff 拆成語意機制，依證據分為 global、僅 home-domain 生效，或拒絕。不同 domain 的衝突可放進有 guard 的分支，而非硬選一邊。
  • 合成後以獨立 validation slice 逐題比較新增解題數與回歸數；失敗可修一次，再不過就 rollback 到前一 shared harness。gate 只保護此驗證準則，不保證未見分布。

證據與限制

作者在 BIRD、DS-1000、LiveCodeBench、SWE-bench Verified、ClawEval 報告 shared harness 皆提升：57.3→70.7、55.5→68.5、33.3→66.7、37.5→57.5、65.8→74.1。DS-1000 的同一 client snapshot 消融中，delegation 64.0、global-only 66.5、scope-typed merge 68.5，支持的不只是 routing。限制是這不是隱私保證，程式 diff 可洩露資訊；亦需代表性標記 validation、可觀測 domain key，且三輪後 harness 明顯膨脹。
