Ranking Function Generation with LLMs for Termination 重點摘要

一句話概括

RAINFALL 把迴圈排名函式合成轉為受限制的程式與斷言填空，再以符號檢查和診斷回饋反覆修正；在所選已知終止的 C 程式上，作者報告比多個基線證明更多題，但其理論敘述有需要釐清的良基性問題。

問題與方法

排名函式將狀態映射到有良基次序的值，要求迴圈執行時依適當條件下降，並藉下界與迴圈 guard 的關係排除無限執行。作者處理單一、字典序及多階段排名函式；論文將多個或巢狀迴圈的處理交給歸約，並將 for 轉換為 while。（§2）

RAINFALL 先解析 C 程式，為每個迴圈插入四個位置：迴圈前宣告輔助變數、迭代前記錄排名值、迭代後更新排名值、最後檢查排名條件。結構化提示包含排名類型的說明與 few-shot 範例，LLM 填入輔助程式與斷言，不直接輸出一個未經確認的答案。（§4.1）

候選依序接受三項檢查，失敗診斷連同候選送回 LLM，直到通過或用完資源：（§4.2）

  1. 原程式語法比對：刪去產生的填空後比較 AST，檢查模型是否修改原程式；語義等價但語法改動的程式不在此比較方式的接受範圍內。
  2. 斷言完整性：檢查輔助變數宣告、前後更新與符合目標排名類型的下降、非負及終止條件。只驗證像 true 這種過弱斷言無法構成排名證明。
  3. 安全性檢查：以 UAutomizer 驗證插入的斷言；若取得反例，將違反位置與執行路徑加入下一次提示。所有檢查通過時輸出 Terminate 與含斷言的證明程式；資源耗盡或未能證明則輸出 Unknown，不是宣稱程式不終止。

作者聲稱此流程可確保通過的候選構成終止證明；其實際可靠性仍取決於程式轉換與完整性檢查是否忠實實作所需證明義務、數值型別語義及底層安全驗證器的正確性。（§4.2.2～4.2.3）

作者自報實驗

作者以兩個公開基準中已知終止的 C 程式測試：BS-F 170 題，BS-L 去除 AST 重複後 188 題，共 358 題。非 LLM 工具每題限時 1,800 秒；LLM 工具每次安全驗證限 60 秒、最多 12 次模型查詢，RAINFALL 使用兩次嘗試、每次最多六次查詢。這些資源限制不同，平均時間也需按各表的統計口徑解讀。（§5）

理論與實務邊界

本檔補註，非作者自陳：原文 §2 稱有理數上的 < 為良基，但一般有理數次序不具此性質；例如正有理數 1, 1/2, 1/4, … 可無限嚴格下降。作者的單一排名函式定義另要求每步至少下降固定 ε>0，有下界時能排除無窮下降；然而 §4.2.2 的斷言完整性樣式僅列嚴格 >。因此若允許無固定下降量的稠密數值語義，不能僅據「嚴格下降」推得終止；各類排名斷言的型別與良基條件仍須具體核實，本文的宣稱不應不加條件外推。（§2、§4.2.2）

作者對範例的推理明示忽略整數溢位與下溢，並將此類問題交由獨立安全驗證；這個假設不能自動視為所有實際 C 執行的保證。評估只選已知終止案例，不能衡量對不終止程式的整體分類表現；公開基準也可能出現在 LLM 訓練資料中。作者認為改為生成程式斷言可緩和污染，但這不證明不存在污染；驗證器逾時、模型選擇與基準代表性也會影響解題數。（§2.1、§5、§5.4）
