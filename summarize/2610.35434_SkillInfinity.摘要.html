論文／訪談原始來源

把「怎麼改技能」也寫成能被改的技能

一句話概括

Skill∞ 讓 meta agent 依 meta-skill 診斷、改寫、評估及選擇技能，並把同一程序用於 meta-skill 自身；改好的程序再用於不同任務技能。自改對象是技能包中的指示、參考檔與腳本，backbone 及評分機制維持固定。（§3.1–3.4）

解決什麼問題

既有技能最佳化多以固定流程改任務技能，即使演化 meta-skill，也可能仍受固定角色／管線限制，且每個任務重學。本文將最佳化程序本身封裝為標準技能，先在多個技能最佳化任務上改良，再重用於不同任務；兩層都透過 native skill discovery 載入，沒有把完整技能直接注入 prompt，也不要求 agent 必須載入。（§1、§3.4–3.5）

核心方法

技能包以 SKILL.md 的名稱、描述與指示為中心，可附腳本和參考資料。agent 初始只看名稱與描述，再自行決定載入；描述因此也可最佳化。task agent 與 meta agent 使用同 harness、同 backbone，而非靠更強最佳化模型。（§3.1）

任務技能分數是每題多次 trial reward 平均，再按題 macro-average。meta-level 的一個任務提供 seed task skill、訓練／驗證任務及內層候選預算；meta-skill 的分數是其導引內層最佳化後，相對 seed 的 validation score 增益，再跨技能最佳化任務平均。這個 meta score 不等於最終 benchmark test pass rate。（§3.1–3.2、附錄 G「Interpret scores」）

每輪先讀 archive、取得 parent rollout 並診斷，再建立有 observation／change／predicted effect／falsifier 的候選，評估、送獨立review，最後決定繼續、回溯或停止。可選較早節點，也可保留有目標失敗改善證據的同分候選；不是單純只選分數最高者。候選數而非 token 是搜尋預算單位，未評估draft也消耗預算。（§3.3，演算法1；附錄 G）

reviewer 在不繼承meta agent對話的隔離context內檢查包、提案及證據，拒絕沒有實質修改、未被啟用或不可用候選；meta-skill候選還須保留review等核心責任。它是另一個審查執行context，不能直接解讀為另一家模型、形式證明或外部真值oracle。只有review通過才可選擇，但作者明說無工具強制agent遵循整套程序。（§3.3、Limitations、附錄 G；review界線為本檔補註，非作者自陳）

自改時每輪安裝當前parent meta-skill，讓它診斷、改寫自己的程序，再用其導引的內層最佳化收益評估。方法確有程序改程序的迴圈，而非只改任務指示；但評分在自改範圍外，backbone不更新，也不保證無界提升。（§3.2–3.3、Limitations；末句無界界線為本檔補註，非作者自陳）

預算、案例與成本

作者自報每task skill最多四候選，自改最多四個meta候選、各內層任務兩候選。budget scaling只挑預設預算已明顯改善seed的子集；作者自報一至八候選時pass rate由47.5%升至82.5%，不能當全83題曲線。（作者自報，§4.1、§4.6、附錄 B）

附錄案例中，meta-skill將同分候選的選擇標準改為必須從rollout看到目標失敗有進展，下一輪依剛寫的標準選同分候選；任務技能案例則加入Three.js exporter腳本及座標／歸屬規則。這些案例展示程序和工具資源會改變，不只是文字潤飾。（附錄 C）

作者自報每task skill最佳化平均8.74M input、66.3k output token，其中8.23M input已cached；SkillEvolver為8.06M、75.8k。自改總97.65M input、778.6k output，攤83技能為每個1.18M、9.4k。input已含cached，不能再相加；表4排除test trials，攤提也不等於含所有部署推論的金錢成本。（作者自報，附錄 E，表4；成本界線為本檔補註，非作者自陳）

局限與證據邊界

作者明示：backbone固定，改善受技能包表達能力限制；兩層需可靠自動verifier，故適用於可計算可靠reward的領域；程序靠模型遵循長指示，沒有工具強制，僅靠meta-skill及獨立review。部署前也應檢查可執行腳本與啟用條件。（Limitations、Ethical Considerations，位於§5後）
