LLM-Guided Program Evolution for Circle Packing: Breaking 10 Packomania Records for $28 重點摘要

一句話

Discovery Loop 用單一 LLM 反覆重寫完整 circle-packing solver，靠 scoreboard、近期嘗試歷史、獨立零容忍 verifier 與逐目標最佳解保存，展示一台消費級電腦也能做出可驗證的程式演化；真正的瓶頸則是固定目標很快進入收益遞減。

方法架構

  • 問題：作者要測試 AlphaEvolve 類型的「LLM 提案、程式執行、客觀評估、保留改進」能否縮到單一模型、單機與低預算，任務是最大化單位正方形內不同半徑圓的半徑總和。
  • 迭代迴圈：prompt 放入完整 champion solver、各目標 scoreboard、最近十二個嘗試與結果，以及問題與介面說明。LLM 每輪輸出一份完整 replacement solver，不產 patch；候選並行跑所有目標，總分勝過 champion 才更新。
  • 逐目標保存：除了全局 champion，系統另保留每個圓數目標曾出現的最佳結果。因此，某個整體分數較差的 solver 若在單一目標創新紀錄，其 artifact 仍不會遺失。
  • 獨立驗證：verifier 與 solver 不共享程式碼，重新檢查所有圓都在邊界內、任兩圓不重疊、半徑總和正確，並用嚴格 feasibility shrink 排除浮點誤差。只有驗證後的結果能進 scoreboard。
  • 停滯偵測：滑動視窗同時檢查近期是否全遭拒絕或沒有 code、是否沒有新 champion，以及累積改善是否低於門檻。這讓「繼續呼叫 LLM」也成為需要用實測收益證明的決策。

作者報告的結果

系統在十二個目標中改善十個 Packomania 紀錄，改善幅度為 2.43%–5.39%，十項 prior total 由 51.814380 升至 54.406044；這些解由獨立 checker 驗證，並獲 Packomania 接受（作者自報）。完整運行共十五輪，LLM 成本為 27.72 美元，約在配有 Intel Core i7-13700KF 與 32 GB RAM 的消費級電腦上跑八小時（作者自報）。

收益高度集中在前段。iteration 0–5 花費 4.96 美元，總分由 59.39 升至 59.96；iteration 6–14 再花 22.76 美元，只升至 59.98，單位改善成本相差 130 倍（作者自報）。作者回測的停滯規則會在 iteration 9 停止，以 13.95 美元取代 27.72 美元，僅少 0.006 的總和，也就是 final value 的 0.01%（作者自報）。演化過程依序出現 basin hopping、hexagonal lattice initialization、island-model parallelism、KKT-Newton polish 與 defect migration 等完整演算法改寫，而非只調超參數。

局限

作者自陳，實驗只涵蓋一種 circle-packing 問題，尚未證明能處理評估昂貴或搜尋空間本質不同的任務；系統只保留一個 champion，缺少 population 帶來的多樣探索。方法也仰賴 LLM 產生可執行 Python 的能力，作者的 MIPLIB 實驗曾有 75% code generation failure rate（作者自報）。最後，固定目標上的收益快速停滯，實務上必須擴張目標或接受平台期。

對 ai_core 的價值／接點

Discovery Loop 是一個很小但邊界清楚的固化迴圈：生成器可以任意重寫 solver，驗證器卻保持獨立且擁有否決權；每次結果還要綁定具體目標與 artifact。對 ai_core 而言，這比「LLM 自我反省後修改」多了兩個可直接採用的控制點。第一，局部專長應逐目標保存，不要只讓單一 aggregate champion 抹掉 niche improvement。第二，繼續探索也要有成本憑證；當最近視窗的可驗證改善低於門檻，就停止昂貴生成，把資源轉向新目標。本文同時提醒，獨立 verifier 能證明解可行，卻不能單憑一個領域的成功證明搜尋框架已普遍泛化。
