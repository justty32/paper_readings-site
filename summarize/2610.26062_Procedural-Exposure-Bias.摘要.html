論文／訪談原始來源

重複看見流程，會不會被誤當成此刻該做的事？

一句話概括

作者在固定狀態與動作適用性下，操弄技能中動作關聯詞的重複暴露並量測動作偏好，辨識出程序暴露偏差 PEB；將相同文字轉成圖像可減弱此效應，但未證明資訊完全等量可及，也未證明整體 agent 的改善全由 PEB 降低造成。（§2、§5）

解決什麼問題

技能與整體任務相關，不代表技能裡每個動作都適合當前狀態。既有研究著重建庫與檢索；本文問技能交給模型後，反覆呈現的程序訊號是否被誤轉成動作證據，以及呈現模態會如何影響這段轉換。（§1、§6）

核心方法

作者自報從成功 ALFWorld 軌跡重建 165 個中間狀態，移除原技能提示，固定歷史、參考動作及候選集合，加入與任務相關但不在當前 admissible set 的干擾動作。以動作關聯物件名詞為 target keyword，在五個技能中控制出現 0、1、2、4、8 次；總字數固定，但不保證不同 tokenizer 的 token 數相同。暴露只計供應的技能，不計全歷史。（作者自報，§2.1、附錄 A.1.1–A.1.2）

以 teacher forcing 評固定候選的長度正規化 token log-probability，再在固定集合內 softmax 得偏好；這不是自由生成干擾動作的機率。圖1(b)的配對端點差另用未除長度的總 log-probability。替換 target keyword 會降低偏差，但一般替換控制只有 128 個合資格狀態，相對原始／target替換的 165 個不是完全配對比較。（作者自報，附錄 A.1.3–A.1.4）

Text 與 Visual 共用程序內容、暴露量與決策資訊；Visual 經原生視覺編碼器讀結構化技能卡。另以不加結構的等寬文字 Rasterized 圖隔離模態與排版。注意力加總提供重複訊號可能累積的解釋，不需單一出現位置權重增大；後續層讀出及 activation patching 再檢查其內部表現。（§3、附錄 A.2）

結果

Qwen3.5-9B 的干擾偏好隨文字暴露增加較明顯，轉圖後較弱；Qwen3.5-27B、Gemma-4-31B-it 有相同定性模式。作者自報 9B 的總 action log-score 對暴露量線性斜率，Text／Rasterized／Structural Visual 為 0.741／0.467／0.552；Gemma 為 2.657／1.283／1.361。平面文字圖已大幅減弱效應，額外結構未成為必要來源，也不代表 Visual 完全免疫。（作者自報，§2.2、附錄 A.5.1）

改問「最常出現的物件」，Text 與 Visual 的 target-word 機率均隨暴露上升，說明圖像中重複訊號仍可讀出；這量的是固定位置字詞序列概率，不是任務 exact-match accuracy，也不表示兩種呈現有相同可及性或完全沒有訊號退化。（§5.2、附錄 A.5.2）

另以 64 條成功軌跡的 185 個狀態，把干擾項改成「可執行但不同於參考」的任務相關競爭動作，以 greedy 自由生成量測選擇率。作者自報彙整斜率 Text 0.0091、Visual 0.0026，配對差 0.0065、bootstrap 95% CI [0.0011,0.0120]；這不是每個狀態都單調切換。強制先走兩個不同首步的 paired rollout 是另一實驗，不能直接估計暴露對完整 agent 成績的效果。（作者自報，附錄 A.5.3–A.5.4）

完整 agent 在 ALFWorld、ScienceWorld、WebShop 比較同一排名技能的 Text／Visual。作者自報三環境等權 macro success，四個 backbone 的 Text→Visual 分別為 Qwen3.5-9B 40.70→44.06%、27B 53.06→53.94%、Gemma 57.24→58.21%、Kimi-K2.5 56.34→58.64%。不是每環境都更好，例如 Qwen27B WebShop 成功率由 23.00 降為 21.50%；作者明說尚不能將整體優勢全歸於 PEB 減少。（作者自報，§4–5.1，表1）

內部分析及局限

作者明示的證據界線：各層隱藏表示經最後 norm/head 讀出，中後層文字暴露證據較明顯；這不是各層獨立生成，也不能由早層弱讀出推論沒有資訊。把高暴露 MLP 輸出移入零暴露 run 時，Qwen 的 score 變化方向與原效應相反，Gemma 則部分同方向恢復，顯示架構依賴；不能把 Visual 的減弱歸給單一 downstream 元件。（§5.2、附錄 A.5.5–A.5.6）

作者明示的評估界線：paired rollout 的步差只算雙分支均成功的配對，不反映失敗率差；其強制首步比較評估動作後果，不直接估暴露造成的完整性能變化。技能卡與 Text 同內容但走不同編碼／呈現路徑；原始 Text–Visual 比較本身未隔離兩者，需 Rasterized 控制。（附錄 A.2、A.5.4）

本檔補註，非作者自陳：控制探針支持這些模型、狀態與關鍵詞操作下的表示效應，不足以推出任意技能轉圖片都更安全／更有效率，也不是對所有模型的完整機制證明。本文未將視覺 token、延遲及運算成本作為主要比較，成功率優勢不直接等於成本效益優勢。

對讀者的價值・接點

對 agent 技能設計，本檔補註的接點是區分「訊號可讀到」「被當成動作證據」「實際自由選擇」「後續任務結果」。技能檢索正確仍需檢查狀態適用性，重複次數不應直接被當成此刻應執行的證據（本檔補註，非作者自陳；依據§1–2、附錄 A.5）。
