論文／訪談原始來源

EMMA：讓多agent系統的記憶更新有明確歸屬與範圍

核心問題與方法

EMMA將多agent的配置本身視為episodic memory：controller routing rules、繼承generalist的specialists，以及逐step指派的procedural skills。Training中controller、sub-agents、reflector都由同一backbone \(\theta\)實例化，weights始終固定；學的是外部文字配置，不是參數訓練。Reflector從失敗trajectory判斷哪個scope擁有修正，再提出一個局部edit，由programmatic guards約束可接受範圍；模型仍決定診斷與內容，guards不代替LLM推理。（§2–3）

與「讓meta-model一次改整個配置」相比，作者把更新分到適當層級，減少backbone偏好主導結構變動。這不等每個edit語意上必然正確：原文明說accepted edits即使chain最後仍失敗也保留，無效或有害entries可能殘留。（§3.2、§6）

三層記憶、逐步執行與overflow

Controller memory \(\mathcal C\)記decomposition、routing、skill選擇及verification；entry有topic／summary／domain tags／generality。Controller讀index自行選load，非similarity retrieval，可一條不載。Agent pool \(\mathcal A\)始於generalist，specialist的effective prompt是當前generalist prompt＋自己specialization，所以一般工作習慣只改generalist就能傳到所有繼承者。Skill pool \(\mathcal S\)是subproblem-class procedures，以one-line when-to-use索引；controller只見index，每step選skill，executor才收全文。（§3.1.1）

Controller規劃後一次dispatch一step，讀output後可修未完部分／終止；每sub-agent只收task、subtask、assigned skills及controller-curated prior-output摘要，不是全history。Context／round耗盡視作subtask太粗的證據：以partial trace拆成existing agents可做的smaller steps、splice回同位置，保留已完成工作；overflow亦留給reflector。這不是同時無限派agent，也不是預先固定整條workflow。（§2.2、§3.1.2、算法2）

Failure ownership不是全部寫成skill

Reflector依localize→classify→generalize→minimize，讀plan、每round code、gate digest、先前revision history、參與agents完整prompts、assigned skills及overflow；必要時inspect selected step full logs。泛化要求不寫此task的entities／values／answer，但這是LLM需要遵循的內容規則，不是由數學定理保證。（§3.2.1、附錄E）

Scope 修正的home與可用action
execution_slip 一次性失誤，只revise_plan／no_change，directive限本task
agent_behavior 一般工作習慣，refine_prompt；通用寫generalist、role-specific寫specialization
procedure 某class方法錯／缺，revise_skill／create_skill
missing_capability 現有pool做不到，優先create_skill，必要才create_agent

一般skill不夠、需要獨立working method/context，或反覆overflow，才有新增agent理由；不能用「找files」之類label-only角色迴避問題。附錄E另明示：若failing specialist繼承generalist，通用習慣可改generalist，即使generalist未直接參與；這是對繼承的特殊targeting規約，不能把participant-only概述擴成沒有例外。本文未因此自行審查外部implementation。（表1、附錄E Inheritance／Overflow）

Guards保更新形狀，不保每條知識正確

Programmatic checks依序核scope–action、strategy change、no leakage、prompt preservation及bounded growth。每失敗revision只准一entry／一level；prompt至少保60%原lines、≤6000chars；specialization≥150chars，agent pool≤10（含seed）、skills≤40且各≤3000chars。No-leak檢reference answer及15-word verbatim task spans，並禁artifact帶dataset/run paths；不等已證明所有語意改寫洩漏或錯誤教訓都被識別。（附錄B、表6–7、附錄E；最後語意界線為本檔補註，非作者自陳）

同memory level不可連續超過兩個failed cycles；同step連兩次overflow須改split strategy，prompt／skill小修不能替代structural response。拒絕理由回reflector，最多3feedback rounds仍不過則no_change；新／改agent或skill會明列rerun plan以確實exercise。Accepted是admissible且再跑過，不是只在score改善時commit；failure-chain最後一次失敗不再改，避免留下從未rerun的edit。（§3.2.2、算法1–3）

一pass training與frozen evaluation

各task在fresh environment跑attempt chain，最多5revisions＝6executions；success就停。Accepted edits不因rerun仍失敗rollback。每chain結束（pass或fail）另做chain-aware controller update，至多2entries，再snapshot；因此「每failed attempt一edit」不等每task只會增加一條記憶。固定order單pass後freeze，每benchmark×backbone一artifact，無checkpoint selection。（§3.3、算法1、表6）

Heldout inference仍可select memory、replan與overflow decomposition，但不呼叫reflector、不寫persistent memory。Controller load cap15entries／12000chars；plan最多15steps且final answer step仍執行，agent每step30Python rounds、re-plan3次。Gate分別KramaBench Opus4.5 judge、AppWorld unit tests、BBEH exact match；weights frozen不代表不用LLM calls，也不代表全部feedback都是相同形式的oracle。（附錄B）

資料、分母與baseline比較邊界

五backbones：Claude Opus5、Sonnet5、GLM-5、DeepSeekv3.2、Kimi-K2.5；每run所有roles同backbone。三benchmark都同disjoint split供各method：KramaBench104中28train／76eval，依六domain及difficulty定序分配、metric為domain macro accuracy；AppWorld90train／168normal／417challenge，TGC是task-goal、SGC要同scenario所有variants皆pass，challenge要用training未見app；BBEH-mini23categories×20，seed42每類4train／16eval，共92／368，equal categories使macro=micro。（§5.1、附錄C）

四主baseline也從training學persistent artifacts再freeze：ACE incremental playbook且best-validation選；GEPA反射prompt、training-split validation Pareto selection；EvoMAS whole configurations、三steps、dataset-evaluator reward減token/latency cost；ADAS code search、budget matched to GEPA、best archive，AppWorld DS／Kimi沒發現比hand-written seed更佳的program時報seed。ACE AppWorld只見unit-test pass/fail與trace，不拿reference答案。這些程序／selection／objectives有差異，不是等token、等wall-time或只差一個guard的對照。（附錄D；最後公平性界線為本檔補註，非作者自陳）

附錄D.1「not described」是本文對baseline論文的規約摘要，本檔沒有再讀外部code核其所有現行features；不能轉述成所有baseline永遠沒有任何安全或檢查。EMMA比較的是failure-typed ownership、incremental preservation與bounded system envelope，不是宣稱別法毫無約束：EvoMAS一component-type mutation、ACE incremental dedup、GEPA round-robin各有不同限制。（附錄D.1、表10）

Learned artifacts與guard的證據界線

Sonnet5／BBEH zebra chain先從procedure失敗建CSP skill，再因overflow建繼承generalist的csp_solver，attempt5通過，endtask寫single-solving-step routing rule；接續三training zebra首attempt通過。Heldout52clues案例load8/101controller entries，dispatch一個solving step，specialist9rounds；原log報blocking re-solve核unique、82.3s、correct1。這是單例reuse證據，不等全測試都檢證unique或guard保證每lesson正確。（附錄F、表11）

Frozen artifact可見routing與skill說one continuous pass，specialist自己分checkpointed phases／round-budget handling；這些是不同controller-step與sub-agent內部粒度，本檔不拿字面「single」推成一次LLM call完成。文獻中的prompt、Python/CSP工具建議、檔案操作與答案都未在本工作區執行，也不是本工作區新規則。（附錄E–F；粒度界線為本檔補註，非作者自陳）

作者限制：backbone差距仍在，強reflector搭弱executors是未來方向而非本文已驗結果；accepted edits即使chain未解仍保留，可能無效／有害，mini-batch cross-verification或多epochs也只是future work。Guard的backbone-independent指acceptance envelope獨立，不代表diagnosis／generalization品質獨立於backbone，亦不保語意正確或無interference。（§6、§3.2；最後保證界線為本檔補註，非作者自陳）
