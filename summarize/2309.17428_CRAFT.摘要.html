論文／訪談原始來源

《CRAFT：透過建立與檢索專用工具集來客製化大型語言模型》重點摘要

一句話概括

CRAFT：離線用貴模型（GPT-4）批量「造」出經抽象化、驗證、去重的可重用程式工具庫，線上用便宜模型（GPT-3.5）以多視角檢索「取」出相關工具來填碼求解——一套免微調、隨插即用的「工具創建＋工具檢索」框架，把領域資料結晶成專用工具集，讓現成 LLM 泛化到未見的領域與模態（視覺問答、表格處理、數學推理）。

解決什麼問題

既有的 LLM 工具增強多受限於通用 API，缺乏為特定任務量身打造的彈性；通用工具集裡往往沒有專門領域所需的 API。而前人的工具創建法要嘛只造單一工具（LATM，用 3 個訓練樣本造 1 個工具）、要嘛每題現造且不可重用（CREATOR，推論時逐題造工具），工具庫小、品質與可重用性都不足。同時，從大工具庫精準檢索相關工具本身也是難題——僅靠「問題 vs API 名稱」的簡單相似度不夠。

核心方法

  • 工具創建（離線，四步）：
    1. Generation（生成）：以 min-max 相似度採樣（SimCSE）迭代挑出多樣問題，令 GPT-4 產生可執行 Python 解，只留通過執行且答對的。
    2. Abstraction（抽象化）：令 GPT-4 把具體變數名換成通用名（cat→animal、df["date"]→df[column_name]）、把文字輸入外提為函數參數，並取通用函數名＋撰寫 docstring → 提升可重用性。
    3. Validation（驗證）：檢查抽象工具能否解回原題，不能者丟棄 → 保正確性。
    4. Deduplication（去重）：依函數名＋參數數分組，令 GPT-4 選最泛用者 → 降冗餘。
  • 工具檢索（線上）：令 LLM 先「描述自己需要什麼」，由目標問題 q_t 生出所需函數名 f_t 與 docstring d_t；對工具三元組 (q_i, f_i, d_i) 做多視角匹配（分別以 q/f/d 檢索 top-k=10/5/10），彙整後按出現頻率多數決取 3 個、濾掉只出現一次者；若全為單次則退回直接生碼。檢索到的工具程式碼加進 prompt 供 LLM 呼叫。
  • 全程免微調、隨插即用；工具集建置總成本約 2,500 美元。

結果

  • Backbone 為 GPT-3.5-Turbo-0613。相對最佳基線，視覺語言任務平均 F1 相對提升 43.16%。
  • 對照 vanilla ViperGPT，GQA/OK-VQA/A-OKVQA 的 soft accuracy 絕對提升 +10.4 / +18.0 / +15.2（CRAFT 45.4 / 33.4 / 30.8）；TabMWP 88.4、MATH(algebra) 68.1，多數任務勝過 LATM、CREATOR、SimCSE、BM25 等基線。
  • 消融：去抽象化明顯掉分（GQA 45.4→37.1）；檢索三元組缺一即傷，其中函數名最關鍵（去掉掉 >6.6 SAcc）。
  • 可擴展：工具數 0→261→337→525，soft accuracy 持續上升（0→261 增益最大）。
  • 工具品質（表 4）：循環複雜度 VQA 2.64 / 表格 2.07 / 數學 1.34（均遠低於 10，結構良好可靠）；525/181/282 個工具分屬 195/23/234 類（MATH 最多樣、TabMWP 最同質）。

局限

  • 目前建立在程式碼生成上，只適用「能寫程式求解」的任務（作者計畫以偽代碼擴展範疇）。
  • 效果高度依賴 backbone 的工具操作能力；部分開源模型在此設定近乎隨機。

對讀者的價值

  • 正是 ai_core §2「資產工廠 vs 資產消費者」分工的教科書級實例：離線用貴稀有智能（GPT-4）批量鑄造工具＝資產工廠；線上用便宜高頻智能（GPT-3.5）檢索復用＝資產消費者。兩端明確解耦，且工具是確定性可執行程式碼節點，LLM 只負責編排與填碼——契合把系統當符號神經網路計算圖（§1，多數確定性節點＋少量 LLM）的取向。
  • 對 §3.6 固化引擎/工具庫沉澱最具啟發：CRAFT 的「生成→抽象化→驗證→去重」流水線，正是把「LLM 反覆處理的案例結晶成確定性程式碼／抽象庫」的一條可操作路徑——抽象化＝把個案泛化成可重用資產、驗證＝憑「解回原題」准入（呼應 §3.4 拒絕為預設＋憑證准入）、去重＝控制工具庫熵。這給 ai_core 最硬未決的固化問題一個現成骨架。
  • 與已入庫工具創建線（LATM/CREATOR/TroVE）對照：LATM＝每任務 1 工具、CREATOR＝每題現造不可重用、CRAFT＝>100 且可檢索＋驗證＋去重（見翻譯檔表 1）；CRAFT 補上的正是資產工廠最缺的品質控管（驗證＋去重）與檢索復用機制。歸 I 類。
