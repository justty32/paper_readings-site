論文／訪談原始來源

《xList-Hate：以檢查清單為基礎的可解釋且可泛化仇恨言論偵測框架》重點摘要

一句話概括

xList-Hate：不用讓 LLM 直接判斷仇恨/非仇恨，而是把仇恨言論拆成10 個概念層二元檢查問題（基於法律、平台政策與學術共識），由 LLM 各自獨立回答，產生的 10-bit 診斷向量再交給一個輕量決策樹做最終分類——LLM 只負責語意判斷、分類邏輯透明可審計；跨資料集泛化穩定、對標註雜訊具抗性，且隨模型增大與端到端監督微調的差距縮小。

解決什麼問題

仇恨言論沒有單一定義——法律框架、平台政策、學術分類各不相同。既有監督微調法雖域內強，但跨資料集崩潰（過擬合特定標註慣例與詞彙捷徑）；零樣本 LLM 直接分類不一致且不透明；事後可解釋工具（SHAP/LIME）只給 token 級相關性而非概念級推理。核心缺口：缺少一個模組化、概念級、可追溯決策路徑的框架，既能適應不同標註標準，又能抵抗標註雜訊。

核心方法

  • 十因子檢查清單（q1-q10）：從法律（聯合國、ECRI）、平台政策（Meta、YouTube、X、Reddit、TikTok）與學術框架交叉歸納出十個最小正交概念因子：(1) 受保護群體鎖定、(2) 貶損/敵意內容、(3) 明確蔑稱、(4) 去人化/妖魔化、(5) 歸咎/代罪羔羊、(6) 鼓吹排斥/歧視、(7) 威脅/傷害願望、(8) 煽動/支持暴力、(9) 說話者背書 vs 引用/諷刺、(10) 目標群體可能感知的傷害。
  • 獨立 LLM 回答：每個問題為一次獨立推論（無跨題污染、可平行化），prompt 含問題本身＋引導理由＋少樣本範例＋二元輸出格式（<a>Yes|No</a>）。最終標籤從未暴露給 LLM，防止捷徑推理。
  • log-probability 強制解析：小模型可能拒答或格式不符→用 token 級 log-probability 在 <a>Yes vs <a>No 間強制二選一（避免系統偏差）。
  • 決策樹聚合：10 位元診斷向量交 scikit-learn DecisionTree 學習→每條預測路徑都是 (q3=Yes ∧ q9=Yes ∧ q4=Yes…) 的顯式邏輯合取，完全可解釋。刻意不用硬編碼聚合規則——因為不同資料集的標註標準各異，讓樹自適應各資料集的隱含標註邏輯。
  • 成本特性：每樣本 10 次 LLM 呼叫（可平行），但一旦產出診斷向量，後續加新資料只需追加推論＋重訓輕量樹（無需重訓完整 LLM）；對照端到端微調，大模型（27B）checklist 約 30h vs 微調約 35h——推論一次後維護成本極低。

結果

  • checklist 全面勝零樣本直接分類（Table 5）：8 個 LLM × 5 資料集，3B 以上模型所有資料集皆正增益（最高 +0.197 AUC HateXplain/gemma3-27b vs 零樣本）；小模型（1B）變異性較大。
  • 域內 vs 跨域：端到端微調域內 AUC 最高（差距隨模型增大而縮小），但 checklist 的 Relative AUC（域外/域內）平均 >100%（多數模型），表示跨域時效能折損比端到端微調小；部分中等/大模型在 HateXplain 與 Stormfront 為訓練集時，checklist 的 OOD AUC 超越微調。
  • 決策樹特徵重要性（Figure 2）：q4（去人化）、q7（威脅/傷害願望）、q3（明確蔑稱）、q9（說話者背書）、q8（煽動暴力）為跨資料集/跨模型規模/跨模型家族一致最強判別因子；q1（受保護鎖定）和 q2（貶損語調）被「語意前提冗餘」解釋——高嚴重性因子（如去人化）已隱含了鎖定與敵意，故分裂時邊際貢獻低。
  • 模型規模效應：更大模型對 q3（蔑稱）賦予更高重要性——更大的詞彙覆蓋使其更可靠辨識新興/小眾蔑稱。
  • 標註雜訊抗性（Table 9, §6.2）：五個分歧案例展示 checklist 在面對明顯誤標註（如種族蔑稱＋貶損刻板卻標為非仇恨）時不會跟隨雜訊，而是以相同診斷路徑分類；對引用/歌詞（無背書→判非仇恨）與人身攻擊（無群體鎖定→判非仇恨）給出與仇恨言論定義一致的決策，凸顯既有資料集常混淆仇恨言論與一般辱罵。

局限

  • 推論成本高：每樣本 10 次 LLM 呼叫（Table 4，gemma3-27b 約 2.7s/sample）——雖可平行仍比單次推論貴；但維護成本（加新資料只需重訓輕量樹）部分抵消。
  • 部分設定 OOD 絕對效能略輸微調：尤其在 MHS 為訓練集時，微調的 OOD AUC 整體仍略高（但差距隨模型增大收窄）。
  • 僅限仇恨言論：框架適用於任何可拆成語意因子的分類任務，但論文只在仇恨言論評估。
  • 因子選擇仍帶研究者先驗：10 個因子雖基於文獻歸納，但不同應用場域可能需要調整因子組合。

對讀者的價值

  • ai_core §3.6「固化引擎」最直接對應（方向二★）：xList-Hate 示範了「LLM 負責語意判斷→確定性模組負責最終決策」的典範退化解——把 monolithic LLM 分類節點退化成一組 LLM 回答的 checklists + 一棵決策樹。一旦對某個領域的因子穩定，決策樹可以直接取代 LLM（不需再呼叫），且每條推理路徑都是顯式邏輯合取。這正是 ai_core 固化引擎的核心命題：「把 LLM 反覆做的事降格為確定性程式碼/規則」。此處已做到：10 次 LLM→0 次 LLM（用已產生的樹推理）。
  • §3.2 前濾網模式（對照 Compiled AI 2604.05150 的編譯路線）：xList-Hate 與 Compiled AI 形成兩條互補路徑——Compiled AI 把 workflow 整段編譯成 Python；xList-Hate 是把 LLM 呼叫結構化為 checklist→tree，保留 LLM 的語意彈性但把分類邏輯確定化。兩者的交集：「前端 LLM 語意擷取 + 後端確定性決策」分離架構是 §3.6 固化的通用模板。
  • §3.4 抗標註雜訊＝治理面向：決策樹從不追隨單一誤標註調整——因子空間受概念問題語意約束、以非監督方式回答——這使系統不會過擬合到孤立標註錯誤。對應 ai_core 治理精神：「拒絕為預設」——寧可與雜訊標註不一致，也要守住概念一致性。
  • 對照方向四「固化價值＝省搜尋」：xList-Hate 的 10 因子×1024 可能組態揭示了另一種度量——診斷空間的可枚舉性就是固化程度的量化：1024 種組合均可被決策樹窮盡，無需 LLM 的機率判斷；這與 SemanticALLI（2601.16286）的「子圖 memoization」、Graph-Memoized Reasoning（2511.15715）的「過去軌跡覆蓋→安全取代」構成「何時 LLM 節點確定性化」的三條判斷準則。
