一句話概括

GuideX：不依賴任何預先給定的標註 schema，而是讓 LLM 對每份文件動態推斷出專屬的標註 schema 與指引（guideline）——並以 Python dataclass 的程式碼形式表達——再據此生成、並以「執行程式碼＋一致性檢查過濾」的方式清洗出合成標註資料；用這批資料微調 Llama 3.1 後，在七個零樣本 NER 基準上刷新 SOTA（無金標資料時平均 F1 較基線 +7.06、疊加金標資料後再取得新 SOTA 平均 64.2，較 GoLLIE 高 6.2 分）。

解決什麼問題

傳統 IE（資訊抽取）系統高度領域相依：換一個新領域就要重新請專家設計 schema、找標註員標資料、訓練模型，成本高昂。近年 LLM 雖能做零樣本 IE、也能自動化部分 schema 定義，但一旦部署到「標籤語意與訓練分布不同」的未見領域，效能仍明顯下滑。作者要解決的正是這個「schema 定義＋標註資料」雙重瓶頸——如何不靠人力，自動為任意新領域生出對齊的 schema、指引與訓練資料。

核心方法

GuideX 是一條四階段、逐步把原始文字收斂成結構化標註的管線（每一步都有對應的 prompt 模板）：

  1. 文件摘要（Document summarization）：LLM 讀原文，抓出關鍵概念，寫成條列式摘要，自主判斷哪些實體/事件值得注意，不受任何預定 schema 限制。
  2. 結構化表示（Structured representation）：結合摘要與原文，把資訊整理成 JSON，並限制抽取片段盡量簡短但保留完整語意。
  3. 指引生成（Guideline generation）：這是關鍵一步——根據上一步的 JSON、摘要與原文，動態生成該文件的標註 schema。每個實體類別被寫成一個 Python dataclass，類別的 docstring 內嵌對該類別的詳盡文字說明，各屬性（attribute）則各自附註解說明其意義與預期格式——用程式碼結構取代人工撰寫的靜態標註手冊，讓每份文件都拿到量身打造、與其內容精確對齊的 schema。
  4. 實例抽取（Instance Extraction）：模型再輸出一個 Python list，每個元素是上一步某個 dataclass 的一個實例，值取自原文中簡短、精確的詞或短語，不附加解釋文字。
  5. 一致性過濾：由於 schema 與標註實例都是「可執行的 Python 程式碼」，GuideX 可以實際執行每筆資料條目，自動偵測未定義的實體型別、屬性不對齊等邏輯錯誤，並用一支自動化過濾腳本丟棄不合規的樣本，只留下 schema-compliant 的標註——以此壓低幻覺與雜訊。

資料集以 FineWeb-edu（教育內容子集）隨機取樣約 1 萬份文件（194～22.6k 字）建構，合成資料生成用 Llama 3.1-70B Instruct，下游微調用 Llama 3.1-8B base（非 instruct，避免輸入格式落差）＋ QLoRA。最終資料集含 28,677 個唯一標籤，平均每文件 5.34 個相異標籤、11.39 筆標註；與 35 個既有 IE 資料集的標籤空間比對，訓練集標籤有 42.4%、測試集標籤有 41.7% 已存在於 GuideX 中。

結果

  • 無金標資料：Llama 3.1 基線七個零樣本 NER 基準平均 F1 30.08；只用 GuideX 合成資料微調（GuideX_FT）平均 F1 提升到 37.14（+7.06）。
  • 疊加金標資料：純金標微調（Gold_FT）平均 62.77；先 GuideX_FT 再 Gold_FT 平均達到 64.15（較基線 +34、較 Gold_FT 單獨再 +1.4），且在七個資料集中有五個因疊加 GuideX 而進步。
  • 對比 SOTA（表 3，同樣 GuideX_FT+Gold_FT 設定）：平均 F1 64.2，超越 GoLLIE（58.0，+6.2）、KnowCoder（60.1，+4.1）；在 Movie（65.3）、Restaurant（55.5）取得最佳，Politics 較 GoLLIE +12.4；僅 Music 略遜 GLiNER-L（67.9 對 69.6）。
  • 細粒度分析：GuideX 顯著緩解零樣本 IE 常見的「過度泛化成通用標籤」問題——如 Scientist vs. Person（F1 38.43→51.21）、Politician vs. Person（35.12→44.37）、PoliticalParty vs. Organization（58.55→65.30）；但對本就通用、定義模糊的「兜底類別」（Other／Miscellaneous）幫助有限甚至略降（如 Music 的 Other 由 15.99→13.02）。

局限

  • 合成資料是文件級文本，但評測基準幾乎都是句子級 IE 任務，訓練與評測粒度存在落差，論文明言尚未評估文件級任務上的效果。
  • **兜底類別（Other／Miscellaneous）**因缺乏明確定義邊界、語意混雜，GuideX 生成的指引對這類標籤幫助有限，作者建議未來對這類殘餘 span 做嵌入聚類＋LLM 再誘導出更細粒度 schema（第二輪 GuideX 迭代）。
  • 合成資料生成模型（Llama 3.1-70B Instruct）雖選用開源模型以利可重現性，論文提及專有模型在部分情形下表現略優，代表結果可能仍受限於生成模型本身能力。
