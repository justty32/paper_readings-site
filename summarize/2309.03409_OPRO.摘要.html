論文／訪談原始來源

《大型語言模型作為優化器（Large Language Models as Optimizers，OPRO）》重點摘要

一句話概括

OPRO（Optimization by PROmpting）：把優化任務用自然語言寫進 meta-prompt，讓 LLM 讀「歷史解＋分數」的整條軌跡、迭代提出更好的解——不需梯度、不需程式化求解器，只靠提示就能做黑箱優化；在 prompt 優化這個主應用上，它把「找 prompt」變成一個 LLM 自己迭代的優化問題，並找出名場面 「Take a deep breath and work on this problem step-by-step.」。

解決什麼問題

許多優化問題沒有梯度（decision space 離散、目標函數只能查詢黑箱），傳統無導數優化須為每個任務客製演算法。特別是 prompt 優化：LLM 對 prompt 格式極敏感、語意相近的 prompt 準確率可差 20%+，最佳格式又因模型/任務而異，而 prompt 空間又大又離散、常僅有 API 存取——軟提示微調、梯度搜尋、RL 等在此都失效。作者主張：既然 LLM 懂自然語言，就讓它直接扮演優化器。

核心方法

  • meta-prompt（元提示）＝優化器的呼叫，含兩塊：(1) 優化軌跡——過往的解及其分數，依分數升序排列；(2) 問題描述（prompt 優化時還含幾個任務範例 exemplar 與插入位置標記 <INS>），加上**元指令（meta-instructions）**說明目標與輸出格式。
  • 迭代循環：每步 LLM 讀 meta-prompt 生成新解 → 評估分數 → 加回軌跡 → 下一步；LLM 無需被告知「如何更新解」，它從高分解的相似性自行外推。
  • 穩定性設計：每步生成 8 個解（類比 mini-batch 降方差）；用溫度調節探索/利用（1.0 最佳）。
  • prompt 優化專用：分 optimizer LLM（優化器）與 scorer LLM（被套用 prompt、算訓練準確率的評分模型），兩者可同可異；指令插入 Q_begin/Q_end/A_begin 三種位置；分數即訓練準確率。
  • 先在線性回歸（連續）與 TSP（離散）做動機示例，證明 LLM 能「比較數字、提出下降方向」的黑箱優化。

結果（具體數字）

  • GSM8K：優化後 prompt 勝人工設計達 8%——PaLM 2-L-IT 優化器＋PaLM 2-L scorer 找到「Take a deep breath and work on this problem step-by-step.」達 80.2（vs「Let's think step by step.」71.8、空字串 34.0）。
  • BBH（23 個困難任務）：勝人工 prompt 有時超過 50%；勝「Let's think step by step.」超過 5% 的任務達 19/23（PaLM 2-L scorer）。
  • 遷移性：GSM8K 找的指令遷移到 MultiArith（95.3）、AQuA（54.3）仍勝基準。
  • 消融：升序排列、顯示整數分數、3 個範例、每步 8 條、溫度 1.0 為最佳組合；一次生成 50 條（不迭代）明顯較差，證明善用軌跡才是關鍵。
  • 數學優化：小規模 TSP 上 gpt-4 與手工啟發式相當；但規模一大（n=50）效能急劇退化，非為打敗專用求解器而設計。

局限

  • 不擴展到大規模：context 長度塞不下大問題，崎嶇地形使 LLM 提不出正確下降方向；TSP 規模一大即被 Farthest Insertion 超越。
  • prompt 優化仍需訓練集算準確率（至少數十樣本），且無法有效利用錯誤案例（把 error case 放進 meta-prompt 效果與隨機取樣相近）。
  • 對初始化敏感、探索/利用權衡仍是開放問題；存在過擬合（訓練常比測試高 5%–20%）。

對讀者的價值

  • ai_core §1「計算圖節點的無梯度優化」的直接工具：ai_core 把系統看成符號神經網路計算圖（多數確定性節點＋少數 LLM 節點）。OPRO 正是當某節點的參數（prompt/指令）沒有梯度時，如何靠「歷史解＋分數軌跡」讓 LLM 迭代逼近更好參數的可操作範式——把「調 prompt」從手工黑魔法變成有目標函數、有收斂曲線的優化流程。
  • 「prompt＝可優化物」的奠基：本文是把 prompt 明確當成優化變數、以任務準確率為目標函數的代表作，是 ai_core 主題 10「自動 prompt 工程」的源頭之一。與 2211.01910 APE（生成語意變體）、APO（自然語言回饋編輯）、TextGrad（文字梯度反傳）對照：OPRO 的差異化在不編輯單一 prompt、不要求保語意，而是餵整條「解-分數」軌跡讓 LLM 自行發現高分模式——對想在 ai_core 裡實作「節點參數自動調優器」的人，這是最小可行且黑箱友善的設計。
  • 對「固化引擎」（§3.6）的啟示與警訊：OPRO 展示 LLM 能把一個模糊任務結晶成一句高效指令（如「深呼吸」名句），呼應「把 LLM 反覆處理的案例固化成可複用資產」；但其不擴展、需標註訓練集、對初始化敏感、無法用錯誤案例等局限，也提醒此類自動優化只適合小規模、有明確評分函數的節點——與 ai_core「成本梯度／逐步剃除 LLM 依賴」的務實取向一致。
  • 定位：方法論文＋跨領域實證，Google DeepMind 出品、ICLR 2024、開源。適合做 自動 prompt 工程、無梯度/黑箱優化、LLM-as-optimizer、agent 自我調優 的人。
