論文／訪談原始來源

KAPPA：以 Lean 與多個代理檢查統計論文證明

一句話概括

KAPPA 協調語言模型代理把統計論文的各項陳述及作者原有證明路線轉成 Lean 4，並用可重跑的機械稽核支持判定。Lean kernel 驗證的是形式化後的陳述，它是否忠實表達原文仍依賴審查；引用或未證事實則明列為條件，不能自動視為已證。（§1、§9）

工作流程與四種判定

KAPPA 對 LaTeX 論文的編號定理、命題、引理與推論逐項作業。撰寫與審查由不同代理處理；每項形式化陳述先與原文比較、確認後記錄指紋，再沿原論文步驟證明。若某步不可成立，系統定位該步並由第二位代理確認，盡可能附 Lean 可重編譯的反例；它不以找出完全不同的證明替代作者原路線。（§5.1–5.3）

判定 讀者可得的結論
無條件驗證 審查後的 Lean 陳述按論文路線完成證明；建置與公理／依賴檢查通過，無外部條件或可達的 sorry
有條件驗證 陳述在明列的引用結果或其他未證輸入等假設下被證明；讀者仍須檢查那些條件
記錄問題 問題經獨立確認，分類並定位；可能是結論本身錯誤，也可能只是論證或假設有缺口
未完成 尚無結論，例如所固定的 Mathlib 缺少必要介面；不將它直接計為論文錯誤

此表依作者規則概述；輸入被寫成具名 Lean 假設，而非默默當作公理。論文陳述是否與 Lean 陳述等價、問題分類是否恰當，仍須人對照原文與紀錄。（§3，表 2–3）

案例與直接使用模型的對照

作者編寫四篇附答案的示例論文，另挑選三篇已有公開更正的統計論文，事先建立答案與可接受分類，再讓每個 run 只讀更正前論文、禁止網路並隔離答案及更正資料。作者掃描 443 份逐字紀錄與 11,341 次工具呼叫，未發現對這些隔離資料或網路工具的存取；有 Lean 檔的證據可在固定版本離線重新建置，另有兩項問題依審閱論證而無檔案可重建。（§6.1）

作者報告三篇均找到公開更正指出的問題：案例 A 是原命題不成立，案例 B 與 C 是可能仍真之結論的證明缺口；額外發現由作者人工核查。選文時已知更正，並挑 Mathlib 大致可表達、受影響結果較少的論文；案例 C 只檢查圍繞更正的局部結果，選取時已參考更正，證據較弱。前兩篇更正早於所用模型訓練資料截止日，不能排除模型曾看過相關內容。（§6.3）

作者另以同一模型直接在 Claude Code 中使用 Lean、或以無工具聊天方式檢查三篇論文，按預先訂定規則比較 23 項結果；分類由 Claude 代理依規則評分並經作者檢查。下表為作者自報（kit／直接代理／直接聊天）；「忠實 Lean 證據」的計數是無條件、可編譯、無 sorry 且忠實陳述原文，不包含 KAPPA 的有條件判定。（§7.1，表 12）

這些是同一小型案例集合的描述性結果。直接代理有時也證出 KAPPA 列為條件的引用輸入；KAPPA 為遵循論文自身證明路線而保留它們，不代表直接代理所有方面較差。（§7.1）

報告核查、修訂與成本

作者報告每份交付前草稿都經獨立事實核查發現問題，類型包括紀錄不支持的修正建議、證據歸屬與行號錯誤。例如案例 B 首份報告共發現 23 項問題；此數字描述作者分類的報告草稿問題，並非 Lean kernel 自行偵測所有語意錯誤。（§7.3，表 14）

修訂流程比對結果及依賴，只重做需要處理的項目並透過新終審關閉舊問題。三個真實論文修訂花費 54–88 分鐘、15–31 美元，為原次檢查費用的 23%–86%；變動範圍不同，不能把這些數字當固定節省率。（§7.4）

較早設計與 1.3 版各跑兩次三結果示例，按所用價格表的平均費用下降 77%；模型分工與流程也同時改變，示例難度亦不足以代表完整研究論文。後續版本和新模型的比較又涉及模型變更，不能將整個費用差歸因於版本。離線重播已封存 Lean 證據在作者機器需 2–13 分鐘，但首次需要約 5 GB 的編譯 Mathlib 下載。（§7.2，表 13、§8）

限制與解讀

  • 全部案例共七篇、42 項結果，每篇檢查一次，作者明說不足以估計錯誤率。案例與更正的選擇、模型潛在訓練資料及正式函式庫覆蓋都影響結果。（§6.3、§9）
  • 封存檔可重編譯證據並重算表格，但代理新 run 的文字、時間及費用會變動；作者保留完整逐字紀錄，公開材料主要包含原始產物與 session 摘要。權限規則與 hook 用來防止代理失誤，作者明示不是安全邊界。（§8–9）
  • 本檔補註，非作者自陳：形式證明、陳述翻譯審查、引用假設的有效性及可重跑流程是不同的可信層；任何一層通過都不能單獨取代其他層的專家核對。
