論文／訪談原始來源

《從 LLM 蒸餾答案集程式設計規則用於神經符號視覺問答》重點摘要

一句話概括

LLM 蒸餾 ASP 規則：在不做微調的前提下，以少量 VQA 範例為指引、只用 prompting 讓 LLM 延伸既有的 ASP（Answer-Set Programming）推理理論以涵蓋新的問題類型，產出規則經由 ASP 求解器驗證語法／語意正確性與迴歸一致後整合，從而讓神經網路（LLM）的推理軌跡被蒸餾成確定性符號規則，後續由符號求解器取代 LLM 呼叫。三資料集（GQA/CLEVR/CLEGRV）×五模型（GPT-4o/DeepSeek/Mistral-Large/LLaMA3-70b/Gemini-3 Pro）驗證。

解決什麼問題

模組化神經符號 VQA 系統的核心優勢是推理模組可解釋、透明、可擴展，但當問題需求變更時——例如需要回答新類型的問題——開發者必須手動撰寫或修改 ASP 規則來擴充推理理論，這對開發者是重大負擔。既有規則學習方法（ILP 等）需要大量訓練資料或明確的模式宣告（mode declarations），而 LLM 的 prompt-only 蒸餾路線可繞過這些前提。核心挑戰：能否用極少量範例引導 LLM 產生正確、非冗餘的 ASP 規則，並由 ASP 求解器自動驗證正確性。

核心方法

  • 問題設定：從一個「完美」的 ASP 理論 T 開始（人工撰寫、永遠能算出正確答案），刻意刪除涉及某個謂詞 P 的所有規則，模擬理論不完整的情境。蒸餾任務就是重建這些缺失規則。
  • 蒸餾演算法（Alg. 1）：對新範例逐一迭代——若既有理論 T 能正確回答則跳過；否則呼叫 LLM 產生候選規則（multi-prompting + CoT simple + CoT complex 三路並行），逐一檢查：(i) 語法檢查（ASP 求解器回報語法錯誤 → LLM syntactic mending），(ii) 語意檢查（求解器輸出不等於預期答案 → LLM semantic mending），(iii) 迴歸測試（新規則加入後過往所有範例是否仍正確）。全部通過才接受此延伸。
  • Prompting 策略：(1) preprompt：設定 VQA 語境＋解釋 ASP 語法＋展示場景/問題/答案的符號表示＋給出初始理論；(2) multi-prompting：一次要求 N=5 個替代解；(3) 兩種 CoT：簡單版（逐步 if-then → ASP 規則）與複雜版（結構化四步驟）；(4) mending：語法/語意修補 prompt。
  • 組成新謂詞（§4.6）：不只重建既有謂詞，更測試 LLM 能否用既有基礎謂詞組合成全新謂詞（如 in_between, connected, isolated, count_class），包含遞迴與聚合規則。
  • 冗餘修剪（§5）：以 prune sample 執行 greedy backward elimination——若移除某規則後準確度不變則標記為冗餘。

結果

資料集 GPT-4o DeepSeek Mistral-L LLaMA3 Gemini-3
GQA（平均%） ~98.8 ~98.8 ~98.9 ~90.3 ~99.9
CLEVR（平均%） ~99.4 ~98.0 ~98.7 ~94.1 ~100.0
CLEGRV（平均%） ~85.6 ~87.0 ~84.3 ~85.3 ~97.5
  • CLEGRV 最難：涉及遞迴（cycle, shortest path）與聚合，多模型表現顯著下降。
  • 範例使用極少：每蒸餾嘗試實際僅用 1–4 個範例即收斂（上限設 N=10），Gemini-3 於 CLEGRV 平均只需 1.73 範例。
  • 消融實驗（§4.5）：對強模型（GPT-4o/DeepSeek），mending/CoT/multi-prompting 全開有顯著增益（+10%）；對弱模型（LLaMA3），關閉某些策略反而更好——策略負擔超過其推理能力。
  • 三種效能原型：(i) 過載型（Mistral/LLaMA3）：複雜 prompt 妨礙；(ii) 平衡型（GPT-4o/DeepSeek）：策略增益明顯；(iii) 飽和型（Gemini-3）：自身推理能力已夠強，策略相對不重要。
  • 冗餘修剪：GPT-4o 產出規則套數最多（CLEVR unique 平均 8.8 條被修剪），Gemini-3 產出最精簡、幾乎無冗餘。
  • 組成能力（§4.6）：GPT-4o/DeepSeek/Gemini-3 可成功從既有謂詞組成含遞迴/聚合的新謂詞，LLaMA3 最不可靠。

局限

  • 假設既有理論 T 是正確的（不處理既有理論有 bug 的情境）。
  • 假設場景與問題已正確解析為 ASP 事實（知覺模組的錯誤不在範圍內）。
  • 規則正確性僅經實證驗證（迴歸測試+求解器），非形式證明。
  • Prompt 敏感性：雖然本實驗的模板跨資料集表現穩定，實際部署仍需調整。
  • 不處理既有規則的除錯/修復（只處理新增/重建）。

對讀者的價值

  • LLM 推理軌跡→確定性符號求解器的閉環（§3.6 固化引擎的「神經→符號→無 LLM」路徑）：LLM 只在蒸餾階段介入（產生新規則），驗證之後由 ASP 求解器完全取代——這是方向二（LLM→確定性）中「以符號形式蒸餾、以符號求解器執行」的具體實現，對照 Compiled AI（2604.05150）的 Python 編譯路線與 SemanticALLI（2601.16286）的語意快取路線。
  • 少量範例即收斂的性質表示 LLM 在此扮演「將既有知識轉化為形式規則」的 translator，而非 data-driven learner——這與 ILP 有根本差異：不需要 mode declarations、不需要大量訓練資料。
  • ASP 求解器作為驗證閘門（§3.4 憑證准入的實例）：語法檢查+語意檢查+迴歸測試構成三道關卡，產出的規則保證在已有範例上一致正確——在符號領域是比「信心分數」更強的保證形式。
  • 與 2604.05150 Compiled AI 對照（LLM→Python vs LLM→ASP，兩條確定性編譯路線的不同權衡）；與 2601.16286 SemanticALLI 對照（cache 命中 vs 規則生成，兩條「省 LLM」路徑）；與 2604.23853 ClawTrace 並讀（成本感知追蹤蒸餾；本論文 token 消耗分析對應表 5）。
