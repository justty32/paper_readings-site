論文／訪談原始來源

把多模型經驗寫回同一張技能圖

一句話概括

MultiEvoSkill 將技能表示為有型別的圖，以異質模型的執行、反思及辯論產生局部修改，再合併成單一候選，通過行為與結構檢查才更新持久技能；推論時使用單一技能，不需帶著整個模型委員會。（§1、§3）

解決什麼問題

線性文字容易把分支、先決條件及資料依賴藏在敘述裡，修改一條全域指示又可能干擾其他分支。單一模型的經驗也可能把其推理習慣寫入技能，降低其他模型的可用性。本文聚焦訓練時編輯同一持久技能圖，與推論時臨時組圖、管理技能庫或更新模型權重有別。（§1–2）

核心方法

技能是帶型別與屬性的有向多重圖。節點表示動作、決策、產物、約束，邊表達順序、分支、產出、消耗及依賴；自然語言仍提供局部指示與條件。實作要求引用有效、符合 schema、無環，且每個可執行節點由 START 可達並能到 END。圖與段落不是可逆的一對一映射，也不是形式驗證過的執行引擎。（§3.2、Limitations）

各 executor 對同一訓練題分別執行，並非分片各做不同題。反思比較成功與失敗軌跡，提出附圖版本、位置、證據題號與可重用修正规則的 issue；共享失敗不等於證明技能是成因。跨批次 issue 聚類的支持度計不同「reflector–sample 配對」，同一配對重複只算一次，不能把門檻解讀成不同樣本數。（§3.3）

每個 issue 的 proposer 對同一 parent graph 辯論有界編輯，支援增刪節點、改節點及增刪邊；優先與其他模型家族交換提案。相似度共識用來停止通訊，不代表接受修改。階層 revisor 合併相容修正、解衝突，可作支持目標內的最小改寫；不是只能選固定操作 ID。所有中間 patch 仍相對同一 parent，操作套用順序與技能本身的任務依賴須區分。合併成功也不能替每個 constituent edit 建立個別因果功勞。（§3.3–3.4）

selection 題與 juror 配對在演化前固定，parent 與 candidate 用同一配置比較；selection 只進 gate，不供提案生成。接受條件為 minD >= -epsilon、meanD >= tau、非退步 juror 比例 Q >= q0，再加機械結構及語意拓撲檢查。任一 topology juror 報高信心硬錯即拒收；冗餘或模糊本身只是警告。這是允許有限 selection 退步的經驗篩選，LLM 語意審查不是正確性證明。（§3.5、附錄 C）

實驗與結果

作者自報各方法共用 GPT-5.6-Luna authoring backbone；本法另用 Gemini-3.8-Flash、MiniMax-M3、DeepSeek-V4-Flash proposer，並稱同 seed、split 及預算等價比較。前三個 benchmark 為工作流程規劃 adapter，報 mean per-instance node F1，不能稱互動環境成功率；SearchQA 是 macro token F1，SpreadsheetBench 是 hard instance accuracy。（作者自報，§4.2）

結論與局限

作者明示：結構驗證只查圖的可接受性，不能涵蓋所有任務語意；LLM topology jury 可能漏掉不支持的依賴，也可能拒絕有用修改。重用 selection set 可能過擬合，狀態相似的停止條件不保證最佳解；技能圖是程序表示，不是形式驗證執行引擎。（Limitations，位於§5之後）

（本檔補註，非作者自陳）表2提供五任務比較，未逐一列出跨部署 backbone 的測試成績；表4只消融 proposer 組成，不能代替未見 backbone 的遷移驗證。表3亦不足以單獨隔離圖表示的量化貢獻。正文把 gate 描述為保證單調演化，但其公式容許個別 juror 在 epsilon 內退步，應以條件式及作者自陳的 selection 過擬合風險理解。（依據§3.5、§4）

對讀者的價值・接點

（本檔補註，非作者自陳）適合借鑑的是「圖版本綁定的 issue → 對同一 parent 的局部 patch → 合併後再評估」這條證據鏈。對持久 agent 技能或 ai_core，可把診斷支持、機械可套用、整體行為改善分開記錄，避免把多模型同意或局部補丁成功誤當整體技能已改善。（依據§3.2–3.5）
