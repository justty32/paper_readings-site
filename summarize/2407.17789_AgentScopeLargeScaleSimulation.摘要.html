論文／訪談原始來源

《AgentScope 的超大規模多 Agent 模擬》重點摘要

一句話概括

AgentScope 把 LLM agent 建模為 actor，以 RPC 跨行程、跨裝置傳訊，並用 proxy 與 placeholder 把既有集中式流程自動轉成非阻塞分散式流程；在 4 台各有 8 張 A100-80G 的機器上，作者讓 100 萬個「猜平均數的 2/3」agent 完成一輪模擬，Llama3-8B 短答版耗時 12 分鐘。每個角色每輪其實呼叫模型兩次，因此這代表大量短任務角色與約 200 萬次模型呼叫，不等於 100 萬個持續自治、彼此密集互動的 agent。

解決什麼問題

  • 大量 agent 的依賴排程、LLM I/O 與跨機器通訊讓傳統循序或僅靠 Python async 的框架難以擴展。
  • 模擬人口不只要多，還要符合年齡、教育、職業等分布；逐一撰寫背景既慢又容易同質化。
  • agent 分散在多台機器後，生命週期、資源、狀態與行為很難人工追蹤。
  • 共享環境要承受高併發，還得支援雙向通知、多個局部環境與自訂狀態操作。

核心方法

  • Actor 式執行層：每個 agent 接收訊息並獨立運算。無未滿足依賴的 agent 可並行；支援一 agent 一行程，以及多 agent 共用一行程兩種配置，分別適合計算密集與大量 I/O 等待。
  • 自動分散式轉換：to_dist 把 agent 移到指定裝置，中央留下 proxy。proxy 收到呼叫後立即回傳 placeholder；下游真正需要結果時，才依 placeholder 等待遠端計算。
  • 環境也是特殊 agent：共享狀態與自訂函式透過 RPC 提供；listener 讓環境主動通知 agent；環境可巢狀化，形成群組內與全域兩層同步。
  • 異質人口生成：先指定人口總數及多個屬性分布，再抽樣成 JSON，交給 LLM 擴寫詳細角色背景；以 seed 與 temperature 增加差異。
  • Agent-Manager：每台遠端機器常駐 server，負責建立、監控與停止 agent；網頁介面彙整 server、agent、IP、運行狀態與資源使用。管理單位偏向 server，而非逐一操作 agent。

主要結果

  • 4 台機器上，100 萬個 agent 使用 Llama3-8B 與短答 prompt 時為 12 分鐘；要求逐步思考後，平均回應 token 增加超過 150 倍，耗時 85 分鐘。Llama3-70B 加逐步思考約 10.6 小時。
  • 排除模型速度、令每個 agent 只睡眠一秒的 dummy 實驗中，100 萬 agent 的 actor 方案為 40 秒；循序執行約 12 天，Python async 約 8.6 小時。
  • 固定 10,000 agent，裝置由 1 增至 4，Llama3-70B 逐步思考版由 22 分鐘降到 5.6 分鐘；每台固定 10,000 agent 時，增加裝置與總 agent 數，耗時大致不變。
  • 在「猜平均數的 2/3」中，模型、prompt、角色背景都顯著改變答案分布。Qwen2-72B 的勝出數由基本 prompt 的 33.70 降至逐步思考的 12.76；第五輪平均值則為 25.16 與 2.02。
  • 詳細理性假設比泛用「逐步思考」更有效。Qwen2-72B 第五輪的平均回報依四種 prompt 分別是 25.16、2.02、0.14、0.15。
  • 教育與職業角色影響行為，但模型敏感度不同；極端角色會失真，例如被要求扮演七歲孩童的 agent 仍展現多步運算能力。

對「千萬 agent 管理」的啟發

這篇最有價值的是把問題拆成三層：actor runtime 負責排程與隔離，環境 agent 負責分區共享狀態，Agent-Manager 負責機器與生命週期。若擴到千萬級，這個分層仍成立，但論文沒有回答 mailbox 背壓、持久狀態、失敗重播、跨區分片、成本配額與故障域等問題。它證明百萬個稀疏、短生命週期 LLM 請求可以承載；不能據此推論千萬個長期自治 agent 已可運作。

局限

  • 核心工作負載是同一規則下的一輪或數輪獨立推理，互動拓樸稀疏，遠比工具型 agent 的長軌跡、密集協作與共享記憶簡單。
  • 「100 萬 agent」大多是邏輯角色與推理請求，不是 100 萬個同時常駐的模型副本；模型服務仍集中於少量 GPU。
  • 效率比較以 dummy sleep 對照循序與 Python async，未與成熟的 Ray、Akka 或專用大規模模擬器做等條件基準。
  • 背景由 LLM 擴寫，人口屬性與實際行為的一致性沒有嚴格驗證；作者自己也觀察到角色扮演失真。
  • 論文展示簡單計算錯誤，但未提供重試、隔離、因果歸因、補償操作或錯誤傳播控制。
