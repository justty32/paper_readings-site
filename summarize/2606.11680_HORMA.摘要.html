論文／訪談原始來源

《HORMA：先組織、再檢索的階層式記憶導航》重點摘要

一句話概括

HORMA 把 agent 記憶拆成兩個不同時間尺度的問題：高能力 LLM 先把原始軌跡整理成帶來源連結的檔案系統式階層，再由一個可用 ls、grep、cat、select、done 的輕量 agent 導航檢索；後者以 evidence-overlap reward 做 GRPO，目標是在有限 context 中找出「最少但足夠」的證據，而不是把語意相近片段一股腦塞回 prompt。

問題與關鍵判斷

  • 保留完整歷史會造成 context overload、資訊稀釋、延遲與成本；摘要、folding 等壓縮又會不可逆地丟失細節。
  • 常見 external memory 是扁平片段集合加 embedding top-k，難以保存時間順序、因果依賴與更新後的有效狀態。
  • memory construction 與 retrieval 不該一起用稀疏 task reward 訓練。前者的影響延遲很久，後者卻直接位於每一步推論的 critical path；兩者綁在一起會產生 credit-assignment gap。

方法

Grounded workspace

  • 每次 interaction／dialogue turn 的 raw trajectory 先進 timestamped directory，不被摘要取代。
  • manager 再建立 entity log、event summary、state tracker 等結構化 notes；note 帶 temporal metadata 與 raw trajectory reference，摘要失真時仍可回到來源。
  • manager 與 retriever 都只能透過可執行的檔案操作碰 workspace，使操作可觀察、可追蹤，也讓 construction 與 retrieval 可以分開改良。

記憶管理技能演化

Memory manager 由 domain-agnostic prompt 起步。作者對照 raw history 與 managed context 的成敗，分成兩種反例：

  • D_exo：raw history 成功、managed context 失敗，表示整理過程漏掉資訊。
  • D_end：managed context 成功、raw history 失敗，表示結構化記憶減輕 hallucination、lost-in-the-middle 或噪音干擾。

LLM 對成對軌跡產生 feedback，再把跨任務 feedback 彙整成新的 management skills。這是非參數式、文字型的 iterative refinement，不更新 manager 權重。

導航式檢索

Retriever 將階層 workspace 當成環境，用 Bash 導航；select 把已確認內容加入 context，done 表示證據足夠。訓練使用 GRPO，reward 是 retrieved context 與 ground-truth evidence 的 Jaccard overlap：相關證據漏拿會扣分，無關或重複內容拿太多也會扣分。

實驗結果

  • ALFWorld：134 個任務、6 類型。Claude Sonnet 4.5 版本的 HORMA 在 1,950／2,200 input-token 限制下成功率為 56.7%／73.9%，同時位於 interaction steps 與 tokens per step 的較佳 Pareto 區域。
  • LoCoMo：519 個 QA 來自 3 段對話，另 7 段用於 Qwen 3.5 4B retriever 訓練。Claude retriever 的 HORMA LLM-judge overall 為 51.6，接近無限制 context 的 55.9，且高於 truncation 32.2。
  • LongMemEval：367 個 QA。Claude retriever 的 HORMA overall 為 55.9，高於 no-limit 20.4 與 truncation 34.1；這同時說明長 context 本身可能因 information dilution 比選擇性記憶更差。
  • conversational tasks 中，各 HORMA variant 每題多在 1,000 tokens 內；論文報告 LoCoMo 只用各 baseline 的 3.07%–22.17% tokens，LongMemEval 為 1.24%–16.19%。
  • Qwen 3.5 4B retriever 只用 LoCoMo 訓練，加入 skills + GRPO 後，LoCoMo 32.6→42.2、LongMemEval 40.6→58.0，retrieval calls 也下降；LongMemEval 結果超過 Claude retriever 的 55.9。
  • memory manager 是瓶頸：低品質組織即使換上更強 retriever，改善仍小。skill library 在 LongMemEval 四輪後長到 63 skills。

局限與閱讀提醒

  • 論文沒有獨立 limitations 章節。由設定可見，workspace 品質高度依賴 frontier proprietary model；作者自己也證明 Qwen 3.5 4B 的低品質 construction 無法由強 retriever 補救。
  • 主結果多用 Claude Sonnet 4.5 同時擔任主 agent、manager、retriever，成本與 model drift 會影響重現。
  • retrieval reward 需要 ground-truth evidence overlap，適合 benchmark training，真實任務通常沒有這種標註。
  • select 所謂「verified content」是 agent 的選擇動作，不等於外部事實驗證；來源連結提高可稽核性，但不自動保證 note 正確。
  • ALFWorld 的 small/large 限制只差 250 tokens，conversation benchmarks 則採 10K／50K 上限；不能把三者的效益視作同一種 scaling 證據。

對讀者的價值

這篇最值得帶回 Agent Machine 的不是「把記憶做成資料夾」這個表面設計，而是三個語意分離：raw event 與 derived note 分離、construction 與 retrieval 分離、強模型的慢速整理與小模型的 critical-path navigation 分離。它直接支持 context pager 以 manifest 組裝 view、每個摘要保留 source refs，以及把 cache／summary 視為可重建的派生狀態，而非權威事實。
