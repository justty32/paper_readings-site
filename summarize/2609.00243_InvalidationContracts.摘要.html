論文／訪談原始來源

Invalidation Contracts for Cross-Episode Agent Memory 重點摘要

一句話

跨 episode memory 要省下重推成本，不能只記「上次怎麼修」；server 還得在 recovery suggestion 上附 cacheability、version 與 dependency metadata，讓 client 在資料漂移時精準驅逐 stale entry，而不是等它再次失敗或粗暴清空整張 table。

問題與方法

agent 從 API error 學到 recovery suggestion 後，可在後續 episode 直接套用；但 server-side reference data 一旦改變，舊 fix 便可能默默失效。若每次都重新推導，memory 的節省又會消失。作者提出 invalidation contract，讓每個 suggestion 攜帶 cache_hint、來源 table，必要時再帶多表 tables dependency vector；每個 response 則帶 table_versions，並可用 rules_version 在 success path 偵測 derivation rule 漂移。reload endpoint 另外回傳 added、removed、changed key 與受影響 downstream node，供 row-level eviction 使用。

protocol 同時區分 wire channel 與 consumption channel。L0–L1 從 raw feedback 走到 typed suggestion 與 version stamp；L2–L3 不改 wire bytes，只教 client 把 suggestion parameters 原樣合併，並將 fix 表成已套用的 input amendment；L4–L6 加入 dependency vector、subgraph propagation 與 rule fingerprint。client 端則用另一條 A-ladder 比較 no memory、naive memory、table-level invalidation、row-level diff、consumer notification、graph propagation 與 rule oracle。

論文把節省拆成 realized_savings = validity * compliance(m,p,a)。validity 是 cached suggestion 在 drift 後仍正確的比例，由 protocol 與 eviction policy 控制；compliance 是 planner 第一次就採用 valid suggestion 的比例，另受 model、protocol level 與 action type 影響。這個分解避免把「cache 是新的」與「model 願意用 cache」混成同一個指標。

作者報告的實驗與結果

實驗涵蓋 payment 與 recipe 2 個作者自建 domain、7 個 model、3 條 serving path、250 個 arm-level run 與 9,432 個 episode（作者自報）。在所有 model 與 seed 上，row-level arm 的 eviction precision 都是 1.00；table-level invalidation 在 6 個可正常解讀的 model 上只有 0.25–0.31，另一格的 1.00 是 run 提早耗盡造成的 measurement artifact（作者自報）。

row-level invalidation 相對 naive memory，在 5 個 model 上提高 compliance。增幅包括 gpt-5-mini 的 66.7 個百分點、Claude Sonnet 4.6 的 63.0 個百分點與 Claude Haiku 4.5 的 55.6 個百分點；另外 2 個 model 的增幅為 0.0（作者自報）。相同 wire bytes 在 Claude Haiku 4.5 可達 100% aggregate compliance，Claude Sonnet 5 卻只有 11% 以下，後者尤其拒絕原始 input schema 沒有的 add-a-field fix（作者自報）。

table-level invalidation 會連帶刪掉同表但未漂移的 funding entry。4 個 model 的 post-drift funding first-try rate 由 A1 的 66.7% 降到 A2 的 0.0%，再於 A2D 回到 66.7%；另一個 model 則由 66.7% 降到 22.2% 後復原（作者自報）。這說明「能偵測 table 變動」還不夠，eviction granularity 本身會決定 memory 是否反而帶來額外成本。

相對各 model 自己的 no-memory baseline，row-level arm 在 4 個 model 上回收 29.2% 到 32.5% 的 token cost（作者自報）。contract 本身平均增加 123 bytes，相當於 response payload 的 15.1%，主要成本來自 per-table version dictionary（作者自報）。在 rule drift stream 上，stamp-plus-vectors 相較 lazy detection 提前 1 個 episode alert，維持相同 eviction 與 restamp disposition，token 差僅約 0.2%（作者自報）。

結論與局限

作者的結論是，version-stamp validity 可以由 protocol 決定性地工程化，但 realized savings 仍受 planner compliance 上限約束。實務上應先以少量 known-valid fix，依 action type 對目標 model 做 compliance preflight；若 model 拒絕部署需要的 mutation type，再精密的 invalidation 也不會換成節省。

作者自陳的局限包括：兩個 API domain 都是為研究手寫的 synthetic system，尚未驗證大型 production schema 與 organic drift；domain 數量有限；dependency vector 已實作，但其獨立 compliance effect 未被隔離；每個 domain 只測一個 base prompt 與有限 task family，prompt sensitivity 未知；drift rotation 增加到一定頻率後，naive 與 governed arm 的 gap 不再單調擴大，觸發預先註冊的 falsification criterion；研究假設 honest server，尚未實作 signed stamp、rate-limited bump 或 client-side eviction sanity bound，精準 contract 也會揭露部分內部 schema。

對讀者的價值／ai_core 接點

這篇把 agent memory 的治理問題說得很清楚：memory entry 不能只有內容與 retrieval key，還要保存 provenance、dependency、version、cacheability 與 eviction policy。對 ai_core，這可直接映射到技能與固化規則的生命週期。上游資料或規格變更時，應沿 dependency graph 做精準失效，而不是整庫清空；同時要把 artifact validity 與 executor compliance 分別量測。前者能靠 protocol 保證，後者必須按 model 與 action type 實測。兩者相乘，才是 memory 真正省下的成本。
