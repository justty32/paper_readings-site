論文／訪談原始來源

WALL-E 2.0: World Alignment by NeuroSymbolic Learning improves World Model-based LLM Agents 重點摘要

一句話

用免訓練的四階段 NeuroSymbolic Learning——比對真實軌跡與 LLM 世界模型預測軌跡、歸納出 action rules／knowledge graph／scene graph、翻譯成可執行 code rules、再用最大覆蓋問題剪枝——把預訓練 LLM 對齊成準確的世界模型，搭配 LLM 當高效 look-ahead 優化器的 MPC 迴圈做規劃。

方法架構

  • 問題：LLM 當世界模型時，其先驗常識常與具體環境動態不一致，導致預測錯誤、幻覺、違反環境物理規則。WALL-E 2.0 不微調 LLM，而是學一批環境專屬的符號知識去補這個落差。
  • Stage 1 軌跡探索：把預測任務簡化成「這個轉移會成功還是失敗」的二元分類，拿真實軌跡與世界模型預測軌跡比對，分成預測正確、預測錯誤兩個集合。真實軌跡用來歸納新規則；錯誤集合留作診斷集，供 Stage 4 剪枝用。
  • Stage 2 符號知識學習：三種知識並存，各司其職——action rules 由 LLM 對一段 context window 內的真實轉移做歸納推理，抓決定性限制（例如沒有 stone_pickaxe 就不能挖 iron）；knowledge graph 是有向標籤圖，節點是物品/材料/地點，邊標 require、consume、enable 這類前置與消耗關係；scene graph 逐步從每步觀測更新，記錄物件的空間關係（位置、擁有、鄰接），補足部分可觀測性缺的全局資訊。
  • Stage 3 翻譯成 code rules：LLM 把三種符號知識轉成 Python 函式 CodeRule(obs, action, KG/SG) -> feedback, suggestion, flag，flag 是布林值，規則命中失敗時連帶給出可讀的診斷與建議。
  • Stage 4 剪枝（規則庫治理核心）：把規則保留問題形式化成最大覆蓋（maximum coverage）最佳化——目標是用最少規則覆蓋 Stage 1 診斷集裡最多的錯誤預測，貪婪演算法逐一挑「新增覆蓋量最大」的規則，直到覆蓋不再增加或撞到規則數上限 K。只覆蓋「本來就預測對」的轉移的規則直接淘汰，被更全面規則涵蓋的冗餘規則也一併剪掉。作者發現 K 越大整體表現越好，且完全不剪枝時效能會因雜訊/衝突規則而崩掉。
  • MPC 迴圈：agent 向世界模型問「在觀測 o 下採取動作 a 會怎樣」，世界模型給出預測，code rules 同步做一致性檢查——若規則結果與 LLM 預測衝突，規則結果覆蓋 LLM 預測；回傳的 feedback/suggestion 引導 agent 修正下一步提案，直到通過檢查或達迭代上限。整個系統交替跑 MPC 與 NeuroSymbolic 學習，持續把新學到、剪枝過的規則併入世界模型。

作者報告的結果

環境是 Mars（Crafter 改版，含反常識的地形/生存/任務依賴修改）與 ALFWorld（134 個家居任務）。Mars 上 WALL-E 2.0 相較 baseline（PPO、DreamerV3、ReAct、Reflexion、Skill Library、IfR、WALL-E 1.0）reward 提升 16.1%–51.6%、score 至少提升 61.7%（作者自報）；DreamerV3 訓練用了 100 萬步而 WALL-E 2.0 只用 5,600 步（其 0.56%）。在反常識場景下 reward 至少提升 21.8%、score 至少提升 51.6%；對比 SOTA 方法 IfR，reward 從 3.6 升到 6.7、score 從 4% 升到 15.3%，分別超越 17.9% 與 51.6%（作者自報）。ALFWorld 上僅 4 次迭代後即達 98% 成功率新紀錄，優於 WALL-E 1.0 與 RAFA（各 95%）、AdaPlanner（91%）與人類表現（91%，作者自報）。消融顯示：只用 action rules 或只用 KG/SG，reward/score 都明顯低於三者合用（Mars 上分別降 23.9%/45.8% 與 34.3%/66.0%）；symbolic knowledge 用在世界模型比用在 agent 提升更大（約 46.3% vs 30.9%）；跳過剪枝階段，reward/score 從 6.7/15.3 暴跌到 1.5/1.6（以上皆作者自報）。

對 ai_core 的價值／接點

這篇對 ai_core 最有參照價值的是 Stage 4 的規則庫治理邏輯：規則准入不是「LLM 生成了就收」，而是用診斷集覆蓋率這個明確、可計算的指標做最大覆蓋最佳化——只留「能修正最多已知錯誤」且不被別的規則涵蓋的最小規則子集，對應 ai_core §3.4「憑證准入治理」想要的不是靜態白名單，而是可重算、可證明貢獻的動態准入門檻。Stage 1 到 Stage 3 的流程也直接對應「模糊意圖→結構化意圖→固化成確定性程式碼」：真實軌跡與預測軌跡的落差先被歸約成二元訊號（成功/失敗），LLM 才在這個窄化後的任務上做歸納，最後才落成可執行、可獨立驗證的 Python 函式而非留在自然語言規則裡——這比直接叫 LLM 生成規則再祈禱它遵守，多了一層「規則命中時用程式碼結果覆蓋 LLM 預測」的強制力（§7 對比 IfR 的自然語言規則 vs code rules 正是這點），值得 ai_core 固化引擎（§5）參考：固化不只是把邏輯寫成程式碼，還要讓程式碼在推理期真的有否決 LLM 輸出的權力。同時作者在附錄 F 承認的局限——目前的規則只處理確定性轉移，碰到隨機性動態（如夜間採集有時成功有時失敗）一律當失敗處理——也提醒 ai_core 在設計成本梯度（§3.2）時，固化門檻要能容納「規則覆蓋不到的殘留不確定性」，而不是假設所有行為最終都能被規則窮盡。
