論文／訪談原始來源

《SOAR：用於演化程式合成的自我改進語言模型——ARC-AGI 案例研究》重點摘要

一句話概括

SOAR（Self-improving Operators for Automated program Refinements）：讓 LLM 在「演化搜尋 ↔ 從搜尋軌跡自我微調」的閉環中持續變強——搜尋階段用 LLM 採樣 + 精煉候選 Python 程式，學習階段用事後重標記（hindsight relabeling）把成功與失敗都轉成 （任務， 解） 訓練對來微調採樣與精煉能力；在 ARC-AGI 上不靠任何人工 DSL／人工資料，純從自身搜尋經驗 bootstrap，最終以開源 LLM 集成達公開測試集 52%（oracle 57.25%），突破固定模型的規模/算力天花板。

解決什麼問題

LLM 直接寫程式解 ARC 太難（連 Claude-4-Sonnet 僅 20.75%、GPT-4.1 僅 8%）。演化搜尋能靠多採樣改善，但底層生成模型能力固定→ 加大採樣/精煉預算只會邊際遞減，存在性能天花板。如何讓「搜尋運算子」本身從搜尋經驗中持續學習變強？

核心方法

  • Sample&Refine 搜尋（每任務 6k 預算）：
    1. 採樣：用 base LLM 直接生成 3k 個通用 Python 程式（歸納式 sample-and-test，非手刻 DSL），執行得輸出格。
    2. 精煉：對錯誤程式，把成功/失敗的輸入輸出回饋餵回 LLM 修補；以 REX（Thompson sampling + 探索獎勵）把精煉當生成式多臂老虎機，平衡探索/利用，跑 3k 步。
    3. 加權多數投票集成：6k 程式按各自在範例上的準確度給其產生的測試輸出格投票，回傳 2 個候選（符合 benchmark 規則）。
  • 學習階段（自我微調）：
    • 採樣微調：用 hindsight relabeling——任一採樣程式雖對原任務或許錯，但對「它自己實際產生的輸出」必然正確 → 造出合成 （任務， 解） 對，化失敗為訓練資料（2.4M 點，子採樣每任務 50 條；greedy-diverse：25 條最佳 + 25 條最差保多樣性最優）。
    • 精煉微調：收集「錯→對」的成功修補對，按父程式準確度分箱（0%/1-34%/34-98%/100%）平衡採樣（diverse 略勝）。
    • 正向協同：採樣與精煉共同微調一個模型勝過各自專用模型（共享程式結構表徵）。
  • 閉環自我改進：迭代「搜尋→學習」；訓練集跑 4 輪；再做測試時訓練（TTT）——目標任務無真值，改用「範例準確度」選解 + hindsight relabeling，於測試任務上續跑 2 輪。

結果

  • ARC-test：Sample&Refine-6k 已讓 7B 勝 GPT-4.1、32B 勝 Claude-4-Sonnet;SOAR 幾乎把搜尋表現翻倍。
  • 訓練集 4 輪自我改進：各尺寸多解 +19~27%（7B 近翻倍）。
  • 測試時訓練再 +5%;7B 從 14.25%→36.25%（2.5 倍）、14B→42.75%、32B→44.37%、72B→44.87%、Mistral-Large→45.5%。
  • 跨尺寸集成投票達 52.00%（oracle 57.25%）——開源 LLM 程式合成 SOTA，無任何人工資料/DSL。
  • 突破模型尺寸天花板（SOAR(no learning) 在 32B 後走平，SOAR 逐輪抬高曲線）與搜尋預算天花板（基線 ~5.2k 次後飽和）。

局限

  • 算力昂貴：每任務每輪 6k 次合成；增益隨輪次遞減（內在或方法侷限未定）。
  • 解多樣性下降：已解任務收斂、未解任務靠 hindsight relabeling 勉強維持多樣性，但仍不足以支撐持續進步。
  • 僅在 ARC 驗證（雖宣稱領域無關）；多數投票與 oracle 差約 9.5%，集成策略仍有改善空間。

對讀者的價值

  • 本批 E 類（ARC-AGI）的**「歸納式程式合成 + 自我改進閉環」代表**——相對 2505.07859（轉導式、PoE 集成、無學習閉環）走完全不同路線：產通用 Python 程式而非直接生格、靠 finetune 而非單純推論技巧。
  • 最值得記：hindsight relabeling 化失敗為訓練資料、採樣/精煉共同微調的正向協同、搜尋↔學習閉環抬高 scaling 曲線、TTT 把訓練集學的搬到測試任務。
  • 與 CodeIt（Butt et al. 2024）的關係：SOAR 四點擴展＝通用 Python（非手刻 DSL）、加執行回饋精煉步、擴到更大開源 LLM、TTT+測試時搜尋結合。
  • 定位：完整方法 + 大量消融，開源（github.com/flowersteam/SOAR）；適合做 程式合成搜尋、自我改進/expert-iteration、ARC、LLM 演化搜尋運算子 的人。可作為 FunSearch/AlphaEvolve 等「固定模型搜尋」系統的 drop-in 升級。
