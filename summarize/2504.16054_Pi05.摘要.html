論文／訪談原始來源

π0.5: a Vision-Language-Action Model with Open-World Generalization 重點摘要

一句話

π0.5 不是只靠擴大單一機器人資料，而是把多種 robot embodiments、web 視覺語言資料、高階 subtask 標註與人類口頭指令放進同一個 VLA co-training recipe，再由同一模型先選語意子任務、後輸出連續動作，讓 mobile manipulator 能在訓練未見過的真實住家執行長時程整理工作。

問題與設計取向

VLA 已能端到端控制機器人，但常在與訓練資料相近的場景評估。把「撿起一個物件」擴到新背景尚可用更多示範處理；清理廚房、整理臥室、鋪床等任務則同時要求物件語意、長期步驟分解、跨場景 skill transfer 與精細控制，逐一蒐集所有住家組合並不實際。

π0.5 的假設是：開放世界泛化需要混合不同抽象層次的經驗。目標 mobile manipulator 的第一手資料提供最直接的控制訊號，其他固定式或不同 embodiment 的機器人資料擴大動作與場景覆蓋，web 圖文資料補物件語意，高階 subtask 標註教模型分解任務，人類 verbal instructions 則示範在執行過程中何時切換子任務。

模型與訓練方法

模型以 π0 為基礎，使用同一個 multimodal transformer 同時表示文字、影像、proprioception 與動作。訓練分兩階段。Pre-training 把 robot actions 經 FAST tokenizer 離散化，與文字、object locations、高階 subtask prediction 及 web VQA 等任務一起做 next-token prediction，取得穩定且可擴充的共訓。Post-training 再加入較小的 action expert，用 flow matching 產生細緻連續 action chunks，並把資料重心轉向 mobile manipulation、跨場景 robot data、高階標註與 verbal instruction。

推論也分兩層，但共用同一套模型權重。模型先根據整體命令與當前觀察產生高階語意子任務，例如「拿起盤子」；低階 action expert 再以這個子任務為條件輸出即時控制。這讓高階決策可吸收 web 與語言知識，低階控制則受益於跨 embodiment robot actions，同時避免另接一個外部 planner 所造成的介面落差。

資料混合包含 mobile manipulator、不同住家的非移動式機械臂、實驗室 cross-embodiment tasks、高階 subtask labels、multimodal web data，以及 post-training 的 verbal instructions。作者自報目標平台的 mobile manipulation 資料約 400 小時；第一階段訓練樣本中有 97.6％ 並非 mobile manipulator 執行家務，顯示系統刻意把主要容量放在跨來源 transfer，而非只複製目標任務（作者自報）。

實驗與作者報告的結果

評估分成五組問題：在全新真實住家能否完成多階段任務、訓練場景數增加時泛化如何變化、各 co-training data source 的貢獻、相對 π0 與強化版 baseline 的差異，以及高階 inference 是否必要。定量比較使用未出現在訓練集的 mock homes，最終 in-the-wild 評估則在 3 個訓練未見的真實住家進行廚房與臥室任務（作者自報）。

作者報告 π0.5 能在新住家完成把物品放入抽屜、把衣物放入洗衣籃與把餐具放入水槽等多階段工作；任務可持續數分鐘，模型只接收高階命令，再自行預測下一個 subtask。隨訓練地點增加，完整任務進度、language following 與新物件成功率整體上升；完整 co-training model 的表現接近直接看過 test homes 資料的 control，顯示場景多樣性與跨來源資料共同縮小了 generalization gap。

Ablation 的方向性結果一致。移除其他 robot embodiments 的資料會明顯傷害 mock-home tasks 與物件操作；移除 web data 對整體家務的影響較小，卻明顯削弱 out-of-distribution object language following 與高階 subtask inference。完整 π0.5 優於 π0 與只改 action representation 的版本，表示提升不只是 FAST 或 flow matching 的工程效果。高階比較中，共訓完整資料但執行時不顯式產生 subtask 的 variant 仍很強，說明 subtask supervision 本身已改變低階 policy；零樣本外接 GPT-4 作高階 policy 反而最差，顯示一般 VLM 知識若沒有 robot-domain adaptation，不能直接替代共同訓練的高階控制。

結論與局限

π0.5 的貢獻不是一個全新控制 primitive，而是一個異質資料如何進入同一 VLA 的完整 recipe。離散 action tokens 讓大規模預訓練容易，continuous action expert 保留即時控制精度，高階文字輸出則成為任務結構與低階行動之間的共享介面。實驗支持這種組合能把中等規模的目標平台資料，放大成跨住家、跨物件與跨任務的泛化能力。

系統仍會被陌生抽屜把手、難開的櫃門、手臂遮住污漬等情況困住，高階模型也可能分心，重複開關抽屜。模型處理的 prompt 相對簡單，context 與記憶有限，不適合需要跨房間追蹤物件或長期記住儲藏位置的任務。評估集中在住家清潔與整理，是否能遷移到不同物理風險、工具或安全需求尚未證明。更重要的是（本檔補註，非作者自陳），paper 沒有把 co-training ingredient 的因果貢獻完全拆開；資料來源、規模、標註方式與訓練階段彼此耦合，ablation 只能回答目前 recipe 裡移除某項會怎樣。

對讀者的價值／ai_core 接點

對 ai_core 的第一個接點是「同一模型、兩種時間尺度」。高階語意 subtask 不必成為另一個鬆散 agent；它可以是低階確定性控制的條件輸入，並在訓練期和 action data 一起學。若 ai_core 要把自然語言意圖轉成可執行步驟，可借用這個介面：上層只輸出受控 vocabulary 的 subtask，下層才接觸高頻 action space，兩者各用適合的資料與更新頻率。

第二個接點是異質資料的功能分工。Web data 主要補語意與未見物件，跨 embodiment data 主要補動作與場景，verbal instruction 補高階切換。ai_core 的資料治理因此不該只問「資料量夠不夠」，而要替每個來源記錄它預期修補哪一層能力，並用對應 ablation 或 probe 驗證；否則混合資料變大，只會讓失敗來源更難追。
