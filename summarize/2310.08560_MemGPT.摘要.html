論文／訪談原始來源

《MemGPT：把 LLM 當作作業系統來思考》重點摘要

一句話概括

MemGPT 把有限 context window 類比成 RAM，把外部資料庫類比成 disk，讓 LLM 用 function calls 自行搬移、搜尋與改寫記憶，並以 memory-pressure warning、事件與 heartbeat 串接多次推論；它證明「固定 context 模型 + 外部階層記憶 + agentic control flow」能處理長對話與多步檢索，但這是 OS-inspired virtual context manager，不是具備 process isolation、資源保護、kernel authority 與 fault recovery 的真正作業系統。

它是什麼，不是什麼

MemGPT 借用虛擬記憶體的設計語彙：應用程式看見大於實體 RAM 的 address space，OS 在 RAM 與 disk 間 paging；對 LLM 而言，可見 prompt 是 main memory，資料庫是 external memory，agent 透過 tools 把資料 page in/out，形成「近似無限 context」的使用體驗。

類比到此為止。論文系統仍是一個由 Python orchestration、LLM prompt、function schema、parser 與 databases 組成的 agent runtime：

  • LLM 依自然語言 instructions 決定何時寫入／搜尋，並非可信 kernel policy。
  • Parser 驗證 function name／arguments 後執行；它不驗證記憶內容是否真實、是否該被覆寫。
  • 沒有 address-space isolation、multi-process scheduling、capability security、durable transaction、crash replay 或 side-effect recovery。
  • 所謂 interrupt 是外部／系統／定時 event 觸發一次 LLM inference，不是硬體 interrupt 或 preemptive execution。

因此論文標題的「Towards」很重要：它提出 OS metaphor 與控制迴圈，不是宣稱已做出 LLM kernel。

記憶階層

Main context

目前一次 inference 真正看得到的 prompt tokens，分三段：

  • System instructions：唯讀，描述控制流、memory tiers 與 functions。
  • Working context／core memory：固定大小、可由 functions 編輯的文字區，保存使用者關鍵事實、偏好與 agent persona。v2 正文用 working context，附錄 prompt 仍稱 core memory。
  • FIFO queue：近期 user/agent/system messages、function inputs/outputs；開頭保留已 eviction 訊息的 recursive summary。

External context

  • Recall storage：完整 message database。每次輸入與模型輸出都寫入；搜尋後的舊訊息重新附加到 FIFO queue，才會被 LLM 看見。
  • Archival storage：任意長文字物件的讀寫資料庫；實驗預設 PostgreSQL + pgvector + HNSW，適合保存文件、長期 facts 或 agent 主動歸檔的內容。

Queue manager 在約 70% context 時插入 memory-pressure warning，讓 agent 先把重要內容寫入 core／archival；到約 100% 時 flush，例如 evict 50% queue，將舊 summary 與被移除訊息重新摘要。原訊息仍在 recall storage，不等於被刪除。

Interrupt 與控制流

Events 可以是 user message、system capacity warning、登入／文件上傳等 interaction，或定時事件。每個 event 被轉成文字加入 main context，再觸發 LLM inference。

LLM completion 若是 function call，executor parse、驗證 arguments、執行並回傳結果／runtime error。Function 帶 request_heartbeat=true 時，結果加入 context 後立即再次呼叫 LLM，使 agent 能連續翻頁、搜尋與 multi-hop lookup；沒有 heartbeat 時則 yield，直到下一個 external event 才繼續。

實驗與規模

長期對話

Multi-Session Chat 每段資料有 5 sessions、每 session 約十多則 messages；作者新增第 6 session 做 memory question 或 opener。

  • Deep Memory Retrieval：固定模型只看過去五次對話的 lossy summary；MemGPT 可對完整 recall history 做 paginated search。
  • GPT-3.5 accuracy 38.7%→66.9%，GPT-4 32.1%→92.5%，GPT-4 Turbo 35.3%→93.4%。
  • Conversation opener 的 persona similarity（SIM-1）在人類為 0.800，MemGPT + GPT-4 為 0.868；但 MemGPT output 更長、覆蓋 persona facts 更多，similarity 不等於真人偏好或長期 engagement。

文件分析

  • Multi-document QA：2018 Wikipedia、NaturalQuestions-Open 的 50 questions，同用 text-embedding-ada-002 retriever；MemGPT 可迭代搜尋 PostgreSQL/pgvector archival memory，而 baseline 只能讀一次放入 context 的 top-K documents。作者另釋出約 2,000 萬 Wikipedia articles 的 embeddings。
  • Nested KV：固定 140 UUID pairs、約 8K tokens，nesting 0–4 層，每層測 30 ordering configurations。GPT-3.5 baseline 在一層即 0%，GPT-4／Turbo baseline 三層時為 0%；MemGPT + GPT-4 在 0–4 層維持穩定，其他 base models 兩層後仍開始下降。

局限與證據邊界

  • 論文沒有獨立 limitations 章節；以下由作者的實驗觀察與設定整理。
  • 效果高度依賴 base model 的 function calling 與遵循 prompt 能力。作者明說 GPT-3.5 明顯較差；GPT-4 Turbo baseline 較強，接上 MemGPT 後 nested KV 反而比 MemGPT + GPT-4 差。
  • Retrieval bottleneck 沒消失。Gold document 常排在前十幾名外；理論上 agent 可一直 pagination，實際上常在查完整個 database 前自行停止。
  • Memory edit 是 self-directed generation，沒有 factual verifier、conflict resolution、dependency invalidation 或 transaction semantics；錯誤 core memory 可能長期影響後續行為。
  • DMR questions 由另一個 LLM 生成，DMR 與 document QA 用 LLM judge；conversation opener 用 embedding similarity。這些指標不能直接證明數月真實互動的安全、人格一致性或使用者滿意度。
  • 原文沒有交代 DMR／opener 的實際樣本數、重複試驗或信賴區間；表格的高 accuracy 不能據此推成穩定的 population estimate。
  • Document QA 僅 50 questions；nested KV 是受控合成資料；對話是五個短 sessions 加一輪測試，不是實際無界 lifetime。
  • Nested KV 段落稱 key-value pairs「stored in main context」卻又說以 function queries 反覆存取；架構章把 function retrieval 定義為 external context page-in，圖例也呈現 query。論文文字在 storage tier 上不一致，本摘要不替作者推定實作真相。
  • 「Infinite／unbounded context」是可反覆查外部儲存的介面幻象，不代表每一步可同時注意全部資料，也不保證一定找回正確項目。

對讀者的價值

MemGPT 的歷史貢獻是把 agent memory 從「塞一份 RAG context」提升為可由 agent 反覆操作的 runtime state，並把 memory pressure、paging、event loop 與 multi-step tool chaining 放進同一架構。對 Agent Machine 而言，它是很好的 userspace prototype；下一步則是把 LLM 的建議降格為 proposal，由 authoritative reducer、typed memory operations、capabilities、evidence 與 durable event log 接管 correctness。

MemGPT 後來更名／發展為 Letta 屬產品沿革，不是本篇 2023–2024 論文的實驗內容；本文不以後來產品功能回寫原始系統。
