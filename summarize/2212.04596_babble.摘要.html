作者：David Cao, Rose Kunkel, Chandrakana Nandi, Max Willsey, Zachary Tatlock, Nadia Polikarpova（UC San Diego／University of Washington／Certora，POPL 2023）

日期：2022-12

arXiv：2212.04596

論文／訪談原始來源

《babble：用 E-Graph 與反統合學習更好的抽象》重點摘要

一句話概括

LLMT（library learning modulo theory，帶等式理論的函式庫學習）：在傳統「純語法」的函式庫學習（把一堆程式壓縮成可重用抽象）之上，額外吃進一份領域專屬的等式理論，用 e-graph + equality saturation 緊湊表示「語義等價但語法不同」的整個程式空間，再用一種新的**e-graph 反統合（anti-unification）**演算法直接在該空間找共同模式並產出候選抽象；作者實作成工具 babble，比當前最先進的 DreamCoder 壓縮更好、且快 1–2 個數量級。

解決什麼問題

既有函式庫學習（以 DreamCoder 為代表）有兩大限制，阻礙擴展到更大、更真實的輸入：（1）候選生成不精確——產生大量根本無法帶來壓縮的候選抽象，拖慢選擇階段；（2）純語法、對表面變異不魯棒——人類一眼看出 2+1 和 1+3 可用 λx→x+1 抽象（因加法可交換），但純語法方法因兩者語法不同而學不到。論文的驅動例：同一組 2d CAD 圖形程式，只要把冗餘的「縮放 1 倍」no-op 去掉（語義不變），純語法方法就從學到最佳抽象 f0（語料 208→72 節點）退化成較差的 f1（196→81，反而更大）——語法學習對「保語義的程式變體」不魯棒。

核心方法

  • LLMT 三階段流水線（Fig. 9）：先 eqSat 用等式理論把語料飽和成 e-graph（代表所有等價程式）；再用 e-graph 反統合生成候選模式、每個模式轉成一條壓縮 κ-rule；最後 select_library 用 beam search 選最佳子集，抽取最小壓縮項。
  • e-graph 反統合（貢獻 2）：把「求兩項最具體共同模式」的反統合從『項』推廣到『e-class／e-graph』；對所有 e-class 對用動態規劃由下而上計算，避免重複子問題；用「支配（dominance）」關係與「太具體／太抽象」兩個 generality filter 修剪候選（只留「最具體且在語料中至少匹配兩處」的模式），並用支配關係處理 e-graph 迴圈造成的無限候選集。
  • targeted common subexpression elimination（貢獻 3）：把「選最佳函式庫」化約為「在有共用子式下從 e-graph 抽取最小項」（傳統要靠昂貴的 ILP）。babble 只針對要共享的 λ-抽象做，用cost set（每個 e-class 記錄各函式庫子集對應的最小 use cost）由下而上傳播，配 partial-order reduce（剪掉可證次優者）與 prune（beam：限制庫大小 N 與 cost set 寬度 K）折衷精確度與效率。
  • 形式化證明了 pattern-based 學習的健全性與完備性（Thm 3.1）；建於 egg e-graph 函式庫之上。

結果

  • DreamCoder 基準（List 59／Physics 18／Text 66／Logo 12／Towers 18 個 benchmark）：babble 在五個領域一致取得更好的壓縮率，且快 1–2 個數量級（Fig. 12）。
  • 消融（RQ2）：純語法版 "BabbleSyn" 已勝過 DreamCoder；加上等式理論後壓縮再顯著提升、額外時間在一個數量級內。純 "EqSat"（不學庫）很快但幾乎不壓縮。
  • 大型 2d CAD（每領域一個約 1.9萬–4.3萬節點的大 benchmark，DreamCoder 無法處理）：加等式理論在四個領域壓縮率全部提升（如 Nuts&Bolts 9.23→10.90），有時甚至更快；輸入規模比 DreamCoder 基準大 10–100 倍。
  • 質性（RQ3）：學到的函式符合人類直覺——如「縮放正多邊形 ngon」、跨 Nuts&Bolts 與 Vehicles 都出現的「一圈形狀 ring」、以及 Gadgets 的整體與零件抽象。

局限

  • 等式理論須由領域專家手工提供（未來可用 Ruler／TheSy 等理論合成工具輔助）。
  • e-graph 反統合不完備，會漏掉某些能帶來更好壓縮的模式。
  • 為求可擴展採 beam search 近似，放棄了理論最優性保證（對照 Stitch 對「單一最佳抽象」有最優性保證）。
  • 學到函式庫的可用性／可讀性缺乏嚴謹使用者研究；形式化為一階（實作無此限制）。

對讀者的價值

  • 直接命中 ai_core §3.6 固化引擎最硬的一環：當固化引擎要把「LLM 反覆處理過的案例」結晶成確定性抽象庫時，必然遇到**「同義但語法不同」的案例該不該去重／能不能共用同一抽象**。babble 給出一條非 LLM、可驗證的路徑——把領域等式理論（交換律、單位元、no-op 化簡…）餵進 e-graph，用 equality saturation 把語法變體收斂成等價類，再靠 e-graph 反統合在「語義等價空間」裡抽共同模式。這正是把「便宜高頻智能的重複產出」壓成「資產工廠一次結晶的可重用函式」的具體機制。
  • 與已入庫 Stitch（2211.16605） 恰成對照：Stitch 純語法、對單一最佳抽象有最優性保證、速度極快；babble 帶等式理論、對保語義變體魯棒、可一次學多個抽象但犧牲最優性。固化引擎的去重層可以「Stitch 打底（快、精確）＋ babble 補等式魯棒性」組合思考——這也正是本文作者列出的未來方向（把 Stitch 的 top-down 搜尋與 LLMT 結合）。
  • 更廣義地：equality saturation 把「符號神經網路計算圖」中確定性節點的等價重寫做成一等公民，對 ai_core §1「多數確定性節點」的可維護性與去冗餘有直接工程參考價值。適合做 抽象庫去重、程式重構／反編譯、DSL 特化、library learning 的人。
