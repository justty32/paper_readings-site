作者：Kai-Chen Cheng, Haejun Han, David Q. Sun（AI/ML@Eight Sleep）

日期：2026-05，ICML 2026 Workshop on Structured Data for Health (SD4H)

arXiv：2605.29652

論文／訪談原始來源

《Think Fast, Talk Smart：為結構化健康文字生成分割確定性與神經計算》重點摘要

一句話概括

Think Fast, Talk Smart (TFTS)：Eight Sleep 提出的系統性分割框架，把結構化健康文字生成（睡眠健康洞察）拆成確定性 Python 層（數值比較、排名策略、證據閘控歸因、寫入介面）＋一次有界 LLM 寫入呼叫，讓程式碼「想得快」處理穩定重複分析，LLM 只負責「說得好」把已驗證事實轉成自然語言。在 280 用戶夜晚、6 模型上，TFTS 達成比 zero-shot/few-shot 單次呼叫 baseline 更低的數值錯誤（0.7%）、指令遵循錯誤（<3%） 與端到端成本。層替換實驗揭露非顯而易見的失敗點：寫入介面本身即使上游全是確定性，若由 LLM 生成仍重新引入錯誤（NumErr 升至 4.8%、AttrErr 升至 10.7%）。

解決什麼問題

LLM 被廣泛用於穿戴式裝置摘要、實驗室報告、用藥指導等結構化健康記錄轉文字，但流暢不足以交付——必須忠於來源數據、解釋需證據支撐、遵循給定策略、產生機器可讀輸出，且足夠便宜以支援重複使用。既有 prompting 研究（CoT、self-refine、PAL、RAG、tool-use、DSPy pipeline）都在改善 LLM 呼叫內部或周圍的事，但迴避一個更根本的系統問題：**重複健康產出任務的哪些責任應該從 runtime LLM 呼叫中移除？**當分析步驟穩定且可驗證（比較測量值與基線、選擇該凸顯什麼、決定哪些解釋有證據支撐），runtime prompting 可能就是錯誤的抽象。

核心方法

  • 四階段分割模式：①結構化輸入→②確定性分析模組（格式化數據、數值比較、排名策略、證據閘控歸因、壓縮事實成證據介面）→③有界 LLM 寫入器（schema 約束下的最後一次 LLM 呼叫，僅負責把已驗證事實轉成面向用戶的文案）→④確定性評估與組裝。寫入器不可重新計算數字、不可新增標籤、不可做證據閘控——那些都由程式碼鎖定。
  • 層替換協議（layer-replacement protocol）：為做機制分析，一次只把一層分析模組換成 LLM 生成的型別化中間產物，上游保持確定性。這比從寫入器 prompt 裡移除某層更嚴格且公平：模型只做一個有界中間任務，而非在寫最終 JSON 時補救遺失的上下文。四種替換條件：Replace Comparison、Replace Ranker、Replace Attribution、Replace Handoff。
  • 數據與模型：280 用戶夜晚（20 位活躍用戶）；評估 GPT-5 nano、GPT-4o mini、GPT-OSS-20B、GPT-OSS-120B、Haiku 4.5、Sonnet 4.6。替換條件每夜晚兩次 LLM 呼叫（一次產出中間產物＋一次最終寫入），TFTS 與 prompting baseline 各一次。
  • 評估指標：全部從儲存的 JSON trace 確定性計算。SchemaErr（JSON parse/schema 錯誤率）、NumErr（數值宣稱不被來源事實庫支持的比率）、SelErr（選擇的 metric 違反選擇規則的比率）、AttrErr（歸因不被證據閘控輸入支持的比率）。

關鍵發現

  1. 錯誤－成本前沿（Error-Cost Frontier）：TFTS 在所有 6 模型上佔據低錯誤低成本的左下角。NumErr 平均 0.7%（最差模型僅 2.0%），指令遵循錯誤 <3%。Structured Zero-Shot baseline SelErr 高達 61–95%，Structured Few-Shot 改善 schema 和歸因但 SelErr 仍 63–71%——prompting 沒有可靠重現驅動洞察的重複分析決策。
  2. 層替換隔離失敗模式：各分析責任在 LLM 接手時以不同方式失敗：Replace Comparison→NumErr 升至 16.9%（數值幻覺）;Replace Ranker→SelErr 65.8%（排名策略退化）;Replace Attribution→AttrErr 24.5%（加入無證據支持的因果語言）。算術、排名策略、證據閘控歸因各自不同地失敗，且各自更容易用確定性程式碼驗證而非用 prompted generation。
  3. 寫入介面的非顯而易見性：Replace Handoff（上游全確定性、僅把壓縮證據→寫入器的介面換成 LLM 生成）使 NumErr 升至 4.8%、AttrErr 升至 10.7%。這暗示「已驗證事實與文句之間的介面本身就是可靠性機制的一部分」，不只是 prompt 格式問題。最終寫入器可用，但約束它能說什麼的證據封包必須保持確定性。

設計規則（對 ai_core 的直接接點）

  • §2「工廠/消費者分工」：TFTS 的確定性分析層＝工廠（code owns recurring analysis），LLM 寫入器＝消費者（LLM expresses verified facts within bounded interfaces）。對應 ai_core 中「把可驗證、穩定、重複的工作從 runtime LLM 移除」的核心原則。
  • §3.6「固化時機」：本論文直接給出「何時該固化」的操作判準——當分析步驟跨輸入幾乎不變（比較測量值與基線、選擇凸顯什麼、決定哪些解釋有證據）、穩定可驗證（可用確定性指標檢查）、且 runtime prompting 無法可靠重現這些決策時，就該寫成確定性程式碼。這與 Compiled AI (2604.05150) 的「邊界案例覆蓋後完全取代」形成姊妹論點：Compiled AI 是事後取代，TFTS 是事前分割。
  • 寫入介面即約束邊界：Replace Handoff 的發現直接對應 ai_core「介面設計即可靠性設計」——證據封包的型別、內容與邊界本身就是防禦層，不能假設「上游正確 LLM 就會跟著正確」。

局限

  • 僅在睡眠健康領域驗證，未擴展至其他結構化健康場景（檢驗報告解釋、用藥遵從教練、慢性病報告）。需要開放式臨床推理、診斷或治療計畫的任務可能不適用此分割。
  • 評估的是對確定性參考系統的保存（preservation），非臨床最優性。SelErr 是與應用選擇規則的偏離，非 ground-truth 健康重要性；AttrErr 是歸因策略遵循，非生物因果性。人類有用性與感知個人化的評估是互補的未來工作。

對讀者的價值

  • 與 ai_core 方向的直接實證：這是少數**明確論證「哪些 LLM 責任該移回程式碼」**的實證論文，提供具體錯誤分解（算術 vs. 排名 vs. 歸因 vs. 介面）而非模糊的「確定性更好」。
  • 與 2604.05150 Compiled AI（LLM workflow→確定性 Python）、2601.16286 SemanticALLI（意圖快取取代 LLM 節點）、2511.15715 Graph-Memoized Reasoning（子圖 memoization）並讀，形成「從 runtime LLM 撤出」的三種策略光譜：事前分割（TFTS）、事後取代（Compiled AI）、快取重用（SemanticALLI/Graph-Memoized）。
  • 定位：ICML 2026 SD4H workshop、工業系統論文（Eight Sleep）、小規模但機制分析扎實（層替換協議），適合做 LLM 系統架構、健康 NLP、確定性/神經混合系統、ai_core §3.6 固化時機 的人。
