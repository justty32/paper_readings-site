論文／訪談原始來源

《CausalEvolve：以因果暫存器達成開放式發現》重點摘要

一句話概括

CausalEvolve 在標準演化式 LLM agent 中加入一個因果暫存器（Causal Scratchpad）——一個主動推理框架，對演化歷史中的「驚喜模式」（surprise patterns）進行溯因推理（abductive reasoning），產生可操作的因果假設來指引後續程式突變方向，從而突破效能高原、解決重複搜尋的停滯問題，在四個開放式科學與演算法發現任務上顯著超越標準演化基線。

解決什麼問題

演化式編碼 agent（AlphaEvolve、AI Scientist 等）以生成-突變-評估循環解決開放式任務，但有兩個根本缺陷：①缺乏目標性引導——突變僅由效能分數或啟發式驅動，等同隨機探索；②歷史知識無法積累——agent 無法從過往演化軌跡中提煉結構化教訓，導致效率遞減、搖擺行為（在效能天花板附近反覆重訪無效方向）。開放式演化最致命的是停滯（stagnation）——agent 永遠在局部最優附近徘徊而無法發現新穎解決方案，這是標準演化 agent 沒有內建機制可解決的問題。

核心方法

  • 因果暫存器（Causal Scratchpad）：一個動態維護的因果知識結構，記錄「哪些因素因何種因果機制驅動效能提升」，由三個子模組驅動： ①結果層級因素識別：在演化早期或開始前，向 LLM 提問以識別可能影響目標指標的高層概念/結構因素（如程式結構、演算法選擇、記憶體配置模式等），建立初始因果假設集。 ②驚喜模式檢測：在演化運行中，當出現意外的效能躍升、暴跌或湧現行為——定義為偏離移動平均的顯著離群值——agent 將其標記為「驚喜事件」並觸發溯因推理。 ③溯因推理與假設生成：針對每個驚喜事件，CausalEvolve 對演化歷史進行溯因（abductive reasoning）——「假如這個新的因果因素是活躍的，是否能最簡潔地解釋這個驚喜結果？」——產生新的因果假設，更新因果暫存器。
  • 因果引導的程式突變：更新後的因果暫存器為後續程式突變提供明確的方向提示——LLM 不再僅依賴效能分數進行隨機突變，而是用因果假設為條件，定向探索高潛力方向（例如：「因為假設 X 成立，請產生一個在維度 Y 上最佳化的變體」）。
  • 與標準演化的整合：CausalEvolve 是演化流程的外掛式增強，不改變基礎演化算子（交配、突變、選擇），僅在突變前插入因果推理步驟，因此可與任何演化式 LLM agent 框架相容。

結果（4 個開放式科學/演算法任務）

  • 跨任務一致超越：在所有四個 benchmark 上，CausalEvolve 展現更優的演化樣本效率——以更少的世代數發現效能更高的程式變體。
  • 突破效能高原：標準演化 agent 在達到一定效能後陷入停滯；CausalEvolve 則在相同或更少評估次數內突破這些高原，發現標準演化完全未發現的更高分數解決方案。
  • 消融實驗：移除溯因模組（變回純分數驅動演化）導致效能在早期即飽和；移除因素識別（僅在驚喜時推理）降低了高層結構創新的頻率，證明因果暫存器的三個子模組各自提供不可替代的貢獻。

局限

  • 依賴 LLM 溯因能力：因果假設的品質受底層 LLM 的推理能力限制，弱模型可能產出無用或誤導性假設。
  • 任務範圍限於程式演化：尚未在非程式領域（如化學合成、材料設計）驗證因果暫存器的泛化性。
  • 驚喜檢測的門檻敏感度：離群值閾值需要針對特定任務調整，缺乏自適應校準機制。
  • 未涉及多 agent 協作：僅測試單一 agent 演化場景，多 agent 情境下的因果知識共享未探索。

對讀者的價值

  • 因果暫存器是 ai_core §3.6 固化引擎的核心對應：它將演化過程中累積的「為什麼有效」結構化為可操作的因果知識，防止知識庫（skill library）退化為無結構的經驗堆積。CausalEvolve 的溯因推理機制——將驚喜事件轉化為因果假設——可被視為 §3.6 中「演化作為新抽象發現引擎」的具體實作。
  • 與 2509.19349 ShinkaEvolve（新穎性拒絕取樣 + 父代選擇）並讀：ShinkaEvolve 維持多樣性，CausalEvolve 提供方向性——兩者互補。與 2604.01658 CORAL（多 agent 非同步演化 + 共享記憶）並讀：CORAL 的共享記憶可作為因果暫存器的跨 agent 廣播通道。
  • 定位：演化式 AI + 因果推理 + LLM agent 的交叉點，適合做開放式發現、AI Scientist、程式合成、演化計算、因果機器學習的人。
