一句話概括

MASS（Multi-Agent System Search）：先用實證分析證明「prompt 優化」與「拓撲優化」對多智能體系統（MAS）表現皆有關鍵影響、且多數拓撲維度其實無效，再據此提出三階段交錯（interleave）優化框架——① block-level 局部 prompt 暖身、② 在以影響力剪枝過的空間內做 workflow 拓撲搜尋、③ workflow-level 全局 prompt 微調——在 8 個推理／多跳理解／程式任務上，用 Gemini 1.5 Pro/Flash 平均分別比最強基線再高約 8–9 個百分點。

解決什麼問題

既有 MAS 自動化研究幾乎都只優化單一維度：DSPy／MIPRO 之類的 prompt optimizer 只調節點內容、不碰拓撲；ADAS／AFlow 之類的拓撲搜尋法用 LLM 或 MCTS 生成新工作流，卻仍套用手寫 prompt，未把 prompt 當可優化對象。作者先做前置分析：把 prompt 優化（MIPRO）與「單純擴大 agent 數量」（self-consistency／self-refine／debate）在相同推理 token 成本下比較，發現優化 prompt 的 token 效益顯著優於單純堆疊 agent；接著逐一測試各類拓撲對 HotpotQA、LiveCodeBench 的增益，發現只有一小部分拓撲維度真正有正面貢獻（如 HotpotQA 上只有 debate 帶來 3% 增益，其餘持平甚至倒退）。結論是：prompt 與拓撲都重要，但各自的有效子空間都很小，因此需要一套能同時、有效率地聯合搜尋兩者的框架，而非各自為政。

核心方法

  • 搜尋空間形式化：定義建構區塊集合 𝒜={aᵢ}，每個區塊由其參數化維度描述——Aggregate（N_a 個並行 agent＋聚合，涵蓋 majority vote／self-consistency）、Reflect（N_r 輪自我反思與精修，涵蓋 Self-Refine／Reflexion）、Debate（N_d 輪全連結多 agent 辯論）、Custom（如 Summarize，N_s 輪長文摘要以增強長上下文能力）、Tool-use（N_T∈{0,1} 的二元工具插入決策，如 RAG 檢索器或程式碼執行器）。目標是求 𝒲*(a) = argmax_{a∼𝒜} E_{(x,y)∼𝒟}[f(𝒲(a(x)), y)]。
  • 影響力量測與剪枝：對每個維度 aᵢ 先各自做局部 prompt 優化得 aᵢ*，計算增量影響力 I_{aᵢ} = ℰ(aᵢ*)/ℰ(a₀*)（相對於單一暖身 agent a₀* 的相對增益），再以 p_a = Softmax(I_a, t)（t 為溫度、經驗設 0.05 以銳化選擇機率）決定每個維度被保留進搜尋空間的機率——高影響力維度更常被納入拒絕採樣（rejection sampling）出的候選拓撲。
  • 三階段演算法（Algorithm 1）：
    1. [1PO] Block-level Prompt Optimization：先用 prompt optimizer 𝒪（預設 MIPRO，可替換 APE／DSPy）暖身單一 agent a₀ 得 a₀*；再對搜尋空間中每個維度 aᵢ，在「最小可行拓撲」（如 debate 用 2 個 predictor＋1 個 debator）下、以 a₀* 為條件各自做局部 prompt 優化得 aᵢ*，同時記錄各自的驗證集表現以算出 I_{aᵢ}。
    2. [2TO] Workflow Topology Optimization：依 I_a 算出的選擇機率剪枝出 𝒜_p；在總 agent 數不超過預算 B 的限制下（𝒩(a)<B），對 𝒜_p 做拒絕採樣，並依固定規則序（[summarize, reflect, debate, aggregate]）把採樣到的區塊、連同其在 Stage 1 已優化好的 prompt，組裝成候選 workflow 𝒲_c；候選在驗證集上評估並取最佳 𝒲_c*。
    3. [3PO] Workflow-level Prompt Optimization：以 𝒲_c* 為整體，再跑一輪聯合 prompt 優化 𝒲* = 𝒪_𝒟(𝒲_c*)，讓 prompt 進一步針對「agent 之間的相互依賴」做微調，而非停留在各自獨立優化的狀態。
  • 框架對 prompt optimizer 與拓撲搜尋演算法皆為即插即用（plug-and-play），實驗預設用 MIPRO，並在附錄消融 APE、DSPy 等替代品。

結果

  • 主表（Table 1，8 個任務：MATH／DROP／HotpotQA／MuSiQue／2WikiMQA／MBPP／HumanEval／LiveCodeBench）：Gemini 1.5 Pro 上 MASS 平均 78.79%，勝過最強基線 Multi-Agent Debate（70.26%）、ADAS（69.72%）、AFlow*（僅部分任務可比）；Gemini 1.5 Flash 上 MASS 平均 74.30%，同樣大幅勝過 Multi-Agent Debate（65.91%）。單項如 MATH 84.67 vs 基線最佳 80.00（ADAS）、MuSiQue 51.40 vs 46.00（Debate）、LiveCodeBench 82.33 vs 73.67（Debate）。
  • 逐階段消融：相對單一 agent 的 APO（MIPROv2）基線，Stage 1（block-level）平均再提升約 6%；Stage 1→2（拓撲搜尋）再提升約 3%；Stage 2→3（workflow-level prompt 微調）再提升約 2%——且消融證實「不先做 prompt 暖身」或「不做影響力剪枝」直接做拓撲搜尋，效果都明顯較差。
  • 對照圖優化基線 GPTSwarm：MASS 在 MATH／HumanEval 上平均 88.2%（Pro）／82.9%（Flash），對比 GPTSwarm 的 80.5%／67.0%——作者將差距歸因於 GPTSwarm 側重「從全連結圖剪成稀疏圖以省推理成本」而非任務表現本身。
  • 最佳架構案例（MATH，Fig. 7）：Stage 1 顯示 debate 是表現最好的單一區塊，但 Stage 2 搜尋後發現「更多並行 agent 聚合（aggregate，最終選 9 個並行 agent，無 reflect／debate）」反而優於 debate 拓撲，驗證了「局部最佳未必是全局最佳、必須真正搜拓撲」的論點。

局限

  • 論文自陳：目前拓撲空間（並行／串行／混合連結）雖涵蓋多數常見設計，但仍可能遺漏更稀疏、非全連結的通訊模式（如近期研究對 agent 間通訊做剪枝）；拓撲搜尋用拒絕採樣＋影響力剪枝，換更先進的貝氏優化等方法可能更有樣本效率；prompt 優化器本身也未接入基於錯誤日誌的文字回饋（如 ProTeGi／TextGrad），留給未來工作。
  • 成本分析（附錄 C.3）顯示：1PO 成本隨區塊數 J 線性增長（每區塊 M 個候選 × K 輪評估 × 該區塊的 agent 呼叫數）、2TO 成本為 N 個候選拓撲各自的 agent 呼叫數總和、3PO 成本隨最終 workflow 的 agent 數線性增長——三階段疊加後，訓練成本與 ADAS／AFlow 等自動化基線相當，但驗證集僅 50–60 筆、拓撲候選數僅 10 個，屬於刻意壓縮過的小規模搜尋，能否線性放大到更大的建構區塊庫、更貴的工具（如需真的跑測試套件）或更大驗證集，論文並未驗證。
  • 依賴自動化評估指標 ℰ 才能跑完整流程（需要 (x,y) 驗證集），對缺乏乾淨標籤、只能用人類或 LLM-judge 打分的任務，適用性未知。
