論文／訪談原始來源

《基於自動機的語言模型解碼約束（Automata-based constraints）》重點摘要

一句話概括

把「受約束解碼」整個問題重述為自動機理論：核心洞見是**「detokenization ＝有限狀態轉導（FST）」——一旦把 token→字元的還原寫成一個 detokenizing FST T_V，就能用標準的 FST-FSA／FST-PDA 組合（composition） 把「與詞彙無關的字元級約束（regex→FSA、文法→PDA）」自動接到「與詞彙相關的 tokenizer」上，得到一個接受 token 序列的閉式解**自動機，解碼時逐步遮罩 logits 即可；相較先前工作（Outlines）在自動機上疊客製方案，本文純自動機路線編譯快約 7,000×、可證明正確、且模組化可擴充。

解決什麼問題

LM 常需生成形式語言（結構化資料、API 呼叫、程式碼），但即使微調也不保證合規，對適合大規模部署的小模型尤然，且微調對罕見／任務專屬格式不划算。理想解法是「約束 LM 只產生合法輸出」，但被 tokenization 嚴重複雜化：資料驅動的子詞 tokenizer 切分對形式語法既有歧義又錯位（如 foo(x="bar") 可能被切成 foo(、x="、ba、r、")，token 跨越多個語法單元）。粗暴強迫 tokenization 對齊語法會扭曲 LM 評分、倒置排名（附錄 A 的 foo(123) vs bar(456) 例）。先前 Outlines 以客製 indexing 處理，但有速度、正確性、可擴充性問題。

核心方法

  • 貢獻一（理論樞紐）：把 detokenization 表述為 FST（演算法 1）——從詞彙表建一個 token→字元的轉導器 T_V，共用前綴合併成 trie 結構。
  • 貢獻二（正則約束）：對任意接受字元的 regex FSA A_R，組合 A_{R∘V}=A_R∘T_V 即得接受 token 的 FSA（演算法 2）。此為閉式解，解碼每步只需索引／切片／基本算術，可在加速器上低延遲執行。乾淨分離關注點：T_V 與詞彙相關可預算、A_R 與詞彙無關可跨 LM 移植——因組合是通用接合器，兩半皆可各自替換。
  • 貢獻三（實用擴充）：以特命名捕獲群組實作。**終端標籤（terminal labels）**解決萬用字元 /./ 造成近 |V| 條出邊（|V|>10 萬）的高分支問題（預算好的 token 遮罩整批套用）；語法糖如 SUBSTRING_OF 把 O(|u|²) 的 regex 規格降到 O(|u|)。另有 QUOTED_TEXT、DELIMITED_LIST 等。
  • 推廣到文法（PDA）：FST 與 PDA 亦可組合，故同一套方法（演算法 3，多維護一個堆疊）延伸到確定性上下文無關語言（涵蓋 LL(k)/LR(k)，即多數程式語言語法）；非確定性 PDA 無法通用確定化，故偵測到即報錯交作者改寫。token 可自然跨越（非）終端邊界，保留 tokenization 自由。

結果

  • 編譯加速（vs Outlines，表 2）：多選 7,970×、ISO 日期時間 7,110×、IP 位址 6,850×、引號字串 13,400×、JSON 物件 7,240×；每步開銷加速 6.5×～33.6×。粗略延遲：JSON 編譯 Outlines 數十秒 vs 本系統數毫秒。加速主因是重述為自動機後可直接用 OpenFST 高度優化實作（類比 NumPy）。
  • 正確性（GPQA + Gemma，表 3）：無約束時 schema 合規率 Gemma-2B 0.09、Gemma-7B 0.65；加約束後皆達 1.0（完美合規）。
  • 應用：符合特定 schema 的 JSON 竟是正則語言（schema 限制遞迴）→ 可自動由 schema 生 regex；Python dataclass 反射生約束並解析回實例；約束推測解碼的近似模型以提高接受率（需可回捲、共享懲罰）。

局限

  • 對 PDA／文法探索仍淺（迄今聚焦更穩健的 FSA）：文法須小心撰寫以避免非確定性 PDA（如 LL(k) 無法解析左遞迴），系統只能報錯要作者改寫。
  • 確定性上下文無關是嚴格子集，無法表達完整上下文無關（雖有限 token 預算會縮小此差距）。
  • 貢獻偏概念，實證僅 Gemma 上小規模驗證速度與合規率。

對讀者的價值

  • 直擊 ai_core §5「受約束填碼」的理論統一：ai_core 第一目標是程式碼助手（上層結構化抽取生資產、下層受約束填碼）。本篇提供了那個「下層」最乾淨的通用表示——自動機即約束的母框架：regex 約束＝FSA、CFG／文法約束＝PDA，兩者靠同一個「detokenization＝FST」的組合機制接到任意 tokenizer 上。ai_core 若要把「schema-guided JSON／API 呼叫／dataclass 填碼」做成可靠函數，這正是把 Outlines(FSM) 與 SynCode(CFG) 兩條線收攏成單一理論框架的關鍵——不必為每種約束或每種 tokenizer 各寫客製方案。
  • 對「把 LLM 呼叫包成可靠函數」的啟發：合規率從 0.65→1.0 意味著輸出格式合規可由建構（construction）保證而非靠模型自律——這把「解析下游 LLM 輸出」從機率事件變成確定性事件，正契合 ai_core「逐步剃除對 LLM 依賴」的北極星（格式正確性徹底移出 LLM 職責）。tokenization 對齊的評分扭曲問題（附錄 A）也提醒：約束設計不當會反噬取樣品質，是把約束納入可靠函數時的必查陷阱。
  • 與固化引擎（§3.6）的呼應：「符合 schema 的 JSON 是正則語言」這類洞見，示範了如何把一個看似需 LLM 反覆處理的生成任務結晶成確定性自動機——即把約束從執行期的 LLM 判斷固化為編譯期的靜態結構，方向上與 ai_core 最硬的固化引擎同構。
  • 定位：理論／方法論文（Google DeepMind，COLM 2024），歸 I 類。適合做 受約束解碼、結構化輸出、schema/JSON/程式碼生成、tokenization 對齊 的人；建議與 Outlines(FSM)、SynCode(CFG) 對照閱讀，本篇是收攏兩者的理論母框架。
