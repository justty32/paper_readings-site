論文／訪談原始來源

《SkillRL：透過遞迴技能增強強化學習來演化代理》重點摘要

一句話概括

SkillRL 將原始軌跡蒸餾為階層式技能庫（SkillBank），並在強化學習過程中與代理策略遞迴共演化，使 LLM 代理從過往經驗中抽象出可復用的行為規則，而非僅記憶冗餘軌跡。

解決什麼問題

LLM 代理在長期規劃任務中面臨一個根本困境：每次都從零開始，無法從過往成敗中學習。現有的記憶機制大多直接儲存原始軌跡日誌，但這些軌跡充滿冗餘、雜訊與任務特定的偶然細節，既消耗上下文 token 配額，又難以泛化到新場景。

人類專家不會死背每個情境的每個動作，而是形成技能——可壓縮、可復用的策略抽象。SkillRL 正是將這一洞察系統化：它把經驗（包括成功與失敗）蒸餾成結構化的技能，並讓技能庫與代理策略在 RL 訓練中相互增強，形成良性循環。

核心方法

  • 經驗蒸餾（Experience Distillation）：同時保留成功軌跡與失敗軌跡，對前者提取關鍵決策模式，對後者合成「失敗教訓」（失敗點、錯誤推理、應做之事、預防原則），實現 10-20 倍的 token 壓縮。
  • 階層式技能庫（SkillBank）：將技能分為「通用技能」（跨任務的策略原則，如系統性探索、進度追蹤）與「任務特定技能」（領域專屬的動作序列、常見失敗模式），每個技能包含名稱、原則描述、適用條件，支援語義檢索。
  • 冷啟動監督微調（Cold-Start SFT）：用教師模型生成示範軌跡，教會代理如何檢索、解讀並應用技能，作為 RL 訓練的起點。
  • 遞迴技能演化（Recursive Skill Evolution）：在每個驗證 epoch 後，根據失敗軌跡生成新技能或修正現有技能，技能庫從初始 55 項成長至 100 項；使用 GRPO 進行策略優化，技能增強後的上下文顯著加速收斂並提高效能天花板。

關鍵發現/數據

  • ALFWorld 成功率 89.9%（超越 GRPO 基線 12.3%），WebShop 成功率 72.7%，搜尋增強 QA 平均 47.1%。
  • 以 Qwen2.5-7B-Instruct 超越 GPT-4o（+41.9%）與 Gemini-2.5-Pro（+29.6%），證明技能學習可補償模型規模。
  • 移除階層結構下降 13.1%；用原始軌跡取代技能庫下降 25%；冷啟動 SFT 移除下降 20%；關閉動態演化下降 5.5%。
  • 技能蒸餾將提示上下文減少約 10.3%，同時效能優於原始記憶方法。

局限

  • 技能蒸餾品質仰賴教師模型（使用 OpenAI o3），強教師模型在部分場景中可能不可得或成本高昂。
  • 實驗環境為文字式模擬（ALFWorld、WebShop），尚未在真實機器人或網頁環境中驗證。
  • 技能庫演化依賴人工定義的驗證閾值與失敗軌跡收集策略，缺乏完全自動化的門檻調節機制。
  • 目前僅驗證於單一基礎模型（Qwen2.5-7B），跨模型規模的泛化性尚未充分探討。

對讀者的價值（ai_core 接點）

SkillRL 的核心架構直接對應 ai_core 框架的多個關鍵模組。其技能庫（SkillBank）本質上是一個動態知識底座，從經驗中自動提取可復用規則，與 ai_core 的 §3.6 固化引擎形成互補：固化引擎負責將驗證過的推理模式沉澱為永久知識，而 SkillRL 提供了從軌跡到技能的蒸餾管線（把多步軌跡壓縮成可檢索的技能條目）。

SkillRL 的遞迴演化機制也為 方向一（技能庫退役與收斂） 提供了直接的操作化路徑：它不僅生成技能，還透過每次驗證 epoch 的失敗分析來修剪低效用技能並生成新技能，實現了「技能庫隨策略成熟而收斂」的動態。這對應了 ai_core 中關於技能生命週期管理（生成→驗證→啟用→退役）的設計需求。

此外，SkillRL 的階層式技能組織（通用 vs. 任務特定）與 ai_core 的 §3.4 憑證准入（基於任務語義相似度的技能准入控制）高度共鳴——它使用語義相似度閾值來篩選適用技能，正是憑證准入的一種實現形式。其 GRPO 策略優化中的 KL 正則化錨定於 SFT 參考策略，也為 §3.6 的「安全約束下的策略更新」提供了具體的訓練正規化方案。
