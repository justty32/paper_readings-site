論文／訪談原始來源

《MeCo：藉由相似任務記憶化增強 LLM 驅動的多機器人協作》重點摘要

一句話概括

LLM 多機器人協作 + 任務級記憶化（memoization）：將「快取並復用」原則引入 LLM 驅動的多機器人任務規劃——當新任務與快取中的歷史任務相似時，S-Planner 直接基於參考軌跡生成運動計畫而無需調用 LLM，相似度測試則根據機器人工作空間重疊程度分為高/低兩類策略，在 MeCoBench 上實現平均 30% 成功率提升、55% 規劃時間節省、最高 70% token 消耗降低。

解決什麼問題

現有 LLM 驅動的多機器人協作方法（RoCo、EMOS、ReCA 等）將每個任務視為獨立單元，即使面對相同或相似的任務仍從頭調用 LLM 重新規劃，造成大量 token 消耗與規劃延遲。不同於簡單的「完全相同任務復用」，辨識「相似但不完全相同」的任務並復用其規劃——尤其是在多機器人環境中——更具挑戰性：目標物體的位置與種類可能不同，但核心目標（如分類包裹、清掃物品）與固有約束（機器人數量、固定資源）保持不變。

核心方法

  • 雙模式相似度測試：根據機器人工作空間重疊程度將任務分為兩類——低重疊任務（如 Sweep Floor、Sort Cubes、Make Sandwich、Arrange Cabinet）使用點映射 Π 保證目標物體僅在同一區域內進行受限幾何變換；高重疊任務（如 Pack Grocery、Move Rope）使用重複使用率 α（歷史可復用軌跡長度/目前任務所需總長度）衡量，並證明成功率隨 α 單調遞增。
  • S-Planner（相似運動規劃器）：低重疊任務直接繼承動作序列並根據姿態差異決定復用現有軌跡或調用 RRT 重新規劃；高重疊任務進行回溯檢查（back checking）與碰撞檢查（collision checking）以截取歷史軌跡的可復用段落，再自適應選取關鍵採樣點引導 RRT 規劃。
  • 連續規劃模組：當 S-Planner 失敗時，LLM 從失敗步驟繼續規劃而非從頭開始——將當前環境狀態存入 prompt，使 LLM 僅修補失敗部分。
  • 選擇性快取與去重：基於 LFU 策略的快取淘汰機制——快取滿時保留使用頻率最高的 k 個任務，並過濾掉有效步驟數超過基線的冗餘任務（如物體先放置於錯誤位置再修正）。

關鍵發現/數據

  • 隨機場景（S1）：成功率平均提升 29%，規劃時間減少達 78%（Make Sandwich），token 消耗平均降低 73%，其中 Move Rope/Make Sandwich/Sort Cubes 降幅超過 90%。
  • 完全相似場景（S2）：成功率平均提升 32%，token 消耗平均降低 82%，Move Rope 規劃時間減少 77%。
  • 完全相異場景（S3）：效能與基線持平——MeCo 不引入額外開銷，僅在低相似度時增加約 6% 規劃時間。
  • 消融實驗：移除相似度測試後成功率平均下降 12%、token 增加最多 189%（Move Rope）；移除 S-Planner 後成功率下降約 30%、規劃時間暴增 222%；移除連續規劃模組使 LLM 重複推理導致 token 與時間顯著上升。
  • 快取容量效應：高重疊任務存在最優快取大小（Pack Grocery 約 30）、超過後搜尋開銷反彈；低重疊任務則快取越大越好。
  • 選擇性快取消融：移除後成功率下降 33%、規劃時間增加 32%、token 上升 47%。

局限

  • 相似度閾值 α/p 與最大快取任務數 k 需針對不同任務手動調整，缺乏自動化機制——作者建議未來探索自監督或 meta-learning 自動學習最佳參數。
  • 目前僅依賴文字描述與空間資訊，未整合視覺/聽覺等多模態輸入。
  • 快取策略僅基於使用頻率（LFU），未考慮任務複雜度或規劃成本等更豐富因素。
  • 實驗限於桌面操作臂場景（RoCoBench 六項任務），未擴展至移動機器人導航或異構機器人協作。
  • 非結構化場景中低重疊任務的區域劃分假設可能不成立——作者建議退階為高重疊模式處理。

對讀者的價值（ai_core 接點）

  • 本文是 ai_core §3.6 固化引擎的直接示範與理論支撐：MeCo 的「任務記憶化」即為固化復用——當系統辨識出當前任務與歷史任務高度相似時，將 LLM 推理結果固化為確定性 S-Planner 軌跡，跳過神經推理環節，僅在失敗時回退至 LLM。這正是固化引擎的核心運作邏輯：行為一旦被驗證為可復用模式，即從「每次推理」退化成「查找+套用」的確定性程式碼路徑。
  • 固化判定閾值：MeCo 的相似度閾值機制（α）為固化引擎提供了可操作的「是否固化」判定標準——當重用率超過閾值，固化是安全的；低於閾值則保持 LLM 推理。這可作為 ai_core 行為固化模組的工程模板。
  • 快取策略作為固化記憶管理：MeCo 的選擇性快取與 LFU 去重機制直接對應固化引擎中的「固化記憶管理」——哪些行為值得保留、何時淘汰、如何保證多樣性以避免過擬合。
