論文／訪談原始來源

On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification 重點摘要

一句話

這是一篇反面／失效分析論文：重新評測兩個代表性 memory-based self-improving 方法（AWM、ReasoningBank）後發現，只要把評測拉開成多次 run、打亂任務順序，這些方法的「進步」多半消失甚至倒退，根源之一是 memory construction 階段對環境與任務的 underspecification。

方法：三軸重新評測 + 記憶內容人工稽核

作者在 WebArena（812 題，6 domain）、VisualWebArena（910 題，3 domain）、SCUBA（267 題，3 domain，人工排除因網站更新失效的題目）上，用更強的 baseline harness 與 GPT-5-mini 作 backbone／memory construction model 重跑 AWM 與 RBank，並直接用 ground-truth reward 建構 memory（而非原論文用的 LLM-Judge 代理 reward，作者稱其雜訊過大會混淆分析）。相較既有工作只跑單一 run、固定預設任務順序，本文刻意加兩軸：(1) 每設定跑 3 次獨立 run，報告 pass@1 平均、標準差、best-worst gap；(2) 除預設順序外，另加兩組隨機打亂順序（Shuffle-1、Shuffle-2）。為釐清退化成因，作者人工檢視 RBank 生成的 memory 條目，歸納出 environment underspecification（環境不支援 API／人工確認，agent 卻反覆寫入並提取相關記憶）與 task underspecification（模糊任務描述誘發誤解、過度推理、錯誤記憶擴散，如 Map domain 把不可靠的 Haversine 公式估距寫成慣用策略並持續放大）兩類失效模式，再嘗試在 memory construction 階段加入 rubric 分數、環境回饋、prompt 修訂三種額外資訊緩解。

作者報告的實驗與資料限制

Variance（§3.2，Table 1）：24 組 baseline vs. 自改方法對比中，17 組（約 71%）在導入 AWM／RBank 後標準差上升，其中 11 組相對增幅超過 50%。WebArena GitLab domain（180 題）：baseline best-worst gap 4.4%（標準差 1.98%），RBank 拉大到 7.78%（標準差 3.34%）；Map domain（109 題）RBank best-worst gap 達 8.26%（標準差 3.89%，相對 baseline +200%）；VWA、SCUBA 的 domain-level best-worst gap 分別最高到 2.4%／6.7%。Table 3（3-run 平均 pass@1）：baseline 在 WebArena／VWA／SCUBA 分別為 54.8%／54.9%／49.6%，AWM 僅 -0.7／-0.4／+0.5 個百分點，RBank +1.5／+0.7／+1.5 個百分點；RBank 在 WebArena 上 +1.5% 的平均增益經 unpaired t-test（3 run）p=0.23，作者稱統計上不顯著。Table 2 對照舊文獻：AWM 原論文（Claude-3.5-Sonnet，812 題）baseline 32.7%→+AWM 36.3%；RBank 原論文（Gemini-2.5-Pro，684 題子集）baseline 46.7%→+RBank 53.9%；本文更強的 no-memory baseline 已達 54.8%／55.3%，作者稱這說明初始化夠強時自改方法的邊際效益遞減。Task order（§3.3，Fig. 2-3）：預設任務順序在 WebArena／VWA 呈現隱含 easy-to-hard curriculum（前段 pass rate 約 75%，task ID 超過 150 後掉到 40% 以下）；Shuffle-1 下 WebArena 整體 pass rate 從 54.8% 掉到 AWM 49.1%、RBank 49.8%，8 組設定中 6 組出現顯著退化；摘要稱預設順序下 RBank 平均 +1.5%，打亂後平均 -4.5%。Underspecification 緩解（§4.2，Fig. 5）：三種額外資訊合併（+All）在 Shuffle-1 下把 RBank 從 49.8% 拉到 52.7%（+2.9 個百分點），Shuffle-2 下 +1.1%，Default 順序下持平；作者稱這只補回打亂造成之退化的 31%，其餘 69% gap 仍未解釋。作者自報限制（Appendix A）：只評測 web-browsing 領域的兩個 memory-based 方法，未涵蓋其他自改方法或領域，也未評測最新記憶管理技術；memory 人工檢視只是質性抽樣，非窮舉，可能還有未記錄的失效模式。以上數字均為作者自報，未經本檔驗證重跑。

對 ai_core 專案的價值／接點

這是一篇對「自我改進迴圈可靠嗎」的反面實證，對 ai_core 最直接的警示在評測方法論：單一 run、固定任務順序的分數（本文重現的 AWM/RBank 原論文設定）在本文的 3-run + 亂序重評下大幅縮水甚至轉負，說明任何宣稱「自改有效」的內部評測，若沒有多 run 變異量與非預設任務序的壓力測試，結論很可能站不住腳——ai_core 做成本梯度分析或固化引擎效果驗證時，應該把「best-worst gap」與「相對 baseline 標準差變化」當成標配報告項，而不是只看單次平均分。第二個接點是固化引擎的失效模式警示：本文的 environment/task underspecification（§4.1）本質上是「記憶生成模組不知道自己在什麼約束下運作」，導致生成看似合理但不可執行的策略（API 建議、等待人工確認）並被後續任務重複提取、逐步放大——這正對應固化引擎把 rollout 蒸餾成技能／記憶時，若 verifier／記憶建構 prompt 沒有明確的環境能力邊界與任務驗收標準，同樣的「幻覺式最佳實踐」污染可能發生且會隨迴圈自我增強（Map domain 的 Haversine 案例是具體範例）。作者提出的緩解手段（把 rubric 分數、環境執行回饋、更嚴格的 prompt 邊界說明餵回記憶建構模組）只補回三成差距，這提醒 ai_core 不能指望單靠加大 context 資訊量解決記憶污染，長期仍需要記憶驗證/過濾機制與人工可介入的稽核介面（作者在 Recommendations for System Development 段的明確呼籲）。
