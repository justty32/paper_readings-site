論文／訪談原始來源

《SkillOS：學習技能策展以實現自我進化代理》重點摘要

一句話概括

技能策展（skill curation）是自我進化代理的瓶頸；SkillOS 用 RL（GRPO）訓練一個技能策展器（skill curator）來管理外部 SkillRepo（增/改/刪 Markdown 技能檔案），透過分組任務流（grouped task streams）與複合獎勵（任務成果＋函式呼叫有效性＋內容品質＋精簡度）把延遲且間接的反饋轉化為策展學習訊號——8B 策展器在多輪代理與單輪推理任務上全面超越無記憶與記憶基礎基線，甚至打敗 Gemini-2.5-Pro 直當策展器，並跨 executor 與跨任務域泛化。

核心貢獻

  1. 模組化雙代理架構：凍結的 Agent Executor（從 SkillRepo 用 BM25 檢索技能→執行任務）＋可訓練的 Skill Curator（觀察軌跡後產生 insert_skill / update_skill / delete_skill 函式呼叫來修改 SkillRepo）。技能格式為 Markdown（YAML frontmatter + 指令本文），操作介面如同檔案系統 I/O——故名「SkillOS」。

  2. 分組任務流訓練實例：每個訓練實例是一組相關任務（用 LLM 標註任務屬性、軟 Jaccard 分組），讓早期任務的技能更新在後續相關任務中被評估——把「這個技能好不好」的訊號從不可觀測變為可觀測。這比先前僅在短任務流內訓練的做法，多了長程技能演化軌跡的學習訊號。

  3. 複合獎勵設計：\(r = r_{\text{task}} + \lambda_f r_{\text{fc}} + \lambda_u r_{\text{cnt}} + \lambda_c r_{\text{comp}}\)——下游任務成功率＋函式呼叫有效性＋外部裁判（Qwen3-32B）對技能內容的抽象/可重用/可操作/忠實度評分＋SkillRepo 精簡度（壓縮比）。四信號共同解決「延遲反饋歸因」問題。

  4. 技能演化湧現行為：訓練初期策展器只會 insert（盲目擴張），後期 update 成主導操作（精煉既有技能），delete 始終少但微增。SkillRepo 從狹窄任務特定技能，演化出驗證、備援規劃、系統性搜尋、策略調整等高階元技能（meta-skills）。

  5. 跨 executor 與跨任務泛化：Qwen3-8B 策展器在 Qwen3-8B/32B、Gemini-2.5-Pro、Gemini-3.1-Flash-Lite 做 executor 時均一致提升效能；從推理任務訓練的策展器特別容易泛化到代理任務（高階策略跨域有用）。

對讀者的價值（與 ai_core 的接點）

§3.6 固化引擎的直接架構參照

ai_core §3.6 固化引擎的核心命題是「把 LLM 反覆處理的案例結晶成確定性程式碼／抽象庫」——SkillOS 為這個命題提供了完整的作業系統層架構：

  • SkillRepo = 固化引擎的「抽象庫」。技能從初始的任務特定片段演化為可組合的元策略，正是固化引擎追求的「從案例到抽象庫」的演化路徑。
  • Skill Curator（增/改/刪） = 固化引擎的決策機制。ai_core 未解決的核心問題是「何時該固化／如何避免庫爆炸」——SkillOS 的 RL 策展器（特別是以 downstream task outcome 為獎勵的設計）直接示範了這個決策該如何被訓練出來。
  • 複合獎勵的歸因結構：\(r_{\text{task}} + r_{\text{comp}}\) 的張力——既要技能有用又要精簡——精確對應固化引擎的「何時值得固化 vs. 何時該刪除過時／無用抽象」的張力。
  • 分組任務流：固化引擎需要「在相關任務上驗證抽象是否值得固化」的評測框架；SkillOS 的分組機制（shared foundation + progression gate）是這種評測框架的實作藍本。

關鍵素材

  • 與 2605.19576 Library Drift 成對閱讀：SkillOS 建立固化引擎的架構（如何建庫），Library Drift 診斷其失敗模式（建了之後如何退化）——兩篇是 §3.6 的建構＋維護完整圖譜。
  • 與 DreamCoder（2006.08381）的對位：DreamCoder 用 wake-sleep 做程式庫學習，SkillOS 用 GRPO 做技能庫學習——兩條線交會點是「如何把 LLM 執行軌跡壓縮為可重用抽象」。

一句對 ai_core 的啟發

固化引擎不只需要「把什麼變成程式碼」，更需要一個 RL 訓練出來的策展器來決定「增什麼、改什麼、刪什麼」——SkillOS 證明這套機制可以被端到端訓練，且 8B 策展器就能超越 frontier model 的 zero-shot 策展。
