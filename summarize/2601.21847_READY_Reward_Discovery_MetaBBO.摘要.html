《READY：為元黑箱最佳化（MetaBBO）做獎勵發現》重點摘要

一句話概括

READY：用 LLM 當自動獎勵發現工具，替元黑箱最佳化（MetaBBO）——一個用 RL meta-learn 黑箱優化器設計策略的雙層 paradigm——自動合成「即插即用」的獎勵函數，取代既有 MetaBBO 全靠人類專家手刻、帶設計偏差與 reward hacking 風險的獎勵。效率上引入多任務演化架構：替多個 MetaBBO 任務各維護一個獎勵程式種群（niche），平行搜尋並透過跨任務知識遷移加速收斂；效果上借「演化啟發式（evolution of heuristics）」思路做五個 reflection-based 程式級演化算子 + 嚴格 rejection sampling（新個體 fitness 須勝過人類設計的獎勵才入種群）。實證：READY 一致提升多個 MetaBBO 的最佳化效能，勝過原始獎勵設計與 Eureka/EoH/ReEvo 等最新 baseline；且驚人地——為某 MetaBBO 發現的獎勵能直接遷移去 boost 未見的 MetaBBO。

解決什麼問題

MetaBBO 用 meta-level RL 策略指揮 low-level BBO 優化器，獎勵函數把「優化器與環境互動」翻成 RL 的反饋訊號，直接影響 RL 的效能與泛化。但現有 MetaBBO 的獎勵全靠人類專家手刻簡單啟發式，帶來：設計偏差與 reward hacking 風險；新架構都得費力重刻獎勵；手刻獎勵常遠非最優、遮蔽各 MetaBBO 架構的真實能力、使公平比較幾乎不可能。因此需要一個自動獎勵發現框架。

核心方法（承 FunSearch/EoH/AlphaEvolve/Eureka 的 LLM 程式演化 paradigm）

  • 問題形式化：MetaBBO 任務 T={D,O,π}＝MDP（D 含 train/test 問題分布、O 為 low-level BBO 優化器、π 為 meta 策略）；每步從 low-level 抽優化狀態 s_t、π 輸出演算法設計動作 ω_t、O 優化一步、獎勵 R 評估此設計動作的效能增益；目標最大化折扣累積獎勵。test 上用正規化目標指標 F（越小越好）評分。
  • 個體表示（承 EoH）：每個 reward 個體＝⟨Thought（LLM 摘要的自然語言描述）, Code（獎勵函數程式碼）⟩。
  • 三大設計：
    1. 多任務程式演化（multitask niche）：替每個 MetaBBO 任務開一個獨立種群（niche），讓它們各自做種群內演化 + 種群間知識遷移 → 共享方法論洞見與架構、加速搜尋。
    2. 細粒度演化算子：五個 reflection-based 程式級算子保證搜尋多樣性（如 M1「debug 反思」找 top-K 最差實例、LLM 診斷獎勵邏輯為何與策略失準再修；M2「全域反思」回溯過去 L 代演化軌跡、找哪些改動歷史上帶來 fitness 增益再外推下一步；另有 exploitative/exploratory prompts）。
    3. 知識遷移：顯式跨任務知識共享 scheme 加速收斂。
  • 效能式 rejection sampling：新個體先按 F 評估，只有 fitness 勝過人類設計的獎勵個體才入 niche → 確保初始種群即支配 baseline；搭配 diversity 約束（與既有獎勵差異 ≥95%）+ quality 約束（須優於既有）。

結果

  • 一致提升：READY 在 DEDQN、RLEPSO、RLDAS 三個 MetaBBO 上一致改善最佳化效能，勝過它們的原始獎勵設計，也勝過最新 baseline Eureka、EoH、ReEvo。
  • 單 run 多任務：READY 一個 run 同時替三個 MetaBBO 發現獎勵（baseline 須各自獨立最佳化），靠多任務 niche + 知識遷移。
  • 可解釋：產出隨獎勵程式共同演化的清晰、可解釋設計洞見（Thought）。
  • 零樣本遷移（驚人）：為某 MetaBBO 設計的獎勵能直接適配去 boost 未見的 MetaBBO。
  • 測試函數上報 51 獨立 run 的 mean 最小成本 ± std（越低越好），含 Avg. Rank。

局限

  • 焦點在 MetaBBO 這個特定 niche（BBO 演算法設計），非通用 RL 獎勵設計；泛化到其他 RL 領域未驗。
  • 每個獎勵候選都要在 MetaBBO 上完整評估（雙層 + 完整優化 run）→ 成本高（多任務 niche 部分緩解）。
  • 依賴 LLM 程式生成品質與 rejection sampling 守衛；仍是「LLM 當演化算子」家族共通的可重現性/成本問題。

對讀者的價值

  • 本批 D 類**「LLM 演化發現 RL 元件」中專攻『MetaBBO 的獎勵函數』——填補「自動獎勵設計 × MetaBBO」這個此前無人碰的交叉（作者自稱 first）；與 2603.28416（發現 update rule）、2606.26327 EVOM（發現架構）、2606.20858（發現 reward 的時間排程）形成「LLM 演化發現 RL 不同元件」完整光譜，READY 打的是「meta 層 RL 的獎勵」**這層。
  • 最值得記：「多任務 niche + 跨任務知識遷移」讓一個 run 同時替多個 MetaBBO 找獎勵且互相加速;「rejection sampling 強制每個入種群個體都支配人類 baseline」 的乾淨守衛；以及反直覺的 零樣本跨 MetaBBO 獎勵遷移（暗示存在 MetaBBO 通用的良好獎勵結構）。
  • 與 Eureka（控制任務的 LLM 獎勵）、2505.20881 MoH（meta 啟發式）相鄰，但 READY 攻的是 MetaBBO 這個「優化器設計策略」層的獎勵，且強調 reward design 對公平比較 MetaBBO 架構的重要性。
