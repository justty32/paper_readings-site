論文／訪談原始來源

讓 agent 提出演算法，並以 Lean 證明查詢時間界

設計與分析一起產生

作者建立分階段管線，讓語言模型提出黑箱最佳化演算法、形式化並構造勢函數與漂移證明，由 Lean 檢查結果；過程沒有用實驗 fitness 比較候選演算法。每次以問題卡、前一演算法與其界限作起點，本研究以均勻隨機搜尋作初始設計。可反覆接續前代，讓下一代的證明上界更好；這是界限比較，不直接保證實際執行時間也更快。（§1、§4、附錄 A）

黑箱模型中的演算法根據歷史選點、向 oracle 查 fitness，成本是首次查到最佳點之前的查詢次數。演算法的內部計算不計費，故查詢次數的多項式界不自動代表整體時間多項式。勢函數只用於分析，並非執行時演算法的一部分。（§3.1–3.2、§5.3）

階段如何約束模型

Stage 0–8 從文字設計到 Lean 定義狀態、初始化、查詢與狀態轉移，並用可達狀態、隨機性、NotRandomSearch、fitness 適應性等 guard 過濾設計。接著 Stage 9 要求勢函數落在 \([0,1]\)，且恰在最佳查詢時為零；Stage 10 證明改善、惡化及直接跳到目標的機率條件，最後取得期望查詢次數上界 \(4/(\varepsilon p)\)。NotRandomSearch 的正式條件只要求存在可達狀態、隨機輸入及 fitness，使查詢與同一隨機輸入的均勻抽樣不同；單點見證不足以推出查詢分布非均勻（本檔補註，非作者自陳）。Lean 報錯時重試並依 Luby 排程回溯；guard 是形式義務，並不等於所有通過者都有實用效率。（§4、附錄 A、附錄 C）

每一代的加速證書比較相鄰代的漂移常數積，因此可以只改善常數而不改善漸近階；作者亦指出簡化漂移定理可能使證明界不緊。已列印公理的指定幾個完成 run 使用 Lean 標準公理，不能因此推論全部 run 都做了相同公理稽核。（附錄 A、§3.2、§6）

完成率與查詢模型界線

作者自報 8 個問題類別的 15 次 frontier-model 分階段 run 中 12 次完成全部階段、Lean 無 sorry。其中 9 次得到不靠未計費離線求解的多項式界，另兩次先查出頂點覆蓋圖後以非建構式方式求解，查詢間計算未有界；最後一個只把隨機搜尋改善常數，仍為指數界。樣本量受成本限制，作者未能做完整統計設計。（表2、§6、附錄 F）

CycleUncover 的合成問題利用隱藏偶環的獨立集結構；產生的演算法藉查詢推斷鄰接、逐步二著色，再查詢最佳解。作者報 Lean 檢查的期望 \(O(n^2)\) 查詢上界，對照論文分析的經典 (1+1) EA 為 \(e^{\Omega(n)}\)；這是該特定問題與模型下的比較，不是對所有演化演算法的下界。（§5.2、附錄 E）

一般 VertexCover 的 flat fitness 案例可探測邊，再在查詢之外求最小覆蓋；Lean 的最小覆蓋定義非建構式，\(O(n^3)\) 是查詢界而非 NP-hard 問題的多項式總時間解法。BandwidthVC 的 flat 版本同樣利用不計費離線求解，得到 \(O(kn)\) 查詢界；graded fitness 的一個完整 run 仍是 \(\Theta(2^n)\)。（§5.3、附錄 F.10–15）

問題卡、結果與限制

LeadingOnes 一次生成得到 \(O(n^3)\) 證明上界；當問題卡額外提供指數不等式時，同類 fitness 自適應突變設計取得 \(O(n^2)\)。OneMax 的產生式證明為 \(O(n^3)\)，作者指出實際算法已有更緊的 \(O(n\log n)\) 分析。整數值次模函數的卡片假設值域 \([0,B]\)、\(B=n^c\)（\(c\geq 1\)） 且最小值為零，並提供應善用次模性的建議；五代後作者報投影次梯度方法的 \(O(n^2B^2)=O(n^{2+2c})\) 查詢界。（§5.1、§5.4、附錄 F.16）

無分階段的兩個消融中，CycleUncover 重現近乎隨機搜尋，BandwidthVC 未證明時間界；兩者也未獲得分階段版的漂移 API 與證明工具。作者報開放權重組合在最近 14 個 OneMax runs 均未完成；此結果屬該設定，並非所有開放模型或形式化工具的普遍結論。搜尋空間限位元字串，結果受問題卡、證明庫及 drift 定理形式影響。（§5.5、附錄 F.1、§6）
