論文／訪談原始來源

TRACE: TRajectory Attribution for Automated Context Engineering 重點摘要

一句話

TRACE 從歷史軌跡中的修正、重述、放棄等不滿訊號，回溯 system prompt、KB、tool description、skill 等 context 元件；它把 root cause 視為待驗證假說，先讀 source 才在 CREATE 與 UPDATE 之間做修復決定。

管線

  • Detector 從顯式（thumb-down、tool error）與隱式（conversation repair、repetition、negative sentiment、semantic drift、abandonment）訊號挑出 DSAT session。
  • Root Cause 將軌跡建模為 context graph，從最終 response 的「預期－實際 delta」反向讀取完整 trace，對節點產生 textual gradient 與 attribution。它不讀 raw context source，以降低成本並將驗證留給下一階段。
  • Recommender 不盲信 attribution：會讀取被指涉的 source、查權威資料、交叉檢查相關元件，再輸出 CREATE、UPDATE、DELETE 或 NO_ACTION 及路徑與證據。

作者報告的結果與資料限制

作者在三層複雜度、60 條 dissatisfaction traces（最多 16 execution nodes）報 root-cause node Acc@1 72.7%、end-to-end fix effectiveness 82%，並在摘要稱 exploratory verification 的 CRUD operation accuracy 為 96%。正文也報一項實驗：未做 exploration 的 CREATE/UPDATE 決定為 33%，做後 83%。數字出自作者以三層 simulation 製作的帶 ground truth benchmark；論文另稱所有 75 traces 都通過 tool-output/source、fault annotation、交叉引用、root-node、attribution sum 等檢查。這不是公開 production log 的外部效能證據。

可採用的檢查表

任何自動修 context 的 pipeline 都應把 attribution 與修復分開：記錄 source snapshot；要求工具輸出逐字能對回 source；fault 到 correction 有可追溯鏈；attribution 加總與最高 root 合理；且用 disjoint trace／task split 測試。論文使用 agent chain-of-thought 作診斷輸入，在實際系統可能因不可得、隱私或不可靠而失效。
