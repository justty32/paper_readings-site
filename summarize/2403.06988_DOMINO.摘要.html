論文／訪談原始來源

《正確地引導 LLM：快速、非侵入式的約束生成（DOMINO）》重點摘要

一句話概括

DOMINO：把約束解碼拆成 parser + scanner，離線預計算一棵詞彙對齊的子終端樹（vocabulary-aligned subterminal tree）來對齊「LLM 子詞 token」與「文法終端符」，達成最小侵入式約束（minimally invasive）——凡無約束模型能生成的合法輸出、受約束模型也都能生成，因此不損準確率；再結合推測解碼與機會式遮罩把約束開銷壓到近乎零、甚至比無約束生成快近 2×。

解決什麼問題

約束解碼（強制輸出符合 JSON／CFG／regex 等形式語言）有兩大痛點：(1) 生成時額外開銷（線上法最壞情況每步須掃整個詞彙表）；(2) 更隱蔽的是準確率被扭曲。因為 LLM 的子詞 token 與文法終端符不對齊，天真/貪婪約束會忽略橋接 token（bridge tokens，橫跨多個終端符，如「空白＋引號」），逼模型選出高困惑度的次佳 token，使分布偏離無約束情形。實測：GSM8K 的 JSON 版，天真約束把準確率從 41.5% 打到 30.8%；模板法（guidance）因外部 tokenizer 誘發不對齊，困惑度從 4.17 爆到 24–49。

核心方法

  • 最小侵入定義：任意提示下，無約束模型能產生的合法輸出，受約束模型也都能產生。
  • parser／scanner 分離：scanner 管終端符的 regex（低階），parser 管 CFG 規則（高階）；合法程式＝終端符序列（引理 3.1）。
  • 子終端樹（離線預計算）：把字元級 NFA 提升到（子）終端層，對每個狀態、每個詞彙 token 列舉可達的子終端序列（區分 full／start／end／continuation 四型），組成前綴樹，token 掛在節點上。推理時 parser 線上剪掉非法延續。
  • 前瞻參數 k：控制在前綴樹往下追蹤的深度；k=0 已保證輸出合法，k=∞ 才最小侵入（納入所有跨邊界橋接 token）。
  • 機會式遮罩（opportunistic masking）：先讓 LLM 提議 token、parser 只驗這一個，合法就過、不必算整個遮罩。
  • 約束式推測解碼：以計數模型 P(l|α,β)（α=scanner 子終端、β=parser 規則狀態）一次推測 s 個 token；結構化語言可預測性高故加速巨大，且只會預測合法 token。獨立於底層 LLM 的標準推測解碼、可並用。

結果（Mistral 7B / Llama-2 13B）

  • 表 1：在 Regex、CFG、可預計算、最小侵入四維度上，DOMINO 是唯一四項全滿足者（勝 lmql／guidance／Outlines／Picard／Synchromesh／llama.cpp／gcd）。
  • 準確率（表 2）：DOMINO 全任務最佳且準確率持平或略超無約束；標準 guidance 最多掉 11 個百分點（如 CoNLL2003/Llama-2：0.09→0.062）。GSM8K/Mistral：無約束 0.415 → DOMINO 0.418；CoNLL2003/Mistral：0.21→0.21。
  • 吞吐：相對無約束最高 2.71×（CoNLL2003/Llama-2），schema-JSON 達 1.77×（+77%）；guidance 與 llama.cpp 的線上約束普遍降到約 0.8×。
  • 前瞻 k（表 4）：k=0→0.308、k=1→0.1、k=∞→0.418（Mistral），低 k 會逼壞空白/格式甚至讓 Llama-2 無法生成長列表。
  • 推測 s=10 對 schema-JSON 得 1.7× 吞吐；自由形式 JSON 改用機會式遮罩僅 4.21% 開銷；C 程式碼最難預測，機會式遮罩 0.78× 仍勝 llama.cpp 0.74×。

局限

  • 明確設定為離線：所有文法須事先已知、不隨請求變化；文法預計算需 1–5 秒（C 語言離群約 20 秒），不計入吞吐。
  • 推測解碼對難預測的結構（如 C 程式碼）無益，該情境仍是唯一淨開銷（<無約束）的工作負載。
  • 計數式推測模型需暖機形成先驗（實驗用 10 次暖機），先驗固定後才量測。

對讀者的價值

  • 直接對應 ai_core §5 第一目標「程式碼助手」的下層——受約束填碼：DOMINO 給出「約束不該拖慢也不該扭曲」的工程解。它把「格式保證」從昂貴的 LLM 反覆重試/後處理，剃成一個確定性、可預計算的解碼層——正合北極星「把 LLM 呼叫包成可靠函數、逐步剃除對 LLM 依賴」：輸出合法性由 parser 免費保證（確定性節點），LLM 只負責內容（少數智能節點）。
  • 子詞對齊＝可靠性的前提：本篇證明「天真約束會偷偷降低推理準確率」，提醒 ai_core 在做結構化抽取／填碼時，約束層必須最小侵入，否則資產工廠產出的「資產」品質會被靜默腐蝕——這是可靠函數化的隱形陷阱。
  • 與已入庫 [[CRANE]] 互補：CRANE 警示「過度受限的解碼會損害 LLM 推理」屬同一問題的理論/現象面；DOMINO 是同一問題的系統/工程面解方（用最小侵入＋橋接 token 保住推理準確率）。兩者一起讀，構成「約束該怎麼設才不傷智能」的完整視角。歸 I 類（推理/約束生成基礎設施）。
  • 定位：演算法/系統論文（ICML 2024），適合做 受約束生成、JSON/schema/CFG 強制輸出、推測解碼、LLM 推理管線 的人；核心可遷移概念為「離線預計算對齊 + 推測 = 近零開銷的可靠格式保證」。
