論文／訪談原始來源

《CoCoDA》重點摘要

一句話概括

針對工具增強小型語言模型的**「庫成長 vs 上下文預算」耦合難題**：工具庫要隨 planner 演化（把反覆出現的子軌跡抽成可重用工具），但庫一大、扁平文字索引的檢索成本就隨工具數線性膨脹、撐爆固定上下文窗。CoCoDA 用單一程式碼原生結構——組合式程式碼 DAG同時解兩問題：節點是 primitive/composite 工具、邊是「呼叫依賴」、每節點存四級紀錄（型別簽章、描述、前/後條件規格、範例）。推論時 Typed DAG Retrieval 是個級聯：先用符號簽章合一剪枝、再用描述排序、再用行為規格過濾、最後用範例消歧——昂貴的 LLM 計費紀錄只在逐級縮小的候選集上實體化，使檢索成本對庫大小次線性。訓練時把成功軌跡折疊成已驗證的 composite 工具（須保 acyclicity 與規格檢查），並用 DAG 誘導的「省下呼叫數」獎勵（composite 按其 primitive 展開大小給信用）訓 planner 偏好可重用 composite。理論證明檢索成本下降、次線性檢索時間、組合優勢、保守更新下單調共演化、DAG 良構。實驗：8B 學生在 GSM8K/MATH 上匹敵甚至超越 32B 教師（GSM8K 93.67 vs 93.40、MATH 63.18 vs 61.62），一致優於強工具使用與庫學習基線。

解決什麼問題

工具增強讓小模型把計算/符號操作/長程程序卸載到可重用庫，但擴庫有張力：一方面庫須隨 planner 成長（否則 planner 反覆重建相同 primitive 計算），另一方面每加一個工具就增檢索負擔——扁平庫讓 planner 提示成本隨工具數成長、上下文預算先被耗盡。既有方法只解部分：靜態工具使用假設固定清單；技能庫/agent 記憶（Voyager、CRAFT、TroVE、ReGAL）存成扁平文字、依賴結構對檢索與訓練不可見；階層記憶/RAG（RAPTOR）按主題相似度聚類而非可執行組合；程式碼庫學習/程式合成（DreamCoder、Stitch）善用組合結構但非為「token 預算下檢索」的 LLM planner 設計。缺的是同時程式碼感知、檢索高效、可線上學習的結構。

核心方法

  • 組合式程式碼 DAG：節點 = primitive（原子可執行函式）或 composite 工具；邊 = 從可執行體抽出的呼叫依賴；每節點四級紀錄：①型別簽章 ②描述 ③前/後條件規格 ④input-output 範例。此 DAG 是耦合「庫成長」與「上下文受限檢索」的單一物件。
  • Typed DAG Retrieval（推論級聯）：給 query 誘導的子目標，L1 符號簽章合一剪枝（倒排索引，O(log n)）→ L2 描述語意排序 → L3 前/後條件相容性過濾 → L4 範例消歧。昂貴 LLM 計費紀錄只在存活候選上實體化，故成本逐級收縮而非隨全庫線性；因階層循呼叫依賴而非文字相似度，檢索能浮現「行為上涵蓋某 primitive 子軌跡」的 composite。
  • 線上共演化（訓練）：成功軌跡交給固定 teacher abstractor 提出 composite 工具，僅在保 acyclicity 並通過依賴與規格檢查時才提交（Add/Merge/Reject）。planner 以 GRPO 更新、獎勵 R = R_res + λ·R_comp：R_comp 是 DAG 誘導的 saved-call credit——調用代表多個 primitive 呼叫的 composite 得正信用、調用 primitive 不得；於是在「相同已驗證結果」的行為等價軌跡中，planner 被引導用可重用 composite。flat（展開後 primitive 呼叫數）是 DAG 遞迴展開的結構不變量、非 teacher 標註，故 R_comp 不可被瑣碎利用。
  • 耦合更新：π 與 L 同步更新（GRPO step + Fold(InsertTool)），兩者攻同一 gap 訊號；只更新 π 則 planner 過擬合固定檢索面、只更新 L 則 planner 無法調用新 composite。保守步長下目標 J(π,L) 單調非減（Theorem 4）。

結果

  • 六基準三類（數學/邏輯 GSM8K、MATH；表格 WikiTableQuestions、FinQA；程式 EvalPlus、MBPP），四種 Qwen3 學生（0.6B–8B）+ Qwen3-32B 教師上界；teacher 也作 composite 抽取器。
  • CoCoDA 贏每個 (size, benchmark) 格，比最強工具基線 ReTool 高達 +2 分；對 vanilla CoT 的增益在最小規模最大（0.6B 時 GSM8K +10.7、MBPP +10.8），顯示共演化庫在學生容量稀缺時最能轉移教師能力。
  • 8B 學生匹敵/超越 32B 教師：GSM8K 93.67 vs 93.40、MATH 63.18 vs 61.62（約 1/4 參數恢復教師級績效）。
  • 無緊密師生迴圈的庫建構基線（CREATOR、TroVE）在數學/程式上反而輸給純 CoT，證實「工具創建只在庫與學習者共演化時才有用」。
  • 理論：Typed DAG Retrieval 使檢索成本 C_hier = o(C_flat)、時間 O(τ₁ log n + (τ₂+τ₃+τ₄)k₂) 次線性。

局限

  • 依賴固定 teacher（Qwen3-32B）做 composite 抽取與冷啟動，學生績效上界仍受教師制約。
  • 評估限六基準、Qwen3 家族；composite 需通過規格/acyclicity 檢查，規格本身須可表達。
  • 理論保證（次線性、單調共演化）建於假設（Assumption 1、保守步長），實務 GRPO 步長需調。

對讀者的價值

  • 本批 G 類中**「技能庫學習 × LLM agent × 程式碼原生組合結構」的代表**——明確點出 DreamCoder/Stitch（程式碼感知但無 token 預算分層）與 CodeRAG/RAPTOR（為 LLM 但扁平嵌入/文字聚類）之間的「缺失象限」，用 typed DAG 同時佔據程式碼感知 + 上下文預算分層。與 2602.00929 TheoryCoder2、2509.04439 ArcMemo 等「學可重用抽象/概念記憶」工作同脈。
  • 最值得記：「同一 DAG 雙重角色——既把檢索控在上下文預算內、又定義訓 planner 用新抽象的 saved-call 結構訊號」，以及「policy 與 library 須在同一 gap 訊號上共演化、否則任一單獨更新都失效」。
  • 與 2606.24245 AutoSpec（ILP 學符號規則）、2507.16405 Poker ILP 等符號學習互補（CoCoDA 學的是可組合可執行工具）；對研究 DreamCoder/Stitch/babble 系庫學習、工具增強 LLM、agent 記憶/技能庫、GRPO 獎勵塑形 的人很有參考價值。
