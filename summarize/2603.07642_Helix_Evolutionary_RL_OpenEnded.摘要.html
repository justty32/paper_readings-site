論文／訪談原始來源

《Helix：用於開放式科學問題求解的演化式強化學習》重點摘要

一句話概括

複雜科學問題具有 domain-specific（領域特定）、open-ended（開放式，需探索龐大彈性解空間）、unbounded（無界，無已知全域最優） 三特性，純後訓練 RL（RLVR）會 entropy collapse 難跳出基模能力、工作流派又靠死板 pipeline 不能複用過往發現；HELIX 把兩者融合——LLM 當「會突變既有解（程式碼）的策略 π_θ」、用 GRPO 線上更新策略提升解品質，同時把所有產出的解組成 population、用 NSGA-II 多目標選擇在「reward × diversity（語意嵌入 KNN 算多樣性）」的 Pareto 前緣保留高品質又多樣的候選，再把 population 中最佳解（沿 lineage tree 譜系的祖先解＋其 reward/feedback）塞進 prompt 做 in-context learning「站在巨人肩上」迭代。在 20 個跨 5 類（ML/物理模擬/圓堆積/函數最小化/符號回歸）開放式任務上，僅用 14B 模型在圓堆積（circle packing）達到 SOTA 半徑和 2.63598308，ML benchmark 上平均 F1 超過「配精心 pipeline 的 GPT-4o」5.95 分（Adult＋Bank Marketing），17/20 任務最佳。

解決什麼問題

用 LLM 解複雜科學問題（符號回歸、分子生成、難最佳化）正熱，但這些問題天生開放式且無界。現有兩派都缺三項關鍵能力（從經驗學習／平衡品質與多樣性／站在巨人肩上）：

  1. 後訓練派（SFT、RLVR；AlphaCode、DeepSeek-R1）：domain 微調效果強，但entropy collapse、罕能超越基模能力，稀疏獎勵下更難發現「根本性新解」。
  2. 工作流派（LLM×GA enzyme discovery、LLaMEA、AlphaEvolve/OpenEvolve）：把 LLM 嵌入預定 pipeline，但高度依賴工作流與 prompt 設計、靠靜態預訓練知識、難複用過往發現指導迭代搜尋。 兩派都難在「需高效探索＋持續精煉」的開放式科學域泛化。

核心方法（三模組協同）

把任務視為「解空間＝程式碼」的最佳化 max_s R(s)。LLM 策略 π_θ 對候選解 s_t 輸出一個「編輯/修改」動作 a_t → 新解 s_{t+1}=T(s_t,a)。

  • (1) RL 策略更新（從經驗學習）：用 GRPO（群組內標準化 reward 算 advantage、KL 懲罰）更新 π_θ，讓模型學會把當前解推向更高 reward；GRPO 的多樣本生成天然豐富演化資料集。
  • (2) 演化機制（平衡品質與多樣性）：所有歷史解 ∪𝒟_s 經 NSGA-II（非支配排序 + crowding distance）在「reward R(s) 與 diversity Div(s)」二維目標的 Pareto 前緣選 top → 構成下一步候選池 𝒫_t。多樣性 Div(s)＝用預訓練語言嵌入模型把（正規化後的）程式碼編碼，取 KNN 鄰居的平均餘弦相似度的 1−補數。
  • (3) In-context「站在巨人肩上」：prompt q 由「問題描述 + 當前解及其 reward/feedback + lineage tree 上 n 個祖先解及其 reward/feedback」構成，讓 LLM 沿譜系記憶迭代精煉、跨挑戰性解空間有效探索。
  • 模型：DeepSeek-R1-Distill-Qwen，主結果用 14B（物理模擬用 32B）。

結果（20 任務、5 類）

  • 圓堆積 circle packing：僅 14B 模型達 SOTA，半徑和 2.63598308。
  • ML 任務：Adult Income 82.07（勝 LightGBM 80.36、GPT-4o+pipeline 76.91）、Bank Marketing 80.65、Boston Housing RMSE 降到 1.747（baseline 2.937～3.258）、Transparent Conductors 0.049（最佳）；平均 F1 超 GPT-4o（配精心 pipeline）5.95 分。
  • 整體 17/20 任務最佳（對比 task-specific baselines、Direct Prompt 測試時擴展上界、OpenEvolve）。
  • 消融確認三模組（RL、NSGA-II 多樣性選擇、in-context 譜系）各自關鍵互補。論文另附 GRPO 與「演化×HELIX」的漂移-擴散/選擇理論分析。

局限

  • 任務雖跨 5 類但每類規模有限、評測指標異質（圓堆積等無已證全域最優，只能報「所有嘗試中最佳值」）；缺跨多種隨機種子的統計顯著性大表。
  • 依賴外部「可驗證 reward / evaluator」與預訓練嵌入模型算多樣性 → 對 evaluator 設計與嵌入品質敏感。
  • 物理模擬需 32B、RL 微調 LLM 成本高；「站在巨人肩上」的 lineage prompt 會推高 context 長度。
  • 仍是「LLM 演化既有程式碼解」的範式，是否能發現真正超出基模先驗的科學新知，需更嚴格對照。

對讀者的價值

  • 本批 D 類把「開放式問題求解」做成具體系統的一篇——與理論派 2606.08369（開放式學習的 bit-equivalent 定義）正好對照：一個定義「何謂開放式」、一個示範「如何在開放式科學任務上有效探索」。其「RL 內層提品質 × EA 外層保多樣 × in-context 站巨人肩」三件套，是 AlphaEvolve/OpenEvolve 路線的「可訓練策略」升級版。
  • 最值得記的配方：用 NSGA-II 在「reward × 語意嵌入多樣性」Pareto 前緣選種、以對抗 GRPO 的 entropy collapse——把 quality-diversity（QD）思想（呼應 2502.02190 LQD、2502.00593 DNS-QD 的 MAP-Elites 系）接到 LLM 程式碼演化上；以及「lineage tree 祖先解 + feedback 進 prompt」當作跨迭代記憶。
  • 與課程/自動課程相鄰：HELIX 不排「訓練什麼任務」，而是讓 population 自我生成「愈來愈好的起點」，是一種 data-side 的開放式精煉。
