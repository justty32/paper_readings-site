論文／訪談原始來源

《Continuum：以 KV Cache TTL 高效且穩健地排程多輪 LLM Agent》重點摘要

一句話概括

Continuum 在 agent 等工具時不立刻丟棄 KV cache，而依 reload／recompute、回來後的 queueing delay 與 GPU memory opportunity cost 算 TTL；過期自動釋放，再配合 program-level FCFS 維持跨 turn 順序，trace replay 降低 delay 1.12–3.66×、提高 throughput 1.10–3.22×。

動機與方法

SWE-Bench 100 traces 平均 10.9 turns，BFCL 100 traces 平均 6.3；工具時間長尾，最慢 10% 的 fetch_url 與 cd 分別占總 delay 52.5% 與 94.1%。固定 pin 會被長工具卡死，end-of-turn eviction 又造成每輪 prefill／reload，加上重新排隊的 bubble。

Continuum 的 utility model 比較保留 cache 的 benefit 與 GPU memory cost。歷史 tool-call CDF 估回來前的機率，offline profiling 估 context-length 對 prefill、CPU reload 的成本；cold start 使用保守 TTL。Scheduler 給較早抵達的 program 優先，不把每個 turn 當獨立 request。TTL 到期就 eviction，避免 failed／long-running tool 永久占住 GPU。

實驗

  • 模型／硬體：Llama-3.1 8B／70B、Gemma-3 12B，A100、H100、B200；另以 8×H100 跑 GLM-4.5 355B rollout。
  • Workloads：SWE-Bench、BFCL、OpenHands；基線含 vLLM 0.10.2、LMCache CPU offload、Autellix、InferCept、SGLang、Dynamo。
  • 三種 model/hardware trace replay：delay 改善 1.12–3.66×，throughput 1.10–3.22×；Llama-8B 相對 vanilla vLLM 平均 response time 最高約 2×。
  • Tensormesh 內部 H100 上跑 500 個真實 SWE-bench Verified agents，同 pass-rate 下最高 delay 改善 8.18×；baseline 超過 15 分鐘會被環境 preempt，故 Continuum 也得到較高 pass rate。
  • OpenHands／Multi-SWE rollout 每分鐘 steps：vLLM 93.4、ThunderAgent 114.8、Continuum 144.9。
  • Scheduler overhead 約 0.96ms（無 offload）／2.30ms（CPU offload）。

限制與矛盾

  • TTL 依歷史 CDF、memoryfulness 與過去 workload；突發 backend contention 或 adversarial latency shift 會失準。
  • Trace 是 GPT-5 產生，再由較小 local models replay；這有利於保持 workflow 正確，但不是相同模型在線產生的完整閉環。
  • 摘要稱平均 JCT「over 8x」，正文一般實驗是 1.12–3.66×；8.18×來自特定內部 real-SWE deployment 的 up-to delay。貢獻段又稱 latency 與 throughput 都最高 8.18×，但正文清楚支持的是該場景的 delay，應保守引用。

證據成熟度：高於一般 agent serving prototype，有多硬體、多模型、真實 agent 與 tail latency；但 8× headline 的外推需謹慎。

對 FreePy 的價值

它強力支持 FreePy 將 model residency、prefix KV、local input cache 與 durable correctness 分開。Cache-aware scheduling 可以是 bounded tie-break；TTL／eviction 只能影響效能，不能改變 Round identity、history branch 或重試語意。
