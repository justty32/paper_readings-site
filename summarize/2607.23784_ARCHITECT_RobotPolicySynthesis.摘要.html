《幾句話就很有用》重點摘要

一句話概括

ARCHITECT 把機器人 policy 視為可重生的模組程式：人以自然語言指出失敗，agent 以 execution trace 對應到程式與工具呼叫，將修正蒸餾為可持久載入的 skill library，讓後續任務少問人幾次。

系統如何運作

LLM coding agent 根據指令，組合控制、感知與本體覺工具，合成 Franka Panda 的模組化 robot program。失敗或 episode 結束後，人可給修正，例如抓取高度不對；trace 幫助 agent 定位該改哪個 tool call／程式片段並重新合成。修正會變成簡潔的自然語言規則或 code pattern，寫入持久 skill library；每次後續 code generation 會同時讀當前任務、trace 與所有已存技能。

這不是端到端 VLA 的 finetune，也不是只在當輪 prompt 中附帶 feedback。其可重用的單位是「語言規則加可執行工具模式」，但 library 仍是 context 載入的文字集合，沒有本文外的安全 sandbox、版本 gate 或顯式衝突規則。

原文實驗結果

作者在真實 Franka Panda、八個任務、每 task 十個 episode 的比較中，以最多五次 expert-correction rollout 建庫，衡量 SR、GCR、NTP。ARCHITECT-HiTL 在多物件、雜亂、抽屜、折布、長程遮布等任務的 SR 分別報 0.80、0.70、0.70、0.90、0.80；表中 CaP 及兩個 π VLA 在後三類多為 0 或 0.10。這是作者的單一硬體／工具套件實驗結果。

六位參與者的 within-subject study 中，帶入先前 task library 後，平均每 trial 人工修正從 4.67 降至 0.83（p=0.036）；沒有 skills 時 Task 2 成功為 0/6，帶 Task 1 library 而不再修正為 4/6。結果支持 effort amortization，但樣本很小且兩個任務結構相近。

可帶走的設計

自然語言修正若要變成資產，至少要和觸發它的 trace、使用的 tool／參數、驗證結果及適用條件相連。否則把「杯子抓高一點」直接堆進 prompt，遇到不同物件很可能成為未受約束的干擾。本文展示可執行組合的價值，也提醒 skill 需要更嚴格的 provenance、作用域與驗收。

局限

低階 grasp、深度估計和 motion planner 是主要瓶頸；library 的效用也受人工 correction 數量與品質限制。作者沒有證明無人監督的安全恢復，也未用大樣本跨場景試驗建立普遍結論。完整原文逐節精要見下檔。
