論文／訪談原始來源

Constrained Decoding：傷害或幫助LLM表現？

一句話概括

本文主張應拆開「用JSON思考造成的prompt／格式改變」與「相同設定下decoder遮掉不合法tokens」：格式約束FC保結構，有效性約束VC再限任務可行答案空間，推理約束RC則會改變reasoning軌跡。合適mask可增加保留正確序列的機率，但前提是正確答案仍被允許；RC可增可減，實驗也未展示任意constraint皆改善或任何模型都能零成本保正確。

三種約束與三種生成策略

約束 本篇操作 必須保留的條件
FC：format JSON結構、欄位；answer設str 任務認為正確的語法必須在schema內
VC：validity GSM8K非負整數；AIME整數0–999；LastLetter恰4／8個字母 先驗由題目／任務界定，不可排除真答案
RC：reasoning 強制開頭為既有step-by-step模式 先驗路徑可能有益，也可能擋掉有效路徑

VC不是給出正解，而是限制可行子空間；這仍需任務先驗。化學有效分子是未來延伸，不是本文已完成領域實驗。（§1、3、附錄A.2.2）

三策略：JSON從頭輸出reason與answer；NL-to-Format先自由reasoning，再由第二個模型抽取最終答案；InWriting在單次生成中先自由reasoning，遇EOS／PAD trigger後切換成受限JSON answer。Litelines建在outlines-core上；JSON與NL-to-Format的格式化生成不允許preamble，InWriting允許，標準例上限600tokens。（§4.3、附錄A.3.4）

公平的decoder消融是同一strategy內固定prompt與expected output format，比較Unconstr.、+FC、+FC+VC；expected format仍寫在unconstrained prompt，只不強制mask。不同strategy的prompt及reasoning空間本就不同，不能用JSON對自由reasoning的差距直接歸因mask。NL-to-Format對照更固定第一步reasoning traces，只改第二步抽取。（§4.3、附錄A.2）

機率論證保證的範圍

固定prompt \(x\)、reasoning trace \(R\)、長度\(T\)的最終答案序列。每一步對允許token集合\(V_C(s_{<t})\)做局部mask與renormalization，\(Z_t\)是該prefix下允許token的原機率總和；假設總有正機率合法token，故\(0<Z_t\le1\)。若真答案\(Y^*\)在約束集合內（Assumption1 soundness），

\[P_C(Y^*\mid x,R)=\frac{P_\theta(Y^*\mid x,R)}{\prod_t Z_t(x,R,s^*_{<t})}\ge P_\theta(Y^*\mid x,R).\]

期望accuracy定義為單一ground-truth序列exact match，故此式支持在上述固定條件下不降低其機率。（本檔補註，非作者自陳）這是自回歸局部renormalization，不是所有完整合法序列的單一全域條件化常數；也不直接證明greedy argmax答案或任意semantic evaluator必改善。（§3.1–3.1.1）

Assumption2要求在正解某個prefix，mask移除原模型有正機率的非法token，於是沿正解的\(\prod Z_t<1\)。作者式14寫strict gain；（本檔補註，非作者自陳）嚴格大於還需\(P_\theta(Y^*\mid x,R)>0\)，原機率為0時乘有限renormalization仍是0。 若沿正解完全沒刪正機率token則等號。僅固定prompt／format仍不足，schema若排掉語義或語法正確答案，soundness就失敗。（§3.1.2）

文末Clarification說把fields設str以保留答案自由度，syntax masking可保extractability；附錄A.4.3補充，如果評分接受Markdown code fence，schema也須允許。（本檔補註，非作者自陳）str放寬欄位值，不代表所有可接受外層語法自動被保留，仍須對齊實際evaluator。（Clarification、附錄A.4.3）

改變reasoning就沒有一般不傷害定理

§3.2分析reasoning–answer pairs：完全排除好路徑／正解可使正確率歸零；只保留oracle好路徑可達完美；實際部分保留同時可能刪好／壞路徑，效應不確定。找出beneficial reasoning traces需先驗，不能把固定\(R\)的答案定理直接套到RC改\(R\)。（§3.2）

模型、資料與量測

十一個開源模型包含十個task solvers：Qwen3-1.7／4／8B、Qwen3.5-2／4／9／27B、Llama3-8B、Gemma2-9B、SmolLM3-3B；Qwen3-32B專作NL-to-Format extractor。不是十一個solver都跑所有任務，表內X為未提供實驗。（§4.1）

任務為GSM8K、四名字LastLetter、八名字LastLetter-Extended及AIME2026。Extended由names-dataset隨機採名字，排compound names；作者說Extended及AIME在模型發布後取得／建立以降低leakage可能，不是已證明零污染。兩份Clarification及A.3.3指向此建構與Supplementary Materials，本文未自行重建資料。（§4.1、Clarification、附錄A.3.3）

主要metric為抽取答案與ground truth exact match，另報parse rate及FC／VC／RC gain。標準任務temperature0、sampling False、reasoning最多600tokens、thinking mode Off、seed1；AIME使用default temperature／sampling、12800tokens、thinking Off、seeds42/43/44。標準JSON有3task-description×1format=3組，InWriting／NL-to-Format為3×3=9組；AIME InWriting為1task-description×3formats×3seeds=9runs。表內\(\pm\)是作者跨適用seed／prompt組合的std，不應通稱所有數字都三seed或顯著性檢定。（§4.2、附錄A.2、表3）

作者自報：同設定約束增益與跨格式差距

  1. Plain text也能mask：LastLetter NL-to-Format固定prompt／reasoning，Qwen3-1.7B由\(60.7\pm4.3\)到\(66.1\pm4.8\)，Qwen3.5-9B由\(86.8\pm1.2\)到\(89.9\pm0.5\)；不是只JSON才適用。相同free-reasoning後第二步改JSON，Qwen3.5-9B的unconstrained／FC+VC為\(89.6\pm1.0\)／\(91.6\pm1.0\)，表2六模型的同條件JSON均值皆高於plain text。（表1–2）
  2. GSM8K InWriting：Qwen3-4B \(85.8\pm3.0\)→\(89.7\pm0.4\)、Qwen3.5-9B \(90.4\pm1.8\)→\(93.9\pm0.3\)。同任務JSON Gemma2-9B \(0\pm0\)→\(86.7\pm0.3\)伴隨parse改善，不能全部解讀為數學推理能力躍升。（附錄表6）
  3. LastLetter的Llama3 InWriting分解：Unconstr. \(53.6\pm5.4\)、FC同\(53.6\pm5.4\)、FC+VC \(71.0\pm3.8\)，VC增加17.4百分點。Qwen3.5-9B JSON則23.1→86.7→88.9，主要是FC救格式，不可把所有大增幅都算VC。（表9）
  4. 八名字Extended：Qwen3.5-27B InWriting \(79.5\pm1.9\)→\(83.9\pm1.4\)；但弱模型JSON仍可0→0，如Qwen3-1.7B及SmolLM3。所有matching設定不能說「每項都嚴格提高」；保格式也不保語義答案。（表8、10）

Few-shot改善pattern／string extraction，但並非通用reasoning增益，後續主實驗採zero-shot；AIME等高難題也不便提供適當few-shots。（§5.1、附錄表5）

VC可以修抽取，不代表重新學會推理

A.4.1的固定trace例：trace列對四字母，但最終漏一字、重一字或插空白，VC迫使抽取為合法四字母；數字28.00正規成28。作者指出空白及字母可能共同位於單token，故這不只是最後字串清洗，而是生成時在trace及合法集合下選continuation。（本檔補註，非作者自陳）例證支持一致性／抽取修正，不能把所有VC accuracy gain當作reasoning本體改善；合法長度仍可能是錯字母。（附錄A.4.1）

FC主要保extractability，但實測非全100%：GSM8K Qwen3.5-2B JSON parse82.2%→88.4%；Extended Qwen3.5-4B JSON93.8%→94.0%，27B82.4%→93.8%。InWriting與第二步抽取通常更接近100%。A.4.3把「自由前文後接JSON」或「Markdown fence包JSON」依原嚴格expected format判失敗；若應用想接受此格式，就需一併改schema／評分。（表11–12、附錄A.4.3）

RC與內容過濾的反例不能省

RC強制既有「Let's think step by step」開頭；不是本文學出最佳推理器。GSM8K InWriting FC+VC→再RC：Qwen3-1.7B75.8→77.7、Qwen3.5-2B74.9→77.4，但Qwen3-4B89.7→89.6、Qwen3.5-4B91.8→91.5、Qwen3.5-9B93.9→93.9。AIME的Qwen3.5-4B \(62.2\pm3.1\)→\(55.6\pm5.7\)，下降6.6百分點；27B \(81.9\pm3.9\)→\(84.3\pm5.6\)。是模型／任務依賴的可行性展示，未提供普遍選好RC的方法。（§5.4、表14–15）

IMDb初步實驗在prompt要求Positive／Negative，另強制換成各5種同義labels。Qwen3-4B baseline／原label約束／替代label為92.6／92.6／83.4，Qwen3.5-4B94.6／94.8／85.8。替代詞仍承載情緒但未追平原label，不是廣義內容安全或任意禁詞不傷準確率的驗證。此實驗的輸出字面label改了，不能直接當\(Y^*\)原token序列保留的定理案例。（附錄A.4.2，表4）

Token成本與作者限制

InWriting本篇新增少於15tokens，例如GSM8K Qwen3-4B164.6→172.8；JSON可因阻止無效長生成而token下降。Token數不是完整compute：JSON從頭每token算合法集合、NL-to-Format還有第二模型call，InWriting只在結尾受限。作者稱VC「near-zero-cost」不能延伸為walltime或kernel overhead為零；本篇未提供全面latency證明。（§5.6、表13）

A.1明列VC主要只在LastLetter／Extended驗證，IMDb是初步；化學等領域待擴展。RC需先驗，有益軌跡不易事先辨識；只用相對簡單JSON，長reasoning加複雜結構仍待研究。（附錄A.1）

摘要寫code available，但footnote與A.3.1明說code在Supplementary Materials、acceptance後才公開；本檔未查核repo或取得補充程式。成果適合的讀法是：先固定prompt／接受格式再評mask效果，分開format、task-validity與reasoning干預；不是「加constraint總是更聰明」。（摘要footnote、附錄A.3.1）
