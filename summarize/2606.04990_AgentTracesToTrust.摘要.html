論文／訪談原始來源

《從 Agent 軌跡到信任：LLM Agent 證據追蹤與執行來源綜述》重點摘要

一句話概括

這篇綜述把 execution provenance 定義為一次 agent 執行的完整 typed graph，把 evidence tracing 定義為其中的 evidence-support projection；它用六維 taxonomy 統一 retrieval、工具、記憶、環境、多 agent 訊息、稽核與恢復，指出現有系統幾乎都只覆蓋局部，尚無完整的 provenance layer 與 full-stack benchmark。

為何只存 log 不夠

Chronological log 能回答「發生過什麼」，不能回答「什麼依賴什麼」。一次正確回答可能引用錯誤來源；一次合法工具呼叫可能把不可信網頁內容寫進敏感 argument；一筆 memory 可能已被新證據推翻，卻持續影響其他 agent。

作者因此區分：

  • Agent trace：執行中產生／消費的 artifacts。
  • Execution provenance：把 evidence、execution units 與 typed relations 接成的完整 process graph。
  • Evidence tracing：從該圖投影出的 support／contradict／invalidation 等證據關係。

六維 taxonomy

  1. Trace sources：reasoning、retrieval、tool/MCP boundary、memory、environment、multi-agent communication。
  2. Evidence／execution units：文件、passage、observation、tool output、memory、claim、policy；以及 reasoning step、retrieval call、tool invocation／arguments、memory operation、action、message。
  3. Relations：Use、Generate、Derive，加上 agent 特有的 Support、Depend-on、Contradict、Invalidate、Trigger、Update。
  4. Granularity／timing：run、step、tool、argument、claim、token；pre-execution、runtime、post-hoc、continuous。
  5. Representations：structured logs、execution/evidence/claim-support/provenance graphs、runtime state。
  6. Trust functions：verification、attribution、debugging、safety enforcement、audit、failure attribution、recovery。

它以 W3C PROV-DM 與 OpenTelemetry 為底，但指出傳統 provenance 缺少 claim support、contradiction、memory invalidation、tool-argument influence 與跨 agent responsibility 等語意關係。

三條主線

工具與安全

只記 tool name 不夠，必須追 argument 從哪裡來、tool output 流向哪裡、external effect 是否發生。Indirect prompt injection 應被視為 untrusted source 流向 privileged sink 的資訊流問題。Capability／access control 決定可用資源，provenance 則判斷這一次具體呼叫的 sources、parameters 與目的是否合法。

記憶

Memory item 應保存 source、write time、update history、retrieval context、downstream usage、conflict 與 invalidation。摘要、反思和跨 agent 傳遞會改寫語意，使 string match 不足以追 lineage；新證據也必須能撤回下游依賴，而非只新增另一筆相反記憶。

多 agent 與錯誤

需追 delegation、message、claim、verification 與 responsibility 如何跨 agent 傳遞。現有 failure localization 能指出步驟或 agent，但很少同時連接 claim-level evidence、memory lineage 與 recovery action。

Benchmark 與 metrics 缺口

現有 RAG、tool-use、memory、multi-agent、trace-debugging、security benchmark 各自很強，卻沒有一類同時強覆蓋 evidence labels、tool calls、memory、multi-agent、attacks、provenance relations、recovery。

成熟 metrics 主要在 citation／faithfulness、ASR／policy violation；trace completeness、provenance accuracy、dependency coverage、temporal consistency 仍是 proposed；recovery success 也只部分建立。Full-stack benchmark 應保存完整 execution 並標註 Support、Contradict、Depend-on、Update、Invalidate、Trigger、unsafe influence 與 recovery intervention。

開放問題

  • 可交換的 trace schema：把 W3C PROV／OpenTelemetry 的 operational spans 接到 agent-specific semantic relations。
  • Claim-level semantic provenance：處理 paraphrase、summary、tool transformation、memory compression 與跨 agent 轉述。
  • Persistent memory／multi-agent lineage：責任、時間有效性、衝突與撤回。
  • Runtime recovery：污染隔離、argument 修正、retry、rollback、human approval、compensation。
  • Privacy-aware audit：trace 本身含 credential、API arguments、私人記憶與 reasoning artifacts，需最小化、權限、加密、保留期限與 selective disclosure。

局限

這是敘事型、聚焦 provenance 的綜述，不宣稱窮盡 RAG、memory、agent 或 safety 文獻；沒有 PRISMA 式檢索計數、納入排除表或 meta-analysis。其 benchmark heatmap 的 Strong／Partial／Limited 是作者依標準做的高階分類，而非量化實驗。六維 taxonomy 是有用的設計語彙，不是已驗證為完整或唯一的標準。

對 FreePy 的價值

這篇幾乎可作 agent_machine event schema 的需求清單：

  • Event journal 是 chronological truth；provenance graph 是由 events 派生的 typed dependency view，兩者不要混成一份可任意修改的 log。
  • ToolRun 需要 argument lineage、intent、receipt、effect evidence 與 downstream consumers。
  • ContextManifest 要記每個 context item 的 source、generation、trust、validity 與 dependency。
  • Replay／fork／rollback 要保留 provenance identity，否則恢復後無法判斷舊證據屬於哪條 branch。
  • Full tracing 成本與隱私很高，應把 provenance 當可分層 pager：高風險 action 用 argument-level runtime tracing，低風險工作用較粗粒度。

更大的研究機會是把這篇仍停在 taxonomy 的 recovery graph，落成 FreePy 的可執行 reducer、invalidation 與 restart semantics。
