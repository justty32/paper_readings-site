論文／訪談原始來源

ATLAS: Scaffold-Free Algorithm Synthesis by LLMs via Embedding-Guided Quality-Diversity Search 重點摘要

一句話

ATLAS 讓 LLM 直接合成「完整可執行演算法」而非填入既定 scaffold 的某個元件，用預訓練 embedding（演算法名稱＋描述＋原始碼）當座標，維護一個 similarity-based 去重與剪枝的 archive，並以三層搜尋（精煉當前最佳、成熟其他 cluster 代表、跨 cluster 重組）在四個 NP-hard 組合優化問題上勝過多個元件合成基線與 matched 的 full-synthesis 對照組。

方法骨架

  • Scaffold-free：只固定問題規格（目標、限制、合法解）與最小 I/O 介面，LLM 自行決定元件庫存、互動與控制流；external evaluator 只負責驗證與重算目標值，不修補或補全不可行解——這把失敗面從「執行錯誤」擴大到「不可行／格式錯誤輸出」。
  • Embedding-based similarity：用 mGTE-large-en-v1.5 把 （名稱， 描述， 前處理過的原始碼） 串接成單一文本 embedding，維護 cosine-distance 矩陣，支援 k-NN 檢索、聚類與去重剪枝——不需要手設計 behavior descriptor。
  • Coverage-preserving archive：兩層去重（strict 去重近乎相同者；performance-aware 去重「相近且分數差在容忍值內」者）＋容量限制剪枝（超過容量時，從最相似的一對中移除表現較差者，但保護 elite region 不被剪）。
  • 語意搜尋算子：Create（零參照，初始化用）、Improve/Tune/Simplify（單參照，維持既有範式的精煉）、Combine/Diverge（多參照，跨區合成／刻意远離既有區域）、Repair（依六種失敗模式分類，把失敗證據路由回 LLM 重新生成整個候選）。
  • 三層搜尋：Layer 1 集中精煉當前最佳 a* 及其 embedding 近鄰；Layer 2 讓每個非 elite cluster 的代表獲得專屬精煉機會；Layer 3 跨 cluster 做 Combine／Diverge 重組元件與互動，產生新的混合設計。Cluster 每輪用 k-medoids（自動選 K）在 embedding 空間重新計算，不是固定的 behavior-descriptor grid。

作者報告的實驗與數字（皆為作者主張）

四個問題（CVRP、CVRPTW、FSS、QAP，各 31 訓練＋31 測試 instance，5 個獨立 run 取 training-best）上，ATLAS 相對於「統計上最佳的人工設計基準」的 test set 相對均值差距：FSS 0.347%、CVRP 0.094%、CVRPTW 0.000%、QAP 0.460%；paired Wilcoxon 檢定下對所有 LLM-based baseline（EoH、ReEvo、MCTS-AHD、以及作者為公平比較特別構造的 EoH-Full full-synthesis 對照組）都有統計顯著優勢，CVRP 上與人工設計的 PyVRP 無顯著差異。三層搜尋消融（Table V）顯示完整三層配置最佳（CVRP gap 0.094% vs. 只用 Layer1 的 3.620%、只用 Layer3 的 2.095%）。作者也用程式碼檢視展示：單一 run 的最終 archive 常同時保留數個 test gap 都在 1% 以內、但核心建構或全域搜尋機制不同的代表（如 regret insertion、savings-based、ruin-and-recreate、tabu-guided local search 等），佐證多模態保留確實發生，但作者明講這不等於證明「embedding cluster 全域對應真實機制家族」或「per-instance portfolio 互補」。

對 ai_core 的價值／接點

這篇對 ai_core 的「archive／族群設計」章節有直接可搬的做法：用預訓練文本 embedding（而非手設計的行為描述子）當 QD 座標，靠 cosine distance 支撐 k-NN 檢索、聚類與去重，省去手工設計 descriptor 的成本，這對 ai_core 若要做「不依賴領域知識」的多樣性度量是個現成參照，但也要注意 Loreley（另一篇同批論文）指出的反例：純檔案/程式碼 embedding 均值在改動集中於局部時可能鑑別力很弱，ATLAS 之所以有效可能得益於「名稱＋描述＋原始碼」三者合併輸入，語意描述文字（LLM 自己生成的 name/description）本身就承載了設計意圖，這點值得 ai_core 在挑 embedding 輸入時參考。另一個直接可用的結構是「三層資源分配」：精煉當前最佳、給非當家代表專屬精煉機會、跨區重組，這比單純的 archive 取樣＋均勻機率更能兼顧收斂與覆蓋，且用 cluster 而非固定 grid，避免 MAP-Elites 常見的網格解析度調參問題，對 ai_core 若要設計「不依賴預先固定維度切分」的 archive 管理策略是個具體可仿的範例。最後，"error-conditioned Repair" 把失敗分類（memory limit／timeout／constraint violation／runtime error 等）路由到不同修復 prompt，而非一律丟棄或給有限懲罰值，這對 ai_core 的程式合成／演化流程處理「無效候選」時是可直接借用的設計。
