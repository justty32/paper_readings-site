Code to Control 重點摘要

一句話概括

Code to Control 把部署時的 LLM 推理或世界模型規劃，改成直接執行 Python 控制器。離散遊戲由 LLM 根據實玩軌跡修訂整份策略；連續控制則由 LLM 提議特徵程式，再用環境回報驅動的無導數搜尋擬合權重。快的是學完後的動作選擇，不代表合成與訓練沒有 LLM 或環境成本。（§2、§5）

問題與方法

世界模型方法要先學轉移模型，再於決策時規劃；模型誤差和規劃成本都可能妨礙即時控制。本文直接搜尋可執行策略，適用於當前觀測已足以支持有效反應的任務。輸入不是原始像素：Atari 由 OCAtari 提供物件類別、框中心、尺寸與相鄰影格估計的速度；Flappy Bird 使用同類物件介面；MuJoCo 提供關節位置、速度等結構化物理狀態。LLM 取得狀態格式、原始動作、物件 API、通用任務說明及初始觀測，但不直接取得環境動力學或示範。（§2.1–2.2、§3.1）

  • 離散領域：LLM 合成 policy(state) -> action，執行後讀取該策略、軌跡與回報，再修訂最新策略。數值常數也由 LLM 負責，沒有另外替初始遊戲策略調參的搜尋器。系統另外保存歷來最佳策略，避免後續退步覆蓋成果。（§2.2.1、附錄 A.1–A.2）
  • 連續領域：先用隨機動作蒐集轉移，LLM 獨立合成多組特徵映射 phi(o,t)；每組固定後，由 Augmented Random Search（ARS）擬合矩陣 W。實驗提示要求每組回傳 14 個特徵。回報只用來調整該候選的 W，不回傳給 LLM 修訂特徵結構，權重也不展示給 LLM。（§2.2.1、附錄 A.1–A.3）

連續策略為 clip(W * normalized_phi(o,t), action_min, action_max)。運行中的均值、變異數正規化可避免特徵尺度讓相同幅度的權重擾動產生懸殊影響；外層裁切符合致動器範圍。時間步可產生週期訊號，與當前狀態回饋共同形成控制，但不等於保留完整歷史。程式內可以用速度外推目標，所謂「無規劃」不是完全沒有預測，而是不在決策時展開世界模型搜尋。（§2.2、§3.2、附錄 A.3）

Atari：效能、搜尋代價與評估口徑

以下皆為作者自報。評分是每次搜尋中最佳 episode 分數，再取三個 seed 的中位數，不是固定最終策略在大量獨立測試 episode 上的平均表現。環境步數按 §3.2 Evaluation 定義，累計至找到報告控制器的最佳 episode 之前，不含該 episode；LLM 呼叫與 token 數則依原圖所報，不將環境步數的截點自行套用到這兩欄。Code to Control 每回合呼叫一次 LLM，預算 20 次；WorldCoder 預算 30 次；ReAct 每個動作都呼叫 LLM，改以 token 限制。PoE-World 只比 Pong，另取得其他方法沒有的 650 步人類示範。（§3.2、圖 2）

本摘要的成本邊界解讀：圖 2B 的總 token 成本、圖 2C 的報告控制器成本欄與 PPO 的訓練預算，不能混為相同統計口徑，也不能當成部署成本。作者依上述截點討論互動效率，沒有把 API 價格或整體訓練牆鐘時間統一換算；這些數字不足以代表完整搜尋、訓練或完整取得成本。（依 §3.2、圖 2B–2C 判讀）

搜尋並不單調改善。作者自報 360 個 Atari episodes 中，72% 低於該次搜尋迄今最佳分數，28% 比前回合下降超過 25%；最佳策略出現回合的中位數為第 5 回合，少數直到第 19 回合才改善。這些實驗沒有語法錯誤、非法動作或執行崩潰，主要失敗是修改破壞有效控制邏輯，不代表任意生成程式都安全可靠。（§3.2）

決策延遲：只在指定量測邊界內成立

作者自報在遊玩中遇到的 300 個狀態上測量單步策略執行，取跨狀態中位數：Code to Control 為 11.4 微秒，PPO 76.5 微秒，ReAct 1.29 秒，WorldCoder 46 毫秒。ReAct 包含單次 LLM API 呼叫；規劃法用規劃時間除以該次規劃供應的動作數。圖中標示 95% 信賴區間，但 WorldCoder 誤差棒是三次執行的範圍。（§3.2、圖 2D）

證據邊界：這是學成後的動作產生時間，沒有證明包含影像擷取、物件辨識、環境模擬或訓練的端到端系統更快。主文及所附關鍵附錄未充分交代硬體、PPO 執行裝置、batch 或暖身設定；因此「比 PPO 快」應保留「依作者此計時流程」的限定，不能泛化為所有神經策略。（本摘要依 §3.2 與附錄 A 的資訊完整性判讀）

Flappy Bird：遷移不等於重新調參

作者只在原版遊戲合成策略，再測試八種重力、阻力、拍翅強度、管道速度或缺口寬度改變。原版控制器用 21,419 環境步、20 次 LLM 呼叫與 96k tokens，存活至 20,000 步評估上限；311 分受該上限限制，不能解讀成策略能力的自然極限。作者以存活為主要成功指標，PPO 約需 200 萬互動步達到相近持續遊玩。（作者自報，§3.3、圖 3A）

三個 champion 在重力增加、速度相關阻力、回合中途重力增加及較窄缺口下，都能不改動地存活至上限。凍結策略失敗後，作者固定程式結構，只依新環境回饋重擬合常數，不再呼叫 LLM；文中稱五個失敗格中有三個恢復至上限，其餘兩個改善但未達上限，並指出反轉重力方向未能恢復成功遊玩，需要結構改動。（作者自報，§3.3、圖 3B）

本摘要保留原文「失敗格」的表述，不把它擅自改成五種不同擾動或五個獨立成功率。重新調參使用了新環境互動，與直接使用凍結控制器的零樣本遷移必須分開。（本摘要解讀）

MuJoCo：結構合成與數值最佳化的組合

作者自報在十項任務中，九項高於 GIF-MCTS 與 WorldCoder，例外為 Reacher；也全數高於引用自既有研究的 CQL 結果。Code to Control 每環境使用 6 次 LLM 呼叫，兩個程式世界模型基線各用 30 次，採相同 LLM 後端與取樣設定。作者明說沒有做匹配環境互動預算的 MuJoCo 樣本效率比較；較少 LLM 呼叫不表示 ARS 的 rollout 成本較低。（§3.4、圖 4）

回報也不等於走得好。作者報 HalfCheetah 在 1,000 步走 212.55 公尺、均速 4.25 公尺／秒，Swimmer 位移 12.83 公尺、均速 0.321 公尺／秒；兩者沒有存活獎勵。相較之下，Humanoid 回報 472.92 卻有 -0.44 公尺中位位移，累積存活獎勵為 512。部分任務可藉少量移動和維持存活得到不低的回報，不能把所有任務成績稱為成功行走。（作者自報，§3.4）

限制與閱讀判斷

作者明示：尚未從像素直接學習；過度修訂可能毀掉好策略，固定結構又限制適應；回報設計會影響所學行為；需要顯式預測與長期前瞻的問題仍可能較適合世界模型規劃。（§5）

本摘要的判斷：本文最清楚的貢獻，是用可解讀程式表徵與數值最佳化分工，把大量計算移出決策時刻。尚不足以推出一般控制的全面優勢：物件與物理狀態屬結構化、相對具特權的輸入，不能當成與像素端到端 RL 同條件；文中不足以核定各基線感知成本及觀測資訊完全相同。連續任務缺少完整匹配互動預算，也未提供足以隔離 LLM 特徵貢獻的純 ARS 特徵對照。這些是證據缺口，不是本文已證明的失敗。（依 §2–3、§5 及附錄 A 判讀）
