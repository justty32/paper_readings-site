論文／訪談原始來源

《智能體系統的自動化設計（Automated Design of Agentic Systems, ADAS）》重點摘要

一句話概括

ADAS + Meta Agent Search（元智能體搜尋）：把「整個 agent 系統本身」當成可自動搜尋的程式空間——用一個 meta agent（元智能體，本身也是 LLM）以程式碼反覆發明並改寫出更好的 agent（其 prompt／工具／工作流全在一個 forward() 函式裡），基於一個持續成長的發現檔案庫（archive）逐輪迭代；因為程式語言是圖靈完備的，此搜尋空間理論上涵蓋所有可能的 agent 設計，實測發明出的 agent 大幅勝過人類手工設計的 SOTA，且能跨領域、跨模型遷移仍保持優勢。

解決什麼問題

現今強力 agent 的建構模組（Chain-of-Thought、Self-Reflection、Toolformer、RAG、多角色協作……）全靠人類專家手工設計與調校，費時費力且組合爆炸。機器學習史反覆證明：手工製品終將被學習出來的解取代（HOG→CNN、手工架構→NAS）。作者因此提出新研究領域 ADAS：能否把 agent 系統的設計本身自動化？既有嘗試多半只優化 prompt（OPRO、PromptBreeder），或把 agent 表示成圖／網路只優化節點連線（DyLAN、GPT-Swarm、DSPy、Trace）——都無法涵蓋工具使用等全部組件。

核心方法

  • ADAS 的三要素（把它formulate成最佳化過程）：搜尋空間（能表示哪些 agent）／搜尋演算法（如何探索、權衡 exploration-exploitation）／評估函式（用什麼目標評分，如驗證集準確率）。
  • 關鍵主張——用「程式碼」當搜尋空間：因大多數程式語言圖靈完備，程式空間理論上能表示任何 agent（prompt、工具、workflow 及其任意組合）；且程式碼可讀（利於除錯與 AI 安全）、能直接站在 LangChain 等既有框架與人類成果之上，並能借力 FM 本身的寫程式先驗。
  • Meta Agent Search 演算法：給 meta agent 一個 <100 行的極簡框架（提供 query FM、格式化 prompt 等基本函式），它只需寫出一個 forward(Task)→Answer 函式來定義新 agent（仿 FunSearch）。流程：(1) archive 選擇性以 CoT／Self-Refine 等 baseline 初始化；(2) meta agent 依 archive 先產出高階想法再寫成程式碼，經兩步自我反思確保新穎；(3) 在目標領域驗證集評估，出錯則自我反思修正、最多重試 5 次；(4) 連同評估指標加入 archive，反覆到達最大迭代數。仿開放式演化（open-endedness）鼓勵探索「有趣（新穎／有價值）」的 agent。
  • 實驗設定：meta agent 用 GPT-4，被發明的 agent 與 baseline 一律用 GPT-3.5 評估以省成本。

結果

  • 勝過手工 SOTA（表 1，獨立於各領域搜尋）：Meta Agent Search 對比 CoT/COT-SC/Self-Refine/LLM-Debate/QD/Role-Assignment 等，Reading Comprehension F1 79.4（baseline 最佳約 65.8，增 +13.6/100）、Math(MGSM) 53.4%（增 +14.4%）、Multi-task 69.6、Science 34.6，且一致勝過純 prompt 優化（OPRO）。
  • 跨領域遷移（表 2）：把 MGSM(Math) 上搜到的 top agent 遷到 GSM8K／GSM-Hard，分別較 baseline +25.9%／+13.2%；遷到 MMLU、DROP 等非數學領域也仍勝過手工 baseline。
  • 跨模型遷移（表 3，ARC）：在 GPT-3.5 搜到的 agent 遷到 Claude-Haiku／GPT-4／Claude-Sonnet 仍領先；最強的 Claude-Sonnet 讓最佳 agent 在 ARC 達 ~48.3%。
  • 可觀察的「踏腳石（stepping stone）演化」：ARC 上第 3 輪出現「多 CoT 生成→精修→集成」的關鍵模式，後續設計反覆沿用；最佳 agent 的複雜回饋機制由第 5／11／12 輪陸續冒出的想法組合而成（類似 LLM 驅動的演化交叉）。

局限

  • 目前只在單步 QA 任務驗證，未及多步、與複雜環境互動的真實應用。
  • 只優化單一目標（performance）；成本／延遲／穩健性等多目標留待未來。
  • 評估昂貴且只用數值分數，浪費了執行日誌中的失敗/成功資訊。
  • 從零 program 一切雖理論可行但實務低效，需給基本函式與種子。
  • 安全：模型生成的程式碼可能有破壞性——作者以容器隔離執行、人工審查、程式庫警語因應。

對讀者的價值

  • 歸 I 類，短名 ADAS。對 ai_core §1「系統＝可優化的符號神經網路計算圖」是一個極致版本的參照：GPTSwarm/DSPy/Trace 優化的是固定圖上的節點/連線/prompt，而 ADAS 把連計算圖的結構本身都交給 meta agent 用程式碼自動生成——等於「可優化計算圖」推到最遠端（結構亦可學）。這正好標出 ai_core 的取捨邊界：ai_core 要的是逐步剃除 LLM 依賴、把反覆案例固化成確定性程式碼（§3.6 固化引擎），而 ADAS 反其道讓 LLM 去生成更多 LLM-heavy 的 agent——兩者可互補：可把 ADAS 當「上游探索器」離線搜出好結構，再由 ai_core 的固化流程把穩定下來的節點結晶成確定性函數。
  • 與已入庫的 GPTSwarm/DSPy/Trace（優化既有圖）及 Agent Symbolic Learning（語言版反向傳播、聯合優化 prompt+工具+pipeline）對照：ADAS 的獨特點是搜尋空間＝圖靈完備的程式碼、以 archive 開放式演化、且主打跨領域/跨模型遷移與可讀性利於安全。最值得記：「meta agent 寫程式發明 agent」＝把 agent 設計問題本身變成可搜尋最佳化、程式碼搜尋空間的通用性論證、以及 higher-order/self-referential ADAS（meta agent 亦可被 ADAS 改進） 的自指前景。
  • 定位：新研究領域宣言 + 概念驗證演算法 + 實證，開源（github.com/ShengranHu/ADAS）。適合做 agent 自動設計、程式碼即搜尋空間、open-endedness／AI-GA、自我改進 agent 的人。
