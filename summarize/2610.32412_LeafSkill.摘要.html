論文／訪談原始來源

LeafSkill：只把葉節點動作接地交給小模型

核心想法與權限邊界

ReCAP已把目標拆到某個leaf task後，仍會呼叫27B host，把「拿起某食材」轉成環境接受的一步action。作者保守audit在library來源軌跡中，strict leaf/action grounding佔Robotouille Sync／Async host tokens22.9／23.7%，ALFWorld44.5%。LeafSkill外置重用這一小段，讓BGE語意檢索提出task–action templates、deterministic binder綁當前state的admissible actions，再由Qwen3-1.7B選一個candidate或abstain。它不接管decomposition、parent plan、recovery或completion；host仍是ReCAP＋Qwen3.5-27B。（§1、§3）

\[G_\theta(\tau_t,o_t,\mathcal A_t;\mathcal L)\in\mathcal A_t\cup\{\bot\}.\]

\(\bot\)是state-preserving fallback：沒有委派action執行，同一task node回原host。候選是request-local support，不是對整個\(\mathcal A_t\)的policy；selector只能回local ID／\(\bot\)、不能生成free-form commands。介面允許執行不等於動作符合leaf intent，後者仍可能選錯；論文的all-negative診斷直接顯示這個差距。（§3 Leaf-Level Delegation、Retrieve–Bind–Select、§4 Selection and abstention；粗體證據界線為本檔補註，非作者自陳）

Retrieve、bind、select各做什麼

Library每skill是canonical task／action-template pair，保surface forms及provenance；同task key可有多個state-dependent actions。BGE-small-en-v1.5依task key取top5、similarity≥.70，再讓該key所有templates進binding；retrieval只求recall，不能直接授權執行。（§3 Retrieve–Bind–Select、§4 Controls）

Canonicalization小寫、接合spaced object IDs、tokenize alphanumerics、把instance suffix轉typed placeholders。Binder枚舉當前\(\mathcal A_t\)中的介面字串，匹配canonical action，並要求task提到的每個具體object ID都在action裡；不是請model生成slot values。只留exact admissible commands、合併重複skill–action pairs。（§3 Canonicalization and binding）

Selector只看task、local observation、admissible actions及localized candidate descriptions，不看root goal、ancestor path、remaining plan、persistent skill ID或historical support statistics。Candidates shuffle且每次重新localize ID，選後resolve再查admissibility；empty retrieval／binding、explicit abstention、unknown ID、stale mapping或final check失敗都fallback。Failed local execution相關skill可只在該episode暫時mask，跨episode重設，不改library。（§3 Selector and guards、表3）

Eligibility是結構邊界，非相似度或confidence：Robotouille用native atomic-leaf flag；ALFWorld只非root、downward execution phase，排除root、upward return及revisit。故同一句「check fridge1」在下降處理未解child時可委派，在recovery revisit時不可。（§3 Adapters、表2）

Library、supervision與split

Robotouille Group A200source trees中199有pair，抽11483task–action instances，canonicalize成413keys／446skills。這是local task→後續action歸屬，不宣稱來源trajectory globally optimal。Group B200tasks用作repeats／ablations，只有growth條件才把其ReCAP traces加庫；Group C200永不進construction／model selection／adaptation。ALFWorld valid_seen140episodes供library及可選adaptation；successful source episodes留1091logged instances、1089unique executable contexts，226keys／228skills；valid_unseen134供final evaluation。（§3 Library construction、表4）

SFT只更新1.7B selector：重現retrieval/binding，trace action存在就標對應request-local ID，不在就\(\bot\)。Mixed-rank資料把正確action移離rank1並放intent-conflicting distractors。Robotouille413keys中289可進3177-decision training set，124保留adoption診斷；ALF適應用1089contexts。Default ALF先Robotouille SFT再valid_seen SFT，transfer-only／target-only分別略第二／第一階段。（§3 Selector adaptation）

各stage一epoch rank16 LoRA，batch1／gradient accumulation16／lr\(2\times10^{-5}\)／max length1536，單A80080GB；加planner context診斷max1792。Host、planner、retriever、binder不更新，evaluation無online memory update。新skill只在既有action grammar、typed slots、retriever、exact admissible binding及local description schema內相容；local IDs不會自動教新binder或新action semantics。（§3 Compatible additions、§4 Controls）

成本比較的分母

Success用所有scheduled episodes，terminated算failure；差異用兩側exact McNemar。Host efficiency只對每個run pairing中兩系統都成功的task計Qwen3.5-27B prompt＋completion tokens及calls，避免失敗何時停止混入接地成本。兩系統各三repeats時，九cross-run cells各自先取共同成功交集、算cost ratio，再取九個reduction的算術平均；不是把同200tasks當600獨立樣本，也不是先pool所有tokens才算ratio。Single-run ablation則對三ReCAP repeats平均；C的cost CI是task-level bootstrap95%。（§4 Metrics）

比較共用task IDs、model services、context limits、decoding與termination；retrieval不做test hyperparameter search。ALF十round-robin shards、49-action limit，每run記全134unseen games。Controller和host tokenizer／scale不同，1.7B開銷另報，不把raw tokens直接相加或當完整美元／延遲節省。（§4 Controls、Controller overhead；最後成本界線為本檔補註，非作者自陳）

End-to-end結果

Robotouille B九pairings平均host tokens−23.09%（16.85–29.68%，每pair \(n=87\)–93）、calls−22.54%。三個同run success比較：ReCAP55.5／56.5／53.0%，Leaf61.5／65.5／59.5%，增加6.0／9.0／6.5pp；McNemar\(p=.126/.025/.079\)，不是每次都顯著。（§4 Robotouille、表6）

獨立Robotouille C用frozen A library：全200tasks成功121→137（60.5→68.5%，\(p=.0259\)）。兩者共同成功106tasks上tokens−14.4%（CI[3.0,24.5]）、calls−14.1%（CI[3.6,23.3]）。14.4%是成功交集成本，不是全200tasks總成本下降。（表5、表6）

ALF default sequential九pairings tokens−41.32%（36.73–45.21%，\(n=114\)–117）、calls−41.75%；all-scheduled mean success89.8→91.8%。R1同90.3%、R2與R3各89.6→92.5%，\(p=1.00/.344/.424\)；數值提高不等每run顯著。（§4 ALFWorld、表6）

Controller額外成本：B R2–R3共400episodes／3849calls／3.98M tokens；C200／1355／1.38M；ALF三runs402／4636／3.31M。量測每episode6900–9952tokens，每call714–1034；B R1有1485calls但尚未token instrumentation，缺值不當0。（表7）

Ablation：admissibility與語意選擇分開

Robotouille B的RawPair-Exact／RawPair-BGE token reductions .20／8.08%；state-bound BGE Top1直接執行13.08%。Canonical-Exact＋SFT在原措辭成功134/200（67.0%）、tokens−29.60%，但reference action coverage從原99.5%降到lexical／syntactic rewrites皆0；semantic Top5在兩種200例rewrites保96.0／97.0%。這些是candidate coverage，不是end-to-end success。（表8–9、Retrieval and binding）

193個mixed-rank cases、最多四個admissible但intent錯誤distractors且正確action放最後，Base→SFT accuracy81.9→93.3%。End-to-end Base成功113/200、tokens−27.01%；SFT三runs mean success62.17%、tokens−23.09%，direct R2比Base高9pp（\(p=.0198\)）。SFT不是所有cost metric都更省，重點是執行與fallback的選擇。（§4 Selection and abstention、表8）

200例all-negative OOD刻意bypass object-coverage binding，只給admissible卻全不符合leaf intent的candidates；正解應fallback，SFT卻僅7.5%做到。這是controller-only stress，不是online abstention rate，支持先做deterministic binding，不能包裝成小模型已可靠辨識任何不適合重用情況。另以相同3177examples分別train的local／加真planner context selectors，在同193mixed-rank cases為93.3／90.7%，不證明planning context普遍無用。（Controlled protocol、表9；後一界線為本檔補註，非作者自陳）

Growth與transfer：相容新增可用，但非每項都提高

在selector training之後用B traces擴A library，413→527keys、446→588skills，不看C、不更新selector。固定三系統都成功的88個C tasks上，對ReCAP token reduction18.35→25.64%、calls17.70→24.22%。直接比較兩libraries的105共同成功則A+B比A省tokens11.41%（CI[2.29,19.49]）、calls10.36%。全C成功A137/200、A+B131/200，\(p=.5118\)；成本收益不能寫成成功率全面提升。Controlled adoption另插124held-out compatible keys，adoption97.3%、retention98.9%，不是任意新skill語法泛化。（§4 Growth、表10）

ALF各route均同228-skill library、三valid_unseen runs平均：bare1.7B success84.33%／use79.41%；Robot-only91.29／70.99；ALF-only86.07／98.02；sequential91.79／98.81；ReCAP89.80%。ALF-only token reduction43.43%、sequential41.32%，default取後者的較高success；不同route的use、success、tokens不當同一指標。（表11、§4 Controller transfer）

作者限制

需要反覆出現且可parameterize的leaves、離散admissible-action interface及environment adapter。新grammar要新adapter／binder；open-ended或continuous actions需更豐富介面。目前證據只有一planner、一host、兩environment及一selector family。實測是可與recursive planning互補的state-bound reuse，不是替代host推理或通用安全／總成本保證。（§5；最後保證界線為本檔補註，非作者自陳）
