論文／訪談原始來源

《TroVE：為程式化任務歸納可驗證且高效的工具箱》重點摘要

一句話概括

TroVE：一個免訓練（training-free）的方法，讓 code LM 在串流解題過程中邊用邊長出一個可復用的高階函數工具箱——每題以 IMPORT／CREATE／SKIP 三模式各採樣 K 個候選，靠執行結果一致性（execution agreement）＋偏好低複雜度選出最佳解並沉澱其函數，再週期性修剪（trim）低使用率函數；在數學、表格 QA、視覺推理共 11 個資料集上，以比既有工具製造方法小 79–98% 的工具箱取得更高正確率，且使人工驗證解答快 31%、準 13%。

解決什麼問題

  • LM 用 Python 原始函數（primitive functions）寫解答時，程式冗長、易錯、難驗證（使用者得逐一檢查每個操作及其交互）；高階函數雖簡潔準確，卻向來依賴人類專家手工設計，昂貴且難以擴展到新領域。
  • 既有 LLM 造工具方法各有代價：CREATOR 產出數百上千個難復用、難驗證的工具；LATM／CRAFT 需額外訓練集與驗證集、外掛自我驗證或去重模組；Voyager 需迭代自我驗證與課程學習。TroVE 主張零訓練、零監督、零迭代，只需測試資料流本身。

核心方法

  • 三模式使用與生長工具箱（§3.1）：維護一個隨時間演進的共享函數庫 F（初始為空），串流式線上處理每個例子；每題同時以三種模式各採樣 K=5 個回應（共 3K）——IMPORT（從工具箱匯入既有函數來解）、CREATE（創建新函數並入庫）、SKIP（只用原始函數）。（初步實驗顯示讓模型自選單一模式會顯著變差。）
  • 基於一致性的選擇（§3.2）：執行全部候選解、剔除跑不動的；按執行輸出的自我一致性（self-consistency）選最高頻答案的解；同頻者取操作數最少（偏好簡單）；再平手取第一個。當選回應的函數入庫、解答定案——執行共識充當免監督的驗證訊號。
  • 週期性工具箱修剪（§3.3）：每 200 步移除使用次數低於 λ 的函數，λ = ½·log₁₀(n)（n 為已處理例數，因觀察到函數使用頻率與資料量呈對數關係）；被修剪函數波及的舊解（<5%）以 IMPORT＋SKIP 模式重生成。
  • 主實驗用 CodeLLaMa2-7b-Instruct（首次證明開源 LM 能造工具），另用 GPT-4 與 SOTA 公平比較；三個評估指標：正確率（acc）、解答複雜度（# ops，AST 深度總和）、函數庫大小（# lib）。

結果

  • 對比基線（表 2，CodeLLaMa）：MATH 七科正確率較 Primitive 提升 30–120%；較逐例造工具的 Instance 高 8.7–83.3% 且少用 60.0–90.2% 的工具。TableQA／GQA 上 Instance 造出數百到 3,175 個低效函數反而低於 Primitive（選項太多干擾模型），TroVE 靠復用＋修剪全面最佳（如 GQA：0.44 vs Primitive 0.37 vs Instance 0.16，僅 7 個函數）。
  • 對比 SOTA（表 3，GPT-4）：MATH-algebra 0.72／16 函數（CRAFT 0.68／282；CREATOR 0.65／875；LATM 0.30）；TabMWP 0.92／38（CRAFT 0.88／181；CREATOR 0.81／4,595）；GQA 0.44／8（CRAFT 0.45／525）——以極簡管線與極小工具箱勝過或追平需額外監督／迭代的方法。
  • 人工驗證研究（§6，WTQ 100 例 × 6 人）：TroVE 驗證每例平均 17.5 秒（比 Primitive 快 31.4%、比 Instance 快 43.0%），偵錯準確率 0.87（比 Primitive 高 13%）；不可復用的 Instance 工具反使驗證變慢 20.4%。
  • 消融：去掉修剪 → 函數庫膨脹 74–90%，正確率與複雜度亦劣化；對例子順序穩健（5 種隨機排序結果差異極小）。7B CodeLLaMa 在 GQA 上藉造工具追平 GPT-4（皆 0.44）——當原始函數不在預訓練分佈內時，大模型優勢即消失。

局限

  • 一致性選擇是弱驗證：共識答案未必正確，複雜度並列時的仲裁近乎任意；修剪門檻／間隔為手調超參數。
  • 依賴「答案可自動執行比對」的任務型態；每題需 3K=15 次採樣（報告 5 次重跑的最佳值），推論成本不低。
  • GQA 顯示：當有效的可復用函數難以歸納時，多數自創函數無效並拖累解答生成（Instance 掉 0.21）。

對讀者的價值

  • 對 ai_core §3.6 固化引擎的直接藍圖：TroVE 就是一個極簡的「案例→工具庫」結晶迴路——LLM 反覆處理的案例流中，共用結構被 CREATE 出來、被 IMPORT 復用、不被復用的被 trim 掉。使用中生成／復用／修剪三件套給出了工具資產「沉澱與汰換」的完整生命週期，且證明它可以免訓練、免額外監督、線上線性時間運行——固化引擎不必是離線批次工程，可以是常駐的串流過程。
  • 對 §2 資產治理的啟發：修剪規則 λ=½·log₁₀(n) 是「使用頻率＝資產存續憑證」的具體實作——入庫容易（CREATE 即入）、留下難（不被復用就淘汰），與「拒絕為預設＋憑證准入」精神互補：TroVE 示範的是事後汰換而非事前准入，兩者可疊加。反面教材同樣珍貴：Instance／CREATOR 式「每案例都造工具、從不修剪」直接導致數千個殭屍資產、消費端（解答生成）反被拖垮——資產庫大小本身是一級治理指標。
  • Agreement-based 選擇＝可用的弱驗證訊號：在無 ground-truth 處，用「多次獨立生成的執行共識」替代形式驗證，正合 ai_core 把 LLM 呼叫包成可靠函數時「驗證訊號從哪來」的難題；且人工驗證實驗證明好的抽象讓人審快 31%、準 13%——固化不只省 LLM 呼叫，還降低治理（人審）成本。
  • 定位：方法論文＋充分實證（11 資料集＋人工研究＋消融），開源（github.com/zorazrw/trove）。適合做工具歸納、函數庫生命週期管理、免監督驗證訊號的人；與 2305.05176 FrugalGPT 的成本梯度互補——FrugalGPT 省在「路由到便宜模型」，TroVE 省在「把重複智能結晶成確定性程式碼」。
