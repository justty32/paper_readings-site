論文／訪談原始來源

《AutoSkill：以技能自我演化做經驗驅動終身學習》重點摘要

一句話概括

用戶會在跨會話中反覆表達穩定偏好（減少幻覺、遵循機構寫作規範、避免術語），但這些互動經驗很少被固化成可重用知識，導致 agent 無法跨會話累積個人化能力；AutoSkill 是一個免訓練、提示驅動的終身學習框架，把重複互動經驗結晶成顯式、可編輯、有版本的 SKILL.md 技能工件（而非只存對話片段或偏好記錄），自動抽取/維護/合併/檢索並動態注入未來請求——把易逝的互動經驗轉成可檢視、可修訂、可組合的能力，不更新底層模型權重。

解決什麼問題

LLM agent 從受控基準走向真實部署時出現一個反覆模式：用戶跨會話重述穩定偏好與操作要求，但這些經驗很少被轉成可重用能力，導致每個新會話都要從頭重建用戶習慣與任務期望。既有方案只解部分：參數更新/自我演化能改行為但對「頻繁、細粒度個人化」往往昂貴或難控；記憶式方法保存事實/偏好/對話，但把過去互動當「待檢索的文字」而非「待操作化的行為」；技能學習方法展示可重用策略價值，但技能常隱含在 prompt/軌跡/policy 裡，缺乏統一的檢視、編輯、遷移、長期維護機制。缺的是「把重複互動經驗轉成顯式、可重用、可維護技能」的機制。

核心方法

AutoSkill 把「重複互動經驗」視為技能形成的來源而非僅記憶，兩個緊耦合的迴圈：

  • 技能演化迴圈（上）：把互動經驗透過抽取與維護轉成顯式技能。技能抽取只用用戶查詢（{q₁…q_t}，不用模型回應 r_t 當證據，避免自我確認）；檢索輔助的技能管理用最近鄰判斷新增/更新/合併；版本化技能合併把相關技能整併成一個改良技能。技能表示為結構化卡片：<名稱 n, 描述 d, 可執行指令 prompt p, 觸發集 τ, 標籤集 γ, 範例集 ξ, 版本 v>。
  • 技能增強回應迴圈（下）：用當前技能庫支援回應生成——查詢改寫 → 混合（dense + 關鍵詞）技能檢索 → 帶門檻的 Top-K 技能注入 → 技能條件化生成。
  • 完全免訓練：以六個提示驅動模組實作（查詢改寫、對話回應、技能抽取、技能管理裁判、技能合併、嵌入向量化），每個模組＝通用 LLM + 對應 prompt；改進全來自顯式技能的構建/檢索/精煉，不優化任何模型參數。
  • 定位為模型無關的 plug-in 層，可置於上游 LLM 前當外部記憶與適應層、不改客戶端呼叫模式，並提供跨 agent/用戶/任務的標準技能表示以利分享遷移。

結果

（本文為系統 + 經驗性語料研究，評測是「從真實互動挖出的 SkillBank 統計 + 案例研究」，非任務準確率對照）

  • 語料：在 WildChat-1M（真實用戶與 ChatGPT 互動）上只保留 >8 輪對話，分中文/英文 × GPT-3.5/GPT-4 四子集各建 SkillBank。英文 GPT-3.5 子集最大（10,243 對話、267,681 訊息、631 技能），中文 GPT-4 最小（1,145 對話、36,834 訊息、224 技能）；GPT-4 子集平均對話更長（30.23–32.17 訊息/對話）。
  • 技能分布：最頻標籤多為程式與資料任務（python 居首，次為 javascript、excel、c++、pandas），另有 creative writing、formatting、education、translation、roleplay；類別上「程式與軟體開發」最大，寫作/資料/通用混合亦佔大宗；平台技能集中於 Twitter/X、Instagram、YouTube。
  • 版本化演化證據：英文技能 professional_text_rewrite 版本 0.1.34（初建後經 34 輪增量優化），中文技能「顶级心理咨询师」仍 0.1.0（近初始態）——證明技能按相關用戶回饋復現頻率以不同速率演化，高頻生產力技能被反覆合併精煉，而非簡單複製堆積。
  • 案例：中文心理諮詢師（抽象高層人際偏好＝溫暖/同理/專業/不亂下診斷）與英文專業改寫（操作型寫作能力＋強反模式約束）——同一工件格式既支援軟性互動行為、也支援剛性任務執行程序，並天然支援多語個人化。

局限

  • 缺乏任務級量化基準：評測以語料統計與案例研究為主，未做與其他記憶/技能系統的 head-to-head 準確率對照，難量化「對最終回應品質」的實際增益。
  • 完全依賴 LLM 提示驅動的抽取/合併/裁判模組品質；若抽錯技能或錯誤合併，會把劣質行為固化進長期工件。
  • 技能抽取只用查詢不用回應雖避免自我確認，但也可能漏掉「需從成功回應才能學到」的程序性技能。
  • 個人化偏好型技能的「正確性」較主觀，缺乏驗證者把關（對比 2606.24428 EDV 的共識驗證）。

對讀者的價值

  • 提出一條與「存記憶」不同的終身學習路線：把累積單位從「原始記憶記錄」上移到「顯式行為知識（技能）」——技能可檢視、編輯、合併、版本化、跨會話重用，對需要「穩定個人化、可審計、可人工修訂」的部署場景特別契合。
  • SKILL.md 工件 + 版本化合併是值得記住的設計：與 Claude Code 的 skills 機制同構，把「易逝經驗→第一類可維護工件」落地；與 Voyager 的技能庫呼應，但 AutoSkill 強調人可編輯、可版本管理而非黑箱 policy。
  • 與本批互補：AutoSkill 累積「技能/行為」、2606.19847 AtomMem 累積「事實/偏好」、2509.04439 ArcMemo 累積「概念抽象」、2606.04815 LifeSkill 把技能內化進權重——四種「累積什麼、存在哪」的不同答案，值得並讀建立記憶/技能累積的設計光譜。
  • 最值得記：「技能抽取只用用戶查詢、不用模型回應」（避免把自己的錯誤當證據）、以及**「技能應是可版本化的第一類工件而非隱含 prompt」**。
