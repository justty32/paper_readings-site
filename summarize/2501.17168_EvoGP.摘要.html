論文／訪談原始來源

《實現基於樹的遺傳編程中的群級並行性以加速 GPU》（EvoGP）重點摘要

一句話概括

EvoGP：一個把樹型遺傳編程（TGP）整條演化流程（初始化／評估／交叉變異）全部搬上 GPU、做群級（population-level）並行的高效框架——靠張量化表示（把大小不一的樹編碼成定形、對齊記憶體的陣列）＋自適應並行（依資料量在「個體內 vs 個體間」並行間動態切換）＋把自製 CUDA kernel 嵌進 PyTorch（無縫接 Gym/MuJoCo/Brax/Genesis）；峰值吞吐 >10¹¹ GPops/s，比現有 GPU 版 TGP 快達 304×、比最快 CPU 庫快 18×，且精度不降、能撐到百萬級族群。

解決什麼問題

TGP（符號迴歸／分類／機器人控制常用）算力需求大，但 GPU 高效執行卡在三個核心難題：

  1. 個體結構異質：每棵樹大小／拓撲／求值邏輯都不同，與張量框架（TensorFlow/PyTorch）天生不合，連 CUDA 也難把變長結構壓成對齊記憶體格式。
  2. 多層並行整合複雜：資料級並行（SIMD 友善）與群級並行要同時用，須協調記憶體佈局、kernel 融合、排程，避免資源競爭。
  3. CUDA 高效 vs Python 靈活不相容：實務部署在 Gym/MuJoCo/Brax 等 Python 生態，要兼顧速度與互通性。

核心方法

  • 張量化資料結構：用線性前綴編碼把樹攤平成節點序列（TGP 中每節點子節點數由類型決定，故前綴即可無歧義還原拓撲）；存三個陣列——節點類型 node_type、節點值 node_value、子樹大小 subtree_size。子樹大小陣列讓子樹邊界 O(1) 直接定位（免反覆解析前綴的 O(n)）。再用超參 最大節點數 以 NaN padding 補成定長 → 整個族群疊成三個批次張量，GPU 可批次處理。
  • 張量化遺傳操作：發現多數算子（單點交叉、子樹變異、hoist 變異…）共用同一基元——子樹交換（subtree exchange）。把它實作成 GPU primitive，新算子只需改「怎麼選／造子樹」而不動 kernel；超出最大尺寸則判無效、原樹返回。
  • 自適應並行（fitness 評估）：
    • 資料量小至中 → 混合並行：二維 CUDA grid，多 block 評估同一個體、各算一段資料的部分 fitness，再用原子操作彙總；單次 kernel 啟動省 overhead，用個體間並行填滿閒置核心。
    • 資料量大 → 純資料級並行：每個體獨立 kernel 啟動，把樹載入常數記憶體（廣播讀取快）。
    • 執行期自動切換：以資料點數 vs GPU 總 CUDA 核心數（SM 數 × 每 SM 核心數）為閾值判斷。實測切換點 ≈ 10⁴（恰為 RTX 3090 的 82 SM × 128 = 10,496 核）。
    • 單個體求值用前綴編碼反向走訪＝後綴（逆波蘭）堆疊式求值。
  • 工程：Python + PyTorch；CUDA kernel 註冊為 PyTorch 自訂算子；**全資料常駐 GPU（zero-copy）**免主機↔裝置搬運；支援 Modi 節點做多輸出（樹變 DAG，適配 RL 策略）。

結果

  • 峰值吞吐 >10¹¹ GPops/s（小資料約 10⁸–10⁹，中大資料達 ~3.5×10¹⁰–10¹¹）。
  • 加速：對 GPU 版 SRGPU 峰值 304×；對最快 CPU 庫 Operon 18×（族群超過某規模時優勢尤明顯）；中大資料時資料級並行已飽和 GPU，故加速倍率收斂但仍領先。
  • 精度不犧牲：四個 SR 資料集上 MSE 持平或更優；執行時間隨族群放大近乎平坦（baseline 為線性）。
  • 三域可擴展（族群 200→5000 越大越好）：HalfCheetah 控制獎勵翻倍多、Daily Demand 迴歸 MSE 降兩個數量級；Yeast 分類超越 NN 標準準確率（56.87%）、逼近 UCI 最佳 Random Forest（62.80%）。

局限

  • 須預設最大樹節點數（padding 換來定形張量，但限制了表達式深度、且 NaN padding 有記憶體浪費）。
  • 中大資料下 GPU 已被資料級並行飽和，群級並行邊際效益遞減、加速倍率受限。
  • 仍受單卡 GPU 記憶體（24 GB）約束族群／樹規模；多輸出僅靠 Modi 節點，更進階表達策略列為未來工作。

對讀者的價值

  • 本批 G 類（遺傳編程）的「系統／GPU 工程」代表——和把 GP 當演算法創新的論文不同，這篇主攻怎麼讓 GP 在 GPU 上真的快。可與同批 2504.10253 TinyverseGP（跨域基準框架）互補：一個談加速基礎設施、一個談統一基準與表示比較。
  • 最值得記：「變長樹 → 前綴編碼 + subtree_size 陣列 + NaN padding → 定形批次張量」 的張量化套路；subtree exchange 作為統一 GPU primitive；依資料量自適應切換混合／資料級並行（閾值＝CUDA 核心數）；CUDA kernel 嵌 PyTorch + 全 GPU 常駐接 RL 環境。
  • 定位：完整系統論文 + 開源（github.com/EMI-Group/evogp）；適合做 GP/演化計算 GPU 加速、大規模符號迴歸、GP-based RL／機器人控制、想把不規則樹結構張量化的人。
