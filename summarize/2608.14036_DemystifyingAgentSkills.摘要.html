Demystifying Agent Skills: Why They Work-Until They Don't 重點摘要

一句話

作者用對照實驗＋成對軌跡分析拆解「skill 何時有用、為何有用、何時失效」：skill 的主要機制不是灌知識，而是把雜亂經驗蒸餾成可依循的程序性錨點；但這個蒸餾動作同時製造出新的失效面——套用不當與檢索退化。

分類法與機制

  • 對 8,135 筆試驗紀錄開放編碼，收斂出三大類、十二種 skill-use 模式，人機一致率 95.8%（Cohen's κ=0.952，作者自報）。
  • 機制標籤中 procedural_anchor 佔 skill 案例 65.7%，knowledge_injection 僅 4.5%（作者自報）：skill 主要穩定「怎麼做」而非補「不知道的事實」。
  • skill 對比 Workflow Memory 在同源軌跡下平均勝出 6.06 個百分點（95% bootstrap CI [+0.76, +11.36]，作者自報），證明差異來自表徵形式而非額外經驗量。

三個失效邊界

  1. 執行層錯誤下降但非萬能：environment_infrastructure_failure 從 raw 的 5.3% 降到 skill 的 0.2%；但 algorithmic_logic_error、static_verification_without_runtime 三臂皆持平，skill 修不了錯演算法或補不了驗證缺口（作者自報）。
  2. skill 引入套用失敗：skill_guidance_misapplied_or_ignored 在 skill 臂佔 10.0%，遠高於 raw 的 0.8%（作者自報）；workflow memory 則主要死於 timeout_budget_exhaustion（10.6% vs raw 1.7%）。
  3. 檢索精確率隨池擴大崩解：候選池從 5 到 100，Arm 3 實際使用精確率從 29.6% 掉到 3.3%，但下游成功率幾乎持平（36.4%→39.3%，作者自報）；相似型 distractor 是主要壓力來源，離線識別精確率與最終成功率是兩個獨立量測，正確檢索既非充分也非必要條件。

對 ai_core 的價值／接點

這篇對技能固化引擎的治理直接有用：procedural_anchor vs knowledge_injection 的區分，印證了 ai_core §3.2「帶 LLM 留白的程序」定位——skill 該固化的是程序骨架，不是塞事實。更關鍵的是失效邊界：即使 skill 通過離線檢索與存在性檢查（相當於通過 §3.4 憑證准入的必要性與穩定性兩道閘），執行期仍可能被「套用不當」拖垮——這是 ai_core 治理原則目前沒單獨處理的第三道閘：適用性判斷，該不該在當下情境套用這條 skill，而非只問「skill 存不存在、選得準不準」。檢索精確率隨池擴張崩解，也提醒 skill 庫成長到一定規模後，必須靠像 ERSkill（見另一篇）那種可演化的路由機制，而非靜態相似度檢索。
