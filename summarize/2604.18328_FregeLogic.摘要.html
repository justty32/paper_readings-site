論文／訪談原始來源

《FregeLogic》重點摘要

一句話概括

Five-LLM ensemble 碰上 3–2 vote split 時，切換到 Z3 SMT 求解器做形式驗證（內容中立）來打破僵局——嵌套 5-fold CV（N=960）上，結合分數 41.88（純 ensemble 39.12）、準確率 94.3%、內容效應 2.85（比純 ensemble 降 16%）。關鍵洞察：LLM 意見分歧的案例，正好是內容偏誤（believability）干擾邏輯判斷的地方，精確介入就夠。

解決什麼問題

  • SemEval-2026 Task 11 Subtask 1：三段論有效性二元分類，同時要求低內容效應（content effect, CE）——模型不該因為前提聽起來合理／荒謬就改變邏輯判斷。
  • 純 LLM 無論多大都有內容偏誤（Dasgupta 2022；Eisape 2024）；純符號求解器（Z3）雖內容中立，但 LLM 結構萃取出錯時會系統性誤判（尤其是 valid→invalid 方向）。
  • 既有神經符號方法有的全量使用形式驗證（太貴且萃取錯誤會放大）、有的需啟動層內部存取（不通用）。

核心方法

  • LLM Ensemble（5 個分類器）：3 個開源模型（Llama 4 Maverick 17B MoE、Scout 17B、Qwen3-32B）x 4 種 prompt（zero-shot/few-shot/few-shot CoT/simple CoT），每 fold 從 12 組中選 top-5 組合分數的。溫度 0.0，輸出經正則解析。
  • Z3 形式驗證管線：(1) LLM 結構萃取（bedrock structured-output API，失敗率從 ~22% 降到接近零）→ 命題類型（A/E/I/O）＋主詞謂詞；(2) 亞里斯多德編碼（含 existential import：全稱命題加了 ∃x 存在公理，因為資料集中 Felapton 型全標 valid）；(3) 兩步可滿足性檢查：先驗證前提一致性（P1∧P2 UNSAT→交給 ensemble 防 ex contradictione），再驗證 P1∧P2∧¬C 是否 UNSAT（決定有效性）。
  • Tiebreaker 決策融合：只在 vote margin ≤ 1（3–2 split）時改用 Z3 判決；其他情況（5–0, 4–1）信任 ensemble majority。3–2 split 占總案例 7.9%。

結果

  • 台 breaker 組合分數 41.88（vs 純 ensemble 39.12, +2.76），準確率 94.3%（+0.9pp），CE 2.85（-16%）。
  • 子群準確率更平衡：純 ensemble 在 invalid-believable 只有 90.2%，台 breaker 拉到 94.5%（內容偏誤最強的格子）。
  • Z3 介入 30 次（3–2 split 76 例中），19 次正確翻轉、11 次錯誤翻轉（全為萃取錯誤導致 valid 被誤判 invalid）。
  • Z3-only 基線：準確率僅 74.7%、CE 高達 26.28（系統性 over-predict invalidity），說明了 raw Z3 不能直接用。
  • 其他融合策略（veto/weighted/confidence/top-3）全部更差：擴大 Z3 權限到高共識案例會覆蓋正確 ensemble 預測。

局限

  • 11 次錯誤翻轉全因 LLM 萃取結構錯誤（雙重否定→錯判命題類型、複合詞邊界誤切、非標準量化詞解析失敗），不是 Z3 編碼問題。
  • 模型/prompt 選擇和 τ=1 閾值全透過 nested CV 調參於同一資料集，無獨立測試集。
  • 每則三段論需 6 次 LLM API 呼叫（5 ensemble + 1 萃取）+ 1 次 Z3，約 4300 tokens、12.1s sequential latency。
  • 未比較單一大模型（70B+），不確定是小規模多樣性 vs 大規模單體哪個更優。

對讀者的價值（ai_core 接點）

  • §5 + §B 指定閱讀：§5 的 error analysis 展示了萃取錯誤的具體案例（圖 2），§B 的 structured-output prompt 是可複用的萃取模板。
  • 「只在爭議處介入形式方法」的模式：ai_core 的約束器不必全量執行——就像 FregeLogic 只在 3–2 split 時調用 Z3，ai_core 的雙重執行比對（決策並行校驗）也只需在 LLM 不穩定時才啟動符號／確定性驗證。這比全量形式驗證省成本又避開萃取錯誤放大。
  • 結構化輸出的教訓：從 free-form prompt → structured-output API，萃取失敗率從 ~22% 降到近零——ai_core 固化引擎中任何需要 LLM 產出機器可讀結構（從自然語言抽取合約/規格/程式骨架）的步驟，都該優先使用 structured output 而非 regex 後解析。
  • 內容中立驗證作為 gate：Z3 solver 不含語意內容（只操作 FOL 符號），正好對應 ai_core §3.4「憑證准入」的獨立驗證器——一個與 LLM 推理路徑正交的檢查者。
