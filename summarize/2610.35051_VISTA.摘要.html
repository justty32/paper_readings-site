論文／訪談原始來源

VISTA: Active Exploration for Self-Improvement in Embodied Agents 重點摘要

一句話概括

VISTA 讓編碼型 meta-agent 在模擬環境主動診斷具身任務，修改指令、技能與控制流程，再以自主執行結果挑選每個任務的 harness；底層模型權重保持固定。作者報告模擬任務成功率提升，但重複用於挑選版本的評估矩陣不能直接作為獨立泛化測試。

方法與選擇規則

具身 agent 的 harness 包含提示、可執行技能、策略 hook、記憶及協調邏輯，連接語言模型規劃器、視覺語言動作模型（VLA）與公開的感知、機器人控制能力。Meta-agent 使用 Codex 與 GPT-6，線上規劃器使用 GPT-5.6 Sol；VISTA 修改 harness，而非訓練底層模型。不同 benchmark 分別使用凍結的 π₀.₅、RLDX-1、LingBot-VLA。（§3、§4.1）

版本與執行證據以 Git 式有向無環圖保存。Meta-agent 可以檢查歷史、編輯版本、要求中途自主測試，也可以從凍結快照開啟私有即時場景，使用公開的控制與感知能力探查失敗假設；診斷時的介入不等同最終自主執行。開發可從舊版本分支或組合既有機制，失敗分支的證據仍可保留。（§3.1～3.3、附錄 A.1）

宿主凍結提交的候選，以預先指定的場景與重複次數矩陣從新初始狀態執行完整自主 episode，只有成功率嚴格高於現任版本才升級，平手保留現任。每個任務選自己的版本；同一開發矩陣可反覆用於升級及報告所選版本，故存在重複選擇帶來的樂觀偏差。最佳保留版本分數不下降是選擇規則的結果，單次修改不一定進步；新初始化也不等於獨立保留任務或場景。（§3.4）

作者自報結果

LIBERO-Pro 四個任務套件各 10 題，分別在指令重導與位置交換兩類擾動下測試，每題 8 個場景 seed、每 seed 重複 2 次。從僅提供最小觀察介面的初始 π₀.₅ harness 出發，八種設定的平均成功率由 17.5% 升至 95.0%；T 類與 S 類分別 97.0%、93.4%。表中 HarnessVLA 為 61.1%，但其起始 harness 與此處的最小初始版本不同，不能把差距視為只改一項因素的對照。（§4.1～4.2、表 1）

RoboCasa365 的 Composite Seen 和 Composite Unseen 各 16 題、每題 8 個 seed 各重複 2 次，以改編 HarnessVLA 的初始 harness 為基準，分別由 16.4% → 24.2%、4.7% → 13.3%。Unseen 是 benchmark 類別名稱；由於逐任務開發和選擇，不能因此推定這些結果是在未見的開發資料上測得。RoboTwin 的 50 題各以 4 個隨機場景重複 2 次，成功率由 48.5% → 74.0%；表列 HarnessVLA 58.0%。（§4.1～4.2、表 2～3）

在四個 LIBERO-Goal 任務的消融中，被動版本仍可看歷史、編輯與自主測試，但不能開即時場景或做診斷操作。第一輪，主動版本相對初始 harness 平均提升 50.0 個百分點，每題累計 42.2M meta tokens；被動版本為 39.1 點、94.2M。第二輪分別為 85.9 點、91.6M 與 56.3 點、137.7M。tokens 包含快取與未快取輸入、輸出及子 agent 使用量；這不是 rollout 次數或等總成本比較，四題結果也不足以確立普遍優勢。（§4.3、表 4）

機制例子與限制

Goal-t09 的個案從 0% 開始：第一輪增加抓取後抬升驗證、有限次重新定位與重試，以及搬運和釋放程序，所選版本達 56.3%；第二輪修正抬升判斷的參考狀態與接觸中斷處理，並調整釋放，達 100%。這是作者展示的單一任務軌跡，仍使用上述開發評估流程，不能推論其他任務必然如此。（§4.4、圖 5）

實驗全部在模擬環境，作者尚未在實體機器人驗證，實際感測雜訊、動作延遲及接觸動力學可能改變表現。每任務開發及反覆評估需要額外模型、模擬和工程資源；文中消融的 meta token 數不涵蓋所有系統成本。有限場景與重複選擇也限制了對新任務、新場景及實機表現的推論。（§4.1～4.3、§5）
