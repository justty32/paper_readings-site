論文／訪談原始來源

《Preble：高效率的分散式 LLM Prompt 排程》重點摘要

一句話概括

Preble 解決分散式 prefix cache 的根本張力：把相同 prompt 都送到同一 GPU，KV reuse 高卻會形成熱點；均勻 round-robin，負載平衡卻重算同一 prefix。其 E2 scheduler 依「共享 prefix 是否長過剩餘 prompt」選 exploitation 或 exploration，再用包含近期負載、KV eviction 與新 request 計算量的成本挑 GPU；相較 SGLang，average latency 改善 1.5–14.5×、p99 改善 2–10×。

問題證據

作者研究 tool calling、embodied agent、code generation、video QA、long-document QA 五種 workload，加 Azure inference trace：

  • 五種 workload 的 prompt 比 output 長 37–2,494×；含 Azure chat 後範圍低至 4×。
  • 每個 prompt 有 85%–97% tokens 與其他 request 共享。
  • 一段 common sequence 平均被 8.6–126 requests 共用。
  • Azure trace 的 inter-arrival time 從 2 μs 到 217 s，負載會劇烈改變。

Single-GPU radix-tree cache 已可重用 prefix，但 production serving 是多 GPU。若 distributed load balancer 不看 prompt，shared requests 落在不同 GPU、每張卡都重算；若永遠黏到已有 cache 的 GPU，popular prefix 又會把該卡壓垮。

E2 與兩層排程

Global scheduler 維護 global radix trees；node 記 token count、哪些 GPU 有其 KV、各 GPU 在 history window 中有多少 requests 使用。對新 request：

  • matched prefix tokens 大於 unmatched tokens 時，exploit，送往擁有 longest matched prefix 的 GPU。
  • matched prefix 較短時，explore，允許新 prefix 在其他 GPU 落地。
  • Explore cost 為三項 GPU compute time 的和：近期 prefill+decode load、為新 request 騰空而 eviction 後未來需重算的成本、新 request 在該 GPU 的實際 miss 計算成本。預設 history window 為 3 分鐘。

Local scheduler 每 GPU 一個，維護 local radix tree 與 wait queue，iteration-level 組 batch、chunk long prefill，memory 不足時依 node LRU eviction。Wait queue 不是單純 FCFS 或最高 cache hit 先行，而是依 cached-token percentage 分 priority groups，再按配額比例取樣；高命中率取得較多 slots，低命中 request 仍會前進。

Preble 還會：

  • 偵測 heavy/light GPU 差距，將未來流量導向輕載卡。
  • 熱 prefix 在 queueing time 持續上升時複製到多 GPU並拆分 subtree load。
  • 把 fully cached prompt 視為 decode-like work、cache miss 長 prompt 視為 prefill-like work，混合兩者改善 compute/memory balance。

實驗結果

系統是可放在 vLLM 或 SGLang 前的 standalone layer。測 Mistral 7B 與 Llama 3 70B，環境為 4×A6000 cluster 與 8×H100 server；後者以 4-GPU tensor parallel 加 data parallel。

  • 五 workload、兩模型與多種 GPU 設定下，相較 distributed round-robin SGLang，average latency 改善 1.5–14.5×，p99 2–10×。
  • Code generation 的 decode 最長，因此改善較小，仍有 average 1.56–1.8×、p99 3–4×。
  • 從 2 張增加到 4 張 A6000，RPS 加倍仍維持近似 latency。
  • Global scheduler 在 50,000 requests burst 下處理 ToolBench 245 req/s、VideoQA 2,931 req/s；作者依 workload 與 A100 token rate 推估單一 scheduler 至少支撐 70–391 GPUs。
  • Ablation 顯示 E2 placement、post-assignment rebalance/autoscale、prefill-decode-aware mixing 依次改善 average 與 p99；local priority quota 主要改善 p99，符合其 fairness 目的。

局限與閱讀提醒

  • 優勢依賴長且高度共享的 prefix。論文明說若 prompt 完全不共享，行為與 vLLM 等 SOTA serving 相同，不應外推為一般 workload 都有 14.5×。
  • Prefix cache 是 exact-prefix reuse；不處理語意相似 context、agent memory correctness 或跨 request 權限隔離。
  • Global scheduler 是單 cluster 中心化視圖；論文對更大規模的答案是部署多個 Preble clusters，而非證明單一全域 scheduler 可到資料中心級。
  • 「至少 70–391 GPUs」是依 scheduler throughput、GPU token rate 與 workload output length推算，不是實際用 391 GPUs 驗證。
  • Local fairness 是按 cache-hit priority groups 配額，不是 formal tenant-level SLO、deadline 或 weighted-fair proof。

對讀者的價值

Preble 對 Agent Machine 最有用的是「cache locality 只能作 bounded scheduling signal，不能壓過公平與負載」。Agent runtime 可把 model/prefix residency 當 tie-breaker，卻必須保有 quota、aging、resource accounting 與 starvation protection。它也證明全域 request placement 與本地 iteration admission 應分層，正好對應 control plane scheduler 與 endpoint-local executor 的責任切割。
