一句話概括

ToolAlpaca：不靠人工蒐集真實 API、也不靠人工撰寫指令，而是用三個角色（使用者／助理／工具執行者）皆由 LLM 扮演的多代理模擬環境，自動「無中生有」出一份涵蓋 400 多個工具、50 個類別、3,938 筆指令-動作-回應範例的工具使用語料，再拿去微調 Vicuna-7B/13B；結果顯示完全沒真實 API 呼叫過的小模型，在未見過的模擬工具與真實世界 API 上都能達到接近 GPT-3.5 的通用工具使用能力（人工驗收率 73%／75%，遠高於未微調 Vicuna 的 16%／25%）。

解決什麼問題

GPT-4 等超大模型可靠 zero-shot prompting 展現通用工具使用能力，但小模型只能靠微調在少量特定工具上打轉，換一個沒見過的工具就失靈——這中間有兩層落差：(1) 小模型能否也學到「通用」工具使用能力，而非只認得訓練時見過的工具；(2) 若答案是可以，訓練語料從哪來？真實世界 API 數量龐大、功能重疊、且真實多輪試誤互動（問使用者補資訊、呼叫錯了再改、串多個函式）極難靠人工大規模標註。ToolAlpaca 要驗證：用完全模擬、不需任何真實可用 API 的方式，能否量產出足夠多樣的語料，讓小模型學會可泛化到未見工具的能力。

核心方法

  • 兩階段流程：①工具集建構 ②工具使用實例生成（多代理模擬）→ ③微調 Vicuna。
  • 工具集建構：從 public-apis（1,400+ 個 API、50+ 類別）隨機挑 500 個 API 的名稱與簡介，用 ChatGPT 把每個工具擴寫成標準化五元組文件 {name, introduction, description, function documentation, OpenAPI specification}——這些工具不需要真的能打，也不需要原本就有結構化文件，全靠 LLM 生成內容補完。過濾後得到 426 個工具、平均每工具 4.85 個函式。
  • 三代理模擬環境（每個代理都是一次獨立 prompt 的 LLM）：
    • 使用者代理：依工具文件生成十種不同格式（命令句、問句等）的指令，並在互動中補答助理反問的缺漏資訊。
    • 助理代理（用 GPT-3.5）：採 ReAct 的 (thought, action, observation) 格式，決定要呼叫哪個函式、帶什麼參數，多輪迭代直到蒐集到足夠資訊，最後彙整成給使用者的回應。
    • 工具執行者代理：檢查助理請求的格式/參數後，不真的發送網路請求，而是讓 LLM 讀該工具的 OpenAPI 規格去「模擬」執行結果，回傳合理的假 API 回應。
  • 三者反覆互動直到助理判定已能作答，產出一筆 {指令， 動作序列（含工具回應）, 最終回應} 的實例。過濾規則：丟棄超過 5 步互動、缺函式呼叫、或輸出解析錯誤的樣本。
  • 語料統計：50 類別、426 個工具、3,938 筆實例（2,512 筆單函式呼叫 + 1,426 筆多函式呼叫）；平均指令長 23.42 詞、平均輸出長 36.19 詞、平均每工具 4.85 個函式、平均每實例 1.66 步動作。
  • 品質抽查（人工看 100 筆）：指令可解性 88%、工具回應有效性 92%、動作序列與最終輸出正確率 80%——三個代理的可靠度都在八成以上。
  • 微調：以 Vicuna-7B/13B 為底，AdamW、學習率 2e-5、batch size 128、3 epoch、max length 2048，得到 ToolAlpaca-7B / ToolAlpaca-13B。

結果

  • 未見過的模擬工具（10 個新工具、100 筆評測）：GPT-4 機器評測搭配人工驗收，ToolAlpaca-7B/13B 人工整體驗收率達 73% / 75%，較未微調 Vicuna-7B/13B 的 16% / 25% 大幅提升（+57 / +50 個百分點），13B 版本已接近 GPT-3.5 水準。
  • 真實世界 API（11 個未見過的真實 API）：ToolAlpaca-7B/13B 整體準確率 55.3% / 61.4%，同樣遠勝對應的 Vicuna 基線，證明模擬語料訓出的能力可遷移到真實工具，而非只認得「模擬味」的假回應。
  • GPT4Tools 測試集（8 個域外多模態工具）：ToolAlpaca-13B 僅用 3.9k 筆訓練實例，達成整體成功率 83.7%，逼近 GPT4Tools 自身模型（用同套生成流程但 71k 筆訓練資料訓出）的 90.6%，凸顯語料多樣性比語料規模更關鍵。
  • 多樣性消融：固定訓練實例總數，只改變涵蓋工具數（10／40／100／400 個），整體準確率從 10 個工具的 51% 一路升到 400 個工具的 70%——工具集多樣性是決定小模型能否「泛化」而非「死記」的主因。

局限

  • 論文正文未設獨立「Limitations」章節，以下為文中散見的自陳限制：
    • 模擬 API 回應非真實回應——工具執行者代理是 LLM 憑 OpenAPI 規格「編」出合理的假回傳值，真實 API 常有的錯誤碼分布、速率限制、資料噪訊、邊界情況都不在模擬範圍內；真實 API 測試集上準確率（55.3%／61.4%）明顯低於模擬工具測試集（73%／75%），論文承認這反映了模擬與真實資料間的落差。
    • 訓練語料不含「不需要工具、直接回答」的樣本，導致在 GPT4Tools 測試集上必須先排除 652 筆中的 50 筆非工具使用案例才能公平比較。
    • 評測高度依賴 GPT-4 當裁判（僅在模擬子集額外做人工評測驗證一致性），真實世界子集無獨立人工複核。
    • 工具集來源侷限於 public-apis 收錄且可被 LLM 合理擴寫文件的 API 類型，未涉及需真實憑證、金流、複雜狀態機的工具。
