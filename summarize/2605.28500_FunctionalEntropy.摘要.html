作者：Dylan Bouchard, Mohit Singh Chauhan, Zeya Ahmad, Ho-Kyeong Ra（CVS Health）

日期：2026-05，UQ for Code × 功能等價替代 NLI 語意等價的瓶頸診斷與解法

arXiv：2605.28500

論文／訪談原始來源

《Functional Entropy：以不確定性量化預測 LLM 生成程式碼的功能正確性》重點摘要

一句話概括

功能性熵（functional entropy）= 語意熵（semantic entropy）的程式碼特化版，其關鍵在於把 NLI（自然語言推論）語意等價替換為 LLM 判斷的功能等價（functional equivalence）——因為 NLI 模型無法區分功能不同的程式碼（幾乎所有回應塌縮成單一群集），而 LLM 功能等價判斷的群集純度 >93%。功能性等價方法在 15 組模型-基準中於 11 組拿下最高 AUROC，校準也最佳。

解決什麼問題

  • LLM 生成的程式碼外觀合理但功能錯誤，在少人審查的自主編碼代理、text-to-SQL 等場景風險極高。需不執行、不使用測試案例就能預測生成程式碼是否正確。
  • NLG 的不確定性量化（UQ）方法能否直接移植到程式碼生成？既有研究範圍有限，缺乏跨語言／跨模型的系統性評估。
  • 其中採樣方法仰賴 NLI 語意等價來群集回應——這是關鍵瓶頸：NLI 無法分辨功能不同的程式碼，使群集類 UQ 方法失效。

核心方法

評測三大類 UQ 方法（token-probability、採樣一致性、自省），跨度：Python（LiveCodeBench 1,055 題）／Java（MultiPL-E 386 題）／SQL（LiveSQLBench 270 題），5 個模型（GPT-4o/mini、Gemini 2.5 Pro/Flash/Flash-Lite），共 1,711 題。

功能性等價方法（本文核心貢獻）

共有基礎：用 LLM（Gemini-2.5-Flash）逐對判斷兩段程式碼是否功能等價（相同輸入→相同輸出），取代 NLI 語意等價。促發模板見附錄 G。

  • 功能等價率（FER）：m 個採樣回應中與原始回應功能等價之比例。
  • 功能性熵（FE）：以功能等價貪婪群集後，對群集分布計算熵：FE = −Σ P(C) log P(C)，標準化至 [0,1] 即功能負熵（NFN）。此為語意熵的程式碼特化類比。
  • 功能集合信心（FSC）：歸一化唯一群集數量 (m+1−|C|)/m，全部在一起→1，全部不同→0。

對照基線

Token-probability（LNSP、MTP、PM、ATN@K、MTN@K）、相似度（cosine sim、CodeBLEU）、自省（P(True)、verbalized confidence）、混合（CoCoA、MCSP、WB-NFN）。

關鍵結果

基準 功能等價最高 AUROC 主要發現
Python 0.867（FER, Gem-Fl） Token-prob 亦佳（0.77-0.80），但功能等價全面壓勝；CodeBLEU 次之（0.81）
Java 0.701（FE, Gem-Fl-Lt） 整體 AUROC 最低（0.55-0.70），功能等價領先幅度縮小，CodeBLEU 競爭力強
SQL 0.842（FSC, GPT-4o-m） Token-prob 接近隨機（0.52-0.55 on Gem models）;GPT-4o-mini 準確率 0.21 但 AUROC 0.84**——一致性排名能力強於生成能力，但此情境應優先換模型而非依賴 UQ 過濾**

NLI vs. 功能等價（Figure 1）

  • 群集類（語意熵／語意集合信心）幾乎完全失效：NLI 把 >80% prompt 的 11 個回應全塌成單一群集 → AUROC 接近 0.5。
  • 功能等價替代後差距 >0.30 AUROC（Python/SQL）；在 SQL 上 NLI 的非矛盾機率具競爭力（因 SQL 語法接近自然語言）。
  • 非矛盾機率 vs. FER：FER 在 12/15 組中勝。

校準

功能性方法在 Python 與 SQL 校準最佳（ECE 低），Java 競爭力佳。token-prob 在 SQL 上 ECE 常 >0.7（信心高但全錯）。cosine sim 雖 AUROC 尚可但校準極差。

消融與成本

  • m=5 即可捕捉大部分增益（距 m=10 的 AUROC 差距 ≤0.02）;FER 只需 5 次等價判斷，群集類最多 15 次。
  • 等價判斷成本遠低於生成成本（僅輸出單一類別標籤）。
  • 等價法官敏感度：Gem-Fl-Lite 差異 ≤0.02 AUROC;GPT-4o-mini 退化 ≤0.07。

局限

  • 僅評測 Python/Java/SQL，不涵蓋靜態型別語言（Rust/Haskell）、多檔案專案或 API 互動任務。
  • SQL 僅 270 題，統計力有限。
  • 全為閉源 API 模型（OpenAI/Google），不含開源模型（Llama/Mistral/Qwen）。
  • 正確性定義取決於既有測試案例，可能漏掉邊界錯誤。
  • 等價法官與生成器可能同為 Gemini 系列（但執行驗證 + 法官消融緩解此疑慮）。

ai_core §3.4 憑證：功能性熵 = 預測程式碼正確性

本論文（2605.28500）的「功能性熵」直接實現 ai_core §3.4 憑證 的核心需求：在不執行、無測試案例的前提下，產出一個能有效排列程式碼正確性的信心分數。功能等價方法在 11/15 組中 AUROC 最高且校準最佳，意味其輸出的信心分數不僅可用於排名（區分對錯），也可作為可靠的機率估計——這正是 §3.4「憑證」作為准入閘門的關鍵運算元件：當功能熵高（信心高）時可自動通過，低時觸發拒絕、升級或人工審查。與同方向的 2607.16868（邏輯圖 UQ＝憑證新方法）、2605.04295（自適應共形語意熵＝形式保證）可形成 UQ 憑證的工具箱比較。

對讀者的價值

  • 本文提供了一套可直接使用的程式碼 UQ 工具（已開源 uqlm），涵蓋三大類共十餘種方法的三語言基準評測，實務者可據此選型。
  • 核心洞見「NLI 不適合程式碼」與「LLM 功能等價判斷高精度（>93%）」對任何想將 NLG UQ 移植到程式碼的工作都有指導意義。
  • 對本庫「方向四 UQ／品質分數」而言，這是第一份跨語言、跨模型、跨方法族的系統性評測，並定錨了「功能性熵」作為程式碼特化 UQ 的基準。
