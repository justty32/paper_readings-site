一句話概括

DSPy 是一個把 LM pipeline 抽象成「文字轉換圖（text transformation graph）」的程式設計模型：不再手寫脆弱的 prompt 字串，而是用 signatures（自然語言 I/O 宣告）+ modules（可參數化、可組合的 prompting 技術，如 ChainOfThought、ReAct） 描述 pipeline，再由 teleprompters（優化器/編譯器）自動 bootstrap few-shot 示範或指令、甚至 finetune 小模型，把宣告式程式編譯成能最大化指定指標的自我改進 pipeline；在 GSM8K 與 HotPotQA 兩個案例上，短短幾行 DSPy 便讓 GPT-3.5 與 llama2-13b-chat 自我 bootstrap 出勝過標準 few-shot 與專家手寫 prompt 的系統。

解決什麼問題

現有 LM pipeline（含 LangChain、Semantic Kernel、LlamaIndex 等框架）普遍以手寫死的「prompt 模板」（靠反覆試誤湊出的長字串）實作各步 LM 呼叫。作者論證此法脆弱且不可擴展——概念上就像手動調分類器權重：同一段 prompt 字串換 pipeline、換 LM、換資料域、甚至換輸入就可能失效；多階段 pipeline 裡多個 LM 呼叫要彼此配合更放大此問題。作者要把「建 LM pipeline」從操弄自由字串推向寫程式——由編譯器自動生成優化過的 LM 呼叫策略與 prompt。

核心方法

DSPy 貢獻三層抽象（程式以 Python 表達，走 PyTorch 式 define-by-run 計算圖）：

  • Signatures（簽章）：以自然語言型別宣告一個文字轉換要做什麼（如 question -> answer、english document -> french translation），只講「做什麼」不講「怎麼 prompt」；欄位名承載語意角色，由 DSPy 展開成對 LM 的指令，並負責結構化格式化與解析。
  • Modules（模組）：把既有 prompting 技術封裝成可套用任意 signature 的模組。核心是 Predict（存 signature、選用 LM、示範清單）；更複雜的有 ChainOfThought、ProgramOfThought、MultiChainComparison、ReAct 等，可互換套用。關鍵是「參數化」——一次 LM 呼叫的參數包括：(1) 要呼叫哪個 LM、(2) prompt 指令與各欄位前綴字串、(3) 最重要的 few-shot 示範；DSPy 主打自動生成與挑選示範。工具（如 dspy.Retrieve，支援 ColBERTv2/Pyserini/Pinecone）亦為模組。
  • Teleprompters（優化器）＝編譯的引擎：compile 時傳入程式、（少量、可只含輸入無標註的）訓練集、一個驗證指標，回傳優化後的新程式。典型 teleprompter 走三階段：
    1. 候選生成：遞迴找出所有 Predict 節點，為每個節點生成候選參數（指令、欄位描述、最重要的示範）。BootstrapFewShot 會用 teacher（或零樣本版程式）在訓練輸入上模擬執行、以高溫多次取樣，透明追蹤多階段 trace，再用指標過濾出能通過的 trace 當示範（即 self-bootstrap）、丟掉壞例。
    2. 參數優化：以隨機搜尋、HyperOpt（TPE）、Optuna 等在候選中挑選（BootstrapFewShotWithRandomSearch/WithOptuna）；或用 BootstrapFinetune 拿示範去更新小 LM 權重。
    3. 高階程式優化：修改控制流，最簡形式是 ensemble（bootstrap 多份程式並行、以多數投票等歸約）。

「編譯＝自動 bootstrap 示範／指令」是全篇核心：LM 雖不可靠，卻擅長為多階段設計搜尋解；良好分解的程式通常能找到幾個通過 signature 與指標約束的訓練例，據此迭代自我 bootstrap。標註需求極低——通常只需最終輸出的標籤（甚至無標籤），中間步驟由 bootstrap 補齊，換 pipeline 只要重新編譯而非重新標註。

結果

  • 總體宣稱：編譯數分鐘內，幾行 DSPy 讓 GPT-3.5 與 llama2-13b-chat 自我 bootstrap 出勝過標準 few-shot 的 pipeline（GPT-3.5 一般 >25%、llama2-13b-chat >65%），也勝過用專家手寫示範的 pipeline（GPT-3.5 高達 5–46%、llama2 16–40%）。編譯成 T5-Large（770M）、llama2-13b-chat 等開源小模型後，可與依賴專家手寫 prompt 鏈的 GPT-3.5 方案競爭。
  • 案例一 GSM8K（數學應用題）：三個程式（vanilla Predict、CoT、ThoughtReflection 多鏈反思）。bootstrap 編譯把簡單程式從 33%→82%（GPT-3.5）、9%→47%（llama2-13b-chat）（見表 1，整體 4–20%→49–88%）。bootstrap 可匹敵或超越用人工推理鏈（+human CoT）的效果。
  • 案例二 HotPotQA（多跳問答，fullwiki + ColBERTv2）：程式含 vanilla、CoT RAG、ReAct、BasicMultiHop（迭代兩跳生成查詢）。編譯把品質從 32%→46%（GPT-3.5）、22%→41%（llama2-13b-chat）（Sec 7）；multihop 最佳，bootstrap 能讓 llama2-13b-chat 逼近 GPT-3.5。finetune 出的 T5-Large（770M） multihop 僅用 200 標註 + 800 無標註輸入即達 39.3% answer EM / 46.0% passage 準確率，推論成本比專有 LM 低數個量級。

局限

  • 本文自陳為程式設計模型的提出 + 編譯器初步實證：優化聚焦於 bootstrap 示範，指令/欄位描述優化與更進階策略（RL、貝式超參、LM 回饋）多屬未來工作。
  • 高階程式優化目前只實作到 ensemble；動態（測試期）bootstrap、自動回溯等留待未來。
  • 對「資訊抽取、低資源合成資料生成」等更廣任務只提及已有大量社群程式，未在受控實驗下報告。
  • 與外部文獻的數字多為非正式比較（評估方法與測試樣本差異大），非嚴格對齊。

對讀者的價值

  • 與 ai_core 北極星的直接學術對應：ai_core（（內部參照） §1）把系統看成「符號神經網路／計算圖——多數節點是確定性 shell/py 函式、少數是 LLM」，並要把 prompt/pipeline 當可優化物、走「自我改進工作流」。DSPy 正是把 LM pipeline 宣告化（signatures/modules）＋ 自動編譯優化（teleprompters 自動 bootstrap few-shot／指令） 的最直接落地：它的「文字轉換圖」＝把 LLM 呼叫組成的可優化計算圖，「編譯」＝自我改進工作流。三層抽象（signature／module／teleprompter）幾乎逐一對上 ai_core 的「宣告介面／可組合節點／優化器」構想。
  • 關鍵差異（務必記住）：DSPy 仍以 LLM 為核心去優化 prompt/示範，把「怎麼呼叫 LLM」做到最好；它未走 ai_core「逐步剃除 LLM 依賴、把節點固化成確定性程式碼」的方向——DSPy 的節點骨幹永遠是 LM 呼叫（頂多 finetune 成更小的 LM），確定性 shell/py 函式只以工具（Retrieve/SQL/PythonInterpreter）身分外掛，不是優化終點。ai_core 更激進：LLM 是「昂貴稀有的生產資產」，理想是把驗證過的行為抽出成便宜確定性程式。
  • 庫內對照：2406.18532（Agent Symbolic Learning）明確把 DSPy 列為「只優化孤立組件」的代表，主張整體聯合優化 prompt＋工具＋pipeline，並用非監督「語言損失」做部署後自我進化；DSPy 則以 bootstrap 示範為主要優化對象、且其搜尋式編譯需可用指標定義（該文指出這對軟體開發/創意寫作等真實任務不適用）。兩篇一起讀，可看清「pipeline 當可優化物」這條線上，DSPy（宣告化+編譯 few-shot）→ Agent Symbolic Learning（語言梯度聯合優化）→ ai_core（進一步剃除 LLM）的光譜。
