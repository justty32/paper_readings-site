論文／訪談原始來源

《自我修復是程式碼生成的萬靈丹嗎？（Self-Repair Silver Bullet）》重點摘要

一句話概括

冷靜反證論文（ICLR 2024）：把「生碼→跑測試→產回饋→修碼」的自我修復當成要付額外呼叫成本的策略來公平核算——一旦以同等預算和「多抽幾個 i.i.d. 樣本」對比，自我修復的增益往往微薄、資料子集間差異極大、有時根本不存在；瓶頸不在修碼而在模型對自己程式碼產生準確有用回饋的能力：換上更強模型或真人來出回饋，增益才明顯解放（人類回饋把修復通過率從 33.3% 拉到 52.6%，1.58×）。

解決什麼問題

自我修復（self-repair）被當成提升 LLM 程式生成的熱門手法，但既有研究範圍窄、多不計回饋與修復的呼叫成本，效力其實未被理解。真正的問題應是：在同等計算預算下，與其反覆修復，不如乾脆多抽幾個初始樣本去跑測試——哪個成功率更高？且競賽程式場景的成敗，除了生碼能力，更取決於一個先前無人細究的階段：模型辨識「自己所生程式碼相對規格哪裡錯」的能力。

核心方法

  • 四階段形式化：程式碼生成（M_P 抽 n_p 個初始程式）→ 執行（跑完整可執行單元測試，過了就停、否則收錯誤訊息）→ 回饋生成（M_F 產文字解釋，刻意設為顯式獨立階段以便消融） → 修復（M_P 依回饋抽修復候選）；整體構成一棵 修復樹（repair tree）。
  • 成本感知的評估：把整棵樹當一個樣本，pass@k 中 k = n_p + n_p·n_fr，與「同樣本數的純 i.i.d. 取樣」公平對比；附錄再以 pass@t（計入回饋 token 的成本）與 batched／sequential 兩搜尋策略交叉驗證，趨勢一致。
  • 三個實驗：(a) M_P=M_F 的真自修復掃超參數；(b) 把 M_F 換成更強模型（Code Llama←GPT-3.5/4、GPT-3.5←GPT-4）隔離回饋品質的作用；(c) 招 16 名人類為 40 支失敗的 GPT-4 程式寫回饋，量化人類回饋的效果。
  • 模型：CodeLlama-13b-instruct、GPT-3.5、GPT-4；資料集：HumanEval、APPS（抽 300 題，含入門/面試/競賽三難度）；溫度 0.8、one-shot 提示、自舉估計。

結果

  • 不是萬靈丹：計入成本後，小預算時純 i.i.d. 取樣常打平或勝出。APPS 上 GPT-4 最多勝 baseline 8%、GPT-3.5 幾無增益；HumanEval 上 Code Llama 最多 10%、GPT-3.5 近天花板僅 3%。難題增益較大（GPT-3.5 競賽級最多 +34%）但難以預測——生碼成功率與修復成功率同漲同跌。
  • 多樣初始樣本 > 大量修復：固定預算下該多抽初始程式。GPT-4／APPS：10 初始 + 各修 1 次 = baseline pass@20 的 1.05×；2 初始 + 各修 10 次 = 0.97×（反而更差）。故 n_fr=1 最佳。
  • 回饋品質才是瓶頸：換更強模型出回饋，弱模型同時打敗自己的 baseline 與自修復模式。表 2（入門級修復成功率）：GPT-3.5 13.7% → 用 GPT-4 出回饋 29.1%，追平純 GPT-4 的 28.8%。
  • 人類回饋（表 1）：整體修復通過率 33.30% → 52.60%（1.58×），越難差距越大（競賽級 3.67%→14.67%）。質化：GPT-4 回饋不準確率 32/80 vs 人類 7/80；人類會表達不確定（7/80），GPT-4 從不（0/80）。

局限

  • 用「先建大樹再子取樣自舉」有統計假象之虞（以壓低 n_p/n_fr、標準差極小來緩解）。
  • 僅限帶可執行單元測試的自足式 Python 任務，與真實軟體開發（規格不全、長依賴、常無測試）差距大。
  • 人類研究未記錄除錯耗時，只能評回饋品質而非人力成本；未跨更多語言／新模型。

對讀者的價值

  • ai_core §3.4 分層修復策略的實證邊界（歸 I 類）：本文把「自我修復」從萬靈丹拉回成本帳本——直接給出 §3.4 修復迴圈的准入規則：一個修復步驟只有在回饋來自接地的真實測試（確定性節點）或嚴格更強的模型時才值得多付那次 LLM 呼叫；若回饋只是同一模型的自省，多半是弱的、甚至淨負的節點，該把預算改花在「多抽幾個多樣的初始樣本」上（對應成本梯度／§3.3 的「先廣撒再擇一」）。這正是「無接地則崩」在成本維度的量化版：不是「自省無用」，而是「自省不接地時，買不到你付出去的算力」。
  • 回饋強度＝定價量表：i.i.d. baseline ＜ 同模型自修復 ＜ 強模型回饋 ＜ 真人回饋 的階梯（33.3%→52.6%、13.7%→29.1%）可直接當 ai_core 修復迴圈的回饋來源分級——越接地／越強的回饋源，越值得為之付呼叫成本；反之別為「同級模型自我審查」付 5× 呼叫。pass@t 的「把回饋 token 算進成本」也提醒 §3.3 級聯核算要把中間反思的 token 計入，別只算最終答案。
  • 與已入庫兩篇對照：2304.05128 Self-Debug 是「有真實測試時修復迴圈有效」的正面原型（執行結果是確定性回饋）；2310.01798 CannotSelfCorrect 是「無外部回饋時內在自我修正退化」的反證。本文補上中間那格——即使有測試、回饋卻由同級模型自產時，增益仍被成本吃掉；三篇合讀畫出 §3.4 的完整邊界：修復要划算，回饋源必須是真實驗證器或更強智能，且要按同等算力對比 i.i.d. 基線。
  • 對固化引擎（§3.6）的一個訊號：表 1 質化分析顯示 GPT-4 回饋「自信卻常錯、從不表達不確定」——把 LLM 反覆處理的案例結晶成確定性程式時，絕不能拿 LLM 自產回饋當通過條件，必須以執行器／測試當 verifier。
