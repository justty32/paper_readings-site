論文／訪談原始來源

《CORAL：朝向自主多 Agent 演化以達成開放式發現》重點摘要

一句話概括

CORAL（Collaborative Open-Ended Reasoning and Learning）：現有 LLM-based 演化搜尋（FunSearch、AlphaEvolve、EvoX 等）把 LLM 嵌在外部固定規則驅動的演化迴圈裡——誰是父代、何時評估、存什麼知識，全由預定啟發式決定，LLM 只在 PROPOSE 階段被動生成候選解。CORAL 把這四個階段（RETRIEVE / PROPOSE / EVALUATE / UPDATE）的控制權全交還給 long-running 自主 agent，搭配共享持久記憶（attempts/notes/skills 三層）、非同步多 agent 組織與心跳式反思機制，在十一個任務上以 3-10x 改善率勝固定演化搜尋 baseline、僅需 5-20 次評估即收斂（baseline 需 60-100 次），並在 Anthropic Kernel Engineering 上以四 agent 協同演化把最佳成績從 1,363 cycles 壓至 1,103 cycles。

解決什麼問題

開放式發現任務（數學最佳化、演算法設計、系統最佳化）沒有標準答案，需反覆提案→評估→修正→累積。現有 LLM-based 演化搜尋（FunSearch、AlphaEvolve、EvoX、OpenEvolve、ShinkaEvolve）把關鍵搜尋決策外包給固定演算法，agent 無權決定：

  • 檢索什麼：用預設選擇規則抽取父代與歷史，而非 agent 自己判斷。
  • 何時測試：何時跑本地驗證、何時提交正式評估。
  • 如何反應：失敗時無法自主調整方向或 pivot。
  • 存什麼知識：什麼觀察值得寫入知識庫供後續重用。

對困難的開放式問題，這些決策本身就是問題的一部分，交給固定啟發式限制了搜尋效率。多 agent 系統更糟：現有方法依賴人類預先分解任務、指定角色、定義溝通拓撲（如 AI Scientist、AI Co-Scientist），但在開放式問題上，人類事先不知道最佳分解與互動架構。

核心方法

  • 共享持久記憶即檔案系統（§3.3）：M 結構化成檔案系統，透過 symbolic link 與各 agent 的 workspace 同步。三層根目錄：
    • attempts/：記錄歷史評估與候選解，agent 可瀏覽高分方案並取回比較。
    • notes/：所有 agent 的觀察、學習、反思，以 markdown 檔儲存。
    • skills/：可重用的程序、工具、腳本與實作模式（SKILL.md＋可執行 artifact）。agent 獲得 skill-creator skill 引導創建新技能。
  • 非同步多 agent 組織：N 個 agent 各維護獨立 context、在隔離 worktree 中執行，僅透過共享持久記憶間接協調（非直接通訊協議）。一個 agent 的發現經由寫入 M 影響另一個 agent 的未來搜尋——技術擴散、自發共識、交互引用全無硬編碼。
  • 心跳式介入（§3.3）：三種週期性 prompt 防止 agent 陷入局部極值或忘記維護共享記憶：
    1. per-iteration reflection：每次迭代提示記錄觀察。
    2. periodic consolidation：固定嘗試次數後觸發，回顧進度、整理 notes、蒸餾可重用程序為 skills。
    3. stagnation-triggered redirection：連續無改善時觸發，提示重新評估方向、決定繼續/修正/pivot。
  • 執行安全機制（附錄 C.7）：隔離 workspace、評估器分離、資源管理、agent session 與健康管理。

結果

單 agent（Table 1）：vs OpenEvolve / ShinkaEvolve / EvoX

  • 全部 11 個任務上 CORAL 取得最佳最終分數，其中 8 個任務建立新 SOTA。
  • 改善率 3–10x 高於固定演化搜尋 baseline;CORAL 通常 5–20 次評估內收斂，baseline 需 60–100 次。
  • 效能非靠更多評估硬堆（CORAL 使用更少），而是 agent 自主選擇探索方向避開無效嘗試。

多 agent（Table 2）：vs 單 agent CORAL

  • Kernel Engineering：四 agent 從 1,350 → 1,103 cycles（18.3% 改善），超越原最佳 1,363 cycles（20% gain）。對比單 agent 達 1,350 cycles、速率快但 plateau 早。
  • Polyominoes：80.2 → 84.2（+5.0%）。開 web search 更達 89.4（超越原 SOTA 87.0）。
  • 開源模型（MiniMax M2.5 + OpenCode）上多 agent gains 依然成立，證明架構優勢非依賴專有模型。

消融（Table 3）

  • 拔除知識累積（disable notes/skills）：Kernel Engineering 從 1,350 → 1,601 cycles（-18.6%）——知識產物因果貢獻於搜尋品質。
  • Co-evolution vs 獨立 best-of-4：協同演化在所有三任務上勝過四獨立的 best-of-4（非僅多算力）。

機制分析（§4.4）

  • 本地驗證：有本地測試的 attempt 改善率高於平均（如 Kernel Eng. 57% 本地測試率→47% 改善率 vs 平均 43%）。
  • 知識累積：進階任務上知識創建量是標準任務的 10x+（0.55–0.68 vs 0.05 每 attempt），存取知識的 attempt 改善率達 55%（Kernel Eng.）vs 26%（標準任務）。
  • 跨 agent 資訊傳遞：Kernel Eng. 36% attempt 以其他 agent 的 commit 為父代，這些 attempt 改善率 17%（全體 9%）;66% 新記錄源自跨 agent parent。
  • 探索多樣性：每 agent 的策略詞彙過半獨特（Jaccard 0.31–0.43），群體探索空間遠大於任何單一 agent。

局限與未來

  • 依賴 frontier 基礎模型（需處理複雜 coding-agent workflow），本地部署困難。
  • 所有 agent 初始同質（相同 prompt 與資訊存取），未來可注入不同人格/角色/私有資訊提升行為多樣性。
  • 假設可取得合理定義的 evaluator；對許多開放式問題 evaluator 自身也不完整或模糊，需 evaluator 與解協同演化。

對讀者的價值

  • 本批 D 類**「開放式演化 × 自主 agent」旗艦——與 2606.26294 紅皇后哥德爾機（agent 與 evaluator 協同演化）、2606.26327 EVOM（agentic 元演化 actor-critic 架構）、2606.26173 AlgoEvolve（LLM 驅動演算法交易元演化）形成族群：CORAL 在架構層把演化控制權交還 agent，紅皇后在博弈層讓 agent 與 evaluator 軍備競賽，EVOM 在設計空間層搜尋 actor-critic 架構，AlgoEvolve 在領域落地層**做交易策略演化。
  • §3.6 固化引擎接點：CORAL 的 skills/ 資料夾就是固化引擎的實例——agent 把反覆使用的程序蒸餾成可重用技能（SKILL.md + artifact），正是「LLM 反覆處理的案例結晶成確定性程式碼/抽象庫」。值得記的是 periodic consolidation heartbeat 觸發固化（而非自動），以及 attempts/notes/skills 三層記憶對應固化引擎三種原料（案例/觀察/抽象）。
  • §1 多 agent 計算圖接點：CORAL 的非同步共享記憶架構示範了一種去中心化計算圖——無預定義角色與通訊拓撲，agent 透過讀寫共享記憶間接協調，自發湧現技術擴散與共識。
  • 與 FunSearch/AlphaEvolve 系列的關係最關鍵：CORAL 不是更好的演化演算法，而是把演化演算法的控制權從演算法交還 agent——這是「固定搜尋 → 自主演化」的範式轉移。
