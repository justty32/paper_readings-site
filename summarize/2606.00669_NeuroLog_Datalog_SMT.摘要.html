論文／訪談原始來源

《NeuroLog：用 LLM 事實＋Datalog＋SMT 做可審計的神經符號漏洞挖掘》重點摘要

一句話概括

NeuroLog：一條**免編譯（build-free）**的 C/C++ 漏洞挖掘流水線，把每一層分派給它最擅長的角色——LLM 逐函式抽取「具型別的資料流事實」→ Soufflé（Datalog）規則網跨函式合成發現 → Z3（SMT）過濾不可行路徑並輸出 SAT 模型 → 第二個 LLM agent 讀 SAT 模型寫出 Python 觸發崩潰輸入 → AddressSanitizer 驗證；關鍵創新是「LLM 產生的事實庫 + 無建置流水線 + 把 SAT 模型當成可被合成消費的工件（而非是/否判決）」，在 stb/cJSON/libxml2/FFmpeg/curl 上端到端重現 8 個 CVE 級漏洞（含 CVSS-9.8 的 curl SOCKS5 堆溢位 CVE-2023-38545），並在 libarchive HEAD 上挖到 5 個記憶體安全 bug（4 個前所未報）。

解決什麼問題

C/C++ 漏洞挖掘長期被兩種工具夾擊：(1) 重量級靜態分析器（CodeQL/CPG）跑任一查詢前必須先能成功編譯，對單一 header 函式庫（如 stb）整合成本高；(2) 自由形式 LLM 讀原始碼方便但會捏造細節、在真實碼庫上丟失跨函式資料流、沒有推導鏈可審計、上下文一長就「工作記憶退化」。NeuroLog 主張：別讓任一工具獨自硬幹，而是各司其職、保留機械可審計性（每個發現都有以具體程式事實為葉節點的推導樹）。

核心方法（六階段流水線）

  • Stage 0 可選偵察：廉價 LLM 讀目標檔＋呼叫者，提出額外種子函式與「bug 類別假設＋對應形式檢查」；只提議不裁決（用語意事實 FieldSemantic(func,field,role)）。
  • Stage 1 切片：Tree-sitter 增量解析，從敏感 sink（malloc 族、memcpy、bitstream reader、libc 字串函式）做後向切片；自適應深度 σ∈{2,4,8}，用「σ-doubling」啟發式（增長率 ≤5% 就停）。
  • Stage 2 氣味掃描：機械底座（tree-sitter 確定性事實 FormalParam/CFGEdge/dominance）＋ LLM 用固定 12 關係 schema（Def/Use/Call/ArithOp/Cast/Guard/ActualArg…）逐函式輸出 JSON；schema 約束禁止發明關係，不確定就省略——把幻覺轉成「召回遺漏」而非「假陽性」。
  • Stage 3 Datalog：約 30 條 Soufflé 規則分五趟（別名→跨程序汙染→型別安全→記憶體安全→sink），只做 may-flow 過近似，不裁決可行性。
  • Stage 4 符號執行：逐發現用 Z3 判 {feasible/infeasible/unknown}；Phase A 程序內、Phase B 函式摘要＋有界內聯（d=3）、Phase D 跨發現並行（4 worker 1.98–2.55× 加速）；可行者帶 SAT 模型。
  • Stage 4b 動態擴展（可選）：從少量正常輸入種子收集likely range invariants收緊 SMT，近零成本；遵守 tier-don't-drop（只能降階、永不刪除）。
  • Stage 5 崩潰合成 + Stage 6 ASan：第二 LLM agent 把「路徑條件 Pc（檔案格式前綴）＋漏洞條件 Vc」分解，寫 Python 產候選輸入，ASan 為唯一真值裁判。

結果（含數字）

  • 端到端重現 8 個 CVE 級漏洞 + 1 個部分（stb 2、cJSON 3、curl 4+2 OOB、FFmpeg 1），含 CVE-2023-38545（curl SOCKS5，CVSS 9.8）、CVE-2023-45676 等，皆 ASan 確認。
  • libarchive HEAD 挖到 5 個記憶體安全 bug（4 個前所未報），全數上報、多個修補已合併；cpio use-after-free 7 小時內被官方確認。
  • 成本：stb 抽取 ~37 秒、$0.005；對照「frontier 模型純抽取」55 分鐘、$0.30–0.50（90× 慢、70× 貴）但 bug 相關函式召回相同。
  • 崩潰合成：2 次迭代、~5 分鐘合出 102-byte stb_vorbis 崩潰，全程無 fuzzer。
  • 動態不變量：3 個 Matroska 種子產 245 個不變量，降階 13.2% 的 FFmpeg 可行集（含一個合成花了 5 次嘗試的靜態假陽性）。
  • 規模驗證：libxml2 2,707 函式、185,839 事實、73 分鐘全流水線；on-demand Datalog 查詢工具讓 host agent 一次調查內發 19 條臨時查詢。

局限

  • LLM 的靜默召回遺漏（schema 把幻覺轉成省略，但缺的語意事實偵測不到）。
  • 免編譯的代價：宏展開/前處理條件/多檔建置旗標不可見；經未解函式指標的前向路徑會漏。
  • 規則網對「不呼叫記憶體 sink 的函式」（憑證範圍洩漏、不完整驗證、陳舊狀態重置）有盲區。
  • 單一 LLM 供應商（DeepSeek）、最大評測僅 libxml2（2,707 函式），>500K LoC 未試；Phase E2 不變量依賴語料是否走到該路徑。

對讀者的價值

  • 本主題 B 中**「LLM＝事實抽取器、符號層＝裁決者」這條保守而可審計路線的最佳工程範例**——與 2602.18095（Logitext 把 LLM 當 SMT theory）、2604.27960（LLM＋ASP 自我修正）、2507.09751（Sound & Complete NeSy LLM）對讀，可見「LLM 做什麼、符號層做什麼」的分工光譜。
  • 與 2509.06921（NeSy 資安）、2511.00776（程式碼幻覺 SLR）互補：示範如何用 schema 約束 + 推導樹把「LLM 幻覺」工程化地關進「召回遺漏」而非「假陽性」。
  • 最值得記：tier-don't-drop（只降階不刪除）+ SAT 模型當工件 + 免編譯逐函式事實抽取三招；以及那組漂亮數字——$0.005/37s 抽取、7 小時被官方確認的真實 0-day。
