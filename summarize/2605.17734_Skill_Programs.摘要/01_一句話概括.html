一句話概括

HASP（Harnessing LLM Agents with Skill Programs）：把智能體技能從被動的自然語言提示升級成可執行的 Program Functions（PF）——每個 PF 由 should_activate（判斷當下狀態／候選動作是否需要介入）與 intervene（決定如何修正：改寫動作、注入脈絡、或不介入）兩個確定性函式構成，作為外掛在 base policy 外的 harness，在failure-prone 的狀態才觸發，同一介面可同時充當推論期 guardrail、訓練期監督訊號來源、以及技能庫自我演化的准入機制；在 web-search reasoning 上僅靠推論期 PF 介入就比 multi-loop ReAct Agent 提升 25% 平均準確率，訓練＋受控演化後對 Search-R1 提升約 30.4%。

解決什麼問題

既有的「技能複用」路線（Reflexion 的言語反思、ExpeL、Voyager 的技能庫等）幾乎都把經驗固化成文字：塞進 prompt、當檢索得到的建議、或間接影響訓練獎勵。這類文字技能保有彈性，卻只是「勸告」——它無法精確表達何時該在策略迴圈中生效、如何具體改變下一步決策，模型在實務上也常常直接忽略它。換句話說，經驗被記下來了，但沒有變成能可靠、明確控制智能體行為的東西。HASP 要補的正是「用語言表達的可複用經驗」和「能可靠控制執行的可複用經驗」之間的落差。

核心方法

  • PF 的介面（雙函式、型別化 Python 物件）：should_activate(step_context, action_type, arg) -> bool 判斷該不該介入；intervene(step_context, action_type, arg, teacher=None) -> Intervention，回傳型別為 MODIFY_ACTION（直接改寫下一步動作，如把過度受限的搜尋查詢重寫、把提前定案的 FINAL 導回 SEARCH）、INJECT_CONTEXT（把修正性脈絡塞進下一輪觀察，如提醒「有相似實體」）、或 NOOP（不改變當下決策，但仍留稽核紀錄）。PF 預設是確定性、每步都跑；只有標記 needs_teacher=True 的少數 PF 才會拿到教師模型 handle（且必須在 teacher 為 None 時優雅退化）。runtime 對每個 PF 設速率上限（如 _MAX_MODIFY_FIRES=2）避免震盪，同一套 dispatcher 機制在 web-search／math／coding 三域無需修改即可套用。
  • 技能怎麼從自然語言變成可執行函式：先從訓練池中回收失敗案例，把反覆出現的「失敗—修復」模式摘要成候選 PF，每個候選必須同時指定啟動條件與介入行為；候選需通過語法／介面／mock-execution 驗證（Q_exec）才進入庫，避免庫裡塞進「聽起來合理但實際跑不動」的雜訊描述文字。附錄以 retrieval_failure（自適應搜尋恢復）為例：SKILL.md 用 YAML frontmatter 宣告 applicable_phases（如 post_search／pre_final）、每個 phase 的 conditions（如 search_empty、no_read_yet）與對應 action（reformulate_search、force_read_best_doc），下方才是給人看的自然語言說明；這份結構化規格再對應到一個真正的 PF 類別，讓「何時觸發」「如何修正」都是可執行、可稽核的程式邏輯，而不是留給模型自行解讀的文字建議。
  • 推論期（guardrail）：base policy 先提出原始動作 \(a_t^{\text{orig}}\)，harness 從技能庫 \(\mathcal{M}\) 中檢索候選 PF、評估其啟動函式，再用介入運算子 \(\Gamma\) 產生最終動作 \(\tilde{a}_t\)、注入脈絡 \(c_t\) 與紀錄 \(\kappa_t\)；沒有 PF 觸發時 \(\tilde{a}_t = a_t^{\text{orig}}\)。可選的輔助教師模型只在多個 PF 都可能適用的模糊情況下協助挑選，而非取代啟動判準本身。
  • 訓練期（把 PF 介入紀錄轉成監督訊號）：每次 PF 觸發都留下一筆事件 \(e_t=(s_t, a_t^{\text{orig}}, \tilde{a}_t, c_t, \kappa_t, \Delta_t)\)，以「介入時機、模式、正確性、結果」四訊號加權合成分數 \(A_t\)；主要訓練配方 HASP-Evolve + RS 用「任務成功度 ＋ PF 介入品質」共同排序，只保留高分軌跡做 rejection sampling；另有 SFT（直接在修正後動作上做加權監督）與 on-policy distillation（教師在學生自己會走到的狀態上示範修正）兩種替代路徑。
  • 技能庫自我演化（准入把關）：固定訓練間隔後，HASP 用當前 checkpoint 重新檢視殘留失敗，摘要出候選 PF 集合 \(\mathcal{C}_r\)；候選須同時通過可執行性驗證 \(Q_{\text{exec}}(c)\ge\eta_{\text{exec}}\)（語法、介面、mock execution、合法回傳型別）與教師五維度審查 \(Q_{\text{teach}}(c)\ge\eta_{\text{teach}}\)（是否捕捉到可複用的失敗模式、啟動條件是否恰當、修復是否有用）才會被接受、更新技能庫 \(\mathcal{M}_r \to \mathcal{M}_{r+1}\)，藉此避免過度特化、重複或雜訊 PF 稀釋檢索精度。

結果

  • 推論期單靠 PF（無教師）：web-search reasoning 平均準確率 51.0%（對照純文字技能提示 Prompt-Only Skills 僅 20.5%，比 7B 基座 Qwen2.5-Instruct 高 39.5、比 multi-loop ReAct Agent 高 25.0）；math 35.9%（Prompt-Only 32.8%）；coding 平均 pass@1 63.4%。加上輔助教師做 PF 選擇後：web-search 56.2%、math 38.8%、coding 68.7%。
  • 訓練期（固定技能庫）：web-search 從 56.2% 提升到 SFT 56.8%／RS 59.3%／OPD 62.5%；math 從 38.8% 到 SFT 40.9%／RS 42.7%／OPD 42.4%。
  • 技能庫演化：主推變體 HASP-Evolve + RS 達 web-search 60.3%、math 45.4%、coding 平均 pass@1 69.9%（比 vanilla SFT 高 12.4 個百分點）；但 HASP-Evolve + OPD 反而掉到 56.7%——同時讓「造訪狀態分佈」與「技能庫」都在變動，會引入不穩定。
  • 機制分析：所有觸發事件中 65.1% 是直接改動作、34.9% 是注入脈絡，說明 PF 真的常常直接改變可執行決策而非只加文字提醒；觸發高度集中在少數技能（decompose_complex_question 322 次、insufficient_exploration 138 次、answer_completeness 100 次），且較難的 MuSiQue（385 次）明顯高於 HotpotQA（95 次）。消融顯示：拿掉時機／模式／正確性／結果任一訊號，PF 選擇分數各掉 7.8／15.5／12.1／12.8 點；技能庫演化若不過濾，分數從 60.3% 崩到 36.3%（只做可執行過濾 48.8%、只做教師審查 47.2%），證明結構化評分與嚴格過濾兩者缺一不可。額外的「無法轉成可執行 PF、只能留文字」的技能，加入後帶來的增益有限且不一致，佐證主要增益來自「可執行」而非單純「庫變大」。
  • 技能內化：訓練後，處理模型自身行為缺陷的 PF（如 retrieval_failure、multi_hop_reasoning_failure）在 100% 先前觸發過的案例中不再需要出手；insufficient_exploration 約 30–37% 案例不再觸發；但處理問題本身結構複雜度的 decompose_complex_question 幾乎不會被內化（僅 3–12% 案例不再觸發），持續在線上提供價值。
