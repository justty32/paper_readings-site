論文／訪談原始來源

《ERL：經驗反思學習——讓 LLM 智能體自我改進》重點摘要

一句話概括

ERL（Experiential Reflective Learning）：一個輕量級自我改進框架，將 LLM 智能體的單次任務軌跡反思蒸餾為可重用啟發式規則（heuristics），測試時以 LLM 檢索相關啟發式注入系統提示——無需微調、無需多次重試，在 Gaia2 上 +7.8% 超越 ReAct baseline，並顯著提升任務完成一致性（pass^3 +8–11%）。消融證明：LLM 檢索 >> 嵌入檢索 >> 隨機；啟發式比原始軌跡泛化更強；失敗啟發式利於搜尋類任務、成功啟發式利於執行類任務。

解決什麼問題

LLM 智能體在專業環境中無法適應陌生工具與領域慣例，每次新任務從零開始。微調雖可適應但計算昂貴、閉源模型無法使用、且不支援持續學習。現有經驗記憶方法（ExpeL、AutoGuide）需多次 rollout 構建對比軌跡，在真實部署中不可行；且 ExpeL 將所有經驗無差別注入提示、AutoGuide 每步檢索額外開銷大。核心缺口：沒有將單次經驗轉化為跨任務可遷移的結構化知識的輕量機制。

核心方法

  • 啟發式生成（heuristic generation）：每完成一個任務（僅需單次 rollout + 二元成敗訊號），智能體反思軌跡，生成結構化啟發式——包含（1）引致成功或失敗的根因分析，（2）含觸發條件與推薦動作的可執行指南（如「發郵件給日曆與會者時，須先用 Contacts 工具解析姓名→郵件地址再調用 email API」）。存入持久啟發式池。
  • 檢索增強執行：對新任務，LLM 將任務分解為潛在子任務與動作步驟，對池中每條啟發式按三維度評分——任務描述相似度、經驗多樣性、指南內容的資訊量——選取 top-k 注入系統提示。預設 k=20。
  • LLM 檢索 vs 嵌入檢索 vs 隨機：LLM 檢索（GPT-5.2）考慮任務相似性＋錯誤模式＋啟發式內容；嵌入檢索（Qwen3-Embedding-0.6B）僅依任務餘弦相似度；兩者皆優於隨機。LLM 檢索最佳（56.1% vs 53.3% vs ~53.8%）。
  • 單次軌跡即可：不像 ExpeL/AutoGuide 需對比成功-失敗軌跡對，ERL 從單次嘗試即可萃取啟發式，更貼近真實部署。

結果（Gaia2 Search + Execution，GPT-5-mini，跨 universe 泛化）

  • 全面最佳：ERL 56.1% 整體成功率，+7.8% 超越 ReAct baseline（48.3%），+5.2% 超越最強前方法 ExpeL（50.9%），+5.3% 超越 AutoGuide（50.8%）。Few-shot 軌跡提示反而退化（46.4%）。
  • 可靠性大幅提升：pass^3（三輪皆成功）Execution +8.3%、Search +10.6%，表明 ERL 讓已能解的任務更穩定，而非僅解新任務。
  • 啟發式泛化優於軌跡：在相同 token 預算下，啟發式比 few-shot 軌跡始終更優（Search +23.8% @40 場景），確認蒸餾為啟發式比堆積原始軌跡提供更強學習訊號。
  • 成敗啟發式有不同適用域：純失敗啟發式整體最高（58.9%），因 Search 類型受益於負面約束剪枝無效策略（+14.3%）；純成功啟發式則在 Execution 最佳（+9.0%），因強化已驗證的動作序列。混合使用是未知任務分佈下的穩妥折衷。
  • 無獎勵訊號仍有效：即使無環境驗證、僅靠自我評估（僅 70% 正確率），ERL 仍達 51.2%，優於 baseline（48.3%）。

局限

  • 僅在 Gaia2（模擬行動環境，12 應用 101 工具）與 τ²-bench 少數領域驗證，未測試更開放/具身任務。
  • LLM 檢索每任務需額外一次 LLM 呼叫（對長任務可忽略，短任務可能有感）。
  • 迭代版 ERL（邊累積邊檢索）在來源任務上更強但在測試泛化上反而退化（-5.4%），因引導下的失敗模式收窄、產生的啟發式覆蓋面不足。
  • 啟發式池擴展後的衝突解決與檢索品質維持仍是開放問題。

對讀者的價值

  • ERL 的啟發式池正是 ai_core §3.6 固化飛輪的輕量原型：單次經驗 → 反思蒸餾 → 結構化啟發式（觸發條件＋動作）→ 持久池 → 檢索注入，形成「經驗反思學習＝固化飛輪」的最小閉環。與 SPyCE（技能-策略 RL 共演化）、HASP（技能升級為可執行 Program Functions）、SkillOS（技能策展作業系統）並讀，ERL 是無訓練、免重試、僅靠 prompt engineering 的最輕量固化路徑。
  • 與 Reflexion（口頭 RL，需多次重試直到成功）對比：ERL 放棄重試、只用單次軌跡反思，但把反思產物結構化為跨任務可檢索的資產——這恰好是 ai_core「資產工廠」從 LLM 呼叫中萃取可復用元件的邏輯。
  • 消融中的「失敗啟發式 vs 成功啟發式各有適用域」是對固化引擎治理規則的啟發：不同任務類型應有不同固化策略（負面約束 vs 正面模板），統一固化可能次優。
  • 定位：適合做 LLM agent 自我改進、經驗記憶系統、固化引擎最小可行原型、prompt-based agent 工程 的人。
