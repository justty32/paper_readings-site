論文／訪談原始來源

《GPTSwarm：語言智能體作為可優化的圖》重點摘要

一句話概括

GPTSwarm：把 LLM 智能體系統統一表示為可優化的計算圖——node＝一個操作（LLM 推論／工具使用／函數呼叫）、edge＝操作之間的資訊流，智能體是圖、swarm 是多智能體組成的複合圖；在此表示上做兩層自動優化——節點層 prompt 優化（固定其他 prompt 逐一改）＋邊層圖結構優化（把離散選邊重構為 DAG 上的機率分佈、用 REINFORCE 學連線分佈），從而自動改進單體 prompt 與跨智能體編排（甚至自動剪除無用／對抗智能體）。

解決什麼問題

各種人工設計的 prompt engineering 與多智能體框架（COT、ToT、Reflexion、AutoGPT、CAMEL、AutoGen、MetaGPT…）產出大量互不相容的程式碼庫，且智能體的提示方案與編排工作流全靠人工工程；既有多智能體系統多半不優化智能體社會的結構本身。作者要一個統一抽象＋自動優化機制。

核心方法

  • 統一抽象：語言智能體＝有向無環圖 G=(N, E, F, o)（節點 N、邊 E、計算例程 F、輸出節點 o）；swarm＝把 K 個智能體圖聯集、再加上連接不同智能體節點的邊 ℰ 而成的複合圖，新增邊＝智能體間溝通通道。COT／ToT／Self-Consistency 都能用此圖表示。
  • 邊優化（edge optimization）：d 條潛在邊有 2^d 種配置且效用因 tokenization 不可微 → 重構為連續優化：對每條邊 e_i 指定機率 θ_i，在「DAG 上的機率分佈 D_θ」上求 max E_{G∼D_θ}[u_τ(G)]；用 REINFORCE（Williams 1992）＋Adam 做無偏梯度上升更新 θ。
  • 節點優化（node optimization）：多數節點都在提示 LLM；靠圖帶來的關注點分離假設「固定其他 prompt、逐一更新每個節點級 prompt」即足夠；用一個改進算子 I（如 OPRO）吃（prompt、功能描述 d_n、節點輸入-輸出歷史 h_n）產出更好 prompt。HumanEval 上以挑選有效示範例（demonstration）方式實作。
  • 開源框架：Node/Graph/CompositeGraph 類別、Operations vs Agents、Dataset/PromptSet/Evaluator，支援 41 種檔案分析、網搜、索引記憶，async 平行。

結果（具體數字）

  • MMLU 對抗設定：邊優化能把混入對抗智能體的 swarm 分數漸近拉回單體基線，自動剪除無用／對抗智能體與邊；協作設定（7 個角色化 IO）比基線 +2.1%±1.1%。
  • Mini Crosswords：邊優化十次迭代達 0.575（初始 0.465）；換 GPT-4-Turbo 評估達 0.800，勝過先前 SOTA 的 ToT（GPT-4 0.675）。控制邊數的消融證明增益非來自邊變多。邊優化後再接節點優化 → 0.668。
  • HumanEval：節點優化把準確率從 0.76 提升到 0.88。
  • GAIA（僅用框架、未做優化）：7×ToT+self-consistency 平均 18.45 vs GPT-4-Turbo 9.70（+90.2%），Level 2 +260.2%。
  • 成本效率（vs DyLAN，MMLU 3T3A）：準確率相當（0.8301 vs 0.8366）但優化成本 $5.32／0.9h vs $105.93／25.4h（約 1/20）。

局限

  • 只優化智能體之間的邊，各智能體內部節點拓撲未動態優化（作者列為未來工作）。
  • GAIA 實驗未套用邊／節點優化，僅示範框架通用性。
  • 規模化難題：智能體數超過 100 時，維持溝通效率與穩健性是重大挑戰。
  • 邊優化需多次取樣圖並評估效用，優化階段 token／成本可觀（見附錄 F）。

對讀者的價值

  • 幾乎逐字對映 ai_core §1「系統像符號神經網路計算圖」：GPTSwarm 把整個 agent 系統顯式寫成計算圖——node＝操作、edge＝資訊流——與你的核心心智模型同構。差別是 ai_core 追求「多數確定性節點＋少數 LLM」，而本文的 node 多半仍是 LLM 呼叫；可把 GPTSwarm 當成「同一張圖抽象、但把節點確定化程度往 LLM 端擺」的參照物，反推你要往確定性端剃除到什麼程度。
  • 兩層優化直接可借用：node 級 prompt 優化＝改進「把 LLM 包成可靠函數」的那顆節點；edge 級 REINFORCE 學連線分佈＝在圖層面自動決定資訊該怎麼流——對 ai_core 的**級聯路由（§3.3）**是一個「用 RL 學路由拓撲」的具體演算法樣板（不同於 FrugalGPT 的閾值級聯，這裡學的是整張 DAG 的邊機率）。
  • 拓撲層治理：MMLU 對抗實驗顯示邊優化會自動把無用／對抗智能體剪除、斷開其邊——這是一種「以效用為准入、預設不連接、有貢獻才保留連線」的機制，恰可呼應 ai_core §3.4「拒絕為預設＋憑證准入」——只是這裡的「憑證」是 REINFORCE 學到的效用貢獻，治理發生在拓撲層而非呼叫層。
  • 對固化引擎（§3.6）的反面提醒：本文把智能體協作結晶為一張學到的邊分佈（近似確定性的圖結構），但節點本身仍是 LLM——它固化的是「編排」而非「案例邏輯」；ai_core 若要固化，關鍵反而在把高頻節點從 LLM 換成確定性程式碼，而 GPTSwarm 的圖抽象正好提供「該固化哪顆節點」的定位框架。
