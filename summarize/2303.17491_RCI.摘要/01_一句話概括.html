一句話概括

RCI（Recursive Criticism and Improvement，遞迴批評與改進）：不微調、不用任務專屬獎勵函數，只用「先產出 → 提示 LLM 找出自己輸出的問題 → 依批評重寫」這個兩步 prompting 迴圈，並把它套用在任務接地／狀態接地／agent 接地三個推理階段上；在 MiniWoB++ 的 55 個任務上超越監督式與強化式學習基線（較 WebN-T5-3B 高 41%、較無字典型輸入動作的 CC-Net 高 6%、較 SL SotA 高 37 個百分點、較 RL SotA 高 27 個百分點），且每個任務只需平均不到 2～3 條示範——比 WebN-T5-3B 少 120 倍、比 CC-Net 少 11,000 倍樣本。

解決什麼問題

要做「能用自然語言指令操作電腦」的通用 agent，過去最好的方法（CC-Net 等）是從頭訓練網路：靠大量專家示範做監督式學習、或靠人工設計的獎勵訊號做強化學習。CC-Net 用了 240 萬條專家示範（相當於 6,300 小時、77 位受試者、104 個任務），平均每任務 23,076 條。這對「新任務」完全不切實際——每個新任務都得重新收資料、重寫獎勵。另一方面，直接讓 LLM 產生鍵盤滑鼠動作又表現不佳，卡在三個接地（grounding）問題上：動作是否切題（task grounding）、在當前狀態下是否可行（state grounding）、是否符合 agent 可執行的格式（agent grounding）。

核心方法

  • RCI prompting 本體：兩步。先零樣本產生輸出，再用「Review your previous answer and find problems with your answer」要 LLM 自我批評，最後用「Based on the problems you found, improve your answer」重寫。迴圈可持續到滿足條件（環境回饋、達到最大迭代數、或啟發式）。
  • 顯式 vs 隱式 RCI：顯式 RCI 把批評文字明確採樣出來、放進改寫 prompt；隱式 RCI 不採樣批評，直接在新脈絡條件下更新前一版輸出。
  • MiniWoB++ 環境：網頁模擬環境，狀態空間只有 HTML 原始碼（無截圖），動作空間是鍵盤打字（含 Backspace／Enter 等特殊鍵）與滑鼠移動點擊，全部以正規表示式定義的自然語言指令表達（如 clickxpath //*[@id="subbtn"]、type ...）。與 CC-Net 的「字典式打字動作」不同，本文是完全生成式地預測要輸入的文字。
  • 三段接地迴圈（動作採樣拆成三個推理步驟）：
    1. 任務接地：先讓 LLM 針對高階任務產生逐步計畫，再以計畫為條件採樣動作。計畫兼作記憶模組（讓 agent 知道自己走到哪一步），並對計畫跑一次顯式 RCI 來提高成功率——作者觀察多數 MiniWoB++ 任務跑一輪就夠。
    2. 狀態接地：以隱式 RCI 提示 LLM 考慮當前 HTML 狀態，把抽象概念（如「Bob 寄來的信」）連結到具體元素（信件標題的 XPath）。作者觀察重複超過一次不會提升成功率，故只跑一次。
    3. agent 接地：再用隱式 RCI，條件於狀態、任務、任務接地動作與狀態接地動作，確保輸出格式可被 agent 執行；重複執行直到動作可執行，最大迴圈數設 3 時表現最佳。
  • 推理任務上的 RCI：以 gpt-3.5-turbo 在 8 個算術／常識推理基準上評測，最大迴圈數 2，並以正確標籤作為停止訊號（＝外部回饋）。

結果

  • 推理（表 1，Zero-Shot → Zero-Shot+RCI）：GSM8K 77.95→85.43、MultiArith 94.48→97.64、AddSub 88.58→89.76、SVAMP 80.70→84.65、SingleEq 86.61→94.49、AQuA 60.23→67.32、CommonSenseQA 64.56→68.11、StrategyQA 48.81→61.81。八個基準全面提升，連不需多步推理的 SingleEq／AddSub 也有增益（CoT 在這類題上通常無效）。
  • 與 CoT 的綜效（表 2）：Zero-Shot+RCI 在 5 個算術任務中有 4 個勝過 Zero-Shot CoT 與 Few-Shot CoT；而 CoT+RCI 組合最強（Few-Shot CoT+RCI：GSM8K 84.25、MultiArith 99.21、AddSub 90.55、SVAMP 87.40、SingleEq 93.70）。
  • MiniWoB++（55 個任務）：較 WebN-T5-3B（12,000 條示範微調 T5）高 41%；較 CC-Net（去除字典式打字動作）高 6%；較 SL SotA 高 37 個百分點、較 RL SotA 高 27 個百分點；相對「SL+RL 合併 SotA」也些微領先（不到 1 個百分點）。唯一整體勝過本方法的是完整版 CC-Net，但它用字典式打字動作，不可直接比較。
  • 樣本效率：本方法只把 2～3 條示範放進 prompt 做 in-context learning、完全不更新參數，所需樣本較 WebN-T5-3B 少 120 倍、較 CC-Net 少 11,000 倍。
  • 接地消融（圖 5）：拿掉任一種接地，成功率都明顯下降，且三者貢獻幾乎相等、彼此互補。狀態接地對「初始狀態資訊不足」的任務（如 terminal）最關鍵；任務接地對長程規劃任務（如 click-checkboxes-large）增益最大；拿掉 agent 接地後，連簡單任務的成功率都掉 60%。
  • 模型消融：GPT-3（davinci）、InstructGPT-3（text-davinci-002）、InstructGPT-3+RLHF（gpt-3.5-turbo）比較顯示，未經指令微調的模型幾乎無法完成任務。
  • 無外部回饋時的反例：在推理任務上若拿掉「用正確標籤決定何時停止」這個外部回饋，RCI 容易產生偽陰性批評（false negative critics），一半基準只回到零樣本水準、另一半甚至更差（附錄表 17）。

局限

  • 主要只在 InstructGPT-3+RLHF（gpt-3.5-turbo、gpt-4）上驗證，RCI 對其他模型的泛化性未探索。
  • 長 HTML 難以處理：受限於脈絡長度，book-flight、choose-date、click-pie 等任務因 HTML 過長而被排除；剪枝 HTML 本身也不容易。
  • 動作空間僅限點擊與打字，缺拖曳、複製貼上等，限制了網頁操作能力。
  • 只顧短期決策：需要前瞻的任務（guess-number、search-engine、use-spinner 長程規劃；tic-tac-toe、use-autocomplete 多步推理）表現差；依賴視覺渲染的任務（count-shape）也弱，顯示單一 HTML 模態不足。
  • RCI 比只採樣一次的方法貴（多次 LLM 呼叫）；作者也承認在部分電腦任務上仍不如任務專屬的 SL+RL。
