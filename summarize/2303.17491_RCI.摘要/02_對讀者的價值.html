對讀者的價值

  • 對 ai_core §3.4「治理＝拒絕為預設＋憑證准入」：本篇最重要的貢獻不是「自我批評有效」，而是把批評對象切成三層接地——任務接地問「這步對不對題」、狀態接地問「這步在當下環境可不可行」、agent 接地問「這步符不符合可執行規格」。這正對應 ai_core 的憑證准入分層：格式合法性（agent 接地）→ 環境可行性（狀態接地）→ 目標一致性（任務接地），而且最底層的 agent 接地是可用正規表示式確定性驗證的——論文自己說 agent 接地迴圈「跑到動作可執行為止（上限 3 次）」，這就是一個確定性驗證器驅動的重試迴圈，不是靠 LLM 自我感覺。消融顯示拿掉它簡單任務就掉 60%，等於量化了「確定性接地訊號」的價值。
  • 「批評的接地層級決定迴圈是否空轉」：本篇同時提供了正反兩面證據。正面是三段接地在 MiniWoB++ 上各自不可或缺；反面是推理任務上一旦拿掉標籤回饋，RCI 就退化成偽陰性批評、效能持平甚至倒退。這對 §3.4 的意涵很直接：自我批評迴圈必須綁定一個外部憑證來源才會收斂，否則只是把 token 燒掉。對照 2310.01798（LLM 無法自我修正推理）——該文正是拿「沒有外部訊號時自我修正反而變差」當主論點，RCI 的附錄表 17 等於是同一現象的自證。
  • 與庫中對照篇的定位差異（主題 7 自我改進／反思迴圈）：2303.17651 Self-Refine 是同一批評-改進骨架但無外部接地、單一物件內迭代；2303.11366 Reflexion 加上外部評估器＋跨試驗持久情節記憶；2210.03629 ReAct 靠環境觀察做接地但不做顯式自我批評；RCI 則是純 prompting、無記憶、無額外訓練模組，把接地拆成三層各跑一次短迴圈。四者連起來剛好是一條「接地訊號從無到有、從瞬時到持久」的光譜。
  • 對 ai_core §3.3「成本梯度」：論文明說 RCI 比單次採樣貴。三段接地各自 1～3 次呼叫意味著單一動作要 5～8 次 LLM 呼叫——這正是「先用 LLM 迴圈做出可用行為，再逐步把可確定化的層（尤其 agent 接地的格式檢查）換成確定性程式碼」的典型成本梯度案例：agent 接地完全可以用 regex 驗證器＋受約束解碼取代（§5 下層受約束填碼），不必燒 LLM 呼叫。
  • 對 ai_core §1「可優化計算圖」／§3.6「固化引擎」：作者在討論一節自己點出 RCI 是「把 LLM 輸出寫進外部記憶再讀回」的基本版，並預期未來會有更進階的迴圈與 prompt 結構、甚至用 RL 去搜尋「有效的迴圈與 prompt 結構」——這正是 ai_core 主張的「把 LLM 呼叫組成可優化計算圖」的早期宣言。但 RCI 本身不沉澱任何東西：每次任務從零開始重跑三段接地，沒有把「這類 HTML 該怎麼點」結晶成可重用資產，因此無法剃除 LLM 依賴。
