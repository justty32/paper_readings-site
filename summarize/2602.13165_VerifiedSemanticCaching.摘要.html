論文／訪談原始來源

《Krites：非同步驗證式語意快取用於分層 LLM 架構》重點摘要

一句話概括

靜態閾值不變 + 非同步 LLM 法官 + auxiliary overwrite：在分層（static/dynamic）語意快取中，維持保守的 serving-path 相似度閾值不動，但對落入「相似度灰色地帶」的靜態 miss，以離線 LLM 法官驗證靜態答案是否適用於新 prompt；核准後將靜態答案以 auxiliary overwrite 注入動態快取（pointer layer），使後續命中直接使用已審查的 curated 答案——靜態覆蓋率最多提升 3.9 倍，且完全不增加關鍵路徑延遲。

核心貢獻

  • Krites 策略：第一個將驗證與 serving 解耦的非同步語意快取策略。Serving path 完全保留 GPTCache-style 閾值決策；靜態 miss 落在 [σmin, τstatic) 灰色地帶時，排程離線 LLM judge 做 binary APPROVE/REJECT。
  • Auxiliary overwrite 耦合機制：核准的 (q, static_answer) 配對以 upsert 寫入動態快取，將 dynamic tier 轉化為 static tier 的可變指標層——不複製靜態內容，僅建立 (prompt → static origin) 的映射；受 LRU/TTL 常規回收，無須 pinning。
  • Trace-driven 實驗：在 vCache 的 SemCacheLMArena（對話）與 SemCacheSearchQueries（搜尋）基準上，靜態來源服務佔比分別提升 +136.5%（8.2%→19.4%）與 +290.3%（2.2%→8.6%），對照組為 vCache Pareto-optimal 靜態閾值基線。
  • Claude Opus 4.5 法官可行性驗證：100 對人工標註灰色地帶樣本，法官與人類標註一致 99/100——證明 LLM-based 驗證實務可行。
  • ROI 模型：法官成本為 λ * pgrey * cJ，收益為 E[papp * N]（N = 動態條目在被回收前的重複命中次數）——頻繁重現的 paraphrase 場景 ROI 最高。

對讀者的價值（與 ai_core 的接點）

  • 直擊 ai_core §3.4 憑證（驗證式快取）：Krites 的核心機制就是「LLM judge 核發憑證後才准入靜態答案」——這正是 ai_core「拒絕為預設＋憑證准入」在快取層的實例化。離線 judge 的角色等同於治理層的驗證器：只有在 equivalence 被確認後，答案才被「核准」進入服務路徑。ai_core backlog 標註本文為「快取+憑證（§3.4+§3.3）」，因為它示範了如何在不阻塞服務的前提下插入驗證關卡。
  • 釋放 §3.3 成本梯度中被束縛的價值：分層架構本身就是成本梯度的體現——static（最便宜，離線審查）→ dynamic（中等）→ backend（最貴，全推理）。傳統單一閾值讓大量合格的靜態答案困在灰色地帶無法被重用；Krites 以微量離線 judge 成本為代價，將這些答案「從成本梯度低端解放出來」，直接減少高成本 backend 呼叫。
  • 輔助寫入 = 固化引擎的輕量類比：auxiliary overwrite 將 curated 答案從 static 推到 dynamic，就像固化引擎將 LLM 反覆處理的模式結晶為確定性執行——二者都是「經一次驗證後永久受益」的模式。差異在於 Krites 保留可回收性（LRU/TTL），適合 dynamic 場景；固化引擎的產出是長期存留的程式碼/抽象庫。
  • 灰色地帶概念通用於治理：Krites 的灰色地帶 [σmin, τstatic) 與 ai_core 治理層的「信心不足不拒絕」設計同構——某些請求落在無法自信判定的區間，不阻斷服務，但排入非同步驗證隊列。這個模式可推廣到其他 ai_core 治理場景（如模糊查詢的參數推斷、意圖歧義的消歧）。
