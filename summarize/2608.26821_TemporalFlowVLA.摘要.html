論文／訪談原始來源

TemporalFlow-VLA: Learning Physically Grounded Execution History for Long-Horizon Robot Manipulation 重點摘要

一句話

TemporalFlow-VLA 不把更多歷史影像直接塞給動作模型，而是在訓練時以機器人運動學投影出的表面 temporal flow 監督兩個時間尺度的查詢 token，迫使它們壓縮「剛才實際怎麼動」；部署時移除幾何標註管線，僅保留查詢 token 與非同步歷史特徵快取。

問題與方法

  • 問題：同一張當前影像可能出現在接近、抓取成功、抓取失敗或恢復階段。普通多幀 VLA 雖會利用歷史，卻未必理解幀序與物理變化；作者的前導診斷甚至發現，打亂三張歷史觀察幾乎不改變離線 action flow-matching loss，而完全移除歷史才讓損失上升約 4.6%（作者自報）。
  • 訓練用物理標籤：作者利用已記錄的關節狀態、URDF 幾何與相機校準，把機器人表面點從歷史姿態投影到當前 RGB 平面，建立 robot-surface temporal flow。可見性、連桿一致性與三維殘差用來過濾錯誤對應，再把位移聚合成 patch 級監督；不需人工 flow 標註，也不把幾何處理帶到部署端。
  • 雙尺度時間查詢：對一個 action chunk，模型取 t-15、t-8 與當前幀。Q8 摘要近期變化，Q15 可再讀取較早影像與 Q8，形成由短到長的單向階層。動作 token 不能直接讀歷史影像，只能經過這兩個受 flow 監督的瓶頸，因此歷史必須先被壓成與執行相關的表示。
  • 共同訓練：總損失結合原有 action flow-matching 與 temporal-flow 重建。輔助解碼頭只在訓練期使用，部署時動作模型從查詢 token 取得歷史，不需要 optical flow、軌跡估計器或額外感測器。
  • 非同步快取：前一個 action chunk 執行期間，背景程序先編碼下一次重規劃會用到的歷史幀；重規劃時只同步編碼當前幀。這移除重複歷史影像編碼，但時間查詢仍會在主 transformer 內運算。

作者報告的結果

在 LIBERO 四套件、三個隨機種子上，TemporalFlow-VLA 的平均成功率為 97.63 ± 0.26%，其中 LIBERO Long 為 96.60 ± 0.87%，比表中最強既有平均結果高 2.1 個百分點（作者自報）。在 RoboTwin 的 12 項任務上，Clean／Randomized 平均成功率為 85.5%／84.2%；隨機化條件比納入比較的最佳既有結果高 8.0 個百分點，優勢主要集中在較長的多階段任務（作者自報）。

消融顯示，直接多幀輸入為 79.8%／81.5%，無 flow 監督的雙查詢為 83.2%／83.6%，完整方法為 85.5%／84.2%，分別對應 Clean／Randomized（作者自報）。歷史移除與次序交換都使六項任務的離線動作損失上升，且五項任務以交換次序最差；作者明確提醒這是離線敏感度診斷，不等於線上成功率（作者自報）。

實體 AgiBot A3 上，杯子堆疊由 57.8% 提升到 77.8%，雙瓶裝箱由 86.7% 提升到 97.8%；每項結果各來自 45 次測試（作者自報）。快取則把 LIBERO Long 的平均伺服器端取樣延遲由 68.10 ms 降到 62.78 ms，在相符的多次重規劃區段節省 7.8%（作者自報）。代價是訓練期加入時間模組與輔助解碼器後，wall-clock 訓練時間約增加 20%（作者自報）。

結論與局限

結果支持的不是「歷史越多越好」，而是歷史需要一個與控制對齊的學習目標。受機器人表面運動監督的窄介面，比讓動作模型自由讀取多幀更能利用次序與物理變化；非同步快取則讓這個介面不必付出多次同步視覺編碼的成本。

作者明確指出，本文固定使用一組歷史觀察，沒有系統性搜尋歷史幀數、間距與最適時間範圍。不同操作任務可能需要不同的時間尺度與取樣密度，這仍是未解問題。此外，幾何標籤依賴訓練資料中的機器人狀態、模型與相機校準；雖然部署期不再需要它們，建立監督資料本身仍有前置條件。

對讀者的價值／ai_core 接點

這篇對 ai_core 的啟發是「先規定壓縮後的表示必須回答什麼，再讓模型學壓縮」。兩個查詢 token 不是泛用記憶槽，而是被物理可驗證的 flow 目標綁定到不同時間尺度；這比無約束地追加 context 更接近可治理的中介表示。另一個接點是快取邊界：可重用的感知特徵移出同步關鍵路徑，但真正參與決策的查詢仍即時計算。若 ai_core 要把長歷史固化為短憑證，這種「離線可驗證監督、線上緊湊介面、明確失效條件」的分層很值得借用。
