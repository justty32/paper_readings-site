論文／訪談原始來源

《法學碩士會夢想離散演算法嗎？（Do LLMs Dream of Discrete Algorithms?）》重點摘要

一句話概括

LLM 本質是機率推理，在需嚴格邏輯／離散決策／可解釋的場景會失效（幻覺、錯誤步驟拆解）；本文提出神經符號方法——用 Prolog 謂詞（一階邏輯：事實＋規則＋否定＋證明系統）＋一組可組合的安全工具，讓 LLM 把複雜查詢拆成可驗證子任務並「拼接」現成元件而非自由生成程式碼，在金融多步推理 benchmark DABStep 上改善精度、覆蓋與系統文件化。

解決什麼問題

LLM 靠 embedding 的統計鄰近性推理（如把 "sunny" 與 "day" 當近義），面對需二元／離散正確答案的任務（數學證明、邏輯謎題、法律解讀、安全攸關決策）會產出「貌似合理但邏輯錯誤」的答案。尤其在 AI Agent 的 planner（規劃器）階段，三大失效模式：(1) LLM 幻覺、(2) RAG 檢索鄰近性與意圖不對齊、(3) planner 選錯執行步驟。無約束的程式碼生成又帶來安全漏洞與不可預測行為。

核心方法

  • 定位於光譜中段：一端是傳統軟工「固定功能」、另一端是「LLM 自由生成任意程式碼」；本文取折衷——LLM 透過智慧組合預定義元件來編排解法，提升可靠性／可解釋性／安全性。
  • 為何選 Prolog（而非 HOL/Lean/Z3）：謂詞無副作用利於追蹤資訊流；可同時表達邏輯與中小型事實/規則資料庫；語言穩定老成、LLM 不易因介面變動而幻覺；夠豐富但不致過度而失控。
  • 事實（facts）＝知識圖譜（如 acquirer_country(gringotts, gb)）；規則（rules）＝路徑；關鍵是 否定（\+） 讓 Prolog 成為一階邏輯證明系統——這是純知識圖譜難以表達的。
  • 把規劃當成「文法問題＋強型別系統」：定義型別（TableName/Filter/Projection/Header/Data…）與一組謂詞工具（query_data、filter、project、count、anomaly、visualize_map…），分為資料源／演算法／UI 視覺化三類（沿用作者前作 [20] 的分類）。
  • 規劃提示（prompt）含自我評估指標：要求 LLM 生成 Prolog 計畫並自評 evaluation 分數（從 1.0 起，未實例化即用 foreign function→0.0、用 LLM 自寫 assert→−0.2、對含 header+data 的物件呼叫 sort/findall→−0.4…），靠獎懲引導自我反思（類似把自生評估指標餵入 GRPO 微調迴圈）。
  • 規格擴增流程：從少量種子問題用 LLM 擴成數百題 → 萃取 MVC 元件 → 找出實作缺口、列出待實作函式（建議人工複審以防幻覺）。

結果

  • 在 DABStep（Data Agent Benchmark for Stepwise Evaluation） 上驗證：456 個任務、平均 3.2 表/題、64% 需 join、28% 需外部文件、易/難 = 55%/45%、採精確匹配（不容部分正確或幻覺）；領域為支付/風險/商戶行為。
  • 用 40 題擴增 + MVC 萃取，自動推導出一整套工具（get_payments_data、calculate_transaction_fee、display_* 等近 30 個函式介面）。
  • 結果顯示混合架構在多步推理上改善精度、覆蓋與系統文件化，重新找回傳統 user story/use case 的嚴謹度，並支援工作量估算與功能缺口辨識。（屬方法論＋案例論文，未給大規模對照數字。）

局限

  • 偏方法論／架構論文，DABStep 上缺乏與其他 agent 的系統性量化對照表（精確 pass@1 數字未明列）。
  • 「拼接現成小元件」的代價：能回答多複雜的問題，取決於初始探索解空間的步驟；過於複雜的開放問題仍受限。
  • 需為大型資料庫表達變數「域（domain）」才能做否定/量詞，對超大資料庫可能不可行。

對讀者的價值

  • 本批 E 類（ARC-AGI/LLM 推理）的「神經符號 planner」代表——主張用符號邏輯（Prolog 一階邏輯）約束 LLM 規劃、以「組合現成工具」取代「自由生成程式碼」，正面對治幻覺與安全。
  • 最值得記：事實=知識圖譜、規則=路徑、否定=證明系統 的層級；把規劃化為文法+強型別；自評 evaluation 指標的獎懲式自我反思；以及 DABStep 這個強調精確匹配的金融多步推理 benchmark。
  • 與本批 2601.05280（同走神經符號路線，但用演算法資訊論/CTM 對抗自我改進崩潰）、2511.00776（程式碼幻覺綜述，亦倡符號執行/約束解碼緩解幻覺）互補：三者共識皆為「純統計 LLM 不夠，需符號/機制層補強」。
  • 適合做 AI Agent 規劃器、神經符號系統、企業級可靠 LLM 應用、資料分析 agent 的人。
