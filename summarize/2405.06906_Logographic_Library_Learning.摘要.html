論文／訪談原始來源

《以庫學習發現語素文字中的結構》重點摘要

一句話概括

把每個漢字編碼成筆畫序列的 LISP 風格程式，用 Stitch 庫學習演算法以「最小描述長度（MDL）」為目標反覆抽出可重用的子程式（部件），結果不僅自動重新發現 93% 的官方部首與人類標註的層級拆字結構，還證明整套漢字書寫系統的程式複雜度隨時間單調下降（甲骨文＞篆書＞繁體＞簡體），為「語言的組合性源自對表徵效率的歸納偏好」提供了可計算、可驗證的證據。

解決什麼問題

人類語言的組合性（用少量building block 組出大量複雜結構）被認為源自對「表徵效率」的歸納偏好，但過去要在形態、句法等層次上做結構發現在技術上一直很困難；書寫系統的結構發現更缺乏可量化、可驗證的計算方法。本文以有 3000 多年演化史、部件高度重用的漢字書寫系統為對象，提出一個以庫學習（library learning）與程式合成技術為基礎的計算框架，一方面驗證該框架能否重新發現漢字已知的語言學結構（部首、層級拆字），另一方面用它來分析書寫系統隨時間演化的複雜度變化——即「書寫系統是否真的朝簡化演進」這個此前有爭議的問題。

核心方法

  • DSL 與程式編碼：定義一個含 33 種基本筆畫（六種基本筆形＋27 種轉折筆形，依中國官方筆順標準）＋1 個 list 輔助符號（共 34 個基本符）的領域特定語言（DSL）；每個漢字依標準筆順唯一編碼成一段 LISP 風格程式，例如「知」＝(list P H H SP N S HZ H)。
  • MDL 目標：把「找出最有效表徵一整個書寫系統」形式化成庫學習問題——尋找最優函式庫 L*，使「用 L* 重寫後所有字元程式的描述長度」加上「L* 本身的描述長度」最小；描述長度沿用 DreamCoder／Stitch 的 λ 演算成本量測。
  • 迭代學習：套用 Stitch 演算法（比 DreamCoder 壓縮階段快三個數量級，故可處理數千字規模）以 top-down 搜尋反覆找出最大可重用子程式並加入庫，新函式可疊在既有庫函式之上形成層級式抽象（如先學出「日」的部件，再學出建立在其上的更大部件）。
  • 資料：Part I 用 6,596 個簡體中文字（涵蓋官方標準所定義 6,763 字中的絕大多數，原文標準名稱因引用標號未能還原故不臆測）；Part II 為做歷時分析，額外對齊甲骨文（約西元前 1300 年）、篆書（約西元前 200 年）、繁體、簡體四階段共 754 個字，甲骨文/篆書筆畫因無現成拆解資料，改以手繪圖形板記錄軌跡、擬合貝茲曲線再以 k-means 離散化為同尺寸的 33 種筆畫類型，確保四套 DSL 可直接比較。

結果

  • 壓縮與層級性：從 6,596 字學出 1,805 個新庫函式（加基本符共 1,839），其中 95.1%（1,717 個）是建立在其他學到的函式之上的層級抽象；整體壓縮率 4.16 倍，平均每字所需函式數縮到原本的 1/5.63（例：「颢」原本需 19 個函式，壓縮後僅需 2 個，分別對應「景」「页」兩個部件，且二者本身又建立在「日／京／贝」之上）。
  • 對照人類拆字標準：與 3,052 字的黃金標準拆解樹比較，模型層級表徵的 F1=61.6、召回率 76.3%，明顯優於平衡二元樹／隨機二元樹／左分枝／右分枝四種基線（F1 分別僅 34.4／28.5／30.8／36.0）。
  • 對照官方部首：官方（中國教育部）201 個部首中，模型自動學出的庫函式重新發現了 187 個（93.0%）。
  • 歷時複雜度分析：以本文的程式（MDL）複雜度衡量，四階段書寫系統複雜度呈單調遞減（甲骨文＞篆書＞繁體＞簡體），支持「書寫系統隨時間趨向簡化」的假說，並與此前一項僅用「圖形周長複雜度」得出非單調結論（篆書＞繁體＞簡體＞甲骨文）的研究形成對照與挑戰。
  • 繁簡對照（3,762 對字）：繁體字在未壓縮的基本 DSL 下描述長度比簡體長 16%，但壓縮後差距縮小到僅 4%——即繁體的壓縮率（可視為系統性的代理指標）高於簡體，顯示 1955–1986 年的簡化改革雖減少了絕對筆畫數，卻也破壞了部分部件重用的系統性。

局限

  • 現代（繁體／簡體）字用官方標準拆解，古代（甲骨文／篆書）字則靠人工標註筆畫軌跡，兩者系統性程度不對等，可能讓古文字表徵顯得較不系統；純筆畫序列表徵也未捕捉筆畫間的空間佈局關係。作者建議未來納入無監督影像解析與空間模板來改善。
  • 目前僅處理「形」的層次，未擴及「形-義」對應；且與人類拆字標準比較時，因模型以最大壓縮為目標，可能挖出比人類慣常認定更細碎的重用模式，故精確匹配率（6.9%）遠低於召回率。

對讀者的價值

  • 本篇是 ai_core §3.6 固化引擎「壓縮即發現結構」命題最乾淨的形式化驗證：固化引擎的判準——把反覆出現的模式結晶成可重用抽象庫——本文完全不涉及 LLM 或 agent，卻直接把「MDL 壓縮」當作抽象發現的唯一目標函式，並且罕見地提供了可獨立驗證的外部真值：官方部首（93% 重現率）與人類標註拆字樹（F1=61.6，遠贏過四種樹狀基線）。這在 agent 技能庫（如 Voyager）或 code refactor（如 ReGAL）場景中通常無法做到——沒有人能給 agent 學出的技能庫打一個「金標準對照表」，但漢字部首恰好是三千年人類獨立驗證過的「正確答案」，讓「壓縮≈發現真結構」這個假說第一次有了可量化的證據，而非工程直覺。
  • 方法上直接站在庫中已有工作的肩膀上並延伸新場域：本文的庫學習演算法即 2211.16605 Stitch（比 2006.08381 DreamCoder 快三個數量級），MDL 目標與層級抽象定義也承襲 DreamCoder／Stitch 一脈；與同屬 G 類的 2310.19791 LILO（doc-string 輔助）、2401.16467 ReGAL（重構程式）、2212.04596 babble（e-graph＋反統一）、1804.04152 Learning Abstractions（合成加速）相比，本文的特色不是提出新演算法，而是把現成的庫學習引擎搬到一個有三千年人類共識答案的全新資料域（書寫系統），等於為整個庫學習範式做了一次跨域外部效度檢驗。
  • 與「何時固化」路線（2605.09985 前瞻式壓縮、2603.23244 人類線上庫學習）互補而非重疊：那兩篇關心的是「該不該現在固化、如何避免庫爆炸」的時機／規範性判準（用人類行為當神諭），本文關心的是「固化出來的東西是否代表真結構」的正確性判準（用人類三千年語言學共識當神諭）——兩條軸線合看，才是 ai_core 固化引擎「何時固化＋固化得對不對」的完整判準拼圖。
  • 建議歸類：G 類（程式合成／庫學習方法論，與 DreamCoder、Stitch、LILO、babble 同組；雖帶有認知科學假說，但核心貢獻是計算方法與可重現的演算法管線，非人類行為實驗）。
