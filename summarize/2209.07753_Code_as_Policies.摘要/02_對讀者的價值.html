對讀者的價值

  • 對 ai_core 主題5「以程式為受約束生成產物」：CaP 是最直接的體現——LLM 的輸出不是自然語言計畫，而是可執行、可檢查、可重用的程式（LMP）；exec 前的 AST 安全檢查、有限的 globals 作用域，正是把 LLM 節點的自由度限制在一個確定性可控的沙盒裡（§1「多數確定性節點＋少數 LLM」、§5「下層受約束填碼」的具體案例）。
  • 對 ai_core §3.6「固化引擎」：階層式程式碼生成把「遞迴新生的函式」累積進 scope／函式庫供後續呼叫重用，是一種執行期的程式碼固化雛形——但要老實指出：本文的固化停在「同一 session 內的函式累積」，沒有像 Voyager 的技能庫那樣做跨任務、持久化、可檢索的資產管理，也沒有 ReGAL 式的「批次重構＋等價驗證＋週期修剪」；CaP 的固化更接近「用完即棄的臨時腳手架」而非長期資產。
  • 與庫中已收錄工作對比：
    • 2305.16291 Voyager：兩者都主張「LLM 輸出＝可執行程式碼」，但 Voyager 額外加了持久技能庫（跨 episode 儲存、向量檢索、零樣本遷移到新世界）與環境回饋驅動的迭代自我修正；CaP 沒有這兩層，是更純粹的「單次生成、single-shot 執行」範式，可視為 Voyager 技能庫機制的前身概念。
    • 2212.10561 Parsel：Parsel 用「規格→階層式自然語言函數描述＋約束→多候選實作→組合搜尋驗證」的複雜管線把「整段寫對」換成「分頭實作＋驗證組裝」；CaP 的階層式生成則更直接——遇到未定義函式就遞迴生成、不做多候選搜尋也不做約束驗證，複雜度低很多但也缺乏 Parsel 式的正確性保證機制。
    • 2305.17126 LATM：LATM 明確把「造工具（貴模型）」與「用工具（便宜模型）」分工、且工具需通過驗證才入庫成為可重用資產；CaP 的第一方 API 庫是人工預先給定而非 LLM 自己造的，遞迴生成的函式也未經任何正確性驗證即可被後續呼叫——是 LATM「工具製造」概念更早、更粗放的類比。
    • 2401.16467 ReGAL：ReGAL 強調「執行結果等價驗證＋週期性編輯修剪」的抽象品質控制，CaP 完全沒有這層品管，函式一旦生成就直接信任並重用。
    • 2307.09702 Outlines：Outlines 用 FSM 保證輸出語法合法，CaP 靠 prompt 範例＋自然語言命名慣例讓 LLM「自律」寫出合法且語意正確的程式碼，只做執行前的安全性（非正確性）檢查——兩者是「語法層強制約束」與「語意層弱約束（僅靠範例與人工 API 設計）」的對照組。
    • 2303.11366 Reflexion：Reflexion 靠外部接地訊號（測試/環境）驅動跨試驗反思修正；CaP 完全沒有失敗後重試或自我修正機制，是「生成即定案」的單輪範式。
  • 老實話：CaP 能可靠工作的根本原因，也正是它的天花板——API/原語庫是人工預先設計並命名良好的，LLM 的貢獻僅限於「組合」而非「發明」感知或控制能力；一旦任務所需抽象層級超出 API 覆蓋範圍或 Examples 所示範的模式，系統即失效且無法自知。
  • 建議歸類：I 類（把 LLM 產物轉為可執行、可檢查的確定性程式碼資產，儘管其「固化」與「品管」機制都比後續工作（Voyager/ReGAL/LATM）原始得多）。
