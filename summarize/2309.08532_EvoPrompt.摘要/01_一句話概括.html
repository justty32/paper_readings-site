一句話概括

EvoPrompt：讓 LLM 當演化算子（負責交配/突變、維持自然語言的連貫與可讀性），演化算法（GA、DE 兩種變體）當搜尋框架——全程不需梯度、不需模型參數，只靠黑箱 API 存取，就能從一個初始 prompt 族群迭代演化出更優的離散 prompt；在 31 個資料集上一致優於人工 prompt 與既有自動化方法，BBH 上最高勝過基準達 25%。

解決什麼問題

Prompt 品質嚴重影響 LLM 表現，但撰寫好 prompt 高度仰賴人力與經驗、缺乏系統性指引。既有自動化離散 prompt 方法多走兩個極端：一是「窮舉候選＋挑最佳」偏重探索（如 APE），容易優柔寡斷、浪費算力；二是「基於錯誤案例編輯現有 prompt」偏重利用（如 APO/ProTeGi 的文本梯度法），容易陷入局部最優且多限於有標準答案的任務。傳統演化算法在探索與利用間有良好平衡，但其算子（突變/交配）通常獨立編輯序列中的元素，忽略 token 間的關聯——這對必須保持連貫可讀的自然語言 prompt 是硬傷。EvoPrompt 要解決的正是「如何讓演化算子在離散、需保持語言流暢的 prompt 空間上運作」。

核心方法

  • 框架三步驟（Algorithm 1）：初始族群（人工 prompt ＋ LLM 生成的變體，共 N 個）→ 演化（每輪從族群選父代 prompt，用 LLM 依演化算子指令生成新 prompt）→ 更新（在 development set 上評分，依演化算法規則決定去留），迭代 T 輪，回傳族群中分數最高者。
  • GA 版本：以輪盤法（roulette wheel selection）依 development set 分數為機率選兩個父代 prompt；LLM 依指令先做交配（crossover，合併兩父代的字句）、再做突變（mutation，對子代做隨機改寫）；更新規則＝新舊 2N 個 prompt 合併後取分數前 N 名（elitist top-N）。
  • DE 版本：模仿標準差分演化 y = a + F(b − c) 的結構，設計三步驟並轉譯成 LLM 指令：(1) 找出兩個隨機 prompt 的差異部分（對應 b − c）；(2) LLM 只對差異部分做突變（對應 F(b − c)），刻意保留兩者共同部分（假設共同部分對表現有正向貢獻）；(3) 把突變後的差異部分與當前族群最佳 prompt（對應向量 a，DE 的一種變體用當前最佳代替隨機向量）結合；(4) 讓結果與當前基礎 prompt 交配，產出候選。更新規則＝逐一以族群中每個 prompt 為基礎生成候選，分數較高者留下（steady-state、逐一淘汰）。
  • 無梯度、黑箱可用：全程不存取 LLM 的參數或機率輸出，只需能呼叫、能評分即可，天生相容閉源 API（GPT-3.5）與開源模型（Alpaca-7b）。
  • 成本結構（附錄 C.3）：評估開銷＝ N × |D| × T（族群大小 × development set 大小 × 迭代輪數）；加上生成候選的 N × T 次呼叫，總 API 請求數＝ N × T × (1 + |D|)，與 APE 同量級。實驗預設 N=10、T=10（BBH 為 T=10、|D|=50，3-shot）。

結果

  • 語言理解（7 個資料集，Alpaca-7b）：EvoPrompt(GA) 平均 76.25、EvoPrompt(DE) 平均 77.05，均大幅優於人工指令 MI（71.07）、Natural Instructions（68.21）、APE（73.80）、APO（僅部分資料集，70.55）；在 Subj（主觀性分類）上 DE 比 GA 高出約 5 個百分點。
  • 語言生成：SAMSum 摘要（ROUGE-1/2/L）與 ASSET 簡化（SARI）上，EvoPrompt 在 Alpaca-7b 與 GPT-3.5 皆穩定優於人工 prompt 與 APE；DE 在摘要任務上明顯優於 GA，在簡化任務上兩者相近。
  • BBH（23 個高難度推理任務，GPT-3.5）：22/22 任務優於基準 prompt「Let's think step by step.」；DE 平均 +3.5%，最高 +25%；GA 平均 +2.5%，最高 +15%；DE 在 6 個任務上贏 GA 超過 2%。
  • 成本分析（Table 13）：在相同迭代數下，GA/DE 僅以些微 token 開銷即顯著勝過 APE；GA 收斂速度與 APE 相近，DE 略慢但天花板更高。
  • 消融：GA 用輪盤法選擇優於錦標賽/隨機；DE「只突變差異部分」＋「以當前最佳為 Prompt 3」均對結果有明顯正貢獻；初始族群用隨機挑選即可逼近用最佳表現 prompt 初始化的效果，但初始 prompt 品質差時 DE 較 GA 更能跳脫局部最優。

局限

  • 演化算子與 EA 框架皆固定為經典、教科書式的 GA/DE，尚未探索更先進的自適應變體（如自適應控制參數的 DE 變種）。
  • 評估成本與族群大小 × 迭代輪數 × development set 大小成正比，對大型 development set 或大量迭代仍是真金白銀的 API 呼叫開銷。
  • BBH 上所有任務共用同一組初始族群、未注入任務專屬先驗知識，作者指出加入任務專屬 prompt 可能再提升表現。
  • 僅驗證 GA、DE 兩種 EA；作者在附錄提出把粒子群優化（PSO）、蟻群演算法（ACO）、MAP-Elites 等其他經典演算法接上 LLM 是未來方向，本文尚未實作。
