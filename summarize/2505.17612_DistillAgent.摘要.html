論文／訪談原始來源

《Agent Distillation：把 LLM Agent 蒸餾進小模型》重點摘要

一句話概括

提出的 Agent Distillation 框架不蒸餾 LLM 的「答案」，而是蒸餾 LLM agent 的**「思考—行動—觀察」完整互動軌跡**，讓小模型（sLM，0.5B–7B）學會像 agent 一樣自行搜尋（retrieval）、寫 Python 碼（code execution）、根據工具回饋修正，而非死記靜態推理鏈（CoT）。搭配 First-Thought Prefix（借 CoT 首步推理修復 agent prompt 的分佈偏移）和 Self-Consistent Action Generation（test-time 多重採樣+過濾無效程式碼+多數一致投票），讓 0.5B/1.5B/3B 蒸餾 agent 的均分勝過以 CoT 蒸餾的下一級 1.5B/3B/7B 模型，尤其在 out-of-domain 的事實（HotPotQA/Bamboogle/MuSiQue/2Wiki）與數學（MATH/GSM-Hard/AIME/OlymMATH）推理任務上泛化更強。

解決什麼問題

CoT 蒸餾（teacher 生推理鏈→student 模仿）在需要稀有知識或精確計算時常失敗：小模型硬記 teacher 的推理步驟卻缺乏驗證機制，容易幻覺（hallucination）。例如「2010 年投 $100 買 AAPL，2020 值多少？」——CoT 蒸餾的學生遇到換股票代碼（NVDA）時算錯 split 次數，因學生只是背了 AAPL 的推論而非學到「檢索+計算」。

ai_core 關聯：§2 工廠→消費者

本論文直接對應 ai_core §2 的「貴稀有智能＝資產工廠 vs 便宜高頻智能＝資產消費者」 分工：大 LLM（32B）充當「工廠」——生成高品質 agent 軌跡（思考→寫碼→觀察→修正）——然後以知識蒸餾將完整問題解決行為批次灌注進消費級小模型（0.5B–3B），讓便宜的小模型端側也能展現類 agent 的決策—執行動作—工具使用能力。這是 ai_core 願景的核心路徑：把 LLM 的產物（軌跡）轉化成永久的、可重複使用的「agent 行為資產」。

核心方法

  • Agent Distillation（AD）：與 CoT 蒸餾對比——CoT 只蒸餾「想什麼（thoughts）」，AD 蒸餾「想什麼（Thought）→做什麼（Action，Python code）→看到什麼（Observation）」整輪迴圈。損失函數只在 thought + action token 上計算（observations 由環境提供，不計入 loss）。基底框架為 CodeAct（smolagents）。
  • First-Thought Prefix（FTP）：原因——instruction-tuned LLM 用 agent prompt 時，初始推理步驟常比用 CoT prompt 差（分佈偏移）。解法——先用 CoT prompt 生成第一步推理，再把該步當成 prefix 餵進 agent prompt 繼續生成完整軌跡。FTP 僅用於 teacher 生成軌跡，student 推論時不需要。
  • Self-Consistent Action Generation（SAG）：小 agent 推論時常產出無效程式碼（parse error / 執行錯誤）。SAG 每步採樣 N=8 條（高溫 nucleus sampling），用輕量 interpreter 過濾掉報錯的、保留執行成功者、挑出 observation 最一致（多數投票）的作為最終 action；全失敗則取一個錯誤、用 interpreter 回饋供下一步修正。
  • 訓練：teacher=Qwen2.5-32B-Instruct，student=0.5B/1.5B/3B/7B Qwen2.5-Instruct。LoRA rank=64 全線性層，2 epochs。Wikipedia 2018 作 KB，e5-base-v2 embedding。HotPotQA(1000)+MATH(2000) 訓練，過濾錯誤軌跡得約 2000 條訓練軌跡。

關鍵結果（8 基準，in-domain + out-of-domain）

  • 跨規模一致提升：0.5B agent ftp+sag Avg=21.90，勝 CoT 7B (33.54) 尚未，但對比同規模 CoT baseline——0.5B AD 30.55 vs CoT 15.90（+14.65）；1.5B AD 36.60 vs CoT 24.64（+11.96）；3B AD 42.68 vs CoT 32.16（+10.52）。
  • 跨級超越：0.5B agent 平均 30.55 > 1.5B CoT (24.64)；1.5B agent (36.60) > 3B CoT (32.16)；3B agent (42.68) > 7B CoT (33.54)。
  • Out-of-domain 強勢：尤其在 OlymMATH 和 AIME 等困難數學上 agent 大幅領先——0.5B AIME：CoT 0.0→AD(+ftpsag) 3.3；3B OlymMATH：CoT 5.0→AD(+ftpsag) 11.5。
  • FTP 效果：在 MATH500 難度 Level 4–5 和 AIME 上 FTP 顯著提升，但對 HotPotQA 偶有負效（FTP 鼓勵 agent 直接陳述事實而非檢索，增加幻覺風險）。
  • SAG 效果：顯著降低 parse error + execution error，對 0.5B 模型尤為明顯（圖 7）；test-time 自一致優於 CoT 的 self-consistency（圖 5）。
  • Code-specific 模型增益有限（表 3）：Qwen-Coder 做 teacher 學生差別不大——「code knowledge 不是學生瓶頸」。
  • 跨模型家族驗證：Llama-3.2-1B 和 Phi-4-mini 上均一致改善（表 4）。

局限（作者自陳）

  • 僅用 Qwen2.5 系（未測 LLaMA/Gemma）；僅用單一 teacher（32B，未測更大/GPT-4）；未探索每題多軌跡的效應；未觸及 embodied/web agent。FTP 有時內部陳述事實而不檢索，增加幻覺。Agent 蒸餾未直接提升核心推理能力（RL in tool-augmented env 可補充）。程式碼安全（sandbox）仍待解決。

對讀者的價值

  • 這是第一份把 LLM agent 行為蒸餾進 sub-3B 模型的系統性研究，展示「不蒸餾答案、蒸餾行動過程」的可行性。最值得記：Agent Distillation > CoT Distillation 尤其在 out-of-domain；FTP 解決 instruction-tuned LLM 的 agent-prompt 分佈偏移；SAG 是針對小模型程式碼產出脆弱的 test-time 修正；蒸餾後的 token 生成量不顯著增加（圖 6：事實型多用檢索 token，數學型用 for-loop 反而更少 token）。
  • 適合任何關注 small agent、知識蒸餾、tool-augmented LLM、on-device AI 的研究者與工程師。
