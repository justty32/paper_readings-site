論文／訪談原始來源

《符號學習使智能體能夠自我進化（Agent Symbolic Learning）》重點摘要

一句話概括

Agent Symbolic Learning（代理符號學習）：把語言代理視為一張符號網路（prompt、tool、把它們堆疊起來的 pipeline ＝可學習權重），用自然語言模擬連結主義學習的反向傳播與梯度下降——以「語言損失（language loss）→語言梯度（language gradient）→符號優化器」整體地（holistically）聯合優化 prompt + 工具 + pipeline，讓代理被部署到真實環境後仍能從資料/經驗自我進化；在 HotpotQA/MATH/HumanEval 及創意寫作/軟體開發上一致勝過 DSPy 等只優化單一組件的方法。

解決什麼問題

當前語言代理研究是 model-centric / engineering-centric：prompt、工具、pipeline 都要人類專家手工逐一打造與調校，無法像神經網路那樣從資料中自動學習，限制了穩健性與通用性。既有自動優化法（DSPy、GPTSwarm、Agent-Pro、AgentOptimizer）只分別優化孤立組件（單一 prompt 或工具），易陷各組件的局部最優，且多需可用方程/程式定義的數值指標（軟體開發、創意寫作這類真實任務無法）。作者主張：要邁向 AGI，須從 engineering-centric 轉向 data-centric——讓代理能自主學習與進化。

核心方法

  • 核心類比（仿 Hinton 連結主義學習）：代理 pipeline ↔ 神經網路計算圖；node（節點/子任務步驟）↔ 層；node 的 prompt 與工具 ↔ 該層權重；trajectory ↔ 計算圖（存前向傳播的輸入/輸出/prompt/工具使用，供反向傳播）。
  • 四步驟流程：
    1. Forward Pass（前向傳播）：執行代理，把每個 node 的輸入、prompt、工具使用、輸出存進 trajectory。
    2. Language Loss（語言損失）：用精心設計的 prompt 把整條 trajectory 餵給 LLM，產出「自然語言評語 + 數值分數」。可餵 ground-truth（監督式），也可不餵（非監督式）→ 後者正是「自我進化」的關鍵（部署後無標籤也能學）。
    3. Back-propagation（語言梯度反向傳播）：從最後一個 node 倒推到第一個，逐 node 用 LLM 產出「分析與反思」式的 language gradient；每個 node 的梯度同時考量自身子目標與對下一 node 的影響 → 避免孤立組件的局部最優。
    4. Update（符號優化器更新）：三種 symbolic optimizer——PromptOptimizer（分別優化任務描述/few-shot/原則/輸出格式）、ToolOptimizer（決定改/刪/新增工具）、PipelineOptimizer（用「代理程式語言」以 add/delete/move node 的原子操作改 pipeline 結構）。
  • 工程細節：非法更新重試最多 3 次否則丟棄；rollback（更新後若語言損失變差則回退）；每個 prompt 有「learning rate」控制優化激進度；支援 batched training（仿 mini-batch SGD，彙整一批同 node 的語言梯度一起更新，更穩定）。

結果

  • 標準 benchmark（表 1）：在 HotpotQA / MATH / HumanEval 上一致勝過 GPTs、Agents、Agents+AutoPE、DSPy；MATH 增益尤大（GPT-3.5 23.8→38.8）。AutoPE 與 DSPy 不穩（有時改善、有時顯著退步），本法更穩健。
  • 複雜真實任務增益更大：軟體開發平均可執行性分數 GPTs 1.6 / Agents 2.4 / 本法 3.8（滿分 4）；創意寫作 GPT-3.5 達 6.9（vs Agents 4.2、ToT 3.8）、GPT-4 達 7.4——甚至勝過精心設計的 Tree-of-Thoughts。
  • 案例分析：本法能像人類專家般「先 plan、再 write、後 revise」並把各步 prompt 優化得很好，自動重現 MetaGPT 式的標準作業流程——印證在「無 ground-truth、表現無法用方程算」的真實任務上有效。

局限

  • 概念驗證（proof-of-concept）：實驗規模有限；未更新 LLM backbone（蒐集野外資料 fine-tune backbone 留作未來）。
  • 初始化影響大：過度工程化的初始代理反而不穩定 → 建議從最簡代理起讓優化器去學。
  • 多項優化操作須在程式空間進行，靠「重試 + rollback」這種較粗略的策略保證合法性。
  • 呼籲社群建立「以代理學習為評估核心、含多樣複雜真實任務」的 benchmark（現有 accuracy/F1 式 benchmark 反映不出本法在真實任務上更顯著的優勢）。
