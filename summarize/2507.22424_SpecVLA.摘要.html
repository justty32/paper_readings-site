論文／訪談原始來源

Spec-VLA: Speculative Decoding for Vision-Language-Action Models with Relaxed Acceptance 重點摘要

一句話

Spec-VLA 用小型 draft model 先猜多個機器人 action token，再由原本的 VLA 平行驗證；關鍵改動是把「token 必須完全相同」放寬成「離散動作距離在門檻內」，以免物理上近似的動作因編號稍有差異而全部重算。

方法架構

  • 問題：OpenVLA 一類模型以自迴歸方式逐一產生七個控制維度的 action token，大型視覺語言骨幹使每一步解碼都很昂貴。一般 speculative decoding 雖能由小模型起草、大模型一次驗證多個 token，但在 VLA 上直接套用時，draft model 要同時理解影像、文字與動作，首個 token 就常猜不中，嚴格比對所得加速有限。
  • draft 與 verification：作者沿用 Eagle-2 的動態 draft tree。單層 Llama decoder 接收 verification model 的 hidden state、視覺與文字 embedding 及先前 action token，建立多條候選路徑；原 VLA 作為 verification model，在一次 forward pass 中平行檢查。第一個拒絕點之後的候選全部丟棄，所以每輪接受長度直接決定可省下多少解碼。
  • relaxed acceptance：OpenVLA 把連續控制維度離散成 256 個 bin，再映成 action token。Spec-VLA 直接以 bin ID 的絕對差作距離 D(a_i, a_hat_i)；只要距離不大於門檻 r 就接受 draft token，否則改採 verification token。這個判準不用另算 embedding 相似度，額外成本近乎為零。
  • 訓練與測試：verification model 是微調後的 OpenVLA，作者用它重建資料來訓練 draft model；評測涵蓋 LIBERO-Goal、Object、Spatial、Long，每個 suite 含十項任務與 500 筆 expert demonstration，主實驗每項任務跑 50 次（作者自報）。

作者報告的結果

嚴格 speculative decoding 相對自迴歸 baseline 只有 1.08× 至 1.15× 加速；加入 relaxed acceptance 後，接受長度提升 25% 至 44%，整體加速落在 1.22× 至 1.42×（作者自報）。以 LIBERO-Goal 為例，嚴格版平均接受長度 2.04、加速 1.09×、成功率 74.2%；放寬後分別為 2.94、1.42×、74.4%，自迴歸成功率則是 78.0%（作者自報）。這組數字顯示速度收益主要來自放寬判準，而不是只加一個 draft model。

門檻消融顯示，增加容許距離可讓不同資料集的接受長度增加 50% 至 70%；Goal、Object、Spatial 的門檻可從 5 放到 9 而成功率未下降，Long 在超過 5 後則明顯惡化（作者自報）。因此放寬幅度不是通用常數，任務愈難，能容忍的 action token 偏差可能愈小。

接受長度分布也支持同一機制。在 LIBERO-Object，長度四的候選由嚴格版 0.56% 升至放寬版 6.22%；LIBERO-Long 同一長度由 0.50% 升至 3.35%（作者自報）。嚴格相等特別容易截斷較長候選，距離門檻則把一部分功能近似的動作留到後續驗證與執行。

結論與局限

論文證明 speculative execution 可以移植到 VLA，但「語言 token 相等」不是合適的物理動作等價關係。利用既有離散動作空間定義局部容忍區，可在不改 verification model 的情況下換取實際加速。

證據仍局限於 LIBERO 模擬環境，作者沒有做真實機器人實驗；verification model 本身也不支援 action chunking，所以這條常見的 VLA 加速路線未被納入。（以下本檔補註，非作者自陳）更根本的風險是 bin ID 距離只描述單一離散維度的接近程度，不保證跨時間、跨控制維度或接近碰撞邊界時仍具功能等價性。論文以成功率做端到端保護，但尚未建立可轉移的安全界線。

對 ai_core 的價值／接點

Spec-VLA 提供一個很實用的治理問題：確定性 verifier 是否只能接受完全相同的候選？如果系統的輸出空間本來就有可計算的鄰近關係，完全相等可能白白拒絕功能等價結果。ai_core 可借用「便宜提案、權威驗證、容忍區內准入」的三段式介面，但容忍區必須綁定任務風險與可觀察結果，不能只靠表面 token 距離。

另一個接點是門檻治理。LIBERO-Long 與較容易的 suite 能容忍的 r 不同，表示憑證不應只寫「此方法通過」，還要記錄驗證場景、門檻與失效邊界。若把近似等價當成系統級加速手段，這些條件就是憑證的一部分，否則離線成功率中的小偏差，到了接觸或安全關鍵任務可能成為不可接受的動作。
