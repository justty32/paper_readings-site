論文／訪談原始來源

AgentCompile: An LLM-Guided Compiler for Direct CUDA Inference

  • arXiv: 2606.07665
  • 作者: Xuanzhe Li, Ziyan Weng, Zhiyu Zhu, Junhui Hou (CityU HK / CityU HK Dongguan)
  • 分類: I（方向二：AI 輔助系統/編譯器）

核心貢獻

提出 AgentCompile，一個 LLM 引導的 CUDA 推論編譯器框架。關鍵設計原則是：LLM 僅提供諮詢性搜尋元資料（語意標籤、候選優先序、參數提示、風險註解），而可執行行為完全由編譯器確定性控制（模板生成、介面檢查、硬體約束、經驗驗證、效能量測、回退機制）。LLM 不得直接產生或允許任何 CUDA 原始碼。

管線架構（八階段）

  1. 模型捕捉：追蹤 PyTorch/HuggingFace 模型，取得標準化計算圖
  2. 圖分析器：依賴/別名/邊界規則將 IR 分割為候選區域，記錄算子序列、張量介面、歸約軸、記憶體存取模式、動態形狀旗標
  3. 規劃器：枚舉合法融合/排程/記憶體/平行化方案，產生的候選空間 C(r,H) 受模板可用性與硬體約束限定；LLM 僅可在 C(r,H) 內重新排序或建議參數
  4. CUDA 程式碼生成：確定性模板庫覆蓋向量化逐元素核、歸約、softmax、LayerNorm/RMSNorm、tiled GEMM、Tensor-Core GEMM、解碼導向 GEMV
  5. 驗證：編譯檢查、介面檢查、數值比對（含 dtype 容差）、結構/煙霧測試、選擇性記憶體安全工具
  6. 效能量測與選擇：取最快驗證候選；LLM 信心分數從不直接選擇核
  7. 回退：無效或無利區域退回框架/函式庫路徑
  8. 混合執行期：生成核 + 手寫 Triton/C++ 融合核 + FlashAttention/cuBLAS 第三方核

關鍵技術

  • 自訂 GEMV：權重 [N,K] 佈局、256 執行緒區塊、128-bit 向量化載入、warp shuffle 歸約（無 shared memory bank conflict）、雙路徑 adaptive-N 策略
  • 融合執行期核：fused RoPE（Q/K 旋轉嵌入單次 Triton 啟動）、fused residual-RMSNorm（float32 累加）、fused activation-multiply（MLP gating）、C++ 擴展 fused GEMV epilogue（Gate/Up + SiLU/GELU，Down + residual）
  • CUDALinear：替換 PyTorch nn.Linear，預轉置權重，M=1 GEMV 解碼，可退回 cuBLAS
  • FlashKVCacheManager：預分配固定 KV 緩衝、GPU 端追蹤序列長度、匯入 HuggingFace DynamicCache 狀態
  • CUDA Graph 重播：消融實驗中貢獻最大（2.06×），消除重複 Python dispatch 與逐 token 啟動開銷

實驗結果

  • 硬體：NVIDIA A800 SXM4 80GB
  • 模型：Llama-3.2-1B/3B-Instruct, Qwen3-1.7B/4B（float16）
  • 工作負載：輸入 128–40960 tokens，輸出 32–32768 tokens

與 ai_core §3.6 的關聯

AgentCompile 是 LLM 引導編譯＝固化（§3.6）的具體實例：LLM 在編譯器定義的確定性邊界內提供語意指導、排序偏好與風險評估，但候選產生、約束檢查、數值驗證、效能選擇與回退全部由編譯器機制執行。這正是 §3.6 所描述的「將 LLM 推理固化到確定性工程管線中」的模式。

限制

原型僅針對 transformer 推論區域；不支援區域退回框架路徑；LLM 引導是搜尋策略（優化排序/語意假設），不保證最優實現。
