作者：Luca Beurer-Kellner, Marc Fischer, Martin Vechev（ETH Zurich）

日期：2022-12（PLDI 2023）

arXiv：2212.06094

論文／訪談原始來源

《Prompting Is Programming：大型語言模型的查詢語言》重點摘要

一句話概括

LMQL（Language Model Query Language）：提出 Language Model Programming（LMP，語言模型程式設計） 這個範式——把 prompting 從「純文字提示」升級為「文字提示＋輕量腳本＋對輸出的宣告式約束」，並用一套急切（eager）部分求值語意，把使用者的高階約束與控制流編譯成逐 token 的解碼遮罩（decoding mask），在生成過程中即時剪除違反約束的 token，從而在保持或略升準確率的同時把昂貴的 LM 呼叫次數與計費 token 砍掉 26–85%。

解決什麼問題

現代 LM 只在 token 層運作、一次只吐一個子詞，實務上有三大痛點：(1) 互動——meta-prompt、ReAct、工具呼叫等多輪流程需要大量手動來回或人在迴路（HITL）；(2) 約束與 token 表徵——使用者想用「詞／句／實體」層級思考，但 LM 只吃 token，要限制輸出格式得深入 tokenization 與解碼細節、手工實作；(3) 效率與成本——每個生成又丟棄的 token 都是真金白銀（GPU 或按量計費 API）。既有高階 API（HuggingFace generate()、OpenAI）都無法做 token 層驗證。

核心方法

  • LMP 範式 + LMQL 語言：SQL 式宣告元素 + 命令式 Python 腳本。一支 LMQL 程式有 5 部分：decoder（解碼器）／query（含 [HOLE] 生成孔與 {var} 變數回填的 Python 腳本）／from（指定模型）／where（約束）／distribute（可選，對支持集算機率分佈，適合分類）。
  • 急切部分求值語意（§5）：核心是 Final 語意——給每個（子）運算式標註 fin（值已固定）／var（可能再變）／inc（單調遞增）／dec（單調遞減）四種標註子，讓約束可在「序列只生成一半」時就短路判定（如 a∧b 中 a 已 fin(⊥) 即可提早否決）。
  • FollowMap（§5.2）：對「若下一個 token 選 t 會如何」做前瞻近似，據此建構逐 token 遮罩，把「保證違反約束」的 token 遮掉。以 Brzozowski 導數給出健全性（soundness）定理 5.1——遮罩只做安全過近似（over-approximation），絕不誤刪任何仍可能合法的 token；無法急切判定時退回 backtracking（等價於 context-free parsing）。
  • Scripted beam search：beam(n) 在所有生成孔與控制流上聯合做 beam search，是既有 API 難以實作的能力。約束＋遮罩可與 LM 前向計算平行、鎖步（lock-step）執行，不增延遲。

結果

  • 三個案例研究（模型：GPT-J 6B、OPT-30B、gpt2-xl，另有限度測 GPT-3.5 text-davinci-003），基線為 chunk-wise 的 generate()：
    • Chain-of-Thought（Odd One Out / Date Understanding）：model queries −43~45%、計費 token −27~31%，準確率持平或微升；LOC 僅為基線的 26%/34%。
    • 互動式 ReAct（HotpotQA）：decoder calls −80%、計費 token −76%（省 5.2¢/query）；ReAct 只需 18 行 LMQL（比 Python 少 63%）。
    • 算術推理（GSM8K，外接計算器）：decoder calls −85.7%、model queries −66%、計費 token −84.9%（省 6.2¢/query）；18 行 vs 78 行。
  • 三案例一致印證：表達力（少很多程式碼即可重現 SOTA prompting）、效率（token 層即時驗證取代 chunk 解碼＋回溯）、準確率不受損甚至微升。

局限

  • 未做真實 prompt engineer 的使用者研究，作者自承這對「易用性」主張構成有效性威脅。
  • 約束遮罩為健全但不完備：涉及前向引用的約束無法急切遮罩，須退回 backtracking。
  • 需要能接觸模型解碼迴圈的整合權限；OpenAI API 不提供 token 層存取，故 GPT-3.5 只能有限度評測。

對讀者的價值

  • 這是 ai_core §1「prompting is programming」命題的學術奠基之作：它率先把「把 LLM 當作可被程式約束、可被控制流編排的計算節點」形式化，正對應 ai_core「系統像符號神經網路計算圖（多數確定性節點＋少數 LLM）」的世界觀——LMQL 的 [HOLE] 就是圖裡那個「少數 LLM 節點」，而 where/{var}/控制流就是包住它的確定性外殼。
  • 對 ai_core §5「受約束填碼的語言層」 最直接：LMQL 的 where 宣告式約束 + FollowMap 逐 token 遮罩，正是「上層結構化抽取生資產、下層受約束填碼」中「下層填碼」該有的機制原型——把「LLM 只能生成合法輸出」變成語言層保證，而非事後 parse／retry。
  • 成本感知解碼（把約束用來剪 LM 呼叫、直接對應計費 token）呼應 ai_core §3.3 成本梯度：LMQL 示範了「約束不只保正確、還同時省錢」的雙重紅利。
  • 定位：本批 I 類代表，宜與 DSPy（把 prompt 當可優化參數）、SGLang / Outlines（後續的受約束解碼／結構化生成執行期）對照閱讀——LMQL 是這條「宣告式約束 + 成本感知解碼」路線的源頭。適合做 structured generation、constrained decoding、agent 控制流語言、把 LLM 呼叫包成可靠函數 的人。
