論文／訪談原始來源

《CRANE：以受約束的 LLM 生成進行推理（CRANE: Reasoning with Constrained LLM Generation）》重點摘要

一句話概括

CRANE（Constrained Reasoning Augmented Generation，受約束推理增強生成）：先用複雜度理論證明「把 LLM 輸出嚴格約束到『只允許合法最終答案』的限制型文法，會把常數層 LLM 的表達力困死在 TC⁰ 電路類、因而無法容納推理鏈」；再證明只要把輸出文法擴增成 G_a → R G（R 容納中間推理、G 保證最終答案合語法）就能同時保住推理力與語法/語義正確；據此提出一個在推理時不約束、只在輸出最終答案時才約束、靠 <<／>> 之類分隔符動態切換的解碼演算法，在 GSM-Symbolic 與 FOLIO 上比 SOTA 受約束解碼與無約束解碼最多高 10 個百分點。

解決什麼問題

LLM 常需把輸出餵給下游工具（Python 直譯器、邏輯求解器、定理證明器、Wolfram Alpha 的 DSL），這些工具對輸入有嚴格語法/語義要求。受約束解碼（constrained decoding）能把輸出投影到形式文法上保證語法正確，但先前研究（Tam et al. 2024）實測發現：嚴格施加約束反而降低 LLM 的推理能力與功能正確率。兩個開放問題：RQ1 LLM 在受約束解碼下是否真的失去推理力？RQ2 如何既享受約束減少語法錯誤的好處、又保住無約束時的推理力？作者要的是不限於特定模型、對任何 LLM 皆成立的形式化解釋，而非個案實驗觀察。

核心方法

  • 理論一（限制型文法傷推理，Prop 3.1）：對只有有限輸出集的問題（如判定型問題，輸出集 O=L(G_c) 是正則語言），受約束解碼只允許單一自回歸步；而常數層 log-precision LLM 的單步只等價於一個 logspace-uniform 常數深度閾值電路（TC⁰）。故受約束 LLM 只能解 TC⁰ 內的問題——像 NL-complete 的 st-connectivity（有向圖可達性）除非 TC⁰=NL 否則解不了。
  • 理論二（無約束/CoT 保表達力，Lemma 3.2）：任何圖靈機 M，都存在常數層 log-precision LLM 能用 t(n) 個自回歸步模擬 M 的 t(n) 步（即 Chain-of-Thought 式中間步驟大幅提升表達力）。
  • 理論三（擴增文法救回推理，Prop 3.3）：把文法固定成 G_a → R_M G 形式，R_M 是能解析圖靈機所有組態編碼 γ̄ 的規則（一個定義在組態編碼上的正則語言），G 是原輸出文法。則 LLM 可在 G_a 約束下用 t(n) 步模擬 M，輸出 r·M(x)：推理串 r 自由生成、最終答案 M(x)∈L(G)。約束不再免費致命，只要留出推理空間即可。
  • CRANE 演算法：不需要為每個任務造專屬 LLM/文法。作法是判斷性地施加約束——推理階段完全不約束，只在最終答案階段約束。用分隔符 S₁（開始）、S₂（結束）標記受約束視窗（實驗用 <<／>>；也對應常見的 ``` 包程式碼），靠 prompt 與 few-shot 誘導 LLM 生成分隔符。遇 S₁ 進入受約束模式、遇 S₂ 切回無約束（因分隔符可能在中間步驟多次出現）。可搭配任意 LLM、任意受約束解碼器（IterGen、SynCode 等）。

結果

  • GSM-Symbolic（符號數學，表 1，用 IterGen 做約束、Z3 驗功能等價）：CRANE 在 9 個開源模型上一致提升功能正確率。Qwen2.5-Math-7B：CRANE 38% vs 受約束 29% vs CoT 29%；Qwen2.5-1.5B：CRANE 31%（比 CoT 高 5pp、比受約束高 9pp）；DeepSeek-R1-Distill-Llama-8B：CRANE 31% vs 受約束 13% vs CoT 21%。CRANE 生成的運算式零語法錯誤，而 CoT 無約束有約 10% 帶語法錯。
  • FOLIO（一階邏輯推理，表 2，用 SynCode + Prover9 文法/求解器）：Qwen2.5-7B：CRANE 42.36% vs 受約束 37.44% vs CoT 36.95%；Llama-3.1-8B：CRANE 46.31% vs 受約束 39.41% vs CoT 32.02%。CRANE 在所有模型上皆勝過無約束與受約束基線。
  • Token 開銷與 CoT 相近（CRANE 保留推理鏈），遠高於純受約束（純約束會壓縮輸出但傷準確率）。

局限

  • Prop 3.1 只證明「當 L(G_c) 為有限語言」時表達力下降；能否推廣到 L(G) 無限的文法仍開放。
  • CRANE 依賴需存取輸出 logits 的受約束解碼工具（如 IterGen/SynCode），對不開放 logits 的封閉模型不適用。

對讀者的價值

  • 對 ai_core §5「受約束填碼」是一記重要警示：你把「程式碼助手」的下層設計成「上層結構化抽取生資產、下層受約束填碼」，很自然會想用嚴格文法把 LLM 鎖死在合法輸出上。本文從複雜度理論證明約束不是免費的——過嚴的文法會把 LLM 表達力困在 TC⁰、直接損害推理，讓它連本來（無約束/CoT）能解的問題都解不了。這補上已入庫 Outlines/SynCode/GCD 那批（純講「如何高效施加語法約束」）的理論盲點。
  • 正面解法可直接搬進 ai_core 的受約束填碼設計：不要從第一個 token 就約束，而是「推理時放開、只在填最終結構化答案時才約束」，並用分隔符（``` / <<>>）動態界定約束視窗——即「擴增文法 G_a→R G 留出推理空間」的工程版。這既守住 §5 下層要的語法/語義正確（生成的東西一定能被下游求解器解析、餵得進確定性節點），又不犧牲貴稀有智能（§2）該有的推理力。
  • 定位：理論（複雜度證明）＋演算法＋實證三合一，歸 I 類。適合做 constrained decoding、structured generation、把 LLM 接邏輯/數學求解器、以及在符號神經計算圖（§1）中設計「LLM 節點如何安全地把輸出交給確定性節點」的人。
