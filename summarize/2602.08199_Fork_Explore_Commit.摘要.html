論文／訪談原始來源

Fork, Explore, Commit：給 Agent 探索用的 OS 原語

一句話結論

本文提出 branch context，把多個 agent 候選路徑包成具有獨立 copy-on-write 檔案視圖、process group、first-commit-wins 與巢狀分支的 OS 抽象。實作完成的是約 3,400 行 Rust 的 FUSE 檔案系統 BranchFS；branch() syscall 與完整 process/memory isolation 仍只是設計提案，因此論文題目所暗示的「filesystem + process state 原子 commit/rollback」目前只被部分實現與評估。

為何需要 branch context

agentic exploration 會同時跑多條解法，最後只保留成功者。每條路徑可能改檔、安裝套件、產生 build artifact、啟動 compiler/test runner。git stash、臨時目錄或 container clone 不是太慢，就是只涵蓋部分狀態；per-file snapshot 也捕捉不到 shell command 造成的所有變更。

作者歸納六項需求：平行隔離；單一贏家與原子 commit；支援樹狀探索的 nesting；捕捉完整 filesystem mutation；低成本、免 root、跨 underlying filesystem；以及可靠 process coordination。現有 OverlayFS、Btrfs/ZFS、device mapper、VM snapshot、cgroup、PID namespace 各自只解一部分，使用者態拼裝還會留下設定順序與 race window。

抽象與實作

每組 N 個 sibling branch 從 frozen origin 原子建立。每個 branch context 含 origin 上方的一層 CoW delta 與一組 process。探索期間兄弟分支彼此不可見；第一個 commit 者把 delta 提升到 parent，其餘 sibling 立即 invalid；abort 只丟棄 delta。branch 可以再 fork 子 branch，子層先 commit 到直接 parent。

BranchFS 以 file-level CoW 實作：第一次寫入時把整個檔案複製到 delta，讀取沿 current branch、ancestors、base 查找；刪除以 tombstone 表示。commit 先套刪除、再複製修改檔，接著提升 parent epoch 使 siblings 失效；invalid/aborted branch 的 mmap 觸發 SIGBUS。父狀態在 branches 存活期間 read-only，因而以禁止 parent concurrent write 迴避 merge conflict。

配套 Python BranchContext library 提供七種模式：Speculate、BestOfN、Reflexion、TreeOfThoughts、BeamSearch、Tournament、Cascaded。standalone BranchFS 以 mount namespace 與 bind mount 隔離各 agent，但 library 的 process isolation 仍使用 fork(2)、timeout 與 resource limit，沒有論文所設想的 kernel 保證。

branch() syscall 擬提供 BR_CREATE/COMMIT/ABORT，以 BR_FS、BR_MEMORY、BR_ISOLATE、BR_CLOSE_FDS flags 組合 filesystem、memory、signal/ptrace 與 fd 行為，並透過三個通用 filesystem ioctls 連接 BranchFS。其價值主張是把 cgroup、PID/mount namespace、branch 建立與 signal barrier 原子組合，消除 userspace 多步設定的 race；但作者尚未實作，預定 Linux 6.19 才開始 prototype。

初步評估

只評估 BranchFS，沒有評估 branch() syscall、process isolation、nested exploration 的端到端 agent 效果或 first-commit race。環境是 Ryzen 5 5500U、8 GB RAM、240 GB NVMe、Pop!_OS 22.04、Linux 6.17；每個數字為 10 次 median。

  • base 100/1,000/10,000 files 時，branch creation 為 292/317/310 μs。資料支持在此範圍內與 base file count 無關，但三個點不足以嚴格證明漸近 O(1)。
  • 修改 1 KB/100 KB/1 MB 時，commit 為 317/514/2,100 μs；abort 為 315/365/890 μs。「small changes under 1 ms」只適用前兩列，1 MB 已是 2.1 ms。
  • 對 50 MB file、64 KB blocks，native read/write 為 8,800/576 MB/s；regular FUSE 為 1,655/631；FUSE passthrough 為 7,236/719。regular FUSE read 只有 native 19%，passthrough 約 82%。
  • BranchFS write 看似快過 native，並非底層更高效，而是 ephemeral branch 將 fsync 視為 no-op、把 durability 延至 commit；比較的耐久語義並不等價。

作者認為 agent workload 通常受 100 ms–10 s LLM API latency 支配，因此這些 filesystem 開銷可接受。這是合理的系統直覺，卻沒有以實際 SWE agent workload 或並行 branch 數量實證。

關鍵限制與風險

  • 現有 prototype 只隔離 filesystem。network、IPC、device I/O 等外部副作用不會在 abort 回滾；完整方案仍需 output/effect gating。
  • branch() 完全是 design proposal；可靠 termination、kernel-enforced sibling isolation、memory branching、PID preservation 都沒有實作數據。
  • first-commit-wins 只能保留一個 branch，無法合併多個互補成果，也不能處理檔案衝突或 semantic merge。
  • file-level CoW 對大檔首次寫入成本高；絕對路徑 symlink 可逃到未分支檔案，hardlink 在 CoW 後失去 link 關係；delta 不支援 FIFO、socket、device node。
  • frozen parent 是強約束：它確實消除 merge conflict，但也阻止 parent 在探索期間正常演進。宣稱「atomic commit」主要是相對於被凍結 parent 的受控模型。
  • fsync no-op 讓 crash durability 的語義需要更仔細驗證。論文未報 daemon crash、電源中斷、partial copy 或 commit recovery 測試。

證據成熟度

這是一篇 ASPLOS 2026 Agentic OS Workshop paper，BranchFS 已開源且有微基準，概念與 interface 清楚；但 sample 小、只報 median，缺乏 variance、併發壓力、故障注入與真實 agent benchmark。最關鍵的 process half 尚未存在。適合視為有可運行 filesystem artifact 的早期 OS proposal，不宜把整套 branch context 當成已驗證的 production primitive。
