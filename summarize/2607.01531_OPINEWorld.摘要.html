論文／訪談原始來源

《OPINE-World》重點摘要

一句話概括

OPINE-World 將 ARC-AGI-3 的「看不出物件詞彙、目標和動作意義」拆為 acting 與 modeling 兩個 LLM 工作：前者探測與執行，後者將假說做成按物件型別分解的程式；只有逐筆 replay 完全一致才接受，並用 Bayesian ontology error 決定下一步該釐清哪種物件。

方法

世界模型是 object-centric 的 factored program：每一物件 type 有局部條件與 effect，匹配後對每個物件套用並組合，而不是把整個畫面塞入單一轉移函式。這使一筆反例可只修一個 type，也能顯示「目前 type 詞彙不夠」而非錯誤地調整全域規則。

acting agent 維護自然語言工作模型，提出 mechanics／goal 假說、挑選能區分假說的探測；synthesizer 把它寫成程式，critic 尋找過度擬合。候選須精確重現所有 buffered transition。live model 若預測失敗，反例會回到 buffer；短暫延遲累積證據，連續兩次修訂未提高 transition accuracy 則暫停，等待新反例。planner 只在已驗過的模型上做有限前向搜尋，且每一步都和 live environment 比對。

ontology error 是按物件型別計算的 Bayesian adequacy 診斷：觀察到的 effect signature 若無法由目前 type 規則解釋，該型別的 error 上升。它將探索從「多試幾次」改成「優先取得能判定型別／規則是否缺漏的資料」。

結果與正確讀法

公開 25 遊戲的 live、on-policy 評估中，OPINE-World 報 78.4 action-efficiency、解 20/25；baseline1 為 63.8、14/25。兩者同時解出的 13 個遊戲，動作總量幾乎相同（OPINE 少 6 個、baseline 少 7 個）；差距主要在六個 baseline 完全失敗的難遊戲：baseline 花 10,874 動作仍失敗，OPINE 全解且用 2,578 動作。作者使用 Claude Opus 4.8，baseline1 用 GPT-5.5，這不是同底座的控制比較。

worldcoder 和文中列的 latent world model 在該預算下皆未解任何遊戲；Vision 雖可作參考，卻先離線玩過同一批公開遊戲，因此不屬「未針對該遊戲訓練」的比較。

工程啟發與限制

此文最具體的界線是：模型接受條件是歷史轉移完全 replay，不是 LLM 自評；規劃另有 live step validation。它沒有元件級 ablation，理由是系統互依太高，故不能把 20/25 的提升歸因於 ontology error 或雙 agent 任一項。現有實作仍假定 structured state；隨機、部分可觀測、raw pixel 感知皆留待未來工作。
