Object-Centric Environment Modeling for Agentic Tasks 重點摘要

一句話

OCM 把 agent 經驗分成共享的 Python 物件模型與必須引用該模型的程序知識；每次更新都執行全部程序，將「記憶」變成可稽核的相容性契約。

問題與主張

自由文字記憶會累積重複、過期與互相矛盾的敘述；單一技能又缺少它依賴的物件、狀態與前置條件。作者主張，介於孤立技能與完整世界轉移模型之間的物件中心程式碼層，可讓經驗持續累積而仍能檢查。

方法

  • Object knowledge：一個 Python module，類別、屬性與方法表達環境實體、affordance、限制、關係與機制。
  • Procedure knowledge：多個窄責任 Python 檔，記錄可重用規則、失敗型態或工作流程；每檔都必須 import 並使用 object knowledge，不能只是軌跡重播或完整控制器。
  • episode 後先做 reflection，產生應新增／修改的物件與程序計畫，必要時讀取舊原碼；再產生候選程式碼。新的 object module 編譯後，所有程序都須可在它上面執行，否則把錯誤回饋給更新模型而不提交。
  • 推論時只先給類別／函式 signature 與程序索引；agent 可在內部 inspection 預算內按需展開原碼，避免所有累積知識塞入 prompt。

作者報告的實驗

作者在 ScienceWorld、ALFWorld、PlanCraft 評估，報告 OCM 在比較方法中平均排名最佳、且 invalid actions 較少。這些是論文作者的實驗報告，不表示語意正確性已被驗證：執行測試只保證程序仍可對更新後的物件模型執行。

局限與可落地檢查

  • executable 不等於正確；錯誤但介面相容的物件模型仍能通過。
  • 原文未把 schema migration、測試覆蓋、並行編輯衝突做成完整解法。
  • 小型原型應把「全程序可載入」升級成：固定 regression fixtures、版本化 schema、失敗更新不覆寫前一版，以及每則程序列出依賴 symbol。
