論文／訪談原始來源

《SkillRise》重點摘要

一句話概括

SkillRise 讓同一個 policy 在相關但不同的任務序列中輪流解題、改寫一份唯一的文字 skill document；解題拿當題 reward，整理技能則拿後續任務的折扣 reward，將「會做」和「留下的規則對下一題有用」分開給 credit。

核心設計

系統依環境 family metadata 把不同 instance 排成由易到難的序列。第 i 題先以舊文件解題，得到軌跡與 reward；除最後一題外，同一 policy 再根據舊文件、軌跡和結果重寫完整文件。早期軌跡不直接帶到下一題，文件是唯一跨題通道，因此後面表現能檢驗它是否真的傳遞了可重用資訊。

credit assignment 是本文的關鍵：solve phase 只接受本題 r_i；curate phase 接受後續 reward 的折扣和。分組 advantage 也依 sequence position 與 phase 分開，避免拿「解題本身很好」錯當成「文件整理很有轉移力」。

原文實驗結果

作者以 Qwen3-1.7/4B，在 ALFWorld、WebShop、ScienceWorld 各 128 held-out instances 上比較 prompting、一般 agentic RL、同題重試的 LaMer。SkillRise Pass@1 分別為 85.9%、84.4%、54.6%，作者稱較最強 baseline GiGPO 高 2.3、7.1、8.5 個百分點。

在同題帶文件重試的 Pass@3，分別為 92.2%、96.1%、61.0%。在 ALFWorld 的跨題測試序列從 K=2 加到 K=6，作者報告 83.6% 上升至 87.5%，每題僅嘗試一次；這支持但不能單獨證明文件促成跨題 transfer。與兩個多階段 skill pipeline 的比較中，作者報告同 GPU 下 SkillRise 達相近或更高效能，運行時間為其 1/6 或約 1/4.3。

可帶走的設計

技能庫不能只以寫入當下的成敗評分。至少要保留「哪一份文件在後續哪些任務被使用、帶來何種增減」的可歸因鏈，否則 extraction、retrieval、execution 混在一起，無從知道該刪、留或修哪條技能。本文的 skill artifact 是自由文字，不提供型別、前後條件、衝突處理或執行驗證。

局限

相關 task family 由既有 metadata 給定，尚不能在開放任務流自行發現；最大模型僅 4B，且全是文字 benchmark 與可驗證 outcome。表中數字是作者報告，未構成獨立再現。完整原文逐節精要見下檔。
