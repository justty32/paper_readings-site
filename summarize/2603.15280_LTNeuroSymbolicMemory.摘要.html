論文／訪談原始來源

《NS-Mem：以長期神經符號記憶推進多模態 Agent 推理》重點摘要

一句話概括

在向量檢索之上疊加一套確定性的符號規則層——將觀測影片中的動作序列自動抽取為 Procedural DAG（有向無環圖），使 Agent 不僅能「找相似」還能「沿著步驟推理」，從而解答純向量記憶無法處理的約束性問題（例如「碗破了」、「附近有店」→正確判斷下一步該做什麼）。

核心貢獻

  1. 三層記憶架構：Episodic Layer（時間戳事件，S1 直覺記憶）→ Semantic Layer（抽象實體屬性，以 entity anchor 做實體對齊，採 reinforcement 政策避免重複節點）→ Logic Layer（S2 確定性推理層，為本系統核心貢獻：每個 Logic Node 以一對 Index Vectors 做神經發現 + 以 Procedural DAG 做符號查詢——相當於為每道流程同時建立「神經索引卡」和「結構化步驟圖」）。

  2. SK-Gen 自動固化機制：從多模態視訊串流中自動萃取程序性知識——透過 PrefixSpan 順序模式挖掘發現頻繁動作序列，LLM 驗證其是否構成可重用的完整知識，通過後建構 DAG 並計算雙層 Index Vectors。這是整個框架的關鍵：把 LLM 從「每次推理都要從頭推論步驟」中解放出來，改為預先將觀測凝結成確定性 DAG。

  3. 混合檢索與符號增強推理：查詢先分類為 factual/constraint/character 三型，以不同權重決定檢索優先層；檢索到 Logic Node 後，直接在 DAG 上執行三個確定性符號函數——getProcedureWithEvidence（返回步驟圖 + 原始證據）、queryStepSequence（枚舉滿足約束的所有路徑）、aggregateCharacterBehaviors（跨流程聚合人物行為）——確保可重現答案。

  4. 增量維護（EMA + 轉移統計）：新觀測匹配到現有 Logic Node 後，以指數移動平均（β=0.9）更新 Index Vectors 防止語義漂移，同步以計數式 transition statistics 更新 DAG 邊權重，支援 Procedure DAG 從單路徑演進為多路徑（knowledge fusion）——避免重建，支援開放世界。

  5. 實驗驗證：M3-Bench-robot（+4.0%）與 M3-Bench-web（+4.7%）上全面超越純向量記憶的 M3-Agent，其中 constrained reasoning queries 相對提升高達 +12.5%；檢索回合數與時間均下降（Robot -15.8% rounds），驗證了符號層的確定性查詢取代多次迭代檢索的效率紅利。

對讀者的價值（與 ai_core 的接點）

本論文對 ai_core 最直接的價值落在 §3.6 固化引擎（長期神經符號記憶）：

  • SK-Gen 就是固化引擎的流程級參考實現：它展示了如何從連續觀測串流中自動識別「這是一道可重用的程序」、建立符號結構（DAG）、並在後續觀測中增量維護——對應固化引擎核心問題「何時該固化、如何避免庫爆量」。NS-Mem 的三階段門檻（PrefixSpan support → LLM verification score → gating threshold δ）構成了一個多層過濾的固化決策鏈：先是統計頻率說「這模式夠穩」，再是 LLM 驗證說「這確是完整知識」，最後是相似度門檻說「新觀測匹配既有節點才更新、不匹配先暫存候選池」——避免每個新觀測都長出新 Logic Node。
  • Procedural DAG 的 transition statistics 對應固化引擎的「可版本化知識單元」：邊權重隨觀測累積收斂至真值（定理 1 後驗一致性保證），讓固化後的程序不僅是靜態步驟清單，而是帶有執行機率分布的「活的流程模型」——哪條路徑最常見、備選路徑有哪些，全部可審計。
  • 與庫內既有脈絡對照：2305.16291（Voyager 技能庫）固化 Agent 自身的程式碼技能；2605.17596（NeuSymMS）固化使用者面向的符號化事實；本作 NS-Mem 補充了第三條——固化環境中的程序性知識（how-to 流程）——程式碼固化（DreamCoder）+ 技能固化（Voyager）+ 使用者事實固化（NeuSymMS）+ 程序知識固化（NS-Mem），四條線構成 ai_core §3.6 的完整圖景。
  • Procedural DAG + 符號函數的設計對固化引擎的「確定性推理出口」有直接借鑑意義：固化後的知識不該只是被檢索出來餵給 LLM，而應該是 LLM 可以呼叫的確定性函數——queryStepSequence(self, goal, constraints) 就是固化知識作為 API 的典範。
