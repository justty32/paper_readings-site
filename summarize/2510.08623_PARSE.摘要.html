論文／訪談原始來源

《PARSE：LLM 驅動的結構描述優化以實現可靠實體抽取》重點摘要

一句話概括

PARSE（Parameter Automated Refinement and Schema Extraction）：不再把 JSON schema 當成「給人類開發者用的靜態合約」硬逼 LLM 遵守，而是把 schema 本身視為一種自然語言理解合約、交給 LLM 自動優化——用 ARCHITECT 離線把 schema 改寫成「利於 LLM 消費」的版本（並用子模組 RELAY 自動產出 Python 轉換碼保持對舊系統的向後相容），再用 SCOPE 以反思式（reflection）＋靜態與 LLM 雙重護欄（guardrail）做可靠抽取；把「結構化抽取」重新框定為 schema 設計與抽取機制的共同優化（co-optimization）問題，在 SWDE 上抽取準確率最高提升 64.7%，並在首次重試內把抽取錯誤減少 92%。

解決什麼問題

在 Software 3.0（LLM agent 自主呼叫 API／工具）情境下，可靠的結構化抽取是任務成敗關鍵。但現有 JSON schema 是為人類開發者與靜態系統設計的合約，常有描述含糊、驗證規則不全、為人類可讀性而非機器理解而做的結構選擇；LLM 用這些「以人為中心」的 schema 抽取時，會遇到實體邊界不清、需求衝突、欄位關係缺乏上下文，導致頻繁幻覺與不遵守 schema（GPT-4 在複雜抽取上有 11.97% 無效回應率）。既有工作只從約束解碼（constraint decoding）、強化學習、自我修正去「強迫 LLM 遵守既有 schema」，把 schema 當不可變合約，只顧語法有效性，而不去優化結構本身以利 LLM 理解。

核心方法

  • 兩階段設計：Build Phase（ARCHITECT 一次性優化 schema）＋ Extract Phase（SCOPE 以優化後 schema 抽取，再經 RELAY 映射回原 schema）。二者形成良性循環：好 schema 提升抽取，抽取錯誤又回饋改進 schema。
  • ARCHITECT（自動 schema 優化）：把問題形式化為 S* = argmax P(S', D_synthetic, M_llm)（在合成驗證資料上使抽取效能最大化的 schema）。做法：分析原 schema→產生更清晰描述／結構／驗證規則的版本→用合成對抗測試資料（由當前 schema＋種子真實樣本生成）評估→迭代 Refine，達準確率門檻 τ 或最大迭代 K 停止。多在前 5-6 次迭代收斂，過久會過擬合。
  • RELAY（Reverse Engineering Layer for Automated Yoking）：ARCHITECT 子模組，自動產生並驗證 Python 轉換碼，把優化 schema 的輸出映射回原始 schema 格式，靠「產樣本對→測試→迭代」確保語意保存，讓下游系統無痛沿用舊格式。
  • SCOPE（反思式抽取＋護欄）：三階段驗證——(1) 缺漏屬性檢查、(2) grounding 驗證（抽出值必須能在原文找到）、(3) 規則遵循檢查（pattern／長度／enum／日期格式等）。每階段回傳 pass/fail 與錯誤細節；失敗時產生結構化反思引導 agent 修正，而非單純重試重問。

結果

  • SWDE 增益最大：原始 schema 下 baseline 僅約 19-26% 準確率；PARSE（ARCHITECT schema＋SCOPE）各模型達 86-93%（Claude 3.7 Sonnet 24.5→93.14），最高提升 64.7%。
  • 跨資料集穩定：Retail-Conv、SGD、SWDE 三資料集、五模型（Claude 3.5/3.7 Sonnet、3.5 Haiku、Llama 4-Maverick、DeepSeek-R1）上組合框架平均提升可達 10%，ARCHITECT+SCOPE 一致最強。
  • 可靠性：SCOPE 相比單純失敗重問，首次重試內減少抽取錯誤 92%；ARCHITECT 優化過的 schema 更少需要重試。
  • schema 修改樣態：結構重組 55%、實體描述強化 34%、pattern 規則 3%、驗證規則 0.08%。schema 具模型無關遷移性（用 Claude 優化的 schema 套 Llama 仍受益）。
  • 成本：SCOPE 因反思平均增 10.16s 延遲，但 ARCHITECT schema 可減少約 4.05s（少幾輪反思）。

局限

  • ARCHITECT 迭代優化對屬性眾多的複雜 schema 計算昂貴（每輪都要合成資料＋評估＋失敗分析），大規模部署有擴展瓶頸。
  • 優化品質高度依賴種子資料集的可得性與代表性；全新領域或快速演變的 schema 難有足量高品質種子。
  • 假設 schema 相對靜態、可離線優化，對持續演變的 schema 較吃力。
  • 目前僅限文字；多模態（文字＋視覺）抽取需擴充驗證框架處理跨模態 grounding。

對讀者的價值

  • 對 ai_core §5 第一目標「程式碼助手」的上層「結構化抽取生資產」最直接：程式碼助手上層要把使用者的自然語言意圖抽成可靠的結構化規格，PARSE 正是「把非結構化文字轉成可信結構化資產」的成套機制——與 §5 下層「受約束填碼」互補，二者可拼成完整程式碼助手管線。
  • 三個可搬用的設計原語：(1) ARCHITECT＝把 schema 當可優化介面（而非固定合約），呼應「貴稀有智能做一次性優化、便宜高頻智能反覆消費」的資產工廠 vs 消費者觀（§2）——schema 優化是一次性 Build，抽取是高頻 Extract；(2) SCOPE 的 grounding／規則護欄＋結構化反思＝把「可靠函數」的驗證與自我修正落到結構化抽取上，正是「把 LLM 呼叫包成可靠函數」（北極星）的具體樣板；(3) RELAY 自動生成確定性轉換碼＝「把 LLM 反覆處理的映射結晶成確定性程式碼」，直接呼應 §3.6 固化引擎的精神（雖只做 schema 映射這一小塊，卻是可運行範例）。
