論文／訪談原始來源

《從工具呼叫到符號思考：置身持久 Lisp 元編程迴圈中的 LLM》重點摘要

⚠️ 本文為概念性框架（conceptual framework），作者於首頁腳註明言：旨在指引未來實作，而非報告實驗結果。全篇無實作、無 benchmark、無實證數據，只有架構設計與原則。

一句話概括

把 LLM 接上一個持久、互動的 Common Lisp REPL（SBCL）：模型在生成串流中直接吐出 <lisp>...</lisp> 程式碼區塊，由一層串流感知中介層（middleware）攔截、送進 REPL 求值、再把結果回注生成串流；因為 REPL 狀態跨對話回合持久保存，模型能定義、呼叫並演化自己的工具（函式／巨集／DSL），從「呼叫固定 API 的工具使用者」升級為「在活體符號環境裡自建工具、自省、自我延伸的元編程者」——把工具呼叫（tool calling）轉化為符號思考（symbolic thinking）。

解決什麼問題

當前 LLM 的工具使用建立在預定義、靜態的 API／工具集／檢索管線之上：工具由人類事先寫好、彼此孤立、呼叫完即消失（ephemeral），模型無法建構或演化自己的工具環境。作者主張把 Lisp REPL 當成模型的持久編程與推理環境，讓工具能累積成長、狀態能跨回合保存，突破固定工具箱的天花板。

核心架構（三組件）

  • ① 語言模型後端（LM Backend）：處理輸入、生成回應；可在自然語言輸出中內嵌 <lisp>...</lisp> 標籤包住的 Lisp 程式碼。支援本地（Ollama）或遠端（OpenAI GPT）。
  • ② 中介層（Middleware Layer）：一個串流感知代理（stream-aware proxy），攔截模型逐 token 的輸出。流程＝偵測到 <lisp> 區塊 → 暫停生成 → 抽出程式碼送 REPL → 捕捉求值結果 → 把結果回注串流 → 恢復生成，讓結果「彷彿本來就是模型輸出的一部分」無縫接續。
  • ③ 持久 Lisp REPL：通常用 SBCL（Steel Bank Common Lisp），跨對話回合保存長期程式狀態——函式／變數／巨集定義持續存活，並支援內省（introspection）與動態重定義。

核心機制

  1. 動態工具創建＋狀態持久：Lisp 定義在同一 REPL session 內跨呼叫持久（不像一般 function call 用完即棄），可累積出一個「不斷成長的函式／巨集／工具庫」，隨對話推進支援越來越複雜的行為。
  2. 反射式編程（reflective programming）：靠 Lisp 的內省設計，模型能動態檢視當前環境——查詢可用函式、檢查原始碼、即時重定義程序——形成「自我覺察的生成流」：不只寫程式，還能推理自己所寫程式的結構與行為。
  3. 巨集元編程（metaprogramming via macros）：善用 Lisp 強大的巨集系統與高階函式，模型可自定義 DSL 或控制結構來貼合任務。
  4. 生成式自我延伸（generative self-extension）（推測性）：模型或可利用 Lisp「修改自身結構與行為」的能力，建構生成管線、可重用常式或包裝器，來為自己的推理搭鷹架。

為何選 Lisp（尤其 Common Lisp）

  • 同像性（homoiconicity）：程式碼與資料統一表示，天然契合 LLM 生成與操作程式的能力，是元編程的根基。
  • 極簡一致語法：降低 token 預測的計算負擔。
  • 符號 AI 血統：長年是符號 AI 核心，累積大量系統、慣用法與文獻。
  • 可延展性：巨集、一等符號、動態重定義讓模型能演化語言本身。
  • 選 Common Lisp 而非 Scheme：因其豐富標準庫、強大物件系統（CLOS）、進階錯誤處理（condition system）、能做完整語言擴充的巨集，以及支援增量與持續互動的 REPL、支撐「持久、可適應代理」的執行期修改能力。

與既有做法的對照

  • vs 標準 function calling：傳統是孤立、不持久的函式呼叫；本架構維持有狀態工具與環境累積演化。
  • vs ReAct／代理框架：可作為代理框架內的一層，支援把複雜任務委派給 Lisp 子程序、或協調多代理。
  • ⚠️ 本文未明確引用或對照 MCP（Model Context Protocol），也未對 ReAct 做細部 benchmark（因為根本沒有實驗）。

應用場景

科學計算（符號代數／解方程）、互動式編程助手（session 中增量建工具箱）、代理框架（任務委派與多代理協調）、自然語言到邏輯的翻譯（動態建構把 NL 指令轉可執行碼的直譯器）；以及作為 RL 的符號接地環境——活體可編程環境讓模型能測試假設、除錯邏輯、迭代精煉策略。

局限與安全

  • 最大限制＝純概念、零實證：無 POC、無實作細節、無評測。
  • 安全風險：讓 LLM 在活體環境執行任意程式碼，有不安全操作（系統存取、敏感資源操縱）之虞。
  • 緩解建議：隔離執行環境（sandbox 容器）、精挑執行期可用函式、監控與存取控制；並坦承未來須處理對抗性穩健、逃逸嘗試、資源耗盡等問題。
  • 未來工作：先做三組件 POC（串流中介＋持久 SBCL＋sandbox）評估工具跨回合的持久性與可靠度；再優化低延遲、建混合符號-神經推理 benchmark、研究自我修改／遞迴生成碼的湧現行為、擴展到 Lisp 以外語言、多代理共享符號工作區、工具生成與重用的元學習。

對讀者的價值

  • 定位：願景／架構設計論文（cs.PL），單一作者、非同儕評審的概念稿。與 I 類 2508.00604（自主智能可組合 OS 核心架構）同屬「為 agent 打底層執行環境」的設計論文，但本文更聚焦「以持久 Lisp REPL 當 agent 的可演化工具環境」這一具體提案。
  • 最值得記：<lisp>...</lisp> 內嵌＋串流攔截＋結果回注的中介層協定、REPL 狀態跨回合持久帶來的「工具庫累積演化」、以及以同像性／巨集把工具呼叫升級為元編程式符號思考的核心論點。
