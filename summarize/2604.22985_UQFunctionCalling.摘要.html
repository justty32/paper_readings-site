Uncertainty Quantification for LLM Function-Calling — 摘要

一句話概括

首個針對 LLM function-calling 場景的不確定性量化（UQ）基準評測：發現簡單的單樣本方法（G-NLL）在多數任務上不輸甚至優於多樣本語意熵（Semantic Entropy），並提出基於 AST 分群與語意關鍵 token 的 FC 特化改進，使 UQ 作為意圖→工具執行的可靠性閘門更精準。

核心貢獻

  1. 首個 FC-UQ 基準：基於 BFCL 資料集，涵蓋 Simple / Multiple / Parallel / Parallel-Multiple / Irrelevance 五種任務與八個 LLM，以 AUROC 評估 UQ 方法區分正確/錯誤 function call 的能力。

  2. 多樣本不贏單樣本：在 FC 場景中 Semantic Entropy ／ DSE 等需要多次採樣的方法，相較於 G-NLL（greedy 解碼的 token 負 log 機率之和）並無明顯優勢（甚至略差），與自然語言 QA 結論相反。原因是 FC 輸出 token 機率極高（平均 0.97 vs NL 的 0.71），語意簇數量少（3.4 vs 6.4），多樣本無法提供額外鑑別力。

  3. FC 特化的 UQ 改進：

    • 多樣本：以 AST 比對取代 exact string matching 做聚類（SE_AST / DSE_AST），效能小幅提升但仍不超越單樣本。
    • 單樣本：定義語意關鍵 token（Semantically Meaningful Tokens, SMT）——排除語法強制 token（如 =["），僅保留決定函數選擇、參數選擇、參數值、呼叫數量的 token，使 G-NLL_SMT / MAX_SMT / AVG_SMT 校準度與 AUROC 均有提升。

  4. 校準分析：MAX 校準最佳；G-NLL 傾向 underconfident（token 機率連乘）；SMT 同時改善校準（smECE 從 0.147 → 0.091）。

對讀者的價值（與 ai_core 的接點）

ai_core §3.4 憑證層：function-calling UQ 即意圖→工具的可靠性閘門

本論文直接提供 ai_core §3.4「憑證管理」所需的決定性閘門機制：當 agent 產生 function call 時，UQ 分數回答「這個呼叫正確的機率有多高」。實務上可在執行前設定閾值——若 G-NLL_SMT 不確定性過高則拒絕執行或轉交人類。論文 Table 3/risk-coverage 曲線顯示：拒絕 30% 最高不確定性的呼叫後，Simple 準確率從 <92% 提升至 96%，Parallel-Multiple 從 79% 升至 86%。這正是 §3.4 中「憑證與權限核發前必須驗證意圖可靠性」的量化實作。

ai_core §5 工具層：工具呼叫的確定性把關

本論文證實 FC 輸出的特殊性（高 token 機率、低語意多樣性）使簡單的 logit-based 方法已足夠有效，不需昂貴的多樣本推論。這與 ai_core §5 的設計方向一致——工具呼叫模組應內建輕量 UQ，在每次函數執行前做低延遲的把關，避免 irreversible actions（金流、資料刪除）。論文提出的 SMT 萃取演算法（基於輸出格式的輕量規則）可直接嵌入 §5 的工具代理層。
