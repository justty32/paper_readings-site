論文／訪談原始來源

《LLM 當 ASP 程式設計師：自我修正解鎖任務無關的非單調推理》重點摘要

一句話概括

LLM+ASP：讓 LLM 把自然語言翻成 Answer Set Programming（ASP，基於穩定模型語意的非單調邏輯），再用 ASP 求解器（clingo）的結構化錯誤回饋驅動自動自我修正迴圈迭代修程式——完全不需逐任務的人工知識模組、領域 prompt 或 few-shot，一套框架橫跨六個多樣基準。三大發現：(1) 穩定模型語意天然表達「預設規則＋例外」，在非單調任務上大勝 SMT；(2) 迭代自我修正是效能主因（從 54.6% → 78.0%）；(3) 精簡參考指南勝過冗長文件，揭露「context rot（脈絡腐爛）」現象。

解決什麼問題

推理型 LLM（o 系列、R1 等）雖能生成「思考 token」自我反思，但計算成本高、超過某複雜度門檻效能急跌、思考與最終答案常邏輯不一致。既有神經符號法多依賴單調邏輯（FOL、SMT）——一旦推出結論就不能因新資訊撤回，無法表達可廢止（defeasible）推理、偏好、例外；而人類推理本質非單調（「鳥會飛」遇到「企鵝」就撤回）。且先前 LLM+ASP 工作（Yang 2023、Ishay 2023）把 LLM 當一次性翻譯器、需手寫知識模組或只在單一問題類（邏輯格謎）評估，沒有錯誤恢復機制。

核心方法

  • ASP 作為目標形式：穩定模型語意把**預設否定（default negation）**與「多個可能世界」當一等公民，比 FOL/SMT 更自然地建模邏輯衝突。
  • 自動自我修正迴圈：LLM 寫初版 ASP → clingo 求解器回傳結構化錯誤訊息 → LLM 反思並修正 → 迭代。建立在 semantic parsing / 程式合成的「執行回饋迭代精煉」傳統上，貢獻在於把它用到非單調語意的 ASP 並做到任務無關。
  • 精簡參考指南（compact reference）：把核心 ASP 慣例與建模樣式蒸餾成簡短形式放進 in-context（約為標準文件的 1/8 長度）。
  • 任務無關：無逐任務 prompt、無 few-shot、無手寫領域知識；推理型模型尤其擅長靠求解器輸出反思修程式。

結果

  • 主結果：LLM+ASP 平均 78.0%，較基線 51.3% 相對提升 52.1%。弱模型 Gemini 2.5 Flash 從 43.3% → 86.9%；強模型 o4-mini 從 63.4% → 82.3%。加 ASP 後模型排名重洗（Gemini Flash+ASP 86.9% 反超 o4-mini+ASP 82.3%）。
  • 非單調推理（MultiLogicNMR）：90.5% 懷疑式 / 81.0% 輕信式（基線僅 59.0% / 52.9%）；Gemini 2.5 Pro+ASP 達 100% 懷疑式。LLM+SMT 在此僅 35.8% / 35.0%（接近隨機 33.3%）——SMT 不適合非單調任務。
  • 維持難題努力：難度升高時基線 LLM 的 token 用量見頂後下滑、準確率崩塌（「放棄」）；LLM+ASP 的 token 隨難度單調上升且高效（12×12 題用約 25,000 token 達 100%，基線同量 token 0%）。
  • 自我修正是主因：無修正 54.6% → 允許自我修正 78.0%；平均僅 2.18 次修正、2.3 秒。Gemini 2.5 Pro 達 93.9% 且平均 <1 次修正（0.45），非推理型 DeepSeek V3 需 >5 次（5.43）。
  • context rot：精簡參考 73.1% > 標準參考 70.0% > 無參考 61.4%；ZL-XXL 上語法錯誤 84（無）→ 41（標準）→ 16（精簡），冗長文件反而害模型漏掉約束。

局限

  • 效能強依賴底層 LLM 推理能力：非推理型模型（DeepSeek V3 僅 45.0%）即使多次修正也達不到高分，自我修正補不了弱底模。
  • 在純約束滿足／規劃基準上 LLM+SMT（無參考）反而略勝 LLM+ASP（如 ZL-XL 84.0% vs 75.2%），歸因於預訓練見過更多 SMT（Z3 Python 綁定）程式碼——但加精簡 ASP 參考後 LLM+ASP 反超。
