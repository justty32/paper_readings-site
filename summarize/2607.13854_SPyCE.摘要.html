論文／訪談原始來源

《SPyCE：多模態智能體的技能-策略共演化》重點摘要

一句話概括

SPyCE（Skill-Policy Co-evolution）：一個閉環共演化框架，把多模態工具使用智能體的 rollout 軌跡蒸餾成階層式技能庫（工作流技能 + 執行技能），並在強化學習過程中讓技能庫與策略互相增強——策略變強產生更高品質 rollout、高品質 rollout 萃取更強技能、更強技能又提供更好的 policy 先驗。八個 benchmark 全面勝過 RL 與記憶類 baseline，消融證明階層設計與線上共演化皆不可或缺。

解決什麼問題

多模態 MLLM 的「用影像思考（think with images）」智能體（DeepEyes、OpenThinkIMG、VTool-R1、CodeVision 等）普遍用 RL 訓練工具使用策略，但軌跡只被消耗為純量獎勵訊號，重複出現的工具使用模式只能透過梯度更新隱性吸收，每次新任務都得從零重新發現。另一方面，記憶類方法（Reflexion、Voyager、MemP、Agent-KB）雖留存過去經驗，但記憶建構與策略改進脫鉤——更強策略不會自動產生更好經驗，更好經驗也不會反過來強化策略行為。多模態場景更難處理：軌跡橫跨「細粒度局部執行」與「高層次任務組織」兩種知識，單層記憶無法清楚分離。

核心方法

  • 階層式技能庫：分兩層：①**執行技能（execution skills）＝（觸發條件 c, 工具操作 u, 預期效果 e） 三元組，捕捉可重用的局部視覺操作（旋轉、裁剪、縮放等），可直接依視覺條件匹配復用；②工作流技能（workflow skills）**＝（瓶頸描述 b, 工作流草圖 w） 二元組，編碼高層次的工具編排與多步推理先驗（如「定位證據 → 增強局部內容 → 驗證一致性」）。
  • 技能庫整併（merge-or-add）：對新萃取的技能候選，以 embedding 餘弦相似度檢查是否與既有條目重複——若相似度高於門檻則合併（merge）精煉既有條目，否則新增（add）為獨立條目。同時以**最低匹配頻率修剪（least-frequently-matched pruning）**在庫超過容量時淘汰最少被匹配的條目（§3.6）。
  • 技能-策略共演化閉環：策略在每個訓練步進行技能條件化 rollout——先從工作流庫檢索 top-K 工作流先驗，再依瓶頸檢索匹配的執行技能，策略以此為條件選擇動作。每 N 步開啟演化窗口，只保留 GRPO 相對優勢最高的 rollout，重新蒸餾技能候選並以 merge-or-add 規則更新技能庫，形成「更強策略 → 更高品質 rollout → 更強技能 → 更強先驗 → 更強策略」的正回饋循環。
  • 階層式檢索：給定任務 (q, I)，actor model 先生成粗略瓶頸查詢 → 檢索相似工作流技能 → 再分解為細粒度瓶頸描述子 → 為每個描述子匹配最佳執行技能。低於門檻的描述子被丟棄，避免無關技能干擾。
  • 獎勵設計：R = 任務成功 + 工具呼叫懲罰（僅懲罰成功 rollout），抑制多餘操作但不壓抑失敗 rollout 的探索。

結果（Qwen3-VL-4B/8B 為基礎模型，八個 benchmark）

  • 全面最佳：V*（80.6/84.3）、HRBench-4K（78.8/78.0）、HRBench-8K（73.9/74.3）、ChartQAPro（51.4/52.5）、MathVerse（55.0/68.7）、MathVision（57.4/61.2）、WeMath（59.7/67.8）、TIR-Bench（32.0），全部勝過 GRPO/RLOO 與 MemP/DynamicCheatsheet/Agent-KB。
  • 效率-效能權衡更優：TIR-Bench 上 32.0% 準確率用 4.83 次工具呼叫，少於所有 RL 與記憶 baseline。
  • 消融：移除工作流技能掉 4.0%、移除執行技能掉 3.3%、凍結技能庫（不演化）掉 3.1%、移除工具懲罰掉 2.6%（且工具呼叫暴增到 6.83）。全部差異顯著。
  • 收斂更快：早期訓練階段就與 GRPO 拉開明顯差距。

局限

  • 任務範圍限於視覺推理與搜尋，未測試更開放的具身或現實世界任務。
  • 技能蒸餾依賴大型 MLLM（Qwen3-VL-235B），計算成本高。
  • 僅成功軌跡用於技能萃取，失敗軌跡的結構化資訊未利用。
  • 只支援單一任務的視覺推理，未涉及多任務間的技能遷移。

對讀者的價值

  • **「技能-策略共演化」**是 ai_core §3.6 固化引擎的直接對應：SPyCE 的 merge-or-add 准入協議 + 容量式修剪（least-frequently-matched）正是技能庫生命週期管理的實作範本。工作流/執行兩層抽象對應 §2「資產工廠」的粗/細粒度資產。
  • 與 2604.17308 SkillFlow（終身技能演化 benchmark）、2606.13317 SkillCAT（因果分水嶺 + 來源重播評分合併）、2605.17734 HASP（技能升級為可執行 Program Functions）並讀：SPyCE 是「RL 線上共演化」路線，補充了 SkillCAT 的免訓練路線與 HASP 的程式化路線。
  • 定位：多模態工具使用智能體 + RL + 技能庫的工業級實作，適合做 RL for agents、技能庫治理、多模態推理、工具使用訓練 的人。
