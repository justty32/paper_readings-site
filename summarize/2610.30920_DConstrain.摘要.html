論文／訪談原始來源

DConstrain：把文法轉移編成帶執行期上下文的程式

為何DLM不只需要下一token mask

DLM一次填多個masked位置，單獨合法的tokens合在一起仍可能不合法。Automata-based joint inference先為canvas各位置展開可達parser configurations，再做max-product找Viterbi path，或sum-product按path weights抽樣。AR只需對一個realized prefix的valid-next-token mask；DLM則要在尚未commit前，對許多假設context的每個候選token取得完整successor set。（§1、§3）

Configuration \(c=(q,s,d,\eta)\)：\(q\)是local grammar state，\(s\)是return stack，\(d\)是container depth，\(\eta\)是field history等choice environment。把stack與\(\eta\)都編成finite states會複製同一local logic。特定\(k\)個required unordered properties的schema，可迫使DFA至少\(2^k\)states、CFG size \(2^{\Omega(k)}\)；factorized object只要\(O(k)\)local states及runtime \(k\)-bit field set。這是存在性／worst-case靜態表示界，不是每個schema都同樣難，亦不是單次字串解析時間下界。（Propositions3.1–3.2、附錄A.5）

Cold／warm分工

Cold compiler把schema降成recursive transition network（RTN），對\((q,v)\)預先解析已知bytes與local操作，stack、depth、choice env留為參數；輸出可能是compact summary，也可能在需要unknown incoming caller時留下residual及剩餘輸入／cursor／protocol state。Summary保target、未配對return frames、net／minimum depth change及有序environment guards/updates；warm時代入實際context，檢underflow、uniqueness、required fields及其他guards才產successors。不能把環境操作視為可任意重排。（§4.1、附錄A.3）

Warm只instantiate當前canvas真正reachable configurations，續跑caller-dependent residual與token-boundary processing，union所有合法alternatives；同local state可共用program，即使不同stack／field histories得到不同successors。Compiler保留每個source與successor的關聯，不能把兩個frontiers任意Cartesian product。Theorem4.1／A.6–A.8相對reference parser證明sourcewise normalized transitions、同candidate sets及boundary condition下window language與完整輸出language一致。（§4.2、附錄A.3 Window languages）

Normalization只刪靜態certified不能完成的dead configurations；proof使用set semantics、matching primitive operations、良好binding scope及completed computations。Cursor耗盡不等token finalization完成，resource exhaustion是error、不能冒充空successor。Language／set correctness不自行保derivation multiplicities、任意path weights或resource-truncated results；raw→normalized的window比較還需相容boundary predicate，complete-output acceptance另有保留定理。（附錄A.3）

Token-effect grouping保什麼分布

在cold階段把同\(q\)、canonical compiled effects完全相同的tokens分group；canon保instruction order、operands、stack/env操作、residual／boundary／protocol metadata及需要的token identity。相等是所有admissible contexts下successor sets相等的充分條件，不是完整semantic equivalence檢定；full keys仍須核等，不能只看hash。每active group在每reached configuration只算一個representative的successors，但保留各token identity及model weights。（§4.3、附錄A.3 Token effects）

Sum-product用\(M_i(G)=\sum_{v\in G}p_i(v)\)，選到group後依\(p_i(v)/M_i(G)\)還原；max-product用\(\max_{v\in G}p_i(v)\)並還原argmax。固定finite layered graph、同normalized sourcewise logical edges各計一次、非負weights、\(Z>0\)及exact arithmetic下，chain／tree grouping保partition function與token-labeled path distribution。Viterbi optimum亦保留；要找回所有最優token sequences須留全部token/state ties，單backpointer只取一解、同選出字串另需同tie-break。（Theorem4.2、附錄A.4）

若同字串\(y\)有\(n(y)\)條accepting paths、\(w(y)=\prod_i p_i(y_i)\)，保留的是

\[Q_{path}(y)\propto n(y)w(y),\qquad Q_{seq}(y)\propto\mathbf1[n(y)>0]w(y).\]

兩者僅在positive-weight legal support上\(n(y)\)為常數才相同；unambiguous足夠，常數\(k\)仍使partition function乘\(k\)。因此不能由language等價就說不同parser representation的sum-product等價。Theorem保chosen graph的measure，不消除ambiguity；greedy取最大group mass亦非正確sampling，同seed／floating reduction order不保同sample，額外token-dependent scores要改aggregation與restoration。（附錄A.4 Parsing ambiguity）

非「任意grammar都指數加速」

Factorization把offline entries從\(S|\mathcal V|\)降成至多\(|Q_{loc}||\mathcal V|\)；grouping把successor instantiations降為各position／configuration的active-group數，仍需處理individual token scores及labels。每entry和residual work未假定constant；reachable contexts仍可能爆增、group數可近vocabulary size，recursive suffix縮短只界chain depth，不界branching tree總量。相同grammar／binding scope可重用cold assets，graph reuse另需compatible candidates與boundary/protocol。（附錄A.5）

Runtime、硬體與計時

Warm與grammar propagation不用logits，CPU在每canvas首個GPU forward時warm，後續candidate sets只縮小，沿用已算successors；每iteration propagation均可與forward重疊，graph與scores都ready才joint solve。C++ cold/warm、CSR及CUDA kernels亦貢獻效能；DINGO-Opt共用C++／CSR工程，保finite-state strategy。Score-dependent solve仍在critical path，cold/artifact loading不算runtime，overlap各段時間不能相加。（§4 Runtime integration、附錄B.3）

Inference用H20-3e、BF16與model CUDA Graphs；LLaDA2.2 SGLang TP4／32-token blocks，DiffusionGemma vLLM0.28.0單GPU／256-token canvases。Cold每schema單thread、最多64個同時編，Xeon8575C；冷計時排除tokenizer/service初始化及warm。LLaDA greedy／threshold.5、禁DELETE/SPLIT；Gemma entropy budget.1、temperature.8→.4、48iterations/canvas，兩者2048output limit，budget exhaustion算failure。這些是本文配置，非跨硬體速度保證。（附錄B.1；最後一句為本檔補註，非作者自陳）

Verification與sampling的證據界線

Boolean verifier只問存在合法continuation，不提供其probability mass。兩位置只准\(aa/bb\)、各位置\(a=.9,b=.1\)時，joint sampling取\(aa\)機率.81/(.81+.01)=98.78%，先sample第一token、可行即commit則90%，兩者都valid仍不同分布。LAVE finite lookahead的accepted proposals另受witness-search機率影響；EPIC的subset selection／shrinking及budget後witness recovery亦非同一joint objective。這不否認對固定proposal完整assignments做exact rejection可抽到其conditioned distribution，也不把單step exactness擴成全denoising trajectory exactness。（§5.3 Verification、§2；最後trajectory界線為本檔補註，非作者自陳）

消融、direct PDA與tree solver

LLaDA tokenizer／BFCL Any消融：full mean cold.72s／solve3.72ms／memory5.94MiB；eager environment specialization使cold10.52s（14.61倍），去local reuse1.87s（2.60倍）；去grouping solve25.32ms（6.81倍）。它們去不同redundancy，不單靠C++換語言。（表4）

Direct-PDA-Opt＋conservative pre-interpretation TG在固定300BFCL、LLaDA TP4／batch1／MAP、serial graph+forward且fresh runtime實驗，E2E878.10→136.63ms（6.43倍）；300例variants皆相同tokens且schema-valid。這是特定controlled設定，非主表asynchronous E2E。Tree inference減sequential depth\(O(L)→O(\log L)\)，但state-space work及intermediate memory增加；DINGO P25 tree Viterbi39.8→7.13ms、仍慢於DConstrain sequential3.90ms，P95反425.081→880.384ms。P25/P95指所選兩例的graph size，非全pool latency quantiles；不能寫tree普遍更快。（附錄D.1、附錄D.2、表7）

Recorded payload不是total process memory；baseline edge arrays與DConstrain native snapshots不同記錄單位，state亦分DFA states／local RTN nodes。Additional Dream7B／LLaDA8B experiments只compile tokenizers、不跑其inference；BFCL300/300、CFB1000/1000、JSB281/300，不能當全5754JSB結果或更多model runtime驗證。（附錄D.3、附錄D.4）

JSB frontend與剩餘限制

LLaDA tokenizer的5754JSB中1072fail（18.6%）：789semantic coverage（13.7%full）、274resource/construction（4.8%）、9implementation/unresolved（.2%）。含unsupported keywords、oneOf exclusivity、general allOf、nested id/$id scope、dialect、regex／tuple等；resource含RSS134、timeout72、其餘budget68。不能說factorization已消除任何schema的編譯失敗。（表11）

178oneOf＋127allOf共305rejections可在archived frontend單獨重現，尚未進factorized token compiler；定位問題在frontend不保延伸frontend後下游一定成功。作者另targeted audit同305original schemas：XGrammar0.2.8 strict mode返回298grammars，bounded search找124schemas的accepted完整JSON卻違original schema；jsonschema4.26全核124、fastjsonschema2.22.2另核104，找到86schemas有valid instances，舊0.1.27重播同witnesses核123。這些是作者的實驗，本檔未自行執行。（附錄D.5）

Audit用empty tokenizer、native complete-string matcher，測character-language membership，不測LLaDA vocabulary或model實際生成機率；按schema dialect、預設2020-12，format assertions及network refs關閉。124是bounded-search lower bound；無witness不證semantic preservation，也不估XGrammar全域正確率，不證DConstrain所有accepted schemas都對，更不代表每個rejected schema本質困難。Compiler相對supported parser的execution correctness、frontend semantic coverage及resource-bounded construction必分開。（附錄D.5 Frontend／Scope）

作者最後明說：warm時未定tokens使reachable contexts可能對nesting／branching仍指數增長；能實用更深層不等無上限或uniformly efficient arbitrary grammar。Incomplete coverage、resource failures與implementation issues仍是目前限制。（附錄D.5 Limitations）
