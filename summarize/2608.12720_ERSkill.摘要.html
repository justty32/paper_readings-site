論文／訪談原始來源

ERSkill: Evolving for Skill-Guided Adaptive Memory Retrieval 重點摘要

一句話

ERSkill 把「怎麼檢索記憶」本身變成可演化物件：記憶檢索行為表示成由固定 primitive（entity_search、dense_search、similarity_expand 等）組成的可執行 skill，訓練一個 router 依查詢挑 skill，並用雙前沿機制讓「探索新檢索能力」與「穩定上線的 router 可選集」分開演化。

架構

  • 記憶儲存：互動歷史切成 atom-level 記錄，搭配索引（供檢索入口）與圖（供擴展遍歷）。
  • retrieval primitive：固定的狀態轉移函式庫，skill 只是這些 primitive 的排列組合，因此不同 skill 的執行結果可共用同一套經驗結構。
  • skill router：query 與 skill 描述各自編碼後，用可學的評分函式排序，softmax 選出最匹配的 skill。
  • skill-router 共演化：experience trie 記錄已探索過的 primitive 路徑組合，避免重複生成等價 skill;capability frontier（追蹤 oracle 側可達到的最佳檢索能力)與 deploy frontier（router 實際能可靠選中、驗證過的部署集)兩條前沿分開維護，只有通過 routed-gain 或緊縮容忍門檻的候選才會被納入 deploy frontier。作者證明（Proposition 2.1）兩條前沿在驗證集上的 oracle coverage 皆單調不減。

作者報告的結果

在 LoCoMo、LongMemEval、PerLTQA 三個 agent 記憶 benchmark 上，ERSkill 對比最強基線，F1／BLEU-1／LLM-judge 平均分別以 Qwen3-Next-80B-A3B-Instruct 提升 31.3%、以 GPT-5.4-nano 提升 28.1%（作者自報，對照組含 A-Mem、MemoryOS、LightMem 等非演化基線與 ReasoningBank、GEPA、MemSkill 等自演化基線）。訓練於 LoCoMo 的 skill 與 router 直接遷移到 LongMemEval 仍領先，顯示學到的是可重用的檢索行為而非資料集特化提示。消融顯示拿掉 skill 演化或 router 兩者掉分最多，雙前沿與 experience trie 的貢獻較小但一致存在。五次獨立重跑的變異係數低於 5.4%（作者自報）。

對 ai_core 的價值／接點

這篇對記憶檢索與技能固化引擎的治理都直接有用。它的雙前沿設計，幾乎是 ai_core §4.3／§4.4（固化決策函數簽章、經濟淘汰、入庫閘）在「檢索技能」這個子領域的具體實作範本：capability frontier 對應「領地擴張仍需蓋章」的 v0.5 半自動 sleep，先在離線驗證資料上證明 oracle 價值；deploy frontier 對應真正拿去服務請求的「已通過憑證准入」集合，兩邊用不同門檻（routed-gain margin、compactness tolerance）解耦，避免探索期的不穩定波及線上服務。這給 ai_core 固化引擎一個可直接借用的教訓：能力擴張的驗證集與部署決策的驗證集要分開跑，不能讓一次強候選直接空降上線。此外，把檢索本身拆成固定 primitive 的可組合序列，而非黑箱 embedding 相似度，也呼應 ai_core 對「LLM 只填必要的洞、其餘走確定性程式碼」的偏好——這裡的 primitive library 就是那層可稽核的確定性骨架。
