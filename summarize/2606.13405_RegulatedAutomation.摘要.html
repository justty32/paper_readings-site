論文／訪談原始來源

《規範流程自動化之神經符號代理人》重點摘要

一句話概括

合規即構造（compliance-by-construction）：將製藥品質管理中的法規、流程模型、合規約束等既有符號結構，從「外部監控層」升級為代理人推理的主架構元件——由 BPMN 流程模型決定行動空間（而非 LLM prompt），由符號契約驗證輸出，從架構層面結構性阻止控制流違規（錯誤排序、遺漏核准、跳過必要步驟），而非事後偵測。

解決什麼問題

LLM 代理人正進入製藥、生技、醫療器材等受法規高度管制的產業，執行偏差管理、根本原因分析、CAPA 提案等品質管理任務。現行做法是外加 guardrail schema validator、治理監視器與 HITL 閘門（如 ShieldAgent、QuadSentinel），但這些都是事後監控：能在違規發生後抓到，卻無法結構性阻止。在高風險受規範流程中，「已被偵測到的違規」本身即是法規缺失。

本文論證：受規範流程自動化結構上要求神經符號整合，因為該領域同時具備三個罕見共存的屬性：(1) 既有符號結構（法規、SOP、BPMN 模型、受控詞彙表）——已在組織內維護、版本控管、審計；(2) 高難度神經任務（多文件推理、語意判斷、證據綜合）；(3) 具法律後果的硬驗證要求（EU AI Act 2026 年 8 月強制生效）。

五項研究挑戰（兩層架構）

基礎層

挑戰 1：法規知識操作化（§3.1）——將 EU-GMP、ISO 13485、EU AI Act 等自然語言法規轉譯為機器可執行的形式約束（時態性質、狀態不變式、轉換守衛），使流程引擎可執行、模型檢查器可驗證。核心難點在於「操作化」而非「抽取」：產出的約束必須同時忠於法規意圖、可形式驗證、且可在流程引擎中執行於多法規環境。

挑戰 2：將代理人接地於符號流程結構（§3.2）——流程模型（而非 LLM prompt）決定代理人的行動空間：在每個流程狀態下，啟用哪些活動由模型決定，LLM 只負責接地——解讀非結構化案例文件、產出滿足活動型別契約的輸出。關鍵設計：**中介層（mediation layer）**將型別化活動規格轉為 prompt，並驗證 LLM 輸出是否滿足符號契約。核心未解難題：表達力 vs 可驗證性權衡。

能力層

挑戰 3：不確定性感知的自主邊界（§3.3）——將 conformal prediction 整合至即時代理人自主控制：當 LLM 分類的不確定性高，符號層應升級至 HITL 無視預設風險等級。prediction set 非單一即觸發干預——具分佈無假設保證的升級閘。

挑戰 4：學習與維護符號流程記憶（§3.4）——提出雙記憶架構：STM（案例暫存區）+ LTM（Case Graph，含型別實體與領域關係的知識圖譜）。建構此圖譜是典型的「從子符號資料學習符號抽象」：神經處理抽取實體/關係，符號層確保本體一致性，法規要求來源追蹤與存取控制。此為神經符號共學習動態：代理人查詢圖譜並將產出回寫。

挑戰 5：跨神經符號邊界的可解釋性（§3.5）——稽核時需同時回答：(a) 為何此時執行此活動？(b) 代理人如何形成判斷？(c) 形式約束是否滿足？挑戰在於符號流程軌跡構造上忠實，但 LLM 理據只是事後重建。需分層解釋架構，為每層標註忠實度保證等級。

合規即構造（§4）

同時解決五項挑戰產生 compliance-by-construction：控制流違規在架構上不可能發生。它與 guardrail 互補——結構層防止確定性違規；guardrail 捕捉語意錯誤與未預見邊界案例。二者構成縱深防禦。

時效性（§5）

(1) 代理人 AI 此刻正進入受規範生產環境；(2) EU AI Act 高風險義務 2026 年 8 月 2 日強制生效——具形式保證的神經符號架構正成為法律必要；(3) 基礎組件已各自成熟（NS 規劃、CP、流程探勘、法規 NLP、符號 guardrail、KG 建構），缺的是整合方案。

局限（§6）

(1) 假設形式流程模型已存在——僅適用於 GMP 規範製造；(2) 低風險流程不需此複雜度；(3) 表達力-可驗證性權衡未真正解決（最有用後條件如「CAPA 處理了根因」無法形式驗證）；(4) 立場論文層次，實務可行性有待證明。

對 ai_core 的價值（§3.4 憑證對應）

  • 規範流程自動化 = 合規憑證的完整示範場域：本文的 compliance-by-construction 是 ai_core 治理層「拒絕為預設＋憑證准入」的宏觀實例——符號流程結構 = 靜態憑證（活動排序、核准鏈、分離職責由模型保證），conformal prediction 閘 = 動態憑證（信心不足即升級 HITL），合規驗證記錄 = 可審計憑證（§3.5 分層解釋架構）。
  • §3.3 升級信號的實作路徑：conformal prediction → 符號風險分類邏輯 → HITL 升級，直接對應 ai_core §3.3「何時應從 LLM 升級至確定性路徑或人類」——prediction set 非單一即觸發，具分佈無假設保證。
  • §3.2 中介層 = ai_core 約束器的系統級實例：型別化活動規格 → prompt、輸出驗證 → 符號契約，正是治理層「約束器」在流程自動化場景的具體化。
  • 雙記憶架構（§3.4）= 固化引擎的前置步驟：Case Graph 將非結構化案例歷史結構化為型別化 KG，為「將反覆處理的案例模式結晶為確定性程式碼」提供抽象基礎。
