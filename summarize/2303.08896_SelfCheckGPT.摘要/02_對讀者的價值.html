對讀者的價值

  • 本篇是 ai_core 主題 12「信心校準／幻覺偵測」中**「黑箱可用」的實作範式代表**：五種變體全程只讀模型的文字輸出，完全不需 token 機率、不需白箱存取、不需外部知識庫，因此最適合直接套在外部 API 型 LLM 節點（ChatGPT/GPT-4 之類無法拿到 logits 的服務）外面當一道 gate，這正是 ai_core 把「多數確定性節點＋少數 LLM」計算圖套在真實 API 邊界上時最常遇到的限制。
  • 與庫中已有路線對照：2203.11171 Self-Consistency 同樣靠「N 條取樣的一致度」，但用途是在多個候選答案間投票選出最終答案（單一封閉式答案的正確性代理）；SelfCheckGPT 把同一機制反過來用在任意長度自由文本的逐句除錯上——不選答案，而是給已生成文本的每一句打幻覺分數。兩者共享「一致性＝可用信號」的核心直覺，但一個做選擇、一個做審查，可以互補而非取代。2207.05221 LMs Know What They Know 走的是另一條路：讓模型自己回答「我有把握嗎」（P(True)/P(IK)），本質上仍是要求模型對自己的輸出做內省判斷；SelfCheckGPT 完全不問模型「你信不信」，只看外顯文本間是否彼此吻合，因此不受「模型自己簽自己的憑證」這個風險影響，但代價是需要 N 倍生成成本而非一次自評。
  • 與 2305.11738 CRITIC 互補而非重疊：CRITIC 靠外部工具（搜尋引擎、程式直譯器）產生接地訊號來批判與修正，能力上限取決於工具能否覆蓋到相關知識；SelfCheckGPT 完全不接外部世界，靠模型自身生成分佈的內部一致性做審查，適用範圍更廣（任何黑箱 LLM 皆可用）但精確度上限受限於模型本身是否「真的知道」——兩者可串接：先用 SelfCheckGPT 便宜地標出低一致性（高風險）句子，只對這些句子觸發 CRITIC 式的外部工具查核，形成一道成本分層的兩段式流程。
  • 對 ai_core §3.3 成本梯度（升級信號）：SelfCheckGPT 本身就是一個典型的成本-效益權衡樣本——Prompt 變體最準但要對每句每份取樣各呼叫一次 LLM，NLI 變體較便宜但效果接近，Unigram(max) 幾乎零額外模型呼叫但仍有可用訊號；這條「便宜→昂貴」的變體序列，本身就可以當成本梯度上「先用便宜訊號篩選、對存疑案例才升級到貴訊號」的現成範例，其代價（N 倍取樣、Prompt 變體再乘一次 LLM 呼叫）必須明確計入升級判斷的成本模型。
  • 對 ai_core §3.4 治理＝拒絕為預設＋憑證准入：SelfCheckGPT 的逐句分數天生就是撤照信號——不是對整段 LLM 輸出做通過/拒絕的粗粒度判斷，而是能在句子級做細粒度准入：高一致性的句子放行，低一致性的句子標記、丟棄或觸發重新生成/升級查核。這比對整段輸出做二元拒絕更貼近「逐項准入」的治理精神，也提示 ai_core 在設計憑證機制時，准入粒度可以下探到「LLM 輸出中的單一陳述/欄位」而非整個回應。
  • 2504.19254 UQ Scorers、2405.01563 Conformal Abstention 這類把「信心分數→棄答決策」形式化、加上覆蓋率保證的下游機制，可以直接把 SelfCheckGPT 逐句一致性分數當作輸入信號使用。另需注意：2302.09664 Semantic Uncertainty、2406.15927 SEP、2402.03744 INSIDE 是同批次由其他 drafter 處理中、尚未入庫的相鄰路線（分別是語意熵、語意熵探針、內部表徵一致性），與 SelfCheckGPT 同屬「用一致性偵測幻覺」家族但取徑不同（白箱/探針 vs 純黑箱取樣），值得日後入庫後並列參照。
