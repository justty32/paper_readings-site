2. 程式合成的兩條路與兩種搜尋空間

抽象推理的核心戰場上，有兩組正交的設計選擇。理清這兩組軸，幾乎能定位本批所有 ARC/程式合成論文。

2.1 軸一：歸納（induction）vs 轉導（transduction）

graph LR
    INPUT["少量 I/O 範例<br/>+ 一個新測試輸入"]
    INPUT --> IND
    INPUT --> TRD
    subgraph IND["歸納 induction：先求函式 f，再套用"]
        I1["合成可執行程式 f<br/>使 f(x_train)=y_train"]
        I1 --> I2["套用：y_test = f(x_test)"]
    end
    subgraph TRD["轉導 transduction：直接預測輸出"]
        T1["神經網路直接<br/>map 到 y_test，無顯式 f"]
    end
    IND --> OUT["y_test"]
    TRD --> OUT
歸納（induction） 轉導（transduction）
產物 一段可執行程式 / 邏輯子句 直接的輸出網格
代表 BARC-歸納 2411.02272、SOAR 2507.14172、GridCoder 2411.17708、ILP 2507.16405 BARC-轉導 2411.02272、TTT 後的神經模型 2411.07279、PoE 2505.07859
可驗證性 高——能用範例過濾，知道何時成功（執行相符才採用） 低——總會給答案，但無法自證對錯
擅長 精確計算、多概念組合、需要嚴格規則的題 模糊的知覺型概念（對稱、重力、補洞等難以言詮者）
弱點 小搜尋預算下命中率低；DSL/語言涵蓋不到就解不出 缺結構化測試時適應；OOD 時靠重採樣或昂貴微調

最關鍵的經驗證據——兩者強互補（2411.02272 BARC）： 即使用同資料、同架構、同先驗分別訓練歸納與轉導模型，兩者能解的題目幾乎不重疊，且跨隨機種子穩定（p<0.004）。直覺分工是「歸納擅精確組合、轉導擅知覺模糊」。集成策略也很實用：歸納為主（可驗證），無解時轉導兜底（總有答案），把 ARC 公開驗證集推到 56.75%，逼近人類平均 60.2%。

互補性的第二層證據（2411.07279 TTT × 2411.02272 BARC 互為依存）：

  • TTT 建在 BARC 神經模型上，把分數從 56.75% → 61.9%，追平人類平均；
  • 但 BARC 回證：拿掉程式合成器只剩 47.1%——精巧的轉導式 TTT 無法完全取代歸納式程式合成。
  • 這對讀者是一條硬結論：ARC 的 SOTA 是「神經 + 程式合成 + TTT」三元組合，缺一塊就掉一截。

2.2 軸二：離散 DSL 枚舉 vs 連續潛在搜尋

在「歸納」這條路內部，還有第二個分裂——程式空間長什麼樣、怎麼在裡面搜。

graph TD
    SEARCH["如何表示並搜尋程式空間？"]
    SEARCH --> DISC
    SEARCH --> CONT
    subgraph DISC["離散：程式 = 符號 token 序列"]
        D1["GridCoder [[2411.17708]]<br/>VLM 出 DSL token 機率 → 機率枚舉"]
        D2["BARC/SOAR<br/>LLM 直接寫 Python（圖靈完備）"]

        D4["eggp [[2501.17848]]<br/>表達式樹 + 等式圖去重"]
    end
    subgraph CONT["連續：程式 = 潛在向量 z"]
        C1["LPN [[2411.08706]]<br/>編碼器→潛在 z→梯度上升搜尋→解碼器"]
    end
離散 DSL 枚舉 連續潛在搜尋（LPN 2411.08706）
程式表示 符號 token / 子句 / 樹 連續潛在向量 z
搜尋方法 機率枚舉、MCTS、演化、Prolog 推理 在 z 空間做梯度上升找最能解釋範例的 z*
需要手工 DSL？ 多半需要（GridCoder、ILP 的 metarules） 完全不需要——解碼器逐像素生成，繞過 DSL
可解釋性 高（程式可讀、可驗證、可組合） 低（z 是稠密向量）
組合泛化 強（但受 DSL 涵蓋限制） 不穩健（潛在空間平滑度不足，有成功也有明確失敗）
算力擴展 枚舉隨深度爆炸；GridCoder 用條件獨立攤平壓成「位置×類別」逼近 只反傳一小部分參數，比 TTT 省

離散路線的兩個典型優化技巧值得單獨記：

  • GridCoder 2411.17708 的「條件獨立攤平」：把自回歸 token 機率近似成只依「位置」不依「先前選擇」，於是只需呼叫神經網路幾次就能算整棵樹的機率，把枚舉成本壓下來。代價是犧牲了 token 間的依賴建模——但實測 79.3% > 不做假設的 75.9%，划算。
  • eggp 2501.17848 的「等式圖去重」：GP 搜尋反覆重訪語意等價的表達式（同一式的無窮參數化變體）。eggp 把編譯器的等式飽和（e-graph）接進 GP，強制交叉/變異只產生「未曾訪問過」的式子，極簡修改就追平 PySR/Operon、且模型更小更可靠。這是「離散搜尋如何不浪費在重複上」的範本。

連續路線的獨特賣點（LPN）： 把「測試時搜尋」直接內建進可微架構——編碼器（System 1 直覺、攤銷推論）給初始 z₀，潛在梯度上升（System 2 搜尋）縮小攤銷間隙，解碼器逐像素出格。關鍵歸納偏置是訓練時就模擬測試時的梯度搜尋（訓練帶 0–5 步潛在優化），於是測試時開搜尋讓 OOD 表現翻倍（7.75%→15.5%）。可視為半攤銷變分推論。

2.3 互補與融合的證據

兩條軸不是要二選一，最好的系統都在融合：

  1. 歸納⊕轉導融合 = BARC 集成 2411.02272（歸納為主+轉導兜底）。
  2. 離散枚舉⊕執行回饋 = GridCoder 自承缺陷後提出（未實作）的 LTS（學變換空間）——把程式中間執行狀態回饋進每步解碼。它的核心洞見極其重要：搜尋能補的是「網格層 OOD（高熵、多種可能輸出）」，補不了「程式結構 OOD（低熵、機率硬卡在 0/1）」；要跨結構泛化，唯有執行引導。Proxy 實驗顯示 LTS 可從 10% 拉到 80%。
  3. 搜尋⊕學習融合 = SOAR 2507.14172——離散 Python 搜尋的軌跡（含失敗，用 hindsight relabeling 化為訓練對）回灌微調生成器，抬高整條 scaling 曲線，突破「固定模型」的搜尋預算與尺寸天花板。

PLVR 2608.28421 在離散路線旁補出另一種融合：它不更新 base model 權重，而把能力存成由 typed neural primitive 與 deterministic primitive 組成的顯式程式，從目標 ontology 反推各層所需型別，並以逐層 contract verdict 提前剪掉違約候選。它因此補上本節把執行回饋主要放在搜尋終點的空白，把可驗證性往中間狀態推進；不過這只適用於中間產物可檢查的任務，不能直接取代轉導路線處理開放式判斷（本檔補註，非作者自陳）。

一句話收束 §2：ARC 沒有單一銀彈。歸納給可驗證性、轉導給知覺覆蓋、離散給可解釋與組合、連續給可微與省算、執行引導給結構泛化、搜尋↔學習閉環給可持續性——SOTA 是這些的拼裝。
