從百萬到千萬個 agent：編排、故障治理與思想模型

這份綜述回答三個相連、卻常被混成一團的問題：大量 agent 如何執行；錯誤如何被發現、定位與限制；所謂 agent「思考」在系統裡到底指什麼。引用格式 [[arxiv_id]] 可回溯到 summarize/ 與 translate/ 的原文產物。

最重要的結論是：agent 身分、活躍 actor 與 LLM 推理呼叫必須分開計數。百萬個可被喚醒的 agent 已有實證；千萬個 agent 若仍被設計成千萬條常駐對話鏈，成本與故障面都會先失控。可行方向是讓大多數 agent 平時只是一份持久狀態，事件到達才短暫啟動，且只有少數事件升級到 LLM。

本文按問題分成五篇：

  • 規模：千萬 agent 不是千萬條對話
  • 故障：從攔截、偵測到反事實歸因
    • 一–四 攔截、量測、歸因與隔離
    • 五–六 效果語意與故障修復
    • 七–八 來源權限與可信完成
  • 思想模型：四種不能混用的 agent 觀
  • 綜合架構與研究缺口
  • 機率管理：從分數到可執行的 probability control plane
