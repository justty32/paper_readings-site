5.1 適應度設計——「內層跑一遍」的詛咒

幾乎每篇都撞到「每個候選都要完整跑一遍內層才能評估」這個根本成本：2603.28416 每候選 25 個完整訓練 run、每代 30 小時；2606.20858/2606.26327 每候選一次 PPO 訓練。對策有三類：(1) 低保真代理（EVOM 用 100k 步 PPO 當內層，但與 5M 全預算有 gap，需最終全預算重訓定論）；(2) 早期關卡 / 早停（2101.03958 CartPole 早關、2605.15308 ESS 自動終止）；(3) 多環境聚合 + 保留集（2603.28416 用 5 訓練 + 5 未見環境防過擬合；2606.26294 用保留真值集）。入選門檻上，2601.21847 的 rejection sampling（須支配人類 baseline 才入種群） 是乾淨的品質守衛。

5.2 多樣性維持——本批的核心技術資產

這是 §2 的工程沉澱。光譜從「外部 archive」到「內建表徵」：

多樣性機制 維持方式 代表
局部競爭函數 用 fitness 變換決定誰存活，自適應 descriptor 空間 DNS 2502.00593、LQD 2502.02190
island / niche 多個半隔離子種群 + 知識遷移 2603.28416、2601.21847

最深的觀念是 LQD 的「多樣性即工具」：純 fitness 目標下多樣性自發湧現——多樣性不必當成獨立目標去獎勵，它是達成高效能的內生手段。

5.3 信用分配——LLM 時代的新議題

傳統演化只給「整個個體的純量 fitness」，LLM 算子卻能消化更細的訊號。本批把信用分配從「個體層」下沉到「子組件層」：2512.13857 的替代方案層級統計（每個 alternative 在所有含它的路徑上的均值/變異/最佳貢獻）、2606.04360 的工具診斷（殘差/量綱把純量誤差變局部結構證據）、2601.21847 的 global/debug reflection（回溯哪些改動歷史上帶來增益）。這是 LLM-as-operator 相對傳統 EA 的真正增量——LLM 能讀懂「為什麼這部分好/壞」，前提是系統把細粒度反饋餵給它。

2609.17590 Evolutionary Ensemble Search 把這套主張落成一個較完整的系統實例：mutation 可讀 residual、泛化落差、fold 變異與預測相關性，parent-relative operator credit 會改變後續算子分布，session memory 與跨任務 library 則保存成功與失敗路線；child 仍須在共同 measurement contract 下重新執行，不能繼承親代 fitness。它補強「細訊號要能進入算子」的工程證據，也同時打臉更強的推論：細粒度 credit、council 與記憶本身不等於可泛化。作者明言 parent-relative reward 不是因果歸因，公開結果又是評分可見的開發 ledger，沒有凍結盲測或元件邊際貢獻；這些機制是否共同帶來未見任務增益仍待實測2609.17590。

5.4 計算成本——三條降本路線

(1) 系統層：2501.17168 EvoGP 的 GPU 群級並行（把不規則樹張量化）。(2) 演算法層：2605.15308 SMCEvolve「效能升、算力降」（更好的取樣機制省呼叫）、2606.04360 40% 預算降 55% NMSE。(3) 流程層：低保真內層 + 最終全預算重訓（EVOM）、自動停止（ESS）。但 LLM 算子引入新成本軸——token 成本與 backbone 綁定，且 2505.22954 DGM 單 run 約 2 週仍是常態。

5.5 可遷移性——「發現的東西能搬走嗎」

可遷移性是「真發現 vs 過擬合」的試金石。本批的正面證據：2101.03958 DQNReg 從簡單環境 meta-train 泛化到 Atari；2505.22954 DGM 跨模型/跨 benchmark/跨語言保持增益；2601.21847 READY 零樣本跨 MetaBBO 遷移；2505.20881 MoH 跨規模優勢愈大愈顯；2502.02190 LQD 從 pop=128/dim≤12 外推到更大族群、更高維、訓練沒見過的 robot control。共識：能跨分布遷移的發現，才是發現了「結構/機制」而非「擬合了 benchmark」——這與 self_improving_program_synthesis.md §3「機制 > 相關」遙相呼應。

2609.04518 Multi-Harness RL 是這條共識的直接反例測試，而不是反駁試金石本身。作者只改 GRPO 的信用分組邊界，讓不同 coding harness 的軌跡在同一相對優勢群組競爭；Cross 的 advantage 因而帶有可辨識的 harness 身分，卻未在訓練時未見的 harness 形成可檢出優勢。每題八次嘗試時，Cross − Within 僅為加 0.25 個百分點，95% 信賴區間為負 0.48 到加 1.02 個百分點（作者自報）2609.04518。因此，來源 harness 上的改善不能直接算成可攜的演化產物；多介面訓練若沒有 harness-swap 與未見介面評估，可能只是在學配置適應。（本檔補註，非作者自陳）
