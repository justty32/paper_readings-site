0. 為什麼把這 26 篇放在一起讀

這批論文表面分散在三個社群——演化強化學習（D 類）、遺傳編程（G 類）、LLM 符號迴歸（C 類）——但它們其實共享同一個母結構：

一個「外層搜尋（演化）／內層評估（跑一遍）」的雙層迴圈，差別只在「演化的物件是什麼」與「變異算子由誰來提」。

把這個母結構拆成兩條正交的演進軸，幾乎能定位本批每一篇：

  • 軸一｜演化的物件（被發現的 X）：從「解」本身（GP 演化表達式）→「演算法的某個函數」（損失、更新規則、競爭函數、reward）→「演算法的架構」（actor-critic 網路）→「演算法本身 / agent 自己的原始碼」。越往上，被發現的東西越接近「系統的設計」，威力越大但搜尋空間越離散。
  • 軸二｜變異算子是誰：從隨機/結構化算子（傳統 GP 的子樹交換、CMA-ES 的高斯擾動）→神經參數化算子（用 Transformer/ES 學競爭函數）→LLM 當算子（讀程式碼、提連貫編輯）→內嵌式自參照算子（網路自己生成自己的變異）。

    end

本檔結構：§1 講軸二的時代轉折（LLM 當演化算子的興起）；§2 講 Quality-Diversity 與開放式進化這條獨立但深刻的支線；§3 把軸一鋪成「演化發現 X」光譜；§4 講演化骨架與符號迴歸／程式合成的三個交叉點；§5 收斂出五個共通設計議題；§6 研究空白與方向。

1. 「LLM 當演化算子」的興起

1.1 轉折點：把隨機算子換成「會讀程式碼、提連貫編輯」的 LLM

傳統演化計算的變異/交叉是盲目的：子樹隨機交換、權重加高斯噪聲。這在「解空間平滑」時有效，但在離散程式結構上幾乎只產出無效或語意崩壞的後代——2603.28416 點得最白：RL 更新規則是緊耦合訓練程序，「盲目 mutation/crossover 幾乎只產出無效變體」。

FunSearch / AlphaEvolve / Eureka / EoH 一脈帶來的範式轉折，就是把變異算子換成 LLM：LLM 讀親代程式碼 + 評估反饋，提出連貫、可執行、帶語意意圖的編輯。本批論文把這個算子推到五個不同層面：

2609.05093 Discovery Loop 替這張圖補上一個刻意縮小的正證：不需複雜族群，只靠完整 solver 重寫、外部評分、與 solver 分離的 verifier、近期嘗試紀錄與 champion 更新，也能形成可驗證的 LLM 程式演化；逐目標保存最佳 artifact，又補住單一總分可能抹去 niche improvement 的缺口。它佐證「LLM 提案、外部執行、客觀篩選」確實是最大公因式，卻也劃出邊界：單一 circle-packing 領域的成功尚不能證明框架可泛化，而單一 champion 也沒有取代 §2 的族群多樣性。

這篇還把 §5 的計算成本問題往前推一步：停不停也應由邊際可驗證改善決定。作者回測的停滯規則可在第九輪停止，成本由 27.72 美元降至 13.95 美元，而最終總值只少 0.01%（作者自報）2609.05093。因此，LLM-as-operator 的完整配方不只要有生成與驗證，還要有一個能拒絕繼續花費的停滾條件。

1.3 抽象躍升：從「設計解」到「設計設計者」

本批最深刻的觀念是遞迴抽象——LLM 不只設計啟發式，而是設計「生成啟發式的優化器」：

  • 2505.20881 MoH 把 LLM-EC 從「設計啟發式」提升到「設計優化器本身」：一個能自我（遞迴）調用的 meta-optimizer，自動生成多樣的 heuristic-optimizer，擺脫人工預設的固定 EC 流程（如「先交叉再變異」）。優化器簽名 optimize_algorithm(population, utility, language_model, ...) 支援把自身實作當輸入。
  • 2606.26327 EVOM 把 LLM 定位成純架構設計師，與策略執行、環境控制完全解耦——「agentic」的有限意義＝維持狀態（current elite + 歷史 log）、採取設計動作（生成架構程式）、觀察反饋（內層 PPO 回報）。

這條「設計設計者」的線，把演化計算從「一個固定流程」變成「流程本身也是被演化的對象」——直接通往 §2 的開放式進化與 §3 的「演化發現演算法本身」。

1.4 LLM 算子帶來的新痛點

LLM 不是免費午餐。本批反覆撞到三個 LLM 特有問題：

  1. 對 backbone 敏感：2603.28416 中 GPT-5.2 末代 fitness 0.65–0.69，Claude 4.5 Opus 只有 0.37–0.47（未產出有競爭力候選而被排除）；2606.26327 也要比較 DeepSeek/Claude/Qwen。結論可重現性受 LLM 版本綁定。
  2. 「結構盲」：純把親代式 + 一個純量 MSE 丟給 LLM，要它一次推斷「怎麼改/為何錯/過去學到什麼」——2606.04360 指這是 LLM-SR 樣本低效的病根，2606.07704 補上 AST 可見性。詳見 §4.3。
  3. 守規則負擔：放任 LLM 自由生成易破壞結構/產生環。2512.13857 的解法是把結構正確性移離 LLM（確定性自我修復保證無環與依賴一致），讓 LLM 只管語意。
