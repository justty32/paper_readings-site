6. 研究空白與有前景方向

  1. 打破「內層跑一遍」的詛咒（最痛的瓶頸）。本批幾乎每篇的局限都寫「每候選一個完整 RL run，極貴」。已見的解（EVOM 低保真、SMCEvolve 早停）都是 ad hoc。前景：訓一個學習型 fitness 預測器（從候選程式碼/架構直接預測最終回報），或借 LQD 的 Meta-BBO 把「評估」也學成攤銷模型——把雙層迴圈的內層從「跑」變成「預測」。

  2. 「算子是誰」的混血（§0 軸二的融合）。2402.05828 證明 ES 才能發現非短視演算法、2101.03958 能產人類可讀的符號損失、2603.28416 的 LLM 算子能提連貫編輯。前景：用 ES/演化發現的符號損失當 LLM 的暖啟動 seed，再讓 LLM 迭代精煉——兼得「ES 不短視」「符號可解釋」「LLM 連貫編輯」三者。這也呼應 self_improving_program_synthesis.md 的「演化發現的可解釋產出回哺 LLM」。

  3. 把 QD/局部競爭內建進 LLM 演化框架。目前 LLM-EC（FunSearch 系、READY、EVOM）的多樣性多靠 island/niche 這種粗粒度機制，而 DNS/LQD 的自適應局部競爭（無需 descriptor 邊界）遠更精緻。EvoLattice 已示範「QD 內建進 DAG」。前景：把 dominated novelty score 這種 competition 函數，直接當 LLM-EC 的選擇規則——讓「LLM 算子」與「QD 選擇」這兩條本批最強的線正式合流。

  4. 非靜止目標推廣到 RL/SR。2606.26294 RQGM 的「協同演化評估者 + 受控效用演化」目前只在 coding/論文寫作 agent 上驗證。前景：RL 演算法發現（2603.28416）與 SR（2606.07704）都假設評估標準靜止（固定環境集、固定 benchmark），這正是過擬合的溫床；把 RQGM 的 epoch 凍結機制引入，讓「測試環境/評估指標」也隨被發現的演算法一起演化，可能緩解 2603.28416 自承的過擬合風險。

  5. 可遷移性的理論刻畫。本批的遷移證據都是實證（DQNReg→Atari、READY 零樣本跨 MetaBBO、LQD 外推）。前景：什麼條件下「發現的演算法元件」會遷移？2402.05828 的「表達力 × 泛化」張力、2502.02190 的「descriptor 消融→退化成 GA」都是線索——一個刻畫「演化發現何時抓到機制、何時只擬合 benchmark」的理論，是把這領域從工程提升為科學的關鍵。

  6. 讓演化流程本身也可演化（遞迴抽象的終點）。2505.20881 MoH「設計優化器本身」、2502.02190 LQD「學競爭規則」、2512.16406 自參照 GHN「evolvability 內收」都指向同一處——meta 流程不該是固定的。但目前 DGM 自承「開放式探索流程本身固定、DGM 不可改」。前景：把「外層演化演算法」也納入被演化的對象（外層的外層），是通往真正開放式自我改進的下一步，也是 Schmidhuber 哥德爾機原始野心的演化式落地。

7. 給讀者的一頁速記

  • 母結構：本批 26 篇共享「外層演化 / 內層跑一遍」雙層迴圈，沿兩軸演進——軸一（演化什麼）：解 → 演算法函數 → 架構 → 演算法本身/agent 原始碼；軸二（算子是誰）：隨機 → 神經參數化 → LLM → 內嵌自參照。
  • LLM 當演化算子的興起（§1）：用「會讀碼、提連貫編輯」的 LLM 取代盲目隨機算子，跨 SR/程式/RL演算法/架構/reward/agent 六個層面鋪開；共通配方＝三元組個體 + mutation/crossover + island/niche + 驗證守衛 + rejection + 反思；抽象躍升到「設計設計者」（MoH 遞迴 meta-optimizer）。新痛點：backbone 敏感、結構盲、守規則負擔。
  • Quality-Diversity 與開放式進化（§2）：QD = GA + 局部競爭函數（DNS 2502.00593 的觀念槓桿）→ 元學習競爭函數（LQD 2502.02190，純 fitness 下多樣性自發湧現）→ evolvability 內收進神經基質（自參照 GHN 2512.16406、可演化編碼 2406.09020）→ 連評估者也演化（RQGM 2606.26294）。
  • 「演化發現 X」光譜（§3）：① loss/update（2101.03958 符號圖 / 2402.05828 ES 動態 / 2603.28416 LLM 可執行）② reward（2601.21847 函數 / 2606.20858 時變權重）③ 架構（EVOM 2606.26327）④ 演算法本身（LQD 2502.02190、MoH 2505.20881）。亮點：禁 TD 自發長出 model-based、novelty 自發早期主導、演化損失對應 CQL/M-DQN。
  • 與 SR/程式合成的交叉（§4）：GP 地基（EvoGP 解慢、TinyverseGP 統一基準、Minimalist GP 質疑「演化＝GP 支柱」）；圖表徵對抗浪費（eggp 去冗餘、EvoLattice 信用分配 + 內含族群）；機率理論與結構意識（SMCEvolve 統一三件事 + 收斂保證、FunctionEvolve/DE 攻 LLM 結構盲）。
  • 五大設計議題（§5）：適應度設計（內層跑一遍的詛咒）、多樣性維持（本批核心技術資產，QD/island/DAG/evolvability）、信用分配（LLM 時代下沉到子組件層）、計算成本（系統/演算法/流程三路降本）、可遷移性（真發現 vs 過擬合的試金石）。
  • 最該做的方向（§6）：學習型 fitness 預測器破內層成本、ES 符號 seed + LLM 精煉的算子混血、QD 局部競爭內建進 LLM-EC、非靜止目標（協演化評估者）推廣到 RL/SR、可遷移性理論、讓演化流程本身也可演化。
