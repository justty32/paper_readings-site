4. 與符號迴歸／程式合成的交叉

演化計算與 SR/程式合成天生同源（GP 本就是程式合成的演化分支）。本批有三個交叉點特別值得單獨記，它們也與 SR_landscape.md 的 GP/e-graph 段互補。

4.1 GP 的基礎設施與「反骨」重構

G 類有三篇不談演化創新、而談 GP 的地基：

  • 2501.17168 EvoGP——把整條 TGP 流程搬上 GPU 群級並行。核心張量化套路：變長樹 → 前綴編碼 + subtree_size 陣列 + NaN padding → 定形批次張量；多數遺傳算子共用同一基元 subtree exchange 當 GPU primitive；依資料量自適應切換「個體內 vs 個體間」並行（閾值＝CUDA 核心數）。峰值 >10¹¹ GPops/s、比 Operon 快 18×。解決 GP「慢」的硬傷。
  • 2504.10253 TinyverseGP——「共同庫 + 每表示一個 tiny 模組」的極簡可擴展框架，一個框架橫跨 SR/邏輯合成/policy search 三域並各接 SRBench/GBFS/Gymnasium，破解 GP 領域碎片化。
  • 2606.10237 Minimalist GP 是全批最反骨的一篇——直接質疑「演化＝GP 第二支柱」。它保留 Koza「學習＝程式歸納」的第一洞見，但換掉演化，改用喬姆斯基極簡程式的語法推導：核心是二元集合形成運算子 MERGE + 馬可夫式增量過程。主打對抗 bloat（GP 老大難），在 Nguyen SR benchmark 上多數問題 30/30 命中真值方程。提醒我們：「演化」不是程式歸納的唯一搜尋機制。

4.2 e-graph 與「DAG 族群表徵」——對抗冗餘與信用分配

兩篇用圖表徵解決演化搜尋的兩個結構性浪費：

  • 2501.17848 eggp——把編譯器的等式飽和 / e-graph 接進 GP，記錄整個搜尋史的等價形式，改造交叉/變異只生成「未曾訪問過」的表達式。解決「GP 反覆重訪語意等價式」的浪費。極簡修改就追平 PySR/Operon、且模型更小更可靠、runtime 不顯著增。e-graph 帶來的衍生能力：存檔/續跑、跨搜尋合併歷史、查「具備某組性質」的式。
  • 2512.13857 EvoLattice——把「LLM 引導演化」從「單候選、覆寫式突變」改成單一 DAG 內含整個族群：每個節點存多個並存替代方案，圖中每條合法路徑＝一個可執行候選，用「不複製結構」換指數級組合搜尋空間。最關鍵的是解決信用分配：對「每個替代方案出現的所有路徑」逐一評分，產生替代方案層級統計（均值/變異/最佳貢獻）餵給 LLM——讓 LLM 不再只看到「整個候選的純量分數」，而能對可重用子組件做信用分配。再用 memoization（含 lambda 原始碼的防碰撞簽章）撐住組合爆炸、用確定性自我修復卸下 LLM 守規則負擔。動態自然呈現 MAP-Elites 式品質-多樣性——把 QD 從外部 archive 內建進單一 DAG 表徵。

觀念連結：eggp 與 EvoLattice 都用「圖 + 共享子結構」對抗演化的兩種浪費——eggp 攻冗餘（不重訪等價式）、EvoLattice 攻信用分配 + 破壞性突變（保留多個競爭策略、按子組件評分）。這與 §2 的 QD 是同一精神的不同實作：把族群結構做進表徵本身。

作為次要對照，2609.05207 FluxDisco 也用圖合併不同展開順序抵達的等價數學狀態，但它不是 e-graph 的等式飽和，也不是把族群內嵌成 DAG；它以 canonicalization 合併重複狀態，再用 Monte Carlo Graph Search 聯合搜尋整組 flux。更關鍵的差別是，它把已知化學計量直接寫進候選表示，而非等候 verifier 淘汰違反結構的 ODE。這填上本章原先只談「讓 LLM 看見結構」的空白：可靠先驗也可以限制什麼候選根本有資格被生成；代價則是先驗矩陣若錯，搜尋會被硬約束帶偏2609.05207。

4.3 把 SR 搜尋奠基於機率理論，與「結構顯式化」

C 類三篇 LLM-SR 把演化骨架往「理論基礎」與「結構意識」推：

  • 2605.15308 SMCEvolve 把 LLM 程式演化重構為序貫蒙地卡羅（SMC）：程式搜尋＝對獎勵傾斜分布 p*(x|q) ∝ p₀(x|q)·exp(βR(x)) 取樣。妙處是單一溫度參數 βₜ 沿探索→利用連續譜統一導出「父代選擇、突變、停止」三件原本各自手工設計的事：自適應父代重採樣（權重 ∝ exp((βₜ−βₜ₋₁)·R)）、四種 LLM 突變核 + Metropolis–Hastings 接受 + Thompson 採樣挑核、以有效樣本數 ESS 二分排程溫度（λₜ=1 自動終止、免預設迭代數）。首次給程式演化有限樣本收斂保證（定理 3.1）。反直覺：效能升、算力降（違反典型探索-利用權衡）。
  • 2606.07704 FunctionEvolve 與 2606.04360 Deliberate Evolution 是攻 LLM-SR「結構盲」的姊妹路線（見 §1.4）：
    • FunctionEvolve 攻結構顯式化——讓 LLM 看見 AST 結構，貫穿「選親/突變/擬合」三環；洞察是「SR 進步常來自局部編輯而非整式重寫」，故把 mutation 拉回 SR 的局部編輯本性。結構感知擬合（變數投影 + 參數吸附）避免低估正確骨架而過早丟棄。
    • Deliberate Evolution 攻提議/控制解耦 + 樣本效率——病根是「用單一純量 MSE 同時逼 LLM 推斷怎麼改/為何錯/過去學到什麼」。補三訊號：方向（adaptive operators 選 refine/mutate/crossover/regenerate）、診斷（殘差/量綱當工具，把純量誤差變局部結構證據）、記憶（reflective memory 累積成功母題與失敗教訓）。40% 預算下 NMSE 降 55%。

與 SR_landscape.md 銜接：那份文件把 GP（A1）、e-graph 增強層（C1）放在「SR solver 派別」框架下；本檔則強調這些都是演化骨架在不同壓力下的變體——EvoGP 解「慢」、eggp 解「冗餘」、SMCEvolve 解「無理論保證」、FunctionEvolve/DE 解「LLM 結構盲」。
