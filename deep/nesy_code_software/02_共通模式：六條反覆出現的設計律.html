2. 共通模式：六條反覆出現的設計律

讀完全批，浮現六條跨論文一致的設計模式。這六條就是「程式碼神經符號」的工程慣例庫。

模式 A：LLM 提案 + 符號驗證器把關（生成-驗證雙向管線）

最核心的骨架。LLM 出候選，符號層出判決＋可操作回饋，回饋餵回 LLM 再生。差別只在「驗證器是誰」：

graph LR
    NL["自然語言／原始碼／意圖"] --> LLM["LLM：提案器<br/>抽事實 / 譯約束 / 生程式"]
    LLM --> CAND["候選（程式 / 事實 / 約束 / 不變量）"]
    CAND --> VER{"符號驗證器"}
    VER -->|通過| OUT["可信輸出（帶證書）"]
    VER -->|失敗 + 結構化診斷| LLM
    VER -.->|累積| LIB["可重用庫"]
驗證器類型 代表作 把關內容
SMT（Z3/CaDiCaL） NeuroLog 2606.00669、Policy Compliance 2603.20449、Logitext 2602.18095、LLM2SMT 2603.06931 路徑可行性、約束滿足、unsat core
Datalog（Soufflé/pyDatalog） NeuroLog 2606.00669、ChatLogic 2407.10162 跨函式資料流、多步演繹

CAS（電腦代數） AXIOM 2606.00671 確定性推導與答案驗證
形式證明器（Lean/IDP-Z3） DreamProver 2604.26311、VERUS-LM 2501.14540 定理正確性、可滿足性
Dafny verifier（Z3） SkillForge 2608.29841 程式與規格一致性、錯誤分類
ILP 求解器（ILASP） AutoSpec 2606.24245 判別謂詞、規則歸納

SkillForge 2608.29841 佐證這副骨架，並替本節只寫到「可操作回饋」卻未交代如何選下一動作的空白，補上一層可重現的控制面：它把 verifier 錯誤分成有限類別，再確定性地路由到對應的 atomic skill；把 structured diagnosis 換成 random route 時，驗證率下降 11.8 個百分點（作者自報）。相較 VeryTrace 的局部修補與 VerIbmc 的子公式拆解，它把模式 E 的「診斷工件」往前推成 action routing key，符號層不只指出哪裡錯，也限制下一步由哪種修復技能接手（本檔補註，非作者自陳）。

但它也直接限縮上圖「可信輸出（帶證書）」的說法：Dafny 通過只證明程式滿足形式規格，不保證符合使用者原意。作者另以 reference implementation 建立 lemma，分開檢查 behavioral equivalence；verification rate 為 91.6%，equivalence rate 為 86.5%（作者自報）2608.29841。因此，模式 A 若要把輸出稱為可信，至少要區分「形式驗證通過」與「語意等價通過」兩道門；只有第一道仍不足以宣稱意圖正確（本檔補註，非作者自陳）。

模式 B：把幻覺工程化成「召回遺漏」而非「假陽性」

程式碼幻覺 SLR 2511.00776 給出問題的權威地圖（三維分類：事實性／忠實性／相容性；四層成因）。本批的工程系統則一致地用同一招拆解它：用 schema／文法約束限制 LLM 的輸出形狀，使「不確定」變成「省略」而非「亂編」。

  • NeuroLog 2606.00669：固定 12 關係 schema，「禁止發明關係，不確定就省略」——把幻覺從假陽性轉成召回遺漏；每個發現都帶以程式事實為葉節點的推導樹（機械可審計）。
  • VERUS-LM 2501.14540：SLM + **文法約束解碼（GNBF grammar）**強制輸出符合 KB 型別，小模型即達大模型水準。
  • AXIOM 2606.00671：LLM 嚴格只當正規化器，把題目改寫成狹窄 schema，「謂詞無法識別 → 必須棄答」。
  • VeryTrace 2606.24124：兩階段「先在看不到推理軌跡下抽脈絡、再譯軌跡」，防止 LLM 為合理化錯誤步驟而幻覺脈絡。

對 ai_core 的直接呼應：這就是「把 LLM 的留白關進可驗證的窄面」。schema 約束 = 受約束生成的具體手段。

模式 C：零相依、確定性檢查的價值——接地訊號免疫崩潰

跨論文反覆強調「機械可驗證的部分越多，系統越可靠」這個可機械驗證性 ↔ 增益的正相關：

  • VeryTrace 2606.24124 在純語義領域 CLUTRR 上增益縮小，正因為可機械驗證的機會少；在算術/規劃密集領域增益大。
  • VerIbmc 2606.16886 的 Phase 1「符號合取零 LLM 解 75 題」，就是純確定性層托底——對弱模型淨增最多（Llama +36）。
  • AXIOM 2606.00671 在可解析題上 100% 信任（零自信而錯），代價是覆蓋率。
  • NeuroLog 2606.00669 以 ASan 為唯一真值裁判、Foresighter 2604.13290 以 FTA run 為唯一判準——驗證器本身零相依、確定性，是整條鏈的接地錨。

這正是 2601.05280（自我改進的極限）在 cross_fusion 檔裡論證的命門：程式執行 = 完美 verifier，免疫 Goodhart 崩潰。本批把這個理論天花板落成了一堆能跑的工程錨點。

模式 D：知識／查詢分離 + 可重用工件

不要每次都重新形式化。把昂貴的形式化產物存成可複用工件：

  • VERUS-LM 2501.14540「知識庫範式」——同一份 FO(·) KB 答 8 種推理任務，查詢時不重寫 KB。
  • Foresighter 2604.13290「離線 presynthesis」——把昂貴的 FTA 建構與可達性分析移到離線，線上只做快速 slicing（中位 0.01 秒解 SQL）。
  • Policy Compliance 2603.20449「政策編碼是顯式、可審查的工件」——靜態政策 SMT 編碼離線做好，執行期只附上動態斷言。

模式 E：把 SAT 模型／診斷當「可被下游消費的工件」，而非是非判決

最精緻的一招。符號層不只回「是/否」，而是回一個能驅動下一步生成的結構：

  • NeuroLog 2606.00669：把 Z3 的 SAT 模型當工件——第二個 LLM agent 讀 SAT 模型寫出 Python 觸發崩潰輸入（而非把 SAT 當「可行/不可行」標籤丟掉）。
  • Policy Compliance 2603.20449：把最小 unsat core 回饋 agent 當解釋，驅動重規劃。
  • VeryTrace 2606.24124：診斷不是「答案錯」而是「Step 7 在狀態 s₆ 下違反約束 c」——LLM 只局部修補該段。
  • VerIbmc 2606.16886：ESBMC 失敗候選拆成子公式、把歸納原子濾進可證庫 𝒫。

模式 F：分級／只在必要時升級（成本-可靠度階梯）

不要一律用最貴的模型/最深的驗證。建立由便宜到昂貴的階梯，能在淺層解決就不升級：

  • VerIbmc 2606.16886：Phase 0 直接驗 → Phase 1 符號列舉（零 LLM）→ Phase 2 LLM 精修。
  • NOVA 2606.27243：靜默失敗感知驗證級聯（結構語義→本地可執行→離線→線上），昂貴訓練前就攔掉架構語義錯的候選；L1–L4 + AutoRun/Copilot 把自動化程度對齊風險。
  • NeuroLog 2606.00669：tier-don't-drop（只降階不刪除）；廉價 LLM 偵察、按需才升級。
