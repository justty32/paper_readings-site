2. 四條關鍵設計軸

整合形態的差異，可投影到四條獨立的設計軸上。理解一個 NeSy 系統，就是定位它在這四軸上的座標。

軸 A：符號是否必須可微？

flowchart TB
    Q{"符號組件<br/>要不要傳梯度？"}
    Q -->|"必須可微"| DIFF["端到端梯度貫穿<br/>· 可微邏輯閘 [[2506.04912]]<br/>· 機率語意/知識編譯 [[2412.07331]]<br/>· 能量基底 LBM [[2505.20313]]<br/>· 可微解釋器 [[2604.18907]]<br/>代價：符號被壓低階、t-norm 近似失真"]
    Q -->|"不必可微（解耦）"| NODIFF["可插任意符號軟體<br/>· EM：E 步任意引擎 [[2606.14463]]<br/>· LLM→solver 外掛 [[2501.14540]]<br/>· ASP 分析層 [[2604.23377]]<br/>代價：失去聯合最佳化訊號"]
  • 可微端的張力：把邏輯塞進梯度，常被迫用模糊/機率鬆弛。2412.07331 實證機率語意顯著優於模糊邏輯；2502.03274 把整個 NeSy 編成 ONNX 算術電路（AND→×、OR→+、¬→1−x）來做形式驗證。最純粹的可微符號是 2506.04912 的可微邏輯閘——訓練時連續鬆弛、推論時「結晶」成確定電路上 FPGA。
  • 解耦是近年大趨勢：2606.14463（EM-NeSy）的核心賣點就是解開「符號必須可微」的枷鎖——E 步用任意（含不可微）引擎算後驗，梯度不穿符號；精確推論下退化回標準端到端 NeSy，卻能擴展到端到端法逾時的規模（100 位數加法 13min vs 372min）。

軸 B：推理在訓練期還是推論期？

軸 C：接地（grounding）怎麼處理？

接地＝把子符號訊號（像素、token、連續觀測）對齊到符號（概念、謂詞、常數）。這是 NeSy 最脆弱的一環，也是推理捷徑的溫床。

2026-09 補入：程序、事件與視線的三層接地

NeSy Procedural VLA 把長程序的接地拆成三層：符號任務圖約束合法順序，append-only 事件記憶保存進度與外部事件，procedural saliency 再把當前子目標對到視覺區域，VLA 只承接已獲准的連續控制 2609.05369。相較於本節既有的「變數該代入哪些常數」與「把感知不確定性傳入規劃器」，它填的是跨時間的空白：接地不只回答「眼前是什麼」，還要回答「目前程序走到哪一步、此刻該看哪裡」（本檔補註，非作者自陳）。

這目前仍是派別提案，不是完整系統的正證。作者自報的局部 saliency 實驗只顯示兩種視覺引導都把五個子目標的整體結果由 20／25 提到 25／25；任務圖、事件記憶、條件分支、人機協作與七步驟程序尚未端到端驗收 2609.05369。因此「三層分工能提高長時程成功率」仍是假設，必須在程序順序、狀態更新、外部事件與低階控制分層實測。

  • 接地本身就是研究主題：2507.08216 把「一階規則的變數該代入哪些常數」參數化為 Backward Chaining 家族 \(BC_{w,d}\)，用寬度/深度兩旋鈕在「表達力 ↔ 可擴展性」間權衡，並用 VC 維解釋「為何淺而高效的接地器就夠、不必窮舉」。
  • 接地不可靠時的工程對策：2511.14533 把感知不確定性顯式傳播到符號規劃器，信心低時主動做資訊蒐集動作（look_closer/push_obstacle），並用校準品質（ECE）連結規劃收斂保證。
  • G-I-A 框架：2509.06921 在資安域把 Grounding 列為三大評估成分之首（接地分 >4.0 的系統泛化好 23%）。

軸 D：推理捷徑（Reasoning Shortcuts）

這是緊耦合 NeSy 的阿基里斯腱，近一年才被系統化。

  • 定義（2510.14538 權威綜述）：RS＝NeSy 靠錯誤接地的概念也能達到高標籤準確率。經典例：把「行人」與「紅燈」概念對調，但因兩者都導致「煞車」，標籤準確率毫髮無傷、概念卻全錯。
  • 核心壞消息：RS 是符號接地問題的必然，無法靠換架構避免。2510.14538 Theorem 4.10 證明 RS 數量與架構無關、隨「多對一」程度指數爆炸；Theorem 4.16 給不可能性結果。只能靠緩解策略（其 Table 2 是選型決策表）對症處理。
  • 形式化與工具：2604.23377 把 RS 重鑄成 CSP，回答「約束何時唯一決定概念映射」，給出 coNP/#P/NP-hard 複雜度三聯，並提供健全完備的 ASP 驗證器 + 貪婪修復 + 主動學習（最大領域 1 秒內驗完，但最小修復 NP-hard、部分領域實務無法修復）。
  • 它傷的是什麼：標籤準確/有效性不受傷，受傷的是可重用性與可解釋性——這正是 NeSy 當初承諾的賣點。RS 也在 LLM 側現身：2602.18095 觀察到「整體答案對、但子句層級推理錯」的捷徑現象，且不隨模型規模縮小（GPT-5 仍枚舉不出 Z3 能找到的 >99% 滿足賦值）。

3. 健全性 vs 實用性之爭

這是貫穿全綜述的核心張力。一派主張形式健全性是 NeSy 的存在理由，另一派反駁健全 ≠ 對人有用、甚至可能誤導。

3.1 健全性陣營（要可證明的保證）

2507.09751 把 LLM 當超協調邏輯的解釋函數，Theorem 4.8/4.10 保證健全＋完整，用容忍矛盾換取不爆炸

3.2 實用性陣營（先有用再說）

  • 多數系統自承無形式保證：2501.14540 保留 solver 卻「無形式正確性驗證」；2507.09854 model-grounded「無收斂保證、無良定義優化目標」；2604.19716 純表徵操控、無健全性保證。
  • 工程模組化優先：2411.08463 安全關鍵時只靠「調大懲罰 λ」；2502.01680 規則純當 0/1 特徵抑制過擬合。

3.3 唱反調的立場文（健全反而誤導）

2604.04177 是最尖銳的一篇：「LLM 翻 FOL ＋ solver 驗證邏輯健全」的事實查核管線，結構性會漏掉誤導性陳述——因為人類接受的推論常系統性偏離形式邏輯（析取→可能性、合取→時序、條件→雙條件），所以「邏輯健全」的結論反而誤導人。它反過來提議：把 LLM 的類人推論傾向當 feature 來偵測誤導。換言之：對人可信（實用）應凌駕形式健全。

3.4 一條折衷主線：生成-驗證雙向管線

健全與實用未必互斥。2606.08728（AI4Math）與 2508.13678 都點出同一條折衷：非形式生成（LLM 出彈性、廣覆蓋）＋ 形式驗證（symbolic 出確定、防幻覺）。2606.20895 是漂亮範例——LLM 溯因補欠定事實解決純符號「資訊不全就脆斷」死穴，把過敏感的 LLM 推向平衡準確（Spec 51-56%→82-90%），抗擾動只掉 2%（非溯因掉 8.5%）。
