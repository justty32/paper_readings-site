0. 為什麼把「程式合成」與「庫學習」綁在一起讀

程式合成（program synthesis）問的是：給定規格（I/O 範例、自然語言、邏輯約束），怎麼自動找出一段滿足它的程式？ 庫學習（library learning）問的是：當你解了一大批題之後，怎麼把反覆出現的片段抽成可重用的抽象，讓下一批題更好解？

這兩問題表面分屬「搜尋」與「壓縮」兩件事，但 DreamCoder 譜系的核心洞見是——它們是同一個迴圈的兩個半圈：

  • 你能搜到什麼程式，取決於你的**原語庫（primitives）**長什麼樣（庫決定搜尋空間）；
  • 而哪些抽象值得進庫，又取決於它們在已解出的程式裡被怎麼用（搜尋產物決定庫）。

DreamCoder 把這個互相依賴關係寫成 wake-sleep 雙階段：wake 階段用當前庫去搜題、解題；sleep 階段把解出來的程式拿去壓縮、把高頻片段抽成新庫項。兩階段交替，庫越長越好、題越解越多。本批論文裡，2604.26311 DreamProver 與 2603.25975 Schank-primitives 是這條 wake-sleep 主幹的直系後代；2605.04622 則把同一個「壓縮即發現」原則換成 e-graph 工具實作。

把這 24 篇放在一起讀，會浮現一條主軸：

可重用抽象的價值，由「壓縮效用」定義（MDL），而非由頻率或表面相似度定義；能不能持續地把抽象抽出來、又不讓庫膨脹失控，取決於三件事——壓縮壓力（發現）、語意去重（防重複）、遺忘機制（防膨脹）。

下面 §1 給範式地圖，§2 講四條核心主軸，§3 給代表作對照表，§4 接回 ai_core 與 AI 設計討論，§5 談研究空白。

讀這張圖的三條線索：

  1. 左半（①②③）偏符號、可形式驗證；右半（④⑤⑥）偏神經、靠經驗驗證。 越往左，抽象越「乾淨」（程式可執行、邏輯可證），但要人給 DSL／背景理論；越往右，越能自動從資料／語言知識長出抽象，但驗證訊號變脆。

  2. ②庫學習是樞紐。 它的「壓縮即發現」原則同時往兩邊輻射：往左給①③一個「抽象該不該留」的 MDL 判準，往右給④⑥一個「怎麼累積可重用微算子」的配方。DreamCoder 的 wake-sleep 被 2604.26311（定理證明）、2602.00929（RL 規劃）直接移植。

  3. 近兩年的合流方向是「把 LLM 接進每一支」。 ④本來就是 LLM-native；⑤的 GridCoder 用 VLM 出 token 機率、SYNTRA 用 LLM 當偽標籤器；⑥的三篇全靠 LLM 合成抽象；連③的 AutoSpec 也把 ILP 嵌進「維護 LLM agent 護欄」的迴圈。LLM 不取代搜尋，而是當「提議器／突變器／偽標籤器」插進既有合成框架。
