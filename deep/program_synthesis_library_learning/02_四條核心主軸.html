2. 四條核心主軸

2.1 主軸一：壓縮即發現抽象（MDL）

這是整條譜系的地基。一個抽象值不值得進庫，不看它出現幾次，看它把整個語料的描述長度壓掉多少——即最小描述長度（MDL）原則：

L* = argmin_L  [ cost(L) + cost(D | L) ]
                  ↑庫本身的成本    ↑用庫 L 重寫全部資料的成本

只有當「編碼節省 > 抽象自身複雜度」時，抽象才被採用。本批把這條原則跨四個天差地別的領域實證了一遍：

論文 領域 壓縮機制 標誌性數字
2603.25975 事件語意（常識） wake-sleep；specialization≈Huffman、composition≈BPE 學出庫的貝氏 MDL 落在 Schank 手工 primitive 的 4% 內，卻解釋 100% 事件（Schank 僅 81%）
2605.04622 爵士和聲 e-graph 等式飽和 + anti-unification + cost-set 三曲總推導 87→27，聯合學習壓縮率 1.5 > 逐曲 1.16
2604.26311 Lean 定理證明 wake-sleep + 語意分群抽引理 緊湊庫（<100 條）vs 龐大低階庫：解題數 104→53 的消融落差
2501.17848 符號迴歸 等式圖去重（避免重訪語意等價式） 極簡修改即追平 PySR/Operon、模型更小

最值得記的洞見（2603.25975）： 「specialization 像 Huffman 編碼（給最高頻 primitive 最短碼）、composition 像 BPE（合併高頻相鄰對）」——這把「概念 primitive 是否存在」這個 1972 年的認知科學老問題，重新表述成「事件語意的 Huffman 碼」，並給出可量化答案。同樣的壓縮壓力，在 2605.04622 自動長出 ii-V-I、降五度進行等爵士理論真實存在的和聲模式。壓縮壓力是領域通用的歸納偏置，這是本批最強的共識之一。

2.2 主軸二：wake-sleep 雙階段與它的變體

DreamCoder 的 wake-sleep 是「搜尋↔壓縮」互相依賴的具體解法。本批可以看到它被搬到完全不同的場景，且結構驚人地一致：

graph LR
    subgraph WAKE["WAKE：用當前庫解題、蒐集可學經驗"]
        W1["DreamProver：LLM 帶引理庫證定理<br/>難證者遞迴分解出中間定理 [[2604.26311]]"]
        W2["Schank：beam search 找解釋事件差的運算子組合 [[2603.25975]]"]
        W3["TheoryCoder-2：用 PDDL 運算子做階層規劃 [[2602.00929]]"]
    end
    subgraph SLEEP["SLEEP：壓縮高頻片段成新庫項 + 維護庫"]
        S1["DreamProver：語意分群→抽引理→樹編輯距離去重→LRU 遺忘"]
        S2["Schank：specialization(Huffman)+composition(BPE)+pruning"]
        S3["TheoryCoder-2：跨 episode 重用並擴充抽象庫"]
    end
    WAKE -->|可學經驗| SLEEP
    SLEEP -->|更強的庫| WAKE

三篇的 wake-sleep 共享同一骨架，但各自解決一個前人痛點：

  • 2604.26311 DreamProver 直面「前人庫學習的引理幾乎不被重用」（LEGO-Prover 的痛點）。它的解法是把「重用」做成第一目標：語意分群讓引理夠抽象、樹編輯距離去重、LRU 遺忘維持 <100 條緊湊庫。消融數字 104→76→53（移除 wake-sleep 精煉→再移除語意分群，甚至低於無庫）強力證明「緊湊抽象庫 > 龐大低階庫」。

  • 2603.25975 Schank-primitive 把 wake-sleep 當「認知科學假說檢驗工具」——不是為了解題，而是問「人類概念 primitive 是否在資訊論上被證成」。

  • 2602.00929 TheoryCoder-2 把 wake-sleep 從「離線壓縮程式庫」搬到「互動式 RL 規劃」：wake 是用 PDDL 運算子規劃、sleep 是跨 episode 累積抽象庫。它最大的貢獻是把 theory-based RL 對「人工手寫抽象」的依賴自動化掉，只留「極簡 prompt 模板控制抽象粒度」這一點人工。

2.3 主軸三：庫維護——三道防膨脹閘門

庫學習的隱藏難題不是「怎麼加抽象」，而是「怎麼不讓庫爆掉」。庫一大，三件壞事同時發生：檢索變慢、語意重複塞滿、低價值項稀釋高價值項。本批給出三道互補的閘門：

閘門 機制 代表作 解決的具體病
遺忘 LRU 淘汰最少用項，維持固定容量 DreamProver <100 條 2604.26311 庫無限增長、檢索成本爆炸
語意去重 e-graph 等式飽和 / anti-unification / 樹編輯距離 eggp 2501.17848、jazz e-graph 2605.04622、DreamProver 語意等價式的無窮參數化變體反覆入庫
次線性檢索 typed DAG 級聯檢索（符號簽章剪枝→描述→規格→範例） CoCoDA 2605.08399 扁平文字索引讓檢索成本隨庫大小線性、撐爆上下文預算

這三道閘門處理的是容量、重複與檢索，尚未涵蓋技能從准入到退役的整段生命週期。Agentic Skills Systems 2608.29596 把 skill 定義成可獨立版本化、依狀態延遲綁定的程序資產；候選入庫前要經測試、sandbox、形式證明或人工核可，路由時要把工具權限納入啟動條件，執行後還要驗證前後條件、局部修補，並維護來源、依賴與退役策略。這使「防膨脹」從庫的幾何問題擴成供應鏈治理問題，補上本節三道閘門之後的准入與失效邊界（本檔補註，非作者自陳）。但這篇是系統性綜述，沒有作者自建實驗；它建立的是設計語言與證據清單，不是某套生命週期架構已優於三道閘門的實證。

eggp 的等式圖去重 2501.17848 是「語意去重」最乾淨的範例：GP 搜尋反覆重訪語意等價的表達式，eggp 把編譯器的等式飽和接進 GP，強制交叉／變異只產生「未曾訪問過」的式子——極簡修改就追平 SOTA、模型更小更可靠。同樣的 e-graph 技術在 2605.04622 用來把「先窮舉所有 parse 再壓縮」的 Catalan 級爆炸剪到可行。

CoCoDA 的 typed DAG retrieval 2605.08399 把「防膨脹」與「LLM 上下文預算」綁在一起解：昂貴的 LLM 計費紀錄只在逐級收縮的候選集上實體化，使檢索成本對庫大小次線性。它精準點出 DreamCoder/Stitch（程式碼感知但無 token 預算分層）與 CodeRAG/RAPTOR（為 LLM 但扁平嵌入）之間的「缺失象限」。實證上 8B 學生靠這套庫匹敵 32B 教師（GSM8K 93.67 vs 93.40）。

CoCoDA 解的是大庫裡如何找到候選，SkillZip Pro 2608.30785 接著問候選被壓縮、搬動後是否還能照原路徑執行。它把根檔、參考檔、子 skill、schema、script 與 asset 編成帶載入作用域的資源圖；每次移除都要提出字面包含、覆蓋保留轉換或受限邏輯蘊涵的 witness，導航、公開入口與鎖定工件則列為不可破壞的契約。作者自報的 held-out 實驗在事前設定的非劣性界線內降低多層 token 成本，無 witness 的激進壓縮卻造成明顯準確率損失。這補上 CoCoDA 沒處理的安全壓縮缺口：可檢索不等於仍可達、可組合，也不等於能安全刪除（本檔補註，非作者自陳）。

一個橫貫結論：2604.26311 的消融（緊湊庫 104 > 龐大低階庫 53）與 2605.08399 的次線性檢索，從兩個方向證明了同一件事——庫的價值不在大，在「抽象、緊湊、可檢索」。這直接呼應 §2.1 的 MDL：庫本身的 cost(L) 是要被算進去的。

2.4 主軸四：歸納 vs 轉導，以及它們在「庫」上的分工

「歸納（induction）：先求函式 f 再套用」vs「轉導（transduction）：直接預測輸出」是 ARC 圈的經典二分（見 [[deep/self_improving_program_synthesis.md]] §2 的完整展開）。在「庫學習」視角下，這條軸有一層新意義：

  • 歸納路線天然產出可入庫的抽象——程式、邏輯子句、PDDL 運算子都是可重用、可組合、可驗證的離散物件。本批的庫學習幾乎全在歸納側。
  • 轉導路線難以累積抽象——直接 map 到輸出的神經模型沒有「可抽出的零件」。ArcMemo 2509.04439 的巧妙之處正在於給轉導路線補一個概念庫：把解題軌跡蒸餾成自然語言概念，不更新權重就能跨題重用，在 ARC-AGI-1 上 55.17→59.33。

PLVR 2608.28421 把「可入庫的離散物件」再推進一步：能力不寫回 base model 權重，而是存成由 typed neural primitive、deterministic primitive 與 operator 組成的顯式程式。每層 populated ontology 同時攜帶型別和值；symbolic backpropagation 從目標輸出反推下一層所需 ontology，contract violation 則在後續層執行前剪除，並成為可定位至 layer 與 primitive 的重訓證據。相較 TheoryCoder-2 的 PDDL 抽象與 NLI 的離散 token，PLVR 補上了「抽象入庫時如何留下逐層驗證與修補位置」這一格（本檔補註，非作者自陳）。它也替歸納側的優勢劃出邊界：型別只保證 well-formed，組合爆炸仍靠 global beam 控制；中間產物不可檢查的開放生成任務不在其適用範圍。

2509.17393 SYNTRA 是這條軸上最有意思的「和解」：它不二選一，而是用轉導當篩子去選歸納的產物——枚舉一批與訓練對一致的候選程式（歸納），再用 LLM 當 transduction 模型對測試輸入產偽標籤，逐一淘汰不一致的假設。把「在程式輸出定義的有限假設類上做主動學習」這個視角講清楚了，任務準確率最高提升 196%。

2604.18907 NLI 則想在單一可微框架裡同時拿到「符號的組合強度」與「神經的靈活性」：inductor 出離散 token 程式、interpreter 遞迴可微執行、test-time 梯度搜尋啟用 OOD 泛化。消融顯示「離散性 + 遞迴執行」是泛化命脈（拿掉就崩到近 0%），且學到的程式展現原語的系統性重用（單次左移恆用 token 231）——泛化來自重用而非記憶，這正是庫學習的精神在可微框架裡的迴響。
