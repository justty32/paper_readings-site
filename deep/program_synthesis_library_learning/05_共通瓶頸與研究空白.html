5.2 有前景的方向

  1. 把「DSL / 背景理論的生成」也納入庫學習迴圈。 目前 2507.16405 的 SONF、2411.17708 的 DSL、2606.24245 的謂詞庫都手工。若能讓系統像 DreamProver 抽引理一樣演化自己的 DSL/metarules，就把「程式級」與「元層級」庫學習打通。這是全批最一致指向的空白。

  2. wake-sleep × LLM 演化的合流。 DreamCoder 的 sleep 壓縮（2604.26311 2603.25975）擅長「發現抽象、防膨脹」；FunSearch 譜系（2512.13857 2606.26173）擅長「LLM 當突變器探索」。把「LLM 突變」當 wake、把「MDL 壓縮 + 去重 + 遺忘」當 sleep，是一條兩邊都缺、且明顯互補的路——EvoLattice 的「累積微算子庫」訴求與 DreamCoder 的「壓縮成庫」機制正好對接。

  3. 執行引導補進庫學習的驗證環。 GridCoder 已論證「執行引導是結構泛化的解方」（proxy 10%→80%）但未實作；SYNTRA 已證「轉導偽標籤淘汰假設」有效。把「每步執行回饋」接進「抽象的入庫驗證」，能讓庫只收結構正確的抽象。

  4. 統一的庫維護理論。 §2.3 的三道閘門（遺忘/去重/次線性檢索）目前各做各的。一個把 MDL（2603.25975）、e-graph 去重（2501.17848）、typed 檢索（2605.08399）、LRU 容量（2604.26311）統一在單一目標下的「庫維護理論」尚不存在，但四篇的零件已備齊。

  5. 離線 presynthesis 思想搬進 LLM 合成。 2604.13290 的「把昂貴的可達性分析移到離線、線上只做快速 slicing」是經典合成的關鍵突破；LLM 合成目前幾乎全線上。把「離線預算好可重用結構、線上快速復用」搬進 LLM agent 的技能庫，可能複製 SQL 上「90× 加速」的收益。

  6. 可微庫學習。 NLI 2604.18907 證明「離散語言 + 可微解釋器」能端到端學出可重用原語（泛化來自重用）。把 DreamCoder 的離散 wake-sleep 與 NLI 的可微執行結合，可能讓「庫學習」第一次變成可梯度優化的端到端目標。

6. 給讀者的一頁速記

  • 程式合成與庫學習是同一迴圈的兩半圈：庫決定你能搜到什麼程式，搜尋產物決定哪些抽象該進庫。DreamCoder 的 wake-sleep 是這個互相依賴關係的標準解法，本批 2604.26311 2603.25975 2602.00929 是其直系後代。
  • 抽象的價值由壓縮效用（MDL）定義，不由頻率。同一條壓縮壓力跨事件語意（2603.25975，Huffman/BPE 類比）、爵士和聲（2605.04622）、定理證明（2604.26311）、符號迴歸（2501.17848）都成立——壓縮是領域通用的歸納偏置。
  • 庫維護有三道防膨脹閘門：遺忘（LRU 2604.26311）、語意去重（e-graph 2501.17848 2605.04622）、次線性檢索（typed DAG 2605.08399）。「緊湊抽象庫 > 龐大低階庫」被 DreamProver 消融（104→53）硬證。
  • 六支社群正在合流到 LLM：經典 FTA 合成（2604.13290）、ILP（2507.16405 2606.24245）、LLM 演化（2512.13857 2606.26173 2605.15308 2606.07704 2606.04360）、神經引導（2411.17708 2411.08706 2604.18907 2509.17393）、agent 技能庫（2602.00929 2605.08399 2509.04439）。LLM 多當「突變器/偽標籤器/抽象合成器」插進既有框架，而非取代搜尋。
  • 接 ai_core：庫維護三閘門就是一台現成的半自動固化引擎，LRU=撤照、e-graph=去重、MDL=固化判準——直接回答 ai_core §3.6「固化引擎手動 vs 自動」的最硬未決問題。
  • 接 AI 設計討論：EvoLattice 2512.13857 的「節點=插槽、替代方案=競標者、路徑分數=出清、替代統計=信用分配」幾乎就是「插槽市場」的可執行骨架。
  • 最大空白：自動長出 DSL/背景理論本身（元層級庫學習）；wake-sleep 壓縮 × LLM 突變的合流；統一的庫維護理論。
