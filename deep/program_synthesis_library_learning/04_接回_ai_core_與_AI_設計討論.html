4. 接回 ai_core 與 AI 設計討論

4.1 ai_core：「貴智能產生可重用抽象 → 便宜智能高頻復用」與固化引擎

ai_core 的北極星（見 [[deep/cross_fusion_aicore_aidesign.md]]）是把智能切成兩種資產：貴稀有智能＝資產工廠（聰明、一次性、生產可重用抽象），便宜高頻智能＝資產消費者（笨、高頻、復用抽象）。本批的庫學習譜系，幾乎就是這條北極星的「學術版實證」：

ai_core 概念 本批對應的「現成零件」 啟示
資產工廠（貴、一次性） DreamProver 的 sleep 階段抽引理 2604.26311；TheoryCoder-2 的 LLM 合成 PDDL 抽象 2602.00929；FunSearch 譜系的 LLM 突變 2512.13857 2606.26173 「貴智能離線生產抽象」不是比喻，是已被多領域實證的可行管線
可重用抽象（折舊很慢的資本） DSL / 引理庫 / PDDL 運算子 / e-graph 等價類 / 技能 DAG composite 抽象的形式可以是程式、邏輯、運算子、概念——但都須「抽象、緊湊、可檢索」（§2.3）
資產消費者（便宜、高頻） CoCoDA 的 8B 學生靠庫匹敵 32B 教師 2605.08399；ArcMemo 的便宜檢索注入 2509.04439 「便宜模型 + 好庫」能恢復貴模型級績效——這是 ai_core 經濟學的硬證據
固化引擎（§3.6 最硬未決：手動 vs 自動） 庫維護三閘門（§2.3）就是一台現成的半自動固化引擎 見下

對 ai_core「固化引擎誰做」這個最硬未決問題，本批給出三條可直接借用的機制：

  1. 遺忘＝撤照的自動版。 ai_core 的「撤照」（有確定性解法就把 LLM 留白踢出）對應 DreamProver 的 LRU 遺忘 2604.26311——追蹤每個抽象的使用頻率，低頻者自動淘汰維持固定容量。把「撤照」從手動決策升級成 LRU 自動機制，是 §3.6 的最小可行答案。

  2. 語意去重＝防止固化出一堆重複資產。 ai_core 的元件庫若無去重，會塞滿語意等價的 snippet。eggp 的等式圖去重 2501.17848、DreamProver 的樹編輯距離去重 2604.26311 是現成解。

  3. MDL 當「該不該固化」的判準。 ai_core 目前「該固化什麼」靠工程直覺；§2.1 的 MDL 給了一個有原則的閘門——只有當「這個留白被固化後省下的成本 > 固化它的維護成本」才固化。這正是 2603.25975 的 savings = n·c_old − (c_lib + n·c_new) 公式，可直接搬成 ai_core 證書欄位的一個量。

一句話：ai_core 的固化飛輪（生產→固化→淘汰）與 DreamCoder 的 wake-sleep（解題→壓縮→遺忘）是同一台機器的兩種語言。ai_core 缺的「自動固化引擎」，DreamCoder 譜系已經跑了八年。

4.2 AI 設計討論：插槽市場 / 元件庫

AI 設計討論的核心機制（見 [[deep/cross_fusion_aicore_aidesign.md]] (a)(c)）是 DreamCoder 式元件庫 + bucket-brigade 經濟信用分配 + 插槽市場：貴的搜尋發現元件、便宜的復用，用經濟機制（財富/破產淘汰）做信用分配。本批與它的對應極為直接：

AI 設計討論機制 本批最接近的實作 可互補之處
元件庫（DreamCoder 式） DreamProver 引理庫、CoCoDA 技能 DAG、TheoryCoder-2 抽象庫 本批提供「元件庫」缺的工程外殼：去重、次線性檢索、LRU 容量管理
插槽市場（每個插槽是一個待填位置） EvoLattice 的「節點存多個並存替代方案、每條路徑＝一個候選」2512.13857 EvoLattice 的 DAG 幾乎就是「插槽市場」的可執行版：節點＝插槽、替代方案＝競標者、路徑分數＝市場出清
bucket-brigade 經濟信用分配 EvoLattice 的「替代方案層級統計（均值/變異/最佳貢獻）」、CoCoDA 的「saved-call credit」2605.08399 本批的信用分配是「結構訊號」（DAG 展開大小、路徑分數），比純財富數字更可被審計、不可瑣碎利用
破產淘汰 EvoLattice 的「單調擴張＋ targeted 刪除」、DreamProver 的 LRU 本批給「淘汰」加了 MDL 判準與容量上限，避免淘汰過激或不足

最強的握手點是 EvoLattice 2512.13857 ↔ 插槽市場。 AI 設計討論想要「插槽 + 競標 + 信用分配」，EvoLattice 把它做成了一個具體可跑的 DAG：

  • 插槽 = DAG 的節點（功能組件）；
  • 競標者 = 該節點存的多個並存替代方案（alternatives）；
  • 市場出清 = 對「每個替代方案出現的所有路徑」逐一評分，產生替代方案層級統計；
  • 信用分配 = 用這些統計（均值效應、最佳貢獻、高斯擾動量測的節點重要性）餵 LLM 做下一輪突變；
  • 防膨脹 = 確定性自我修復（保無環/依賴一致）+ targeted 刪除。

AI 設計討論若要落地「插槽市場」，EvoLattice 是現成骨架；反過來，AI 設計討論的「bucket-brigade 經濟」可以給 EvoLattice 補一層「替代方案要不要付出維護成本」的破產機制，治它自承的「長期結構膨脹」局限。
