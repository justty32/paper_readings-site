地圖：可靠性是一條迴路

具身 Agent／VLA 的可靠性不能由單一成功率代表，因為一次動作是否可信，同時取決於系統看見了什麼、記住了什麼、如何處理失敗，以及模擬證據能否落到真實世界的公制控制。（本檔補註，非作者自陳）本章回答五個軸為何必須一起讀，並為量測、記憶、失敗恢復、sim-to-real 與空間接地各立一個錨點。安全不是另一項平行能力，而是這條迴路每次更新狀態、選擇動作與放行新技能時的准入判準。（本檔補註，非作者自陳）

一、終局成功與過程可信互相衝突

一句話地圖是：量測把行為拆成可驗證的過程證據，記憶把證據維持成當下狀態，偵測與恢復依狀態選路，sim-to-real 判斷低成本證據可以外推到哪裡，空間接地再把語意與不確定性轉成真實動作；執行結果則回流，改寫下一輪的測試、記憶、規格與准入。（本檔補註，非作者自陳）

這張圖的第一個矛盾，是任務完成不等於過程可靠。（本檔補註，非作者自陳）IS-Bench 把安全條件綁到會引發風險的動作，區分動作前必須成立的 pre-caution 與動作後必須恢復的 post-caution，並把任務成功與安全成功分開計量。2506.16402 明示安全推理能改善風險處理，卻可能犧牲任務完成；直接給定安全目標後表現又大幅改善，瓶頸因此包含風險察覺，而不只是約束遵循。2506.16402

量測軸的錨點便是「觸發事件加過程 predicate」，而不是多做一個終局評審。（本檔補註，非作者自陳）只看最後場景，會把先造成傷害再補救的軌跡算成安全，也會把記憶錯誤、幾何錯誤與控制失手壓成同一個失敗標籤。（本檔補註，非作者自陳）中間分數可以指出斷點，卻未必能證明成因；後面的記憶與空間評測都必須守住這條界線。（本檔補註，非作者自陳）

可靠性議程把同一問題放到整個生命週期。2606.03593 它主張讓測試、組合式驗證與 runtime assurance 共用結構化表示，保存模組假設、不確定性、保證與 fallback，並讓部署時的假設違反回流到規格與情境生成。2606.03593 該文是研究議程，沒有量化實驗，也沒有證明一套已完成的整合架構。2606.03593 因此，本綜述把「迴路」當成閱讀與設計契約，不把它寫成已有論文完成的系統。（本檔補註，非作者自陳）

二、記憶決定恢復是在修正，還是在重複犯錯

第二個咬合是記憶與恢復不能分開驗。（本檔補註，非作者自陳）MEMOBench 用可執行的 Storage、Update、Compression checkpoint 檢查資訊是否寫入、舊狀態是否修訂，以及長歷史是否被壓成可行動的任務狀態；prefix completion 則避免模型碰巧達到後段 predicate，就冒領前序進度。2609.07047 它顯示物件記憶表現好，不代表 temporal、spatial 與 procedural memory 也可靠，而且起初存到資訊不代表後續會正確更新與使用。2609.07047

記憶軸的錨點因此是「經環境 predicate 驗證的當下狀態」，不是聊天歷史變長，也不是模型聲稱自己記得。（本檔補註，非作者自陳）若容器已傾倒，記憶仍保留「可沿原策略前進」，重試就會把一次偏差放大成連續失敗；反過來，若環境仍有效，只因夾爪姿態偏離就整段重置，又會浪費仍可利用的進度。（本檔補註，非作者自陳）

FLARE 把這個分界實作成 Retry／Reset 路由。2608.26645 世界仍在有效任務狀態、只有機器人姿態偏離時，由主任務策略銜接回正確動作；環境前提已被破壞時，才切到物件中心的 Reset 專家，恢復後再回主任務。2608.26645 人類指定 Reset 優於自動路由，表示「有恢復技能」與「知道何時切換」是兩種能力（本檔補註，非作者自陳）。2608.26645

失敗恢復軸的錨點不是 retry 次數，而是可恢復邊界：先查任務前提是否仍成立，再決定續跑、重置、停止或升級。（本檔補註，非作者自陳）這也說明為何過程記憶要先於恢復。（本檔補註，非作者自陳）沒有可信的狀態真相，分類器只能猜錯誤類型；恢復動作改變物理世界後，又必須產生新證據，觸發記憶更新與重新驗收。（本檔補註，非作者自陳）未知 OOD 失敗、多步重置與動態人機環境仍未被 FLARE 的預建技能庫涵蓋，這一段跨任務、跨平台的恢復效果尚待實測。2608.26645

三、模擬能保留排名，不等於控制已跨過物理落差

第三個矛盾發生在 sim-to-real 與空間接地之間。（本檔補註，非作者自陳）R2S-Eval 校準真機幾何、運動學、控制介面、相機與初始化，再讓策略於模擬器做 closed-loop rollout，以匿名影片的成對偏好聚合策略排序。2609.03276 作者把證據邊界放在「模擬側能否保留真機的相對比較結論」，並未宣稱單條模擬 rollout 與真實物理等價。2609.03276

sim-to-real 軸的錨點是「先用真機校準代理結論，再決定哪些重複試驗可以搬到模擬」，而不是把擬真畫面視為轉移證明。（本檔補註，非作者自陳）這個限制很重要：排名一致可以支援模型選擇，卻不能單獨證明接觸力道、恢復路徑或安全邊界在真機上相同。（本檔補註，非作者自陳）若模擬器漏掉的因素恰好是安全關鍵條件，平均排序正確仍可能放行危險策略；這個風險尚待跨 embodiment、複雜接觸與動態場景實測。

VA-Bench 從另一端揭露代理證據的落差。（本檔補註，非作者自陳）它要求模型從 RGB 示範抽出程序，主動選視角，在沒有物件姿態、深度、相機校準或 oracle trajectory 的條件下輸出公制笛卡兒命令，並依執行回饋修正。2609.19554 目標定位與空間關係診斷較好，仍不能保證接觸操作成功；局部物件放置進展也沒有自然組成嚴格的長時域成功。2609.19554

空間接地軸的錨點便是「主動補證據後的公制重定位」，不是靜態圖片上的關係問答。（本檔補註，非作者自陳）模型需要把「杯子在盤子左邊」轉成相機、機器人與物件共享座標下的位移、旋轉與接觸決策，並讓執行回饋改寫下一步；否則語意正確仍可能在最後幾公分失敗。（本檔補註，非作者自陳）VA-Bench 的軌跡標註能定位可見斷點，作者也提醒它不能在沒有介入實驗時，越權把失敗歸因給感知、規劃、數值 grounding 或執行。2609.19554

兩篇合讀後，模擬證據與空間接地形成一個必要張力：前者追求低成本、可重複的比較，後者逼系統為每次真實動作承擔幾何與接觸誤差。（本檔補註，非作者自陳）最合理的接口不是要求模擬證明一切，而是把其保真的結論類型寫清楚，將未被證明的公制與安全假設帶到真機 gate 驗收。（本檔補註，非作者自陳）這種跨層不確定性傳遞仍缺共同表示與系統性實驗，尚待實測。

四、能力成長得經過准入，迴路才不會變成漂移

第四個咬合是泛化與更新治理。（本檔補註，非作者自陳）π0.5 把多種 robot embodiment、web 視覺語言資料、高階 subtask 標註與人類口頭指令放入同一套 VLA 共訓，並由同一模型先產生語意子任務、再輸出連續動作。2504.16054 這條路能把不同來源的語意與控制經驗帶到未見住家，但作者也記錄了重複開關抽屜、有限 context 與記憶，以及不適合跨房間長期追蹤等限制。2504.16054

這裡的矛盾是：增加資料可擴大行為分布，卻不會自動產生可稽核的狀態更新、恢復理由或安全證明。（本檔補註，非作者自陳）共訓模型可作為能力底座，前述過程 checkpoint、恢復路由、代理校準與公制 gate 仍要各自留下證據；否則「在新場景做得到」容易被誤讀成「知道何時不該做」。（本檔補註，非作者自陳）

Weights or Skills 把更新路徑分成能力固化於權重的 VLA，與可生成、修補、搜尋及保存程式技能的 code-as-policy agent。2608.01851 該綜述指出 Feedback、Memory、Search 三者合流的系統仍少，第三方技能的來源、跨形體可攜性、安全驗證、前置條件與效果詞彙也缺乏公認治理方式。2608.01851

更新准入的錨點因此是「新權重或新技能必須攜帶來源、適用假設、測試證據、可恢復邊界與撤回條件」，而不是只要一次任務成功就寫入資產庫。（本檔補註，非作者自陳）權重路線難以局部稽核，技能路線較可檢視與替換，卻增加組合、來源與調度風險；兩者都必須回到同一套量測與 runtime gate，沒有哪一派能跳過驗收。（本檔補註，非作者自陳）這套共同准入契約目前是綜合八篇後提出的設計要求，尚待實測。

本綜述與既有地圖的分界也放在這裡。純 LLM agent 的故障攔截、責任定位、工具副作用與恢復語意，直接接到故障治理綜述，本章只處理它們進入感測、接觸與實體狀態後新增的限制。形式規格、可靠函數與可接受解區域，接到可靠函數綜述，本章不重建其數學框架。這裡保留的問題只有一個：證據如何沿「量測→記憶→恢復→模擬代理→公制控制→安全准入」傳遞，又如何由真實執行返回起點；少掉任一段，其餘局部高分都不能單獨背書實機可靠性。（本檔補註，非作者自陳）
