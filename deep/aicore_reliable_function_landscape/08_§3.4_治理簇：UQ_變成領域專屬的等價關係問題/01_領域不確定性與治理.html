9.5 §3.4 治理簇：UQ 從「選哪個分數」變成「這個領域該用哪種等價關係」

§8.1 曾列一個待驗證題目——把三條品質分數路線（黑箱一致性／模型自評／白箱內部表徵）在同一個任務上做成本×效果對照。這批直接補上：2406.15627 LM-Polygraph 在同一套 11 個任務上並行測了 10+ 方法，給出清楚的選型樹——短輸出靠資訊型分數（MSP、CCP）、長輸出反而是取樣多樣性方法（SAR、DegMat NLI、語意熵）逆轉勝出，且常被忽略的簡單基線 MSP 在短輸出上近乎無敵，任何新方法都該先證明贏過它。2503.15850 用「輸入／推理／參數／預測」四維度把 30+ 方法整理成選型決策表，補上「按不確定性來源」這條既有地圖沒有的分類軸。2504.19254 uqlm 給出工程收尾：把任何方法族壓成 0–1 標準化分數、用可調集成取代「押一個贏家」。

但壞消息一起來：2602.05073 把選型焦慮延伸到 agentic 場景，τ²-bench 上既有 UQ 方法（NLL、熵、口語化信心）的軌跡級 AUROC 只有 0.47–0.69，幾近隨機——單輪 QA 的選型智慧在多輪 agent 軌跡上目前沒有能打的答案。

比選型結果更關鍵的新發現：UQ 方法不是領域通用的。 一換到 ai_core 真正在意的節點類型，既有共識常被推翻：

  • 工具呼叫：2604.22985 首次評測 function-calling UQ，發現「多樣本一致性通常優於單樣本」這條在文字 QA 上成立的經驗法則被反轉——FC 場景 token 機率平均高達 0.97（NL QA 僅 0.71）、語意簇數量極少，多次取樣買不到額外鑑別力，單樣本 G-NLL 已足夠；拒絕最不確定的 30% 呼叫可讓 Simple 任務準確率升到 96%，是把 UQ 接成工具准入閘門的直接數字。
  • 程式碼：2605.28500 Functional Entropy 揭露瓶頸完全不同——語意熵賴以聚類的 NLI 蘊涵在程式碼上幾乎失效（超過 80% 的 prompt 候選全塌成一個群集，AUROC≈0.5），換成 LLM 判斷的功能等價後才恢復鑑別力。
  • 多 agent：2603.28360 CoE 把不確定性拆成 intra-model（UA）與 inter-model（UE）兩分量——四象限中「低 UA、高 UE」（每個模型都很有把握卻彼此矛盾）是既有單模型 UQ 完全看不見的危險狀態。
  • 檢索：2603.19281 URAG 發現乾淨檢索下準確度與不確定性本應強負相關，混入無關文件後這個相關性直接被打破；且對 LLM 已擅長的任務噪音影響小，對知識薄弱的任務則「選哪種 RAG」比「要不要 RAG」更重要。

四篇合起來的教訓：通用語意熵／NLI 聚類是文字 QA 的產物。ai_core 每個節點類型都得重新定義「什麼算等價／一致」，不能把同一套 UQ 直接套用到所有節點。

「gate 必須比它省下的更便宜」被推向兩個新極端。 2604.06389 SELFDOUBT 的 HVR=0 gate 甚至不需要一次額外前向或探針——單靠推理軌跡裡 hedge／verify 詞彙的計數，就在約四分之一覆蓋率下拿到 96.1% 精確度，完整分數以約十分之一成本在 AUROC 上顯著擊敗語意熵。2506.09669 Internal Confidence 則把 gate 搬到生成之前：對查詢做一次 forward pass、只看模型自評就能判斷「這題答不答得出」，比生成後再驗證快 30–600 倍。兩篇分別往訊號來源（免機率、免探針）與決策時機（免生成）探底。

2307.02764 給級聯退讓補上既有地圖缺的理論件：貝氏最優延後規則是「下游答對機率 − 當前答對機率 > 呼叫成本」，只看當前信心的信心式延後只在下游錯誤率均勻時最優；一旦下游是專家、有標籤雜訊、或分布偏移就會系統性失準，此時需改用只吃上游輸出訓練的 post-hoc 規則逼近最優。這把「憑證何時可信」從「有沒有信心分數」精煉成「這個信心分數在此下游配置下是否還是貝氏一致估計器」。

共形保證陣營繼續擴張並拿到工業驗證。 2405.01563 用自評一致性當分數、共形風險控制校準出對幻覺率的嚴格上界，並首度給出「match 函數本身也可共形校準」的做法；2605.04295 在共形化前先用叢集脆度自適應膨脹不確定性，修正硬聚類語意熵對「表面一致但事實錯」的誤判（FPR@95 相對降低 35.4%）；2607.16868 從另一角度修正聚類假設——用蘊涵圖把「說法不同但邏輯收斂」的答案正確歸為低不確定性，只有根假設互斥才拉高分數。但 2607.20526 ConfidenceBench 潑了一盆必要的冷水：15 個前沿模型的實測顯示準確度與校準品質是正交的兩個維度——選擇「哪個模型當憑證簽發者」不能只看它答得準不準。

自我改進的失效模式延伸出兩條既有地圖沒有的軸線。

第一條是成本軸：2306.09896 用成本核算重新檢視「有測試存在」（本應是強接地）的自我修復，發現一旦把回饋與修復的呼叫算進預算，同模型自產回饋的增益往往微薄甚至為負——瓶頸不是接地強度，而是「模型評判自己程式碼哪裡錯」的能力，只有換更強模型或真人出回饋才明顯解放（人類回饋把修復通過率從 33.3% 拉到 52.6%）。有接地也不保證划算，回饋源必須比被評估者更強。

第二條是記憶寫入層：2606.24428 EDV 把「自我簽發者＝被簽發者」的污染模式（既有地圖已在 Self-Rewarding 見過）搬到 agent 長期記憶——單一 agent 既執行、又總結、又決定寫入，會把「錯但自洽」的軌跡當成功寫入，注入 10% 這類污染軌跡使 Pass@1 從 82.5 暴跌到 77.2。解法是把執行／蒸餾／驗證三角色解耦後才准入記憶，且消融顯示只解耦驗證角色而不擴大執行多樣性效果有限——直接呼應 §6.2「入庫要審查」，但把審查對象從技能庫合併延伸到 agent 經驗記憶的每一次寫入。

驗證器的細粒度化持續下探，並第一次被推進訓練迴圈與歸因本身。 2302.08468 LEVER 用僅約 0.5% 生成器大小的小模型讀「問題＋候選碼＋執行結果」判正誤並對執行結果相同的候選做邊際化；2402.16906 LDB 把驗證粒度砍到 CFG 的 basic block、逐塊比對真實 runtime 變數值而非讓 LLM 自己心算執行流（Self-Debug 2–3 輪即停滯，LDB 持續改善到 20 輪）。兩篇的共同啟示：驗證的可靠性上限由「錨定在確定性執行的真值」決定，粒度越細越能把 LLM 擠出「判斷對錯」，只留給它「解釋／修補」。

2207.01780 CodeRL 展示驗證訊號不必只做推論期過濾——critic 預測測試結果可直接餵進 RL 的 token 級密集獎勵，把驗證器從「事後把關」延伸到「訓練期的梯度來源」，這是既有驗證器四來源表沒有的新軸線。2401.08500 AlphaCodium 的 test anchors 把「已通過測試不可退步」做成強制閘門，擋掉被自產測試誤導而改壞碼的風險；2305.04087 Self-Edit 則把「執行回饋→修復」蒸餾進一個獨立的 110M 小型故障感知編輯器——修復迴圈本身也能被固化成便宜資產，不必每次都叫大模型自我除錯。

最後，2606.09071 REFLECT 把錯誤歸因本身變成需要被驗證的憑證，而非事後敘事：先診斷候選錯誤步，對該步注入結構化修補計畫做前綴保留式重播，只有重播結果從錯誤翻轉為正確，才機械地採納這個回溯點。這補上既有地圖完全沒有的一塊：多步軌跡裡「哪一步該負責」必須靠介入後的結果翻轉驗證，不能相信 LLM 自己對軌跡的敘述。對照 2303.11366 Reflexion 易失、跨題不保留的情節記憶，REFLECT（歸因要可驗證）與 EDV（寫入要多方共識）分別把 Reflexion 留下的缺口往前推了一步，但都還沒回答「這個反思何時該從自然語言升級成確定性程式碼」——§3.6 的核心問題依然開放。

對既有結論的修正：

  1. §6.1「品質分數已是選型問題」被收窄而非推翻：選型比想像中更深——還要按應用領域（工具呼叫／程式碼／多 agent／RAG）重新定義「什麼算等價」。2604.22985 甚至反轉了「多樣本一致性通常優於單樣本」這條在本庫其他地方成立的經驗法則。三分光譜仍是入口，但終點分數必須按節點類型客製化。
  2. §6.5「無外部接地則自我改進崩潰」被加了一個新警訊並收窄：2306.09896 證明有接地（測試存在）也不保證划算——同級自產回饋的自我修復在成本核算後常打平甚至倒虧。ReST^EM 式確定性接地仍是最強正證不變，但光譜中段的定位從「有效但普通」修正為「經濟上常不划算」。
  3. §6.2「入庫要審查」延伸並量化到 agent 記憶的逐次寫入層（2606.24428），屬補完。
  4. 約束非免費、便宜端應專用兩條既有結論本批未觸及，無修正。
