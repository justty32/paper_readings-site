9.2 §2／§3.3 成本梯度：測試時運算長成第三軸，語意快取補上驗證與位置

這批 24 篇沒有推翻查詢尺度（級聯／路由）與生命週期尺度（蒸餾）的骨架，但把 token 尺度從「4 個無損案例」擴成一條完整光譜，並新開一整條軸——測試時運算預算（TTS），這是初版與 §6 都沒處理過的。語意快取則從一則帶警告的孤例，長成解決驗證、位置、容量與交互作用的完整堆疊。

查詢尺度：本批替 §6.1「品質分數從哪裡來」補上四個具體答案。2407.10834 MetaLLM 把選模重構成 contextual bandit，reward 直接寫成「準確率 − p·成本」——一個係數就是成本梯度旋鈕，且路由決策本身完全不呼叫任何 LLM。2404.14618 Hybrid LLM 改問「小模型追得上大模型的機率」，並誠實暴露失效邊界：兩模型能力差距夠大時樸素路由器幾乎退化成隨機，得靠鬆弛標籤救回——這是 FrugalML 最優性保證「一離開有限標籤集就退回啟發式」在真實模型對上的具體案例。2310.03094 Mixture-of-Thought Cascade 則直接證偽「該訓一個外部評分器」的預設：微調評分器或 LLM 裁判的準確率明顯低於讓弱模型自己在 CoT 與 PoT 兩種思維表徵間互檢一致性——因為換示範集常犯同一種錯（一致但假），換表徵才會暴露真正的不確定性。這給 §6.1 三分光譜補上第四條路線：跨表徵互檢。2310.03046 EcoAssistant 則示範查詢尺度與固化引擎怎麼疊加——便宜模型先試、失敗才升級，成功的 query-code 對存進同一案例庫回頭教便宜模型，GPT-4 平均呼叫次數 2.51→1.25，是「系統對貴智能的依賴隨使用遞減」少數有具體數字的案例。

token 尺度：初版只有 4 個範例，本批把它撐成完整光譜，答案是「便宜端不必永遠是第二個神經網路」。2305.09781 SpecInfer 把單序列驗證推廣成 token tree＋樹狀平行解碼並證明輸出分佈與逐步解碼相同，成為後續 2311.08252、2308.04623、2406.16858 共用的驗證骨架。2309.08168 Draft & Verify 讓同一個 LLM 跳過部分中間層當草稿、全層前向當驗證，跳哪些層由貝氏優化離線搜一次後固化成固定向量——昂貴搜尋只做一次、之後便宜複用在 token 粒度的縮影。2402.02057 Lookahead 把自回歸解碼重寫成 Jacobi 迭代，連 draft 模型都省掉，且是與推測解碼正交的加速軸。2311.08252 REST 把便宜端換成非參數檢索資料庫，資料庫放大即持續獲益。2406.16858 EAGLE-2 解決「便宜端該花多少力氣」——關鍵發現是草稿信心與真實接受率幾乎落在對角線上，於是可以不查詢昂貴的目標模型就估出動態草稿樹該往哪展開，正是 §6.1「gate 必須比它省下的更便宜」在 token 粒度的翻版。2308.04623 Staged Speculative 把梯度遞迴分層到最底層是 N-gram 統計；2302.07863 BiLD 的 fallback/rollback 則是 token 級的憑證准入。整條光譜合起來：便宜端從「神經網路」逐步退到「跳層的同一模型」「純算法自產」「檢索資料庫」「N-gram 統計」——正是 §3.6 固化引擎在毫秒級時間尺度上的預演。

測試時運算——新的第三軸：兩篇綜述（2503.24235 四維分類學、2507.02076 L1 可控／L2 自適應二層分類）讓 TTS 第一次有了與級聯／推測解碼同級的系統化地圖。更關鍵的是實證：2512.02008 大規模量測發現 beam search 在推理任務上呈現反向擴展，且最優策略取決於模型的 RL 訓練方式（short-horizon vs long-horizon），沒有放諸四海皆準的策略。2604.10739 進一步指出「想更久」為何反噬——出現 correct→incorrect 的翻轉事件，肇因於遞迴自我懷疑與過度複雜化。這是 §6.5「Self-Refine 敗在回饋端」在推理軌跡內部的鏡像：即使沒有外部批評步驟，光是「繼續想下去」本身就可能推翻正確答案，所以「何時該停止想」和「何時該呼叫」同樣需要治理。2501.19393 s1 把這條軸具象成顯式旋鈕（追加 "Wait" 延長、注入截斷標記），且千條精選軌跡已逼近數萬條隨機樣本的效果。

語意快取的工程成熟：這條「成本梯度終點＝不呼叫 LLM」的路線，過去只有一則帶警告的孤例（門檻寫死、缺乏線上驗證），本批四個面向都補上解法。2602.13165 Krites 用非同步 LLM 法官只對「相似度灰色地帶」做驗證、核准後寫入可回收的動態層——等於把 §3.4 憑證准入原封不動搬進快取層，且不阻塞服務路徑。2604.20021 把離散有限查詢集換成連續嵌入空間並給出次線性 regret 保證，其後驗變異數正好是「這次命中要不要再驗證」所缺的信心訊號。2601.16286 SemanticALLI 的洞見是位置比演算法重要：把檢查點從攔截整個 prompt 搬進管線內部的結構化中間表徵，命中率 38.7%→83.1%（使用者措辭多變，但下游模板反覆重複）。2605.18825 把問題從「該不該命中」擴展到「容量有限時該丟什麼」，補上從未點名的快取容量治理子問題。

2607.15516 則是警告而非增益：prompt caching 與 prompt compression 這兩個各自成立的省錢技術疊加時會互相拆台——query-aware 壓縮讓每次呼叫產生不同前綴、等於每次 cache miss，實測反而比不壓縮貴 40.1%。「多套幾招省錢手段」不是預設安全的加法。 2601.20577 MeCo 把記憶化原則搬到多機器人任務軌跡層級並用重用率給出可操作的固化判準；2511.15715 Graph-Memoized Reasoning 補上理論骨架，把「重算 vs 重用」形式化為 min Cost + λ·Inconsistency，替以上工程實作提供共同的目標函數。

蒸餾邊界則多了一個新軸：2505.17612 Agent Distillation 不蒸餾答案也不蒸餾符號知識，而是蒸餾完整的「思考→行動→觀察」軌跡，讓小模型在分佈外任務上比同規模 CoT 蒸餾泛化更好——因為工具執行提供的是與 §6.5 grounding 光譜同一種確定性接地訊號。這沒有推翻 2301.12726「小模型能力零和」，而是補上一個維度：蒸餾什麼（是否含接地校驗）跟蒸餾多少一樣重要。

對既有結論的修正：一項實質修正、一則新警告，其餘屬補完。

  1. 語意快取的核心風險已降級：此前記錄的「門檻寫死、線上缺乏二次驗證」，現由 2602.13165 的非同步法官（事後審查）與 2604.20021 的後驗變異數（事前信心量化）兩路補上，從「無解」變成「兩條可操作路線」。
  2. （新警告）省錢手段不可無腦疊加：2607.15516 證明快取與壓縮疊加會互相拆台，併入 §3.3 設計紀律。
  3. TTS 作為第三軸、token 尺度光譜化、蒸餾的「內容維度」都是補完，未改變 §7 總表列出的「實際收益低於理論」這個缺口。
