5. §5 下層受約束填碼——「收窄輸出」的技術光譜

ai_core 程式碼助手的下層要「受約束填碼」。本批把「把 LLM 輸出收窄到合法空間」鋪成一條可選型的光譜：

  • 收窄的原型與工程化：2109.05093 PICARD 是「推理期外掛約束、逐步剔除非法 token」的原型（無效 SQL 12%→2%，beam 4 勝事後過濾 beam 64——早剔除比事後過濾划算，直接支撐 §3.2「前濾網」）；2403.01632 SynCode 把它工程化到 sound/complete 的 CFG＋離線 DFA mask store，撐起通用語言全文法。
  • 免微調換掉大模型：2305.13971 GCD 最貼 ai_core「剃除 LLM 依賴」——把結構化 NLP 任務全表述成文法約束生成，免微調的 few-shot 就勝過專訓模型；確定性約束換掉了訓練。
  • 填空能力的訓練學基礎：2207.14255 FIM 證明「前綴-後綴-中段」資料重排即可免費獲得填空能力——這是「上層定骨架、下層填洞」那個「填洞節點」的訓練學根據。

5.1 工具使用：把「意圖」接到確定性工具

「受約束填碼」的近親是「受約束地呼叫工具」——讓 LLM 只負責產意圖、由確定性工具執行：

  • 2210.03629 ReAct 是執行迴圈原型（推理與行動交錯、外部 API 接地把 CoT 幻覺失敗 56%→0%）——「LLM 節點＋確定性工具節點交替」的最早範式。
  • 2302.04761 Toolformer 讓 LLM 自監督學會何時呼叫工具（以損失下降篩選 API 呼叫）＝§3.4「必要性閘」雛形。
  • 2305.15334 Gorilla 把執行端縮小：微調 7B 準確產 API 呼叫勝 GPT-4（AST 子樹匹配判幻覺）＝「LLM 退縮到意圖→工具映射」的便宜高頻端；但它也警告——檢索器本身必須是高可靠確定性節點（接不完美 BM25 反挫 52%）。
  • 2303.12570 RepoCoder（迭代檢索-生成倉庫級補全）與已入庫 2506.10021（持久 Lisp 元編程迴圈）補上「填碼要接倉庫上下文」與「工具庫可跨回合演化」兩塊。

5.2 2026-09 補入：從「限制輸出」走到「分配真值權」

Programmable World Model 把 §5 的分工移到世界模型：可執行引擎保存身分、狀態與轉移真值，生成模型只負責畫素呈現。這比語法遮罩更深，因為它不是規定模型「怎麼說」，而是把「什麼為真」整段移出生成器（本檔補註，非作者自陳）；現有數字只支持粗粒度狀態一致性，不能外推成完整實體對應的驗證2609.10540。

DREAM 把同一骨架落在 sim-to-real 資料工廠：LLM 只能組合既有 predicate，TAMP 與物理 checker 決定軌跡能否入庫。它佐證「LLM 出候選、符號層出准入」，也補上一個反例邊界（本檔補註，非作者自陳）：符號與物理可行不等於資料對每個消費模型都有用，SmolVLA 在 FruitPacking 使用更多合成資料仍未改善（作者自報）2608.29078。

GAVEL 則把確定性層從否決器升成修補器：圖世界模型若能由前置條件唯一推出缺少的導航、開啟或恢復動作，就直接補上；只有證明鏈斷掉的語意缺口才退回 LLM。這填補既有工具使用段落只寫「模型產意圖、工具執行」的空白，並提醒不確定位置應保留分布，等新觀察到來再重排，而不是過早壓成單一答案（本檔補註，非作者自陳）2609.19315。
