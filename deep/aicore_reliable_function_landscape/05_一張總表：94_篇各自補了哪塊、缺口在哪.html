三個最該記住的跨篇結論（2026-07-22 更新）：

  1. 同一個缺口出現兩次 → 已補上，但變成選型與成本問題。FrugalML→FrugalGPT 丟掉的最優性保證（§2.1）與治理憑證（§3.4）確實是同一個 missing piece，而現在它有三條技術路線（黑箱一致性／模型自評／內部表徵）、可升級成統計證書（PAC、conformal）、可細到逐主張粒度。新的關鍵約束是**「gate 必須比它省下的更便宜」**——2406.15927 SEP 與 2311.08692 Zooter 給出同一個解法：把昂貴判斷蒸餾成單次前向。詳見 §6.1。
  2. 接地訊號有正反鐵證 → 升級為一條按接地強度排序的連續譜（§6.5）。最有用的單一發現是 2303.17651 Self-Refine 的失敗歸因：敗在回饋端而非精煉端——所以 ai_core 該優先剃除的是評估端的 LLM，生成端可以留著。
  3. 固化引擎難在時機 → 時機問題已有可操作答案（§6.2）：價值判準用「省下多少搜尋」而非壓縮長度、決策要前瞻、入庫前要審查、抽象後仍需保留小案例集。真正剩下的開放問題換成了「退役」——2604.17308 證明放任會技能膨脹與碎片化，但沒人給出庫的收斂機制。
  4. （新）約束不是免費的：2606.21619 證明約束器對規格不完整時，功能正確率反而輸給無約束解碼（最多倒退 97%）。「加了約束就更可靠」是錯的——約束器與規格的對齊度必須被當成可量測的量。詳見 §6.3。
  5. （新）便宜端應專用而非通用：2301.12726 證明小模型能力零和，特化到多步推理會讓通用 CoT 能力歸零。這修正了「蒸餾成小一號通才」的預設，並反過來支持「多數確定性節點＋少數 LLM」的分工。詳見 §6.4。

8.1 下一批該找什麼

已結案：本節三個方向即 batch2/3/4 的搜尋依據，回收成果與逐條判定見 §10；新的下一批方向在 §10.3。

本次擴充把 backlog 清空，但 §7 總表也浮出三個現有文獻沒答的問題，可作為下一輪找論文的方向：

  1. 技能庫／抽象庫的退役與收斂機制——2604.17308 證明放任會膨脹碎片化，但「何時刪、怎麼把技能收回策略內」無人給機制。關鍵字：skill library pruning／forgetting、abstraction retirement、library convergence。
  2. 節點從 LLM 退化成確定性程式的自動化路徑——2605.17734 把技能變成程式函式，但觸發與退役仍靠啟發式；ai_core 想要的是「這個 LLM 節點的行為已被案例覆蓋到可以換成程式碼了」的自動判定。關鍵字：LLM call replacement／memoization to code、behavioral coverage。
  3. 約束器與規格的對齊度量測與自動補完——2606.21619 只提出兩條修復路徑（微調模型／完整化約束器），都還沒有系統性作法。關鍵字：constraint completeness、specification-constraint alignment。

另外兩個由本次閱讀衍生、但屬於「驗證假設」而非找缺口的題目：把 §6.1 的三條品質分數路線在同一個任務上做成本×效果對照（現有論文各測各的）；以及 2603.23244「省搜尋」與 MDL「壓縮長度」兩種固化價值判準的直接比較。
