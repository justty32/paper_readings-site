9.4 §1 計算圖與 agent 架構：§1 與 §3.6 在「編譯」這個動作上合流

這批 28 篇把 §1 原本停在「優化 prompt／拓撲」的敘事往兩個方向推進：一是推到「連圖結構都自動生成」的極限後，出現一群真正把整張圖編譯掉的論文；二是把「LLM→確定性」的退化模式從程式碼／技能庫，擴散到長期記憶治理與工具介面兩個新戰場。

§1 內部的深化：2410.10762 AFlow 把「節點＝帶 prompt 的 LLM 呼叫、邊＝程式碼」的圖交給 MCTS 自動搜結構與 prompt，讓小模型以極低成本反超前沿模型；2406.11695 MIPRO 補上另一種信用分配範式——貝氏代理在無梯度、無模組級標籤下聯合優化多節點的指令與示範，教訓是「示範優化幾乎總是比指令優化更有效」；2412.03624 證明 TextGrad 的鄰居無關假設不成立，且消融顯示拿掉「更新閘」（只有驗證集變好才接受更新）準確率從 71.2% 崩到 49.2%——這其實是把 §3.4 的憑證准入原則直接搬進圖優化本身。2506.08234 綜述把這些方法收進「結構彈性×學習訊號」2×2 地圖並點名痛點（NL 回饋優化缺收斂理論、meta-LLM 優化成本失控），是 ai_core 該往「彈性＋可編譯成程式碼」象限走的論文級佐證。2408.08435 ADAS 把這條線推到理論頂點（meta agent 用圖靈完備程式碼發明整個 agent 系統），但它是反方向操作——讓 LLM 生出更多 LLM-heavy 的 agent，恰好標出 ai_core 要剃除的邊界：可當上游探索器，真正的固化仍需下一步。2312.07104 SGLang 與 2212.06094 LMQL 補上這條線缺的執行棧：LMQL 是「prompting is programming」的學術源頭（逐 token 遮罩＋健全性證明），SGLang 給出生產級 runtime（前綴快取命中率過半、壓縮 FSM 一次解多 token），證明「圖當可執行程式」不只是比喻。

真正跨過 §1／§3.6 邊界的是四篇「編譯掉整張圖」的論文。 2604.05150 Compiled AI 讓 LLM 只在編譯期出現一次，產物經安全／語法／執行／準確度四階段驗證後部署為靜態程式碼，BFCL 上零 LLM 呼叫達 96% 任務完成率、57–84× token 節省、約 17 筆交易即攤平編譯成本。2605.22502 更激進——連 55 節點、6 決策樞紐的完整多步驟程序都全參數微調進 3B–8B 權重，部署時連抽象庫與外部編排器都不需要，128–462× 成本節省、重編譯只要 30–50 分鐘。2605.13647 FlowCompile 提供第三種產物型態：不是程式碼也不是權重，而是部署前一次性探索出的 accuracy–latency Pareto 配置集，換偏好只需輕量選擇。2605.01293 Lifting Traces to Logic 把同一命題推進 agentic 長時程任務內部——互動軌跡被提升為以一階邏輯驅動、帶條件分支與迴圈的可執行工作流圖，失敗時局部嫁接修補而非全局重生成。

四篇說的是同一件事：「編譯」不是單一形態，可以是程式碼、權重、配置集，也可以是邏輯工作流圖。

長期記憶治理可以是固化引擎的一種型態：2605.17596 NeuSymMS、2604.02734 雙記憶框架、2603.15280 NS-Mem、2601.15311 Aeon 共享同一分工——神經端只做相似召回，符號端做確定性執行與稽核——把固化光譜延伸出三條新軸線：使用者事實（LLM 萃取候選事實→規則引擎做分類／矛盾偵測／真值維護，存取次數達門檻自動晉升長期記憶）、程序性知識（頻繁序列挖掘→LLM 驗證→門檻→固化成 Procedural DAG，邊權重隨觀測收斂）、經驗與可行性雙軌（成功軌跡→神經藍圖式進展記憶，失敗轉換→編譯成可執行驗證函數的可行性記憶）。

2606.25115 CURATOR 把 §3.4「拒絕為預設＋憑證准入」從「該不該呼叫」延伸到「該不該留、該不該傳、該不該信」——用單一淨值／位元組分數同時治理三項決策，證明遺忘低淨值位元組是修復而非削弱（記憶縮小、注入攻擊成功率歸零、準確率不降反升）。2606.19847 AtomMem 則潑一盆冷水：表示品質優先於編排複雜度——拿掉分層與圖檢索的扁平變體反而在多跳推理大幅勝出且 token 最省，提醒固化引擎別急著疊架構，先把儲存的基本單元做對。

2606.01435 與 2509.26433 把「LLM→確定性」的退化樣板推廣到記憶衝突解決與分類任務本身：前者證明「LLM 判斷新鮮度」有兩個系統性失敗模式（訓練先驗蓋過上下文規則、候選池變大時追丟最大值），換成 max(serial) 一行 Python 就拿到 +10.8～+21pp、且隨上下文變長差距擴大；後者證明分類節點可整個退化成訓練期用 TextGrad 優化分裂、推論期只走確定性決策樹。兩篇合起來說明：該剃除的不只是整段工作流，任何「LLM 反覆做同一種簡單判斷」的節點都是候選。

多智能體編排的可靠性邊界：2308.08155 AutoGen 的消融直接證明「拿掉確定性守門節點就出事」（移除棋步驗證代理後出現非法棋步）。2606.27243 NOVA 把這原則搬到生產級推薦系統：提出「架構梯度」聚合驗證診斷／離線指標／軌跡記憶當非可微更新訊號，並把驗證失敗轉成禁區方向回饋進搜尋本身，搭配風險分級決定自動執行或人機協作。2510.25445 綜述給出上位框架：符號範式主宰安全關鍵域、神經範式主宰資料豐富自適應域，治理必須是範式特定的、不能一刀切——這解釋了為何鬆散的多代理對話編排需要領域專屬的驗證級聯才能落地。

工具介面：從模型卡走向可稽核合約，但合約深度不是免費的。 既有地圖點名 2303.17580 HuggingGPT 的模型卡「無型別／契約保證」是缺口，2606.07904 Contract2Tool 直接補上——從文件＋執行軌跡的混合證據推斷 (precondition, effect, risk, cost) 四元組合約，並證明軌跡證據不可替代（純文件只在 84.1% 步驟暴露正確的下一步工具，混合證據才到 100%）。2305.11554 ToolkenGPT 給出更輕量的對照組（工具當一個新 token、只學一個 embedding 掛進凍結 LLM 的輸出頭）；2308.00675 確立中間立場——文件本身就能讓零樣本追平甚至超越少樣本，且在工具規模化時是唯一還撐得住的方法。2605.19077 ReacTOD 把合約落到執行期（LLM 只提議、確定性符號驗證器攔截所有狀態變更，絕大多數違規靠結構化錯誤回饋一次修正），證明「架構對，模型可以小」。

但 2603.00718 SkillCraft 給出這條線最重要的警示：工具技能可以組合，但組合深度不是免費的——分層巢狀技能的單步執行率仍有 95–99%，端到端成功率卻從 90% 反降到 79%，因為錯誤在巢狀鏈裡複合放大。這與 §6.3「約束不是免費的」是同一種代價結構的另一個實例，只是代價軸換成組合深度。2602.21320 Tool-R0 則補上生成端的答案：完全零人類資料的 self-play 也能讓「意圖→工具」映射自然浮現。

對既有結論的修正：

  1. §1 與 §3.6 在「編譯」這個動作上已經合流。原本 §1 說「這些框架的節點目前多半仍是 LLM……真正的差異化仍在 §3.6 固化」，把兩者當成接續但清楚分開的階段。2604.051502605.225022605.136472605.01293 四篇證明「編譯掉整張圖」本身就是可規模化、有明確經濟帳本（攤平點、百倍級節省、數十分鐘重編譯週期）的生產技術，不再是「先優化、之後才固化」的線性順序。
  2. §3.4 的範疇被擴大而非推翻：2606.25115 把憑證准入從「該不該呼叫」擴展到「該不該留／傳／信」。
  3. （補完） 2606.19847 與 2603.00718 分別在記憶與工具兩側證明「表示／組合深度存在甜蜜點，過度編排或過深巢狀都會反噬」——同一代價結構在新維度上的實例。

本節跳過 3 篇：2508.00604（OS 核心層 AI 願景，無量化證據）、2606.12683（AGI→ASI 路線願景）、2605.24238（生成認知哲學立場）——皆為願景型論述，與「可靠函數／固化引擎」的命題無可驗證接點，列在 index 但不納入本地圖。
