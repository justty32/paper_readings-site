9.3 §5 約束器與規格對齊：語法已見頂，代價有定理，規格缺口被系統性填補

既有 §5 停在「語法約束的光譜」（Outlines／PICARD／SynCode／GCD）與「約束不是免費的」這句警示。本批 35 篇把這條線一次推進四步：約束該收到多深、代價有多精確、代價怎麼繞開、規格不完整這個病根有沒有系統性解法。

一、語法早已不是天花板，型別才是。 2504.09246 實測 SOTA 開源模型生成的 TypeScript：語法錯誤只占編譯錯誤的 6%，其餘 94% 都是型別錯誤——理想化的語法約束上界本來就低（HumanEval/MBPP 只能減 9.0%／4.8%），而型別約束直接把編譯錯誤砍半以上（−75.3%／−52.1%）。這修正了既有地圖只講「語法約束引擎選型」時的隱含預設。2510.10216 TyFlow 給出同一目標的另一端：不在推理期外部拒絕，而是把型別推導樹與合成決策序列做成同構、訓練期就內化型別系統，與 2504.09246 的「推理期外掛護欄」構成「固化 vs 護欄」的互補選項。

二、「約束不是免費的」從觀察升級為定理，三條獨立路線收斂到同一解法。 2502.09061 CRANE 用複雜度理論證明：輸出限制到有限文法、單步生成的 LLM 等價於常數深度 TC⁰ 電路，原則上解不了 NL-complete 問題，而無約束／CoT 保留圖靈完備的表達力——這把 2606.21619 的實證「約束器不完整就倒退」升級成「即使約束器完整，過嚴的約束本身就有複雜度代價」的定理級陳述。2604.06066 給出對應的實證慘案：把整套診斷 schema 壓進 8B 模型反思階段，準確率不升反降，絕大多數首輪診斷淪為格式不符、超過半數樣本陷入死迴圈——結構雪崩，是幻覺雪崩的對偶失敗。2603.03305 則把代價精確量化：每步 KL 失真恰等於 log（1/可行質量），累積成「投影稅」。

三篇分別給出解法，卻收斂到同一原則——把自由推理與受限實現拆成兩階段，稅只在最後一哩繳：CRANE 只在填最終答案時才約束、2403.06988 DOMINO 用最小侵入＋橋接 token 對齊保住準確率並同時加速、2603.03305 的 DCCD 乾脆先無約束起草再約束。2511.22277 TreeCoder 把六種解碼策略與四級約束（語法／型別／執行／測試）統一進同一樹搜尋框架，證實「約束—規格對齊度決定增益或損失的方向」是可操作的設計軸，而非偶發現象。2405.21047 則提供這條代價的形式化診斷（GCD 扭曲分布的成因與修正）。

三、工程開銷已被打到近零，代價因此被純化成「語意對齊」一個變數。 2411.15100 XGrammar（context-independent/dependent token 分治＋自適應快取）、2407.08103（detokenization＝FST 的統一理論框架，編譯加速數個量級）、2502.05111 GreatGramma（離線預處理再快一個量級，並揭露既有引擎的健全性錯誤）、2602.22647（Trie 向量化，生產環境每步僅增加微秒級延遲、線上零違規）——四篇把「準備約束」與「執行約束」的成本壓到可忽略。

這使 2501.10868 JSONSchemaBench 在真實上萬個 schema 上的結論格外關鍵：受約束解碼在真實任務上是淨收益而非稅。這與第二步的負面結果不矛盾，是任務依賴的——當 schema 只是鬆散包住答案（{"reasoning":…,"answer":…}）約束幫忙；當 schema 本身就是與推理緊密耦合的多類別語意判斷（如 2604.06066 的診斷分類）約束就傷。「工程開銷」與「語意對齊代價」是必須拆開看的兩個維度，混為一談會誤判約束的淨值。 2602.00612 把同一套問題延伸到擴散 LLM：非自迴歸生成使「合法前綴」的定義本身失效，作者用前瞻取樣＋文法剖析器重新定義可靠約束（每步都必須存在合法完成路徑）。2211.15458 ReLM 則從另一側示範同一機制的第二種用途——把 LLM 行為測試形式化為正則查詢。

四、約束器第一次被證明是安全攻擊面，這是既有地圖完全沒有的新軸。 2606.11817 CodeSpear 指出：一旦套上普通的程式碼文法約束，自然語言的拒絕語句因不在合法輸出空間內而被排除，模型被迫在從未經過安全對齊的 code modality 中繼續生成惡意碼（本地攻擊成功率 54.92%→81.82%、商用 API 22.00%→67.39%），且攻擊零成本、無需對抗性文法。防禦解法是在 code modality 內重建安全偏好（蜜罐碼：語意無害＋結構多樣），把成功率壓回個位數。這揭示一個此前從未觸及的原則：安全憑證是模態綁定的——任何改變輸出空間的約束機制，都要有自己的安全閘，不能只靠自然語言層的對齊。

五、規格對齊從「無系統性作法」變成一條完整光譜，是本批對既有地圖最大的填補。 2604.16198 REA-Coder 最早介入——生成前先用問答清單校準模型對需求的理解，消融顯示拿掉「語意遮罩恢復驗證」比拿掉問答對齊傷更重，呼應 §6.5「敗在回饋端而非精煉端」。2509.01313 Specine 與 2505.07270 SpecFix 走中段：前者用雙代理偵測 LLM 對規格的感知偏誤再以十條需求工程規則對齊，後者把程式分佈當 LLM 詮釋的代理、用語意熵＋對比推斷做最小文字修補且跨模型可遷移。2607.02949 BeSpec 走最深——不比對測試結果，而是預測可檢查的行為義務再與觀察行為逐項比對定位規格缺口；失敗分析顯示對齊後僅 4.4% 的剩餘失敗仍歸咎規格模糊（Specine 13.1%、SpecFix 8.9%），意味著行為層對齊幾乎把「規格不夠」這個病根榨乾，剩下的是純演算法難度。

四篇合起來，直接填補 §8.1 方向三點名的缺口——現在有了一條「越早介入增益越大、越深入行為層越能定位真因」的可操作光譜。2212.10561 Parsel 與 2605.01562 從兩端補強：前者示範「規格分解→組合搜尋→測試驗證」的完整閉環，後者示範規格合規本身可以做成純確定性、可審計的硬閘，而非另一個 LLM 判斷。2510.08623 PARSE 則提出把 schema 當可優化介面而非固定合約的第三條路。

六、程式合成的形式保證閉環，成熟度已超出既有地圖記錄的「僅受限語言成立」。 2604.16584 LeetProof 用「PBT→SMT→互動證明」三層遞增成本的過濾把 vericoding 壓到可負擔規模，多模態管線比單模式 Lean baseline 多出六成以上的完全認證解，並順手揪出既有 benchmark 約一成的規格缺陷。2511.21104 BRIDGE 更關鍵：用「函數式推理鷹架」當生成 Lean 前的中介表徵，不只提升正確率與樣本效率，還可以被 SFT 內化——形式驗證的輔助結構第一次從「prompt 技巧」變成「可學習的歸納偏誤」。2502.05714 FVAPPS 揭露新瓶頸：LLM 偏好命令式證明雖易編譯卻幾乎無法做歸納證明。2605.10712 AutoSOUP 把「LLM 只做有界子任務、確定性分析驅動全流程、每個 LLM 輸出都要再過確定性驗證」搬到記憶體安全單元證明，九成以上目標可驗證並揪出多個新漏洞——這是「LLM-as-function-call」在形式驗證域最落地的產業實證。

七、庫學習的「審計」缺口，與約束器不完整是同一個病根的兩種病徵。 2410.20274 對 LEGO-Prover 與 TroVE 的雙系統解剖是本批最尖銳的一記：LEGO-Prover 學了超過兩萬條引理，只有約 6% 曾出現在最終 prompt 裡、逐字重用僅 1 次；TroVE 的函數在三千多題測試集上只成功重用 3 次。最小改動消融顯示真正的增益來自自我修正與自我一致性，不是庫重用。

但這不是「固化無效」的翻案——2310.00656 LEGO-Prover 自己的受控消融（固定取樣預算下有庫 50.4% vs 無庫 47.1%）確實測到真實貢獻且隨庫成長擴大。真正被推翻的是「宣稱重用就等於真的重用」。這與 2606.21619 在 §5 層揭露的病根同構：兩者都是「機制看似在把關／加速，但沒人真的驗證憑證是否被兌現」。強化（而非重複）§3.4 的治理原則：入庫准入的第一審計指標應是實際重用次數，不是壓縮率或整體準確率差。

同批裡，庫候選的確定性准入驗證本身也在多樣化：2212.04596 babble 用 e-graph＋反統合把 Stitch 的純語法去重擴充到語義等價（快 1–2 個數量級、能處理大 10–100 倍的語料）；2410.06438 Leroy 示範同一想法搬到命令式語言的真實代價；2307.13883 ExeDec 改在執行空間而非 token 空間分解子目標，組合泛化顯著提升；2504.04942 Lemmanaid 與 1804.04152 Atlas 是「神經出模板、符號填細節」的兩個世代（前者用本地小模型即勝過前沿大模型）。2405.17514 AbstractBeam 給出最鋒利的警告：庫成長飛輪在分佈內顯著，換到分佈外卻毫無提升、反而更慢——再次確認抽象必須貼「適用分佈」標籤。

對既有結論的修正：

  1. §8.1 方向三的缺口大部分被填補：REA-Coder／Specine／SpecFix／BeSpec 構成一條可操作光譜。仍未到「無需人工設計對齊規則」的全自動程度，故非完全解決。
  2. §6.3「約束不是免費的」升級為定理級陳述：2502.09061 的 TC⁰ 證明，加上 CRANE／DOMINO／DCCD 三條路線收斂出的同一解法（推理與結構解耦、稅只在最後一哩繳）——從「小心約束」進化成「怎麼設計約束才不傷」。
  3. 型別級約束從 forward-pointer 變成實質內容：94% 編譯錯誤是型別錯誤而非語法錯誤，收窄了「把語法約束做得更完善就能大幅提升可靠性」的預設。
  4. §3.6「零件已就緒」新增一記收窄：2410.20274 證明代表性庫學習系統的重用率趨近於零、真實增益另有來源。不是推翻固化有效，而是把重用計數審計立為固化評估的第一指標。
  5. （全新維度）約束器＝安全攻擊面（2606.11817），不修正既有結論，屬純粹補完。

2026-09 補入：形式通過與語意相符之間仍要再設一道門。 SkillForge 把 Dafny verifier 的錯誤類別確定性路由到 atomic skill，補強本節「LLM 提案、符號驗證與修補」的骨架；但其 verification rate 與 behavioral equivalence rate 分別為 91.6% 與 86.5%（作者自報）。這個落差直接限縮「通過 proof 即符合使用者意圖」的讀法（本檔補註，非作者自陳）：形式檢查負責可判定契約，reference semantics 或另一個 equivalence gate 才負責規格是否寫對2608.29841。
