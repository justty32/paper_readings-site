3. 如何負擔得起又準確地使用 LLM

我們提出三種降本策略（圖 1(b)）：prompt adaptation、LLM approximation、LLM cascade。圖 2 以圖示說明五種省本手法。

策略一：Prompt adaptation（提示調適）

LLM 查詢成本隨提示大小線性增加，故縮小提示即可降本。

  • Prompt selection（提示選擇，圖 2a）：不用含大量示範範例的提示，而是只保留一小部分範例。挑戰在於「針對不同查詢該保留哪些範例而不損表現」。
  • Query concatenation（查詢串接，圖 2b）：逐一處理查詢會重複送出相同提示；串接的核心是只送一次提示、讓 LLM 一次處理多個查詢，避免重複處理提示。作法是把數個查詢串接成一個、並在提示中明確要求 LLM 處理多個查詢。

策略二：LLM approximation（LLM 近似）

若某 API 太貴，就用更便宜的模型或基礎設施近似它。

  • Completion cache（回應快取，圖 2c）：向 API 送出 query 時把回應存進本地快取（如資料庫）；處理新 query 時先查是否有相似 query 已回答過，有則直接取用，只有找不到相似 query 時才呼叫 API。當相似查詢頻繁出現（如 LLM 驅動的搜尋引擎有大量相同關鍵字）時省本可觀。
  • Model fine-tuning（模型微調，圖 2d）：三步——先蒐集昂貴 LLM API 對少量查詢的回應；再用這些回應微調一個更小更便宜的模型；最後用微調後模型回答新查詢。除省本外，微調後模型通常不需長提示，附帶改善延遲。

策略三：LLM cascade（LLM 級聯）

異質效能與成本的 LLM API 提供了「資料自適應選模型」的獨特機會——不同 API 對不同查詢各有強弱，適當選擇既能降本也能增效。**LLM cascade（圖 2e）**把 query 依序送給一串 API：若某 API 的回應可靠就回傳、不再往下；只有前面 API 的生成被判定不夠可靠時才查詢後面的 API。若前幾個 API 便宜且產出可靠，查詢成本便大幅降低。

兩個關鍵元件：

  1. Generation scoring function（生成評分函式） g(·,·): Q×A → [0,1]：給定 query 與某 API 產生的答案，輸出可靠度分數。可用一個簡單的迴歸模型訓練得到，讓它從 query 與生成答案學習「該生成是否正確」。
  2. LLM router（路由器）：選出要放進級聯的 m 個 API，記其索引為 L ∈ [K]^m。對新 query，依序呼叫第 i 個 API 得答案 f_{L_i}(q)，用評分函式算出分數 g(q, f_{L_i}(q))；若分數高於閾值 τ_i 就回傳該生成，否則查詢下一個服務。

學習 L 與閾值向量 τ 可建模為受約束最佳化問題：在「平均成本受預算 b 約束」下，最大化級聯停止處生成 f_{L_z}(q) 相對正解的品質（z 為 router 停下並回傳答案的 API 索引）。此問題本質是混合整數最佳化、計算昂貴，作者設計專用最佳化器：(i) 剪枝——忽略「答案分歧小」的 LLM 組合以縮小 L 的搜尋空間；(ii) 用少量樣本內插逼近目標函式；由此得到高效且表現令人滿意的實作。

Compositions（組合）：策略內與跨策略組合可進一步降本增效。例如 joint prompt and LLM selection（提示選擇 + LLM 級聯的組合）：為給定 query 尋找「能達到滿意表現的最小提示與最便宜 LLM」；又如同時在既有 API 與微調模型間搜尋。但組合也增加訓練的計算成本，因而開啟「查詢成本 / 任務表現 / 計算成本」三者取捨的研究空間。

4. LLM Cascade 降低成本並提升準確率

本節對 FrugalGPT 的 LLM cascade 做實證研究，目標有三：(i) 理解簡版級聯學到了什麼；(ii) 量化在匹配最佳單一 API 表現時省下的成本；(iii) 衡量表現與成本的取捨。

設定：API、任務、資料集、FrugalGPT 實例：從 OpenAI、AI21、CoHere、Textsynth、ForeFrontAI 共 5 家主流供應商選 12 個 LLM API（詳見表 1，成本於 2023-03 取得，可差達兩個數量級）。在三個不同任務的資料集上評估（表 2）：

  • HEADLINES（金融，10000 筆，提示 8 範例）：讀金融新聞標題判斷金價趨勢（漲／跌／中性／無）。
  • OVERRULING（法律，2400 筆，提示 5 範例）：判斷一句話是否為 overruling（推翻先前判例）。
  • COQA（段落閱讀，7982 筆，提示 2 範例）：對話式閱讀理解，改編為直接查詢回答任務。

聚焦級聯長度為 3 的 LLM cascade（簡化最佳化空間且已有好結果）。各資料集隨機切成訓練集（學級聯）與測試集（評估）。

案例研究（HEADLINES）：預算設 6.5 美元（GPT-4 成本的五分之一），用專為迴歸調整的 DistilBERT 當評分函式（比此處所有 LLM 都小、都便宜）。學到的 FrugalGPT 依序呼叫 GPT-J → J1-L → GPT-4：對任一 query 先取 GPT-J 的答案，若分數 > 0.96 即接受為最終回應；否則問 J1-L，其分數 > 0.37 即接受；否則才呼叫 GPT-4。有趣的是此法在許多查詢上勝過 GPT-4——例如標題「Gold off the lows after dismal U.S. GDP data」，FrugalGPT 正確預測金價下跌而 GPT-4 答錯。整體上（圖 3c）成本降 80%、準確率反高 1.5%（GPT-4：準確率 0.857、成本 33.1；FrugalGPT：0.872、6.5）。

LLM diversity（多樣性）：為何多個 API 可能勝過最佳單一 LLM？本質在生成多樣性——便宜 LLM 有時能答對昂貴 LLM 答錯的 query。以 **MPI（maximum performance improvement，最大表現提升）**衡量：LLM A 相對 B 的 MPI，是「A 答對而 B 答錯」的機率，代表在 B 之外再叫 A 可獲得的最大增益上限。圖 4 顯示市場內潛力可觀：在 HEADLINES 上 GPT-C、GPT-J、J1-L 各能把 GPT-4 表現最多再提升 6%；在 COQA 上有 13% 的資料點 GPT-4 錯而 GPT-3 對。這些上界雖不總能達到，卻證明用更便宜服務取得更好表現的可能。

成本節省（表 3）：FrugalGPT 匹配最佳單一 LLM 表現時的省幅介於 50%～98%：

資料集 最佳單一 LLM 該 LLM 成本 FrugalGPT 成本 省幅
HEADLINES GPT-4 33.1 0.6 98.3%
OVERRULING GPT-4 9.7 2.6 73.3%
COQA GPT-3 72.5 29.6 59.2%

之所以可行，是因 FrugalGPT 能辨識「小 LLM 就能準確回答的查詢」而只呼叫便宜模型，只把 GPT-4 這類昂貴模型留給它偵測到的困難查詢。

表現與成本取捨（圖 5）：

  • 成本排序不固定：如 J1 在 HEADLINES 是第二貴，而 GPT-3 在 OVERRULING／COQA 佔此位——源於異質定價（J1 每生成 token 貴但 input 不收費，GPT-3 則 input／output 都收費）。
  • 更貴不一定更準：如 HEADLINES 上 J1 比 GPT-3 貴但表現更差——凸顯即使無預算約束也該妥善選 API。
  • 平滑的表現—成本取捨：FrugalGPT 在所有資料集上提供平滑取捨，且可同時降本增準。例如 OVERRULING 上較最佳 API（GPT-4）準確率增 1%、成本降 73%（因整合了多個 LLM 的知識）；在相同成本下最多可提升準確率約 5%。
  • 例子也顯示：GPT-4 有時答錯而低成本 API 答對，FrugalGPT 能識別並只依賴便宜 API；單一 API 不總是對，級聯用一串 API 克服之。但 FrugalGPT 不完美——仍有「鏈中所有 API 給同一答案，但它不確定前面是否正確、被迫查完整條鏈」的浪費案例，如何避免屬未解問題。
