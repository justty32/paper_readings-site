2. 問題設定

技能契約（Skill Contract）。SkillOps 將每個技能建模為可執行契約，而非僅有名稱或文字描述。每個技能 s ∈ S 寫為 s = (P, O, A, V, F)，其中 P 是呼叫該技能的前置條件、O 是可執行操作、A 是技能產出的型別化 artifact、V 是對 A 的驗證器、F 是已知失敗模式集合。當 V = ∅ 時，技能沒有本地正確性檢查，我們稱之為驗證缺口。此契約形式使 SkillOps 能在執行前或執行後檢查相關性、適用性、可組合性與本地可驗證性。

層次技能生態圖（HSEG）。技能庫為 tuple L = (S, R)，其中 S 是技能集合、R 是技能之間的型別化有向關係集合。我們使用四種關係型別：

  • 依賴邊（dep）：si → sj 表示 si 產出的 artifact 可滿足 sj 前置條件的一部分，即 Asi ⊆ Psj。
  • 相容性邊（comp）：si → sj 表示 si 的輸出型別與 sj 所需的輸入型別相容。
  • 冗餘邊（red）：si → sj 表示兩個技能暴露等價介面，Psi ≡ Psj 且 Asi ≡ Asj。
  • 替代邊（alt）：si → sj 表示兩個技能目標相同但透過不同操作實作，goal(si) = goal(sj) 且 Osi ≠ Osj。

維護動作 M。SkillOps 使用一組型別化動作來維護庫：

  • merge(si, sj)：折疊由 red 邊連接的冗餘對。
  • repair(s)：使用執行回饋重寫操作 Os。
  • retire(s)：移除過時或持續失敗的技能及其附帶邊。
  • add_validator(s)：當 Vs = ∅ 時插入驗證器。
  • add_adapter(si, sj)：當 si 被 sj 需要但其介面不直接相容時插入型別轉換墊片。
  • instantiate(s, arg)：在任務時間將任務特定參數值綁定到參數化技能。

3. SkillOps：一個自我維護的技能生態系

3.1 任務時間迴圈：圖中圖規劃器

給定任務 τ 與庫 L = (S, R)，任務時間迴圈分為兩個主要階段：技能匹配與依賴拼接。

階段一——技能匹配。SkillOps 首先透過結合詞法與語意相關性對每個技能評分： r(s, τ) = λ·rBM25(s, τ) + (1−λ)·rsem(s, τ) 然後僅保留高分且前置條件被當前狀態滿足的技能：C = {s ∈ S : r(s, τ) ≥ θ}。這防止規劃器選擇文字相關但不可執行的技能。

階段二——依賴拼接。SkillOps 在 C 中搜尋同時滿足依賴與相容性約束的候選來建構計劃。從 si 到 sj 的轉換僅在 si → sj（dep）且 si → sj（comp）時被允許。因此，單有依賴是不夠的：技能轉換僅在產出 artifact 也匹配下一個技能預期輸入型別時才被接受。這避免了單邊依賴圖可能在執行時期才偵測到的介面不匹配。

階段三——驗證器與轉接器插入。若候選計劃包含一個非終端技能且 Vs = ∅，SkillOps 將離開 s 的邊標記為不可驗證，並在可能時插入驗證器節點。若依賴邊存在但無相容性邊，SkillOps 插入轉接器節點：si → aij → sj。轉接器 aij 僅在其輸出型別滿足下游前置條件時被接受：type(Aaij) ⊆ type(Psj)。因此轉接器並非自由形式的修補；它們是為了恢復被破壞的型別約束而插入的圖節點。

階段四——局部修復。執行期間，若技能 sk 失敗且剩餘計劃可恢復，規劃器嘗試以 alt 鄰居替代 sk，或使用觀察到的錯誤追蹤作為回饋重新調用 repair(sk)。若無法恢復，規劃器將失敗記錄到庫時間診斷緩衝區中以供後續維護。

3.2 庫時間迴圈：健康診斷與維護

五維健康診斷。每個技能 s 沿五個維度評分，每個維度針對一種常見的技能技術債形式：

  1. 效用 U(s) ∈ [0, 1]：最近任務調用成功使用 s 的比例，偵測膨脹檢索池的低價值技能。
  2. 冗餘 R(s) ∈ [0, 1]：包含 s 的最大 red 叢集的歸一化大小，偵測降低檢索精確度的近重複技能。
  3. 相容性 C(s) ∈ [0, 1]：與 s 相連的依賴邊中同時為相容性邊的比例，偵測產出 artifact 與預期輸入之間的介面不匹配。
  4. 失敗風險 F(s) ∈ [0, 1]：s 的經驗失敗率，偵測需要修復的執行時期破損技能。
  5. 驗證缺口 G(s) ∈ [0, 1]：定義為 1[Vs = ∅]，偵測可能允許無效 artifact 向下游傳播的缺失驗證器。

整體庫健康分數 H(L) 為這些維度的加權平均（使用均勻權重 wU = wR = wC = wF = wG）。這些維度共同涵蓋了跨使用頻率、複製增長、介面一致性、執行可靠性與驗證覆蓋率的技能劣化。

CGPD：契約圖傳播診斷。標準健康診斷獨立評估每個技能。CGPD 是一個額外的進階組件，沿 dep 邊傳播風險分數，使得對結構上健全但繼承高上游風險的技能能進行先發性驗證器插入。令 R(t)(s) ∈ [0, 1] 表示技能 s 在第 t 次迭代的傳播風險分數，Rloc(s) 為從五個健康維度計算的本地風險分數，Parents(s) 表示具有指向 s 的依賴邊的上游技能。CGPD 按以下方式更新風險： R(t+1)(s) = (1−α)·Rloc(s) + α·max_{s'∈Parents(s)} R(t)(s') 其中 α ∈ (0, 1) 控制傳播多少上游風險。根據 Banach 收縮映射定理，此更新收斂到唯一不動點。

維護程序。SkillOps 從執行追蹤計算技能層級健康信號，在啟用 CGPD 時沿依賴邊傳播風險，然後應用型別化維護動作：merge、repair、retire、add_validator、add_adapter。

3.3 演算法

任務時間迴圈（演算法 1）將 HSEG 視為可執行規劃結構：檢索候選技能、依前置條件過濾、僅透過依賴與相容性邊拼接、在需要時插入驗證器或轉接器、並在執行期間執行局部修復。庫時間迴圈（演算法 2）在執行後維護庫：計算健康信號、透過 CGPD 沿依賴邊傳播風險、並應用型別化動作。

3.4 插件介面

SkillOps 設計為技能庫維護的插件層。它不假設特定的下游規劃器或檢索器；而是將原始技能庫轉換為已維護庫，可直接被既有 agent 演算法使用：L' = run_maintenance(L)。此處 f : L ↦ L' 是純庫變換：它診斷並修復技能庫，但不需要存取下游 agent 的內部檢索、規劃或執行邏輯。因此任何檢索型或任務導向 agent 都可以透過以已維護庫替換原始庫來使用 SkillOps。下游程式碼保持不變。
