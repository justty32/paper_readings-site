4. 實驗

4.1 資料集

我們在 ALFWorld [Shridhar et al., 2021] 上評估 SkillOps，這是一個衍生自 ALFRED PDDL 資料集的純文字家居操作基準。ALFWorld 提供具有結構化動作序列的多步驟家居任務，適合測試技能檢索、組合與維護。

我們從 229 個精選 SkillsBench 技能 [BenchFlow AI, 2026] 建構技能庫。對於不超過 229 的庫大小，所有技能皆為真實精選技能。對於更大的庫，我們保留所有可用的真實技能並添加合成劣化變體以達到目標規模。這些劣化變體涵蓋六種常見技術債模式：冗餘複製、陳舊複製、缺失驗證器、缺失 artifact、錯誤介面、以及過度特化技能。我們評估九個庫規模，|L| ∈ {200, 250, 500, 750, 1000, 1250, 1500, 1750, 2000}，使用不同的取樣種子。

4.2 基線

我們將 SkillOps 與四個代表性基線比較：

  • ReAct [Yao et al., 2023]：Thought-Action-Observation agent，接收完整技能庫作為純文字提示。
  • LLM_Skill_Planner：基於 LLM 的規劃基線，要求 GPT-4o-mini 按語意相似度對技能排序，從排序列表中建構計劃。
  • Hybrid_Retrieval：結合 BM25 關鍵字檢索與 hashing-vectorizer 嵌入相似度。
  • GoS_Style [Liu et al., 2026]：最小化 Graph-of-Skills 風格基線，使用單一依賴邊型別進行計劃子圖提取。
  • SkillWeaver [Zheng et al., 2025]：自我修復技能使用基線，執行任務時間技能驗證與打磨。

所有基線使用相同的 GPT-4o-mini 骨幹、相同的技能庫與相同的 gold-argument 假設。

5. 結果

5.1 H1：SkillOps 獨立 vs 基線

在 ALFWorld 200 技能庫上，SkillOps 達到 79.5% SR（零標準差跨三種子），超越最強基線 LLM_Skill_Planner（70.6%）+8.9pp，以及 GoS_Style（61.1%）、Hybrid_Retrieval（58.2%）、SkillWeaver（50.3%）、ReAct（12.8%）。改進顯示型別化技能契約與 HSEG 式規劃提供了超越純文字檢索或僅依賴圖搜尋的好處——SkillOps 不僅檢索語意相關的技能，還檢查前置條件、綁定任務參數、並僅透過相容轉換拼接技能。

5.2 V4：即插即用插件有效性

SkillOps 作為純插件維護層時，持續幫助檢索型 agent：Hybrid Retrieval +2.90pp、BM25 Only +1.00pp、Dense Only +1.12pp。這支持了插件主張：維護庫使檢索候選池更乾淨，因此僅檢索方法較不會選中冗餘、陳舊或介面不相容的技能。對 LLM 規劃與圖規劃基線的效果較小，因為它們已有部分任務時間過濾能力。

5.3 V2：Token 成本分析

維護通常是中性或有利於 token 用量：35 個設定中 24 下降、4 近乎持平、僅 7 增加。最大降幅為 Dense_Only 在 lib=1000 的 −3.95%。主要原因為庫修剪：merge、retire 與 repair 在檢索前減少冗餘或劣化候選。

5.4 H2：庫規模敏感性

在控制雜訊分級壓力設定下（劣化密度從 15% 增至 90%），SkillOps 保持穩定。最大規模時 SkillOps 達 80.5% SR，領先次優基線超過 31pp。相比之下，僅任務時間的基線對雜訊候選池更敏感。

5.5 H3 消融：隔離主動機制

兩個迴圈與兩個圖層次都很重要。移除任務時間迴圈導致最大降幅（79.5% → 15.7%）。移除庫時間迴圈降至 71.9%。外部跨技能關係與內部技能契約的移除分別降至 64.6% 與 72.2%。在維護動作中，add_adapter、add_validator 與 repair 最關鍵（分別降至 13.2%、38.0%、55.9%），而 merge、retire 與 CGPD 有較小但可見的效果。

6. 結論

我們提出 SkillOps，一個用於 LLM agent 技能庫的庫時間維護框架。SkillOps 將技能形式化為型別化契約，組織進層次技能生態圖，並透過即插即用介面應用可觀測規則驅動的維護動作。ALFWorld 上的實驗顯示 SkillOps 改善了對強基線的任務成功率，在規則式維護迴圈中達到近乎零 LLM 調用，並揭示了維護效益是方法條件性的：檢索型 agent 受益最多、LLM 規劃型多為持平、自我修復型可能與外部維護衝突。這些結果顯示技能庫應被視為需要管理的軟體資產，而非靜態檢索池。

7. 局限

SkillOps 目前依賴結構化技能契約，並在某些設定下依賴 gold PDDL 風格參數，這些在真實部署中可能無法取得。評估的庫為半合成，主要基於 ALFWorld，因此需要更廣泛的基準與真實長期 agent 日誌。規則式維護迴圈近乎零 LLM 成本，但可能遺漏語意冗餘或需要更深層推理的複雜技能衝突。最後，CGPD 在當前設定中未能改善任務成功率，因為驗證器欄位尚未在計劃時間的技能選擇中被消耗。

附錄（節選）

A. 完整演算法（演算法 3 與 4）

任務時間迴圈使用當前 HSEG 作為可執行規劃基底：檢索候選技能、僅透過同時滿足相容性約束的依賴邊建構計劃、在執行前插入驗證器與轉接器以減少靜默介面失敗、在當前 episode 期間透過局部修復處理可恢復錯誤。

庫時間迴圈在任務執行後更新庫：檢查累積健康變化是否足夠觸發維護、計算技能層級健康分數、透過 CGPD 沿依賴邊傳播風險、應用型別化維護動作（merge、repair、retire、add_validator、add_adapter），將執行回饋轉換為持久性庫更新。

複雜度分析：N = |S|，k = 計劃長度，dmax = 最大 HSEG 出度。任務時間：技能匹配 O(N log N)、受限拼接 O(k·dmax)、驗證器/轉接器插入 O(k)。庫時間：健康診斷 O(N)，所有維護動作為線性掃描，合併使用 body-hash 查找為 O(N)。完整維護階段在 N=2000 時於標準 CPU 上不到一秒完成。

B. 資料集細節

ALFWorld 使用 json_2.1.1 標註版本，評估子集包含 185 個任務實例，計劃長度範圍 3 至 20 個高階動作（中位數 7、p90 12）。SkillsBench 提供 229 個精選 SKILL.md 檔案。

D. 實作細節

所有 LLM 方法使用 GPT-4o-mini。SkillOps 超參數：健康閾值 θ=0.5、BM25 檢索 top-k=10、LLM 語意評分器過濾 top-5、轉接器觸發 Jaccard 相似度 <0.3、局部修復最多 2 次嘗試。

G. 維護動作樁與劣化注入

六種劣化型別：冗餘複製（改 skill 名稱保留 body）、陳舊複製（改寫參考至棄用版本）、缺失驗證器（移除檢查清單）、缺失 artifact（清空子目錄）、錯誤介面（覆蓋 artifact.type）、過度特化（附加過窄標籤）。維護動作基於可觀測信號觸發：body-hash 碰撞、缺失驗證器、失敗日誌、缺失 artifact、型別不匹配。

K. CGPD 細節

CGPD 沿依賴邊傳播風險分數，無需標註失敗資料。由於上游項以 α<1 加權，更新在 ℓ∞ 範數下定義收縮，由 Banach 不動點定理保證收斂。在無環依賴圖中，傳播分數可在有限次數（受限於圖深度）內計算。CGPD 在 lib=1000 時改善 +0.5pp、lib=2000 時改善 +0.6pp。
