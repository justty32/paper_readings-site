1. 引言

演化式編碼 agent——如 AlphaEvolve 與「AI Scientist」框架——利用大型語言模型（LLM）在開放式科學與演算法任務中迭代生成、突變與評估程式。這些 agent 已展示在程式合成、數學發現、演算法設計等領域的潛力。然而，現有方法面臨兩個關鍵瓶頸。

第一，缺乏目標性引導。傳統演化 agent 的突變操作僅由純量效能分數或簡單啟發式驅動，使探索本質上等同於隨機搜尋——agent 不知道「為什麼」某個變體更好，因此無法系統性地往高效能區域前進。

第二，歷史知識無法積累。每次演化世代的經驗僅透過種群選擇隱性傳遞，agent 無法將過往軌跡提煉為可重用的結構化知識。這導致效率遞減——隨著世代增加，每個評估樣本帶來的改進越來越少——以及搖擺行為：agent 在效能天花板附近反覆重訪相同的無效搜尋方向。

這兩個缺陷的根本後果是演化停滯（evolutionary stagnation）——agent 永遠被困在局部最優附近，無法發現真正新穎的解決方案。停滯是開放式發現的頭號殺手。

CausalEvolve 提出一個直接的解決方案：在演化流程中嵌入因果暫存器（Causal Scratchpad）——一個動態的因果知識結構，透過溯因推理（abductive reasoning）將演化歷史中的驚喜事件轉化為可操作的因果假設，並用這些假設指引後續突變方向。

2. 相關工作

2.1 演化式 LLM Agent

深度學習時代的演化演算法已從傳統遺傳程式設計演進為 LLM 驅動的程式演化。AlphaEvolve 使用 LLM 作為變異算子，在程式庫中進行交叉與突變；AI Scientist 框架則將 LLM 應用於從想法生成到實驗執行的完整科學發現循環。這些方法共享一個特徵：演化操作（突變、交叉、選擇）是**無模型（model-free）**的——不嘗試理解程式的語義，只依賴終端效能回饋。

2.2 因果推理與機器學習

因果推理（causal reasoning）在機器學習中主要用於表示學習（causal representation learning）和泛化（out-of-distribution generalization）。與預測推理（「如果輸入改變，輸出會怎樣」）不同，**溯因推理（abduction）**是對觀察到的事實進行回溯性解釋：「觀察到結果 R，什麼原因最能解釋 R？」這是 CausalEvolve 使用的因果推理形式。

2.3 開放式發現

開放式（open-ended）系統的核心挑戰是持續產生新穎且有趣的產物，而非收斂到固定點。在演化計算中，Quality-Diversity（QD）演算法通過同時優化品質與多樣性來接近開放性。然而 QD 需要預定義的行為特徵空間，在開放式程式演化中這個空間難以事先指定。CausalEvolve 的因果暫存器提供了一種替代方案：以動態發現的因果因素作為探索方向的指引，無需預定義特徵空間。

3. CausalEvolve：以因果暫存器引導演化

3.1 整體架構

CausalEvolve 由標準演化迴圈 + 三個因果子模組構成，不修改基礎演化算子：

  1. 標準演化迴圈：種群初始化 → 適應度評估 → 選擇 → 突變/交叉 → 新世代。與任何 LLM-agent 演化框架相容。
  2. 因果暫存器：一個在第一、第二步之間插入的外掛模組，執行三個因果推理任務：因素識別、驚喜檢測、溯因假設生成。

3.2 結果層級因素識別（Outcome-Level Factor Identification）

在演化開始前或早期世代，CausalEvolve 提示 LLM 分析任務並列舉可能影響目標指標的高層概念/結構因素。這些因素涵蓋：

  • 程式結構層級：遞迴 vs 迭代、分治策略、動態規劃 vs 貪婪
  • 演算法選擇：排序演算法選擇、資料結構選用（陣列 vs 鍵值對）
  • 資源利用模式：記憶體配置策略、快取友善性、平行化潛力

LLM 為每個因素產生一個結構化的因果陳述，例如：「如果使用分治策略，則中間結果可被重用，從而降低冗餘計算——這可能導致執行時間縮短。」這些陳述構成初始因果暫存器。

3.3 驚喜模式檢測（Surprise Pattern Inspection）

在演化運行中，CausalEvolve 持續監控效能軌跡。一個「驚喜事件」定義為偏離移動平均的顯著離群值——可以是正向（意外的高效能躍升）或負向（意外的效能暴跌）。具體而言：

  • 計算最近 K 個世代效能分數的移動平均 μ 和標準差 σ
  • 若某變體的分數與 μ 的差距超過 θ·σ（θ 為靈敏度門檻），將其標記為驚喜事件
  • 每個驚喜事件觸發一次溯因推理（§3.4）

驚喜檢測是關鍵的資訊瓶頸——只有最具資訊量的演化事件才會觸發因果推理，從而控制運算成本。

3.4 溯因推理與假設生成（Abductive Reasoning & Hypothesis Generation）

對每個驚喜事件，CausalEvolve 對演化歷史進行溯因推理：

  1. 擷取上下文：收集驚喜變體及其祖先的程式碼差異（diff）、效能分數變化、世代距離
  2. 溯因提示：LLM 被提示回答：「假設一個新的因果因素正在活躍，這個因素能否用最少的輔助假設解釋所觀察到的驚喜？」
  3. 假設生成：LLM 產生一個因果假設，形式為「因素 F 透過機制 M 導致結果 R」，以及對該假設的簡短信心評估
  4. 暫存器更新：新的因果假設以**合併或新增（merge-or-add）**策略寫入因果暫存器——若與既有條目在語義上高度重疊，則合併精煉；否則新增為獨立條目

3.5 因果引導的程式突變（Causally-Guided Program Mutation）

更新後的因果暫存器改變了突變操作的語義：

  • 標準突變：LLM 僅接收「當前程式 + 效能分數 → 產生變體」
  • 因果突變：LLM 接收「當前程式 + 效能分數 + 因果暫存器（top-K 最相關因果假設） → 以這些假設為條件產生變體」

具體而言，LLM 被提示：「基於因果暫存器中的假設 H1, H2, ...，請產生一個新的程式變體，針對假設所指的方向進行探索。」這使突變從無方向的隨機擾動轉變為因果假設驅動的定向搜尋。

3.6 與演化框架的整合

CausalEvolve 是**外掛式（plug-and-play）**設計——因果暫存器在每次突變前執行，但不修改選擇、適應度評估或種群管理的底層邏輯。在實作中：

對每一世代：
  1. 評估種群適應度
  2. 若偵測到驚喜事件 → 觸發溯因推理，更新因果暫存器
  3. 從因果暫存器檢索 top-K 相關假設
  4. LLM 以因果假設為條件執行突變
  5. 選擇 + 種群更新
