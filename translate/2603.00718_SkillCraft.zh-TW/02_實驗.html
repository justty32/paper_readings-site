4. 實驗

4.1 設定

模型：Kimi-K2-Thinking、DeepSeek-V3.2-EXP、DeepSeek-R1、GLM-4.7、Minimax-M2.1、GPT-5.2、Gemini 3 Pro、Claude 4.5 Sonnet。所有 agent 使用統一任務提示、工具端點、環境約束。

指標：成功率 = score ≥90%（依 Toolathlon 模式，每任務由人類專家定義 handcrafted evaluation rule）；技能執行率 = 成功技能執行佔全部技能執行嘗試的比例；重用率 = 每技能平均被調用次數。效率指標為 token 總數（InTok/OutTok）、成本、對話回合數、工具呼叫數，均計算 Diff = (mskill − mbase)/mbase（負值 = 節省），僅在兩種模式均成功的任務子集中平均以確保公平比較。

關鍵觀察：

(1) Skill Mode 為所有模型顯著降低 token 與成本。例如 GPT-5.2 token 從 1.23M 降至 0.26M（-79%）、成本從 $1.77 降至 $0.43（-75%）。Claude 4.5 Sonnet token 從 1.36M 降至 0.40M（-71%）、成本從 $1.08 降至 $0.28（-74%）。當技能被發現並快取後，長時程工具鏈規劃可通過重複重用同時更有效且更有效率地解決。

(2) 效率增益幅度與模型基礎能力正相關（SR 與 Turns Saved 相關 r=0.53）。閉源強模型從技能重用獲益最大；開源弱模型獲益有限甚至為負——Skill Mode 是能力放大器。

(3) 強模型與弱模型的行為差異：強模型靈活組合工具、僅在有益時重用；弱模型傾向僵化遵循提示、過度套用組合。這支持「工具組合能力是智慧的核心度量」的觀點。

(4) 對話回合數可能增加（部分模型 Avg Turns 上升），因為 Skill Mode 在選擇與執行快取技能時增加了額外的決策與驗證步驟。但這些額外回合通常輕量，總體 token 與成本仍下降。

4.3 相關性分析

跨指標相關性熱力圖顯示兩個關鍵模式：

  • 技能執行率與任務成功率相關 r=0.65：表示高品質代碼生成能力直接轉化為可靠的工具組合
  • 效率節省與基礎成功率相關 r=0.53：確認越強的模型從技能重用的獲益越大

5. 什麼是好的工具組合？

沿兩個維度研究工具組合品質：composition depth 與 generalization ability。

5.1 深層組合一定更好嗎？

Hierarchical Mode 允許技能在執行期間呼叫其他技能（max nesting depth=10），理論上可實現乘法級效率增益。但實驗揭示反面結論：

三個微觀失敗機制：(1) 組合性失敗：深度 d 的技能依賴整個依賴子樹，成功率隨嵌套急劇退化；(2) 潛伏 bug：早期建立的技能可能在邊界情況下含錯，僅在重用時觸發，污染所有基於它的高層技能；(3) 除錯開銷：診斷嵌套失敗需追蹤整個依賴鏈，成本常超過簡單以平面工具呼叫重新執行。

實證結果（Table 3）：

模型 Mode 成功率 Token Cost
GPT-5.2 Base 87% 1.23M $1.77
GPT-5.2 Skill 90% 0.26M $0.43
GPT-5.2 Hier 79% 0.60M $0.81
Claude 4.5 Skill 96% 0.40M $0.28
Claude 4.5 Hier 96% 0.63M $0.44

GPT-5.2 從 flat Skill 移至 Hierarchy 後成功率從 90% 降至 79%、token 從 0.26M 回升至 0.60M。Claude 成功率未變，但 Hierarchy 效率仍較差（0.40M vs 0.63M）。值得注意的是 Hierarchy 執行率可達 95–99% 但這並未轉化為更高的任務成功率。

結論：shallow、充分測試的技能庫當前比深層自動生成的層級更可靠且更具成本效益。

5.2 跨任務泛化

兩階段靜態轉移實驗：Phase 1（技能創造）在來源難度層以 Skill Mode 解決任務、創建並快取技能；Phase 2（技能轉移）將預計算的快取複製到目標難度層工作區、注入結構化技能摘要至系統提示、agent 僅可重用不可新建。

三種轉移方向結果（Table 4）：

  • Claude Easy→Hard：成功率 95%→100%、token 1.92M→1.56M（-19%）
  • Claude Hard→Easy：成功率 95%→95%、token 1.06M→0.69M（-35%）
  • Claude Hard→Hard：成功率 95%→95%、token 1.96M→0.47M（-76%）
  • Gemini Easy→Hard：成功率 76%→90%、token 1.33M→0.78M（-41%）
  • Gemini Hard→Hard：成功率 76%→100%、token 1.30M→0.75M（-42%）

轉移技能的執行率始終 97–100%，證明預計算技能緩存可跨難度層穩定重用。

5.3 跨模型技能泛化

四個模型（Claude、Gemini、GLM、Minimax）各在 8 個 hard 任務上建立技能後，以靜態重用模式提供給全部四個模型執行（16 個組合含 4 個自重用基線）。agent 可透過 execute_skill 調用預載技能但不能創建新技能。

兩個關鍵發現（Figure 7）：

(1) 高品質技能達成普遍成功：Claude 創建的技能在所有四個執行模型上（含 Gemini、GLM、Minimax）均達 100% 成功率——良好抽象的、含清晰參數介面的技能可跨不同架構的執行模型有效轉移。

(2) 技能品質決定效率增益或損失：Claude 創建的技能跨所有執行者產生 54–81% token 節省；Minimax 創建的技能部分反而增加了成本（+13% 到 -48%）——設計不佳的技能無論何模型執行都會傷害效能。

(3) 執行者能力可補償中等技能品質：Claude 使用 Gemini 的技能節省 69.2%，遠超 Gemini 自用的 14.8% 自重用——但不能挽救根本設計錯誤的技能。

啟示：多代理系統應從高能力模型策劃技能庫，而非允許所有參與者任意貢獻。

6. 結論

SkillCraft（126 個含重複子結構的任務）與 Skill Mode protocol 使 agent 能自動組合、快取、重用工具序列。頂尖模型評估發現：(1) 技能重用降 token 用量最高 80% 同時維持/提升成功率；(2) 效率增益與模型智能強相關；(3) 技能跨任務、跨模型泛化良好（>95% 執行率）；(4) 層級組合因嵌套錯誤累積而不如 shallow 技能庫可靠。本文將組合性技能獲取確立為長期穩健工具使用的核心能力。
