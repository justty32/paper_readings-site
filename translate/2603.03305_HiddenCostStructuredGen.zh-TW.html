結構化生成的隱藏成本：草稿條件受約束解碼

arXiv: 2603.03305 | ICML 2026
作者: Avinash Reddy, Thayne T. Walker, James S. Ide, Amrit Singh Bedi
（中佛羅里達大學 + Lockheed Martin AI Center）

一、研究動機

大型語言模型（LLM）日益被部署為軟體管線組件，必須產生機器可解析的輸出：JSON 物件、API 呼叫、SQL 查詢。在這些場景中，單一語法錯誤——缺少括號、錯誤的引號——就能讓整個輸出無法被下游系統使用。因此，「受約束解碼（Constrained Decoding, CD）」成為可靠部署 LLM 的關鍵技術：它在每個生成步驟遮罩非法 token 並重正規化剩餘機率，保證輸出永遠符合結構約束。

然而，越來越多的證據表明 CD 並非免費：它會降低語意正確性，尤其在推理密集型任務上（Tam et al., 2024; Castillo, 2024; Schall & De Melo, 2025）。根本原因在於：當嚴格格式強制低熵語法決策（括號、引號、欄位名），模型可能只對這些合法 token 分配極少機率，重正規化就變成大幅擾動。多次累積後，解碼被系統性推向「容易維持合法」的路徑——即使對應的解答是錯誤的。

二、核心機制：KL 投影與投影稅

2.1 可行質量（Feasible Mass）

對於前綴 \(h_t = (x, z_{<t})\)，令 \(A(h_t)\) 為當前合法 token 集合。標準 CD 的每步分佈為：

\[q(z_t \mid h_t) = \frac{\pi_\theta(z_t \mid h_t) \cdot \mathbb{I}[z_t \in A(h_t)]}{\alpha(h_t)}\]

其中 \(\alpha(h_t) = \sum_{a \in A(h_t)} \pi_\theta(a \mid h_t)\) 是「可行質量」——模型分配給所有合法後續 token 的總機率。

2.2 每步 KL 失真

從 KL 投影觀點，CD 的每一步等價於將 \(\pi_\theta(\cdot \mid h_t)\) 逆向 KL 投影到合法單形 \(\Delta_{A(h_t)}\) 上，每步失真精確為：

\[\text{KL}(q(\cdot \mid h_t) \mid\mid \pi_\theta(\cdot \mid h_t)) = \log\frac{1}{\alpha(h_t)}\]

2.3 累積投影稅（Projection Tax）

整條序列的總失真為各步累積：

\[\text{KL}(\rho_q \mid\mid \rho_\theta) = \mathbb{E}_{z \sim \rho_q}\left[\sum_{t=1}^T \log\frac{1}{\alpha(h_t)}\right]\]

這就是結構化生成的隱藏成本。當 schema 強制模型在早期輸出 {、"、欄位名等低機率 token——而模型原本傾向輸出自然語言如「答案是 14」——每一步 \(\alpha(h_t)\) 極小，投影稅迅速累積。即使最終輸出合法，解碼已被推向語意錯誤的軌跡。

2.4 軌跡偏差

更微妙的是，即使兩條序列都在 \(L(x)\) 內，重正規化按 \(\prod_t 1/\alpha(h_t)\) 加權，使 CD 偏好「容易投影」的前綴而非「全域正確」的解答。

三、DCCD：草稿條件受約束解碼

3.1 核心洞察

可行質量 \(\alpha(h_t)\) 並非由約束單獨決定——它依賴上下文。如果先提供輔助內文 \(d\)（草稿、計畫、中間表示），模型產生的下一個 token 分佈會改變：

\[\alpha(h_t; d) = \sum_{a \in A(h_t)} \pi_\theta(a \mid h_t, d) \gg \alpha(h_t)\]

當 \(d\) 包含推理軌跡與正確答案時，schema 相容 token 的機率大幅提高，投影稅自然降低。

3.2 演算法

階段 1 — 無約束草稿生成：

\[y \sim p_{\text{draft}}(\cdot \mid x)\]

產生自由形式推理，捕捉語意規劃，不需滿足任何結構約束。

階段 2 — 草稿條件受約束解碼： 以 \((x, y)\) 為條件進行 CD：

\[\tilde{q}(z_t \mid \tilde{h}_t) = \frac{p_2(z_t \mid \tilde{h}_t) \cdot \mathbb{I}[z_t \in A(x, z_{<t})]}{\tilde{\alpha}(\tilde{h}_t)}\]

其中 \(\tilde{h}_t = (x, y, z_{<t})\)。硬約束僅在階段 2 生效，保證最終輸出合法性。因階段 2 主要是結構化實作（非開放推理），可使用相同或更小模型。

多草稿變體：採樣 \(K > 1\) 個草稿 → 以累積 log-可行質量進行延遲選擇 → 僅對選中草稿執行階段 2。\(K=1\) 時退化為基本兩步驟方案。

3.3 為何有效

DCCD 將「推理」與「格式化」明確分離：階段 1 讓模型自由思考，階段 2 僅做約束下的結構化實現。條件化於草稿後，格式 token（括號、引號、欄位名）變成「分佈內」token，大幅降低重複的「強迫意外」，保留模型對內容 token 的語意偏好。

四、實驗設計

資料集與約束類型：

  • GSM8K、MATH500（數值數學）→ JSON schema
  • GSM-Symbolic（符號數學）→ 運算式語法
  • FOLIO（一階邏輯推理）→ FOL 語法，Prover9 驗證

模型：Llama-3.2-1B、Qwen2.5-1.5B/3B/7B/14B、Llama-3.1-8B

基線：Constrained Prompting (CP)、Constrained Few-Shot (CF)、標準 Constrained Decoding (CD, XGrammar)

指標：嚴格結構化正確率（同時滿足答案正確 + 結構合法）

六、深入分析

6.1 CD 退化歸因

MATH500 上比較三種設定：(1) 純 prompt（無 CD）、(2) 結構化 prompt（無 CD）、(3) 結構化 prompt + CD。結果：加入結構化 prompt 僅損失 0.2-5.2pp；疊加 CD 再損失 10-30pp。退化主要來自解碼時的重正規化，而非 prompt 提及結構。

6.2 草稿品質為上限

階段 1 草稿正確時，階段 2 保留率 72.9-83.6%；草稿錯誤時，極少被修正（0.2-3.3%）。DCCD 的角色是結構化實現草稿語意，而非自主修正。

6.3 延遲成本

vLLM + H100：DCCD 比 CD 增加約 13% wall-clock（7B 模型），但準確率從 37.8% 提升至 53.6%（+15.8pp），結構遵循率接近 100%。

6.4 Schema 嚴格度效應

將 GSM8K schema 的 answer 欄位從 string 改為 int：CD 退化 3.4-18.6pp。更嚴格的約束放大投影稅，驗證了 DCCD 的動機。

6.5 與思考型生成對比

DeepSeek R1 1.5B + CD at answer stage：51.2%。DCCD (R1 1.5B + Qwen2.5 1.5B)：62.6%。即使在回答階段才套用 CD 仍引入足夠投影稅——DCCD 的優勢不僅來自「先推理後回答」，而是來自推理過程不受約束。

6.6 非可驗證任務

TL;DR 256-token 摘要：DCCD win rate ~78-80.5%（整體品質/忠實度/覆蓋率）。

八、結論

受約束解碼雖然保證結構合法性，但每一步都在繳納「投影稅」——當可行質量極低時，累積失真使模型偏離正確語意。DCCD 透過簡單的兩階段免訓練推論策略：先讓模型自由思考（草稿），再以草稿為條件進行受約束解碼，大幅提高可行質量，保留結構保證的同時近乎消除品質-合法性的取捨。
