6. 評測

三個核心問題：表達力（能否用簡潔查詢實作常見與進階 prompting，尤其互動式）、效能（能否降低模型查詢次數與計算／API 成本）、準確率（約束解碼是否影響任務準確率）。

基線：HuggingFace generate() 這類高階、純文字介面——不支援 token 層驗證，只能 chunk-wise 生成後手動剖析／驗證；多 token 約束與字元級長度約束無法強制。指標：LOC（功能行數）、模型查詢次數（Model Queries）、解碼器呼叫次數（Decoder Calls，反映 API 成本）、計費 token（Billable Tokens，依 GPT-3 davinci $0.02/1K 估算）。模型：GPT-J 6B、OPT-30B、gpt2-xl，另有限度測 GPT-3.5 text-davinci-003（A100 GPU）。

  • 6.1 案例一：Chain-of-Thought（圖 10）——多選題（Odd One Out、Date Understanding，BIG-bench）。以 few-shot + 約束（REASONING 詞數上限、禁 "Pick" 與換行、多個停止條件）引導推理，末以 distribute 對選項算分佈。結果（表 3）：準確率持平或微升（Odd One Out 33.33%→34.52%）；Model Queries −43~45%、Billable Tokens −27~31%；LOC 僅為基線 26%（34%）。GPT-3.5 控制實驗：Odd One Out 42.86%、Date Understanding 85.29%→86.10%。
  • 6.2 案例二：互動式 ReAct（圖 11）——問答時讓 LM 以 Search/Finish 動作互動查 Wikipedia。LMQL 用一個解釋迴圈 + 約束（MODE∈{Tho,Act}、ACTION∈{Search,Finish}、停止條件）即可實作，且天生支援 beam search 的分支（Python 基線難做）。結果（HotpotQA，表 5）：Decoder Calls −80%、Model Queries ≥−30%、Billable Tokens −76%（省 5.2¢/query）；僅 18 行 LMQL（比 Python 少 63%）。圖 12 比較不同 chunk size 下基線的取捨。
  • 6.3 案例三：算術推理（圖 13）——掃描 << 觸發外接計算器評估算式再回填，並用 int(RESULT) 約束強制最終輸出為合法整數。結果（GSM8K，表 5）：Decoder Calls 從 7 降到 1（−85.7%）、Model Queries −66%、Billable Tokens −84.9%（省 6.2¢/query）；18 行 vs 78 行。

6.4 討論：三案例證明 (i) 表達力高（遠少於 Python 的行數即可，表 4：Odd One Out 9 vs 34、Date 13 vs 38、Arithmetic 22 vs 59、ReAct 18 vs 78）；(ii) 靠 token 層驗證即時強制約束，大減模型查詢與執行時間；(iii) 不損準確率、有時微升；且在付費 API 情境省下可觀費用。侷限：未做真實 prompt engineer 的完整使用者研究，對易用性主張構成有效性威脅。

7. 相關工作

LMP：CoT、ReAct、self-consistency、ThinkSum、Iterated Decomposition、program-aided CoT（PAL/PoT，把 LM 產的程式碼餵給直譯器）等皆屬 LMP／prompt programming。PromptChainer、langchain、OpenPrompt、PromptSource 提供 LM 互動的 IDE 或函式庫（後兩者有簡單模板語言，近似 LMQL 頂層字串），但都未實作 LMQL 式的約束或控制流。Dohan et al. 的 language model cascades 把 LM 查詢連結到機率程式設計。約束 LM：Shin et al.（把輸出約束到易解讀的英語子集）、Poesia et al./Scholak et al.（生成程式碼時整合剖析器保證語法語意有效）多需手工客製；LMQL 則提供通用的高階約束介面，且運算子集可由使用者擴充（接入文法剖析器、語意驗證等）。

8. 結論

本文提出 Language Model Programming 這個與 LLM 互動的新方式，並實作高階查詢語言 LMQL——語法簡潔直觀，以專用求值語意實現高效執行。三個案例研究證明複雜的 SOTA prompting 技巧可寫成直觀、簡潔、高效的 LMQL 程式，最多降低 80% 計算成本。程式碼開源於 github.com/eth-sri/lmql，專案頁 lmql.ai。
