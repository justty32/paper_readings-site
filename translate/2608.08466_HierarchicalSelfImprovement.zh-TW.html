Hierarchical Self-Improvement：任務專用可演化 Agent Harness

摘要與問題

現行 agent 常人工改 prompt、工具或工作流，卻把包住模型的可執行 harness 當成定稿。本文改問：固定 LLM 能否藉由持續改寫自己的任務 harness 變好？作者提出 HSI，並強調這不是權重更新，也不是在執行時額外擴增思考。

1–2. 背景與定位

既有 Gödel-style 系統多改決策程式；harness engineering 可改更廣的 prompt、記憶、工具與驗證，但常倚賴較強的外部設計者。HSI 的主張是同一凍結模型同時做任務與改寫；每個任務家族各自演化，不假設一個通用 harness 能跨域適用。作者因此以 held-out split 而非只看演化時的分數檢驗泛化。

3. 分層自我改進

H 是直接執行任務的 harness；Σ 是挑種子、改寫、提交與選最終版本的 evolver 策略；meta-evolver 可改 Σ。但 meta-evolver 自己的執行邏輯從外部初始化模板載入、不可改，形成 frozen outer anchor。主迴圈保留多個 commit，而非只留最高分版本，以維持不同演化方向；最後才以 validation 表現選匯出版本。

作者刻意讓任務層關閉 reasoning、改寫兩層開啟 reasoning。任務互動仍須經同一骨幹模型，演化可改 prompt、工具、記憶、狀態與控制邏輯，不能偷換成外部搜尋器或不同政策。

4. 實驗

BALROG 的 % Progress 是 episode 完成度。候選版以平均值減去不確定度的 lower-confidence reward 排名，但報表展示 raw mean。除同分布的 TextWorld、BabyAI、Crafter、MiniHack、NLE 外，BabaIsAI 依子套件作開發／驗證／20% 封存測試切分。

meta-on 對 initial harness 的成績為 BabyAI 42.0→81.3、Crafter 11.6→44.6、TextWorld 40.0→65.0、MiniHack 0.8→15.8；NLE 0.0→0.2。關閉 meta-evolution 的對應值為 77.3、36.4、46.0、5.8、0.0。BreakStop 與 GoTo 的封存測試很高，Make 僅 0.3625，顯示可轉移的導航模式不代表多步製作也被解決。

5. 討論與結論

作者把有效演化歸因於執行回饋與既有能力：早期先補狀態表示或揭露隱藏訊號，中段加入較結構化的策略，後段再微調或淘汰。這是非單調搜尋，可能回歸；NLE 的結果是反例。故 HSI 證明的是一條受邊界限制的工程軸，而非凍結模型可無限遞迴升級。
