2 相關工作

2.1 多模態推理

MLLM 正在迅速增強其視覺-語言推理能力。通用模型如 InstructBLIP、LLaVA、Qwen2.5-VL 和 GPT-4V 已大幅改善視覺理解和指令跟隨。後續工作將純文字思維鏈推理擴展到多模態設定，Visual ChatGPT 和 MM-REACT 等方法表明明確的中間視覺-語言推理可在挑戰性任務上產生可衡量的增益。然而這些方法仍將影像視為靜態輸入：視覺證據在開始時提供後被動消費，而非隨推理展開被積極重新審視或操作。近期工作將此擴展為多模態工具使用智能體，使模型能與外部工具互動操作動態演變的視覺證據。OpenAI o3 標誌著此方向的重要一步，能將影像直接納入推理過程（「用影像思考」）。更近期的 DeepEyes、OpenThinkIMG、VTool-R1 和 CodeVision 進一步推動此範式，通過訓練策略模型進行多步影像推理和工具使用。然而這些方法主要強調改進的獎勵設計，而忽略了互動軌跡的內在價值——軌跡大多被化簡為純量訊號，而非被蒸餾為可重用的結構化知識。相比之下，SPyCE 更充分地利用互動軌跡，將其蒸餾為技能並促成技能與策略的共演化。

2.2 從經驗中學習

賦能智能體從過去互動中學習已成為提升能力的有前景方向。Generative Agents、Reflexion、Voyager 和 ExpeL 表明長時程行為可受益於保留互動歷史、反思失敗和提取可重用經驗。更近期方法如 Dynamic Cheatsheet（演化備忘錄）、MemP（程序性記憶）和 Agent KB（階層式儲存庫）使此設計更明確。這些方法暗示了一條超越參數更新的演化替代路徑，然而它們主要為文字主導設定開發，依賴外部記憶建構後測試時檢索，使策略更新與經驗演化保持脫鉤。相比之下，我們的工作針對異質視覺觀察下的多模態推理，通過訓練期間的聯合共演化封閉了技能與策略之間的迴圈。

3 方法

我們考慮多模態視覺推理任務，其中 MLLM 通過主動對影像進行操作並通過工具使用與之互動，將其推理奠基於任務相關的視覺證據。我們首先形式化任務設定並呈現支撐框架的優化目標（第 3.1 節）。如圖 2 所示，框架通過兩個階段將策略優化與階層式技能庫耦合：（1）在策略演化過程中從成功軌跡建構階層式技能庫（第 3.2 節）；以及（2）技能-策略共演化階段，在此階段中檢索到的技能引導策略優化，而改進的 rollout 持續被蒸餾回技能庫（第 3.3 節）。

3.1 預備知識

問題形式化。 我們將多模態工具使用推理形式化為部分可觀察馬爾可夫決策過程（POMDP）。一個任務實例 T = (q, I) 由自然語言查詢 q 和影像集 I = {I_1, ..., I_m} 組成。在每一步 t，智能體接收觀察 o_t 並選擇一個工具動作 a_t，該動作產生新的觀察並更新互動狀態。此過程產生軌跡 τ = [(s_0, a_0, o_0), ..., (s_T, a_T, o_T)]，之後輸出最終答案 ŷ。

基於群組的策略優化。 我們通過最大化取樣的工具使用軌跡的期望獎勵，以強化學習優化策略。對於每個任務輸入 x_i，我們從當前策略取樣一組 N 個 rollout {τ_i^(n)}^N_{n=1} ∼ π_{θ_old}(· | x_i)。每個 rollout τ_i^(n) 被分配一個純量獎勵 R(τ_i^(n))，策略優化旨在增加具有更高獎勵的 rollout 的似然性。兩個代表性實例是 GRPO 和 RLOO。GRPO 在其取樣群組內正規化每個 rollout 獎勵：

A_i = (R_i − mean({R_j}^N_{j=1})) / (std({R_j}^N_{j=1}) + ε)

其中 R_i = R(τ_i)。對應的截斷 GRPO 目標為：

L_GRPO(θ) = E_i[ min( r_i(θ) A_i, clip(r_i(θ), 1−ε, 1+ε) A_i ) − β D_KL(π_θ(·|x_i) ∥ π_ref(·|x_i)) ]

其中 r_i(θ) = π_θ(τ_i|x_i) / π_{θ_old}(τ_i|x_i) 是重要性比率，π_ref 是用於 KL 正則化的參考策略。RLOO 與 GRPO 不同之處在於以留一基準（leave-one-out baseline）取代正規化的群組統計量。

在我們的方法中，每個 rollout 的獎勵定義為：

R(τ) = R_acc(τ) − λ_call · 1[Succ(τ) = 1] · N_tool(τ)

其中 R_acc(τ) = r(τ) ∈ {0, 1} 表示任務成功，Succ(τ) 表示任務是否成功解決，N_tool(τ) 表示工具呼叫次數。僅對成功 rollout 施加工具使用懲罰，可以在抑制冗餘操作的同時，不壓抑失敗 rollout 中的探索。

3.2 階層式技能庫

在策略優化的第一階段，我們從互動軌跡建構技能庫，為後續學習提供可重用的引導。多模態工具使用推理需要兩種互補粒度的技能：用於高層次任務引導的工作流技能，和用於互動期間細粒度決策支持的執行技能。局部視覺瓶頸——如旋轉的證據、微小目標或擁擠區域——需要可執行的短時程操作，而更複雜的任務也依賴高層次的工作流先驗來進行工具編排和多步推理。因此，我們將技能空間階層式組織為兩個層級：執行技能層 K 和工作流技能層 H。

3.2.1 執行技能

執行技能編碼用於解決局部視覺瓶頸的可重用操作。每個執行技能表示為三元組 k = (c, u, e)，其中 c 表示文字觸發條件、u 表示工具動作或動作模板、e 表示預期的局部效果。此表示使每個技能在何時適用、應如何使用、以及預期產生何種局部證據改進方面變得明確。為蒸餾執行技能，我們使用專門的 MLLM（MLLM_dk）。給定一條成功軌跡 τ 及其關聯的任務輸入 (q, I)，提示 MLLM_dk 將可重用的局部工具使用模式摘要為執行技能三元組：{k_j}^{K_τ}_{j=1} = MLLM_dk(q, I, τ)。每個 k_j 是可重用局部模式的緊湊文字抽象，而非原始軌跡片段。例如，一條成功軌跡可能揭示旋轉的證據可通過影像旋轉解決，而小的或邊界證據可通過局部裁剪處理。由於執行技能以條件–動作–效果三元組表示，它們可基於視覺條件直接匹配和重用，無需與整條軌跡的相似性。

3.2.2 工作流技能

工作流技能用於捕捉多步工具編排和推理的工作流層級先驗。每個工作流技能表示為 h = (b, w)，其中 b 表示視覺瓶頸的粗略摘要（例如跨區域一致性檢查），w 表示對應的解決模式工作流草圖（例如定位證據 → 增強局部內容 → 驗證一致性）。與執行技能不同，工作流技能不直接編碼可執行動作，而是蒸餾用於編排工具使用的工作流層級模式。蒸餾方式與執行技能一致：h = (b, w) = MLLM_dk(q, I, τ)。

3.2.3 技能庫整併

若不進行整併，新蒸餾的技能直接插入庫中會導致兩個問題：近似重複條目的檢索噪音增加，以及條目增殖導致的庫增長失控。為解決此問題，我們對兩個庫應用統一的 merge-or-add 規則。對於每個新蒸餾的技能候選，系統檢查在嵌入空間中是否存在任何足夠相似的既有條目。對於執行技能，相似性基於觸發條件計算。給定候選 k̂ = (ĉ, û, ê)，系統檢查是否存在既有執行技能 k = (c, u, e) ∈ K 與 ĉ 的餘弦相似度高於門檻 θ^K_sim。若存在，候選通過精煉項目合併到最相似的匹配技能中；否則作為新條目新增。對於工作流技能，匹配使用瓶頸描述進行。給定候選 ĥ = (b̂, ŵ)，系統檢查是否存在既有工作流技能 h = (b, w) ∈ H 與 b̂ 的餘弦相似度高於 θ^H_sim。若是，候選合併到匹配條目中；否則插入為新工作流技能。為進一步控制庫大小，記錄每個條目的相似性匹配次數，並在庫超過容量時修剪最少被匹配的條目（least-frequently-matched pruning）。
