4. 實驗

四個研究問題：(RQ1) SkillSmith 的聯合技能–工具共演化能否顯著優於僅演化技能的強 baseline？(RQ2) 效能增益是否確實來自三個核心組件？(RQ3) 當任務複雜度增加、技能庫增長、多技能共活化成為常態，SkillSmith 的優勢是否隨之放大？(RQ4) SkillSmith 能否在長期演化中保持效能增益，同時控制技能庫膨脹、冗餘與版本退化？

4.1 實驗設置

基準：OfficeQA（跨文檔表格定位＋多步數值推理，246 題）、SealQA（噪音搜尋環境中的事實 QA，111 題）、WildClawBench（15–50 步多模態多工具任務，模擬真實代理部署）。

Baseline：Base Agent（初始技能庫 S_0 + 固定工具集 T_0，無演化）、EvoSkill（失敗驅動僅技能演化 + Pareto 前沿選擇）、SkillClaw（多人軌跡驅動的集體技能演化）。

4.2 RQ1 主結果與 RQ2 消融

主結果（Table 1）：SkillSmith 在 OfficeQA 與 SealQA 上一致優於 Base Agent 與 EvoSkill。規模效應顯著：模型從 9B 增至 397B，SkillSmith 相較 Base Agent 的增益從 +2.8% 升至 +18.3%（OfficeQA）與 +1.8% 至 +18.9%（SealQA）——更大的模型更好地利用了高品質外部資產。

在 WildClawBench 上（Figure 4），SkillSmith 不僅達到更高終端準確率，且維持演化進展比固定工具 baseline SkillClaw 更久。SkillClaw 在 Day 2–4 間因工具層瓶頸而平台化，SkillSmith 則透過產生統一 bundle 提案來包裝或修補缺陷工具，持續改善至 Day 6。

消融（Table 2）：

  • Skill-only（鎖定工具層）：效能降最大，WCB −6.8%。無法更新工具迫使人們生成膨脹的技能指令（達 16 個技能），導致關鍵崩潰。
  • FreeTool（允許不受約束的工具編輯）：雖修補部分工具，但工具錯誤率激增至 14.7%（4.6×），退化率 8.9%——證明型別化生命週期操作對平衡可演化性與安全至關重要。
  • −Eco（取消生態模型）：庫膨脹至 21 技能 + 7 工具，略微降低效能並劣化檢索精度。
  • −Anti（取消反模式記憶）：退化率從 2.1% 增至 7.6%，因系統反覆提出先前失敗的組態。

4.3 RQ3 規模效應與 RQ4 演化穩定性

規模效應（Figure 5）：SkillSmith 的優勢隨任務步驟數（→更高共活化率）系統性增加，從簡單任務約 5–10% 增至高複雜度任務逾 20%。右面板分解增益至五個維度（工具複雜度、交互密度、上下文大小、動作空間、技能協同），各維度的高三分位數均展現更大增益。

演化穩定性（Figure 6）：100 輪的兩次環境擾動——第 30 輪注入更高步數的新任務、第 60 輪隨機破壞 3 個既有工具實現（模擬 API 棄用）——SkillSmith 可在工具層崩塌後重構受損工具並更新依賴技能，恢復至近 70%；EvoSkill 因固定工具層無法修復第 60 輪後的受損介面，僅靠增加技能文本為低效變通，平台在 ~30%。生態控制的重要性：−Eco 變體在擾動後組件數超過 80，造成檢索噪聲與上下文溢出，準確率從 68% 掉至 35% 以下。−Anti 變體因無失敗記憶反覆探索無效路徑，產生 40%–60% 的振盪。

案例研究：Figure 7 展示典型 OfficeQA 失敗——根因為工具層 bug（table_extractor 使用整數索引，在合併標頭表格上靜默錯位）、SkillSmith 以一個原子 bundle（W RAP + EDIT）修復錯誤類別，並級聯更新三個依賴技能。

5. 結論與局限

SkillSmith 透過原子 bundle 提案、生態效用動力學、反模式否決，聯合演化技能、工具與失敗記憶。當前局限包括：依賴骨幹 LLM 的反思品質；生態模型冷啟動時共現資料稀疏的噪聲；評估限於 QA/搜尋/多工具協調場景——嵌入式或多用戶代理留待未來工作。

附錄 A：理論分析

定理 A.1（聯合最佳化嚴格優於僅技能最佳化）：在固定的工具層 T_0 缺乏硬任務子集 D_hard（正測度 P_H > 0）所需的能力 c* 的假設下（即 c* ∉ span(T_0)），SkillSmith 的聯合最佳化全域最優嚴格大於僅技能最佳化的理論上界：J*_joint > J*_skill。性能間隙 ε·P_H > 0。

定理 A.2（搜尋複雜度的多項式有界性）：SkillSmith 將工具操作限制為五種型別化生命週期原語（|Ω_tool| = 5），且工具修改必須與依賴技能的級聯更新共同封裝為原子 bundle。在此約束下，單步狀態轉換的分支因子 b_SS 嚴格有界於常數與局部依賴技能突變空間的乘積，完全避免了未約束程式合成的指數級組合爆炸（b_SS ∝ |∆S_dependent| ≪ O(|V|^L)）。

附錄 B：Tool-Smith 生命週期操作

五種操作定義（詳見原文 Definitions 1–5）：

  • W RAP(τ, g)：在既有 τ 外加前/後處理層，不修改原實現，型別簽名可保留或窄化。
  • E DIT(τ, ∆)：以約束 diff ∆ 修改實現體或介面簽名（每次僅修改函數體、輸入 schema、輸出 schema 三者之一；簽名變更時同一 bundle 內所有引用技能被標記為需共同更新）。
  • C OMPOSE(τ₁, τ₂, π_c)：依組合計劃 π_c 將兩工具鏈接或並行化為一個工具，原始工具保留於 T' 以向後相容。
  • S PLIT(τ, π_s)：將捆綁多職責的工具拆為兩個，原始被替換，所有引用技能被重寫以調用適當組件。
  • R ETIRE(τ)：從 T' 中移除，記錄墓誌銘至 F_{t+1}（觸發於被完全取代或連續 T_ret 輪無活躍技能引用時）。

附錄 C：額外案例研究

  • 案例研究 2（生態衝突檢測，SealQA）：Search-Breadth-Protocol 與 Source-Authority-Filter 兩技能單獨有益但組合時衝突（β̂_AB = −0.31）；經 4 次共活化後生態模型觸發合併為兩階段 Search-and-Verify-Protocol，消弭衝突源頭。
  • 案例研究 3（多輪技能–工具共演化鏈，WildClawBench）：一個 9 步任務在兩個工具和一個技能的三個獨立失敗點上失敗。經兩輪演化、四個工具操作和兩個技能更新完全解決。其中 C OMPOSE 由生態冗餘檢測觸發——Slack-Message-Handler 與 Calendar-Coordinator 各自獨立維護頻道名稱解析邏輯——抽出為共享的 slack_resolver 工具，消除兩技能共 23 行重複程式碼。
  • 案例研究 4（反模式否決，WildClawBench）：SkillClaw 在 Day 2 嘗試 git-auth-fallback（與 Clone-to-Directory 的路徑衝突），被驗證拒絕。Day 5 因無失敗記憶重新生成幾乎相同的 Git-Push-Auth-Fallback，再次被驗證拒絕。SkillSmith 的反模式記憶在 Day 5 成功匹配相似度 0.91，否決提案並將實現重定向為在既有 Git-Ops 技能內增加 SSH-fallback 分支——不阻擋意圖（驗證回退確實需要），而是將實現從經驗證會失敗的路徑重定向。
