摘要

語言模型（LM）常被要求生成某種形式語言（formal language）的字串，例如結構化資料、API 呼叫或程式碼片段。雖然可以透過微調（tuning）讓 LM 更遵循形式語法，但這不保證合規（conformance），對適合大規模部署的小型 LM 尤其如此；且微調耗費可觀資源，對罕見或任務專屬格式並不實際。理想上我們想「約束」LM 使其只產生合法輸出以杜絕下游解析錯誤，但這被 tokenization 嚴重複雜化——它通常既有歧義（ambiguous）又與形式語法錯位（misaligned）。我們透過套用自動機理論（automata theory）解決這些問題，為正則語言（regular languages）——一大類有眾多實務應用（API 呼叫、schema 導引的 JSON 與 YAML）的形式語言——推導出高效的閉式解（closed-form solution）；並討論應對「高分支因子」問題的實用擴充，再把技術延伸到確定性上下文無關語言（deterministic context-free languages），後者同樣有高效閉式解。先前工作（Outlines，Willard & Louf 2023）是在自動機之上疊加客製方案（bespoke solutions），導致速度、正確性與可擴充性的問題；我們則把整個任務重新表述為自動機，得以善用經充分研究與優化的演算法。本系統編譯約束的速度快約 7,000 倍、可證明正確、且能以模組化方式擴充。

1. 引言

LM 的常見用途是生成某種形式語言的輸出（結構化資料、API 呼叫、程式碼）。強大的 LM 常能產出語法良構的輸出，但這無法保證。對任意 LM 施加約束的通用配方是遮罩解碼器 logits（mask the decoder logits）：(1) 依約束目前狀態建立「合法下一 token」的遮罩；(2) 用遮罩懲罰採樣 logits，使只有合法 token 被考慮；(3) 把選中的 token 回饋給約束以更新其狀態。

Tokenization 是主要難題：主流 LM 使用資料驅動的子詞（sub-word）tokenizer，其切分方式對形式語言的 token 而言通常既有歧義又錯位。例如 API 呼叫 foo(x="bar") 一般會被詞法分析器（lexer）切成 foo ( x = "bar" )，但 LM 可能把它切成 foo( x=" ba r ")——把某些 lexer token 合併、又把某些拆開。若粗暴地強迫 tokenization 對齊形式語法，會損害品質（因為它會扭曲 LM 的評分，見附錄 A）。作者在自動機理論中找到優雅解法。

主要貢獻（偏概念而非實證）：(1) 指出 detokenization 與 transduction（轉導）之間一個此前未被注意的連結；(2) 用此連結與自動機運算解決 tokenization 問題；(3) 定義解決效率與便利性的實用擴充。相較先前工作以客製方案處理，本文透過建立正確的理論基礎，在速度、正確性、可擴充性上皆有優勢。

2. 有限狀態約束（Finite-state constraints）

2.1 有限狀態自動機（FSA）

FSA 是一個五元組（輸入符號集、狀態集、初始狀態、終止狀態集、邊集）。每條邊記錄來源狀態、輸入標籤（或 ε 空轉移）、目標狀態。若存在一條從初始狀態走到某終止狀態、其邊標籤串接等於輸入字串的路徑，則 FSA 接受該字串。FSA 接受的所有字串構成其語言；由 FSA 定義的語言即正則語言。正則語言也可由正則表達式（regex）定義，兩者等價（Kleene）；如 UNIX grep 就是把 regex 編譯成以 Unicode 為字母的 FSA。FSA 分非確定性與確定性：確定性 FSA 無 ε 邊、每個狀態對每個輸入至多一條出邊，執行時只需追蹤當前狀態並沿匹配輸入的邊走。關鍵性質：任意非確定性 FSA 都可被**確定化（determinize）**成語言相同的確定性 FSA（Rabin & Scott）。

2.2 有限狀態轉導器（FST）

FST 是「會產生輸出」的 FSA：邊除輸入標籤外還帶一個輸出標籤。FST 把輸入字串轉導（transduce）成輸出字串。最關鍵的性質是組合（composition）：一個 FST 的輸出可餵給另一個 FST 或 FSA。給定輸出字母等於後者輸入字母的兩者，可組合成新的 FST（T2∘T1）或新的 FSA（A2∘T1），其行為等於先跑前者再跑後者。這個「組合」正是全文的理論樞紐。

2.3 把 detokenization 表述為轉導（第一項貢獻）

核心洞見：detokenization（把 token 序列還原成文字字元序列）本身就是一個 FST。演算法 1 從詞彙表 V 建出「detokenizing FST」T_V：對每個 token，建一條字元鏈——除最後一個字元外的字元都以「無輸入、有輸出」的 ε 邊串起，最後一條邊才吃入整個 token 並輸出末字元、迴圈回根狀態。為求緊湊，各鏈的共同前綴可合併成類似 trie（字典樹） 的結構。這個 FST 的輸入是 token、輸出是字元。

2.4 把正則表達式適配到 token（第二項貢獻）

給定詞彙表 V 與一個接受字元序列的 FSA A，只需組合 A' = A ∘ T_V，就得到一個接受token序列、語言與 A 本質相同的 FSA。即：A' 接受的每個 token 序列，其 detokenization 都落在 A 的語言裡。注意反向不必然成立——只有能被 V 切分的字串才有對應的 token 序列；又因 tokenization 有歧義，同一字串可能對應 A' 中多個 token 序列（這正是我們想保留的「tokenization 自由度」）。

演算法 2（約束 LM 到正則語言）：先由 V 建 T_V、由 regex R 用 Thompson 建構法建字元 FSA A_R，再組合並確定化得 A_{R∘V}（接受 token 的 FSA）。解碼時：從初始狀態出發，每步先算 logits，取當前狀態的所有出邊輸入標籤作為「合法 token 集合 A」，對不在 A 的 token 把 logit 設為 −∞，採樣後沿匹配邊走到下個狀態。A_{R∘V} 是一個閉式解：它用 V 中所有相關 token 表達 R，且可獨立於兩者執行。所需運算僅是索引、切片與基本算術，可直接在加速器上以極低延遲執行。

此解法漂亮地分離關注點：T_V 與詞彙相關（雖大但可為每個 LM 預先算好一次）；A_R 與詞彙無關、易於指定、可跨 LM 移植。這種乾淨分解只因「FST-FSA 組合」提供了快速、自動、通用的接合方式才可能——因此替換 detokenization 自動機（見 4.3）或替換約束自動機（見 3.1）都不需改動系統其餘部分。

2.5 擴充

以特別命名的捕獲群組（capturing group）撰寫的一組 regex 擴充，大幅提升效率與表達力。

2.5.1 萬用字元匹配（Wildcard）：像 /./ 這種幾乎匹配任何字元的 regex，在與 T_V 組合後某些狀態會有近乎 |V| 條出邊（常用 LM 的 |V| 超過 10 萬），使用起來很貴。作法：定義終端標籤（terminal labels）——與 V 不相交、映射到預先算好的合法 token 遮罩的 token ID。例如 PARAGRAPH_TOKEN 的遮罩表示「不含換行的 token」。懲罰 logits 時整批套用終端遮罩；更新狀態時若選中 token 匹配某終端遮罩就走該終端邊。普通 token 邊與終端邊可能都匹配、造成歧義，以簡單啟發式解決：優先走普通 token 邊，否則依終端標籤的優先序——因為終端多用於萬用匹配，而萬用匹配實務上常被互斥的分隔表達式（如換行）夾住。

2.5.2 語法糖（Syntactic sugar）：有些約束用 regex 定義很沒效率。例如強迫 LM 只生成參考字串 u 的某個子字串（可減少幻覺），其 regex 大小是 O(|u|²)，但對應 FSA 只 O(|u|)——這是規格語言的缺陷。故定義語法糖 (?P<SUBSTRING_OF>abc) 提供 O(|u|) 的規格語法。表 1 列出更多擴充：QUOTED_TEXT、UNQUOTED_TEXT（YAML 風格）、IMAGE（多模態 LM 生成的圖像）、TEXT_TOKEN、TEXT_UNTIL（生成到停止片語為止）、DELIMITED_LIST（同質項目分隔清單）、DELIMITED_SUBSEQUENCE_OF 等。
