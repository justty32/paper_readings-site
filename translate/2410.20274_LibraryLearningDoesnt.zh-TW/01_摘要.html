摘要

大型語言模型（LLM）的進步催生了一波用於數學推理的 LLM 庫學習系統。這些系統旨在學習一個可重用的工具庫，例如形式化 Isabelle 引理或針對一組任務量身訂製的 Python 程式。許多這類系統受到人類將知識組織為可重用且可擴展概念之方式的啟發——但當前的方法真的學到了可重用的工具庫嗎？

我們研究了兩個報導準確率提升的數學庫學習系統：LEGO-Prover 與 TroVE。我們發現，在 miniF2F 與 MATH 資料集上，函數重用極為罕見。我們的後續消融實驗表明，自我修正（self-correction）與自我一致性（self-consistency）——而非重用——才是觀測到的效能增益之主要驅動力。

1. 導論

數學進步是建立在對前人工具的使用與延伸之上。因此，對能自動學習這類可重用數學工具的系統之研究興趣自然而生。近期，LLM 使新的工具學習方法得以實現並改善了效能——但這些系統真的學到了泛化、可重用的知識，還是效能改進來自其他機制？本研究探討兩個先前的系統：旨在學習可重用形式化 Isabelle 引理的 LEGO-Prover，以及旨在學習可重用 Python 函數的 TroVE。對兩者，我們對模型行為的分析皆揭示直接重用微乎其微。我們進一步執行兩個消融實驗，支持函數重用在這些系統改進的數學推理中僅扮演有限角色的立場。

2. 相關工作

LLM 庫學習（即創建並重用工具）依賴 LLM 使用工具的能力。先前的工具使用評估涵蓋真實世界查詢、專用測試環境，以及從 LLM 作為評判者到追蹤任務檢查點完成的各種指標。

相較之下，庫學習系統的評估一直很有限。準確率是首選指標，但無法捕捉重用的程度或品質：一個優秀的庫對弱推理器是無用的，而一個強大的推理器可以忽略無用的庫，從第一原理推導結果。先前評估庫學習的嘗試僅限於靜態的個別函數量測，如迴圈複雜度與抽象語法樹深度，或僅回答特定問題，如人類驗證的容易度、領域轉移下的準確率，或重構真值解的次子問題效能。

本研究評估兩個數學推理庫學習系統：LEGO-Prover 與 TroVE。

2.1 LEGO-Prover：目的與架構

LEGO-Prover 接收一組命題定理以產生對應的形式化 Isabelle 證明。它在 miniF2F 資料集上評估：每個問題嘗試 100 次，系統在每次嘗試後從 Isabelle 驗證器獲得回饋。LEGO-Prover 被設計來執行庫學習——以"技能（skills）"一詞代替工具。它透過兩個 LLM 系統進行庫學習：1) PROVER 使用庫來產生證明；2) EVOLVER 迭代地精煉庫。它們透過共享資料庫溝通，例如請求資料庫（request db）儲存待證明的命題引理以加入庫中。

2.2 TroVE：目的與架構

TroVE 是一種"誘導可重用函數工具箱以解決程式化任務的方法"，設計來接收一連串文字問題而無真值或驗證器。對每個問題，它嘗試產生一個印出正確解的 Python 程式。TroVE 的數學推理以 MATH 資料集評估。每個問題僅考慮一次：LLM 產生 15 個解，最佳解基於自我一致性（即多數投票）選出。在生成中，5 個解忽略庫並直接生成程式（SKIP 模式），5 個創建可重用輔助函數以納入庫（CREATE 模式），5 個使用庫中的函數（IMPORT 模式）。

3. LEGO-Prover 分析

我們從分析 LEGO-Prover 公開發布的評估日誌檔案開始。這些日誌是未發布的 PROVER 日誌之子集，對應成功解出問題的最終嘗試。注意 LEGO-Prover 在 4 個資料分割上評估，總共學了超過 20,000 條引理。

我們發現僅 1,233 條引理（約 6%）出現在最終求解步驟中（即作為 PROVER 的輸入）。其中，恰好一條引理被 PROVER 逐字重用（出現在兩個解中）。考慮到 PROVER 可能調整引理（如改寫、加註釋等），我們重複分析時僅檢查引理名稱。再次，引理重用極為罕見，且沒有引理被重用超過一次（即沒有引理名稱出現在 3 個或更多解中）。

鑑於這些發現，LEGO-Prover 進行重用的可能性只有兩種：1) 間接重用（學到的工具作為有用的、可重用的範例而非直接用於最終解），或 2) 直接重用發生在 EVOLVER 中。

我們的假設是：重用並未顯著提升效能。我們認為透過請求資料庫進行的自我修正才是主要作用機制。PROVER 透過以下方式填充請求資料庫：1) 加入 LLM 建議可能有助的子步驟引理，以及 2) 加入 Isabelle 無法驗證的解嘗試中之引理。EVOLVER 使用請求資料庫來修改既有工具以"協助解決請求"並"使用庫解析分解後的子目標"。因此，效能增益可能來自思維鏈（透過 PROVER 提議有用引理給 EVOLVER 解決）與自我修正（透過 EVOLVER 重試失敗引理）的組合。

為了測試任何形式的重用是否提升效能，我們對 LEGO-Prover 進行消融：移除跨問題共享——每個定理以其自己的獨立狀態與資料庫求解。我們在驗證分割的隨機 12 題子集上評估，每題 50 次嘗試。我們使用 OpenAI GPT-4o-mini 進行消融，因原始結果使用現已棄用的 GPT-3.5-Turbo 版本。跑 2 次試驗後，消融版效能表現強勁，僅比基線少解 1 題。研究僅由基線解出的問題，發現只有最簡單的輸入引理可能被使用（即 a^2 >= 0 與 ax^2 + bx + c = 0 ⇒ c = -(ax^2 + bx)）——甚至這些事實也沒被當引理對待、被賦予了不同的證明理由。這表示：1) 若 LLM 需要基本事實的範例，它可能太弱了；2) LLM 連複製既有已驗證證明都在重用上掙扎。
