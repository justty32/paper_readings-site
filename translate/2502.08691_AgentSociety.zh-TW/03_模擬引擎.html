5. 大規模社會模擬引擎

5.1 架構

社會中的人並非遵循一張固定 SOP，而是各自依記憶、認知與環境非同步行動。引擎因此把 agent 視為沒有顯式全域依賴的獨立單位，透過訊息互相影響。

所有實驗共用 LLM API、EMQX MQTT、PostgreSQL 與 MLflow。每場實驗建立自己的 Agent Simulation 物件、環境子行程、Ray cluster 與多個 agent groups，避免實驗互相干擾。GUI 從資料庫讀狀態，並經 MQTT 對 agent 對話、訪談或送問卷。

5.2 Group 式分散執行

若每個 agent 都是一個行程並各自連線，MQTT、資料庫與指標服務的 TCP 埠很快耗盡。系統把多個 agent 均分成 groups，每組只建立一套 LLM、MQTT、環境、資料庫與 metric clients。每個 group 是一個 Ray actor／行程，跨機器由 Ray 分散；組內以 asyncio 同時等待 LLM 與環境 I/O。

連線數因此與 group 數相關，而不是與 agent 數相同。代價是固定分組會受最慢 group 拖累；作者把跨組動態排程與自適應負載平衡留給未來。

5.3 MQTT 訊息

MQTT 的 publish/subscribe 模型原為百萬 IoT 裝置設計，適合大量 agent 的輕量可靠傳訊。topic 同時包含 experiment UUID、agent UUID 與用途，分成 agent-chat、user-chat、user-survey。agent 只訂閱自己的前綴，未來可在其下擴充新訊息種類。

5.4 工具與社會實驗介面

平台提供多種 LLM adapter、預設最多三次重試、JSON parser、MLflow 指標、AVRO／PostgreSQL 儲存與 GUI。保存內容包括 profile、狀態、思想、對話、問卷、實驗設定與錯誤。

干預可在模擬前修改人格、目標與偏好，也可在模擬中修改 profile、情緒或想法，或用訊息通知外部事件。訪談與問卷經 MQTT 傳給 agent，不必中斷其主要行動；問卷依預定格式逐題回答，便於彙整。
