4. 相關工作

工具學習：近期研究已揭示 LLM 在掌握工具、於複雜環境中做決策方面日益增長的能力。存取外部工具賦予 LLM 即時事實知識、多模態功能、以及垂直領域的專門技能。然而開源 LLM 在工具使用上仍遠遠落後於頂尖 LLM，且頂尖 LLM 如何習得工具使用能力仍不明朗。本文旨在彌合此落差、探究其底層機制。

指令微調：指令微調能增強 LLM 理解人類指令並生成適當回應的能力。由於人工標註指令微調資料耗時，self-instruct 提出從頂尖 LLM 生成高品質資料，帶動近期多輪對話資料策劃的潮流。然而相較對話，工具學習因 API 的巨大多樣性與多工具指令的複雜性而更具挑戰——以至於即便 GPT-4 也常找不到有效解答路徑。既有工具學習資料集及其構建方法無法有效滿足第 1 節所述的真實人類需求；相對地，ToolBench 專為實務情境設計，改進了既有的工具學習資料構建流程。

提示 LLM 做決策：提示能促使 LLM 將高層次任務拆解為子任務並生成有依據的計畫。ReAct 將推理與行動結合，讓 LLM 為某個動作給出合理理由，並將環境回饋納入推理。然而這些研究並未納入「決策回溯」機制，這在初始錯誤會引發後續一連串錯誤時就成了問題。近期 Reflexion 透過讓 LLM 反思先前失敗來緩解此問題。我們的 DFSDT 將 Reflexion 延伸為一種更通用的方法，讓 LLM 得以評估不同推理路徑並選擇最有希望的一條。值得注意的是，DFSDT 與同期工作 tree-of-thought（ToT）推理有相近的構想；然而 DFSDT 針對的是決策空間無窮的通用決策問題，相較之下 ToT 處理的是可用暴力搜尋解決的相對簡單任務（如 24 點遊戲、填字遊戲）。DFSDT 與 ToT 目標的顯著差異，決定了兩者在實作細節上的重大不同。

5. 結論

本文介紹如何激發 LLM 的工具使用能力。我們首先提出指令微調資料集 ToolBench，涵蓋 16k+ 真實世界 API 與涉及單工具、多工具的各種實務情境。ToolBench 的構建純粹使用 ChatGPT，僅需極少人工監督。此外我們提出 DFSDT 以強化 LLM 的規劃與推理能力，使其能策略性地在推理路徑間導航。為高效評測工具學習，我們設計了自動評測器 ToolEval。透過在 ToolBench 上微調 LLaMA，所得模型 ToolLLaMA 表現可比擬 ChatGPT，且對未見 API 展現出卓越的泛化能力。此外，我們開發了神經 API 檢索器，為每條指令推薦相關 API，可與 ToolLLaMA 整合成更自動化的工具使用管線。實驗中，我們展示了此管線對分佈外領域的泛化能力。整體而言，本工作為指令微調與 LLM 工具使用交叉領域的未來研究鋪路。

附錄要點

  • A.1 RapidAPI 過濾細節：過濾流程分兩步——① 基本功能測試，剔除無法運作的 API；② 範例回應評估，依回應時間與品質篩選，剔除回應時間過長、或回應品質低劣（如回傳 HTML 原始碼或其他錯誤訊息）的 API。
  • A.2 API 回應壓縮：部分 API 回應含冗餘資訊、過長難以塞入 LLM 脈絡。由於每個 API 的回應格式固定，用 ChatGPT 分析一則回應範例，去除不重要的欄位以縮短長度；prompt 內容包含工具文件（工具名稱/描述、API 名稱/描述、參數、範例回應）與 3 個人工撰寫的原始回應-壓縮 schema 對照範例。推論時，若 API 回應長度超過 1024 token 就先壓縮，壓縮後仍超過則只保留前 1024 token。人工評估顯示此壓縮保留了回應中的關鍵資訊，同時成功去除雜訊。
  • A.3 ToolLLaMA 訓練細節：以多輪對話模式訓練，輸入輸出格式與 ChatGPT 一致（函式呼叫欄位直接串接進輸入作為 prompt 的一部分）；學習率 5×10⁻⁵、warmup ratio 4×10⁻²、總 batch size 64、最大序列長度 8192、位置插值比例 2；訓練兩個 epoch，取開發集上表現最佳的 checkpoint 在測試集上評估。
  • A.4 DFSDT 演算法細節：經典 DFS 在每步生成多個子節點後需排序、選最高分節點展開，此排序過程用 LLM 兩兩比較子節點約需 O(n log n) 次 API 呼叫，是最耗資源的部分。作者發現實務上排名最高的節點通常就是最先生成的節點，因此略去排序步驟，改用前序遍歷（pre-order traversal，DFS 的一種變體）：模型不需回溯時（如簡單指令）DFSDT 退化為 ReAct、效率相當；演算法結束後探索到的節點又幾乎與經典 DFS 找到的相同，因此也能處理只有完整 DFS 才能解決的複雜指令——整體達到與 DFS 相近的表現，同時大幅降低成本。ReAct 可視為 DFSDT 的退化版本，因此雖然 ToolLLaMA 是用 DFSDT 標註的資料訓練，推論時仍可選用 ReAct 或 DFSDT。
  • A.5 ToolEval 細節：
    • 通過率規則：先判斷指令是否「可解」（至少一個提供的工具對解決指令有潛在幫助）或「不可解」（所有 API 均與指令無關，或指令本身資訊無效，如無效的電子郵件地址）。針對可解指令：若模型呼叫「Finish by Giving Up」且已充分嘗試所有 API 仍無有效資訊則判 Pass，只嘗試少數 API 或已取得有效資訊卻放棄則判 Fail；若模型呼叫「Finish with Final Answer」，API 無有效資訊且已嘗試所有 API、最終答案仍未解決指令或表達拒絕則判 Pass，API 有有效資訊但最終答案未完全解決或屬拒絕則判 Fail，完全解決則判 Pass，無法判定則標 Unsure。針對不可解指令：若最終答案解決了原本判定不可解的指令、或答案是誠實拒絕，則判 Pass；若答案是模型自行幻覺出的假陽性回應（如「我已完成任務，最終答案是……」）則判 Fail；若呼叫「Finish by Giving Up」則一律判 Pass。每條解答路徑由 ChatGPT 評測器生成至少 4 次預測、多數決得出最終通過率。
    • 勝率規則：僅比較兩者評測結果同為 Pass 或同為 Fail 的解答路徑對，依六項準則判定勝負或平手——① 資訊豐富度（明顯更豐富者較優，同等程度則平手）；② 真實性（更準確描述已完成/失敗事項者較優）；③ 推理品質（若指令未解決，給出更詳細準確失敗原因者較優）；④ 里程碑（達成的里程碑數）；⑤ 探索廣度（嘗試更多潛在有用 API 者較優）；⑥ 成本（API 使用數相同時，重複/冗餘呼叫較少者較優）。同樣生成至少 4 次預測、多數決得出最終勝率。
    • 與人工評測的一致性：從四種方法（ChatGPT+ReAct、ChatGPT+DFSDT、ToolLLaMA+DFSDT、GPT-4+DFSDT）中各採 300 條測試指令的解答路徑對，讓人工分別標註通過率（ChatGPT+DFSDT、ToolLLaMA+DFSDT、GPT-4+DFSDT）與勝率（ChatGPT+ReAct 對 ChatGPT+DFSDT）。ChatGPT 評測器與人工標註在通過率上達 87.1% 一致率、勝率上達 80.3%，顯示評測器可視為模擬人類評測的可信裁判。作者也坦言工具學習的評測遠比對話等傳統任務複雜——同一指令可能存在無窮多「正確」解答路徑，初期調查甚至發現人類專家彼此對「哪條路徑更好」常有分歧（如有人偏好用少量 API 快速給答，有人偏好窮舉所有 API 交叉驗證），工具使用領域的公平評測仍有很長的路要走。
  • A.6–A.8：分別提供 APIBench 實驗設定細節、指令生成的 prompt 模板、解答路徑標註的 prompt 模板（均為附錄原文引用之操作性細節，未含額外數字結果）。
