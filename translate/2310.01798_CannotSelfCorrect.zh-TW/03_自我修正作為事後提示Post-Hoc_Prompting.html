4. 自我修正作為事後提示（Post-Hoc Prompting）

儘管推理上失效，自我修正在某些場合確有亮眼成果（Self-Refine、Constitutional AI、moral self-correction）。從形式上看，自我修正可視為一種 post-hoc prompting：提示施加在 LLM 的回應之上（相對地，標準提示稱 pre-hoc prompting）。自我修正能改善回應的情境，是它能提供 pre-hoc 提示給不了的有價值指示或回饋——例如要讓回應更安全時，很難只靠 pre-hoc 指令讓模型第一次就生成完全無風險的回應，此時自我修正可透過細粒度的事後檢查提升安全性。但對推理任務，「審查你先前的答案並找出問題」這類回饋 prompt 未必帶來實質益處。

再者，即使觀察到修正後的顯著改善，也須細究 prompt 設計。若要求可以輕易寫進初始指令（輸出須含某些詞、程式碼須高效、情感須強烈負面），更省成本的策略是把要求直接（且明確地）嵌入 pre-hoc prompt，而非事後當回饋餵。以 Self-Refine 的受限生成任務（用 20-30 個概念造連貫句）為例：與其讓模型先找缺漏概念、再經回饋引導補入，不如一開始就指示「寫一段合理的段落，包含以上全部概念」——這一要求在 Self-Refine 的 pre-hoc prompt 中並未明示。我們據此造了個「作者隨手寫、未經任何優化」的基線 prompt（象徵 true zero-shot 設定），以概念覆蓋率為指標（表 5）：

設定 呼叫數 CommonGen-Hard
Standard Prompting（Madaan et al. 原 prompt/原結果） 1 44.0
Self-Correct（Madaan et al. 原結果） 7 67.0
Standard Prompting（我們復現其 prompt） 1 53.0
Self-Correct（我們復現） 7 61.1
Standard Prompting（我們隨手寫的 prompt） 1 81.8
對上行輸出再套其 Self-Correct 7 75.1

隨手寫的初始 prompt（81.8）勝過 Self-Refine 修正後的結果；再套其修正 prompt 反而降到 75.1（且大量輸出因格式問題失敗、需多次重生——自我修正的另一潛在缺點）。我們的用意不是爭論「是否存在能勝過隨手 prompt 的 post-hoc prompt」，而是呼籲更批判地檢視自我修正實驗：用精心打造的 post-hoc prompt 去「自我修正」一個由劣質 pre-hoc prompt 生成的回應，是沒有意義的。公平比較應在 pre-hoc 與 post-hoc 提示上投入同等心力；考量自我修正可觀的 token 成本，研究者與開發者應審慎衡量它相對於 pre-hoc prompt 的真實效益。

5. 討論

自我修正對「使回應對齊特定偏好」可能仍有益。 首先重申：我們並非宣稱自我修正無用。改變回應風格、增強安全性等任務中它可有效運用；但當任務是 LLM 難以判斷初答錯誤、難以評估初答正確性的（如本文研究的推理任務），自我修正便不見效。

利用外部回饋做修正。 一旦引入外部回饋，敘事就改變了：CRITIC 顯示 LLM 與搜尋引擎、計算機等外部工具互動時能更有效地驗證並修正回應；Self-Debug 等顯示用執行器與單元測試確認程式碼運作，LLM 能改善生成、更好地解決推理任務；另有工作在高品質資料集上訓練 verifier 或 critique 模型來驗證/精煉輸出。日常使用中人類提供的回饋亦然——高品質的外部回饋直觀上有益。

以自我一致性作為自我驗證手段。 表 1 的 oracle 設定準確率高得多，暗示 LLM 的搜尋空間內可能存在正確答案；若有穩健的驗證流程引導方向，結果可望提升。途徑之一是外部回饋，另一是 self-consistency——如 Tree of Thoughts 便以逐步驗證搭配自我一致性增強推理。

Pre-hoc vs post-hoc 提示。 post-hoc 的延遲與成本較高；若「回饋」可編碼進初始指令，pre-hoc 是更優選擇，也應把功夫更多放在 pre-hoc prompt engineering。但當要利用必須伴隨回應給出的外部回饋時，post-hoc 更合適。

比較準則。 第一，比較自我修正方法與其他基線時，應報告推論成本（呼叫數或 token 數），並納入同呼叫數/回應數的 self-consistency 作基線。第二，避免「劣質 pre-hoc prompt ＋精心 post-hoc prompt」的不對等設計。第三，方法利用外部回饋時應考量回饋是否合理：自動呼叫外部工具、或從環境接收回饋，可視為合理；用 ground-truth 標籤判斷回應正確與否，只能視為 oracle。

6. 結論

我們的研究顯示 LLM 尚無能力自我修正其推理。期望這些模型內在地辨識並糾正自身的不準確，至少以當前技術水準而言可能過於樂觀。這凸顯了在真實應用中部署 LLM 時，持續改進與多管齊下方法的必要。研究者與實務者應以明辨的視角看待自我修正概念——認識其潛力，也認清其邊界。

7. 局限與更廣影響

雖然我們的探索橫跨多種自我修正策略、prompt 與任務，但仍可能存在能在特定基準上增強推理的特定 prompt 或策略——只是搜尋它們可能不自覺地依賴外部回饋（人類洞見或訓練資料），且同等的搜尋功夫也可用在 pre-hoc prompt 上。本研究可能使某些應用的自我修正研究卻步，但我們樂觀地認為它會把未來研究導向更務實的方向——尤其是利用外部回饋的方向。多項相關工作已呈現與我們一致的發現：無外部回饋的自我修正是相對弱的基線。但社群中仍瀰漫模糊：部分文獻把標籤使用的關鍵細節放在不顯眼處、或未澄清其「自我修正」策略其實納入了外部回饋，連領域專家都對自我修正何時、如何運作感到不確定。標題「LLM 尚無法自我修正推理」並非對自我修正技術的全盤否定，而是行動呼籲。為求清晰，我們建議：當語境不嚴格符合內在自我修正設定時，省去 self-correction / self-critique 中的「self」，改用「藉外部工具/回饋修正」等較不易混淆的措辭。最後，鑑於 LLM 難以純憑固有能力自我修正推理，對「LLM（與 AI 系統）透過自我改進自主演化」的任何無根據的樂觀（或恐懼），我們敦促採取更審慎的看法。
