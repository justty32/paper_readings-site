3. 實驗

3.1 實驗設定

評估基準：(1) AIME24——美國數學邀請賽 2024 年題目（30 題），極具挑戰性的高中競賽數學，多為非標準解法、需深度創造性推理；(2) MATH500——MATH 資料集的 500 題子集，涵蓋代數、幾何、數論、計數、預科微積分，難度從 AMC 到 AIME 層級；(3) GPQA Diamond——研究生層級科學推理（物理、化學、生物），198 題，設計為非專家難以猜對的「Google-proof」題目；(4) LiveCodeBench——程式碼生成基準，評估演算法解題能力。所有評估採 pass@1（單次生成一次性評分），答案經自動化比對（數學題對數值/表達式做正規化比對，程式碼題對 test case 輸出比對）。

推論設定：所有模型以 greedy decoding（temperature=0）生成，確保可重現性。s1-32B + Budget Forcing 設定：思考 token 下限 256、上限 2048（AIME/GPQA），MATH500 上限調至 1024。Wait 追加上限設為 10 次（即最多追加 10 次 Wait 以延長思考）。

訓練細節：s1K（1,000 樣本）→ Qwen2.5-32B-Instruct，SFT with next-token prediction loss。學習率 1e-5、batch size 16、1 epoch、max sequence length 8192 token、AdamW optimizer（β1=0.9, β2=0.95, weight decay=0.1）、cosine LR schedule with 3% warmup。訓練於單節點 8×H100-80GB，約 26 分鐘完成。

3.2 主要結果

Benchmark Qwen2.5-32B-Instruct s1-32B（標準） s1-32B + Budget Forcing o1-preview
AIME24 16.7% 50.0% 56.7% 40.0%
MATH500 58.2% 81.6% 83.2% 81.4%
GPQA Diamond 49.0% 56.1% 59.6% 56.6%
LiveCodeBench 35.8% 44.5% 46.2% 43.6%

核心發現：

  1. SFT 的巨幅增益：僅 1,000 條 s1K 微調即有顯著提升——AIME24 從 16.7% → 50.0%（+33.3pp）、MATH500 從 58.2% → 81.6%（+23.4pp）、GPQA Diamond 從 49.0% → 56.1%（+7.1pp）。這些提升來自 s1K 的高品質推理軌跡——模型在微調過程中學會了「進行長鏈推理」的行為模式，而非僅記憶答案。

  2. Budget Forcing 的額外增益：在微調基礎上，Budget Forcing 進一步提升 AIME24（50.0% → 56.7%，+6.7pp）、MATH500（81.6% → 83.2%，+1.6pp）、GPQA Diamond（56.1% → 59.6%，+3.5pp）、LiveCodeBench（44.5% → 46.2%，+1.7pp）。增益在 AIME24 最顯著，因其題目最需要「深度推理」——Budget Forcing 追加的 Wait 使模型得以重新檢查、發現並修正錯誤，而標準模式下模型可能過早提交了含錯誤的答案。

  3. 全面超越 o1-preview：s1-32B + Budget Forcing 在所有四基準上均超越 o1-preview。特別值得注意的是 AIME24（56.7% vs 40.0%，+16.7pp）——此基準最適合評估推理模型的優勢，s1 以 32B 參數規模擊敗專有的 o1-preview，且訓練成本（30 分鐘 × 8 H100）遠低於 o1 的推測訓練成本。

  4. 對比蒸餾模型：s1-32B 標準（AIME24 50.0%）與 DeepSeek-R1-Distill-Qwen-32B（AIME24 49.1%）接近——後者使用 800K RL 蒸餾樣本、前者僅 1K SFT 樣本（1/800 資料量）。雖非嚴格的受控對比（蒸餾模型的教師不同、訓練管道差異大），此比例（800× 資料差異）仍暗示高品質樣本在推理訓練中具備不成比例的效率。

3.3 Budget Forcing 的深入分析

追加次數的累進效應

作者在 AIME24 上實驗了不同次數的 Wait 追加（1–10 次）對正確率的影響。結果呈現單調上升趨勢——0 次追加（標準模式）正確率 50.0%，隨著追加次數增加正確率穩步提升，在約 6–8 次追加時達到峰值（~56.7%），之後趨於飽和。這顯示 Wait 的效用非無窮——每次追加的邊際收益遞減，模型「思考」的品質增益有其上限。每次追加約增加 50–150 token 的額外推理內容，模式包括：(a) 重新檢查主要計算步驟的數值正確性；(b) 驗證邏輯推導的前提是否成立；(c) 測試邊界案例（如變數為零或趨近無窮時解是否仍有效）；(d) 嘗試替代解法路徑（如同時使用代數與幾何方法解同一題目）。

截斷思考的影響

截斷（上限式 Budget Forcing）在部分案例中產生正向副作用：某些模型「自由思考」產生循環推理（反覆重述相同論點而無實質推進），而截斷強制模型在預算結束時提交答案——在這些案例中截斷後答案反而正確。作者報告數個案例研究，模型在無限制思考時陷入無窮的「等價變形循環」（將方程式反覆改寫為等價形式而不實際求解），截斷迫使模型跳出此迴圈。但並非所有截斷都正向——在約 15% 的截斷案例中，模型因被迫過早結束而遺漏關鍵推理步驟，導向錯誤答案。

追加 Wait 的 token 層級分析

追蹤 Wait 之後模型產生的第一個 token 分佈：基礎模型在相同前綴（思考到一半後接 Wait）下的下一個 token 通常為思考的延續（如「Next, I'll...」「Let me...」「We can...」）。偶爾出現「Wait,」——即模型自主產出 wait 作為自我打斷——顯示 s1K 的訓練使模型在某些情況下內化了「檢查自身」的行為。初始 token 多樣性（追加 Wait 後的 entropy）高於自然延續（無追加）——Wait 作為外部刺激迫使分佈重新校準，而非保持確定性的下一 token 預測。
