3. 複合式 AI 系統優化

3.1 四個原則性維度

  • 結構彈性（Structural Flexibility）：優化法能修改計算圖 G 的程度。Fixed Structure（固定結構） 假設拓撲 (V,E) 預先給定，只優化節點參數 {Θ_i}（如 prompts）；Flexible Structure（彈性結構） 則聯合優化節點參數與圖結構本身（邊連結 E、節點數 |V|、甚至 F 中的操作類型），擴大搜尋空間以更有效地為目標任務編排系統。
  • 學習訊號（Learning Signals）：源自效能指標 μ，有兩種形式。NL Feedback（自然語言回饋）：由系統外的輔助 LLM 產生文字指引，善用 LLM 的推理能力。Numerical Signals（數值訊號）：以數值表示，進一步（圖 3）分為 (a) 以規則式演算法直接從原始效能指標學習，與 (b) 把評估結果轉為形式化訓練目標——後者再細分為 (b1) SFT 損失、(b2) RL 獎勵函數、(b3) 直接偏好優化（DPO）損失。
  • 組件選項（Component Options）：F 中考量的操作類型。多數 Φ 以 LLM 為核心，但常整合 RAG 模組、程式碼直譯器（CI）、工具呼叫（如網路搜尋），多模態情境下還有影像生成模型（IGM）。以 Python 程式碼作系統表示者，本質上即支援 CI。
  • 系統表示（System Representations）：最常見是把 Φ 建模為圖——DAG（有向無環圖） 確保每節點每次前向傳播至多被呼叫一次，循環圖則支援多輪辯論或多跳 RAG。另一路線把工作流程表示為自然語言程式或 Python 程式碼，可支援條件邏輯與迴圈而無無環限制。

3.2 代表性方法（2×2 分類法）

沿兩大軸——結構彈性（Fixed vs. Flexible）與學習訊號（NL Feedback vs. Numerical）——回顧全部 26 篇方法（表 1，依 arXiv 首次發表日排序；星號＝需模型微調，dagger＝限 DAG）。

象限一：Fixed Structure + NL Feedback 多數方法借用 LLM 生成 prompt 優化建議的能力。TextGrad 是最早把此概念延伸到複合式系統者，仿 PyTorch 數值梯度下降，分三階段：(1) 評估器 LLM 比對輸出與參考、產生文字損失；(2) 梯度估計器 LLM 為每節點產生文字建議；(3) 優化器 LLM 依建議精修節點參數——用自然語言模擬反向傳播。後續工作：AIME 指出單一評估器易漏檢程式碼錯誤，改用多評估器串接；REVOLVE 補入過往 prompt/回應的執行歷史，產生「曲率感知」回饋（類比數值優化的 Hessian）以避免停滯震盪；GASO 提出語意梯度下降以計入手足輸入（sibling-input）互動；LLM-AutoDiff 以時序梯度處理被重複呼叫的節點、並提供跳接（skip-connection）機制以優化大規模系統。Trace 與 TextGrad 並行，改為一次性聯合更新所有 prompt：取得全域 NL 回饋後，用單次 LLM 呼叫、以最小子圖（類比 Python 執行軌跡）更新每個節點，解決 TextGrad 的兩缺點——不精確 NL 回饋造成的誤差累積、與 LLM 呼叫數隨節點線性成長。限制：這些方法成功多屬經驗性、缺乏理論基礎；依賴專有 LLM 產生回饋，API 成本高。

象限二：Fixed Structure + Numerical Signals DSPy 提供 Python 函式庫與宣告式編程模組，以拒絕採樣式常式（Bootstrap-*）從系統效能生成高品質 in-context 示範，並可選擇性微調 LLM 權重。MIPRO 進一步以貝式代理模型聯合優化示範與指令。BetterTogether 交替進行 prompt 與權重優化。其餘方法涉及微調、把數值訊號實例化為不同訓練損失：SFT 類的 SiriuS（給 LLM 節點指派角色如「物理學家/數學家」，蒐集高分軌跡分別微調各節點，失敗者以額外智能體回饋做軌跡擴增）、Multiagent Finetuning（多智能體辯論下為各代/批評模型蒐集訓練資料）；RL 類的 MAPoRL（訓練驗證器 LLM 給即時正確性獎勵，並引入影響力感知的獎勵塑形鼓勵協作）；DPO 類的 SysDPO（LLM＋擴散模型的影像生成系統，以順序一致性與分布均勻性算偏好分數，並以機率分解使多組件可同時微調）。限制：過多人為設計規則限制通用性；逐一微調每個 LLM 耗費大量 GPU。

象限三：Flexible Structure + NL Feedback 以 NL 回饋聯合優化節點參數與整體結構。Agent Symbolic Learning 設計三種優化器（PromptOptimizer / ToolOptimizer / PipelineOptimizer），後兩者支援工具創建與節點的增刪移動。MASS 透過分析實驗證明「優化 prompt 比探索拓撲更易帶來增益」，據此設計三階段框架（prompt 優化先於拓撲搜尋）。ADAS 首度採用 Python 程式碼作系統表示：條件於維護過往程式碼及其效能的 archive，由 meta LLM 迭代設計新工作流程；但其線性啟發式搜尋與粗略儲存會累積無關資訊。AFlow 以蒙地卡羅樹搜尋（MCTS）保存經驗、用預定義運算子高效找最佳設計。DebFlow 引入辯論框架（多辯手提設計、由裁判彙整）以突破單一 meta LLM 的限制。限制：與 meta LLM 有效互動需高 token 消耗或多次推理；在較弱開源模型上的評估仍稀少。

象限四：Flexible Structure + Numerical Signals 不設固定拓撲、以數值訊號精修 Φ。不需微調者：DyLAN（把多輪辯論建模為時序前饋網路，以規則式演算法評分各智能體重要性、剪除無用者並自適應連接存活者）、GPTSwarm（把 Φ 建模為節點/智能體/群（swarm）的階層框架，以參數化機率分布 D_θ 治理連結、用 REINFORCE 的梯度上升變體優化——屬 RL 類）。其餘方法採查詢自適應（query-adaptive） 模式，即為每個 q_i 實例化新的 Φ（對比前述「一個優化好的 Φ 用於所有查詢」），並微調 meta LLM 來生成管線。SFT 類的 MAS-GPT（建查詢池與逾 40 種系統設計的 MAS 池，經評估/選擇/精修策劃一致的訓練集）；RL 類的 AutoFlow（以 CoRE 語法生成 Φ、用任務資料平均分數為獎勵迭代微調，並提供閉源 meta LLM 的 in-context 變通）、MaAS（建構並優化「智能體超網路（agentic supernet）」機率分布，並把 token 成本納入損失以取捨效能與複雜度）、W4S（僅約束工作流程介面、用小型弱模型降訓練成本，框定為多輪 MDP）；SFT＋RL 的 FlowReasoner（先 SFT 學基本系統生成推理、再以多目標獎勵 RL）；DPO 類的 ScoreFlow（提出 Score-DPO，每輪為每查詢採樣多候選 Φ、由 LLM 執行器評估後依效能差蒐集偏好資料）。趨勢與限制：把系統優化框定為「meta LLM 微調」以繞開模組不可微分性，但仍需大量心力策劃高品質訓練資料，且跨模型家族的全面評估不足限制了實用性。
