4. 挑戰與未來方向

  • 人工超參數配置：儘管標榜自動化，仍殘留人為介入。Fixed 類需憑領域知識配置拓撲；文字超參數（TextGrad 的評估器/梯度估計器/優化器 prompt 模板、ADAS 的 meta LLM prompt）多由作者手工設計、缺乏設計理據或敏感度分析；數值超參數（DSPy 的 bootstrap 樣本數）仍需使用者調。即便 metaTextGrad 用元學習自動優化模板，仍需人工設計元學習器的 prompt。呼籲減少對文字與數值超參數的依賴，並對殘留者做徹底敏感度分析。
  • 過高的計算負擔：NL 回饋法（TextGrad）需多次 LLM 呼叫近似單步梯度；Trace/ADAS 雖用全域呼叫卻須嵌入大量脈絡（最小子圖、archive），提高 token 吞吐；依賴專有模型帶來高 API 成本。數值法改用開源 LLM 避 API 費，但需微調而轉嫁到 GPU——形成「API 成本 vs. GPU 消耗」的取捨。此外 Flexible 類常忽略對系統複雜度（多輪迴圈、冗長執行）的正則化，導致執行期資源無界。建議發展資源高效的優化演算法並有原則地約束系統複雜度。
  • 有限的實驗範疇：多數論文仍用單一 LLM 常見資料集（數學 GSM8K、常識 MMLU、程式碼 HumanEval/MBPP，見圖 4）評估。呼籲納入更複雜的基準（AgentBench、AgentGym 需系統內多 LLM 協作討論；GAIA 檢驗真實世界工具使用），並評估「人類作為系統節點」時的表現。
  • 經驗性的 NL 回饋：NL 回饋雖經驗有效卻缺理論保證——文字梯度下降的收斂性尚未證明，而古典梯度下降有形式收斂證明。呼籲為 NL 回饋學習提供嚴謹的收斂與最優性分析。
  • 潛在安全風險：複合式系統的攻擊面顯著擴大——即使隱私保護模型，被整合為大系統的組件時仍可能洩漏敏感資料；因系統常以程式碼在企業環境中執行，即使無明顯攻擊也可能有潛伏失效模式。目前研究多只關注執行效率，鮮少觸及系統層級對齊或安全。呼籲把單模型成熟的對齊與防護技術延伸到複合式系統。
  • 函式庫支援不一致：領域缺乏標準化、廣泛採用的函式庫；雖有 TextGrad、DSPy 等維護良好者受歡迎，大部分工作仍用自製程式碼。建議系統性地基準測試並比較既有函式庫，建立「何時該用哪個函式庫」的明確指引。

5. 結論

本文綜述了由智能體、工具等互動組件構成之複合式 AI 系統的優化進展。為統一分歧的研究，提出帶條件邊的圖式形式化以進行結構化分析；以此沿四個原則性維度檢視既有方法、組織為 2×2 分類法；點出關鍵趨勢與取捨（計算負擔、NL 介面、規模化與泛化挑戰），並勾勒開放問題與未來方向。

局限（作者自陳）：因「複合式 AI 系統」缺乏公認定義，也納入自我標榜為 MAS 或 LM programs 的工作而未系統分析其概念重疊；只聚焦明確優化多節點系統的方法而排除單 LLM prompt 優化；因領域快速演進，投稿前兩個月的研究可能只被部分涵蓋，故維護開源儲存庫供讀者補充遺漏；因篇幅只強調各方法的核心動機與演算法設計，省略實驗細節。
