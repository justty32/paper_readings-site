SagaLLM：多 Agent LLM 規劃的 Context 管理、驗證與交易保證

摘要與 1–2. 動機

多 agent planning 常有 self-validation 失敗、context loss、缺乏 rollback 與跨 agent inconsistency。SagaLLM 借用 long-lived transaction 的 Saga pattern，以 persistent memory、independent validation、checkpoint 與 compensating actions 維持 workflow consistency。它放寬 ACID，追求可補償的全域恢復。

作者將需求分成 transaction integrity、independent validation、context preservation。需要注意，原文以 Gödel 不完備定理支持 LLM 自驗證限制，這不是嚴格的推論；LLM empirical failure 與形式系統不可證命題是不同問題。

3. 系統需求

每個 operation 是 local transaction，並有 compensation。失敗時依相依關係反向執行，而非假裝所有外部 effect 可原子 rollback。Committed state、transaction metadata、dependency 與 recovery history 持久保存。

Global validation 分 intra-agent output 與 inter-agent input：schema、factual、constraint、temporal ordering、shared state、dependency。結果可 rejection／compensate、augmentation 或 feedback。Context manager 選擇性保存 goal、justification、dependency 與 compensation plan。

4. 設計與實作

Travel planning 分成使用者確認 itinerary 的 manual phase，以及 SagaLLM 接手的 automated phase。系統生成 agent graph、transaction／compensation pairs、validation rules 與 log schemas。

Task agents 處理 flight、hotel、train、budget、itinerary。GlobalValidationAgent 掌握全域狀態並在 commit 前驗證；SagaCoordinatorAgent 排序 transaction、偵測 failure、建立 compensation queue。

狀態分為：application state（booking、budget、preference）、operation state（log、decision、compensation）、dependency state（prerequisite、temporal constraint、validation）。標準 flow 為 pre-check、execute、validate、commit、register compensation。Flight 失敗可取消 reservation、refund、恢復 budget，並觸發 hotel／train re-evaluation。

5. 實驗

使用 REALM 的 P5、P6、P8、P9，測 Claude 3.7、DeepSeek R1、GPT-4o、GPT-o1。Thanksgiving P9 的 flight delay 後，Claude 忘記 oven supervision、交通時間、料理工時與 dinner deadline；GPT-o1 遵守 constraints，卻自行加入額外 traffic buffer。

Wedding P5 中，Claude 抵達 tailor 時已超過關門；P8 的 1PM airport accident 下，Claude、DeepSeek、GPT-4o 都未正確更新歷史與位置，DeepSeek 把已發生行程重寫。GPT-o1 可行但保守。

SagaLLM 的 proposed remediation 是保存 checkpoint／immutable action log，針對差異補償，並持續驗證 physical-temporal constraints。然而文中沒有完整展示 SagaLLM 對四題的 output，也沒有 success rate、validation accuracy 或 rollback 指標；「significant improvement」「Always」「Guaranteed」超出已呈現證據。

6. 結論與限制

SagaLLM 把補償、外部狀態、依賴與 validation 提升為 first-class objects，這是重要方向。但 validator 與 compensation generator 仍依賴 LLM；作者也承認需 formal verification LLM-generated compensation。論文較像架構論證加 baseline failure case，而非完成的 transaction system evaluation。
