3. DSPy 程式設計模型

DSPy 把 LM 視為文字生成的抽象裝置，並優化其在任意計算圖中的用法。程式以 Python 表達：接受任務輸入（如一道待答問題、一篇待摘要論文），經一連串步驟回傳輸出。DSPy 貢獻三層抽象：signatures、modules、teleprompters——signature 抽象模組的 I/O 行為；module 取代既有手動 prompting 技術、可組進任意 pipeline；teleprompter 優化 pipeline 中所有模組以最大化指標。

3.1 自然語言簽章（Signatures）可抽象 prompting 與 finetuning

DSPy 不用自由字串 prompt，而用自然語言簽章把工作指派給 LM。一個簽章是「函式的自然語言型別宣告」——一段短的宣告式規格，講清一個文字轉換要做什麼（如「吃問題、回答案」），而非某個 LM 該怎麼被 prompt。形式上，簽章＝輸入欄位 + 輸出欄位（+ 選用指令）的元組；欄位有名稱與選用中繼資料。典型用法中，欄位角色由欄位名推得：DSPy 編譯器會用 in-context learning 把 question 和 answer 詮釋成不同角色並迭代精修。

簽章相對於 prompt 有兩利：可被編譯成自我改進、且隨 pipeline 自適應的 prompt 或 finetune（主要靠為各簽章 bootstrap 有用示範）；並處理結構化格式化與解析，減少使用者程式裡脆弱的字串操作。

簡寫記法如 question -> answer：dspy.Predict("question -> answer") 即一個完整的問答系統。欄位名指出其在轉換中的語意角色，DSPy 會展開成對 LM 有意義的指令——如 english document -> french translation 就會 prompt 英翻法。需要時另有進階介面對簽章下更明確約束（附錄 A）。

3.2 參數化與模板化的模組（Modules）可抽象 prompting 技術

如同程式語言的型別簽章，DSPy 簽章只定義介面與型別式提示；要使用它須用該簽章宣告一個模組（如上面實例化的 Predict），宣告回傳一個具該簽章的函式。

  • Predict 模組（核心）：內部存簽章、選用 LM（初始 None，否則覆寫此模組的預設 LM）、prompting 用的示範清單（初始為空）。如 PyTorch 的層，實例化後就是可呼叫函式：吃對應簽章輸入欄位的關鍵字參數（如 question）、格式化實作該簽章的 prompt 並納入合適示範、呼叫 LM、解析輸出欄位。當 Predict 偵測到自己處於 compile 模式，還會內部追蹤 I/O trace，協助 teleprompter bootstrap 示範。
  • 其他內建模組：把 prompting 技術翻譯成支援任意簽章的模組函式，如 ChainOfThought、ProgramOfThought、MultiChainComparison、ReAct，可互換套用某簽章。例如把上面的 Predict 換成 ChainOfThought，系統就會先逐步思考再給輸出。這些模組都只用幾行程式實作——把使用者定義的簽章擴展後、在新簽章上呼叫 Predict 一次或多次。例如 ChainOfThought 就是把簽章從 *inputs -> *outputs 改成 *inputs -> rationale, *outputs（prepend 一個 prefix 為「Reasoning: Let's think step by step.」的輸出欄位），再宣告一個 Predict 子模組。這是能為任意 LM/任務學會有效 few-shot prompting 的完整模組（對照附錄 C 那些從研究與熱門 prompt 庫抄來的冗長手寫推理 prompt）。
  • 參數化（獨到之處）：任一想實作某簽章的 LM 呼叫，需指定參數：(1) 呼叫哪個 LM、(2) prompt 指令與各簽章欄位的字串前綴、(3) 最重要的——few-shot 示範（凍結 LM 當提示、finetune 時當訓練資料）。作者主力放在自動生成與挑選有用示範：案例中發現 bootstrap 好示範是系統性地教會複雜 LM pipeline 新行為的強力手段。
  • 工具（Tools）：執行計算的模組。透過 dspy.Retrieve 支援檢索（內建 ColBERTv2、Pyserini、Pinecone），另有實驗性 dspy.SQL、dspy.PythonInterpreter（沙箱執行 Python）。
  • 程式（Programs）：模組以 define-by-run 介面組進任意 pipeline（仿 PyTorch/Chainer）——先在初始化宣告所需模組（供 DSPy 追蹤以優化），再在 forward 用任意程式碼呼叫它們。例如一個完整 RAG：__init__ 宣告 self.retrieve = dspy.Retrieve(k=num_passages) 與 self.generate_answer = dspy.ChainOfThought("context, question -> answer")，forward 先檢索取 context、再生成答案。把 ChainOfThought 當 Predict 的即插即換即凸顯模組化；若把簽章改成 "context, question -> search query"，就得到一個生成搜尋查詢而非答案的系統。

3.3 Teleprompters 可為任意 pipeline 自動化 prompting

編譯 DSPy 程式時通常呼叫一個 teleprompter——它是優化器：吃程式、訓練集、指標，回傳一個新的優化過程式；不同 teleprompter 用不同優化策略。

  • 訓練集可很小（少數幾例），愈大則優化愈強；訓練例可不完整（只需輸入值）；除非指標需要，pipeline 各步不需標籤。實務上通常只假設有程式最終輸出的標籤（甚至沒有），不需中間步驟標籤。此標籤效率對模組化至關重要：建新 pipeline 只要重新編譯其程式碼，不必為新 pipeline 標新資料。
  • 指標可以是 exact match（EM）、F1 等簡單概念，也可以是權衡多重考量的整個 DSPy 程式。例如把上面的 RAG 對一組問答資料與 EM 指標編譯，優化目標就是有效 bootstrap few-shot 示範：BootstrapFewShot(metric=...) 的 .compile(RAG(), trainset=...) 會在訓練例上模擬 RAG、蒐集各模組「能共同導出通過簽章與指標之有效輸出」的示範。若要程式更「摘錄式」（答案須是檢索段落的子字串），可自訂指標；這類指標可由另一個 DSPy 程式檢查（如檢查答案是否忠實接地）。
  • teleprompter 可組合：指定一個 teacher 程式，DSPy 會從它取樣示範來優化 prompt——讓昂貴程式（如用大 LM 的複雜集成）監督便宜程式（如用小 LM 的簡單 pipeline）。例如先有一個編譯到 Llama2-13b-chat 的 compiled_rag，再用 BootstrapFinetune(teacher=compiled_rag) 把 Flan-T5-large finetune 成高效程式（訓練問題無標籤，所有步驟標籤都靠 bootstrap）。
