摘要

ML 社群正快速探索 prompting 語言模型（LM）並把它們堆疊成 pipeline 以解複雜任務的技術。可惜現有 LM pipeline 通常用手寫死的「prompt 模板」（靠試誤湊出的長字串）實作。為邁向更系統化地開發與優化 LM pipeline，本文提出 DSPy：一個把 LM pipeline 抽象成文字轉換圖（text transformation graph）的程式設計模型——即一種指令式計算圖，其中 LM 透過宣告式模組被呼叫。DSPy 模組是參數化的，意即它們能（透過建立與蒐集示範）學會如何組合套用 prompting、finetuning、augmentation、reasoning 等技術。作者設計了一個編譯器，能優化任意 DSPy pipeline 以最大化給定指標。透過數學應用題、多跳檢索、複雜問答、代理迴圈控制等兩個案例研究顯示：簡潔的 DSPy 程式能表達並優化複雜的 LM pipeline。編譯數分鐘內，幾行 DSPy 就讓 GPT-3.5 與 llama2-13b-chat 自我 bootstrap 出勝過標準 few-shot prompting（分別一般 >25%、>65%）與勝過含專家手寫示範之 pipeline（分別高達 5–46%、16–40%）的 pipeline。此外，編譯到 770M 參數的 T5、llama2-13b-chat 等開源小模型後，可與依賴專有 GPT-3.5 之專家手寫 prompt 鏈的方法競爭。

1. 引言

LM 讓研究者能以更高抽象層、更低資料需求建 NLP 系統，催生了爆炸性的「prompting」與輕量 finetuning 技術（CoT 引出系統性推理、以檢索/工具增強等）。愈來愈多人建多階段 pipeline 與代理，把複雜任務拆成較好管理的 LM 呼叫以提升表現。

問題：LM 對「怎麼被 prompt」極敏感，在多個 LM 呼叫須彼此配合的 pipeline 中更嚴重。因此現有 pipeline 與熱門框架的 LM 呼叫，普遍用手寫死的「prompt 模板」（大段人工試誤的指令與示範字串）。作者論證此法雖普遍卻脆弱、不可擴展——概念上像手動調分類器的權重：同一段 prompt 字串換 pipeline、換 LM、換資料域、甚至換輸入就可能失效。

DSPy 把「建 LM pipeline」從操弄自由字串推向寫程式（組合模組化運算子建文字轉換圖），由編譯器自動從程式生成優化過的 LM 呼叫策略與 prompt。靈感來自神經網路抽象達成的共識：(1) 通用層可模組化組進任意複雜架構；(2) 權重用優化器訓練而非手調。

對應地，DSPy：先把字串式 prompting 技術（含 CoT、ReAct 等複雜且任務相依者）翻譯成攜帶自然語言型別簽章的宣告式模組（如神經網路層般的任務自適應元件）；再參數化每個模組，使其能在 pipeline 內迭代 bootstrap 有用示範來學會目標行為；模組以 PyTorch 式 define-by-run 計算圖使用——(1) 宣告所需模組、(2) 用任意控制流（if、for、例外等）把模組邏輯串接。

接著開發 DSPy 編譯器（§4）以優化品質或成本。編譯器輸入＝程式 + 少量（可選標籤的）訓練輸入 + 驗證指標；它在輸入上模擬程式的各版本、為每個模組 bootstrap 範例 trace 做自我改進，用來構造有效 few-shot prompt 或 finetune 小 LM。優化高度模組化，由 teleprompters（通用優化策略，決定各模組如何從資料學習）執行；編譯器藉此自動把宣告式模組映射到 prompting/finetuning/reasoning/augmentation 的高品質組合。（teleprompter 一名取自「把 prompting 抽象化、自動化、在遠端無人工介入地完成」。）

作者聚焦一個維度：專家手寫 prompt 對系統表現的角色，欲用 DSPy 模組與 teleprompters 減少乃至移除其角色。主要貢獻為實證與演算法性的：用 DSPy 寫極短程式，即可用 llama2-13b-chat、T5-Large（770M）這麼小的 LM bootstrap 出自我改進的多階段 NLP 系統；無手寫 prompt、編譯數分鐘至數十分鐘內，可把簡單程式品質從 33%→82%（§6）、32%→46%（§7）（GPT-3.5），並從 9%→47%（§6）、22%→41%（§7）（llama2-13b-chat）。

（註：DSPy 讀作 dee-ess-pie，是先前 Demonstrate–Search–Predict 框架 DSP 的第二代。）

2. 相關工作

本工作受 Torch、Theano、Chainer 等在深度學習發展中提供強大抽象的角色啟發；作者稱之為 foundation model programming，借鑑可微分程式設計（但套在 LM 呼叫而非神經網路上）與 PyTorch 的語法。

  • In-context learning 是 foundation model programming 的關鍵機制：配合指令微調，可用 prompting 引出複雜行為；過去需任務專屬或手建啟發式的弱監督，如今由 LM 完成。
  • In-context 方法已常規化地呼叫工具（檢索模型、多模態基礎模型、API、計算機），催生 LangChain、Semantic Kernel、LlamaIndex 等工具包；但它們仍以手寫 prompt 模板表達任務專屬行為，正是 DSPy 要解的普遍痛點。
  • 已有人用離散優化與 RL 找有效 prompt，但多針對單一邏輯 LM 呼叫。DSPy 要一般化此空間：從高層宣告式簽章出發，透過帶約束地 bootstrap 高品質多階段示範，優化任意 pipeline；其 teleprompters 原則上可用交叉驗證、RL＋LM 回饋、貝式超參優化等。
