附錄 A 實作細節（要點）

A.1 資料集：ALFWorld 抽樣 200 訓練集為 D_support（seed=42）。WebShop test split 500 集，額外抽樣 500/250 goals 為 D_support/D_query（三集合互斥）。

A.2 LLM 設定：Worker 採用 ReAct 風格提示，ALFWorld 每集 50 步、WebShop 每集 15 步，每步最大生成 2048 tokens。外層組件（Distiller/Diagnoser/Planner）皆使用 GPT-5.4。

A.3 技能檢索：以混合評分器檢索 top-3：score(q, s) = 0.30·BM25(q, s) + 0.70·cos(e_q, e_s)。檢索文本由 title + principle + when_to_apply 組成。評分低於 0.30 者剔除。嵌入使用 text-embedding-3-small。

A.4 策展迴圈：固定 10 輪，每輪 Distiller → Diagnoser → Planner 依序執行。Pareto 選擇器 ϵ = 0.03，平手以 J_div + J_cov hypervolume 貢獻打破。前一輪銀行作為 null 候選——若其贏得平手則銀行不變。

A.5 反事實重播快取：以 SHA-256（任務 ID + 每個檢索技能的規範化內容）為鍵，worker 配置版本標籤失效機制。第二輪起命中率 >60%。

附錄 B 技能示例（要點）

論文展示了 ALFWorld 和 WebShop 最終策展庫中的代表性技能，以及一項技能在 Skill Diagnoser 的 REWRITE 判決前後的對比。ALFWorld 技能如「檢查並清潔所有物體再使用」；WebShop 技能如「購買前先確認所有屬性匹配目標規格」。REWRITE 示例顯示 Diagnoser 可將過於寬泛的技能精煉為更具體的版本。

附錄 C 提示（要點）

Skill Distiller 兩階段：先分析失敗軌跡找出缺失能力，再以成功軌跡生成具體技能。Skill Diagnoser 對比原本與反事實結果，生成每項技能的 KEEP/REWRITE/REMOVE 判決及理由。Edit Planner 以結構化 JSON 輸出 K 個候選銀行。
