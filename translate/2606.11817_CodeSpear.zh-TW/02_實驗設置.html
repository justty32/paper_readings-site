5. 實驗設置

5.1 研究問題

  • RQ1：CodeSpear 對本地部署 LLM 的效果（5 模型，三家族）
  • RQ2：CodeSpear 對商業 API LLM 的效果（5 模型，含 GPT-5 等）
  • RQ3：CodeShield 能否抵禦 CodeSpear（3 模型）
  • RQ4：CodeShield 是否保留良性程式碼生成能力（HumanEval/MBPP）
  • RQ5：CodeSpear 與 CodeShield 對關鍵超參數的敏感度

5.2 模型與基準

本地部署：Qwen2.5-Coder-7B/32B、Qwen2.5-7B/32B、LLaMA3-8B。API 商業：GPT-5、GPT-5-mini（OpenAI）；MiniMax-M2.5/M2.7、GPT-OSS-120B（Fireworks AI）。

安全基準：RMCBench（182 筆，10 類惡意場景）+ MalwareBench（320 筆，6 類）。皆使用原始請求子集以隔離 CodeSpear 效果。效用基準：HumanEval（164 題）+ MBPP（974 題）。

5.3 指標與基線

指標：ASR（LLM judge 判定有害比例）、MR（功能實現惡意意圖比例，更嚴格）、pass@k。CodeSpear 基線（7 個）：Vanilla、Vanilla-T、DAN、LRL、PAIR、APT（對抗性前綴樹，技術上最接近但需設計對抗語法）、CodeJailbreaker。CodeShield 基線（2 個）：Vanilla、Safe-DPO（僅自然語言拒絕對齊，無蜜罐碼 ≡ 消融）。

5.4 訓練資料與實作

PKU-RLHF 篩選惡意程式碼請求（Qwen3-32B 過濾 744 筆種子）→ DeepSeek-V4-Pro 擴增至 2,000 筆。每筆：DeepSeek-V4-Pro 生成拒絕、GCD 收集有害碼、OpenCodeInstruct 取樣蜜罐碼。llguidance 實作 GCD、K=5、lr 1e-5、1 epoch、混入 40k 通用任務保留效用。溫度 0.9、top-p 0.95、重複三次取平均。

6. 實驗結果

RQ1：本地部署 LLM

CodeSpear 平均 ASR 從 54.92%→81.82%（+26.90pp）、MR 從 36.61%→54.58%（+17.98pp），顯著超越所有基線。在 20 個模型–基準–指標組合中，CodeSpear 在 12 個案例取得最佳。通用越獄對惡意程式碼生成效果不佳——僅 CodeSpear 與 CodeJailbreaker 在 ASR/MR 皆有正向平均增益。原因：惡意碼生成高度依賴模型能力，通用越獄可能損害生成品質（如 PAIR 多輪互動降低 LLM 表現），而 CodeSpear 透過語法約束（原設計為提升程式碼能力）維持生成品質。

RQ2：API 商業 LLM

CodeSpear 在 API 部署中仍有效：平均 ASR 22.00%→67.39%（+45.39pp）、MR 11.04%→36.62%（+25.59pp）。GPT-5 與 GPT-5-mini 傾向在 GCD 下生成 pass 拒絕，但收緊 grammar 禁止 pass 後 ASR 進一步升高（GPT-5 RMCBench：55.49%→70.30%），證實固定程式碼模式的安全行為脆弱。

RQ1/RQ2 答案：CodeSpear 有效越獄本地與 API LLM，固定碼模式可被收緊語法繞過。

RQ3：CodeShield 防禦效果

  • 無 GCD：CodeShield 進一步強化內在安全（Qwen2.5-Coder-7B：ASR/MR 28.36%/22.05%→2.08%/0.80%）
  • 有 GCD（CodeSpear 攻擊）：顯著恢復安全（Qwen2.5-Coder-7B：ASR/MR 83.11%/54.12%→5.57%/2.78%；Qwen2.5-7B：84.28%/55.49%→5.61%/1.87%；LLaMA3-8B：66.74%/32.91%→7.87%/3.34%）

Safe-DPO（消融蜜罐碼）在無 GCD 時接近 CodeShield，但 GCD 生效後幾乎無效（Qwen2.5-Coder-7B ASR 77.39% vs CodeShield 5.57%），直接證實 code-modality 對齊的必要性。

RQ3 答案：CodeShield 透過將模型對齊至蜜罐碼在 GCD 下恢復安全，標準安全對齊一旦 NL 拒絕不可用即不足。

RQ4：良性效用保留

CodeShield 對程式碼生成效用影響輕微（Qwen2.5-Coder-7B MBPP pass@3：78.00%→77.00%）。部分模型甚至改善（Qwen2.5-7B MBPP pass@1：37.40%→44.93%），歸因於混入的 40k 通用任務。Safe-DPO 有較大效用損失（Qwen2.5-Coder-7B HumanEval pass@1：70.93%→66.26%）。

RQ4 答案：CodeShield 對一般程式碼生成能力的影響在可接受範圍內。

RQ5：敏感度分析

CodeSpear 在 Python/C++/Java 三種 grammar 下皆有效。CodeShield 蜜罐碼數量 K 從 1→10，ASR 持續下降而 pass@1 幾乎不變。較大 K 提供更多比較惡意碼與無害替代品的偏好對。

RQ5 答案：CodeSpear 跨 grammar 有效，CodeShield 受益於更多蜜罐碼樣本。

7. 討論

7.1 自適應攻擊下的穩健性

考慮知道 CodeShield 機制的更強攻擊者：每輪以 DeepSeek-V4-Pro 觀察回應並提出收緊語法（排除觀察到的蜜罐行為），最多 N=10 輪。三模型評估：CodeShield 的 ASR/MR 在自適應攻擊下幾乎不增加甚至下降。歸因於蜜罐碼結構多樣性——安全行為不錨定於單一可識別語法結構，攻擊者無法在不排除惡意碼所需結構的前提下壓制它。

7.2 評判可靠性與效度威脅

100 筆隨機樣本人工驗證：ASR 一致性 87%、MR 一致性 85%，支持 LLM judge 可靠性。效度威脅包括 GCD 實作差異（透過雙設定 + 多 grammar 緩解）、基準覆蓋率（10+6 類場景多樣性）與倫理考量（CodeSpear 僅向研究人員釋出、CodeShield 完全開源）。

8. 結論

本文提出 CodeSpear 與 CodeShield。在 10 個熱門 LLM 與 4 個基準上的全面實驗表明：CodeSpear 可有效繞過本地與 API LLM 的安全對齊；CodeShield 在 GCD 下恢復模型安全（ASR 從 83%→5~8%）並保留良性效用。源碼：https://github.com/TsinghuaISE/CodeSpear-CodeShield。
