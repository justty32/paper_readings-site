摘要

LLM agent 會在 episode 中途迴圈、連鎖觸發工具錯誤、偏離目標、捏造結果或吸收損壞內容。每一步都用第二個 LLM judge 代價可能高於 agent 本身。本文只用可觀測 telemetry，從健康 runs 訓練 one-class monitor；再加入內容 grounding、deterministic verification 與 rollback repair。統計 monitor 適合行為變化，確定性檢查適合可重算、可列舉的規格，殘餘案例才升級給 judge。

在作者彙整的 corpus 中，deterministic checks 在 served-temperature 同批案例抓 60% failure，加 coverage 為 96%，false positives 0/63；behavior monitor 為 54%、false positives 17%。Frozen checks 在後續 120 episodes 為 54%／93%、0/64。修復以 failure-check 名稱提示 agent，recover 45%，高於單純 resample 的 16%，net success 由 52% 增至 73%。

1. 引言

每個 agent step 都會產生文字、token 信心、工具呼叫、工具結果與 latency。研究問題是：能否用低成本 always-on watchdog，在 task 最終失敗或預算耗盡前，從這些串流偵測 derailment onset？要求是不讀模型內部、不用 failure labels、不中途呼叫第二個 LLM。

作者使用 2,823 episodes、25 datasets，涵蓋 bespoke、LangGraph、AutoGen，三個本地模型與 Gemini API；另建立 43 維 telemetry 模擬器做機制分析。研究特別強調負面結果：monitor 不跨 deployment transfer、organic failures 表現弱、silent abort 和可信但錯誤的數值需要別的機制。

2. 相關工作

方法建立在 CUSUM sequential change detection、one-class anomaly detection、Mahalanobis distance 與 echo-state network。與每個 prefix 用 7B LLM 審核的 AgentForesight、用 terminal outcomes 監督的 PrefixGuard 不同，本文只用健康 run，fit 只需 closed-form ridge regression。

作者也不主張 cheap、online、label-free 任一性質單獨新穎；貢獻是 causal per-step one-class monitor、deterministic hash embedding、低成本重新校準，以及在外部 corpus 上明示可用與失效範圍。若能讀模型 residual stream，內部 probe 可能更早；本文針對只能取得 API telemetry 的部署。
