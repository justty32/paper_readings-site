論文／訪談原始來源

神經符號語言推理即可滿足性模理論（SMT）

首爾大學 / UMass Amherst / Microsoft

摘要

自然語言理解需要交織文字推理與邏輯推理，但大型語言模型（LLM）常無法可靠地做這件事。現有神經符號系統把 LLM 與求解器結合，但只限於完全可形式化的任務（數學、程式合成），對「只有部分邏輯結構」的自然文件束手無策。本文提出 Logitext——一個把文件表示成自然語言文字約束（NLTC）的神經符號語言，讓部分邏輯結構顯式化。我們開發一個演算法，把基於 LLM 的約束評估與可滿足性模理論（SMT）求解整合，實現文字－邏輯的聯合推理。在一個新的內容審查基準，以及 LegalBench 與 Super-NaturalInstructions 上，Logitext 同時提升準確率與覆蓋率。本工作是首個把 LLM 推理當成一個 SMT 理論，將神經符號方法延伸到完全可形式化領域之外。

1. 引言

LLM 在自然語言邏輯推理上仍不可靠，常產生不一致或不完整的結果；邏輯求解器雖能提供保證，卻只限完全可形式化的領域。現有 LLM+求解器神經符號系統有兩大限制：

  1. 只能處理完全可形式化的設定，無法自然處理「文字＋邏輯」混雜的文件。
  2. 多採分階段（staged）架構——LLM 一次形式化、求解器執行——排除了許多自然語言任務所需的「文字與邏輯推理迭代交織」。

範例：政策「一則貼文若同時仇恨且為立即威脅就須移除」。「仇恨」「立即威脅」無法完全形式化，但可表示成 NLTC；Logitext 用邏輯合取串接這些文字約束，使決策同時取決於邏輯結構與文字判斷結果。

貢獻：（概念） 證明交織文字／邏輯推理的必要、刻畫分階段法的限制；（語言） 提出 Logitext，把文件表示成與 SMT 求解器對接的 NLTC；（NLTC 求解器） 提出解 NLTC 並擴展 SMT 框架的演算法；（評估） 在新內容審查基準上勝過分階段基線，在 LegalBench 與 SNI 上改善準確與覆蓋。

2. 文字理解中的文字／邏輯交織推理

以內容審查政策示範。一份多頁政策定義「破壞性行為」「立即威脅」等概念，配上任務描述與輸入訊息後變成 LLM prompt。

2.1 自然文字中的組合式 vs 組合爆炸式推理

  • 組合式（compositional）推理：判斷某訊息是否「破壞性（d）」或「立即威脅（t）」——需先一輪文字推理評估每個子句 C_i，再做邏輯求值。看似只需文字推理的 t，其實 C6（「表達暴力或滅絕意圖」）依賴先前 C4、C5 的邏輯析取，凸顯交織的好處。
  • 組合爆炸式（combinatorial）推理：受約束生成（給定部分賦值，生成滿足整個政策的訊息）需「邏輯求解器提議候選賦值 → 生成器合成文字 → 失敗則換賦值重試」。高覆蓋生成更難：要生成涵蓋所有滿足賦值的訊息，本質上要求邏輯求解與文字合成迭代協作。

2.2 邏輯推理鴻溝

定義「推理鴻溝」＝（LLM 做文字推理＋求解器做邏輯推理） 與 （LLM 獨自處理整個 prompt） 的效能差。

  • 組合式鴻溝：小模型大，強模型縮小；同模型內隨任務複雜度（互動子句數）增大。
  • 組合爆炸式鴻溝：差距驚人——即便 SOTA 的 GPT-5 也漏掉 SMT 求解器（Z3）能枚舉的 >99% 滿足賦值，GPT-4o-mini 全任務失敗。此鴻溝不隨模型規模縮小。Logitext 即為彌合這些鴻溝而設計。

3. Logitext：語言、表示與求解器

把傳統文字 prompt 標註成 Logitext 程式（§3.1），解析成一組混合 NLTC（§3.2），再用 LLM 求解器 NLSolver 配邏輯求解器產生最終回應（§3.3）。

3.1 Logitext 語言

把純文字 prompt 擴展成混合文字／邏輯文件，支援部分形式化：只標需要邏輯結構的部分。四種構件：

  • 變數宣告：(M:str, d, t, …)，可為布林或字串（字串須顯式定型，如 M:str）。
  • 文字 let 綁定：{{let C1 = [[子句]] where 子子句 is 變數}}——把文字子句綁到邏輯變數，並把子句內的子子句關聯到外部變數。
  • 子句間的邏輯定義：如 d = C1 and C2 and (C3 or C4 or C5)、t = C6 and C7。

3.2 自然語言文字約束（NLTC）

把文件解析成混合的文字／邏輯約束集合，使「文字判斷」與「符號約束」能協同。

3.3 解 NLTC

SMT 求解器逐步賦值並跨理論（字串/浮點/集合）傳播後果；加入 NLTC 後，傳播需迭代解文字約束以保持與布林條件一致。NLSolver 用 LLM 做 LLMPropose（提議賦值）與 LLMVerify（驗證約束），整合進既有 SMT 框架——等於把 LLM 當成一個 SMT theory solver。三類任務統一為 check() 約束檢查（分類 / 部分約束生成 / 覆蓋生成）。

4. 評估

4.1 基準與設定

  • 內容審查（CMOD，新建）：五份多頁政策（毒品 22 子句、政治 8、宗教 6、霸凌 21、詐騙 12）。
  • LegalBench（LB）：5 項任務，每項 20–50 行、2–4 標註子句。
  • Super-NaturalInstructions（SNI）：5 項任務，每項 3–10 行、2–5 標註子句。 三種設定：任務執行（TE，分類準確率）、文字實例生成（TIG）、文字覆蓋生成（TCG）。

4.2 結果

  • TIG：用 GPT5 / GPT5-nano 皆能透過 check() 可靠生成有效賦值；弱模型 GPT5-nano 近飽和，直接 prompt 強模型 GPT5 反退化（複雜 CMOD 政策最明顯）。
  • TCG：固定 3000s 預算下覆蓋更廣（尤其 GPT5-nano）；候選生成用求解器枚舉而非反覆 LLM 呼叫，快很多；求解階段瓶頸在 NLSolver 呼叫。
  • TE：在 CMOD、NI 上勝過 few-shot 與「生成並執行程式碼」基線，但 LegalBench 上反而較弱。兩大錯誤源：(i) LLM 把單一子句 C_i 判錯，而純 LLM 用整體推理反而對（穩健性短板）；(ii) 列表「x, y, and z」本為舉例卻被標成合取。擴充至每任務 100 樣本後，TE 10 項勝 7、LegalBench 5 項勝 4、SNI 5 項勝 3。子句層級推論其實多半正確（子句準確率遠高於整份文件準確率）。

5. 相關工作 / 6. 結論

首個把 LLM 推理形式化為 SMT 理論、支援「部分邏輯結構」推理的框架。在受約束生成與分類上跨多基準提升效能，同時點出子句層級穩健性與標註處理的待解問題。
