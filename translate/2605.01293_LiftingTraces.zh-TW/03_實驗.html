6. 實驗

6.1 設定與基線

三個智能體基準：(1) ALFWorld（Shridhar et al., 2021）——文本具身家居環境，134 測試實例跨六種任務類型，以標準的每任務類型 2 條示範（原用於上下文提示）作為離線誘導資料；(2) WebShop（Yao et al., 2022a）——電商平台，評估導航產品頁面、選擇屬性、執行購買的能力，僅以單次成功購買軌跡進行技能誘導（對齊標準的一次性示範設定）；(3) TextCraft（Prasad et al., 2024）——Minecraft 合成組合泛化，200 遞迴任務（depth 2–4），僅以 3 條 depth=1 專家軌跡要求智能體組合原語來解決未見長時程目標。

基線：ReAct（Yao et al., 2022b）、Reflexion（Shinn et al., 2023）、ADaPT（Prasad et al., 2024）、StateAct（Rozanov & Rei, 2025）、AWM（Wang et al., 2025c，將成功軌跡抽象為文本工作流記憶）、ASI（Wang et al., 2025b，參數化程式化技能但缺顯式邏輯控制流與變數綁定）。所有方法使用 GPT-4o，溫度 0。

6.2 主要結果

NSI 在三個基準上持續大幅超越最強基線。ALFWorld：NSI 98.0%（含線上打磨）vs ASI 70.6% / AWM 91.3%；WebShop：NSI 76.5% 得分（含打磨）vs 最佳基線 AWM 51.8%；TextCraft：NSI 95.2% vs ADaPT 72.5% / ASI 77.8%。

關鍵發現：(1) 非結構化記憶的局限——Reflexion 的語言逐幕記憶在跨幕泛化上增益微小；(2) 表達性的必要性——AWM 透過抽象為文本工作流取得穩定增益，但 ASI 將其形式化為參數化程式後效能反而下降，揭示線性腳本無法捕捉任務內在複雜邏輯；(3) 邏輯接地技能的優勢——NSI 的神經符號學習將可重用流程內化為可驗證、狀態感知的邏輯（分支、迴圈），顯著增強子目標實現能力。

效率與長時程穩健性：NSI 每次技能調用平均執行原子步驟數比 ASI 提升 100%–140%，表示更高語義抽象與邏輯凝聚。生存分析顯示基線在 22 步門檻發生長時程崩潰（Long-Horizon Collapse，累積推理錯誤導致成功率歸零）；NSI 將有效執行維持至 53+ 步，透過每次技能封裝約 7.4 個原子動作有效壓縮規劃視野。

6.3 模組化技能打磨

圖 3 展示了 ALFWorld（clean_item_and_place，含 CheckOp not is_closed(TOREC) 與失敗嫁接）、WebShop（search_and_open_product，含 DataOp 產品選擇與 Next Page 迴圈邏輯）、TextCraft（craft_item_from_ingredients，含 LoopFold 原料迭代與 Provisional Module 的條件修正）的代表性案例。初始技能為從最小離線資料誘導的邏輯骨架；運行時失敗暴露邏輯缺口，反思規劃捕捉失敗生成局部修正軌跡，合成功能子圖後嫁接至 Failure 節點。終端失敗轉為條件恢復分支，技能從簡單線性鏈演化為穩健分支網路，修復自身邏輯而不改變正確運作的部分。線上打磨消融：移除線上打磨後效能大幅下降（ALFWorld 93.5% vs 98.0%，WebShop 58.8 vs 76.5，TextCraft 78.5 vs 95.2），驗證反思規劃是關鍵組件。

7. 結論

本文提出 NSI，將瞬態智能體推理轉化為持久、邏輯接地的技能。透過將互動軌跡提升為模組化程式，NSI 超越線性參數化腳本的限制，合成顯式控制流與動態變數綁定。反思式規劃機制賦予智能體在部署期間自主修復並增長技能圖的能力，將運行時失敗轉化為永久邏輯改進。在具身、網頁、遊戲領域的實驗表明 NSI 顯著壓縮規劃視野並實現高效泛化。

8. 影響聲明

NSI 增強 LLM 驅動智能體的長時程規劃與泛化能力，透過軌跡到邏輯的提升促進資源高效 AI 開發，減少對大量示範資料或手動工程的依賴。然而，更強大的自主智能體可能被誤用於敏感領域，應配合嚴格安全對齊與倫理護欄部署以降低偏見或非預期行為的風險。

附錄 A — NSI 的表示語言

NSI 以領域特定語言（DSL）表示邏輯接地技能，基於一階邏輯（FOL）接地詞彙。表 2 定義領域無關語言：變數（x, y, z）、型別（Object, Num, Bool, List）、條件運算子（predicate, not, and/or, 數值比較）、變數綁定運算子（count, 算術運算， select_idx, select_one, select_all）。語言含兩層——表達式層（節點內查詢狀態推導變數，含 FOL 謂詞與集合運算）與控制層（指定工作流結構，條件分支與迴圈直接編碼到 πω 的圖拓撲中）。

技能節點語意：(1) DataOp 作為變數綁定單元，執行合成函數 fv 將抽象引數解析為具體實體（如 target = select_one(Os, is_apple(x) ∧ is_clean(x))）；(2) ControlOp 作為決策閘門，評估布林謂詞 pv 決定控制流方向，顯式處理環境變化（如開/關門）而不產生幻覺動作；(3) PrimitiveOp 代表環境原子介面，引數嚴格從 C 提取；(4) TerminalOp 標記執行結束，失敗時返回符號診斷驅動反思規劃。

表 3 定義各基準的任務特定謂詞：ALFWorld（is_type, is_clean, is_hot, is_cool, is_open, contains, holds, locates）；WebShop（if_clickable, description_match, price_match, current_price_match, current_description_match, current_option_match, current_option_clicked）；TextCraft（goal, inventory, unavailable, current_count_of_item）。

附錄 B — 實驗細節

所有基線使用 GPT-4o，溫度 0.0。核心系統指令包括：

觀察到謂詞 Prompt：將原始觀察（文本）轉換為接地的謂詞事實（add_facts / remove_facts），使用規範謂詞名稱與參數順序（如 locates(receptacle_id), contains(receptacle_id, item_id), holding(item_id) 等），要求蛇形命名與數字後綴。

子目標萃取 Prompt：從互動軌跡摘要子目標，規定中等複雜度（至少兩個原始動作、步驟 2–5 項）、可泛化性、顯式列出輸入參數與型別（ReceptacleName, ItemName, List_T 等）、開始條件、成功條件、步驟分析（支援「If , then 」的分支與迴圈表示）。

技能誘導 Prompt：產生 Mermaid 流程圖風格的節點綁定輸入、純邊界控制的技能工作流，使用 DataOp/Check/LoopControl/PrimitiveAction 節點類型與類定義，嚴格遵循變數作用域、資料流順序、雙大括號占位符等約定。

技能-動作路由器與執行 Prompt：路由 prompt 決定使用技能或原始動作（提交最多三個候選並附證據），執行 prompt 遵循路由推薦調用技能（附參數綁定）或原始動作。
