3. AutoGen 的應用

作者示範六個應用（圖 3），依「真實世界相關性、問題難度與 AutoGen 賦予的解題能力、創新潛力」挑選：

A1 數學解題：（情境 1）直接重用兩個內建代理即可建自主解題系統；在 MATH 資料集上與 Multi-Agent Debate、LangChain ReAct、vanilla GPT-4，以及商用 ChatGPT+Code Interpreter、ChatGPT+Plugin（Wolfram Alpha）比較（皆用 GPT-4 為底），內建代理開箱即用就勝過所有對照方法（含商用）。（情境 2）只需設 human_input_mode='ALWAYS' 即納入人類回饋，解決無人時無法解的難題。（情境 3）進一步示範多位真實使用者（student／expert）共同參與解題。附錄 D 量化：全 5000 題測試集 AutoGen 準確率 69.48% vs GPT-4 的 55.18%。

A2 檢索增強的程式生成與問答：用 AutoGen 建 RAG 系統「Retrieval-augmented Chat」，含兩代理——Retrieval-augmented User Proxy（內含 Chroma 向量庫＋SentenceTransformers 檢索器）與 Retrieval-augmented Assistant，皆由內建代理擴展而來。（情境 1）在 Natural Questions 上與 DPR 比較；AutoGen 引入創新的互動式檢索：當檢索脈絡不含所需資訊時，助手不終止而回覆「Sorry, I cannot find any information about… UPDATE CONTEXT.」以觸發更多檢索。消融（改成回「I don't know」）顯示此互動檢索機制作用不小。（情境 2）示範基於「不在 GPT-4 訓練資料內的程式庫」生成程式碼。

A3 文字世界環境中的決策：在 ALFWorld（家庭情境的語言互動決策任務）上，用 AutoGen 建兩代理系統——LLM 助手代理（提出計畫）＋執行代理（在環境中執行動作），整合 ReAct prompting，達到相近表現。ReAct 與此兩代理系統的共同弱點是偶爾無法運用基本物理常識、陷入重複錯誤迴圈。靠 AutoGen 的模組化設計引入一個 grounding agent，在系統露出重複錯誤徵兆時適時提供關鍵常識（如「你必須先找到並拿起物件才能檢視它；必須先到目標物件所在處才能使用它」）。在 134 個未見任務上（GPT-3.5-turbo）與 ReAct 比較，引入 grounding agent 平均帶來 15% 效能提升，顯著緩解系統固執於錯誤計畫的傾向。

A4 多代理寫碼：基於 OptiGuide（擅長寫碼解讀供應鏈最佳化解、回答使用者問題）建多代理系統。工作流：使用者把問題（如「若禁止供應商 1 出貨給咖啡烘焙廠 2 會怎樣？」）送給 Commander；Commander 協調 Writer（寫碼）與 Safeguard（安檢）；Writer 產碼交 Commander，Commander 先請 Safeguard 檢查安全，通過才用外部工具（如 Python）執行，再請 Writer 解讀結果（如「總成本會增加 10.5%」），最後把結論回覆使用者；若 Safeguard 舉紅旗，Commander 帶除錯資訊把問題退回 Writer，過程可重複多次。用 AutoGen 後核心工作流程式碼由 430+ 行縮到 100 行，生產力大增；並省約 3 倍使用者時間、減少 3–5 倍互動。消融證明多代理抽象是必要的：對照「單一代理同時寫碼與安檢」，在 100 個（安全／不安全各半）程式任務上，多代理設計把辨識不安全程式碼的 F1 提升 8%（GPT-4）／35%（GPT-3.5-turbo）。

A5 動態群聊：AutoGen 原生支援動態群聊——參與代理共享同一脈絡、以動態方式（而非預定順序）對話。GroupChatManager 反覆做三步：動態選發言者、收集其回應、把訊息廣播給其他代理；選發言者採角色扮演式 prompt。在 12 個手工複雜任務的前導研究中，角色扮演式 prompt 比純任務式 prompt 更能兼顧對話脈絡與角色對齊，帶來更高成功率與更少的 LLM 呼叫。

A6 對話式西洋棋：用 AutoGen 開發自然語言介面的西洋棋，含玩家代理（可為人或 LLM）與第三方 board agent（依標準規則提供資訊並驗證棋步）。啟用兩項關鍵特性：(1) 自然、彈性、引人入勝的對局動態，支援 AI–AI、AI–人、人–人並可於單局中無縫切換；(2) grounding（接地）——board agent 檢查每一步是否合法，非法則回錯誤、要求玩家代理重提合法棋步，確保棋局完整性。消融：移除 board agent、改用 prompt 提醒「你應確保雙方都下合法棋步」，結果非法棋步造成棋局中斷——凸顯確定性驗證節點的必要。模組化設計也讓 board agent 能因規則變體快速調整。

4. 討論

作者推出開源函式庫 AutoGen，融合「可對話代理」與「對話式程式設計」兩範式，提供代理間統一對話介面與自動回覆機制，善用對話最佳化 LLM 的廣泛能力，容納廣泛應用。實驗（§3）顯示諸多益處：表現超越 SOTA、程式碼變少、人工負擔降低；提供彈性（A1 情境 3、A5、A6 讓多代理走動態模式而非固定往返）；讓人以對話方式與多個 AI 代理協作。儘管這些應用複雜（多含兩個以上代理或動態多輪協作），基於 AutoGen 的實作仍簡潔；把任務分派給不同代理促進模組化，各代理可獨立開發、測試、維護。

本工作仍屬早期實驗階段，但開啟諸多方向：如何有效整合既有代理實作、如何在自動化與人類控制間取得最佳平衡、哪種代理拓撲與對話模式最有效等。增加代理數與自由度雖能處理更複雜問題，也可能帶來新的安全挑戰，需審慎研究。

倫理聲明（摘要）

作者列出數項考量：隱私與資料保護（框架允許人類參與對話，須保護使用者資料）；偏見與公平（LLM 帶有訓練資料偏見，須察覺並緩解）；問責與透明（多代理協作須可追溯決策過程）；信任與依賴（須清楚溝通系統能力與限制）；非預期後果（允許 LLM 代理透過程式碼執行或函式呼叫改變外部環境——如安裝套件——有風險，須設適當防護）。

附錄 A 相關工作（重點）

作者把相關系統分為單代理與多代理，並在表 1 對照 AutoGen 與其他多代理系統。

  • 單代理系統：AutoGPT（自主達成目標，單代理＋工具，不支援多代理協作）；ChatGPT+（code interpreter／plugin，付費）；LangChain Agents（通用 LLM 應用框架的子套件，用 LLM 選一連串動作，如 ReAct 代理；皆單代理範式，非為協作設計，甚至其 CAMEL 重實作也不是基於 LangChain Agents 而是從頭寫）；Transformers Agent（HuggingFace，單代理＋工具）。AutoGen 的差異在於支援多代理 LLM 應用。
  • 多代理系統：BabyAGI（多 LLM 代理的任務管理腳本，但採靜態對話模式）；CAMEL（溝通式代理框架，角色扮演＋Inception-prompting，但不原生支援工具／程式碼執行、僅靜態對話）；Multi-Agent Debate（多 LLM 實例辯論，無工具與人類、須預定順序）；MetaGPT（把不同角色指派給 GPT 協作做軟體開發的特化方案）。
  • 表 1 對照要旨：AutoGen 在四維度上勝出——Infrastructure（是否為通用基礎設施）：AutoGen ✓、CAMEL ✓，其餘 ✗；Conversation pattern：AutoGen＝flexible（靜態＋動態），其餘皆 static；Execution-capable（能否執行 LLM 生成的程式碼）：AutoGen ✓、MetaGPT ✓，其餘 ✗；Human involvement：僅 AutoGen＝chat/skip（可對話介入且可跳過），其餘 ✗。
