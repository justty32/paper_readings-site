論文／訪談原始來源

Memorizing Who, Knowing How: Benchmarking Personal and Procedural Memory for Persistent Assistants

摘要與第1節：為誰服務，決定如何行動

持續個人助理既要記住使用者，也要記住程序。兩者不能只是互不相干的脈絡槽：使用者的偏好、限制及關係，會決定哪個程序適用、如何實例化，以及何時應修訂。單次寫對記憶仍不足，後續更新可能破壞個人資訊與程序間的關聯。PraxisMemBench以生活及工作軌跡檢驗這種共同維護；PraxisMem則學習記憶內容與組織位置。§1

第2節：基準建構與持續評估

建構者依序維護個人、程序、關聯及應用狀態，選事件、領域與標準作業程序，產生自然請求、工具環境及評分規則。新資訊首次出現時會明示；之後依賴它的請求省略歷史條件。獨立測試者看公開請求、必要記憶及工具介面，不看fixture、參考步驟或評分碼；通過驗證才推進建構狀態。§2.1–2.2、C.2

作者自報訓練與測試各20名使用者、500個session、20個應用領域，領域池分開；每軌跡25個session。測試有2,185個記憶依賴，360個可執行任務中303個需共同使用兩類記憶。Scheduled在預定時點檢索；Autonomous讓助理面對較不具體的請求，自行決定何時及如何查記憶。§2.3、C.3

正式評估按時間自由運行，將實際記憶及應用狀態帶入下一session；失敗造成的物件遺失、已消耗狀態等漂移不由runner修復。建構用標準狀態不會覆蓋受測軌跡。附錄D

第3節與附錄B：把共同狀態變成訓練訊號

PraxisMem以同一管理器做Update及Retrieval。USER.md放當前個人資訊，events/*.md記時間變化，領域SKILL.md存程序；MEMORY.md由目前狀態連到事件，再由事件連到程序，沒有直接skill連結。這是PraxisMem的表示法，並非基準要求唯一正確的記憶格式。Update可封存與編輯；Retrieval僅列目錄、詞彙搜尋及讀檔，回傳精簡脈絡。§3.1、B.1–B.2

位置感知GRPO比較實際與標準狀態的變化。先限定型別相容、語意達門檻的配對，再依「位置正確數、配對覆蓋、語意相似」的字典序選一對一匹配。作者自報錯位置但語意相符的權重為0.2；多餘預測降低precision、遺漏目標降低recall。事件不罰位置，個人／索引單位看標題，程序看領域skill路徑。Update獎勵為0.8 F_state + 0.1 R_format + 0.1 R_eff；Retrieval不改狀態，因此無位置懲罰。§3.2、B.3

若同組rollout全都漏掉某項準則，僅靠相對獎勵沒有成功範例可學。動態殘差OPSD先啟動全組未滿足的準則，再只監督其缺陷仍存在的chunk。殘差比較學生實際狀態與當時目標，指出缺失、過時、衝突、錯置及冗餘；早先錯誤會持續可見，直到修復。教師只在訓練看到與啟動準則相關的殘差，用凍結策略快照對學生自己的token評分，不另生成替代軌跡。GRPO覆蓋完整有效管理器token，OPSD只覆蓋被選chunk；部署不給標準狀態或殘差。§3.3、B.4

第4節與附錄D–F：結果如何解讀

作者使用Qwen3.7-Plus作任務代理、GLM-5作使用者模擬器及語意裁判，PraxisMem由Qwen3.5-9B訓練。工具與產物結果另有程式檢查；每方法報一次完整測試集推論。受控方法最終注入記憶上限為作者自報4,096 tokens；Long Context用128,000-token總脈絡，超限先刪最舊歷史。§4.1、E.1

Session SR是記憶條件診斷。作者規定Tool／Artifact各適用個人與程序維度至少0.75；Memory QA需F1至少0.75且precision、recall各至少0.60。Strict E2E還要求完整執行及結果成功，不能混稱。少數session在人類最終驗證後排除；overall按符合資格session合併計算，不是三類平均。附錄D式40–41

作者自報Scheduled結果如下；這些SR不能當成完整工具任務成功率：

前三欄見表2，overall見表18。作者自報固定前八條測試軌跡消融中，content-only GRPO至完整PraxisMem的Combined Completion由66.2%至83.4%，Interdependent Completion由54.9%至82.1%，Avg SR由23.5%至43.1%；前兩項合併工具步驟與產物assertion，與Session SR不同。表3

DualMem分庫維護、任務前才合併檢索。作者自報其Combined Completion在個人專屬84.7%、程序專屬84.5%、協同80.1%、相互依賴77.9%；更強依賴的邊際檢索覆蓋反而較高，故不能把差距只歸於沒取回資料。MemOS、Hermes及PraxisMem的失敗稽核顯示，關聯相關失敗占比由早期59.8%升至後期72.9%；這是失敗組成，並非所有任務失敗率。§4.3、F.4–F.5

作者自報Autonomous下PraxisMem三類SR為23.00%、22.22%、31.64%，可靠自主查記憶仍是未解問題。Oracle只供正確記憶，後續整合、參數接地與執行仍可能錯誤；它是固定任務代理下的記憶供給上界，不是完美求解器。F.1–F.2
