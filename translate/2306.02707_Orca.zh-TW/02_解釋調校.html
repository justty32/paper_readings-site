3 解釋調校

為解決既有方法的不足，我們運用大規模、多樣任務、搭配複雜指令與豐富訊號的訓練資料，取材自 FLAN-v2 collection 中人類與增強系統指令共同構成的大量任務。

3.1 資料集建構

每筆訓練樣本為三元組 {系統訊息， 使用者查詢， LFM 回應}。系統訊息置於提示開頭，提供 LFM 必要的脈絡、準則等資訊——我們用它調節回應長短、設定助理性格、界定可接受行為、決定回應結構；使用者查詢定義實際任務，取材 FLAN-v2 以取得大量多樣查詢。共取樣 500 萬則使用者查詢蒐集 ChatGPT 回應，再從中取樣 100 萬則蒐集 GPT-4 回應。所有查詢皆以系統指令增強。

3.1.1 系統訊息：手工設計共 16 則系統訊息（表 2），涵蓋「空白系統訊息」「詳細作答不需使用者外查」「像對五歲小孩解釋」「逐步思考並論證步驟」「先給正確答案再解釋其他選項為何錯誤」「把任務定義拆解成小部分並逐一舉例說明」等，讓 Orca 學會生成長短不一的答案、遵循格式指引、產生創意內容與資訊型回答，最重要的是——依提示生成解釋與逐步推理。不同 FLAN-v2 子集合套用不同系統訊息分佈（圖 6），其中訊息 #8、#10 僅用於選擇題故頻率較低。

3.1.2 FLAN-v2 collection 取樣：FLAN-v2 含 CoT、NiV2、T0、Flan 2021、Dialogue 五個子集合，本研究僅取樣零樣本查詢，跳過 Dialogue（其查詢常缺乏引出有用 ChatGPT 回應所需的脈絡）。Zero-Shot CoT：18 個任務（數學文字題、自然語言推理、常識推理、科學問答、奇一項推理），約 15 萬則查詢，全數納入。NiV2：1560 個任務、約 500 萬則查詢，每任務隨機取 300 則（查詢數不足者全取），共取 44 萬則。Flan 2021：142 個任務（源自 62 個資料集），總計約 2,890 萬則查詢，用演算法 1（隨機取任務、任務內無放回隨機取查詢，任務取盡即移除）取 250 萬則。T0：193 個任務（35 個資料集），僅納入訓練切分（排除 Big-Bench，因後者用於評估），約 8,570 萬則查詢中取 200 萬則。合計構成 500 萬筆訓練資料（表 3）。圖 7 舉例展示同一則 CoT 查詢下，人工原答案、ChatGPT、GPT-4 三種回應的差異：三者最終答案一致，但 ChatGPT／GPT-4（配合系統指令）產生的回應遠比人工原答案詳細。

3.1.3 ChatGPT 作為教學助理：以上述取樣產生的 500 萬則指令稱為 FLAN-5M，再隨機子取樣 100 萬則為 FLAN-1M。用 Azure OpenAI API 對 FLAN-5M 收集 ChatGPT（GPT-3.5-turbo）回應，對 FLAN-1M 收集 GPT-4 回應。訓練分兩階段：先在 FLAN-5M（ChatGPT 增強）上訓練，再接續在 FLAN-1M（GPT-4 增強）上訓練，以 ChatGPT 當中介教學助理的理由有二：

  • 能力落差（capacity gap）：Orca（13B）遠小於 GPT-4（尺寸未公開），既有知識蒸餾研究顯示，用能力落差較小的中介教師（此處為 ChatGPT）可改善小模型的模仿學習效果，可視為一種漸進式／課程學習——學生先學較易的範例，再學較難的範例，假設是「較長回應較難模仿」，且更大的教師能提供更豐富的推理與逐步解釋。
  • 成本與時間：Azure OpenAI API 大規模資料蒐集受限於每分鐘請求數配額、每分鐘可用 token 數（受服務延遲影響）、以及依提示與補全長度計費的美元成本（表 4：ChatGPT 每千 token $0.002、每分鐘 300 請求／12 萬 token；GPT-4（8K）每千 token 提示 $0.03／補全 $0.06、每分鐘僅 1 萬 token），ChatGPT API 遠比 GPT-4 端點快且便宜。故蒐集的 ChatGPT 資料量是 GPT-4 的 5 倍。圖 9 顯示 GPT-4 回應平均比 ChatGPT 長 1.5 倍，這使 Orca 得以隨教師解釋複雜度遞增而漸進學習；消融實驗驗證了教學助理的效果。

3.2 訓練

分詞：採 LLaMA BPE tokenizer，數字逐位拆分、未知 UTF-8 字元退回位元組表示；新增 padding token 「[[PAD]]」，詞表共 32,001 個 token。Packing：將多筆樣本串接為單一序列以提升訓練效率，總長度不超過 max_len=2,048 token；先打亂樣本再依長度分組，並補 padding token 到統一長度，實測 packing factor 為每序列 2.7 筆樣本。損失：僅對教師模型生成的 token 計算損失（不含系統訊息與任務指令本身），確保模型聚焦學習最相關、資訊量最高的 token。算力：20 張 NVIDIA A100（80GB）；FLAN-5M（ChatGPT 增強）訓 4 epoch 耗時 160 小時，FLAN-1M（GPT-4 增強）續訓 4 epoch 耗時 40 小時；資料蒐集本身耗時（考量限流、端點負載、查詢/回應長度分佈）ChatGPT 2 週、GPT-4 3 週。

4 實驗設置

設定涵蓋寫作、理解、分析、數學、邏輯推理等多面向的嚴謹評估協議。

4.1 基線：Text-Davinci-003（GPT-3.5 系列，優化文字補全）、ChatGPT（GPT-3.5-turbo，優化對話）、GPT-4（最新一代，多項專業/學術基準達人類水準）、Vicuna-13B（以 LLaMA-13B 微調 ShareGPT 對話資料，2023-04-21 版本，多個排行榜居冠的開源模型）。除特別說明外，Orca 各實驗一律用空白系統訊息、temperature=0.7。

4.2 任務：開放式生成能力——沿用 Vicuna 提出的 GPT-4-as-judge 評分框架（0–10 分），在 Vicuna Prompts（80 題，9 類技能）、Awesome Prompts（164 個角色扮演式提示）、WizardLM Prompts（218 題，29 類技能與難度標註）三個資料集上評估。推理能力——AGIEval（源自 GRE/GMAT/SAT/LSAT 等人類標準化考試，僅取英文選擇題部分，共 3,546 題）；Big-Bench Hard（23 項人類評分者過去平均勝過模型的高難度任務，僅取選擇題形式，共 5,511 題）。選擇題一律採 AGIEval 的提示模板與解析邏輯（「Among 0 through 3, the answer is」句式接續，僅取回應中第一個大寫字母比對正確答案，若答案出現在後段則視為未命中），評估設定皆為零樣本、無範例、無 CoT。

5 開放式生成評估

表 7（GPT-4 當裁判，以 ChatGPT／GPT-4 為參照模型計算候選模型的相對分數）：Orca 整體保有 ChatGPT 95%、GPT-4 85% 的品質，較 Vicuna-13B 提升約 10 個百分點；在 Vicuna 原始評測設定下與 ChatGPT 打平；在涵蓋 164 種生成角色的 Awesome Prompts 上保有 ChatGPT 98%、GPT-4 89% 品質。作者提醒：GPT-4 評分對「先呈現的模型」有正向偏誤（呼應近期文獻），以上評估皆依 Vicuna 慣例把參照模型放在前面；若把候選模型放前面，Vicuna 在 WizardLM Prompts 上的分數會從原本明顯落後大幅拉近至接近 WizardLM 報告值，顯示 GPT-4 評分可能有明顯偏誤。
