摘要

C/C++ 原始碼上的漏洞挖掘，逼分析者在兩者間取捨：重量級靜態分析器（跑任一查詢前先要能成功編譯）與自由形式 LLM（讀原始碼容易，卻會捏造細節、在真實碼庫上丟失跨函式資料流）。本文提出 NeuroLog——一條端到端、免編譯的流水線，把每層分派給它獨擅的角色：LLM 逐函式抽取具型別的資料流事實；Soufflé 規則網把事實合成跨函式發現；Z3 後處理過濾不可行發現、為存活者輸出 SAT 模型。為了超越純靜態推理，再折入執行期證據：少量語料種子得到的 likely range invariants 以近零成本收緊 SMT 問題。第二個 LLM agent 讀每個 SAT 模型、寫出產生候選崩潰輸入的 Python 程式，由 AddressSanitizer harness 驗證。「靜態收窄＋SMT」（Saturn、Pinpoint）與「Datalog＋SMT」（Formulog）是既有技術；新的是LLM 導出的事實庫、免建置流水線，以及把 SAT 模型當成工件（崩潰合成的輸入）而非是/否判決。在 stb、cJSON、libxml2、FFmpeg demuxer 切片與 curl 8.3.0 上，NeuroLog 端到端重現 8 個 CVE 級問題（含 CVSS-9.8 的 SOCKS5 堆溢位 CVE-2023-38545），全數 ASan 確認；在 libarchive HEAD 上挖出 5 個記憶體安全 bug（4 個前所未報）。

1. 引言

NeuroLog 解決 C/C++ 漏洞挖掘的根本張力：CodeQL 類靜態分析器要先成功編譯才能跑查詢，而自由形式 LLM 讀碼方便卻捏造細節、丟失跨函式資料流。核心貢獻：「用逐函式的 LLM 取代 IR-lifting 編譯器，讓它吐出具型別的 Datalog 事實」，同時靠 schema 約束維持可審計性——每個結論都有以具體程式事實為葉節點的推導樹。系統重現 8 個已發表 CVE，並在 libarchive HEAD 上挖到 5 個新 bug。

2. 背景：四個技術支柱

  • Datalog 靜態分析：以 Horn 子句做宣告式漏洞偵測；Soufflé 把 Datalog 合成 C++，達「完整關聯吞吐量」同時保留可審計性。
  • CPG 與 CodeQL：圖式可達性查詢可審計，但需編譯。NeuroLog 刻意分道揚鑣：用逐函式 LLM 抽取取代 IR-lifting。
  • 符號執行與 SMT：KLEE、SAGE 類 fuzzer 顯示 Z3 後端能沿特定路徑編碼求滿足輸入或證明不可行；NeuroLog 的優化是「被 Datalog 發現而非程式分支因子所界定」。
  • LLM 做靜態分析：近期工作（IRIS）顯示 LLM 擅長推斷（sanitizer 辨識、API clone、文件解析）。NeuroLog 把 LLM 放在規則網之下：只做逐函式事實抽取、schema 受限輸出，寧可漏報也不捏造。
  • Likely Invariants 與失敗素描：借 Sahoo 等人的觀察（8–16 次正常輸入跑出熱點區域變數的緊範圍界）與 Kasikci 的 Gist（σ-doubling 自適應後向切片）。

3. 啟發範例：stb_vorbis 的 CVE-2023-45676

stb_vorbis.c 第 3652–3676 行配置 Vorbis comment 字串，兩種失敗模式利用攻擊者提供的 32-bit 長度：(1) 第 3664 行乘 sizeof(char*) 在 length=2^29 時 32-bit size_t 環繞為 0；(2) 第 3670 行加 1，使 len=UINT32_MAX 產生 0-byte 配置，後續迴圈寫越界 UINT32_MAX bytes。

  • 古典靜態分析卡在：CodeQL/CPG 要先把 stb 建成可索引形式；單一 header 函式庫整合成本高。
  • 自由形式 LLM 卡在：讀 5,000 行檔有時抓對、有時抓語法相似但無趣的位置、偶爾在不存在的行捏造 bug，且無推導鏈、上下文一長工作記憶退化。
  • NeuroLog 做法：把 LLM 當逐函式事實抽取器，吐出 Def、Call、ArithOp、ActualArg 等結構化元組；Datalog 規則把事實組成推導樹：TaintSourceFunc(get32_packet) → TaintedVar(...,len) → TaintedNarrowArith（報告），每步機械可審計。SMT 階段把 len 編成自由 32-bit BitVec、回走 def-use 鏈，證明 size 引數沿可行路徑可被攻擊者控制；合成 agent 寫 Python 產 102-byte Ogg/Vorbis 檔，ASan harness 驗證。

4. 架構：六階段流水線

每階段產出單一輸出供下一階段消費，允許「在任一階段停下取部分工件」。

  • Stage 0 可選偵察：廉價 LLM 讀目標檔＋呼叫者，提出種子函式與「bug 類別假設＋形式檢查」；用 FieldSemantic(func,field,role) 提議，只有真正觸發的形式規則才裁決。
  • Stage 1 切片：Tree-sitter 增量解析，從敏感 sink 後向切片；σ-doubling（增長率 ≤5% 取最小 σ）。FFmpeg demuxer 推薦 σ=3（109→124→124 函式，σ=4 時增長 1.6%）。
  • Stage 2 氣味掃描：機械底座（確定性結構事實）＋ LLM 用固定 12 關係 schema 逐函式輸出 JSON；每個事實須落在具體原始碼行，禁止發明關係，不確定就省略。
  • Stage 3 Datalog：約 30 條規則五趟（別名→跨程序汙染→型別安全→記憶體安全→sink）。只做 may-flow 過近似，不裁決可行性。Pass 6「source_arith_sink_bridge」補 LLM 暫存變數缺口（recovered 6/6 CVE-2025-6021 site，從 181 候選中）。
  • Stage 4 符號執行：逐發現給 {feasible/infeasible/unknown}；Phase A 程序內、Phase B 函式摘要＋有界內聯（d=3）、Phase D 跨發現並行。可行者帶 SAT 模型；不可行者降階到次級層並附「排除它的 guard」反向指標。
  • Stage 5 合成：多輪 LLM agent 讀 SAT 模型＋def-use 鏈＋檔案格式骨架，產 Python；每輪 N=3 候選，無崩潰則把 ASan 尾巴＋解析進度分數餵下一輪，預設 5 輪。
  • Stage 6 harness：唯一被建置的工件——ASan 驗證；ASan 可辨識簽章＋非零退出才算崩潰。
  • Tier-don't-drop 原則：任何精度步驟都不靜默丟棄發現，只降階並附理由；次級層暴露降階依據。
  • 為何六階段不是三：開發期消融顯示「塌成 LLM-讀整個碼庫」會丟結構事實底座並捏造；「塌成 LLM-產輸入」會失去 SAT 模型錨點、產出流暢但到不了 bug 的 blob。

5. 方法細節（精選）

  • Stage 0：後向切片到不了「不呼叫記憶體 sink」的函式，漏掉大類 bug（憑證範圍洩漏、不完整驗證、陳舊狀態重置）。偵察用 FieldSemantic 補：小族省略規則機械證明「對某 role 操作 ≥2 欄位卻漏掉安全相關欄位」的處理器。
  • Stage 2 成本 vs 召回：stb 切片（128 函式、18.6 KLoC）氣味掃描 36.6 秒、$0.005（Lite 級模型、15 路並行）；frontier 模型純抽取 55 分鐘、$0.30–0.50（90× 慢、70× 貴）但 bug 相關召回相同。
  • on-demand Datalog 查詢：host agent 推理時可透過 neurolog__query_datalog 工具下任意 Datalog；Soufflé 在 temp 跑、facts 以 symlink 連入（不複製 20 萬列）。libxml2 案例：一個段落 prompt 下 agent 發 19 條臨時查詢，2 條 schema 出錯被 Soufflé 拒、讀行號回顯後修正重交。
  • Stage 4b likely range invariants：在 GDB 下對語料正常輸入於 Datalog 標記點蒐集整數型局部變數範圍，聚合成 LikelyRangeInvariant(func,var,addr,lo,hi,n_obs)，編碼時 assert lo≤v≤hi。兩層比對（精確三元組 / 同函式同變數寬鬆聯集），刻意不做第三層跨函式比對（會引入未走到的攻擊者輸入界、靜默降階想要的發現）。

6. 實作

Tree-sitter（官方 tree-sitter-c grammar）+ Soufflé 2.4 + Z3 4.12（Python 綁定）+ AddressSanitizer，約 8 KLoC Python。兩個 LLM 階段走 LiteLLM 抽象：氣味掃描用 Lite 級（DeepSeek V4-Flash），合成 agent 用 frontier（DeepSeek V4-Pro）。無自製框架——以 Model-Context-Protocol（MCP）工具暴露各階段，由 host agent（Claude Code、OpenCode）驅動，交錯確定性工具與推理。每次掃描可開 TSV 審計日誌（哪些關係觸發、行數、agent 查詢、symbex 批次結果），供事後審計。
