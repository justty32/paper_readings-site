3. 方法

3.1 串流技能策展與模組化多代理設計

考慮串流測試環境：LLM 代理被部署解決隨時間到達的任務序列 \(\mathcal{D} = \{x_1, x_2, \dots, x_T\}\)。在每個時間步 \(t\)，代理須先解決當前任務 \(x_t\) 才能看到未來任務，產生執行軌跡 \(\xi_t\)。此設定捕捉自我進化代理的核心挑戰：系統必須從過去軌跡中蒸餾有用經驗以提升未來表現。

技能庫（SkillRepo）：時間步 \(t\) 維持外部技能庫 \(\mathcal{S}_t = \{s^1_t, s^2_t, \dots, s^{N_t}_t\}\)。每技能以 Markdown 表示：(i) YAML frontmatter（技能名稱＋自然語言使用描述），(ii) Markdown 指令文本（可執行知識、工作流、約束、可重用啟發法）。此格式遵循社群廣泛採用的 SKILL.md 設計。

Agent Executor：給定任務 \(x_t\)，凍結的 executor \(\pi_L\) 以當前環境觀察與檢索到的技能為條件解決任務。使用 BM25 從 SkillRepo 檢索技能子集 \(\tilde{\mathcal{S}}_t\)，executor 取樣動作 \(a \sim \pi_L(\cdot \mid x_t, o_t, \tilde{\mathcal{S}}_t)\)。

Skill Curator：executor 完成任務後，策展器 \(\pi_S\) 觀察軌跡 \(\xi_t\)、自我判斷的正確性訊號 \(\mathbb{1}_{\xi_t}\)（LLM-as-a-judge）、及檢索到的相關技能 \(\tilde{\mathcal{S}}_t\)，生成結構化策展操作：

\[c_t = (u^1_t, \dots, u^{M_t}_t) \sim \pi_S(\cdot \mid \xi_t, \mathbb{1}_{\xi_t}, \tilde{\mathcal{S}}_t)\]

每個操作為 {insert_skill, update_skill, delete_skill} 之一，以函式呼叫實現。操作應用後 SkillRepo 轉變為 \(\mathcal{S}_{t+1} = \text{ApplyOps}(\mathcal{S}_t, c_t)\)，供 executor 在後續任務使用，形成任務執行與經驗驅動技能演化之間的閉環。

3.2 用 RL 學習技能策展

核心挑戰：策展決策的反饋是間接且延遲的——只能透過 executor 在未來相關任務上的表現才能揭示。SkillOS 以兩項設計解決此問題：(1) 分組訓練實例（§3.2.1），(2) 複合獎勵（§3.2.2）。

3.2.1 訓練實例建構

對每個任務 \(x_i\)，先用 Gemini-2.5-Pro 標註一組技能相關屬性：

\[Z_i = \{T_i, S_i, C_i, R_i, P_i\}\]

五維度分別為：高階主題、所需技能或能力、底層數學概念或定理、適用的啟發策略、常見陷阱。每維度為一組少於 5 字的簡短短語。對於代理任務（ALFWorld），直接使用任務類型註釋（6 類）替代 \(Z_i\)。

然後將資料集劃分為 \(M\) 組相關任務。分組使用兩階管線：

Stage 1：LLM 標註屬性（Gemini-2.5-Pro，結構化解碼輸出 JSON，要求標準化術語、無任務特定內容、每維度盡量少短語）。

Stage 2：基於屬性相似度的群組建構——以軟 Jaccard（combining exact match + sentence-embedding cosine similarity，使用 all-MiniLM-L6-v2）計算短語列表相似度。對每對候選任務應用 dependency gate 過濾：(1) shared foundation（共享概念與技能短語數達標）；(2) shared reasoning（共享策略或陷阱短語）；(3) not a near-duplicate（整體相似度在上界以下）；(4) not too unrelated（相似度在下界以上）；(5) progression（候選引入至少一個新概念或技能）；(6) curriculum direction（難度正向遞增）。

檢索透過預計算 inverted index 加速（以 dependency fields {C, R, P} 為鍵，候選池上限 2,000）。最終選取加權相似度（五維度加權）＋難度獎勵最高的候選。此設計使技能由 curator 在早期任務中衍生後，可透過其是否幫助解決後續相關任務來被評估——提供學習複雜策展操作所需的長程反饋。

3.2.2 訓練迴圈與策略最佳化

採用 GRPO（Grouped Reward Policy Optimization）。對任務組 \(G = (x_1, \dots, x_{|G|})\)，策展器產生一系列決策 \(c = (c_1, \dots, c_{|G|})\)。每個訓練步驟的複合獎勵為：

\[r = r_{\text{task}} + \lambda_f r_{\text{fc}} + \lambda_u r_{\text{cnt}} + \lambda_c r_{\text{comp}}\]
  • 任務成果獎勵 \(r_{\text{task}} = \frac{1}{|G|-1}\sum_{i=2}^{|G|} \mathbb{1}(\xi_i)\)：排除首任務（使用空 SkillRepo），平均剩餘任務的成功率——提供 executor 接地信號。
  • 函式呼叫獎勵 \(r_{\text{fc}}\)：有效且成功執行的函式呼叫比例——衡量操作格式的正確性。
  • 內容品質獎勵 \(r_{\text{cnt}}\)：由 Qwen3-32B 外部裁判按四維度評分——抽象性（捕捉可泛化程序，非逐字複製軌跡）、可重用性（原子化與模組化）、可操作性（提供具體指引）、忠實度（所有陳述有軌跡證據支撐）。
  • 精簡度獎勵 \(r_{\text{comp}} = \frac{1}{|G|}\sum_{i=1}^{|G|} (1 - \frac{|\mathcal{S}_i|}{|\chi_i|})\)：SkillRepo token 長度 vs 輸入上下文長度——抑制逐字複製軌跡，鼓勵蒸餾可重用技能。

每任務組取樣 \(N\) 條獨立 rollout，每條 rollout 中 executor 使用不同 SkillRepo 歷史。GRPO advantage：

\[A^n = r^n - \frac{1}{N}\sum_{n'=1}^{N} r^{n'}\]

最佳化 \(\pi_S\) 用 clipped surrogate objective：\(\mathcal{L} = \mathbb{E}_n[\min(\rho^n A^n, \text{clip}(\rho^n, 1-\epsilon, 1+\epsilon)A^n)]\)，其中 \(\rho^n = \pi_S(c^n \mid \chi) / \pi_{\theta}^{old}(c^n \mid \chi)\)。Advantage 統一分配至 \(c^n\) 的所有 token，廢棄 KL 項以鼓勵策略探索。

實作細節：Qwen3-8B 作為策展器基模型，凍結 executor 訓練時亦用 Qwen3-8B。GRPO 參數：學習率 \(1 \times 10^{-6}\)、batch size 32、group size 8、temperature 1.0。獎勵權重 \(\lambda_f = 1.0\)、\(\lambda_u = 0.1\)、\(\lambda_c = 0.05\)。16 張 H100 GPU、verl 框架。ALFWorld 訓練約 3 天（50 steps，group size 10），WebShop 約 5 天，推理約 2.5 天。測試時使用 top-30 skill retrieval（代理）/ top-5（推理），ReAct 用於代理任務、CoT 用於推理。
