摘要

端側語言模型 agent 靠「在檢索記憶中累積經驗」而非更新權重來改善。這份記憶是硬上限且暴露的：它消耗 RAM 與能量、透過一條細上行抵達同儕、並因「被 agent 讀到的東西可寫入」而成為攻擊面。既有系統各只覆蓋問題的一部分：agentic 記憶無預算地生長、端側方法只憑成功保留條目、投毒多被當成攻擊而非記憶治理問題。我們提出 CURATOR——一個「每位元組淨值」分數，治理 agent 經驗記憶的生命週期。核心想法是讓預算當策展者：每個條目以「價值減危害、除以位元組」評分，一把尺決定留、傳、信。CURATOR 做三項決策：(1) KEEP 在 RAM 與能量預算下淘汰低值位元組；(2) SHARE 只在洞見價值超過上行成本時傳送；(3) TRUST 以來源把關同儕條目。在 LLM-agent 任務漂移基準與一個含兩個機械臂節點與一個 hub 的真實異質 Jetson 測試台上，CURATOR 把記憶縮 2.7×、上行縮 2.4×、把注入成功率從 0.75 降到零，並在被投毒或過時記憶污染的案例上提升準確率。按淨值策展同時降低足跡、能耗、上行與注入成功率，而不降準確率。在此設定下，按淨值遺忘是讓 agent 變強而非變弱。

1. 引言

端側語言 agent 正從純雲端服務轉向本地硬體（Apple、Google、Microsoft、Meta、阿里皆已在手機上跑模型，機器人與邊緣裝置亦然）。它們留在本地以保護隱私並在斷線時仍能工作。部署後仍被期望「在場域內持續改善」而不回傳用戶資料重訓：做法是累積經驗而非更新權重——成功與失敗的任務經歷被蒸餾成可重用洞見、寫入外部記憶、推理時檢索。這沒有消除持續學習問題，只是把它從「參數更新」搬到「記憶存取」。伺服器上長大的記憶主要是管理成本；邊緣上它是資源與安全約束。

三個邊緣約束逼出對同一份記憶的三個決策：RAM 與能量預算逼出 KEEP（哪些累積經驗值得它的位元組？近期性與「按成功重播」會留下過度特化、過時的條目，許多原始經驗逐字保留甚至帶負價值）；因為記憶可被讀到的東西寫入，逼出 TRUST（一條被設計成「在攻擊者查詢上有用」的投毒條目，正是純價值濾器會保留的，少數幾條即可把注入成功率拉到 90–99%）；細上行逼出 SHARE（哪些蒸餾洞見值得送）。留、傳、信是同一問題的三種形式：一段經驗是否值得它的足跡。

CURATOR（Continual, bUdget-cuRated Agent-memory neT-value scOreR）用單一「每位元組淨值」分數，在三個預算下讀同一個量回答三問。貢獻：(1) 把端側經驗記憶治理圍繞單一原則——預算即策展者；淨值/位元組是 recency/success 策略缺的狀態變數。(2) 證明單一分數覆蓋完整記憶生命週期；生命週期覆蓋格顯示每個先前方法只落在留/傳/信之一。(3) 提供真機證據與明確投毒分析：跨三骨幹峰值記憶縮 2.7×、每輪上行縮 2.4×、注入從 0.75 降到 0，並在被污染案例上回補準確率；以 37% 足跡達 oracle 97% 準確率；真機上能耗/記憶/上行各降到全留的 0.38–0.64。

與直覺相反——遺忘並非以能力換取——按淨值策展記憶讓四條通常互相競爭的軸同向變好：足跡、能耗、上行下降，注入成功率下降，任務準確率維持並恰在被過時/投毒記憶毀掉的案例上回升。原因有二：凍結的 agent 抗遺忘，故丟低值位元組代價極小；許多累積的原始經驗帶負價值，移除它是修復而非削弱。

2. 背景與動機

端側持續學習：端側語言 agent 主要靠「改變它記得什麼」而非更新權重來適應。本文的 agent 是一個凍結的 LLM planner，呼叫固定的底層原語；持續學習因而從參數更新搬到記憶存取。

邊緣記憶預算：常駐條目搶固定 RAM、每次檢索與重嵌耗電池能量、與同儕分享用細而間歇的上行。沒有一個預算會隨記憶長大，故「留全部」不是硬體可行的基線。

記憶作為攻擊面：記憶可被 agent 讀到的任何東西（觀測、工具輸出、同儕洞見）寫入。單條存活的投毒條目即可在攻擊者選定查詢上操縱 agent；檢索增強記憶中 5 條精製條目即可把注入 ASR 拉到 90–99%。更大的庫只擴大這個開口。表 I 量化「留全部」的代價：足跡停在最大值，新鮮度優先檢索器讓注入 ASR 留在 0.75，窮舉檢索器更達 1.00——更多記憶在兩種檢索規則下都不更安全。

洞見 1（按淨值遺忘）：淘汰低值經驗代價極小，因為凍結 agent 的技能留在權重而非被丟的位元組裡；且累積經驗價值不均——一條逐字保留的原始軌跡在難案例上可帶負價值，而把同一軌跡蒸餾成抽象洞見能把淨貢獻從 −26.1 移到 +3.3。但價值本身不夠：投毒條目被寫得看似有用，純價值濾器會留它；唯有當分數的來源項對可疑來源收費，注入 ASR 才降到零。

洞見 2（一把尺治留/傳/信）：三個決策都問「一段經驗是否值得它的成本」，成本可能是常駐位元組、上行位元組、或可疑來源的風險。一個分數能治理三者，因為成本共用一種貨幣。表 II：一個分數同時把足跡縮 2.7×、上行縮過半、注入 ASR 歸零。

3. 系統設計

CURATOR 用單一分數 ρ 跨三階段治理凍結 LLM agent 的經驗記憶：profile（剖析）→ score（評分）→ govern（治理）。剖析維護三個輕量統計（近期查詢嵌入的滑動草圖、每條目對任務結果的無標籤效果估計、來源標籤），開銷可忽略。CURATOR 不更新 agent 參數，唯一學習組件是 V̂ 內的無標籤有用性頭。

淨值密度分數：

\[\rho(m)=\frac{\hat{V}(m)-\lambda\,\hat{H}(m)}{b(m)}\]
  • 價值 V̂(m) = p(m)·q(m)·a(m)：p 為對近期查詢草圖 q̄ 的 softmax 檢索傾向；q 為條件有用性＝把 m 納入檢索集的平均邊際效用，無標籤地以 agent 取樣答案的自洽度當效用、線上校準串流頭追蹤；a 為抽象增益＝原始位元組 / 蒸餾後位元組（壓縮可把逐字負貢獻轉正）。
  • 危害 Ĥ(m) = η(m) + π(m)：η 為負遷移風險＝特異性 × 嵌入到當前任務中心 μ 的 Mahalanobis 距離（對過擬合遠經歷的條目收費）；π 為來源風險、是承重項＝對特徵圖的 logistic 閘控，編碼來源（外部/同儕/自產）、跨會話自我強化次數、與注入指令的相似度；閘權重是固定先驗、不線上擬合，不給攻擊者訓練面。

三預算下三決策（Algorithm 1，一趟）：

  • KEEP：按 ρ 降序貪婪填入常駐集直到 RAM 預算 B 用盡（密度排序貪婪解連續鬆弛近最佳，O(|M|log|M|)）；將被淘汰者先 Distill，蒸餾後 ρ 可能升足以留下。能量不入分母，改用虛擬佇列 Q(t+1)=[Q(t)+ε(t)−ε̄]₊ 的 drift-plus-penalty 把時均能耗壓在 ε̄ 內。
  • SHARE：對同儕廣告的單一查詢草圖 q̄_p 重投影檢索傾向得 V̂_p（蒸餾有用性 q 與抽象增益 a 不變、只重算傾向），只在 ρ_s = (V̂_p − λĤ)/b > τ 且非冗餘時傳；過一條向量、無原始查詢/軌跡離開裝置；τ 隨剩餘上行縮小而升。
  • TRUST：接收方本地重算 ρ，只在 ρ(m′) > θ 才納入；來源項把投毒條目壓到 θ 下。同一危害項三次作用於同一對手：自我強化條目被 KEEP 淘汰、被 SHARE 扣留、被 TRUST 拒絕，無需在三者間重調目標。
