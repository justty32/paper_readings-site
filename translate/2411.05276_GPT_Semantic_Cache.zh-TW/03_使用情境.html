6 使用情境

GPT Semantic Cache 適用於重複或相似查詢常見的領域，主要使用情境包括：

  • 客服聊天機器人：常見問題向 LLM API 產生大量冗餘查詢，增加成本與回應時間；透過快取過往查詢與回應的嵌入，系統可直接為語意相似的問題檢索答案，跳過 LLM 呼叫。例如銀行聊天機器人可即時回答「儲蓄帳戶利率是多少？」或「如何重設網銀密碼？」等重複查詢。
  • 檢索增強生成（RAG）系統：RAG 系統頻繁向 LLM 查詢特定脈絡的答案，導致高延遲；GPT Semantic Cache 讓這類系統能對語意相似查詢重用快取結果，減少 API 呼叫並加快回應。例如文件搜尋系統可避免對「摘要 2024 年第三季財務趨勢」這類相似摘要要求重複呼叫 LLM。
  • 即時程式碼助理：開發者常對程式碼補全或除錯提出相似查詢；透過快取程式碼相關查詢與解答的嵌入，系統能快速重用相同或相似提示的回應。例如「如何寫一個反轉字串的 Python 函式？」可重用「反轉文字的 Python 函式」這類提示的快取回應。
  • 電商產品支援：電商平台常收到關於產品功能與庫存的冗餘查詢；基於嵌入的快取能快速檢索語意相似問題的回應，提升客服效率。例如「這支手機有什麼功能？」與「這支手機有雙鏡頭嗎？」都能利用快取回應。

7 結論

本文提出 GPT Semantic Cache，一個利用語意嵌入為語意相似查詢快取並檢索 LLM 回應的系統。透過將使用者查詢轉為嵌入並連同對應回應存入記憶體內快取，系統能有效辨識相似問題並立即提供答案，而不需對 LLM 進行重複 API 呼叫。

實驗顯示，各查詢類別的 API 呼叫顯著減少——最多達 68.8%——快取命中率介於 61.6% 至 68.8%。系統展現出色的準確度，正確命中率超過 97%，顯示快取回應在多數情況下與使用者意圖高度吻合。這些結果凸顯系統在降低營運成本與改善回應時間上的成效，對處理重複查詢的 LLM 應用格外有益。

GPT Semantic Cache 為提升客服聊天機器人、RAG 系統、即時程式碼助理與電商平台等 AI 應用的效率，提供了一個可擴展且具成本效益的方案；其支援多種嵌入模型與設定的彈性，讓系統能適應各種領域。未來工作將探索相似度匹配的動態門檻調整、提升可擴展性的分散式快取機制，以及整合領域專用嵌入模型以強化特定應用中的語意理解。

8 限制

儘管 GPT Semantic Cache 顯著降低了 LLM 成本與延遲，仍有其限制：固定的相似度門檻（0.8）未必能推廣至所有使用情境，可能遺漏細微的查詢變化；隨嵌入集合成長，系統擴展至海量資料集時可能出現效能下降，在動態更新時引入延遲；領域專用查詢可能需要量身打造的嵌入以提升準確度；此外，僅依賴 TTL 維持快取新鮮度，不足以應對快速變動的資料，系統也不處理具上下文相依的多輪對話互動；在資源受限的環境中，快取管理本身的資源開銷也可能構成挑戰。
