論文／訪談原始來源

幾句話就很有用：語言引導的機器人 policy 合成

摘要與問題

VLA 雖能零樣本操作，卻是難以檢視、難以針對小失敗修正的黑盒 policy。ARCHITECT 改把 policy acquisition 當成互動式程式合成：LLM coding agent 寫可執行的模組 robot program，人以語言修正失敗，修正藉 execution trace 落到程式並留下可重用技能。

ARCHITECT

初始自然語言指令進 system prompt，LLM 合成使用控制、感知、本體覺工具的程式。控制 primitive 涵蓋幾何 motion；感知含開放詞彙偵測、抓取與放置模組；本體覺可查 robot state。工具刻意保持通用，讓高層語意能對應到實際幾何控制。

偵測失敗或 episode 結束後，系統請人給 correction。agent 同時看 robot execution trace，因此可將「抓太高，從杯緣拿」這種話連到特定 code／tool call，再重建 policy。這比讓人手改程式或收 demonstrations 的門檻低，但仍需要人在關鍵物理錯誤出現時做診斷。

Skill library

每個 correction 被合成成簡短自然語言 rule 或 code pattern，加入持久 library。之後每次生成都把全部 skills、當前指令、上輪 trace 放入 context。作者將它稱為長期 in-context learning：它保留過去修正並避免重犯，而不是更新 VLA 權重。文中沒有把 library 做成有型別的 API，也未聲稱它能自動處理過期或衝突技能。

真機評估

實驗使用 Franka Panda、Robotiq 夾爪與 ZED 相機，orchestrator 是 Claude Opus 4.6；最多五輪 expert corrections 後，以十次 episode 評估八項操作。指標為完整成功率 SR、goal condition recall、與依任務順序的 normalized task progression。相較 CaP、π0、π0.5 與以 VLM correction 取代人的版本，作者報告 HiTL 版在抽屜（SR .90）、折三角布（.80）、遮布取香蕉長程任務（.80）明顯較強。

人類研究

六位使用者先處理「杯子直立放桌上」，再做結構相近的「盒子直立放架上」。帶入自己的舊 library 時，平均 queries/trial 從 4.67 到 0.83，p=.036，其中三人不需新修正。沒有 Task 1 skills 的 Task 2 成功是 0/6；載入 skills、但不開修正迴圈後為 4/6。作者也指出先前只給一條 correction 的參與者通常無法零樣本轉移。

限制與結論

ARCHITECT 仍受低階抓取 sampler、深度估計與 cuRobo 無碰撞路徑能力限制。人的 correction 對相機難察覺的高度、材質或慢速夾取等物理直覺尤其有價值，但這也表示系統尚非自主修復。真機結果、少量使用者與相關 task 的轉移是有前景的作者證據，不等於安全、跨機器人普遍成立。
