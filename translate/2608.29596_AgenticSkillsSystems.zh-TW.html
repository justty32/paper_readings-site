論文／訪談原始來源

Towards a Systems Foundation for Agentic Skills: Architecture, Lifecycle, and Security

摘要與第 1～2 節：skill 是什麼

長時程 LLM agent 的失敗會沿著步驟傳播，程序知識若只留在一次性 transcript，又無法讓下一次任務受益。把所有流程常駐 context 會增加 token 與干擾，寫入模型權重則跟不上工具、API 與組織規範的變動。本文因此把 agentic skill 定位為外置的程序記憶：可持久保存、按需載入、獨立更新，銜接高階規劃與確定性執行環境。

skill 形式化為 s=(A,I,C,T,pi,E)，分別表示啟用條件、程序指示、適用限制、工具介面、執行 policy 與預期狀態效果。它必須同時具備封裝模組性、late-binding 動態呼叫與程序性狀態轉換。因而，常駐 system prompt、單一無狀態 API、硬編碼 agent loop、episodic log 或一次性 plan，都不自動算 skill；只有把可重用控制流程外置、可獨立版本化並依狀態動態載入，才符合這個抽象。

第 3 節：九階段程序生命週期

本文把 skill 系統整理成九個相連階段。Discovery 從成功與失敗軌跡找可重用程序，並在入庫前做測試、judge 或人工 gating。Authoring 把程序寫成自然語言 SOP、JSON／DSL、狀態機、可執行程式或合約式規格；越容易執行的表示通常越容易驗證，但也更依賴特定環境。

Storage 把 raw episodic trace 壓縮成可版本化的 procedural asset，並依 utility、成本、老化與衝突做合併或淘汰。Retrieval 先以 sparse／dense 方法產生候選，再用 full-text reranker 與 capability permission gate 選擇；只索引名稱與短描述會看不見真正的參數限制與前置條件。Composition 把 skill 串成 pipeline 或 typed DAG，要求上游效果滿足下游前置條件；Execution 則在 sandbox 中施作，利用 invariant、post-condition 與錯誤歸因做局部修復。

Adaptation 分成短期 context 內調整與長期記憶演化，但 policy 與 skill store 同時更新會形成 co-adaptation drift。Evaluation 不能只看最終成功率，還要量測可靠性、效率、泛化、組合能力、持續學習、可解釋性與安全。Security governance 貫穿 admission、retrieval、execution、sharing 與 evolution，要求最小權限、來源簽章、靜態掃描、動態 sandbox、runtime monitor 與撤銷機制。

第 4～5 節：分類、生態與實證圖景

功能面可分為 instructional／SOP、tool／API calling、reasoning／planning、domain-specific execution，以及 collaborative／meta-skills。領域則涵蓋軟體工程、GUI／作業系統操作、具身機器人與科學探索。這些類型可用相同生命週期理解，但可驗證性與風險不同：自然語言易攜但語意模糊，可執行程式較確定卻擴大權限與供應鏈攻擊面。

**本文彙整，作者自報：**SkillsInWild 對 34,000 個真實 skill 的量測顯示，從大型社群池自主檢索時，distractor、模糊 metadata 與參數簽名重疊會使端到端任務成功明顯低於 oracle skill subset。這支持 full-text routing、依賴圖與污染控制，而不是把 registry 當成普通文件向量庫。

**本文彙整，作者自報：**SkillsBench 涵蓋 87 個複雜任務與 8 個操作領域，文中引用其結果支持外置程序 skill 對多領域 base LLM 的一致改善；但另一個具即時 CLI 錯誤回饋的資安測試呈現負結果，提醒 skill 的價值會隨環境回饋頻寬提高而下降。

**本文彙整，作者自報：**SkillSec-Eval 檢查 327 個 enterprise skills、涵蓋 15 個領域，發現風險橫跨 marketplace admission、檢索劫持、runtime state tampering 與 co-evolution poisoning。本文據此主張 zero-trust：不能因套件名稱或自然語言說明無害，就授予未驗證程式碼高權限。

第 6～8 節：開放問題、結論與局限

六類開放問題是跨模型與小模型可攜性、大型 registry 的低延遲路由、graph compilation 與局部復原、zero-trust marketplace、避免終身共同演化漂移，以及能調節環境回饋頻寬的真實 benchmark。核心結論是，agentic skills 並非較長的 prompt，而是一套可尋址、可執行、可修補、可治理的程序資產；它的價值要由整個系統生命週期判斷。

作者自陳三項範圍限制：領域與 runtime 演進很快，文中框架和專有 harness 可能迅速變動；分析偏重軟體工程、作業系統自動化、網頁操作與資料分析，對真實機器人的物理動力學和硬體延遲著墨有限；材料主要是英文及 Python／JavaScript 生態，不能直接代表其他語言與執行環境。
