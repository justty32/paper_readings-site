摘要

LLM 廣泛用於複雜 AI 應用中，其輸出須遵循特定格式（JSON、YAML 等資料序列化格式，或程式語言的程式碼）才能與系統其他組件整合；這些格式規則通常以上下文無關文法（context-free grammar, CFG）表達。本文提出 SynCode，一個高效且通用的 LLM 語法約束解碼（syntactical decoding）框架：相對於形式語言的 CFG，SynCode 保證健全（soundness，保留所有合法 token）且在特定條件下完備（completeness，剔除所有非法 token）。SynCode 的核心是離線建構的高效查找表——DFA mask store，由文法終端符的 DFA（確定有限自動機）建成。SynCode 可無縫接上任何以 CFG 定義的語言，實驗涵蓋 JSON、SQL、Python、Go：JSON 生成上消除全部語法錯誤並顯著勝過最先進基線；Python 與 Go 程式碼生成上平均削減 96.07% 的語法錯誤。程式碼開源於 github.com/uiuc-focal-lab/syncode。

1. 引言

LLM 在複合 AI 系統（compound AI systems）中扮演樞紐：OpenAI code interpreter 生成並執行 Python、Wolfram Alpha 把數學問題譯成 DSL、其他應用把自然語言譯成邏輯求解器或定理證明器的輸入。這些場景都要求輸出遵循特定語法結構，但幻覺與不穩健使 LLM 不可靠；理論與實證研究更指出 transformer 難以學會基本形式文法。既有的文法導引生成（grammar-guided generation）方法有三類問題：

  • 語法準確度不足：文法的終端符（terminal）（關鍵字、運算子等）由 lexer 從輸入切出詞法 token；而 LLM token 是訓練前就固定的詞彙表元素，與任何文法的詞法 token 並不對齊——此即 **token misalignment（token 錯位）**問題，使精確的文法導引生成困難、健全性難以形式化證明。
  • 推論時運算負擔高：語法檢查通常在 CPU 上序列執行，與 GPU 加速的 LLM 生成形成瓶頸。低開銷需要（1）把計算盡量移到離線；（2）把額外計算卸載到 GPU 等硬體平行執行。
  • 通用性不足：先前工作綁定特定解碼方案（如 PICARD 綁 beam search）；理想演算法應可與 greedy、beam search、各種溫度取樣任意組合。

SynCode：輸入以 EBNF 規則表示的 CFG，保證 LLM 輸出遵循該文法，且可與任何解碼演算法組合。解碼每步分兩階段：先由部分輸出算出可接續的終端符序列（accept sequences）與可能改變詞法型別的後綴（remainder）；再以 remainder 走 DFA、查 DFA mask store 得到每個 accept sequence 的布林遮罩（mask），取聯集即得語法合法 token 集合。主要貢獻：（1）基於剖析（parsing-based）的 LLM 解碼技術與高效演算法；（2）可用於任何使用者提供 CFG 的通用框架；（3）對 JSON、SQL、Python、Go 的廣泛評估。

2. 背景

語言模型與解碼：LM 在 token 詞彙表 V 上運作，對輸入 token 序列輸出分數向量 z，softmax 後得下一 token 的機率分佈；greedy、取樣、beam search 等策略反覆選 token 直到 EOS。受約束遮罩（constrained masking）：以函數 f_m 產生遮罩 m ∈ {0,1}^|V|（1 為可用、0 為剔除），解碼作用於 m ⊙ softmax(z) 並重新歸一化。SynCode 即以此技術剔除語法非法 token。

形式語言文法：CFG 由產生式規則 E → β 組成（E 為單一非終端符）。終端符集合記為 Γ，各終端符以正則表達式 ρ 描述（如 int 為 [0-9]+），正則表達式對應 DFA（五元組 (Q, Σ, δ, q0, F)）。Lexer 假設：詞法分析採 1 字元前瞻（lookahead）、不回溯——這是 SynCode 效率的關鍵假設。

3. 綜覽

3.1 說明性範例

以 Lark EBNF 定義的算術 DSL 文法為例（含四則運算、括號與 math_exp／math_sqrt／math_sin／math_cos 函數）。讓 LLM 把自然語言譯成此 DSL、由直譯器算出精確結果。標準 LLaMA-7B 生成會發明文法中不存在的函數（math_area、math_side）且不停止；SynCode 則在每步剔除語法非法選項——生成 math 後排除 _area 等，模型改選合法的 _sqrt。形式化地說：令 L(G) 為文法 G 的所有合法字串、L_p(G) 為其所有前綴（可延伸為合法輸出的字串）；只要維持不變式「每步部分輸出 C_k ∈ L_p(G)」，完成時 C_n 必屬 L(G)。

3.2 SynCode 演算法

對部分輸出 C_k，定義 V_k ⊆ V 為所有能維持 C_k.t ∈ L_p(G) 的 token 子集；此公式化與任何解碼演算法皆可組合。兩步驟：

  • 剖析部分輸出：先 lexing。remainder r 是 C_k 中詞法型別仍可能改變的後綴：情況一，C_k 尾端有未被 lex 的後綴 u，則 r = u；情況二，C_k 恰以完整詞法 token 結尾，則 r 取最後一個詞法 token（如 Python 中 ret 下一步可能變成關鍵字 return）。1 字元前瞻的 lexer 假設保證 remainder 之前的部分（C_k□）詞法切分不再變動——這使增量剖析可行且 r 恆小。再以自底向上 LR 剖析器從已剖析部分算出 accept sequences A：可接續目前剖析結果的終端符序列（如剖析 math_sqrt(3) * (2.27 後，{rpar}、{add}、{mult} 是 1 長度、{add, int} 等是 2 長度的 accept sequence）。
  • DFA mask store：問題化約為「r.t（remainder 接上 LLM token t）是否與某個 accept sequence Λ ∈ A 部分匹配」。逐 token 檢查太慢；SynCode 的關鍵洞見是：對每個 DFA 狀態，可離線預計算「從該狀態出發走到活狀態（live state，可達接受狀態者）」的 LLM token 集，存成布林遮罩。推論時對每個 Λ 只需以 r 走一次 DFA、查一次表得 m_Λ，再對所有 Λ 取聯集 ∪ m_Λ——遮罩以張量存放，聯集是少量張量運算，可在 GPU 上高效執行。定理 1 證明此聯集過近似（overapproximate） V_k，保證健全；定理 2 證明前瞻夠長時恰等於 V_k，即完備。

3.3 時間複雜度

每步解碼成本為 O(T_∪ · |A|)（T_∪ 為布林遮罩聯集時間）。實務上 |A| 很小（實驗平均 <10），最壞情況等於終端符數 |Γ|（最大的 Python 文法 |Γ| = 94）；GPU 上向量化聯集運算高效。
