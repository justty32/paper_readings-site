論文／訪談原始來源

Program Learning with Verifiable Rewards: Symbolic Backpropagation for Post-Training LLMs

摘要與問題

SFT 與 RL 都把新能力寫回模型權重，因此能力難以逐步檢查、難以指出是哪個推理步驟改善，也難直接搬到另一個 base model。作者主張，若任務的中間產物可驗證，推理能力可以放在權重之外：學一個由 deterministic 與 neural primitives 組成的顯式程式，而不是更新服務中的 base model。

這帶來 credit assignment 問題。離散、部分符號化的 program 不可微，單看整條 trajectory 的 scalar reward 又太粗。PLVR 的答案是 symbolic backpropagation：每層攜帶 typed ontology 與 output contract；forward pass 找出輸出錯在哪些物件，backward pass 不生成自然語言 critique，而是根據 primitive signature，以 type inference 推導上一層必須提供的 ontology。credit 因而是一段 derivation，不是從 rollout 估出來的 gradient analogue。

方法：ontology、contract 與 symbolic backward pass

ontology 是帶型別的巢狀物件集合，也是每一層可直接檢視的狀態。neurosymbolic tokenizer 把原始文字轉成 ontology，並要求文字欄位必須是來源中的 verbatim span、cross-reference 可解析、formal language 可 parse 與 type-check。這個邊界決定 loss 看得到什麼；tokenizer 若漏掉結構，後續 contract 也無法補救。

primitive 是具單一職責、無狀態且有 input／output signature 的 leaf。symbolic primitive 依規格構造正確；neural primitive 處理語意判斷，再用型別、值域或結構 contract 攔截可表達的錯誤。operator 則負責 Sequence、Parallel、Branch、Foreach、Loop、Fallback 等控制流，本身不產生結果，而以 typing rule 限制組合。

loss 先比較 type error，再比較 value error，採 lexicographic order。code 以測試通過情形衡量，tool call 則以函式與 bindings 的 match 程度衡量。backward pass 從目標輸出 ontology 開始，先用 signature unification 列出能產生所需型別的 composition，再把其 leaf input types 聯集成上一層需求；無法由下層供應的型別先淘汰。值參數只在 declared ranges 與現有 context 中搜尋，任何違反 primitive contract 的候選，不必跑完整層便可剪掉。

訓練交替進行 program search 與 primitive retraining。搜尋階段凍結 primitives，逐例累積 score 並保留全域 beam；階段之間把 required ontology 與局部 contract violation 轉成 primitive 的訓練目標，再用新 primitives 重算 surviving programs。base model 始終不更新，最後能力位於可檢查的 program 與可獨立驗證、重訓的 primitives。

實驗與主要結果（作者自報）

實驗涵蓋 LiveCodeBench 與對話式 tool-use benchmark，並和 vanilla prompting、token-matched agentic harness、已發布的 RL post-training checkpoints 比較。作者自報，以中型 base model 的代表設定計，PLVR 對 matched-budget RL baseline 平均領先 27.8 個百分點，對參數量大一個數量級的 frontier vanilla models 平均領先 13.6 個百分點。這些比較仍混有不同資料與系統配置，作者因此把 data-matched 與 parameter-matched 解讀分開，不聲稱是 FLOP-matched 結果。

最重要的 mechanism ablation 保留相同 type-admissible space、availability filter 與 budget，只把 loss-guided search 換成 uniform sampling。作者自報，guided pool 的 median accuracy 為 65.6％，random pool 只有 17.5％。差異不只是更快找到同一批好程式，而是兩種 proposal mechanism 落在品質不同的區域，支持 backward derivation 的作用不等同於單純型別約束。

在 program identification 上，作者自報，跨不同資料排列後，最佳可用 program 能在 七十個 examples 內穩定進入 leading indifference class。論文也特別區分 accuracy plateau 與 identification：表面分數很早不再上升，不代表搜尋已找到同一個最佳 program；後續 examples 仍可能發現新的 competitive behavior。

討論與結論

PLVR 將 RLVR 的「可驗證終點」往內推到每個 program step。型別讓候選 well-formed，contract 讓錯誤可局部化，beam 才真正讓巨大組合空間可計算。這三者不能混為同一項貢獻。作者也把最可攜的命題說得比 benchmark 結果更保守：在中間輸出可檢查的任務上，對 typed、contract-verified primitives 做 program construction，可能比對 raw model calls 做同類搜尋更有效；本研究只以自家 loss-guided procedure 驗證較弱版本，尚未用第三方 construction method 測試。

局限

作者在討論中明列三條界線。held-out split 並非 i.i.d.，因此觀察到的落差只能解讀為 difficulty effect，不能直接當作一般化誤差。loss function 與 symbolic backward pass 在各 arm 中一併固定，研究證明的是此 loss 下的 target-directed derivation 勝過其他 proposal mechanism，沒有獨立隔離 loss 設計的貢獻。最後，訓練分布上 well-typed 的 program，對未曾走過的 branch path 沒有靜態保證；contract 能在部署時偵測並定位 off-type failure，但不能事前證明整個程式對所有路徑都正確。方法本身也只適用於中間輸出可檢查的任務，不涵蓋摘要與開放生成等主要靠主觀品質判斷的情境。
