論文／訪談原始來源

AgentSpec: Understanding Embodied Agent Scaffolds Through Controlled Composition

摘要與第 1 節：問題

具身 LLM agent 的能力不是單次模型呼叫所能說明，而是感知、記憶、推理、反思、動作與學習共同形成的閉環。既有系統通常把這些元件綁在任務專屬 prompt 與控制流程裡；即使成績提升，也難拆出何種元件有效，或是哪一對元件彼此相容。作者要解決的問題是：能否把 agent scaffold 變成可控制的設計空間，系統性比較元件本身及其交互作用。

AgentSpec 將 agent 表成具型別介面的模組組合，讓元件能在共同協定下替換與重組。論文的主張不是「最強元件必然最好」，而是長時程任務常由 scaffold 相容性決定：記憶若保留的粒度不適合推理器，反會帶來雜訊；推理再強，若遺失先前任務狀態，仍會失敗。

第 3 節：方法——可替換的 Perception–Memory–Reasoning–Reflection–Action 迴圈

每一步，感知模組把任務描述與原始觀測整理為統一狀態；記憶從歷史取回軌跡、摘要或知識；推理器提出決策與理由；反思模組可批評或修正決策；動作模組再將結果轉為環境可執行命令。環境回傳下一觀測、報酬與終止訊號，轉移會寫回記憶，學習模組可選擇性依回饋更新策略。

關鍵在於固定模組間的輸入輸出型別，而不是只把程式切成幾個檔案。感知可把符號狀態、感測資料、RGB 影像或文字回饋正規化為結構化欄位與摘要，讓後面的語言模型元件跨環境重用。記憶同時涵蓋 episodic 的具體成敗軌跡與 semantic 的地圖、限制、策略；推理器可替換為 CoT、ReAct、RAP 或 ToT；反思器可做逐步 Self-Refine、跨軌跡 Reflexion 或回顧式分析；強化學習則以同一介面接入 GRPO、SUPO 等策略更新。

第 4 節：實驗設計與主要結果

作者在四個具身 benchmark 測試：DeliveryBench 檢驗資源與期限限制下的長時程規劃；ALFRED 檢驗家務操作與任務狀態維持；MiniGrid 檢驗部分可觀測的符號導航；RoboTHOR 檢驗逼真三維場景的第一人稱物件導航。DeliveryBench 含九張城市地圖，主實驗採一小時設定，衡量每小時利潤；其餘基準主要報成功率與路徑效率。以上規模與設定皆為作者自報。

結果支持「結構化記憶才有用」而非單純延長 context。以 GPT-5 mini 的 DeliveryBench 為例，Base memory 換成 MemoryBank 後，ReAct 的每小時利潤由 8.54 升至 30.67，Plan-and-Solve 由 6.18 升至 26.78，皆為作者自報。作者將此解讀為：規劃型推理需要濃縮策略，而非只是原始觀測或軌跡片段。MemoryBank 同時保留原始軌跡、經驗摘要與高層環境洞見，能讓不同推理器按所需粒度取用，因此是長時程任務較穩健的預設。

環境差異同樣關鍵。較短、較符號化的 MiniGrid 比較依賴逐步推理；ALFRED 同時受記憶與推理影響；RoboTHOR 還暴露感知、導航與長時程復原的瓶頸。多 agent 推理對低階記憶較不敏感；反思對弱的推理—記憶組合提升更大，但強組合也有一致的小幅修正收益。成本分析則顯示相近 token 預算可能得到迥異利潤，更多思考時間也不保證更好，重要的是計算是否符合任務與模組配置。

第 5 節：學習與 scaffold 的相容性

作者以 DeliveryBench 研究學得的策略能否在部署時接上新 scaffold。GRPO 與 SUPO 都以每回合最多四十個互動回合、四個 rollout、batch size 為 32 訓練；SUPO 每八個動作摘要一次歷史，這些訓練設定均為作者自報。裸策略確實因 RL 而改善，但把外部記憶事後加到 GRPO 策略並不穩定，因為新 context 分佈改變了它習慣的輸入格式。

表中，GRPO 的 ReAct＋DynamicCheatsheet、ReAct＋MemoryBank、ReAct＋OpenClaw 分別得到 5.02、4.03、4.79；相同 scaffold 下 SUPO 為 8.27、7.07、6.57，皆為作者自報。作者的結論是：以摘要式歷史訓練的策略較能使用部署時的結構化記憶。強化學習不該只最佳化裸 LLM，還應把將來會接觸的記憶、推理與反思介面一併納入訓練。

第 6 節與附錄 A：結論與局限

AgentSpec 提供的不是另一套固定 agent，而是一個比較 scaffold 的控制實驗框架。實驗的共同趨勢是：模組相容性比孤立強度更重要；多粒度結構化記憶有助長時程狀態追蹤；反思最適合修補局部執行錯誤；學得策略的訓練 context 要接近部署 scaffold。

局限也很直接。研究沒有覆蓋所有 agent 任務，具身決策的結論未必遷移到網頁導航、軟體工程或開放式人機互動；各模組只測代表性實作，仍受 prompt、檢索與更新策略、context 預算及環境介面影響。受算力限制，作者不能對所有模型—模組—環境組合擴大測試或重複試驗，個別結果可能受抽樣變異影響；token 效率、延遲、記憶成長、檢索品質與軌跡誤差傳播也仍需更細緻的診斷。
