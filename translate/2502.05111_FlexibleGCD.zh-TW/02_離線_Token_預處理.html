3. 離線 Token 預處理

方法先預處理 lexer，有效率地建立「LLM token ↔ 終端符序列」雙向查表（§3.1、§3.2），再用預處理過的 lexer 分析剖析器，判定文法中實際可能出現哪些終端符序列（§3.3）。

3.1 Lexer 預處理

終端符以一組正規式指定，方便起見以詞法自動機（lexing automaton）（接受符合任一終端符定義之字串的 FSA）表達。

  • 簡化假設。 lexer 採兩個實務假設以提升效率、避免回溯：最長匹配原則（maximal munch）——lexer 從當前位置起匹配符合某 token 樣式的最長子字串（例如 ++ 優先當成遞增運算子而非兩個 +）；以及 1-lookahead（1 個字元前瞻）——在每一步只需檢視下一個字元即可解決所有分詞歧義。若掃到的前綴無法被詞法化為單一終端符，多數 lexer（含 Python）會報錯停止。
  • 詞法轉換器（lexing transducer）。 由詞法自動機建構一個有限狀態轉換器（FST，能在讀字元時產出終端符）T_A：逐字元轉移；當某字元無合法轉移時，檢查當前狀態是否對應合法語言 token，據此吐出終端符並重置。無法消耗的字元即為無效字元，指示解碼時該遮哪些 token。
  • LLM token 到終端符。 執行時若逐字元跑 lexing transducer 開銷大。於是把「字元→終端符」的 lexing transducer 與 Koo et al.(2024) 的去分詞轉換器（detokenizing transducer） T_V（把 LLM token 映回其字元序列）組合，得到 token 級的組合轉換器 T_{A∘V} = T_A ∘ T_V（確定化後）。此「token→終端符」轉換器讓「在每個狀態查合法下一 token 與所產終端符」變得高效；共享前綴以 trie 結構重用計算。

3.2 可實現的終端符序列（Realizable Terminal Sequences）

有了上述機制，便能把 LLM token 映到可能的終端符序列。對組合轉換器 T_{A∘V} 的每條轉移 q -[t:T1…Tk]-> q'，我們檢查是否存在終端符 T 使得 (i) T 能從 q' 沿某路徑產生、且 (ii) T1…Tk T 被文法接受。由此定義：可產生終端符（Producible Terminals） Prod(q)——從 q 出發某路徑可產生的終端符集合；以及 可實現終端符序列（Realizable Terminal Sequences） Re_{A∘V}——所有「某轉移產出 T1…Tk、且 T∈Prod(q')」的序列 T1…Tk T 之集合。由於 LLM 詞彙表含 Σ 中所有字元（故 Σ*=V*），可產生性檢查可只在較小的 T_A 上算可達性，不必分析龐大的 T_{A∘V}。

  • 逆向 token spanner 表（Inverse Token Spanner Table）Tinv。 演算法 4 建構此關鍵結構：對 lexer 狀態 q 與序列 T1…Tk T，Tinv(q, T1…Tk T) 是「能從狀態 q 產生該終端符序列的 token 集合」。可達性算法（Floyd 1962）可預算每個狀態的可產生終端符。此表讓解碼器能反查「哪些 LLM token 能從某 lexer 狀態產出某可實現終端符序列」。例如序列 BC 在狀態 q0 由 token aba 產生，在狀態 q2 由 token ac 產生。

3.3 剖析器預處理

CFG 剖析器通常形式化為 PDA（FSA 加執行堆疊）。與 lexer 預處理一樣，目標是預處理剖析器以免執行時逐一遍歷 lexer 產生的每個終端符序列。PDA 相較 lexer 的難處在於需要堆疊：堆疊內容須在執行時才知，故無法在預處理時完全判定某序列是否可從某狀態被接受。但仍可辨識許多「無論堆疊為何都必被接受或必被拒絕」的序列。

  • 作法：把去分詞得到的 Re_{A∘V} 直接與剖析器產生的 PDA P（其轉移操作於單一終端符）組合，得到新 PDA P ∘ T_{Re_{A∘V}}（轉移操作於終端符序列），能有效率地從每個剖析器狀態判定合法終端符序列。同時（in tandem）預處理 lexer 與剖析器，是本文與先前工作（Beurer-Kellner et al. 2024；Ugare et al. 2024）的關鍵區別。
  • 命題 3.5（堆疊不變性 Stack Invariance）。 若 PDA P 在狀態 q、堆疊 γ 下接受輸入 w，則堆疊為 γ'·γ 時（γ 在頂、下方多疊符號）也接受。故以空堆疊被接受的終端符序列，在任何堆疊下皆被接受——給出「何時序列必被接受」的充分條件。
  • 命題 3.6（以 FSA 過近似 Overapproximation）。 把 PDA 的所有堆疊操作移除得 FSA A_P；若 w 不被 A_P 在狀態 q 接受，則 w 在任何堆疊配置下都不被 P 接受——給出「必被拒絕」的判定。
  • 據此為每對 (lexer 狀態 q_A, 剖析器狀態 q_P) 建兩張表：永遠被接受的 token 表 A(q_A,q_P)（不論堆疊皆被接受）與依上下文而定的終端符序列表 D(q_A,q_P)（某些堆疊下才接受）。一個效率關鍵是：組合轉換器裡許多轉移產出相同終端符序列，使 |Re_{A∘V}| 小於 |V| 或 |δ|，讓預計算「剖析器該考慮哪些終端符序列」更有效率。

4. 線上 Token 遮罩

有了預處理好的 Tinv、永遠被接受表 A、依上下文表 D，即可描述線上解碼（演算法 6 ComputeValidTokenMask）。每個解碼步驟分析 lexer 狀態 q_A、剖析器狀態 q_P 與當前堆疊 γ，產出「所有能導向被文法接受序列」的 LLM token 集合 V_allowed。

雖然預處理時用組合 PDA P ∘ T_{Re_{A∘V}} 來算「一個 token 能產生哪些終端符序列」，但在解碼時用同一自動機做檢查會很沒效率——PDA 未必能確定化，且須對不同堆疊配置算可達性，等於在解碼時測試 Re_{A∘V} 中所有序列，使剖析器預處理白費。因此演算法 6 盡量用永遠被接受表 A 以避開遍歷 PDA，只對 D 描述的「依上下文序列」在解碼時才分析 PDA 能接受哪些終端符；接著對每個被文法接受的終端符序列查逆向 token spanner 表 Tinv，取出能導向該序列的 token 集合，得到下一步合法 token。
