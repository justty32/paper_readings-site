論文／訪談原始來源

RelayEvolve：別逐次路由，改做自適應族群交棒

摘要、相關工作與經驗動機

成本感知 LLM 路由通常按 request 或 mutation 選模型。本文認為演化搜尋不是獨立查詢：新程式會成為後續 parent，故預算要配置給族群狀態。作者用 Qwen-3.5-Flash 與 Plus、各題十次跑 100 代的觀察顯示，突破與分數多集中前段；便宜模型早期不差，但早期軌跡排名只部分預測終局，不能太早押一條路。

問題與 RelayEvolve

目標是在金錢預算 B 與 call 上限 N 下最大化找到的最佳 fitness。便宜階段維持所有已發現、去重的候選池 C 及小型 relay bank S。S 的分數同時獎勵前 r 名品質，和對 C 中高品質區域的相似度覆蓋；後者混合程式碼 embedding 與文字 metadata embedding。每個 block 的 Relay Gain 是相同更新後候選池上，bank 新舊分數之差，避免把候選池變大誤記成貢獻。

排程、停損與交棒

Grow 從共同初始程式開獨立軌跡，Deepen 延伸其中一條；兩者都跑固定代數。近期窗口的 UCB 分數平衡探索與利用。若 patience 窗口內所有相對 Relay Gain 都低於門檻，或便宜預算耗盡，即 handoff。此時在完整候選池以貪婪子模最大化加局部交換，並和線上 bank 比較，選較佳 seed set。強模型從這個共用族群繼續演化，而不是把每個 seed 切成獨立預算。

實驗、消融與結論

四個 program evolution benchmark 使用同一 ShinkaEvolve backend、評估器與 call 上限 200，比較 all-cheap、all-strong、固定切換、隨機、bandit 和 LEVI。RelayEvolve 在 11/12 setting 最高平均分，且各題最佳單次分數持平或最佳。拿掉 relay control、品質或多樣性任一側、或將強→便宜反向串接都變差；預設保留 85% 預算給強模型最佳。這些是特定 API 價格、三次重複下的結果，宜把交棒門檻與品質／多樣性權重視為待外部重測的假設。
