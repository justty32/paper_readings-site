摘要

終身學習對運作於動態互動環境的 LLM agent 至關重要。然而現有面向長視野任務的終身學習 agent 通常依賴推理時「離散技能或過去經驗檢索 + 靜態參數」，使它們無法像人類學習者那樣持續內化測試時回饋。為彌合此鴻溝，我們提出 LifeSkill——一個給線上終身學習 agent 的「技能增強測試時共演化」兩階段強化學習框架。具體而言，我們設計 Verifier-Guided Skill Learning（驗證者引導的技能學習），以「多次技能條件化 policy rollout 的平均驗證者成功率」獎勵候選技能，解決技能抽取缺乏直接監督的問題，鼓勵模型生成「對解題有用」而非「文字上看似合理」的技能；並引入 Online Skill Internalization（線上技能內化），在測試時互動中把技能條件化軌跡轉成獎勵信號、持續改進 policy 模型。在 LifelongAgentBench 上的實驗顯示 LifeSkill 比既有終身 agent 基線平均提升 7 個絕對百分點。

1. 引言

LLM agent 在長視野決策、互動規劃、序列問題求解上表現亮眼。但真實環境是動態的：任務分布隨時間演化、有用策略在反覆互動中浮現、agent 必須從經驗持續累積知識。這使終身/持續學習成為 LLM agent 的核心需求：終身 agent 應在與環境互動時持續改進、把測試時回饋轉成持久能力增長，而非把每個 episode 當孤立推理問題。

近期工作朝此目標邁步，主要透過記憶式經驗重用與測試時自我改進。記憶驅動 agent（Synapse、AWM、AgentKB、CER）儲存並檢索過去軌跡或摘要工作流以引導未來決策；測試時擴展與自反思方法（Reflexion、Self-Refine）透過探索多推理路徑與修正失敗嘗試改善表現；帶可驗證獎勵的 RL（DeepSeek-AI）在確定性結果領域顯示強潛力。

但現有終身學習 agent 仍未達真正的持續適應，面臨三個關鍵限制：第一，多數 agent 測試時保持參數固定、靠外部記憶改善，無法真正在部署中學習；第二，雖能總結軌跡或產反思，但如何從互動回饋抽取可重用技能（尤其在可靠、執行接地的監督下）仍探索不足；第三，習得知識通常表示為離散外部文字，使模型難以內化、組合、泛化為參數知識。結果：agent 能檢索經驗，卻無法有效把它轉成持久能力。

LifeSkill 的關鍵想法是用強化學習同時改進「agent 從失敗抽取什麼技能」與「這些技能如何被吸收進 policy」。第一階段 VGSL 解決技能抽取缺直接監督：失敗後技能抽取器提候選技能，每個技能以多次技能條件化 policy rollout 的平均驗證者獎勵評估，訓練抽取器生成「對解題有用」而非「文字上合理」的技能。第二階段 OSI 解決「技能引導探索」與「部署」的不匹配：從成功的技能條件化軌跡移除顯式技能文字、僅在原始任務輸入下更新 policy，使互動中發現的行為被內化進模型參數而非留作外部記憶。兩階段形成測試時共演化迴圈：更好的技能抽取帶來更有效的探索，改良的 policy 參數又產出更強軌跡供後續技能學習。在 LifelongAgentBench 上，LifeSkill 一致勝過強基線、平均提升 7 個絕對百分點。

2. 相關工作

近期綜述與基準主張 agent 能力應被當成持續適應而非單 episode 推理來研究。主流一線以外部記憶/經驗庫增強 agent（軌跡範例、工作流記憶、上下文重播緩衝、跨域知識庫、持久記憶系統），相關 agent 也在庫中累積可重用反思或可執行程序——這些證明經驗重用有價值，但多數增益留在模型參數之外，因而在部署時招致檢索開銷、上下文增長或記憶干擾。互補一線靠分配更多推理時計算到分解、修正、搜尋來改善表現（CoT、ToT、Reflexion 等），能從局部錯誤恢復，但增益通常短暫：agent 常在相關未來任務上重複類似搜尋或自我修正，因為發現的策略未被持久吸收進 policy。本工作保留測試時探索的好處，但把它當成未來能力的監督而非僅當前 episode 的額外計算。第三線把可重用行為表示為技能、工具、程式或時間擴展選項（RL 的時間抽象、LLM agent 外化為程式碼模組/工具呼叫/工作流）——多假設手工設計工具介面、依賴離線累積成功程序、或在未來推理中保留技能為顯式 scaffold；相對地，我們把技能當成中間學習介面：失敗後引導探索，再把結果行為內化回 policy。在參數層面，持續學習研究如何在獲取新行為時保留先前知識（正則化、重播、線上樣本選擇）；測試時適應在分布偏移下更新模型。本設定的差異在於：適應必須在互動環境內線上發生，且監督必須來自任務驗證者而非偏好標籤或自由形式裁判。

3. 方法

研究跨任務流的線上終身學習，把 LifeSkill 實例化為技能增強的測試時共演化框架。不同於部署中固定參數或把適應當分離的事後步驟，LifeSkill 邊與當前任務流互動邊學習。它維護兩個同骨幹架構但不同參數的模型：Policy Model π_θ（任務執行）與 Skill Extraction Model π_ϕ（從失敗互動蒸餾可重用技能），透過兩個 RL 機制耦合：

  • VGSL（§3.3）：用下游驗證者結果訓練 π_ϕ，鼓勵它抽取「能改善執行」而非「聽起來合理」的技能。技能 s_i 的效用以其經驗成功率定義。
  • OSI（§3.4）：用成功的技能條件化軌跡在線上更新 π_θ，移除輸入中的顯式技能 scaffold 後更新，使有用行為被吸收進模型參數。
flowchart LR
  W[任務窗口 W_t] --> P[Policy π_θ 執行]
  P -->|失敗| SE[Skill Extractor π_ϕ 提候選技能]
  SE --> RO[多次技能條件化 rollout]
  RO --> V{任務驗證者獎勵}
  V -->|平均成功率 = 技能效用| VGSL[VGSL 更新 π_ϕ]
  V -->|成功軌跡去技能scaffold| OSI[OSI 更新 π_θ 參數]
  VGSL & OSI --> W2[進到窗口 W_t+1]
  W2 -.共演化迴圈.-> W

在窗口 𝒲_t 上的這些互動同時扮演兩角色：一方面技能條件化重試透過失敗後的針對性探索改善當前窗口表現；另一方面收集的驗證者信號提供線上監督，在 agent 進到 𝒲_{t+1} 前更新兩模型——VGSL 改善抽取技能品質、OSI 把成功的技能引導行為轉成無 scaffold 的參數改進。如此，acting、技能發現、參數適應整合進一個連續線上迴圈。
