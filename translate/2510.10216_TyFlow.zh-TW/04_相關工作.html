7. 相關工作

型別導引程式合成：本文受此啟發，但有三點顯著不同——（1）能從型別推導樹生成合成推導樹，得以利用既有訓練程式（既有工作不關注此、也不支援）；（2）以保證型別系統與合成系統間同構的方式設計，確保型別顯性與推導鄰近性（既有工作亦不關注）；（3）探索如何設計高效神經網路來實作型別導引合成過程（既有文獻未研究）。

拒絕不合法生成：既有研究多探索把符號約束外部強制施加於 LM。generate-and-validate 反覆生成並以外部驗證器（如編譯器）檢查，但因無效生成率高而低效；受約束解碼在 token 生成時即時驗證、丟棄無法導向合法完整程式的 token，已用於語法正確性、型別正確性、漏洞規避等，但此 token 級剪枝會扭曲 LM 輸出分布。關鍵在於兩者都是外部強制——不改變 LM 的內部推理過程，模型內部分布可能因對可型別性的錯誤評估而對正確程式碼賦予低機率。

內化符號約束：另一條路線把符號約束的推理過程暴露給 LM，引導其學會滿足約束；藉把約束推理的複雜度外置到表示，讓 LM 把更多容量分給程式語意與演算法邏輯，且此增益隨模型規模有效擴展。基於語法的編碼（把程式解析為 AST、序列化為語法規則序列）是其一例——當語法規則以 CHC 表達時，它是本框架的特例，本文把此概念推廣到任意 CHC 可表達的約束。Tare 為程式修復學習 Java 型別系統，但專用於 Java 型別系統子集、經 AST 遍歷運作、未達完全型別顯性。Refine4LLM 以順序精化規則生成程式，但需含精化過程的訓練資料（實務稀缺）且綁定特定精化演算；相較之下 TyFlow 給定型別檢查器即可用現成程式訓練、並支援任何 CHC 可表達的約束。

8. 結論

TyFlow 藉由把型別推理直接整合進程式碼生成過程來保證型別正確性。透過同構的合成系統與合成決策序列表示，TyFlow 確保程式與其型別推導對齊生成，在消除型別錯誤的同時顯著提升整體生成表現。超越型別正確性，其基於 CHC 的基礎開啟更廣應用（安全性驗證、其他結構化資料生成）。核心洞見——讓程式表示與底層形式系統對齊能提升生成表現——為其他「結構約束至關重要」的領域指出了有希望的方向。
