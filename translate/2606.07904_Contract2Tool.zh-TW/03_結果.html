7. 結果

7.1 內在合約品質

Schema 與 documentation 提供最強的前置條件恢復：Requires F1 分別達 0.99 與 1.00。Name-only 與 metadata-only 設置可恢復有用的效果資訊（Produces F1 0.86），但在精確合約恢復上較不可靠。工具名稱與描述常揭示工具的主題，而 schema 與文件更適用於識別可靠執行所需的狀態變數。

7.2 軌跡與混合證據

Hybrid 給出最佳整體結果：Claude Opus 4.8 達到 Requires F1 1.00、Produces F1 0.98、exact match 0.77；Claude Sonnet 4.6 達到 Requires F1 1.00、Produces F1 0.99、exact match 0.74。軌跡在靜態文件描述人類面向輸出但下游工作流依賴更具體狀態變數時尤為有用——例如數個模型推斷日曆搜尋工具產生事件列表，而基準要求特定 event identifier。

7.3 Filter-Oracle 評估

文件與 schema 衍生的 Opus 4.8 合約在 84.1% 決策步驟暴露金下一步工具，7.8% 步驟無可見工具。相比之下，軌跡與混合合約精確恢復金因果前沿：Opus 4.8 Hybrid 與 Sonnet 4.6 Hybrid 均達到 1.00 金工具暴露率、0.00 無可見率、每步一個可見工具。Llama 3.3 的文件與 schema 合約僅在 60.4% 步驟暴露金工具。

7.4 下游 Agent 表現

金 CMTF 成功率 0.990，學習 CMTF 0.980——近乎匹配。學習 CMTF 將錯誤工具調用降至 0.020/任務，消除過早行動（0.000），每步僅暴露一個工具。相對於全工具暴露：可見工具從 100→1，token 從 26,172→2,528。

在模型層面，Nova 2 Lite、Nova 2 Pro、Claude Sonnet 4.6 上學習 CMTF 精確匹配金 CMTF。Claude 3.5 Haiku 上學習 CMTF 略低（成功 0.92 vs 金 0.96，錯誤工具 0.08 vs 金 0.04），但仍大幅優於所有非因果基線。

8. 討論

8.1 合約作為缺失層

結果支持工具合約構成 schema 與 agent 執行之間的有用中間層。Schema 描述如何調用工具；合約描述工具何時應暴露及實現什麼任務狀態轉換。此區別對多步驟工具使用至關重要——agent 可能知道如何調用工具，卻仍過早調用、選擇語意相關但不必要的工具、或未能暴露工作流所需下一步工具。

8.2 軌跡證據為何重要

文件與 schema 不總是描述因果過濾所需的狀態變數。工具描述可能說日曆搜尋返回事件列表，但下游工作流要求特定 event identifier。此區別在 filter-oracle 中顯現：文件合約僅 84.1% 暴露金工具，軌跡合約精確恢復因果前沿。執行軌跡直接暴露前後狀態變化，使學習合約能觀察成功執行後的狀態變數。

8.3 內在準確性必要但不充分

合約集可達高平均 F1 卻仍遺漏任務關鍵因果邊——導致過度過濾或過濾不足。Filter-oracle 評估透過逐步測試因果前沿來填補此缺口。Exact match 是保守指標——可能懲罰無害的額外欄位，而下游過濾最依賴保留關鍵因果邊。

8.4 學習合約可近似金合約過濾

學習 CMTF 成功率 0.980 vs 金 CMTF 0.990，每步平均一個可見工具。精確合約恢復不總是必要——最重要的是保留暴露正確下一步工具並隱藏過早或不相關工具所需的因果結構。

8.5 朝向自我維護的工具註冊表

大型工具生態隨時間變化。Contract2Tool 暗示一條通往自我維護工具註冊表的路徑——使用元資料、schema、文件與執行軌跡引導與刷新合約。實踐中此類系統應保持人類可審查，尤其是高風險行為。學習合約最好視為可規模化合約生成與監控層，而非安全審查替代方案。

9. 局限與有效性威脅

  • 使用受控合成工具註冊表（100 工具），可能未捕捉真實 API 生態的完整複雜性（不完整文件、不一致 schema、認證限制、速率限制、副作用）。
  • 假設固定的標準狀態變數詞彙；定義此詞彙本身為設計挑戰。
  • 軌跡實驗主要使用受控模擬任務軌跡；真實軌跡可能稀疏、嘈雜、偏向常見工作流。
  • 下游使用模擬工具執行隔離工具選擇行為，未測試真實 API 故障、延遲變化、授權錯誤、非確定性輸出或不可逆副作用。
  • 下游結果受模型特定工具調用行為影響，應解釋為學習合約集、過濾方法與工具調用模型的組合行為。

10. 結論

本文提出 Contract2Tool，一個為工具增強 LLM agent 學習輕量級工具合約的框架。核心動機：因果工具過濾依賴前置條件、效果與風險註解，但手動定義與維護不具規模性。Contract2Tool 從工具元資料、schema、文件與執行軌跡推斷結構化合約，並在內在與下游因果過濾中評估。

結果顯示學習合約可保留金合約的大部分可靠性與效率優勢。使用 Hybrid 證據的學習 CMTF 達到 0.980 下游成功率（金 CMTF 0.990），將可見工具從 100 降至 1，token 從 26,172 降至 2,528。軌跡證據至關重要——它暴露 schema 與文件可能遺漏的任務狀態轉換。更廣泛而言，此工作表明可靠的工具增強 agent 需要在 schema 與 agent 執行之間建立合約層。未來工作應在真實 API 生態系統、更大動態工具註冊表、生產執行軌跡與高風險場景中驗證合約學習。
