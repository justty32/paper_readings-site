Evolutionary Ensemble Search: Council-Guided Program Evolution with Persistent Memory

摘要與問題

機器學習工程的搜尋對象不只是超參數，還包括資料表示、訓練流程、推論規則與最終預測的組合。Evolutionary Ensemble Search，簡稱 EES，以 executable procedure 為演化單位：語言模型可以建議改法，但候選必須實際執行並取得自己的驗證證據，不能繼承父代分數。

EES 也試圖解決短期搜尋容易遺忘的問題。它同時保留活躍族群、可重用 archive、session memory、mutation operator 權重與剩餘預算。失敗候選雖不進入品質排序，仍留在 execution log，供後續診斷與成本稽核。

搜尋架構與演化流程

Council 由 discovery、methodology、memory、modeling 與 code review 等角色組成。角色不是投票選答案，而是從同一份任務證據提出互補的實驗方向、風險與警告；orchestrator 再把它們變成有界的 profiling、研究、實作、訓練、推論或 synthesis 工作。

每次 mutation 都從已量測父代與診斷紀錄出發。critic 根據 residual、資料切片錯誤、train-validation gap、fold variability 或預測相關性判斷問題，architect 再把診斷轉成可執行 edit directive。變異可改設定、pipeline、局部程式碼、跨父代組合或 ensemble 結構；任何子代都要重新執行，確認 artifact、輸出語意與比較 protocol 相容。

Nested profile 用品質與父代被使用次數共同決定繁殖機率，避免高分單一路線壟斷。候選可因預測多樣性或品質與複雜度取捨而保留，不必每次都擊敗父代。Operator credit 只在相同 protocol 下，依子代相對自己父代的改善 gate 更新；作者強調這是操作性 credit，不是因果歸因或科學假設檢定。

記憶分成多個時間尺度。短期 session memory 保存資料輪廓、假設、失敗與 incumbent；一輪結束後，再把有效及浪費的策略、特徵與來源警告濃縮成 problem-indexed lesson。新任務只把相似 lesson 當先驗，取回的 procedure 仍須依新任務契約重測。

最後的 prediction ensemble 只能組合 row、target、class 與 protocol 語意一致的候選。即使 shape 相同，也不能把類別標籤誤當機率平均。Ensemble 必須在共同 validation 基礎上超過最佳單一候選與預設門檻，否則保留 incumbent。

MLE-bench Lite 開發研究

作者以 MLE-bench Lite 的二十二個任務整理一份版本固定的開發 ledger（作者自報）。每題保存最強 artifact、方法說明與三筆 confirmation，但 confirmation 可能是新 seed、獨立 process execution，或完全相同 prediction file 的 replay；它們不是一致且獨立的完整搜尋重跑。

作者也清楚標出量測邊界。開發期間可看到 grade，後續工程會受其影響；部分路線使用外部語料、圖片、歷史查找，甚至直接 target lookup。數值 grader 只驗 prediction artifact，不會自行證明資料來源合規。公開 ledger 也未涵蓋每次候選、總 compute，或所有 council、credit 與 retrieval 的啟用紀錄。

主要結果

Ledger 在二十二題中記錄十九題達 medal threshold，比例為百分之八十六點三六；最佳成績分布為十一金、五銀、三銅（作者自報）。三欄 confirmation 都在同樣十九題保有 medal，但等級會變動（作者自報）。五十七筆 medal confirmation 只對應四十六組不同的 task 與 submission hash（作者自報），所以穩定的達標比例不能直接當作盲測不確定性估計。

成果跨越文字、影像、表格、音訊、科學幾何與 deterministic transformation。NOMAD 例子用晶格與原子結構特徵配合 ExtraTrees；Dirty Documents 以背景估計、成對影像重建與逐像素 serialization 產生輸出；文字正規化則混合訓練資料查表與決定性規則。這些案例說明搜尋空間能改造完整計算程序，不等於證明每項 artifact 都由整套 EES 元件共同產生。

結論與局限

EES 把專家式檢視、父代條件 mutation、族群保存、prediction ensemble 與跨輪記憶串在同一套可執行介面中。核心原則是提案與量測分離：推理決定哪裡值得搜，只有執行結果能決定候選是否留下。

作者明確限制結論範圍。這份開發紀錄不估計 council、nested evolution、memory 或 ensemble 各自的邊際效益，也不證明統一成本優勢或對未碰觸任務的盲泛化。有限 validation 經反覆 adaptive selection 可能被過度利用，retrieved memory 也可能攜帶任務特例或錯誤來源。完整 engine 為 proprietary，公開的是 ledger、solution notes、選定 artifact 與 reproduction instructions，因此可重現 artifact 檢查，不等於可重跑完整搜尋。
