摘要

大型語言模型（LLM）採用自回歸解碼（auto-regressive decoding），每一步都依賴上一步輸出而必須循序計算。這造成瓶頸：每步都需把完整模型參數從高頻寬記憶體（High-Bandwidth Memory, HBM）搬到加速器快取。雖有推測解碼（speculative decoding）等方法試圖緩解，但其實作受制於「取得與維護一個獨立 draft 模型」的困難。本文提出 Medusa：在 LLM 推論上外加額外的解碼頭（decoding heads）以並行預測多個後續 token。透過樹狀注意力（tree-based attention）機制，Medusa 在每一解碼步建構多條候選延續並同時驗證，藉並行處理大幅減少所需解碼步數。我們提供兩種微調層級：Medusa-1——在凍結（frozen）主幹上直接微調頭，達成無損（lossless）加速；Medusa-2——頭與主幹聯合微調，頭預測更準、加速更高，但需特殊訓練配方以保住模型能力。另提出數項擴展：**自蒸餾（self-distillation）**處理無訓練資料的情形、**典型接受（typical acceptance）**在維持品質下提升接受率。實驗顯示 Medusa-1 可達 2.2× 以上加速而不損品質，Medusa-2 進一步提升到 2.3–2.8×。

1. 引言

LLM 隨規模成長品質提升，但推論延遲也隨之增加。從系統角度看，LLM 推論主要是記憶體頻寬受限（memory-bandwidth-bound）：延遲瓶頸來自加速器的記憶體頻寬，而非算術運算。這源於自回歸解碼的循序本質——每次前向都要把完整參數從 HBM 搬到快取，卻只生成一個 token，嚴重低估現代加速器的算力潛能。

一種加速思路是提高解碼過程的算術強度（arithmetic intensity，總 FLOPs 對總資料搬運之比）並減少解碼步數。推測解碼即循此而生：用一個較小的 draft 模型生成一段 token 序列，再由原大模型一次評估、接受可用的延續。但取得合適的 draft 模型很難，將其整合進分散式系統更難。

本文改採「在主幹上加多個解碼頭」的舊概念（Stern et al., 2018）並加以精煉。我們提出 Medusa：加入額外解碼頭以並行預測多個 token；這些頭以**參數高效（parameter-efficient）**方式微調、可加到任何既有模型；無需 draft 模型，能無縫整合進現有 LLM 系統（含分散式環境）。

兩項關鍵洞見：(1) 每步只生成單一候選延續浪費算力，故我們用 Medusa 頭生成多條候選、僅靠調整 attention mask 就並行驗證；(2) 可沿用推測解碼的 rejection sampling 產出與原模型同分佈的結果，但那無法進一步提升加速，故我們另提典型接受方案——以溫度當閾值管理與原模型預測的偏離，作為更有效率的替代。

兩種微調程序：資源有限、或希望「加 Medusa 而不動原模型表現」時用 Medusa-1（記憶體需求極小、可量化）；資源充足、或要直接從基底模型做 SFT 時用 Medusa-2（頭與主幹聯合訓練、加速更大）。取得訓練資料的策略依模型訓練配方而定：若模型是在公開資料上微調則可直接用；若資料不可得或模型經過 RLHF，則建議自蒸餾產生訓練集。

實驗聚焦 batch size = 1（代表 LLM 本地個人使用場景），在 Vicuna-7B/13B/33B 與 Zephyr-7B 上測得跨不同 prompt 類型 2.3–2.8× 的加速而不損品質。
