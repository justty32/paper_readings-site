3. 方法論

給定基底 LLM ℬ 與目標任務 𝒯，提示工程師的工作是打造一個優化後的自然語言提示詞 𝒫^𝒯，最大化 ℬ 在 𝒯 上的表現。然而，新手與專家提示工程師之間的落差可能相當可觀，尤其在需要專門領域知識的任務（如生醫領域）上更是如此。本文的核心目標是自主精煉任務提示詞 𝒫^𝒯 以彌合這道知識落差，同時盡量減少人類介入。多數既有方法依賴迭代取樣局部提示詞替代方案，不僅耗費資源，也無法保證產出最優的最終提示詞。為此，本文提出 PromptAgent——一個基於智能體的框架，透過策略規劃與在提示過程中反思錯誤回饋，產出專家級任務提示詞，在探索與表現間取得適當平衡。

問題形式化：延續提示詞優化的標準設定，從初始自然語言任務提示詞 𝒫₀（例如「讓我們一步步解這個問題」）與來自目標任務 𝒯 的一小組訓練樣本 (Q,A)={q_i,a_i} 出發。給定由 𝒫 與 q_i 組成的模型輸入，基底 LLM ℬ 依 p_ℬ(a_i|q_i,𝒫) 做出預測（典型上是由左至右的生成過程；注意這是傳統的零樣本設定，任務提示詞不包含任何訓練樣本）。提示詞優化的目標是找出最大化衡量函數 ℛ（如準確率）的最優自然語言提示詞 𝒫*，形式化為在提示詞樣本空間 𝒮（一個無限、難以窮舉的空間）上求 arg max 的優化問題。人類專家傳統上靠一套啟發式與領域洞見的組合來打造這種提示詞；本文則提出一個統一框架，無縫整合策略規劃來達成更優的專家級提示詞優化。

3.1 PromptAgent 框架設計

PromptAgent 的目標是有效地把專家先驗知識整合進任務提示詞，同時確保對龐大提示詞空間的高效、策略性探索。在此規劃框架下，把每一次迭代／每一版任務提示詞定義為狀態 s_t = 𝒫_t，藉此系統性監控提示詞的演化，並直接對其套用精煉。動作在此語境下可想成對當前提示詞（狀態）的潛在修改，如換詞或改寫（既有研究已探討）；但更理想的動作空間應能引入更有效、更有意義、能喚起專家先驗知識的修訂，最終導向專家級提示詞。因此本文提出以錯誤為基礎的動作：每個動作依基底模型犯下的特定錯誤而生成。具體而言，如圖 3(b) 所示，動作被表述為錯誤回饋，用來引導後續的提示詞精煉。這類錯誤回饋能有效建議修正模型錯誤的潛在方向，確保修訂後的提示詞更能指導基底模型避免先前觀察到的錯誤。這也呼應了近期關於 LLM 自我反思能力的發現——LLM 能直接反思自身錯誤以產出更好的提示詞修改。

給定狀態與動作的定義，PromptAgent 把提示詞優化問題表述為由 (𝒮, 𝒜, T, r) 構成的馬可夫決策過程（MDP）：𝒮 為狀態空間、𝒜 為動作空間、T 為轉移函數 T: 𝒮×𝒜 ↦ 𝒮、r 為獎勵函數 r: 𝒮×𝒜 ↦ ℝ。對於任一當前狀態 s_t，PromptAgent 迭代地依 a_t ~ p_𝒪(a|s_t, m₁) 生成動作，其中 m₁ 是優化器 LLM 𝒪 用來輔助動作生成的元提示詞。具體而言，動作生成分兩步：從訓練樣本收集基底模型的錯誤（步驟一），再反思這些錯誤以提煉出有用的錯誤回饋（步驟二）。之後，PromptAgent 依轉移函數 p_𝒪(s_{t+1}|s_t, a_t, m₂) 取得新狀態，其中 m₂ 是另一段元提示詞，同樣運作在 𝒪 上，協助狀態轉移以更新提示詞。更具體地，給定當前錯誤回饋作為動作 a_t，m₂ 要求優化器生成一則新提示詞（狀態），以運用任何領域知識、有效解決模型錯誤，類似提示專家依錯誤回饋修訂自己的提示詞的方式。

最後，每個新生成狀態 s_t 在套用動作 a_t 後的品質，由獎勵函數 r_t = r(s_t, a_t) 決定。類比強化學習中獎勵工程的複雜性，設計獎勵以容納特定任務的領域知識或偏好可能相當複雜。在不失框架跨任務通用性的前提下，本文直接把獎勵定義為在與訓練樣本分開的留出集上的任務表現；獎勵的確切定義則依後續實作細節中描述的任務特定指標而定。

3.2 提示詞優化的策略規劃

上述對提示詞優化的重新表述，讓本文能無縫地把 PromptAgent 與有原則的規劃算法——尤其是蒙地卡羅樹搜尋（MCTS）——結合起來，策略性地導航龐大的提示詞空間，同時在尋找高獎勵錯誤回饋路徑（通向最具泛化性的專家級提示詞）時，平衡探索與利用。具體而言，本文觀察到某些錯誤回饋（動作）可能把難以跨任務泛化的個案細節注入任務提示詞（利用），因此需要策略規劃來探索能帶來更高獎勵的新錯誤回饋（探索）。MCTS 透過逐步構建一棵樹（每個節點是一個狀態、每條邊是轉移狀態的動作）來實現這種策略規劃。MCTS 藉由維護狀態-動作價值函數 Q: 𝒮×𝒜 ↦ ℝ（代表對狀態 s_t 套用動作 a_t 的潛在未來獎勵）策略性地擴展這棵樹。換言之，本文依賴這個函數 Q(s_t, a_t) 來前瞻並估計沿著當前狀態-動作對之後路徑的潛在獎勵。為更新 Q 函數並擴展樹，MCTS 迭代執行四項操作：selection、expansion、simulation、back-propagation。迭代過程在達到預定迭代次數時結束，接著選出獎勵最高的軌跡作為最終提示詞。

Selection（選擇） 是第一步，在每一層挑出最有希望被進一步擴展探索的節點。每次迭代從根節點 s₀ 出發，逐層走過樹的每一層，在每一層選出一個子節點，直到停在葉節點。在每層選擇子節點時，採用著名的 Upper Confidence bounds applied to Trees (UCT) 算法，以下列公式在利用（選高價值節點）與探索（選較少被造訪的節點）間取得平衡：

a*t = argmax{a'_t ∈ A(s_t)} ( Q(s_t, a'_t) + c·√(ln 𝒩(s_t) / 𝒩(ch(s_t, a'_t))) )

其中 A(s_t) 是節點 s_t 的動作集合，𝒩(s_t) 是節點 s_t 被造訪的次數，ch(s,a) 代表節點 s_t 套用動作 a'_t 後的子節點，c 是調整探索程度的常數。第一項代表由 Q 值體現的利用，第二項代表探索——衡量較少被造訪節點的不確定性。

Expansion（擴展） 藉由對前一步 selection 到達的葉節點新增子節點來擴展樹，做法是多次套用動作生成與狀態轉移（圖 3(b)），得到多個新動作與新狀態（可能取樣多個訓練批次以得到多樣的錯誤回饋／動作）。在這些新節點中，取獎勵最高者送入下一步 simulation。

Simulation（模擬） 是為前一步 expansion 選出的節點模擬未來軌跡的前瞻步驟，通常搭配一種能快速抵達終止狀態、計算未來獎勵的 playout 策略（選擇可以很靈活，如隨機走到底）。為降低模擬的計算成本並簡化流程，本文改為反覆執行前述 expansion 步驟直到終止，也就是持續生成多個動作、在其中選獎勵最高的節點推進到下一樹層。

Back-propagation（反向傳播） 發生在模擬過程遇到終止狀態時。終止狀態通常定義為達到預定最大深度，或觸發提早停止準則。此時沿著從根節點到終止節點的路徑，回頭反向傳播未來獎勵，更新 Q 值函數：對路徑上每個狀態-動作對，Q(s_t, a_t) 藉由彙總所有從 s_t 出發的未來軌跡獎勵來更新：

Q*(s_t, a_t) = (1/M) Σ_{j=1}^{M} ( Σ_{s'∈S^j_{s_t}, a'∈A^j_{a_t}} r(s', a') )

其中 M 是從 s_t 出發的未來軌跡數量，S^j_{s_t} 與 A^j_{a_t} 分別代表從 s_t、a_t 出發的第 j 條狀態與動作序列。

PromptAgent 以預定迭代次數執行上述四項操作，使 Q 值穩定並完整長成能探索龐大提示詞空間的樹。最終需選出最佳軌跡與節點（即提示詞）做最終評估——可選「最高獎勵路徑上獎勵最高的節點」，或直接選「造訪次數最多的葉節點」。為求簡單並基於實證效果，本文採前者作為輸出策略，在實驗中效果最好。
