5. 相關工作

5.1 庫抽取：庫抽取藉把多函數的共用功能抽成單一反覆使用的函數來壓縮碼。多數最先進工作基於 DreamCoder（Ellis et al., 2020）——一個以 wake-sleep 演算法（Hinton et al., 1995）自小型問題語料自舉歸納式程式合成的合成器，用 EC²（Explore, Compress, Compile）演算法在睡眠階段抽庫。DreamCoder 雖能解多領域問題但有效能代價。Babble（Cao et al., 2023）用基於語意的抽象，更快產生更好抽象，但需額外提供語意等價清單，才能對語法不同卻語意等價的碼做抽象。Stitch（Bowers et al., 2023）則以定義效用度量、用 branch-and-bound 做自頂向下搜尋（剪掉效用上界小於當前最佳者的分支）來縮小搜尋空間、高效抽庫。Stitch、Babble、DreamCoder 都是為函數式（Lisp 類）語言設計，Leroy 延伸並增強前人技術以在命令式語言上抽庫。

5.2 使用大型語言模型：Lilo（Grand et al., 2024）像 DreamCoder 以 wake-sleep 運作，在合成階段用 LLM、並用 Stitch 壓縮演算法學庫，還用 LLM 為學到的庫寫文件以助後續合成——但聚焦函數式語言。ReGAL（Stengel-Eskin et al., 2024）針對特定領域（如畫形狀）依提示生成 Python 程式，在庫抽取與程式合成兩階段都用 LLM；但因依賴 LLM，其抽象未必可證明等價於原碼，且受 context window 大小限制、無法擴展到大型軟體庫。相較之下 Leroy 能處理大語料且抽象等價。此外 Lilo 與 ReGAL 聚焦程式合成（抽象為輔），Leroy 則專注於在語料上學抽象。

5.3 視覺抽象、程式學習與重寫：庫抽取工具（含 Leroy）屬「程式理解與重寫」的大研究領域。有工作聚焦程式的視覺表示（如 ShapeCoder 用神經網路與 e-graph 從視覺建模抽象並解釋輸入形狀）；另有程式學習與程式重寫（用尋找慣用語、蒙地卡羅樹搜尋等方法）等相關線。

6. 討論與未來工作

Leroy 泛化了 Stitch 並解決其吃 Python 碼時的主要問題，但仍待更廣、更嚴格的測試。Leroy 可用更進階的程式分析法進一步處理 lambda、巢狀函數、類別等問題。此外 Leroy 延伸 Stitch 時未如 Babble 利用程式語意，故可借鑑 Babble、用語意等價擴大抽象選擇。最後，目前 Leroy 只測壓縮，但 Python 的庫抽取也應瞄準可讀性等程式品質指標（可編進效用函數），尚未測試。

附錄 A：P2 文法（要旨）

P2（Siek and Chang, 2017）含整數與布林值/變數、加減、布林運算、比較子、條件、三元運算、while 迴圈、函數呼叫與定義。已發表的 P2 亦支援巢狀函數定義與 lambda，本文將其支援留待未來。文法要點：program ::= module；module ::= statement+；語句含 print(expression)、target = expression、return expression 等；運算式含 name、整數、True/False、一元負號/not、+、and/or、==/!=、三元 expr if expr else expr、is、串列 [...]、字典 {...}、下標、呼叫 expression(expr_list)、以及 eval(input())；compound_stmt ::= def identifier(id_list): suite。
