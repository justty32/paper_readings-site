7. Prolog 協助規劃器活動的角色

先理解使用者提問時可能出什麼錯：(1) LLM 幻覺；(2) RAG 鄰近度量與意圖不對齊、檢索不到答案；(3) planner 選錯執行步驟（這是要用邏輯推理攻克的）。神經符號與 LLM+Prolog 已有多項前作。規劃器要能：把步驟定義為正/負謂詞序列、用大量謂詞覆蓋技術提問、組合步驟（and/or）、用 LLM 已學過的語言、且建立 ground truth 成本極低（用 Prolog 則編譯即可驗證、parse tree 可評估解的好壞）。

7.1 透過拼接邏輯元件來規劃

策略：把問題化為文法問題＋強型別系統。定義基本型別（StrOrList、TableName、Filter、Projection、Header、Data），再定義操作資料的謂詞工具（表 1：query_data、filter、project、count、anomaly、visualize_map），分三類——SQL 類資料函式、演算法（傳統預測 ML/複雜算術）、UI/UX 產物。沿用 [20]：由種子問題擴增題庫 → 萃取 MVC 元件（盡量重用既有元件）→ 找缺口列待實作函式（演算法 1；因 LLM 會幻覺，建議人工複審）。

規劃 prompt 要求 LLM 解讀查詢、生成 Prolog 計畫並依 evaluation 指標自評最大化，輸出 JSON（explanation/gaps/findings/plan/action/result/evaluation）。評分守則：生成後從 1.0 起；未實例化即用 foreign function 之輸入 → 0.0；用 LLM 自寫 assert 謂詞 −0.2；對含 header+data 的物件呼叫原生 sort/findall/aggregate −0.4…。藉獎懲讓 LLM 自我反思推理步驟（類似把自生評估指標餵入 GRPO 微調迴圈 [57]）。三種「動態實例化函式」情境：固定 user story（傳統）、動態生成程式碼直到通過（連 Python 但太複雜）、提供大量小元件由 LLM 拼接（較能控幻覺與安全、可用小模型，但能力受初始探索步驟限制）——本文取中道。

8. 資料集概覽

8.1 DABStep benchmark

DABStep（Data Agent Benchmark for Stepwise Evaluation of Planning）：450+ 個真實多跳推理任務，領域含金融交易、風險分析、商戶行為、營運指標。每題含結構化資料（CSV/JSON）、選用非結構化脈絡（文件/手冊）、與須高度精確作答的自然語言問題，採精確匹配，不容部分正確或幻覺。核心資料檔含 payments.csv（13.8 萬筆匿名交易+詐欺風險訊號）、fees.json（1000 條費率規則）、acquirer_countries.csv、merchant_category_codes.csv、merchant_data.json、manual.md。統計（表 3）：456 題、平均 3.2 表/題、中位 5,000 列/表、64% 需 join、28% 需外部文件、易/難 55%/45%、精確匹配。

8.2 範例任務

如「2023 年哪個 card scheme 平均詐欺率最高？」（答 SwiftCharge）、「2023 年 Crossfit Hanna 若鼓勵用戶換 ACI 以降詐欺，哪選項最省費？」（答 E:346.49）——須時間過濾、欄位選取、彙總、領域知識解讀。用 40 題/查詢擴增 + MVC 萃取，推得近 30 個工具函式介面（get_payments_data、calculate_transaction_fee、identify_local_acquiring_opportunities、display_* 等），並擴展 [20] 同時生成 controller/view 介面。

9. 結論

LLM 擅機率語言任務，但面對嚴格邏輯推理、離散決策、形式規則時有關鍵限制，在安全攸關領域尤甚。本文提出神經符號方法：用模組化可組合工具（尤其 Prolog 謂詞）增強 LLM，使其把複雜查詢拆成可驗證小步驟、拼接專用函式編排解法；藉一階邏輯與顯式規則精確表達事實、規則與否定（純機率模型或知識圖譜難達）。在 planner 階段整合邏輯推理，配合自我反思/評估，緩解幻覺與錯誤步驟拆解。DABStep 實驗驗證：把使用者問題擴成完整子任務集並映到 MVC 元件，重獲傳統 user story/use case 的精度與覆蓋，利系統文件化、工作量估算與功能缺口辨識。整體：LLM + 邏輯推理模組 + 模組化工具編排，提供通往可靠、可解釋、安全的複雜域 AI agent 的可擴展路徑，為 LLM 驅動系統恢復工程嚴謹度。
