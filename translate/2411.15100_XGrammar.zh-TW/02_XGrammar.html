3. XGrammar

XGrammar 以 byte-level PDA 解釋 CFG：字元邊可含一或多個 byte，處理不規則 token 邊界並支援含 sub-UTF8 字元的 token。自動機結構經 §3.4 優化以加速匹配。預處理階段生成 adaptive token mask cache（§3.1），並由 context expansion（§3.2）增強其效果；執行期快取快速產生大部分 mask，持久化執行堆疊（§3.3）高效處理其餘 context-dependent token；mask 生成與 LLM 推理重疊（§3.5）以最小化開銷。LLM 在 mask 約束下生成新 token 後，該 token 用來更新 PDA 堆疊狀態，供下一步生成 mask。

3.1 自適應詞元遮罩快取（Adaptive Token Mask Cache）

token 匹配 PDA 時堆疊有三種變化：(1) 展開子規則，push 新元素；(2) 規則內前進，更新棧頂節點；(3) 到達當前規則末端、返回父規則，pop 元素。前兩者的判定只依賴棧頂節點 → 定義為 context-independent tokens；第三者需檢視整個運行堆疊 → context-dependent tokens。對 PDA 每個節點，都有一組「該節點在棧頂時」的 context-independent token，其合法性可事先算好，故以棧頂節點為 key 預存進快取。執行期直接依棧頂取 context-independent token 的合法性生 mask，其餘少數 context-dependent token 才用完整堆疊執行 PDA 判定；若有平行堆疊，各自 mask 取被接受 token 的聯集合併。實測 Llama-3.1＋JSON 文法下，context-dependent token 僅占 不到 1%（128k 中 1134 個）。

自適應儲存（圖 5）：每個節點把詞彙分成「被接受的 context-independent」「被拒的 context-independent」「context-dependent」三部分；三者涵蓋全部 token，故只需存兩個較小子集。觀察到一組 context-independent token 傾向「幾乎全接受」（accept-heavy，如當前節點可匹配 [^"\]* 這類萬用字元）或「幾乎全拒」（reject-heavy，只接受少數特定字元）。據此：accept-heavy 存「被拒 + context-dependent」；reject-heavy 存「被接受 + context-dependent」；兩者相當時把接受/拒絕壓成詞彙表大小的 bitset。實作會枚舉三種格式取最小者。此法把 Llama-3.1＋JSON 的總記憶體從 160MB 降到 0.46MB（0.2%）。合併平行堆疊 mask 的演算法（Algorithm 1）依儲存型別優化：accept-heavy 對 PartialRej 取交集、reject-heavy 對 PartialAcc 取聯集，最終被拒集為 PartialRej \ PartialAcc，讓集合運算只落在小子集上。

3.2 上下文擴展（Context Expansion）

即使有快取，執行期仍需檢查所有 context-dependent token，是效率瓶頸。觀察：token 之所以 context-dependent 是因匹配到當前規則末端、還有剩餘部分需返回父規則續查；但很多情況下該剩餘部分其實不合法——因為許多規則到末端時，能返回的父規則位置有限、其後可再匹配的字串集合也有限。

據此，context expansion 為每條規則預先算出「返回父規則後能接受的字串集合」，稱 expanded suffix（擴展後綴）。context-dependent token 未匹配的剩餘部分必須是 expanded suffix 的前綴、或以 expanded suffix 開頭，否則直接拒絕。此過濾在預處理就剔除「在更高層規則上下文會失敗」的 token，把 Llama-3.1＋JSON 的 context-dependent token 從 1,134 降到 120（減 90%）。

Algorithm 2 以 FSA A_R^ctx 表示規則 R 的 expanded suffix：找出 PDA 中所有引用 R 的邊 (s,t)（屬某規則 R′，R′ 不必異於 R），從 t 起以 DFS 找出「R 之後可能跟隨的字串」子圖；為避免規則間遞迴引用，不走引用其他規則的邊（故抽取子圖只含字元標籤），節點若同時有字元邊與規則引用邊則停在該節點。對所有規則重複並取聯集。雖不考慮規則引用邊，但因 §3.4 的 inlining 會把碎片規則內聯進父規則，仍能抽出許多有用上下文。

3.3 持久化執行堆疊（Persistent Execution Stack）

文法引擎既要對 context-dependent token 執行 PDA，也要在預處理時對所有位置執行 PDA 算 context-independent 集合；兩者都需維護多條平行堆疊並隨字元匹配分支。為支援高效分支，引入持久化執行堆疊（Driscoll et al., 1989）（圖 7）：把「當前時點的平行堆疊」與「歷史時點的堆疊」組織成一棵樹，每條堆疊是從根到某節點的路徑，棧頂以指標表示。相鄰時點的堆疊常共享大部分深層元素、僅少數 push/pop，故合併成樹可避免重複儲存的記憶體冗餘。匹配新字元遇文法歧義需分裂堆疊時，只需分裂該分岔而非複製整條堆疊，降低分支開銷。

它也支援快速回滾：維護歷史時點堆疊，回滾只需改當前棧頂指標（常數時間）。這對檢查大量 token 特別有用——許多 token 共享前綴（如 read、ready、reader 共享 read）；把待檢 token 依字典序排、算最長共同前綴，逐一檢查前先回滾到「與前一 token 的共同前綴之後」，即可省去重複檢查共同前綴。Llama-3.1＋JSON 下，整個詞彙表需檢查的字元數降到 30%，大幅加速預處理。

回滾支援更多應用：jump-forward decoding（Yin et al., 2024）需重新 tokenize（回滾部分 token 再插入新 token）——可讓自動機狀態隨輸出 token 一起回滾，確保回滾後仍能續行結構化生成。需樹狀生成的應用（Tree-of-Thought、SGLang、投機解碼 SpecInfer）——可為輸出樹每個分支維護自動機狀態，輸出分岔時快速分裂狀態（只需在樹上維護各分支的棧頂指標）。

3.4 下推自動機結構優化

借鑑傳統編譯器優化概念，但發現對高效受約束解碼特別有用。

  • Rule inlining（規則內聯）：CFG 常有很多「碎片規則」（只含少數元素），轉成 PDA 中的小 FSA，既增加文法歧義（執行期須查進這些碎片規則），又因 context expansion 不考慮碎片規則引用而使抽取的上下文自動機更小、錯失剔除機會。故採自動內聯策略：反覆挑「不引用其他規則」的規則內聯進父規則；為避免自動機爆炸，限制內聯規則與內聯結果大小為常數。此舉幾乎消除碎片規則，提升 token 檢查效率與 context expansion 效果。
  • PDA 節點合併（Node merging）：歧義常來自「同一節點有多條同標籤出邊」——匹配到此節點且下一字元符合標籤時堆疊會分裂成多條（每出邊一條），增加計算。合併演算法把滿足「a) 由同源同標籤邊指向、b) 未被其他邊指向」的後繼節點合併。此外 epsilon 邊（可不消耗字元從 s 移到 t）也增歧義（到 s 時堆疊分裂成 s、t 兩條），故在「s 無其他出邊 或 t 無其他入邊」時把 s、t 合併成單一節點。兩優化保持自動機等價、但減少節點與邊，執行期降低堆疊數與 token 檢查計算。

3.5 mask 生成與 LLM 推理重疊

mask 生成雖大幅加速，仍需 CPU 計算。為進一步消除開銷，把 mask 生成與 LLM 推理重疊（圖 8）：mask 生成只需 CPU、只依賴已生成 token；LLM 推理（除採樣階段）只需 GPU、也只依賴已生成 token——故可讓 CPU 上的 mask 生成與 GPU 上的推理並行，採樣前同步，GPU 取得 mask 後做 masked sampling 生成新 token。預處理階段也可與 LLM prefill（處理 prompt）重疊。實務上 mask 生成時間短於 LLM 推理，不會成為瓶頸 → 對推理近乎零開銷。
