摘要

LLM Agent 應用日益複雜多樣，對「可被解析成程式碼、結構化函式呼叫、具身代理指令」的結構化輸出需求大增，也讓 LLM 推理中的結構化生成成為重要問題。context-free grammar（CFG，上下文無關文法）是透過受約束解碼（constrained decoding）實現結構化生成的靈活途徑；但執行 CFG 需在執行期對詞彙表中所有 token 走過數個堆疊狀態，帶來不可忽視的開銷。本文提出 XGrammar——一套靈活且高效的結構化生成引擎。它把詞彙表分成兩類加速 CFG 執行：可預先檢查的 context-independent tokens 與需執行期解釋的 context-dependent tokens；並建立變換來擴展文法上下文、減少 context-independent（原文如此，實指縮減需執行期處理的）token 數；再以高效的持久化堆疊加速 context-dependent token 檢查；最後把文法引擎與 LLM 推理引擎協同設計，使文法計算與 GPU 執行重疊。評估顯示 XGrammar 相較既有方案最高可達 100 倍加速；結合 LLM 推理引擎可在端到端服務中達成近零開銷的結構化生成。

1. 引言

LLM 的近期進展催生了程式生成、除錯、透過 function calling 呼叫外部工具、機器人控制等複雜應用；這些應用都需要 LLM 的輸出符合特定格式或文法（JSON、SQL 或任務專屬格式），下游系統才能有機地消費這些結構化輸出並做後續互動。

受約束解碼是結構化生成常用手法：它在每個解碼步驟只允許符合結構的 token 被生成，藉此保證輸出遵守指定結構——先掃描整個詞彙表找出不合法 token，把它們機率設為零。為支援多樣應用中豐富的結構格式，需要靈活的機制來指定與檢查約束。CFG 以一組規則定義結構，每條規則含字元序列或對其他規則的引用，可遞迴組合表達複雜結構；相較正規表達式，CFG 允許遞迴結構、更靈活，適合描述 JSON、SQL 與各種 DSL。

但純樸地把 CFG 用於受約束解碼並不高效，原因有三：(1) 每步都要對詞彙表中每個 token（Llama-3.1 達 128k）解釋 CFG；(2) CFG 解釋需維護追蹤「已匹配遞迴規則」的堆疊狀態，其組合無窮多、無法事先全部預算並快取；(3) LLM 每個 token 由多個字元組成，可能跨越文法元素邊界，執行期造成進一步遞迴或 pop，邊界不對齊須小心處理。

XGrammar 用 byte-level 下推自動機（PDA） 表示 CFG。核心洞見（圖 1）：把 token 分成僅憑自動機局部上下文即可判定的 context-independent tokens，與需整個堆疊狀態才能判定的 context-dependent tokens。前者的合法性預先算好、以量身訂做的儲存格式存進 adaptive token mask cache；再以演算法擴展各局部規則的上下文、減少 context-dependent token；並建立持久化堆疊系統支援快速狀態分支與回滾，加速 context-dependent 檢查與快取預處理；最後把文法引擎與推理引擎協同，讓文法計算與 GPU 計算重疊。

成果：對 CFG，單詞元延遲相較 SOTA 最高降 100 倍；整合進 Llama-3.1 的 LLM 服務引擎，在 H100 上端到端最高 80 倍加速。已開源並整合進主流開源 LLM 框架。三項貢獻：adaptive token mask cache、支援快速回滾的 persistent execution stack、與服務框架協同設計的高效文法引擎。

2. 背景

2.1 LLM 受約束生成

LLM（GPT-4、Llama、Mistral）以自回歸方式逐詞元生成；token 是基本輸入輸出單位，每個 token 代表固定字串、未必對應完整語意單位、甚至可能切斷一個 Unicode 字元——這對結構化文本生成造成挑戰。每步模型對詞彙表產生 logits，經 softmax 轉機率後由採樣器選下一 token。受約束解碼在每步限制可用 token：把會違反結構的 token 的 logits 設為 −∞（softmax 後機率為零，且保留其他合法 token 的相對機率），確保只採樣到合法 token。高效地辨識與遮罩不合法 token 至關重要，因為它直接影響生成速度（圖 2）。

2.2 上下文無關文法與下推自動機

CFG（Chomsky, 1956）含多條規則，每條含字元或對其他規則的引用，可遞迴組合定義複雜結構，適合 JSON/SQL/DSL；其遞迴本質比正規表達式表達力更強。下推自動機（PDA）用堆疊管理巢狀結構，常用來辨識 CFG 所生成的語言。本文採用一種等價但更利於說明演算法的 PDA 定義（形式定義見附錄 A）：PDA 由多個有限狀態自動機（FSA）組成，每個代表一條文法規則，堆疊處理遞迴規則展開。FSA 的邊有兩種——字元邊（接受特定字元）與規則引用邊（遞迴進入其他規則）。匹配字串時從主規則開始，遇規則引用邊就 push、規則匹配完就 pop 返回；棧頂即當前所達節點。若文法非確定（同一輸入字元有多個可能轉移），PDA 維護多條平行堆疊。但堆疊長度無界 → 狀態無窮多 → 無法對所有情境預算 token mask，這正是高效受約束解碼的難點。
