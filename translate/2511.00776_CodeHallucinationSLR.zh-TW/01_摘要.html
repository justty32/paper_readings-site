摘要

模型幻覺是 LLM 面臨的最關鍵挑戰之一，尤在高風險的程式碼智能任務。本文從四個視角系統綜述程式碼導向 LLM 的幻覺：第一，調查 60 篇論文以定義程式碼語境下的幻覺、總結主因（資料噪聲、曝光偏差、語意接地不足），並追蹤 NLP 與軟工社群的近期趨勢。第二，更廣地回顧模型幻覺綜述，總結代表性緩解策略（知識增強生成、約束解碼、後編輯）。第三，回顧程式碼智能專屬方法，凸顯加劇幻覺的程式碼特有挑戰（語法敏感、嚴格型別系統、外部函式庫依賴），並分析程式分析、符號執行、單元測試等新興任務如何用於偵測/緩解幻覺。第四，總結現有評測 benchmark（從靜態指標到編譯/執行正確性等動態檢查），強調需要幻覺導向的 benchmark。最後凸顯關鍵挑戰與未來方向：探討幻覺與泛化的微妙平衡、區分幻覺與一般功能錯誤、以及私有程式庫因缺公開資料使幻覺更難偵測修正的挑戰。本文為理解、評測、緩解 code LLM 幻覺、邁向可靠 AI 奠定基礎並勾勒路徑。

1. 引言

LLM 在程式碼摘要/生成/補全表現亮眼，但易產出語法正確、貌似合理、卻事實錯誤、不可執行、或與輸入意圖不符的輸出＝幻覺（源自心理學，描述輸出缺乏對輸入或現實的接地）。有研究主張幻覺是生成式推理機制的固有副產物。程式碼任務面臨相同風險但有領域特定代價：程式碼受嚴格語法語義約束、依賴模組元件、經多階段 build/test 管線、且必須執行——核心區別在自然語言供人解讀，PL 須被機器無歧義解析執行同時仍可供人理解。雖 PL 文法約束強（多為上下文無關文法、PDA 建模）但領域特異性更強，故幻覺後果更嚴重（編譯錯誤、安全漏洞）。程式碼智能工作流常含四階段：RAG、模型微調、各種 CoT 推理、迭代精修（圖 1）。

相較前作（Lee 等 [67] 僅綜述程式碼生成幻覺），本文四項優勢：(1) 不只生成、擴及摘要/補全/推理等更廣任務；(2) 跨 NLP 與軟工雙視角；(3) 對成因與表現做細粒度分析、擴至架構/語意層（模組化、設計模式違反）；(4) 強調緩解法與幻覺的交互。從三大資料庫（ACM、IEEE、WoS）識別 60 篇研究。四大 RQ：RQ1 定義/成因/趨勢；RQ2 NLP 緩解法的發展與分類；RQ3 程式碼專屬緩解法；RQ4 benchmark 與指標。並指出後續研究機會：幻覺與錯誤之別、信心 vs 幻覺、幻覺與泛化能力的關係、私有資料挑戰。

2. 背景

2.1 LLM 訓練流程與知識使用

三階段（圖 2）：預訓練（大規模無標註文本學語言模式與通識）、SFT（標註指令資料提升任務表現）、RLHF（對齊人類偏好）。關鍵：RLHF 用負回饋抑制不良 token，而 SFT 缺「哪些 token 不可生成」的顯式訊號，故即使資料多樣，SFT 仍可能強化錯誤 token（尤其常被標註/曝光者）。知識使用技術（圖 3）：RAG（從外部知識庫檢索）、微調（全參數 vs P-tuning/LoRA 等參數高效法）、CoT（中間推理步驟，及 Tree-of-Thoughts、GPT-4o(o3)、DeepSeek-R1 等進階推理）、agent（與外部工具/環境互動，迭代計畫-行動-推理）。

2.2 程式碼表示的多視角

程式碼智能涵蓋生成/補全/搜尋/摘要/修復/翻譯。三個表示視角（圖 5）：(1) Token 類別——從詞彙層（token/識別符）、語法語義層（文法結構、PDG）到脈絡語用層（慣用法、編碼慣例、領域約束）；(2) 功能分類法——Core Logic（核心邏輯：演算法/資料處理）、Supportive Logic（錯誤處理、輔助工具、調用碼）、Verification Logic（測試/斷言碼）；(3) 程式碼智能流程——從需求理解、程式合成，到後開發（優化、靜態驗證、動態驗證、人在迴路精修）。

4. RQ1：定義、成因與文獻趨勢

4.1 程式碼幻覺定義

程式碼幻覺＝LLM 在程式碼智能任務的產出語法正確或語意貌似合理、卻依賴捏造/不存在/脈絡無支撐元素者 [123]。與一般生成錯誤不同——幻覺源於模型的過度泛化與不確定下的過度自信機率推理。綜合 NLP 綜述 [46] 與程式碼分類法 [78,154]，提出統一三維分類（表 3）：

  • I. 知識幻覺（Factuality 事實性）：API 誤用（捏造/誤用真實 API、錯誤方法呼叫或參數型別不符）、函式庫誤用（假設不存在的功能，如 np.linear_regression(X,y)）、語言特性誤用（誤解語言語義/領域構造，如錯誤 async for）。
  • II. 功能不對齊（Faithfulness 忠實性）：功能需求違反（要 merge sort 卻給 bubble sort）、非功能需求違反（效能關鍵卻給 O(n²)）、邏輯流違反（控制邏輯偏離意圖、造成微妙缺陷）。
  • III. 環境與相依幻覺（Compatibility 相容性）：環境衝突（PyTorch<2.0 卻用 torch.compile()）、相依幻覺（假設 openai.ChatAPI 存在）、資源路徑錯誤（寫 /tmp/output.txt 未查目錄）。 事實性與相容性都涉及正確性，但事實性是程式碼內在錯誤（API/語法），相容性是程式碼邏輯正確卻因環境因素（缺相依、路徑錯）失敗。

4.2 幻覺在 LLM 中的進展

幻覺源於病理學/心理學（感知不存在的實體）；對 LLM 指生成內容不忠於輸入或無意義卻語法流暢。LLM 常被「激勵產出自信答案而非表達不確定」（許多評測獎勵作答勝於棄答），這解釋了幻覺程式碼為何貌似合理。

4.3 LLM 幻覺趨勢

成因四層（圖 8）：模型層（解碼漂移、曝光偏差、知識缺口、虛假泛化）、提示/輸入（需求模糊、缺脈絡、過長噪聲提示）、訓練資料（低品質/未篩程式碼、領域不匹配）、專案/環境（缺相依脈絡、API 版本衝突、環境特定假設）。趨勢（圖 6-7）：程式碼幻覺發表 2023 年 5 篇→2024 暴增 20 篇→2025 上半 13 篇；NLP 幻覺綜述 2024 峰值 12 篇。Venue：arXiv 預印本 54%、會議 30%、期刊 16%；貢獻型態：新方法 58%、實證 27%、benchmark 14%、綜述僅 1%（凸顯綜述稀缺）。 RQ1 小結：(1) 幻覺受關注與 LLM 廣泛採用同期；(2) 程式碼幻覺源於模型缺陷、不良提示、噪聲/不匹配訓練資料、執行環境不一致；(3) 分為事實性幻覺、忠實性幻覺、相容性幻覺三類。
