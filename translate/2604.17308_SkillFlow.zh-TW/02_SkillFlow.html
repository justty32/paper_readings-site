2 SkillFlow

2.1 Benchmark 概覽

SkillFlow 含 20 個工作流家族、166 個任務，橫跨五大領域：Finance & Economics、Operations & Supply Chain、Healthcare & Life Sciences、Governance & Strategy、Data & Document Intelligence。每個 benchmark 實例由「家族內任務序列」「固定的家族內難度序」「對應的驗證器風格」定義，家族規模 8–9 題不等。整體涵蓋一系列真實職場工作流：以試算表為中心的規劃、OCR 與 PDF 擷取、辦公文件編輯、合規分析、量化推理等。

2.2 領域無關執行流程（DAEF）

SkillFlow 的核心設計原則是 DAEF：一族任務在移除領域專屬實體、檔名與商業語意後共享的工作流骨架。形式化地，任務實例表示為領域接地的工作流圖 𝒯=(V,E,λ,γ)，其中 V 是可執行子目標/操作的集合，E⊆V×V 是優先序/依賴邊，λ(v) 為每個節點指定領域無關的操作類型，γ(v) 提供任務專屬的接地（如具體檔案、實體、欄位、商業物件）。DAEF 即移除任務專屬接地、保留操作類型與依賴結構後得到的抽象工作流圖：ℱ=φ(𝒯)=(V_F,E_F,λ_F)。不同任務可具象化出同一個抽象工作流，藉此支持跨領域的技能遷移評測。

操作化 DAEF：透過兩階段人工標註與標準化協定，使抽取過程顯式、標準化且可驗證。階段一（meta-step 抽取）：每個種子任務被獨立標註成 5–8 個可執行操作的 meta-step 節點序列、依賴邊，附短文字理由；節點類型取自受控的單詞詞彙（如 read、retrieve、compute、detect、output）。階段二（工作流建構）：抽取出的工作流表徵被正規化——摺疊任務專屬接地、標準化節點標籤、只保留跨任務穩定的依賴結構與操作清單；正規化後的 DAEF 也界定了允許的變化類別，以控制後續具象化任務的難度梯度。DAEF 只在內部一致、能支持受控泛化到新任務（且不引入新工作流）時才保留。

2.3 任務建構協定

分四步：

步驟 1（種子任務蒐集與技能整理）：從兩個 benchmark 套件識別種子任務，保留反映真實職場情境、不需外部網路服務的高品質範例，排除過窄、過簡或難以可靠驗證的任務，得 64 個種子任務（SkillsBench 18 個、GDPval 46 個）。同時從公開儲存庫蒐集超過 8000 個開源技能，經安全性、格式、領域相關性過濾後得 2318 個用於任務建構的技能。

步驟 2（任務–技能配對）：用 Qwen3-embedding-4B 計算任務與技能描述間的語意相似度，為每個種子檢索 5–10 個候選技能，得 64 組任務–技能配對。

步驟 3（迭代式家族泛化）：人工標註者依前述協定把每個種子轉成 DAEF（抽取 meta-step、定義工作流），去重與泛化難度檢查後保留 30 個 DAEF；由此構成的種子任務參照套件（原始資產、配對技能、檔案、環境、穩定 DAEF）進入自動化建構迴圈——若五輪修訂內未達執行穩定性或 DAEF 一致性，該種子即被捨棄。(a) Architect Agent：在 Cursor 中以 GPT-5.3-Codex 實作，依目標 DAEF、以原種子任務為參照，提出新任務類型、建構任務目標、任務資產與驗證方案，並在配對技能協助下建構對應的 Docker 任務環境與求解器/驗證器資產，產出四個 Harbor 格式的初始任務。(b) Critic Agent：以 Claude Opus 4.6 實作，在真實 Docker 環境中驗證與評估這四個初始任務，綜合評估工作流一致性、難度梯度、任務可解性、驗證器正確性與環境可靠性後給出詳細回饋。(c) 修訂迴圈與擴增階段：兩代理互動多輪直到 Critic Agent 核准該家族（超過五次拒絕則放棄該家族）；通過後進入第二輪建構，沿用同一迴圈再產出 4–5 個新任務。兩輪流程使每個家族產出 8–9 個任務序列，最終得 20 個任務家族。

步驟 4（人工複審與家族修訂）：人工複審者從指令洩漏、任務邏輯健全性、最終任務環境正確性、難度梯度合理性四個維度審視每個候選家族，任一維度有問題即退回人工修訂。得益於前述步驟的嚴格構造流程，20 個任務家族均未出現致命環境錯誤，全數在人工修訂後保留。最終管線產出 20 個工作流家族、166 個任務。

2.4 Agentic Lifelong Learning 協定

把終身學習協定形式化為一族任務上的序列過程：ℱ={T₁,T₂,…,Tₙ} 為依家族內難度排序的任務序列，智能體在每個時刻 t 維護一個可更新的技能庫 𝒮_t。第一題執行與回饋：對 T₁，智能體不使用任何技能、在其原生 agent harness 下完成任務，產生執行軌跡 τ₁；完成後模型收到驗證器導出的 rubric r₁（缺失/錯誤內容的正規化文字描述）。技能補丁生成：每題後，模型從軌跡與驗證器回饋中學習，依固定的技能補丁 prompt 模板 g 生成補丁；此步驟依賴模型自身能力，而非其所在的 agent harness。第一題：Δ₁=Model_g(∅,τ₁,r₁)，𝒮₁=Apply(Δ₁,∅)（從零引導技能庫）。之後每題 t>1：智能體用當前庫 𝒮_{t-1} 執行 T_t，得軌跡 τ_t 與 rubric r_t，再以相同的提示生成過程增量更新：Δ_t=Model_g(𝒮_{t-1},τ_t,r_t)，𝒮_t=Apply(Δ_t,𝒮_{t-1})。補丁 Δ_t 可新增、修訂或刪除技能；此增量更新方式保留技能演化史，避免每次從頭重生整個技能庫。家族重置：此設計對應 SkillFlow 的目標——評測單一類別任務內的終身學習，而非智能體跨異質工作流精準套用技能的能力；把不同工作流的任務交錯在同一評測流中會引入不必要的系統雜訊（包含技能檢索機制帶來的混淆因素）。

技能補丁 schema：使用最小化、可審計的技能演化介面，避免複雜的指令遵循效應干擾評測公平性。技能補丁生成依賴模型自身能力，與執行任務所用的 agent harness 解耦。g 為固定的補丁生成 prompt 模板（詳見附錄 B.2）。每個補丁含三欄位：summary、upsert_files、delete_paths，合起來足以記錄高階教訓、建立或覆寫 SKILL.md 與輔助腳本、刪除過時的資產。生成的技能遵循前述標準技能結構。此檔案層級介面保留補丁歷史、支持隨時間追蹤更新，並讓「技能庫失控成長（冗餘或低價值資產累積）」等失敗模式可被直接檢視。

技能使用偵測：每個任務都在其原生 agent harness 的規劃策略下完成；由於這些 harness 已原生支援技能，模型可自行選擇是否使用技能，無需額外控制機制。作者只擷取任務完成結果與技能庫檔案相關的執行軌跡事件（如技能讀取或呼叫）來偵測技能使用並計算技能重用率。此協定不只評測智能體能否從靜態外部記憶中受益，也評測它能否隨時間持續維護、修復並改進一個可重用的技能庫。

2.5 指標

三組指標：任務成功率（最終輸出是否通過任務驗證器）；效率（每任務執行成本，以互動輪數、美元成本、輸出 token 數呈現）；技能生成與重用（家族內最終保留的技能平均數量，以及先前存入的技能在後續任務中被重用的比率）。
