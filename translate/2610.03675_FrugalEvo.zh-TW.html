論文／訪談原始來源

FrugalEvo：邁向成本感知的 LLM 引導程式演化

摘要

以 LLM 引導的演化方法已能處理圓形填裝等困難的計算最佳化問題，但過往通常關注固定迭代次數後的效能。本研究主張，實際最佳化應關注每單位成本帶來的收益。

FrugalEvo 由較強、較昂貴的模型探索解題策略，再由便宜模型實作並反覆精煉程式；同時設計能增加共享前綴的提示與執行流程，以重用快取。作者另提出預算感知曲線下面積（Budget-Aware Area Under the Curve，BA-AUC），衡量固定 LLM 成本預算內，累積成本對目前最佳分數曲線的面積。（摘要）

作者自報，在數學與系統最佳化共 10 項任務中，最終解答品質可與主要基線相當或更好，且在 9 項有較高 BA-AUC；另在 10 項 ALE-Bench-Lite 演算法任務取得最高平均表現。（摘要；細部配置與例外見第 3 節及譯註）

第 1 節：從每次迭代收益改看每單位成本

典型程式演化維持高品質解答池，反覆挑選父程式、讓 LLM 提出變異，再由評估器測試。若只按候選數或評估次數畫進步曲線，容易忽略不同方法的實際支出；較好的分數也可能只是花費更多。

實際成本可包含 LLM API 費或推論 GPU 成本、評估器 CPU 成本，以及任務本身的 CPU／GPU 資源。作者認為，這類計算最佳化中的 LLM 推論常占主要搜尋成本，因此本文集中改善 LLM 推論的成本效率，以固定 LLM 成本預算評估品質。作者的模型分工不需額外訓練模型；快取設計則利用支援提示快取的 API，重用相同前綴的 KV 狀態。（§1、§4）

譯註：列出廣義成本不等於實驗全部納入。本文預算及 BA-AUC 的橫軸是 LLM 美元成本，不能翻成固定總算力、固定牆鐘時間或端到端全部成本。

第 2.1 節：問題形式化與 BA-AUC

令 x 為候選程式，評估器回傳 E(x)=(s(x),a(x))，其中 s 是要最大化的任務分數，a 是輔助回饋。起始程式經評估後建立資料庫；搜尋策略從資料庫組合任務分析、父程式、參考程式、評分及歷史摘要，作為 LLM 產生下一候選的脈絡。新候選及評估結果再存回資料庫。目標是固定預算 B 內找到最高分程式。（§2.1，式 1–3）

令 q(c) 表示累積 LLM 成本為 c 時已找到的最佳分數，作者定義：

\[\operatorname{BA\text{-}AUC}(B)=\int_0^B q(c)\,\mathrm{d}c.\]

為讓方法都在相同成本區間比較，提前結束的 run 將目前最佳分數持平延伸至 B；超出預算的 run 則在 B 截斷。（§2.1，式 4）

譯註：不要補上原文沒寫的正規化。 上式沒有除以 B，也沒有扣掉起始分數。表 1 的圓形填裝原始分數約 2.636，BA-AUC@2 卻約 1.99，不能直接把表中半徑總和當作 q(c) 重算。另有越低越好的原始指標，而形式化定義統一最大化；所提供全文未明示完整分數轉換。本文照錄定義與表值，保留缺口，不猜測正規化或倒數。比較面積時應限於同任務、同預算及同尺度。（§2.1；表 1–2；附錄 B；最後一句為譯者判讀）

第 2.2 節：方法流程

冷啟動與脈絡建立

弱起始程式可能讓昂貴模型產生品質不足的策略。因此先由低成本模型反覆改善起始程式，直到評分不再進步，把所得最佳程式當作目前最佳解（incumbent）。

脈絡建立器使用高成本模型分析題目與評估器程式，找出最佳化目標及限制，再合併目前最佳解、評分回饋與搜尋記憶。搜尋進行時，持續加入近期最佳程式、嘗試過的策略、候選及評估結果。（§2.2）

快取友善的提示

為降低輸入 token 成本，提示把共同內容放在最前：固定任務說明及輸出要求先出現；較少變動的例子放在後面，其中島嶼最佳解與菁英程式排在隨機抽樣程式之前；最常變動的內容排在最後。每次嘗試的回饋附加於尾端，以增加連續呼叫之間的共享前綴。（§2.2）

譯註：這項機制以 API 支援相同前綴快取且實際命中為前提，不是任意提示都免費，也不是把評估器執行快取掉。主文沒有提供命中率、快取獨立消融或可歸因於快取的節費比例；附錄 C 的快取價目不等於實測命中帳。（§2.2、§3.3；附錄 C）

策略探索、實作與精煉

高成本模型一次提出多個不同策略，每項策略須說明如何改父程式、為何有望改善，以及必須遵守的運算限制。

低成本模型先為各策略產生試作，依評估分數排名，再依排名精煉。每輪固定策略與目前最佳父程式，最多進行 M 次循序嘗試；失敗回饋會影響下一次提示，但父程式不變。一旦某次嘗試改善目前最佳解，即結束本輪，更新父程式，再以相同策略開下一輪。若整輪沒有改善，才改用下一策略。（§2.2）

評估器與搜尋記憶

評估器使用各任務專屬評分函式。搜尋記憶以島嶼式 MAP-Elites 維持程式多樣性，保存候選、評估結果、策略及失敗回饋。剩餘預算不足支付後續 LLM 呼叫時，停止搜尋並回傳找到的最佳程式。（§2.2）

解答分析與圓形填裝成本

作者自報，圓形填裝由初始半徑總和 0.95976 改善至 GPT 的 2.635996，花費 $1.68；GLM 達 2.635990，花費 $0.55。對照文獻中的 CORAL／SwarmResearch 約花 $50，分別達 2.635985／2.635996。（§3.2，圖 3）

作者的解法使用帶非對稱位移的五列布局，以受限 SLSQP 與固定圓心的半徑線性規劃改善，再在評估器容差內微增半徑。Signal Processing 則自適應混合 Savitzky–Golay、Butterworth 及頻譜濾波，抑制輕微方向反轉；Heilbronn Convex 結合多起點爬山、線性規劃精煉與凸包面積縮減。（§3.2）

譯註：圓形填裝的末位數值須連同容差理解；達到評估器認可的高分，不等於提供嚴格幾何最優證明。引用方法的費用也不能換算成端到端或固定算力節省。

演算法任務與成本曲線

所有方法從 ALE-Agent 提供的解答出發，用 private score 評估。作者自報，在 GPT 配置、$1 預算下，FrugalEvo 的跨任務平均為 1924.9，高於 OpenEvolve 的 1887.5 與 AdaEvolve 的 1881.9；圖 4 未表示每一題都領先。（§3.2，圖 4；末句為譯者辨析）

AHC016 的解法使用互不相交的團及其補圖，依排序後的頂點鄰居數與噪音調整期望分類；AHC027 則依髒污累積速率、距上次拜訪時間及移動距離規畫清潔路線。（§3.2）

作者展示 Signal Processing、Heilbronn Convex 及 Transaction Scheduling 的目前最佳分數對成本曲線，報告在前 $0.2 內即取得優勢並延續至後續搜尋。圖 5 上排是三次 run 平均，下排是各方法最佳 run，不應混用。（§3.2，圖 5）

第 4 節：相關研究

FunSearch 將 LLM 生成與自動評估結合；AlphaEvolve 將演化範圍擴及較大程式。OpenEvolve、CodeEvolve 提供開源框架；ShinkaEvolve 關注樣本效率；ThetaEvolve、TTT-Discover 在測試時改善生成模型；AdaEvolve、EvoX 調整搜尋流程；CORAL、SwarmResearch 協調多個編碼代理。作者以「每單位成本」而非固定迭代收益作為本文定位。（§4）

成本效率相關研究涵蓋模型串接、路由、反思與快取。FrugalGPT 以模型串接平衡準確率與成本，RouteLLM 學習強弱模型間的路由；SimpleTES 後訓練模型以處理長程探索，Squeeze Evolve 使用模型自身信心訊號。FrugalEvo 按任務步驟分配模型能力，不額外訓練模型，也不需 token 層級機率。（§4）

第 5 節與研究聲明：結論、限制與責任

作者結論是，強模型探索與便宜模型實作配合快取友善流程，能在固定 LLM 成本預算下改善程式最佳化；BA-AUC 補充僅看最終分數的評估。（§5）

限制在於，方法專為生成及評估都能在程式環境中完成的任務設計，不能直接延伸到需要濕實驗的生物學等領域。策略探索指令由人工設計，尚未從各題自動導出；未來方向是實體世界互動及自動產生策略指令。（§5）

AI Use Statement 說明作者以 LLM 協助寫作、實作與執行實驗，但研究構想、實驗設計、分析及科學主張由人類作者負責。Ethics Statement 指出生成解答雖通過任務評估器，未經人類專家驗證，只供研究參考。Reproducibility Statement 承諾發表時公開程式、資料與補充材料；本譯文不另行查證實際公開狀態。

附錄 D：提示的主要要求

策略探索提示要求每個方案提供機制類別、替換範圍、額外計算限制及增益機制。策略應是不同機制，不是只改種子、容差或迭代次數；方案必須自足、可實作，維持公開介面與有效性限制，不依賴不存在的工具、捏造資料或未指定的未來最佳化。結尾須提供同尺度的分數估計，或連到新機制的可測假設；「不變好就退回原解」本身不是改善證據。依要求可另輸出獨立參考程式。（附錄 D）

實作提示要求忠實執行策略，安全移除被替代程式，不可只作表面修改或再疊上一整套無關流程；新機制必須進入正常回傳路徑。試作先建立能運作的最小版本，後續依評分與錯誤修正；超時應縮減工作量但保留增益機制。搜尋／取代區塊須精確且唯一匹配目前父程式，先前失敗嘗試不能取代父程式；若修復指定失敗程式，應回傳完整一致的修正版。（附錄 D）
