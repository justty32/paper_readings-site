3. 用 LLM 做自然語言程式合成

考慮一個由「輸入/輸出示範資料集」指定的任務與一個受提示的模型。自然語言程式合成的目標是找到單一指令，使模型在被「指令＋給定輸入」串接後提示時，能產生對應輸出。形式上化為最佳化問題：尋找能最大化「某逐樣本分數在可能的輸入/輸出上之期望」的指令（式 1）。註：指令一般也可為空字串，即把指令直接當作能產出輸出的 prompt 來優化。由於我們對「某指令與模型有多相容」所知甚少，我們把這個人類難解的問題當成由 LLM 引導的黑箱最佳化。

APE 在兩個關鍵組件都用 LLM：提案（proposal）與評分（scoring）。如 Algorithm 1，APE 先提出若干候選 prompt，再依選定分數函式過濾/精修候選集，最終選出最高分指令。

Algorithm 1（APE）概要：輸入訓練樣本與分數函式；(1) 用 LLM 取樣一批指令提案；(2) while 未收斂：選一隨機訓練子集、對每個候選在子集上評分、過濾出高分前 k%、更新指令或用 LLM 重採樣；最後回傳最高分指令。

3.1 初始提案分佈

因搜尋空間無限大，直接找對指令極難，這也是自然語言程式合成過去難解的原因。但近期 NLP 顯示語言模型很擅長生成多樣文本，故我們用預訓練 LLM 提出一組良好候選解來引導搜尋——不是隨機取樣（不太可能產生想要的輸入/輸出對），而是要 LLM 在給定輸入/輸出示範下，近似推論出高分的最可能指令。

Forward Mode（前向）生成：把提案分佈「翻成文字」，例如在 Instruction Induction 實驗中依 Honovich 等的做法、以圖 2（上）的模板提示 LLM。

Reverse Mode（反向）生成：forward 模型雖多數預訓練 LLM 開箱即用，但把分佈翻成文字需跨任務客製，因為指令通常在段落開頭、而 forward 模型只能由左至右生成（迫使指令被預測在 prompt 結尾）。為求更彈性、讓指令可置於文中任意位置，我們採用具 infilling（填空）能力的 LLM（如 T5、GLM、InsertGPT）來推論缺漏的指令，直接以「填空」取樣（圖 2 中）。

客製提示：依所用分數函式，或有比上述更合適的提示。例如 TruthfulQA 實驗中，我們從原資料集的人寫指令出發，要 reverse 模型提出「能吻合缺漏脈絡」的初始指令樣本（圖 2 下）。

3.2 分數函式

為把問題化為黑箱最佳化，需選能準確衡量「資料集與模型生成資料之對齊程度」的分數函式。Instruction Induction 實驗考慮兩種：

  • 執行準確率（Execution accuracy）：採 Honovich 等提出的度量，多數情況即 0-1 loss；某些任務會考慮不變性（如順序不變的集合匹配損失）。
  • 對數機率（Log probability）：較「軟」的機率式分數——在目標模型下、給定指令與問題時「期望答案的對數機率」。我們假設它在搜尋低品質候選時能提供更細緻的訊號。

高效分數估計：對所有候選都在整個訓練集上算分很貴。我們採多階段過濾：先用訓練集的一小子集評估所有候選；對分數高於門檻者，再抽一個不重疊的新子集評估、更新分數的移動平均；重複直到只剩少數候選，才在整個訓練集上評估。此自適應過濾把精確算力留給高品質樣本、大幅削減低品質候選的算力。

3.3 迭代式提案分佈

即使力求直接取樣到高品質初始候選，3.1 的方法仍可能因缺乏多樣性、或未含足夠高分候選而失敗。此時我們探索重採樣的迭代過程。

迭代 Monte Carlo 搜尋（iterative APE）：不只從初始提案取樣，而是在當前最佳候選附近局部探索。每階段評估一組指令、過濾掉低分者，再要 LLM 生成與高分指令相似的新指令（重採樣提示見圖 3）。圖 6（右）顯示此法雖提升提案集整體品質，但最高分指令隨階段增加多半不變。我們因此認為迭代生成相對於 3.1 的簡潔有效性只帶來邊際改善，故預設不使用迭代搜尋（除非另行說明）。
