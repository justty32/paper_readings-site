4. 實驗

任務：自由形式問答（開放事實知識與多跳推理的真實性）、數學程式合成（生成程式的正確性與可執行性）、毒性降低（開放輸出空間的安全性）。兩種設定：CRITIC 對所有樣本套用修正；CRITIC* 為 oracle 設定，只修正錯誤樣本。模型：text-davinci-003、gpt-3.5-turbo（ChatGPT）、開源 LLaMA-2（7B/13B/70B），各 LLM 用相同 prompt。

4.1 自由形式問答

實作：不依賴任務特定檢索器（避免過擬合），改建基於 Google 的網頁搜尋工具：搜尋 LLM 生成的查詢、抓取 top-1 網頁、以模糊比對 Google 摘要截取最多 400 字元；最大互動次數 7。以 CoT 產生初始答案，最多修正 n=3 輪，答案連續兩輪不變即提前停止；驗證面向為合理性（plausibility）與真實性（truthfulness）；全程貪婪解碼。為解決 Google API 的時間不一致性，對網頁搜尋採快取機制確保穩定、公平與可重現。 資料集：AmbigNQ、TriviaQA、HotpotQA 各隨機抽 500 驗證例，報告 EM 與 F1。 基線：Vanilla few-shot、CoT、Self-Consistency、ReAct（用本文搜尋 API 重製、表現更好）、ReAct→CRITIC（對 ReAct 初始結果套 CRITIC）、CRITIC w/o Tool（移除搜尋 API、由 LLM 自行生成證據）、Rejection Sampling、各資料集的監督式 SoTA。 結果（表 1、表 8）：(1) CRITIC 在所有資料集、設定與 LLM 上大幅超越初始 CoT，只需三輪修正，且多數情況勝過 self-consistency。(2) 模型越強增益越大：CRITIC / CRITIC* 在 text-davinci-003 上 F1 提升 5.6 / 10.3，在 ChatGPT 上提升 7.7 / 12.4。(3) 結合參數化知識與外部回饋的 CRITIC 顯著優於只靠檢索的 ReAct（兩 LLM 平均 F1 各 +5.1、+8.2），且多數情況勝過 ReAct→CRITIC。(4) 工具互動是關鍵：模型自己的批判貢獻甚微（兩 LLM 各 −0.03 與 +2.33 F1），甚至不如初始輸出。(5) CRITIC 亦能進一步強化檢索式結果。(6) 附錄 E 展示 CRITIC 能修正不實事實、矯正錯誤推理軌跡、偵測過時知識。

表 1 擇要（ChatGPT，F1）：

方法 AmbigNQ TriviaQA HotpotQA
CoT 64.3 79.2 42.8
Self-Consistency 65.4 81.3 47.0
ReAct 64.8 69.8 50.2
CRITIC 74.9 81.7 52.9
CRITIC w/o Tool 67.3 79.9 46.1

4.2 數學程式合成

實作：以 Python 直譯器為工具，取得兩類回饋——錯誤訊息（如 NameError、Time out，表示為「Execution: {error message}」）與執行結果（執行後變數 answer 的值）。以 program-of-thought（PoT）生成初始程式，最多 n=4 輪修正，執行結果連續兩輪不變即停止；初始結果貪婪解碼、修正時以 p=0.5 取樣避免迴圈。 資料集：GSM8k、SVAMP、TabMWP 官方測試集，報告 exact match。 結果（表 2、9、10）：(1) CRITIC 在兩種修正策略（全修 / 只修錯的 oracle）下均明顯優於 PoT。(2) 模型越強效果越好。(3) 擴展性佳：TabMWP 上 LLaMA-2 7B/13B/70B 的增益分別 +4.7、+9.4、+16.0。(4) 沒有直譯器執行回饋時，LLM 修正程式的能力有限且不穩定：text-davinci-003 上出現 −1.8 的劣化；Codex 上的 Self-Refine 更因 LLM 對程式正確性的回饋不可靠而劣化（PAL 71.3 → Self-Refine 26.7，−44.6）。

表 2 擇要（ChatGPT，solve rate）：

方法 GSM8k SVAMP TabMWP
PoT 72.5 82.0 75.0
CRITIC 78.2 (+5.7) 83.3 (+1.3) 89.0 (+14.0)
CRITIC w/o Tool 77.0 (+4.5) 82.0 (+0.0) 87.0 (+12.0)
CRITIC*（oracle） 83.9 (+11.4) 89.0 (+7.0) 94.0 (+19.0)

4.3 毒性降低

實作：以 Perspective API 為工具取得細粒度毒性資訊（整體毒性分數＋侮辱、褻瀆、身分攻擊等六種屬性分數），取最高分屬性表示為批判「The text has {score} toxicity of {attribute}」。最多迭代 n=4，整體毒性低於 10% 即終止；nucleus sampling p=0.9。 資料集：RealToxicityPrompts 非毒性 prompt 隨機抽 1k，度量 25 次生成的最大毒性與毒性機率（≥50% 至少一次），以 text-davinci-003 計算流暢度 perplexity，另報 dist-2/dist-3 多樣性。 結果（表 3）：(1) CRITIC 大幅降低毒性生成、同時保持與原始 LLM 相當的流暢度與多樣性（ChatGPT 最大毒性 0.325→0.173、毒性機率 0.192→0.040）；(2) 無需額外資料或訓練即達到與監督式 SoTA（PPO、Quark、Self-Correct 等）相當的減毒能力；(3) 再次凸顯外部回饋的重要性——僅靠 LLM 自身難以有效減毒（w/o Tool 幾乎無改善：0.325→0.339）。

4.4 額外消融與分析

  • 迭代修正的效果：迭代通常帶來持續改進，oracle 設定（只修錯的）躍升顯著；多輪修正邊際效益遞減，通常 2–3 輪就取得多數增益；缺乏可靠回饋時，只靠模型自身迭代改進的報酬較差且低效。
  • 與 Rejection Sampling 比較：CRITIC* 對比 best-of-n 拒絕採樣（重新生成 n 條 CoT 取最高分者），在兩個 LLM 上 EM 各高出 4.5 與 3.3——顯示批判不只指認錯誤，還提供可行動建議與可信依據，引導新生成避免相似錯誤。

5. 結論

CRITIC 是即插即用（plug-and-play）框架，讓凍結的 LLM 藉與外部環境互動自我驗證與自我修正，無需進一步訓練。跨任務跨模型的實驗一致顯示其有效性、通用性與可互操作性。此外，本文揭示 LLM 自我驗證的不可靠性，凸顯外部工具互動解決此問題的潛力。
