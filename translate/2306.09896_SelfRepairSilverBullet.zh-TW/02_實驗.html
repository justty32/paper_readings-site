4. 實驗

研究問題：(a) 在 Python 程式謎題上，自我修復是否勝過無修復的 i.i.d. 取樣？若是，何種超參數下最有效？(b) 更強的回饋模型能否提升修復表現？(c) 讓人類進迴圈提供回饋，能否連最強模型都解放更好的修復表現？

設定：評估三個模型——GPT-3.5、GPT-4（凍結端點 gpt-3.5-turbo-0301、gpt-4-0314）與可在消費級硬體本地執行的 CodeLlama-13b-instruct；資料集為 APPS 與 HumanEval。每個資料集各取一個「baseline 較強」與一個「較弱」的模型（HumanEval：GPT-3.5 強、Code Llama 弱；APPS：GPT-4 強、GPT-3.5 弱）。APPS 為求可行只評 300 題（依難度比例抽樣：180 面試級、60 競賽級、60 入門級）。以樣板字串串接 + one-shot 提示實作，解碼溫度 0.8。baseline（圖中黑線）即同模型的純 i.i.d. 取樣。

4.1 自我修復不是萬靈丹，但靠「多樣初始樣本」可改善

此小節設 M_P = M_F（真自修復），在 (n_p, n_fr) ∈ {1,2,5,10,25}×{1,3,5,10} 範圍內變動。

  • APPS：GPT-3.5 僅在最大 n_p 時見微幅增益；GPT-4 增益較明顯，最多勝 baseline 8%。按難度拆解（附錄 C）發現越難的題增益越大：GPT-3.5 在競賽級題最多得 34% 相對增益。
  • HumanEval：Code Llama 增益與「GPT-4 於 APPS」相仿（最多 10%）；GPT-3.5 因逼近天花板增益有限（最多 3%）。
  • 結論：自我修復並非總是最佳策略（尤其小預算時），且難以預測何時有效。分析發現：強模型在簡單任務修復成功率高，但簡單任務靠「重抽」得到正確程式的機率也高——生碼成功率與修復成功率同漲同跌，眾多未知的微妙因素決定何者勝出。
  • 清楚的超參數趨勢：固定 n_fr、增加 n_p（更多初始程式）對所有模型都穩定帶來相對增益；反之固定 n_p、增加 n_fr（更多修復）不值得——高預算時僅微幅、低預算時甚至掉分。在固定預算下，決定成敗的關鍵是「初始樣本的多樣性」而非「修復的多樣性」——多抽初始程式提高「至少有一支接近理想解、因而可被成功修復」的機率。故 n_fr=1 為整體最佳；作者再以 (n_p,1)、n_p∈{1..25} 密集掃描：HumanEval 上 Code Llama 與 GPT-3.5 都有增益；APPS 上僅 GPT-4 明顯獲益，Code Llama 與 GPT-3.5 多半打平或落後；所有情況下小預算增益極微或不存在，隨預算增大才略增。

4.2 提升回饋品質可解放修復增益

此實驗檢驗「自我修復受限於模型自省／自我除錯能力」的假說：把 M_P 設為較弱模型、M_F 設為較強模型（Code Llama 配 GPT-3.5 或 GPT-4；GPT-3.5 配 GPT-4），在 (n_p,n_f,n_r)∈{1..25}×{1}×{1} 掃描。結果一致：APPS 上 Code Llama 與 GPT-3.5 現在同時打敗各自的 baseline 與各自的自修復模式；HumanEval 上 Code Llama 的增益隨回饋模型越強而越大（尤其 GPT-4 回饋）。這說明文字回饋階段本身至關重要，改善它即解除自修復的瓶頸。

4.3 人類回饋顯著提升 GPT-4 的修復成功率

最後檢驗「用專家人類程式員的回饋去修復強模型（GPT-4）」的效果（目的不是比較「人在迴圈 vs 自修復」的整體成本，而是深究回饋品質如何影響下游修復）。

  • 資料蒐集：招募 16 名參與者，為 40 支「GPT-4 生成且失敗」的程式各蒐集 2 份人寫回饋（每支給兩人看以降變異）；每人約花一小時、酬 $15 禮券；經 IRB 核可。

  • 量化結果（表 1）：對每組（回饋， 程式）從 GPT-4 抽 25 個修復候選並跑測試。用人類回饋替換 GPT-4 自產回饋，整體修復成功率提升 1.58×（33.30% → 52.60%）；且題目越難、差距越大：

    難度 GPT-4 回饋 人類回饋
    入門 Introductory 42.64% 62.21%
    面試 Interview 19.33% 45.67%
    競賽 Competition 3.67% 14.67%
    整體 Overall 33.30% 52.60%

  • 質化分析：GPT-4 回饋明顯更常出錯（不準確 32/80 vs 人類 7/80）；GPT-4 較常建議「小改動」，人類較常提出「高階、大規模改寫」；人類會表達不確定（7/80），GPT-4 從不（0/80）。故表 1 的差距並非「人類直接給程式碼讓模型照抄」的假象，而是源於更準確的回饋 + 需要時提出高階改寫的能力 + 敢於表達不確定（而非自信地給出可能錯誤的回饋）。

5. 局限

  • 為省算力而「先建一棵大修復樹、再子取樣自舉」，有引入統計假象之虞；作者以「把 n_p、n_fr 遠壓在 N_p、N_f 之下」與「實驗中標準差極小」來降低此風險。
  • 實驗僅限帶可執行單元測試的自足式 Python 任務，與真實軟體開發差異大（規格常不完整、有長距上下文依賴、每個片段未必有測試）。未來需研究自修復在該處的角色——例如能否解決規格歧義，或搭配自動單元測試合成（CodeT 等）與測試驅動開發（TDD）以彌補缺測試之困。
  • 人類研究未記錄參與者的除錯耗時，故只能評回饋品質而非人力成本；何時、如何引入人類介入，需 HCI × AI × 程式合成的進一步研究。

6. 結論

我們研究了 Code Llama、GPT-3.5、GPT-4 於 HumanEval／APPS 的自我修復，發現：(1) 計入修復成本後，增益往往微薄、在資料集之間與內部都差異大、且仰賴初始程式的足夠多樣性；(2) 把弱模型的自產回饋換成強模型的回饋能顯著提升表現；(3) 把 GPT-4 自產回饋換成資深程式員的回饋，使通過全部測試的修復程式增加 1.58×。結論：自我修復並非程式碼生成的萬靈丹，當前模型的瓶頸在於「無法可靠地產出關於程式碼為何出錯的準確而有用的回饋」。

附錄要旨

  • 附錄 A（pass@t）：以「達到某通過率所需的 token 數」為成本，分 batched（批次並行，模擬無人介入的大規模部署）與 sequential（深度優先搜尋，模擬使用者與聊天式助手互動）兩策略。整體趨勢與正文一致；但在 sequential 設定下自修復更不划算，尤其 baseline 通過率本已高時。
  • 附錄 C（難度 × 修復）：GPT-3.5／GPT-4 越難的題越受益於自修復，Code Llama 則相反。表 2「修復成功率」（入門級）：Code Llama 2.8%、Code Llama+GPT-3.5 5.4%、GPT-3.5 13.7%、GPT-3.5+GPT-4 29.1%、GPT-4 28.8%——用 GPT-4 當 GPT-3.5 的回饋來源，修復成功率追平甚至略勝純 GPT-4，再證回饋品質才是瓶頸。作者推測增益不隨 baseline 表現完美同步，是因（a）回饋／修復成功率（利自修復）與生碼成功率（利 i.i.d.）的拉鋸、（b）自然語言規格的歧義、（c）單元測試的資訊量三者交互所致。
