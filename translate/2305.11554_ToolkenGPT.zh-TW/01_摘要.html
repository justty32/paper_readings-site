摘要

以外部工具增強大型語言模型（large language models, LLM）已成為解決複雜問題的有力途徑。但傳統做法——用工具示範資料**微調（fine-tune）LLM——既昂貴又受限於預先定義好的工具集合。近期的脈絡內學習（in-context learning）**範式緩解了這些問題，但有限的 context 長度只容得下少量 few-shot 示範，導致對工具的理解不佳；而當可選工具眾多時，in-context learning 可能完全失效。本文提出替代方案 ToolkenGPT，兼取兩派之長：我們把每個工具表示為一個 token（稱 "toolken"）並為它學一個 embedding，使得「呼叫工具」與「生成一個普通字詞 token」的方式完全相同。一旦某個 toolken 被觸發，就提示 LLM 去補齊該工具的參數並執行。ToolkenGPT 可透過即時擴充 toolken 集合，靈活地插入任意數量的工具；並能用大量示範資料來學習 toolken embedding，從而改善工具使用。在數值推理、知識庫問答、具身規劃等多元領域，本方法都能有效地為 LLM 接上工具，並大幅勝過多種最新 baseline，展現在複雜情境下從龐大工具集中挑用相關工具的潛力。

1. 引言

LLM 已是各種真實應用的利器，人們日益關注其「與真實世界互動、透過整合外部工具（計算機、資料庫等）擴充功能」的潛力。掌控大量工具不僅是智能的指標，也是克服 LLM 若干根本弱點的希望之路：更新最新世界知識、減少幻覺（hallucination）、執行符號運算等。而新工具（進階軟體庫、新 API、領域專用工具）快速湧現，更凸顯「讓 LLM 能迅速適應並掌握海量新工具」的重要性。

現有工具整合有兩條主線（見表 1）：（1）微調 LLM 學特定工具——例如把檢索器整合進 LLM 的一系列工作，以及 Toolformer 微調 GPT-J 學 5 種工具；此法有效但計算昂貴、且缺乏對新工具的適應力。（2）in-context learning——在 prompt 中給工具描述與示範讓 LLM 學用工具，催生了 LangChain、ChatGPT Plugin 等；但受 context 長度本質限制，無法在脈絡中示範海量工具，且僅靠 few-shot 就掌握新工具很難（即便 GPT-4 面對不尋常工具也吃力）。

表 1（工具學習範式對比）：四個維度——凍結 LM／海量工具／即插即用（Plug-&-Play，可靈活裝卸工具，但不等於 zero-shot）／能吃大量資料。微調：✗/✗/✗/✓；in-context learning：✓/✗/✓/✗；ToolkenGPT：✓/✓/✓/✓（四項全中）。

本文提出 ToolkenGPT，無須任何 LLM 微調即讓 LLM 掌握海量工具、又能快速適應新工具。核心想法：把每個工具表示為一個新 token（toolken）以擴充詞彙表；每個工具對應一個 embedding，插入 LLM head，如同一般詞 token 的 embedding。生成過程中一旦預測到某 toolken，LLM 便暫時（透過提示）切換到特殊模式產生工具的輸入參數並執行，再把輸出注回生成流。此法只需學習輕量的 toolken embedding，即結合微調與 in-context learning 之長而避其短。

我們在數值推理、知識庫問答、具身智能體規劃三類問題上驗證其靈活與有效：複雜數值推理中，ToolkenGPT 有效運用多個數學工具，勝過 CoT、ReAct；知識庫問答中可容納 200 多個關係 API 以做事實預測；具身規劃中為 58 個接地（grounded）動作與物件學 toolken embedding，接地效果優於既有 in-context learning 與專門的解碼方法。

2. 相關工作

微調 LLM 用工具：早期多靠微調讓 LM 在特定領域學一兩種工具，如檢索增強的 REALM、RAG、RETRO；WebGPT 微調 GPT-3 學用瀏覽器；TALM、Toolformer 則調整模型學一組通用工具（QA 模型、計算機、翻譯器等）。但微調昂貴、且調過的 LLM 難泛化到新／更新的工具。ToolkenGPT 為新工具學輕量 toolken embedding，不對 LLM 參數做任何梯度計算，適應新工具高效、訓練記憶體開銷極小（約等同 LLM 推理）。

工具的 in-context learning：靠 LLM 強大的脈絡內學習力，在 context 中給工具描述與示範即可用工具，並可疊加推理鏈（ReAct 等）處理更複雜問題，催生 ChatGPT plugins、LangChain，以及 code interpreter、具身智能體、多模態控制器等應用。但所有 in-context 方法在工具陌生或眾多的複雜情境下表現都差。一個同期工作（li2023api）以工具文件的文字 embedding 檢索工具或可緩解此問題，但 ToolkenGPT 根本不同：toolken embedding 能從大量示範中編碼工具的隱含語義，這是工具表面文字永遠推不出來的。ToolkenGPT 也相容 CoT 等進階提示技巧以再提升表現。

LLM 的高效調參（PEFT）：只微調少部分參數、凍結其餘，與本文 toolken embedding 有相似處，如 Adapters、BitFit、prompt tuning、prefix tuning、LoRA 等。但既有 PEFT 未被證實適合高效的工具學習，在工具示範上用這些方法未必能像 ToolkenGPT 這樣有效捕捉工具知識。就作者所知，本文是首個為「把工具當 token 預測」而探索高效調參、以學習海量工具的工作。
