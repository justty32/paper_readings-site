3 光譜揭露了什麼

透過壓縮鏡頭審視既有工作，揭露四個從任一社群內部單獨都看不見的結構性洞見。

3.1 光靠專門化並不足夠

有人會說記憶–技能的分工反映健康的專門化（記憶服務個人化、技能服務能力）。但光譜揭露兩社群各自獨立地重複解相同子問題（在成長中的知識庫上檢索、矛盾條目間的衝突偵測、陳舊辨識、下游效用評估）而不共享解法。此外真實部署兩者都需要：只會抽取可重用工作流卻忘掉使用者偏好的代理是殘缺的；記得 context 卻無法鞏固反覆模式的代理則會壓垮檢索預算。光譜使這些共同挑戰可見，暗示一個統一架構（層專屬壓縮器共用同一套檢索、衝突解決、生命週期基礎設施）能避免跨社群的重複工程。

3.2 評估方法與壓縮層緊耦合

L1 系統用 QA 指標（F1、exact match）評估、L2 用任務成功率、L3 無既定方法學。此耦合意味系統只為其層的指標最佳化，未必反映真實下游效用：MemSkill 有強 QA F1 但對多步任務完成的影響不明；EvoSkill 的任務成功率無法捕捉使用者特定 context。統一評估框架應以「知識產物對代理表現隨時間的下游影響」評估之，與壓縮層無關——一個捕捉「每 token 儲存知識價值」的效率指標。

3.3 可遷移性隨壓縮層上升

實證支持一種單調關係：L1 記憶可跨基礎模型遷移（MemSkill：LLaMA→Qwen）；L2 技能可跨任務（EvoSkill：SealQA→BrowseComp，+5.3%）與跨模型尺寸遷移（Trace2Skill：35B→122B，+57.7pp）。此關係可能是凹曲線，甜蜜點在 L2——平衡可遷移性與具體性。「固定來源經驗、只變壓縮層」的對照實驗尚未進行，但現有證據一致（表 1）。

3.4 生命週期管理仍是事後補丁

既有系統聚焦知識取得，把維護當次要。有些含部分機制（Mem0 的 LLM 驅動操作、Memory-R1 的 RL 學習更新、ExpeL 的重要性計數、AutoSkill 的版本管理）但彼此孤立。無系統處理完整生命週期：跨知識類型的衝突偵測、陳舊辨識、有原則的退役、跨層一致性。合併技能未必有益（納入成功軌跡訊號可造成 ±21pp 表現擺盪），代理行為在長時間運作下即使正確性維持仍可能退化。一份對技能庫漂移（skill-library drift）的診斷（Zhang et al., 2026c）顯示：若無「結果驅動的退役」與「有界的 active-cap」，自演化技能庫會退化到低於其無技能基線——將生命週期管理而非技能撰寫本身，孤立為故障根因。軟體工程社群的版本控制與退役實務，為知識產物提供了具體的遷移機會。

可證偽的預測：光譜產生區別於純分類法的預測：(i) 固定來源經驗時 L2 壓縮在跨域遷移上應勝 L1 檢索；(ii) 多層知識庫（L1+L2）應勝任一單層，且差距隨部署時長拉大；(iii) 可遷移性–具體性曲線應為凹形、L2 居甜蜜點；(iv) L3 規則以約束而非指令形式呈現時最有幫助（呼應 RuleShaping 早期證據）。驗證或推翻這些預測，可判定光譜究竟是有用的設計工具還是僅為描述性框架。

4 開放問題與設計原則

  • 問題 1：自適應選層。設計一個 meta-controller，給定新軌跡 𝒯 就決定最佳壓縮層 L*。agentic RL 綜述指出 RL 主要放大既有能力、真正新策略只在嚴苛條件下浮現——暗示壓縮的層級可能比演算法更重要。這需要一個 value-of-information 框架：𝒦_L 相對其計算與維護成本能提供多少未來效用？一個關鍵設計張力是「聯合優化 meta-controller 與層專屬壓縮器」還是「固定 meta-controller、只優化壓縮器」；對迭代生成式優化的分析顯示設計決策（起始產物、credit horizon、經驗批次化）常主導演算法選擇，暗示固定 meta 策略、只優化組件可能更實用。
  • 問題 2：跨層一致性。當知識同時存在多層（如關於同一行為的 L1 記憶與 L3 規則），系統如何偵測與解決不一致？與資料庫正規化的類比有啟發但不完整——知識產物是語義的而非關聯的。
  • 問題 3：有原則的生命週期管理。向軟體工程借鏡：知識產物的版本控制、層間依賴追蹤、退役協定、衝突解決。工作流優化綜述倡議「最小可塑性（minimum plasticity）」原則；一個類比的知識管理原則（唯證據充分時才升層）能在保留適應性的同時減輕維護負擔。
  • 其他方向：免獎勵壓縮（把 STaR、ReST 等自訓練法延伸到無乾淨獎勵訊號下引導多層壓縮）、跨域遷移協定（一次部署的 L2 技能能否 warm-start 另一次？）、擴展到多模態軌跡。

三條設計原則：

  1. 層無關壓縮核心（Level-agnostic compression core）：壓縮引擎應以「輸出層」參數化，而非寫死。DSPy 已示範宣告式規格可編譯成預設層的優化管線；層無關核心會將其一般化。
  2. 雙向升/降級：知識應向上流（記憶→技能→規則，當模式累積）也向下流（規則→技能→記憶，當 context 要求具體性）。
  3. 持續生命週期治理：每個知識產物都應攜帶 metadata（來源出處、信心、使用頻率、上次驗證時間）以支援有原則的維護。

光譜也暗示閒時鞏固（idle-time consolidation）：向上壓縮（L1→L2→L3）應在低活動期進行，類比睡眠時的海馬迴–新皮質鞏固。當前無系統實作此點；所有系統都在 ingestion 時同步壓縮。

具體「對角線」系統設想：三個組件。meta-controller 依新穎度與頻率把每條軌跡路由到一或多個層專屬壓縮器：首見模式停在 L1；累積 k 條相似 L1 條目後，升級引擎鞏固成 L2 技能；跨域再現後泛化成 L3 規則。升/降級引擎處理轉換：新升級的 L2 技能須先在留出任務上驗證才替換其來源 L1 條目；當技能反覆被檢索卻不被使用、或抽象規則在特定 context 失敗時觸發降級，退回重新蒐集 L1 證據。生命週期管理器追蹤每個產物的來源、使用頻率、上次驗證時間以支援有原則的退役。具體例：客服代理在 /api/export 遇 timeout，存一條 L1 記憶；五次類似後升級產生 L2 技能（Handle_Export_Timeout：檢查批次大小、>1000 列則縮小、重試）；跨端點數十次後泛化出 L3 規則（「資料密集端點的 timeout 通常源於批次過大」）；若規則在新 context 失敗則降回 L1 重啟蒐證。既有組件（MemSkill 的 RL 控制器做路由、EvoSkill 的 Pareto 選擇做升級、AutoSkill 的版本管理做生命週期）可作此架構的積木。

局限：本框架聚焦 scaffold 層知識，訓練時方法（RLHF、Constitutional AI）互補但不同。框架是概念性而非經實證驗證——其作為設計工具的效用尚待實驗確認。四離散層是簡化抽象；實務中壓縮可能連續（EvolveR 的策略橫跨 L2/L3）。本調查是 2026 Q1 快照，領域變動極快。雖聚焦文字代理，光譜自然延伸到多模態經驗（視覺觀察與跨模態互動放大各層高效壓縮的需求）。
