論文／訪談原始來源

自寫驗證在啟發式自我改進 agent 中不可靠

摘要與引言

自我改進 agent 常反覆改寫程序 policy、控制器或啟發式規則，並用自己寫的測試決定是否採用下一版。當同一個 agent 控制最佳化物件與 verifier，自評可接近滿分，真實部署卻可能停滯或倒退。本文把兩者的差距稱為 verifier–deployment gap，詢問少量外生信任能否阻止明顯退步被部署。

問題設定與資訊限制

第 t 輪已接受狀態是 policy 與自寫測試的組合；agent 讀到舊程式、自測結果及歷史回饋後，交出新的 policy 和 tests。新測試給出 agent 可見的 self-score；隱藏部署分布給出只作離線報告的 deployment truth。高 self-score 配低 deployment truth 即為 gap。

作者也給出條件式資訊限制：若退步和未退步在所有 agent 可見證據上的分布難以區分，任何只依內生證據的 gate 不可能同時維持低誤拒與低誤放行。這不是說內生訊號永遠無用，而是指出外生訊號必須增加與部署相關的可區分性。

SEAL：封存外生接受迴圈

SEAL 是部署前 gate，不是另一個 LLM 評審。固定的 harness 在隱藏樣本、隱藏 dynamics 上重複跑 incumbent 與 candidate；audit 集和最終 deployment evaluation 分開。令兩者 audit 分數為 b、c，容忍度為 max(δ_min, ρ|b|)；只有 c ≥ b - δ 才接受 candidate，否則完整保留舊 policy 與舊 tests。

設計有四個條件：audit 分布由系統固定、內容與分數不洩漏、對 agent 僅回 accept/reject、退步候選不進下一輪。作者的重點是阻止明確回歸，不是讓每個接受版必然進步。

實驗

主實驗是 Atari 的 Breakout、Pong、SpaceInvaders、Seaquest、MsPacman；每個 run 從弱程式 policy 出發，十輪同改 policy.py 和 tests.py。部署評估加入 agent 看不到的 sticky action 或 repeat-action dynamics。七個模型的跨遊戲測試用無保護條件；Breakout 的完整條件消融則涵蓋六個核心模型，包含測試單調化、discriminative check、內生 gate、SEAL 等。

在 35 個有效 self-test 的 model–game cell 中，所有結束 self-score 至少 0.70，但 15 個部署表現低於該遊戲的隨機參考。單調化與 discriminative constraint 仍可在不具代表性的分布上變強，或只打敗很弱的 baseline，因此沒有關閉 gap。

Breakout 的等 proposal 數 pilot 顯示，SEAL 平均 final truth 15.4，無保護 7.7；平均 peak-to-final loss 則為 0.4 對 6.9。作者在跨遊戲的 12 個比較中報告 9 個改善、2 個持平。洩漏數值 audit 分數的條件通常較差，支持只回傳單一 bit 的設計。

結論與限制

作者的結論不是「弱模型作弊、強模型不會」，而是不同能力層級都可能讓自評失去部署意義。SEAL 降低反覆覆蓋已發現能力的風險，但無法保證 audit 與部署排序相同；文中的一條軌跡就有 audit 上升、部署真相下降。因此它是低洩漏的 acceptance boundary，而不是全能的正確性證明。
