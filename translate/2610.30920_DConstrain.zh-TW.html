第1–3節：瓶頸

DLM同時填多位置，單token合法不保聯合合法。Joint inference先對許多假設parser configurations構graph，再max-product找Viterbi或sum-product抽path。這需完整token-labeled successors，非AR單一prefix的boolean mask。

\(c=(q,s,d,\eta)\)把local state、return stack、container depth及field history分開。存在\(k\)個required unordered properties的schema使DFA≥\(2^k\)states、CFG size\(2^{\Omega(k)}\)；factorized object用\(O(k)\)local states與runtime \(k\)-bit history。這是worst-case表示界，非每schema解析時間。（§3）

第4節、附錄A.3：cold／warm

Cold把schema降RTN，specialize\((q,v)\)已知bytes，stack／env留參數。Summary保target、return frames、depth變化及有序guards／updates；unknown caller留residual到warm續跑。Field history用runtime bitmask，不offline枚舉subsets。

Warm只instantiate reachable contexts，執行guards／caller／boundary processing；同program可給不同successors，但source關聯不能混接。Theorem4.1保reference normalized successors；同frontier／candidates／boundary保window language。（§4.1–4.2）

Proof限well-formed bindings、對應primitives、set semantics及completed computations。Normalization只刪certified dead configs；cursor耗盡非finalization，resource exhaustion是error非空successor。保complete-output language，raw window另需boundary相容；不保multiplicity或truncated results。（附錄A.3）

第4.3節、附錄A.4：grouping與measure

Cold依local state的canonical effects分groups，保ordered ops／operands／stack-env／boundary metadata。Canon相等是相同successors的充分非必要條件；每group算一representative，保token IDs／scores。

Sum-product用\(M_i(G)=\sum_{v\in G}p_i(v)\)，選group後按\(p_i(v)/M_i(G)\)還原；max-product用group max並還原argmax。在同finite graph、logical edge各計一次、nonnegative weights、\(Z>0\)、exact arithmetic下，chain／tree保partition function與token-labeled path distribution。Viterbi optimum保留，全部最優解需留所有ties，同字串另需同tie-break。（附錄A.4）

若\(y\)有\(n(y)\)條accepting paths，\(w(y)=\prod_i p_i(y_i)\)，則\(Q_{path}(y)\propto n(y)w(y)\)，合法sequence各算一次的\(Q_{seq}\propto w(y)\)。僅positive-weight support上\(n(y)\)常數才相等；unambiguous足夠。Grouping不去ambiguity，language等價不保不同parser measure等價；greedy group mass非sampling，同seed／浮點次序不保同輸出。（Parsing ambiguity）

仍需individual scores／labels，entry成本不假定constant，contexts／groups仍可爆增，非任意grammar指數加速。（附錄A.5）

第4–5節、附錄B–C：runtime與評估

CPU warm／propagation不用logits，分別於canvas首forward／每iteration與GPU重疊；graph＋scores ready才solve。Candidates只縮小可重用successors。C++／CSR／CUDA亦加速，DINGO-Opt共用工程但保finite states；score-dependent solve仍在critical path。（附錄B.3）

LLaDA2.2用32token blocks、Gemma256token canvases。BFCL2495（排除無valid instance schemas）、JSB5754training schemas、CFB1000cases；主cold depth4／180s timeout。Success除all attempts，quantiles用各自successes，speedup用paired means，timeouts不入latency。（表1、附錄B）

第5.2–5.3節、附錄D.1–D.4：分析

Verifier只問有無合法continuation，不給其mass；完整assignment exact rejection可保固定proposal conditioned分布，但local acceptance／lookahead／recovery非joint objective，單iteration exact非全trajectory exact。（§5.3；trajectory界線為本檔補註，非作者自陳）

Direct-PDA-Opt+TG對300BFCL的6.43倍E2E來自serial MAP設定。Tree solver減depth但增work／memory，未必快；P25/P95指兩selected graph sizes。Payload非total process memory。Dream7B／LLaDA8B只測tokenizer compile，JSB281/300非全5754或model runtime。（附錄D.1–D.4）

附錄D.5：frontend與限制

JSB LLaDA tokenizer1072/5754fail：789semantic、274resource、9implementation/unresolved。OneOf／allOf、nested scope／dialect等仍有限制。305個oneOf／allOf拒絕可由frontend單獨重現，未進token compiler；不保延伸frontend後下游成功。

作者targeted audit同305schemas：XGrammar0.2.8 strict返回298，bounded search找124schemas的accepted完整JSON違原schema；舊0.1.27重播核123。測empty-tokenizer complete-string membership，非model生成率；依declared dialect，format／network refs關閉。124是lower bound，無witness不證語義保留，也不估全域正確率或證DConstrain全accepted schemas正確。本檔未執行audit。（附錄D.5）

Supported parser的execution correctness、frontend coverage及resource construction須分開。Warm reachable contexts仍可對depth／branching指數增長，非無限深或uniformly efficient arbitrary grammar。（Scope／Limitations）
