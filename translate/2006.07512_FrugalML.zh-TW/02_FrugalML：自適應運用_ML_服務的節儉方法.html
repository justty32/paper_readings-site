3. FrugalML：自適應運用 ML 服務的節儉方法

圖 2（策略示意）：FrugalML 先選並呼叫一個基服務（base service）；若其品質分數小於「其預測標籤對應的閾值」，FrugalML 就選一個**加值服務（add-on service）**呼叫並回傳其預測；否則直接回傳基服務的預測。

我們把圖 1(c) 的方案推廣到 K 個 ML 服務、L 個標籤類別。以三元組 s ≜ (p⁽¹⁾, Q, P⁽²⁾) 表示一個 FrugalML 產生的呼叫策略。給定輸入 x：

  • FrugalML 先呼叫基服務 A⁽¹⁾ₛ，它以機率 p⁽¹⁾ᵢ 為第 i 個服務，回傳品質分數 qᵢ(x) 與標籤 yᵢ(x)。
  • 令 Dₛ 為「品質分數是否小於閾值 Q_{i, yᵢ(x)}」的指示。若 Dₛ=1，FrugalML 就以機率 P⁽²⁾_{i, yᵢ(x), j} 呼叫第 j 個加值服務 A⁽²⁾ₛ，並以其標籤 yⱼ(x) 作為最終預測 ŷˢ(x)；
  • 否則直接回傳基服務標籤 ŷˢ(x) = yᵢ(x)。

注意策略是自適應的：加值 API 的選擇可取決於基模型的預測標籤與品質分數。可能策略集合 S 由三部分參數化（p⁽¹⁾ 為 K 維機率向量、Q 為 K×L 閾值矩陣落在 [0,1]、P⁽²⁾ 為 K×L×K 的路由張量且對最後一維為機率分佈）。

Definition 1（最優策略）：給定預算 b，最優 FrugalML 策略為

s* ≜ argmax_{s∈S} E[rˢ(x)]　s.t.　E[η⁽ˢ⁾(x, c)] ≤ b，

其中 rˢ(x) ≜ 𝟙[ŷˢ(x)=y(x)] 為 reward，η⁽ˢ⁾(x,c) 為策略 s 在 x 上的總成本（= 該 x 上所有被呼叫服務的成本之和；若呼叫服務 1 與 2，則為 c₁+c₂）。

Remark 1：此定義可推廣——例如把 0-1 loss 換成負平方損失以處理回歸任務；此處取具體形式僅為示範。

3.1 最優策略中的稀疏結構

Lemma 1：若問題 3.1 可行，則存在一個最優解 s* 使得 ‖p⁽¹⁾*‖ ≤ 2。換言之，最優策略的基服務至多只從市場中 2 個服務（而非全部 K 個）隨機挑選。

直覺（經 Lemma 2 展開）：用全期望公式展開 E[rˢ(x)] 與 E[ηˢ(x)]，兩者都對 Pr[A⁽¹⁾ₛ=i]（即 p⁽¹⁾ᵢ）線性。故固定 Q 與 P⁽²⁾ 後，問題 3.1 對 p⁽¹⁾ 是一個線性規劃。其可行域的角點必為 2-稀疏（除了成本約束 E[ηˢ]≤b 與 𝟏ᵀp⁽¹⁾≤1 外，其餘約束 p⁽¹⁾≽0 都在逼出稀疏）；線性規劃的最優解落在角點，故 p⁽¹⁾ 必 2-稀疏。

此稀疏性讓問題 3.1 等價於一個主問題（master problem，式 3.2）：

max_{(i₁,i₂,p₁,p₂,b₁,b₂)} p₁·g_{i₁}(b₁/p₁) + p₂·g_{i₂}(b₂/p₂)　s.t.　b₁+b₂ ≤ b

其中 g_i(b′) 為**子問題（式 3.3）**的最優值：固定基服務為 i、預算為 b′ 時，對 Q、P⁽²⁾ 最大化期望 reward。主問題決定「哪兩個服務可當基服務（i₁,i₂）、各多常被呼叫（p₁,p₂）、各分配多少預算（b₁,b₂）」；子問題則在固定基服務與預算下最大化期望 reward。

3.2 實用演算法

**演算法 1（FrugalML 策略訓練）**輸入 K、M、成本 c、預算 b 與訓練資料 {y(xᵢ), {qₖ(xᵢ), yₖ(xᵢ)}}，輸出策略三元組 ŝ = (p̂⁽¹⁾, Q̂, P̂⁽²⁾)，三步：

  1. 估條件準確率：從訓練資料估 E[rᵢ(x) | Dₛ, A⁽¹⁾ₛ]（第 1 行）。
  2. 解主問題：對每個 i∈[K] 與 M+1 個預算格點 b′ₘ，解子問題 3.3 得最優值 gᵢ(b′ₘ)（第 2 行），再以線性內插建構分段線性的 gᵢ(·)（第 3 行，並令 gᵢ(b′)=0 當 b′≤cᵢ）；給定分段線性 gᵢ(·)，主問題 3.2 可經枚舉幾個線性規劃求解（第 4 行）得 i₁*,i₂*,p₁*,p₂*,b₁*,b₂*。
  3. 還原原始域策略：對兩個基服務 i₁*、i₂* 分別解子問題 3.3 得各自的 Q、P⁽²⁾（第 5 行），再適當對齊組合成最終 ŝ（第 6 行）。

Theorem 3（效能分析）：設 E[rᵢ(x)|Dₛ,A⁽¹⁾ₛ] 對 Q 的每個元素為 Lipschitz 連續（常數 γ）。給定 N 個 i.i.d. 樣本，演算法 1 的計算成本為 O(NMK² + K³M³L + Mᴸ K²)；且以機率 1−ε，產出的策略 ŝ 滿足

E[r^ŝ(x)] − E[r^{s*}(x)] ≥ −O(√((log ε + log M + log K + log L)/N) + γ/M)，且 E[η⁽ŝ⁾(x,c)] ≤ b。

參數 M 用來權衡計算成本與 ŝ 的準確率下降。實務上當 K、L 約十、N 逾數千時，M=10 即兼顧準確率與低計算成本；Mᴸ 項係數很小（實驗中 L=31、M=40 也僅需幾秒）。標籤數極大時可把標籤聚成幾個「超類（supclass）」，或用近似演算法把 O(Mᴸ) 降到 O(M²)。此外略改 ŝ 即可滿足嚴格預算約束：預算允許時用 ŝ 選 API，否則切到最便宜的 API。
