摘要

付費提供的預測 API（prediction API）是快速成長的產業，也是機器學習即服務（machine learning as a service, MLaaS）的重要一環。雖然可用的服務眾多，但其價格與效能的異質性使得使用者難以決定：針對自己的資料與預算，該用哪個 API、或哪些 API 的組合。我們朝解決此挑戰邁出第一步，提出 FrugalML——一個有原則的框架，聯合學習每個 API 在不同資料上的強項與弱項，並執行一次高效最佳化，自動找出在預算約束下自適應使用可用 API 的最佳循序策略（sequential strategy）。理論分析顯示，此問題公式中天然存在的稀疏性（sparsity）可被利用來使 FrugalML 高效。我們用來自 Google、Microsoft、Amazon、IBM、Baidu 等供應商的 ML API，在臉部情緒辨識、情感分析、語音辨識等任務上做了系統性實驗。跨各種任務，FrugalML 可在匹配最佳單一 API 準確率的同時最多降低 90% 成本，或在匹配最佳 API 成本的同時準確率最多提升 5%。

1. 引言

機器學習即服務（MLaaS）是一個快速成長的產業。例如可用 Google 預測 API 以 $0.0015 分類一張圖片、或以 $0.00025 分類一段文字的情感。MLaaS 之所以吸引人，是因為使用這些 API 減少了自行開發 ML 模型的需要。MLaaS 市場 2019 年估計約 10 億美元，預計 2025 年成長至 84 億美元。

第三方 ML API 也帶來自身的挑戰。一大挑戰是不同公司對相似任務收費差異甚大：圖像分類上 Face++ 每張收 $0.0005，比 Google 便宜 67%，而 Microsoft 收 $0.0010。此外，不同供應商的 API 對不同類型的輸入表現有好有壞——例如已有研究觀察到性別分類對不同膚色存在準確率落差；而如本文稍後所示，這些 API 的效能還會按類別（class）而異：在 FER+ 資料集上，Face++ API 對 surprise（驚訝）圖像最準，而 Microsoft API 對 neutral（中性）圖像最準。更貴的 API 並非一致更好，且各 API 往往在某些特定類別的輸入上勝過其他。這種價格與效能的異質性，使使用者難以決定該用哪個或哪組 API。

本文提出 FrugalML，一個有原則的框架來應對此挑戰。FrugalML 聯合學習每個 API 在不同資料上的強弱，然後執行一次高效最佳化，在使用者預算約束下自動找出使用所有可用 API 的最佳自適應策略。FrugalML 利用 API 的模組化本質，設計可循序呼叫 API 的自適應策略。例如：先把輸入送給 API A；若 A 高信心地回傳標籤「dog」——而我們知道 A 對 dog 通常很準——就停下並回報「dog」；但若 A 以較低信心回傳「hare」，而我們已學到 A 對 hare 較不準，就可自適應地選第二個 API B 做額外評估。

FrugalML 對這類自適應策略做最佳化，比「固定品質閾值的 model cascade」等較簡單的作法大幅提升預測效能（圖 1）。透過在多樣任務上用真實商用 ML API 的實驗，我們觀察到 FrugalML 通常降本 50% 以上、有時高達 90%。自適應策略之所以難學難優化，是因為「若要選第二個預測器，其選擇取決於第一個 API 的預測與信心」，且 FrugalML 可能需要對不同類別分配不同比例的預算。我們證明：在相當一般的條件下，此問題存在天然稀疏性可供利用來使 FrugalML 高效。

圖 1（示意）：比較使用 ML API 的不同作法。(a) 天真地呼叫固定 API 給出固定成本與準確率；(b) 簡單級聯用一個低成本開源模型的品質分數（quality score, QS）決定是否呼叫額外服務；(c) 本文的 FrugalML 同時利用品質分數與預測標籤來選 API；(d) 在臉部情緒資料集 FER+ 上展示 FrugalML 的效益。

貢獻：

  1. 我們形式化並研究「在預算下學習如何最優地使用商用 ML API」這一日益重要但探索不足的問題。
  2. 提出 FrugalML 框架，聯合學習各 API 強弱並做最佳化以在預算約束下找出最佳策略；利用問題中的天然稀疏性，設計出**有可證保證（provable guarantees）**的高效演算法求解。
  3. 用來自 Google、Microsoft、Amazon、Baidu 等多樣供應商的真實 API，在臉部情緒辨識、文字情感分析、語音辨識等分類任務上評估：FrugalML 可在成本最多低 90% 下匹配最佳單一 API 準確率，或在同成本下準確率最多提升 5%。
  4. 釋出由商用 API 標註的 612,139 筆樣本資料集，作為研究 API 間差異、改進使用方式的公共資源。

相關工作：

  • MLaaS：既有研究多聚焦評估「單一」API 的效能、穩健性與應用；FrugalML 則旨在找出「選用或並用多個 API」的策略以降本增準。
  • Mixture of Experts（專家混合）：用 gate function 決定用哪個專家，研究多在發展 SVM／高斯過程／神經網路等 gate 模型。但把 MoE 用於 MLaaS 會導致固定成本、無法讓使用者指定預算約束；且本文稍後顯示，帶預算約束的 FrugalML 有時能用更少預算勝過 MoE。
  • Model Cascades（模型級聯）：一串模型用來平衡推論品質與執行時間。但級聯僅用品質分數來決定是否呼叫昂貴模型，而 FrugalML 的策略同時利用品質分數與預測類別來選下游昂貴加值服務——這需要解一個顯著更難的最佳化問題（例如如何在各類別間分配預算），但也大幅提升了效能。

2. 預備知識

記號：矩陣與向量用粗體，純量、集合、函數用一般字體。𝟙 為指示函數。

ML 任務：全文聚焦（多類）分類任務——把來自分佈 D 的資料點 x 分入 L 個標籤類別。許多真實 ML API 針對此類任務，如臉部情緒辨識（x 為人臉圖像，類別為 happy/sad 等情緒）與文字情感分析（x 為文字段落，類別為正／負情感）。

MLaaS 市場：考慮由 K 個針對同一分類任務的 ML 服務組成的市場。輸入資料點 x，第 k 個服務回傳預測標籤 yₖ(x) ∈ [L] 與品質分數 qₖ(x) ∈ [0,1]，分數越大表示對其預測越有信心（許多主流 API 皆如此）。每個服務有單位成本，向量 c 記所有服務單位成本；cₖ = 0.005 即每次呼叫第 k 個服務須付 0.005。記 y(x) 為 x 的真標籤，rᵏ(x) ≜ 𝟙[yₖ(x)=y(x)] 為在 x 上使用第 k 個服務的 reward（對錯）。
