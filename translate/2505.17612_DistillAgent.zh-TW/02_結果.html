6. 結果

整體結果（表 2）

Agent 蒸餾在所有規模上一致提升效能。蒸餾前，除 7B 外各規模透過 prompt 無法產生有效 agentic 輸出（常產出無法解析或錯誤的程式碼）。蒸餾後，agent 在尤其 out-of-domain 的事實與數學任務上大幅超越 CoT 蒸餾。FTP 與 SAG 進一步放大增益。

跨級超越：0.5B agent (30.55 avg) > 1.5B CoT (24.64)；1.5B agent (36.60) > 3B CoT (32.16)；3B agent (42.68) > 7B CoT (33.54)；7B agent (46.00) 甚至 > 32B CoT (39.54)。

事實推理結果

RAG 對 CoT 蒸餾有幫助，但因其靜態本質在數學推理上反而損害效能。蒸餾 agent 勝過 RAG 強化的 CoT——因為 agent 蒸餾賦予模型主動檢索與整合知識的能力，（而非僅依賴可能不適合任務的預取文件）。

數學推理結果

Agent 在 AIME 和 OlymMATH 上受益於程式碼工具，GSM-Hard 上改善了對罕見數字組合（如六位數運算）的穩健度。MATH500 上 3B/7B agent 落後於 CoT——原因是 Qwen2.5 系列已在 MATH 被大量 instruction-tuned，CoT 更匹配其既有訓練；且較大模型內部計算能力更強，工具使用在 MATH500 上益處較小。但在更難的數學題（GSM-Hard, AIME, OlymMATH）上 agent 仍持續獲益。

7. 分析

Code-specific 模型：teacher 有差，student 無大差（表 3）

使用 Qwen2.5-Coder-32B-Instruct (teacher) 與 -1.5B-Coder (student) 重複實驗——code-specific teacher 稍佳，code-specific student 影響不大。「程式碼知識不是學生的瓶頸」。

跨模型家族（表 4）

Llama-3.2-1B-Instruct 與 Phi-4-mini-instruct (3.8B) 均受益於 agent 蒸餾，FTP/SAG 一致改善，證明方法具廣泛適用性。

FTP 提升複雜推理（圖 4）

分析 MATH500 按問題類別×難度分解：單純蒸餾在大部分難度上損害 3B agent，但加入 FTP 後在 Level 4–5 問題上顯著改善。FTP 主要幫助更難的推理任務（AIME 亦印證）。部分類別（precalculus）下降歸因於問題性質需解析式推理（如三角函數性質）而非直接計算。

SAG vs CoT self-consistency（圖 5）

CoT + self-consistency（多數投票）在 MATH（CoT 本來就贏）進一步提升；但在更難的 AIME 上，小 agent + SAG 在同等生成預算下仍優於 CoT + self-consistency。在事實推理（HotpotQA、MuSiQue）上，self-consistency 僅帶來邊際增益。

Token 生成量（圖 6）：沒顯著差異

事實推理中，agent 因多次檢索而多生成 token；數學推理中，agent 少於 CoT——因為把重複計算委託給程式碼（for-loop）。

SAG 大幅降低無效程式碼（圖 7）

SAG 對 0.5B 模型的效果最明顯。小模型有能力生成有效程式碼，但機率較低——SAG 透過多重採樣提高命中率。

檢索呼叫：模型越大，檢索越多；FTP 減少檢索（圖 8）

大模型更善於決定何時檢索與組織查詢。FTP 使 agent 減用檢索——FTP 鼓勵在思考中陳述事實，可能導致 agent（尤其小者）依賴內部知識而非檢索，增加幻覺風險。

8. 結論

本工作提出 Agent Distillation——將 LLM 的 agentic 行為與工具使用轉移至 sLM 的框架。透過 FTP 改善 teacher 軌跡品質、SAG 提升 test-time 穩健性，蒸餾後的小 agent 可匹配或超越下一級更大的 CoT 蒸餾模型，尤其在 out-of-domain 任務上——展現在建構實用、能使用工具之小型模型上的前景。

局限與未來工作

  • FTP 有時讓 agent 以內部分析代替工具使用，增加幻覺——需要更好的 agentic 軌跡生成策略。
  • SAG 的成敗暗示了 test-time compute scaling 與 process-level reward model 的潛力。
  • Agent 蒸餾未直接提升核心推理能力，在工具擴增環境中的 RL 可在蒸餾後進一步精煉模型。
  • 為擴展至 Qwen2.5 以外模型家族、更強 teacher、更多軌跡數、及 embodied/web agent 情境。
  • 程式碼安全（sandbox 執行）與安全部署仍需配套措施。
