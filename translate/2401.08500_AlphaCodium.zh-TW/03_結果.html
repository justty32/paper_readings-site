5. 結果

5.1 Direct prompt vs. AlphaCodium flow

表 1 比較 AlphaCodium 與「單一精心設計 direct prompt」的結果，metric 為 pass@k（用每題 k 個生成解所解出問題的百分比）。摘要（皆 pass@5）：

模型 集合 Direct prompt AlphaCodium
DeepSeek-33B validation 7% 20%
DeepSeek-33B test 12% 24%
GPT-3.5 validation 15% 25%
GPT-3.5 test 8% 17%
GPT-4 validation 19% 44%
GPT-4 test 12% 29%

AlphaCodium 對開源（DeepSeek）與閉源（GPT）、validation 與 test 皆一致且顯著提升。GPT-4 validation 由 19% 到 44%（x2.3）。

5.2 與前作比較

表 2：同模型（GPT-3.5）同 metric（pass@5）下，AlphaCodium 一致勝 CodeChain（validation 25% vs 17%、test 17% vs 14%）。與 AlphaCode 比較須留意其方法不同——微調一個（未知）模型、生成極大量解、叢集、從頂端叢集提交 K 個（如 pass@10@100K 意指生成並叢集 10 萬解、最終挑 10 個提交）。AlphaCode 用微調模型與暴力式高呼叫數，但 AlphaCodium 的最佳結果更好（GPT-4 validation 44% vs AlphaCode pass@10@100K 24%；test 29% vs 28%）。注意 AlphaCode 與 CodeChain 都未釋出可重現的開源方案；本文則釋出完整可重現的生成與評估腳本，以利未來更可靠一致的比較。

5.3 算力與對 AlphaCode / AlphaCode2 的比較

AlphaCodium 每解約 15-20 次 LLM 呼叫，故 pass@5 提交約 100 次呼叫。AlphaCode 未報告每次執行的呼叫數；假設每次執行一呼叫，則 pass@10@100K（從 10 萬生成解 curated 出 10 個提交）約 100 萬次呼叫，比 AlphaCodium 多四個數量級，而 AlphaCodium 的頂端結果仍更好。

近期 AlphaCode2（微調 Gemini-Pro）也在一個未公開的 CodeContests 更新變體上報告結果，稱「約需 100 個樣本即達 AlphaCode 用百萬樣本的表現，樣本效率高 10000×」。故 AlphaCode2 與 AlphaCodium 同樣比 AlphaCode 高四個數量級（就 LLM 呼叫而言）；但 AlphaCode2 用了為 CodeContests 競賽重度微調的現代基礎模型（Gemini-Pro），而 AlphaCodium 直接用通用模型 as-is，無需額外資料與昂貴訓練即提升表現。

6. 結論

本文提出 AlphaCodium——一條程式碼導向 flow，迭代地對生成碼執行並根據輸入輸出測試修復。flow 分兩階段：預處理（用自然語言推理問題）與程式碼迭代（對公開與 AI 生成測試迭代）。AlphaCodium 也用了對程式生成有益的設計概念：YAML 結構化輸出、生成模組化碼、bullet point 語意推理、soft decisions 加雙重驗證、鼓勵探索、test anchors。我們在 CodeContests 上測試，該 flow 對多種閉源與開源模型持續且顯著改善結果，也以小得多的算力預算勝過前作。

附錄（擇要）

  • 附錄 A：一個典型 HumanEval 題（has_close_elements），用以對比其簡潔性遠低於 CodeContests。
  • 附錄 B — 為何 YAML 比 JSON 更適合程式生成：生成的碼常含單引號、雙引號、特殊字元，LLM 難以在 JSON 中合法擺放（JSON 需外圍雙引號）；而 YAML 的 block scalar 只需遵守縮排，任何正確縮排的文字或碼都合法。此外 YAML 不需大括號、引號或跳脫字元，token 更少，降低成本與推論時間並提升品質。
  • 附錄 C — 對我們無效的方法：(1) 把失敗執行 trace（最後 50 行）注入 prompt；(2) 把最近 K 個失敗碼注入 prompt；(3) 把最近的 git patch diff 注入 prompt；(4) 複雜的單階段 prompt 或非迭代 prompt 鏈——皆無明顯改善，模型仍看不懂冗長題目、忽略細節、產出錯碼。
  • 附錄 D — 估計測試輸出間的距離：除 pass/fail 布林值外，也估生成輸出與正解的距離：輸出為數字則算 L2 距離；為數字陣列則算對應格 L2 距離之和；為字串陣列則逐格布林比較、回傳不同格數。用於挑選「輸出最接近」的 base 碼。
