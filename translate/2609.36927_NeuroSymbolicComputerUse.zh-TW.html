論文／訪談原始來源

Neuro-Symbolic Computer Use: Learning Reusable Policies for Reliable and Efficient Execution

第 1～2 節：用政策重用反覆工作流

反覆任務通常只有日期、檔名或起始狀態變動，純神經 agent 卻每次重新規劃，錄製腳本又容易因環境改變失效。本文以神經符號政策保存穩定的順序、變數、迴圈與分支，將畫面定位與狀態判斷留給神經 primitive。快捷鍵、shell 與檔案操作可直接執行；GUI grounding 與 state_satisfies 仍需呼叫模型。政策以 Simulang 與 Python 控制流程實作。（§2.2、附錄 A.1）

可靠性定義為 Pass^k=p(g)^k，即同一任務的 k 次獨立執行全部成功。本文每任務測三次，Pass^3 是三次皆成功的任務比例；建構失敗也保留在分母。它不是「三次至少成功一次」的 Pass@3。（作者自報，§2.1、式 2、§4.1）

第 3.1 節：執行、診斷、探索與改寫

NSPI 從單條 base-agent 軌跡建立初始政策，示範不必成功。Converter 抽出動作、以語意目標取代像素座標，將任務特定值改成參數。主實驗最多五次政策迭代，每輪最多五次重設 rollout；遇第一個失敗即停下診斷，整輪皆通過或額度用完才返回政策（作者自報，附錄 B.1）。

任務完成評審以唯讀工具探查持久終態，不能查證時可 abstain；applicability gate 可事先跳過不適用的任務。逐步評審先由 observer 描述前後變化，observer 不看任務、程式或動作意圖，再由 localizer 閱讀任務、程式與觀察描述，指出首次偏離與失敗模式。主流程依 §3.1.2、算法 1，要求 localizer 成功且任務評審成功或被 gate 跳過；abstain 算失敗。

失敗後 agent 從 rollout 結束狀態續作，其進展經摘要後交 coding healer，連同診斷、執行紀錄與畫面改寫程式。執行例外則跳過評審與續作，直接交 traceback。政策迭代不用 benchmark evaluator 回饋，評估腳本只對返回的政策衡量成績。（§3.1、附錄 A.2～A.4）

第 3.2 節：變體泛化與部署攔查

參數變體保留起始狀態但改請求值；初始狀態變體保留請求但改起始環境。系統依序在變體上改寫同一政策，再凍結政策測未見原任務。附錄 B.2 的變體實驗採較寬鬆 gate，由任務評審判定成功，localizer 協助定位。另須區分資料生成與政策迭代：變體生成器會讀原任務的評估腳本，政策迭代本身不取其回饋。（§3.2.1、附錄 B.2）

部署的 pre-action verifier 另在納入攔查的狀態改動 primitive 前，讀取任務、呼叫、意圖註解、當前畫面／可及性樹與執行歷史，將 yes／no token 機率正規化，當 p_no>=theta 時攔下。門檻在校準階段決定；被攔後可交 agent、修復或人工處理。程式內狀態檢查只在程式指定位置決定控制流程，不能取代統一攔查。（§3.2.2、附錄 A.5）

第 4.1～4.3 節：重複執行與未見實例

以下均為作者自報。主評估含 ScienceBoard 169 題、OSWorld-Verified 361 題，使用 GPT-5.6 Terra 或 Claude Opus 5。表 1 的 base／NSPI Pass^3 為：ScienceBoard／Terra 13.6%／26.0%、ScienceBoard／Opus 5 29.6%／42.6%、OSWorld／Terra 34.6%／50.4%、OSWorld／Opus 5 68.4%／72.0%。NSPI 在四設定均最高。

摘要寫相對 base 高 3.6～15.8 個百分點，引言寫 4.5～13.9；此處按表 1 逐設定列數值。只轉程式而不迭代的 Batch2Code 雖也穩定，但其成功率較低，顯示可重播不等於正確。（§4.1～4.2、表 1）

泛化實驗以 Terra 在 40 個參數家族、35 個初始狀態家族上學習，每家族至多三個變體。凍結後測原任務，NSPI／AutoRPA 的參數家族 Pass^3 為 55.0%／37.5%，初始狀態家族為 60.0%／51.4%。（§4.3、表 2）

第 4.4 節：每次重用與學習費用須分開

以下均為作者自報。表 1 的 base／NSPI 單次費用比，按 ScienceBoard／Terra、ScienceBoard／Opus 5、OSWorld／Terra、OSWorld／Opus 5 排序為 15、65、67、217 倍；時間比為 4.6、3.9、5.1、3.4 倍。分母是學成政策的一次重用，沒有把一次性構建分攤進去。

令 C_pi 為構建費、c_pi 為政策單次費、c_mu 為 base 單次費，平均費用為 C_pi/n+c_pi，當 c_mu>c_pi 時，費用損益兩平點為 n*=C_pi/(c_mu-c_pi)。表 3 的平均構建費為 2.03～6.45 美元；費用攤平點為 3.1～26.8 次，時間攤平點為 8.6～16.9 次。

附錄 B.1 以供應商模型帳單加 grounding 呼叫計費；一次性構建包含 conversion 與 policy iteration，單次費用對應一輪最終 trial。初始化用一條軌跡，不表示完整學習只花一次執行；迭代、評審、續作與變體處理仍有成本。作者也提醒 benchmark 複雜度與其他差異混雜，不能僅由此宣稱任務越複雜必然越划算。（§2.1、式 3、§4.4、表 3、附錄 B.1）

第 4.5～4.7 節：長流程、verifier 與評審的邊界

作者自報，OSWorld-V2 的 strict Pass^3 低於 base 5.6 個百分點，partial-credit 指標低 18.5 個百分點；長軌跡轉政策會遺失資訊。重複執行較一致，不代表任務成功率一定更高。（§4.5）

另節 verifier 實驗使用補入的意圖註解與 rubric 修訂，theta=0.78。作者自報，Qwen3.6-35B-A3B 的 rollout 錯擋率最高 8.4%，卻漏放應攔 24 個 primitive 中的 17 個，WPR 為 70.8%；Qwen3.8-27B 漏放 6 個，WPR 為 25.0%，錯擋率為 9.4%～25.0%。錯擋以正確 rollout 為分母，漏放以應攔 primitive 為分母。（§4.6、附錄 B.4）

作者自陳限制：附錄 B.3 指逐步評審看不到 primitive 回傳值與腳本輸出、容易將後續症狀當首次偏離、無法辨識不可行任務；任務評審則可能過信已存檔或工具輸出。評審過度保守也增加構建成本。附錄 A.5 說 headless API 寫入需另設防護；若 verifier 完成內容沒有 yes／no，會 fail open。（§4.7、附錄 B.3、A.5）

原文在設計描述、實作限制與 abstain 處理上有不同寫法：A.4 設計描述可讀非視覺動作輸出，B.3 則將實作不可見輸出列為限制；A.4 一處說 abstain 回退逐步評審，也與主文及算法 1 不同。本文分別依主流程與 B.3 實測限制表述。（附錄 A.4）
