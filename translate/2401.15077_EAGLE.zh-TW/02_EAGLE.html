3. EAGLE

與其他推測取樣方法一致，EAGLE 含 drafting 與驗證兩階段。

3.1 Drafting 階段

EAGLE 與其他方法的主要差異在 drafting 階段（圖 5 對比示意）：傳統推測取樣與 Lookahead 用 token 預測 token；Medusa 用 target LLM 的特徵 f_2 各自獨立地預測 t_4 與 t_5；EAGLE 則用特徵序列 (f_1, f_2) 加提前一步的 token 序列 (t_2, t_3) 預測 f_3，再由 p_4 = LM_Head(f_3) 取樣出 t_4，接著把 f_3 與 t_4 串進輸入預測 f_4、取樣 t_5——特徵層級自回歸持續推進。

草稿模型含三個模組（圖 6）：Embedding 層與 LM Head 直接沿用 target LLM 參數、無需訓練；Autoregression Head（自回歸頭）由一個 FC 層加一個 decoder 層組成。輸入為特徵序列（bs, seq_len, hidden_dim）與提前一步的 token 序列（bs, seq_len）；token 轉為 embedding 後與特徵串接為（bs, seq_len, 2×hidden_dim），FC 層降維回 hidden_dim，decoder 層預測下一特徵，LM Head 據特徵算分佈並取樣下一 token；預測出的特徵與取樣出的 token 再串進輸入，繼續自回歸。

EAGLE 用 tree attention 產生樹狀草稿：深度 m 的草稿樹經 m 次前向可生成多於 m 個 token——例如 3 次前向即可起草一棵 10-token 的樹（圖 6；實際採用的樹結構見附錄 A.1）。

3.2 草稿模型的訓練

預測下一特徵是回歸任務，用 Smooth L1 損失：L_reg = SmoothL1(f_{i+1}, Draft_Model(T_{2:i+1}, F_{1:i}))。預測特徵只是中介目標，最終目標是預測 token，故同時加分類損失直接對齊最終目標：p_{i+2} = Softmax(LM_Head(f_{i+1}))、p̂_{i+2} = Softmax(LM_Head(f̂_{i+1}))，L_cls = CrossEntropy(p_{i+2}, p̂_{i+2})。合併損失 L = L_reg + w_cls·L_cls；因分類損失數值上通常比回歸損失大一個數量級，取 w_cls = 0.1。

理想上該用 target LLM 自回歸生成的文本訓練，但成本高。所幸 EAGLE 對訓練資料不敏感（見 4.3.3 消融），改用固定資料集即可，大幅降低開銷。此外，drafting 階段自回歸處理特徵會累積誤差，故訓練時對 target LLM 的特徵加入均勻分佈 U(−0.1, 0.1) 的隨機雜訊做資料增強（仿 NEFTune, Jain et al., 2023）。

3.3 驗證階段

利用 tree attention，target LLM 單次前向即可算出樹狀草稿中每個 token 的機率。在草稿樹的每個節點遞迴套用推測取樣演算法做取樣或分佈調整（細節見附錄 A.2），與 SpecInfer（Miao et al., 2023）一致，確保輸出文本分佈與 target LLM 對齊。同時記錄被接受的 token 及其特徵，供下一輪 drafting 使用。

4. 實驗

模型與任務：Vicuna（7B/13B/33B）、LLaMA2-Chat（7B/13B/70B）、Mixtral 8x7B Instruct，涵蓋主流尺寸。任務含多輪對話（MT-bench）、程式碼生成（HumanEval）、數學推理（GSM8K）、指令遵循（Alpaca）。多數實驗沿用推測取樣慣例 batch size = 1（bs>1 見 4.4）。

指標：(1) 實測加速比（walltime speedup ratio）；(2) 平均接受長度 τ：target LLM 每次前向平均接受的 token 數；(3) 接受率 α：草稿 token 被接受的比率（量測時用鏈狀草稿以對齊既有方法）；因特徵自回歸會傳播誤差，另定義 n-α：輸入含 n 個由草稿模型預測（可能失準）的特徵時之接受率。由於 EAGLE 理論保證輸出分佈不變，評估生成品質既無必要也無意義。

訓練：target LLM 凍結。用 ShareGPT 資料集 68,000 筆對話、學習率 3e-5、AdamW（β=(0.9, 0.95)）、梯度裁剪 0.5。對應 7B/13B/33B/70B 的可訓練參數量分別為 0.24B / 0.37B / 0.56B / 0.99B（Mixtral 8x7B 為 0.28B）。70B 的自回歸頭在 A100 40G 伺服器上 1–2 天可訓完。

4.1 有效性

  • temperature=0 加速優於 temperature=1：如 LLaMA2-Chat 13B 在 T=0 為 3.01x–3.76x，T=1 為 2.66x–2.89x。
  • 程式碼生成（HumanEval）加速最佳（如 LLaMA2-Chat 13B 達 3.76x）——程式碼中大量固定模板讓草稿更好起。
  • 相較 Lookahead 快 1.70x–2.08x、相較 Medusa 快 1.47x–1.60x。
  • 傳統推測取樣在 Vicuna/LLaMA2-Chat 系列很難用：7B 無合適草稿模型；以 7B 當草稿時，13B 無加速、33B 僅 1.12x、70B 僅 1.88x。DistillSpec 蒸餾雖略有改善，但瓶頸在草稿模型本身開銷太高，提升接受率幫助有限。
  • EAGLE 中 target LLM 每次前向生成 3.2–4.5 個 token（vanilla 僅 1 個）。完全精準特徵下的接受率 0-α 明顯高於含一個錯誤特徵的 1-α，顯示特徵誤差確有影響；但 1-α 到 4-α 變化甚小，顯示 EAGLE 對特徵誤差穩健、能妥善抑制誤差累積（MT-bench 上 0-α 約 0.71–0.79、4-α 約 0.60–0.71）。
  • Mixtral 8x7B Instruct 僅 1.5x（τ=3.25）：MoE 模型 vanilla 解碼每 token 只需讀兩個 expert 的權重，驗證階段處理多 token 卻可能要讀更多 expert，故加速較 dense 模型有限。

4.2 案例研究：EAGLE + gpt-fast

EAGLE 與其他加速技術相容。與 gpt-fast（量化＋編譯）結合，LLaMA2-Chat 7B 在單張 RTX 3090、MT-bench、T=0 下：Huggingface 原生 24.5 tokens/s → gpt-fast int4 106.9 tokens/s → EAGLE + gpt-fast int4 160.4 tokens/s（FP16 下 EAGLE+gpt-fast 為 100.2）。

4.3 消融研究

Tree attention（4.3.1）：樹狀 draft 與驗證使平均接受長度增加約 0.6–0.8、加速比增加約 0.3–0.5（如 Vicuna 7B 鏈狀 τ=3.20 → 樹狀 3.94）。樹狀化不增加前向次數、只增加每次前向處理的 token 數，故加速比增幅小於接受長度增幅。即使不用樹狀，EAGLE 仍有約 2.3x–2.7x 加速。

草稿模型的輸入（4.3.2）：在 Vicuna 7B 上對比四種輸入——feature&shifted-token（EAGLE）、feature&unshifted-token、僅 token、僅 feature。三個觀察：(1) 參數量受限時，用特徵略優於用 token；(2) 特徵＋token 融合適度提升表現，主因是離散、無誤差的 token 能抑制特徵誤差累積（feature&unshifted-token 與純 feature 的 0-α 相近、但 1-α 顯著更好）；(3) 消解取樣隨機性帶來最大提升——shifted 相比 unshifted 不增加任何複雜度，僅把 token 提前一步，就讓草稿模型得以納入取樣結果。

訓練資料（4.3.3）：用 target LLM 生成的答案訓練僅帶來邊際提升（2.88x/τ=3.75 vs 固定 ShareGPT 資料集 2.78x/τ=3.62），證明 EAGLE 對訓練資料低敏感、用固定資料集降本是合理的。

4.4 Batch size 與吞吐量

LLM 推論是 memory-bound，GPU 算力閒置；推測取樣正是靠更有效利用閒置算力加速。batch size 增大時可用算力減少、加速比隨之下降（Vicuna 7B：bs=1 2.90x → bs=4 2.76x；LLaMA2-Chat 70B：bs=1 3.01x → bs=4 2.40x）。吞吐量方面：EAGLE 記憶體略高（RTX 3090 24G 下 Vicuna 7B 最大 bs 為 7 vs vanilla 的 8），在各自最大 bs 下比較，EAGLE 吞吐量約為 vanilla 的 2 倍（7B 1.97x、70B 1.99x；bs 大、算力吃緊時不用 tree attention 反而更有利）。
