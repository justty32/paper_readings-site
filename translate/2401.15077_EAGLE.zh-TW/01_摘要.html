摘要

自回歸解碼（autoregressive decoding）使大型語言模型（LLM）推論耗時。本文重新審視推測取樣（speculative sampling），得出兩個關鍵觀察：其一，在特徵（feature，倒數第二層、LM head 之前的隱狀態）層級做自回歸比在 token 層級更直接；其二，特徵層級自回歸固有的（取樣）不確定性制約其效能。基於這些洞見，我們提出 EAGLE（Extrapolation Algorithm for Greater Language-model Efficiency），一個簡單而高效的推測取樣框架：藉由納入提前一個時間步的 token 序列，EAGLE 有效消解不確定性，以極小開銷實現精準的倒數第二層特徵預測。我們在 Vicuna 與 LLaMA2-Chat 全系列、MoE 模型 Mixtral 8x7B Instruct，以及對話、程式碼生成、數學推理、指令遵循等任務上全面評估。對 LLaMA2-Chat 70B，EAGLE 達成 2.7x–3.5x 延遲加速、吞吐量加倍，且維持生成文本的分佈不變。

1. 引言

自回歸解碼逐一生成 token，緩慢且昂貴。推測取樣類方法（Leviathan et al., 2023; Chen et al., 2023a）把生成過程拆為低成本 draft 階段與對草稿 token 的平行化驗證階段，讓單次 LLM 前向即可驗證多個 token。更重要的是，驗證階段確保文本分佈與原始 LLM 的解碼結果精確一致。

推測取樣的關鍵在找到「功能近似原 LLM 但延遲更低」的 draft model（草稿模型），通常取同系列低參數版本。但 LLaMA2 系列（7B/13B/70B）中，最小的 7B 找不到合適草稿模型；改用 TinyLLaMA 又因指令模板不一致而不可行於 instruct-tuned 模型；即便可用 7B 當草稿，其高開銷也侵蝕加速收益。為推測取樣專門訓練新草稿模型也不划算：TinyLLaMA 訓練用 3,000B tokens，而 EAGLE 只用 2–4B tokens。

提升加速的關鍵在降低 draft 時間開銷、提高草稿被原 LLM 接受的比率。Lookahead（Fu et al., 2023）用 n-gram 與 Jacobi 迭代；Medusa（Cai et al., 2023）用一組 MLP 基於原 LLM 的倒數第二層特徵預測 token。它們顯著降低了草稿延遲，但草稿準確率偏低——Medusa 約 0.6，Lookahead 更低；相較之下，本方法達約 0.8。

EAGLE 建立在兩個觀察上：

  1. 特徵層級的自回歸比 token 層級更簡單。本文「特徵」指原 LLM 倒數第二層（LM head 之前）的特徵。token 序列是自然語言的簡單轉換，特徵序列則展現更多規律性。先在特徵層級自回歸、再用原 LLM 的 LM head 導出 token，效果優於直接自回歸預測 token：draft 模型只吃 token 加速比 1.5x，改吃特徵升到 1.9x（圖 4）。
  2. 取樣過程固有的不確定性顯著制約「預測下一個特徵」的表現。目標 LLM 預測 token 分佈後取樣，引入隨機性；特徵是高維連續的，無法同樣處理。如圖 3 所示，取樣到「am」或「always」會導向不同的特徵序列，給特徵層級自回歸帶來歧義（Medusa 預測隔位 token 也面臨類似問題：不確定輸入 f_I 的真目標該是 p_am 還是 p_always）。EAGLE 的解法：把提前一個時間步、包含取樣結果的 token 序列一併輸入草稿模型——即基於 (f_I, t_always) 預測 f_always、基於 (f_I, t_am) 預測 f_am。消解不確定性後，加速比從 1.9x 進一步升到 2.8x（圖 4）。

在 MT-bench 上，EAGLE 相較 Lookahead 快 1.7x–2.1x、相較 Medusa 快 1.5x–1.6x。EAGLE 與量化、編譯等其他加速技術正交：搭配 gpt-fast，單張 RTX 3090 上把 LLaMA2-Chat 7B 解碼提升到 160.4 tokens/s。

訓練成本低：對 LLaMA2-Chat 70B，EAGLE 只訓練一個參數量 <1B 的 decoder 層，用不超過 7 萬筆 ShareGPT 對話，4x A100（40G）1–2 天完成；7B/13B/33B 甚至可在 RTX 3090 節點上 1–2 天訓完。訓練一次即可為所有後續查詢提供加速，查詢量越大攤提成本越趨近於零。

其他優點：

  • 通用性：原則上適用任何自回歸 LLM；已零樣本（zero-shot）應用於 LLaMA2-Chat（7B/13B/70B）、Vicuna（7B/13B/33B）、Mixtral 8x7B Instruct——所有實驗共用同一組僅在 ShareGPT 上訓練的權重，不在評測資料集上額外訓練。只需在 LLM 上加一個輕量外掛（單個 transformer decoder 層），易於生產部署。
  • 可靠性：完全不微調原 LLM，且在 greedy 與 non-greedy 兩種設定下都有輸出分佈保持不變的理論保證——與只顧 greedy 或不保證分佈的 Lookahead / Medusa 形成鮮明對比。

2. 預備知識

符號：「target LLM」指要加速的 LLM，「draft model」指產草稿的模型。「特徵」指 LLM 倒數第二層、LM head 之前的隱狀態。token 記 t、embedding 記 e、特徵記 f、分佈記 p；序列用大寫如 T_{i:j}。LLM 中，輸入 T_{1:j} 經 embedding 層變 E_{1:j}、再變特徵 F_{1:j}，LM head 把 f_j 映為分佈 p_{j+1} = LM_Head(f_j)，取樣得下一 token。原生 token 層級自回歸即 T_{1:j} → E_{1:j} → f_j → p_{j+1} → t_{j+1}。

推測取樣：分 draft 與驗證兩階段。draft 階段用小模型生成 γ 個 token T̂ 及其分佈 P̂；驗證階段 target LLM 一次前向得到機率 P，逐一評估：token t̂_{j+i} 以機率 min(1, p_{j+i}(t̂)/p̂_{j+i}(t̂)) 被接受；一旦拒絕某 token，其後全部丟棄，並從調整後分佈 norm(max(0, p−p̂)) 重取樣該位置。Leviathan et al. (2023) 附錄 A.1 已證明此法等價於直接從 target LLM 取樣。EAGLE 採用此法，確保 greedy 與 non-greedy 下生成文本分佈皆不變。
