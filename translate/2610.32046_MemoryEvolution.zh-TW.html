論文／訪談原始來源

測試時記憶演化能否勝過測試時訓練？

摘要與第 1–2 節：研究問題

科學發現式程式搜尋反覆生成候選、執行驗證器，再依結果繼續探索。測試時訓練（TTT）用這些經驗在線更新模型權重；本文提出測試時記憶演化（TTME），保持權重固定，把搜尋結果整理成外部文字記憶，加入後續生成脈絡。作者在兩個既有搜尋框架及五種數學構造題上比較這兩類適應。（摘要與 §1、§2）

第 3 節：方法

每個搜尋框架維護候選程式 archive，依既有規則選父代，生成、執行及評估子代，目標是在預算內找到分數最佳的有效構造。TTME 保留框架的父代選擇、archive 更新及任務驗證器，以外部記憶取代在線權重更新；每次執行的兩類記憶均從空開始。（§3.1、附錄 C）

Guideline Memory 整理跨父代的有效結果、分數和失敗，記下觸發條件、可能機制與具體行動。相似建議合併並計數，過期項目移除，容量有限。Strategy Memory 只從有效且優於父代的修改出發，分析父子程式、差異與評估結果，將演算法想法及適用條件按策略家族整理，並保留來源。（§3.2–3.3、附錄 C.2）

每個父代由同一固定權重模型選擇策略並寫成適用該程式的修改指令；一半候選直接根據父代和指南生成，另一半另受策略指令引導。評估結果再更新記憶。實驗每兩個搜尋步驟更新兩類記憶；TTME 的記憶整理與策略選擇需要額外模型呼叫。（§3.4、附錄 C.3）

第 4.1 節：比較與任務

作者在 TTT-Discover 使用 Qwen3-8B、gpt-oss-120b，測 Erdős 最小重疊、第一與第二自相關不等式（AC1／AC2）；在 ThetaEvolve 使用 Distill-Qwen3-8B，測 AC2、AC3 與 29 階 Hadamard 最大行列式。作者自跑 TTME 和固定權重無 TTME 基線，TTT 數值引用原始論文；因此這不是三組均由本文同一實驗重跑的比較。（§4.1）

兩個本文固定權重條件同用初始任務、驗證器及主要候選預算，但 TTME 有額外記憶模型呼叫。TTT-Discover 使用 50 步、每步 8 個父代各 64 個主要候選，合計 25,600；ThetaEvolve 使用 65 步、每步 32 個父代各 16 個，共 33,280。以表 8 的 gpt-oss-120b 為例，原 TTT 與本文固定權重條件的服務引擎分別為 Tinker 和 vLLM。（附錄 B.1–B.2，表 7–8）

在所列任務與模型中，TTME 的最佳分數均優於引用的 TTT 結果；某些差距很小，表格本身未給出不確定區間，不能推定所有差異穩健。（§4.2）

成本比較僅在 TTT-Discover、Qwen3-8B 的 AC1、AC2、Erdős 三題報告，包含候選生成、記憶呼叫及適用時 RL 訓練，但排除候選評估時間。作者自報 TTME 的執行時間減少 47.7～58.4%，FLOPs 減少 82.8～84.6%；這些比例不是五題、所有模型或端到端成本的實測範圍。（§4.2，表 3）

第 4.3–4.4 節：消融與搜尋分析

Qwen3-8B 的 AC2 與 Erdős 比較中，作者報 TTME 單獨使用的分數優於同時使用 TTT 與 TTME；聯合設定中，RL 更新後的模型同時負責生成與記憶操作。gpt-oss-120b 的三題消融中，移除指南或策略記憶都使最佳分數低於完整 TTME；這些是所測設定的結果，不能推出兩種適應在任何任務上都互相妨礙。（§4.3，表 4–5）

作者將「結合」定義為子代保留父代想法，同時加入此前在其祖先鏈以外探索的想法；在 Qwen3-8B 的 AC1／AC2 中，TTME 後續選為父代的結合比例為 10.2%／24.7%，TTT 為 8.2%／18.6%。這是依其分析定義的搜尋行為，並非對想法來源或因果效應的獨立證明。（§4.4）

第 5 節：結論與界限

作者認為，在這些可執行候選與任務驗證器的數學構造設定中，演化外部記憶可作為測試時權重更新的替代方式。結論受任務、基礎模型、搜尋框架與候選預算限制；引用的既有 TTT 數值、不同服務系統及未計入的評估時間，也限制對一般部署成本和全面優劣的推論。（§5、附錄 B）
