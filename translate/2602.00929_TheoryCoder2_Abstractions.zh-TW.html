論文／訪談原始來源

為程式合成智能體學習階層規劃的抽象（TheoryCoder-2）

摘要

人類學習抽象並用以高效規劃，能快速跨任務泛化——這對 SOTA 的 LLM 智能體與深度 RL 系統仍是挑戰。受「人如何形成抽象與對世界知識的直覺理論」之認知科學啟發，Theory-Based RL（TBRL）系統（如 TheoryCoder）透過有效運用抽象展現強泛化。然而它們重度依賴人工提供的抽象、迴避了抽象學習問題。我們提出 TheoryCoder-2：一個利用 LLM in-context learning 能力主動學習可重用抽象（而非依賴手寫抽象）的 TBRL 智能體——從經驗合成抽象並整合進階層規劃過程。我們在多樣環境（BabyAI、Minihack、Sokoban 等 VGDL 遊戲）上實驗，發現 TheoryCoder-2 比「以古典規劃域構造增強的 LLM 智能體、推理式規劃、WorldCoder 等程式合成智能體」樣本效率顯著更高，能解基線失敗的複雜任務，且只需最少人工 prompt（不像先前 TBRL 系統）。

1. 引言

人類智能的標誌是階層式規劃——結合抽象表徵與低層世界模型。嬰兒早期就理解 containment（容納）、support（支撐）等抽象謂詞，這些表徵是日後技能發展的基礎。例如「容納」的表徵對「把果汁倒進杯子」的抽象規劃不可或缺，再與生物力學/物理的低層模型結合，構造出 grounded 的具體計畫。

現代 AI 仍難達此流暢度。受認知科學啟發，TBRL 為智能體賦予「物件導向、關係性、因果性」的人類式世界模型（「理論」）。最先進者 TheoryCoder 學一個低層世界模型，再結合高層抽象支持階層規劃，其效能與樣本效率遠勝深度 RL 與 LLM 智能體——它用 LLM 把過去經驗翻譯成推斷的世界模型，藉 LLM 的聯想記憶與類比檢索取得高穩健與計算效率，並構造符號模型供階層規劃（而非端到端代理）。

TheoryCoder 的主要限制是依賴手寫抽象，大幅限制其應用範圍：進任何新域，須先由人想出相關抽象再寫程式碼；否則只能近乎隨機動作去建低階世界模型，喪失抽象帶來的效率與遷移性。本文用自動學習抽象概念解決此核心限制：讓智能體不僅能構造與操作抽象，更能把抽象遷移到新域並即時 grounding，無需領域適配，學得一種會泛化的階層規劃能力。所得方法 TheoryCoder-2 能合成 PDDL 形式的高層抽象（規劃域定義語言運算子），只需最少人工引導（初始 prompt 與示例）。

2. 背景

2.1 Theory-based RL

TBRL 用物件導向、關係、因果的世界模型支持規劃，靠抽象取得遠勝深度 RL/LLM 的樣本效率。

2.2 TheoryCoder

學低層 Python 世界模型 + 結合手寫高層 PDDL 抽象做階層規劃；抽象與謂詞語意均由人提供。

3. 方法：TheoryCoder-2

3.1 學習抽象

原 TheoryCoder 靠手工 PDDL 檔（定義抽象運算子與謂詞），TheoryCoder-2 用 LLM in-context learning 自行合成這些檔案。唯一須手工的系統輸入是初始 prompt——對環境最終目標的自然語言描述，加上幾個說明「學抽象運算子是什麼意思」的極簡示例（如 eat：前提 not eaten、效果 eaten，基於一個玩具問題）。這些示例刻意極簡，且與實際互動環境無關，僅作為「抽象如何表徵」的模板；它們對「引導 LLM 在恰當層級合成抽象——既不太細也不太粗」至關重要（這是 LLM 完全自主時的難點）。

3.2 重用與成長抽象庫

實驗測試 TheoryCoder-2 透過一連串與不同環境互動的「episodes」累積可重用抽象概念庫的能力。每個 episode 含一或多個按相似度分組、按難度排序的環境；也構造打亂課程順序的消融。每個 episode 內，智能體零樣本學到運算子後，再像原 TheoryCoder 學一個 Python 世界模型；不同的是，它還學 Python 函數來把謂詞語意 grounding 到該環境（先前這些由人連同 PDDL 抽象一起提供）——即學謂詞分類器（生成 Python 程式，作用於原始狀態、回傳布林表示謂詞是否成立）。從每 episode 第二個環境起，智能體嘗試重用先前學到的抽象並按需擴充。

4. 實驗

問題：TheoryCoder-2 能否成功學抽象狀態與動作？學到的抽象能否跨環境重用？重用是否提升新問題的樣本效率？在對既有 LLM 智能體非平凡的挑戰任務上表現如何？

評估於 VGDL 的 Labyrinth、Maze、Sokoban（§4.1），BabyAI，以及 Minihack（§4.2）。指標：token 成本（衡量樣本效率）、計算時間、解題率（首次嘗試成功解出的任務比例）。

基線：

  • LLM + 簡單規劃：純推理模型直接以原始動作生成計畫，無顯式抽象或可執行世界模型（測 o4-mini 高/中/低推理；另測非推理的 GPT-4o）。
  • WorldCoder：合成代表轉移函數的 Python 程式，供低層規劃器生動作（GPT-4o 合成 + BFS）；不做階層規劃。
  • TheoryCoder-2（本系統）：用 GPT-4o 合成 PDDL 運算子做高層規劃，加 Python 版謂詞與 Python 轉移函數做低層動態，實現 grounded 的抽象學習與跨環境重用。它與其他智能體不同處在於階層式建模世界（高層 PDDL 抽象 + 低層 Python 轉移）。
  • Oracle：用手寫抽象，作為比較學到抽象品質的參考。
  • 消融：TC-P（移除可執行抽象與 Python 世界模型，LLM 直接輸出抽象與高層計畫再轉動作，等同 CoT）；TC-C（移除課程學習，每 episode 從空白抽象與轉移函數開始）。

4.1 簡單環境的抽象學習與重用：Labyrinth、Maze、Sokoban 皆為導航式 VGDL 遊戲，主要涉及學與重用「移動到某位置」的抽象。Table 1 顯示：TheoryCoder-2 學到關鍵抽象並解出任務（LLM 將此運算子命名、對應抽象程式碼見內文 Box），且在 Maze、Sokoban 兩新環境重用。效率上，最樸素的 LLM+簡單規劃 在這些簡單環境最高效，TheoryCoder-2 次之，勝過 LLM+P 與 WorldCoder 兩個進階 LLM 智能體；所有系統都能解這些簡單題。

4.2 遷移到更難問題：在 BabyAI、Minihack 等更難環境，TheoryCoder-2 能解基線失敗的複雜任務，並以更低 token 成本展現顯著更高的樣本效率；學到的抽象跨環境遷移、即時 grounding、無需領域適配。消融（TC-P、TC-C）皆掉效能，證實可執行抽象、Python 世界模型、課程學習各組件的必要性。

5. 討論 / 7. 結論

TheoryCoder-2 解除了 TBRL 對手寫抽象的核心依賴：用 LLM 從經驗合成可重用 PDDL 抽象（高層）與 Python grounding（低層），整合進階層規劃並跨 episode 累積成長抽象庫。它比進階 LLM 智能體與程式合成智能體更樣本高效、能解更難任務，且只需最少人工 prompt，朝「會泛化的階層規劃」邁進，模擬了人類學習與抽象的關鍵演算法面向。
