3. 結果

3.1 Beam search 呈現反向或零擴展

Short-horizon 與 non-reasoning 模型上 beam search 展現一致的 inverse-scaling：beam size N 增大→正確率單調下降（Figure 1）。Short-horizon 模型（R1, QwQ-32B）在 N>2 時正確率急遽下降；non-reasoning 模型也有較溫和的下降趨勢。Long-horizon 模型（GPT-OSS-120B, Qwen3-32B）也無法從 beam 擴展中受益——正確率曲線持平或下降。由於總 token 消耗隨 beam 寬度增加，這是明確的 inverse compute scaling。

發現：Beam search 在 AIME/GPQA 等推理資料集上，效能隨 beam size 增加而下降或持平。

3.2 Trace 長度與品質的相關性

為理解 FFS/LFS 的長度假設（"短更好" vs "長更好"），依 trace 長度區間×問題難度報告正確率（Table 1）。關鍵考量是問題難度與 trace 長度混淆：短 trace 通常來自簡單問題、長 trace 對應困難問題。為緩解此混淆，僅分析同時有短和長 trace 可用的任務。

Short-horizon 模型（R1, QwQ-32B, DAPO-32B）：對給定難度，短 trace 比長 trace 更可能正確——"shorter is always better"。 Long-horizon 模型（GPT-OSS-120B, Qwen3-32B, R1-32B）：簡單題短好、困難題長好——"shorter is better for easy, longer is better for hard"。 Non-reasoning 模型（Qwen3-235B, DeepSeek-Chat）：也呈現 short-horizon 行為。 DAPO-32B 長度偏差程度接近 R1，DAPO 宣稱的 GRPO 偏差修正效果有限。

4. 分析

FFS-k@N 與 LFS-k@N 在不同 k、N 值上跨模型的行為（Figures 4-5）。

LFS 永遠劣於 MV：對 LFS 家族，最優效能總是在 k 大（即 k=N）時達成——而 k=N 就是 MV@N，消耗相同 tokens 但 LFS 用最長 trace 過濾一致降低正確率。

FFS 更細緻：對所有模型類型，k 增加時效能提升（同時消耗更多 tokens）；但對固定 k 的 N 行為不同。Short-horizon 模型上更大 N 總是最好的（更高效能、更少 token）；Long-horizon 和非推理模型則存在效能與計算的權衡——但調節方向相反：long-horizon 要縮小 N 換效能（等同 simple decoding）、非推理要放大 N。

5. 處方

決策矩陣（Table 2）：最優 TTS 策略取決於模型家族×計算預算的組合（與難度無關）。

Short-horizon：低預算 → FFS-k@N, k=1, N 大；高預算 → MV@N, N 大。因短 trace 永遠較好、FFS 隨 k 增加在正確率與計算成本上均改善、效能隨 N 增加而提升。

Long-horizon：低預算 → Simple Decoding；高預算 → MV@N, N 大。因 LFS@N 隨 N 改善、固定 N 時效能隨 k 增加、低預算下 N=k=1 即 simple decoding。有趣的是，雖然不同難度下的 trace 偏好不同（簡單題短好/困難題長好），最優策略最終與難度無關。

Non-reasoning：與 short-horizon 相同——低預算 FFS-1@N、高預算 MV@N。

發現：最優 TTS 策略與任務難度無關。

6. 結論

我們的大規模研究證明沒有單一最優 TTS 策略可增強 LLM 推理。最有效的方法取決於模型訓練方法、問題難度與可用計算預算之間的關鍵交互。不同模型家族展現不同行為：short-horizon 模型一致偏好簡短 trace、long-horizon 模型對難題受益於更長更慎重的推理（而簡單題偏好簡潔）。關鍵的是，beam search 對複雜推理一致證明為次優。我們的工作為從業者提供了實用框架，強調最大化效能需要對推論進行細緻的、模型感知的方法，而非通用策略。
