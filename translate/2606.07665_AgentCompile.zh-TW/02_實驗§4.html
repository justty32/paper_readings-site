實驗（§4）

設定：NVIDIA A800 SXM4 80GB；HuggingFace Transformers、FlashAttention-2、Triton、vLLM；Llama-3.2-1B/3B-Instruct、Qwen3-1.7B/4B（float16）；固定形狀貪婪解碼，輸入 128–40960、輸出 32–32768 tokens；編譯器管線 LLM 為 Claude-Opus-4.6。延遲含計時 prefill 與 decode，不含一次性準備（快取分配、attention 修補、擴展載入、暖機、CUDA Graph 捕捉）。兩次暖機 + 十次量測重複。

五個評估問題：(1) 編譯器控制管線是否完成區域到候選流程；(2) 混合執行期相較 PyTorch eager 的端對端延遲降低幅度；(3) 與 torch.compile 和 vLLM 的比較；(4) 逐步消融中各機制貢獻；(5) LLM 輔助最終組合對全系統影響。

§4.1 端對端延遲比較

模型 vs PyTorch eager vs vLLM
Qwen3-1.7B 5.66× 1.06×
Qwen3-4B 4.05× —
Llama-3.2-1B-Instruct 4.26× —
Llama-3.2-3B-Instruct — 1.07×

輸出長度增加時加速比更顯著：自訂 KV 快取緩衝、CUDA Graph 重播、特化 GEMV/融合核降低長自迴歸循環中的逐 token 開銷。PyTorch eager 則保留大量框架 dispatch 與動態快取開銷。torch.compile 在短輸入工作負載有效，但長輸入時計算與 KV 快取流量主導執行期，融合無法消除的開銷減少；圖中斷、動態快取更新與形狀變化進一步降低圖重用或引入重編譯。極長輸出時加速比逐漸降低：成長中的 KV 快取使 attention 成本日益主導，且此成本在各系統間差異較小。

與 vLLM 比較的說明：vLLM 最佳化分頁 KV 快取管理、請求排程與生產解碼執行，AgentCompile 聚焦編譯器選擇核、融合解碼元件、自訂 KV 快取緩衝與單請求 CUDA Graph 重播。兩者最佳化推論堆疊不同層次，比較衡量端對端執行期行為而非互斥策略；原則上生成/融合核元件可補充服務層級系統。

§4.2 消融研究（Qwen3-4B）

步驟 對前一步加速 累積加速
baseline (PyTorch eager + FA) 1.00× 1.00×
+ CUDALinear & GEMV 1.45× 1.45×
+ FAKV & fused QKV projection 1.02× 1.48×
+ CUDA Graph replay 2.06× 3.05×
+ LLM & fused kernels 1.33× 4.05×

CUDA Graph 重播為最大單一步驟（2.06×），消除重複 Python dispatch 與逐 token 啟動開銷。LLM 輔助搜尋 + 手寫 Triton/C++ 融合核貢獻額外 1.33×。全系統在五個工作負載上分別達 4.50×、4.37×、3.86×、4.31×、3.19× 加速。注意最後步驟綑綁 LLM 引導搜尋與融合核，未隔離 LLM 單獨貢獻。

編譯器管線統計

Llama-3.2-3B：192 IR 節點 → 34 區域 → 174 計畫/候選 → 174/174 驗證通過 → 34 選定核（延遲 7.78–13.97 μs），模板建議覆蓋全部 34 區域。Qwen3-4B：236 IR 節點 → 34 區域 → 174 候選 → 174 驗證通過（最大絕對/相對差異 0.00e+00）→ 34 選定核（7.46–14.00 μs），產出 7 檔案/43 簽名。確定性對照結果保留給後續消融。

相關工作（§5）

  • 神經網路編譯器：TVM、XLA、PyTorch 2、MLIR、Triton；AutoTVM/Ansor（自動排程）；ROLLER、Welder、TASO、DNNFusion、AStitch、Rammer。AgentCompile 互補：以 LLM 語意引導優先探索，不削弱編譯器確定性約束、驗證與量測。
  • 推論執行期與核：vLLM（分頁 KV 快取/排程）、ORCA、CUDA Graphs、FlashAttention。這些系統為評估提供效能背景。
  • LLM 用於程式碼與編譯器：Codex（評估 LLM 程式碼生成）、AlphaCode（競賽級程式碼）、StarCoder、Reflexion（語言代理反思）、NExT（教 LLM 推理程式碼執行）、KernelBench（評估 LLM 直接生成 GPU 核）。AgentCompile 關鍵區別：不讓 LLM 產生最終 CUDA 程式碼或依文字合理性選擇實作，LLM 僅形塑語意搜尋策略。

限制（§7）

AgentCompile 為原型。僅針對 transformer 推論區域，不受支援區域退回框架/函式庫路徑。LLM 引導是編譯器定義候選空間上的搜尋策略（可改善排序或提供語意假設），不保證最優實作。未來將探索更精細高效的 CUDA 核。
