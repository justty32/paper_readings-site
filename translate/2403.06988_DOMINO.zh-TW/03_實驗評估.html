4. 實驗評估

設定：在 Mistral 7B 與 Llama-2 13B 上評估，推理後端用 transformers 與 llama.cpp，硬體為 A100 40GB / H100 80GB。DOMINO 明確在離線設定評估（所有文法事先已知、不隨請求變化）。

資料集：以 GSM8K（數學推理）與 CoNLL-2003（命名實體辨識，取 400 筆測試）評估下游準確率；並以 JSON、帶 schema 的 JSON、C 程式語言、帶 schema 的 XML 及靜態 regex 模板等任務比較相對無約束解碼的開銷。基線：無約束生成、guidance 程式（模板式與對空白不敏感的 CFG 式 WS）、llama.cpp 的 EBNF 文法（代表線上解析法）。

4.1 任務準確率（表 2）

DOMINO 在所有任務上取得最佳準確率，同時吞吐量遠超無約束生成。DOMINO 的準確率相對無約束皆持平或提升，顯示極低或零侵入性。反觀標準 guidance 有明顯侵入性痕跡，準確率最多掉 11 個百分點；guidance 的優化雖能提吞吐（最高 2.02×），DOMINO 更快（最高 2.71×）且維持高準確率。改用彈性空白的 guidance WS 能救回部分準確率但不完全，且吞吐降到約 0.8×；llama.cpp 的線上解析也非完全非侵入（準確率受損較輕），吞吐同樣降到約 0.8×。

代表數據（Accuracy / 相對吞吐）：

資料集 / 模型 無約束 guidance llama.cpp DOMINO (k=∞)
GSM8K / Mistral 7B 0.415 (1.0×) 0.345 (0.98×) 0.375 (0.80×) 0.418 (1.77×)
GSM8K / Llama-2 13B 0.262 (1.0×) 0.152 (1.12×) 0.237 (0.86×) 0.262 (1.66×)
CoNLL2003 / Mistral 7B 0.21 (1.0×) 0.098 (2.02×) 0.117 (0.80×) 0.21 (2.66×)
CoNLL2003 / Llama-2 13B 0.09 (1.0×) 0.062 (2.18×) 0.080 (0.86×) 0.09 (2.71×)

（guidance 在 CoNLL2003/Llama-2 準確率 0.062 vs 無約束 0.09，掉幅顯著；DOMINO 完全還原無約束準確率。）

4.2 參數研究

前瞻 k（表 4）：k 值過低會顯著損害表現。人工檢視發現 k 太小時模型被逼入不同的空白行為（如 }, 這類橋接 token 不可用導致格式異常），甚至使 Llama-2 無法生成長度大於 1 的物件列表。Mistral 7B：k=0 為 0.308、k=1 為 0.1、k=∞ 為 0.418（略超無約束 0.415）；Llama-2 13B：k=0 為 0.0、k=1 為 0.036、k=∞ 為 0.157（無約束 0.155）。k=∞ 完全還原並略超無約束準確率，印證最小侵入性。

推測與機會式遮罩：對 schema 驅動的 JSON，推測解碼（s∈{6,8,10}）特別有效，達到相對無約束 1.7× 吞吐；但對自由形式 JSON 推測無效，改用機會式遮罩較佳，僅 4.21% 開銷。

4.3 效率（表 3）

DOMINO 明顯降低推理時約束的計算負擔，顯著勝過 guidance 與 llama.cpp 的線上解析。對結構可預測的文法（如 schema 驅動格式），推測解碼特別有效，吞吐比無約束生成高出最多 77%（1.77×），且仍最小侵入。代表數據（相對無約束吞吐，DOMINO 取「機會式遮罩或推測解碼中較佳者」）：

文法 / 模型 llama.cpp CFG guidance CFG DOMINO
JSON （無 schema） / Mistral 7B 0.79× 0.88× 0.96×（機會式）
JSON (GSM8K schema) / Mistral 7B 0.80× 0.99× 1.77×（推測 s=10）
C 程式語言 / Mistral 7B 0.74× 0.41×* 0.78×（機會式）
XML （帶 schema） / Llama 13B 0.87× 0.98× 1.84×（推測 s=10）
固定模板 / Llama 13B 0.69× 0.99× 1.91×（推測 s=10）

C 程式碼生成開銷最大（C 文法最複雜、推測解碼因難以用簡單計數模型預測而無益），但靠機會式遮罩仍以 0.78× 勝過 llama.cpp 的 0.74×。文法預計算時間未計入吞吐，範圍約 1–5 秒（C 為離群值約 20 秒）。

5. 結論

作者論證了對「最小侵入、高效率」約束解碼方法的需求，並提出 DOMINO 作為針對文法約束的首個實例。DOMINO 結合預計算、推測解碼與機會式遮罩，實現最小侵入約束（無準確率損失）、常常零開銷甚至更快的生成，因而達成高吞吐推理。
