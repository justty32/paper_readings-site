IV. 實驗

目標：(i) 評估階層式程式碼生成的影響並分析泛化模式；(ii) 在模擬語言指令操作任務比較 CaP 與基線；(iii) 在不同機器人系統展示 CaP 的靈活性。定量評估限於 IV-D 的模擬任務，IV-B/C/E 為無定量指標的能力展示。

IV-A 階層式 LMP 於程式碼生成基準

RoboCodeGen（本文新提 37 題機器人主題函式生成基準）：機器人主題（空間/幾何推理、控制）、鼓勵用第三方函式庫、函式標頭無文件字串/型別提示、允許用尚未定義函式（可靠階層式生成建立）。在四款模型（GPT-3 6.7B/175B、Codex cushman/davinci）上，評估指標為通過人工單元測試的百分比。

表一（RoboCodeGen pass rate，%）：

方法 GPT-3 6.7B GPT-3 175B Codex cushman Codex davinci
Flat 3 68 54 81
Hierarchical 5 84 57 95

Hierarchical 全面優於 Flat，且符合 scaling law（模型越大表現越好）；依五種泛化類型分析，Hierarchical 對「Productivity」（新指令需更長/更多邏輯層的程式碼）幫助最大，但此增益只在兩個 davinci 模型出現，cushman 沒有，暗示需先達到一定程度程式碼生成能力，階層式生成才能帶來進一步改善。

表二（HumanEval pass rate，%；Greedy 為 temperature=0；P@N 為 temperature=0.8 下 N 樣本正確率）：

方法 Greedy P@1 P@10 P@100
Flat 45.7 34.9 75.1 90.9
Hierarchical 53.0 39.8 80.6 95.7

階層式程式碼生成不僅改善策略程式碼，也改善通用程式碼，數值高於近期相關工作。

IV-B/C/E CaP 於真實機器人（能力展示，無定量指標）

IV-B 畫圖：真實 UR5e 手臂透過生成/跟隨 2D 路徑點繪製形狀，用四個 LMP（解析指令與維持會話、解析物件名稱、解析路徑點、生成新函式），感知用 MDETR。能引出空間推理繪出新形狀，也能解析精確尺寸、操縱先前形狀、處理多步指令。 IV-C 抓放：真實 UR5e 手臂搭配吸盤夾爪與腕上相機做桌面抓放，感知經 MDETR，動作靠腳本化抓放原語，展示歷史指代（「撤銷那個」）、幾何/空間描述（「最小的」「最右邊的」）推理。 IV-E 移動機器人：具移動底座與 7 自由度手臂的機器人在真實廚房做導航與操作，感知經 ViLD，展示跨系統/跨 API 部署、長程反應式指令、精確空間推理能力，是先前工作難以做到的。

IV-D CaP 桌上型操作模擬評估

沿用先前工作 8 個「長程」任務（如「把積木放進配對的碗」），新增 6 個需精確空間幾何推理的任務（如「排成對角線」）。任務指令（I）/屬性（A）各分「已見」(S)/「未見」(U)。基線：(i) 3 萬筆示範模仿學習訓練的 CLIPort，(ii) 用自然語言（非程式碼）少樣本提示的 LLM 規劃器。

表三（50 次試驗成功率，%，擇要）：

Train/Test 任務族 CLIPort NL Planner CaP
SA SI Long-Horizon 78.80 86.40 97.20
SA SI Spatial-Geometric 97.33 N/A 89.30
UA SI Long-Horizon 36.80 88.00 97.60
UA SI Spatial-Geometric 0.00 N/A 73.33
UA UI Long-Horizon 0.00 64.00 80.00
UA UI Spatial-Geometric 0.01 N/A 62.00

CaP 在已見任務上與監督式 CLIPort 相比具競爭力（僅用一個示範 rollout 提示）；未見屬性時 CLIPort 明顯下滑，LLM 系方法維持相近；未見任務+屬性時端到端 CLIPort 難以泛化，CaP 優於純自然語言 LLM 推理；自然語言規劃器不適用於需精確數值空間幾何推理的任務（N/A）。附錄另示用程式碼推理相較自然語言推理（含 CoT）在精確數值運算上的優勢。

V. 討論與限制

CaP 在機器人堆疊的特定層次泛化：解讀語言指令、處理感知輸出、為控制原語低維輸入賦參數。適合分解式感知/控制系統，賦予一定泛化能力而不需端到端學習所需的資料量。也繼承與寫程式碼無關的 LLM 能力（非英語語言、表情符號指令），並能表達跨具身計畫（依可用 API 不同、以不同方式完成同一任務），但此能力在現有 LLM 上仍脆弱，可能需要在領域專用程式碼上訓練的更大模型。

CaP 受限於：(i) 感知 API 能描述的範圍（目前無視覺語言模型能描述軌跡是否「顛簸」或「更呈 C 形」）；(ii) 可用控制原語的範圍，只有少數具名參數可調而不使提示過度飽和。CaP 難以解讀明顯更長、更複雜、或抽象層級與 Examples 不同的指令（如桌上型領域「用積木蓋房子」，因無蓋複雜 3D 結構的示範）。本方法也假設所有指令皆可行，且無法事先判斷回應是否正確。
