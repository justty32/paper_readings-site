論文／訪談原始來源

AGDecode：以屬性文法導數約束語意安全

摘要與第 1 節：研究問題

語法約束解碼只允許能接成合法語法的 token，卻不保證產生的程式符合型別或資料相依的安全條件。AGDecode 用屬性文法描述語意，將未完成語法樹的語意可實現性轉成關係約束，交給 SMT 或受約束 Horn 子句（CHC）求解器；作者的理論健全性與完整性相對於理想驗證 oracle 成立。（PDF 第 1–3 頁，摘要與 §1）

實際求解器可能回傳未知或逾時。保守處理可拒絕尚未證偽、可能有效的 token；推測式處理則先允許繼續，必須等待後續驗證才能對整段前綴作結論。（第 3 頁，§1）

第 2 節：背景

對語言 L 與字元 c，導數 ∂c(L) = {w | cw ∈ L} 表示讀入 c 後可接續的字串集合。語法監視器在導數非空時接受下一輸入；語意監視器還要求存在滿足指定性質的完整續寫。屬性文法把類型、作用域或狀態等屬性與語法節點及產生式關聯，藉此表達超越語法形狀的規則。（第 3–5 頁，§2）

第 3 節：方法概觀

作者將未生成的語法節點表示為孔洞，每個孔洞代表所有可由對應非終結符展開的可能樹。語意規則以關係約束連結節點屬性；給定部分樹與頂層安全要求，查詢是否存在能填滿孔洞並滿足約束的完成樹。這把語言規格與實際求解技術分開，並可使用外部 SMT／CHC 引擎。（第 7–10 頁，§3）

第 4–6 節：部分樹、導數與求解

殘餘屬性文法在部分樹上定義聲明式語意；隨生成推進，孔洞縮小或具體化。字元導數處理尚未完成的詞法片段，並以結構選擇變數及守衛關係連結候選產生式；全域結構一致性條件避免求解器把不相連的推導拼成一個看似有效的解。（第 11–16 頁，§4–5）

第 16 頁定理 5.6 表述：若新前綴的導數約束經 oracle 判為不可滿足，則沒有以該前綴開頭且符合頂層語意規格的完整樹。定理 5.7 表述：若完整樹符合頂層規格，其產生字串的每個前綴之導數約束皆可滿足。這是相對理想 oracle 的模型內健全性與完整性，不等於現實求解器對每個查詢都能及時判定。（第 16 頁，§5.3）

作者將殘餘約束編譯為一階關係與 CHC，以遞迴關係表示語法與屬性，利用求解器尋找關係不變量處理遞迴和無限續寫。語意規格及其背景資料理論仍決定可表達和可驗證的性質。（第 16–18 頁，§6）

第 7.1–7.2 節：C 安全案例與實驗

案例關注三種路徑敏感的未定義行為：空指標解參照、除以零與存取未初始化變數。系統追蹤變數和路徑條件，但作者明確說未納入完整記憶體模型，因此這不構成對任意 C 程式的完整記憶體安全保證。實作以 Python 建立 CHC，輸出 SMT-LIB v2，交由 Z3 Spacer 求解。（第 19 頁，§7.1–7.2）

測試選自 MultiPL-E 的 HumanEval C++ 子集：將介面轉為 C 後，選出 77 個偏重記憶體與指標存取、排除浮點的題目。使用 CodeLlama-13B，在溫度 0.3、0.5、0.7 下生成；每個求解查詢限時 5 秒。實驗採推測模式，未知或逾時先視為可繼續，並非當下已驗證。（第 19–20 頁，§7.2）

作者舉例，在一個陣列存取前保留 assert(arr) 的前綴可通過檢查；移除該斷言後，監視器會拒絕後續 [。這是個案說明，不是全測試集成功率或完整功能正確性數據。（第 20 頁，圖 6 與 §7.3.1）

第 7.4–9 節：限制與結論

作者指出，保證受提供的文法和規格限制，而手寫規格可能出錯；實驗未實作回溯，推測接受後若後續查詢否決，還需決定應替換哪些 token。求解不完整或逾時帶來拒絕有效輸出或暫時接受未驗證輸出的取捨；細粒度查詢也有顯著延遲。強制遮罩可能改變模型輸出分布與生成品質。（第 22 頁，§7.4）

作者將此方法與以共歸納方式裁剪程式空間的 ChopChop 作概念比較，指出兩者對資料相依可達性和結構表示的取捨；本文沒有在所選 C 路徑安全案例上提供對 ChopChop 的直接實驗比較。作者將主動引導及回溯列為未來工作。（第 22–25 頁，§7.5–9）
