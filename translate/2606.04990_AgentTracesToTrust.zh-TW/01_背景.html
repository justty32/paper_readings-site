摘要

LLM agent 已從文字生成器變成會規劃、檢索、使用工具、讀寫記憶、操作環境與協作的執行系統。Final answer 不能回答輸出如何產生、claim 由何證據支持、tool call 是否正當、memory 如何影響後續，或 failure 從哪一步進入。

本文把 execution provenance 定義為一次 agent execution 的完整 typed graph，把 evidence tracing 定義為它在 evidence-support relations 上的 projection。作者提出六維 taxonomy，綜整 provenance representation、evidence attribution、tool-use provenance、runtime guardrails、provenance-bearing memory、observability 與 failure diagnosis，並列出 schema、semantic provenance、safety、benchmark、recovery 與 privacy 的開放問題。

1. 引言

Agent trace 是執行中產生或消費的 artifacts：instruction、query、document、tool call／output、memory operation、observation、claim、inter-agent message、action 與 response。Traceability 使其可檢視；provenance 再加入 typed dependencies。

Execution provenance 是 process view；evidence tracing 是 support view。這個區分讓 RAG grounding、工具安全、記憶 lineage、graph representation、observability 與 failure analysis 能在同一框架討論。

本文只納入明確記錄、表示、限制、評估或診斷中間 evidence／execution artifacts 的工作。它不是對所有 RAG、memory 或 agent literature 的全面系統性回顧。
