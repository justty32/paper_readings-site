2. 證據追蹤與執行來源 taxonomy

2.1 六個維度

Trace sources 包含 reasoning、retrieval、tool／MCP boundaries、memory、environment 與 multi-agent communication。

Evidence units 是可能支持、反駁、使 claim 失效或提供脈絡的物件，例如 passage、observation、tool output、memory、claim、policy。Execution units 是系統做過的程序性動作，例如 retrieval、tool invocation、arguments、memory reads／writes、environment action 與 message。同一 tool output 可同時是 execution result 與後續 evidence。

Relations 保留 W3C PROV 的 Use、Generate、Derive，並加入 Support、Depend-on、Contradict、Invalidate、Trigger、Update。Granularity 從 run、step 到 parameter、claim、token；timing 可在執行前、runtime、事後或持續進行。Representation 可是 structured log、execution／evidence／claim-support graph、完整 provenance graph 或 runtime state。Trust functions 包含驗證、歸因、除錯、安全強制、稽核、failure attribution 與 recovery。

2.2 設計張力

細粒度 provenance 支援 claim verification、argument-level safety、rollback 與 audit，代價是儲存、instrumentation、annotation 與 privacy。完整 trace 與選擇性記錄也有衝突：少記會失去因果鏈，多記可能保存敏感內容與 reasoning artifacts。另一張力是 post-hoc explanation 與 runtime enforcement；前者可較豐富，後者必須低延遲且確定。

3. 表示與證據歸因

3.1 從 log 到 execution graph

Structured log 保存事件順序與 metadata。W3C PROV-DM 提供 entity、activity、agent 與 derivation；OpenTelemetry 提供 trace／span；AgentOps、AgentTrace 等開始記 agent artifacts。然而 log 只說 retrieval、tool call、memory write 曾發生，不一定說哪個 passage 支持哪個 claim，或哪個 output 改變 plan。

Execution graph 把 artifact 變成 nodes，把依賴變成 typed edges，因此能做 step、component、agent 或 error-mode localization。簡言之，log 回答 what happened，graph 回答 what depended on what。

3.2 Claim support

引用存在、來源相關與 claim 受支持是不同關係。Evidence graph 應分開 Cited、Support、Contradict、Omitted 與 Invalidate。Agent evidence 不只 document，也包含 tool output、memory、environment observation、policy 與 message。

3.3 表示取捨

Static schema 定義 objects、relations、trust labels 與 required fields；runtime provenance 在一次具體執行中實例化。低風險 RAG 可用 claim-level post-hoc links，高影響工具需 parameter-level runtime lineage，長期個人 agent 則需 memory update／invalidation／recovery。

4. 工具型 Agent 的執行來源

4.1 Tool call、argument 與 output

需記工具為何被選、arguments 從何而來、output 是否可靠、流向哪些後續 consumers。工具本身合法不代表呼叫合法；敏感度往往落在 recipient、path、query 或 amount 等 argument。

4.2 間接提示注入

網頁、文件、郵件、資料庫與 API 回傳可能把 data 偽裝成 instruction。Provenance 問題不是只偵測惡意文字，而是判斷該 source 是否影響 tool argument、memory update 或 privileged action。Flat log 看得到先讀網頁後寄郵件，卻未必知道 recipient 來自使用者還是網頁。

4.3 資訊流與 taint

Instruction hierarchy、結構化 channel、control/data separation、IFC、semantic taint 與 argument lineage 都在處理 low-integrity source 到 sensitive sink 的流動。安全取決於 value 的 origin 與 use，不只內容。

4.4–4.5 存取邊界、guardrail 與驗證

Least privilege 與 complete mediation 要求每次作用在使用點檢查。Capability 限制能接觸的工具／資源；provenance policy 再決定這次 action 應放行、限制、請人確認或拒絕。執行前驗證 arguments，執行後驗證 effect；只有 intent 或模型自述都不夠。

5. 記憶作為帶來源的證據

Memory write 應保存原始 source、time、writer、transformation 與 trust；retrieval 應記 query、ranking、被選 item 與使用位置。舊記憶可能與新 observation 衝突，或因 poisoning 跨 session 延續。系統需要 revision 與 invalidation，並能找出依賴已失效 memory 的 downstream claims／actions。

多 agent 中，memory 與 message 也要保存 sender、delegation、verification、transformation 與 responsibility。另一 agent 的摘要不是原始證據，不能在轉傳後自動升格。
