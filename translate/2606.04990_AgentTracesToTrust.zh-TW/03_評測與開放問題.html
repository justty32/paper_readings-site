6. Benchmarks、datasets 與 metrics

RAG benchmark 強在 evidence labels；tool benchmark 強在 calls／state；memory benchmark 強在 recall；multi-agent 與 trace-debugging 各自測協作與 fault localization；security benchmark 測 attacks／policy。沒有一個 family 同時完整涵蓋 evidence、tools、memory、messages、attacks、typed relations 與 recovery。

三個主要缺口是 cross-component chain、relation annotation 與 recovery evaluation。成熟 metrics 有 citation precision、faithfulness、ASR、policy violation；trace completeness、provenance accuracy、dependency coverage、temporal consistency 多半仍未形成共識。Recovery 則應測 invalidate、quarantine、retry、rollback、approval 與 compensation 是否成功。

Full-stack benchmark 至少要保存 request、retrieval、tool call／output、memory operation、message、claim、response、external state 與 permission context，並標註 Support、Contradict、Depend-on、Update、Invalidate、Trigger。

7. 開放問題

7.1 統一 schema

W3C PROV、OpenTelemetry、OpenLineage 與 agent observability 都是部分基礎。缺少的是把 operational trace 與 claim／evidence／memory／argument 的 semantic relations 接起來，並支援跨框架 replay、audit 與交換。

7.2 Semantic provenance

Evidence 會被 paraphrase、aggregate、summarize、寫入 memory、通過工具或由另一 agent 重述。Citation 與 string match 無法追這些 transformation；需要 semantic influence 與 claim-level relation。

7.3 Memory 與多 agent

Memory 應有 source、write time、update history、retrieval context、downstream use、conflict、invalidation。多 agent provenance 還需把 message propagation、delegation、responsibility、verification 與 recovery 接到同一圖。

7.4 Runtime recovery

只 block 不夠。發現污染後應定位 source、移除錯誤 argument、阻止寫入 memory，或從安全 checkpoint retry。新證據推翻 memory 時，也應使所有依賴它的 claims／actions 可追蹤並重算。

7.5 Privacy 與 governance

Trace 會包含私人文件、credentials、arguments、記憶與內部 artifacts。Provenance infrastructure 本身需 data minimization、access control、anonymization、retention、encryption 與 selective disclosure，且要證明 traces 可稽核、符合政策、可比較。

8. 結論與範圍

可信 agent 需要的不只是更豐富的 logs，而是可互通 schema、semantic attribution、memory／multi-agent lineage、runtime enforcement、recovery 與可評估的完整 trace。本文提供的是研究地圖與設計 vocabulary，不是實作或量化驗證；文獻選擇也採聚焦式敘事回顧，未提供系統性回顧的檢索流程與統計。
