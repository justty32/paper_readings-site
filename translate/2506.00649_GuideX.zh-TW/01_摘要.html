摘要

資訊抽取（IE）系統傳統上高度領域相依，需要昂貴的調適過程：專家設計 schema、資料標註、模型訓練。雖然大型語言模型在零樣本 IE 上展現潛力，但在標籤定義不同的未見領域中效能會顯著下滑。本文提出 GuideX，一個能自動定義領域專屬 schema、推斷指引（guideline）、並生成合成標註實例的新方法，藉此改善跨領域泛化。用 GuideX 微調 Llama 3.1，在七個零樣本命名實體辨識（NER）基準上刷新 SOTA。以 GuideX 訓練的模型在無人工標註資料的情況下，較先前方法最多提升 7 個 F1 點；與人工標註資料結合後再高出近 2 個 F1 點。以 GuideX 訓練的模型也展現出對複雜、領域專屬標註 schema 的更佳理解。程式碼、模型與合成資料集公開於 neilus03.github.io/guidex.com。

1 引言

IE 任務環繞兩個核心組件：一個指定目標實體/關係的正式 schema，以及定義其詮釋方式的人類可讀指引。適應新領域需要大量資源：(1) 領域專家設計 schema 與標註規則，(2) 訓練有素的標註員照規則標資料，(3) 機器學習專家開發高效能模型。此一複雜流程在標籤定義頻繁變動的實務場景中形成瓶頸。

早期消除標註資料需求的嘗試（零樣本 IE）把任務框架成問答或自然語言推論範式，借用這些輔助任務的監督資料，但仍受限於人工設計 schema、跨領域泛化有限。近期利用 LLM 的進展簡化了 schema 定義流程，但當部署到標籤語意與訓練分布不同的未見領域時，效能落差依然存在。本文的做法是自動化生成領域專屬 schema、指引與標註資料，以彌合「已見／未見領域」的落差。

資料增強與合成資料生成在 LLM 時代格外有價值。在 IE 領域，傳統的遠距監督（distant supervision）雖能提高召回率，卻常因依賴不完美的啟發式而產生偽標籤（spurious label）雜訊；LLM 蒸餾（大模型教小模型）則受限於教師模型能力上限，且往往無法涵蓋所有有效實例。兩種技術都需要預先定義的標註 schema，嚴重限制其對標籤定義可能變動之新領域的適應力。

本文引入 GuideX，一個受領域專家工作方式啟發的新資料生成方法，旨在為任意新領域生成 schema、指引與標註範例，藉以提升在新領域及未見領域上的 IE 效能。整體方法含四個依序步驟：給定目標領域的一組文件，先用 LLM 找出每份文件的關鍵資訊，摘要並整理成條列式重點；接著把抽出的資訊結構化為標準格式（通常是 JSON）；然後要求模型根據前述結構化標註生成標註 schema 與對應指引——這確保標註與指引彼此對齊、且完整；最後要求模型依照標準的程式碼風格格式生成最終標註。

用此方法生成的合成資料微調 Llama 3.1 基礎模型後，在七個零樣本 NER 基準上平均提升 10 個 F1 點；把此資料用於強化既有 SOTA 方法時，在同一批基準上再取得近 2 個 F1 點的提升，建立新 SOTA。

2 相關工作

LLM-Based IE：近期 IE 研究愈來愈多借助 LLM 處理 NER、關係抽取（RE）、事件抽取（EE）的零樣本與少樣本設定，透過提示或微調引導模型抽取相關片段。InstructUIE、RUIE 等方法把 IE 表述為指令遵循或檢索式生成任務。另一支線強調 schema 與指引導引策略（如 GoLLIE、KnowCoder），證明提供精確的標註定義與範例能顯著改善零樣本 IE 表現，但這類方法通常仰賴費時的人工指引撰寫，難以隨新任務/領域擴充。

IE 的合成資料生成：遠距監督是最早的合成標籤形式之一，但因實體共現不必然代表關係成立而易生標籤雜訊；後續工作雖引入多實例多標籤學習與去噪啟發式，但仍多依賴僵固的預定 schema。UniNER、KnowCoder 等利用 LLM 生成符合特定標籤 schema 的訓練實例，但結果可能出現風格重複、領域錯位或 schema 遵循不一致的問題。另有以 V-information 等資訊理論準則挑選/加權合成樣本、或以 Snorkel 式資料編程結合提示做弱監督（如 PromptRE）的工作，但同樣預設 schema 已知。GuideX 的定位是整合 schema 驅動與合成資料兩條路線，同時解決多樣性與雜訊控管的關鍵限制，動態為每份文件建構 schema 與指引，再合成與之對齊的標註文字。

3 GuideX：引導式合成資料生成

GuideX 不同於仰賴預定義標註 schema 的傳統 LLM 蒸餾或遠距監督，而是動態推斷標註 schema，藉此降低標註不一致、提升跨 IE 任務彈性、實現高品質、由指引驅動的標註。整體流程含四個依序步驟：文件摘要、結構化表示合成、標註指引生成、實例抽取。先前研究顯示 LLM 在零樣本情境下難以一步到位完成整個 IE 任務，因此本方法用漸進式、多階段的過程逐步精煉原始文字。

文件摘要：管線第一步聚焦辨識文件中最重要的概念。LLM 生成一份摘要凸顯關鍵重點，有效辨識相關實體與事件並整理抽取到的資訊。不同於依賴預定義標註 schema，這一步讓模型自主判斷哪些元素相關，帶來更多樣、更貼合領域的標註。（論文以一篇討論機器學習框架的文章為例，模型成功辨識出 TensorFlow、PyTorch 兩個框架及其開發者、特色等相關細節。）

結構化表示：第二步結合前一步摘要與原始文件，把抽取資訊整理成結構化 JSON 格式，同時對抽取片段施加「盡量精簡但保留完整意義」的長度約束，確保資訊既可解讀又便於後續機器處理。

指引生成：標註指引透過確保一致性、降低歧義，對改善零樣本 IE 效能至關重要，但人工撰寫此類指引十分複雜，需針對不同領域定義精確規則。GuideX 依據結構化 JSON、文件摘要與原文，動態生成標註指引：模型自主為每個實體類別推導完整描述，確保所有相關屬性都被清楚捕捉。每個生成的指引都被表述為一個 Python dataclass，將該實體類型詳盡的文字描述內嵌於類別 docstring 中；實體的預期屬性也被明確定義，每個欄位都附上說明其含義與預期格式的註解。以此方式建構標註 schema，模型產出的是標準化、可解讀的資訊表示。與可能受限於固定範疇的靜態標註指引不同，每份文件都會拿到與其內容精確對齊的量身訂做指引；把這些指引編碼為 Python 程式碼，也維持了高度的結構一致性。

實例抽取：管線最後一步是抽取指引中定義的實體與屬性的具體實例。模型利用結構化 JSON 表示與推斷出的標註 schema，用直接取自原始文件的具體值填入實體類別，確保抽取實例嚴格遵守預定結構、忠於原文。實作上，模型生成一個 Python list，每個元素對應指引生成步驟所建的某個 dataclass 的一個實例；每個實例都用簡潔的值（優先取單詞或短語而非冗長描述）填入，模型被明確要求只回傳結構化實例，不附加任何解釋文字。

一致性驗證與過濾：GuideX 藉由把標註指引與抽取實例都結構化為可執行的 Python 程式碼來提升合成資料的可靠性，從而能做自動化驗證以偵測幻覺與不一致。一套一致性檢查機制會系統性地執行資料集中的每個條目，標記出未定義實體型別、屬性不對齊等邏輯錯誤；一支自動化過濾腳本會捨棄不合規標註，只保留符合 schema 的部分，顯著降低偽關係與標註雜訊。這套結構化驗證流程確保了與指引對齊、高品質的合成資料，帶來更穩健、更可信的 IE 模型。
