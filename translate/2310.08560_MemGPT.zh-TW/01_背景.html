摘要

LLM 受限於有限 context window，妨礙長期對話與文件分析。本文提出 virtual context management，靈感來自傳統 OS 的階層式記憶體：OS 在 physical memory 與 disk 間 paging，讓程式看見更大的 virtual memory。

MemGPT（MemoryGPT）管理不同 storage tiers，在有限 context 內提供延伸 context。作者在兩個領域評估 OS-inspired design：文件分析中，MemGPT 處理遠超底層 LLM context 的資料；multi-session chat 中，agent 能在長期互動裡記憶、反思並動態演化。

1. 引言

直接延長 transformer context 會增加 self-attention 的時間與記憶體成本；即使 context 裝得下更多 token，模型也未必能有效使用中段資訊。作者因此研究如何在固定 context model 上提供「近似無限 context」的幻象。

Virtual memory 讓應用處理超過 RAM 的資料，方法是由 OS 在 RAM 與 disk 間搬移 pages。MemGPT 將 LLM context window 類比為 physical/main memory，將 databases 類比為 disk。隨 function-calling 能力成熟，LLM agent 可以讀寫 external sources、修改自己的 context，並決定何時回覆使用者。

Function calls 還能在同一 user request 中反覆修改 context：搜尋一頁資料、讀結果、再搜尋下一頁，直到取得足夠資訊。記憶階層、functions 與 event-based control flow 因而共同支援超出固定 window 的任務。

這裡的「LLM OS」是架構類比。MemGPT 沒有實作 process isolation、hardware abstraction、preemptive scheduler、capability enforcement 或 crash recovery；實際系統是 LLM agent 加 queue manager、function executor 與 external databases。
