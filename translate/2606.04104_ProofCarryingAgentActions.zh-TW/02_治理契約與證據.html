5. Proof-Carrying Agent Actions

5.1 邊界與流程

PCAA 不是 replacement runtime。外部 runtime 或 governor 可以就近 enforcement 並產生 receipts，但 tenant-visible certificate 負責 admission、approval 與 proof closure。

五個 checkpoint 對應 SDK：guard 在副作用前路由；createAction 建立 trust object；recordAssumption 保存當時所信條件；waitForApproval 暫停；updateOutcome 寫入結果與證據。

5.2 Externality-aware admissibility

Route 評估的不只是 action label，而是 action 加 boundary facts。Externality 包括 destination type/visibility/ownership、destination tenant、account/client provenance、外部寫入、敏感 payload、可逆／破壞性，以及 approval enforceability。同一工具動作若寫入公開目的地、使用個人帳號或不可逆，其治理路徑應不同。

6. Neutral Runtime Contract

Runtime 被投影成 family、adapter mode、execution boundary、authority split、session projection 與 receipt projection。只要 vendor 不同但能映射到共同語彙，便可比較治理狀態。

Families 包含 OpenAI-compatible gateway、managed platform、framework SDK、tool-hook、observer/import-only。Adapter modes 的控制深度依次包含 inline SDK、lifecycle hook、session adapter、gateway、bridge、observer。前兩者可強介入，observer 只有弱 post-hoc visibility。

Authority 分 workspace、runtime、external governor。Workspace 管 tenant、approval、replay 與 closure；runtime 管真正工具執行與 native trace；external governor 可在 pre-input、pre-tool、post-tool、pre-output enforcement。Receipts 可被吸收，但最終 authority 不因此轉移。

Approval enforceability 分 pre-execution gate、observe-only、delegated runtime control、runtime-controlled。這讓稽核者區分真正 fail-closed gate 與事後有紀錄而已。

7. Portable Action Envelope 與責任

Envelope 保存 action identity/goal、tenant/agent、runtime/adapter、boundary、authority、authorization、workflow、evaluation、externality、accountability、trace 與 partner inputs。

Authorization 指 allowed systems/actions、data domain、escalation 與 human review。Workflow 指 business process 與 stage。Accountability 記 requested-by、policy owner、runtime owner、final authority、approver lineage。Externality 則回答使用誰的 account、哪個 client、寫到何處、是否可逆。

Assumption capture 是必要 checkpoint。若沒有保存決策當時相信的條件，後續 replay 只能顯示歷史 status，不能解釋當時為何准許。

8. Proof、Replay 與 Integrity

Proof bundle 包含 summary、evidence、verification state 與 canonical manifest。Replay 重新計算 envelope、risk result、policy snapshot 與 manifest，檢查 missing evidence、digest mismatch、policy drift、risk drift，而非只載入舊 JSON。

未執行也要有 proof：execution、pending execution、partial execution、non-execution 四類。Receipt completeness 則用 expected 與 observed stages 的交集比例表達，避免把 partial evidence 說成完整 enforcement。

Integrity 分 fast commitment、portable trust material、future verification。Chain receipt、wallet attestation、transport receipt 都只是相鄰信任材料，不能替代 PCAA closure。現階段「proof」應理解為可重播稽核 artifact 與完整性檢查；更強密碼學證明尚在未來。
