9. 實作概觀

Reference SDK 具體提供 guard → createAction → recordAssumption → waitForApproval → updateOutcome lifecycle。周邊 API 產出 proof bundle、replay state、health summary、runtime inventory、buyer assurance 與 connector posture。

實作明確區分 inline、hook、gateway、bridge、session、observer coverage，不把 imported evidence 當成 inline interception。示例涵蓋 smoke test、support triage、release gate，分別展示低風險連線、帶 assumptions 的 workflow routing、production approval gate。

10. Public Validation Protocol

Raw corpus 不公開。24 executable seeds 跨 framework SDK、gateway、managed platform、observer/import-only 四 family replay，形成 96 traces；decision buckets 為 allow 24、simulate-first 20、require-approval 28、block 24。

Static rules 的 exact accuracy／macro-F1／severe recall／block precision 為 0.583／0.493／1.000／0.400；scalar heuristic 為 0.375／0.296／0.778／0.182；PCAA 四項都是 1.000。作者提醒 perfect score 只代表此 protected benchmark 與 route semantics 一致，不表示治理已解決。

PCAA 將 29.2% 送 review、20.8% simulate-first、25.0% block。Manifest 與 replay 為 1.0，receipt completeness 只有 0.516，原因是 corpus 故意混合強 inline 與弱 observer。平均 latency 0.35 ms、P95 0.54、P99 0.72。

移除 externality 後 accuracy 0.875、review 0.167；移除 enforceability 後 accuracy 0.917、review 0.375；移除 integrity 對 routing 無影響，但 manifest stability 變 0、proof closure 降到 0.708。

11. 討論與結論

PCAA 的新意是架構性：heterogeneous runtime normalization、selective review、externality、replay 與 integrity 都繫在決策當下的同一 certificate。它不是 rule table，也不是 LLM judge；即使底層模型或 runtime 改變，certificate 應保留可讀的 authority、approval 與 closure。

證據仍很有限。Benchmark protected 且由實作者自己建構，無法讓第三方重算；弱基線與完美成績不足以證明 production 優勢。不同 adapter 的真正控制能力也不相等。PCAA 最可信的主張不是「已證明 action 安全」，而是「提供一個穩定 schema，誠實保存誰以何種控制深度准許何種動作，以及事後有哪些證據」。
