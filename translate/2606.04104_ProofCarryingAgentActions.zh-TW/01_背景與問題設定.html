摘要

Agent 可能透過本機 coding tool、framework SDK、managed platform、API gateway 或 observer integration 執行。同一個外部發布動作，在不同 runtime 中可能表現為 shell command、tool call 或 hosted session transition，難以一致回答授權者、approval semantics 與事後證據。

PCAA 以 action certificate 取代 vendor-native session record 作為治理核心。它有 pre-action admissibility、action open、assumption capture、approval、outcome closure 五個 checkpoint，並綁定 portable envelope、runtime/approval receipts 與 replay-ready proof。Certificate 也記 externality，以及 approval 真能在何種程度阻止副作用。Protected benchmark 由 24 seeds 擴成四 runtime family 的 96 traces；消融顯示 externality、approval enforceability 與 integrity lane 分別影響 routing、review 與 proof stability。

1. 引言

Model system card、managed runtime trace、guardrail validator、cryptographic attestation 各自讓一種物件可見，卻沒有提供跨 runtime 穩定的 action-level trust object。PCAA 的設計選擇是：決策當下建立 certificate，之後所有 route、review、runtime receipt、outcome 與 proof 都附在它上面。

Operational method 是 route-review-prove。Route 將動作正規化並決定姿態；review 在政策或不確定性需要時分配人工審查；prove 將結果封裝成可重播、匯出且可加 integrity reference 的證據。

2. 相關工作

Auditable-agent 研究要求 recoverability、lifecycle coverage、policy checkability、責任歸屬與 evidence integrity。Managed agents、Azure AI Foundry、LangSmith、NeMo Guardrails 等則分別提供 runtime、trace、evaluation 或 rails。PCAA 不主張發明這些能力，而是把它們重新組合到同一 action certificate。

方法借用 proof-carrying code 的「artifact 攜帶 proof」精神，但目標是 action admissibility，不是低階程式 safety proof。Verifiable credentials、attestation、zkVM 與 blockchain settlement 是可接入的 integrity lanes，不是目前每個 action 已具備的保證。

3. 前置定義

PCAA certificate 由 action envelope、runtime-stage receipts、human approval/accountability receipts、replay proof state 與 integrity projection 組成。Envelope 至少有 tenant/identity、runtime/adapter、authorization、workflow、evaluation、accountability，以及可選的 runtime、partner 與 integrity 欄位。

這個模型不把 policy 藏在一個分數中，而把治理決策的依據做成可檢查、重播、匯出的 versioned object。

4. 問題設定

Raw action 可能是 SDK call、tool hook、managed transition、browser operation、gateway request 或 signed protocol message。控制問題不是單一 safe/unsafe，而是決定 allow、要求更多證據、hold for approval、deny、因不確定而 defer，或在只有部分覆蓋時標成 observe-only。

所需性質包括 runtime neutrality、final authority 可見、approval semantics 可攜、replay/export、coverage 誠實披露，以及可逐步增強的 integrity。在 review budget 下，機制要盡量避免嚴重的 missed escalation，而非只最佳化平均分類分數。
