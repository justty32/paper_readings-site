論文／訪談原始來源

SkillZip Pro: Execution-Aware Dynamic Compression of Progressively Loaded Skills for Self-Evolving Agents

摘要與第 I～III 節：問題與形式化

正式環境裡的 skill 是目錄，不是一段 prompt。catalog metadata 在選擇前可見，root 在啟用後載入，reference、schema、script、asset 與巢狀 subskill 則按執行路徑才讀取。只壓 root 會漏算大部分部署成本，甚至把少見分支搬進每次都載入的 root；把全目錄攤平又會破壞 progressive loading 與路由。

SkillZip Pro 把 bundle 建模成帶 guard 的資源圖 B=(V,E,r)，並以 entry contract 區分 private、public 與 conditional 資源。壓縮後必須覆蓋原始 typed contract、保持鎖定檔案位元組一致、讓內部引用安全可達；凡依賴 host environment 刪除的內容，也要有綁定環境 digest 的精確 witness。作者把成本拆成 catalog、activation、deployment 與 path 四層，避免用單一壓縮率掩蓋 root 變長或尾端路徑惡化。

第 IV～V 節：執行感知壓縮

核心有兩根支柱。第一是跨檔壓縮：若 root 或明示環境契約已完整涵蓋某義務，就以 witness 刪除重複內容；跨分支的重複片段只提升到需要它們的最低共同 activation scope，不任意塞入 root；具明確觸發條件的長分支可移成按需 capsule，原處保留 dispatcher。第二是路由保存：鎖定路由表與帶引用的來源行，產出後重新從磁碟解析整個目錄，任何檔案不可達、guard 遺失、鎖定資產改變或 interface contract 被拆散，都拒絕候選並回退原文。

系統另有兩組互相獨立的選擇。One-Shot 重新掃描並全域最佳化整個 bundle；Continual 保存編譯狀態，每次 patch 只重算受影響的圖閉包，累積偏移達門檻才全域 repack。Persistent 直接改寫要發布的 canonical bundle，適合穩定且重複使用的私有資源；Transient 保持 canonical bundle 位元組不變，按 entry 建立可快取的暫時 execution view，適合直接呼叫 public entry 或經常變動的 bundle。兩個軸組成四種部署模式，執行端仍只看到普通目錄與相對路徑，不需更改 agent harness。

第 VI 節：主要實驗

**作者自報：**在 BFCL-v4、LiveMathematicianBench 與 SpreadsheetBench 的共同設定中，One-Shot SkillZip Pro 相對未壓縮 Evolved Bundle 減少 19.7% shipped tokens、7.3% always-loaded tokens、14.3% 平均單次載入與 10.8% 最差單次載入，且三項 task success 的平均為 0.560，高於未壓縮 bundle 的 0.541。

**作者自報：**對合併後 102 個 held-out tasks 做 paired bootstrap，SkillZip Pro 的成功率差異信賴區間維持在預先設定的五點非劣界線之上；它也是測試的壓縮器中唯一通過者。路由稽核保留全部宣告路由且沒有 link error，說明節省來自內容縮短與重用，不是讓必要分支消失。

**作者自報：**生產內容審核 skill 的最終 witness-gated 設定，移除 38.1% 部署內容並降低 10.4% 配對量測的每次執行 tokens；兩次壓縮執行的 accuracy 均為 89.00%，同 session 未壓縮基線分別為 92.00% 與 91.00%。相反地，未保護設定雖縮得更多，卻明顯增加單邊 false positive，顯示安全上限由刪除證據決定，而非壓縮率決定。

第 VII 節與附錄 D：結論與局限

SkillZip Pro 的主張是：skill 壓縮必須保存內容，也保存 agent 找到內容的載入結構。圖範圍配置、host witness、capsule 與產後稽核共同把「較短」約束成「仍可執行且可路由」。Continual 與 Transient 並非另一套壓縮器，而是讓同一核心適應更新頻率與 public entry 獨立性的部署策略。

作者也明言三項邊界。typed coverage 只保護顯式契約，不能保證所有模型對語氣、暗示與重複強調的解讀都不變；contract extraction 與 audit 可能共享錯誤，高風險 skill 仍需人工審查或更強形式規格；結構可攜不等於各模型的載入效率一致，跨模型測試中已有 executor 對共享路由的理解較差。中文生產案例也顯示，語言專屬的確定性保護規則若只支援英文，會漏掉大量義務。
