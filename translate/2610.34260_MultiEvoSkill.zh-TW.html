論文／訪談原始來源

MultiEvoSkill：以結構感知的多 agent 演化技能

第 1–2 節：把程序知識留在可重用產物裡

凍結 LLM 可於執行時載入技能文件，不必修改權重。但線性文字把程序分支、先決條件與約束留給模型自行推斷，局部修正可能干擾其他流程；由單一模型經驗生成的技能，也可能帶有特定家族的推理慣例。MultiEvoSkill 將異質模型的經驗整合到同一持久技能圖，重點在訓練時的圖編輯與驗證，與推論時臨時組合、技能庫管理不同。測試時使用單一技能產物，不需推論 ensemble。（§1–2）

第 3.1–3.2 節：技能圖、診斷與編輯

train、selection、test 互斥。初始化器由訓練輸入建圖或匯入 checkpoint；每步收集軌跡、反思、辯論、合併，再由 gate 決定保留 parent 或接受候選。角色是功能分工，模型可重疊。（§3.1）

技能為帶型別與屬性的有向多重圖，節點為動作、決策、產物、約束，邊描述順序、分支、產出、消耗與約束關係；節點指示、適用條件及邊註解仍使用自然語言。實作要求所有引用有效、型別合規、無環，且可執行節點均由 START 可達並能到 END。段落可對應子圖，故不是可逆的文字轉圖映射。（§3.2）

issue 綁定 parent hash、圖位置、缺陷、可重用修正规則、支持題號、預估影響與風險；成功經驗另記行為與適用條件。這些證據支持診斷，不代表已量得修補效益。編輯也綁定同一 parent 與 issue，以有序操作增刪節點、改節點及增刪邊；能套用不代表有效。（§3.2）

第 3.3 節：異質經驗與兩層辯論

多個 executor 對同一訓練題各自執行，供 reflector 比較成功、失敗及模型差異；這比一題只給一模型更貴，不能解讀為不同模型分片處理。共同失敗可支持問題反覆出現，不能證明技能而非模型共同弱點造成失敗。reflector 看同儕回饋修訂診斷，再跨 batch 合併。（§3.3）

pending issue 依語意 embedding 與 cosine 相似度歸群，支持度計不同 reflector–sample 配對，同配對重複診斷只算一次；達門檻才生成提案，並須確保舊圖引用在當前 parent 仍有效。門檻並不要求同樣數量的不同 sample。（§3.3）

各 issue 獨立對同一 parent 生成局部編輯；後續輪次接收自己的提案及稀疏同儕提案，優先來自其他模型家族。以渲染技能的語意聚類達跨家族 quorum、穩定高共識或輪數預算時停止。共識只控制通訊，不能代替接受檢查。（§3.3）

第 3.4 節：階層合併

revisor 先排除結構無效編輯、去除等價操作序列，再優先把目標重疊或圖位置相近的修改組成小批次。各層合併都相對同一 parent，保留 issue 與證據來源，結合相容修正並處理衝突。允許支持目標內的最小改寫，不是只能選不可變的操作 ID。（§3.4）

最終操作須符合套用依賴，例如先建節點才能加相連邊；此依賴不同於技能中的任務執行依賴。空 patch、套用失敗或結構無效皆回到 parent。只有實際合成的候選接受行為評估，整體成功不能替個別輸入編輯提供因果功勞。（§3.4）

第 3.5 節：接受條件

演化前固定 juror 與 selection 題的配置，同配置比較 parent、candidate。selection 用於 gate，不供生成提案。令每個 juror 的分數差為 Delta_j；接受須同時滿足最差差值 minD >= -epsilon、平均增益 meanD >= tau、非退步比例 Q >= q0，以及結構和語意拓撲檢查。（§3.5）

機械檢查驗 schema 與 START-to-END DAG；topology jury 檢查依賴是否有節點語意支持。缺少先決條件、矛盾依賴及無支持依賴可構成高信心硬錯；冗餘或模糊本身只警告。任一 topology juror 找到高信心硬錯即拒收。此為 LLM 審查，不是語意正確性證明。（§3.5、附錄 C）

第 4 節：評估與消融

作者自報各方法共用 GPT-5.6-Luna authoring backbone，本法另使用 Gemini-3.8-Flash、MiniMax-M3、DeepSeek-V4-Flash proposer，並稱同 seed、split 與預算等價比較。WikiHow、ToolAlpaca、WebShop 為 workflow-planning adapter，報 mean per-instance node F1，非互動成功率；SearchQA 報 macro token F1，SpreadsheetBench 報 hard instance accuracy。（作者自報，§4.2）

作者自報本法五欄測試分數依序為 55.58、53.88、34.77、88.25、86.07，皆為所報方法中最高。同欄最佳其他方法依序為 SkillGen 54.56、SkillOpt 53.54、SkillOpt 34.54、SkillOpt 88.14、CoEvoSkills 83.93。這些欄位的量測不同，不能視為同一成功率。（作者自報，表2）

表3以查值、聚合、公式保留、條件格式說明：共享檢查步驟可接不同分支，範圍選取先於聚合、公式檢測先於修改，局部修補不必新增全域指令。（§4.3.1）

作者自報移除 GPT-5.6-Luna proposer 時，WikiHow／ToolAlpaca／WebShop 為45.88／27.71／31.53；完整 panel 為55.58／53.88／34.77。逐個移除其他 proposer 或任一 gate 也低於完整配置；例如去掉非退步比例 gate，WikiHow 為40.84。（作者自報，§4.4，表4–5）

第 5 節及作者局限

本文把異質執行、圖定位反思、issue-specific 辯論、階層 patch 合併及 gate 結合，產生單一可重用技能。作者明示：結構合法不保證任務語意；LLM jury 可漏錯或誤拒；反覆使用 selection set 可能過擬合；狀態相似的停止規則不保證最佳解，技能圖也不是形式驗證執行引擎。（§5 及其後 Limitations）
