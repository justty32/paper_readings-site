3. ReLM

ReLM 用形式語言表達 LLM 驗證任務。輸入（稱 query）＝① 形式語言描述、② 一個 LLM、③ LLM 解碼/決策規則、④ 走訪演算法；本文以正則指定語言，其餘三者在構造查詢時引用。輸出＝在查詢約束下 LLM 中的匹配字串集合：形式上，設正則定義語言 L_r、LLM 及其決策規則定義語言 L_m，ReLM 輸出交集 L_r ∩ L_m，其生成順序由走訪演算法決定。ReLM 逾 7000 行 Python/Rust，開源；原型聚焦 GPT-2，但設計可推廣，也可用於其他受約束解碼（如由關鍵字生成）。

3.1 軟體架構（圖 2）

ReLM 是由使用者 Python 程式呼叫的框架：把外部庫（如 Hugging Face Transformers）中的 LLM 連同 Query Object（含 regex、決策規則、走訪演算法）傳入。regex 先經 parser 構造出等價自動機——稱自然語言自動機（Natural Language Automaton），定義在 ASCII/Unicode 上，尚不能直接跑；ReLM 須把它編譯成在 LLM 字母表（token 空間）運作的 LLM 自動機（LLM Automaton）。之後執行器依 LLM、決策規則、走訪演算法產出「匹配 token 元組」串流回使用者程式（可入庫或起新查詢）。以查詢 The ((cat)|(dog)) 為例回傳 The cat。確定性走訪可跑到語言窮盡；隨機查詢因重取樣為無限長。

3.2 圖編譯器

主要難關是把字元/Unicode 上的形式語言映到 GPT-2 token。

  • 表示全編碼集（Full Set of Encodings）：簡單 regex The 會轉成有 4 條非零機率路徑的自動機——因為 The 有 4 種切分（T-h-e、Th-e、T-he、The），長度 n 的字串切分數以 2^(n-1) 成長，而 GPT-2 對這些切分都有 token。這是某些 LLM 的過參數化，無法還原「哪個 token 序列產出了此字串」，故稱模糊編碼／全編碼集，對應無條件生成（unconditional）。構造法：把 tokenization 視為 transducer，對字元自動機做 transducer 組合——在字元狀態間加「捷徑邊（shortcut）」代表可用的 token（如對 T-h-e 做 DFS 匹配出 token The、對 h 匹配出 he）。演算法耗時 O(V·k·m_max)（V 頂點數、k 詞彙量、m_max 詞彙最大長）。
  • 表示僅規範編碼（Canonical Encodings）：只用最短切分（唯一 token The），常見於輸入/輸出被使用者固定時（如圖 2 的多選，直接把 The 送進 encoder 得規範表示、再以其為前綴評 cat/dog），對應條件生成（conditional）。還原較繁複，三選一：① 枚舉 regex 所有字串再編碼（小集合可行）；② 執行期動態走訪、遇非規範 token 回溯；③ 用字串改寫（transducer 組合）把規範 token 直接代入——此法是函數式的（每個輸入字串映到唯一輸出），因替換是強制而非可選。

3.3 執行器與走訪

執行器輸入為 LLM 自動機＋走訪演算法，輸出 token 元組串流。它最吃效能，因為要 ① 在加速器上排程海量測試向量、② 用解碼/決策規則剪枝。後者是查詢複雜度主因：GPT-2 的 top-k 把圖走訪分支因子從 50257 降到 k，且被 top-k 淘汰的前綴會連帶剪掉所有共享該前綴的字串，一步就消掉大批測試向量。兩種常用走訪：

  • 最短路徑走訪：以 Dijkstra 為基礎，把 LLM 機率取 log 轉成加性成本函數，用來取語言中最高機率字串（記憶化/推理）。前綴不受解碼規則、原本設 0 成本會使「首元組延遲」暴增（須先訪完所有前綴）；改用啟發式——依前綴原始成本排序（當它們不是前綴般），但不以解碼規則淘汰前綴，可把啟動延遲壓到數十秒而不改查詢語意。
  • 隨機走訪：估事件機率，須無偏。對前綴均勻取樣不等於對「前綴集合」均勻取樣（如語言 {a, b, bb, bbb}，首轉移均勻取樣會給 a 和 b 各 50%，但 a 只導向 1 字串、b 導向 3）。實務須正規化：否則偏見實驗中 80% 的前綴編輯集中在前 6 字元（而非約 20 字元均勻分佈）。解法：每條邊按其離開起點後的**走訪數（walks）**成比例加權——p(e)=walks(e)/Σ walks(e')。以稀疏向量編碼初態、鄰接矩陣 A 計一步轉移、A^n 表長 n 走訪數、walks(q₀,n)=s(q₀)ᵀ·Aⁿ·f(F)，總串數為各 n 之和（有環時「展開」到 LLM 最大序列長）。取樣前綴後由 LLM 決定後綴，並可能需接 EOS 以區分「回傳較短字串」或「續生成」（b vs bb/bbb）。

3.4 ReLM API

ReLM 對程式者暴露 Python 介面，把語言模型與查詢組合。查詢含 regex 與解碼參數。範例（圖 4）：

query = relm.SearchQuery(
  "My phone number is ([0-9]{3}) ([0-9]{3}) ([0-9]{4})",
  prefix="My phone number is", top_k=40)
ret = relm.search(model, query)
for x in ret: print(x)   # My phone number is 555 555 5555

前綴（可為 regex）固定並以 top-k 條件取樣、避開一般解碼約束；只有匹配電話號碼模式者被走訪回傳；結果經 Python 迭代器存取。旗標可指定走訪/取樣法。

前處理器（Preprocessors）：使用者常知曉保持查詢語意的領域不變性（同義替換、輕微拼錯不應改變語意），手工枚舉緩慢易錯，故可提交前處理器（定義為 transducer，依序施加於自然語言自動機）擴增查詢自動機。兩例：Levenshtein 自動機——把語言 L 轉成「與 L 中字串在 1 個編輯距離內的所有字串」的 L̂（可鏈接以達更高階編輯，如距離 2＝兩個 Levenshtein 自動機串接），因模型會部分記憶文本，使用者常想在來源字串的某編輯距離內搜尋；filters——把停用詞/毒詞映成空字串以移除（因移除字串常使自動機變大，ReLM 支援延到執行期再過濾）。
