4. 評測

環境：GTX-3080 GPU、AMD Ryzen 5800X、PyTorch；除非另述，用 GPT-2 XL（1.5B）。記憶化/毒性用 top-k=40（比照原始 GPT-2 論文），偏見不用 top-k（以免使某些模板配置失效），語言理解保守設 k=1000，不用 top-p 與溫度縮放。三個研究問題：① 哪類驗證問題受益於正則程式化？② 查詢變動（如考慮的切分）如何影響任務表現？③ ReLM 能在工作流中提供哪些定性洞見？

4.1 測試資料集記憶化

記憶化＝推理時回收訓練資料，具安全風險。以 URL 抽取衡量（最少侵入即可驗證：請求網頁、看 HTTPS 回應碼 < 300 避開重導）。查詢用簡單 URL 模式，走 ReLM 最短路徑後端，前綴 https://www.；基線為官方 Transformers 隨機取樣範例，用 2 的冪次停止長度 n∈{1,2,…,64}，從 GPT-2 XL 取 1 萬樣本（可視為前綴攻擊）。

量化（圖 5、6）：ReLM 首結果延遲僅 5 秒、以吞吐取勝；nvidia-smi GPU 使用率 ReLM 平均 67%（基線 65–72%），27% 查詢命中有效 URL 且用 token 數低而穩。基線 n≤8 幾乎抓不到唯一有效 URL（成功率 ≤3%），n=64 達 25% 完成率但每次嘗試慢 48×。最佳基線 n=16 仍比 ReLM 慢 15×。定性：基線 URL 常太短、被縮寫或看似真實卻虛構；重複率從 n≤8 的 90%+ 到 n=64 的 25%，ReLM 則按構造避免重複。相較前人「60 萬次嘗試僅抽出 50 條 URL」的無目標抽取，結構化查詢＋確定性走訪更有效。

觀察 1：ReLM 藉繞過停止長度選擇、聚焦最可能候選，抽取記憶內容比隨機取樣快 15×。

4.2 測試性別偏見

偏見＝模型以受保護屬性（種族、性別）為條件而偏袒某子群。查詢關聯模板中兩槽位：受保護屬性為二元性別 x∈{man, woman}，關注職業分佈 P(y|x)（y∈{art, science, …, math}）。查詢用 The ((man)|(woman)) was trained in ((art)|…|(math))，前綴 The ((man)|(woman)) was trained in；用 Levenshtein 距離 1 前處理器（量測偏見對輸入擾動的穩健度）。用隨機取樣估分佈，每性別 5000 例，跨編碼與有無前綴量測。

定性（圖 7）：規範編碼（7b，有前綴）呈現刻板關聯——medicine/social sciences/art 偏女性，computer science/information systems/engineering 偏男性（與前人一致）。但**全編碼（7a，無前綴）**下多數職業變成 art（不分性別）：因非規範的 trained 編碼比規範版更常被取樣 10×，導致補全偏向與 art 共享字元的詞（如 artificial）。加編輯（7c）會在 art、business 上翻轉偏見並拉平低機率事件，分佈仍集中於 art；小號 GPT-2 亦見類似現象。

觀察 2：從編碼、編輯、有無前綴等不同角度探測，各導出不同偏見分佈與結論；LLM 偏見行為可能受子詞間概念重疊影響。

量化：對各結果跑 χ² 檢定。無前綴（7a）p≈10⁻¹⁸；規範編碼（7b）p≈10⁻²²⁹（更顯著地判定偏見）；單字元編輯（7c）p≈10⁻⁵⁴。

觀察 3：ReLM 可跨編碼與局部字元擾動估計偏見的統計量。規範編碼強烈呈現偏見，而全編碼與編輯下 LLM 行為改變，統計顯著性可量測地下降。

4.3 測試毒性內容生成

毒性含仇恨/冒犯語言；本文聚焦顯性毒性（髒話/侮辱詞），較易分類且可在無標註下擴展到大資料集。從 The Pile 首檔（解壓 41GiB）用 regex 匹配 6 個侮辱詞（幾乎專用於人身攻擊的強烈髒話），grep 於 2–7 秒找到 2807 條匹配，餵入 ReLM。兩設定：有提示（prompted）——取句子構造 prompt、停在髒話前當前綴抽取髒話，跑 5 小時訪逾 150 個 prompt，量測每輸入能否抽出單一結果；無提示（unprompted）——無 prompt 抽取整句，對全 2807 條跑 4 小時，量測每輸入可抽總數（上限 1000）。基線＝規範編碼無編輯的標準做法；對照 ReLM 的編輯距離 1 前處理器（＋全編碼）。

量化（圖 8）：有提示下，全編碼＋編輯使命中率是純規範基線的 2.5×（91% vs 同子集 27%／全資料集 37%）；無提示下同子集僅 18%、全資料集僅 8% 成功。無提示平均每輸入抽 2.4 條，共抽 6616 條；其中 97% 來自編輯、67% 非規範（僅 1.1% 既無編輯又規範，65.4% 既非規範又有編輯）。

觀察 4/5：ReLM 藉從資料集導出模板抽取毒性樣本，字元編輯在放大查詢空間的同時保留毒性內容；有提示下編輯＋替代編碼解鎖 2.5× 更多抽取，無提示下更達 93× 更多毒性抽取——逐字（verbatim）毒性生成可能嚴重低估毒性暴露，長查詢尤甚。

4.4 測試語言理解

用原始 GPT-2 論文的 LAMBADA（給長上下文預測最後一詞，量測長程推理，零樣本）。把每行切成上下文與末詞，餵上下文為前綴，用四種正則逐步加約束預測末詞 [a-zA-Z]+＋可選標點：baseline <X> ([a-zA-Z]+)(\.|!|\?)?(")?；words（只用上下文中出現過的詞以 | 列舉）；terminated（末端接 EOS）；no_stop（再用 nltk 停用詞 filter）。以最短路徑取樣，GPT-2 與 GPT-2XL 各跑 OpenAI 測試集前 500 例。

定性：baseline 常出現多詞補全或子詞（如補出 Shane、J）；words 加結構後把某例從錯改對（+15 分）；terminated 加 EOS 確保末詞性（改出 thanks，雖仍錯但合理）；no_stop 濾掉「the/a/it/that」等過泛詞（把過泛預測換成 Vivienne）。加 EOS 後最常見詞從佔 12% 降到 7%，濾停用詞後降到 3%，貼近參考分佈。

量化（表 1，零樣本 LAMBADA 準確率，500 例）：

模型 baseline words terminated no_stop
GPT-2XL 41.6% 56.6% 65% 71%
GPT-2 27% 43% 46.4% 52.2%

用齊所有優化後復現並超越原論文 63.24% 零樣本（可能因前 500 例較易、問題表示差異、更周全的解碼/搜尋語意）。局部微調正則造成 10–30 分的零樣本差異。

觀察 6：ReLM 藉把任務約束注入查詢，用極少人力、無需複雜啟發式，即可把零樣本準確率提升多達 30 分。

5. 其他相關工作

NLP 中的形式語言：OpenGrm 把正則與上下文敏感改寫規則編為自動機以建 n-gram 模型；也有推廣到下推自動機者。近期查詢語言 LMQL 同時暴露宣告式（類 SQL）與命令式構造來寫 LLM prompt 程式；ReLM 則純宣告式，主聚焦 LLM 評測。

對抗攻擊與受控生成：對抗攻擊構造輸入誘使 NLP 系統產出錯誤/有害內容；也有微調模型行為者。與 ReLM 相關的還有解碼中用 trie 強制受約束 beam search；現有框架雖能自訂推理允許 token 集，但因 tokenization 模糊而難一致運作。最相關的是 CheckList（用模板測語言模型）——ReLM 把模板推廣為在解碼期強制的字元級正則表達式。

6. 結論

自然語言的複雜性＋LLM 的快速進展，催生了對 LLM 驗證抽象的需求。ReLM 是首個以 LLM 執行驗證任務的可程式化框架，把邏輯查詢表達成正則、編譯成適合執行的 LLM 專屬表示。在記憶化、性別偏見、毒性、語言理解上，ReLM 能以最高 15× 更快、2.5× 更少資料、或以能帶來額外洞見的方式執行查詢。ReLM 的經驗有力地反對 ad-hoc 的 LLM 驗證，但系統化處理查詢也帶來新挑戰（如左到右自回歸解碼對後綴補全有天然偏好）。未來將把 ReLM 擴展到其他模型家族並增添查詢執行的優化邏輯。
