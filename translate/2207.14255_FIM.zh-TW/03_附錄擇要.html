附錄擇要

  • A 架構與資料：8 個模型（50M–6.9B，架構仿 GPT-3/Codex，改用相對注意力，context 2048）；程式碼用 Codex 同款 159GB Python 資料（2020-05 抓取，無 HumanEval 污染），自然語言用 GPT-3 資料集；一律從隨機初始化訓 100B tokens。
  • C 實作細節：context-level＋字元級 FIM 須把已 tokenize 的文件解碼回字串再變換，注意 UTF-8 多 token 字元的碎片；變換後 context 長度會變，須修剪或填補。
  • D SPM 編碼：不用直觀的 <suf>∘Enc(suffix)∘<pre>∘Enc(prefix)∘<mid>∘…，而用 <pre>∘<suf>∘Enc(suffix)∘<mid>∘Enc(prefix)∘Enc(middle)∘<eot>——後者使 SPM 自然成為「prefix 為空的 PSM」特例，最大化 PSM↔SPM 遷移（這解釋了純 PSM 模型在 SPM 評測仍強）；前者對 prefix 尾端子詞處理較強，純 SPM 訓練時可考慮。
  • G 頂尖模型比較（表 4，SPM 模式，temperature 0.2）：6.9B FIM50 單行 0.730/多行 0.406/random span 0.521；FIM90 0.751/0.441/0.551；InCoder 6.7B 0.690/0.386/無；code-davinci-002 0.916/0.699/0.742。
  • H 質性評估：成功例——單一模型從「from sym…」的 subtoken 前綴推斷出 import isprime 並補完函數（需通讀全檔才可能）。失敗模式——suffix 與 prefix 無關時生成過長接不回去；<eot> 機率被更長候選稀釋導致不知何時停、生成冗餘內容甚至無視 suffix 自寫結局；接不上時鎖死重複 prompt（大模型亦然）。緩解——編號式 few-shot 提示約束中段長度與位置；EOT-aware best-of-n：多採樣並偏好以 <eot> 結尾者，再按似然重排。
