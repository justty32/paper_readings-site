5. 實驗

透過實驗回答三個關鍵問題：(1) ARCHITECT 是否有效為 LLM 消費優化 JSON schema？(2) SCOPE 的反思式護欄系統是否提升抽取可靠性？(3) 兩組件如何協同以實現 Software 3.0 應用所需的可靠結構化抽取？

5.1 實驗設置

資料集（三個測試不同面向的互補資料集）：

  1. Retail-Conv：內部精選的 6 種零售對話 schema、每種 40 樣本（共 240），測試從自然商務溝通中抽取——客戶以對話語言描述產品問題、請求與更新；
  2. Schema-Guided Dialogue（SGD）：大規模資料集，含 20,000 條標註的任務導向對話，橫跨銀行、活動、媒體、旅遊等 20 個領域；
  3. Structured Web Data Extraction（SWDE）：標準基準，含 8 個垂直領域共 1,600 個測試樣本（每領域 200 個），測試從半結構化網頁內容（格式多樣）的抽取。

Baseline：以最佳提示實務＋約束解碼、用使用者提供的原始 schema 實作抽取 agent；用清晰指令、few-shot 範例、標準 JSON 格式要求，但無護欄、無 schema 優化。跨五個 LLM 變體評估以確保穩健：Claude 3.5／3.7 Sonnet、Claude 3.5 Haiku、Llama 4-Maverick、DeepSeek-R1-671B。

指標：測 field-level accuracy（所有必填欄位都須正確抽出且格式正確——此嚴格指標反映「部分抽取常無價值」的真實需求）。也追蹤含所有反思迭代與護欄檢查的端到端抽取時間。ARCHITECT 評估則分析 schema 修改樣態並追蹤各迭代的準確率改進。

5.4 ARCHITECT 分析

  • 迭代改進：schema 優化隨迭代持續改善，多數增益在前 5-6 次迭代取得，之後又下降——顯示過程能有效辨識並處理最關鍵的 schema 限制，但迭代過久會過擬合（圖 4）。
  • schema 修改樣態（圖 5，跨資料集一致）：(1) 實體描述強化 34%（加詳細描述與上下文）、(2) 結構重組 55%（扁平化巢狀結構、釐清欄位關係）、(3) 驗證規則新增 0.08%（格式約束與列舉值）、(4) pattern 規則新增 3%（用嚴格 regex 約束輸出）。
  • 跨模型泛化：表 2 顯示用一個 LLM 優化的 schema 套用到不同模型仍保有效益，代表 ARCHITECT 找的是模型無關的 schema 改進，而非模型特定優化。

5.5 SCOPE 護欄有效性

  • 反思式改進：SCOPE 的多階段驗證明顯優於單純重試機制。平均而言，SCOPE 在首次重試內減少 92% 抽取錯誤（相比失敗時只重問的 baseline，圖 3）；且 ARCHITECT 優化過的 schema 更少需要重試。
  • 成本-準確率取捨：SCOPE 因反思迭代平均增 10.16 延遲，但對應 SWDE 上 +64.7% 準確率增益，展現巨大實用價值。用 ARCHITECT 優化 schema 可平均減少 4.05s 延遲懲罰（需要更少反思輪次，表 3）。表 3 顯示 SWDE 上各模型 Baseline／Agent／SCOPE 在原始 vs. ARCHITECT schema 下的延遲（例如 Claude 3.7 Sonnet：SCOPE 原始 25.58s → ARCHITECT 19.06s）。

5.6 定性分析

  • ARCHITECT 一致地把含糊欄位描述轉為精確、上下文豐富的規格。例如泛用的 "price" 欄位變成 "newPriceValue: 產品更新的具體數值價格，不含貨幣符號"，並附格式與範圍約束的驗證規則。
  • SCOPE 的反思機制有效辨識並修正常見錯誤。當 baseline agent 混淆相似實體（如「舊價」vs.「新價」）時，SCOPE 的 grounding 驗證抓到錯誤並透過結構化反思引導修正。
  • SWDE 資料集複雜度：SWDE 上的大幅提升（最高 64.7%）源於其 HTML 結構需要精確抽取與特定格式。表 4 為代表案例：輸入 HTML <title>2010 Subaru Legacy 2.5 i 4dr Sedan</title>，baseline schema {"model": {"type": "string"}} 抽出過多細節 "2010 Subaru Legacy 2.5 i 4dr Sedan"；PARSE schema 加上描述 "完整車款名含年份、廠牌與型號" 與 regex pattern 約束，配合 SCOPE 的 grounding 驗證，精確抽出 "2010 Subaru Legacy"。ARCHITECT 的優化 schema 為解析複雜 HTML 提供了足夠指引，SCOPE 的 grounding 則確保抽出值與原文一致、防止 HTML 抽取常見的幻覺。

結論

我們提出 PARSE，透過 schema 優化與反思式護欄處理結構化抽取挑戰。ARCHITECT 自動為 LLM 消費精煉 JSON schema，SCOPE 以多階段驗證確保可靠抽取。三資料集評估展現大幅提升——SWDE 準確率最高增益 64.7%、首次重試內減少 92% 錯誤，確立 PARSE 為 Software 3.0 應用中可靠 LLM agent 系統的有效方案。

局限

  • ARCHITECT 的迭代精煉對屬性眾多的複雜 schema 計算昂貴：每輪都需合成資料生成、抽取評估、失敗分析，對大規模部署形成擴展瓶頸。
  • ARCHITECT 的優化品質高度依賴種子資料集的可得性與代表性；全新領域或快速演變的 schema 需求下，難有足量高品質種子資料。此外方法假設 schema 結構相對靜態、可離線優化，對持續演變的 schema 較吃力。
  • 幾個有前景的方向：多模態延伸是自然演進——schema 可同時為文字與視覺內容的抽取而優化；「把 schema 當可優化介面」的原理同樣適用於多模態情境，但需擴充驗證框架以處理跨模態 grounding。
