摘要

從非結構化文字抽取結構化資訊，對於新興的 Software 3.0 系統至關重要——在該系統中，LLM agent 自主地與 API 及工具互動。近期方法直接把大型語言模型套用到抽取任務、使用既有的 JSON schema，常搭配約束解碼（constraint decoding）或強化學習來確保語法有效性，但這些方法把 JSON schema 當成為人類開發者設計的靜態合約，導致抽取效能不佳、頻繁幻覺，且當 schema 含糊或規格不完整時 agent 行為不可靠。我們認為 JSON schema 本身就是一種自然語言理解合約，它以描述文字與驗證邏輯編碼了關於資料結構的規則、關係與期望，而 LLM 應當既能詮釋、也能系統性地改進它。據此我們提出 PARSE（Parameter Automated Refinement and Schema Extraction），包含兩個協同組件：ARCHITECT（自主優化 JSON schema 以利 LLM 消費，並透過整合的程式碼生成系統 RELAY 維持向後相容）與 SCOPE（實作結合靜態與 LLM 護欄的反思式抽取）。我們在三個資料集上（Schema-Guided Dialogue（SGD）、Structured Web Data Extraction（SWDE）、內部零售對話資料）做定性與定量評估，發現 PARSE 在 SWDE 上抽取準確率最高提升 64.7%，跨模型的組合框架提升達 10%，同時在首次重試內減少 92% 抽取錯誤，並維持實用的延遲。

1. 引言

Software 3.0 的出現，代表從靜態、表單式應用，轉向由 LLM agent 自主與 API／工具互動以完成複雜任務的動態系統。在此新範式下，從非結構化文字可靠地抽取結構化資訊成為任務關鍵——agent 必須精準解析自然語言請求、抽出精確參數、以有效引數呼叫正確工具。不同於傳統軟體由人類開發者處理資料轉換的複雜性，LLM agent 必須大規模且可靠地執行抽取，這是「有用助理」與「在正式環境災難性失敗系統」的分野。

為何可靠的結構化抽取對 LLM agent 如此困難？ 核心是一個根本的錯配：定義預期輸出結構的 JSON schema，是為人類開發者與靜態系統之間設計的合約，而非給 LLM agent 的指令。這些 schema 常含糊描述、驗證規則不全、為人類可讀性（而非機器理解）而做結構選擇。當 LLM agent 用這些「以人為中心」的 schema 抽取時，會苦於實體邊界不清、需求衝突、欄位關係上下文不足，導致頻繁幻覺與不遵守 schema。

既有工作主要聚焦於用約束解碼、強化學習、自我修正去強迫 LLM 遵從既有 schema 結構，但把 schema 當成不可變合約，而非為 LLM 理解去優化結構本身。

我們觀察到：JSON schema 本身就是一種自然語言理解合約——它用描述文字與驗證邏輯編碼規則、關係與期望，LLM 應能既詮釋又系統性改進它。與其把 schema 視為靜態產物，不如把它當成為 LLM 消費而優化、同時對既有系統向後相容的演進式介面。

我們提出 PARSE，透過兩個協同組件同時處理結構化抽取挑戰的兩端；二者形成良性循環：schema 優化提升抽取效能，抽取錯誤又回饋進一步的 schema 改進。主要貢獻：

  1. ARCHITECT（Automated Refinement and Conversion Handler for Information Transformation and EnhanCemenT）：一套自動 schema 優化框架，透過分析抽取效能、加入詳細實體描述與驗證規則、重構 schema 以更清晰表示，來迭代地為 LLM 消費精煉 JSON schema，並透過 RELAY（Reverse Engineering Layer for Automated Yoking，自動生成 Python 轉換碼）維持與原 schema 格式的向後相容。
  2. SCOPE（Schema Compliant Organized Pattern Extractor）：一套完整的反思式抽取框架，結合靜態與 LLM 護欄，做系統性錯誤辨識與修正，透過精密驗證機制確保可靠的結構化抽取。

評估顯示 PARSE 在 SWDE 上相對 SOTA baseline 抽取準確率最高提升 64.7%，跨 SGD／SWDE／內部零售對話三資料集的組合框架提升達 10%——代表把結構化抽取重新框定為 schema 設計與抽取機制之間共同優化（co-optimization）問題的範式轉移。

2. 相關工作

基於 LLM 的結構化抽取與 schema 遵循：LLM 把資訊抽取從判別式轉為直接產出結構化輸出的生成式方法。結合通用 LLM 與領域精煉的兩階段框架對複雜抽取有潛力，但現有方法有明顯限制：LLM 在複雜 schema（尤其巢狀實體辨識）上與傳統方法有顯著落差；常見錯誤含 span 缺漏、型別錯誤、不遵守 schema，GPT-4 在複雜抽取上有 11.97% 無效回應率。傳統 JSON 生成已從簡單提示演進到精密約束強制：像 Outlines 這類約束解碼透過文法引導保證 schema 遵循，但有時犧牲輸出品質；強化學習法以 schema 作訓練訊號達到高有效 JSON 率（98.7% vs. baseline 82.3%）；「Thought of Structure」範式在生成前鼓勵結構推理，帶來 44.89% 增益。然而這些方法都聚焦語法有效性，而非為 LLM 理解優化 schema。

自我修正與 agent 框架：自我修正技術透過 Chain-of-Thought、自我驗證、迭代精煉提升 LLM 可靠性；Chain of Self-Correction 把修正內嵌為固有能力；AgentSpec 這類執行期護欄用領域特定語言做輕量約束強制，但現有方法主要針對一般文字生成，而非嚴格遵守 schema 的結構化抽取。LLM agent 已成為自主操作工具與 API 的關鍵框架：ReAct 展示交錯推理與行動；RestGPT 直接與 RESTful API 互動。但 agent 仍面臨高推論延遲、輸出不確定、安全漏洞等可靠性挑戰，「Agentic ROI」凸顯價值與運營成本間的根本取捨。

與本文的差異：現有工作把「LLM 抽取／JSON schema 優化／自我修正」當成互相獨立的問題。目前的 schema 優化聚焦語法有效性而非抽取效能，自我修正機制也非為結構化資料遵循而設計。最關鍵的是，既有方法假設靜態、人類設計的 schema，而非在「LLM agent 為主要消費者」的 Software 3.0 情境下探索為 LLM 消費而做的 schema 優化。本文以整合方式填補此缺口：把「專為 LLM agent 的自動 schema 優化」與「為結構化抽取量身的反思式護欄」結合。
