附錄要點

  • A.1 SCOPE 定性樣本：SGD／Retail-Conv 案例顯示 SCOPE 較 baseline 更能處理長上下文與否定改口。例如使用者先訂 Castle Rock 後改口「請改訂 Mcdonald's」，SCOPE 正確抽出最終餐廳與地點，baseline 則抓錯（restaurant_name 為 null）。當必填欄位不足時，SCOPE 正確回傳 {NULL}（如缺時間範圍、或價格模糊「39.99 或 49.99」時），而 baseline 會擅自填值。
  • A.2 ARCHITECT 優化樣本：表 6 展示 SWDE Auto schema 跨 5 次迭代的演變——欄位從裸 {"type":"string"} 逐步加上 required、regex pattern、minLength、condition（自然語言條件）等，描述亦愈趨精確。
  • A.3 RELAY 向後相容：範例把優化 schema 的 currency_symbol + price_value 兩欄，用自動生成的 reverse_transform() Python 函式拼回原始 price 字串欄位。RELAY 生成樣本對並迭代測試轉換碼，正式部署顯示一致的轉換準確率、無轉換錯誤。
  • A.4／A.5 Agent 提示詞：附錄給出 ARCHITECT 的三個提示（Schema 生成、合成對抗測試資料生成、schema 精煉）與 SCOPE 基礎提示全文。精煉提示明確限定 schema 只能用 [name, description, type, enum, properties, title, pattern, minLength, maxLength, condition]，禁用 if/else/anyof/allof；condition 只能放自然語言條件。合成資料提示要求生成含上下文歧義、結構挑戰、語意陷阱、語言複雜性、錯誤條件的對抗樣本，schema 不足時 ground truth 標為 INSUFFICIENT_SCHEMA。
