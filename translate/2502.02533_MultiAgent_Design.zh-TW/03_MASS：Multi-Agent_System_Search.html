3. MASS：Multi-Agent System Search

第 2 節的分析凸顯了「為個別 agent 妥善設計 prompt」與「審慎定義搜尋空間以達成有效 MAS 表現」兩者的重要性。在此基礎上，作者提出多階段優化演算法 MASS，超越了那些只專注優化 workflow 拓撲、卻沒有適當 prompt 設計的既有工作。相反地，此方法展示了「配合妥善優化的 prompt 與經審慎設計的搜尋空間」在 MAS 設計上的更大有效性。MASS 框架的呈現如 Algorithm 1 與 Fig. 3，遵循「由局部到全局、由 block-level 到 workflow-level」的直覺，用每階段有效的優化來克服組合優化的複雜度：

1）Block-level prompt 優化。 在組成 agent 之前，作者先確保個別 agent 在 block level 已被徹底優化（如 2.1 節所述）——此步驟確保每個 agent 在最可控的計算預算內，以最有效的指令為其角色做好準備。為進一步克服在大型 MAS 空間上聯合優化的複雜度，作者先用單一 agent APO 暖身初始預測者：a₀* ← 𝒪_𝒟(a₀)，其中指令與範例都由模組化 prompt optimizer 𝒪 聯合優化。接著以暖身過的預測者為條件，繼續用最少數量的 agent 優化每個拓撲：aᵢ* ← 𝒪_𝒟(aᵢ|a₀*)——例如，2 個預測者搭配 1 個辯論者組成辯論拓撲的最小建構區塊，藉此降低優化複雜度，此拓撲之後可再擴大更多預測者與辯論者，但都已配備優化過的 prompt。為衡量每個建構區塊的影響力，作者在優化完成後儲存驗證表現。雖然 Stage 1 是每個建構區塊的暖身階段，它仍是關鍵階段，確保後續的拓撲優化是在一個有效的空間中搜尋——由表現良好的 agent 組成，而非受任何用手工 prompt 的劣質 agent 的複合影響所累。

2）Workflow 拓撲優化。 此階段聚焦於優化整體 MAS 結構，決定 agent 之間最有效的排列與連接方式。為理解個別區塊的影響，作者在 Fig. 4 中報告各種拓撲的表現，並觀察到：並非所有拓撲對 MAS 設計都有益，有正面影響的拓撲只佔整體集合的一小部分——例如在 HotpotQA 上，只有 debate 帶來 3% 增益，其餘則未能改善甚至損害系統表現；在 LiveCodeBench 的 test-output-prediction 子任務上也觀察到類似趨勢。這凸顯了在搜尋空間中「有影響力子集」搜尋的重要性，納入遞減效益的建構區塊不僅可能提高搜尋複雜度，還可能損害表現。因此，作者旨在把強表現拓撲的精髓精煉進一個經剪枝的空間，讓 workflow-level 拓撲搜尋更有效率。

在此，作者提出量測增量影響力 I_{aᵢ} = ℰ(aᵢ*)/ℰ(a₀*)，量化整合搜尋維度 aᵢ 相對於初始 agent a₀ 的相對增益。依循「有影響力的維度應有更高選擇機率」的直覺，若 u>p_{aᵢ}（u∼Uniform(0,1)、p_a=Softmax(I_a,t)，t 為 softmax 的溫度），則拒絕對應的拓撲搜尋維度 aᵢ，藉此形成經剪枝的搜尋空間。因此 workflow 可從一個經剪枝的配置空間中隨機取樣，並受限於最大預算：a∼𝒜_p s.t. 𝒩(a)<B，其中 𝒩(a) 限制 agent 的總數、B 為最大預算。取樣自 𝒜_p 的有效配置，再依預定規則排列成 workflow 𝒲(a)=(aᵢ,aᵢ₊₁,…)，此以規則為基礎的流程消去了設計中各種排序的冗餘，降低優化複雜度。此規則遵循一個對齊 agent 設計實務的簡單預定序列：[summarize, reflect, debate, aggregate]。

Algorithm 1（MASS）流程摘要：輸入搜尋空間中的 agentic 模組 aᵢ∈𝒜、agent 工作流 𝒲(a)、prompt optimizer 𝒪、評估器 ℰ、驗證集 𝒟、溫度 t、候選數 N、預算 B；輸出優化後的 𝒲*。[1PO] 先對初始 agent 做 prompt 優化 a₀←𝒪_𝒟(a₀)；接著對 𝒜∖{a₀} 中每個 aᵢ，做局部 prompt 優化 aᵢ←𝒪_𝒟(aᵢ|a₀*)，並取得增量影響力 I_{aᵢ}←ℰ(aᵢ*)/ℰ(a₀*)。[2TO] 由 I_a 取得選擇機率 p_a←Softmax(I_a,t)；重複 N 輪：剪枝出 𝒜_p、在預算內拒絕採樣配置 a、以規則序建構帶優化 prompt 的 workflow 𝒲_c、評估並記錄分數 ℰ_𝒟(𝒲_c)；取得最佳 workflow 𝒲_c←argmax_{c∈𝒞} ℰ_𝒟(𝒲_c)。[3PO] 對最佳拓撲做 workflow-level prompt 優化 𝒲←𝒪_𝒟(𝒲_c*)，回傳 𝒲*。

3）Workflow-level prompt 優化。 作為最後一步，作者把整個 MAS 設計視為一個整合實體，在 Stage 2 找到的最佳拓撲條件下，對所有 agent 同時做一輪聯合 prompt 優化：𝒲*=𝒪_𝒟(𝒲_c*)。雖然 prompt 已在 Stage 1 於個別層級被優化過，此階段扮演一種調適或微調流程的角色，確保 prompt 被裁製為適合在 MAS 內編排、且 agent 之間的相互依賴被妥善優化。實驗（Fig. 5 & 6）顯示此階段常帶來實質效益，表現最終收斂如 Table 6 所示。
