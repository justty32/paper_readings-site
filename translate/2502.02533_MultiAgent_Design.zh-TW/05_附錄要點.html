附錄要點

  • 附錄 A（局限與未來工作）：作者自陳目前拓撲空間雖涵蓋多數有效 MAS 設計（並行、串行、混合連結），仍可能遺漏其他能進一步提升表現的拓撲；近期研究已在識別 agent 通訊的稀疏性、剪枝冗餘通訊可能進一步提升最強 MASS 設計的效率；拓撲 optimizer 雖已能有效在既有空間中搜尋，導入更進階的搜尋演算法（如貝氏優化）可能在面對更複雜設計空間時提升樣本效率；同樣，prompt optimizer 的樣本效率也可能透過根據錯誤日誌的文本回饋進一步強化，留待未來工作探索。
  • 附錄 B（實作細節）：Table 2 列出各任務的驗證／測試集規模（多為 50–60／100–200 筆）、拓撲搜尋空間、以及 Gemini 1.5 Pro 上 MASS 找到的最佳配置（如 MATH 為 {Aggregate:9, Reflect:0, Debate:0}，HotpotQA 為 {Summarize:0, Aggregate:5, Reflect:0, Debate:1} 等）。作者對 MBPP／HumanEval 使用公開測試案例讓執行器取得可靠外部回饋訊號（做法與 AFlow 一致）。
  • 附錄 C（額外實驗）：C.1 驗證跨 LLM 骨幹的泛化性（Claude 3.5 Sonnet、Mistral Nemo 上一致改善）；C.3 成本分析給出三階段成本公式（1PO 隨建構區塊數線性增長、2TO 為候選拓撲的 agent 呼叫數總和、3PO 隨最終 workflow 的 agent 數線性增長），並展示 MASS 訓練成本與自動化基線相當、Pareto 前緣上比基線更具 token 效益；C.4 與圖優化基線 GPTSwarm 比較，MASS 在 MATH／HumanEval 上大幅勝出（Pro 平均 88.2% vs 80.5%、Flash 平均 82.9% vs 67.0%），作者指出 GPTSwarm 更側重從全連結圖剪成稀疏圖以提升推理效率，而非任務表現本身；C.5 消融不同 prompt optimizer（APE、DSPy），顯示 MASS 對 optimizer 選擇具一定穩健性、且更好的 optimizer 只會進一步強化整體表現。
  • 附錄 D／E：提供 prompt 模板與 MASS 發現的最佳 prompt 範例。
