論文／訪談原始來源

Invalidation Contracts for Cross-Episode Agent Memory

摘要與問題

LLM agent 可以把 API error 的 recovery suggestion 存進跨 episode memory，下次直接套用，省去重新推導。但 server-side reference data 一旦 drift，舊修正會悄悄失效；若每次都重新推導，又把 memory 的 token 與 model-call 節省全部還回去。現有 error envelope 會說明哪裡出錯，卻沒有協議告訴 client：這個建議能不能快取、依賴哪些 server data、何時已經過期。

作者提出 invalidation contract，在每個 suggestion 上附 cacheability hint 與 version metadata，並在 schema reload 時送 structured diff。目標不是讓模型自己猜 memory 是否仍正確，而是讓 server 用機器可讀訊號宣告 freshness，client 再精準 evict stale entry，同時保留未受 drift 影響的知識。

方法：把節省拆成 validity 與 compliance

論文將 realized savings 分解為 validity * compliance(m,p,a)。validity 是 drift 後仍正確的 cached suggestions 比例，由 protocol 與 eviction policy 控制；compliance 是 planner 第一次就採用有效建議的比例，取決於 model、protocol presentation 與 action type。這個分解把責任邊界說清楚：API provider 能保證 freshness metadata 一致，卻不能保證模型願意使用它。

每個 suggestion 可攜帶 cache_hint、單一 table，或多表 tables dependency vector；每個 response 則帶 table_versions 與 rules_version。client 在快取時記下相依版本，之後發現版本移動便失效。row-level diff 只清除真正變動的 key；table-level invalidation 會連同同表但未 drift 的 entries 一起刪掉；dependency graph 與 rule fingerprint 再處理跨表衍生關係與成功 response 上的 rule drift。

協議另區分 wire channel 與 consumption channel。前者是 server 實際送出的 metadata；後者決定 client 如何把有效 suggestion 呈現給 planner，例如明確要求照參數修改，或先把修正合併進 request。相同 wire bytes 仍可能因模型對新增欄位、覆寫欄位的信任不同，而產生完全不同的 compliance。

實驗設計

主要 domain 是帶多種 constraint classes 與預排 drift event 的 payments API；第二個 recipe domain 提供另一種 suggestion shape。各 arm 從 no memory、naive memory、table-level invalidation、row-level diff，一路加入 notification、graph propagation 與 rule-drift detection。評估同時量 first-try compliance、eviction precision、retry、completion 與各模型自身相對 baseline 的 token saving。

作者特別排除 drift 後第一個仍注入舊修正的 slot，因為任何 memory arm 都不可能在 server 回報前預知資料已變；把這個必然 stale 的嘗試算進 compliance，會混淆 protocol freshness 與 planner 是否照做。論文也警告，提早耗盡 retry budget 的 run 可能因根本沒走到後續事件，表面上呈現虛假的高 eviction precision，因此 event count 必須和 completed episodes 一起看。

主要結果（作者自報）

整體評估涵蓋 9432 個 episodes。作者自報，version-stamp validity 在所有模型與 serving paths 上一致，整個評估沒有 contract failure；row-level oracle 下，各模型的 eviction precision 都達 1.00。相較之下，table-level invalidation 會誤刪同表中的有效 entry，導致未被 drift 直接影響的 constraint class 也失去 first-try 表現。

row-level invalidation 對 compliance 的作用高度依 model 而異。作者自報，提升範圍從 0 到 66.7 個百分點；有些模型已在 naive memory 達上限，有些幾乎不採用 cache，另有模型對 add-a-field suggestion 特別保守。這種 input-schema conservatism 表示 protocol 可以把 memory 保持正確，卻無法跨越 planner 對某類 mutation 的拒絕。

在成本面，作者自報，較能利用 memory 的模型可回收約 29％ 到 33％ 的 baseline token cost，而 contract 本身增加約 15％ response payload。更精細的 invalidation 不一定自動轉成 savings；只有 validity 與 compliance 同時高，token gain 才會實現。rule drift 實驗則顯示，stamp 提供零延遲偵測，dependency vector 提供局部處置，兩者結合比只看 stamp 後整批清空更合算。

討論與結論

論文的工程結論是先做 compliance preflight：用少量已知有效、涵蓋部署所需 action types 的 fixes，量出指定 model 是否真的採用。若 planner 拒絕關鍵 mutation，再精密的 invalidation protocol 也只會維持一個從不被使用的正確 cache。

另一方面，協議也新增信任面。讓 client verbatim 套用 suggestion，既提高 compliance，也形成 parameter-injection channel；server 若不更新 version，可把 stale fix 永久釘在 memory，若濫發 version bump，又能迫使 client 持續重算。精準 invalidation 還會暴露 table 名稱與 derivation graph。作者因此把 signed stamps、異常 bump rate 與 client-side eviction bound 留作後續安全工作。

局限

作者明列的限制包括：兩個 API domains 都為本研究合成，reflective layer 也是手寫，尚不知能否直接轉移到大型 production schemas 與自然 drift。模型與 episode 規模雖足以檢查重現性，domain 數仍不足以支撐廣泛外推。dependency vectors 已實作，但其獨立 compliance 貢獻沒有和 graph propagation 完全拆開；prompt sensitivity 與更多 task families 也未測。最後，增加 drift 頻率後，naive 與 governed arms 的差距未如預註冊假說持續擴大，表示 ceiling effect 或 rotation schedule artifact 尚待 episode-level 分解。
