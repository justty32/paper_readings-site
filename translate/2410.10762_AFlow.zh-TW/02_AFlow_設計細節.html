4. AFlow 設計細節

核心是把 LLM 當作 MCTS 變體中的優化器來發現有效工作流。MCTS 中每個樹節點代表一個完整工作流（而非單一 LLM 呼叫節點），以發現「一類問題」的通用解。搜尋是「軟性混合機率選擇 → LLM 驅動的優化擴展 → 執行評估 → 經驗反向傳播」的反覆循環，直到達最大迭代數或收斂。關鍵想法是用 MCTS 的樹結構保存 Nmax 輪工作流優化的探索經驗：當工作流被再次造訪，精準複用過去的成功經驗、避開失敗，提升搜尋效率。為防局部最優，特設一個允許任何一輪都能從空白模板重新生成的選擇機制。

  • 初始化：從模板工作流 W₀ 開始（LLM 優化器只需補完呼叫函數即可完成工作流）。資料隨機切成驗證集（20%）與測試集（80%，seed 固定 42）。先把空白模板在驗證集上跑 5 次，挑出「分數變異高」的子集作為最終驗證集。
  • 選擇（Selection）：以軟性混合機率選擇策略持續選工作流——結合「均勻分布」與「基於分數的加權分布」，從 top-k 工作流與初始工作流中挑選；納入初始工作流可維持持久探索、避免局部最優。公式：P_mixed(i) = λ·(1/n) + (1−λ)·softmax，其中 α=0.4 控制分數影響、λ=0.2 平衡探索與利用。
  • 擴展（Expansion）：用 LLM 當優化器，利用被選工作流的經驗（含所有修改及其對應的改善或失敗、以及預測與期望輸出的精確日誌）生成新提示或改動節點連接（改程式碼），產出新工作流。
  • 評估（Evaluation）：因推理任務有明確評估函數，直接執行工作流取回饋；每個工作流在驗證集上跑 5 次取均值與標準差，回饋更準、進而減少所需迭代數。
  • 反向傳播（Backpropagation）：記錄（1）工作流表現、（2）優化器對父工作流的修改、（3）相對父的優化成敗，存入經驗傳回父工作流，分數則加入全域紀錄供選擇使用。
  • 終止條件：早停——top-k 平均分數連續 n 輪無改善，或達 N 總輪數即停。

（演算法 1 概述上述迴圈：Select → Expand → Evaluate → Backpropagate → 若改善則更新 W*。）

5. 實驗

設定：六基準（GSM8K、HumanEval、MBPP 用全集；HotpotQA、DROP 各隨機取 1000 筆；MATH 取難度 5 的四類共 617 題），驗證：測試 = 1:4。基線含人工設計法（IO、CoT、CoT-SC、MultiPersona Debate、Self-Refine、MedPrompt）與自動化法 ADAS。AFlow 用 Claude-3.5-sonnet 當優化器，執行器用 DeepSeek-V2.5、GPT-4o-mini、Claude-3.5-sonnet、GPT-4o；迭代 20 輪（ADAS 30 輪）。指標：GSM8K/MATH 用 Solve Rate、HumanEval/MBPP 用 pass@1、HotpotQA/DROP 用 F1，並依 token 用量算成本畫 Pareto front。

主結果（表 1，皆以 GPT-4o-mini 執行）：AFlow 平均 80.3%，較人工設計法平均勝 5.7%、較 ADAS（67.2%）等自動化法勝 19.5%。各項：HotpotQA 73.5 / DROP 80.6 / HumanEval 94.7 / MBPP 83.4 / GSM8K 93.5 / MATH 56.2。在更難的任務上優勢更大：MATHlv5* 與 MBPP 上較 ADAS 提升達 57%，顯示對複雜資料集的穩健性。

模型無關性（表 2）：用 GPT-4o-mini 與 DeepSeek-V2.5 搜出的工作流套到其他模型，多數仍勝基線，顯示可遷移性。但用 DeepSeek-V2.5 搜出的工作流套到 GPT-4o-mini 時明顯較弱——不同語言模型需要不同工作流才能發揮最佳表現。

成本分析：AFlow 能在成本效益的 Pareto front 上找到讓較弱模型勝過較強模型的工作流。即摘要所述——小模型以 GPT-4o 推論成本的 4.55% 在特定任務上超越 GPT-4o。這既消除了人工設計工作流的人力成本，也以更低成本達更佳表現，利於代理工作流的廣泛採用。

消融：算子是人工設計的效率增強。GSM8K 上（圖 5）算子幫助 AFlow 更有效發現更好工作流；但即使無算子，AFlow 仍達 93.1%、超越人工設計，且自主發展出類 ensemble 的結構，是邁向完全自動化的重要一步。

案例研究：AFlow 從空白模板（僅單一無提示節點）逐步演化。每輪僅做單步修改（加一個算子，或針對某 prompt 做定向修改）。GSM8K 最佳工作流：生成 5 個解 → SC-Ensemble → 用 Programmer 算子做驗證步驟。失敗探索也有意義（如第 5 輪加一個直接改答案而不再推理的 review 節點使準確率下降；第 14 輪過度聚焦「折扣」資訊致下降）。在 MBPP 上，AFlow 發現了與現有人工設計相似的「由 LLM 生成並執行測試」結構。

6. 結論

AFlow 全面形式化了自動工作流優化問題，並以 MCTS ＋ 程式碼表示的工作流高效導航龐大搜尋空間。六基準實驗顯示其勝過人工設計與既有自動化法；消融顯示即使無預定義算子也能自主發現有效結構；更重要的是，AFlow 讓較弱模型在成本效益 Pareto front 上勝過較強模型，凸顯其在提升 LLM 解題能力的同時優化計算成本的潛力。
