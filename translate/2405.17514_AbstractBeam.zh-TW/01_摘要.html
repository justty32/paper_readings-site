摘要

LambdaBeam 是最先進的、由執行引導（execution-guided）的程式合成演算法，能在領域特定語言（Domain-Specific Language, DSL）中運用高階函數（higher-order functions）、lambda 函數與迭代迴圈。LambdaBeam 每支程式都從零開始生成，並未利用「特定領域中程式區塊或子程式常反覆出現」這一事實（例如遍歷串列的迴圈）。為解決此限制，我們提出 AbstractBeam：一個利用**庫學習（Library Learning）**來強化 LambdaBeam 的新穎程式合成框架。AbstractBeam 辨識反覆出現的程式結構並將其整合進 DSL，藉此優化合成過程。實驗評估顯示，在整數串列操作領域中 AbstractBeam 以統計顯著（p < 0.05）之差距優於 LambdaBeam。除了解出更多任務外，AbstractBeam 的合成也更有效率，只需更少時間與更少候選程式即可得出解答。此外，我們的發現指出：即使在並非刻意設計來凸顯庫學習優勢的領域，庫學習仍能有效強化程式合成，凸顯其更廣泛的適用性。

引言

程式合成（program synthesis）的目標是讓機器能依使用者提供的規格自動生成程式。已有多種技術：圖神經網路、序列到序列模型、大型語言模型（LLM）等端到端方法。在此基礎上，結合 DSL 與**範例編程（Programming-By-Example, PBE）**能使自動生成更精準、更聚焦。PBE 允許以「輸入-輸出（I/O）範例」而非自然語言來指定程式。

解 PBE 任務最直接的作法是窮舉並執行 DSL 中所有運算組合，但組合數隨程式長度指數成長，導致組合爆炸（可視為決策樹：程式越長則深度越大，DSL 越複雜則寬度越大）。因此純試誤法對複雜任務不可行。許多 DSL 合成法便用類神經網路或 LLM 引導組合搜尋，但搜尋空間的指數成長仍是關鍵瓶頸。

人類程式設計常採由下而上（bottom-up）：先寫小而自足的函數處理大問題的各面向，再組合成完整方案；同時大量使用預建軟體庫（library）以降低複雜度與開發時間（如 ML 實務者直接取用 PyTorch 的模型架構）。

受此啟發，DreamCoder 等方法把庫學習納入由上而下（top-down）的合成框架。庫學習辨識並抽取常出現的程式模式或子程式，做成可重用元件加入初始 DSL。DreamCoder 將此程序放入清醒-睡眠（wake-sleep）循環：清醒期用簡單的貝氏由上而下演算法生成程式；睡眠期辨識重複子程式並加入 DSL。藉由把含多運算與常數的子程式抽象化，可縮短合成程式長度、降低搜尋深度、提升效率。

LambdaBeam 則聚焦於縮窄搜尋寬度，採用由執行引導的由下而上搜尋：合成過程中執行子程式，並以這些中間程式狀態為後續搜尋提供更細緻的引導；並納入高階函數以處理複雜任務。然而 LambdaBeam 雖在「評估的程式數量」上有效率，卻不用庫學習，導致生成這些程式相當耗時。反之，DreamCoder 擅長庫學習與抽象化，卻缺乏執行引導合成所具備的細緻脈絡資訊。此外，DreamCoder 評估的領域含有「僅差一個參數」的多個任務叢集（例如 add-k 之 k=1、k=2……），使抽象化容易被找到並套用——這種環境偏袒庫學習法，卻忽略了可擴展性與泛化的挑戰。

此情境正好帶來一個機會：把「由執行引導的由下而上合成」與「庫學習」兩者的長處統合起來。我們的假設是：以庫學習強化 LambdaBeam，可透過縮短程式長度與搜尋深度來提升效能；且抽象化能在「並非刻意設計成含程式重複」的領域中被找到，但除非這些抽象化精準反映該領域，否則不會泛化到領域之外。基於此，我們提出 AbstractBeam：沿用 LambdaBeam 的搜尋策略，並採用受 DreamCoder 啟發的庫學習框架。AbstractBeam 可定義、使用並推理含 lambda 函數、迭代迴圈與高階函數的運算與抽象。我們在 LambdaBeam 的串列操作領域驗證其效果。

背景

範例編程（PBE）

PBE 讓使用者以 I/O 範例（而非自然語言）描述程式。目標是找出一支程式 P ∈ L，使其能把所有輸入 I = {I₁,…,I_N} 正確對應到各自的輸出 O = {O₁,…,O_N}。此處 L 是由 DSL 定義的所有可能程式空間，含常數、輸入變數與運算；運算可任意巢狀並作用於常數與輸入變數。

λ-演算（lambda-Calculus）

lambda 演算是數理邏輯中的形式系統，可模擬任何圖靈機。其項（terms）定義為變數、函數應用與 lambda 抽象；lambda 抽象以特定變數集建立新函數，界定其作用域與函數本體。與傳統一次引入一個變數的「柯里化（currying）」不同，本文允許 lambda 抽象同時引入多個變數。此外，作者以人工設計的領域特定基元（primitives）如 Add、Sort、Map 擴充 lambda 演算，並採用**簡單型別 lambda 演算（simply-typed lambda calculus）**以協助資料型別管理與函數驗證。

LambdaBeam

LambdaBeam 是採由下而上的程式合成框架，透過重組先前探索過、稱為「值（values）」的程式來高效生成新程式。這些值存於一個集合，初始只含輸入變數與常數。每一步驟中，演算法遍歷 DSL 中可用運算，依運算的元數（arity，即所需引數個數）從此集合選出下一運算的引數。一個神經模組評估搜尋脈絡（含 I/O 範例、當前運算 f、以及先前探索過的值），輸出「在已探索值集合上的機率分佈」，引導一個集束搜尋（beam search）演算法選出運算 f 最適合的引數 aᵢ。所需引數選齊後即執行 f(a₀,…,a_arity)，其輸出加入已探索值集合。此過程持續到成功合成滿足規格的程式、或搜尋逾時。

由下而上生成讓 LambdaBeam 能漸進建構程式，並依中間執行結果精修搜尋。確定性集束搜尋可能因新生成的值與既有值重複、使集合不變而停滯；為避免此狀況，UniqueRandomizer 有系統地選取唯一樣本並記錄於專用資料結構，防止重選已選過的值。此外搜尋過程含週期性重啟以擺脫無效搜尋路徑，代價是丟棄先前探索過的值。

Stitch

Stitch 實作一種自動化合成方法，從程式語料庫中抽取抽象。它以初始 DSL 為起點，採由上而下搜尋來辨識能**壓縮（compress）**程式語料庫的抽象。

此法一大挑戰在於：語料庫中的程式未必處於正規形式（normal form），語意等價的子程式可能以不同語法形式出現（如 t₁(x)=x+1 與 t₂(x)=1+x），使其難以辨識；而用規則將程式轉為正規形式又常因規則套用的複雜度與頻率上升而不切實際（類似程式生成的搜尋空間爆炸）。為此，Stitch 放棄預定義的改寫規則，改用一個「不為解任務、而為壓縮語料庫（辨識共通模式）」而生成程式的合成演算法；此作法犧牲部分壓縮完整性以換取更高效的辨識。

Stitch 從空抽象開始，依序加入 DSL 運算。初始時抽象中的引數是佔位符（placeholder），可在後續迭代填入新運算、變數或常數。為增強泛用性，Stitch 支援部分抽象（partial abstractions）：引入稱為「洞（holes, ??）」的新變數來填佔位符。Stitch 遍歷 DSL 運算以比對並擴充抽象；因窮舉由上而下搜尋不可行，它改為挑選能最佳化語料庫壓縮的動作——優先選「能使抽象之長度與其在語料庫中出現頻率之乘積最大」的運算；若某新加運算的貢獻低於當前抽象，整條分支即可剪除，帶來可觀的處理速度與記憶體效率提升。
