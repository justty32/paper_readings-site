3. 實驗

3.1 實驗設定

任務、資料集與指標（三類任務）：

  • 視覺問答（VQA）：依關聯影像回答問題。用 GQA（需組合式推理）、OK-VQA、A-OKVQA（後二者主要用影像中物件/動作的真實世界外部知識）。以開放式生成處理，用 soft accuracy（SAcc）指標；並補用 F1（因 LM 生成常為描述性長句而非簡短片語，會低估 exact-match 表現）。
  • 表格處理：用 TabMWP（每筆含一表格＋一自然語言問題），需理解問題、從表擷取資訊、再計算；以 exact-match accuracy 衡量。
  • 數學推理：用 MATH 的 algebra 子集（881 題競賽級代數題，因預算僅測此子集）；以 accuracy 衡量。

基線四類：(1) 無工具基礎推理——CoT（VQA 不適用，因無視覺工具無法處理影像）；(2) 工具學習——Vanilla（VQA 用 ViperGPT，其餘用 Program-of-Thoughts）與 External library（額外用 Numpy/SciPy/Scikit-Image/Mahotas 或 Pandas/SymPy 等）；(3) 不同 LLM 造工具法——LATM（用 3 訓練樣本造 1 個工具、3 驗證樣本核驗，套用全部測試）與 CREATOR（推論時逐題現造工具）；(4) 替代檢索法——SimCSE 與 BM25（僅以問題 vs API 名相似度，且皆基於 CRAFT 所造工具集以公平比較）。

表 1（基線與 CRAFT 的差異）：CREATOR 用測試集造工具、不可重用、工具庫 0、無檢索；LATM 用訓練集、可重用、工具庫 1、無檢索；CRAFT 用指令集或訓練集、可重用、工具庫 >100（理論上無上限）、有檢索。

所有方法皆以 GPT-3.5-Turbo-0613 為 backbone（較 GPT-4 划算，且 Turbo-0613 專為工具學習優化；CodeLlama 等在此設定近乎隨機表現）。

要點：直接借用 Python 外部庫工具無助益、甚至有害（如數學推理），顯示工具相關性影響表現，故需為每個任務造高品質工具庫。LATM 在所有資料集掙扎、帶來負效；CREATOR 對數學有顯著提升、對其餘僅邊際——顯示需足量且多樣的工具。檢索基線各資料集表現不一，除 TabMWP 外多無實質增益，凸顯更佳檢索演算法之需。整體 CRAFT 全面領先，尤在困難的 VQA 上：較 vanilla ViperGPT，GQA/OK-VQA/A-OKVQA 的 SAcc 絕對提升 10.4 / 18.0 / 15.2；基於同一工具集，CRAFT 的檢索也優於替代法（唯 TabMWP 上 BM25 例外，因該資料集模式較單純、未能凸顯 CRAFT 檢索優勢）。

4. 進一步分析（於 VQA 資料集）

表 3 涵蓋抽象化與檢索組件的消融、以及不同 backbone 下 ViperGPT 與 CRAFT 的比較。

4.1 抽象化是否有助工具使用？

把抽象化步驟消融（但仍為每個解指派獨特函數名與 docstring 以利多視角檢索、公平比較）。結果（表 3）：去抽象化明顯掉分（GQA 45.4→37.1），確認其重要性。不過即使去抽象化的 CRAFT 仍勝過 ViperGPT（尤在 OK-VQA/A-OKVQA），原因可能是：工具集夠大夠多樣，即使不抽象也能覆蓋新題；且取回的工具提供正確解法思路，LLM 能據以高效適配新題。

4.2 檢索三元組中每個匹配同等重要嗎？

分別把問題、函數名、docstring 從匹配中移除。結果（表 3）：三者缺一皆傷表現，驗證設計合理性。其中函數名最關鍵——消融時 SAcc 掉超過 6.6（絕對值）。

4.3 CRAFT 對更強 backbone 仍有效嗎？

改用 GPT-4 為 backbone（因預算僅與 ViperGPT 比）。結果（表 3）：CRAFT 於 GPT-4 仍一致更佳（如 GQA 55.6/58.8、OK-VQA 39.0/49.1、A-OKVQA 35.3/44.8），確認對更強 backbone 亦有助。但增益不如在 GPT-3.5-Turbo 上明顯——作者推測與近期發現一致：LLM 可從更強模型的指引獲益，卻難從自身指引獲益；由 GPT-4 造的工具對 GPT-4 自身洞見較少，故外部工具增益受限。

4.4 工具集變大能否持續提升？

依 §2.1 的迭代採樣（共 11 個 epoch），取初始、中間、最後 epoch 的工具，構成大小 0、261、337、525 的工具集。結果（圖 3）：三個資料集的 soft accuracy 隨工具集擴大持續上升，展現可擴展性；上升趨勢未止，暗示續擴仍有潛力。最大增益出現在「從無工具到 261 個工具」——驗證造專用工具集以客製 LLM 的有效性。

4.5 工具集裡有什麼？（表 4）

以**循環複雜度（cyclomatic complexity）**衡量複雜度（良好軟體應 ≤10，越低越不易出 bug），以工具分組數衡量多樣性（用 Louvain 社群偵測分群）。結果：VQA / 表格 / 數學的平均複雜度為 2.64 / 2.07 / 1.34（均遠低於 10，結構良好可靠）；工具數 525 / 181 / 282，分屬 195 / 23 / 234 類——顯示 MATH 模式最多樣、VQA 次之，而 TabMWP 較同質、用較少工具即可解好。

5. 相關工作

5.1 LLM 工具學習：LLM 接上真實 API 便能與外部系統互動；先驅工作把 GPT-3 接上瀏覽器並用人工示範網搜，後續擴及計算機、日曆、直譯器、物理模擬器、地圖等，並探索 bootstrapping 等弱監督法；近期則把閉源 LLM（ChatGPT）的工具使用能力蒸餾到開源 LLM（讓 ChatGPT 產生示範 API 用法的合成資料再微調開源模型）。本文則超越僅依賴既有工具——透過創建客製工具＋推論時檢索來適配下游任務。

5.2 工具創建與檢索：此領域探索相對有限。工具創建方面，Cai et al.（LATM）用三個訓練樣本造工具、三個驗證樣本評估，工具庫量受限且假設訓練/測試分佈相近；Qian et al.（CREATOR）僅依當下查詢造工具，故不可重用，削弱了工具創建的根本目的。工具檢索方面，既有多為人工預選工具、啟發式選擇、或僅「使用者查詢 vs API 名稱」的簡單相似度。本文則要造一個可被下游任務有效利用的大工具庫，並解決「從大工具庫檢索相關工具」的挑戰。

6. 結論

CRAFT 是一個以工具創建與檢索泛化 LLM 到多樣領域與任務的通用框架。其效果由困難任務上的表現提升印證，並附有對組件貢獻、所造工具集、可擴展性的洞見。

附錄重點（實作與局限）

  • 實作（附錄 B）：VQA 從通用指令集採樣造工具——用 LLaVA 並補一個基於 COCO-2017 的指令集（令 GPT-3.5-Turbo 依影像 caption 生 QA 對並過濾掉可純語言回答者），共採 2,000 題（1,000 來自首輪隨機、其餘 1,000 來自後 10 輪各 100），以 ViperGPT 生具體解。表格與數學無高品質指令集，改用 TabMWP、MATH(algebra) 的訓練切分造工具，採 500 題（200 首輪＋後 3 輪各 100）。檢索數 k 對 q_t/f_t/d_t 分別設 10/5/10。
  • 局限與未來（附錄 A）：(1) 目前建立在程式碼生成上，只適用「能寫程式求解」的任務——擬用偽代碼（pseudocode）擴展範疇；(2) 效果高度依賴 backbone 的工具操作能力，部分開源模型在此具挑戰的工具操縱設定下近乎隨機——未來將設法激發開源模型的工具操縱能力。
