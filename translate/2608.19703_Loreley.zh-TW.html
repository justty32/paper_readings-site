論文／訪談原始來源

Loreley: Repository-Scale Program Evolution with Quality-Diversity Search

問題與貢獻

序列式 agent 搜尋只沿當前 champion 累積修改，捨棄其他分支；獨立提案式搜尋保留廣度卻每次從根重來。Loreley 在 QD archive 中保留完整 repository 狀態（每個候選是隔離 worktree 產生的 Git commit，由專案自帶 evaluator 判定），將其取樣作為 parent 或供作後續編輯的上下文。三項貢獻：(1) 結合 agent 變異、隔離 worktree、外部 evaluator、持久化排程與 QD 保留的 repository-evolution runtime；(2) 等量候選 job 下比較 Loreley QD、Sequential Champion、Independent Root，Zstandard 上 48 job 未能證明 QD 優勢；(3) 區分「機制是否啟動（engagement）」與「是否有效（efficacy）」——血緣顯示非當家狀態被保留並再取樣，但 checkpoint 與 holdout 在測試視界內未顯示對應效益。

方法：Repository-Level QD Search

Engagement 指 archive 保留多個可行狀態，且後續 job 取樣到「若套用單一當家規則就不會保留」的狀態；efficacy 指此可用性能否在固定預算下改善 held-out 端點。Evaluator 把 commit 映射到目標向量與報告產物，正確性／範圍／資源／精度檢查都在其內。Behavior descriptor 由完整合格 repository 狀態的 file embedding 均值算出，PCA 降到 3 維後選一個 MAP-Elites cell；cell 內用 ε-tolerance 去近重複、ε-dominance 篩非支配解，超容量時用 crowding distance 保留邊界權衡。Cell 選擇與 cell 內成員選擇分兩步均勻取樣，避免大 Pareto front 被過度取樣。

Inspiration 從鄰近 occupied cell 無放回取樣，只提供上下文、不改變新 commit 的 Git parent；parent edge 記血緣，inspiration edge 記「餵給 agent 的資訊」，兩者分開統計。流程：warm-up 收集 descriptor 歷史 → fit PCA、warm-up 狀態上 Pareto front → 凍結當前 archive 為抽樣快照 → 抽 cell、base 與鄰近 inspiration → agent 在隔離 worktree 編輯並外部評估 → 無論成敗計入 job 預算，有效且獨特的結果才進歷史與嘗試 Pareto admission → 定期 refit PCA 並用「refit 前保留的紀錄」原子性重建 archive。系統把搜尋基礎設施與 evaluator 分開；agent 文字說明不當作正確性證據，descriptor 是搜尋座標，不宣稱能完美度量語意新穎性。

實驗設計

受控研究：單一 Linux ARM64 主機，7 組 paired block，每 block 三政策各 48 個 physical job（共 1,008），全部只從同一 frozen root（c604f825）初始化，共用目標修訂版本、任務指示、planning/coding route（gpt-5.6-sol / gpt-5.6-luna）與 training evaluator，差異只在 online 的 parent／context 規則——這正是三政策的定義。QD 額外用 1,536 維程式碼 embedding 降到 3 維 whitened PCA 座標，每 4 個新狀態 refit；單一 island、無 migration，設有深度 gate（正式 QD block 皆通過）。Evaluator 做乾淨 release build，交叉解碼並量測 level 1/3/5 單執行緒壓縮／解壓縮效能；訓練／驗證／holdout 用互斥語料庫。8/16/24/32/40/48 job 記錄 checkpoint，按 training lower bound 排序取最多 10 個 finalist 上 validation；holdout 只量測固定下來的 winner。主要端點是 48-job holdout 壓縮吞吐比，用配對 log 差異的 BCa 95% 區間（20,000 次重抽樣）、精確符號翻轉檢定與 Holm 校正；作者明講 7 個 block 是同目標同主機的獨立搜尋重複，不是跨 repository 樣本。

三個較早的 capability campaign（markdown-it-py、python-pathspec、另一版 Zstandard）用凍結修訂版本、外部 evaluator 與人工種子（因系統當時無可靠自動多樣化起始生成法），種子照樣計入 job 預算，最終回報候選皆為 generation-4 後代，屬能力案例、非政策對照。

結果

配對政策比較：1,008 job 產出 948 個成功候選。48-job 增益：Independent Root +0.502%（2/7 達 ≥0.5%）、Loreley QD +0.824%（6/7）、Sequential Champion +0.960%（7/7）。配對效應：QD 對 Independent +0.320%（95% BCa [-0.082%,+0.686%]，Holm p=.375），QD 對 Sequential -0.135%（[-0.556%,+0.161%]，Holm p=.547）。兩區間皆跨零——未證明 QD 優於任一對照，也未證明等效，觀測排序特定於 Zstandard、這兩個 GPT route、root-only 初始化與 48-job 視界。逐一移除單一 block 的敏感度分析顯示 QD–Sequential 點效應在 -0.226% 至 +0.020% 間游移。

Archive 血緣：7 個 block 中 QD archive 全被啟用，每個最終 winner 都是後代而非 root。作者定義「非當家」＝training compression lower bound 嚴格低於「root 分數與此前所有 QD 候選分數的最大值」，是回溯套用在觀測串流上的規則，不是對 Sequential 若獨立跑會產生什麼的反事實宣稱。4/7 winner 的 primary-parent 血緣含非當家祖先，納入 inspiration edge 後增至 6/7；67 個相關節點中 49 個曾被 admit 為非當家、之後又出現在某條 outgoing edge。4 條血緣含 15 個非當家祖先，其中 7 個祖先的後代分數超過祖先進入串流時的當家分數——作者稱這是政策內的延遲分支存活證據，不是因果效益估計。全體 QD 資料庫中位數 20 個不同 primary parent，最深候選達 generation 5–9，最終 archive 佔 64 格中的 9–12 格。

capability campaign：348 個終端 job，310 成功。markdown-it-py 候選在驗證集 +6.75%；python-pathspec 候選從 -0.22% 種子四代進化至 +25.14%（training winner 未過 allocation gate 被替換，回報候選為 post-hoc 選定）；較早版 Zstandard 候選在擴大驗證集排名第十而非人工種子，選定集 +1.234%、原始 holdout +1.173%、新密封語料庫 +0.891%。

討論、局限與結論

Sequential Champion 也產生過 generation-5 最佳範例，QD 最終 winner 深度中位數僅 3，顯示序列搜尋不需多條活分支也能累積大改動；QD 的代價是持續維護多條軌跡的機會成本，除非保留分支之後帶來更好編輯。48-job 視界是關鍵開放變數：已有理論證明 MAP-Elites 在特定組合問題類別上有優勢，但不能直接推論到 repository 優化，目前資料無法區分「視界不足」與「descriptor／archive／取樣規則本身無效」。Archive 覆蓋率 14.1%–17.2%（分母與投影不同、不可跨任務排名）；未投影的 repository 向量彼此極接近（中位數餘弦距離 3.22e-6，patch 通常只動一小部分檔案的自然結果）；51 個候選中 22 個（43.1%）在最終 PCA 下會落入不同 cell，顯示 descriptor 對投影排程路徑依賴。

配對比較只涵蓋一個 repository、一組 GPT route、一台主機、7 個 block，區間仍與正負兩方向的中等效應相容，估計的是同任務重複搜尋間的變異，不是跨 repository 變異。實驗未拆解學習 descriptor、Pareto 保留、inspiration 取樣、並行度各自的獨立效果。三個 capability case 的選定資格各有保留，只確立能力而非共享推論主張。下一步是在 Zstandard 做更長配對曲線並加入第二個 repository，測試 QD 保留的分支能否回本。

結論：archive 確實保留非當家 commit 並後續取樣，capability campaign 也產生累積多檔案改動。但受控結果窄：單一 Zstandard 修訂版本、48-job 視界下 QD 未勝過 Sequential Champion，對 Independent Root 的正向點估計仍不確定。
