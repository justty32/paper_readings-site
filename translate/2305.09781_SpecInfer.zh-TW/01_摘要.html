摘要

本文提出 SpecInfer，一套以樹狀推測推論與驗證（tree-based speculative inference and verification）加速生成式大型語言模型（LLM）服務的系統。核心想法是：用小型的推測模型（small speculative model, SSM）去預測 LLM 的輸出，並把這些預測組織成一棵 token tree（詞元樹），樹中每個節點代表一條候選 token 序列。整棵 token tree 所代表的所有候選序列，透過一種新穎的樹狀平行解碼（tree-based parallel decoding）機制，一次性地對 LLM 平行驗證其正確性。SpecInfer 把 LLM 當作詞元樹的驗證器（verifier）而非逐步解碼器（incremental decoder），在可證明地保持模型品質的前提下，顯著降低端到端延遲與運算需求。評測顯示 SpecInfer 對分散式 LLM 推論加速 1.5–2.8×、對卸載式（offloading）LLM 推論加速 2.6–3.5×，且產生與逐步解碼完全相同的生成結果。

1. 引言

GPT-4 等生成式 LLM 在問答、程式合成、任務自動化等領域展現強大能力，但因參數量龐大、架構複雜、運算需求高而難以快速且低成本地服務（例如最大的 GPT-3 有 1750 億參數，需 8 張以上 A100 才能以半精度存放，單次推論需數秒）。

LLM 採自迴歸解碼（autoregressive decoding）：一次生成一個 token，每個 token 的生成都依賴輸入 prompt 與先前生成的所有 token。既有系統採逐步解碼（incremental decoding）——先一步算完所有 prompt token 的 activation，之後每次迭代只解出一個新 token。這種做法尊重 token 間的資料依賴，但每個請求內的平行度極低、GPU 利用率不佳；且 Transformer 的注意力機制需存取先前所有 token 的 key/value，為避免重算而採 KV 快取（key-value cache），對長序列任務（GPT-4 支援達 32K token）帶來可觀記憶體開銷，限制了並行服務的請求數。

受處理器最佳化中「推測執行（speculative execution）」啟發，近期出現序列式推測推論（sequence-based speculative inference）：用一個 SSM 生成一段 token 序列，再用 LLM 平行檢查其正確性。但這類方法只考慮單一 SSM 產生的單一序列，因 SSM 與 LLM 之間存在模型容量鴻溝（SSM 通常小上數個數量級）而難以良好對齊。

本文提出的 SpecInfer 用樹狀推測推論改善此問題。關鍵洞見是同時考慮多樣的推測候選（而非既有方法的單一候選），把候選組織成 token tree（每個節點代表一段推測 token），再對 LLM 平行驗證整棵樹的所有候選序列，大幅增加單一 LLM 解碼步驟能生成的 token 數。相比序列式推測，樹狀結構能顯著提升驗證單一 token 的成功率（隨機解碼下由 52–57% 提升到 96–97%，見表 1）。

要實現此效益須克服兩大挑戰：

  • 挑戰一：候選序列的搜尋空間極大。 現代 LLM 詞彙表龐大（OPT 家族有 50,272 個 token），且要最大化推測效能需一次預測多個未來 token；SpecInfer 平均可正確預測未來 4 個 token，對應的搜尋空間高達 50272⁴ ≈ 6×10¹⁸ 種組合。SpecInfer 利用既有的蒸餾／量化／剪枝版本 LLM 作為 SSM 來引導推測，並提出 **expansion（擴張）**與 **merge（合併）**兩種建樹機制，分別挖掘單一 SSM 內部與多個 SSM 之間的多樣性。
  • 挑戰二：驗證推測的 token。 許多應用採隨機解碼（stochastic decoding）（依機率分佈取樣），為保持 LLM 的生成品質，SpecInfer 必須保證其樹狀推測驗證產生的下一個 token 服從與逐步解碼完全相同的機率分佈。為此提出 multi-step speculative sampling（多步推測取樣， MSS），在保證等價的同時最大化可驗證的 token 數；並以樹狀平行解碼在單一 LLM 解碼步驟內同時驗證整棵 token tree。

貢獻：(1) 提出樹狀推測推論與驗證系統 SpecInfer；(2) 提出 merge 與 expansion 兩種建樹法挖掘 SSM 內與跨 SSM 的多樣性；(3) 提出樹狀平行解碼一次驗證整棵樹；(4) 實測分散式加速達 2.8×、卸載式達 3.5×。

2. SpecInfer 概觀

SpecInfer 包含一個以學習為基礎的推測器（learning-based speculator），吃進一段 token 序列、產出一棵推測 token tree，目標是最大化推測樹與 LLM 逐步解碼所生 token 的重疊。

準備 SSM 的方式：其一，現代 LLM 家族常已附帶用相同資料集預訓練的較小架構（如 OPT 家族除 OPT-175B 外還有 OPT-125M、OPT-350M），可直接當 SSM；其二，SpecInfer 以 expansion 與 merge 兩種推測法提高覆蓋率，推測 token 皆組織為樹。

演算法對比：既有系統的逐步解碼（Alg. 1）在迴圈中每次 Decode(LLM, S) 得一個 token 並附加。SpecInfer（Alg. 2）則每次迴圈先 Speculate(S) 得 token tree N，再 TreeParallelDecode(LLM, N) 為每個節點產出一個 token O(u)，最後依貪婪或隨機分別用 VerifyGreedy / VerifyStochastic 對照 O 與 N 產出一串已驗證 token V。

SpecInfer 對 LLM 的用法異於既有系統：不是當「預測下一個 token」的逐步解碼器，而是當驗證整棵推測樹的驗證器。計算每個 token 的 activation 時，把它在樹中的所有祖先當作前置 token（例如節點 t₃,₀ 的注意力依序列 (t₀, t₁,₀, t₂,₁, t₃,₀) 計算）。此設計帶來兩大優勢：

  • 減少對 LLM 參數的記憶體存取：逐步解碼每生成一個 token 就要存取 LLM 全部參數（卸載式推論下更嚴重）；只要推測樹與 LLM 實際輸出有非空重疊，SpecInfer 就能顯著減少參數存取。存取 GPU HBM 的能耗比浮點運算高 2–3 個數量級，故也直接省能。
  • 降低端到端延遲：逐步解碼因 token 間的順序依賴而必須序列化；SpecInfer 把 LLM 當驗證器，一次驗證 pass 就能同時檢查樹中所有 token，實現單一請求內跨 token 的平行化。
