5. 覆蓋率

每個框架在「把 JSON schema 翻譯成能可靠保證 LM 輸出合法的約束集」時都有其限制。定義三種覆蓋率：

  • 定義 5.1 Declared Coverage（宣稱覆蓋率）：框架未明確拒絕該 schema、也未發生執行期錯誤（例外、崩潰）即算宣稱覆蓋。
  • 定義 5.2 Empirical Coverage（實測覆蓋率）：實驗顯示框架產生的約束確實使 LM 輸出符合 schema，即算實測覆蓋。
  • 定義 5.3 True Coverage（真值覆蓋率）：框架產生的約束與原 JSON Schema 定義精確等價（放行所有合規生成、拒絕所有不合規生成）。

理想的是 True Coverage，但因能對某 schema 驗證的 JSON 實例有無限多，缺乏「窮盡比較 schema 語義 vs 框架實作」的形式驗證方法時實務難測。Empirical 是 True 的近似（只檢查實驗中看到的有限輸出）。（附錄另定義 theoretical coverage：特性完全被引擎支援的 schema 比例。）

Declared 雖非 True 的估計，卻是 Empirical 與 True 兩者的上界，並可導出額外指標 Compliance Rate（合規率）= Empirical / Declared：估計「框架一旦接受某 schema，真能保證合規」的可靠度。

5.1 設定

以 Llama-3.2-1B-Instruct 測實測覆蓋率（夠小可高效運行、輸出品質仍佳）。prompt 為簡單指令 + two-shot 範例，驗證用 jsonschema Python 函式庫（JSON Schema Draft 2020-12，開啟 string-format 檢查）。採零溫度貪婪解碼、單次生成，文法編譯限時 40 秒、生成另限 40 秒，超時即視為 schema 處理失敗。

5.2 結果（Table 4）

實測覆蓋率：Guidance 在 8 個資料集中的 6 個最高；其餘兩個（領域專屬的 Washington Post、以及格外難的 JSON Schema Store）由 Llamacpp 領先。閉源文法引擎（OpenAI/Gemini）覆蓋率一貫最低（除一個資料集外都墊底）。LM-only（Llama 3.1 已特別微調以遵守 JSON schema）在易到中等資料集覆蓋率尚可，但在 Github Hard、JSON Schema Store 等難集及 Washington Post 這類領域專屬集顯著下滑。實測覆蓋率是真實表現的合理指標，但受所用 LM 與取樣方法影響。

5.3 JSON Schema Test Suite：互補評測

官方 Test Suite 原為測試 JSON Schema 驗證實作的正確性與合規性而設，是覆蓋規格眾多特性的完整測試案例集，適合用來評估文法引擎的正確性。它把測試案例組織成 45 個類別，每類對應 JSON Schema 的一個特性（通常是特定 keyword 如 required，或緊密相關的 keyword 群如 if-then-else），少數類別測更廣的行為（如 infinite-loop-detection）。每個測試案例含一個 schema 配一組被標為 valid 或 invalid 的 JSON 實例。評估覆蓋時，引擎須能成功生成每個 valid 實例、並阻擋每個 invalid 實例才算「通過」。除編譯失敗外，定義兩種失敗模式：

  • 定義 5.4 Over-constrained（過度約束）：框架拒絕了依 schema 應為 valid 的實例——過嚴，排除了本應允許的輸出。
  • 定義 5.5 Under-constrained（約束不足）：框架允許了依 schema 應為 invalid 的實例——過鬆，放行了本應拒絕的輸出。

過度約束會限制 LM 的表達力，可能擋掉合法回應、傷害下游表現；約束不足則無法保證所有回應合法，往往需要額外的後處理或重試邏輯。

  • 單獨最高：Guidance 在 19 類單獨最高，XGrammar 10 類，Outlines 1 類，Llamacpp 0 類。

失敗分析（Table 6，各失敗類型至少出現一次的類別數）：

失敗類型 Outlines Llamacpp XGrammar Guidance
編譯錯誤 42 37 3 25
過度約束 16 18 5 7
約束不足 8 7 38 1

Guidance 總失敗最少，尤其把 under-constrained 錯誤壓到最低。Outlines、Llamacpp、Guidance 有一致的失敗型態：多數錯誤發生在編譯階段，且過度約束比約束不足更常見。XGrammar 相反——編譯錯誤最少，但 under-constrained 失敗最多，是偏向寬鬆的取捨。

作者強調：Test Suite 表現與實測覆蓋率無直接對應。其一，各特性在真實 schema 中出現頻率不均，特定特性的強弱會依其普及度而有不成比例的影響；其二，under-constrain 實質上把責任下放給 LM，LM 縱使缺乏嚴格約束仍可能產出合法輸出。因此 under-constrain 可以是正當策略，但需謹慎實作與透明揭露才能確保可靠。
