6. 品質

原則上受約束解碼只過濾非法 token，不應影響輸出品質。但因 tokenization 的歧義 與約束干預造成的分佈偏移（distributional shift），情況更複雜。舉一個假想的玩具例子：LM 在 GSM8K 題中可能答 89,000 而非正確的 89000；受約束解碼會擋掉非法的 ,，雖強制了結構合規，卻可能讓 LM 走出分佈而改生成 890000。Will Kurt（2024b）則主張，先前研究（Tam 等人 2024）觀察到的效能下降，來自不當的 prompting、上下文資訊不足、以及設計拙劣的 schema。

6.1 設定

沿用並擴充 Kurt（2024b）與 Tam 等人（2024）引入的任務，採其中三個推理任務評估受約束解碼對任務準確率的影響（Table 7）。這些任務刻意設計成輸出結構簡單，以隔離受約束解碼對「推理本身」的影響。用 Llama-3.1-8B-Instruct 量測，遵循 Kurt（2024b）的原始設定與 prompt。

三任務（Table 7）：

  • Last Letter：輸入數個名字，輸出各字首尾字母的串接（如 nrdn）；CoT 推理 + 答案為 a–z；大小寫敏感精確匹配。
  • Shuffle Objects：輸入一連串交換序列與選項，輸出 A–E；CoT 推理 + 答案為 A–E；精確匹配。
  • GSM8K：基礎計算題，輸出數字；CoT 推理 + 答案為整數；數字精確匹配。

三任務約束：Last Letter 輸出須為 a–z 字母串接；Shuffle Objects 輸出須為括號內單一 A–E 字母；GSM8K 輸出須為合法整數或浮點數。三者輸出統一為含 "reasoning" 與 "answer" 兩欄的 JSON 物件：{"reasoning": <對答案的推理>, "answer": <最終答案>}。

6.2 結果（Table 8）

無論哪個框架，受約束解碼都優於無約束設定。 Guidance 在所有任務一致最佳，每個任務約比 LM-only 高 3%，作者認為可能歸功於其 token-healing 實作。

框架 Last Letters Shuffle Objects GSM8K
LM only 50.7% 52.6% 80.1%
XGrammar 51.2% 52.7% 83.7%
Llamacpp 52.0% 52.6% 82.4%
Outlines 53.3% 53.0% 81.6%
Guidance 54.0% 55.9% 83.8%

7. 結論

我們提出了一個以 JSON schema 為對象、聚焦效率／覆蓋率／輸出品質三面向的完整受約束解碼評估框架，並引入含 10K 條真實 JSON schema 的 JSONSchemaBench，讓評估能在真實條件下穩健進行。評估既凸顯了當前最先進框架的進展，也揭示其限制。我們希望這些發現與基準能引導結構化生成的後續研究，並協助社群辨識最有效的工具、擴展受約束解碼的能力。
