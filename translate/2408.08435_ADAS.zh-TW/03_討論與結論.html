6. 討論與結論

安全考量：雖然在本文採用的 FM 與設定下，模型生成的程式碼極不可能有明顯惡意行為，但仍可能因模型能力或對齊不足而具破壞性。因應措施：所有生成程式碼在容器化、隔離的安全環境執行、徹底人工審查以確認無害、並在程式庫中放明確警語。這些作法對齊 SWE-Bench、Voyager 等文獻的安全標準。作者主張發表此工作淨效益為正：它揭示只需 API 存取 FM（無需昂貴 GPU）即可輕易寫出強力 ADAS 演算法，讓社群知其可及性與影響；且 ADAS 能透過自動設計明確、可解釋的 workflow 提升 agent 安全（更可控、可審計）。作者呼籲研究 safe-ADAS，可納入 Constitutional AI 等機制。

未來工作：

  • 高階（Higher-order）ADAS：因 meta agent 本身也是 agent，ADAS 可變得自指（self-referential）——meta agent 也能被 ADAS 改進，甚至 meta-meta agent，形成更高階的 meta-learning。
  • 線上持續學習（Online Continual Learning）：部署後 agent 會從環境與使用者收到大量回饋，人工持續改進困難；ADAS 自動化設計後，部署後的線上持續學習變得可行。
  • 多目標 ADAS：本文只優化 performance，實務常需同時考慮成本、延遲、穩健性等，可整合 NSGA-II 等多目標搜尋。
  • 更理解 FM：從湧現架構獲得洞見。例如 GPT-3.5 上最佳 agent 用複雜回饋機制，但遷到更強模型時「較簡單回饋機制＋更多精修」反而更好——顯示 GPT-3.5 評估/精修能力較弱，需複雜回饋機制，而更先進模型更受益於簡單回饋。
  • 更複雜領域：目前只在單步 QA 驗證，未來可擴到與複雜環境多步互動的真實應用。
  • 以既有模組作種子：站在 LangChain、RAG、搜尋引擎工具等人類成果之上，並支援多模態、讓不同 FM 依難度/隱私彈性可選。
  • 更好的搜尋演算法：目前搜尋演算法很簡單，可引入 Quality-Diversity、AI-GA、開放式演算法等更精巧的想法。
  • 更智慧的評估函式：目前只用數值分數，昂貴且遺漏資訊；可讓 meta agent 分析詳細執行日誌、處理無標準答案的主觀任務、乃至搜尋跨多領域的通才 agent。
  • 理解複雜性從人類組織中的湧現：agentic system 主要在自然語言上運作，與人類組織/社會有密切連結，ADAS 或有助觀察「如何從簡單條件 bootstrap 出複雜性」。

結論：本文提出新研究問題 ADAS，示範一條有前景的路線——把 agent 定義在程式碼裡，由 meta agent 以程式碼自動發現新 agent；並提出 Meta Agent Search，讓 meta agent 基於既往發現反覆撰寫有趣的新 agent。實驗顯示它跨眾多領域一致勝過 SOTA 手工 agent，且發現的 agent 能良好地跨模型、跨領域遷移。整體上，本工作揭示了一條「由下而上、全自動開發強力 agent 系統」的令人振奮的新方向。
