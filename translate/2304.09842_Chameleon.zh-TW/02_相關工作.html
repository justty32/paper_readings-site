2. 相關工作

組合式推理：神經模組式與組合式方法一直被用來自動完成子任務分解，提升可解釋性與跨任務調適性。早期工作（Andreas et al.）主張複雜推理任務本質上是組合式的，提出神經模組網路（NMN）以分解子任務，但依賴脆弱的既有解析器且受限於模組配置。後續工作在無需解析器的前提下以端到端方式、藉強化學習與弱監督預測特定實例的網路佈局。視覺推理領域曾提出結合深度表徵學習與符號程式執行的「程式生成器＋執行引擎」模型；數學推理領域也有可解釋求解器，把定理知識當作條件規則、逐步做符號推理。Chameleon 取靈感自神經模組網路，但有兩項優勢：其一，不需要昂貴的特定任務程式監督來訓練模型，而是生成易於泛化到不同領域任務、可即插即用擴充新模組的循序程式；其二，不需訓練，而是靠 LLM 的 in-context learning 能力，以自然語言指令與示範來提示生成程式。

工具增強型語言模型：LLM 的發展刺激了 prompt learning 與 instruction learning 研究。儘管 LLM 性能亮眼，仍受限於無法存取最新資訊、無法用外部工具、無法做精確數學推理等問題。ScienceQA、TabMWP 等基準因而出現，用以評估 LLM 應付需要外部工具的複雜推理挑戰的能力。與此同時，運用外部工具與模組化方法強化 LLM 的研究興趣日增：藉網頁搜尋引擎存取即時資訊、運用外部資源的領域知識；也有工作用 Python 直譯器生成複雜程式以運用強大算力、更有效執行邏輯推理（如 Toolformer 構建工具使用增強資料以訓練語言模型選用五種工具）。視覺工具方面，多項工作以 Hugging Face 模型、Azure 模型、視覺基礎模型強化 LLM 處理視覺任務的能力。

論文 Table 1 系統性比較 Chameleon 與其他工具增強型語言模型（CoT、Lila、PoT、Code4Struct、PAL、MathPrompter、ART、Toolformer、WebGPT、MM-ReAct、Visual ChatGPT、ViperGPT、VisProg、HuggingGPT），涵蓋工具規模與類型（OpenAI／Hugging Face／GitHub／網頁搜尋／程式碼）、技能維度（圖像、網頁、知識、數學、表格）、以及是否支援組合、規劃、即插即用擴充。多數既有方法要嘛工具集小，要嘛限定特定任務工具，因而在技能維度上受限、難泛化到新任務。近期工作多依賴大量監督資料聚焦於生成指令或程式來推斷工具選擇，需針對特定任務與工具精心設計提示，缺乏彈性與適應性。相對地，Chameleon 只用自然語言指令描述各模組角色並附上少量呼叫範例，即可教會 LLM 組合不同工具，無需額外訓練或工具專屬提示；使用者可自由更換底層 LLM、新增工具、適應新任務。Chameleon 與 AutoGPT（具 AGI 企圖、整合大量工具以達成使用者定義目標的自主 GPT-4 代理）精神相通，但 AutoGPT 仍在開發中，本文首次在成熟基準上落實此構想並驗證有效性。

3. 通用框架：Chameleon

Chameleon 包含一個模組庫（module inventory），定義各類工具，以及一個 LLM 規劃器，負責把原始問題分解成可由特定任務工具有效解決的子任務。不同於既有工具增強型 LLM，Chameleon 的模組庫涵蓋多種工具類型（Table 2），使其能展現圖像理解、知識檢索、網頁搜尋、複雜數學推理、表格理解等多種推理能力。Chameleon 不生成特定領域程式，而是用 LLM 規劃器生成遵循自然語言指令的自然語言式程式，較不易出錯、易擴充新模組、對使用者友善。

形式化：給定輸入查詢 x₀、模組庫 ℳ 與約束 𝒢，自然語言規劃器 𝒫 透過生成自然語言式程式，選出一組可依序執行以回答查詢的模組。模組庫 ℳ 由一組預建模組 {Mᵢ} 組成，各對應一種工具（Table 2）；𝒢 是計畫生成的限制條件（例如模組的並行關係與先後順序）。𝒫 是在少樣本設定下被提示生成一串模組名稱的 LLM，提示內容含規劃任務指令 ℐ、ℳ 中各模組描述與對應限制 𝒢、以及少量示範 𝒟。一個長度 T 的計畫記作 p=⟨M¹,…,M^T⟩，其中每個 Mᵗ∈ℳ；即 p←𝒫(x₀; ℐ, ℳ, 𝒢, 𝒟)。

計畫生成後，各步驟對應模組依序執行。計畫是以字串比對綁定各模組的自然語言程式。在時間步 t 評估模組 Mᵗ 時，執行輸出 yᵗ←Mᵗ(xᵗ⁻¹; cᵗ⁻¹)，其中 xᵗ⁻¹ 是當前模組的輸入、cᵗ⁻¹ 是先前模組執行歷史累積的快取資訊（如圖像語意、檢索到的知識、生成的程式）。供下一模組 Mᵗ⁺¹ 使用的問題輸入 xᵗ 與快取 cᵗ 分別由 xᵗ←update_input(xᵗ⁻¹, yᵗ) 與 cᵗ←update_cache(cᵗ⁻¹, yᵗ) 更新，這兩個函式是針對每個 Mᵢ 手工設計的：update_input 作用於問題、表格脈絡、圖像等輸入元素，於模組執行後更新；update_cache 對應新資訊的生成（如輸入圖像的描述、從外部資源檢索到的知識）。最終，查詢的回應 r 由最後一個模組 M^T 生成：r=y^T←M^T(x^{T−1}; c^{T−1})。
