論文／訪談原始來源

Agentic Transaction: Towards ACID-Compliant Agent Systems

摘要與第 1 節：問題

LLM agent 正從單輪對話助手演變成在持久環境、多步驟工作流上執行長程任務的自主系統。作者觀察到這與交易型資料庫系統要解決的問題類似：可靠執行、一致結果、安全並行、持久狀態管理。論文提出「agentic transaction」概念，把 agent 與執行環境間多輪、任務導向的互動定義為一個有界執行單元，並提出 ACID-compliant agent system 框架，把經典 ACID 性質重新詮釋為四項語意保證：Semantic Atomicity、Semantic Consistency、Semantic Isolation、Semantic Durability。與傳統資料庫交易不同，agent transaction 結合非決定性推理與異質、可能非交易性的副作用；本文提出的語意約束的是「已 commit 的效果」而非要求決定性的執行軌跡。

Definition 2.1（Agentic Transaction）

一個 agentic transaction τ 是有界的 agent 執行單元，由 agent 與執行環境間有限序列的 LLM 驅動互動組成，用來完成一個任務。給定工具集 T 與 skill 集 S，τ=⟨r1,…,rn⟩ 由 n 個 step 組成，每個 step rᵢ=(cᵢ,aᵢ,fᵢ) 包含該步驟可用的 LLM context cᵢ（含 T 與 S）、呼叫工具或 skill 的動作 aᵢ、環境回傳的 feedback fᵢ。τ 只有在執行滿足任務條件且保持語意不變量時才 commit；否則中間效果會被回滾或補償，確保不留下無效副作用。

第 2.2 節：ACID-Compliant 資料 Agent 系統

Semantic Atomicity：把一段 dependency-aware 的模型呼叫、工具呼叫、文件變更、外部動作序列視為單一語意單元，效果只有在必要操作與驗證都成功後才可見，否則回滾或補償。挑戰在於 agent 工作流長時間執行、動態生成，且常涉及非交易性的外部資源，部分執行可能留下不一致的工作區或無支撐依據的結果。實作分兩層：離線 skill hub 把工具與 skill 變成一級交易物件，具備生命週期介面，對會修改 workspace 的 skill 用 idempotency key、write-ahead action log、checkpoint、自動補償防止無效的部分更新；並用 workload-aware 的 skill router 週期分析歷史系統日誌、動態調整檢索與選用權重。線上則把 agent 軌跡建模成一連串 exploration-execution-validation 循環，每個循環是受 commit-or-retry 語意管控的語意交易單元：confidence-guided exploration 讓 agent 迭代收集證據並避免冗餘探索（比較「有無先前觀察」時的信心差異，差異大代表探索高度依賴既有觀察、新資訊有限，超過門檻就終止）；失敗步驟會被隔離——context 不進記憶、workspace 更新被排除，透過 append-only workspace 確保狀態演化是原子的。

Semantic Consistency：即使中間推理軌跡非決定性，commit 的結果仍須滿足任務目標、執行限制與可得證據。挑戰在於 LLM 生成的計畫可能語法上可執行、但因工具選錯、宣稱無支撐、觀察過期、或使用者意圖與執行結果分歧而語意上無效。離線層面：把成功工作流固化成可重用、帶語意驗證邏輯的 skill（類比資料庫的 materialized view）；並主張需要專門衡量「執行穩定度」而非單次正確率的 benchmark 來指導微調。線上層面：confidence-based validation 整合執行錯誤、決策/程式碼信心差異、LLM 反思回饋三種訊號，任一超過門檻即觸發重試。信心量化為目標輸出 token 級 log 機率平均值的指數；決策信心差異比較「有無探索證據」下對已執行決策的信心；程式碼信心差異則對決策相關的程式碼片段比較有無探索證據時的信心。

Semantic Isolation：與傳統交易主要隔離讀寫衝突不同，agentic transaction 需要隔離 agent、context、workspace、operation 間的語意依賴。Agent 級隔離依子任務語意與依賴關係決定策略（存取限制、分支策略、通訊間隔、終止條件），對應三種協作模式：independent 子 agent 處理互斥子任務、各自獨佔資源並行執行；collaborative 子 agent 共建單一產物，各維護獨立 workspace 分支、定期結構化同步、用類 Git 工作流合併；competitive 子 agent 探索不同假設，各自在隔離環境（如 Docker）執行，最終選最有希望的軌跡，可用 copy-on-write 與提早終止改善效率。Operation 級隔離則由 skill hub 透過效果標註推論、版本化 workspace、快照執行、樂觀驗證防止失敗或衝突操作污染共享狀態。

Semantic Durability：透過 (1) transaction-aware 語意狀態管理與 (2) 持久執行追蹤與復原達成。既有作法多用逐步 LLM 摘要壓縮互動歷史，但常無法保留 transaction 級的語意結構——過度壓縮關鍵資訊，或保留無用的 step 級細節。作者提出 transaction-aware evolving memory，以知識圖形式演化，由專門 LLM 執行插入、合併、拆分、刪除操作；訓練監督可從 agent 軌跡自動導出，未來執行步驟引用過的資訊即為長程相關性訊號。此外用 append-only workspace 記錄 provenance、LLM 互動、工具呼叫、版本化產物，支援稽核與版本感知的失敗復原。

第 3 節：實驗（作者自報）

在 KramaBench（104 個自然語言任務，涵蓋 24 個資料源、6 個領域、1700 個真實資料檔案）上，比較 Claude Code、ACID-Agent、DA-Agent（移除 ACID 設計的消融變體）三種 harness，backbone 用 Qwen3.5-397B-A17B 與 GLM-5.2。主結果：ACID-Agent 在不同 backbone 下整體分數都高於 Claude Code；用 Qwen3.5-397B-A17B 時領先 10.6 個百分點，甚至超過搭配更大 GLM-5.2 backbone 的 Claude Code，但代價是更多 code step 與 token 消耗（主因是探索與重試機制）。一致性評測（Environment 領域，三次獨立跑）：ACID-Agent 分數 88.9±18.6，Claude Code 63.9±30.9（誤差為平均每任務變異數的平方根），作者稱這代表 confidence-guided 探索與驗證能緩解偏離交易語意的非決定性。Ablation：ACID-Agent 優於 DA-Agent，證明 exploration-execution-validation 循環優於傳統 ReAct 式執行；移除失敗步驟隔離機制（讓中間失敗直接更新 workspace 與 context 記憶）分數掉 11.7 個百分點，證明傳播失敗狀態會污染後續執行；ACID-Agent 用比 3-majority-voting Claude Code 更少的 token 卻分數更高，作者以此主張增益來自 ACID 啟發的 harness 設計而非更大推論預算。

第 4 節：開放問題

作者列出四個尚未解決的方向，直接對應四個 ACID 性質：原子性方面，如何建立具可執行語意、品質保證與安全保證的可擴展 skill 生態系；一致性方面，如何透過新架構、benchmark、模型對齊技術、執行 harness、machine-checkable contract、typed tool interface 確保跨執行的可靠推理與穩定表現；隔離性方面，多 agent 系統如何安全協調對共享 context、工具、產物、語意狀態的存取，需要交易抽象與整合資料庫—LLM 服務機制來管理 context、所有權與衝突；持久性方面，如何把 agent 記憶變成支援交易感知狀態管理、失敗復原、持久演化的系統化基礎設施，服務長壽命 agent。

論文未設獨立限制章節，但自稱實驗為「初步驗證」，僅涵蓋資料 agent 垂直領域、單一 benchmark，尚未驗證框架在通用 agent 系統上的適用性。
