論文／訪談原始來源

EvoAlloc：自我修訂的程式評估配置器

第 1–2 節：評估也是搜尋決策

完整評估成本高，而且只有完整評估的候選能進 archive 影響後代，故配置也會改變搜尋方向。既有規則可依中間結果改變決策，通常不修訂規則本身；EvoAlloc 則從配置後果修訂策略，承接選擇性評估及自我改進搜尋研究。（§1–2）

第 3 節：有限預算下的目標

配置器依候選、上下文及中間證據，選完整評估或停止；未完整評估的分數仍隱藏。目標為預算內的期望最佳完整評估分數，另比較達共同目標所需資源。固定規則也可依上下文決策；自我演化另以歷史更新決策機制。（§3）

第 4 節：策略、經驗與反事實探索

固定 allocator LLM 接收自然語言 Strategy、Experiences、程式變動、譜系／手足結果、目前最佳及剩餘預算，選 Full 或 Discard。有便宜中間評估時可選 Partial，取得證據後再決定繼續 Full 或 Stop。當前候選的 Full 結果不在決策輸入內，Partial 也只在取得後供續行判斷使用。（§4.1、附錄 E.1–E.2）

經驗描述反覆出現的情境及結果傾向，記錄支持／反駁案例與 tentative、active、stale 狀態；stale 留作歷史但不指導配置。策略把經驗轉為此次 run 的配置指引。作者設定每五個新 Full 結果更新經驗，每十個提出策略 challenger；warm-up 期間仍作配置判斷，但所有候選均完整評估，直到至少出現一個新最佳與一個非新最佳。（作者自報，§4.2、附錄 B.1）

新舊策略共用線上候選、archive、經驗與決策資訊，執行評估請求聯集一次並共享證據。兩個路徑不同且 Full 已知的案例後，依序比較漏新最佳數、請求 Full 數、Partial 數；首個較佳項決定採納，平手保留原策略。有限視窗的後果排序不保證改善期望搜尋分數。（作者自報，§4.2、附錄 D.7）

選擇性配置會隱藏遭拒候選的結果。EvoAlloc 因此對 Discard／Stop 候選獨立以機率 0.3 作反事實 Full 探索：好結果反駁現行準則，差結果亦提供支持；探索候選完整評估後照常參與搜尋。warm-up、探索與驗證 Full 全計入同一預算，共用評估只算一次。（作者自報，§4.3、附錄 A）

第 5 節：兩種評估情境

所有方法共用 ShinkaEvolve 搜尋骨架，只改評估配置。ADAS-AIME 演化固定 Qwen3-8B solver 外的 Python harness，在 AIME 2024 同一組 30 題搜尋與評估；一次 Full 是三次獨立運行的平均，Partial 用前八題、單一評估種子。Circle Packing 演化安排 26 個不重疊圓、最大化單位正方形內半徑和的 Python 程式；其評估確定性、無 Partial。作者設定 Full 預算分別 75、150，通常各跑五種子；配置及自我演化模型為 Qwen3-Coder-Next。（作者自報，§5.1、附錄 B）

基線為全部評估的 ShinkaEvolve、移除持續策略及蒸餾經驗的 One-Step Alloc、固定統計規則 Lineage-UCB，以及每批生成 15 個候選再由 LLM 淘汰賽選一個的 RPM 適配版。One-Step 使用相同配置模型、上下文、動作及反事實探索。全部方法使用本研究本地開放權重搜尋模型，並非重現 ShinkaEvolve 原研究專有模型結果；RPM 未中選提案的生成成本亦計入。（作者自報，附錄 D.1）

作者自報五種子平均±標準差：ADAS-AIME 最終正確率 EvoAlloc 39.56±6.80%、ShinkaEvolve 35.33±2.57%；Circle Packing 半徑和 2.547±0.030 對 2.343±0.254。主文報相對改善 12.0%、8.7%。達基線平均最終分數所需 Full 減少 59–82%、記錄 LLM tokens 減少 61–89%；這是相同目標的效率，並非完整搜尋總消耗下降。（作者自報，§5.2、附錄 D.2–D.3，表4–5）

消融中移除演化或探索皆有較弱平均軌跡。Circle Packing 探索率掃描的最終表現接近，達標 token 成本以0.3最低。代表案例策略由寬鬆轉嚴，將省下的 Full 投入更多提案。（作者自報，§5.3–5.4、附錄 C）

第 6 節：適用範圍

研究限兩種 benchmark、單次搜尋內的評估層配置；生成器、評估器及更新機制固定。跨 run 經驗繼承、配置生成資源及讓更多機制演化是未來方向。作者稱程式及設定將於接受後釋出。（§6、可重現性聲明）

ADAS 搜尋與評估同題，因此上述結果不能當成未見題目泛化或通用推理提升；策略有限驗證也不是全域最優保證（本檔補註，非作者自陳；依據附錄 B.2、D.7）。

附錄 A–E：成本、驗證與證據邊界

初始策略由五個 baseline run 各十個紀錄、共 50 案例摘要而來，取得案例的成本未計入報告搜尋成本。matched-target 先依完成 Full 索引平均五種子分數與累積 tokens，再找平均曲線首次達標；不是逐種子首達成本的平均，也不是 token 對齊平均曲線的首達成本。（作者自報，附錄 B.1、D.3）

tokens 含提案、評估、配置、自我演化及 shadow validation；Partial 無論停止或繼續均計入。用盡 Full 預算後，作者自報 EvoAlloc 總 tokens 在 ADAS-AIME 為 128.76M、基線 98.44M；Circle Packing 為 10.85M、基線 6.11M，因省下評估被再投入更多提案。配置器自身分別花 1.02M、1.67M tokens。故達標節省不能套成完整預算總節省。（作者自報，附錄 D.3–D.4，表6）

額外消融保留探索候選進 archive，卻隱去其顯式案例回饋，平均結果仍較差，與探索同時支援搜尋及配置學習的解釋一致。不同策略階段覆蓋的 run 不同，不能把彙整探索成功率看成共同時間趨勢。實際策略採納由節省 Full／Partial 決定，對應視窗內漏新最佳數相同。（附錄 D.5–D.7）

prompt 限用決策時可見條件。經驗為描述，UPDATE 只附證據／改狀態，改命題須刪除再新增。案例卡區分原始路徑與後續探索；未探索的丟棄／停止仍為未知 Full。（附錄 E）
