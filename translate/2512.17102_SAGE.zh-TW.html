論文／訪談原始來源

SAGE：基於技能庫的強化學習自進化代理

摘要

LLM 代理在複雜推理與多輪互動中表現出色，但部署到新環境時難以持續自我改進。一個有前景的方向是讓代理將互動經驗轉化為可重用技能存入技能庫，供未來類似任務使用。然而，既有技能庫方法主要依賴 LLM prompt，難以穩定實作。本文提出 SAGE（Skill Augmented GRPO for self-Evolution），一個以 RL 強化技能庫代理自進化能力的新框架。核心組件「Sequential Rollout」讓代理在相似任務鏈中逐步積累技能庫，後續任務可直接取用前置任務產生的技能；「Skill-integrated Reward」在 outcome-based reward 之上疊加技能生成與利用的額外獎勵。實驗於 AppWorld 資料集上，SAGE 應用於以專家經驗做 SFT 初始化的模型後，SGC 提升 8.9%（60.7% vs 51.8%），互動步驟減少 26%，生成 token 減少 59%，全面超越既有訓練方法。

1. 導論

既有 RL 方法（如 GRPO）只考慮單一任務的 outcome reward，不獎勵技能生成品質與跨任務重用。此外，純 prompt-based 技能庫極度依賴基礎模型的指令遵循能力，開源模型難以勝任。SAGE 的設計包含三個關鍵：統一格式的技能庫代理（產生即呼叫）、循序任務滾動（讓技能價值在後續任務中顯現）、技能積分獎勵（額外獎勵高品質技能生成與成功利用）。實驗證明 SAGE 讓開源模型（Qwen2.5-32B）在技能庫代理格式下超越專家（Claude 3.5 Sonnet）的表現。

2. 相關工作

LLM 代理從 ReAct 的「推理後行動」管線到 CodeAct 的「產生可執行程式碼」框架逐步演進。技能庫代理方面，Voyager（Minecraft）、Agent Workflow Memory（網頁）、Agent Skill Induction（瀏覽）皆在任務完成後才定義技能，存在兩缺陷：(1) 長任務中技能生成進一步延長上下文；(2) 任務執行與技能生成分離造成不一致、不利 RL 學習。本文採用 DynaSaur 的統一格式：代理與 API 互動時先定義技能函式再呼叫執行。

3. 方法

3.1 技能庫代理

代理與環境互動的四種操作：(1) 技能使用（從庫中取用 aᵢ 處理任務）；(2) 技能生成（定義新函式 â 並立即呼叫）；(3) 技能更新（執行失敗時修正並重呼）；(4) 技能儲存（執行無誤則入庫）。亦允許直接 API 呼叫（不需定義函式時）。

3.2 SAGE 框架

3.2.1 預備：GRPO

基礎 GRPO（Shao et al., 2024）：對每筆 query q 從舊策略抽樣 G 組輸出，以 clip 後的 importance sampling ratio 乘上組內標準化優勢更新策略。

3.2.2 Sequential Rollout

以任務鏈 (q¹, q²) 取代單任務 rollout。任務 1 產生的技能存於 M² 供任務 2 使用，技能生成品質的獎勵訊號從後續成功回傳至前置任務。任務鏈取自同一場景（AppWorld 每場景含三相似任務），確保技能可跨任務轉移。

3.2.3 Skill-integrated Reward

R₁ = r₁ + 1[r₁=1] × 1[r₂=1] × 1_skill(q²|q¹)
R₂ = r₂ + 1[r₂=1] × 1_skill(q²|q¹)

即任務 1 成功完成且其技能被任務 2 成功使用時額外 +1；任務 2 成功且使用任務 1 技能亦 +1。無程式碼即終止的回合罰 -1.0。此設計等效於自動濾除噪音技能建議、只獎勵後續實際驗證的高收益程序性知識。

3.2.4 SAGE 目標

將 GRPO 的期望擴展為任務鏈 (q¹,q²)∼Q，每組 rollout τᵢ 循序處理兩任務，o²ᵢ 來自不同技能庫 M²ᵢ（異於原始 GRPO 的同 query 設定）。無 KL penalty、優勢以組均值計算。

3.3 一般化至長任務鏈（附錄 B）

支援 K 任務鏈，技能生成獎勵：max_{k<i≤K} 1[rᵢ=1] × 1_skill(qⁱ|qᵏ)；技能使用獎勵：1_skill(qᵏ|q¹,...,qᵏ⁻¹)。實驗顯示三任務鏈不如二任務鏈（TGC 70.6% vs 72.0%），原因為獎勵不對稱與梯度變異增大。

4. 實驗

4.1 設定

  • 資料集：AppWorld（750 任務/250 場景，9 模擬 App、457 API）的 Train 集訓練、Dev 集選 checkpoint、Test-Normal/Challenge 集評估。
  • 基礎模型：Qwen2.5-32B-Instruct。
  • SFT 初始化：Claude 3.5 Sonnet V2 以 rejection sampling 產專家軌跡，保留三任務全成功或前兩任務成功的場景，得 1,129 有效範例。
  • SAGE 訓練：4×H100 8-GPU、full-parameter、嚴格 on-policy、lr 1e-6、場景級採樣鏈內取兩任務、G=8 共 384 rollout。
  • 評估指標：TGC（任務完成率）、SGC（場景三任務全完成率）、Avg. Steps（互動步數）、Avg. Tokens（生成 token 數）。

4.2 主要結果

方法 Test-Normal TGC SGC Steps Tokens
ReAct（GPT-4o） 48.8 32.1 — —
LOOP（RL w/o skill lib） 71.3 53.6 — —
GRPO（baseline） 69.2 51.8 16.4 3,613
技能庫代理（prompt only） 30.7 19.6 13.4 2,988
+ SFT（Claude 專家） 55.2 41.7 11.4 1,340
+SAGE 72.0 60.7 12.1 1,475

SAGE 的 SGC 較 baseline GRPO 提升 8.9pp、token 減少 59%。即使 SFT 初始化已超越 prompt-based 方法，純模仿專家行為仍不足以最佳化；SAGE 的 RL 進一步提升 SGC +19pp。

4.3 技能庫使用分析

SAGE 的 Skill Usage Rate 與 Success Skill Usage Rate 皆大幅優於 Base Model 與 SFT。Base Model 雖生成更多技能（Skill Library Size 高），但 Used Skill Num 與成功率低；SFT 僅提升成功率、未提升使用率。SAGE 在技能使用率與成功率兩軸上同時改善，說明 RL 訓練出真正的技能重用能力而非盲目產生。

4.4 消融研究

  • 無技能評估：SAGE 空庫時 SGC 從 60.7%→54.8%（-5.9pp），證明技能庫貢獻。Base Model 空庫反而 TGC 更高（34.7% vs 30.7%），因其技能使用能力弱、不當技能使用造成任務失敗。
  • 檢索方法：Query N-gram（2-gram Jaccard）在 TGC 72.0% 等同 Same Scenario，Query Embedding 略低但效率更高（11.8 steps），Skill Embedding 最差（TGC 66.3%）因技能檢索需理解工具語意而非純文字相關性。
  • 獎勵設計：Skill-integrated > Outcome-based > Chain-based。Chain-based 獎勵全鏈成功但未追蹤技能使用，早期低技能使用率時反而強化「不使用技能」的行為。
  • RL 初始化：Base Model 直訓 RL 僅 TGC 40.7%/SGC 25.6%；RL Warm-Up（無技能庫的 GRPO 初始化）68.3%/55.3%；SFT 初始化 72.0%/60.7% 最佳。證實專家軌跡對技能庫格式學習的必要性。

5. 結論與限制

SAGE 是首個將 RL 應用於技能庫代理自進化的框架，在 AppWorld 上取得 SOTA。限制：(1) 僅評估 AppWorld 單一資料集；(2) 三任務鏈不如二任務鏈，獎勵設計仍有改進空間；(3) 尚無技能退役/收斂機制，技能庫只增不減。未來工作將擴展至其他工具使用代理資料集。

ai_core 接點

SAGE 的 Skill-integrated Reward 是 §3.6 固化引擎方向最直接的 RL 實作：1_skill(q²|q¹) 作為「高收益程序性知識」的篩選器——只有被後續任務成功使用的技能才獲得額外獎勵，等價於自動濾除噪音技能建議、限制庫擴張只收高產出技能。Sequential Rollout 讓技能價值在多任務鏈中自然驗證。缺失：(1) 無技能退役算子——只增不減；(2) 部署中無 critic 閘門做即時准入否決；(3) 技能價值以二元成功為單位，缺乏細粒度效用追蹤。
