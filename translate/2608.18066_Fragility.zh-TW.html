論文／訪談原始來源

On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification

摘要與第 1 節：問題

memory-based self-improving agent（從線上任務流學習、靠文字記憶庫持續改進）近期文獻看好，但可靠性面向被嚴重忽視。作者重新評測兩個代表方法，沿兩軸擴大評測：(1) 多 run 量化變異；(2) 隨機打亂任務順序。結果：自改方法在 71% 的情況下增加了跨 run 變異，best-worst gap 最多達 10 個百分點；打亂任務順序後表現從預期的 +1.5% 改進變成 -4.5% 退化。人工檢視記憶後，作者假設任務／環境 underspecification 是主因——agent 會生出「看似合理但不可執行」的記憶（如在純瀏覽器環境建議用 API）。加入更明確的資訊只補回 31% 的退化，其餘缺口未解。

企業部署對錯誤容忍度低，初期失敗即可能失去使用者信任，且錯誤可能長期靜默累積。本文重評 Agent Workflow Memory (AWM) 與 ReasoningBank (RBank) 於 WebArena、VisualWebArena、SCUBA 三個 web-browsing benchmark，用更強的模型與 harness 建立更高的 baseline。WebArena GitLab 子集（180 題）baseline 最佳最差 run 差 4.4%，RBank 拉大到 7.8%。RBank 預設順序平均 +1.5%，打亂後 -4.5%。

第 2 節：問題設定與兩個代表方法

Agent 需完成線上任務序列 Q，維護文字記憶 M；每輪結束依 reward 更新記憶，供後續任務檢索。AWM 從成功軌跡摘要可重用 workflow，逐一去重後全部放入 context；RBank 從成功與失敗軌跡都生成較通用的推理型記憶，用 retriever 挑最相關的項目。

第 3 節：以擴大評測揭露脆弱性

設定：baseline harness 沿用先前工作，backbone／記憶建構模型統一用 GPT-5-mini，記憶建構時直接餵 ground-truth reward（而非原論文用的、雜訊較大的 LLM-Judge 代理 reward）。每設定跑 3 次獨立 run，報告 pass@1 平均、標準差、best-worst gap；另加 Shuffle-1／Shuffle-2 兩組隨機任務序。

變異（§3.2）：baseline 本身已有明顯變異——WebArena GitLab（180 題）best-worst gap 4.4%、標準差 1.98%；VWA、SCUBA 的 domain-level best-worst gap 分別最高到 2.4%、6.7%。24 組（method×domain）對比中 17 組（≈71%）在套用 AWM/RBank 後標準差上升，11 組相對增幅逾 50%；Map domain RBank 標準差達 3.89%、best-worst gap 8.26%（相對 baseline +200%），GitLab domain RBank best-worst gap 7.78%。作者認為這是自改方法「有狀態」的直接後果：記憶建構取決於先前任務結果與隨機取樣，早期隨機性會隨時間複合放大跨 run 差異。

Table 3（3-run 平均 pass@1）：baseline 在 WebArena／VWA／SCUBA 為 54.8%／54.9%／49.6%；AWM 僅 54.1%（-0.7）／54.5%（-0.4）／50.1%（+0.5）；RBank 56.3%（+1.5）／55.6%（+0.7）／51.1%（+1.5）。RBank 在 WebArena 的 +1.5% 增益，經 unpaired t-test（3 run）p=0.23，統計上不顯著（WebArena 人類表現為 78%，顯示仍有進步空間）。對照舊文獻（Table 2）：AWM 原論文（Claude-3.5-Sonnet，812 題）baseline 32.7%→+AWM 36.3%；RBank 原論文（Gemini-2.5-Pro，684 題子集）baseline 46.7%→+RBank 53.9%；本文更強 baseline 已達 54.8%／55.3%，顯示初始化夠強時自改方法邊際效益遞減。

任務順序（§3.3）：預設順序（按 task ID 由小到大）在 WebArena／VWA 呈隱含 easy-to-hard curriculum：前段 pass rate 約 75%，task ID 超過 150 後掉到 40% 以下，可能是標註流程先易後難所致。切到 Shuffle-1，WebArena 整體 pass rate 從 54.8% 掉到 AWM 49.1%、RBank 49.8%；8 組（method×benchmark×shuffle）設定中 6 組出現顯著退化；VWA 上 AWM 對順序敏感、RBank 較不敏感。作者原預期打亂只是讓學習變難、表現應持平於 no-memory baseline，但實際上常常更差。

第 4 節：Underspecification 作為脆弱性的潛在成因

人工檢視 RBank 記憶後歸納三個現象：(1) 環境 underspecification——記憶建構模組不知道環境是純瀏覽器、不支援 API，導致 agent 反覆寫入並提取 API 相關記憶；「使用者確認」在 WebArena／VWA 的 3-run 記憶中分別出現 26／22 次，而環境不支援此動作，導致 agent 反覆發出 wait 直到超時。(2) 任務 underspecification——模糊任務描述（如「有磨牙問題，給我能緩解的東西」本意是找護齒套，agent 卻回答「請諮詢牙醫」）導致誤解、過度推理，並把錯誤反思寫成記憶擴散到後續任務；評測器 bug 造成的假陰性也會誘發此現象。(3) 記憶會「傳染」——Map domain 中，地圖網站有時無法即時載入，agent 改用不可靠的 Haversine 公式估算距離，偶爾湊巧答對後被寫入記憶並持續放大使用，可能是變異增加的一個來源。

緩解（§4.2）：加入三種資訊——rubric 與分數（+Rub）、環境執行回饋如點擊/輸入失敗（+Env）、明確排除 API／外部網站／人工確認並鼓勵程序性知識的 prompt 修訂（+PMod）。單獨使用各有小幅提升；三者合併（+All）在 Shuffle-1 下把 RBank 從 49.8% 拉到 52.7%（+2.9 個百分點），Shuffle-2 下 +1.1%，Default 順序下表現持平。作者強調即便加了這些資訊，agent 在 Shuffle-1／Shuffle-2 下仍不及 no-memory baseline，三類資訊只是初步嘗試，未必涵蓋所有 underspecification 來源。

第 6 節：結論與建議（含 Appendix A 限制）

結論重申：自改方法的評測結果可能有顯著變異，單一 run 評測會妨礙準確衡量進步；當 baseline 已夠強或任務隨機到達時，agent 常常不是自我改進而是退化。加入更明確資訊只補回打亂造成退化的 31%，其餘 69% 的差距顯示仍有未釐清的成因。

建議：評測應報告多 run 與隨機任務序下的結果，先在良好指定任務上試點方法，再對 underspecified 任務做壓力測試估計最差表現；系統開發應正視「未經驗證的記憶只是未驗證的假設，可能是錯的且會向後續任務級聯負面影響」，需要記憶驗證／過濾機制，以及讓人可以及時介入糾正的介面。

作者自報限制（Appendix A）：評測範圍限定在 web-browsing 領域的兩個 memory-based 方法，未涵蓋其他自改方法／領域，也未評測最新記憶管理技術（惟作者稱 AWM／RBank 仍具代表性、被廣泛採用）；人工檢視記憶只是質性抽樣而非窮舉，可能還有未記錄的失效模式。Appendix B 補充：GPT-5-mini 跑完整 812 題 WebArena 約 $25，267 題 SCUBA 約 $29（皆為 no-memory baseline 估計，記憶類方法額外成本預期不高）。
