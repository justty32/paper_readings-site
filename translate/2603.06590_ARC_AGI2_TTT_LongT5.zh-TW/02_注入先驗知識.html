4. 注入先驗知識

先驗編碼任務結構的歸納偏置、約束假設空間。三種互補策略：(1) 架構等變性（探索過但未進最終系統）、(2) 過濾先驗（符號驗證規則）、(3) 資料增強先驗（對稱變換）。

4.1 符號先驗過濾

推理時用符號一致規則砍掉無效候選。過濾函式 ℱ(Ô, I, D_train) ∈ {0,1}。三大過濾器：

  • 顏色一致過濾：輸出只用任務中出現過的顏色（C(Ô) ⊆ 訓練對與測試輸入的顏色聯集）。
  • 網格尺寸一致過濾：若所有示範輸出同尺寸，則測試輸出須同尺寸；若所有輸出對輸入有固定比例 k，則測試輸出須維持同比例。
  • 包含過濾：許多 ARC 轉換維持輸入輸出的包含關係（物件抽取則輸出⊆輸入；建構任務則輸入⊆輸出）。亦在剛性變換（D4 二面體群）下檢查，捕捉旋轉/翻轉版。

這些過濾器砍掉少量候選、通常保留正解（內部測試僅 1% 退化），減輕排序負擔。

4.2 對稱先驗增強

用 ARC 域的對稱群 𝒢 = D4 = {恆等、90°/180°/270° 旋轉、水平/垂直/對角翻轉}。對每訓練對生成其在 𝒢 下的完整軌道，提供 8 倍 有效擴展且維持語意一致，並正則化模型、防學到方向敏感的偽啟發。測試時對輸入施同對稱、對輸出施逆變換以與其他候選比較。

4.3 電腦視覺式變換增強

離線訓練再加三種 CV 啟發變換（隨機施於輸入/輸出）：

  • upscale：隨機 ×2/×3 放大（方向 row/column/both）。
  • framing：等同 padding，框色取自任務未用的補色。
  • metagrid：每隔 s 行/列插入一列指定色，把像素推遠。

核心目的：讓模型少關注 token 層（單像素）、多泛化「物件性（objectness）」與空間關係概念。

4.4 遍歷先驗作為表示增強

不同於對稱（保 2D 結構），遍歷提供同一網格的不同 1D 序列化，暴露多樣演算法模式，鼓勵模型學「轉換規則本身」而非過擬合特定表示。形式上 τ 是 {1..HW} → 網格座標 的雙射。

  • (1) 逐行遍歷（Row-by-row, 左到右）：標準閱讀順序，基準表示。
  • (2) 蛇形（zig-zag）遍歷：相鄰行交替方向，避免嚴格左到右的規則偵測偏置。

（也提及對角、螺旋、Hilbert 曲線等，但未用於最終流水線。）遍歷增強用來建新任務而非任務內增強（因增長上下文常損害效能）。若 O_k = f(I_k)，則用遍歷訓練強制 τ(O_k) = f(τ(I_k))，教模型發現底層規則 f。

遍歷 token：<|row_by_row|>（預設）與 <|snake|> 前置於 prompt，讓模型依遍歷視角推理。結果：不改架構下，遍歷條件化把 Kaggle 從 19.86% 提到 25.00%（+6.14% 絕對增益）。

4.5 細胞自動機（CA）增強

CA 是離散模型，依局部轉移規則（每格新色由自身與鄰居決定）同時更新所有格、迭代至穩定（如 Conway 生命遊戲）。用 CA 生成逾 75 萬 新任務。給定任務隨機抽低複雜度自動機 f，套四種生成方案：

  1. 對輸入施 f → 全新邏輯 (I_k, f(I_k))。
  2. 對輸出施 f → 疊加既有邏輯 (I_k, f(O_k))。
  3. 若 f 不損資訊，只對輸入施 f 保留原輸出 (f(I_k), O_k)。
  4. 若 f 不損資訊，對輸入輸出都施 f (f(I_k), f(O_k))。

後兩方案要求 f 在輸入上局部可逆（見「共軛技巧」，附錄 A.2）。並用 Pixel Features（對稱、洞、物件等遮罩）擴展、提升可解釋性。

4.6 增強在 TTT/解碼/評分中的分工

以 AEIDR 字母標示各階段：A=Augment、E=Encode、I=Infer、D=Decode、R=Reverse augment。

  • 階段 1：TTT（AE）：每任務建小適應集（D4 剛性變換 8 種 + 顏色置換 + 示範重排），編碼用兩種遍歷。LoRA（r=8、35 epoch、lr=8×10⁻⁴）。最終配置 TTT 僅用 RbR 遍歷（離線訓練保兩種）。
  • 階段 2：候選生成（AEIDR）：抽 A=18 個增強視角 + RbR 編碼 + beam search（B=10）→ 反向增強映回原座標 → 共達 18×10=180 個候選；違反符號先驗者剔除。
  • 階段 3：候選評分（AEI）：對每候選施 A=8 個 D4 剛性變換，僅 RbR 編碼，純前向算對數似然。最終分數 S(Ô) = 對所有對稱條件視角的似然加總。取分數最高的 2 個作答（「change of perspective」策略：最佳解是在對稱變換下最一致者）。

5. 模型架構

5.1 動機

ARC 需像素級全對（一 token 錯整題零分），要求注意力能處理長序列且 token 級精確。每任務序列化達 10,000 token（多示範對串接）。標準注意力對序列長度二次擴展、不實用，故採 LongT5。序列超過約 1000 token 後純局部注意力不足，故用 Transient Global Attention（TGlobal） 提供稀疏但表達力強的全域互動。

5.2 LongT5 編碼器-解碼器

LongT5 擴展 T5 支援長輸入（達 16k token）：編碼器用局部+暫態全域注意力處理長上下文；解碼器維持 T5 標準因果自注意（ARC 輸出通常 500–900 token）。編碼器收「訓練對 + 測試輸入」，解碼器自回歸生成測試輸出。

5.2.1 注意力機制

T5 與 LongT5 主要差別在編碼器注意力。LongT5 支援：(1) 局部注意力（每 token 只看固定窗鄰居）、(2) 暫態全域注意力：把序列分固定大小塊，每塊聚合（求和正規化）成暫時全域 token；每 token 同時關注局部鄰域與所有全域 token，使資訊跨遠端傳播。稱「暫態」是因全域 token 每層動態重算（非固定一次）。

5.3–5.7 實作改進

  • 動機：LongT5+TGlobal 表現強但 PyTorch 舊注意力實作極慢、記憶體開銷高。FlashAttention 快但原生不支援 T5 系列關鍵的相對位置偏置。
  • FlashAttention 整合：自行擴展 FlashAttention 支援注意力偏置項，僅用於編碼器（處理 5k–10k token），解碼器（<1000 token）續用標準 PyTorch 注意力。FlashAttention 無原生 dropout，故只在 TTT 用它；離線訓練用標準注意力 + dropout 0.1 以利穩定泛化。
  • 結果（表 4）：線上微調時間提速約 1.589×（1.24h → 0.78h），準確維持或提升。架構從 Llama3.1 1B 換成 LongT5 並整合上述優化後，Kaggle 從 5.00% → 12.08%（+7.08%）。
  • 融合相對位置偏置嘗試：把位置偏置直接整進 FlashAttention，記憶體降 4 倍但計算更慢，未進最終流水線。LongT5 用桶化相對距離（小距離高精度、大距離對數分桶）編碼相對位置，可泛化到未見序列長、維持平移不變。
  • TGlobal 配置：relative_attention_max_distance=1024、local_radius=1024、global_block_size=4（每 4 token 共享全域表示）。
