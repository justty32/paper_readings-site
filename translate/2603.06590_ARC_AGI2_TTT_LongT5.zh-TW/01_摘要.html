摘要

抽象與推理語料庫（Abstraction and Reasoning Corpus, ARC）旨在評估「超越模式匹配」的泛化能力，要求模型從極少範例推出符號規則。本文提出一套以 transformer 為基礎的系統，靠四個核心想法推進 ARC 表現：

  1. 重新表述為序列建模：用僅 125 token 的緊湊任務編碼，搭配改造的 LongT5 架構做高效長上下文處理。
  2. 有原則的增強框架：基於群對稱、網格遍歷（grid traversals）、與細胞自動機擾動，強制模型對「表示變化」保持不變性。
  3. 測試時訓練（TTT）+ 輕量 LoRA：讓模型針對每個未見任務，從示範對學其轉換邏輯而專化。
  4. 對稱感知的解碼與評分：在多種增強視角下聚合似然，等同於對候選解做「多視角推理（multi-perspective reasoning）」。

這些元件協同運作：增強擴展假設空間、TTT 銳化局部推理、對稱評分提升解的一致性。最終 200M 參數的 LongT5 在 Kaggle 半私有評測集達 27%，在算力約束下具競爭力，並超越先前的神經 ARC 解法。

1. 引言

ARC（Chollet 2019 提出）要求用極少資料解謎、強調泛化與抽象推理。傳統 ML/DL 依賴大資料集與固定模式，難以應付。本系統圍繞 LongT5 編碼器-解碼器 架構：

  • 離線訓練階段：分層結合課程學習（curriculum learning）、多任務學習、grokking，讓模型逐步建立對 ARC 推理模式的理解與穩健內部表示。
  • 推理時的線上策略：測試時訓練（TTT）、基於空間/顏色對稱的自適應解碼與評分、以及把不合理候選砍掉的過濾機制（以白盒函數編碼領域先驗）。

所有元件都需在 Kaggle 嚴格約束下運作：4×L4 GPU、12 小時內處理 240 個任務。即便如此，200M LongT5 仍在半私有集達 27%。

資料規模：ARC 公開任務僅 1120 個（訓練/評測各半），太少不足以直接訓大模型。團隊納入其他公開 ARC-like 資料集，並用對稱、遍歷、細胞自動機自建生成流水線，產出 逾 230 萬個合成任務。

1.1 貢獻

  1. 離線訓練配方：分層結合課程學習（漸進理解）、多任務學習（不只解題還要去噪）、grokking（最大化效能、培養穩健內部規則表示）。
  2. 逐任務適應的 TTT：把 TTT 新應用於 ARC，僅用 prompt 中的輸入-輸出範例即可動態適應。不同於傳統微調，用輕量 LoRA + 任務專屬外部記憶，達局部專化又不災難性遺忘。
  3. 結構感知資料增強：三種領域感知增強——對稱增強（微改規則、改像素表示）、自動機擾動（保語意改表面、教規則不變性）、網格遍歷（蛇形/逐行，同一網格的不同序列視角）。
  4. 對稱感知評分：受 2024 冠軍解法 [FDH24] 啟發，在旋轉/反射等對稱變換下評估候選，靠多視角的多數一致來驗證或否決假設，比「出現次數」排序更可靠。

Kaggle 增量歷程（一句話總結）：llama3.1 1B 首投 3.75% → 調超參 5.00% → 換 LongT5 7.08% → 跑全資料集（先前誤跑一半）12.08% → 加 grokking 19.86% → 加 2-遍歷 25.00% → 加多任務 UL2 27.08%。

1.2 ARC 背景

ARC 是格狀謎題集，每任務含少量示範對（輸入網格 → 輸出網格），網格最多 10 種符號（顏色）、尺寸 1×1 到 30×30。目標：推出輸入→輸出的規則並套用到新測試輸入。挑戰在於：示範極少、任務抽象多樣、強調泛化、不依賴領域知識。

ARC-AGI-2（2025 推出） 比 1 更難：任務平均更大（達 30×30）、用更多顏色（每題達 10 色）、需序列套用多個組合規則，且設計成更能抵抗暴力搜尋與 DSL 法。但每題仍經驗證至少兩名人類可解。

1.3 相關工作

  • 資料增強：Hodel 的 DSL 法（每任務生成達 10,000 例）、Concept-ARC（160 個概念導向手作任務）、BARC（從 100 seed 經 LLM 生成達 40 萬合成題）。
  • 早期 DSL 搜尋解法：2020 冠軍 [JS20]（142 個一元函式組合成有向無環圖再貪婪堆疊）。
  • 神經符號：DreamCoder（清醒/睡眠交替，DSL+神經）、CodeIt（程式迭代）。
  • 直接 prompt LLM：最佳達公開評測集 50%（[Gre24]，GPT-4o 生約 5000 候選程式再修），但因閉源與算力不適合 Kaggle。
  • 2024 ARC Prize 名次解法：第二名 [FDH24] fine-tune Mistral-NeMo-Minitron-8B，隱藏集 56.5%（靠資料增強 + 測試時微調 + 增強下聚合機率選解）；第三名 [Bar24] 用 Qwen2.5-0.5B（小很多），隱藏集 40%（單獨 LLM 33%，外加 Icecuber 解法集成）。

2. 方法總覽

2.1 流水線

模組化、可擴展，分三階段：

  • Setup：初始化環境、下載資料與模型、初始化 Wrapper。
  • Training：在攝入的資料上微調基礎模型，權重存檔供推理重用。
  • Inference（對新任務）四大元件：
    • TTT：在單一任務上對增強資料做低秩 LoRA 微調，使模型專化到新任務邏輯而不過擬合。
    • Decoding：適應後模型用標準 beam search 生成多個候選輸出網格。
    • Filtering：白盒啟發式依形狀一致、顏色約束、物件層一致性砍掉不合理候選。
    • Scoring：對剩餘候選做一次前向（在原始與變換版任務上），利用 ARC 固有空間對稱（旋轉/反射/轉置）算每像素信心分。取最高分的 1 個（ARC 取 2 個）作答。

整個流水線由人類可讀的 .yaml 設定檔定義。

2.2 設計原則

可擴展性（分散式訓練/推理）、模組化（各元件可替換）、可適應性（可泛化到任意 transformer）、可重現性（固定 seed，結果在 1% 容差內確定）。

3. 資料

3.1 公開訓練集

蒐集官方 1240 例外的所有公開 ARC-like 資料集（共 11 個開源資料集，多數 <1000 例）。排除 BARC（40 萬題）：雜訊高、含缺乏人類可解邏輯的任務；ARC-AGI 要求高精度，雜訊換穩健的取捨不划算。最終用約 2275 個來源樣本（再經生成流水線擴增）。

3.2 測試集

由於 Kaggle 測試集寫稿時仍未公開，團隊手工設計 177 個新任務，本文所有數字都在此內部集上計算（邏輯與公開資料集相似但不相同）。

3.3 編碼

LLM 是序列處理器，ARC 網格須轉成 token 化文字。兩大挑戰：

  • 上下文長度限制：序列長則記憶體/延遲暴增、長序列表現下降，需緊湊編碼。
  • Tokenization artifact：標準 BPE 會把多位數字併成單 token（如「112」→「11」「2」），但 ARC 每個數字是不同顏色類別。故完全自控 tokenizer，把詞彙表從 32,128 縮到 125 個原子 token（每個視覺符號一 token）。

詞彙設計含結構分隔符（<|start_example|>、<|start_input|>、<|start_row|> 等）、顏色 token（<|color_0|>…<|color_9|>）、遍歷 token（<|row_by_row|>、<|snake|>）、UL2 去噪 token。此緊湊語意對齊編碼把參數從 250M 降到 201M（約 20% 減少），且更易訓練。
