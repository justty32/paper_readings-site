6. 離線訓練

大規模離線預訓練，賦予模型對符號網格轉換的廣泛理解，再做任務專屬適應。

  • 6.1 分散式設定：HuggingFace Trainer + PyTorch DDP，8 節點 × 8×H100 = 64 GPU，有效批次 512。從 google/long-t5-tglobal-base 初始化。
  • 6.2 學習率排程：70 epoch，AdamW + weight decay，cosine 排程 + 100 步線性 warm-up。
  • 6.3 課程學習：依複雜度分階引入——階段 1 僅 ARC-AGI-1 訓練集（學基本網格語意）→ 階段 2 加 ARC-AGI-1 評測集 + 其他公開資料集 → 階段 3 加 ARC-AGI-2 公開資料（需組合推理）。
  • 6.4 增強流水線：所有課程資料過對稱增強 + 網格遍歷 + 自動機擾動。
  • 6.5 訓練去「解題」：標準 token 級交叉熵自回歸生成測試輸出。也試過 Goldfish loss（隨機遮 token 防死背，但因 ARC 需像素精度反而變差）與 DGA loss（正則化保持權重近預訓練初始化，結果幾乎與標準交叉熵相同）。優化器離線用 adamw_torch_fused、TTT 用 adamw_8bit，全精度 fp32，梯度裁剪 ≤1.0。
  • 6.6 訓練去「理解」（UL2 去噪）：依 UL2（統一語言學習範式），模型重建被遮的網格區域而非直接預測輸出，促進雙向推理與潛在規則發現。三種去遮模式（不同噪比/遮罩）。課程中交錯標準 ARC 任務與去噪任務，比例隨時間變化（ARC 重 → 去噪重 → ARC 重）。消融顯示 60% 去噪混比 最佳，高噪反而最強（噪聲作正則）。本地約 +2 個百分點。結果：把 Kaggle 從 25.00% → 27.08%（+2.08%）。
  • 6.7 多任務離線訓練：交替「解題批次」（交叉熵）與「理解批次」（UL2 去噪），隨機混合防 mode collapse。
  • 6.8 Grokking：模型先過擬合（訓練損失低、驗證高），持續訓練後突然轉入強泛化。可用 WeightWatcher 分析權重相關矩陣特徵值，對尾部擬合冪律 P(λ)∼λ⁻ᵅ，2<α<4 表示重尾、進入 grokked 狀態。實驗觀察到數層落在此範圍。結果：把 Kaggle 從 19.86% → 25.00%（+5.14%）。

7. 推理流水線

7.1 測試時訓練（TTT）

目標非重訓而是局部精修以貼合單一未見任務。

  • 線上微調程序：用「leave-one-out」把一個訓練對提升為測試對（輪流對所有對做），再用群對稱 + 顏色置換增強，形成小適應集 D_TTT（M≈2–5 例/任務、N≈20–60 增強組合），做幾步 LoRA 微調。
  • LoRA 配置：對編碼器與解碼器線性層套 LoRA。rank r=8、scaling α=16、dropout=0，目標模組為 q/k/v/o 投影 + 前饋層（HuggingFace 的「all-linear」）。低秩防過擬合與死背。
  • 記憶體管理：bfloat16 混精度、動態批次（OOM 則減半批次、加倍梯度累積）、TTT 間重用狀態（基礎模型只載一次、只掛/卸 adapter）。
  • 跨任務檢索的外部記憶：用 LongT5 編碼器 mean pooling 把每訓練任務嵌入向量庫（FAISS），測試時以餘弦相似度檢索近鄰。檢索任務以三模式併入 TTT（資料擴展 / 對增強 / 評估引導早停），並有多種增強策略（Many_sim、Aug_0–3）。
  • 平行與動態負載平衡：TTT 各任務獨立（embarrassingly parallel），自製負載平衡器把任務動態派給 GPU，近常駐飽和。

7.2 解碼策略

把解碼形式化為前綴圖搜尋：節點是前綴序列、邊是接 token、邊權是對數機率。各解碼法對應不同圖探索：貪婪（取最大邊）、Top-k/nucleus 抽樣、beam search（保 B 個最佳假設、有界最佳優先）、DFS、BFS。

  • 熵分支法：算每 token softmax 熵，低熵（高信心）不分支、高熵（≥閾值 α）才分支探索多續寫。效果與抽樣相當（略勝），但每 token 算熵的開銷使其略慢，未進最終提交。
  • 溫度：τ<1 更確定、τ>1 更多樣；跨層輸出快取加速批次 beam search。
  • 解碼時遍歷：只用逐行（RbR）。
  • 長上下文處理：KV 快取、LongT5 暫態注意力分塊解碼、可用時的記憶增強解碼。
  • 推測解碼（speculative decoding）：用簡單轉移矩陣 M（144×12，對應 10 色 + 2 結構標記）取代草稿模型，依局部 token 統計平行提多個候選續寫，再經基礎模型批次驗證。M 每任務以頻率法快速建好，下個 2–3 token 預測平均準確 84%，跨 beam 平行推測達 1.598× 提速。
  • BFS 評述：用類似 [FDH24] 的閾值（10–17%）剪枝，比 beam search 快 2–3 倍但效能顯著下降；降到 ~1% 閾值才補回，但又略慢於 beam。即便 1% 閾值，BFS 仍比 beam search 低約 0.5–1%——因 beam search 有時能撈到機率僅 0.1%（且只在某剛性變換下）的真解。故多數提交用 beam search。

7.3 過濾

解碼產大量語法有效但邏輯不一致的候選，評分前套白盒過濾先驗（即 4.1 節）。影響：過濾把候選集減 35–55%（整個 held-out 集只砍掉約 1% 正解），顯著改善評分時間與穩定性，且任務無關、免學參數。

7.4 評分

ARC 每任務全有或全無，排序策略關鍵。

  • 基準：出現次數排序：最常被生成的網格較可能正確，平手時用累積對數似然破。
  • 遍歷式評分嘗試：在不同遍歷下評分。無 UL2 的 2-遍歷模型上，從純 RbR 改用雙遍歷 + top-5 用 RbR 精修，Kaggle 約 +2%。但引入 UL2 後純 RbR 反而更好，成最終配置。
  • 對稱式評分（Mini-Arch）：受 The ARChitects [FDH24] 啟發，對每候選在 D4（8 個剛性對稱）變換視角下重編碼前向、加總對數似然，取最高分。正解在對稱下似然穩定、錯解不穩。
  • 兩階段選擇：(1) 預選——出現次數排序保 top 50%；(2) 對稱精修——對該 50% 套 Mini-Arch 取 top-2。
  • 效率：8 個對稱視角每任務在 H100 約加 30 秒，但比出現次數排序提升選擇準確 逾 25%。

8. 監控、日誌與作業排程

以中央 Ray cluster 編排分散式執行；MLflow 追蹤實驗（HF 指標 + 系統統計 + artifact）；OAuth2/Microsoft Entra 安全存取；自製 Ray 作業排程器。引入 ARC 專屬診斷：像素級評分模擬器（每 epoch 在 held-out 算正確像素百分比直方圖）、似然基診斷（訓練損失、長度正規化損失、平均/最大序列對數似然）。觀察：已解任務聚於低訓練損失、高對數似然；對數似然比損失更能預測可解性（尤其用 beam search 時）；正規化損失與成功的相關強於原始訓練損失。可重現性：固定全部 seed 並啟用確定性運算，但因 CUDA 非確定核、多 GPU 排程、浮點累加序，仍有 ±1% 波動（不影響定性結論與排名）。

9. 結果

在內部 177 任務私有評測集（與 ARC-AGI-1/2 完全不相交）上：

  • 9.1 pass@k（top-k 任一精確全對即解）：pass@1 35.12%、pass@2 45.99%、pass@3 51.79%、pass@5 55.93%。k 增則覆蓋漸升，顯示解碼/評分產多樣候選。
  • 9.2 候選品質：最佳候選的像素級準確分布強烈偏向接近 1.0——多數錯誤嘗試其實非常接近正解（小範圍局部錯），佐證「生成+精修多假設」策略與結構化評分的重要。
  • 9.3 TTT 中似然/損失行為：已解任務 top 候選對數似然一致較高；正規化損失是弱預測子（逐任務 TTT 收斂不夠，還需跨對稱的候選一致性）。
  • 9.4 上界與最終準確：完美選擇的上界——過濾前 69.02%、過濾後 68.17%。最終系統（TTT + 過濾 + Mini-Arch 評分）達 pass@2 = 46.99%。即：解碼能穩定產正解（約 68% 覆蓋），評分與選擇仍是逼近上界的主瓶頸。8×H100 一輪：TTT 1.52h、解碼 0.66h、評分 0.22h、共 2.42h/177 任務（49.3 秒/任務）；4×L4 約 11.7h。
