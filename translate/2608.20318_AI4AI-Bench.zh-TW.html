論文／訪談原始來源

AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement

摘要與第 1 節：問題

遞迴自我改進（RSI）問的是 AI 系統能否改進「產生 AI 系統」的過程，讓下一代繼承改進。這個過程就是訓練演算法：更好的目標函數或更新規則會改變此後每次訓練的算力換能力匯率，包括產生下一個 agent 的那次訓練。作者把 agent 能自動化的層次分三類：系統工程層受硬體 roofline 限制，資料層受人類文字存量與冪律限制，只有演算法設計層（目標、更新規則、正則化、排程）不同——Adam、DPO、GRPO 都一次性付費、持續生息，RSI 的複利多數要來自這層。

現有 benchmark 都沒把這層獨立量測：Kaggle 系比的是特徵工程；PostTrainBench／RSIBench-Data 最大槓桿是資料組成；MLS-Bench 元件邊界給定，分數混合執行層與學習層改動；最接近的 autoresearch 開放一個訓練檔案，但五分鐘 script 不是研究 repo，agent 的編輯表現得像超參數搜尋，還輸給 CMA-ES、TPE。界線不在改動大小而在碰到什麼：超參數是演算法視為已知的數字，演算法改動則重寫演算法本身。這些設定都沒回答：agent 改的是「run 怎麼跑」還是「模型怎麼學」？

第 2 節：AI4AI-Bench

任務形式化。任務是五元組 (C, a₀, q, m, d)：C 是凍結原始碼，a₀ 起始模型，q 是可自由查詢的便宜 proxy，m 最終指標。Agent 4 小時探索預算（一張 B300）觀察 (C, a₀, q)，交回改寫原始碼 C′，全程不評估 m。C′ 在 12 小時驗證預算下執行得模型 a(C′)，分數由事先固定、對 agent 環境無存取權的 evaluator 算出。固定量測、開放方法，不能碰的是評測本身。

十個任務（家族／指標）：OpenR1 監督微調／LiveCodeBench↑；RAGEN 多輪 agentic RL／解題率↑；OPD on-policy distillation／AIME 24-25↑；BTRM Bradley–Terry reward model／RewardBench↑；DPO 偏好最佳化／IFEval strict↑；DDPO diffusion RL／美學分數↑；NPO 機器遺忘／平衡分數↑；DiGress 離散圖擴散／test NLL↓；Model Soup 權重平均（72 CLIP checkpoint）／ImageNet-V2 top-1↑；OWL one-shot pruning（OPT-6.7B）／WikiText-2 perplexity↓。入選條件：真在跑的訓練演算法、有凍結起始模型、指標能單張 B300 半天重現。Model Soup／OWL 不訓練只執行一次，演算法問題仍在；十指標互不可比，跨任務數字各對自己 baseline 計算。

協定：4 小時內自由讀 repo、改碼、自行訓練、無限次查 proxy，時間到只留原始碼。八個訓練任務從頭初始化跑最多 12 小時，取最近三個 checkpoint 最好者計分；兩個不訓練任務執行一次直接計分。

Baseline 與評分：baseline 是 repo 自己的原始演算法在完全相同流程（同硬體、同預算、同 evaluator、同資產）下的分數，非已發表數字、非官方指令微調版、非人類專家嘗試，只問 agent 的程式碼是否產出更好模型。每任務配遞增進度座標 φ 及三參考點——不帶資訊模型 x⊥、baseline x_b、最優 x*：σ(x)= 0.1·(φ(x)−φ⊥)/(φ_b−φ⊥)（低於 baseline 時）或 0.1+0.9·(φ(x)−φ_b)/(φ*−φ_b)（高於 baseline 時），clip 到 [0,1]，未交出模型記 0，兩段在 0.1 相接（追平 repo 配方是支點）。perplexity 這類任務取 −log（否則 OWL 從 53.4 到 16.2 會誤讀成補了 71% 距離，正確是 30%）。跨任務平均一律是 σ 的平均。

第 3 節：實驗

設定。受測單位是「模型＋harness＋reasoning effort」組合，稱 system。六個 system：GPT-5.6 三變體（Sol、Terra、Luna）在 Codex 下跑六個 effort 等級；Opus 5、Sonnet 5 在 Claude Code 下跑五個等級；Kimi K3 在 Claude Code 下跑最高等級。合計 29 組合 ×10 任務＝290 格。

結果（均作者自報）。290 格平均分 0.166，最強 system Claude Opus 5 平均 0.250，單一最佳組合（Opus 5、medium）0.288——最好也只補不到五分之一距離。124 格（逾五分之二）低於 0.1，比原演算法還差。排序：Opus 5 0.250、Sol 0.191、Kimi K3 0.174、Sonnet 5 0.145、Terra 0.135、Luna 0.117，全落在量表最底五分之一。花費解釋不了結果：同 harness 下花費跨系統近九倍（Sol 中位數 $434，Luna $48），Opus 5 中位數只花 $181 就居冠。

第 4 節：分析

4.1 多數提交只改 run 不改 learning。另一語言模型讀每份 diff，歸到 run 側（訓練多久多常存檔、超參數、留哪個 checkpoint、容量位置）或 learning 側（loss、監督訊號、更新規則、訓練資料）八家族（不互斥，平均命中 3.13 個）。280 份中 17 份無法歸類，餘 263 份：141 份只碰 run 側，僅 122 份碰 learning 側——任務明白寫著「改進訓練演算法」，逾半數從未觸及。碰 learning 側平均分 0.226，只碰 run 側 0.126，差距 0.100（標準誤 0.022）；排除 agentic RL 仍有 0.182 對 0.128。但這非隨機化比較：本來較強的 system 碰 learning 側更頻繁，差距是「有去 vs 沒去」而非因果效應。

4.2 Reasoning effort 買到敢動的膽量，膽量正是報酬所在。唯一單獨可調的旋鈕是 reasoning-effort。效果：碰 learning 側比例從 8.0% 升到 64.0%；低 effort 只動預算、日誌、最佳化參數，高 effort 動目標、換更新規則、加新監督訊號。也買到更多嘗試——Codex 網格中位數評測次數 4→16 次、改動行數 18→246 行、輸出 token 1.1 萬→10.9 萬，每任務探索成本中位數 $1.69→$34.60，全場共花 $5,334（不含訓練與 evaluator 算力）。也買到完成度：19 格掛零中 8 格沒交出可用 patch、11 格交了完整 patch 卻沒產出合約要求的模型，12 格集中在最低兩個等級。分數確實升但絕對值小：平均分 0.094→0.196（Codex 子集內 0.094→0.204），相對於比例的八倍增幅只翻倍，0.196 距最優仍只走十分之一——effort 的作用是讓更多 agent 願意去做「讀訓練動態、指名失敗機制、改動它」這件有回報的事，而非讓同一次嘗試品質更好。

4.3 真正碰到演算法層的提交做了什麼。122 份中三個案例動手前都先建了可量測工具：（1）OWL 本應只做一次選權重→移除→停，一份提交改成三階段管線（選取規則＋逐層蒸餾＋遮罩式蒸餾微調），把 perplexity 從 53.4 壓到 13 出頭，並診斷出首次得 572 分是因 activation 前向覆寫了 layer 0 輸入、pruning 其實讀到 layer 31。（2）Model Soup 原是 72 模型均勻平均，一份提交先把評分工具從約 190 秒壓到 0.38 秒，再比出學習係數與 greedy soup（0.7020／0.7025）優於均勻平均（0.6880）。（3）RAGEN 原用 GRPO，拿滿分的提交改用生成盤面＋標最優步的模仿學習（一份再加 dagger）。三案例共同點：先建診斷或工具再動手，這正是 §4.1 發現多數提交缺少的能力，263 份中屬例外。

第 6 節：結論

RSI 靠演算法這條鏈複利，AI4AI-Bench 為單獨量測它而造。演算法層是距離真正被補上之處，多數提交從未抵達；更多 reasoning effort 主要買到抵達的意願。今天 agent 在這環做的是找回一個還算能打的預設值，而非設計出超越它的東西。
