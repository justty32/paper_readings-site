論文／訪談原始來源

Agent 設計黑箱演算法並在 Lean 證明時間界

第 1–3 節：查詢模型與漂移分析

作者研究語言模型能否同時設計最佳化演算法並證明其效率。給定問題類別，黑箱演算法反覆選點並取得 oracle 的 fitness；時間定義為首次查到最佳點的查詢次數，查詢間計算不收費。勢函數量測狀態距離目標的進度，只參與分析；漂移定理從單步變化推導期望到達時間。（§1、§3）

作者以有界勢函數和改善、惡化、直接跳到目標的機率條件，把較一般的漂移分析化為模型需證明的義務。跳躍機率的正下界確保 hitting time 可積；證明條件成立後，管線得到期望查詢次數上界 \(4/(\varepsilon p)\)。一般加法漂移定理在所用 Lean 庫內已證；論文對有列印公理的指定 run 報告僅依賴 Lean 標準公理。（§3.2、附錄 B）

第 4 節：分階段設計與驗證

輸入包含問題卡、基準演算法與其上界；實驗以均勻隨機搜尋起步。模型先文字提出設計，再定義狀態、初始化、查詢與轉移，證明可達狀態相關的完整性、隨機性、NotRandomSearch 及 fitness 適應性等 guard。NotRandomSearch 在正式表中僅要求存在可達狀態、隨機輸入和 fitness，使查詢不同於同一輸入的均勻抽樣；這個單點見證不保證兩個分布不同（本檔補註，非作者自陳）。勢函數階段要求值在 \([0,1]\)、最佳查詢時且僅此時為零，並排除純二值勢函數。最後提出漂移集合與參數，證明其機率和跳躍條件，再套用時間界。（§4.1–4.3、附錄 A）

每次 Lean 拒絕一個宣告，錯誤回饋模型；重試額度依 Luby 序列，耗盡後回溯。完成一代後可將其接為下代起點。相鄰代的證書要求漂移參數積有嚴格常數因子改善，因此進步可以只是上界常數改善；形式通過不表示漸近階必下降。（附錄 A、附錄 C）

第 5 節：結果與對照

作者自報 8 個問題類別中，15 次 frontier-model 分階段 run 有 12 次通過全部階段且無 sorry。其中 9 次是不用未計費離線求解的多項式界；兩次靠查詢學得頂點覆蓋圖，然後以非建構式最小覆蓋定義離線求解，另一次仍是指數階。故黑箱查詢複雜度不能當成包含離線計算的總運行時間。（表2、§5.3、§6）

CycleUncover 由隱藏偶環構成，fitness 設計對一般演化搜尋形成陷阱。產生的算法透過查詢判斷鄰接，走訪並二著色環後查詢一個色類；其機器檢查期望查詢界為 \(O(n^2)\)。論文對該問題上的經典 (1+1) EA 證得 \(e^{\Omega(n)}\) 期望時間，這個對照限於該問題與指定演算法。（§5.2、附錄 E）

OneMax 的演算法證明 \(O(n^3)\)，作者指出此演算法的已知真實上界更緊。LeadingOnes 的 fitness 自適應突變先得 \(O(n^3)\)；向問題卡加入指數不等式後證得 \(O(n^2)\)。整數值次模最小化假設值域 \([0,B]\)、\(B=n^c\)（\(c\geq 1\)）、最小值為零，卡片另提示利用次模性；五代後生成的 Lovász 延拓投影次梯度設計達 \(O(n^2B^2)\) 查詢界。（§5.1、§5.4、附錄 F.16）

不分階段的 CycleUncover 消融複製近似隨機搜尋；BandwidthVC 消融沒有證出界。該消融也沒有分階段管線提供的漂移 API 與工具，故不能把差異全歸因於階段拆分。作者報最近 14 個使用 Goedel-Prover-V2-32B 與 Gemma 4 的 OneMax runs 均未完成；較弱模型的結果依此具體配置理解。（§5.5、附錄 F.1）

第 6 節：限制

高成本使作者無法進行完整統計設計；簡化的漂移定理可能得到不緊界，搜尋空間限於位元字串。問題卡、外加引理及 Lean 庫構成分析前提；機器檢查的是形式化陳述與證明，不應自動擴成任意實際問題的端到端效率保證。（§6、附錄 C；末句為本檔補註）
