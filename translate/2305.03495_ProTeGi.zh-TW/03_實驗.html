3. 實驗

本文提供一個有限、初步的案例研究，在四個基準 NLP 任務上展示 ProTeGi 能在效率與表現上超越最先進的 prompt 學習基線。

3.1 資料

雖然 ProTeGi 原則上可套用到任何任務（如剖析、聊天機器人設計、摘要），只需選擇不同的度量函數 m，本研究以四個 NLP 二元分類基準任務作為初步案例：Jailbreak（新提出的任務，判斷使用者輸入是否構成越獄攻擊——即企圖讓 AI 破壞自身規則的互動策略，含 452 筆多語言、人工標註的樣本）、Ethos（英文線上仇恨言論偵測，997 筆線上留言）、Liar（英文假新聞偵測，4000 筆含陳述、脈絡與說謊標籤的樣本）、Sarcasm（阿拉伯文諷刺偵測，10,000 筆線上留言）。

3.2 設定

每個任務隨機抽樣 50 筆做開發集、150 筆做測試集，所有結果為 3 次實驗試驗的平均，回報測試集二元 F1（依束內候選取最大池化）。除非另有說明，實驗以 2023 年 1 月版 gpt-3.5-turbo（透過 Azure OpenAI API）進行，少樣本分類時溫度設為 0.0，其餘情境為 1.0；因本文聚焦通用適用的非參數化演算法，並未對基線或所提演算法做超參數搜尋，一律採預設值。除非另有說明，ProTeGi 採 minibatch 大小 64、束寬 b=4、6 個優化步驟；每步取 4 個錯誤一組產生梯度，每組錯誤產生 m=4 個梯度、每個梯度編輯一次 prompt，再對每個新候選額外生成 p=2 個蒙地卡羅樣本；為避免計算量暴增，每個父代候選僅隨機抽樣 8 個後繼候選再進入 bandit 選擇。度量函數 m 全任務統一採 F1；雖然近期一些工作改用模型對數似然作評估，初步實驗顯示此法對本演算法無幫助，且當時許多強大的 LLM API（如 ChatGPT、GPT-4）並不提供對數似然。本演算法優化的是 prompt 的措辭，而非挑選最佳少樣本範例；但因演算法本就會用到訓練資料，實務上大多也會把部分訓練樣本當作少樣本範例放入 prompt——因此 §3.4 所有實驗都固定使用一組隨機抽取的兩個少樣本範例，僅優化 prompt 的其餘部分。

3.3 基線

本文比較以下非參數化基線（與 ProTeGi 直接可比）：Monte-Carlo（MC）——Zhou et al.（2022，即 APE）提出的、對 prompt 空間做迭代但無方向的蒙地卡羅搜尋，為公平比較，MC 每候選的取樣數與 ProTeGi 的後繼數對齊；Reinforcement Learning（RL）——如 GrIPS、TEMPERA 等並行工作，依賴對 prompt 文字做片語級操作（用 nltk 把 prompt 切成片語，搜尋空間包含新增、釋義、交換、刪除等操作），本文以 RL 訓練的版本作為此類搜尋空間表現的上界；AutoGPT——一個開源 AI 智能體，靠智能體自行控制的回饋迴圈改進回應，用以比較「本文有方向的梯度下降」與「AI 自行決定的回饋框架」；此外，鑑於並行工作曾提出以演化搜尋處理 prompt 空間，本文為所提 bandit 選擇程序設立的主要對照基線是均勻分配查詢預算的演化搜尋。

3.4 實驗結果

整體結果：ProTeGi 在本研究考慮的全部四個資料集上都勝過其他最先進演算法。平均而言，ProTeGi 分別以 3.9% 與 8.2% 的顯著差距勝過 MC 與 RL 基線，同時較起始 prompt p₀ 提升 15.3%、較 AutoGPT 提升 15.2%；此優勢在查詢預算從 12 變化到 50 次評估/候選時大致保持穩定，不過所有演算法都會因評估次數減少、過程變異增加而略微失效。就基線而言，MC 能穩定改進 prompt 表現，但 RL 的片語級操作與 AutoGPT 的 AI 導向改動有時反而不理想：在 Ethos 與 Sarcasm 上，RL 基線表現接近起始 prompt p₀；在 Jailbreak 與 Sarcasm 上，6 輪 AutoGPT 回饋實際上降低了起始 prompt 的表現。這些發現顯示不同優化技術可能更適合不同類型的 NLP 任務，而 ProTeGi 這類更具適應性的方法可能是取得最佳表現所必需的。整體而言，多數演算法隨預算增加而改進，印證了「更低變異的評分估計應能帶來更準確搜尋序列」的假設。

束搜尋消融（表 1）：為釐清 §2.2 束搜尋流程的效益，作者以單輪「先枚舉後選擇」與貪婪深度優先搜尋取代束搜尋，並使每個變體的整體 API 查詢預算相同以匹配候選數。結果顯示束搜尋在所有任務上都優於這兩個基線，在 Jailbreak 與 Liar 偵測上改善尤其顯著（Jailbreak：無迭代 0.80、貪婪 0.82、束搜尋 0.85；Liar：0.63、0.63、0.67；Sarcasm：0.87、0.85、0.88）；貪婪與無迭代兩者間無明顯優劣，可能因搜尋本身變異度高。

Bandit 演算法比較（表 2）：作者比較 §2.2.2 各最佳臂辨識演算法（並將 Successive Rejects 類演算法的預算參數 B 換算對齊 UCB 類演算法的查詢預算）。結果顯示，所有近似最佳臂辨識演算法皆勝過將預算平均分配給候選的均勻基線；有趣的是，UCB 系列演算法穩定優於 Successive Rejects 系列，與 §2.2.2 理論上的假設相反——作者推測這是因為實務上 UCB 系列較擅長平衡探索與利用（本文將探索參數 c 統一設為偏高的 2.0），而 Successive Rejects 系列更專注在探索「可能最優」的臂，代價是犧牲對較不看好選項的探索。（25 次查詢/候選：Unif 0.77/0.59、UCB 0.83/0.66、UCB-E 0.83/0.65、SR 0.81/0.62、SH 0.82/0.64（Jailbreak/Liar）；50 次查詢/候選：Unif 0.77/0.61、UCB 0.85/0.66、UCB-E 0.83/0.67、SR 0.82/0.66、SH 0.80/0.62。）

學習曲線：為進一步了解學習動態，作者對每個資料集跑相同步數，繪製每步後的測試表現（圖 4）。結果顯示過程可能在僅僅幾個優化步驟後就開始對訓練資料過擬合、或陷入局部極小——所有資料集都在約 3 步左右達到高峰。資料中呈現兩種模式：Jailbreak 與 Liar 快速改進並維持改進效果，Ethos 與 Sarcasm 則全程相對穩定，可能因起始 prompt 與任務本就較契合。

底層模型（表 3）：作者以不同 LLM API 驅動 ProTeGi 做比較。RLHF 調校過的模型明顯優於 GPT-3，GPT-4 表現最佳（Sarcasm/Jailbreak：GPT-3 0.73/0.55、InstructGPT 0.83/0.75、ChatGPT 0.86/0.85、GPT-4 0.86/0.88）。作者認為這可能是因為 RLHF 調校 LLM 有更強的推理能力，對 Jailbreak 這類新穎或定義不清的問題尤其重要。

質化分析：表 4 對每個資料集展示一次優化步驟的比較範例。可觀察到幾個模式：對 Ethos，梯度成功指出當前 prompt 與該資料點間的不一致——梯度指出「並非所有關於穆斯林的留言都是仇恨言論」，對 Liar 則指出「說話者的立場或偏見（而不僅是脈絡）可能強烈影響其說謊傾向」；但 Jailbreak 的梯度較不理想——它把 prompt 的焦點窄化成兒童誘拐這個特定問題，而 Sarcasm 的梯度則反其道而行，變成一個非常籠統的陳述。各演算法對後繼候選 p′ 的效果也不同：MC 衍生的候選只是重新措辭起始 prompt，RL 衍生的候選則顯得「支離破碎、不連貫」；ProTeGi 的候選在句法與語意上有更大變異，但這有時反而有害——例如新的 Jailbreak ProTeGi 候選要求 LLM 解一個新任務；在其他情況下，ProTeGi 沒有恰當運用梯度，而是直接用其內部知識重新定義一個概念（如 Ethos 案例）。
