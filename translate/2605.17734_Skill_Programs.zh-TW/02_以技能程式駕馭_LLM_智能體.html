3 以技能程式駕馭 LLM 智能體

HASP 把智能體經驗轉成可執行的狀態—動作介入函式，即 Program Functions（PF）。PF 可插入智能體推理過程並在解題途中觸發，修正中間決策。每次 PF 執行都留下結構化紀錄：智能體原本打算做什麼、PF 如何改變它、之後發生了什麼；這些紀錄可用於後訓練，反覆出現的失敗模式也會被轉成候選 PF、驗證後加入技能庫。

3.1 帶 Program Function 的推論期智能體 Harness

考慮一個能逐步推理、使用外部工具的智能體，策略記為 \(\pi_\theta\)。給定輸入 \(x\)，智能體產生步驟序列 \(\tau=(s_0,a_0,o_1,\ldots,s_T,a_T)\)。推論時，HASP 用外部 harness（一層控制層）包住基礎策略：從技能庫檢索相關 PF，讓它們在下一步動作執行前介入，藉此直接修正中間決策。智能體可存取外部工具箱 \(K\)。

Program Function 與技能庫：每個技能表示為一個 PF，包含 should_activate（決定該技能是否該在當下觸發）與 intervene（若觸發，回傳修復）兩部分。相較自然語言提醒，PF 讓技能既明確又可執行：不只是陳述「避免重複搜尋」這種原則，而是同時指定何時適用、如何改變下一步決策。我們維護外部技能庫 \(\mathcal{M}\)：初始化時，從訓練池的已恢復失敗案例中，把反覆出現的失敗—修復模式摘要成可複用候選 PF（例：過早定案、實體混淆）；每個候選都須同時指定啟動條件與介入行為，只有通過語法、介面與 mock-execution 驗證後才被允許進入庫，確保庫裡是可執行、可複用的介入，而非雜訊描述文字。

PF 在智能體迴圈內的引導式介入：在第 \(t\) 步，基礎策略先提出動作 \(a_t^{\text{orig}} \sim \pi_\theta(\cdot|s_t)\)。harness 檢索候選 PF \(\mathcal{R}(s_t) \subseteq \mathcal{M}\)、在當前狀態與提議動作上評估其啟動函式；在純 PF 設定下，PF 僅靠啟動函式觸發。harness 再透過介入運算子 \(\Gamma\) 套用已啟動的 PF，得到 \((\tilde{a}_t, c_t, \kappa_t) = \Gamma(s_t, a_t^{\text{orig}}, \mathcal{R}(s_t))\)：\(\tilde{a}_t\) 是介入後的最終動作、\(c_t\) 是可選的注入脈絡、\(\kappa_t\) 紀錄觸發的 PF 與介入模式。無 PF 觸發時 \(\tilde{a}_t = a_t^{\text{orig}}\)；否則 \(\tilde{a}_t\) 可能是被修改或改道的動作。

PF 介入有兩種主要方式：直接修改下一步動作本身（如改寫過度受限的搜尋查詢、把檢索導向更有資訊量的中間實體），或把修正性脈絡 \(c_t\) 注入回推理過程（如提醒有相似實體）。這種設計把「選擇下一步做什麼」和「修正它」分開：策略提議下一步，PF 決定該動作應原樣執行、被修訂成更好的動作、還是被補充額外脈絡。\((a_t^{\text{orig}}, \tilde{a}_t)\) 這對紀錄同時保留策略原本會做的與 harness 如何修復/改道，把技能使用變成對中間決策的監督，而不只是對最終答案的回饋。

用於 PF 選擇的輔助教師：HASP 支援一個最簡的「純 PF 介入」設定，候選 PF 僅靠啟動函式觸發。若有輔助教師可用，可在多個 PF 都可能適用的模糊情況下協助挑選，提升介入精準度。

3.2 HASP 用於後訓練：內化 PF 引導的介入

除了改善推論期行為，PF 引導的介入也為後訓練提供監督。每次 PF 觸發都產生紀錄 \(e_t=(s_t,a_t^{\text{orig}},\tilde{a}_t,c_t,\kappa_t,\Delta_t)\)，包含觸發狀態、策略原本提議的動作、修正後動作、注入脈絡、元資料與最終回饋。HASP 用四個訊號（介入時機 \(t_t\)、模式 \(m_t\)、正確性 \(q_t\)、結果 \(o_t\)）為每筆紀錄打分，聚合成 \(A_t = \lambda_t t_t + \lambda_m m_t + \lambda_q q_t + \lambda_o o_t\)（權重 \((\lambda_t,\lambda_m,\lambda_q,\lambda_o)=(0.15,0.10,0.25,0.50)\)），再算出軌跡層級分數 \(A(\tau) = T^{-1}\sum_t A_t\)。HASP 不只用最終答案訓練，而是用 PF 修正後的動作與軌跡（依這些 PF 衍生訊號打分）更新學生基礎策略，目標是讓學生在同一套 PF 引導管線下，產生更接近修正後結果的動作與軌跡。主要訓練變體 HASP-Evolve + RS 結合演化中的技能庫與 PF 引導的 rejection sampling；SFT 與 OPD 則作為在同一批 PF 衍生訊號上的替代訓練路徑。

主要配方：PF 引導的 rejection sampling：給定取樣軌跡 \(\{\tau_i\}\)，HASP 同時用「最終任務成功度」與「PF 引導介入品質」為每條軌跡打分：\(\text{Score}(\tau_i)=\beta_1 \text{TaskSuccess}(\tau_i)+\beta_2 A(\tau_i)\)，只保留高分軌跡訓練。相較只依最終正確性過濾的標準 rejection sampling，HASP 還偏好那些中間決策更貼合 PF 引導修正的軌跡——介入要發生在恰當狀態、用恰當模式、產生有效且有正向下游效果的修復。這是 HASP-Evolve + RS 的主要訓練配方，因為它在技能庫持續演化下仍保持穩定，同時抑制雜訊或有害軌跡。

變體一：在修正後動作上做 SFT：作為較簡單的基線，每筆介入紀錄提供修正後目標 \(s_t \mapsto \tilde{a}_t\)，依介入品質加權，優化 \(\mathcal{L}_{\text{SFT}} = -\sum_t w_t \log \pi_\theta(\tilde{a}_t|s_t)\)，\(w_t\) 是 \(A_t\) 的單調函式。這讓學生直接在 PF 修正的局部動作上訓練，例如改寫過度受限的搜尋查詢、在定案前強制驗證證據、或用注入脈絡改善下一步決策。

變體二：on-policy distillation（OPD）：為測試同一套評分機制是否也對學生自己走到的狀態有幫助，OPD 讓當前策略跑 rollout、在容易失敗的步驟保持 PF 啟用，並在修正後行為上訓練學生：\(\mathcal{L}_{\text{OPD}} = -\sum_t \hat{w}_t \log \pi_\theta(\tilde{a}_t|s_t)\)，\(\hat{w}_t\) 反映當前策略下的介入品質。OPD 因此是在學生實際會造訪的狀態上訓練，但當技能庫同時演化時可能較不穩定，因為造訪狀態分布與介入記憶會同步變動。

3.3 HASP 用於自我改進的技能庫

同一套 PF 介面也支援受控的技能庫成長。固定訓練間隔後，HASP 在當前 checkpoint 下重新檢視殘留失敗，從反覆出現的失敗—修復模式提出候選 PF 集合 \(\mathcal{C}_r\)。每個候選都須同時指定啟動條件與介入行為，才能插入同一套 rollout harness。為避免庫遭污染，候選只有通過可執行驗證與教師審查才被接受：\(Q_{\text{exec}}(c)\) 檢查語法、介面有效性、mock 執行、合法回傳型別；\(Q_{\text{teach}}(c)\) 評估候選是否捕捉到可複用的失敗模式、是否在恰當條件下觸發、是否提出有用的修復。只有當 \(Q_{\text{exec}}(c)\ge\eta_{\text{exec}}\) 且 \(Q_{\text{teach}}(c)\ge\eta_{\text{teach}}\) 才會被接受，之後 \(\mathcal{M}_{r+1}=\text{Update}(\mathcal{M}_r,\{c\in\mathcal{C}_r:\text{Accept}(c)\})\)。這道過濾步驟移除過度特化、重複或雜訊的 PF，避免拖累檢索精度與未來介入品質。被接受的 PF 更新外部技能庫 \(\mathcal{M}_r \to \mathcal{M}_{r+1}\)，後訓練則更新基礎策略 \(\pi_\theta \to \pi_{\theta'}\)。
