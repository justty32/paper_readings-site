4 實驗

沿三個軸評估 HASP：PF 是否改善推論期決策、PF 衍生事件能否被後訓練內化、殘留失敗能否透過過濾演化更新外部技能庫。

任務與指標：web-search 與數學推理報準確率、coding 報 pass@1。Web-search 用 HotpotQA、2Wiki、MuSiQue；數學用 AIME24、AMC23、GameOf24（GPT-4o 判分）；coding 用 HumanEval（Base/Plus）、MBPP（Base/Plus）、BigCodeBench（Full/Hard）。除非特別說明，所有方法都用 Qwen2.5-7B-Instruct 為基座，遵循 §3 所述的 PF 增強多步智能體設定；初始技能庫源自訓練池中回收的失敗—修復模式。主推訓練變體是 HASP-Evolve + RS；消融時評估 2×3 網格：固定庫 HASP + SFT/RS/OPD 與閉環 HASP-Evolve + SFT/RS/OPD；OPD 中由 GPT-4o 提供帶主動 PF 介入的教師軌跡。Web-search 與數學基線沿用 AgentFlow 的設定，coding 基線取自公開結果或在本文的 coding 切分下重新評估。

4.1 主要結果：PF 介入、選擇與內化

推論期 PF 介入即可超越強基線：純 PF（無教師）已在 web-search 推理上把平均準確率推到 51.0%，遠高於純文字技能提示（Prompt-Only Skills）的 20.5%；coding 純 PF 達 63.4% pass@1；數學純 PF 為 35.9%（Prompt-Only 32.8%）。加上輔助教師做 PF 選擇後，web-search 提升到 56.2%、數學 38.8%、coding 平均 pass@1 68.7%。

PF 衍生分數為後訓練提供有效監督：在固定技能庫下，三種後訓練變體都優於單純推論期介入：web-search 從 56.2% 分別提升到 SFT 56.8%、RS 59.3%、OPD 62.5%；數學從 38.8% 分別提升到 40.9%、42.7%、42.4%。訓練動態顯示 SFT 快速降低損失、提高「修正對齊 token 準確率」，對應其穩定但溫和的增益；RS 維持高對齊度與相對低熵，符合它偏好任務成功且 PF 對齊軌跡的性質；OPD 對齊過程較慢、較非單調，但拿下固定庫 web-search 最佳成績 62.5%。相對於表 2 中既有的訓練式基線，PF 引導後訓練已具競爭力甚至更強，尤其在 web-search 推理上。

閉環 PF 演化進一步改善外部技能庫：主推變體 HASP-Evolve + RS 相對固定庫 RS 進一步提升到 web-search 60.3%、數學 45.4%。相對地，HASP-Evolve + OPD 掉到 web-search 56.7%，顯示同時改變 on-policy 狀態分布與技能庫可能帶來不穩定——固定庫訓練收斂較平滑，而 HASP-Evolve 同時刷新 PF 與源自殘留失敗的 rollout 資料，帶來有益但非平穩的更新；這種額外的非平穩性與 RS 搭配良好，但對更依賴當前策略分布的 OPD 較不穩定。HASP-Evolve + RS 是開源權重設定中整體最強的：web-search 60.3%、數學 45.4%、coding 平均 pass@1 69.9%，優於多種先前的智能體與訓練式基線，在數學上與更專精的推理方法相當，coding 上比 vanilla SFT 高 12.4%，同時與 GRPO、KodCode-RL 相當。

4.2 機制分析：PF 如何介入、為何有效

PF 主要透過兩種機制介入：直接修訂下一步動作，以及在推理過程中注入修正性脈絡。web-search 推理上所有觸發的 PF 事件中，65.1% 是動作層級介入、34.9% 是脈絡層級介入，說明 HASP 經常直接改變下一步可執行決策，而不只是加文字提醒。

介入模式集中在少數高價值技能：多步 ReAct rollout 中所有 PF 觸發的統計顯示，觸發高度集中而非均勻分佈在庫中。最常被觸發的技能是 decompose_complex_question（共 322 次），其次是 insufficient_exploration（138 次）與 answer_completeness（100 次）。這種集中程度也隨基準難度而異：MuSiQue 有 385 次觸發，遠高於 2Wiki 的 161 次與 HotpotQA 的 95 次，說明較難的多跳設定更依賴 PF 介入。語意上，多數動作層級介入是把過早的 FINAL 決策延後、改導向額外的 SEARCH 步驟；多數脈絡層級介入則提供分解或完整性方面的引導。

論文用一個 MuSiQue 兩跳實體消解問題的案例（圖 4）示範 PF 如何透過改寫過度受限的查詢並注入分解提示，救回一條容易失敗的軌跡。更廣泛地，表 6 顯示回收的失敗案例集中在少數反覆出現的失敗類型（如「推理漂移／無支持定案」佔 31.7%、「錯誤實體焦點」佔 24.1%、「過早定案」與「定案前證據不足」合佔 17.8%），最有用的演化 PF 都緊貼這些高頻可恢復模式，而過度特化或難以複用的 PF 貢獻很小、甚至有害（如 pf_override_harmful 帶來 -0.8 / -0.8 的負向 Δ）。此外，論文也研究了無法轉成可執行 PF、只能以文字技能形式留在庫中的技能，加入前後比較顯示增益有限且不一致——說明單純擴大技能庫並不夠，主要效益來自能被執行為 PF 的技能（詳見附錄 B.5）。

結構化訊號與嚴格過濾兩者缺一不可：表 5 顯示 PF 效果不只取決於最終答案獎勵。完整 HASP-Intervention 拿到 56.2%，拿掉時機、模式、正確性、結果任一訊號分別掉 7.8、15.5、12.1、12.8 點，說明 PF 評分必須同時捕捉「介入最終是否有幫助」以及「是否在對的時機以對的形式產生有效修復」。同一張表也顯示嚴格過濾對穩定的技能庫演化至關重要：完整過濾拿到 60.3%，無過濾則暴跌到 36.3%；只做可執行過濾或只做教師端過濾則落在中間的 48.8% 與 47.2%。

技能內化在「行為修正型」PF 上最顯著：進一步分析後訓練實際教會了學生什麼。修正模型自身行為（如讀得不夠、查詢寫得過長）的 PF 訓練後往往變得較不必要，而綁定在問題本身的 PF 通常持續活躍。量化上，multi_hop_reasoning_failure 與 retrieval_failure 在先前觸發過的案例中 100% 變得沉默，而 insufficient_exploration 約 30–37% 案例沉默；相對地 decompose_complex_question 幾乎不被內化，三個資料集上僅 3–12% 沉默。整體而言，只有 8–38% 的準確率增益能直接歸因於「這些 PF 不再需要觸發」，更大的效果來自更廣泛的行為改變，包含更多 SEARCH/READ 動作、更少零搜尋就 FINAL 的情節。這說明後訓練主要內化的是行為修正型 PF 與更強的整體推理風格，而輸入依賴型 PF 會持續提供有用的線上引導。

5 結論

本文提出 HASP，把技能表示為可複用的狀態—動作介入函式。以 Program Functions（PF）具體化後，技能成為可直接介入智能體下一步決策、為後訓練提供結構化訊號、並作為經驗證的外部記憶成長的可執行模組。同一套介面讓 PF 能在推論時「行動」、透過後訓練訊號「教學」、並在驗證與教師審查下從殘留失敗中「演化」。在 web-search 推理、數學推理與 coding 任務上，HASP 改善了推論期行為、支援不需完整強化學習的選擇性內化、並受益於過濾式技能演化。這些結果指向一條互補路徑：PF 幫助浮現並穩定那些模型「通常能做到但不可靠地執行」的策略，而要發現真正全新的策略，可能仍需更廣義的 RL 式探索。
