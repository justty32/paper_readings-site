3. 庫導致的退化：分解與理論上界

我們形式化兩個退化機制。技能陰影發生在干擾技能在選擇時排擠 oracle 技能，降低智能體調用正確技能的機率。上下文開銷則在即使智能體選對技能時，擴大的語境仍使執行品質下降。

定義 6（Oracle 技能集）：對任務 q 與技能增量閾值 τ > 0，oracle 技能集為 S*(q) = {S_i ∈ S | p(q, {S_i}) − p(q, ∅) ≥ τ}。每個技能單獨對 q 測試，只有通過率提升超過閾值的被納入。τ 取值與實證 oracle 集大小報於第 4 節。

定義 7（干擾技能）：所有非 oracle 技能 S \ S*(q) 為干擾技能。干擾技能並非對抗性構造，僅是庫中未達 oracle 閾值的技能。

定義 8（調用事件）：對具備 S*(q) ≠ ∅ 的任務 q，軌跡產生調用集 I。每條軌跡歸入互斥的三類：

  • n（無技能調用）：I = ∅。
  • m（混合調用）：I ≠ ∅ 且 I ⊄ S*(q)——調用了至少一個技能但不全是 oracle。
  • o（僅 oracle 調用）：∅ ≠ I ⊆ S*(q)。

定義 9（庫導致的通過率下降）：∆(q, S) = p(q, S*(q)) − p(q, S)。

依調用事件分解。對 S*(q) ≠ ∅ 的任務，三類調用事件分割軌跡空間。由全機率公式： p(q, S) = π_n ρ_n + π_m ρ_m + π_o ρ_o 其中 π 為給定 (q, S) 下各事件的機率，ρ 為對應的條件通過率。對 S = S*(q) 的庫亦然（m 事件不可能）： p(q, S*) = π*_n ρ*_n + π*_o ρ*_o

經代數重排得到精確分解： ∆(q, S) = [π_n (ρ_n − ρ_n) + π*_o (ρ*_o − ρ_o)]** ← ∆_ctx（上下文開銷） 　　　　 + [(π_n − π_n) ρ_n + (π_o − π_o) ρ_o − π_m ρ_m]** ← ∆_shd（技能陰影）

上下文開銷 ∆_ctx：事件機率固定在 S* 的值，僅條件通過率變化。ρ*_o − ρ_o > 0 表示全庫語境即使在智能體選同樣技能時也降低了執行品質。

技能陰影 ∆_shd：條件通過率固定在全庫的值，僅事件機率變化。全庫下，機率質量從 o 移到 m 與 n，降低效能。因 π*_n + π*_o = 1 = π_n + π_m + π_o，有 π_m = (π*_n − π_n) + (π*_o − π_o)，可進一步簡化。

引理 1（上下文開銷上界）：∆_ctx ≥ 0，且 ∆_ctx ≤ max{ρ*_n − ρ_n, ρ*_o − ρ_o}。

引理 2（技能陰影上界）：∆_shd ≤ (|π*_n − π_n| + |π*_o − π_o|) · max{|ρ_n − ρ_m|, |ρ_o − ρ_m|} ≤ |π*_n − π_n| + |π*_o − π_o|。

解讀：兩個上界作為結構性診斷工具。陰影上界分解為兩個可解釋因子：選擇不穩定性（全庫下調用事件分佈的偏移量）與選擇風險（不同事件間通過率的差異）。陰影只有在兩者都大時才大——智能體的選擇必須偏移，且偏移必須將質量移向低效能的事件。

4. 實驗

資料集：SkillsBench，88 個任務涵蓋文件處理、金融、科學計算、資料分析等領域。僅納入其對應技能相較無技能基線提供至少 4% 通過率提升的 （任務， 模型） 對，得到 38 對（Haiku 4.5 的 21 個任務、Sonnet 4.6 的 17 個任務）。每對在僅含 oracle 技能的基線（S=S*）與三個擴張庫（|S| ∈ {52, 102, 202}）下評估。共計 2,545 條軌跡。

分解與規模化（表 1）：

| |S| | ∆_ctx | ∆_shd | ∆ | |---|---|---|---|---| | 52 | .06 [−.11, .22] | .03 [−.01, .07] | .08 [.02, .15] | | 102 | .06 [−.11, .23] | .08 [.02, .15] | .14 [.09, .19] | | 202 | .07 [−.13, .25] | .14 [.06, .26] | .21 [.15, .27] |

∆_ctx 與 ∆_shd 皆隨庫規模增長，∆_shd 佔 ∆ 的份額遞增。∆_shd 是唯一 CI 排除零的組件，且在最大庫時佔退化主導份額。∆_ctx 點估計始終正向但不分離於零。

調用模式分佈轉移（表 2）：oracle-only 軌跡佔比從 S* 的 88.0% → 52 技能時 80.3% → 102 時 64.4% → 202 時 52.6%。兩種互補失敗模式：放棄（質量移向 n，12.0%→38.5%）與選錯（質量移向 m，0%→8.9%）。

理論上界驗證：∆^sup_ctx 在所有條件下始終很小且無 CI 排除零。∆^sup_shd 隨庫規模大幅增長，且幾乎在所有場景排除零。

按模型拆分：Haiku 的 ∆_shd 在最大庫時 CI 排除零；Sonnet 的 ∆_ctx 點估計匹配或超過 ∆_shd，但樣本不足以分離於零。

陰影案例：mario-coin-counting 中 video-frame-extraction 技能在全部 26 條軌跡中排擠 oracle 技能；powerlifting-coef-calc 中類似模式（37 次陰影）;manufacturing-equipment-maintenance（14 次）等。

結論：在實證觀察基礎上，技能陰影是退化的主導效果；上下文開銷的點估計僅為提示性。

5. 討論

結果指向技能陰影為擴展技能庫時的主要瓶頸：一旦語意相似的技能在選擇中競爭，準確度即下降，無論底層模型為何。自然的下一步是透過檢索式預過濾、描述消歧、或學習式路由等技術直接攻擊此瓶頸。我們的研究涵蓋 202 個技能、同一供應商的兩個模型，在此規模下上下文開銷仍溫和。當庫再增長一個數量級或跨越異構架構時，這些模式——以及上述緩解措施——是否持續，仍為開放問題。

附錄摘要

A. 實驗組態：oracle 集以 τ=0.04 閾值篩選，每技能單獨測試；oracle bundle 即 SkillsBench 任務作者手選的技能包（中位數 2 個、平均 2.7 個技能）。最大庫 |S|=202 為全部 88 個 authored bundle 經逐字去重與同名歧義處理後的聯集。

B. 補充實驗：Haiku 在 |S|=52 時 ∆ 即分離於零；Sonnet 僅在 |S|=202 時。二元與分數通過率對各調用事件的詳細列於表 7–8;oracle-only 事件的條件通過率隨庫增長仍下降（提示上下文開銷可能真實但樣本不足確認）。
