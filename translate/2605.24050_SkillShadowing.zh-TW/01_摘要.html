摘要

技能庫讓 LLM 智能體按需載入任務特定的指令，使非專家使用者能透過自然語言解決領域任務而不需知道有哪些技能或它們如何運作。然而，效能隨技能庫增長而退化——從一小組有效技能擴展到 202 個技能的庫時，通過率最多下降 21%。本文將此效能退化形式化為「載入已知有效技能的庫」與「載入全庫」之間的通過率差距。進一步，我們提出以技能調用——智能體在軌跡中所選擇的技能——為條件，將通過率下降分解為兩個效果：技能陰影（skill shadowing），即庫擴張時智能體更頻繁地選錯技能；以及上下文開銷（context overhead），即擴大的語境即使在選擇正確時也會使執行品質下降。我們對兩個效果分別推導理論上界以刻畫其對通過率下降的影響量級。效果及其上界的實證估計均顯示：技能陰影效應隨庫規模增長且對效能退化貢獻顯著，而上下文開銷效果始終很小且與零無法區分。此不對稱性確立了技能選擇失敗——而非擴大的語境——是擴展技能庫時的主要瓶頸。

關鍵詞：智能體技能、智能體退化、技能庫、技能選擇、技能陰影、上下文開銷。

1. 引言

LLM 智能體愈來愈不僅透過新增工具調用，更透過載入技能（skill）來擴展——技能是自包含的指令、腳本與參考文件包，將領域專業知識注入智能體的語境。此抽象已迅速成為產業標準：Anthropic 為 Claude 發布了 Agent Skills 並將規格以開放格式釋出，來自 Atlassian、Stripe、Figma 的合作夥伴技能進入策展目錄；OpenAI 隨後為 Codex 採用相同的 SKILL.md 慣例。其吸引力在於可組合性：實作者將數十個技能組裝成單一智能體，而基礎系統展示了透過語言介面大規模組合與選擇能力庫的可行性——Voyager 逐步構建由嵌入相似度檢索的技能庫，HuggingGPT 則用自然語言描述從數千個專家模型中選擇。前提是使用者可以用自然語言描述任務，智能體自主選擇正確技能，而使用者不需知道有哪些技能或它們如何運作。然而，在我們的實驗中，202 個技能的庫打破了這個前提：跨越兩個模型，通過率平均下降 21%。

多數既有工作一次只評估一個技能：如何撰寫技能、檢索一個技能、或衡量其相較無技能基線的邊際貢獻。來自更成熟的工具使用文獻的證據表明，這種單一技能觀點是危險的不完整。工具選擇準確度從少於 30 個候選時的 90% 以上掉到 11,100 個時的 13.6%，而在語境中選擇「可能完全失敗」。技能放大了這些失敗模式：它們依賴自然語言描述，語意範圍比型別化工具綱要更廣且更重疊，且一個錯誤的技能會將看似合理但錯誤的推理注入智能體的語境而被當作權威——而一個錯誤的工具調用更可能因結構化綱要而產生可偵測的錯誤（型別不匹配、缺少參數、API 錯誤碼）。

動機。儘管日益警覺——近期工作已在漸進真實的技能設定下記錄了退化，並顯示壓縮技能內容可產生"少即是多"的效果——如圖 1 所示，我們在 SkillsBench 上評估並觀察到：當我們載入漸進更大的技能庫時，相較僅載入已知有效技能（即 oracle 技能）出現單調的通過率下降。我們的主要假設是庫中的某些技能會遮蔽 oracle 技能。例如：在 mario-coin-counting 任務中，庫中包含一個名為 video-frame-extraction 的技能，其描述表面上看比提供的有效技能更匹配查詢；結果智能體在全部 26 條軌跡中都調用了這個錯誤技能。

然而，尚無既有工作將庫導致的退化形式化，或試圖透過控制實驗將其分解為可分離的因果機制。挑戰在於智能體軌跡——從接收任務查詢、經技能選擇與調用到產出最終輸出——很大程度上是黑箱：我們觀察到任務結果，但觀察不到產生它的中間決策。若無完整的中間狀態觀察，就無法將退化歸因於特定的失敗機制。

貢獻。我們提出以技能調用作為這樣一個可觀測的中間狀態。我們形式化軌跡結構來定義調用模式，從而將庫導致的退化精確分解為兩個可分離的效果——技能陰影與上下文開銷——並對每個效果推導理論上界（第 3 節）。實驗顯示：技能陰影主導退化，佔退化最高達 68%，且是唯一統計顯著的效果；上下文開銷的點估計始終合理但不顯著，與噪音無法區分（第 4 節）。

2. 形式化

我們研究技能增強智能體——從共享庫中選擇並載入任務特定指令集的 LLM 智能體。與工具增強智能體不同（調用工具會執行程式並回傳計算結果），調用技能會將指令文字注入智能體的語境窗口；智能體隨後以基礎工具驅動任務執行，並以注入的指令為引導。

定義 1（技能）：技能為三元組 S_i = (n_i, d_i, b_i)，包含名稱 n_i、自然語言描述 d_i，以及主體 b_i（引導任務執行的完整指令與範例）。(n_i, d_i) 為技能的介面——智能體在選擇時唯一可見的資訊。主體 b_i 在技能被調用前不會揭露。

定義 2（技能庫）：技能庫為有限集 S = {S_1, ..., S_l}。

定義 3（智能體）：智能體 A_θ 為一大型語言模型（參數 θ），每回合根據當前觀察、先前互動歷史、任務 q，以及技能描述 {(n_i, d_i)} 選擇一個動作。動作可以是：技能調用 Skill(n_i)、基礎工具調用（如檔案讀取、shell 命令）、或終止信號。

定義 4（智能體語境）：C(q, S) = (q, D(S))，其中 D(S) = {(n_i, d_i)}^l_{i=1}。智能體語境完全由任務與庫決定，且是唯一跨實驗變化的輸入。

定義 5（任務）：任務為三元組 T = (q, r, v)，包含查詢 q（自然語言目標描述）、參考解 r（證明可解性的已知正確實作）、驗證器 v（獨立可評測子任務的確定性測試套件）。智能體只觀察到 q;r 和 v 被保留。

給定 T=(q, r, v) 與 S，一條軌跡分三階段：

  • 階段 1 語境載入：智能體接收 q 與 D(S)。技能主體被保留。
  • 階段 2 技能調用：智能體在有限回合（或時間）內行動。若動作為 Skill(n_i)，主體 b_i 被附加到智能體語境（即技能調用）。智能體可在一條軌跡中調用多個技能。令 I ⊆ S 表示軌跡期間調用的不同技能集合。
  • 階段 3 輸出：軌跡在智能體發出完成信號或達到回合（或時間）上限時終止。智能體產出最終產物（如修改後的檔案、生成的程式碼）。

輸出驗證。驗證器 v 在智能體軌跡之外運行，評估最終環境狀態。任務完成隨機變數 T_q = #{通過的子任務} / m ∈ {0, 1/m, ..., 1}。二元通過率 p(q, A_θ, S) = Pr[T_q = 1|q, A_θ, S]；分數通過率 p̄ = E[T_q|...]。
