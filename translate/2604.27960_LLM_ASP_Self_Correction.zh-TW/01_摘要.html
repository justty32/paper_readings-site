摘要

近期大型語言模型（LLM）達成亮眼的推理里程碑，卻仍受困於高計算成本、邏輯不一致、高複雜度問題上效能急跌。神經符號法試圖透過耦合 LLM 與符號推理器緩解，但既有作法多依賴單調邏輯（如 SMT），無法表達可廢止（defeasible）推理——而那是人類認知的核心。

本文提出 LLM+ASP 框架，把自然語言翻成 Answer Set Programming（ASP，基於穩定模型語意的非單調形式體系）。不同於先前需手寫知識模組、領域 prompt 或限於單一問題類的 LLM+ASP 作法，本框架完全無逐任務工程，一套橫跨多樣推理任務。系統用自動自我修正迴圈——ASP 求解器（clingo）的結構化錯誤回饋驅動迭代精煉。在六個多樣基準上證明：

  1. 穩定模型語意 讓 LLM 自然表達預設規則與例外，在非單調任務上大幅勝過 SMT 法；
  2. 迭代自我修正是效能主因，有效取代手寫領域知識；
  3. 精簡 in-context 參考指南顯著勝過冗長文件，揭露「context rot（脈絡腐爛）」現象——過多脈絡反害約束遵循。

1. 引言

推理型 LLM（Gemini 系列、OpenAI o 系列、DeepSeek R1）靠生成顯式中間「思考 token」、反思、自我修正來解多步問題。但有三弱點：計算成本高、超過某複雜度門檻效能急跌、思考軌跡與最終答案常邏輯不一致。

神經符號法（結合 LLM 自然語言能力 + 外部符號推理器的嚴謹）有潛力，但常侷限窄領域、需仔細 prompt 或人介入。關鍵限制：許多既有法依賴單調邏輯（FOL、SMT）——一旦推出結論就不能因新資訊撤回，無法表達可廢止推理、偏好、例外。而人類推理本質非單調：常做預設假設（「鳥會飛」），遇到例外（「企鵝」）就撤回。

LLM+ASP 把 LLM 耦合 ASP 來補此缺口。ASP 的穩定模型語意把預設否定（default negation） 與多個可能世界當一等公民，比 FOL/SMT 更自然建模邏輯衝突。

與先前 LLM+ASP 工作的區別：作者早期工作依賴逐任務工程——Yang et al. (2023) 生成部分 ASP 表示、需手寫知識模組與逐問題類 few-shot；Ishay et al. (2023) 用自訂 prompt 生完整程式但只在邏輯格謎評估。兩者都把 LLM 當一次性翻譯器、無錯誤恢復機制——若程式有缺陷就無修正路徑。LLM+ASP 引入求解器回饋驅動的自動自我修正迴圈，無逐任務 prompt、無 few-shot、無手寫領域知識，使單一任務無關框架橫跨六基準（約束滿足、規劃、非單調推理）。

關鍵實證觀察：近期 LLM（尤其擴大測試時計算者）只需少量指引即能生成 ASP 程式（可能因訓練資料見過足夠 ASP），但首次嘗試常有瑕疵。雖「執行回饋迭代精煉」的核心原則建於語意剖析/程式合成既有工作，本文貢獻在於證明它用於非單調語意的 ASP 時，能跨多樣任務型達穩健自動推理而免任務專屬工程。推理型模型尤其擅長靠求解器輸出訊息反思修程式。

2. 相關工作

2.1 LLM 推理

大型推理模型靠擴大測試時計算達高效能，但面臨三限制：高計算成本、超複雜度門檻後急跌、推理軌跡與答案不一致。

神經符號替代：耦合 LLM 與符號推理器一致勝過直接 LLM 規劃，但既有法需手寫領域知識、手設 schema、人在迴圈介入或任務專屬 prompt 工程。已知 LLM 可靠各種回饋自我修正，程式合成系統用編譯器回饋迭代精煉。LLM-Modulo 框架提供結構化回饋但需正確初始模型。

LLM 與 ASP：先前 LLM+ASP（Yang 2023、Ishay 2023）把 LLM 當一次性翻譯器、需任務專屬工程、無錯誤恢復。Ishay and Lee (2025) 改用動作語言 BC+ 配自修但主要聚焦規劃。本文的自動自我修正迴圈（4.3 節指為效能主因）解決這共通限制。

2.2 Answer Set Programming（ASP）

ASP 是基於穩定模型語意（Gelfond and Lifschitz 1988） 的知識表示形式體系，能表達因果推理、預設推理、聚合、約束。其宣告式本質讓使用者指定「什麼必須為真」而非「怎麼找解」。高效求解器如 clingo 用衝突驅動子句學習（CDCL）處理 NP-hard 及更難問題。

ASP 規則形如「derive H if 能推 B 且不能推 not-part」，其中 not 是預設否定。例：flies(X) :- bird(X), not penguin(X) 讀作「X 若是鳥且無證據是企鵝則會飛」。事實如 bird(tweety) 無 body。約束如 :- flies(X), penguin(X) 禁止某模式。現代 ASP 含聚合（#count、#sum）、選擇規則（{color(X,red); color(X,blue)}）、優化（#minimize）。寫 ASP 通常需專業；本文證明近期 LLM 整合自我修正迴圈即能免人介入自動生成 ASP。

3. 方法

LLM+ASP 流水線（圖 1）：

  1. LLM 生成器 收自然語言問題描述，用簡短指令 prompt 寫/更新 ASP 表示。Prompt 含問題描述、任務無關指令、可選 ASP 參考指南（in-context learning）。「任務無關」指 prompt 無逐任務工程：無逐任務 prompt、無 few-shot 任務範例、無手寫領域知識。
  2. 兩種參考：
    • 標準參考（standard reference）：Gemini 2.5 Pro 對官方 clingo 手冊的摘要（22k token）。
    • 精簡參考（compact reference）：由標準參考衍生，限於常見 ASP 構造（基本規則語法、變數慣例、常見運算子、pooling、標準約束格式），2.6k token，僅 1/8 長。
    • 參考製作是一次性手工，但消除每問題的逐任務 prompt 工程。
  3. clingo 求解（用 v5.8.0）：輸出回饋給生成器，生成器決定接受所提答案集（穩定模型）還是依求解器回饋更新 ASP——指令為「UPDATE」或「PASS」。PASS 只在 LLM 判定輸出正確時選；否則迭代直到通過或達最大修正次數。
