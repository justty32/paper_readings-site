4. AutoSOUP 設計與實作

4.1 核心概念

4.1.1 記憶體安全導向的單元證明

有別於忠實度導向的單元證明（選擇 V 以逼近程式行為），安全導向的單元證明選擇 V 以保留證明或駁斥 Q 所需的行為（在資源預算 R 內）。這給出每個選擇的安全導向解釋：

  • Sc 應包含貢獻可檢查記憶體安全行為的程式碼。
  • B 應足夠大以覆蓋或暴露屬性相關的迴圈行為。
  • E 應暴露可能違反、同時排除不可行違反。

三個技術實現此解釋：

  1. 資源感知範圍擴張：將範圍選擇視為資源感知覆蓋率問題，而非完整語意建模問題。以檔案為單位逐步擴張 Sc，用簡單模型代理範圍外的函式。從小型可控範圍開始，只在需要時擴張。

  2. 屬性引導迴圈界限精煉：將迴圈界限選擇視為屬性引導的精煉問題。直覺是多數記憶體安全屬性取決於局部程式狀態，且最直接受鄰近迴圈影響。因此只對影響檢測屬性可達性或違反的迴圈精煉 B。

  3. 上下文感知環境精煉：從寬鬆模型（暴露可能違反）開始→推論抑制不可行違反的前提條件→在原始程式的呼叫上下文中驗證這些前提條件。被呼叫上下文滿足的前提條件成為 E 中的顯式假設；被違反的前提條件標識可行記憶體安全錯誤。

4.1.2 以 LLM-as-function-call 自動化安全導向單元證明

自動化需要兩個能力：專案特定的推理（建置配置、本機程式碼慣例）與可審計的驗證選擇。程式分析可強制語法與語意約束，但難以處理建置配置與可擴展語意推論。LLM 可處理專案特定推理，但無約束生成不適合——無效的範圍/界限/環境假設會使生成保證失效。

AutoSOUP 以 LLM-as-function-call 架構平衡可靠性與泛化性：確定性演算法控制證明建構工作流程並定義每步驟目標；當步驟需要語意理解或專案特定調適時，AutoSOUP 將綁定任務委派給具備工具的 LLM agent；程式分析模組隨後在納入單元證明前驗證返回的產物。

4.2 資源感知範圍擴張

以檔案為擴張單位（相關函式常共置一檔）。三步驟：

  1. 初始化：Sc 初始化為包含 Ce 的檔案，所有迴圈界限設為 1，建構型別導向的輸入模型。LLM agent 合成輸入模型並回復建置配置。
  2. 建模外部呼叫：識別跨越當前範圍邊界的呼叫邊，用簡單型別模型取代其目標。LLM agent 合成並整合這些模型。
  3. 擴張範圍：若驗證仍在資源預算內，透過加入定義先前建模被呼叫者的檔案來擴張 Sc。

4.3 屬性引導迴圈與模型精煉（演算法 1）

使用檢測屬性 Q 作為決定哪些精煉重要的預言機（oracle）。兩步驟：

步驟 1：覆蓋屬性相關程式碼。覆蓋可被三個因素阻擋：不足的迴圈界限、缺失的編譯配置、或回傳值模型未捕捉的外部呼叫副作用。AutoSOUP 以覆蓋率模式執行 BMC，識別未覆蓋屬性區塊，使用 LLM agent 分類阻擋因素，然後應用對應的局部修復（增加相關迴圈界限、調整配置、或精煉外部模型）。

步驟 2：暴露迴圈相關屬性違反。AutoSOUP 檢查覆蓋報告中當前界限不足以完全展開的迴圈。對每個此類迴圈，LLM agent 判斷該迴圈是否可影響鄰近記憶體安全屬性的違反，若是，估算可能暴露違反的最小界限。

4.4 上下文感知環境模型精煉（演算法 2）

寬鬆模型下發現的違反可能在更廣泛系統 S 中不可行。此技術將不可行違反（由過度寬鬆環境假設造成）與真實記憶體安全錯誤分開。兩步驟：

步驟 1：推論近似 weakest precondition。AutoSOUP 解析驗證報告，提取每個被違反屬性 q、位置 loc(q) 及其反例見證 w(q)。LLM agent 推論一個保持 loc(q) 被覆蓋但抑制 q 違反的前提條件。

步驟 2：針對呼叫上下文驗證與精煉。AutoSOUP 識別 Ce 的呼叫點與被建模函式的實作。對每個上下文，LLM agent 識別到達呼叫點的路徑約束，檢查這些約束是否蘊含推論的前提條件。若呼叫路徑違反前提條件但仍滿足屬性→弱化前提條件；若前提條件在所有上下文成立→成為 E 中的顯式假設；若呼叫路徑違反前提條件且觸發 q→報告為可行記憶體安全錯誤。

4.5 保證與局限

保證：AutoSOUP 生成的單元證明提供由 BMC 支持的有界形式記憶體安全保證——在編碼的範圍、迴圈界限與假設範圍內，無任何從元件入口點的執行違反已驗證記憶體安全屬性。此與專家撰寫單元證明提供的保證形式相同。

局限：(1) 使用 LLM 進行專案特定推理——透過確定性工作流程發出綁定任務並驗證輸出來減少不可靠輸出；隨著程式分析改進，這些模組可被確定性技術取代。(2) 依賴靜態分析回復呼叫圖——間接呼叫周圍的不精確可能導致遺漏相關呼叫邊。(3) 以檔案粒度擴張範圍——大型檔案可能超出 R 而阻止探索更廣範圍。

4.6 實作

  • 15,463 行 Python + 1,230 行 prompt。
  • BMC 後端：CBMC（ANSI-C Bounded Model Checker）。
  • 確定性程式分析模組：CBMC goto-instrument（呼叫圖/符號提取）、libclang（函式指標呼叫定位）、cscope（專案級程式碼索引與呼叫關係）。
  • LLM 驅動模組：OpenAI Python SDK + LiteLLM（支援 GPT 家族與開源/自託管模型）。Agent 配備三個工具：(i) 容器化終端（檢查原始碼/建置日誌/驗證報告）、(ii) cscope 導航（程式碼搜尋/定義查詢/呼叫圖）、(iii) 單元證明驗證工具（確認證明編譯、呼叫目標入口點、滿足精煉任務、不降低覆蓋率）。
