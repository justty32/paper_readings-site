5. 實驗結果

系統比較 vanilla vLLM、保留 original arrival time 的 ImprovedDiscard、Preserve、Swap 與 InferCept。模型與環境為 GPT-J 6B（單 A100）、Vicuna 13B（單 A100與雙 A100 tensor parallel）、Llama 3 70B（四 A100 tensor parallel）。混合 workload 從六種 augmentation 均勻抽樣。Metrics 包括 median normalized latency、finished requests/s、TTFT；normalized latency 扣除各系統相同的 interception time。

6B 下，InferCept 在相同 normalized latency 承受 1.6× arrival rate；相同 request rate 時 latency 改善 1.9–5.7×，在最低 TTFT 下可服務 1.7× arrival rate。相較 ImprovedDiscard 與 Swap，系統消除逾 60% recomputation waste 與 96% swap waste。

13B 單 GPU 的空間較小，因 model weights 占更多 memory、正常 forwarding 占更多 latency，提升上限只有約 1.25× request rate。但雙 GPU tensor parallel 讓每張卡保留更多 KV 空間、同時活躍 requests 與 interceptions 增加，InferCept 提升到 1.8× arrival rate、1.6–10× normalized latency。

Llama 3 70B 下，InferCept 承受 2× arrival rate，同 RPS normalized latency 改善 1.3–12×，相同 TTFT 下 load 高 2.4×。GQA 壓縮 KV，使 Preserve／Swap 相對好一些，但 adaptive policy 仍最好。

單一 augmentation 中，QA、Chatbot 的 normalized latency 相較 vLLM最高改善 2.3×、1.9×。Chatbot 等長等待 workload 中，chunking 與 pipeline 占總 speedup 的 54%。

Ablation 以 6B、2 requests/s 混合 workload 逐步加入功能：保留 original arrival time、recomputation chunking、budgeted swapping、按長短等待的 preserve/discard heuristic、完整 min-waste policy，normalized latency 依次再改善 24.5%、7.8%、12.7%、46.1%、46.4%。完整 InferCept 的 GPU memory waste 僅 0.69%。

6. 結論

InferCept 把 tool/API interception 納入 LLM inference lifecycle。它不把 Preserve、Discard、Swap 當固定流派，而依 GPU memory-time waste、當前 batch 與等待狀態逐 request 決策，再以 pipeline／chunking 降低資料搬移與重算對 foreground 的干擾。結果可承受 1.6–2× request arrival rates，normalized latency 改善 1.3–12×。
