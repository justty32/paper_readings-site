2. 背景與相關工作

2.1 從專家系統到統計與神經範式

1970-80 年代的專家系統（MYCIN、XCON）建立在四個規範組件上：知識庫、工作記憶、推理引擎、解釋設施，提供明確推理鏈、可控決策與透明解釋。然而知識工程成本高昂、系統在窄域外脆斷、維護不可持續。其衰退與統計機器學習及深度學習的興起同步，這些方法擴展性好但犧牲了可解釋性。

LLM 集中體現了這一取捨。GPT-3 展示湧現的 few-shot 推理，GPT-4 擴展至多模態輸入，GPT-5 推進推理基準——然而即使 GPT-5 仍以意外方式幻覺、犯基本事實錯誤、在 PhD 級宣稱之下暴露明顯錯誤，甚至屈服於越獄攻擊。此持續的脆弱性揭示了更深層問題：原始模型能力不保證架構可靠性。

2.2 LLM 智能體與漸進式修補

ReAct、Reflexion、LangChain agents、AutoGPT 將 LLM 與工具、檢索、上下文提示結合，在多步驟任務中展現潛力，但也不穩定、循環工具調用、長期推理不一致。Tree of Thoughts、Voyager 等提供啟發式規劃支架；TME、A-MEM 等記憶聚焦方法將工作記憶外部化為向量資料庫或情節存儲以穩定智能體。但這些方法降低 token 開銷、改善回憶，卻未構成架構改革——推理、控制與行動執行仍糾纏在 prompt 驅動的迴圈中，智能體仍易於揮發與不透明行為。這些方法體現了 Kim (2025) 所稱的「漸進式外部化」：卸載 LLM 負擔卻不處理結構缺陷。

2.3 混合智能：傳統與局限

學者長期主張混合智能——結合符號與神經方法的架構。CLARION、ACT-R、Soar 等認知架構強調模組化、記憶與推理機制，但亦有限制：CLARION 未為動態工具使用或即時外部行動設計；ACT-R 聚焦人類心理逼真而非智能體穩健性；Soar 擅長基於規則的問題解決但缺乏機率推理或自適應約束執行機制。神經符號系統整合知識與學習，但通常缺少治理推理週期與外部執行的控制迴圈。記憶增強策略解決持久性卻未能提供透明性或結構控制。

關鍵區別：多數混合方法將符號與神經視為共存表徵，而 SCL 強調在治理層的軟符號控制——Regulation 的約束與指令引導 LLM 的生成輸出而不取代之，獨立的確定性 Control 模組治理執行層面。這不是表徵式混合，而是控制架構式混合。

2.4 結構化認知迴圈：橋接專家系統與 LLM 智能體

SCL 的五模組設計——R-CCAM——與專家系統的結構模式密切對應：

  • Retrieval + 常駐指令→動態知識庫，超出靜態規則庫，避免脆弱的人工編碼。
  • Cognition→由 LLM 驅動的機率推理，取代僵化的符號規則，具跨域泛化能力。
  • Regulation→取代靜態規則庫的常駐治理層：本身不執行或中止任何事，但透過軟符號控制形塑 Cognition 被允許形成哪些提案。
  • Control→反映推理引擎的執行調度器角色：確定性的程式碼層級模組，約束執行本身——阻斷重複或失控工具調用、基於累錯中止、判定終止。
  • Memory→穩健的工作存儲，外部化並跨迭代持久，防止 prompt 中心智能體的狀態漂移。
  • 日誌化的決策軌跡→支援解釋設施，實現系統性內省與審計，無需人工撰寫規則。

2.4.1 Regulation 與軟符號控制：新穎治理機制

軟符號控制的正式定義：一項治理機制，在控制層（而非表徵層）靈活地對機率推理施加符號約束。區別於：(1) 神經符號 AI（聚焦於表徵層整合）；(2) 認知架構（聚焦於人類認知的心理逼真度）；(3) prompt 工程（將約束隱含於文字中而非架構式執行）。在 SCL 中，軟符號控制透過 Regulation 運作，具體表現為定義治理政策（如「必須引用證據」「選擇恰好一個分支」「每循環提出單個工具調用」）的 Metaprompt。Regulation 是軟約束——它形塑 Cognition 生成什麼，但本身不執行、不中止、不檢查任何事；它既不是 Control 模組，也不將執行委派給 Control——兩者作為獨立層級作用於不同對象。
