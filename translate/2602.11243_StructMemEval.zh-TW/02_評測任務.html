3. StructMemEval

任務刻意選成「只要記憶結構正確，其他推理就簡單」。如此可避免 agent 失敗時分不清是記憶、程式設計還是一般推理錯誤。評測只看 final answer，允許各 framework 用自己的等價表示。

任務類型

  • Tree-based：由零散訊息建立家族樹、公司階層等；還要推得隱含關係與反向關係。
  • State tracking：實體狀態隨時間改變。使用者搬家後，舊鄰居不能仍被視為目前鄰居。
  • Count-based：在數百則訊息中維持交易帳本，最後做債務 netting。無關訊息增加誤寫機會。
  • Recommendation：從電影、音樂、書籍等使用／評價歷程，持續累積偏好與統計，回答類別比較或機率問題。

資料由人工標註與 LLM augmentation 加人工驗證建立。總計 207 scenarios：90 tree、45 count、42 state、30 recommendation，超過 2,000 questions；scenario 長度為 10–500 messages。

主 benchmark 取 51 個最長問題：10 tree、15 count、14 state、12 recommendation，均至少 250 messages。完整 207 題 extended set 用於觀察 scaling。Accuracy 由 GPT-4o-mini 對 reference answer 判定 factual correctness。

每個 scenario 另附 optional organization hint，描述人類會如何整理。主評測不用 hint；分析時用它判斷失敗是「沒選到正確結構」，還是「即使告知結構，仍無法維護／使用」。
