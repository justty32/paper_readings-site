摘要

現代 LLM agent 與 chat assistant 依靠長期記憶架構保存可重用知識、回想偏好並輔助推理。記憶架構愈來愈複雜，也愈難判斷它們究竟增加了什麼能力。多數 benchmark 著重事實保留、多跳回想與時間更新，這些任務常可由簡單 retrieval-augmented LLM 解決，未真正測到複雜記憶階層。

本文提出 StructMemEval，測試 agent 組織長期記憶的能力，而不只測 factual recall。任務取自人類會用 transaction ledger、to-do list、tree 等結構整理的問題。實驗顯示簡單 retrieval agent 很難解題；memory agent 若明確收到如何組織的提示，能可靠解決更多問題，但現代 LLM 常無法自行認出所需結構。

1. 引言

LLM 面對更長文件、長期助理、推理與 agentic tasks 時，不可能把所有輸入與自身工作歷程永久放在 working memory。External long-term memory 讓模型把知識卸載到外部資料庫，需要時再取回；表示法從 lookup dictionary、Markdown notes 到 knowledge graph、temporal database 與整套 memory OS 都有。

問題是現有 benchmark 多問單一事實、多跳關係或時間更新。已有研究顯示，簡單 EMem retrieval 能在 LoCoMo、LongMemEval 超過複雜架構。因此作者把問題改成：哪些任務真的需要記憶階層？

本文答案是 knowledge organization。Agent 不只是取回舊訊息，而要把事件組成 graph、todo list、分類索引、running statistics 等結構。若問題規模超過 retrieval window，原始片段 top-k 不足以還原整體；可更新的 memory agent 則可能持續維持 compact state。

2. 背景

Transformer 的 working memory 是 KV cache。它受 accelerator memory 限制，且 context 愈長推論愈慢；文中舉例，Qwen2.5-7B-Instruct-1M 以 bfloat16 保存 100 萬 tokens，KV cache 超過 180 GiB。

當資訊超過 KV cache，可壓縮／量化／prune／offload cache，也可用 external long-term memory。後者必須處理動態更新，而不是只查靜態 corpus。MemGPT 讓 agent 以工具建立與更新 entries，之後又衍生 graph、hierarchy、note-taking、cognitive-inspired 與專用 memory-trained model。

評測的困難是：不同系統內部表示不一樣，而 LoCoMo、LongMemEval 之類題型未必需要複雜結構。StructMemEval 因此不直接評內部資料結構，而讓任務本身迫使 agent 組織資料。
