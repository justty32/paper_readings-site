4. LATM 為 LLM 服務催生功能快取機制

真實情境中任務常以序列串流到達。為此引入第三個 LLM——dispatcher（分派器），對每個進來的任務決定該啟用工具使用者還是工具製造者。此工具選擇功能雖與既有工作類似，但本 dispatcher 的獨特貢獻在於創造功能快取：它能辨別「現有工具解不了的新任務」，從而觸發製造者為之生成合適工具。

dispatcher 維護一個由製造者打造、以函式 API 形式存放的工具庫。收到新任務實例時，先在快取中找相容工具：找到就把實例與對應工具指派給使用者求解；若無合適工具，則辨識為新任務——用強模型解，或必要時呼叫人工標註者。這些新實例會被快取，累積到足夠數量後再造一個新工具，進一步豐富功能快取。此機制讓功能相似的任務重用工具，擴展了傳統快取的覆蓋、降低整體服務成本。由於分派任務簡單，配上適當 prompt 的輕量模型即可勝任，只為整條管線增加邊際成本。

5. 實驗

5.1 設定

  • 資料集：六個來自不同領域的資料集——Logical Deduction、Tracking Shuffled Objects、Dyck Language、Word Sorting、Chinese Remainder Theorem、Scheduling Meeting。前五個取自 BigBench（Logical Deduction 與 Tracking Shuffled Objects 取 5 物件版），最後一個（排會議）由作者建構以展示真實情境效果。每個資料集分訓練/驗證/測試＝ 3 / 3 / 240 個實例。
  • 模型設定：工具製造階段 temperature 設 0.3（引入隨機性、允許必要時重試），用 GPT-4 與 GPT-3.5 Turbo 的 ChatCompletion API、每步把回應附進聊天歷史；工具使用階段 LLM 只呼叫一次，temperature 設 0.0，並在 GPT-3 型模型（standard Completion API）上做消融。工具提議與驗證階段最大重試次數設 3。

5.2 工具製造階段的有效性

製造階段用強而慢的模型生成針對特定任務的通用 Python 函式，每類任務只做一次、開銷被攤提。以 GPT-4 為代表製造者，配少量 few-shot 範例引導它生成通用程式。觀察發現：GPT-4 常能為任務設計出合適演算法（如 Logical Deduction 用「枚舉所有排列並挑符合約束者」的搜尋法）。實驗中驗證階段主要用於提供「問題→函式呼叫」的示範；60 次試驗中僅 2 例是製造者靠錯誤訊息引導而修正成功。

5.3 LATM 提升輕量 LLM 的表現

表 2 比較 CoT prompting 與 LATM：以 GPT-4 為六任務造工具，評估 GPT-3.5 Turbo 與 GPT-4 當使用者。結果顯示有工具之助，GPT-3.5 Turbo 可達與 GPT-4 相當的表現，遠勝 CoT，且平均成本遠低於用 GPT-4。例如 Chinese Remainder Theorem 由 0.0 → 100.0（+100.0）、Scheduling Meeting 18.9 → 100.0（+81.1）、Tracking Shuffled Objects 61.6 → 99.6（+38.0）。有趣的是 Dyck Language 任務，GPT-3.5 Turbo 當使用者甚至反超 GPT-4 當使用者——原因是 GPT-4 在把問題轉成函式呼叫時，有時多此一舉地在參數內補上括號，反而導致輸出錯誤。表 2 末欄以成本分析：處理 n 個樣本時，C 為 GPT-4 單次呼叫成本、c 為 GPT-3.5 Turbo 單次成本，撰文當時 C 是 c 的 15 倍以上——故 LATM（O(nc + C)）遠比全程 GPT-4（O(nC)）省。

5.4 讓 LATM 適應多樣任務的動態串流

如 §4，可讓 LATM 處理即時到達、可能來自不同任務的實例串流；此時加入 dispatcher（用 GPT-3.5 Turbo）辨識每個進來實例屬於哪個任務，並評估其兩項功能：

  • 辨識既有工具：從六任務隨機混合生成 100 樣本測試集，dispatcher 需從既有工具中判定合適者。經五次隨機構建測試集，正確辨識準確率 95%±2%。
  • 請求製造工具：隨機指定四任務為「已有工具的既有任務」，另選四任務測試（其中兩個未見、兩個屬既有）。同樣 100 樣本，dispatcher 判斷該請求造工具或用既有工具解，正確決策準確率 96%±3%。

結果顯示 dispatcher 能有效辨識既有工具、準確為未見任務請求製造工具，佐證 LATM 可無縫適配含多樣任務的串流環境。

5.5 消融研究

  • 工具製造模型所需容量（表 3）：每模型每任務跑 5 次。整體而言強而貴的模型更適合（此階段只做一次、高準確率對成功傳給小模型至關重要）。難任務（Logical Deduction、Tracking Shuffled Objects）GPT-3.5 Turbo 5 次全失敗（工具不夠通用、只在訓練樣本有效），GPT-4 分別 3/5、4/5 成功；但簡單任務（Word Sorting）GPT-3.5 Turbo 5/5 就能勝任。另一失敗因素是上下文長度限制——因每步用完整歷史以提升可靠性，導致較長上下文，故偏好 8192 上下文的 GPT-4。
  • 工具使用模型所需容量（表 4）：所有模型用同一支 GPT-4 所造工具。GPT-3.5 Turbo 在效能/成本間取得最佳平衡。就較舊的 GPT-3 系列（ada、babbage、curie、davinci），發現指令微調前的版本常優於微調後版本（text-ada-001 等），推測指令微調損害了 tool-using 所需的 in-context learning 能力。
  • CoT 當工具無益（表 5）：用同一大模型（GPT-4）做「CoT 製造」（zero-shot「Let's think step by step.」引出中間步驟），再把 CoT 傳給同一小模型（GPT-3.5 Turbo）。結果與人寫 CoT 相近甚至更差，遠不如 LATM。

6. 結論與未來工作

本文提出 LATM——一個賦能 LLM 自造與使用工具的閉環框架，靈感來自人類演化中的工具創造。兩關鍵階段（工具製造、工具使用）的分工，讓我們善用先進 LLM 的能力同時顯著降低計算成本。實驗證實 LATM 在多項複雜任務上表現與耗資源模型相當、卻更省成本；再加一個 dispatcher LLM 可提供隨機造用工具的彈性。評估過程中發現嚴重缺乏「忠實反映日常人機互動（如以 email/電話排會、訂機票等重複任務、原始自然語言形式）」的高品質資料集，期望本工作能激勵社群建立此類資料集。一個令人期待的未來方向是讓工具製造者能像軟體開發般精修、升級既有工具以應對新問題實例。
