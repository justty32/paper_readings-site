附錄要點

  • 附錄 A（Dispatcher 圖示）：串流情境下 dispatcher（輕量模型）評估每個進來實例——快取有合適工具則選之並轉給使用者；無則轉給製造者造新工具供日後使用。
  • 附錄 B（更廣影響與局限）：讓 LLM 自造工具賦予其發展生態的更大自主性，可能革新客服、技術支援乃至研發；但這是雙面刃——工具品質未必達人類標準、可能次優/錯誤/有害，自主性升高亦增失控風險。本文未深入處理控制與安全議題，框架仍屬早期階段，真實世界的表現與安全會依任務複雜度與性質而異，工具在真實環境的評估驗證仍是待解挑戰。
  • 附錄 C（LATM Prompts）：列出 Tool Maker、Tool Verifier、Tool Wrapper、Dispatcher 的 prompt 模板（如製造者被要求「只用標準 Python 函式庫寫一個通用函式、用 python 包起」）。
  • 附錄 D（封裝工具範例）：給出六任務的實際封裝工具，如 Logical Deduction 的 find_order（枚舉 permutations 逐一驗證約束）、Tracking Shuffled Objects 的 square_dance、Dyck Language 的 complete_sequence（用堆疊補全括號）、Word Sorting 的 sort_words_alphabetically、Chinese Remainder Theorem 的 find_number、Schedule Meeting 的 find_earliest_time_slot（取兩人可用時段交集找最早足長時槽）。
  • 附錄 E（資料集建構）：排會議任務用模板生成，interval 隨機取自 {0.5, 1, 1.5} 小時、A/B 可用時段從 8:00–18:00 以 30 分鐘粒度隨機取樣，答案為兩者可用集合交集中最早的足長時槽，若無則回「No time slot works.」。
