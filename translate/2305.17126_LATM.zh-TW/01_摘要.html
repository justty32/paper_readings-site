摘要

近期研究凸顯了大型語言模型（LLM）藉助合適外部工具提升問題求解能力的潛力。本文更進一步，提出一個閉環框架 LATM（LLMs As Tool Makers），讓 LLM 為問題求解創造自己的可重用工具。方法分兩階段：1) 工具製造（tool making）：一個 LLM 擔任「工具製造者」，為一組任務打造工具，工具以 Python 工具函式形式實作；2) 工具使用（tool using）：另一個 LLM 擔任「工具使用者」，套用製造者所建工具來解題（使用者可與製造者同模型或不同模型）。在問題求解伺服器端，工具製造能隨新請求出現而持續生成並快取工具，讓後續請求能透過對應 API 取用已快取工具，提升解題效率。

除了讓 LLM 自造工具，本框架也揭示優化 LLM 服務成本的機會：由於工具製造需較高能力，把它交給強大但耗資源的模型；較簡單的工具使用階段則交給輕量模型。這種分工讓工具製造的一次性成本被攤提到多次工具使用上，在維持強表現的同時顯著降低平均成本。此外，本法透過快取與重用工具提供一種功能快取（functional cache）——存的是「一類請求的功能」而非 LLM 的自然語言回應，擴展了傳統快取機制的適用範圍。我們在多種複雜推理任務（含 Big-Bench 任務）上評估：以 GPT-4 為工具製造者、GPT-3.5 為工具使用者，LATM 表現等同於兩個角色都用 GPT-4，但推論成本顯著降低。

1. 引言

LLM 已在廣泛 NLP 任務展現卓越能力。類比人類智能的演化，近期研究揭示以外部工具增強 LLM 能大幅提升其問題求解能力與效率。然而這些工具使用方法的適用性，很大程度取決於是否有現成合適的工具。從人類演化里程碑學到的一課是：關鍵轉捩點在於人類獲得了自造工具以應對新挑戰的能力。受此啟發，本文把這個演化概念套用到 LLM，提出閉環框架 LATM，讓 LLM 生成自己的可重用工具來處理新任務。

方法含兩關鍵階段：1) 工具製造——一個 LLM（工具製造者）為給定任務設計工具（以 Python 函式實作）；2) 工具使用——另一個 LLM（工具使用者，可與製造者相同）套用工具處理新請求。兩階段設計讓 LATM 能把各階段工作分配給最合適的 LLM：需高能力的工具製造交給強大但耗資源的模型（如 GPT-4）；相對較簡單的工具使用交給輕量、成本低的模型（如 GPT-3.5 Turbo）。這不僅增強問題求解能力，也顯著降低處理一系列任務的平均計算成本。

由於工具製造對某功能只需執行一次，所得工具可跨任務實例重用，為處理複雜任務提供可擴展且省成本的方案。例如「安排一個所有人都合適的會議」（如 email 對話中）這類需複雜算術推理的任務，GPT-3.5 Turbo 常做不好，GPT-4 能對但成本高；LATM 用強模型當製造者造好工具、傳給便宜模型當使用者，之後輕量使用者就能高效高表現地解題。此範式同樣適用於各種工作流中的重複任務（解析網頁文件成特定格式、規劃路線、解 24 點或數獨等）。

在降低服務成本方面，LATM 引入為 LLM 伺服器建立功能快取的機會：在 LLM 伺服器持續收到請求序列的串流情境下，傳統快取（如 GPTCache）存 LLM 產生的回應、對文字相似的請求重用；而有了工具製造能力，系統可存製造者打造的工具、對功能類似的請求重用。此新法結合製造者/使用者的策略分工，能顯著降低處理請求序列的平均成本並維持高表現。實驗在多項複雜推理任務（含數個具挑戰性的 Big-Bench 任務）上驗證有效：LATM 表現能與更耗資源的模型持平，同時更省成本。

2. 相關工作

  • 思維鏈（CoT）：CoT prompting 強化 LLM 推理，通常以自然語言表達，也可用程式語言表達。Arora et al. (2023) 用 LLM 在文件上生成結構化視圖、以多函式抽取集成平衡品質與成本；本法在管理成本/品質權衡上精神相近，但聚焦更通用的使用情境。
  • 以工具增強語言模型：ReAct、Toolformer、Chameleon、HuggingGPT 等以計算器、搜尋引擎、翻譯、行事曆、API 等補足 LLM。與 LATM 類似，Chameleon 也在管線中納入 Python 執行器，但其主要用途是精確解算術子步驟；本法則用 Python 執行器創造可重用工具去處理其他任務實例，且製造者/使用者分離使多數推論可用輕量模型，提升效率與成本效益。
  • 自適應生成：推測解碼（speculative decoding）用較快較弱的模型加速生成、再用大模型評分。本法「把工具從貴模型傳給小而快模型」也有自適應計算的精神，但改為在模型間傳遞新生成的工具而非改動解碼程序。
  • 語言模型級聯（cascade）：多 LLM 組合可延伸能力、FrugalGPT 顯示挑最佳組合能降本增準。本法動機一致，但不只是級聯——而是辨識出適合用新工具解的任務類別，再把該類別內每次推論指派給較小模型。
  • 工具製造的早期嘗試：與本工作並行且獨立，Voyager（Minecraft 中以程式形式習得新技能）、Qian et al. （2023, CREATOR，把求解拆成抽象工具創造與具體工具應用階段）等。本法與它們「讓 LLM 自造工具」的精神一致，但強調工具可重用性與分工帶來的成本效益。

3. LLM 作為工具製造者（LATM）

主流程分兩階段（工具製造、工具使用），各用不同類型 LLM 平衡表現與成本。

工具製造（Tool Making）：用強大而較貴的模型（如 GPT-4）當工具製造者，從少量任務示範造出通用可重用工具（Python 函式）。分三子階段：

  • 工具提議（Tool Proposing）：製造者嘗試生成能解該任務示範的 Python 函式，遵循「舉例編程（programming by example, PbE）」範式——給幾個具體示範、要模型寫出重現該行為的程式。實驗用 3 個示範。若提議工具不可執行或報錯，製造者把錯誤訊息附進歷史再試一次。
  • 工具驗證（Tool Verification）：製造者用驗證樣本生成單元測試並在提議工具上執行。實驗用 3 個驗證樣本。若工具未通過測試，製造者把錯誤記入歷史、嘗試修正——注意此程序只修正單元測試中的函式呼叫、不修函式本身。此驗證階段有兩個關鍵作用：1） 提供「如何把自然語言問題轉成函式呼叫」的示範；2) 驗證工具可靠性，使整個流程可全自動。
  • 工具封裝（Tool Wrapping）：若執行或驗證失敗超過預設門檻，則工具製造視為失敗；否則製造者把函式碼與「如何把任務轉成函式呼叫」的示範（取自驗證步驟）打包成成品，交付給工具使用者。

工具使用（Tool Using）：第二階段用輕量、低成本模型（如 GPT-3.5 Turbo）當工具使用者，套用已驗證的工具解各種任務實例。此階段的 prompt 就是封裝好的工具（含解題函式與「查詢→函式呼叫」的示範）；使用者據此以 in-context learning 方式生成所需函式呼叫，執行後解題。可選地做後處理把輸出轉成任務要求格式（如選擇題選項）。

工具製造（提議＋驗證＋封裝）對每類任務只需做一次，所得工具可重用於該類所有實例，故 LATM 比單用強模型顯著更省。此外 Python 函式工具是「更通用形式的 CoT」，能解需演算法推理的問題。
