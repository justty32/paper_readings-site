3. 結果

在五個多樣應用上展示 TextGrad 的靈活性。

3.1 程式碼優化

程式碼優化是 instance optimization 的代表用例。常見計算圖為 Code-Refinement Objective = LLM(Problem + Code + 測試時指令 + 本地測試結果)，我們在有限的本地測試監督與自我評估下優化 Code。圖 1e 例子：對一道「回傳中位數等於 k 的非空子陣列數量」的難題，gpt-4o 首個解未過測試，TextGrad 指出一個邊界案例並給出改進建議，優化後的實作通過所有測試。

  • 任務：LeetCode Hard 資料集，成功指標為 Completion Rate（通過某題全部測試案例；GPT-4 據報僅 7%）。測試案例不公開，須提交平台在未見測試上評估。
  • 基線：Reflexion（該資料集 SOTA，用候選單元測試自我反思再改碼）以 gpt-4o 跑 1-shot；另有 gpt-4o zero-shot 基線。TextGrad 在 zero-shot（無任何示範） 下運行。
  • 結果（表 1，5 個 seed 平均）：zero-shot 0.26；Reflexion（1 示範、5 迭代）0.31±0.012；TextGrad（0 示範、5 迭代）0.36±0.018。考慮到 Reflexion 用了 in-context 示範而 TextGrad 沒有，此增益更顯突出。

評估用的 loss prompt 大意：「你是最佳化系統中的評估者，分析程式實作與單元測試結果；程式會用更難的測試檢驗，故不要只看有沒有通過提供的測試；思考正確性與更難案例下的表現；對每個失敗案例以『這段程式沒通過此測試是因為…』開頭分析；不要提供修正版實作，只給出問題與反饋。」

3.2 以測試時訓練優化解答來改進解題

在 solution optimization 中目標是改進複雜問題（如量子力學、有機化學題）的解答。計算圖為 Solution Refinement Objective = LLM(Question + Solution + 測試時指令)，待優化參數是 Solution，loss 由對解答的評估（如用 LLM）取得。每輪把問題、當前解答、與一段「請批判/檢視當前版本」的測試時指令餵給 LLM，沿優化軌跡靠自我評估精修解答。這一般稱為測試時訓練（test-time training）——在測試實例上、常以自監督目標訓練模型；近期工作也顯示自我精修對推理任務有益（即使 LLM 首次答錯，也能靠迭代精修改善）。

其精修目標函數（GPQA 例）大意：「以下是選擇題與一個預測。你是批判且富創意的科學家，任務是調查這個預測，批判性地走過推理步驟，看看預測是否可能有誤。用 Janusian 思考法，考慮其他答案是否可能為真。問題：{Question}；語言模型的答案：{Solution}。」

代表性實作（Code Snippet 1）：取得 zero-shot 解答後 solution = zero_shot_llm(question)；optimizer = tg.TextualGradientDescent(parameters=[solution])；迴圈中 optimizer.zero_grad()、loss = test_time_loss_fn(question, solution)（注意 loss 是自監督、不依賴任何 ground truth）、loss.backward()、optimizer.step()。

  • 任務：GPQA（研究生級、由 PhD 領域專家出題並標註的 google-proof 選擇題；專家 81%、熟練非專家僅 22%，且表現尚未飽和，gpt-4o 於 diamond 子集約 53.6%）；另用 MMLU 兩個難子集（機器學習、大學物理，專家人類約 90%）。
  • 方法：對 gpt-4o 做 3 次測試時更新（更新解答三次）後對所有解答做多數投票得最終答案，用字串比對算準確率。
  • 結果（表 2）：GPQA CoT 51.0 → 最佳報告 53.6 → TextGrad 55.0（迄今最佳）；MMLU-機器學習 85.7 → 88.4；MMLU-大學物理 91.2 → 95.1。顯示在測試時多花算力做 TextGrad 自我精修，能改進即便是最強模型的問答表現。

3.3 推理任務的 prompt 優化

LLM 推理表現對 prompt 敏感，選對 prompt 可顯著改善。prompt 優化的目標是找一個能引導 LLM 在給定任務表現良好的 prompt/指令。計算圖為 Answer = LLM(Prompt, Question)、Evaluation Metric = Evaluator(Answer, Ground Truth)。給少量訓練例，目標是最大化 LLM 在該任務的表現。實驗中我們的目標是用強模型（gpt-4o）產生的反饋去改進較弱較便宜模型（gpt-3.5-turbo-0125）的表現——這在實務上有用：付一次性固定成本優化 prompt，之後就能用便宜模型以較低推論成本運行，取代昂貴強模型。

實作（Code Snippet 2）：system_prompt = tg.Variable("You are a helpful language model. Think step by step.", requires_grad=True, role_description="...")；model = tg.BlackboxLLM(system_prompt=system_prompt)；optimizer = tg.TextualGradientDescent(parameters=[system_prompt])；每輪取一個 batch，前向 responses = model(batch_x)、losses = [loss_fn(r,y) ...]、total_loss = tg.sum(losses)、total_loss.backward()、optimizer.step()。用 minibatch SGD，優化的是「一個對整個 benchmark 都好用的單一 prompt」（不同於 instance 優化逐一改解答）。

  • 任務：Big Bench Hard 的 Object Counting 與 Word Sorting（50/100/100 訓練/驗證/測試）、GSM8k（用 DSPy 的切分）。GSM8k 與 Object Counting 用字串精確比對，Word Sorting 用 LLM 比對。
  • 方法：forward 推理模型是 gpt-3.5-turbo-0125，用 gpt-4o 於反向傳播提供反饋改進 prompt；batch size 3、12 迭代（共見 36 個訓練例，抽樣有放回）；每輪跑驗證集，較上輪好才更新 prompt。
  • 基線：zero-shot CoT（初始 prompt「Think step-by-step」）；DSPy（SOTA 的 LLM 程式化與 prompt 優化框架，用 BootstrappedFewShotRandomSearch：生成能通過 metric 的 LLM 輸入輸出軌跡當 few-shot 示範，對至多 8-shot 子集做隨機搜尋）。
  • 結果（表 3）：Object Counting CoT 77.8 / DSPy 84.9 / TextGrad 91.9（勝 DSPy 7%）；Word Sorting 76.7 / 79.8 / 79.8；GSM8k 72.9 / 81.1 / 81.1。DSPy（加 in-context 示範）與 TextGrad（優化 system 指令）做的是互補調整——把 DSPy 選的示範併入 TextGrad 優化的 prompt，GSM8k 進一步升到 82.1，顯示結合兩者是有前景的方向。

優化前後 prompt 對比（GSM8k）：初始「You will answer a mathematical reasoning question. Think step by step...」（72.9%）→ 12 輪後變成「…用自己的話重述問題以確保理解；把問題拆成小步、詳細解釋每步計算；驗證每步並重新核對計算；用正確數學記號、與題目脈絡保持一致…」（81.1%）。

3.4 分子優化

TextGrad 也支援科學/工程常見的多目標優化。以藥物分子優化為例，展示框架如何與計算工具介接、同時改善結合親和力與 druglikeness。

  • 任務：藥物分子的結合親和力由自由能 ΔG 刻畫（越負越可能結合標的），用 AutoDock Vina 的 Vina score 估計（docking 模擬）；druglikeness 用 QED score（0~1，綜合分子量、親脂性、極性表面積等）。Vina 偏好大而多官能基的分子，QED 偏好輕而簡單的分子——兩目標衝突，同時優化非平凡。
  • 方法：把分子編碼為 SMILES 字串當變數，用 Vina 與 QED 構造多目標 loss Evaluation = LLM(Affinity(SMILES_i, target), Druglikeness(SMILES_i))，再以 SMILES_{i+1} = TGD.step(SMILES_i, ∂Evaluation/∂SMILES_i) 更新。LLM 用 gpt-4o；每輪用 AutoDock Vina 估親和力、RDKit 算 QED。用 DOCKSTRING 基準的全部 58 個標的（皆為臨床相關蛋白，其中 29 個有臨床核准藥），每個標的用 3 個不同起始片段（各從一官能基小片段起）優化 10 輪。
  • 結果：58 個標的上，無論起始片段為何，TextGrad 一致生成親和力與 druglikeness 皆改善的分子；對 29 個有臨床藥的標的，生成分子在同一 loss 下與臨床核准藥高度競爭，且結構新穎、in silico 安全性相近。相較 de novo 分子生成的其他 ML 方法，TextGrad 兩大優勢：(1) 結合傳統化學資訊學工具與 LLM 的通用知識與推理，即使無先驗訓練集也有競爭力；(2) 自然語言梯度產生可解釋的決策，讓研究者理解分子結構「如何且為何」被構建。

3.5 放射治療計畫優化

放療用高能束（如 X 光）殺癌細胞，治療前團隊須設計有效計畫（決定劑量與精確照射位置）。放療計畫可視為兩層優化：內圈（inverse planning，如影響圖優化、直接孔徑優化）是受約束的數值優化，最小化平衡多個衝突目標的加權成本函數——既要對計畫標的體積（PTV，含腫瘤與邊界） 給足處方劑量，又要保護危及器官（OARs） 不受過量照射。主要難處是「把整體臨床目標翻譯成加權目標函數與劑量約束」，人類規劃者常用試誤法反覆調整超參數（各 PTV/器官權重），過程主觀、耗時、且反覆呼叫昂貴的優化算法。

  • 方法：TextGrad 做外圈優化——即內圈數值優化器的超參數優化。用 gpt-4o 做 instance optimization，超參數以字串表示 θ = "weight for PTV: [...], weight for bladder: [...], weight for rectum: [...], weight for femoral heads: [...], weight for body: [...]"。給定超參數，先用數值優化器 matRad 解內圈得治療計畫 P(θ) = matRad(θ)；loss 由 LLM 就「計畫 P 與臨床目標 g」計算 L = LLM(P(θ), g)；再 θ_new = TGD.step(θ, ∂L/∂θ)。為幫 LLM 理解 θ 與 P 的關係，TGD.step 時額外提供一組配對的 {(P_i, θ_i)} 當脈絡。
  • 評估指標：平均劑量、以及 D_q（標的/器官體積中 q% 所受的最小劑量，如 D95）。
  • 結果：TextGrad 的梯度提供有意義的引導——當劑量溢出 PTV 時，梯度建議提高 PTV 權重使劑量更均勻集中；但這會降低膀胱、直腸的相對權重致保護不足，故下一步梯度又建議略提膀胱與直腸權重。對 5 名前列腺癌病人，TextGrad 優化計畫在 PTV 的所有指標上優於臨床計畫（更高平均劑量、D95 精確匹配處方劑量），且對膀胱、直腸的平均劑量更低（更好的器官保護）。
