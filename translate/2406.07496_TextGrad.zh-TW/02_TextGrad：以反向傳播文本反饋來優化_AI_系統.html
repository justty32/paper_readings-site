2. TextGrad：以反向傳播文本反饋來優化 AI 系統

暖身：兩次 LLM 呼叫的系統。 考慮簡單系統：Prediction = LLM(Prompt + Question)、Evaluation = LLM(Evaluation Instruction + Prediction)，其中 + 表字串串接、待優化的自由參數是 Prompt。以鏈式記號寫作 Prompt+Question →LLM Prediction →LLM Evaluation。

梯度計算。 要用 evaluation 改進 Prompt，我們實例化反向傳播的類比：

  • ∂Evaluation/∂Prediction = ∇_LLM(Prediction, Evaluation)；
  • ∂Evaluation/∂Prompt = ∇_LLM(Prompt, Prediction, ∂Evaluation/∂Prediction)。

其中 ∇_LLM 是「前向函數為 LLM 呼叫」時的梯度算子，回傳形如「這個預測可以這樣改進…」的自然語言反饋，描述如何修改變數以改善下游目標——類比優化裡的梯度。一個具彈性的實作（對 x →LLM y →LLM L）是把提示組成：「這是與 LLM 的一段對話 {x|y}。以下是對 {y} 的批評：{∂L/∂y}。請說明如何改進 {x}。」再交給 LLM。梯度物件＝變數出現的脈絡＋從 LLM 取得的反饋；此算子不依賴應用領域，一旦實作，全框架所有應用共用同一套。

優化器。 標準梯度下降是 θ_new = θ − ∂L/∂θ。延續類比，我們用文本梯度下降（Textual Gradient Descent, TGD）：Prompt_new = TGD.step(Prompt, ∂Evaluation/∂Prompt)。一種具體實作是把「對 x 的批評 {∂L/∂x}」餵給 LLM，指示「納入這些批評、產生一個新變數」。此函數同樣與領域無關，全框架共用。

一般情況。 抽象可直接套用到任意複雜系統。定義計算圖 v = f_v(PredecessorsOf(v))，∀ v ∈ 𝒱；v 的值可為文字、影像等非結構化資料（本文多數為文字），f_v 是消耗一組變數、產生 v 的轉換（可為 LLM 或數值模擬器）。梯度由 ∂L/∂v = ⋃_{w ∈ SuccessorsOf(v)} ∇_f(v, w, ∂L/∂w) 計算——即從變數 v 被使用過的每個脈絡蒐集反饋並聚合。此式遞迴算出下游目標對各變數的梯度；更新任意變數用 v_new = TGD.step(v, ∂L/∂v)。對有 n 條邊的圖，每輪優化最多多做 n 次 LLM 呼叫（每條邊一次梯度算子）。

目標函數。 數值優化中目標多為可微函數（MSE、交叉熵）；TextGrad 的目標可以是複雜、可能不可微、定義域與值域皆為非結構化資料的函數——這帶來重要的通用性。目標可由「LLM prompt」（§3.3）、「跑單元測試的程式直譯器輸出」（§3.1）、「分子模擬引擎輸出」（§3.4）給出。例如程式片段的 loss 可寫成 Loss(code, target goal) = LLM(這是程式片段 {code}。這是它的目標 {target goal}。請就正確性與執行複雜度評估它。)，此評估訊號即可用來優化程式碼，靠的是 LLM 已被充分驗證的「模擬人類反饋、自我評估、自我改進」能力。

Instance 優化 vs Prompt 優化。 兩類問題：

  • instance optimization（實例優化）：直接把「某問題的解」——程式片段、解答、分子——當優化變數，框架對它產生梯度並就地優化（如 Eq.13 的程式碼在測試時被改進）。
  • prompt optimization（prompt 優化）：目標是找一個能跨多筆查詢泛化的 prompt（如找一個能改善數學推理的 system prompt）。與 instance 優化不同，這裡要求 prompt 具泛化性，而非只改好單一查詢的解。

兩類問題都無須手工調校框架即可求解。

優化技巧（自動微分作為強類比，為框架提供概念支撐）：

  • 批次優化（Batch）：實作隨機 minibatch 梯度下降；前向對一批實例算各自 loss，用 tg.sum（類比 torch.sum）加總；反向時各 loss 對變數的梯度被串接，鏡像「穿過加法的反向傳播」。
  • 約束優化（Constrained）：用自然語言約束（如「回應最後一行須為 'Answer: $LETTER' 格式」）引導優化器；拜 instruction-tuning 之賜 LLM 能遵守，但約束過多時可靠度會下降。
  • 動量（Momentum）：類比梯度下降的動量——優化某變數時，TGD 可選擇性地看到該變數的前幾輪版本。
