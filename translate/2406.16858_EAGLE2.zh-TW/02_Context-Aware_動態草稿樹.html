4 Context-Aware 動態草稿樹

EAGLE-2 動態調整草稿樹，但不改變草稿模型的訓練與推論，也不影響驗證階段。改進聚焦兩處：如何**擴展（expansion）草稿樹（§4.1）、如何重排（reranking）**草稿 token（§4.2）。擴展階段把最新一層中最有希望的節點輸入草稿模型以形成下一層；重排階段挑接受機率較高的 token 組成給原 LLM 驗證的輸入。（下文「節點 node」與「token」互換使用。）

4.1 擴展階段

靠 tree attention，草稿模型能在單次前向同時輸入當前層所有 token 並算出各自下一 token 的機率，一次展開整層。但一次輸入太多 token 會拖慢草稿模型前向，且每層節點數指數成長，故須選擇性擴展。

我們選當前層中全域接受機率（global acceptance probability）最高的 top-k 個 token 來擴展。由於拒絕一個草稿 token 會丟棄其後全部，一個 token 只有在其所有前綴都被接受時才最終被接受，故定義節點 t_i 的 value V_i ＝從根節點到 t_i 路徑上所有 token 接受率的連乘，並用信心分數 c_j 近似接受率 p_j：

V_i = ∏_{t_j ∈ Path(root, t_i)} p_j ≈ ∏_{t_j ∈ Path(root, t_i)} c_j

value 較高的分支較可能被接受，故取最後一層中 value 最高的 top-k 節點輸入草稿模型、依輸出擴展草稿樹（圖 7 上半）。

4.2 重排階段

擴展的目的是加深草稿樹。因接受率介於 0 與 1，較深 token 的 value 必然較低，某些未被展開的淺節點 value 反而高於已展開的深節點。故不直接把擴展階段選出的 token 當草稿，而是把所有草稿 token 重排、取 value 最高的 top-m 個。由於節點 value 恆 ≤ 其父節點，且 value 相同時優先取較淺節點，可保證重排後選出的 top-m 仍構成一棵連通樹。

之後把選出的 token 攤平成一維序列作為驗證階段輸入。為與原始自回歸解碼一致，需調整 attention mask：原始解碼中每個 token 可看到所有前面 token（下三角矩陣）；用草稿樹時不同分支的 token 彼此不可見，故須依樹結構調整 mask，使每個 token 只能看見其祖先節點（圖 7 下半）。

5 實驗

  • 模型：Vicuna 7B/13B、LLaMA2-Chat 7B/13B/70B、LLaMA3-Instruct 8B/70B。
  • 任務：6 個生成任務對應 MT-bench、HumanEval、GSM8K、Alpaca、CNN/Daily Mail、Natural Questions；各任務對原 LLM 沿用同一組草稿模型權重。
  • 指標：因 EAGLE-2 無損，不評估生成品質，只評加速——(1) 加速比（speedup ratio）：相對原始自回歸解碼的實測加速；(2) 平均接受長度 τ：每個 draft-verify 週期平均生成（被接受）的 token 數，與硬體無關但不反映草稿模型開銷。為何不看接受率？因 EAGLE-2 不改草稿模型結構，接受率與 EAGLE 相同。
  • 比較對象：以原始自回歸解碼為 1.00x 基準，對比標準推測式取樣、PLD、Medusa、Lookahead、Hydra、EAGLE；用 Spec-Bench、同硬體確保公平。

5.1 有效性

跨所有資料集與 LLM，EAGLE-2 加速比皆最高。多數方法在程式生成（HumanEval）加速最大（程式碼多用固定模板）；EAGLE 在程式生成上加速可達 5x。PLD 因基於檢索的草稿生成，在 Vicuna 摘要（CNN/DM）上加速比最高。

平均接受長度上 EAGLE-2 也最長：每週期約 4–5.5 個 token，約為標準推測式取樣與 Medusa 的兩倍。代表性數據（表 1／表 2，摘錄 Mean 與 MT-bench）：

原 LLM 方法 MT-bench Speedup / τ 六任務 Mean Speedup / τ（T=0）
Vicuna 13B EAGLE 3.07x / 3.98 2.95x / 3.82
Vicuna 13B EAGLE-2 4.26x / 4.83 4.04x / 4.65
LLaMA2-Chat 13B EAGLE 3.03x / 3.90 3.09x / 3.89
LLaMA2-Chat 13B EAGLE-2 4.21x / 4.75 4.10x / 4.68
Vicuna 7B EAGLE-2 3.62x / 4.98 3.39x / 4.68
LLaMA2-Chat 70B EAGLE-2 3.51x / 4.48 —（僅 MT-bench）
LLaMA3-Instruct 8B EAGLE-2 3.46x / 4.53 —（僅 MT-bench）

在 MT-bench 上 EAGLE-2 約比 Medusa 快 2x、比 Lookahead 快 2.3x，且輸出分布不變。Medusa、Hydra、EAGLE、EAGLE-2 在 QA（Natural Questions）與摘要（CNN/DM）上接受長度較低，標準推測式取樣則無此下降——因前者草稿模型只用 SFT 資料訓練，而世界知識主要來自預訓練、摘要在 SFT 資料中也較少；即便如此 EAGLE-2 在這兩項仍優於標準推測式取樣，也暗示擴充草稿模型訓練資料有潛在好處。

5.2 消融實驗（Vicuna 7B, T=0）

  • §5.2.1 value vs 信心分數：草稿模型的信心是**局部（local）**近似，無法反映一個草稿 token 被接受的實際（全域）機率。用 value（信心沿路徑連乘）而非單一信心來排序節點，加速比與接受長度都更高。
  • §5.2.2 重排：擴展選出的 token 在全域上可能不如未被選的淺節點，故重排全部草稿 token。消融顯示重排同時提升接受長度與加速比。

表 3（MT-bench）：w/o both 2.81x/3.92 → w/o value 3.21x/4.39 → w/o reranking 3.48x/4.86 → EAGLE-2 3.62x/4.98，證明 value 與重排各有貢獻。

6 相關工作

加速 LLM 推論的工作包括低位元量化、剪枝、知識蒸餾，但這些多少會降低模型品質，是「生成品質 vs 計算開銷」的取捨。推測式取樣則靠原 LLM 驗證達成無損加速。後續工作多聚焦於降低草稿開銷、提升草稿與原 LLM 的一致性：SpecInfer 整合多個小模型並用 tree attention 平行驗證；Medusa 訓練多個 MLP 用原 LLM 特徵平行預測多 token；EAGLE 在特徵層自回歸以消除不確定性；Hydra、Recurrent Drafter 沿用此消除不確定性原則；Lookahead、Ouroboros、CLLMs 等用 Jacobi 迭代生成草稿；Draft & Verify 等用 layer skipping／early exit 拿原 LLM 部分參數當草稿模型；REST、LLMA 用檢索生成草稿；亦有級聯不同大小草稿模型的工作。部分方法為更高加速而犧牲品質（如 BiLD 放寬接受條件，Medusa-2、CLLMs、SPACE 微調原 LLM）。

已有工作用部分動態的草稿樹：BiLD、Kangaroo 依草稿模型信心做 early stopping 控制樹深；GLIDE 與 CAPE 在 top-1 信心低時加候選，但這些額外候選不再進一步展開，樹結構受限。相較之下 EAGLE-2 沒有此限制，能靈活動態調整草稿樹結構，性能更好。

7 結論

本文提出 EAGLE-2，一種高效且無損的推測式取樣方法。我們發現 EAGLE 的草稿模型信心是草稿 token 接受率的良好近似，據此 EAGLE-2 採用 context-dependent 的草稿樹結構，顯著提高被接受的草稿 token 數、取得更好加速比。EAGLE-2 保證生成結果與原 LLM 一致且不需額外訓練；在多種 LLM、多個資料集、與多個先進方法的比較中，EAGLE-2 皆取得最高加速比。

附錄 A 實作細節（擇要）

Vanilla 用 HuggingFace transformers（PyTorch、預配置 KV cache）；標準推測式取樣用 HF 的 assisted generation；PLD/Lookahead/Medusa/Hydra 用官方權重與預設；EAGLE 的 Vicuna、LLaMA2-Chat 用官方權重，LLaMA3-Instruct 以 ShareGPT 訓練。EAGLE-2：7B（8B）／13B／70B 原 LLM 分別設草稿 token 總數 60／50／48，草稿樹深度 6，擴展階段選 10 個節點。
