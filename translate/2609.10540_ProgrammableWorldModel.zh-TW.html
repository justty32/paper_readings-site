Programmable World Model

摘要與第 1～2 節：把真實狀態與畫面生成拆開

互動式影片世界模型能生成逼真畫面，卻通常把世界狀態隱含在生成 context 裡。它們難以直接操縱個別實體，也不可靠地保存離開鏡頭的角色、inventory、任務進度等事實，更不能把「門在何種條件下打開」寫成可反覆執行的規則。提示某次結果，並不等於建立支配後續互動的世界法則。

Programmable World Model 把責任拆開：輕量 engine 保存並執行 canonical world state，預訓練影片模型只負責把狀態渲染成視覺觀察。兩者之間採 state-augmented 3D oriented bounding boxes。OBB 提供可跨視角重投影的位置、大小與方向，再附加 persistent identity、semantic category、dynamic state 與 appearance。它比文字、2D box 或 mask 更能約束世界座標，又不像完整 mesh、骨架、動畫與 G-buffer 那樣迫使顯式系統處理所有細節；材質、肢體形變、光照與次級運動仍交給生成模型完成。

第 4 節：可程式化 box world 與生成 renderer

從單張初始影像開始，3D detector 先恢復可見實體與 OBB；VLM coding agent 再把自然語言規格翻成 engine-readable program，為實體設定屬性、關係、可用動作、事件、目標與狀態轉移規則。engine 對每次玩家行動檢查合法性、套用效果並觸發事件，持續維護包含 health、inventory、faction 等不可見變數的 authoritative state。

state compiler 不改動世界狀態，只把目標 camera 下的 OBB 投影成 pixel-aligned controls。identity map 讓同一實體在遮蔽、離鏡與重返時仍可對應；semantic map 表示類別；direction map 由 world-space velocity 轉到 camera coordinates，再量化移動方向，以區分物體運動與相機造成的表觀位移。三種 map 與 camera trajectory 一同餵給附加在預訓練 backbone 上的 Structured Spatial ControlNet。

長時程渲染採 chunk-autoregressive 方式。每個完成的 chunk 把 latent 加入多尺度 temporal history，初始觀察則作為持久 anchor；另把既有 RGB frame 依深度與 camera parameter 提升到 world-space spatial memory，生成新 chunk 前再投影到目標視角。自動資料管線從未標註 gameplay video 估計相機、深度、semantic category、instance mask、track 與 3D OBB trajectory，產生訓練所需控制圖。

第 5 節：CombatStateBench 實驗

**作者自報：**CombatStateBench 有 50 段 combat clips。Count Accuracy 在每段抽八個 frame，共 400 個 frame；State Accuracy 涵蓋 50 次 death events，並在每次轉移後抽三個 frame。VLM judge 只看生成 RGB，不取得 ground-truth box、identity、預期數量或死亡位置。

**作者自報：**本法的 Count Accuracy 為 94.00%、State Accuracy 為 98.00%；LingBot-World-V2 分別為 40.75% 與 8.00%，YUME 分別為 32.00% 與 58.00%。作者據此認為，外部 engine 維護狀態並用結構化空間控制傳給 renderer，比 prompt switching 更能維持角色數與死亡狀態。

**作者自報：**四項 VBench 指標中，本法的 Imaging Quality、Subject Consistency、Background Consistency 與 Temporal Stability 分別為 67.62、94.74、96.98 與 99.00，均為表中最高。定性案例也涵蓋大角度鏡頭旋轉、初始鏡頭外實體重現、賽車場景與異質類別共同渲染。

第 6 節：結論與正文明示邊界

論文的核心判斷很簡單：生成世界不應靠畫面生成器記住世界裡什麼是真的。把可執行、可驗證的狀態演化交給 engine，再讓生成模型補完外觀與細部動態，能同時取得規則控制、離鏡狀態持久性與視覺彈性。

作者沒有獨立的限制小節，但正文清楚限定兩點。OBB 只顯式表示維持實體、世界座標一致性與狀態改變所需的粗結構，內部 articulation、局部形變等仍由生成 prior 決定。其次，Count Accuracy 與 State Accuracy 只量測粗粒度、全域可觀察的結果，不要求 judge 辨認哪個角色死亡或死亡位置，也不直接獎勵 instance-level correspondence。因此，這組實驗證明的是狀態一致性改善，不是完整物理模擬或所有細粒度互動都已解決。
