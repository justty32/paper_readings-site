摘要

隨著預訓練時代對規模化計算（資料與參數）的熱情逐漸降溫，測試時擴展（test-time scaling, TTS）——亦稱「測試時計算」——已成為突出的研究焦點。近期研究顯示 TTS 能進一步激發大型語言模型的問題解決能力，不僅在數學與程式等專業推理任務取得重大突破，也在開放式問答等通用任務中展現成效。然而，儘管近期此領域的研究爆發式成長，仍迫切需要一份提供系統性理解的全面綜述。為填補此缺口，我們提出一個統一的階層架構，沿著 TTS 研究的四個核心維度組織：擴展什麼（what）、如何擴展（how）、在哪擴展（where）、擴展效果如何（how well）。

1. 引言

預訓練規模化（更多資料與參數）的進展因資源密集與人類資料有限而放緩，促使研究者將注意力轉向如何在測試時充分激發 LLM 編碼的智慧。人類認知提供了線索：面對複雜問題時，人們傾向進行更深思熟慮的思考，常產生更好結果。受此啟發，測試時擴展方法在推理階段分配額外計算來提升任務效能，部分研究甚至觀察到類似縮放律的模式：增加推理計算帶來一致的效能提升。推理模型 o1 和 R1 的成功進一步放大對 TTS 的興趣。然而，領域目前缺乏統一的系統性框架來合成洞見、比較技術或辨識 TTS 中的一致趨勢。本文是首篇跨多正交維度全面檢視 TTS 的綜述。核心貢獻：(1) 四軸分類學——what/how/where/how well；(2) 系統性文獻組織與實用分析；(3) 挑戰、洞見與前瞻方向。

2. 擴展什麼（What to Scale）

2.1 並行擴展（Parallel Scaling）

LLM 通常每次查詢生成單一回應。並行擴展透過並行生成多個輸出再聚合為最終答案來改善測試時效能。候選集合 S = {s_{m,i}}，最終答案 ŝ = A(S)。有效性取決於覆蓋率（至少一個正確回應的機率）與聚合品質。兩種常見形式：(1) 單模型重複取樣（self-consistency）；(2) 跨多模型取樣（mixture-of-model）。額外增強技術包括超參數調整（temperature）與輸入修改（prompt rephrasing）。

2.2 順序擴展（Sequential Scaling）

順序擴展基於中間步驟明確引導後續計算。n_{t+1} = R(n_t, p)。許多問題需要深思熟慮而非即時模式匹配，單次「系統一」式生成常在複雜推理任務失敗。迭代方法模擬「系統二」方法，逐步拆解與精煉解決方案。早期工作：CoT prompting（逐步解決）；Self-Refine（精煉回應）；Least-to-Most（分解問題→依序整合）。後續研究顯示迭代修正觸發自我糾正，改善困難任務準確率。

2.3 混合擴展（Hybrid Scaling）

混合擴展利用並行與順序的互補優勢。並行擴展以廣撒網降低遺漏正確思路的風險，順序擴展允許對看似有前景的思路深探。F_{t+1} = S(∪E(s))，T 次迭代後聚合器選出最終解。從認知角度，這反映人類解題者如何生成多個假說（發散思考）再精煉/評估（收斂思考）。ToT 在決策點分支探索多條推理路徑再修剪至單一序列。後續：Graph-of-Thoughts、Forest-of-Thought、MCTS、多代理推理。

2.4 內部擴展（Internal Scaling）

內部擴展讓模型自主決定推理時分配多少計算，而非依賴外部人為策略。透過訓練程序 Φ：(M_0, D) → M_1 更新模型，其中 D 包含多步推理任務。令人驚訝的是：僅使用結果導向獎勵建模進行 RL 就能使模型自主擴展推理過程。測試時：M_1 生成內部狀態序列 z_{t+1} = f_θ(z_t)，學習到的策略 π_θ 控制何時停止。內部回饋迴圈可導致湧現行為——如更詳細的推理鏈或自我評估步驟——無需任何外部提示。在實踐中，內部擴展常匹敵或超越標準技術，因其能將計算專注於單一連貫推理軌跡。

3. 如何擴展（How to Scale）

3.1 調優式方法

3.1.1 監督微調（SFT）：三個子路徑——(1) 模仿：用規劃器演算法（如 MCTS）生成長 CoT 示範，再微調模型模仿。STaR 用模型自身生成逐步解、過濾正確結果、以驗證解作為新示範；ReST-MCTS 整合 MCTS 規劃器探索推理步驟空間。(2) 蒸餾：將更強模型的能力轉移到目標模型。32B 模型在精選樣本集上訓練後可接近教師模型的競賽級數學解題能力。(3) 暖身：RL 前的短時 SFT 階段，穩定後續訓練、避免非接地行為導致的不穩定。

3.1.2 強化學習（RL）：分兩類——(a) 無獎勵模型：DeepSeek-R1 引入的可驗證獎勵 RL 是關鍵創新，透過 rule-based 獎勵機制高效可靠地優化模型。cDPO/CPL/Focused-DPO 優先處理關鍵或易錯區域；VC-PPO 解決長 CoT 任務中 PPO 失效問題。開源框架：SimpleRL/Open-Reasoner-Zero/OpenR1。(b) 有獎勵模型：PPO 為基礎；GRPO 以改進取樣策略取代傳統值模型；PRIME 將 SFT 模型作為 PRM 在統一 RL 框架中線上更新。

3.2 推理式方法

刺激（§3.2.1）：提示策略（hint-infer: 先推理解答、budget forcing: 控制思考長度）；解碼策略（filler tokens, AFT: 自適應焦點思考）；潛在策略（Coconut: 連續潛在空間推理、CoDI: 連續擴散思維）。

驗證（§3.2.2）：兩類——(1) 結果驗證：輸出驗證器（OVM）、生成式驗證器、判別器、功能性驗證、bandit 驗證；(2) 過程驗證：狀態評估器、SIaM（自我改進代理模型）、演繹驗證、自我評估器、工具輔助驗證。

搜索（§3.2.3）：樹搜索（ToT/MCTS/C-MCTS）、圖搜索（GoT）、beam search、前瞻搜索。MCTS 是 2024 至今最活躍的混合搜索方法。

聚合（§3.2.4）：多數投票、過濾投票、長度過濾投票、Best-of-N、加權 BoN、LLM 合成融合。

4. 在哪擴展（Where to Scale）

推理密集任務（§4.1）：數學（AIME/MATH/GSM8K/FrontierMath）、程式（USACO/LiveCodeBench/SWE-bench）、科學（GPQA/OlympiadBench/TheoremQA）、遊戲與策略、醫療。

Agent 任務（§4.2）：WebShop、WebArena、SciWorld、TAU-bench 等互動環境。

其他（§4.3）：知識（SimpleQA）、開放式（AlpacaEval/ArenaHard）、多模態（MMMU/MathVista）。

5. 擴展效果如何（How Well to Scale）

5.1 效能

Pass@1（首次輸出正確率）；Pass@k（k 次取樣至少一次正確）；Cons@k（k 次多數投票正確率）；LLM-as-a-Judge 成對比較；Codeforces 百分位/Elo 評級。

5.2 效率

核心公式：推理效率 η(M) = E[Q(M,D)/C(M,D)]，其中 Q 為任務效能、C 為計算成本（token/FLOPs/延遲）。多維低效模式：(1) 冗餘：過度重複推理步驟；(2) 欠思考（underthinking）：過早轉換推理方向；(3) 過思考（overthinking）：即使簡單問題也過度回訪/驗證早期步驟。

5.3 可控性

控制度量（輸出長度與目標長度偏差）；長度偏差（平均偏差/RMSE）；k-ε 可控性（是否存在長度 ≤k 的提示使模型以 ≥1-ε 機率輸出目標）。

5.4 可擴展性

Scaling Metric（準確率對計算的平均斜率）；縮放曲線（準確率 vs 計算預算圖，揭示收益遞減與效能飽和）。
