2. 背景

大型語言模型的能力：大型語言模型在多個維度上展現強大能力，顯著改變了 NLP 的研究範式（Brown et al., 2020；Hoffmann et al., 2022；Chowdhery et al., 2022；Wei et al., 2022a）。目前訓練 LLM 的新配方是：先訓練一個基礎模型（如 GPT-3、PaLM、OPT），再透過指令微調引出基礎模型的能力（如 GPT-3→InstructGPT，Ouyang et al., 2022；PaLM→FlanPaLM，Chung et al., 2022；OPT→OPT-IML，Iyer et al., 2022；亦見 Fig. 1A 步驟一、二）。就基礎模型而言，Wei et al.（2022b）最初顯示若模型規模小於 100B，CoT 表現曲線近乎為零；後來 Chung et al.（2022）更新此假說，顯示若把 CoT 資料當成一種特定指令類型納入，仍可解鎖 CoT 能力，但其模型表現不如預期，因為模型能力分散在多個維度上。本文顯示，若把模型能力集中到目標能力，CoT 表現可被大幅拉高（Fig. 1A 步驟三）。

特化語言模型：儘管現代語言模型在多個方向上展現強大的通用能力，近期分析（Fu et al., 2022）顯示模型確實有不同的側重（如 code-davinci-002 側重程式碼、text-davinci-003 側重文字）。能力取捨在各種規模上都會發生：對大模型而言，這種取捨不必是全有或全無——code-davinci-002 雖特化於程式碼，仍能解決大量文字問題；對小模型而言，由於容量有限，它們必須用全部通用能力交換一項特殊能力。一個例子是 GitHub Copilot，據信是一個 12B 的小模型（Thakkar, 2022）。特化的實際做法就是簡單微調：要把模型特化到目標能力，只需用相關資料微調模型，這正是同期關於小模型 CoT 能力研究的做法（Magister et al., 2022；Shridhar et al., 2022；Ho et al., 2022）。這裡的問題是如何在微調資料之外泛化，因為小模型可能只是過擬合微調分佈，在分佈偏移時難以泛化（Liu et al., 2022；Si et al., 2022）。目前社群對 OOD 泛化的假說涉及兩個重要面向：(1) 模型規模（Chowdhery et al., 2022）；(2) 指令微調（Chung et al., 2022），本文也會研究此點。這些因素標誌了本文與同期蒸餾工作的差異：我們展示模型如何用通用能力交換目標能力，以及模型規模與指令微調如何幫助模型取得更好的同分佈與 OOD 表現。

圖 1 說明：A. 模型特化流程——預訓練給出強基座模型（Raffel et al., 2020；Chowdhery et al., 2022），指令微調引出模型能力（Chung et al., 2022），接著特化（本文重點）把模型能力搬向目標方向；本文用 BigBench Hard 量測的通用能力，交換多步數學推理能力。B. 本文考慮的四種微調資料格式——後續會顯示，用帶上下文範例的思維鏈資料微調對模型的 CoT 能力特別重要。C. 用動態規劃把 GPT 分詞對齊到 T5 分詞——若某個 T5 token 與某個 GPT token 一對一對應，則沿用 GPT 的 top-5 機率當目標分佈；若映射是一對多／多對一，則把 T5 token 的分佈視為 one-hot。

蒸餾與資料增強：本文用 code-davinci-002 生成的資料微調更小的 FlanT5，可視為蒸餾（Tan et al., 2019）或資料增強（Li et al., 2022）。這裡我們僅把生成資料當作模型特化的工具，特化資料也可以來自其他來源，如人工標註。本文重點是研究特化過程中的能力取捨，而非直接對蒸餾或資料增強文獻做貢獻。

最相關工作：兩條最相關的工作脈絡：(1) FlanT5（Chung et al., 2022）與 UL2（Tay et al., 2022），是最早討論小模型 CoT 能力的工作，但它們聚焦通用 CoT，本文則以通用能力交換數學 CoT。(2) 語言模型自我改進（Huang et al., 2022），同樣使用 CoT 資料增強，但只考慮大模型、未展示模型能力間的取捨；本文聚焦小模型並清楚展示能力提升所需付出的代價。
