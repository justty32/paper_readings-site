3. 特化多步推理

本文目標是研究提升小模型思維鏈數學推理所需的條件。我們用 GSM8K（Cobbe et al., 2021）當種子資料集，因為它是數學推理問題最多樣的資料集之一，但用另外三個數學資料集（MultiArith、ASDiv、SVAMP，Wei et al., 2022b）測試模型表現，以展示模型能泛化到 OOD 資料。我們進一步用 BigBench Hard 測試模型的通用推理能力，以展示通用能力與目標能力間的取捨。我們用 T5（原始預訓練 checkpoint）與 FlanT5（指令微調 checkpoint）當基座模型，用 code-davinci-002 生成蒸餾／特化資料。

從 Code-Davinci-002 蒸餾：給定一組訓練問題語料，我們用 code-davinci-002 為每題生成 40 個新的 CoT 解答，取其中導向正確答案者當訓練資料。一個解答包含一個答案與一段解釋中間步驟的思維鏈。除了標準微調設定（用問題當輸入、用 [CoT, 答案] 對當輸出，Fig. 1 B4）外，我們進一步考慮三種額外資料格式：(1) 上下文答案式（in-context answer-only，Fig. 1 B1）——不使用 CoT 資料（故稱「answer-only」），並在問題前加入 4 個上下文範例（故稱「in-context」）。加入上下文範例的原因是先前工作顯示，用上下文範例微調能改善模型的上下文學習能力（Min et al., 2022）。(2) 上下文思維鏈（in-context chain-of-thought，Fig. 1 B2）——在上下文範例與輸出中都加入 CoT。(3) 零樣本答案式——直接輸入問題、輸出答案；使用答案式資料是因為先前工作顯示它們能改善表現。實驗中我們會顯示：上下文資料能誘發零樣本能力，但零樣本資料會犧牲上下文學習能力。我們也注意到還有像加計算機（Cobbe et al., 2021）或 self-consistency 解碼（Wang et al., 2022）等技術能進一步提升表現；這些技術與本文使用的蒸餾正交，未來絕對可整合進本文方法以獲得更好表現。因本文重點是模型特殊能力與通用能力間的平衡，我們把這些正交技術的整合留給未來工作。

就訓練目標而言，蒸餾文獻中通常有兩類做法：(1) 樣本匹配（sample matching）——在教師生成的資料上訓練學生模型；本文中即直接優化學生在 code-davinci-002 生成資料上的似然。(2) 分佈匹配（distribution matching）——最小化學生輸出分佈（本文中為逐步自回歸分佈）與教師分佈間的 KL 散度。通常分佈匹配比樣本匹配收斂更快、表現更好，因此我們用分佈匹配當訓練目標。分佈匹配在儲存分佈參數上有額外挑戰：每一步都需儲存定義在詞彙表 𝒱 上的完整分佈，資料集大小因此是樣本匹配的 |𝒱| 倍。然而 OpenAI API 每個解碼步驟只提供最可能的 5 個 token，而非整個詞彙表上的機率分佈。儘管逐步分佈只涵蓋 top-5 token，多數時候它們的機率總和已接近 1，是完整詞彙分佈相當不錯的近似。我們把不在 top-5 內的 token 機率設為零。

以動態規劃對齊分詞器：匹配兩個分佈時的一個問題是 GPT 分詞器與 T5 分詞器之間的錯位。我們用動態規劃解決此問題。具體而言，給定兩個 token 序列 [𝐬₁:L, 𝐭₁:N]，目標是找出一個對齊方式，最小化把一個序列編輯成另一個序列的總成本。我們的動態規劃是生物資訊學中序列比對教科書演算法（如 Needleman–Wunsch 演算法）與訊號處理中動態時間校正（dynamic time warping）的簡易變體。遞迴函式為 f(i,j) = min{ f(i-1,j)+c(𝐬ᵢ,𝐭ⱼ), f(i,j-1)+c(𝐬ᵢ,𝐭ⱼ), f(i-1,j-1)+c(𝐬ᵢ,𝐭ⱼ) }，其中 f(i,j) 表示對齊 𝐬₁:ᵢ 與 𝐭₁:ⱼ 的總成本，c(𝐬ᵢ,𝐭ⱼ) 是 token 𝐬ᵢ 與 𝐭ⱼ 之間預定義的字串編輯距離；此演算法不強制兩序列間一對一匹配，𝐬 中一個 token 可能對齊 𝐭 中多個 token，反之亦然。若 GPT token 與 T5 token 間存在一對一映射，我們沿用 GPT 分佈當 T5 分佈；若映射非一對一（如兩個 T5 token 映射到一個 GPT token，或反之），則不使用對應的 GPT 分佈，改把 T5 分佈設為 one-hot。我們也指出，對齊不同分詞器生成的序列是當代 NLP 的一個通用問題，但我們尚未見到相關的既有函式庫；我們計畫釋出此動態規劃的實作，希望對未來研究有幫助。
