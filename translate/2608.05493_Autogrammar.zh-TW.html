Autogrammar：學習可供 constrained decoding 的 CFG

摘要

LLM 對罕見 DSL 容易產生語法無效程式。本文的 Autogrammar 由文件與 execution data 學習 CFG，並把 agent 寫成由 LLM 解決非確定選擇的 Kripke structure；LTL 描述可允許的 agent 行為。三種 DSL 的未見 precision 為 91–100%，加性能限制可快 3.8×而無顯著 precision 損失；所生 grammar 讓十個實務任務中的八個改善。

1–2. 動機與背景

GCD 只允許 decoder 輸出可延伸成合語法程式的 token，前提卻是有 CFG。低資源 DSL 的問題正在此。作者不把 grammar learning 做成固定演算法，也不讓 general coding agent 自由漫遊，而是找出可宣告、可檢查的中間形式。

3. LTL constrained agent

Kripke structure 以狀態集、初始狀態、轉移關係、標記函式與原子命題描述 agent。LLM 只在非確定位置挑選分支；LTL 公式限制那些分支序列，例如必須先收集資料、驗證後才輸出、或限制昂貴修訂。更換公式即可得到不同 agent policy，且能證明每條執行路徑滿足該 temporal specification。

Autogrammar 的實例使用 Strands SDK 與 Lark。它提示 LLM 產出能通過訓練例子的 grammar，從文件及 API execution 中得到素材，並以精確率為優先目標：GCD 若誤拒合法 query，實用性也會消失。這個保證不替 grammar 的語義或未知資料表現背書。

4. 實證

作者在 CWIL、DQL、DSS 做五折。Autogrammar 平均 precision 91–100%，並勝過 LM 基線與 Arvada；後者在 CWIL 平均 63k oracle、14.6 小時卻只有 0.025 precision。性能限制將上限從 120 分鐘等條件改寫進 LTL，報告 3.8×加速且 precision 無統計顯著差異；CWIL 的 recall 則有統計顯著下降。

消融顯示 execution data 至關重要；去除文件多數情況不影響，DQL 有小幅顯著下降。CFG 接入 CloudWatch decoding 後，在十個原本用於分析的真實任務中八個提升，且等同或優於 professionally maintained grammar。這是 end-to-end 受限於該十任務的證據，不是通用語義正確保證。

4.3–5. 威脅與結論

log／任務來源可能偏、LLM 與時間預算影響結果，三個 DSL 也不能代表所有 DSL。本文的穩固貢獻是工程形態：以執行資料補文件，以 CFG 作 decoder 的硬邊界，並以 LTL 讓 agent 搜尋程序本身可聲明、可驗收。
