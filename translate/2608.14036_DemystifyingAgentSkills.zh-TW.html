論文／訪談原始來源

Demystifying Agent Skills: Why They Work-Until They Don't

摘要與第 1 節：問題

既有 skill 評測多半只看聚合成功率，沒回答「skill 何時有用、為何有用、何時失效」。作者設計對照研究：固定同一批來源軌跡，比較 Raw（無先驗經驗）、Workflow Memory（清洗過的執行痕跡）、Skill（蒸餾成 SKILL.md 的標準化程序）三臂，並用成對軌跡分析把差異歸因到具體機制，而非只看端到端輸贏。

第 3 節：研究設計

四道研究問題：RQ1 表徵形式（直接塞 workflow trace vs 蒸餾成 skill）如何影響行為；RQ2 outcome 標註（成功/失敗註記）本身貢獻多少，用 no-hint 消融隔離；RQ3 蒸餾出的程序知識能否跨 agent framework 遷移；RQ4 skill pool 變大變混淆時，檢索品質與下游執行的關係。實驗用 Codex+GPT-5.3-Codex 與 Gemini CLI+Gemini-3.1-Pro-Preview 兩組配對，在 Terminal-Bench-2、SkillsBench、Terminal-Bench-Pro 上跑，並用固定預算的成功/失敗軌跡組成網格（如 5s0f 到 0s5f）控制輸入。

第 4 節：對照分類法

作者把 8,135 筆試驗紀錄正規化，對 240 筆抽樣軌跡開放編碼，收斂出 238 個有效唯一標籤，再歸併成三大類、十二種 skill-use 模式。人工驗證：238 個標籤各抽 3 條支持軌跡（714 次檢查）全數獲確認來自真實行為；人機分類一致率 95.8%,Cohen's κ=0.952（作者自報）。三大類為 SC1（成功的程序性錨定）、SC2（執行層與驗證失敗）、SC3（套用、適用性與邊界失敗）。528 組配對三元組（跨三個 benchmark）顯示 skill 臂把更多軌跡推進 SC1（326/528 vs workflow 294/528），降低 SC2（124/528 vs raw 197/528、workflow 176/528），但把 SC3 從 raw 的 19/528 推高到 78/528。

第 5 節：主要發現

skill 作為程序性錨點而非知識注入（5.1）：skill 臂 oracle 成功率 61.9%，高於 raw 59.1%、workflow 55.9%;skill 對 workflow 的淨勝出為 +6.06 個百分點（95% bootstrap CI [+0.76, +11.36]）。機制標籤中 procedural_anchor 佔 skill 案例 65.7%,knowledge_injection 僅 4.5%，顯示 skill 主要穩定「怎麼做」。兩個輕量對照基準（指令衍生短計畫 47.7%、workflow 衍生的 test-first 模板 59.2%）皆遠低於 Skill injection（79.2%），排除「任何精簡提示都有效」的解釋。

執行穩健度提升，但補不了推理缺口（5.2）：SC2 模式從 raw 37.3%、workflow 33.3% 降到 skill 23.5%。environment_infrastructure_failure 從 5.3% 降至 0.2%,output_format_schema_mismatch 從 7.4% 降至 3.2%。但 algorithmic_logic_error（raw 8.3%、workflow 11.0%、skill 7.4%）與 static_verification_without_runtime（12.5%、12.5%、11.7%）三臂皆持平，skill 修不了錯的演算法邏輯，也不會自動補上執行期驗證。

skill 引入新的套用失敗面（5.3）：skill_guidance_misapplied_or_ignored 在 skill 臂佔 10.0%，遠高於 raw 0.8%、workflow 0.4%——skill 內容本身可能合理，但 agent 機械套用、漏判前提條件。workflow memory 的主要弱點不同，是流程過載：timeout_budget_exhaustion 在 workflow 臂佔 10.6%（raw 1.7%、skill 4.4%），長探索與失敗分支的雜訊拖垮執行。

outcome 標註影響 skill 品質（5.4）：來源池全為成功軌跡時，拿掉 outcome 標註（no-hint）影響不大；一旦混入失敗軌跡，影響急遽放大。例如 Gemini 在 Terminal-Bench-2 的 3s2f 組合，有標註達 0.7462，無標註僅 0.4000。

檢索是獨立瓶頸（5.5）：SkillsBench 上，candidate pool 從 5 擴到 100,Arm 3（全池真實執行）實際使用精確率從 29.6% 掉到 3.3%，但下游成功率僅從 36.4% 微降至 39.3%（走勢近乎持平，作者自報）;Arm 3 recall 在 k=100 仍有 54.3–73.6%，顯示 agent 常同時碰觸多個候選而非漏看正確 skill。兩個離線診斷（embedding top-1 精確率、agent 顯式選擇精確率）都隨池擴大下降，相似型 distractor 是主要壓力來源（如 embedding 在相似池從 70.5% 掉到 53.4%，遠比隨機池或不相似池陡）。三者互為獨立量測，精確選中 ground-truth skill 既非成功的充分條件，也非必要條件。

第 6–7 節：結論與局限

作者主張 skill 使用應被當成生命週期問題：先蒸餾成正確抽象層級，再跨框架遷移或檢索到相容情境，最後被正確套用與調適，每一步都可能失效。局限：評測集中在終端機／工具型 benchmark，未涵蓋長程網頁互動或開放式協作；模型與框架組合有限；機制分類法來自約 3% 記錄的分層抽樣開放編碼，罕見行為模式可能代表性不足。
