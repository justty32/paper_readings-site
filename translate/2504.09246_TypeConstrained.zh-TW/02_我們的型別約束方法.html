3. 我們的型別約束方法

3.1 一個簡單型別語言 L_B

定義一個簡單型別、Turing-complete 的語言 L_B，其文法與型別系統泛用、近似 TypeScript/Java/Go（略偏 TypeScript）。

  • 語法（Figure 4）：含運算式、帶型別註記的變數與函式定義、控制流。運算式分base expression（識別子、字面量、分組、匿名函式）與 extension expression（二元運算子、函式呼叫、成員存取——對既有運算式施加後綴運算子形成更複雜運算式）；此區分對 §3.4 建構運算式自動機很有用。
  • 運算式型別規則（Figure 5）：採用 Bierman 等人的 safeFTS（TypeScript 的型別安全子集）之子集，得以沿用其 soundness 結果。用標準型別環境 Γ（識別子：型別 對），Γ ⊢ e : T 表示 e 在 Γ 下型別為 T。二元運算子有預定義簽章（如 number + number : number）、函式呼叫須參數符合簽章、成員存取 e.n 用輔助函式 lookup(S,n) 取型別。
  • 敘述與型別環境（Figure 6）：Γ1 ⊢ s ↣ Γ2 表示執行敘述 s 後環境由 Γ1 變 Γ2。變數宣告引入識別子（須未定義）；block/ite/fun 內部須維持有效環境但不外洩（fun 例外：函式簽章最終加入外部環境）；seq 沿執行傳遞環境。
  • 回傳型別（Figure 7）：Γ ⊢ s : R 表示敘述序列 s 保證回傳 R 型別的值——回傳運算式須符函式宣告回傳型別，且每條執行路徑都須回傳（if-then-else 兩分支須回傳同型別）。
  • 語言定義：程式 s ∈ L_B 當且僅當 (i) 合乎 Figure 4 文法，且 (ii) 依 Figure 5–7 型別規則 well-typed。

3.2 Prefix automaton 定義

自動機 A := ⟨Σ, Q, δ, I, F⟩（字母、狀態、轉移函式、初始態、接受態）。轉移函式 δ 定義 Q 上的有向圖 G；A 接受的語言 L(A) := {s | γ(I,s)∩F ≠ ∅}（γ 為遍歷函式）。兩個可歸納證明的可達性性質：(P1) 路徑可任意切分；(P2) 若 s◦s′ 可達某狀態，則 s 也可達某狀態。

  • 定義 2（prefix property）：對自動機 A，若 ∀q∈γ(I,s): ∃s′: γ(q,s′)∩F ≠ ∅（每個可達狀態都存在通往接受狀態的路徑），則 A 是 prefix automaton。直覺上：以字串 s 到達某狀態，即意味 s 是 L(A) 某成員的前綴。
  • Lemma 1：若 A 是 prefix automaton，則 L(A)_p = L_r(A)（前綴語言等於「可達語言」＝能到達某狀態的所有輸入）。證明用 (P1)(P2) 與定義 2。
  • 從 prefix automaton 到 completion engine：定義 CE_{L(A)}(s) := γ(I,s)≠∅。因目標語言是 L 而非 L(A)，須確保 L(A) ⊆ L——如此所有受約束生成都落在 L 內（即都 well-typed）；反之 L(A) ⊇ L 只保證每個 L 中字串都能被表達、但不保證每次生成有效。理想是 L(A)=L。作者的最終自動機覆蓋 L_B 一個顯著但不完整的子集（為保證演算法終止，不涵蓋實務罕見的高階型別，§3.4 詳述）。
  • Σ 取 Unicode 字元集，使 completion engine 與 LLM 詞表無關（呼叫時逐字元處理採樣到的 token）。並先介紹幾個 base prefix automata：Union、Concatenation、Kleene-Star、Terminal（固定非空字串）、Empty（空語言），後續組合成更複雜自動機。

3.3 識別子、字面量、型別的 prefix automata

  • 字面量 A_l := A_num ∪ A_str ∪ A_bool：由對應正規表達式的 DFA 定義，並剪掉到不了接受態的狀態以確保 prefix property。
  • 識別子 A_x：Γ 中已定義識別子的 terminal 自動機之聯集。
  • 型別 A_T := A_{type-lit} ∪ A_{type-fun}：函式型別 (p)=>T 遞迴於 A_T；遞迴定義有效（初始態有限、接受集可判定、保持 prefix property）。這些自動機解析的語言與 L_B 對應成分完全相符。

3.4 運算式的 prefix automaton（核心）

  • 無限制運算式 A_e：base 自動機（A_x, A_l, A_(e), A_{(p)=>e}）與 extension 自動機（A_{⊙e}, A_{.n}, A_{(e)}）的聯集，透過遞迴調整轉移函式 δ_e——從當前自動機的接受態加出邊到擴充自動機的初始態。狀態上標 q_Y^X 追蹤「已解析字串 X、當前活躍自動機 A_Y」與當前表達的型別，據此判定擴充是否合法並在需要時轉入型別受限運算式。例：狀態 q_42，加法 +e 語法上可用（42 是 number，number+number:number 合法）但函式呼叫 (e) 不可用；且為使 +e 合法，e 須為 number，於是把 I_{+e}^{42} 設為 A_+ ◦ (A_e ↓ number) 的初始態。
  • 型別受限運算式 A_e ↓ T：須判定部分運算式 s 能否補全成棲居型別 T。因擴充可無限施加、無法窮舉，作者設計兩層演算法：
    1. derivable(q_s)（可導出型別）：s「不加擴充」時所有可棲居型別的集合。Table 1 給各類部分運算式的規則（字面量用 pmatch 部分比對；識別子取 Γ 中前綴相符者的型別；成員存取用 lookup 等）。Lemma 2：derivable(q) 恰回傳所有「存在不含擴充的後綴 s′ 使 Γ ⊢ s◦s′ : T」的 T。
    2. type reachability（Algorithm 2）：reachable(T,G) 在抽象型別圖上做 DFS，從當前型別 T 找目標型別 G——每個二元運算子簽章 T⊙X:S 建 T→S 邊，每個成員建 T→lookup(T,n) 邊，函式型別 (p)=>R 連到回傳型別 R。標記已訪型別避免環路。因自參照成員（如 Java 的 clone、TS 的 valueOf，型別 ()=>T）可無限導出高階函式，於 Line 6 加入啟發式 pruneSearch（基於 Gvero 等人的結果，剪掉「複雜度高於目標/來源型別、且不含未探索原始型別」者）以保證終止。
  • 可靠性與不完備性：搜尋是 sound（Lemma 3：若 reachable(T,G) 成立，則存在擴充序列 y 使 Γ ⊢ e◦y : G），這足以保住 prefix property；但為終止而不完備（可能拒絕合法但高複雜度的型別，實務影響小）。Corollary 4 + Lemma 5：A_e ↓ T 與 A_e 都是 prefix automaton 且解析的是 L_B well-typed 運算式的子集。

3.5 敘述的 prefix automata

A_s := A_decl ∪ A_expr ∪ A_ret ∪ A_block ∪ A_fun ∪ A_ite（遞迴定義）。宣告自動機接受除既有識別子外的所有字串；回傳敘述在函式外是空語言、在函式內把運算式限制到函式回傳型別。

  • 追蹤型別環境：一般依 seq 規則傳遞識別子；在 block/ite/fun 解析後丟棄區域環境；fun 額外把函式簽章與參數加入函式體環境、把簽章加入後續敘述環境。
  • 保證回傳型別：A_fun 追蹤宣告回傳型別與已遇回傳敘述，只接受「所有回傳值符型別、所有執行路徑都回傳」的狀態；若尚未在所有路徑回傳，就強制再生成一個敘述（因總能用字面量表達所需型別，恆能補上正確回傳敘述，不違反 prefix property）。
  • Lemma 6：A_M := A_s 是 prefix automaton 且 L(A_M) ⊆ L_B。
