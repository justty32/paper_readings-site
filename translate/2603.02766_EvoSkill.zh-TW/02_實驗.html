3. 實驗

沿三個軸評估：(1) 迭代技能演化是否提升代理效能；(2) 訓練設置的哪些性質影響技能品質；(3) 演化出的技能是否能 zero-shot 遷移。額外展示發現技能的定性範例。

3.1 OfficeQA

基準：OfficeQA 建立於美國財政部公報——約 89,000 頁、橫跨五十年的月度與季度出版品。每份公報 100–200 頁，包含散文、複雜表格、圖表。基準含 246 題，分為簡單與困難兩級。人類解題平均每題 50 分鐘，多數時間花在查找跨表格與圖形的相關資訊。

設置：使用 Claude Code + Opus 4.5。分割為訓練集、17 題驗證集（≈7%）與保留測試集。評估三種訓練集大小：5%（12 題）、10%（24 題）、15%（36 題），各演化 1.5 epochs。另評估 skill-merge 配置（合併多次獨立運行的獨特技能）。

結果（Table 1 / Figure 2）：EvoSkill 在所有設置上一致優於基線。Exact match（0% tolerance）：5% 訓練 60.6%→63.4%（+2.8%），10% 訓練 →65.8%（+5.2%）。15% 略低於 10%（64.5%），提示收益遞減或輕微過擬合。Skill-merge 達最佳 67.9%（+7.3%），顯示獨立運行的技能互補——每次運行浮現不同失敗模式與對應能力，合併產生更完整的技能庫。

定性分析：發現的技能具備可解釋性與領域針對性——data-extraction-verification（數值提取驗證協議，處理相鄰儲存格誤讀與指標混淆）與 quantitative-analysis-methodology（量化分析檢查點，強制計算前驗證步驟）。技能針對具體失敗模式，而非產出不透明的黑箱最佳化。

3.2 SealQA

基準：SealQA 挑戰搜尋增強模型在網路搜尋傳回衝突、噪音或無用結果時的事實尋求問答。與 OfficeQA 的固定文件語料推理不同，SealQA 評估代理在對抗性檢索條件下導航開放網路的能力。

設置：seal-0 分割（111 題），Claude Code + Opus 4.5，10% 訓練分割，演化 1.5 epochs。

結果：準確率 26.6%→38.7%（+12.1%）。發現的核心技能為 search-persistence-protocol：強制窮盡搜尋策略（詞語解釋擴展、多來源驗證、完整性檢查），直接針對噪音檢索下過早終止搜尋的失敗模式。此結果證明 EvoSkill 能泛化到不同任務類型，發現適合目標領域的質性不同技能。

3.3 Zero-Shot 技能遷移

EvoSkill 的關鍵設計目標是演化出的技能（具結構化與可解釋性）應能無修改地跨任務遷移。將 SealQA 上演化的 search-persistence-protocol 技能 zero-shot 應用於 BrowseComp（評估瀏覽代理在挑戰性事實尋求問題上的基準，128 題分層樣本）。

結果：準確率 43.5%→48.8%（+5.3%）。此技能捕捉了一個通用能力——提交答案前先窮盡搜尋——對各類事實尋求任務均有價值，不受特定基準限制。這直接支援了「技能級別最佳化（相較於 prompt 或程式碼級別）產出更具遷移性的改進」的假設。

4. 相關工作

4.1 代理技能

Voyager 為 LLM 驅動的 Minecraft 代理引入了一個不斷增長的技能庫，技能作為程式儲存在向量資料庫中，透過語義相似度檢索。Agent Skills specification 將技能格式標準化為包含 SKILL.md、觸發元資料與選用腳本的資料夾目錄，被 Claude Code、Claude API 等採納。此範式利用漸進式揭露（progressive disclosure）：元資料在啟動時載入，指令按需讀取，腳本執行不進入上下文窗口。儘管技能基礎設施已成熟，目前技能仍以手工編寫為主。EvoSkill 填補此缺口，自動發現與精煉符合標準格式的技能。

4.2 文字回饋與演化最佳化

Self-Refine 展示了單一 LLM 可透過生成-批評-精煉迴圈改善自身輸出，但僅作用於個別輸出，不累積跨迭代知識。Feedback Descent 將其形式化為通用最佳化框架，維護 frontier 與回饋歷史，使編輯 LLM 能做出日益知情的修訂。AlphaEvolve 使用 LLM 群體演化整個程式碼庫，GEPA 對 DSPy 框架內 prompt 進行演化。EvoSkill 建立在這些基礎上，在更高抽象層級（技能而非 artifact）操作——演化出的技能具備可解釋性、可組合性與跨任務遷移性。

4.3 LLM 代理的遷移學習

Voyager 展示了在一個 Minecraft 世界學習的技能庫可應用於新世界的嶄新任務。Prompt 遷移（跨任務或跨模型）結果好壞參半。EvoSkill 提供不同角度：技能作為自包含資料夾，具備明確觸發條件與程序性指令，與訓練任務及底層模型解耦——這使技能級別最佳化成為比 prompt 或程式碼級別更自然的遷移單位。

5. 結論

EvoSkill 在技能抽象層級自動發現與精煉可復用代理技能，產出結構化、可解釋的能力，隨迭代累積並能跨任務遷移。實驗在兩個不同基準上展示一致改善（OfficeQA +7.3%、SealQA +12.1%），並提供 zero-shot 技能遷移的直接證據（SealQA→BrowseComp +5.3%）。

未來方向：(1) 在更廣泛領域評估，區分哪些技能是領域通用的（搜尋持續性、驗證協議）vs. 領域特定的（財政部表格提取）;(2) 擴展到多模態任務（視覺、程式碼、語言協調）;(3) 建立共享技能庫，供不同代理與使用者瀏覽、組合與復用；(4) 深入探討技能跨任務、跨模型、跨 agent harness 的遷移性。
