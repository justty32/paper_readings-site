摘要

我們研究一類優化問題，其動機是自動化 AI 系統（如程式碼助手、機器人、copilot）的設計與更新。AutoDiff 框架（如 PyTorch）能高效地端到端優化可微分系統；但一般的計算工作流（computational workflow）可能不可微分，且涉及豐富回饋（如 console 輸出、使用者回應）、異質參數（如 prompt、程式碼）與複雜目標（超出最大化單一分數）。我們研究端到端生成式優化（generative optimization）——在優化器內使用 LLM 這類生成模型來自動更新一般計算工作流。我們發現：工作流的執行軌跡（execution trace）類似 AutoDiff 中反向傳播的梯度，能提供解讀回饋所需的關鍵資訊以實現高效優化。形式上，我們提出新的數學框架 OPTO（Optimization with Trace Oracle）：優化器在每輪迭代收到執行軌跡與對輸出的回饋，據以更新參數。我們提供 Python 函式庫 Trace，以 PyTorch 式語法把工作流優化問題高效轉換為 OPTO 實例；並基於 Trace 開發通用的 LLM 生成式優化器 OptoPrime。實驗顯示 OptoPrime 能做一階數值優化、prompt 優化、超參數調校、機器人控制器設計、程式碼除錯等，且常與各領域的專用優化器競爭。

1. 引言

整合 LLM、ML 模型、編排（orchestration）、檢索器、工具的計算工作流驅動著最先進的 AI 應用——從聊天機器人、程式碼助手、機器人到多代理系統。但設計工作流需要繁重工程，因為涉及許多異質參數（prompt、編排程式碼、ML 超參數）；且部署後任何錯誤行為都會持續存在，除非開發者手動修正。此類優化問題具有：異質參數、豐富回饋（console 輸出、使用者口頭回應）、複雜目標；工作流還可能含相互依賴的步驟（自適應編排、回饋控制迴圈）與不可微分、半黑箱、隨機的操作（ML 模型、模擬），計算結構會隨參數與輸入改變。

過往此問題多被框架為黑箱優化或演算法配置問題，用貝葉斯優化、演化演算法、RL 等以純量分數為回饋的通用技術處理；但單一純量回饋觀測不提供改進方向訊號，當參數空間很大（如程式碼或自然語言 prompt）時這些演算法極低效。近期 LLM-based 優化器被提出以提升效率。本文研究如何把生成式優化更廣泛、系統性地應用於端到端優化一般計算工作流。

1.1 邁向計算工作流的高效端到端優化

受反向傳播（back-propagation）啟發，我們採端到端方法。AutoDiff 框架已把反向傳播擴展到數十億參數的可微分工作流；我們延伸 AutoDiff 的想法，設計新框架 Trace，聯合優化一般（可能不可微分）計算工作流中所有異質參數。Trace 把計算工作流視為像神經網路一樣的圖：節點是輸入、參數或計算步驟的結果，有向邊表示節點如何由其他節點產生。但 Trace 傳播的不是梯度，而是工作流的執行軌跡（記錄中間計算結果及其被使用的方式），透過最小子圖（minimal subgraph）概念（§3.3）。我們證明：傳播執行軌跡包含（subsume）可微分工作流的反向傳播，且對不可微分工作流依然適用。以圖看待工作流、用執行軌跡除錯是軟體工程的標準做法；我們的新洞見是：執行軌跡也能使端到端生成式優化成為可能，因為它提供了把豐富回饋關聯到一般工作流參數所需的資訊。

1.2 Trace 實戰範例（Battleship）

Trace 是 Python 函式庫，API 仿 PyTorch：使用者以 trainable 旗標宣告要優化的參數，用 node 與 bundle 包裝器裝飾工作流，然後執行 Trace 優化器——就像宣告與訓練神經網路一樣。以打造 Battleship（戰艦棋）遊戲 AI 代理為例：代理的 policy 有兩個組件（reason 與 act，皆為內容為空、僅有 docstring 的 Python 函數），串接以應對不同棋盤。環境提供文字形式的二元獎勵回饋。人類程式員會執行 policy、依觀察到的回饋改程式碼、嘗試不同啟發式、用 stack trace 修執行錯誤——Trace 自動完成這一切：使用者把 reason 與 act 宣告為 trainable，在 PyTorch 式訓練迴圈中執行代理；執行時 Trace 記錄一個 DAG 並用它計算執行軌跡供優化，還自動捕捉錯誤（語法/語義錯誤）作為回饋（TraceExecutionError）。程式碼中完全沒提 Battleship 環境 API、也沒說 reason/act 該如何行為——Trace 優化器透過互動與對輸出的回饋自行想通所有細節，代理快速學到越來越複雜的策略。

1.3 優化的新世界

Trace 的設計基於新的迭代優化數學框架 OPTO。我們論證：把工作流優化框成 OPTO 能比黑箱方法更快收斂，並給出建構性證明——設計通用高效的生成式優化器 OptoPrime：它把 OPTO 的每輪迭代轉為一個擬演算法（pseudo-algorithm）問題，將執行軌跡與輸出回饋格式化後呈給 LLM（GPT-4，ReAct-CoT prompt）求解。實驗中我們把同一個 OptoPrime 原封不動應用於 prompt 優化、一階數值優化、超參數調校、機器人控制器設計等迥異應用，皆與各領域專用優化器競爭——例如優化 DSPy 程式時在 BigBenchHard 上比 DSPy 手工設計的優化器高 10% 準確率。Trace、OPTO 與 OptoPrime 共同提供了第一個端到端優化一般計算工作流的可行演算法。我們推測「訓練深度代理網路（deep agent networks）」——流暢混合張量、LLM 與其他可程式化工具的計算——即將成為可能。
