4. 追蹤級診斷

終端指標（pass@1, 解決率）不足以診斷庫漂移：它們將任務難度、模型隨機性與庫品質混為單一數字。本文引入三個互補診斷訊號：

4.1 逐技能貢獻分數

對每個 active 技能 s ，追蹤：

ĉ(s) = (successes(s) − failures(s)) / trials(s) （式 2）

由證據日誌（s 被注入的 capsules）計算。庫均值 ĉ 下降即為漂移訊號。在 Default 條件下，均值 ĉ 隨輪次上升（有害技能被退休）；在 A4 條件下則震盪，因為過早退休移除有用技能。

4.2 歸因判決

對每個失敗 capsule，一個獨立的 Critic LLM 呼叫產生結構化判決：HELPED、HURT、NEUTRAL 或 INAPPLICABLE，外加模式標籤與信心分數。這些判決有雙重目的：(1) 合成基質（共享正則模式且 ≥3 個失敗的叢集觸發新技能）；(2) 早期預警診斷。HURT 判決比例上升是漂移的領先指標：在 A4 中，庫在第 30 輪即崩塌至 2 個 active 技能（Router 參與率降至 18.9%），而聚合 pass@1 僅緩慢下降——因為 Router 在多數任務上適應性地選擇 NONE。

4.3 Router 參與指標

追蹤 Router 分配技能 vs. NONE 的任務比例。健康條件維持 70–80% 參與率，而 A4（漂移中）因庫清空降至 19%。A2（僅檢索，無 LLM 閘）顯示 98% 參與率但品質較低；LLM 閘拒絕注入的能力本身就是一個防漂移機制。

5. 經驗證修復：Ratchet 配方

Ratchet 是一個單代理迴圈：frozen LLM 撰寫、檢索、策展並退休自己的自然語言技能。三個治理機制聯合防止庫漂移：

5.1 結果驅動退休

當技能累積 n(s) ≥ Nmin 次試驗後，若經驗貢獻 ĉ(s) ≤ −τ，即被退休。Default 使用 Nmin=100, τ=0.10——保守到足以讓有用技能在隨機噪聲中生存（Hoeffding ϵ ≈ 0.20），但積極到足以最終移除有害技能。這直接對應漂移的第一階段：「無品質訊號下的累積」。

5.2 有界 active-cap

硬上限 C（Default: 50）強制策展者在合成將超 cap 時淘汰最低貢獻技能。這直接對應漂移的第二階段「檢索退化」：通過限制庫大小，檢索精度不會隨無界增長而衰減。結合退休機制，提供了形式上的非發散保證：

Proposition 1：在 cap C 與退休閾值 τ 下，期望 eval pass@1 無法漂移低於無技能地板超過 τ + ε + Cδ，其中 ε 為 Hoeffding 估計容忍度、δ 為逐技能失敗機率。

無 C 與 τ 的系統（Wang et al., 2023; Zhao et al., 2024; Chen et al., 2024）沒有此界的有限類比：庫漂移不受約束。

5.3 Meta-skill 寫作先驗

一份 meta-skill 文件約束 Synthesizer 產生風格一致的技能。這從源頭對應「沉默注入傷害」階段：通過強制結構同質性，減少有害或冗餘技能的誕生，降低下游退休的負載。消融實驗 A3（無 meta-skill）顯示移除它導致損失 Default 中 43% 的增益；它是價值最高的單一組件。

令人意外地，給定 meta-skill 後，顯式去重機制（模式正則化， A5; cover-guard, A6）並非必要——A5 和 A6 略優於 Default。meta-skill 在此規模上涵蓋了顯式去重。這是任何涉及 LLM 編寫 artifacts 的系統的關鍵設計洞察。

6. 實驗

6.1 實驗協議

評估基準：MBPP+ hard-100。從 MBPP+ 測試分割的 378 任務（Liu et al., 2023）中，丟棄 Claude Opus 4.7 在全部 5 組基準種子上都解決的任務（∼273 個），從其餘中隨機取樣 100 個（60 train / 40 eval，固定種子）。這樣隔離了技能庫可能真正幫助的任務。

所有 LLM 呼叫使用 Claude Opus 4.7；embedding 使用 Cohere embed-v4（皆通過 Amazon Bedrock）。Solver 是單次直接 LLM 呼叫——無執行回饋、無自我修正、無工具使用——隔離技能庫的貢獻。每 run 100 輪；報告 3 組種子的 mean ± std。

6.2 主要結果

Default（全治理）將 pass@1 從 0.258 基準提升至 0.584 晚期窗口均值（峰值 0.658），在真正困難的任務上超過兩倍效能。A1 確立無技能地板（+0.002）；A4 確認漂移可將庫推至低於地板（−0.019）。

6.3 分解修復

八組消融實驗（A1–A8）各修改 Default 中的一個旋鈕，測試對應機制是否為 load-bearing。

A1–A3：哪些組件是必要的？ A1（無技能注入）Router 總是選 NONE：+0.002。A2（僅檢索路由）繞過 LLM 閘，直接注入最高排名的檢索命中：+0.077，僅 Default 增益的 24%——確認 LLM 閘貢獻超越 tf-idf ∪ embed 相似度。A3（無 meta-skill）移除寫作先驗：+0.187，僅 Default 增益的 57%——meta-skill 是最高價值組件（移除時損失 −0.141）。

A4：嚴苛退休是有害的。A4 將 Nmin 從 100 降至 20、τ 收緊至 0.0。結果 −0.019。在 Nmin=20 時，Hoeffding 偏差 ϵ ≈ 0.44；真實貢獻在 [−0.44, 0] 的技能可能因運氣不佳被退休，使庫崩塌至 2 個 active 技能。這驗證了 Prop. 1：退休閾值在沒有足夠大的證據地板時不足以防護。A4 的警示性教訓：治理並非均勻有益。

A5–A6：顯式去重並非必要。A5（無正則化）將 τ_canon 提高至 1.0 以禁用模式去重；A6（無 cover-guard）禁用重複叢集跳過。兩者均略優於 Default：A5 +0.374, A6 +0.363（vs. Default +0.328；在 n=3 下 ±2σ 範圍內）。meta-skill 的寫作指導強制了足夠的風格一致性，以至於顯式過濾器的偽陽性（false positives）捨棄的有用技能多於它阻止的重複——這是對任何 LLM 編寫 artifacts 系統的可遷移設計洞察。

A7–A8：放寬 cap 與 meta-skill 刷新。A7（bank cap=100）加倍 active-cap：+0.317 的均值可比較但方差顯著更高（±0.110 vs. ±0.018）；cap 主要控制方差而非均值。A8（meta-synth 刷新）每 10 輪重新生成 meta-skill：+0.372 且最高峰值（0.725），但壁鐘時間增加 55%（10.1 h vs. 6.5 h）。結論：更頻繁刷新對學習曲線無顯著改善但產生可觀計算開銷，在此規模並不合理。

6.4 運行成本

Default 每 100 輪使用 ∼14.5k LLM 呼叫（10k Solver + 4.3k Critic + 152 合成），比無技能基準（A1, 10k 呼叫）多 43%。壁鐘時間為 6.5 小時 vs. A1 的 2.3 小時（2.8×）。Solver 在所有條件中占據成本主導（總呼叫的 63–99%）。
