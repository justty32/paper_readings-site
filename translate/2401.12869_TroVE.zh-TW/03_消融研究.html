8. 消融研究

  • 對順序的穩健性（§8.1）：本方法以串流輸入、按資料集原始順序處理例子。從每任務各選一個代表資料集（MATH-algebra、HiTab、GQA），以不同隨機種子打亂五次再跑 TroVE：原始順序的結果全落在隨機排序的數值範圍內、標準差極小（如 GQA acc 0.43 vs 隨機 0.43–0.44、std 0.005），顯示 TroVE 對例子順序穩健。
  • 不修剪工具箱（§8.2）：加入修剪機制後函數庫大小顯著縮小 74–90%（圖 8）；不修剪時正確率與複雜度也輕微劣化（如 HiTab acc 0.15→0.18、GQA 0.39→0.44）。修剪門檻與時間間隔易於調整——可靈活留更多函數以探索多樣性，或因約束而留更少。

9. 相關工作

  • 生成程式解答：許多工作用 Python 程式解數學與表格 QA，但多以基本操作或庫（sum、pandas）建構，可能冗長易錯；VisProg 等以手工任務特定函數生成影像可執行程式並延伸到音訊／視訊，但仍需人類專家設計。本工作以 LM 歸納函數，兼得高階函數之利與人力之省。
  • 領域特定函數庫抽象：Shin et al. 挖掘常見程式碼慣用語；DreamCoder 以 wake-sleep 貝氏過程自底向上從大語料歸納函數；STITCH 自頂向下省記憶體；LILO 把 LLM 整合進 STITCH 並自動撰寫文件。這些方法都作用於領域特定邏輯形式，改用通用語言會使搜尋空間暴增，在許多真實任務上適用性受限；本方法直接生成通用 Python 程式，可輕易延伸到新任務。
  • 用 LLM 造程式工具：LATM 針對同質的 BigBench 任務（每任務單一工具）；CREATOR 處理數學與表格 QA 但造出大量不跨任務復用的工具（即本文 Instance 基線）；CRAFT 以額外訓練提高工具共享但仍產出冗餘工具；LEGO-Prover 為數學定理證明生長引理庫，但需定理證明器的外部監督與專家啟發式；Voyager 在 Minecraft 具身世界中構建與學習技能，但需自我驗證與迭代精煉。相比之下，本方法只憑執行一致性，無需任何訓練或監督（表 9：LATM／CRAFT／Voyager 需訓練或課程，LATM／CREATOR／CRAFT／Voyager 皆需自我驗證，唯 TroVE 只靠自我一致性）。

10. 結論

我們提出 TroVE，一個歸納可復用函數工具箱以解程式化任務的方法。TroVE 以顯著更小的函數庫產出比既有方法更簡單、更準確的解答，並使人工程式驗證快 31%、準 13%。TroVE 還能跨任務與資料集歸納多樣函數，為資料特性提供洞見。
