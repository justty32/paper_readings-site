1. 引言（Introduction）

現代 LLM 智能體（Yao et al. 2023; Schick et al. 2023）依賴技能庫（skill libraries）——預先撰寫的程序性文件集合，agent 在任務時檢索並遵循。OpenAPI 規範（OpenAPI Initiative 2024）等帶類型目錄已提供機器可讀的函數簽名，但當今 agent 技能更常見的部署表面是 markdown：Anthropic 的 SKILL.md、Graph-of-Skills（GoS）庫、以及伺服器端 MCP 描述均以自由散文（free-form prose）形式發布，供人類與 LLM 讀取。

散文是瓶頸。 作者論證並以實驗支持：散文表示本身——而非缺乏分解（factoring）——才是 LLM agent 消費 markdown 技能庫時的主導瓶頸。Markdown 技能文件不區分「技能產生什麼（output schema）」與「技能如何調用（環境接受的原語動作）」——兩者常與散文提示、警告、範例交錯排列。每次檢索時 agent 必須重新推導這兩者。經驗上這在 ALFWorld 中產生一個反覆出現的檢索-動作回饋迴圈（retrieval-action feedback loop）：agent 發出 SkillRequest → 讀回長 markdown 正文 → 發出語法稍偏差的動作（put X in/on Y 而非 move X to Y；先加熱杯子再拿杯子）→ 環境回傳「Nothing happens.」→ agent 重新檢索尋找缺失細節。同一迴圈既驅動任務失敗，也驅動 per-game LLM 調用成本。

帶類型偽代碼（typed pseudocode）是更好的表示。 兩段資訊可短路該迴圈：(1) 一個帶類型合約（typed contract），暴露技能的觸發器、輸入 schema、輸出 schema 與前置/後置條件，一眼告訴 agent「可以做什麼、必須提供什麼參數」——與 OpenAPI spec 給予 typed-routing agent 的可供性相同。(2) 具體動作模板（"go to {recep}"、"heat {obj} with {appliance}"），告訴 agent「如何實際調用底層環境」，以環境接受的精確 token 表達。兩者構成結構化偽代碼規範：帶類型簽名配對模板級具體語法。現有 markdown 技能庫同時包含這兩段資訊——但僅以散落散文形式存在；而現有 typed-routing 方法（RestGPT、ToolLLM、Gorilla）假設合約已由上游手動撰寫。

Skill-as-Pseudocode（SaP） 提出以確定性品質控制自動化散文→偽代碼的轉換。每個原始 markdown 技能（稱 parent skill）解析為程序單元序列。跨 parent 具有相似 verbs、objects、code linkage 的單元分組為候選群集。SaP (i) LLM 起草合約 κ，(ii) 四個確定性檢查覆蓋、綁定、替換與風險，(iii) 改寫為 invoke(κ, args) 佔位符。BE 與 RC 兩個 LLM 覺察後驗證通過具體化佔位符並移除殘留散文衝突。檢索時 agent 接收代換後 bundle：改寫後的 parent 骨架 + 內聯合約 + 恢復的動作模板——what 與 how 在單次回應中交付。

2. 相關工作（Related Work）

Typed routing 假設合約已存在。 RestGPT、ToolLLM、Gorilla、API-Bank 與更廣泛的工具增強 agent 範式、集成表面（Anthropic Skills、MCP、OpenAPI）以帶類型目錄為輸入，解決 agent 端的選擇與路由問題；SaP 為互補的生產者端——從散文 markdown 恢復帶類型合約。

技能庫維護與帶類型技能圖。 SkillOps（Song et al. 2026）將技能表示為帶類型合約，診斷庫健康（冗餘、相容性、缺失驗證器）以驅動 merge/repair/retire/add_adapter 操作；GraSP（Xia et al. 2026）將平面技能集編譯為帶類型 DAG。兩者皆在合約存在後操作。SaP 解決上游表示差距：將散文轉換為帶類型偽代碼合約加內聯動作模板——供應鏈的生產者端。SkillRet（Cho et al. 2026）為技能檢索 benchmark，非技能內容。

跨 parent 分解為次要收益。 合約在多 parent 中可調用者提升為獨立 child skill（分解真實發生，§5.1），但檢索池消融（§5.5）顯示 agent 收益來自 parent 端代換 bundle 非 child library：暴露 children 為獨立檢索結果使獎勵下降 27%。

庫壓縮 vs. 驗證後重構。 DreamCoder、Stitch、LAPS、LILO、Agent Workflow Memory 以 MDL/重用頻率從 λ-calculus 或散文提取可重用單元。SaP 不同：目標為帶類型偽代碼合約，且遞迴僅提出候選——可調用性為單獨的確定性檢查。軌跡成長庫（Voyager、Reflexion、BOSS、AutoManual、LATS、SkillWeaver）依賴成功執行，SaP 假設靜態庫。軟體重構（Fowler 1999）啟發框架，risk check 處理工具調用安全，GoS 為檢索 baseline。
