6. 相關工作

  • 語言到程式碼生成：歷經規則系統、結構化預測、深度學習，近期預訓練 code LM 表現亮眼；已有測試案例執行、跨樣本相似度、最大互資訊等樣本篩選法。本文提出可學習的驗證模組來判斷 LLM 輸出。
  • 結合執行的程式生成：弱監督法把程式當潛變數、用執行結果導出監督訊號；中間執行結果曾用於訓練/推論期導引程式搜尋；大規模取樣時執行結果的多數投票有效，Shi et al.(2022) 以「與其他樣本執行結果最大共識」推廣之。本文改為訓練驗證模型、把執行結果納入判斷。
  • 學習驗證：驗證器已在數學 QA、常識 QA 有效，但那些解多為自然語言。多數工作獨立於生成器訓練驗證器（Cobbe 2021、Li 2022b），Shen(2021) 則聯合微調。Kadavath(2022) 顯示大 LM 可少樣本自我驗證；CodeT(Chen 2022a) 等則用 LM 生成測試案例而非直接判正確性。LEVER 較接近 Li(2022b)——分開訓練、且用小得多的 LM（約生成器參數的 0.5%）；本文首度在語言到程式碼任務上做出「善用程式執行結果」的全面評估。
  • 判別式重排：長期用於摘要、機器翻譯、對話回應、程式生成等序列生成；LEVER 可視為一種判別式重排框架。

7. 局限

用執行資訊驗證程式，須依賴至少一組輸入（如函式引數）與足夠的執行脈絡（如資料庫），某些應用未必具備；也不能總假設模型生成的程式可安全執行。此外主要用 pass@1 為指標——對 text-to-SQL、數學推理這類「使用者只要答案」的應用很理想，但對一般程式任務（如 MBPP），pass@k 或 n@k 可能提供不同視角。

8. 結論

LEVER 是提升 code LLM 於語言到程式碼任務的簡單方法：學習獨立的驗證模型、把執行結果納入考量以判斷生成程式的正確性。可用約生成器 0.5% 大小的驗證器、以監督式基準資料訓練；且與其直接依驗證器輸出做拒絕取樣，不如混合生成與驗證機率做樣本重排。LEVER 在四個語言到程式碼任務上一致提升並全部達成新 SOTA；分析指出執行結果對驗證至關重要，且方法可跨不同 LLM 泛化。
