論文／訪談原始來源

SkillForge: Compositional Skill Synthesis with Verification-in-the-Loop for Generating Formally Verified Dafny Programs

摘要與問題

從自然語言生成可形式驗證的 Dafny 程式，不只要演算法正確，還要同時寫出足以讓 verifier 完成證明的 precondition、postcondition、loop invariant 與 termination measure。one-shot generation 沒有失敗後的處理；naive repair 把所有錯誤都丟回模型重寫，容易反覆震盪；一般 agent 則讓模型自行決定下一步，在錯誤類型有限且 oracle 明確的形式驗證場景裡，顯得不透明又浪費搜尋預算。

SkillForge 把任務拆成原子 skills，再由 deterministic harness 依 Dafny verifier 的結構化錯誤路由。核心判斷是：形式驗證的失敗空間可分類，下一步不必交給開放式 reasoning；只要把 error category 映射到專用 repair skill，就能保留可觀察性、限制迭代，且只有 verifier 通過的程式才會被回傳。

方法：skill library 與 verification-driven harness

每個 skill 由 prompt template、tool binding 與 decidable success criterion 構成。INFERSPEC 從自然語言抽出 types 與 contracts；SYNTHBODY 在固定 specification scaffold 下生成 body，不能靠弱化規格過關；GENINVARIANT 針對 entry、preservation 與 postcondition 三項義務產生 loop invariant；DIAGNOSEERROR 將 verifier failure 分成 invariant missing、spec gap、body error 或 type error；REPAIRCODE 只改診斷出的局部；STRENGTHENSPEC 逐條補入並驗證隱含 domain constraints。

初始候選由 INFERSPEC 與 SYNTHBODY 組合。若 verification 失敗，DIAGNOSEERROR 先輸出 category、location 與 suggestion，再由固定 mapping 選 repair skill。harness 保存當前程式、error set、diagnosis 與 history；若修改停滯就重新 synthesis，若錯誤數持續惡化則回滾最佳候選，達預算便停止。soundness 來自最後一道閘門：任何 skill 都可能犯錯，但 harness 絕不回傳未通過 Dafny verifier 的結果。

除了 self-verification，作者還用 Dafny lemmas 檢查生成程式與 reference implementation 的 precondition、postcondition 與 behavior equivalence，避免把「可驗證」誤當成「符合原題語意」。

實驗與主要結果（作者自報）

benchmark 由官方教材、DafnyBench 與開源驗證專案整理而來，分成 simple、medium、hard，並以同一主要 backend 與相近迭代預算比較 one-shot、一般 repair、ReAct／CodeAct 類 agent、tree search、closed-loop 與 RL-guided baselines。

作者自報，SkillForge 的 verification rate 為 91.6％，最強比較 baseline 為 85.4％，差距 6.2 個百分點。同時，成功案例平均只需 1.8 輪，first-pass rate 為 71.3％。結果顯示主要收益不是用更多探索換來，而是初始 specification anchoring 與錯誤條件式路由減少了無關修補。

skill ablation 指向兩個關鍵。移除 DIAGNOSEERROR、改為隨機路由後，作者自報整體 verification rate 下跌 11.8 個百分點，說明結構化診斷是相對 agentic baseline 的主要優勢。移除 GENINVARIANT 時，hard subset 下跌 22.2 個百分點，符合困難題主要卡在迴圈不變量的觀察。每個 skill 都有可量測貢獻，但 invariant synthesis 仍是最弱環節。

成本分析也支持 targeted repair。SkillForge 的 token、latency 與 verifier calls 都低於所列 iterative baselines；原因包括較高的 first-pass success、較少無效迭代，以及不需為每一步生成開放式 reasoning trace。不過這些成本都受特定 backend 與實作影響，應解讀為這組系統設定下的效率比較。

結論

當環境提供完美、可分類的 oracle feedback 時，SkillForge 主張用 deterministic harness 編排專門 skills，比讓通用 agent 自由選工具更合適。它的優點不是消除 LLM，而是把 LLM 放進範圍明確、成功條件可判定的模組，讓 verifier 決定何時通過、錯在哪裡、下一步該走哪條已知路徑。

局限

作者明列的限制是：benchmark 規模有限，且 skills 為 Dafny 特製，轉移到 Lean 或 Coq 需要重新實作；主要實驗集中在少數閉源模型，尚未檢查 open-source models。verification 與 reference equivalence 之間仍有落差，表示通過 verifier 不保證完全符合自然語言意圖。GENINVARIANT 的成功率最低，複雜 quantified loops 仍是主要 failure mode。skill templates 由人工編寫，尚未自動改善；各 agentic baseline 雖依公開方法改作 Dafny 版本，實作差異仍可能影響絕對分數。
