5. 結果

**錯誤－成本前沿。**圖 2 展示主要比較。在所有六種模型中，TFTS 佔據低成本、低錯誤的區域：平均 NumErr 為 0.7%、最差模型僅 2.0%，指令遵循錯誤維持在 3% 以下。單次呼叫 baseline 無法恢復此前沿。Structured Zero-Shot 經常選擇錯誤 metric 並做出無支持的數值宣稱；Structured Few-Shot 改善了 schema 和歸因行為，但聚合 SelErr 仍達 68.6%（見表 1），且數值錯誤在數個模型上仍高。這不應被讀作 prompting 的負面結果：prompting 有助於格式化和某些安全語言，但它無法可靠重現驅動洞察的重複性分析決策。

**層替換隔離失敗模式。**表 1 補充前沿資訊，定位當委託給 LLM 時哪些分析責任會失敗。Replace Comparison 將數值觀察與基線比較委託給 LLM 產物；聚合 NumErr 升至 16.9%。Replace Ranker 保持數值事實 grounded，但劣化了對選擇規則的遵循，聚合 SelErr 達 65.8%。Replace Attribution 保留了選擇與數值 grounding，但增加了歸因錯誤，聚合 AttrErr 達 24.5%。此模式比單一端到端分數更具資訊性：算術、排名策略和證據閘控歸因以不同方式失敗，而每一項都更容易用確定性程式碼驗證，而非用 prompted generation。

**代表性示例。**圖 3 展示了四種主要錯誤家族的標註示例。紅色高亮標記違反目標規則的 LLM 輸出的文段；綠色標註顯示評估器使用的確定性參考。SchemaErr 捕獲 parse/schema 失敗；NumErr 捕獲數值幻覺；SelErr 捕獲選擇策略不匹配；AttrErr 捕獲無支持歸因。這些示例本身不用作證據，它們讓表 1 中的確定性指標變得可理解。它們也展示了為何 schema 有效的輸出還不夠：回應可以正確 parse，同時仍使用無支持的數字、選擇錯誤的 metric、或新增缺乏高於閾值證據的歸因。

6. 討論與局限

本研究評估的是對確定性參考系統的保存（preservation），而非臨床最優性。SelErr 是與應用選擇規則的偏離，而非 ground-truth 健康重要性；AttrErr 是歸因策略遵循，而非生物因果性。有用性與感知個人化的人類評估是互補的未來工作。

對重複性結構化健康輸出而言，確定性程式碼應擁有穩定、可驗證的責任：記錄上的算術、選擇策略、證據閘控歸因、以及控制哪些事實可以進入文句的寫入器介面。LLM 在其優勢匹配任務的地方仍有用：將已驗證的事實轉化為自然、有同理心、受 schema 約束的語言。此框架補充了 RAG、工具使用與 LLM 管線最佳化：這些方法可以改善學習式呼叫或檢索更好的上下文，而我們的問題是哪些重複健康生成責任應被完全從 runtime prompting 中移除。另一個有前景的方向是建置時（build-time）的智能體 AI，LLM 智能體幫助人類在部署前建構與審計確定性健康洞察管線——這更接近管線編譯系統與穿戴式健康智能體案例研究，而非本文評估的 runtime prompting baseline。

分割原則最應直接轉移到具有結構化輸入、穩定分析規則、重複部署、與可驗證中間產物的領域。檢驗報告解釋、生命體徵監控摘要、用藥遵從教練、和慢性病報告通常共享此形狀。我們尚未在此處驗證這些領域，而需要開放式臨床推理、診斷或治療計畫的任務可能需要不同的分割方式。

7. 結論

結構化健康生成既需要可靠的分析計算，也需要自然的面向使用者的表達。在我們的睡眠健康案例研究中，單次呼叫 prompting 無法匹敵確定性分析管線加上有界寫入器，即使有 few-shot 示例。層替換展示原因：數值比較、排名策略、歸因閘控、與寫入器交接各別編碼了 LLM schema 有效產物經常無法保留的責任。TFTS 支持一條對具有重複性分析工作的結構化健康系統而言實用的設計規則：讓程式碼對穩定事實與策略「想得快（think fast）」，然後讓 LLM 在受驗證的邊界內「說得好（talk smart）」。

附錄 A：完整結果

見表 1 呈現的各條件逐模型完整結果，含 SchemaErr、SelErr、AttrErr、NumErr、Cost/night 與延遲。TFTS 在六種模型上 SchemaErr 均為 0.0%、NumErr 0.3–2.0%、SelErr 0.0%、AttrErr 0.0–2.5%。Structured Zero-Shot 在 SchemaErr 高達 32.5%、NumErr 高達 54.2%、SelErr 高達 95.0%。Structured Few-Shot 改善 SchemaErr 至全部 0.0%，但 SelErr 仍 63.2–71.1%。Replace Handoff 中最值得注意：即使上游全是確定性，NumErr 仍升至 1.5–8.1%、AttrErr 升至 7.8–16.8%。
