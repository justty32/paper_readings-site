摘要

大型語言模型（LLM）正越來越多地被用於從結構化記錄（如穿戴式時間序列、生物標誌物、生命體徵和照護管理日誌）生成健康文字。對於重複性健康產出，僅有流暢是不夠的：系統必須忠於來源數據、將解釋性宣稱建立在可得證據上、遵循既定策略、發出機器可讀的輸出，且運行成本須足夠低廉以支援重複使用。我們追問：在結構化健康生成中，哪些責任應該是確定性計算而非 runtime LLM prompting？我們引入 Think Fast, Talk Smart（TFTS），一條睡眠健康洞察管線，其中確定性程式碼執行重複性分析，之後才進行一次有界的 LLM 寫入器呼叫。在 280 個用戶夜晚與六個模型上，TFTS 比結構化 zero-shot 與 few-shot 單次呼叫 baseline 達成更低的數值錯誤、更低的指令遵循錯誤、與更低的端到端成本。層替換（layer replacement）揭示了合約特定的失敗模式：LLM 比較會提高數值錯誤、LLM 排名會劣化策略選擇、LLM 歸因會增加無支持的因果語言，而即使上游事實是確定性的，LLM 生成的寫入器介面也會重新引入錯誤。結果支持一條更廣泛的設計規則：讓程式碼擁有重複性分析，讓 LLM 在受有界的介面內表達已驗證的事實。

1. 引言

許多健康與醫療應用要求 LLM 將結構化記錄轉為面向使用者的文字：穿戴式裝置教練摘要、實驗室結果解釋、用藥指導、生命體徵監測和照護管理報告。這些應用的前景恰恰在於語言模型能使技術記錄變得可理解，而風險則在於流暢的健康文字必須保持對來源記錄的忠實（faithful）、對任務指示的一致（consistent）、以及明確指出每項宣稱由什麼證據支持。近期穿戴式與個人健康系統展示了 LLM 在此空間的潛力，它們也凸顯一個實務問題：在重複的健康生成任務中，哪些部份應該是學習式生成，哪些應該是驗證式計算？

Prompting 研究提供了多種改善模型推理的方法：chain-of-thought 引出中間推理步驟、反覆精煉以更多呼叫換取改善的輸出、程式輔助方法將計算外部化、檢索與工具使用系統在 runtime 擴增 LLM、以及 DSPy 等 prompt 程式化框架最佳化 LLM 管線。這些方法改善的是 LLM 呼叫內部或周圍發生的事。我們的工作追問一個不同的系統問題：**重複的健康任務何時應該在 LLM 呼叫之外實作？**對結構化健康工作負載而言，某些決策跨輸入幾乎不變地重複出現，例如將測量值與基線比較、選擇該凸顯什麼、以及決定哪些解釋性宣稱受到記錄證據的支持。當這些步驟穩定且可驗證時，runtime prompting 可能就是錯誤的分析工作抽象。

我們透過 Think Fast, Talk Smart（TFTS）來研究這個分割問題，這是一條睡眠健康洞察管線。睡眠健康是一個有用的案例研究，因為穿戴式記錄是縱向且異質的，而最終輸出必須簡短、有依據、且能被非專家讀者使用。TFTS 將穩定分析步驟實作為確定性層，並僅使用 LLM 作為一次有界的最終寫入器，透過緊湊的證據介面進行。我們將此設計與單次呼叫 baseline 進行比較，然後一次一個地將分析層替換為 LLM 生成的型別化產物。此層替換協議測試的是：模型在產生語法有效的 JSON 之外，是否保留了中間分析產物的預期語義。

我們的貢獻有三：首先，展示確定性分析層加上有界寫入器，在重複健康洞察生成任務上比強大的 prompting baseline 達成更低的錯誤與更低的成本；其次，引入層替換協議，以型別化的 LLM 生成中間產物隔離個別分析責任；第三，將寫入器介面識別為一個非顯而易見的失敗點。雖然我們的實驗使用睡眠健康數據，但分割原則指向更廣泛的結構化健康場景：輸入是機器可讀的、分析規則重複出現、且中間產物可以被檢查。

2. 任務與管線

圖 1 展示了四階段分割模式以及我們評估的睡眠健康實例。對每個用戶夜晚，系統攝取來自穿戴式裝置的睡眠、恢復、生理和行為信號，並返回一個受 schema 約束的洞察，包含標題、核心洞察、改善建議、所選 metric 的元數據、歸因標籤、以及圖表數據。確定性參考管線遵循經典的 data-to-text 分解：它格式化數據、計算數值比較、排名應凸顯哪個 metric、以證據閘控歸因、並將所選事實壓縮進一個確定性的 prompt 介面。最後一次 LLM 呼叫隨後在受有界的 schema 下產出面向使用者的文句，之後的確定性組裝正規化並包裝回應。

TFTS 將分析推理與語言表達解耦：確定性程式碼處理重複、可驗證的推理，LLM 則專注於為使用者措辭已驗證的事實。實驗追問的是：哪些重複性責任可以被安全地從確定性程式碼移到 LLM 生成的中間產物。

3. Baseline 與層替換

**單次呼叫 prompting baseline。**我們將 TFTS 與兩種單次呼叫替代方案進行比較。Structured Zero-Shot 接收原始數據、輸出 schema、以及以 prompt 形式給出的相同睡眠洞察生成規則；它必須在單次呼叫中分析、選擇、歸因與寫入，無示範。Structured Few-Shot 以結構化 metric 表、few-shot 示例、明確選擇規則與數值 grounding 指令來強化此 baseline。

**層替換協議。**為進行機制分析，我們精確地將一層分析層替換為 LLM 生成的型別化產物。所有上游參考層保持確定性；生成的產物取代目標層的參考輸出。此協議比從最終寫入器 prompt 中移除某層更嚴格且更公平：模型被要求執行一個有界的中間任務，而非在寫最終 JSON 的同時補救遺失的上下文。主要的替換條件為：Replace Comparison、Replace Ranker、Replace Attribution、與 Replace Handoff。

**數據與模型。**實驗使用來自 20 位活躍用戶的 280 個用戶夜晚。我們評估六種模型：GPT-5 nano、GPT-4o mini、GPT-OSS-20B、GPT-OSS-120B、Haiku 4.5 與 Sonnet 4.6。替換條件每夜晚使用兩次 LLM 呼叫（一次產出中間產物呼叫＋一次最終寫入器呼叫）；TFTS 與 prompting baseline 各使用一次呼叫。因此我們報告的是每則洞察的端到端成本與延遲。

4. 評估

所有指標皆從儲存的每夜晚 JSON trace 確定性計算。SchemaErr 是最終 JSON parse/schema 錯誤率。NumErr 是所提取的數值宣稱中不受來源事實庫支持或與之不一致的比例；未提取任何數值宣稱的輸出從 NumErr 分母中排除，故各條件分母可能不同。SelErr 是所選 metric 違反同時給定給確定性排名器與 LLM prompt 的選擇規則的輸出比例。AttrErr 是做出不受證據閘控輸入支持的歸因的輸出比例。

寫入器介面至關重要。Replace Handoff 測試了一個更細微的邊界。上游計算、排名與歸因皆保持確定性，然而將緊湊的證據-to-寫入器交接（handoff）替換為 LLM 生成，仍使聚合 NumErr 升至 4.8%、AttrErr 升至 10.7%。這暗示已驗證事實與文句之間的介面本身就是可靠性機制的一部份，而不僅僅是 prompt 格式。最終寫入器可以是有用的，但約束它可說什麼的證據封包應當保持確定性。
