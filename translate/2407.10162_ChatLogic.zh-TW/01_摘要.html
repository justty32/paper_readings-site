摘要

ChatGPT、GPT-4 等 LLM 在各種生成任務上展現亮眼能力，但其表現常受長期記憶存取與利用的限制所妨礙，導致特定弱點與偏差（尤其長互動時）。本文提出 ChatLogic——專為 LLM 推理任務設計的創新框架，透過整合邏輯程式設計增強 LLM 在多步演繹推理上的表現。在 ChatLogic 中，語言模型扮演核心控制器、參與系統每個運作階段。我們提出把邏輯問題轉成與推理引擎的符號整合的新方法，利用 LLM 的情境理解與模仿能力、並用符號記憶增強多步演繹推理。結果顯示 ChatLogic 顯著提升 LLM 的多步推理能力。（程式與資料：github.com/Strong-AI-Lab/ChatLogic）

關鍵詞：演繹推理、多步推理、大型語言模型。

I. 引言

LLM（ChatGPT-3.5、GPT-4、Llama2）大幅增強各產業能力，但在多步邏輯推理上面臨顯著挑戰：擅長內容生成，卻在需多步推理時難產出連貫回應——其 next-token 預測訓練法限制了套用邏輯規則與深度情境理解的能力（圖 1：在打亂的命題序列中找合理解釋路徑判斷對錯）。此外 token 上限在連續對話中尤其受限（多步邏輯推理常是多輪對話）。

外部記憶增強（整合大型資料庫）是一途，但會把檢索模型的偏差嵌進 LLM、影響準確與穩定。

本文提出 ChatLogic：用邏輯推理引擎增強 LLM 的推理能力，並創新實作 Mix-shot Chain of Thought（結合多種 prompt 工程法，以最少資源高效引導 LLM 走邏輯推理步驟）。ChatLogic 相容既有 LLM、在高精度場景顯著提升準確度。核心是用 pyDatalog 把自然語言轉成邏輯符號，強化推理過程的穩定性。特色：

  • 結合 LLM 與 pyDatalog，把 NL 查詢翻成邏輯程式提升推理準確（在 PARARULE-Plus、CONCEPTRULES V1/V2 上明顯）;
  • 緩解資訊遺失，解決多步推理採用 LLM 時的長序列限制;
  • 含語法修正模組等自動化增強（從先前執行中學習精煉邏輯程式）。

II. 相關工作

  • II-A LLM 推理：自我一致性（self-consistency）、因果推理路徑、最具影響力的 CoT（揭示中間推理步、可持續自我修正）——但都或多或少暴露「從長且無序資訊中抽有效內容」的弱點。
  • II-B LLM 程式生成：LLM 能生多種語言程式，但直接部署到實際環境仍未解。SELF-DEBUGGING 賦予 LLM 除錯能力；Logic-LM 造確定性符號 solver。本文要改進的是：LLM 雖可能因預訓練缺 pyDatalog 知識而「幻想」偏離現實，但仍能靠「模仿」產高精度輸出。終極目標：生成可直接本機部署、在裝有基本 Python 環境的使用者電腦上得推理結果的程式。
  • II-C LLM prompt 工程：few-shot（少標註資料）、zero-shot prompt（全靠模型內在知識，無需下游微調）、zero-shot CoT（「Let's think step by step」+ 兩階段答案抽取，目前最佳推理 prompt 之一）。ChatLogic 為框架不同環節造獨立 prompt 模板、獨立呼叫。

III. 任務定義

LLM 善於把文字轉成數學式、程式語言等形式結構，但多步推理時隨推理深度增加常漏關鍵步。主要目標：提升 LLM 用邏輯程式語言（特別是 pyDatalog，整合邏輯程式範式的 Python 庫）表示問題的能力。

多步演繹推理問題＝Fact（主謂賓陳述句，謂詞有否定，如「Bob is poor」）+ Rule（含條件判斷的陳述句，如「若某人窮則他壞」）+ Query（同格式陳述句）。兩子任務：

  • III-A 增強 LLM 推理能力：利用 LLM 的 one-shot 泛化與 zero-shot 思考；用涵蓋所有潛在邊界情況的精製範例讓模型熟悉 pyDatalog；高精度生成的 code 由本機編譯器執行得準確多步推理結果。
  • III-B 放大自動程式生成的可執行性：LLM 文字轉 code 首次常不完美、含錯；設專屬模組確保 NL 與翻譯碼高精度對齊、本機易執行直接產出結果。

IV. ChatLogic

IV-A 框架概覽

四階段（圖 2）：輸入處理、語意修正（SE）、語法修正（SYN）、本機執行回應。LLM 生的初版邏輯碼經兩模組兩次以上迭代修正後，可執行性顯著提升、結果更精確。除本機執行部分外，所有子任務皆由 LLM 當組件控制驅動。

演算法 1（ChatLogic）：

  • 輸入：U（依封閉世界假設補充的規則）、X（命題組＝Fact+Rule）、Y（問題）；輸出：TRUE/FALSE。
  • 語意修正迴圈（line 3–8）：Code←PropositionTransformation(X)（依 CWA 生邏輯程式）→ RevProposition←ReverseTransformation(Code,U)（把 code 反翻回自然語言）→ TextComparison(X, RevProposition) → 用 zero-shot CoT 兩步判語意相似狀態、更新 DifferentFlag。LLM 擅長語意修正，少量修改即可達正確翻譯。
  • 語法修正迴圈（line 11–16）：Code←CodeImprovement(Code, ExecutionError)（依錯誤訊息改）；但語法修正不可靠、可能陷無限迴圈，故設執行時間上限終止（略降推理力但大增穩健）。
  • return CodeExecution(Code)（本機執行 pyDatalog 得結果）。

IV-B Mix-shot CoT

混合 zero-shot CoT（用 LLM 生成力與鏈式思考，無需訓練/微調）與 one-shot learning（手寫一個任務完成範例引導 LLM 模仿達高精度）。核心：利用 LLM 自主識別子任務的能力——

  • 需高精度處（NL 問題→邏輯碼）用策略性選擇的高品質範例（one-shot 精度）;
  • 需大量分析處（如生成命題與原命題的相似度比對）給 LLM 更大自主權發揮分析力。
  • 用 zero-shot CoT 的兩步呼叫：第二次呼叫時從第一步抽有效關鍵資訊當狀態標籤引導框架運作。

對比（Table I）：one-shot（幻覺最少但表現差、不同任務需不同範例）、zero-shot CoT（幻覺高、準確相對高、無需範例只需簡單引導）、Mix-shot CoT（幻覺較少、任務準確最高、需較少範例且優於 few-shot）。在精度與適應性至上的真實應用中務實有效。

V. 評估

V-A 資料集與指標

  • PARARULE-Plus：~40 萬樣本、全 CWA、兩情境（People/Animal）；各深度（2–5）從兩類各隨機選 50、合 100 測例。
  • CONCEPTRULES V1/V2：需多步推理、深度至 3，有 simplified/full 版；把 train/test/dev 併池後隨機抽 100。
  • 模型：ChatGPT（gpt-3.5-turbo）、GPT-4、Llama 2-7B（RTX 3090 24GB）;temperature=0。

V-C 中間過程

圖 3：ChatGPT 直接推理（即使加 CoT）常含多處邏輯不一致；ChatLogic（同由 ChatGPT 驅動）多數情況準確生 pyDatalog 碼、本機執行得精確結果。

  • meta 屬性補全：實驗發現 CWA 資料集下 LLM 無法依 CWA 補全缺失資訊 → 推理效率大降。多步演繹鏈起點須是物件本有的屬性（meta 屬性，非推理得來），但 CWA 資料集缺此 → 用 NER 腳本抽主語與屬性歸屬、以人工合成自然語言格式補進命題（即演算法 1/圖 2 的 U）。例：Rules 中無句可推出某人有「big」屬性 → 此屬性須在角色屬性定義中出現，若 Facts 沒有則預設其無、需手動加進 Facts。CONCEPTRULES V1/V2 不需此補全。
