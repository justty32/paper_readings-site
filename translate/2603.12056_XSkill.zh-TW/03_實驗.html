3. 實驗

3.1 實驗設定

資料集：五個 benchmark 三領域。(1) 視覺代理工具使用：VisualToolBench（單輪混合工具推理任務）、TIR-Bench（過濾至五類相容任務：refcoco、maze、instrument、ocr、contrast）；(2) 多模態搜尋：MMSearch-Plus、MMBrowseComp（130 樣本，純測試用於 OOD 評估）；(3) 全方位：AgentVista。每 benchmark 隨機抽 100 題訓練、其餘測試。

基線：AWM（Agent Workflow Memory，從成功軌跡提取可重用工作流、k = 1 最相似）、Dynamic CheatSheet（演化式筆記本記憶、每次查詢動態更新、不篩選成功狀態）、Agent-KB（四組件結構化知識庫、TF-IDF + 語意混合檢索 k = 3、查詢推理優化）。

工具集：程式碼解釋器（持久 Jupyter 核心、PIL/OpenCV/NumPy/Matplotlib/SciPy/Scikit-learn/Pandas/SymPy）、網頁搜尋、影像搜尋（文字/反向）、網頁瀏覽。

Backbone：Gemini-2.5-Pro、Gemini-3-Flash（使用自身軌跡累積知識）、GPT-5-mini、o4-mini（直接使用 Gemini-3-Flash 累積的知識以檢查跨模型可轉移性）。Qwen3-VL-235B 與 Qwen3-VL-32B 用於開源模型分析（附錄）。嵌入模型為 text-embedding-3-small，推論溫度 T = 0.6、top-p = 1.0、最大回合數 = 20。

指標：Average@4（4 次 rollout 平均成功率，反映可靠性）、Pass@4（至少一次成功的任務比例，反映上限能力）。

3.2 主要結果

XSkill 在所有 benchmark 與模型組合上一致優於純工具基線與學習型基線：

  • Gemini-2.5-Pro：Average@4 提升 2.58–6.71 分
  • Gemini-3-Flash：Average@4 提升最多，TIR-Bench 上從 36.62%（Agent-KB）提升至 47.75%（+11.13 分）
  • GPT-5-mini 與 o4-mini（使用轉移知識）：Average@4 提升 2.58–4.16 分，顯示外部化知識結構跨不同模型架構仍有效

3.3 消融研究（VisualToolBench, Gemini-2.5-Pro）

  • 移除經驗流：-3.04 分（Average@4）
  • 移除技能流：-3.85 分
  • 移除 Phase 1 的經驗管理器：-4.09 分
  • 移除 Phase 1 的技能管理器：-3.62 分
  • 移除 Phase 2 的任務分解：-1.28 分
  • 移除 Phase 2 的任務適配：-1.52 分

階段一貢獻大於階段二——累積知識的品質比檢索機制更關鍵，但兩個階段皆為最佳效能所必需。

技能減輕低效工具使用：Experience Only → Skill Only 轉換使總錯誤數從 168（29.9%）降至 95（15.3%）；語法錯誤從 114（20.3%）降至 71（11.4%）；工具名稱錯誤接近清零（16→2）。技能通過提供清晰的工具模板與工作流指令，防止agent 浪費推理步驟在錯誤恢復上。

經驗實現靈活編排：經驗顯著改變工具使用分佈——VisualToolBench 上程式碼使用從 66.63% → 76.97%（全管線）；MMSearch-Plus 上程式碼從 6.18% → 14.37%、影像搜尋從 15.43% → 23.89%。經驗捕捉戰術知識：視覺推理任務偏向程式碼處理，多模態搜尋任務優先使用專用視覺工具而非通用文字搜尋。

3.4 分析

Rollout 數量影響：N ∈ {1, 2, 3, 4} 時 Average@4 與 Pass@4 持續改善——更多 rollout 提供更豐富的軌跡多樣性，使跨軌跡對比批判能提取更高品質的經驗、並從多樣執行路徑中歸納更可泛化的技能。

跨任務可轉移性：VisualToolBench 知識 → TIR-Bench 測試、MMSearch-Plus 知識 → MMBrowseComp 測試。XSkill 一致優於所有基線（平均較 Agent-KB 高出 2–3 分）。原因：階層式固化移除案例特定細節而保留廣泛適用洞察，任務適配過程使經驗與技能貼合當前任務脈絡。

開源模型（附錄 A）：Qwen3-VL-235B 與 Qwen3-VL-32B 使用 Gemini-3-Flash 累積的知識。MMSearch-Plus 上有正向增益，但 VisualToolBench 上 Average@4 低於工具基線——外部累積知識可能干擾較弱模型的原始工具使用行為。然而 XSkill 大幅增加探索行為（工具呼叫次數），使 Pass@4 在 Average@4 退化的情況下仍上升，說明即使單次平均品質較低，增加的探索仍提供更多達成正確答案的機會。

4. 相關工作

4.1 多模態代理推理

MLLM 的演進已將範式從靜態視覺理解轉向主動「以影像思考」。現代代理利用多元工具集操作與分析視覺資料：主動縮放或調整影像屬性以澄清細節、合成可執行程式碼進行精確視覺轉換、基於視覺線索編排網頁搜尋。然而多數既有框架本質上無狀態——以孤立回合運作，阻止跨任務內化成功工具使用模式或矯正性回饋。強化學習等參數化方法雖被提出以內化此類策略，但面臨領域特定訓練的高成本與適應演變中工具集的難度等可擴展性瓶頸。因此亟需非參數化機制，使代理能持續且靈活地累積推理能力。

4.2 從經驗與技能中學習

賦予代理從過去互動中學習的能力已成為替代持續參數微調的引人注目方案。早期方法通過檢索原始執行軌跡來輔助決策，近期研究轉向將原始軌跡抽象為可重用知識，典型表現為兩種互補形式：(1) 經驗捕捉針對特定脈絡的戰術條件－行動洞察；(2) 技能編碼高層次程序性工作流與可重用模板。此外，EvolveR 與 ReasoningBank 等框架引入閉環演化生命週期以精煉並固化此類知識。儘管這些在文本領域取得成功，多模態設定中的經驗學習仍顯著不足——既有嘗試多侷限於 GUI 導航或空間推理等專業任務，且在檢索時主要依賴原始文字指令、缺乏接地於視覺脈絡的「先規劃再檢索」機制，也不會將檢索到的經驗或工具模板適配至當前多模態脈絡。XSkill 通過統一框架解決這些限制。

5. 結論

本研究處理了多模態代理中的一個根本限制：缺乏有效機制以利用過去互動中的知識。既有方法依賴靜態文件或純文本提取，而我們證明多模態設定中有效的知識累積需要同時將任務級與動作級知識接地於視覺觀察。為此我們提出 XSkill，一個通過視覺接地提取與階層式固化統合任務級技能與動作級經驗的框架。視覺接地檢索與適配進一步在推論時橋接累積知識與任務特定需求。跨多元 benchmark 與 backbone 模型的廣泛實證驗證確立了 XSkill 的有效性，消融研究揭示兩個知識流提供相異但互補的優勢：技能確保工具執行的穩健性，而經驗基於任務特定脈絡引導策略性選擇。此外，框架強大的零樣本可轉移性表明其捕捉了可泛化的推理原則而非簡單啟發式。雖然當前評估展示了單一累積後測試週期，但框架架構與在新任務遭遇時進行迭代精煉相容。通過使多模態代理能在無需參數重訓練的條件下累積與利用知識，XSkill 為實際環境中演化自主系統提供了一條實用且可擴展的路徑。

影響聲明

本研究提出 XSkill，一個使多模態代理能在無參數更新條件下累積並利用任務級技能與動作級經驗以實現持續改進的框架。通過將知識外化為結構化、人類可讀的表徵，XSkill 改進了代理決策的透明度與可解釋性，而技能與經驗的明確分離使人工操作員能夠審計、編輯或移除特定累積知識片段。然而，更強大的代理可能被濫用於涉及敏感視覺資料的惡意自動化，或可能透過累積閉環繼承並放大先前軌跡中存在的偏見。實驗中展示的跨模型可轉移性進一步暗示：一個模型累積的偏見知識可能在無額外防護措施下傳播至其他模型。為緩解這些擔憂，我們建議對累積知識庫進行人工監督審查、對技能文件與經驗庫進行定期偏見審計、以及治理跨模型知識轉移的存取控制政策。
