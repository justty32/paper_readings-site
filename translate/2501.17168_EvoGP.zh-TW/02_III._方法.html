III. 方法

III-A 張量化資料結構

為達群級 GPU 並行，需可 coalesced 記憶體存取與統一張量形狀。採線性前綴編碼把樹攤平成節點序列：一般前綴序列不足以還原任意樹（每節點子數可變），但 TGP 中每節點子數由其類型與值完全決定（常數／變數無子、一元函數一子、二元函數二子），故前綴的「類型 + 值」即可無歧義編碼拓撲與值。先用兩陣列：node_type（第 i 節點類型）、node_value（第 i 節點值），長度＝節點數。

但此表示不存顯式結構，子樹交叉／變異須反覆解析前綴定子樹邊界，複雜度 O(n)，GPU 上低效。故再加一陣列 subtree_size（第 i 節點為根的子樹大小），子樹邊界可 O(1) 直接定位，省去結構解析、大幅提升 GPU 遺傳操作效率。

為解決變長難批次：引入超參 最大允許節點數，把三陣列各以 NaN padding 補成定長（真實資料佔前段、其餘填 NaN），使所有樹共用一致張量形狀、利 GPU 批次。最後把族群（共 P 棵樹）沿族群維串接成三個批次張量 node_types、node_values、subtree_sizes。如此遺傳算子與 fitness 評估皆可有效用 GPU 並行（圖 2）。

III-B 張量化操作

此編碼不只利批次評估，也提供統一結構表示利高效 GPU 遺傳操作；EvoGP 全程在裝置上做交叉／變異。關鍵觀察：許多常用算子（單點交叉、子樹變異、hoist 變異）共用一個結構基元——把某節點處的子樹換成另一子樹，故抽象成子樹交換（subtree exchange）：SubtreeExchange(原樹, 目標子樹根, 替換子樹)。在張量編碼下用張量拼接重組三陣列；新樹的 subtree_size 由「對目標節點所有祖先的子樹大小加上 Δ」算得。若新樹超過最大尺寸約束，操作判無效、直接返回原樹（靠顯式 subtree_size 陣列使此檢查高效）。

藉子樹交換可實作幾乎所有 TGP 算子：單點交叉＝把一父的隨機子樹換成另一父的隨機子樹；子樹變異＝把隨機子樹換成新生成子樹（圖 3）。一旦子樹交換成為 GPU primitive，新算子只需改「如何選／造子樹」、核心張量操作不變、不必改 GPU kernel——兼得高效能與廣擴展性。

III-C fitness 評估的自適應並行

符號迴歸是 TGP 核心應用：每個體 fitness ＝其預測與所有資料點目標值比較。為各種資料量都高 GPU 利用率，EvoGP 在執行期動態選執行模式：

  • 資料量小至中：單個體評估不足以填滿 GPU → 採混合並行，單次 kernel 啟動內結合資料級與群級並行。配置二維 CUDA grid（形如 族群 × 資料分段）；多個 block 評估同一個體、各算一段資料的部分 fitness，再用硬體原子操作彙總。即使資料量小，個體間並行也補上每個體工作量不足；單 kernel 啟動省 overhead（圖 4 右上）。
  • 資料量大：單個體在大量資料點上已能飽和所有 CUDA 核心，加群級並行幾無增益 → 切純資料級並行，每個體獨立 kernel 啟動，啟動前把該樹載入常數記憶體（執行期不可變、跨執行緒廣播存取快），較混合模式從較慢全域記憶體讀樹，大幅提升記憶體吞吐與大規模 runtime（圖 4 右下）。
  • 執行期自動切換（Choose Parallelism Adaptively）：以資料點數 vs GPU 總 CUDA 核心數（由 SM 數 × 每 SM 核心數估計）為閾值決定，無需手動配置。

不論用哪種並行，單個體輸出計算皆走後綴（逆波蘭）堆疊式求值：樹雖以前綴格式存，但反向（從尾到頭）走訪即模擬後綴遍歷；每步由節點類型推 arity、對堆疊上的值施對應運算。此模式天生相容前綴編碼、特別適合 GPU 高效實作。

IV. 實作

IV-A EvoGP 總覽

以 Python + PyTorch 實作（張量操作與 GPU 資源管理）。為效能，內含一套自製 CUDA kernel（樹初始化、變異、交叉、推論、SR fitness 評估），並依資料量採資料級／混合並行；這些 kernel 以 PyTorch 自訂算子整合，無縫相容 PyTorch 生態。採全 GPU 常駐模型：族群與評估上下文皆留 GPU，免主機↔裝置頻繁搬運（zero-copy 設計），契合 GPU 加速的 RL 環境，達端到端高效並行模擬、消除 IO 瓶頸。內建支援符號迴歸、策略優化、分類三類應用與標準化基準（圖 5：Algorithm 模組＋Problem 模組）。

IV-B 豐富功能與客製

除基本 GPU 加速操作，提供多種演化算子變體（選擇、變異、交叉），可自由組合配置成客製 TGP 演算法（表 I 比較各主流庫的算子變體，EvoGP 支援最全面）。並提供直觀介面定義自訂算子與問題；用戶可用低階 CUDA 實作自家最佳化算子；模組化設計利套用至自有問題域。

IV-C 多輸出支援

擴充傳統 TGP 支援多輸出（如 RL 策略優化）。用 Modi 節點（圖 6）：① 每個 Modi 節點指定其值貢獻到哪個輸出，同一輸出的多個 Modi 貢獻依預定規則（此處為求和）彙總；② Modi 節點若有父節點，不向上傳遞自身計算值，而直接採其最右子節點的值——此機制使樹結構實際變成 DAG，可同時計算多個輸出。使 EvoGP 適配 RL 等需多個相關輸出的任務。
