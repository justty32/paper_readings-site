ERSkill: Evolving for Skill-Guided Adaptive Memory Retrieval

摘要與第 1 節：問題

LLM agent 愈來愈依賴長期記憶維持跨會話互動，但既有工作多把「記憶內容如何建構／更新」當演化對象，「查詢時怎麼檢索」卻仍是固定策略。不同查詢的資訊需求質性不同——單純找一個事件 vs 串連因果關係——固定檢索策略無法兼顧。作者提出核心問題：agent 能否演化並學會組合複雜檢索動作，讓檢索行為適應查詢的異質資訊需求?

第 2 節：方法概覽

ERSkill 分三步：先把互動歷史編譯成結構化記憶儲存；再把檢索行為表示成一組可執行 skill，每個 skill 是固定 primitive 庫的組合序列；最後用訓練好的 router 依查詢挑最合適的 skill，執行後把 primitive 逐步更新的證據狀態送去生成答案。訓練期間 skill 集合與 router 共同演化。

第 2.2–2.3 節：記憶儲存與推論

互動歷史 D 切成 atom-level 記錄集合，搭配索引集合（供不同角度存取，如 embedding 索引、entity 索引）與圖集合（供 atom 擴展，如相似性邊）。retrieval primitive 是狀態轉移函式 p:(q,s,M(D))→s′，初始定義 entity_search、lexical_search（BM25 式）、dense_search 三個檢索 primitive，加上 temporal_focus_expand、similarity_expand、relation_expand 三個擴展 primitive，以及處理查詢重寫與證據過濾的 llm_process。primitive 庫在演化過程中固定不變，skill 只在組合方式上有差異，因此不同 skill 的結果可以累積進共用的經驗結構。

一個 skill κ=(c_κ,ρ_κ) 包含描述與資訊偏好 c_κ、primitive 序列 ρ_κ，依序執行後回傳最終證據視圖。router 把 query 與每個 skill 用共用編碼器映射到向量，經可學評分函式 u_θ(q,κ) 打分，再 softmax 正規化成 skill 上的機率分布；推論時選機率最高的 skill 執行，執行結果連同 query 送 LLM 生成答案。

第 2.4 節：skill-router 共演化

演化用兩條 Pareto 式前沿：capability frontier 保留具有 oracle 側獨特價值的 skill（不受 router 誤判影響、理論上能達到的最佳效用）;deploy frontier 是 router 實際會選中且經路由驗證通過的部署集，只暴露穩定的 skill 給線上使用。演化從三個單一 primitive 的種子 skill（semantic-clue、entity-focus、surface-fact）開始，兩條前沿初始相同。

每個演化步驟，ERSkill 在 capability frontier 上的所有 skill 對訓練批次逐一執行，把查詢-skill 表現、執行痕跡與能力重疊記入 experience trie——skill 是 primitive 庫上的序列，共享前綴只存一次，可偵測重複候選，也讓生成器讀取歷史 rollout 統計、避免重複探索等價程式。候選 skill 生成後，先用訓練批次算出臨時前沿並篩掉未保留的候選，通過的候選再拿驗證資料算正式的 capability frontier 更新——這種兩段式更新（訓練批次過濾、驗證資料定案）兼顧效率與穩定性。router 用 rollout 分數誘導出的軟標籤分布做交叉熵訓練。deploy frontier 只在 capability frontier 變動時才重算候選，並要求路由後效能提升超過門檻 γ_route，或效能小幅下降但集合更精簡（容忍度 ξ_drop）才接受更新；作者證明兩條前沿在驗證集上的 oracle coverage 皆單調不減（Proposition 2.1，證明見附錄 C）。

第 3 節：實驗

在 LoCoMo、LongMemEval、PerLTQA 三個 agent 記憶 benchmark，對比非演化基線（A-Mem、MemoryOS、LightMem）與自演化基線（Dynamic Cheatsheet、ReasoningBank、GEPA、MemSkill），用 Qwen3-Next-80B-A3B-Instruct 與 GPT-5.4-nano 兩個骨幹、GPT-4o-mini 當判官，報 F1、BLEU-1、LLM-judge 三指標。ERSkill 在兩個骨幹上皆取得最佳整體平均，對最強基線分別提升 31.3% 與 28.1%（作者自報）。在 LoCoMo 訓練的 skill 與 router 直接搬到 LongMemEval（無額外訓練）仍領先，顯示學到的是可遷移的檢索行為。成本面，ERSkill 是 LLM-based 記憶建構方法中最省 token 的（因為 LLM 只用於 atom 間關係抽取），推論成本也落在低成本區間但分數最高。消融顯示拿掉 skill 演化或 router 掉分最多；拿掉雙前沿或 experience trie 也都劣於完整版，前者穩定 skill 接受過程，後者靠歷史路徑經驗減少重複探索。批次大小 20 在穩定性與更新頻率間取得較好平衡。五次獨立重跑的變異係數（CV）全部低於 5.4%（作者自報），顯示演化過程本身穩定。

第 5 節與附錄 F：結論與局限

ERSkill 把記憶檢索本身變成可演化物件，用共用 primitive 庫、experience trie、雙前沿機制達成有效且可部署的演化。作者列出三點局限：skill 演化仰賴 rollout 評估與 LLM-as-a-Judge 監督，訓練期成本較高（即使最終部署輕量）;primitive 庫固定，雖穩定搜尋空間但也限制了可表達的檢索行為範圍，原則上可擴展成 primitive 也能被提議與驗證；實驗聚焦長期記憶問答，尚未涵蓋規劃、工具使用、個人化等更廣的互動情境。
