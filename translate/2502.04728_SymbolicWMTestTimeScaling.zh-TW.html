Generating Symbolic World Models via Test-time Scaling of Large Language Models

摘要與第 1 節：問題

複雜規劃任務要求 LLM 顯式建模狀態轉移，才能避免違反規則、逼近最優解，但自然語言本身有歧義。連 o1 這類擅長推理的模型，在 Barman、Termes 這種約束多、需要操作空間關係的任務上依然吃力，加自我批評、多次重採樣也一樣：論文附圖示範 o1 規劃 Termes 時把不相鄰格子誤判成相鄰、誤以為已達成目標，連 o1 自己檢查這個計畫都判定為正確——是幻覺而非規劃。

作者的解法是把自然語言世界描述翻譯成 PDDL(Planning Domain Definition Language)，用一階邏輯顯式描述狀態與關係，讓 A* 這類經典搜尋演算法可以派上用場。但直接叫 LLM 生成 PDDL domain 品質很差，原因有二：訓練資料稀缺，以及要在整份 domain 裡維持謂詞與動作間的邏輯一致性本身就難。既有做法多靠人類專家逐一修正，或蒐集大量微調資料，都難以規模化。作者提出不需額外訓練、靠拉大 test-time 運算量提升 LLM 的 PDDL 推理能力。

第 3 節：方法

3.1 PDDL 當世界表示：光判斷一個規劃問題「有沒有解」就是 NP-hard。PDDL 借用 STRIPS 邏輯系統表達 atom 與 predicate，語法形式化、無歧義，動作與狀態可被精確驗證，轉成 PDDL 後規劃變成經典顯式搜尋問題，可用 A* 配合規劃圖求解。

3.2 Best-of-N 取樣做初始化：方法採 coarse-to-fine 兩階段，先粗略搜出好的初始解，再細部迭代精修。初始化用 BoN 取樣：高溫度平行生成多個候選解，依生成 token 的 log-likelihood 加總打分，取分數最高的 top-K 候選當精修起點。BoN 強調探索，不利用過去預測，取樣數過大後會飽和甚至下滑。

3.3 iVML:Instance Verbalized Machine Learning:iVML 把 verbalized machine learning（[35]）改造成 instance-level 最佳化——原本 VML 拿訓練資料迭代更新文字 prompt 做迴歸、分類；PDDL domain 精修是單一實例任務，沒有訓練資料產生 verbalized gradient,iVML 改用 LLM 直接檢查候選 domain 有效性，把結果寫成文字批評當梯度。兩個自然語言參數化函式交替迭代：optimizer 評估當前思路 c_t 與 domain d_t，產出回饋 f_t;update 依回饋更新成 c_{t+1}、d_{t+1}，各是一次獨立 LLM 呼叫，d_0 由 BoN 結果初始化。

驗證器怎麼在沒有 ground truth 下篩出正確 PDDL:optimizer LLM 就是驗證器，但它不比對隱藏的正確答案，而是把候選 domain 拿回去對照原始描述 x 檢查邏輯一致性——謂詞是否用對、前置條件與效果是否互相吻合。Table 3 案例：TyreWorld 的 fetch 動作，BoN 生成的前置條件寫成「container 是 closed」，但描述要求 container 要 open;iVML 抓出矛盾，改成「not (closed ?container)」。同樣模式也見於 BlockWorld 的 stack、TSP 的 return-against、Termes 的 remove-block 等動作。這種自我一致性稽核不需外部標註，靠 LLM 對照描述做邏輯檢查。BoN 廣但取樣過大後報酬遞減，iVML 持續改善卻易陷區域最優，兩者互補：BoN 生出多樣初始解，iVML 再逐輪利用式精修。

第 4 節：實驗（作者自報數字）

4.1-4.2 PDDL domain 生成：評測用 IPC benchmark,NL2Domain（283 個 domain）與 Prob2Domain（332 個），成功率看能否通過驗證系統 VAL，骨幹涵蓋 Qwen2.5 系列、LLaMA3.1、Yi-1.5 與 GPT-4o、o1-mini、o1-preview。現有 LLM 普遍表現差：Qwen2.5-Instruct-72B 只 38.5% / 32.8%；閉源裡 o1-preview 最強，平均 54.1%,GPT-4o 平均 27.7%；程式碼模型優於通用模型（Coder-7B 的 NL2Domain 比同尺寸 Instruct 版高 16.2 個百分點）。

BoN 對幾乎所有規模都有效，如 BoN-8 讓 Instruct-14B 的 NL2Domain 從 21.6% 拉到 51.6%。iVML 疊加再進一步提升：iVML-5-BoN-8 讓 Instruct-32B 的 NL2Domain 到 86.2%，平均 88.6%（86.2% / 90.9%）是全表最高。作者摘要強調的是較小的 Coder-7B 搭 iVML-5-BoN-8:NL2Domain 85.2%、Prob2Domain 71.4%、平均 78.3%，大幅超過 o1-mini 的 41.7% 與 33.7%。

4.3-4.4 收斂與初始化消融：以 Coder-7B 為骨幹，BoN 隨取樣數先次線性成長，取樣數大到一定程度後飽和甚至退步（NL2Domain 約 260/283 附近打平）;iVML 單調上升，同預算下能推進到 270 以上，作者歸因於 BoN 缺乏帶回饋的 in-context learning。消融顯示 BoN-8 初始化比 single-pass 更早飽和、分數更高（Deepseek-Coder-7B 約 270 對不到 200）；對主表零分的「弱模型」LLaMA-3.1-8B,BoN-8+iVML 能拉到約 10 個成功 domain，仍遠遜 Coder 系，作者認為是預訓練期邏輯推理暴露不足，test-time scaling 補不回。

4.5 PDDL problem 生成（Planetarium benchmark）：對照組是微調過約 13 萬筆資料的模型，Gemma-7B 98.79%、Mistral-7B 99.00%,GPT-4o zero-shot 只 35.12%。作者用 Coder-7B 做 test-time scaling、不微調：BoN-16 達 99.24%，加 iVML-1 到 99.60%，追平甚至超過微調版本。

4.6 與 LLM 直接當 Planner 比較：用 Fast Downward 做搜尋與計畫驗證，測試域含 Floortile、Barman、Tyreworld、Grippers、Termes、Blockworld,LLM-as-Planner 對照組即使加 self-critique、Pass@8 仍普遍差：o1-preview Pass@8 下 Floortile 33.3%、Termes 19.0%，常見四類錯誤是違反規則、狀態轉移估計錯誤、目標達成誤判、自我評估失準。相對地，BoN-16-iVML-5 生成 domain 交給 Fast Downward,Floortile、Barman、Tyreworld、Grippers、Termes 全部 100%、Blockworld 81.0%，作者認為這證明 PDDL 把狀態轉移顯式建模，差距在約束密集任務上尤其明顯。

第 5 節：結論與限制

結合 BoN 初始化與 iVML 精修的框架，能讓開源 LLM 在 PDDL 生成上超越 o1-mini 且不需額外訓練；iVML 在 PDDL problem 生成上甚至超過專門微調過的模型。生成 PDDL 符號世界模型能讓經典搜尋演算法接手規劃，避免 LLM 當 planner 常見的狀態轉移錯誤。兩點局限：一是評測靠 VAL 做語法與計畫驗證，能保證謂詞元數、型別一致、動作可執行，但驗不出違反 domain 原意或常識的語意錯誤，與形式化數學證明「編譯器檢查測不出語意對齊」的困境同類；二是模擬環境偏理想化，假設動作完全準確執行、狀態完全可觀測，與真實機器人場景有落差。
