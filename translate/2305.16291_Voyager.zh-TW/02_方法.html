2. 方法

VOYAGER 由三個新穎組件構成：(1) 為開放式探索建議目標的自動課程（§2.1）；(2) 發展愈趨複雜行為的技能庫（§2.2）；(3) 生成可執行程式碼做具身控制的迭代提示機制（§2.3）。

2.1 自動課程（Automatic Curriculum）

具身智能體在開放環境會遇到不同複雜度的目標。自動課程的好處是：確保「有挑戰但可管理」的學習過程、培養好奇心驅動的內在動機、鼓勵發展通用而靈活的解題策略。本課程善用 GPT-4 內的網路級知識，prompt 它源源不絕地提供新任務/挑戰。課程以自下而上方式展開，對探索進度與智能體當前狀態高度適應與回應。隨著 VOYAGER 邁向更難的自驅目標，它自然學會多樣技能（如「挖鑽石」）。

輸入 GPT-4 的 prompt 由數部分組成：

  1. 指令：鼓勵多樣行為並施加約束，例如「我的終極目標是盡可能發現多樣事物……下一個任務不應太難，因為我可能還沒有必要資源或還沒學到足夠技能」。
  2. 智能體當前狀態：庫存、裝備、附近方塊與實體、生態圈（biome）、時間、血量與飢餓條、座標。
  3. 先前已完成與失敗的任務：反映當前探索進度與能力邊界。
  4. 附加語境：另用 GPT-3.5 依當前狀態與探索進度自問自答（基於預算考量，標準 NLP 任務用 GPT-3.5 而非 GPT-4）。

實作上採暖身排程（warm-up schedule）：依已完成任務數逐步把更多狀態與附加語境納入 prompt，使 prompt 隨探索進度接觸愈來愈多資訊，讓智能體從基礎技能起步、漸進到更繁複多樣者。全文 prompt 見附錄。

2.2 技能庫（Skill Library）

當自動課程持續提出愈來愈複雜的任務，就必須有作為學習與演化基礎的技能庫。受程式的通用性、可解釋性、普適性啟發，我們用可執行程式碼表示每個技能——它「鷹架」出完成某任務所需的時間延展動作。

輸入 GPT-4 生成程式的 prompt 含：

  1. 程式生成指引，例如「你的函式將被復用來構建更複雜的函式，因此應寫得通用且可復用」。
  2. 控制原語 API 與從技能庫檢索出的相關技能（對 in-context learning 奏效至關重要）。
  3. 上一輪生成的程式碼、環境回饋、執行錯誤與批評（供 GPT-4 自我改進，§2.3）。
  4. 智能體當前狀態（庫存、裝備、附近方塊與實體、生態圈、時間、血量飢餓、座標）。
  5. 思維鏈（chain-of-thought），在生成程式前先做推理。

加入新技能（圖 4 上）：每當 GPT-4 生成並驗證一個新技能，就把它加入以向量資料庫表示的技能庫——key 是程式描述的 embedding 向量（由 GPT-3.5 生成），value 是程式本身，程式經迭代提示機制反覆精煉後方才納入。

技能檢索（圖 4 下）：面對自動課程提出的新任務，先用 GPT-3.5 產出解該任務的一般性建議，結合環境回饋作為查詢語境；再據此查詢、找出最相關的前 5 個技能。透過持續擴充與精煉技能庫，VOYAGER 能在廣泛任務上學習、適應、精進，不斷拓展在開放世界的能力邊界。

（此設計即「不斷成長的可組合可執行資產庫」：驗證通過的行為固化成可檢索、可組合的程式技能——見對應摘要中的 ai_core §2／§3.6 接點。）

2.3 迭代提示機制（Iterative Prompting Mechanism）

透過三種回饋達成自我改進：

  1. 環境回饋：呈現程式執行的中間進度（圖 5 左）。例如「我無法造鐵胸甲，因為我還需要 7 塊鐵錠」點出失敗原因。我們在控制原語 API 內用 bot.chat() 產生環境回饋，並 prompt GPT-4 在生成程式時也使用此函式。
  2. 執行錯誤：程式解譯器回傳的無效操作或語法錯誤，對除錯很有價值（圖 5 右，如意識到 Minecraft 沒有「acacia_axe」，應改造木斧）。
  3. 自我驗證：檢查任務是否成功。與其為每個新任務手寫成功檢查器，我們另實例化一個 GPT-4 智能體當 critic——給它 VOYAGER 的當前狀態與任務，請它判斷程式是否達成任務；若失敗，還給出「該如何完成」的批評（圖 6）。因此本自我驗證比單純的 self-reflection 更全面：既查成功、也反思錯誤。

每輪生成程式後即執行、取得環境回饋與執行錯誤，納入 GPT-4 下一輪的 prompt 做程式精煉。此迭代過程重複直到自我驗證確認完成，此時把新技能加入技能庫並向自動課程要新目標；若 4 輪程式生成後仍卡住，就向課程要另一個任務。此法顯著改善具身控制的程式合成，使 VOYAGER 能在無人類介入下持續習得多樣技能。

演算法（附錄 A.1）：reset 環境取得狀態 → 迴圈：課程 agent 依狀態與探索進度提出下一任務 → 最多 4 輪內：技能管理器依任務與環境回饋檢索技能、action agent 生成程式、環境執行程式回傳狀態/環境回饋/執行錯誤、critic agent 檢查成功與批評；成功則跳出 → 成功則把技能加入技能庫、記為已完成任務，否則記為失敗任務。
