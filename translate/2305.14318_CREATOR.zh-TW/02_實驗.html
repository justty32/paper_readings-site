4. 實驗

4.1 設定

以 **ChatGPT（GPT-3.5-turbo）**為所有方法的基座模型（最大生成長 512、temperature 0.3）。資料集：MATH（七個數學競賽領域，只評數值答案題，約覆蓋全部的 80%）、TabMWP（一至八年級、多樣表格問題）、Creation Challenge（2K 題）。基線四類：

  • Vanilla LLM（w/ 與 w/o CoT）；
  • PoT（另加入矯正版 PoT w/ Rec. 作為更強基線以公平比較）；
  • Tool Use：以 WolframAlpha API 為通用計算工具；
  • CREATOR-Entangled：把創造與決策合併為一階段的消融基線。

4.2 Creation Challenge

既有基準不是為評估工具創造而設計。Creation Challenge 測試 LLM 在沒有現成工具或程式套件可直接套用的新情境下的解題能力。以人工種子資料＋Text-Davinci-003 迭代擴增建成；每筆資料含問題、標準的被創造工具（含用途 utility、輸入、輸出、實作 realization）、工具呼叫決策、最終答案——標準工具的各組件可作為 LLM 工具創造的**提示（hint）**分級使用。

4.3 實驗結果

CREATOR 在 MATH / TabMWP / Creation Challenge 分別達 59.7% / 94.7% / 75.5%，全面大幅超越基線最佳值。擇要：

方法（最佳設定） MATH TabMWP
Vanilla（w/ CoT） 37.9 75.2
PoT（w/ Rec.） 53.9 87.3
Tool Use（WolframAlpha） 43.0 79.6
CREATOR-Entangled 57.2 93.5
CREATOR 59.7 94.7

所有任務上，把創造與決策階段解耦普遍優於合併（CREATOR-Entangled）。Creation Challenge 上，工具創造提示可把表現提升最多 18.7%（no hint 63.8 → utility hint 67.2 → all hint 75.7）。

4.4 結果分析

  • CoT 與程式碼不相容：MATH 上 PoT 與 CREATOR 加了 CoT 表現反而一致下降，TabMWP 則相反。原因在於難題上自然語言推理與程式推理內在衝突：MATH 涉及複雜計算與多樣推理路徑，用 CoT 時 LLM 傾向跟著自然語言思路寫程式，破壞了程式思維的連貫性與獨特優勢（不用 CoT 時反而採暴力演算法與直接計算而更準）。TabMWP 計算簡單、推理直接，語言與程式推理一致，CoT 反而加分。
  • CREATOR 對難題更穩健：按難度分層比較，CREATOR 全面優於基線，且難題上的優勢尤其大。
  • 矯正提升表現：矯正階段可把準確率提升約原值的 10%，證明設立此階段的必要性。
  • 工具創造的兩大影響因子：(1) 創造與決策的分離——本質上就是 LLM 抽象與具體推理的解耦，帶來表現提升；(2) 提示（hints）的可得性——實務上常需引導 LLM 的工具創造行為，更詳細的提示能顯著提升表現。

5. 進一步分析

5.1 促進知識遷移

工具創造的主要目的之一是可復用性：工具內容是知識概念的抽象，一個工具可助解多個共享核心概念的不同情境問題（例如為情感分析建的關鍵詞抽取工具，也適用於文件分類與主題建模）。

設定：建 300 題、分 100 組，每組三題共享核心知識概念（普遍適用的關鍵方法）但情境不同（問題背景與具體細節相異）。先以一般 CREATOR 流程分別測試，再測「某一情境下創出的正確工具能否遷移到另兩題」。

結果（表 5）：透過遷移工具，準確率從 63.0% 升至 78.3%（+15.3%）；100 組中 39 組因遷移受益、僅 2 組變差——LLM 的工具創造能力確能促進知識遷移，在共享核心概念的問題簇上表現更好。

5.2 LLM 工具創造的三種層級

無需特別引導，LLM 便會以不同層級創造工具——印證創造力是 LLM 的內在湧現能力。被創造的工具可分三級：

  1. 強化既有工具（enhancement of existing tool）：封裝既有工具/API 並改變其用途（例：把天氣查詢 API 包成「計算平均溫度」的新工具）。
  2. 串接多個工具（concatenation of multiple tools）：把多個 API 組織成管線以達成特定目的（例：在新工具中呼叫兩個既有 API 共三次）。
  3. 層級化工具（hierarchical tool）：建立清晰的呼叫者—被呼叫者（caller-callee）關係以減輕重複推理負擔（例：is_prime 作為子工具，主工具呼叫它來計數合規數字）。這是實驗中最常見的現象，也代表 LLM 推理潛力最進階的一面。

6. 結論

我們提出「由 LLM 自動創造工具」的概念並實作 CREATOR。透過解耦 LLM 的抽象與具體推理，CREATOR 使邏輯更清晰、整體表現更佳。在既有基準與 Creation Challenge 上的全面評估，證明 CREATOR 相對 CoT、PoT 與 tool-using 方法的優越性與不可或缺性。

局限

實驗僅限 MATH、TabMWP 與新建的 Creation Challenge，未來需擴展到更廣任務以評估可泛化性。對 LLM 工具創造潛力的展示也有限：現有 LLM 甚至能創造工具以搭建完整專案管線，但其創造物的執行能力與正確性仍缺乏適當評估、尚存疑問，有待未來研究劃定 LLM 工具創造潛力的邊界。
