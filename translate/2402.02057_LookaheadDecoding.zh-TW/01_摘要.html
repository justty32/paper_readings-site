摘要

大型語言模型（LLM）的自迴歸解碼（autoregressive decoding）受記憶體頻寬（memory bandwidth）限制，導致高延遲，並大量浪費現代加速器的平行運算能力。既有加速方法（如推測解碼 speculative decoding）通常需要一個 draft model（草稿模型），而好的 draft model 難以取得、也無法跨模型泛化。本文提出 Lookahead Decoding——一個精確（exact／無損）、平行的解碼演算法，無需輔助模型或資料存放區即可加速 LLM 解碼。它用「每步較多的 log(FLOPs)」換取「總解碼步數的減少」，在單顆或多顆加速器上更易平行化，且相容於省記憶體的注意力（如 FlashAttention）。實作在 MT-Bench 上可加速自迴歸解碼達 1.8 倍，在程式碼補全任務用多 GPU 強擴展（strong scaling）達 4 倍。

1. 引言

自迴歸解碼效率不彰有兩個主因：(1) 每步只生成一個 token，總生成時間正比於解碼步數；(2) 每步都嚴重低估加速器的平行能力。既有解法之一是推測解碼及其變體，皆遵循「猜測—驗證（guess-and-verify）」範式：用 draft model 猜測後續數個 token，再用原始（base）LLM 平行驗證。由於驗證多個 token 與生成單個 token 成本相近，可獲可觀加速；但其加速受 **token 接受率（acceptance rate）**上限所限——凡驗證失敗的 token 都須由 base model 重新生成，最壞情況甚至可能拖慢解碼。要維持高接受率必須訓練好的 draft model，而這既不容易、也無法跨 base model 與資料集泛化。

核心觀察：自迴歸解碼可等價表述為用不動點 Jacobi 迭代（fixed point Jacobi iteration）求解一個非線性方程組——本文稱之為 Jacobi decoding。每個 Jacobi 步驟能在不同位置平行生成多個 token；雖然這些 token 可能出現在錯誤位置，但可借其平行生成的能力，讓 LLM 在單一步驟內平行生成數個互不重疊（disjoint）的 n-gram，這些 n-gram 經 base model 驗證（以維持輸出分佈）後即可併入未來序列。Lookahead Decoding 正是利用「解碼受記憶體頻寬而非算力限制」這一特性，用原本閒置的算力來近乎零成本地生成並驗證 n-gram。

貢獻：(1) 一個無損、平行、無需任何輔助元件的新解碼演算法；(2) 揭示其擴展律（scaling law）——每步 log(FLOPs) 與解碼步數呈線性遞減關係，可在步數與每步 FLOPs 間權衡；(3) 相容於最新的省記憶體注意力，並以分散式 CUDA 實作易於平行化；(4) 在多種設定下驗證有效性。

2. 背景

解碼器模型中的因果注意力（Causal Attention）：LLM 由 token-wise 模組（MLP、正規化）與注意力模組組成。注意力對 Q、K、V 執行 O = softmax(QKᵀ)V，因果注意力對 QKᵀ 施加下三角遮罩，確保第 i 個輸出 token 只受第 j≤i 個輸入 token 影響。因其他層皆為 token-wise，故對任意輸入 x、輸出 o，oᵢ 只受 xⱼ（j≤i）影響——這是後續平行生成合法性的基礎。

LLM 中的自迴歸解碼：給定使用者提示 x⁰，模型逐步生成 m 個 token；生成 m 個 token 可視為逐一求解 m 個 argmax 問題（式 1，以貪婪取樣為例）。

猜測—驗證範式（Guess-And-Verify）：以推測解碼為例，於步驟 t 用 draft model 自迴歸生成長度 n 的草稿序列，因草稿已知，遂用 base LLM 平行求解（式 2），再逐一驗證 base model 的輸出是否等於草稿 token；命中則接受並前進，一遇不符即停止、丟棄其後 token，最後以所有被接受的 token 更新序列。這類方法皆依賴一個好的 draft model，難得且不泛化。

Jacobi Decoding：定義 f(yᵢ, y₁:ᵢ₋₁, x⁰) = yᵢ − argmax P_M(yᵢ | y₁:ᵢ₋₁, x⁰)，可將式 1 轉為非線性方程組（式 3）。從隨機初始猜測 y⁰ 出發，用 Jacobi 迭代同時更新所有 yᵢ，沿軌跡 y¹,…,yᵗ,… 收斂到不動點解 yᵐ。此過程保證至多 m 次迭代即得全部解（因每次 Jacobi 更新的第一個 token 必與自迴歸相符）；有時單次迭代能正確生成不只一個 token，可望減少步數。又因 yᵗ 基於軌跡上的 yᵗ⁻¹ 生成，相鄰兩步的相鄰 token 可構成有意義的 2-gram。

Jacobi Decoding 的限制：實測上它幾乎無法減少解碼步數——生成的 token 常被放在錯位，且已放對的 token 又常被後續迭代替換掉，故難有實際牆鐘（wall-clock）加速。
