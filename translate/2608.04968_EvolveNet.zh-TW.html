論文／訪談原始來源

EvolveNet：協作式 Harness 演化的 Agent 自我改進

問題與 4.1

harness 是建構 context、呼叫工具、驗證與失敗恢復的程式。集中式演化先集中 workload 再沿單一路徑改一份 harness；但組織與環境的經驗常不可匯集。EvolveNet 反過來：每個 client 從同一 broadcast harness 在自己資料上平行找改動，server 僅合成產生的程式適應，再廣播下一版。這降低 serial depth 至最慢 client，而非各端時間總和。

4.2–4.5：有證據的程式合成

程式不能像權重取平均。所有 client 從共同 base 出發，故 diff 可比較；client 也附上相對 base 新解與新失敗的行為證據。LLM aggregator 先把 diff 分成機制，再依證據判定 global、home-domain guard，或丟棄。若兩個 home scope 互斥且不改共享狀態或 prompt，論文的 scope-isolation proposition 保證域外行為不變。

合成候選必須在獨立 validation 逐題檢查。若新增能力未超過回歸，回報回歸項供一次修訂；仍失敗便 rollback。這不是搜尋所有組合的最適解，也不把 validation 總分拿來挑 client，只用行為翻轉作 commitment gate。

5–6：實驗

五種資料局部 client：BIRD 資料庫、DS-1000 函式庫、SWE-V repo、ClawEval task family、LiveCodeBench 難度帶。所有流程以 frozen deepseek-v4-flash，並禁改 endpoint、憑證或讀 gold。作者報告上述五個 held-out 分數均升，配對檢定也過 Holm 校正。DS-1000 中保留最佳 client 59.5、只委派 specialists 64.0、只 global 合成 66.5、完整法 68.5；五 client 的新解聯集有 90% 被合成版保留。

7–8：限制與結論

資料不離開不等於隱私，因 diff 本身可能硬編 client 資訊；gate 需要標記資料與 domain key。harness 會成長，BIRD 從 14 行至 253、DS-1000 從 17 至 409，尚無長期退休機制。作者的結論是可執行程式也能承載跨部署經驗，但前提是可組成、可量測、可回滾。
