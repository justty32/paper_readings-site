論文／訪談原始來源

What Is a Skill Worth? Structure-Aware Shapley Valuation of Agent Skills

摘要與第 1 節：問題

自動 feedback loop 可寫出很長的 agent skill，但分不清其中 rule、example、script、heuristic 各值多少。本文固定「skill、目標 agent、held-out task distribution 與 metric」，只為 skill 內部單元配信用。不同於資料點或 prompt span，skill 的單元有依賴、文件層級、trigger 與 context 成本。

任意 coalition 往往不是可讀、可跑的 skill。若留下引用已刪 script 的段落，所量到的是壞 artifact。SkillSV 因此只比較結構合法的反事實版本。

第 2 節：Shapley 背景

Shapley value 平均一個玩家加入不同先前 coalition 的邊際貢獻，能分攤冗餘與互補帶來的收益。作者指出一般均勻 subset／permutation 適用於平面單元，不能直接移到有文件結構的 skill；本法改用已宣告的 feasible-order distribution μ。

第 3.1 節：編譯 skill 結構

compiler 不用模型，輸出 (N,D,H)。N 的粒度跟 skill optimizer 的可編輯 block 相同；D 包含可見的 link/path／heading reference、程式中 definition-to-use 的 semantic edge、及 patch history 留下的 continuity edge。H 是目錄到單元的樹，約束兄弟單元連續出現，避免拿零碎半段去評分。

合法 coalition 對 dependencies 要 downward-closed：保留一個 unit 就必須保留它需要的 unit。作者不以重寫殘存內容修補非法 coalition，避免混入「刪除加改寫」效果。

第 3.2 節：價值與兩種 removal

一個合法 insertion order 的每個 prefix 都是有效 partial skill。單元值是加入前後 agent verified rollout score 的期望差。ρ_del 直接刪掉缺席單元，ρ_pad 用與目標模型 token 長度相稱的中性 placeholder 替代。前者為淨刪除效果，後者保持 context footprint；兩者差被解作 context cost，前提是 placeholder 確實中性。

frontmatter 觸發整份 skill，作者另以 bare agent 與只含 frontmatter 的差異估 trigger value；所有其他單元都在 trigger 已存在的條件下估值。

第 3.3 節：有限 rollout 預算

若 50 個單元、40 task、10 orders 且雙 rendering，直接評估需 40,800 次 rollout。作者改用 chain-coupled task windows：一個 order 的 n+1 個 prefix 同用一個分層抽出的 task window，因此每個相鄰差共享相同 task 難度，一條 chain 同時給所有 unit marginal sample。接近 full-skill anchor 的 prefix 可被 noise gate 截斷，剩餘單元置零；此只界定該 window 的 aggregate 遺漏量，不保證每個單元誤差。

第 4–5 節：評估與結論

作者在 LiveMath、OfficeQA、SpreadsheetBench、ALFWorld 報告 faithfulness、actionability 與 explanation。實驗選定後凍結 skill，切分 attribution panel 與未參與選擇的 confirmation panel；作者稱 SkillSV 可維持 value closure，並以 held-out pruning 支持 keep／compress／delete 的判斷。兩種 operator 的結論只在 OfficeQA 審核，四 benchmark 的結果及排名效益都應視為作者報告。
