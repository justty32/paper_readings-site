摘要

我們提出一個新穎架構，將大型語言模型（LLM）與一個持久、互動的 Lisp 環境整合。此設置讓 LLM 能透過與活體 REPL 的程式化互動，去定義、呼叫並演化自己的工具。做法是把 Lisp 運算式內嵌於生成之中，並以一層中介層（middleware）加以攔截；如此系統便能提供有狀態的外部記憶、反射式編程、以及動態工具創建。我們提出一套設計框架與架構原則，以指引未來「將符號編程與神經語言生成整合」的互動式 AI 系統之實作。

1. 引言：從靜態工具箱到可演化的符號環境

當前 LLM 系統的工具使用，多建立在預定義的 API、工具集或檢索管線之上。這些機制本質上是靜態的：工具由人類事先定義、彼此孤立、呼叫完即消散，模型無從建構或演化自己的工具環境，能力因而受限。

本文的核心提案：賦予模型使用一個 Lisp REPL 作為持久編程與推理環境的能力。當模型能在一個跨互動保存狀態的活體環境裡即時執行程式碼、累積定義、內省與重定義，它便從「呼叫固定工具的使用者」，轉變為「在符號環境中自建工具、反思自身程式碼的元編程者」——這正是標題所謂「從工具呼叫（tool calling）到符號思考（symbolic thinking）」的躍遷。

2. 系統架構

系統由三個組件構成。

2.1 語言模型後端（Language Model Backend）

負責處理使用者輸入並生成回應。其關鍵能力是可在自然語言輸出中，用 <lisp>...</lisp> 標籤內嵌 Lisp 程式碼。後端可為本地模型（如 Ollama 服務）或遠端模型（如 OpenAI GPT）。

2.2 中介層（Middleware Layer）

中介層是一個串流感知代理（stream-aware proxy），攔截語言模型所生成的輸出 token。其處理流程為：

  1. 在生成串流中偵測 <lisp>...</lisp> 區塊；
  2. 暫停生成，抽取其中程式碼，轉送給直譯器（REPL）；
  3. 捕捉求值結果；
  4. 把結果**回注（reinject）**進生成串流；
  5. 恢復生成，讓結果被透明地整合進去——彷彿該結果本來就是模型初始輸出的一部分。

如此便能在不打斷整體互動流程的前提下，達成執行期的動態計算與情境感知的內容展開。

2.3 持久 Lisp REPL（Persistent Lisp REPL）

通常採用 SBCL（Steel Bank Common Lisp），負責維持：

  • 跨對話回合的長期程式狀態；
  • 函式、變數、巨集的定義（持續存活、可演化）；
  • 內省（introspection）與動態重定義的支援，以利符號推理與元編程。

3. 核心機制

3.1 動態工具創建與狀態持久

系統讓模型能隨時間累積一個不斷成長的函式、巨集與工具庫。不同於稍縱即逝（ephemeral）的一般函式呼叫，Lisp 定義在同一 REPL session 內跨呼叫持久保存，形成一個「會演化的工具箱」，隨對話推進支撐越來越複雜的行為與越來越豐富的互動。

3.2 反射式編程（Reflective Programming）

Lisp 的內省式設計讓模型能動態檢視自己當前的環境：查詢有哪些可用函式、檢查其原始碼、即時重定義程序。這支援一種「自我覺察的生成流（self-aware generation flows）」——模型不只是寫程式，還能推理其結構與行為。

3.3 巨集與元編程（Metaprogramming via Macros）

本文強調 Lisp 強大的巨集系統與對高階函式的支援，讓模型能為其任務量身定義領域特定語言（DSL）或控制結構。

3.4 生成式自我延伸（Generative Self-Extension）

一項具推測性、但作者特別點出的能力：模型或可利用 Lisp「修改自身結構與行為」的能力，去建構生成管線、可重用常式或包裝器，來為自己的推理搭建鷹架（scaffold its own reasoning）。

4. 為何選擇 Lisp

  • 同像性（Homoiconicity）：程式碼與資料的統一表示，天然契合 LLM 的能力，是元編程的根本。
  • 語法：極簡而一致的語法，降低 token 預測的計算負擔。
  • AI 歷史血統：長期居符號 AI 核心，留下大量系統、慣用法與文獻資產。
  • 可延展性：巨集、一等符號（first-class symbols）與動態重定義，讓 LLM 能演化語言本身。
  • 文件：良好且慣用的 Lisp 程式碼文件，提升模型生成輸出的可靠度與可用性。

為何特別選 Common Lisp（而非 Scheme）

  • 豐富的標準庫、強大的物件系統（CLOS）、進階的錯誤處理（透過其 condition system）；
  • 能做完整語言擴充的巨集系統；
  • 支援增量編程與持續互動的互動式 REPL；
  • 支撐「持久、可適應代理」的執行期修改能力。

5. 互動協定／工作流程

論文將流程描述為：

  1. LLM 生成含內嵌 <lisp>code</lisp> 標籤的回應；
  2. 中介層偵測到並暫停生成；
  3. 程式碼被抽出，在持久 REPL 中執行；
  4. 結果被捕捉並重新插入生成串流；
  5. 生成繼續進行，「彷彿該結果本就是模型初始輸出的一部分」。

如此即實現執行期的動態計算與情境感知的內容展開，而不擾動整體互動的流暢性。

6. 與既有做法的比較

  • 相對於標準函式呼叫（Function Calling）：傳統做法使用孤立、不持久的函式；本架構維持有狀態的工具與環境的累積式演化。
  • 相對於 ReAct／代理框架：置於代理框架中，本架構能支援把複雜任務委派給 Lisp 定義的子程序，或透過結構化協調來編排多個代理。
  • 註：論文並未明確引用或對照 MCP（Model Context Protocol），也未提供對 ReAct 的細部 benchmark（因本文無實驗）。

7. 能力總覽

  • 有狀態工具建構：函式跨回合持久；
  • 自我檢視：模型能檢查並推理自己生成的程式碼；
  • 元編程彈性：依任務需求創建 DSL；
  • 外部工具整合：可延伸接上搜尋引擎、embedding 編碼器等工具；
  • RL 的符號接地：活體可編程環境作為外部工具，讓模型能測試假設、除錯邏輯、迭代精煉策略。

8. 應用場景

  1. 科學計算：符號代數、解方程、計算工具開發；
  2. 互動式編程助手：在 session 過程中增量建構工具箱；
  3. 代理框架：任務委派與多代理協調；
  4. 語言到邏輯的翻譯：動態建構「把自然語言指令轉為可執行程式碼」的直譯器。

9. 局限與安全考量

已識別風險：讓語言模型在活體環境中執行任意程式碼，會引入不安全操作的風險，包括潛在的系統存取或對敏感資源的操縱。

建議緩解：

  • 部署於隔離的執行環境（如 sandbox 沙箱容器）；
  • 透過謹慎策展執行期環境來限制潛在不安全函式；
  • 實施監控與存取控制。

未解的安全問題：作者坦承未來的安全分析須處理對抗性穩健（adversarial robustness）、沙箱逃逸嘗試、以及資源耗盡情境。

10. 未來工作路線

實作階段：

  • 打造包含三組件的概念驗證（串流中介層、持久 SBCL REPL、沙箱化）；
  • 評估工具跨對話回合的持久性與可靠度。

研究方向：

  • 優化中介層以達低延遲互動；
  • 建構混合符號-神經推理的 benchmark；
  • 研究自我修改／遞迴生成程式碼中的湧現行為；
  • 擴展至 Lisp 以外的其他可編程語言。

擴展性與整合：

  • 與現有 LLM 生態整合；
  • 分散式多代理環境與共享符號工作區；
  • 工具生成與重用的元學習；
  • 為自主代理設計有效的安全協定。
