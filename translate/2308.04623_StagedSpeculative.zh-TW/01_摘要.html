摘要

大型語言模型（LLM）近期進展展現其多樣能力。我們提出一個新演算法——分階段推測解碼（staged speculative decoding），用於加速小批次、裝置端（on-device）情境的 LLM 推論。我們藉由改進既有推測解碼（speculative decoding）來對付小批次推論的低算術強度（arithmetic intensity）問題：第一，把推測批次重構為一棵樹（tree），以降低生成成本並提高每批次的期望 token 數；第二，再加一個推測解碼階段。兩者合起來，用 762M 參數的 GPT-2-L 模型把單批次解碼延遲降低 3.16x，同時完美保留輸出品質。

1. 引言

LLM 近年高速成長，能力涵蓋高品質文本生成、複雜推理、決策與問題求解。但這些進展伴隨系統層級的挑戰：模型越強、運算需求越大，推論常需大量雲端資源，對許多需要低延遲、或重視資料隱私的應用而言是難以承受的門檻。

本文以加速本地（小批次）推論回應此挑戰——這類推論因算術強度低而算力利用極差。我們認為此問題關鍵有三：延遲（latency）——優化本地推論延遲能改善即時互動；個人化（personalization）——本地推論讓模型能為個別使用者在地客製；隱私（privacy）——資料無須離開使用者裝置。更哲學地說，能在本地高效運行 LLM 的方法，能賦權運算資源有限的個人，促進 AI 民主化。

本文建立在 Leviathan et al.（2022）與 Chen et al.（2023）的推測解碼之上：以一個快但不準的草稿模型（draft model）預先猜測 oracle 模型的輸出並批次送去驗證，在完美保留模型分佈的前提下改善序列解碼效能。但這類方法一開始擴展良好、增益卻很快飽和——因為草稿模型連續猜對多個 token 的機率呈指數級遞減。我們從兩個關鍵面向改進：

  1. 把推測批次重構為「可能 token 序列的樹」，以更快組出更大、更高品質的推測批次。
  2. 對草稿模型本身也做推測解碼，進一步提升效能。

我們發現這些技術在確定性與採樣式解碼上都顯著提升推測解碼效能。

2. 背景

2.1 自回歸 LLM 推論

decoder-only LLM 的自回歸生成分兩階段。第一階段 prompt 過模型、產生 KV cache 與第一個輸出 logits，因整段 prompt 可平行處理故通常很快。第二階段是解碼（decoding）：從 logits 選出一個 token 餵回模型、產生下一個 token 的 logits，反覆直到生成足夠 token。因解碼必須循序進行、每產一個 token 就要把整個模型權重串流過計算單元一次，小批次下此階段算術強度極低，通常是自回歸生成中最昂貴的部分。

2.2 GPU 優化

現代 LLM 推論多在 GPU 上進行（工作負載以大型矩陣乘法為主、高度平行）。優化小批次推論的關鍵挑戰是極低的算術強度：16-bit、batch size 1 時解碼的算術強度為 1。以 GPT-2-L（762M）的參考 PyTorch 實作為例，推論約需 1.4 GFLOP，但一台靜置的 NVIDIA RTX 4090 僅達 150 tokens/秒，算力利用率僅 0.13%。此糟糕表現主要源於 GPU roofline——在低算術強度區受記憶體頻寬支配（圖 1）。因此提升效能的唯一途徑是提高推論的算術強度。

2.3 推測解碼

推測解碼的基本想法：用較小、較快的草稿模型預先解碼數個 token，再把它們當成單一批次餵給 oracle 模型。若草稿猜對（大模型同意），一個批次就能解碼數個 token，省下每 token 的可觀記憶體頻寬與時間；若大模型拒絕草稿的預測，該批次其餘部分作廢、演算法自然退回逐 token 解碼。推測解碼可搭配拒絕採樣（rejection sampling）方案以從原始分佈取樣。此法只在「頻寬為瓶頸」的小批次情境有用——它用算力換頻寬。

推測解碼吸引人之處有二：其一，完全不降低模型品質；其二，其增益與其他方法（如量化、flash attention）大致正交，因為它的收益來自把序列執行轉為平行執行。

3. 方法

我們對推測解碼做兩項改進：樹狀批次與額外階段。兩者結合即「分階段推測解碼」。

3.1 樹狀批次（Tree-structured batches）

現行推測法為批次預測單一序列，但對大批次或低草稿對齊度擴展不佳——兩模型在長連續序列上一致的機率指數級偏低，故推測解碼隨算術強度擴大而報酬急遽遞減。

我們的作法是動態建構一棵「可能序列的樹」，帶來三個好處：

  • 每批次期望真 token 數更多：把算力從超長序列尾端重分配到前段，納入模型第二、第三可能的 token。
  • 葉節點更多、批次「免費」取得更多：標準推測解碼中「跑草稿模型組批次」成本不可忽略；但在樹中草稿模型只在內部節點執行，樹越寬葉節點越多。
  • 對小模型可跨樹平行化：進一步降低草稿成本；極限下只需執行「等於樹深度」次數。這很重要，因草稿模型也是小型 transformer、在小批次下同樣記憶體綁定。

實作要點：把解碼時的 self-attention 拆成「對 KV cache 的 cross-attention」與「批次內 self-attention」；再依樹結構控制位置編碼與因果遮罩來建構樹狀批次；整個批次的新 KV cache 須另存，token 取樣後再把適當切片附加回主 KV cache。

3.2 分階段推測（Staged Speculation）

現行推測法用單一較小模型（通常是較小 LLM）當草稿。此設定下草稿模型大小是重要超參數：越大越對齊 oracle 但越貴、越小批次品質越低但便宜；實務上草稿約比 oracle 小 15–20x 似乎最佳。

然而在樸素推測解碼下，組大批次會反轉成本結構——花在草稿模型上的時間反而多於 oracle。因此應加速草稿模型的序列生成，而推測解碼本身正是天然解法。於是我們對草稿模型也加上推測解碼。整體「分階段推測解碼」即由 oracle、draft、draft2 三個模型搭配樹狀批次構成。
