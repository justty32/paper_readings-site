4. 結果

模型設定：oracle 為 GPT-2-Large（762M，在 The Stack 的 Python 子集微調）；draft 為小型 GPT-2（40M，同資料訓練）；draft2 為 Katz backoff trigram（N-gram）模型——由 draft 模型以採樣溫度 1.5 跑兩小時生成 1.2 億 token 後建成。所有評測在靜置的 RTX 4090（頂級消費級硬體）上進行。對照兩種方法：baseline（oracle 逐 token 解碼）與 Leviathan et al. 的標準推測解碼。於 HumanEval 的 164 題、確定性與 topk 兩種採樣下評測。

表 1（記憶體頻寬，相對 baseline=1.00）：確定性 baseline 1.00 → 推測 0.31 → staged 0.23；topk 1.00 → 0.48 → 0.35。分階段推測用的頻寬顯著少於另兩法。

表 2（吞吐量 tokens/秒）：

採樣 baseline 標準推測 分階段推測
確定性 150 350 475
Topk 150 219 298
  • 確定性採樣：較參考實作平均提速 3.16x、較標準推測採樣 1.36x。且本文用的是相對小的模型，更大模型預期增益更大。Profiling 顯示實作有 35% 來自 Python 基礎設施的開銷，可由更有效率的實作或攤到更大模型上降低。
  • Topk（k=50, T=1）採樣：兩種推測法都因批次中 token 被隨機拒絕而明顯退化，但分階段推測仍領先——較 baseline 1.98x、較標準推測仍 1.36x。

Token 來源（圖 3）：模型通常能把最簡單、最明顯的 token（如空白）透過兩個 transformer 批次解出，因它們源自 N-gram 模型；較難的由小模型生成；最關鍵的 token（如「if」之後的 token）才由 oracle 產生。（當然所有 token 最終都經 oracle 校驗。）因批次大小有限，這只是趨勢、非每個 token 皆然。

增益變異（作者自陳缺點）：真實 prompt 上效能增益高可達 10x、也可能僅 2x，很大程度取決於難內容的稠密或稀疏——例如高縮排 Python 比無縮排更能利用 N-gram 模型、增益更大。作者推測這些模型代表「每單位資料熵約為固定成本」：極低熵生成（如純空白）會被極快產生、效能逼近大批次推論；高熵稠密生成則各階段都得靠小批次解碼。由此得一推論：LLM 生成的多數文本，其熵低於其作者模型的能力；大模型增加的準確度僅集中在少數關鍵 token 上。

未來工作：(1) T>0 時或可先生成 multinomial CDF、再據此挑選要組進批次的 token 而更快；(2) 用更大模型（8-bit 量化下消費級 GPU 可容納 20B 模型）可在裝置端獲得更大增益，並容納再多一階段推測（20B→1B→50M→N-gram）；(3) 研究比 N-gram 更好、但仍能在 <10μs 內執行的更佳最底層草稿模型。

5. 結論

本文描述並實作了對既有推測解碼的數項改進。第一，把送給 oracle 的批次重構為樹，以降低生成成本、提高每批次期望 token 數。第二，加入第二階段推測以加速草稿模型的解碼。整體上，較標準單批次推論達到平均 3.16x 的加速。
