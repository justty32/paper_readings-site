摘要

大型語言模型（LLM）在眾多任務上表現卓越，但選對模型往往要在效能與成本間權衡：強大的模型效果好卻昂貴，較小的模型便宜卻能力較弱。為處理此取捨，本文提出一個訓練框架，用來學習高效的 router 模型，在推論時動態地在較強與較弱的 LLM 之間選擇。框架利用人類偏好資料，並採用資料增強技術提升效能。在公開 benchmark 上的評估顯示，本方法可在不犧牲回覆品質下把成本降到 2 倍以上；此外 router 展現強大的泛化能力，即使路由於訓練時未見過的 LLM 之間仍能維持效能。這凸顯本框架在提供「兼顧成本與高效能的 LLM 方案」上的潛力。

1. 引言

LLM 在對話、問答、摘要、程式生成等任務展現流暢與理解力，這得益於 Transformer 架構與資料／訓練基礎設施的擴大。然而各 LLM 並不等價：模型規模不同會影響服務所需資源，訓練資料不同又造成強弱能力差異——大模型通常更強但更貴，小模型較弱但便宜。

這種異質格局造成部署兩難：全部查詢丟給最強模型能保品質但貴得離譜；全丟給小模型可省成本（原文舉例 Claude-3 Haiku vs Opus，以每百萬輸出 token 計為 $1.25 vs $75，差 50 倍以上），但複雜查詢品質會下降。**LLM 路由（routing）**提供解法：先讓每個查詢過一個 router，由它判斷最適合的 LLM——簡單查詢送小模型、複雜查詢送大模型，藉此平衡品質與成本。

達成「在成本約束下最大化品質，或在目標品質下最小化成本」的最佳路由很有挑戰。理想 router 須：(1) 每個查詢只呼叫單一 LLM，相對多 LLM 法把成本與延遲降到最低；(2) 泛化到域外查詢，不必為不同領域各訓 router；(3) 跨多種 LLM 而不需重訓，保有面對模型版圖演變的彈性。

本文提出一個以偏好資料學習 LLM router 的原理化框架。路由對象是兩類模型：(1) 強模型，高品質高成本（如 GPT-4）；(2) 弱模型，低品質低成本（如 Mixtral-8x7B）。目標是在達成特定效能目標（如強模型的 90%）下最小化成本，做法是把簡單查詢智慧地導向弱模型、把複雜查詢留給強模型。以此框架訓練多個 router，在 MMLU、MT Bench 等 benchmark 上顯示成本降低 2 倍以上而品質幾乎不損，且跨多組強／弱模型配對免重訓仍有效。

三項貢獻：(1) 提出利用人類偏好資料與資料增強的 router 學習框架，在熱門 benchmark 上省成本 2 倍以上而對品質影響極小；(2) 展示 router 能泛化到未見資料、跨多個 LLM 維持效能，單一訓好的 router 即可廣泛適用；(3) 開源訓練、服務與評估 LLM router 的整套框架。

2. 相關工作

  • 獎勵建模 vs LLM 路由：獎勵建模是在 LLM 生成回覆之後評估品質；路由則是事前選對 LLM，需要對查詢複雜度與各模型能力有深刻理解。
  • 多 LLM 的成本-效能取捨：LLM-Blender 用集成框架推論時查多個 LLM 再選最佳回覆；FrugalGPT 走級聯（cascading），依序查詢 LLM 直到得到夠可靠的回覆；AutoMix 讓小模型先自我驗證回覆、必要時才路由到大模型。這些法都依賴多次 LLM 查詢、會增加延遲；相對地，本文對每個查詢只路由到單一 LLM，滿足理想 router 的延遲約束。
  • Hybrid-LLM：與本框架相似但關鍵不同——它用 MixInstruct 上基於 BARTScore 的合成偏好標籤與單一 BERT-based router；本文用 Chatbot Arena 的人類偏好標籤並探索多種 router 架構，且證明資料增強能全面提升各架構；Hybrid-LLM 只在 MixInstruct 測試集評估、缺域外泛化證據，本文則在多個去污染公開 benchmark 上驗證。
  • Zooter：用 QwenRM 獎勵模型的路由標籤，可能繼承其訓練資料偏誤、且訓練訊號綁定固定一組 LLM；本文主要靠人類偏好資料，並展示對訓練外 LLM 仍維持效能。

3. LLM 路由

3.1 問題形式化

考慮 LLM 集合 \(M\)，每個模型 \(M: Q\to A\) 把查詢 \(q\) 映到答案。本文聚焦兩類：強模型 \(M_{strong}\)（高品質高成本，如 GPT-4）與弱模型 \(M_{weak}\)（低品質低成本，如 Mixtral-8x7B）。此二元路由在實務常見（尤其使用者想從閉源轉開源以優化品質-成本），也是延伸到更複雜 N-way 路由的基礎。

假設有偏好資料 \(D_{pref}=\{(q, l_{s,w})\}\)，其中 \(l_{s,w}\in L=\{\text{win}_s, \text{tie}, \text{win}_w\}\) 是「對查詢 \(q\)，強模型與弱模型回覆比較的結果」。學一個二元路由函式 \(R^α: Q\to\{M_{weak}, M_{strong}\}\)，由兩個關鍵組件定義：

  1. Win Prediction Model（勝率預測模型）：估計「對查詢 \(q\)，強模型會勝過弱模型的機率」\(P_θ(\text{win}_s|q)\)，透過最大化觀測偏好資料的似然學參數 \(θ\)（式 1）。此舉讓模型捕捉兩類模型在不同查詢型別上的相對強弱。
  2. Cost Threshold（成本閾值）\(α\in[0,1]\)：把預測勝率轉成路由決策——\(P(\text{win}_s|q)<α\) 走弱模型、\(\geq α\) 走強模型（式 2）。\(α\) 越高越嚴格省錢（偏好弱模型），\(α\) 越低越偏高品質（偏好強模型）。

最後由路由函式與兩個模型組成 router 模型 \(M_{R^α}\)：\(R^α(q)=M_{strong}\) 時回傳強模型答案，否則回傳弱模型答案（式 3）。

3.2 評估指標

  • 成本效率 \(c(M_{R^α})\)：對強模型的呼叫百分比（式 4）——因強模型顯著較貴。
  • 效能 \(r(M_{R^α})\)：平均回覆品質（式 5），品質分數可以是黃金標註資料上的正確率（如 MMLU）或評分（如 1–5、1–10）。
  • PGR（performance gap recovered）：\(\frac{r(M_{R^α})-r(M_w)}{r(M_s)-r(M_w)}\)（式 6），衡量 router 補回了強弱模型效能差距的多少。
  • 上述指標單看皆不足（例如「永遠送強模型」PGR=1 但零省錢）。因此變動 \(α\) 畫出「呼叫-效能圖」，定義 **APGR（average performance gap recovered）**＝不同成本約束下 PGR 的積分／平均（式 7、8，對應 router 曲線與弱模型曲線間的面積）。
  • CPT(x%)（call-performance threshold）：達到 x% PGR 所需的最少強模型呼叫比例。圖 1 中 CPT(50%)≈37%（達 50% PGR 需約 37% 呼叫走 GPT-4）。
