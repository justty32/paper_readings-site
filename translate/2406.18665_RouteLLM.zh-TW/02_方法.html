4. 方法

4.1 Chatbot Arena 資料

主偏好資料來自 Chatbot Arena 線上平台的 80k 對戰：使用者送 prompt、收到兩個匿名模型的回覆並投票選勝或平手，形成含查詢、回覆、成對人類比較標籤的資料集 \(D_{arena}\)。

主要挑戰是標籤稀疏：任兩模型間的比較標籤平均不到 0.1%。解法是依 Chatbot Arena 排行榜分數把模型分成 10 個 tier（動態規劃最小化 tier 內變異），取前兩 tier 為強模型類、第三 tier 為弱模型類。關鍵是訓練只保留「誰贏」的身份、丟棄模型回覆內容。

4.1.1 資料增強

即使分了 tier，跨模型類的人類偏好訊號仍稀疏，會限制泛化（尤其參數量大的 router）。兩種增強：

  • Golden-labeled 資料集 \(D_{gold}\)：用 MMLU validation split 約 1500 題，以已知正確答案 \(l_g\) 比對強、弱模型回覆得到比較標籤 \(l_{s,w}\)。
  • LLM-judge-labeled 資料集 \(D_{judge}\)：對開放式對話用 GPT-4 當裁判做成對比較（LLM-as-judge 與人類判斷高度相關）。挑戰是大量收集 GPT-4 回覆與比較很貴；作者借用 Nectar 資料集（取有 GPT-4 回覆的查詢當強模型回覆 \(M_s\)），對其生成 Mixtral-8x7B 回覆當弱模型 \(M_w\)，再用 GPT-4 裁判打成對標籤。共收約 120K 樣本、總花費約 $700。

4.2 路由方法（四種 win prediction model）

  1. Similarity-weighted (SW) ranking（相似度加權排序）：採 Bradley-Terry 模型。對查詢 \(q\) 計算它與訓練集每個 \(q'\) 的餘弦相似度（以文字嵌入，並按最大相似度縮放，式 9），據此對每筆訓練查詢賦權 \(ω'=γ^{1+S(q,q')}\)（實務用指數尺度、\(γ=10\)）；以加權二元交叉熵解出強、弱模型的 BT 係數 \(ξ_s, ξ_w\)（式 10），勝率 \(P_θ(\text{win}_s|q)=\frac{1}{1+e^{ξ_s-ξ_w}}\)。此法無需訓練，於推論時即時求解。
  2. Matrix factorization（矩陣分解）：借鏡推薦系統捕捉低秩結構的思路，學一個隱藏評分函式 \(δ(M,q)\)（模型 \(M\) 對查詢 \(q\) 回覆的品質），以 sigmoid 建模勝率 \(P_θ(\text{win}_s|q)=σ(δ(M,q)-δ(M',q))\)（式 11）。\(δ\) 建成模型嵌入 \(v_m\) 與查詢嵌入 \(v_q\) 的雙線性函式（式 12，含投影層對齊維度、線性層輸出純量），本質是對 \(Q\times M\) 評分矩陣做矩陣分解。在 8GB GPU 上訓約 10 epoch（batch 64、Adam、lr 3e-4）。
  3. BERT classifier：用 BERT-base 取查詢的上下文嵌入，以分類 token（CLS）的嵌入接 logistic 頭定義勝率 \(P_θ(\text{win}_s|q)=σ(Wh_{CLS}+b)\)（式 13）。在 \(D_{pref}\) 上全參數微調（2×L4 24GB、約 2000 步、batch 16、seq 512、lr 1e-5）。
  4. Causal LLM classifier：用 Llama 3 8B、指令跟隨範式——輸入含使用者查詢的指令 prompt，以 next-token 預測方式輸出勝率（不另設分類頭）；把比較標籤當額外詞彙 token 附加，勝率＝對標籤類別 \(L\) 的 softmax。在 8×A100 80GB 上訓約 2000 步（batch 8、seq 2048、lr 1e-6）。

5. 實驗

訓練資料：主要用 80K Arena 資料（留 5k 驗證），剔除短於 16 字元的 prompt 後得 65k 成對比較、涵蓋 64 個模型；對話跨 100+ 語言（英文 81%、中文 3.1%、俄文 2.2%）。並以 \(D_{gold}\) 或 \(D_{judge}\) 增強。

評估 benchmark：MMLU（14,042 題、57 科）、MT Bench（160 題開放式、LLM-as-judge）、GSM8K（1000+ 小學數學）。並做訓練-評估交叉污染檢查、只報未污染結果，藉此理解域外泛化。

設定：矩陣分解與 SW ranking 用 OpenAI text-embedding-3-small 嵌入查詢；BERT 與 Causal LLM 全參數微調。以 gpt-4-1106-preview 為強模型 \(M_s\)、Mixtral 8x7B 為弱模型 \(M_w\) 具體評估；基準為「在成本約束下隨機路由」的 random router。

5.1 結果

  • MT Bench（表 1）：只用 Arena 訓練時，矩陣分解與 SW ranking 已顯著優於隨機（矩陣分解達 50% PGR 只需隨機一半的 GPT-4 呼叫）；但 BERT、Causal LLM 在低資料下接近隨機。加 GPT-4 裁判增強（\(D_{judge}\)）後全面提升：BERT 的 APGR 相對隨機提升逾 50%，矩陣分解成為最佳 router、CPT(80%) 幾乎減半。MT Bench 在 CPT(50%) 的分數 8.8＝GPT-4（9.3）的 95%；相對隨機 router 最高省成本 75%。
  • MMLU（表 2）：只用 Arena 訓練時全部 router 都近隨機（多數題域外）；加 \(D_{gold}\) 後大幅改善，各 router 在 CPT(50%) 約比隨機少用 20% GPT-4 呼叫——而這批黃金標註僅約 1500 樣本、不到總資料 2%，證明少量增強即有效。MMLU 在 CPT(50%) 分數 75＝GPT-4（81）的 92%。
  • GSM8K（表 3）：同樣只用 Arena 近隨機，加 \(D_{judge}\) 後全部 router 由「差於隨機」翻成「優於隨機」；Causal LLM 最佳，CPT(50%)、CPT(80%) 皆比隨機少約 17% GPT-4 呼叫。GSM8K 在 CPT(50%) 分數 75＝GPT-4（86）的 87%。

5.2 跨模型適應性

上述用 GPT-4／Mixtral。為證明對新 LLM 的適應性，用同一批（Arena+\(D_{judge}\) 訓的）router、完全不重訓，只替換路由對象為兩組新配對：(1) Claude 3 Opus／Claude 3 Sonnet、(2) Llama 3.1 70B／Llama 3.1 8B（皆不在訓練資料中）。結果（表 4）顯示效能與原配對相當、仍顯著優於隨機，最佳 router 達 CPT(80%) 約只需隨機一半的 GPT-4 呼叫——說明 router 學到了「能區分強弱模型的查詢共通特徵」，可在推論時泛化到新模型而無需額外訓練。

5.3 量化資料集與 benchmark 相似度

同一資料訓的 router 在不同 benchmark 表現差異，歸因於評估與訓練資料分布不同。作者定義 benchmark-dataset similarity score（每個評估 prompt 對訓練樣本的平均最大相似度，式 14）。相似度越高、對應 benchmark 上表現越強；資料增強（golden 或 LLM-judge）會把偏好資料分布拉近 benchmark、提高相似度並轉化為更好表現。此分數是「依查詢分布系統化改善路由」的一個有前景方向。

5.4 成本分析

估 GPT-4 約 $24.7／百萬 token、Mixtral 8x7B 約 $0.24／百萬 token（附錄 D，依平均輸入 95 / 輸出 264 token 與 GPT-4 定價 $10 輸入 / $30 輸出推得）。以「最佳 router 相對隨機的 GPT-4 呼叫比例之倒數」計成本節省（因 GPT-4 成本為主導）——結果（表 6）：MT Bench 3.66×（95% GPT-4 品質）、MMLU 1.41×（92%）、GSM8K 1.49×（87%），最高達 3.66×。

5.5 路由開銷

擔心路由相對單模型的額外開銷，故量測（表 7）：GPU-based router（矩陣分解、分類器）吞吐較高（矩陣分解 155 req/s）；最貴的 SW ranking（CPU-only）相對 GPT-4 生成成本額外開銷不超過 0.4%，證明 router 部署成本相對 LLM 生成很小、且能撐真實負載。
