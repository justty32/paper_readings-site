摘要

本文展示如何把「神經文字生成」問題建設性地重構為有限狀態機（FSM）各狀態之間的轉移。此框架帶來一種高效途徑：藉由在語言模型的詞彙表上構造一份索引，來用正則表達式與上下文無關文法（CFG）引導文字生成。此法與模型無關、能施加領域特定知識與約束、並藉由保證生成文字的結構而能構造可靠的介面。它對 token 序列生成過程只增加極小的額外負擔，且顯著優於既有方案。實作已提供於開源 Python 函式庫 Outlines。

1. 引言

我們關注的問題是：從 LLM 生成符合正則表達式或 CFG 的 token 序列。這類引導式生成，用於在難以（或代價高昂）僅靠 fine-tune 捕捉的嚴格格式要求下，讓 LLM 輸出可用。此類功能近來已被泛化進各種 prompting 函式庫與介面，但其適用性常受縮放成本限制。

多數引導式生成的實作是偏置分數值（用來決定 LLM 詞彙表中各 token 機率的 logits）。一種常見且足夠的做法是：反覆對整個詞彙表評估，判斷哪些 token 依約束與先前已取樣的 token 為合法，並把不合法 token 的機率設為 0。這種做法對每個生成的 token 帶來固定的 O(N) 成本，N 為 LLM 詞彙表大小。

我們提出的方法用正則表達式的有限狀態機（FSM）表述，來（a）任意地開始與停止引導式生成，並（b）構造一份索引，使每一步能高效取得「非零機率 token 集合」。其結果是一個平均 O(1) 成本的演算法。

在正則表達式情形，本法與 Kuchnik et al. [2023]（用轉換器/transducer 表述在語言模型詞彙表上取得 FSM）最相似；那些 FSM 含有與本文索引大致相同的資訊與縮放好處。但本法不需要完整的轉換器抽象，且更容易在不修改底層自動機及其實作的情況下，擴充既有的高效正則表達式函式庫。更重要的是，本文的索引法可延伸到 CFG 與 LALR(1) 剖析器，以支援對熱門資料格式與程式語言（JSON、Python、SQL 等）的高效引導式生成；此延伸是透過對傳統 LALR(1) 剖析器組件與操作的增補達成，同樣可用來擴充既有剖析器實作。

2. LLM 取樣與引導式生成

令 Sₜ = (s₁ … sₜ) 表示 t 個 token 的序列，sₜ ∈ V，V 為詞彙表，|V| = N。詞彙表由取自固定字母表的字串組成，N 常為 10⁴ 量級或更大。下一個 token 定義為隨機變數：α = LLM(Sₜ, θ)，sₜ₊₁ ∼ Categorical(α)，其中 θ 為訓練參數、α ∈ ℝᴺ。本文中 LLM 指做「下一 token 補全」訓練的深度網路，但方法可推廣到任何「吃 token 序列、回傳下一 token 機率分佈」的函數。

2.1 序列取樣

令 F ⊂ P(V) 為以特殊 token EOS ∈ V 結尾的多 token 字串子集；文字生成任務即從 F 抽樣。既有程序有貪婪解碼、beam search、以及較新的 SMC 取樣。Algorithm 1（基本 LLM token 取樣） 描述一般程序（常稱 multinomial sampling）：遞迴地從上述 categorical 分佈取樣新 token，直到取到 EOS。

2.2 引導生成

可藉由操作輸出 logits α，從下一 token 分佈導出其他隨機變數。因處理的是有限離散分佈，可施加一個布林遮罩 m : P(V) → {0,1}ᴺ 來限制原分佈的支撐集，得未歸一化的條件分佈：α = LM(S̃ₜ, θ)，α̃ = m(S̃ₜ) ⊙ α，s̃ₜ₊₁ ∼ Categorical(α̃)。如此，遮罩 m 可設計成讓生成序列表示：數字樣本、匹配正則 [a-zA-Z] 的字串、或依指定文法（Python、SQL 等）可剖析的字串。

Algorithm 2（帶遮罩的 LLM 取樣） 是 Algorithm 1 的簡單增補：每步先算 α，再構造遮罩 m(s)，取 α̃ = m ⊙ α 後取樣。問題在於：遮罩 m 的計算（第 2.5 行）隱含遍歷 V 全部元素——除了算 α 外，這步是最貴的。在正則引導（及更複雜情形）中，支撐集與遮罩 m 必然依賴先前已取樣的 token；這種引導生成本質上是迭代式比對／剖析問題，不適合「需一次拿到完整字串」的標準做法。若每次迭代都從序列開頭做部分比對，成本會至少隨長度線性增長，再乘上遍歷整個詞彙表的 O(N)。由此引出本文核心問題：如何在 Algorithm 2 每次迭代中高效地依正則／CFG 比對或剖析不完整字串、並決定遮罩 m？
