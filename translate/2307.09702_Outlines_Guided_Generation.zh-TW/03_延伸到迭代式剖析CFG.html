4. 延伸到迭代式剖析（CFG）

轉向一般的剖析器引導生成。以一個 Python 風格 CFG 為例：詞彙表含 "d"、"ef" 等可拼接出 Python 式語法的字串，依 Algorithm 1 逐一取樣拼接。設 CFG 有終結符 DEF（對應字串 "def"，正則 def）與 NAME（Python 識別字，正則 [^\W\d]\w*）。想在取樣時逐步剖析以符合 Python 語法。

難點（迭代式詞法／剖析）：例如序列 ["d","ef"," f","oo(","):"," ","pass"] 拼起來是 def foo(): pass。但在第三步只看到 "def f" 時，傳統詞法／剖析會回傳 DEF NAME，把 "f" 誤判為完整的 NAME——而後續顯示正確的 NAME 應是 "foo"。一般而言，接下來可取的合法字串是：(1) 繼續擴展目前以 "f" 起頭的 NAME，和/或 (2) 以 "("（LPAR，正則 (）開頭、進入合法引數簽名者。

用 FSM 的狀態形式化「部分匹配／子模式」：NAME 的正則 [^\W\d]\w* 可用一個三狀態 FSM M 表示——狀態 0（起始 q₀）、1（[^\W\d]）、2（\w*），其中 1、2 ∈ F（接受態）。對 "f" 套 Algorithm 3 會得到狀態序列 (0,1)、(1,2)、(2,2)：意即 "f" 的匹配可始於狀態 0、1 或 2，並可終於狀態 1 或 2。據此：case 1 表示可在先前停於 1 或 2 後繼續剖析 NAME；case 2 表示下一字串可含 LPAR（意味 M 已終止——因 1、2 是 M 讀完 "f" 後可停的終態；M 終止也代表一個 NAME 完成、文法允許轉移到接受 LPAR 的狀態）。於是這批詞彙中，下一合法字串至少有 "d"、"ef"、"pass"、" "、"oo("（皆能擴展部分匹配的 NAME，最後一個還能推進剖析狀態去讀 LPAR）；而 "):" 會造成非法語法。對應到索引：Algorithm 4 會把 FSM 狀態 0、1、2 都映射到子集 {"d","ef","pass"," ","oo("}（對 NAME 及其 FSM M 而言）。

4.1 下推自動機（PDA）表述

上例略去了「決定哪些文法符號與轉移被允許」的剖析器狀態；本文用**下推自動機（PDA）**擴充 FSM 法補齊細節：

定義 2（下推自動機）：由 6-tuple (Q, Σ, Γ, δ, q₀, F) 給定，Q、Σ、Γ、F 皆有限集，Γ 是堆疊字母表，δ : Q × Σ_ε × Γ_ε → P(Q × Γ_ε)，Γ_ε ≡ Γ ∪ ε，ε 為空字元；其餘符號沿用有限自動機定義。

要為 PDA 驅動的剖析器建索引，需連結「CFG 符號（經對應 PDA 的字母表）」與「產生 PDA 所讀符號的詞法／掃描步驟」。具體地：剖析器由詞法器（lexer）與掃描器（scanner）支援，從字元輸入辨識符號。可為每個剖析／PDA 狀態，依 δ 在該狀態允許的符號與堆疊轉移，構造一份有序終結符清單——這意味可為每個剖析狀態構造一個 FSM，它是「該狀態所讀各終結符對應 FSM 的聯集」。 掃描步驟則對「自上一個完全辨識符號以來所讀字元」辨識出一組可能終結符 V ⊂ Σ（例：Python-like CFG 在起始態 q₀ 掃描 "de" 得 V = {DEF, NAME}——DEF 對應能補全 "def"、且其後接非 NAME-FSM 所讀之字串者；NAME 對應其 FSM 所讀之其他字串）。掃描（及 LLM 取樣）步驟會逐步縮減 V，直到定出單一終結符。

對 V 中每個字串、用各剖析狀態的合併 FSM 套 Algorithm 3，即可決定由「PDA 狀態＋對應 FSM 狀態＋潛在終結符集」構成的剖析器配置。類比 Algorithm 3，用 PDA 轉移映射的原像 δ⁻¹(q, V, ·) ≡ { g : δ(q, v, g) ∈ P(Q × Γ_ε), g ∈ Γ_ε, v ∈ V } 來決定「能讀入這些 PDA 狀態與終結符集的堆疊值」。這些堆疊值用來找出「能讓 V 中各字串從其可能剖析配置完整成功剖析」的 PDA 路徑。對應 LALR(1) 剖析器 REDUCE 操作的狀態×終結符組合，其剖析配置不只含堆疊頂值，而是含「該 REDUCE 所涉全部合法前綴」的子堆疊。最終，每個「允許完整剖析某詞彙字串」的剖析器配置都被加入 PDA 的索引；此時索引須是 trie 資料結構，以便對剖析器堆疊值做查詢。

5. 討論

本文引入的詞彙表索引，移除了引導式生成中令人卻步的執行期縮放障礙。它自然是在「處理 vs 記憶體」之間做取捨，但作者相信平均而言記憶體成本相對低，必要時亦可用常規手段降低。實測中，用稍加擴增的 Python 文法時，即使天真構造（含未使用、冗餘的剖析器與 FSM 狀態配置）、且用未化簡 DFA（含大量冗餘狀態、無謂放大索引）的索引，也僅約 50 MB；若狀態機的精確表述成為問題，可改用記憶體需求更低的其他表述（如 NFA）。

本工作意涵不限於神經文字生成：可用此索引法輔助需結構化輸出的 LLM 訓練／fine-tune（並推測訓練時的輔助生成，可能減少模型學習語法細節的需要）；亦提供評估現有模型的另一途徑（如量化本法遮罩後 logits 與原始 logits 的差異，回饋訓練目標）。此外，或可把本法算出的遮罩「上提（lift）」進語言模型本身——遮罩隱含決定了哪些計算不必進行；目前只在最底層施加遮罩，若把遮罩上提到模型架構更高處，或能在對某些參數切片做無謂運算前就先判定其是否需要，進一步降低計算成本。
