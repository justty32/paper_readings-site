3. 迭代式 FSM 處理與索引（本文核心）

我們用狀態機來框定正則引導生成。此框架能精確指定「正則比對如何被任意開始與停止」，因此能在 s̃ᵢ₊₁ 各次取樣之間輕易且高效地續接，也說明遮罩如何在不對 V 做執行期評估的情況下算出。

正則表達式＝5-tuple 有限自動機（Sipser 定義 1.5）：

定義 1（有限自動機）：一個有限自動機／有限狀態機由 (Q, Σ, δ, q₀, F) 給定，其中 Q 是有限狀態集、Σ 是有限字母表、δ : Q × Σ → Q 是轉移函數、q₀ ∈ Q 是起始狀態、F ⊆ Q 是接受狀態集。

詞彙表 V 中字串的字元取自 Σ（即 V ⊂ P(Σ)）；為簡化，FSM 狀態 Q 以整數表示。此表述讓我們能精確判定：取樣單一詞彙 token s̃ₜ₊₁ 後，引導正則的 FSM 停在 Q 中哪個狀態。這些 FSM 狀態便可在 Algorithm 2 的取樣過程中被追蹤，用以高效續跑狀態機，而不必每次都從成長中序列的開頭重讀。

Example 1（浮點數正則）：以正則 ([0-9]*)?\.?[0-9]*（生成浮點數）為例，令詞彙表僅含 "A"、"."、"42"、".2"、"1"。生成起於 FSM 狀態 0，演算法遮掉 "A"（不被 FSM 接受），此時只能取 "."、"42"、".2"、"1"。若取 ".2"，FSM 前進到狀態 3，此時只有 "42"、"1" 是合法補全，取樣前遮掉其他；若改取 "1"，FSM 前進到狀態 1，此時 "."、".2"、"1" 等為合法、遮罩不變。（圖 1 即此正則的 FSM 遮罩過程。）

核心構造一：把正則編譯成 FSM 後，離線對詞彙表建索引

問題：逐一遍歷詞彙表判斷合法下一 token，仍是最大瓶頸。解法：用正則表達式的 FSM 預處理詞彙表、建立一份索引。關鍵在於——要考慮「從每一個可行 FSM 狀態出發」，因為詞彙表裡的字串可能匹配正則的任意片段，而這些片段隱含地就是FSM 的狀態。

Algorithm 3（find_sub_sequences：找出 FSM M 接受字串 v 所走過的狀態子序列）：

  • 對「能讀入 v 首字元 v₀ 的所有狀態 r」（即 δ⁻¹(·, v₀)，轉移函數在 v₀ 上的原像）逐一嘗試作為起始狀態；
  • 從 r 起沿 δ 逐字元走 FSM（walk）：若某字元 vᵢ 無轉移（δ(r, vᵢ)=∅）就放棄此起始狀態、換下一個；否則把每步到達的狀態附加進路徑 p；
  • 回傳一組子序列，每條記錄「FSM 接受該字串時走過的狀態」。

Algorithm 4（map_states_to_vocab：構造映射 σ）：對詞彙表每個字串 v，用 Algorithm 3 取得其被接受的狀態子序列集合 Z；對每條子序列 z，把 v 加入 σ(z₀)（z₀＝該子序列的起始狀態）。最終得映射 σ : Q → P(V)——把每個 FSM 狀態，連到「在該狀態下會被 FSM 接受的詞彙子集」。

為何是 O(1)：把 Algorithm 2 單步循環最後到達的 FSM 狀態，去對映射 σ 查詢，即可高效取得該狀態下合法的詞彙子集。用雜湊表（hash-map）實作 σ，可使 Algorithm 2 的遮罩步驟平均只花 O(1)。此外，σ 是在 token 取樣程序之外構造，其執行期成本實質上無關緊要——雖然理論上需要正比於 FSM 狀態數 |Q| 的記憶體。所幸對「非病態」的正則×詞彙表組合，並非每個詞彙字串都會被 FSM 接受，也並非每個 FSM 狀態都對應到 V 中某字串，故記憶體通常可控。

3.1 示例（實機）

以 GPT2-medium（355M）配 Outlines 展示正則引導生成：generate.regex(model, r"\s*([Yy]es|[Nn]o|[Nn]ever|[Aa]lways)", ...) 把「1+1=2?」的自由續寫收斂為 Always；r"\s*19[0-9]{2}" 強制生成四位年份（Chomsky 出生年 → 1952）；IP 位址正則 ((25[0-5]|2[0-4]\d|[01]?\d\d?)\.){3}(...) 強制輸出成 IP 格式（如 2.2.6.1）。相對地，未引導版本則自由發散、格式不受控。

3.2 與現行方法比較

為展示索引法效率，與 Guidance 函式庫做簡單比較。撰文當時 Guidance 採部分正則比對——每步都從取樣序列開頭重做，且每步須遍歷 LLM 詞彙表（N = 50,257）。作者用 Guidance 與 Outlines 各自對「產生合法 Python 變數名（正則 [^\W\d]\w*）」計時（用 timeit，單一 loop、單一 repeat，即每個 max_tokens 只取一個樣本）。結果：隨 max_tokens 增加，Guidance 的執行時間顯著攀升（圖示 runtime 隨生成 token 數迅速拉高至上百秒量級），Outlines 幾乎持平。作者聲明：除非有造成大落差的配置疏失，否則此隨「最大取樣 token 數」的縮放差異相當明顯，正指示了該做法內含的計算問題。
