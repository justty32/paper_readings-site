5. 結果與分析

5.1 RQ1：有效性與效率

有效性：Specine 在所有 20 個 subjects 上 Pass@1 與 AvgPassRatio 均為最佳，平均勝過所有 baseline 29.60%∼93.55%（Pass@1）與 27.95%∼79.12%（AvgPassRatio），Wilcoxon p < 2.40×10⁻⁷。

例如在 Gemini-1.5-Flash + APPS 上，最佳 baseline（TGen）的 Pass@1 為 55.67%，Specine 達到 65.33%。

效率：Specine 的時間開銷比所有六個 agent-based baseline 低 22.44%∼39.14%，token 開銷低 9.69%∼46.89%（Wilcoxon p < 1.56×10⁻²）。

5.2 RQ2：迭代數影響

迭代數從 1 增至 10 時，所有 agent-based 技術都有改善，但 Specine 在所有迭代設定下均優於所有 baseline（Pass@1 高 27.29%∼42.86%）。關鍵差異：其他 baseline 在迭代數 ≥3 時趨於平台期，Specine 則持續上升——因為規格提取組件能從新生成的程式碼中持續提取更精細資訊，逐步精煉 LLM 感知到的規格。Specine 在 N=1→10 時 Pass@1 平均提升 47.97%，其他 baseline 僅 13.27%∼45.40%。

5.3 RQ3：消融實驗

建構五個變體：

  • Specine_woPTC：移除公開測試案例
  • Specine_woT：移除 tester agent（只用公開測試案例）
  • Specine_wTF：以測試執行回饋取代規格提取
  • Specine_woA：移除 aligner agent，隨機選對齊規則
  • Specine_woAR：移除十條對齊規則，LLM 自由生成對齊規格

結果：

  • Specine > Specine_woPTC：公開測試案例貢獻 Pass@1 +17.59%
  • Specine > Specine_woT：tester agent 貢獻 Pass@1 +12.41%，且 Specine_woT > Specine_woPTC（+4.27%），驗證階層式通過率的必要性
  • Specine > Specine_wTF：規格提取策略勝過測試執行回饋 Pass@1 +14.75%，證明 lift 資訊比粗粒度測試回饋更有價值
  • Specine > Specine_woA：aligner agent 貢獻 Pass@1 +20.94%
  • Specine > Specine_woAR（效果最差的變體）：十條對齊規則貢獻最大 Pass@1 +34.57%（Wilcoxon p < 1.77×10⁻⁷）

6. 討論

6.1 案例研究

以 CodeContests + Gemini-1.5 為例追蹤迭代過程：(1) 初始 Pass@1 = 0%；(2) 應用 Purpose 對齊規則 → 77.56%；(3) 添加 Input Requirements 規則 → 80.00%；(4)-(5) 多次嘗試無效規則後捨棄；(6) 應用 Hints or Tips 規則（二分搜尋）→ 100%。

6.2 對齊規則影響分析

所有十條規則都對齊了超過 5% 的問題。前三最有效的規則：Examples with Explanations（14.48%）、Specification Purpose（13.54%）、Output Requirements（11.59%）。建議開發者為 LLM 編寫程式設計規格時優先改善這三個方面。

6.3 LLM 生成測試案例的品質

測試案例正確率為 60.17%∼72.92%（vs 標準解），雖有錯誤但正確案例比例超過錯誤案例，透過投票原理（正確程式碼通過較多測試）與階層式通過率（優先公開測試案例）緩解負面影響。未來將引入型別檢查與測試覆蓋率引導 LLM 測試生成。

6.4 DSL 的可擴展性

目前 DSL 聚焦結構化程式設計任務，但其核心原理（將 LLM 生成程式碼抽象為結構化、語義豐富的表示以改善與使用者意圖的對齊）廣泛適用。DSL 設計模組化、可擴展，未來可加入領域特定成分（如前端 UI 佈局約束、資料分析 schema）。未來將探索使用先進 LLM 自動生成新領域的 DSL schema，並以專家知識精煉。

7. 威脅與有效性

  • 建構有效性：LLM 的固有隨機性——三次重複實驗的標準差僅 0.008（Pass@1）與 0.022（AvgPassRatio），Wilcoxon p > 0.55 確認無統計顯著差異。
  • 外部有效性：使用多樣化基準、指標、baseline 與 LLM 緩解，未來將擴展到更廣泛的基準與模型。

8. 相關工作

現有程式碼生成技術分為兩類：（1）Prompt-based——以精心設計的 prompt 提升程式碼生成，包括生成前（Self-planning、SCoT）、生成後（Self-debugging、Self-repair）、混合（μFiX）三種；（2）Agent-based——模擬人類協作開發流程，多代理互動完成任務規劃、程式碼生成與測試（Self-collaboration、AgentCoder、PairCoder）。

Specine 與現有技術正交：可作為前處理模組，在規格進入其他技術前先對齊需求，未來將探索整合以進一步提升效能。

9. 結論

Specine 從軟體需求工程實踐中汲取靈感，提出了一個新穎視角：透過規格對齊提升 LLM 程式碼生成效能。具體包含偏誤規格識別、規格提取、規格對齊三個組件。在 4 個先進 LLM 與 5 個競賽級基準上的全面實驗證明，Specine 在多個評估指標上一致超越 state-of-the-art prompt-based 與 agent-based 技術。
