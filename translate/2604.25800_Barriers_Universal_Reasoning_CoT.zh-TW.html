論文／訪談原始來源

用 Transformer 做通用推理的障礙（及如何克服）

摘要

CoT（思維鏈）經驗上提升 Transformer 表現、理論上把表達力抬到圖靈完備。但 Transformer 是否能學會泛化到比訓練更長的 CoT 軌跡鮮被研究。本文用最新的 Transformer 長度泛化理論框架，發現：在標準位置編碼 + 有限字母表下，配 CoT 的 Transformer 在「可長度泛化學習」這更嚴格要求下無法解 TC⁰ 以外的問題（表達力紅利失效）。但若允許字母表隨問題規模增長，可得「可長度泛化地模擬圖靈機」的構造，CoT 軌跡長度與模擬執行時間呈線性（至多差常數）。此構造克服兩大障礙：重複複製與最後出現檢索——給每個帶位置一個唯一 signpost token，且只記錄值的變化，使當前帶符號可由計數回復。實驗進一步證明 signpost token 與值變化編碼能對困難任務的長度泛化提供可操作的指引。

1 引言

CoT 經驗上提升推理；理論顯示任意圖靈機可被配 CoT 的 Transformer 模擬（無 CoT 則限於 TC⁰）。但這些結果只指出存在這樣的模擬，不保證能從有限 CoT 軌跡學到。實證上 Transformer 準確率隨 CoT 變長急墜（演算法、邏輯、規劃、符號推理皆然），理論上不明白。

本文用 C-RASP（Yang & Chiang 2024；Huang et al. 2025）與 C-RASP*（Sarrof et al. 2026）做兩項互補理論貢獻：

  • 第一關鍵結果：在標準位置編碼 + 有限字母表下，配 CoT 的 Transformer 很可能只在 TC⁰ 內的問題上長度泛化，即使被訓練去做 CoT。證法＝證明任何可在 C-RASP 表達的任務（輸入 + CoT 軌跡）也可在 TC⁰ 定義，強化了 Jiang et al.(2026)「C-RASP CoT 非圖靈完備」的結果。這出人意料——先前工作把 CoT 的成功歸於「超越 TC⁰ 障礙」，但那只對表達力成立，對長度泛化不成立。
  • 兩大障礙：複製任意字串、基於位置的檢索（圖 1）。本文用 signpost token 解決複製限制；用「記錄帶 cell 計算前後值」的新 CoT 方案繞過檢索限制，使各 CoT 步驟可寫進 C-RASP*（無限字母表）。
  • 第二關鍵結果：若 (a) 允許無窮的 signpost 符號字母表、(b) 把圖靈機計算以正確方式編進 CoT，則 Transformer 可可長度泛化地學會模擬任意圖靈機。

實證上：從零訓練的 Transformer 在 Parity、Boolean Evaluation、Permutation 上不長度泛化，但「隨實例規模增長的 signpost 符號庫 + 值變化格式」能提升之；這些洞見也改善預訓練 LLM（Qwen2.5-7B、Mistral-Small-24B、Llama-3.3-70B）的提示表現。核心訊息：圖靈完備不被保證，而是高度依賴 CoT 的具體格式；把 CoT 格式的可學習性納入考量，能造出真正兌現底層計算力的方案。

2 背景

  • 2.1 相關工作：大量文獻顯示 CoT 本身不保證長度泛化（性能隨長度急墜）；但 CoT 的形式很重要——加 padding、改 scratchpad 格式、更結構化中間表示或特定位置編碼，都能改善長度泛化（甚至 parity）。本文的 signpost token 構造受 index hints 啟發並推廣之，並理論解釋了 index hints 為何有用。先前圖靈完備構造多談表達力（能被硬編去模擬），不談學習性。
  • 2.2 預備：C-RASP、C*-RASP（以 C 為 signpost token 字母表，membership 亦可在其中表達）、Limit Transformers。

3 理論

  • 3.1–3.2 負面結果：C-RASP[Pos] 可表達的任務屬 TC⁰（定理 3.4，與 CoT 長度無關）；當 L 不在 TC⁰ 時，理想化學習模型下長度泛化在無窮多個 n 上失敗（引理）。
  • 3.3 正面構造：輸入 w 先以 signpost token 標註（Annotate(w) 交錯插入每 token 的唯一路標）。圖靈機模擬中：
    • (A.1) signpost token：每個 cell 配唯一定址路標，繞過「需任意定址/檢索先前所寫帶位置」這個不長度泛化的問題。
    • (A.2) value-change encoding：即便有路標，「從 CoT 軌跡回復 cell 最新內容」仍是非唯一檢索問題（無長度泛化解）；故只在有變化時記錄「新值相對舊值」，當前值由「比較各符號對之間的變化計數」算出，同時繞過兩障礙。
    • 結果：可把 CoT 步驟編進 C*-RASP，得到「CoT 軌跡長度線性於模擬執行時間」的可長度泛化圖靈機模擬。

4 實證驗證

  • 4.1 從零訓練：三任務 Parity、Boolean Evaluation、S5 Permutation。模型＝GPT-2 + APE，6 層、8 頭、dim 512、25M 參數，去偏置與正規化、去 layer-1 MLP、因果遮罩，AdamW lr=1e-3、weight decay=2e-2，自訂逐任務 whitespace tokenizer，訓練最大長 30/50。為 APE 泛化用隨機 offset 訓練 OOD 位置編碼，並對 signpost token 套類似 offset 技巧（Sarrof et al. 2026）。ID 驗證集 1000 樣本（長度 1..max_train），OOD 測試集 500 樣本（長度 max_train+1..2×max_train）。
    • 結果（圖 4）：PARITY 上 value-change 編碼穩健泛化到 2 倍長、樸素 CoT 失敗；S5 與 Boolean Evaluation 上加 signpost token 帶來顯著改善；S5 僅泛化到約 1.7 倍訓練長（疑有捷徑使其較難），但仍大幅勝過無 signpost 版。
  • 4.2 預訓練 LLM 提示：把 signpost / value-change 洞見用到輸入與 CoT 的格式（B.1 按布林公式後序遍歷放路標；B.2 把變數多次賦值的變化記在註解中以助判最終值），改善多尺寸 LLM 表現。

5 與既有工作對比 / 結論

本文有別於僅談表達力的圖靈完備構造，強調學習性 + 長度泛化。結論：CoT 的圖靈完備不被自動保證，取決於格式；signpost token 與 value-change logging 能在格式化輸入與 CoT 上帶來實際好處——可能解釋了既有 CoT 方法為何在長度泛化上受限。
