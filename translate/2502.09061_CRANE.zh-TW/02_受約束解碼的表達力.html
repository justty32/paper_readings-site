3. 受約束解碼的表達力

先證明任何常數層 LLM 在受約束解碼下都會損失表達力。作者找出一類問題與對應輸出文法 G，使得對任何常數層 LLM 施加此約束後，除非基礎複雜度類崩塌（如 TC⁰≠NL 被推翻，NL 為非確定對數空間），否則問題無法被解。

3.1 受約束解碼的限制

考慮輸出數有限的問題，其所有可能輸出集 O 可表為簡單正則語言，故存在文法 G_c 使 O=L(G_c)。例如任何判定型問題（yes/no）——如 st-connectivity（問有向圖中 t 是否從 s 可達）——只需單位元輸出 L(G_c)={0,1}。這意味著在 G_c 約束下，對任何輸入 LLM 都只被允許單一自回歸步。

一系列既有工作證明：在適當假設下，任何常數深度 LLM 對長度 n 輸入的單一自回歸步可表為常數深度電路。因判定型問題只允許單步，LLM 只能解對應電路類內的問題。作者建基於 Merrill & Sabharwal（2023）最新結果——常數層 LLM 對長度 n 輸入的單一自回歸步可被 logspace-uniform 常數深度閾值電路族模擬（允許用 log(n) 精度浮點數，稱 log-precision LLM）。

  • 命題 3.1：對任何常數層 log-precision LLM ℒ，存在 logspace-uniform 閾值電路 Th_n，使 ℒ_{G_c}(x)=Th_n(x) 對所有長度 n 輸入成立。（證明見附錄 C。）

由命題 3.1 得：任何判定型問題在受約束解碼下，LLM 只能解 logspace-uniform TC⁰ 類（常數深度閾值電路）內的問題；被普遍認為在此類之外的問題便解不了。而 st-connectivity 已知為 NL-complete，故除非 TC⁰=NL，否則受約束 LLM 無法解 st-connectivity。

  • 引理 3.2：對任何帶字母 Γ 的圖靈機 M，存在常數深度、log-precision 的 LLM ℒ_M（Γ⊆V_M）能用 t(n) 個自回歸步模擬 M 的 t(n) 步（t(n) 為 n 的多項式）。（證明依 Merrill & Sabharwal 2024 定理 2。）

命題 3.1 與引理 3.2 合起來說明：存在像 st-connectivity 這樣的問題，LLM 在無約束下能解、在受約束下卻不能解（除非 TC⁰=NL）。這正是 RQ1 的形式化回答：是的，限制型文法確實會讓 LLM 失去推理力。

3.2 以擴增文法進行推理

命題 3.1 的表達力下降主因是：所有合法輸出串的語言 L(G_c) 太受限、容不下（非常數長度的）推理鏈。因此自然要問：能否用額外產生規則把任意輸出文法 G 擴增成 G_a，使其既能容納推理步驟、保住 ℒ 的表達力，又保持非平凡（不接受所有字串、不退回無約束）？

作法是強制擴增文法固定為結構 G_a → R G：非終端符 R 捕捉推理步驟、G 表最終輸出。這保證任何 s∈L(G_a) 都能拆成 s=r·a，其中最終答案 a∈L(G)（原輸出文法）、r 為導向最終輸出的推理序列。

形式上證明：對任何圖靈機 M 與含 M 所有合法輸出的文法 G，存在常數層 log-precision LLM ℒ_M 與上述格式的擴增文法 G_a，使 ℒ_M 能在 G_a 約束下用 t(n) 步模擬 M 的 t(n) 步。

具體構造：ℒ_M 在每步計算 M 組態 γ_i 的編碼 γ̄_i 並存入輸出的推理部分（串 r），依 M 的轉移函數逐步生成下一組態編碼、附加到推理序列，直到 M 停機才產出最終答案 a∈L(G)。由於狀態集 Q、帶字母 Γ、帶數 k 皆為常數，所有可能組態編碼的集合 Γ̄={γ̄_(1),…,γ̄_(l)} 有限可枚舉。於是定義擴增文法規則：

G_a → R_M G；R_M → S R_M；S → γ̄_(1) | … | γ̄_(l)

即 L(R_M) 是定義在組態編碼 Γ̄ 上的正則語言。輸出 ℒ_{G_a}(x) 為完整的推理增強序列 γ̄_1 … γ̄_{t(n)} · M(x)。

  • 命題 3.3：對任何帶字母 Γ 的圖靈機 M，存在常數深度 log-precision LLM ℒ_M（Γ⊆V_M），使對任何長度 n 輸入 x（M 在 t(n) 步內停機），ℒ_{M,G_a}(x)=r·M(x)（r∈V_M*）。（證明見附錄 C。）

這回答 RQ2：擴增文法能救回表達力——約束不必致命，只要留出推理空間。

4. CRANE 演算法

命題 3.3 雖證明「在擴增文法 G_a 上對特定 LLM ℒ_M 做受約束解碼能模擬 M」，但無法直接變成實用演算法：該構造假設了特定 LLM（詞彙 V_M）與已知的特定圖靈機 M（用來定義規則 R_M）。實務上需要能套用到多樣開源 LLM、各種文法、不同受約束解碼演算法的高效方法。

關鍵洞見：從一開始就施加輸出文法 G 會限制表達力，因此要判斷性地施加約束以免限制推理。對形如 γ̄_1…γ̄_{t(n)}·M(x) 的推理增強輸出，只從第 t(n)+1 步（即最終答案）起才施加約束，讓推理過程不受限、只有最終答案遵守文法。

主要挑戰：何時在「無約束推理生成」與「受約束生成」之間切換。像 Python 這類通用程式語言的文法允許開頭是任意字串（如變數名），難以偵測推理串何時結束。解法：用特定分隔符 S₁（開始）、S₂（結束）標記受約束生成的起訖，並靠 prompt 的明確指示與 few-shot 範例誘導 LLM 生成分隔符。這與常見通用 LLM 已用的分隔符一致（如 ``` 包 Python/SQL、<< >> 包數學運算式塊）。於是生成 r·S₁·M(x)·S₂：推理 r 無約束生成，見到 S₁ 進入受約束模式；因分隔符在中間步驟可能多次出現，見到 S₂ 即切回無約束以免不必要地限制輸出。

（圖 2：CRANE 依起訖分隔符 <<、>> 動態追蹤哪些「視窗」該施加約束，在受約束與無約束生成間自適應切換。）

演算法 1（CRANE）要旨：輸入任意 LLM、受約束解碼器 CSD、輸出文法 G、分隔符 S₁／S₂。先用 G'=S₁ G S₂ 初始化 CSD。從無約束生成起，維護一個指標標記「上次受約束生成後、當前生成視窗的起點」。每輪：

  • 取當前視窗 currGen（指標之後的序列）；若 S₁∈currGen 則設 isConstrained=True，否則 False。
  • 若受約束：抽出當前受約束視窗（currGen 中屬 G' 的部分），依 CSD 的約束遮罩取樣下一 token（t_i ∼ LLM(tokens)⊙CSD(constrained)）；否則直接無約束取樣（t_i ∼ LLM(tokens)）。
  • 附加 t_i；若為 EOS 則結束。
  • 若受約束且當前受約束串以 S₂ 結尾，把指標更新到當前 token 序列長度（切回無約束，直到再次生成 S₁）。

此設計簡單、成本高效，且相容於各種受約束解碼器。
