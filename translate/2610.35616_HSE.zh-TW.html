論文／訪談原始來源

HSE：程式代理的階層式技能演化

來源身分註記。 同一 arXiv ID／v1 的 摘要頁 題名為 Coding Agent，HTML 內文題名為 Coding Agents；摘要頁中 Shiyang Zhang Yuhua Zhou 與 Baian Chen Weiyi Shang 各被記為一名作者，HTML 內文則將每組分列兩名。兩處摘要與方法一致，本檔依 HTML 內文署名，未判定哪一處正確。（HTML 原文）

摘要與第 1 節：研究問題

程式代理的執行軌跡包含搜尋、編輯、測試與修復，但常混有任務專屬路徑與補丁細節。Hierarchical Skill Evolution（HSE）將這些軌跡逐層彙整成可重用的程序與失敗恢復技能。外部 writer–evaluator 迴圈持續調整技能與建構規則，底層程式模型保持凍結。（摘要與 §1）

第 2–3 節：背景與問題設定

作者將 HSE 與軌跡檢索、反思、工作流記憶、技能合成及提示最佳化比較。每個任務由 issue、repository 快照和執行環境組成；代理的工具互動形成軌跡。HSE 在模型外保存技能庫、writer 規則和 evaluator 規則：程式代理接收技能，外部控制器依規則建構及篩選新技能。（§2、§3）

第 4 節：三層證據與技能演化

L1 從單題軌跡整理重現、定位、編輯、驗證、恢復五階段，訓練時加入驗證器結果。相鄰輪次由失敗轉成功或由成功轉失敗，分別構成較強的正或負證據；連續成功或失敗為較弱證據，首輪沒有配對結果時也保守視為弱證據。（§4.1）

L2 彙整同一 repository 的任務記錄。候選需至少兩個正向任務記錄及重複出現的路徑或測試指令等訊號；writer 制定觸發條件、證據門檻、行動、驗證與停止條件，evaluator 依支持度、範圍及風險接受、要求修訂或拒絕。強負證據阻止提升。（§4.2、附錄 B）

L3 跨 repository 彙整：程序技能來自重複支持的成功模式，恢復技能來自反覆出現的失敗徵兆與修正行動。移除特定 repository 識別資訊後，仍保留可觀察證據門檻及驗證程序，避免將歷史補丁當作當前任務的答案。（§4.3）

訓練中，外部 writer 規則根據累積證據作有界變更；evaluator 以證據特徵加權評分，根據先前提升與後續結果調整權重，接受與修訂門檻保持固定。技能庫和更新規則一起構成提案狀態，先在保留的驗證任務評估；拒絕時保留已接受版本。（§4.4–4.5、附錄 B）

靜態推論只將凍結技能庫交給代理，沒有使用目標 benchmark 軌跡更新技能。目標 benchmark 適應則從轉移的技能庫與固定 writer／evaluator 規則出發，用目標任務軌跡更新技能庫；候選評估不讀取目標 verifier 結果。（§4.6）

第 5.1 節：靜態技能轉移

作者從 SWE-Gym 取樣 500 題，其中 474 題、10 個 repository 用於訓練，bokeh/bokeh 的 26 題為保留驗證集，兩者 repository 不重疊。得到的技能庫有八個程序技能、兩個恢復技能；靜態測試不使用目標軌跡建構或更新技能。（附錄 E.1–E.2）

作者以 GLM-5.2 比較 Pi 與 Claude Code（CC）代理框架，評估 SWE-bench Verified 500 題及 DeepSWE 113 題。下表為作者自報的三次完整執行平均解題率與樣本標準差；成功以 benchmark verifier 判定。（§5.1，表 1）

基準／框架 無技能 靜態 HSE
SWE-bench Verified／Pi 73.5±1.10% 75.4±0.20%
SWE-bench Verified／CC 76.1±1.30% 80.6±0.20%
DeepSWE／Pi 43.1±2.23% 48.7±0.88%
DeepSWE／CC 44.8±3.11% 52.5±0.51%

HSE 在這四組平均值中高於測試的其他技能基線；這些標準差來自三次執行，不能單憑數字推定所有任務或模型皆有相同增益。（§5.1）

第 5.2 節：目標 benchmark 適應

作者自報 GLM-5.2 在八輪適應後，SWE-bench Verified 的 Pi／CC 從 75.4%／80.6% 升至 90.1%／93.9%，DeepSWE 從 48.7%／52.5% 升至 71.7%／75.8%。每輪對整個目標 benchmark 執行後再更新技能，評估也在同一完整目標題集進行；目標 verifier 結果只用於報告解題率，不回饋 writer 或 evaluator。這是對目標題集的重複適應，不是適應後在獨立未見題集上的泛化測試。（§5.2，表 2、附錄 E.2）

第 5.3–5.4 節：元件與轉移

作者移除程序技能或恢復技能時，四組設定的解題率都下降。DeepSWE 上移除恢復技能的下降為 Pi 5.3、CC 5.6 個百分點；作者推測困難任務更常需要恢復指引，這是解釋而非直接證明的機制。（§5.3，表 3）

破壞 repository 分組的消融將相同軌跡隨機打散；另一消融保留階層但凍結初始 writer 與 evaluator 規則。兩者的解題率均低於完整 HSE，但後者同時移除兩種控制規則的更新，無法單獨識別 writer 或 evaluator 的貢獻。（§5.3，表 4）

跨模型實驗只使用 Pi。作者報 GPT-5.5 的無技能／HSE 解題率在 SWE-bench Verified 為 82.6%／85.4%，DeepSWE 為 67.2%／73.5%；Opus 4.8 分別為 88.6%／90.2% 與 59.3%／61.1%。跨框架及跨模型結果限於所測技能包與環境。（§5.4，表 5–6）

第 6 節：限制與結論

作者指出實驗涵蓋兩個 benchmark、兩個代理框架和三個模型；跨模型評估只有 Pi，控制器消融將 writer–evaluator 更新作為一體。HSE 的證據支持在這些設定下轉移文字技能及利用目標軌跡適應；未證明在所有 repository、模型或新的獨立任務上都能持續改善。（§6）
