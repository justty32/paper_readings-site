3. 評估

3.1 推理任務

作者先在推理基準上驗證 RCI 的效果，與 CoT 比較：包括 Few-Shot-CoT 與 Zero-Shot-CoT（加上「Let's think step by step」）。依 Kojima 等人的設定，用兩類共 8 個資料集（算術與常識），底層模型改為 InstructGPT-3+RLHF（gpt-3.5-turbo），沿用 CoT 的 prompt、答案抽取與清洗方式。

最大 RCI 迴圈數設為 2，且一旦輸出與真值一致就停止迴圈。作者明言：若缺少這個外部回饋機制，RCI 容易產生「偽陰性批評」，反而導致效能下降——實驗顯示沒有外部回饋的 RCI 在一半基準上只達到零樣本水準，其餘則更差（附錄表 17）。

與零樣本比較（表 1）：Zero-Shot → Zero-Shot+RCI 在八個基準上全面提升——GSM8K 77.95→85.43、MultiArith 94.48→97.64、AddSub 88.58→89.76、SVAMP 80.70→84.65、SingleEq 86.61→94.49、AQuA 60.23→67.32、CommonSenseQA 64.56→68.11、StrategyQA 48.81→61.81。值得注意的是，RCI 連在不需要多步推理的 SingleEq 與 AddSub 上都有增益，這點與 CoT 類方法不同（CoT 在簡單推理任務上通常無用）。此外 RCI 在常識推理上增益顯著；Wei 等人曾指出只有 540B 的 PaLM 才能從 Few-Shot-CoT 受益，而 RCI 用 175B 的 InstructGPT-3+RLHF 就有增益。

與 CoT 比較（表 2，算術任務）：Zero-Shot+RCI 在五個任務中有四個勝過 Zero-Shot CoT 與 Few-Shot CoT（例外是 MultiArith，該任務標準 prompting 已有 96.06% 正確率，改進空間有限）。RCI 與兩種 CoT 基線有綜效：Zero-Shot CoT+RCI 與 Few-Shot CoT+RCI 在五個任務中的四個取得最高分（Few-Shot CoT+RCI：GSM8K 84.25、MultiArith 99.21、AddSub 90.55、SVAMP 87.40、SingleEq 93.70）。作者建議未來把 RCI 與 self-consistency 等方法結合。

3.2 電腦任務

3.2.1 設定

MiniWoB++ 基準。 MiniWoB++ 是 MiniWoB 的擴充，為網頁式模擬環境，涵蓋從單純按鈕點擊到需要進階推理（如解數學題）的複合任務。動作空間有兩類：打字（任意字元或 Backspace、Enter 等特殊鍵）與滑鼠移動點擊（與可見 HTML 元素互動）；所有動作都透過在初始 prompt 中以正規表示式定義的自然語言指令執行。與先前工作不同的是，打字動作不採用字典式（從預定義文字清單中挑選），而是要求 agent 預測正確的輸入文字，因此對多樣電腦任務的泛化能力更好。狀態空間僅由 HTML 原始碼構成。

模型選擇。 使用 GPT-3（davinci）、InstructGPT-3（text-davinci-002）、InstructGPT-3+RLHF（gpt-3.5-turbo、gpt-4）。主要評估以後者為主，前兩者用於消融。所有模型皆透過 OpenAI API 取得（2023 年 1 月至 3 月間），最大 token 長度 256、temperature 0（貪婪解碼）。

評估任務。 採用 55 個任務以便與基線公平比較，並特意納入需要自由形式文字輸入、先前工作成功率幾近為零的困難任務（如 terminal）；部分常見任務因 UI 元件的 HTML 過長而被排除。

評量指標。 沿用成功率（獲得正向獎勵的 episode 比例）。失敗模式有二：產生無法執行的動作（在隱式 RCI 步驟後仍不可執行則立即失敗），以及計畫執行完畢卻未完成任務。

圖 4 要旨：(a) 與基線的平均表現比較，RCI agent 在 MiniWoB++ 上達到 state-of-the-art；(b) 表現與專家訓練資料量的關係，本方法在使用最少資料的情況下達到與現有最佳分數相當的表現。

3.2.2 在 MiniWoB++ 上勝過基線

結果較用 12K 條專家示範微調的 WebN-T5-3B 高出 41%；也勝過需要多一個數量級環境互動的 RL 方法。所有基線中唯一整體勝過本方法的是 CC-Net（RL 與模仿學習共同訓練），但 CC-Net 在部分任務使用字典式打字動作（從預定義清單挑文字），與本文完全生成式的做法不可直接比較；與 CC-Net（去除字典式動作） 這個對等比較對象相比，本方法高出 6%。

按類別彙整各任務最佳表現後：本方法較 SL 的 SotA 高 37 個百分點、較 RL 的 SotA 高 27 個百分點；即使對手（LLM 類 SotA）同時使用微調與 prompt 中的少樣本範例，RCI 仍勝出。相較同時使用大量專家資料與線上互動的 SL+RL 合併 SotA，本方法也些微領先（不到 1 個百分點）。

觀察到三類主要失敗模式：(i) 需要長程規劃的任務表現較差（guess-number、search-engine、use-spinner）；(ii) 需要多步推理時難以選擇適當動作（tic-tac-toe、use-autocomplete）；(iii) 依賴 HTML 視覺渲染才能解的任務分數較低（count-shape）。

3.2.3 最低的樣本複雜度

CC-Net 使用 240 萬條專家示範（相當於 6,300 小時，由 77 位人類參與者在 104 個任務上收集）做行為複製，平均每任務 23,076 條；WebN-T5-3B 使用 12,000 條專家示範微調 T5。相對地，本方法不更新任何參數，只把 2～3 條示範放進 prompt 做 in-context learning 來偏置模型輸出，因此能以極少示範泛化到未見任務。結果是：成功率高於所有基線，而所需樣本較 WebN-T5-3B 少 120 倍、較 CC-Net 少 11,000 倍。

3.2.4 接地的消融

作者分別移除三個階段的 RCI prompting：任務接地消融＝移除計畫採樣階段，直接由狀態產生動作；狀態接地消融＝直接把 agent 接地更新套用在任務接地動作上；agent 接地消融＝讓狀態接地動作直接成為最終輸出。任務依難度分三級（easy [0.9,1]、medium [0.6,0.9)、hard [0,0.6)）。

結果顯示每一種接地都不可或缺，且三者對整體成功率的貢獻幾乎相等；部分原因是三種接地並非互斥而是互補，一種接地的改進會同時嘉惠其他接地（附錄 E 有跨接地改進的實例，例如狀態接地順手刪掉計畫中多餘的打字指令、或補回被漏掉的標點）。此外：狀態接地在初始狀態資訊不足的情境（如 terminal）特別關鍵；任務接地在需要長程動作計畫的任務（如 click-checkboxes-large）大幅提升成功率；agent 接地顯著提升動作的可執行性——即使在簡單任務上，移除 agent 接地也會讓成功率下降 60%。這點尤其重要，因為先前工作是靠額外訓練的模型元件來做接地，本文則完全仰賴語言模型自身的推理能力。

3.2.5 語言模型的消融

比較 GPT-3、InstructGPT-3、InstructGPT-3+RLHF（gpt-3.5-turbo）在不同難度任務上的平均成功率。結果顯示未經指令微調的 LLM 難以有效完成任務；作者認為這可能與缺少精細的 prompt engineering 有關，因為觀察上 GPT-3 對 HTML 程式碼、正規表示式與推理本身其實具備足夠理解力。

4. 局限

  • 主要聚焦 InstructGPT-3+RLHF（gpt-3.5-turbo、gpt-4），RCI 對其他模型的泛化能力尚未探索。
  • 長 HTML 難以處理：現行模型難以應付龐大的 HTML 狀態；雖有人建議剪除非關鍵元素，但這件事本身並不簡單。LLM 的脈絡長度限制是根本約束，可能需要架構調整或新的解析方法。
  • 動作空間主要限於點擊與打字，限制了網頁導覽能力，需要更多元的動作。
  • agent 只顧短期決策，忽略了長期策略的必要性，對需要協調序列的任務尤其不利。
  • 現代網站複雜的 UI 元件難以僅由 HTML 完整理解，凸顯在狀態定義中加入更多模態的需求。
