論文／訪談原始來源

Tycho：主動抽象與程式世界模型

摘要

ARC-AGI-3 要 agent 在未知互動世界中以少量動作取得技能。Tycho 從互動證據構造能執行、可檢驗的程式世界模型，並將「要不要建、修、用這個模型」本身列為決策。模型會在行動前模擬，驗證器則檢查預測、覆蓋率與終局；實驗顯示選擇性使用模型能改善效率，但預測轉移正確並不等於能更好地完成遊戲。

1. 引言

每個轉移同時是證據與動作預算支出。作者稱此為 active abstraction：從少量、昂貴的觀察製成可測的模型，並判斷測試模型值不值得。程式模型能重播、修訂、模擬反事實和定位錯誤；但通過既有轉移不代表能泛化，也不代表模型的目標推論正確。

2–3. 形式設定

環境是 deterministic Moore machine：狀態與輸入決定唯一後繼，render 把狀態變成畫面，然而畫面可能遺失隱藏狀態。外層 protocol 定義關卡、reset、成功與失敗。模型可對某些畫面格輸出未知；因此評估必須同時問「已預測格對不對」與「預測了多少」，不能用部分正確覆蓋全部。

4. Tycho

task memory 保存原始觀察、動作、結果、假說及其測試。LLM 產出包含狀態、轉移、render、outcome 的自由格式可執行假說；verifier 以 recorded evidence 重播。規劃從當前 threaded state 模擬，不確定時可改做鑑別假說的探測。

metareasoning 管理四項選擇：actor 直接做、actor 自建模型、委派 builder、或在 coverage 不足、轉移不符、outcome 不一致、新關卡／致命 reset 時重建。委派不把環境控制權交出，仍由 actor 行動。這讓「模型何時有用」成為可被 trace 與反駁的系統行為。

5. 評估

作者在 25 個公開遊戲（183 關）比較四種 Opus policy。主要分數為官方 mean game RHAE；另報完成遊戲／關卡、scored actions 與人類 first-run replay midrank。模型診斷用 action 前版本計算：可執行率、accepted transition match、prediction coverage、terminal recall／false positive 與建議是否被原樣採納。

無模型、single、orchestrator、trigger 的 RHAE 是 79.07、85.36、88.49、83.07；完成遊戲為 19、19、21、18。orchestrator 最佳。trigger 的預測 match 較高，卻有更多 builder call、推理成本，且較少完成關卡。結果否定「更精確的轉移模型必然帶來更強玩法」：目標辨識、建模時機及採用建議的方式同樣關鍵。

限制與結論

這是固定基準、固定設定下的人類參與式開發成果；五個遊戲曾參與 harness 開發，且每個報告配置只跑一個 stochastic run。動作效率不含 inference 成本，且 RHAE cap 會掩蓋頂端差異。本文可取的是驗收方式：把模型精確度、coverage、終局判斷與任務績效拆開，讓世界模型的失敗可見，而不要把「有模型」當成功。
