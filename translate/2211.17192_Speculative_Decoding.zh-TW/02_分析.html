3. 分析

3.1 產生的 token 數

分析對目標模型串行呼叫次數的縮減，等價於 Algorithm 1 單次期望產出的 token 數。定義接受率 β_{x_<t}（Definition 3.1）：給定前綴，經 speculative sampling 接受 xₜ∼q 的機率。若簡化假設各 β 為 i.i.d. 並令 α = E(β)，則單次產出的 token 數是一個「成功機率 1−α、上限 γ+1」的截斷幾何變數，期望為：

E（產生的 token 數） = (1 − α^{γ+1}) / (1 − α)　……(1)

（見圖 2：期望 token 數隨 α 與 γ 增大。）

3.2 計算 α

定義散度 D_LK(p,q) = Σₓ|p(x)−M(x)|（M(x)=(p+q)/2）。Lemma 3.3：D_LK(p,q) = 1 − Σₓ min(p(x), q(x))。由此：

  • Corollary 3.4：D_LK 是 [0,1] 上的對稱散度；=0 ⇔ p=q，=1 ⇔ p、q 支撐不相交。
  • Theorem 3.5：β = 1 − D_LK(p,q)。
  • Corollary 3.6：α = 1 − E(D_LK(p,q)) = E(min(p,q))。實驗中的經驗 α 見表 3。

3.3 Walltime 改善

i.i.d. 假設下，演算法把對目標模型的呼叫次數縮減 (1−α^{γ+1})/(1−α) 倍。推測執行（含本法）假設有足夠算力支撐提高的並行度（§3.4）；walltime 分析假設可平行跑 γ+1 份 Mp 而不增加 walltime，再計入近似模型 Mq 的成本。

定義成本係數 c（Definition 3.7）＝跑一次 Mq 對跑一次 Mp 的時間比。注意 α 是模型與任務的固有性質，而 c 取決於硬體與軟體實作。實驗中 Mq 通常比 Mp 小兩個數量級，c 恆小於 0.05，且常接近 0。

Theorem 3.8（總 walltime 期望改善因子）：

(1 − α^{γ+1}) / [(1 − α)(γc + 1)]

（證明：每次 Algorithm 1 花 Tcγ+T（Mq 跑 γ 次、Mp 跑 1 次），依 (1) 平均產出 (1−α^{γ+1})/(1−α) 個 token，故每 token 期望成本 (cγ+1)(1−α)/(1−α^{γ+1})·T，除以標準解碼每 token 成本 T 即得。）此定理假設生成夠長（因至少要跑一次 Mp，改善因子被生成 token 數所限）。

直覺：α（接受率）越高、c（近似模型相對成本）越小，加速越大。

  • Corollary 3.9：若 α > c，必存在某 γ 帶來改善，且改善因子至少 (1+α)/(1+c)。

3.4 算術運算量

Algorithm 1 平行跑 γ+1 份 Mp，故並行算術運算量增為 γ+1 倍；由於每次最多產出 γ+1 個 token，總運算量可能高於標準解碼。接受 Mq 的猜測時，提高的並行度是「免費」的（總運算量不增）；拒絕時則浪費運算。定義 ĉ 為 Mq 對 Mp 每 token 的運算量比，Theorem 3.11：總運算量期望增加因子為 (1−α)(γĉ+γ+1)/(1−α^{γ+1})。α 越低、運算量增幅越大，反之亦然。

值得注意：與運算量相反，總記憶體存取量反而可能下降——目標模型的權重與 KV cache 每次 Algorithm 1 只需讀一次，故其記憶體存取量縮減 (1−α^{γ+1})/(1−α) 倍。這正呼應「大模型推論常卡在記憶體頻寬」的觀察。

3.5 選 γ

給定 c 與 α（並假設算力充足），最佳 γ 即最大化 Theorem 3.8 的 walltime 改善式者；γ 是整數，可數值求解（見圖 3）。由於各 β 並非常數，若能預測 β 並在執行中動態調整 γ，可再改善：若有 γ 的 oracle，則 E（產生 token 數）=1/(1−α)；對典型 c、α 且算力無上限時，動態 γ 的加速可比固定 γ 再高約 60%（留作未來工作）。

3.6 近似模型

speculative sampling（因而 speculative decoding）對任意近似模型 Mq 皆保證輸出分佈相同、無任何限制（附錄 A.1）。實驗多用現成、與 Mp 同架構、同機率標準化的小 Transformer；此設定下取 Mq 約比 Mp 小兩個數量級通常最佳，能在 α 與 c 間取得平衡。

表 1 / 圖 4（假設 c=ĉ=0）展示速度與運算量的取捨，例如：α=0.7、γ=3 → 速度 2.53X、運算量 1.58X；α=0.9、γ=10 → 速度 6.86X、運算量 1.60X。

零成本近似模型（c≈0，如 n-gram 只需查表）：期望 walltime 改善為 (1−α^{γ+1})/(1−α)，上界為 1/(1−α)。有趣的是即使是 trivial 的 n-gram，經驗上 α 也非零——例如英德翻譯用 T5-XXL 11B 當 Mp、trivial bigram 當 Mq，得 α≈0.2，γ=3 時帶來 1.25X 加速。其他零成本啟發式（如摘要或聊天這類長序列易重複的情境，直接從上下文複製匹配前綴）也可能給出高 α。非自迴歸模型亦可作 Mq（此時 Algorithm 1 的自迴歸迴圈換成呼叫一次非自迴歸模型）。連「隨機選 token」的近似模型都能保證某種（雖極小的）改善。

4. 實驗

4.1 實測 walltime 改善

實作本演算法並與 T5X 對 T5-XXL 的加速實作比較。設定：標準 encoder-decoder T5 v1.1，兩項任務——(1) 英德翻譯（WMT EnDe 微調）、(2) 文本摘要（CNN/DM 微調）；兩者皆用 T5-XXL（11B）當 Mp。近似模型 Mq 測 T5-large（800M）、T5-base（250M）、T5-small（77M），全用現成 checkpoint。在單張 TPU-v4、batch=1 上，量測 argmax（temp=0）與標準抽樣（temp=1）。

結果（表 2）：T5-small（77M）在 c 與 α 間平衡最佳、加速最高。α 隨近似模型變大而升高；argmax（temp=0）的 α 與 walltime 改善都比 temp=1 高。翻譯任務加速 2.6X（temp=1）/ 3.4X（temp=0），摘要任務略低 2.3X（temp=1）/ 3.1X（temp=0）。經驗結果與理論預測吻合良好（表 4 比較理論 EXP 與實測 EMP，差異來自實作最佳化差異與 β i.i.d. 的簡化假設）。

4.2 經驗 α 值

雖只為 T5 完整實作加速，但作者在多種任務 / 抽樣法 / Mp / Mq 上量測 α（依 Corollary 3.6，對 Mp 生成的 10K token 估計期望）：

  • GPT-like（97M，lm1b 無條件生成）：Mq=GPT-like 6M 時 α≈0.88（T=0）/ 0.89（T=1）；Mq=unigram/bigram 則 α≈0.03–0.05。
  • T5-XXL（11B，EnDe / CNNDM）：Mq=T5-large/base/small 時 α 約 0.53–0.82；unigram/bigram 約 0.07–0.23。
  • LaMDA（137B，對話）：Mq=LaMDA 8B/2B/100M 時 α 約 0.57–0.75。

觀察：比 Mp 小兩個數量級的近似模型，α 多落在 0.5–0.9；分佈越尖銳（如 argmax）α 越高；連 trivial 的 unigram/bigram 也有不可忽略的 α（如 EnDe 的 bigram α=0.2、c=0 → 1.25X 加速，對如此 trivial 的模型意外地高，但仍低於用 T5-small 的加速）。

5. 相關工作

大模型推論效率已被廣泛研究。許多技術試圖對所有 token 一律加速：蒸餾、稀疏化、量化、架構修改。更接近本法的是自適應計算（依問題難度調整計算量，如注意力子集、early-exit）。其中 Wisdom of Committees 也利用現成小模型，但屬自適應計算、用啟發式決定何時停止，因而失去「輸出與目標模型相同」的保證。一般而言，自適應計算法通常同時省下推論時間與運算量，但需改架構、改訓練、訓練客製模型，且通常改變輸出。

兩個先前方法也用推測執行加速自迴歸解碼：Blockwise Parallel Decoding（Stern et al. 2018）平行解碼數個 token，但只支援 greedy（temperature=0）、需額外訓練客製模型、且以保留下游任務品質為目標而非保證輸出相同；Shallow Aggressive Decoding（SAD）（Sun et al. 2021）也平行解碼，但只支援把輸入複製到輸出（僅適用輸入輸出高度相似如文法糾錯），且同樣不支援一般隨機抽樣情境。本文發表後，一個獨立實作（Chen et al. 2023）在 Chinchilla 70B 上展示了相近的 2X–2.5X 改善。
