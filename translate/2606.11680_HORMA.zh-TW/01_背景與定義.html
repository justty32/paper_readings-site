摘要

LLM agent 本身無狀態，長期任務只能把相關資訊持續編入愈來愈長的輸入 context，造成推理退化、成本與延遲上升。現有方法若非採有損壓縮，就是以相似度檢索，往往抓不到多步任務所需的時間結構與因果依賴。

本文提出 HORMA（Hierarchical Organize-and-Retrieve Memory Agent）。它把經驗組織成類似檔案系統的階層，摘要實體連回原始軌跡，讓系統不必在效率與細節間二選一。工作記憶分成結構建造與導航檢索兩階段。建造模組藉由辨認「缺少資訊」和「context 誤導或過載」兩類失敗，反覆修正組織方式；導航模組由強化學習訓練的輕量 agent 穿越階層，只選取最少但足夠的 context。ALFWorld、LoCoMo、LongMemEval 顯示，HORMA 在 context 受限時改善表現；長對話任務最多只需 baseline token 用量的 22.17%。

1. 引言

長期 agent 的工作記憶常落入兩個極端。history hoarder 留住大量歷史，最後被 context overload、lost-in-the-middle、成本與延遲拖垮；summarization、folding 等方法則壓縮歷史，可能永久刪掉下游才發現重要的細節。

External memory 雖擴充了儲存量，多半仍是扁平的獨立條目，再以 semantic similarity 撈取。這種方法不擅長表達長期累積的時間階層與因果關係，容易取回語意相像、時間卻已過期的資料。

作者進一步主張，memory construction 和 retrieval 的角色不同。Construction 決定經驗如何被抽象與組織，效果要經過很長互動才顯現；retrieval 決定本次推論看見什麼，直接影響當下決策。若用稀疏 task reward 聯合訓練，失敗時很難判定錯在組織、檢索或下游推理。

HORMA 因此讓兩個 tool-using agents 共用一個階層 workspace：manager 建造穩定結構，retriever 在執行路徑上導航取證。前者透過成功／失敗軌跡的對比，累積非參數式管理技能；後者以 evidence-grounded reward 做 RL，降低 credit assignment 的混雜。

2. 相關工作

現有 working-memory 方法可粗分兩線。一線在資訊進入 context 前或期間壓縮、重構歷史，例如 ReSum、ACON、hierarchical folding 與 subgoal-based 方法；另一線在固定 budget 下動態維護文字狀態，讓 policy 決定儲存、更新與刪除。

近期 RL memory systems 開始把 memory operation 當作 action，但往往保留完整 trajectory，或用 task-level reward 一起訓練 construction 與 retrieval。HORMA 只訓練專用 retriever，把較難歸因的 construction 改成 skill evolution。

技能方面，既有方法有參數式 skill policy、code skill library，也有不更新模型的文字技能演化。HORMA 屬後者：把管理經驗寫回 prompt／skill library，而非微調 manager。

3. 預備定義

任務 query 為 q。第 t 步觀察 o_t、輸出動作 a_t，歷史為 H_(t-1)。主 agent M_θ 權重固定，依觀察、歷史、query 與主 prompt 產生動作。

真正的瓶頸是 H_t 隨時間增長。在 context window W 有限時，截斷會丟失遠距依賴；即使裝得下，過長歷史仍增加運算與資訊稀釋。問題不只是保存，而是如何在嚴格 budget 下組織與取回。
