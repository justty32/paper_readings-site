5. 實驗

5.1 設定

  • ALFWorld：134 tasks、6 categories；回報 success rate、平均 steps 與每步 input tokens。
  • LoCoMo：10 conversations；519 QA 取自其中 3 段，另外 7 段訓練 Qwen 3.5 4B retriever。
  • LongMemEval：367 QA，涵蓋 knowledge update、single-session、preference、temporal 等類型。
  • 主表公平比較時，主 agent、memory manager、retriever 與 baselines 均用 Claude Sonnet 4.5。對話 benchmark 用 Claude Sonnet 4.5 作 LLM judge，另在附錄提供 F1。
  • Baselines 包括 truncation、sliding window、embedding retrieval、Fold、HIAGENT、ReSum、ACON、A-MEM、Mem0；另測試「結構化 notes + embedding retrieval」，分離 organization 本身的貢獻。

5.2 主結果

ALFWorld 在 1,950-token small limit 下，truncation、sliding window、HORMA overall success 分別為 17.9%、29.1%、56.7%；在 2,200-token large limit 下為 34.3%、70.1%、73.9%。Fold 保存 reasoning traces，卻因占用太多可操作 context，在 small setting 僅 17.9%。

LoCoMo 的 HORMA overall LLM-judge score 是 51.6，高於 truncation 32.2、embedding 34.8、Mem0 43.4，也接近 no-limit 55.9。LongMemEval 則為 55.9，高於 truncation 34.1、Mem0 43.6，甚至高於 no-limit 的 20.4。作者將後者解釋為資訊稀釋：選擇性 context 有時比把 100K tokens 全送入模型更可靠。

各種 HORMA retriever 與「structured notes + embedding」都可把每題輸入控制在約 1,000 tokens 內。相對各 baseline，LoCoMo token 使用量為 3.07%–22.17%，LongMemEval 為 1.24%–16.19%。

5.3 分析

只用統一 management prompt、不加入技能時，Claude retriever 在 ALFWorld／LoCoMo／LongMemEval 是 51.5／42.2／43.6；加入 skills 後變成 73.9／51.6／55.9，retrieval calls 同時略降。

Qwen 3.5 4B retriever 的 no-skill/no-RL 結果為 35.8／27.0／30.8；加 skills 為 40.3／32.6／40.6；再加 GRPO 後成為 64.9／42.2／58.0。它只在 LoCoMo 訓練，卻對 ALFWorld 與 LongMemEval zero-shot transfer，且 LongMemEval 超過 Claude retriever。

換 manager backbone 的實驗顯示：若 construction 已把 workspace 組織壞了，即使換成 Claude retriever也救不回來。Retriever 能在結構中找資料，不能補造不存在或錯放的資料。

時間敏感題的 error attribution 顯示，相較 embedding retrieval，HORMA 主要降低 temporal staleness 與 irrelevant retrieval 等 non-reasoning errors；主 agent 相同，所以 reasoning-error 差異較小。LongMemEval 的 skill library 由空白起步，四輪後增至 63 項，task performance 隨之提升。

6. 結論

HORMA 把 working memory 明確拆成長時間尺度的 construction 與 critical-path retrieval。階層 workspace 保留摘要與原始軌跡的連結，memory skills 以反例反覆修正，retriever 則用 RL 學會以少量 context 找到必要證據。三個 benchmark 顯示這種分工可同時改善任務表現與 token efficiency，並讓輕量 retriever 跨領域泛化。
