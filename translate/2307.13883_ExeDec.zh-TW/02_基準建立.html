3 基準建立

第 2 節是元基準框架，本節把它實例化到兩個常用域：RobustFill 與 DeepCoder。

RobustFill（字串處理）：目標是由 I/O 範例合成一串字串操作；程式是多個運算式的串接（concatenation）。運算式有 4 類：擷取子字串（如 GetUpto(regex)）、回傳輸入的修改版（如 ToCase(case)）、特殊的 Compose（把修改運算套在另一運算結果上）、以及常數字元。例：程式 GetToken(WORD,-1) | Const(' ') | Compose(ToCase(PROPER), GetUpto(',')) 把 "TURING, Alan" 轉成 "Alan Turing"，長度為 3（即 3 個串接運算式，每個運算式即一個子程式）。作者在原 RobustFill DSL 上加了更多運算。輸入為最長 20 字元的隨機字串、每題 4 個範例。各泛化任務的長度/概念切分：長度泛化訓練 1–6、測試 7–10；概念切分把子字串運算歸「substring 概念」、修改運算＋常數歸「non-substring 概念」等。

DeepCoder（整數串列處理）：以逐行風格操作整數串列。每行對輸入或先前變數套一個 DSL 運算並賦值給新變數，最後一行結果即輸出。運算含一階（Sort、Reverse、各種索引/切片/彙整）與高階（Haskell 風的 Map、Filter、Count、ZipWith、Scanl1，搭配數個硬編碼 lambda）。例：x1=INPUT | x2=Map(**2) x1 | x3=Sort x2 把 [5,3,-4] 轉成 [9,16,25]，長度 2（每個非輸入行即一子程式）。用 3 個 I/O 範例、至多 2 個輸入、串列至多 5 元素、整數 −50..50。長度泛化訓練 1–4、測試 5；概念切分把一階運算加 Map 歸一概念、其餘高階運算歸另一概念等。

謹慎建構 DeepCoder：RobustFill 的串接結構使「一個任務的解程式數」較少，較無「測試題其實有訓練分佈內的解」問題；DeepCoder 較嚴重，故作者對訓練/測試分佈做窮舉列舉搜尋，找出各任務所有最小長度解，只把「最小長度解落在訓練分佈」者收為訓練題、「所有最小長度解都在測試分佈」者收為測試題，以確保解出測試題確實反映泛化。

選域理由：兩域都能大量生成帶有真實子程式分解的合成資料。二者差異大：RobustFill 由多個「大致獨立」的子程式逐步拼出輸出（近似 inverse CAD、實例化多欄位物件）；DeepCoder 則對同一批物件反覆施加運算直到得輸出（近似張量操作、動態規劃），且每行新增變數繫結使程式狀態隨時間改變、更接近真實程式、更複雜。

4 經由分解的程式合成

本節描述以執行分解為基礎的合成法：模型給定 I/O 範例後預測逐步的執行子目標，並為每一步合成子程式。

演算法 1（ExeDec）：以 t=1、原始 (Iᵢ,Oᵢ) 起步，迴圈中：(5) SubgoalModel 由當前規格預測下一批執行子目標 {Sᵢ⁽ᵗ⁾}；(6) SynthesizerModel 由「輸入＋子目標」預測下一子程式 P⁽ᵗ⁾；(7) 執行得 Eᵢ⁽ᵗ⁾；(8) 若所有範例執行結果都等於當前輸出，則合併 P⁽¹⁾…P⁽ᵗ⁾ 為完整程式並回傳；(11) 否則以領域特定的 UpdateSpecification 更新「還剩什麼要做」的規格，t 加一續行。

4.1 執行分解（Execution Decomposition）

核心是推理程式的逐步執行行為，而非碼 token。每一步先呼叫 SubgoalModel（吃 I/O，預測下一子程式在每個範例上的輸出＝子目標）；因子目標就是此步期望輸出，故「預測下一子程式」本身即是一個 PBE 任務，交給 SynthesizerModel 生出對應子程式；執行後算出「剩餘工作」的更新規格。更新規格全程以 I/O 範例維護：直覺上，輸入是當前程式狀態、輸出是整體任務輸出，但細節依 DSL 而異——RobustFill 因頂層恆為串接，輸入不變、輸出移除已合成的前綴：(Iᵢ⁽ᵗ⁺¹⁾,Oᵢ⁽ᵗ⁺¹⁾) ← (Iᵢ⁽ᵗ⁾, RemovePrefix(Oᵢ⁽ᵗ⁾,Eᵢ⁽ᵗ⁾))（若某子程式對某範例並非輸出前綴，此嘗試必失敗、在 beam search 中被當「非法」剔除）；DeepCoder 則把輸入擴為完整程式狀態（隨新變數擴增）、輸出不變：(Iᵢ⁽ᵗ⁺¹⁾,Oᵢ⁽ᵗ⁺¹⁾) ← (Iᵢ⁽ᵗ⁾∪Eᵢ⁽ᵗ⁾, Oᵢ⁽ᵗ⁾)。

Beam Search：演算法 1 只是單次嘗試；實作用改良版 beam search 並行多次嘗試，每個 beam 狀態是一次逐步合成的部分展開。候選序列 C＝[{Sᵢ⁽¹⁾},P⁽¹⁾,…,{Sᵢ⁽ᵗ⁾},P⁽ᵗ⁾]，分數為各步子目標與子程式的 log 機率之和再加合法性項 Valid：Score(C)=Σⱼ Score({Sᵢ⁽ʲ⁾})+Score(P⁽ʲ⁾)+Valid(C⁽ʲ⁾)。兩模型皆自回歸序列模型，故 log 機率即分數。Valid 預設 0，但若任何子目標/子程式無法解析或無法成功執行則設 −∞；若某候選的程式功能與 beam 中另一更高分候選等價（不同子目標可能得同一子程式、不同子程式合起來也可能功能等價）亦設 −∞；領域特定檢查或達步數上限亦然。非法元素於下一步掉出 beam。值得注意：不為每次模型呼叫另起 beam search，而是全程維持一條長 beam search，模型呼叫視為對既有候選序列「續加 token」並保持其分數。

4.2 模型架構

ExeDec 用兩個 seq2seq 模型（SubgoalModel、SynthesizerModel），皆採 Transformer。因有多個 I/O 範例、需對「範例集合」運作，作者改造為 Specification-Transformer：對每個範例 Xᵢ，編碼器先對輸入 Iᵢ 自注意、再由輸出（Oᵢ 或 Sᵢ）對 Iᵢ 交叉注意（雙重注意力，沿用 Devlin 等 RobustFill 作法）得 φᵢ，再跨範例串接為 φ；解碼器據 φ 自回歸逐 token 生成輸出（SubgoalModel 輸出以特殊 Sep token 分隔各範例子目標，SynthesizerModel 輸出即子程式 P）。

Aligned Relative Attention（ARA，對齊相對注意力）：採相對注意力（用位置間距離而非絕對位置），有助長度泛化。但 SubgoalModel 輸出是「跨範例的子目標串接」，子目標 Sᵢ 與其 I/O 編碼 φᵢ 間的相對位置對不同範例 i 並不一致，樸素相對位置嵌入會跨範例失準。ARA 修改子目標 token 在相對距離計算中的「位置」：每個 token 位置照常加 1，但每開始一個新子目標 Sᵢ 就把當前位置設為 φᵢ 的位置，確保 Sᵢ 與 φᵢ 起點的相對位置恆為 0。

4.3 No-Subgoal 消融

一個消融：同樣逐步分解，但不先預測執行子目標，直接由 I/O 範例預測下一子程式（把演算法 1 的第 5、6 行併為 P⁽ᵗ⁾←CombinedModel({(Iᵢ⁽ᵗ⁾,Oᵢ⁽ᵗ⁾)})，跳過子目標）。用相同架構（無 ARA）與類似 beam search。

4.4 模型訓練

以第 3 節方式生成訓練題，用教師強制（teacher forcing）+ 分解資料訓練：對真實解的每個子程式，蒐集 (A) 執行前面真實子程式後的更新規格、(B) 該子程式在所有範例的執行結果、(C) 子程式本身；訓練 SubgoalModel 由 A 預測 B、SynthesizerModel 由 B 與範例輸入預測 C、CombinedModel 由 A 預測 C。每種模型針對每個泛化任務分別訓練。DeepCoder 的變數名於固定集合中隨機取（而非規範順序），使模型能預測用到未見變數名的子程式（長度泛化所需）；模型只預測賦值式右側，測試時再依規範順序指派新變數名。超參：學習率 2×10⁻⁴、嵌入維 512、隱藏維 1024、batch 128、500K 步；RobustFill 約訓練 1 天、DeepCoder 約 5 小時，各用 8 顆 TPU v2。
