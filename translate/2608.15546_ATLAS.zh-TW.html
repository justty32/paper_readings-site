論文／訪談原始來源

ATLAS: Scaffold-Free Algorithm Synthesis by LLMs via Embedding-Guided Quality-Diversity Search

問題

多數 LLM 自動演算法設計方法（FunSearch、EoH、ReEvo 等）只在使用者指定的 scaffold 內優化一個元件（優先權選擇器、建構啟發式、評分函式），整體組織與元件互動被固定，限制了 LLM 能探索的設計空間。Full-algorithm synthesis 拿掉這個限制，讓 LLM 掌控完整演算法（LLaMEA 生成完整 metaheuristic，AlphaEvolve 演化使用者標記區塊），但代價是搜尋空間更大更異質，候選更容易在執行、介面合規、解建構、限制處理上失敗，且不同組織的競爭性演算法可能落在完全不同的設計區域，容易過早收斂到單一設計。

ATLAS 方法

設定：只固定問題規格、最小 I/O 介面、實驗協定；LLM 完全掌控元件庫存、互動與端到端流程。External evaluator 執行候選後驗證可行性並獨立重算目標值，不會替候選補完或修正不可行解，因此把 error-conditioned Repair 當成明確的搜尋算子。

Embedding-based similarity：演算法表示成 (name, description, source code) 三元組，用 mGTE-large-en-v1.5 把三者串接的文本嵌入，維護 cosine-distance 矩陣 D，支援 k-NN 檢索、聚類與去重／剪枝，不需手設計行為描述子。

Coverage-preserving archive：兩層去重（strict 去重近乎重複者；performance-aware 去重「距離小且分數差在容忍值內」者）；超過容量上限時反覆從最相似的一對候選中移除較差者，但保護 elite region（a* 及 k 近鄰）不被剪掉。這不同於「按全域 fitness 排名淘汰」，能保留非當前最優候選的代表性。

語意搜尋算子：Create（零參照，只用於初始化）；Improve/Tune/Simplify（單參照精煉/調參/去冗）；Combine/Diverge（多參照，整合互補想法／刻意產生差異大的設計）；Repair 接收被拒候選＋分類過的失敗證據（記憶體限制、逾時、限制違反、執行錯誤等六類），要求 LLM 針對性修正並重新生成整個原始碼再重新評估。

初始化：兩階段 bootstrap——先用 Create 高溫取樣（常聚集在教科書式做法附近），再反覆用 Diverge 要求「產生與參照不同的做法」擴大覆蓋，比只用 Create 明顯更廣。

三層搜尋：每輪重新計算 embedding 聚類，elite region {a*} ∪ 其 k 近鄰排除後，對餘下 archive 做 k-medoids（自動選 K）得到非 elite cluster，每個 cluster 挑 training 最佳成員為代表。Layer 1 對 a* 及其鄰域反覆精煉；Layer 2 對每個非 elite cluster 代表做同樣的單參照精煉與 cluster 內 Combine，讓「目前較弱區域」也有專屬提案機會，不需靠全域 fitness 排序才能被選為 parent；Layer 3 跨區發現——cluster 代表間 Combine、a* 與代表間的品質錨定 Combine、以代表與 a* 為參照的 Diverge。此機制與 island model、經典 MAP-Elites 都不同：沒有靠遷移連結的持久 deme，也沒有固定的行為描述子網格，聚類是每輪重新計算的暫態分組。

實驗設計

四個 NP-hard 問題：CVRP、CVRPTW、FSS（50 job/10 machine）、QAP（50 facility），各用 31 個訓練與 31 個獨立測試 instance，搜尋只碰訓練集，訓練選出的演算法在測試集評估一次（不可 fallback、重排、修復或重測）。基準三組：人工設計領域專用方法（PyVRP、OR-Tools、VROOM；NEH、IG-TB、Iterative Beam Search；RoTS、SA、BLS、BMA）；元件式 LLM 方法（ReEvo、EoH、MCTS-AHD，共享 greedy scaffold 評估）；以及作者構造的 EoH-Full（EoH 演化框架接上 ATLAS 的 full-algorithm 算子與 evaluator，保留 EoH 原本 fitness-driven 選擇），用來把「scaffold-free 效果」與「ATLAS 的 QD 搜尋效果」分開檢驗。

所有 LLM-based 方法用 GPT-5-mini（reasoning effort low，溫度 1.0），依 token 用量對齊每次合成 run 的預算（各問題 5–7M token）。各設定共用單 instance 執行時限（30s–240s），所有方法單核單執行緒執行；PyVRP、OR-Tools 的關鍵部分是編譯後 C++，LLM 合成演算法以 Python 執行，相同 wall-clock 上限實際上偏向人工設計基準。統計檢定：每個測試 instance 先對 5 次獨立 run 取平均，再用兩側 Wilcoxon signed-rank test（α=0.05）配對比較 31 對 per-instance 原始目標值；報告的百分比差距只是描述性的，不是檢定輸入。

結果

與基準比較（Table II）：paired Wilcoxon 檢定下 ATLAS 在全部四個預設設定都統計顯著優於所有 LLM-based 基準（EoH、ReEvo、MCTS-AHD、EoH-Full）。EoH-Full 比元件式版本大幅進步，證明換成 full-algorithm artifact 加對應算子有實質效果；EoH-Full 與 ATLAS 共用全部 full-synthesis 機制，ATLAS 對它的剩餘優勢更直接支持 archive-based QD 搜尋本身的貢獻。ATLAS 對「統計上最佳人工設計基準」的相對均值差距：FSS 0.347%、CVRP 0.094%、CVRPTW 0.000%、QAP 0.460%；CVRP 上與 PyVRP 無統計顯著差異。

跨規模泛化（Table III，FSS 與 CVRP 在預設規模的一半與兩倍上重新合成）：ATLAS 在全部四個額外設定都是 LLM-based 方法裡最好的（FSS n25m5 差距 0.029%、n100m20 為 1.651%；CVRP n25 打平最佳參照、n100 差距 1.820%）。規模越大，合成演算法對數值超參數越敏感，Tune 算子沒做反饋式超參數優化，可能是差距擴大原因之一；較小的 FSS 設定上 EoH 反而優於 EoH-Full，顯示簡單 scaffold 在簡單設定上仍相當有效。

訓練選出的 archive 代表（Table IV）：以 5 次 run 中訓練目標最佳的那次 run 為例，四個問題的最終 archive 中，多個代表的 test 相對差距都落在 1% 以內。程式碼檢視顯示這些代表在核心建構或全域搜尋邏輯上確實不同——CVRP/CVRPTW 涵蓋 regret insertion、savings-based construction、ruin-and-recreate 等；FSS 涵蓋 NEH 式建構、genetic search、tabu-guided local search；QAP 涵蓋 memetic search、pheromone-guided search 等。作者明講這只顯示 scaffold-free 合成能保留多個結構不同的競爭設計，不因此證明 embedding cluster 全域對應真正的機制家族，也不證明各代表在 per-instance 上互補。

三層消融（Table V）：完整三層配置最佳（CVRP gap 0.094%、FSS 0.347%）；加入 Layer 1（elite 區集中精煉）與 Layer 2（代表級精煉）都各自有貢獻；僅 Layer 3（CVRP gap 2.095%）優於僅 Layer 1（3.620%）。附錄補充：mGTE-large-en-v1.5＋三欄串接是最強的 embedding 策略；雙階段初始化擴散更廣；語意近鄰選取優於 fitness-based 或隨機；GPT-5-mini 用 Low reasoning effort 品質-成本平衡最佳；換其他 LLM backend 仍有效。

結論與局限

ATLAS 用問題規格＋最小 I/O 介面取代預先指定的內部結構，靠 embedding-guided coverage archive 與三層搜尋支援多模態搜尋、精煉與跨區重組，在四個組合優化基準上優於多個元件合成基線與 matched 的 full-synthesis 對照組，同時與強力人工設計基準高度接近。後續方向：合成的混合演算法常帶特定超參數，Tune 算子尚無經驗式超參數優化（可能是差距來源之一），計畫整合訓練期 HPO；另一方向是讓資源分配依累積訓練證據動態集中在有希望的區域，同時維持覆蓋度。
