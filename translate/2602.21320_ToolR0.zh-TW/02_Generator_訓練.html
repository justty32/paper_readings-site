3.2 Generator 訓練

Tool-R0 以 GRPO 訓練 Generator 策略 πθ，從頭合成具挑戰性的工具呼叫任務，僅使用提示與任務規格 s。每個生成樣本包含：（i）使用者請求，（ii）明確工具菜單，（iii）gold 工具呼叫。Generator 須輸出四個標記區塊：<think>、<question>、<available tools>、<tool call answer>。工具菜單為 JSON 列表（含名稱、描述、參數 JSON schema），gold 工具呼叫為純原始參數 JSON 列表——使工具菜單與呼叫可 JSON 驗證，實現執行基礎回饋。

3.2.1 Generator 獎勵設計

在零資料制度中訓練 Generator 需要同時強制可靠且目標化學習信號的獎勵。Generator 以三種獎勵訓練，服務三個互補目的：（i）強制嚴格的程式碼可驗證輸出介面（rfmt），（ii）保證工具菜單與 gold 工具呼叫間的內部一致性（rvalid），（iii）以瞄準當前 Solver 既不瑣碎也不可解的任務來誘導自適應課程（rcurr）。

格式獎勵 rfmt：rfmt(x) = Itags(x) + Itools-json(x) + Igold-json(x)，分別檢查四個必要區塊可提取、工具菜單解析為 JSON 工具規格列表、gold 呼叫解析並正規化為規範工具呼叫表示。

有效性獎勵 rvalid：rvalid(x) = λMenu·I[n⋆∈T] + λGold·I[req(n⋆)⊆keys(a⋆)] + λValue·I[vals(a⋆)↪q]。三項分別驗證 gold 工具存在於菜單、所有 schema 所需參數存在、每個非平凡參數值（不含布林與 null）以詞邊界匹配出現在問題中。權重 (λMenu,λGold,λValue)=(0.4,0.4,0.2)。

課程獎勵 rcurr = rdiff + rsem：

難度獎勵 rdiff（Fig. 3 帶通濾波）：以當前 Solver 做 K=8 次 MC 隨機解碼，估計成功率 p̂succ = (1/K)ΣI[ĉ(k)=c⋆]。對於可解任務（p̂succ≥1/K），難度獎勵在 p̂succ∈[Plow,Phigh]=[0.25,0.75] 內為 1，兩側 Gaussian 衰減（σ=0.12）。此帶通結構反映三個設計洞察：（1）p̂succ<1/K 的任務（無樣本匹配 gold）為零獎勵——可能為表述不當或不可解的生成；（2）獎勵平台而非單一峰值，確保任務不瑣碎也不沮喪困難，平台寬度吸收 MC 估計的固有噪音；（3）Gaussian 衰減提供漸進衰減——過難任務鼓勵 Generator 產生稍簡單變體，過易任務鼓勵更難變體，無硬截斷震盪。硬截斷消融顯示 -3.74pp（↓7.82%）劣化，證明平滑轉換對穩定訓練至關重要。

語意對齊獎勵 rsem：當前 Solver 對 Generator 輸出評分語意連貫（1–5 分，Fig. 11），正規化至 [0,1]：rsem=(s−1)/4。防止即使工具呼叫語法有效但問題模糊或模板化的情況。

3.3 Solver 資料集建構

訓練 Generator 後凍結之，純粹作為條件化於相同控制規格的任務合成器。從領域條件化輸入出發，透過三階段管線構造 Solver 訓練資料：

  1. 規格接地生成與去重：從凍結 Generator 採樣 10,000 候選任務（使用者請求、工具菜單、gold 工具呼叫三聯體），以問題-工具-呼叫組合的正規化簽名去除近重複樣本。
  2. Solver 基礎交叉驗證：以 Solver 多次採樣每個候選，衡量預測與生成 gold 工具呼叫間的一致性，僅保留具一致解的任務。此程序遵循可重現答案提供更可靠監督的原則。
  3. 難度探測與課程選擇：從經驗證池以 Solver pass@K 成功率估計難度，分為 easy／medium／hard 三桶。選取樣本以保持領域多樣性同時維持平衡難度混合。10,000 候選過濾至 2,000 樣本。

所選資料按階段課程組織，從易到難在批次層級推進：早期以簡單樣本為主，較難任務逐步引入。當 Solver 過早暴露於遠超當前能力的任務時，策略梯度嘈雜且無資訊量；按 Solver 答案一致性分類合成任務並逐步暴露更難問題，確保在可靠範例上建構基礎技能後才應對組合式多工具場景。

3.4 Solver 訓練

Solver πϕ 被訓練為給定使用者查詢 q 與工具菜單 T 預測正確工具呼叫，使用引發明確推理的提示模板，遵循推理導向 RLVR 的先前工作。Solver 在 TIR 設定中訓練；首先生成 <think> 標籤內的推理，隨後在 <tool call answer> 標籤內生成預測工具呼叫。

格式獎勵 rfmt：rfmt(ŷ) = 0.3·Itag + 0.3·Iparse + 0.4·Inorm。使用超寬鬆載入器（接受嚴格 JSON、Python 字面量風格、code-fenced JSON），將省略佔位符視為無效並賦予零獎勵。

準確度獎勵 racc：將工具呼叫正確性分解為三成分——工具名稱匹配 sname∈{0,1}、參數鍵重疊 skey∈[0,1]（鍵集合 F1）、值匹配 sval∈[0,1]（交集鍵上的匹配值比例，使用穩健比較器——數值強制與空白不敏感字串匹配）。配對分數 s(ĉ,c⋆)=0.2·sname+0.3·skey+0.5·sval。匹配分數在 gold 呼叫間平均得基礎準確度 s̄。以乘法懲罰抑制多餘呼叫：racc=s̄·1/(1+0.25·max(0,|Ĉ|−|C⋆|))。

當 Solver 改善時，其成功統計直接影響 Generator 的難度獎勵（Eq.(4)），閉合自我對弈迴圈。
