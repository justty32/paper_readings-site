摘要

大型語言模型已迅速進化為能解決廣泛任務的通用代理，然而當前模型在推理上仍效率不彰：它們對所有任務都投入固定的推理階段計算量，不分任務複雜度──常在簡單問題上過度思考（overthinking），卻在困難問題上思考不足（underthinking）。本綜述對高效的測試時計算（test-time compute, TTC）策略進行全面回顧，這些策略旨在提升 LLM 推理的計算效率。我們提出一個二層分類學，區分 L1 可控性──在固定計算預算下運作的方法──與 L2 自適應性──根據輸入難度或模型信心動態擴展推理的方法。我們對主流商業 LLM 跨多樣資料集進行基準測試，凸顯推理效能與 token 用量間的關鍵取捨。相較於先前的效率推理綜述，本回顧強調 TTC 方法的實用可控性、自適應性與可擴展性。最後討論混合思維模型等新興趨勢，並為未來研究指出關鍵挑戰，旨在讓 LLM 更計算高效、穩健且能響應使用者約束。

1. 引言

LLM 成功的三大支柱：Transformer 架構、萬物即 token 序列、神經擴展律。然而，LLM 在複雜推理、規劃與搜索任務上仍掙扎。與人類能靈活分配認知努力不同，LLM 在推理時對每個 token 使用固定的計算量（即固定層數），不分任務難度。測試時計算方法讓 LLM 將複雜問題分解為中間步驟（CoT）、或並行探索多條解題路徑。這些方法在數學等重推理領域帶來顯著增益，但代價高昂──常超過普通前向傳播 10 倍以上。大型推理模型如 o1、DeepSeek-R1 頻繁對「1+1=?」這類簡單查詢過度思考，卻對更複雜問題分配不足。

近期的效率 TTC 研究轉向根據使用者偏好或任務難度來適應或約束推理階段計算。商業 LLM 開發者如 Anthropic（Claude 3.7 支援 thinking token budget）、OpenAI（o1 系列提供多種 reasoning effort 等級）已大量投資可控 TTC 機制，反映了「快慢思維」概念正被實作於產品中。這凸顯了可控與自適應測試時計算研究的實務意義。

2. 背景

2.1 測試時計算

測試時計算方法分為兩大類：**並行（parallel）**──對同一問題取樣多組解後聚合（如 self-consistency 多數投票、Best-of-N 用獎勵模型選最佳）；**順序（sequential）**──迭代精煉單一候選解，基礎形式為 CoT，進階包括自我修正、beam search、MCTS 等混合策略。近期大型推理模型以 RL 訓練產生長 CoT，內化了搜索過程（回溯、自我評估、並行探索），順序方法因後面計算能構建在中間推理步驟上而擴展得比純並行方法更好，但需要非線性多跳推理路徑的難題可能仍需兩者結合。

2.2 問題定義

形式化：對推理軌跡 r∈R（如 self-consistency 中 r 為生成的響應集合），P(r,x) 為效能指標、E(r,x) 為效率指標。L1 可控：max P(r,x) s.t. E(r,x)≥1/C（C 為使用者預設預算──對順序方法為 token 數，對並行方法為取樣數）。L2 自適應：max P(r,x)+αE(r,x)（α 為超參數，不需預設 C）。效率指標包括：token 成本、FLOPs 成本、以及結果效率指標 E_O = T̂(r)/T(r)（到首次產生正確答案的 token 數與總 token 數之比）。效率實現手段分三層：prompting（無微調）、SFT（微調於高效響應）、RL（直接最大化效率指標作獎勵）。注意：本綜述聚焦推理過程本身的效率，不涵蓋量化、KV 快取等系統級推論最佳化。

3. 大型推理模型的效率分析

3.1 現有模型 L1 可控性分析

評估 Claude 3.7 Sonnet 的 thinking budget 參數。結果顯示模型確實在 AIME（競賽數學）上消耗遠多於 MATH500 的 token，且存在長尾──部分問題大幅超出預算。說明即便最先進的商業模型在預算一致性控制上仍有改進空間。

3.2 現有模型效率分析

基準測試（AIME、MATH500、MMLU Pro STEM/Non-STEM）：非推理基線模型 token 用量顯著較低；o1/DeepSeek-R1 等經 RL 訓練的高效能推理模型產出長達 5 倍，但在難題上達到最先進準確率；透過蒸餾訓練的精簡推理模型（如 DeepSeek-Qwen 7B）在四類中的三類反而產出最長輸出，效能卻低於基線──與「SFT 記憶、RL 泛化」的發現一致，蒸餾可能導致死記推理軌跡。三大發現：(1) 順序推理模型普遍缺乏預算意識；(2) 簡單題上加預算回報遞減甚至誘發 overthinking，難題卻 underthinking；(3) overthinking 不限於 STEM，也泛化到非 STEM 推理任務。

4. 可控測試時計算（L1）

4.1 順序

Prompting：CoT 對簡單問題也會導致冗長輸出。CCoT（「簡潔」+「逐步思考」）可壓縮但弱模型在數學上準確率下降；CoD（每步 ≤ 5 字）省 token 達 92.4% 且不限步數；s1「預算強制」──截斷超預算部分或追加 "Wait" 提示以鼓勵重新評估。SFT：CoT-Valve 用 LoRA 適配器調控 CoT 長度（系統 1↔系統 2）；TokenSkip 按語義重要性壓縮 CoT（但壓縮後難以閱讀）；System-1.x Planner 用 hybrid factor 在快慢規劃間切換。RL：LCPO（L1-Exact/L1-Max）以長度懲罰獎勵訓練模型遵守 token 預算，準確率隨預算線性增長；Elastic Reasoning 將總預算分為思考階段 t＋解答階段 s，t 耗盡時強制插入 </think>，搭配 budget-constrained rollout 教模型即使用部分思考軌跡也生成正確答案。

4.2 並行

Prompting：Self-Consistency（固定 N 取樣＋多數投票）；Universal Self-Consistency（對自由形式答案用另一 LLM 呼叫求共識）；BoN（獎勵模型／驗證器給候選評分）。Finetuning：BoN-SFT 與 BoN-RL 考慮推論階段 BoN 過程進行「推論感知微調」，改善 exploitation-exploration 取捨。

L1 方法總結：順序方法在 token 級控制上更精細但需任務特定調校；未來挑戰在於開發跨模型、跨任務、跨預算泛化的直觀 token 級控制機制。
