好的，沒錯。嗯，首先是我看待它的方式，我覺得這個領域對它的看法隨著時間推移發生了變化。嗯，像是很久很久以前，程式合成意味著在給定對所需程式非常精確的規格說明（Specification）的情況下，在某種程式語言中生成或構建出程式。當時的想法是，你基本上寫下了一個類似數學題目，或者你在演算法考試中會看到的描述，然後你希望得到的是像 Lisp 或 Python 或其他語言的程式碼，用來計算正確的數學函數，或者在圖形結構上執行正確的操作。嗯，這對「什麼是程式」做了非常強烈的設定。它認為程式必須是在人類用於編寫軟體的正式語言中。嗯，而且它也對你如何告訴合成器（Synthesizer）你想要什麼做了非常強烈的設定，比如你基本上必須寫下一些數學規格說明。

我想隨著時間的推移，嗯，大家越來越清楚，指定一個程式意味著什麼可以變得更加寬鬆。你可以提供程式應該做什麼的範例（Examples）。嗯，甚至給出程式行為範例的不一定非得是人類。比如如果你試圖編寫一個程式來描述現實世界中某些事物是如何運行的，那麼你給系統的材料可能就是數據（Data）。所以這更像是你從數據中學習程式。嗯，而且，特別是隨著語言模型在編寫程式碼方面變得強大許多，大家清楚地看到我們不必侷限於以前為了完成演算法作業而寫的那種生硬的程式。相反地，我們可以直接寫出任何你在 Python 中會寫的東西。這就為你可以在電腦上做的任何事情打開了大門。因此，現在我認為程式合成的概念寬廣得多了。嗯，我個人認為「程式」的概念比我們使用的程式語言更寬泛，它只要是同時具有語法（Syntax）與語意（Semantics）的東西即可。重要的是語法應該是遞迴且具可組合性的（Recursive and compositional），就像我可以利用小元件來建構更大的程式一樣。嗯，而且同樣重要的是，程式不單單是你寫下來的文字，你還必須有某種執行它們的方式，它們與真實世界是相互連結的。嗯，當你擁有這種看待程式的觀點時，就會發現自然語言其實也是一種程式，因為我們現在擁有了執行自然語言的方法。嗯，所以對我以及許多其他研究者來說，一個轉變就是將自然語言視為一種程式語言，只是它剛好比我們以前使用的語言更加飄忽不定（Flakier）。嗯，所以程式合成，無論是我個人對它的看法還是整個領域對它的看法，都隨著時間發生了演變。現在我認為它非常寬廣，但真正重要的是，程式是一種符號產物（Symbolic artifact）。它具有你可以進行重新組合的組件。通常情況下，你能理解這些組件代表什麼意思。嗯，而且不僅僅是組件本身，還包括其語意，所以你可以去執行它。嗯，不過這個定義有點過於寬泛，以至於你甚至可以說任何東西都是程式。嗯，因此，當大家在實踐中使用這個詞以及我自己使用它時，我確實帶有一點常識性的理解。比如我覺得神經網路的權重（Weights）就不是程式，即使它們可以被執行，即使它們也有某種組合性（我可以為另一層添加更多權重），但我就是不會稱之為程式。嗯，所以這其中有一部分是比較非正式的，就像你看到一個程式時自然就會認出來一樣。

這聽起來太棒了，感謝您給出如此細緻入微的解答。嗯，您剛才提到您擁有認知科學的背景，而且您剛才也提到了神經網路。所以，那是符號化的那一側。那「神經符號 AI」（Neurosymbolic AI）呢？大家對於將深度學習與程式合成或其他符號化方法相結合的方法感到非常興奮。這顯然是您工作非常重大的一塊，嗯，甚至包括我們今天會聊到的 DreamCoder。您能為我們定義一下，您是如何看待神經符號 AI 的嗎？

好的。神經符號 AI 基本上只需要具備非平庸的（Non-trivial）神經組件與符號組件，並且它們能夠協同工作。也許是符號部分調用神經部分，也許是神經部分調用符號部分。嗯，從這個角度來看，有許多非常成功的 AI 系統，比如 AlphaGo 或者 Claude Code，它們其實都是神經符號系統。嗯，我想這個詞通常不會被用在那些系統上，但我覺得原因更多是歷史性的，比如它們並不是從喜歡使用「神經符號」這個詞的學術社群中成長起來的。因此，它們通常不會稱自己為神經符號系統。嗯，但顯然它們非常成功。所以這個通用的範式運行得非常好。

這太酷了。我以前還沒聽說過 Claude Code 被歸為這一類，但仔細想想確實很有道理。

沒錯。而且它們的核心絕對是大型語言模型（LLM）。你知道的，有些系統的核心是符號化的，然後它們疊加神經網路，比如用於搜尋導向（Search guidance）；而另一種我也知道您在實驗室中一直在研究的非常令人興奮的方向——我們之前還請過您的學生 Top 來過節目——就是「世界模型」（World models）。嗯，您是如何定義世界模型的？我知道這不是一個……我並不是想出難題，我知道來自認知科學背景的人可能對此有各種不同的觀點，但如果用最通用的術語來說，您會如何描述世界模型？

好的。世界模型是一個允許你回答關於世界、或關於世界某一部分的問題的物件。所以，我覺得這裡最難的部分是定義什麼是「世界」。通常世界模型並不會建立整個世界的模型，它們可能建立的是一個電子遊戲的模型，或者一個機械零件的模型之類的。所以它並不是真正的整個世界，它們選擇了世界的某個切片。但是關於這些被建立模型的系統，重要的是它們具有某種隨時間變化的狀態（Time-varying state）。嗯，而且通常我們還會引入「動作」（Actions）的概念，意味著存在我們可以進行干預的變數。而這些變數同樣具有時間組件，我們可以談論隨時間進行的動作。要讓它們真正成為「動作」，關鍵在於你的干預只能以先前發生的事情為條件（Condition on things that happened earlier）。這是一個比僅僅預測下一幀（Predicting the next frame）更寬泛的世界模型定義。嗯，因此，當人們談論影片世界模型或者像 Genie 這樣的系統時，它們往往是在預測下一幀、完全模擬世界，而模擬器（Simulators）確實是世界模型的經典範例。嗯，而 Top 以及其他合作者、學生以及其他實驗室的人一直在研究的，是一種稍微不同類型的世界模型。在這種模型中，目標不是預測下一幀，但目標仍然是能夠回答關於世界的各種不同問題。嗯，比如未來會發生什麼，無論是近期的未來還是遠期的未來；過去可能發生了什麼；或者我如何達成某些目標。嗯，你還可以詢問關於世界的隱藏狀態（Hidden states）的問題，比如我可能把一顆球扔到屏風後面，然後我可以問：球在什麼時刻有半個身軀藏在屏風後面？嗯，這是一個關於世界的問題，它不應該引用你所能觀察到的任何像素。重點就在於你無法觀察到屏風後面的球，但這是一個結構完整的合法問題，人類能夠回答它。而為了回答它，我們顯然在使用關於世界如何運作的通用知識。嗯，所以，我對世界模型的看法是，它應該能為各種不同的下游查詢（Downstream queries）服務，其中有些查詢顯然無法簡化為按幀預測世界的模擬。

完全有道理！我們稍後在今天的對話中會更多地探討世界模型。嗯，不過感謝您剛才給出的概述，這非常令人興奮。當你考慮到像機器人學（Robotics）之類的應用時，這似乎是長期以來一直缺失的關鍵拼圖。在我們進一步深入討論 DreamCoder 之前，嗯，回顧一下這篇論文，您最初是怎麼進入這個符號化研究領域的？這一直都是您研究的核心支柱。嗯，您當時在 MIT 讀書，而 DreamCoder 這篇論文也正是出自 MIT。您當初是怎麼發現這個方向的？嗯，還有，為什麼您當時沒有被拉進深度學習那邊，或者在 LLM 浪潮到來時直接搭上 LLM 的列車呢？

好的，沒錯。我是說，最坦白的笨回答是：我的年紀夠大，在我開始做 AI 的時候深度學習根本還行不通！所以……[笑聲] 如果說這不是我沒有立刻跳上神經網路列車的部分原因，那我就是在撒謊了。嗯，但真正的答案是，嗯，我當時作為一名學生在學習 AI，接觸到了各種各樣的 AI 系統，它們擁有非常適合特定領域專業知識的知識表示（Knowledge representations）。比如你可能會提出某種常識推理問題，寫下某種帶有機率的符號模型，然後你會展示這個模型非常擅長回答關於該常識推理情境的問題。嗯，這看起來非常令人興奮，而且有許多領域都有這樣的範例，比如機器人規劃（Robot planning）或視覺感知（Visual perception），人們寫下一個模型，它是符號化的，而且它確實精準擊中了人類擅長思考且我們認為 AI 也應該擅長思考的狹窄切片。嗯，但這就提出了一個問題：這要在哪裡終結？難道我們就只能手動編碼一堆符號模型，以一種零碎拼湊的方式覆蓋所有的智慧嗎？這似乎偏離了重點，因為智慧的重點在於沒有人在我們大腦裡預先寫好程式，我們是即時生成（On the fly）這些知識的。這似乎表明，我們應該打造能夠即時為自己編程、並根據需要組裝這些知識區塊的 AI 系統，而我們擁有極佳的程式語言可以用來表達這些東西。因此，這意味著 AI 只需要為自己編寫程式。嗯，而且在那個時候，我也在修 Josh Tenenbaum 的課程，學習貝氏 AI（Bayesian AI），並且也在修一門探討高莫哥鏡複雜度（Kolmogorov complexity）的計算理論課。所以有各種各樣的想法都建議我走這條路。於是我就去和 Josh 聊了這些事，他聽了之後說：「沒錯！我和我的實驗室完全贊同，我們正在做程式合成的研究，加入我們吧！」嗯，這就是我如何進入這個領域的過程。
